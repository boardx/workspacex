# 00 · 概览：上会材料智能审阅助手（`/agent/team1`）

## 用户原话
> 根据现有的 skills 和 tools，以及附件的需求文档，设计一个独立的 agent，
> 他的链接地址是 `http://www.boardx.com.cn/agent/team1`，
> 写一份需求文档描述这个新 agent 的需求和整个交互过程，需求需要充分利用当前有的能力。

## HMW（来自 HMW 问题定义卡附件）
> **我们如何能够帮助「投资分析人员」，在「集团投决会前项目分析」中，克服「资料分析工作量大、时间长」，
> 从而「快速识别资料问题，加速沟通与分析过程」？**

这一句是本阶段的北极星：**不是替人做投资判断，而是把"读材料 + 查缺 + 找矛盾"的机械负担拿走，
把人的时间还给"追问什么、怎么定价、要不要投"**。

## 这个 Agent 是什么
一个**独立可分享的 Agent 落地页**：`http://www.boardx.com.cn/agent/team1`。
访问者打开即得一个已配置好的 Agent 会话（不需要先建项目、不需要懂 Skill/MCP 后台），
把一包上会材料拖进去，拿回三样东西：

1. **资料汇总提纲** —— 多份材料合成一份结构化的项目背景摘要（交易、标的、行业、财务、估值…）。
2. **缺失项清单** —— 对照集团上会标准模板逐条比对，标出「已满足 / 部分满足 / 缺失」，
   已满足的要引用材料原文，缺失的要说明缺什么、为什么它是上会必需。
3. **风险与矛盾标注** —— 跨文档交叉验证 + 行业常识校验，标出显性矛盾、隐性异常与关联遗漏，
   每条给出「问题 / 原因 / 材料中如何体现（可回跳的出处）」。

随后由人做两次确认（见 `01-interaction-journey.md`），Agent 再按人指定的方向做定向深挖，
最后整合成可归档的最终报告。

## 目标用户与场景
| 角色 | 场景 | 现状痛点 |
|---|---|---|
| 投资经理 / 投资分析人员（主） | 上会前 1-2 周收到项目组材料包，需判断"够不够上会" | 材料动辄数百页多格式，人工通读 2-5 天；矛盾点靠经验偶遇 |
| 投委会秘书 / 风控（次） | 上会前把关材料完备性 | 缺失项清单靠人工勾模板，反复退回项目组 |
| 项目组（被追问方） | 收到追问清单后补材料 | 追问口径不一致、来回多轮 |

## 成功标准（可度量）
- **S1 完备性**：对测试文件 A，输出的缺失项清单命中率达到 `04-acceptance-tests.md` 测试 A 的通过标准。
- **S2 矛盾识别**：对测试文件 B，命中 B-1…B-5 中 ≥3 项（含 ≥1 项隐性）。
- **S3 深层判断**：对测试文件 C，命中 C-1…C-4 中 ≥3 项且含 ≥1 项深层（C-1/C-2）。
- **S4 可追溯**：结论中每一条"材料中如何体现"都能回跳到具体文件 + 页码/章节（PDF 给到 bbox 级定位）。
- **S5 时效**：一包 ≤50 份、≤200MB 的材料，从上传到交出第一版三件套 ≤15 分钟。
- **S6 不编造**：材料里没有的事实，只能出现在"需核实清单"里，不得出现在"已满足"一栏；
  外部检索得到的行业数据必须标注来源链接与获取时间，与材料内事实**分栏呈现**。

## 硬边界（这个 Agent 不做什么）
- 不下投资结论、不给"建议投/不建议投"的评级；它输出的是**事实、缺口与问题**。
- 不修改、不回写上传的原始材料。
- 不把材料内容用于跨租户的记忆或训练；材料与产出物归当前访问者的项目层（见 02 的隔离要求）。
- 不在未标注来源的情况下引用任何外部数据。
