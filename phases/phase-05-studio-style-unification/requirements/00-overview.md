# 原始需求 — Studio 样式统一

## R1 Studio 列表与创建样式统一

- **Actor**：拥有现有 Studio 页面访问权限的已登录用户。
- **目标**：在研究、访谈和转录之间切换时，看到一致的列表层级、卡片和名称/标签创建表单。
- **范围**：`/research`、`/itv`、`/rec` 列表首页和创建弹窗的名称、标签区域；不包含详情页、工作台或后端接口。

### 前置与触发

用户已登录并按现有权限可访问对应页面。用户访问列表首页，或点击“创建研究”“新建访谈”“新建转录”。

### 主流程

1. 三个列表首页以转录页为视觉基线统一内容宽度、页头、筛选区、卡片、状态标签和主操作层级。
2. 用户继续使用已有筛选、搜索、排序、打开和返回操作，原有数据与路由不变。
3. 创建弹窗统一标题区、名称计数、标签输入容器、标签 chip、辅助说明和底部操作区。
4. 用户输入非空名称和零到五个标签后，进入各页面既有创建流程。

### 备选与异常流程

- 列表为空时保留已有空态和创建入口。
- 读取或创建失败时保留现有结构化错误提示与重试行为。
- 名称为空时提交不可用；标签达到五个后标签输入不可用。
- 用户取消或关闭弹窗时清空未提交草稿，不创建资源。
- 在 375px、768px、1280px 视口不发生横向溢出或按钮遮挡。
- 无访问权时继续由现有权限守卫拒绝或隐藏入口。

### 不变量与边界

- 名称上限 100 字符，标签最多 5 个，沿用当前校验语义。
- 不新增搜索、排序或筛选功能。
- 不修改 API、数据模型、持久化、权限、路由或详情页。
- 不增加网络请求；保留 loading、empty、error 状态。

### 验收线索

用户可在三个页面看到一致的列表和名称/标签表单风格；原有创建、取消、筛选、错误和移动端行为均可验证。
