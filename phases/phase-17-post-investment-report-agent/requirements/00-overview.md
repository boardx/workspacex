# 00 · 概览：投后管理报告 AI 生成单元（`/agent/team4`）

## 用户原话
> 根据我们 workspacex 现在有的 skills 和 tools，以及附件的需求文档，设计一个独立的 agent，
> 他的链接地址是 `http://www.boardx.com.cn/agent/team4`，
> 写一份需求文档描述这个新 agent 的需求和整个交互过程，需求需要充分利用当前有的能力。

## HMW（来自 HMW 问题定义卡附件）
> **我们如何能够帮助「投后管理人员」，在「编制项目投后管理报告」中，克服「数据局限、行业分析欠缺、
> 风险识别滞后」，从而「优化财务分析与风险预警」？**

这一句是本阶段的北极星：**不是替人做投资/退出判断，而是把"读材料 + 抓外部数据 + 拼对比 + 找风险"
的机械负担拿走**，把人的时间还给"要不要追加、要不要退出、怎么谈"。

## MAAU 一句话总结（来自 MAAU 画布附件）
> 依靠 AI 自动生成数据准确、来源可验证的投后管理报告，辅助退出决策并持续沉淀分析能力。

## 这个 Agent 是什么
一个**独立可分享的 Agent 落地页**：`http://www.boardx.com.cn/agent/team4`。
访问者打开即得一个已配置好的 Agent 会话（不需要先建项目、不需要懂 Skill/MCP 后台），
把一包投后材料（财务报表、审计报告、经营简报、合同条款、临床/研发进展、股东协议…）拖进去，
拿回三样东西：

1. **财务与经营分析底稿** —— 多份材料合成一份结构化摘要（营收/利润/毛利率/现金流/资产负债/
   关联交易/客户集中度…），含同比环比与趋势结论，每项标注出处。
2. **外部对标与行业研判** —— 从公开渠道抓取行业政策、可比上市公司数据，与材料内事实**分栏**呈现，
   每条带来源链接与获取时间。
3. **风险清单与预警** —— 显性异常、隐性风险、跨文件关联风险三分类，每条固定四列
   「编号 / 问题是什么 / 为什么属于问题 / 在材料中如何体现（可回跳出处）」，并给出风险窗口时点。

随后由人做两次确认（见 `01-interaction-journey.md`），Agent 再按人指定的方向做定向深挖
（重算、拉明细、补对标、测算现金跑道），最后整合成可归档的投后管理报告终稿。

## MAAU 画布落到需求（人与 Agent 的分工）
| 画布格 | 落到本阶段的要求 |
|---|---|
| Agent：从权威公开渠道抓工商/诉讼/新闻/研报信息 | 外部检索走既有 web/browser 工具，结果必须带来源 URL + 获取时间（`03` E 节） |
| Agent：对上传的财务报表做初步分析，输出趋势与异常结论 | 财务指标抽取 + 同比环比 + 异常判据（`03` B/C 节） |
| Agent：抓可比上市公司数据做同行业对比 | 对标口径与"未取证降级"规则（`03` E 节） |
| Agent：结合行业政策与上下游地位生成发展预测与风险提示 | 风险清单的"政策/外部"来源类，与材料内风险分栏 |
| Agent：整合全部分析，拼接输出投后报告初稿 | 报告模板与产出物（`03` F 节） |
| 人：上传原始材料并确认完整性与真实性 | 步骤 1 的上传确认（`01` 第 1 步） |
| 人：逐条审核结论与引用数据，确认无编造无偏颇 | **人工确认关口①**（阻断性） |
| 人：给风险分级并指定追问方向 | **人工确认关口②**（深挖唯一任务来源） |

## 目标用户与场景
| 角色 | 场景 | 现状痛点 |
|---|---|---|
| 投后管理人员（主，如 MAAU 画布中的刘俊） | 季度/半年度编制被投企业投后管理报告 | 材料多格式、人工读 2-5 天；行业趋势要另找资料；风险常在事后才发现 |
| 风控/合规（次） | 复核报告结论与数据引用 | 结论无出处，无法快速验证是否编造 |
| 投资总监 / 投决会（读者） | 依据报告判断追加、退出、条款触发 | 报告口径不一致，缺"什么时候会出事"的时间轴 |
| 被投企业（被追问方） | 收到追问清单后补材料 | 追问口径不一致、来回多轮 |

## 成功标准（可度量，对齐 MAAU 画布指标）
- **S1 数据准确**：报告中引用的财务数据与材料原文的一致率 100%（`04` E-3 机械核对）。
- **S2 显性识别**：对测试文件 A，命中 A-R01…A-R03 中 ≥2 项且数据引用无误。
- **S3 跨文件关联**：对测试文件 B，命中 B-R01…B-R05 中 ≥3 项，且含 ≥1 项跨文件关联（B-R02/B-R04）。
- **S4 深层研判**：对测试文件 C，命中 C-R01…C-R06 中 ≥4 项且含 ≥1 项深层（C-R05/C-R06）。
- **S5 可追溯**：每条"在材料中如何体现"都能回跳到具体文件 + 页码/章节/单元格；
  外部结论能点开来源 URL 并显示获取时间。
- **S6 不编造**：材料与外部来源都没有的事实，只能出现在"需核实清单"，不得进入结论区；
  Agent 生成的结论中人工核准无需大幅修改的比例 ≥70%（画布指标，按月统计）。
- **S7 时效**：一包 ≤50 份、≤200MB 的材料，从上传到交出第一版三件套 ≤15 分钟；
  单份报告编制时长较该组织人工基线缩短 ≥50%（画布指标，按季度对比）。
- **S8 风险预警覆盖**：`03` C 节定义的风险维度（财务 + 业务 + 行业/政策）三档覆盖率 ≥90%（每季抽查）。

## 硬边界（这个 Agent 不做什么）
- 不下投资结论、不给"建议退出/继续持有"的评级；对退出问题只输出**前置条件清单与风险窗口**，
  决策仍由人做（对应 `04` 测试 C 的第 3 问）。
- 不修改、不回写上传的原始材料。
- 不把材料内容用于跨租户的记忆或训练；材料与产出物归当前访问者的项目层（见 `02` 的隔离要求）。
- 不在未标注来源的情况下引用任何外部数据；未取得原始出处的行业数字一律降级为"未取证的常识判断"。
- **不复述数字**：材料里写错的（如测试文件 C 附件 A 的专利到期日笔误），Agent 要**指出冲突**
  并列入需核实清单，不许沿用其中一个版本当既成事实。
