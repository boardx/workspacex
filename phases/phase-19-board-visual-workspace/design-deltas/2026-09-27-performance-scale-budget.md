# Board 全规模工程性能预算

本轮在用户授权的 adhoc 设计范围内，将既有 5k 建议基线统一用于下列规模。1k 与 10k 的适用范围是本轮工程设计选择，不是既定 PRD 数值承诺，也不表示人类已签核或真实验收已通过。10k 不享有放宽预算。

applicable-object-counts: 1000, 5000, 10000

数值单源继续使用 `docs/design/whiteboard/requirements.md` 的 R9：冷加载 p95、本地输入/拖动反馈 p95、持续拖动最低帧率、重连恢复上限。远端收敛 p95 使用 `requirements/05-collaboration-history.md` 的 R9。这里不复制这些数值，机械策略从原文读取，来源漂移即失败。

热加载 p95 使用与冷加载相同的上限，不要求每次热加载实测都快于该次冷加载。帧率以 p95 帧间隔不超过最低帧率的倒数判断，避免对边界值再次取倒数引入浮点误判。重连检查全部采样中的最大值。

执行单源是 `apps/web/scripts/board-performance-policy.mjs`，类型声明与负向测试同目录。三个规模均必须通过每个数值门及既有数据身份、运行构建、真实传输、持久图片、trace 和收敛证据门，失败不能退回“仅测量”状态。

Heap、保留堆和 long task 继续采集；本轮没有为它们制定数值门，不能把“有测量”描述成内存/长任务性能达标。整体评分仍为 null：机器性能门不授予视觉九分，不替代人工视觉、真实硬件或 50 客户端长时验收。

本次不修改 producer 的对象分布、负载、样本数量、动作或 timeout。运行结果由主 session 的真实验收产物给出。
