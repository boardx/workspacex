# design-delta · prototype-board（自由画布原语）

> 用户在 devapp 实测做一个白板产品（进入白板 / 添加便签 / 连线与整理 / 多人协作），四页都画不出白板本身：
> 原语里没有「可以随意摆放便签、形状、连线的区域」，模型只能拿列表和卡片凑——首页成了「白板列表」，
> 「添加便签」成了一排小卡片。用户原话：「感觉无法理解我的意思」。
> 人类裁决（2026-09-27）：**新增 board 原语**（备选「只改提示词模拟」「允许自定义 HTML 区块」未采纳）。

## §1 形态：自带数据的叶子，不给所有原语加坐标

| | 做法 | 取舍 |
|---|---|---|
| **A（本 delta）** | `board` 是叶子（同 `table` / `chart`），便签 / 形状 / 文字 / 连线 / 光标都在它的 props 里 | 坐标只在画布里有意义；其余布局照旧靠 stack，不多一种出错的写法 |
| B | `board` 是容器，孩子带 `x/y` | 坐标要加到所有原语上，属性面板、导出、质量门全都要多判一层 |

## §2 契约（唯一事实源：`packages/contracts/src/design-prototype.ts`）

```
board{
  items: [{ kind: sticky|shape|text, text, x: 0–100, y: 0–100, w?: 4–60,
            color?: yellow|pink|blue|green|purple|gray, shape?: rect|round|circle|diamond, author? }]  ≤ 24
  links?: [{ from: items 下标, to: items 下标, label? }]  ≤ 24，from ≠ to 且都存在
  cursors?: [{ name, x, y }]  ≤ 4
  grid?: bool（默认开）
  height?: sm|md|lg|fill
}
```
- `x / y` 是元素**中心**相对画布宽高的百分比——换设备 / 缩放不跑位，连线中心连中心。
- 纸色 / 字色：`PROTOTYPE_BOARD_COLORS`（HSL，深浅主题同一套浅纸深字，字对纸 ≥ 9:1）。
- 图标闭集加 `cursor`（白板工具栏的「指针」，真实生成里模型要用而清单没有）。
- 属性面板字段类型加 `structured`：画布的便签 / 连线 / 光标**不开编辑框**，只显示有几项并指向对话——让普通用户在面板里改一串坐标对象，就是把 JSON 端到他面前。

## §3 各层跟进

| 层 | 改动 |
|---|---|
| 画布渲染 | 点状网格底；元素按中心坐标绝对定位；连线 SVG（拉伸不改线宽）+ 中点标签；光标 = 指针 + 名字 |
| React 导出 | 同一套几何 |
| 设计文档导出 | 列出便签 / 形状 / 连线 / 在线协作者 |
| PPT 导出 | 底板 + 按坐标摆放的色块；**连线暂不画**（PPT 这层的形状里没有线段，范围外） |
| 属性面板 | `structured` 字段只读摘要；草稿里跳过（否则保存时会被当字符串写坏） |
| 给模型的说明 | 何时用 board（产品本身是白板 / 思维导图 / 流程图 / 看板）、坐标含义、写真实内容、协作页画光标 |
| 质量门 M1 内容量 | 画布里的每个元素计入——否则「导航栏 + 工具栏 + 一块 15 张便签的画布」被判「几乎是空的」打回重画 |
| 保守修正层 | 纯图标按钮（`label` 空）用图标的中文名补文字（取契约里 `icon` 的中文名表，单一事实源） |

## §4 不改的

API 路由、数据库、错误码都不动：`board` 是组件树里的一种节点，走既有的原型写回。
