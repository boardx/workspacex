# design-delta · device-simulation（迭代 14）

> 人类交办（2026-09-08）：「对于 web 在预览的时候，有不同的设备的模拟的 view，
> 比如 laptop，pad，iPhone 等，模拟效果。」

## §1 语义：设备是**看的方式**，不是设计的属性

两种读法，本 delta 取 A：

| | 做法 | 取舍 |
|---|---|---|
| **A（本 delta）** | 设备是**预览时的镜头**，存在组件状态里，不进 `DesignProject` | 「这稿是给 iPhone 的」与「我现在用 iPhone 尺寸看」保持是两件事 |
| B | 设备写进项目（像 `theme` 那样 PATCH） | 换个尺寸看一眼就改了别人的项目；而且它会被误当成"这个设计只给这个设备" |

选 A 的第二个理由：**这套原语没有断点**。切到 iPhone 不会让原型变成"响应式之后的样子"，
只是把画板换成 393×852，内容按 flex 自适应到新宽度。把一个不产生响应式行为的开关
写进项目，会让读到它的人以为那里有响应式设计。界面上的 title 逐字说明了这一点。

项目的 `template` 仍然决定**默认**镜头：mobile ⇒ iPhone，ui ⇒ 笔记本，wireframe ⇒ iPad。

## §2 预设表是唯一事实源

`apps/web/lib/prototype-devices.ts` 一张表定义 id / 标签 / 机身形态 / 逻辑分辨率 /
圆角 / 是否可旋转。画布的 inline style、画板视图的布局算式、切换器的下拉**都从它来**。

⚠ 迭代 6 的 `PrototypeDevice`（phone|tablet|desktop）与 `DEVICE_SIZE` **已删除**——
它们是第二份尺寸声明。

### §2.1 为什么用真实逻辑分辨率

旧的画板尺寸（手机 300×560）是拍脑袋取的，看着像手机但比例不真。而"模拟"的全部意义
就在比例是真的：393×852 上放得下的东西，换成 375×667 的 iPhone SE 就未必放得下——
这正是设计者要看的。比例不真，得出的结论也不真。

闭集（顺序即下拉顺序，从小到大）：iPhone SE 375×667 · iPhone 15 393×852 ·
iPad 820×1180 · 笔记本 1280×800 · 桌面 1440×900。
加一款的判据是「有人真的会用它做设计决定」，不是「再多几个看起来更全」。

## §3 缩放：只缩不放

画板按**逻辑分辨率**渲染，再 `transform: scale` 整体缩进可用空间。

- 用 transform 而不是改宽高：改宽高等于换了个更小的设备，那就不是"在 1280 的笔记本上
  长什么样"了。
- **上限 1，永不放大**：把 393px 的手机放大到占满 900px 的面板，字会跟着变大、
  看起来"很清楚"——而那恰恰掩盖了「这行字在真机上有多小」，正是模拟要回答的问题。
- 容器尺寸为 0（首帧 / jsdom）⇒ 返回 1，不产生 Infinity 或 NaN。

## §4 机身 chrome

| 形态 | 画什么 |
|---|---|
| phone | 灵动岛（新机型）或上下额头（SE）+ 状态栏（时间/信号/电量）+ home 指示条 |
| tablet | 状态栏 + home 指示条，机身圆角更小 |
| browser | 红黄绿窗口按钮 + 地址栏（栏里放页标签），无 home 条 |

⚠ chrome 是**装饰，不是原语**：不进 `data-proto`、不可选中、不进导出的 class 比对
（V47 比的是原语树）。做成可选中的节点会让「选中一个节点去改」多出一批用户根本改不了的目标。

⚠ 交通灯用**语义 token**（destructive/warning/success）而不是 macOS 的字面色值：
模拟要的是"像个浏览器窗口"，不是像素级复刻，而字面色值在浅/深两套主题下不会跟着变。

## §5 旋转

可旋转的预设（手机/平板）交换宽高。桌面浏览器没有"竖屏"这回事 ⇒ `rotatable: false`，
按钮禁用，且**即使 landscape 状态还留着也不生效**——否则切到桌面会变成 800×1280 的竖条。
