> 前一 delta：[`prototype-navigation`](../prototype-navigation/)（`links` / `setLinks` / 预览模式）

## §0 现状与病根

**首次生成是「一次模型调用吐出所有页的完整组件树」。** 输出长度随页数线性增长，
模型单次输出预算固定 ⇒ 到 4、5 页必然撞顶。2026-09-07 线上实测的三个现象是**同一个根因**：

| 现象 | 机制 |
|---|---|
| 连续五次 `design chat model call timed out` | 生成几千 token 的时间超过 90s 预算（已把默认提到 180s，是止血不是治本） |
| 「AI 这次的输出太长被截断了」 | 输出撞到 provider 的 token 上限 |
| 对话里出现裸 JSON | 截断后 JSON 不完整，`JSON.parse` 失败（已修：`looksLikeJson` ⇒ 走 `MODEL_BAD_JSON` 不再回显；**库里修复前的旧消息仍在**） |

并且：`apps/api` 全仓**没有任何地方设置输出 token 上限**，用的是 provider 默认值。
这个天花板具体在哪，我们既没设定也没观测——"撞上了才知道"。

配套的第二处：prompt 现在明写「增页/删页必须整页给 `prototype`」
（`design-chat-model.ts:124`），因为 `frames` 与树必须等长。**这是整页重生成最常见的
触发原因之一**，而它本可以是一个局部 op。

第三处（本 delta 的另一半，人类 2026-09-07 交办）：现在导出只有 `.md` / `.json` / 当前页 PNG。
**拿不出可以直接发给别人的东西**——`.md` 要有 markdown 阅读器，`.json` 是给机器的，
PNG 一次一页。缺的是两样：**能点的 HTML** 和 **能发的 PDF**。

## §1 分页生成：一次骨架 + 每页一次

首次生成（当前 `prototype` 为空，或用户要求整页重画）从**一次调用**改为 **1 + N 次**：

```
第 0 次（骨架）  → {"reply": "...", "outline": [{"frame":"登录","intent":"一句话说明这页做什么"}, ...]}
第 i 次（第 i 页）→ {"screen": {"frame":"登录","root":{...},"links":[...],"notes":"..."}}
```

- **骨架轮**只输出页标签 + 每页一句意图，几百 token，实际上不可能截断。
  骨架一落库画布就有了 N 个空页 —— 用户 2–3 秒内看到结构，而不是盯着空画布等三分钟。
- **每页一轮**只生成那一页。单次输出量与页数解耦：8 页和 3 页一样安全。
- 每页**生成完就写回**（各自一条版本记录，`source: "model"`），画布一页页长出来。

### §1.1 页间风格一致性

每页轮的上下文里带**已生成页的结构摘要**（页标签 + 顶层节点类型序列 + 已用到的原语集合），
**不是**完整组件树——带完整树等于把省下来的输入 token 又填回去。

⚠ 这条是本 delta 最大的**未验证假设**：摘要够不够让模型保持风格一致，只能实测。
V44 就是钉它的：8 页项目生成后，页与页之间的 `navbar` / 间距 / 按钮 variant 用法一致。
若实测不通过，退路是「摘要里再带第 1 页的完整树」（输入变长，但仍与页数解耦）。

### §1.2 失败面：从「全有全无」降级为「哪一页没成」

现在截断 = 整段丢弃 = 用户白等三分钟。分页后：

- 骨架轮失败 ⇒ 与今天等价（什么都没有），照 `DesignChatFallbackReason` 回执。
- 第 i 页失败 ⇒ **只损失第 i 页**。该页在画布上标为「未生成」，其余页照常可用。
- 该页可**单独重试**，不重跑整个项目。

页级状态是**派生的，不新增存储**：`screens[i].root === undefined` ⇒ 未生成。
（`root` 可缺是 `prototype-navigation` §5 已经确立的合法初始状态——新建项目就是「有标签没树」。）

### §1.2b 实现偏差登记（2026-09-07 实现时发现，**不是**契约变更）

契约 §1 写的是「每页生成完就写回，画布一页页长出来」。实现是**一次原子写回**。

原因不是省事：这条路径是**一次 HTTP 请求一次响应**，服务端写八次也不会让用户的画布逐页
刷新——客户端只在响应回来时才看到结果。真要逐页可见需要流式或轮询通道，那不在本 delta
范围内。写多次只会多担事务风险、多记 N 条版本，换不到任何用户可见的东西。

因此两条随之落空，一并登记为**未实现**（见 verification.md V39 / V45）：
- **页级三态与「重试这一页」按钮**：失败的页现在**不落库**（不是落一个 `root` 缺的洞），
  所以画布上没有"未生成的页"这个状态可显示。
- **单页重试接口**：同上，没有可重试的目标行。用户侧的替代是回复里说清哪几页没画出来，
  并给一条「补画「X」」的建议 chip，点了就是一句新的对话。

**本 delta 真正兑现的**是病根那一半：单次输出量与页数解耦（不再超时/截断），
以及失败面从「全有全无」降到「只损失那一页，其余照常落库」。

### §1.3 输出预算显式化

1. 新增运维开关 `KERNEL_MODEL_MAX_OUTPUT_TOKENS`（缺省不传，保持今天的 provider 默认行为）。
2. prompt 里给出**单页节点数硬上限**（沿用契约既有的 `PROTOTYPE_MAX_NODES`，写进 schema guide）。
3. 截断判据不再只靠「JSON 解析失败」：模型返回的 finish reason 是 `length` 时直接判 `MODEL_OUTPUT_TRUNCATED`
   （`DesignChatFallbackReason` 闭集**加这一个成员**——本 delta 唯一的闭集扩张）。

## §2 两个新 patch op：`addScreen` / `removeScreen`

```ts
{ op: "addScreen", at: number, frame: string, root?: PrototypeNode }   // at = 插入位置（0..len）
{ op: "removeScreen", screen: number }
```

- 增删页不再需要整页重给 `prototype`；`frames` 与树**由 op 同时改**，等长不变量由实现保证而不是由模型自觉。
- `removeScreen` 之后统一过 `validateLinks`：指向被删页的 link 逐条丢，指向后面页的 link **索引整体前移**。
  （不前移会让所有跳转静默错位——比丢掉更糟，因为看起来是好的。）
- `addScreen` 同理：插入点之后的 link 目标索引整体后移。
- 人改与模型改仍是**同一个 op**，同一条 `applyPrototypePatch` 路径。

## §3 导出（一）：可点击的自包含 HTML

一个 `.html` 文件，双击就能在任何浏览器打开，**不联网、不依赖本产品**：

- 所有页按顺序渲染；
- `links` 是**真的能点的**——点击在文件内换页（锚点 + 一小段内联脚本），
  等于把预览模式装进一个可以发给别人的文件；
- 顶部一条页索引；每页带标签、交互说明（`frameNotes`）、跳转清单；
- 无外链：CSS 内联，字体走系统栈，不引 CDN。

### §3.1 渲染从哪来——本 delta 最大的隐性成本

画布现在由 React 组件 `PrototypeCanvas` + Tailwind 工具类渲染。导出 HTML 需要同样的像素，
三条路：

| | 做法 | 代价 |
|---|---|---|
| **A（建议）** | 把原型原语的样式从 Tailwind 工具类收敛成**一份 `wx-proto-*` 语义 CSS**，实时画布与导出**共用这一份**；导出用 `renderToStaticMarkup` 渲染同一套组件 | 一次性重构 21 个原语的 class；换来**单一事实源** |
| B | 导出侧另写一个 `renderNodeHtml(node): string` + 一份手抄的 CSS | 便宜一半，但**同一件事声明在两处**——违反 AGENTS.md 那条已经栽过五次的硬约束，且从此每加一个原语就要改两处、漂移无门控 |
| C | 抓已渲染 DOM 的 `outerHTML` + 内联 computed style | 最便宜，产物巨大且不可读；只能导当前视口里渲染过的页 |

**建议 A。** B 的省事是借来的，利息是漂移。

## §4 导出（二）：PDF 交付文档

内容按人类交办：**包括界面一节，每个界面一段说明文档**。

```
封面：项目名 / 生成时间 / 模板
1. 问题与目标
2. 验收标准
3. 界面
   3.1 页 1「登录」   [该页整屏图]  + 交互说明 + 结构大纲 + 跳转清单
   3.2 页 2「首页」   ...
4. 设计过程（对话摘录）
```

每页一屏图 + 一段说明，**图文同页**，跳转清单写成「按钮『发送』 → 第 2 页『设置』」这种人话
（`design-doc-markdown.ts` 已有的 `describeNode` + 标签解析逻辑，直接复用，不另写一套）。

### §4.1 PDF 怎么生成——请人类拍板

| | 做法 | 得到 | 失去 |
|---|---|---|---|
| **A（建议）** | PDF **就是 §3 那份 HTML 的打印视图**：加一份 `@media print` CSS，点「导出 PDF」调 `window.print()` | 真文字（可选中可搜索可复制）、中文字体走系统、**零新依赖**、与 HTML 同一事实源 | 用户要在浏览器打印对话框里点一次「保存为 PDF」；页边距/页眉由浏览器控制 |
| B | 客户端 `jsPDF` 直接下载 `.pdf` | 一键直接落盘 | 中文要打包字体（~8MB 进 bundle）或把文字光栅化成图（不可选中、不可搜索）；第二条渲染管线 |
| C | 服务端 headless Chromium print-to-PDF | 一键 + 真文字 + 版式完全可控 | 要给 `apps/api` 引入并运维一个 Chromium，部署面显著变大 |

**建议 A**：它把「PDF」变成「HTML 的一个视图」而不是第二条管线；中文字体这个坑
（B 的真实成本）也一并绕开。代价只有一次点击。

## §5 界面

1. **生成中**：画布上骨架页立刻出现，每页有「生成中 / 已完成 / 未生成」三态；
   已完成的页正常可点可改，不必等全部完成。
2. **未生成的页**：页面位置画占位框 + 一行原因 + 「重试这一页」按钮（只重跑该页）。
3. **导出菜单**（`prototype-export.tsx`）在现有四项后加两项：
   - 「可点击原型 (.html)」
   - 「设计文档 (PDF)」
4. 现有四项（`.md` / `.json` / 当前页 PNG / 复制 JSON）**一个不动**。

## §6 范围外（本 delta 不做，登记）

- **不做**导出产物的在线托管/分享链接——导出就是下载一个文件。
- **不做**并发生成（N 页并行调模型）：先把串行做对；并发会让「一页页长出来」的顺序不可预期，
  且放大配额压力。留作后续。
- **不做**PDF 的自定义模板/主题。
- **不改**任何既有路由；分页编排全在 `appendProjectChat` 这一条路径**内部**。
- **不清理**库里修复前存下的裸 JSON 历史消息（那是数据，不是代码；要清得单独走数据变更）。

## §8 对既有契约的改动清单（就这四处）

1. `DesignChatFallbackReason` 闭集 **+1**：`MODEL_OUTPUT_TRUNCATED`
   （闭集成员会进响应体 ⇒ 必须同步 `all-exceptions.filter.ts` 允许清单）。
2. `PrototypePatchOp` **+2**：`addScreen` / `removeScreen`（第 6、7 种 op）。
3. `validateLinks` 增加**索引平移**语义（增删页时目标索引整体前/后移）——纯函数，仍只声明一处。
4. 新增运维开关 `KERNEL_MODEL_MAX_OUTPUT_TOKENS`（缺省不传 = 今天的行为）。

**没有新路由、没有新表、没有新错误码。** 页级「未生成」状态是 `root === undefined` 的派生，
不新增存储字段。
