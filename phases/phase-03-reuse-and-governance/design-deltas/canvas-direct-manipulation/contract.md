# design-delta · canvas-direct-manipulation（迭代 15）

> 人类交办（2026-09-08）：「改进用户友好度……朝着 Claude design 的方向迭代」。
> 本轮取五处：图层面板、复制、上移/下移、键盘导航、快捷键安全。

## §1 为什么是这五处

画布已经能"选中一个节点改属性"（迭代 5），但**结构层面的操作一个都没有**。
模型一次画出来的树常有二三十个节点、嵌套三层，而用户此刻只能：用鼠标在渲染结果上试点，
选中后改文案，或者把整个节点删掉。想复制一个卡片、想把一行往上挪、想选中"外面那个容器"——
都做不到。这五处补的是同一个缺口：**看得见结构，动得了结构**。

## §2 op 复用：不新增 `move`

契约已有 `remove` + `insert`，而 `applyPrototypePatch` 按顺序执行——
「先删掉、再插到新位置」就是移动。新增一个 op 意味着契约、校验、模型 guide、
服务端应用逻辑各多一处要维护，换来的只是少写一行。

⚠ 插入下标要按**删除之后**的数组算。这一处差一格就变成"下移两格"或"原地不动"，
V80 用真实的树（应用完 op 再看顺序）钉住它——只断言 op 的形状会漏掉差一格。

## §3 复制去 id，移动保留 id

| | id | 为什么 |
|---|---|---|
| 复制 | **去掉**整棵子树的 id | id 在项目内唯一。带原 id 插进去会造出两个同 id 节点，之后按 id 寻址一律命中第一个——表现是「改了 A 却看到 B 变」。服务端 `ensurePrototypeIds` 补新 id |
| 移动 | **保留** | 它还是同一个节点，只是换了位置。去了 id 会让选中态与连线指向一个不存在的东西 |

## §4 三个入口，一份逻辑

属性面板按钮 / 图层面板 / 键盘快捷键，三处都调 `lib/prototype-node-actions` 的纯函数
算出 op，再交给**同一个** `runNodeOps` 执行（走与模型写回同一条 `patchPrototype`，I-11）。
三处各写一遍"复制是什么意思"，迟早出现「面板里复制会带 id、键盘复制不带」这种分叉。

## §5 快捷键的安全边界

快捷键**只在**编辑态、非预览、且**焦点不在输入框/文本域/下拉/contentEditable** 时生效。

⚠ 少了最后那个判断，用户在对话框里按 Delete 会把选中的节点删掉，而他只是想删一个字。
**这是这类快捷键最常见的翻车方式**，V83 专门钉它。

走不动的方向键**保持原选中**而不是清空——按一下方向键选中就没了，比没反应更让人困惑。

## §6 图层面板

摊平成 `{node, depth}` 一列，容器的孩子跟在它后面缩进 +1（与树的阅读顺序一致）。
只读结构不读样式——props 细节是属性面板的事。标签用 `prototypeNodeLabel`，
与面包屑同一个函数，不另写一份。

没有 id 的节点（服务端还没补上）点了也选不中 ⇒ **禁用**，比点了没反应诚实。
预览态不显示：那时候没有"选中"这回事。

# 迭代 16 追加：页管理与撤销

## §7 契约有能力，UI 够不着

`addScreen` / `removeScreen` 从**迭代 12** 起就在契约里，连"指向被删页的跳转自动偏移"
（`shiftLinkTargets`）都实现了。但三轮下来**没有任何 UI 调用它们**——模型能加页删页，
用户不能。本轮接上：页签行右侧的加 / 复制 / 删三个按钮。

## §8 新增 `renameScreen` op

改名此前没有 op。用 `removeScreen` + `addScreen` 拼是错的：

- `addScreen` 只带 frame/root/links，会**丢掉这一页的 notes**；
- `shiftLinkTargets` 先 -1 再 +1，中间那一步已经把指向本页的跳转改掉了，两步之后不保证还原。

改名是**只动一个字段**的操作，就该是一个只动一个字段的 op。

## §9 复制整页也要去 id

理由与复制节点同一条：id 项目内唯一，带原 id 插进去会造出两页各有一个同 id 节点，
之后按 id 寻址一律命中第一页。

## §10 一键撤销

复用既有 `restorePrototypeVersion`，不另造回滚路径。取**倒数第二版**——
最后一版就是现在这份，恢复到它等于什么都没发生。没有可回退的版本时说一句，不静默。

## §11 把页级 op 告诉模型（本轮抓到的真洞）

`PROTOTYPE_PATCH_GUIDE` 从没提过 `addScreen` / `removeScreen` / `setLinks`，
而它原本写着「新页面 ⇒ 用 prototype 整页给出」——**等于教模型为了加一页把所有页重画一遍**，
正是「单页超输出预算」那条根因的推手。

新增门控：契约里的每个 patch op 都必须出现在 guide 里。这条门当场抓到两个洞
（页级三个 + `setLinks`），不是假想的风险。
