## 0. 本束在回答什么

「反馈与迭代」这件事今天的实际状态是：**采集口一个都没有**。
后台有一块画得很完整的屏，每个按钮都在，点了什么都不会发生；
`/chat` 里对 AI 消息可以打 👍/👎（F176 已真），但没有任何地方能说一句
「这个 agent 老是漏附件」。所以本束先把水放进来。

## 1. 用例

### UC-F1 · 任何成员在任何页面提一条反馈

**主角**：组织内任何成员。

1. 点左侧图标栏最下方的「反馈」图标（<md 时在顶栏）。
2. 弹层打开，默认目标是**产品本身**。
3. 选类型（`缺陷` / `需求`）、写标题、写正文。
4. 弹层明写「将一并附带：当前页面 X · 版本 Y · 你的账号；正文只有组织管理员和你自己能看到」。
5. 提交 → 服务端落库，状态恒为 `待处理`，并写一条 `from = null` 的状态事件。
6. 弹层**自动切到「我提过的」**，刚提交那条排在第一行并标「刚提交」。

**R1**：提交人、状态、创建时间由服务端定，**不入参**。
**R2**：`occurredRoute` / `appVersion` 由客户端给（服务端不可能知道用户站在哪一屏、
浏览器上跑的是哪个构建），分列存，**不是一个 jsonb 口袋**。
**R3**：提交失败时弹层明说「这条反馈没有被保存」，**不切标签页**。
反馈是一次性表达——用户以为提交成功就不会再提第二次。

### UC-F2 · 在对话里对某个 Agent / Skill 提反馈

**主角**：组织内任何成员，在 `/chat` 里。

1. AI 消息的身份行上有一个反馈按钮（hover / 键盘聚焦显形），指向**这条消息的 agent**。
2. 会话内已挂载的每个 skill chip 旁有一个反馈按钮，指向**那个 skill**。
3. 点开的是同一个弹层，只是目标不同，标题写成「对 Agent「调研助手」提反馈」。

**R4**：目标传的是**真实 id**（`agentId` / `skillId`），不是显示名——显示名会改。
**R5**：skill 目标**不带版本**。👍/👎 是对某一次具体回答的评价，那次回答确实用了某个
确定的版本；而「我想给这个 skill 提个意见」是对这个 skill 这件事说的，用户心里没有版本。
服务端替他填一个「当前生效版本」会制造一个凭空生成、没人能反驳的归属。
**R6**：这条反馈**不进任何满意度分子分母**。满意度口径是 `👍/(👍+👎)`（O-37），
让文字反馈也参与会让同一个不满被计两次，而两个数字看起来都很正常。

### UC-F3 · 看别人提的，并投票

**主角**：组织内任何成员。

**R7（D3，2026-08-15 人类裁决）**：标题、类型、票数、状态**对全组织可见**；
**正文只有组织管理员与提交人**看得到。无权时投影 `detail: null`，界面说
「正文仅组织管理员与提交人可见」——**不是**「暂无内容」。
两者可分辨的前提是落库的正文非空（迁移里的 CHECK），所以 `null` 恒等于「无权」。

**R8**：票数是 `COUNT(*)`，**没有计数列**。同一人重复投票是 no-op，不是 +1；可撤票。
**R9**：**提交人可以给自己的反馈投票**。票数的口径是「有多少人也遇到了」，
提交人显然也遇到了；禁止自投会让「1 人遇到」显示成 0。

### UC-F4 · 组织管理员分诊

**主角**：组织管理员（`orgRole === "admin"`），在 `/admin/feedback`。

1. 屏分两列：左「软件反馈」（目标 = 产品），右「Agent / Skill 反馈」。
2. 顶部一条状态分布（总数 + 四个状态），**一次查询派生**。
3. 每条上按当前状态出现该状态**出得去的那几条边**。
4. 转 `不做` 时先展开理由输入框，理由必填。

**R10**：状态机四态，转移见 `domain.md` §3。每个终态都能回 `待处理`
（「已修复」会被证伪，「不做」会被推翻）；`已修复 → 不做` **不是一条边**——
那要先退回 `待处理`，让改判在流水里留下两条痕迹而不是一条抹掉中间判断的直达边。
**R11**：状态变更 append-only 留痕（谁、何时、从哪到哪、为什么）。
这是这条闭环里唯一能回答「为什么我提的那条一个月没人管」的东西。
**R12**：本体除 `status` / `status_reason` 外**不可改**。提交人事后改正文会让已经据此
分诊、已经生成 PR 的链路指向一段不再存在的文字。

## 2. 明确**不做**的（缺了是结论，不是遗漏）

- **附件**（D4 已裁）：第一版纯文字 + 自动上下文。附件牵扯 E2 的脱敏阻断，是 FB-4 的量。
- **`[打开迭代看板]` / `[导出]`**：UC-17.6 A1/A2 逐字「按钮存在，但点击后无目标屏
  （原型待补）」。留一个点了会出现「实现者自己设计的看板」的按钮，比没有按钮更糟。
- **分页**：量级是「一个组织一周几十条」。分页会引入游标契约、稳定排序、总数口径三件事，
  此刻一件都没有被需要。
- **反馈的编辑 / 删除**：反馈是历史事实。要补充就再提一条。
- **skill 屏那块重复的看板**（D1 已裁）：后台屏是唯一入口，skill 屏降级为链接。
