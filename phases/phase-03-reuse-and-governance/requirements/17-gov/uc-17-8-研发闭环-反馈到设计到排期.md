# 原始需求（细化）— UC-17.8 研发闭环（Feedback → Design → Dev）

> 所属：阶段三 · 跨项目与对外 / M17 审计、合规与数据治理
> 来源：人类 2026-09-04 交办的需求文档《研发闭环（Feedback → Design → Dev）需求文档 v1.0》
> （PDF，覆盖范围仅「研发闭环.dc.html」这一设计——用户反馈到 PM 设计到工程排期的端到端闭环）。
> 人类原话：「目标是改进反馈提交、需求设计，和后台的反馈/需求管理」。
>
> **与 UC-17.6 的关系**：UC-17.6 + 契约束 `feedback-loop`（已签核，FB-2/FB-3）已把
> **采集弹层 + 后台分诊**做成真栈（`components/feedback/feedback-dialog.tsx`、
> `components/admin/feedback-screen.tsx`、`packages/contracts/src/feedback-loop.ts`）。
> 本 UC 是其**第二轮迭代**：在同一条流水线上补三样东西——
> ① 反馈可以先存**草稿**、由高级用户对话细化后再提交；
> ② 后台由「三 tab 列表」升级成**统一收件箱**（列表 + 看板，四态状态机）；
> ③ 新增 **PM 设计工作台**，反馈可「深化」成设计方案并推回收件箱排期。
> 口径标记：**[需求]** ＝ PDF 明文要求；**[现状]** ＝ 仓内已真栈化的行为，本轮**沿用不重做**；
> **[设计]** ＝ 由前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P1**；估点 **13**（UI 先行阶段不含后端）。

## R1 概览

- **Use Case ID / 名称**：UC-17.8 / 研发闭环（反馈 → 设计 → 排期）
- **Actor**：**普通用户**（任意界面唤起快速反馈，直接提交或存草稿）；
  **PM / 运营（高级用户）**（处理草稿、运营收件箱全部条目、PM 设计工作台）。
  [需求] 当前版本不做登录态区分，所有角色共用同一账号视角；
  [设计] 落地时高级用户 = 现有 `feedback-screen` 的组织管理员视角（`/platform-admin/*`）。
- **目标**：把「用户反馈」和「PM 主动设计」两条路径统一汇入同一条研发流水线，
  并能关联 GitHub Issue/PR 做工程排期。
- **本用例结果**：两条路径的终点都是**同一个运营收件箱数据源**，运营/工程只维护一条流水线。
- **系统边界（In scope）**：
  - 快速反馈弹窗：类型选择、结构化字段表单、长语音填充、最多 5 个文件上传（拖拽/点击）、存草稿/直接提交、「我提过的」。
  - 反馈管理：草稿列表、新建（跳转快速反馈）、编辑/删除（右侧 drawer）、继续完善（AI 对话细化边界）。
  - 运营收件箱：列表 + 看板两种视图、按类型/状态筛选、搜索、看板拖拽换状态、右侧详情 drawer、转「不做」必须填理由、创建 GitHub Issue。
  - PM 设计工作台：三类模板入口（移动端设计 / UI 原型 / 线框图）、项目卡片（编辑/删除）、新建设计弹窗、全屏深色设计详情页（AI 对话 + 原型画布 + 说明与验收标准）、推送到收件箱、推送成功页。
  - 反馈 ↔ 设计方案的双向关联标记（「源自 B-3」/「已生成 D-2」）。
- **不属于本轮（Out of scope）**：真实屏幕截图（Screen Capture API，用文件上传代替）；
  真实语音转写/大模型摘要（[现状] 仓内已有真 ASR + `structureFeedbackDraft`，**沿用**，PDF 的固定模板填充只是原型演示口径）；
  系统异常的权限隔离（仅平台运维可见）；真实原型绘制/组件拖拽编辑器（画布是结构占位块）；
  [需求] PDF 把 GitHub 调用也列为模拟——但 [现状] 仓内 `triageFeedback` 已真建 Issue，**沿用真栈，不退回模拟**。
- **核心数据对象**（PDF §6，字段命名供后端参考）：
  - 反馈草稿 `Draft`：`id, type(bug|req), chat[{role,text}], screenshot(bool), files[{id,name,size}], createdAt, refineSeeded(bool)`
  - 收件箱条目 `InboxItem`：`id, kind(feedback|design|exception), type(bug|req，仅 feedback), code, title, body, reporter, time, votes, status(backlog|doing|done|archived), reason, github{num,state,kind}, linkedFeedback, resolvedByDesign, location/count/users(仅 exception), severe(bool)`
  - 设计项目 `Project`：`id, name, template, emoji, owner, updated, thumbBg, pushed(bool), linkedCode, problem, criteria[], frames[], chat[{role,text}]`
  - GitHub 状态枚举：`open`（绿）/ `draft`（灰）/ `merged`（紫）/ `closed`（红）；`kind` 区分 issue / pr；展示文案统一 `{Issue|PR} #{num} · {State}`。
  - [设计] 与现有契约的对齐：`type(bug|req)` ↔ 现有 `FeedbackKind(缺陷|需求)`；四态 `backlog|doing|done|archived` ↔ 现有
    `FeedbackStatus(待处理|已进入迭代|已修复|不做)`——**同一状态机换了显示名，不是第二套**。[待确认] 系统异常
    （现有 `live-system-errors`）与设计方案并入同一四态时，「已修复」对设计方案的语义是「已交付/已上线」。

## R2 前置条件 / 触发条件

- 前置：请求者是本组织成员；高级用户视角需管理员身份（[设计]）。
- 触发：
  - 用户在任意界面点「快速反馈」（[现状] 左侧图标栏最下方 / <md 顶栏 / chat 内 agent、skill 按钮）。
  - 高级用户打开「反馈管理」处理草稿；打开「运营收件箱」分诊；打开「PM 设计工作台」新建/深化设计。
  - 运营在收件箱对一条反馈点「用 PM 设计工作台深化」。

## R3 主流程

### 路径 A · 用户反馈
1. 快速反馈弹窗 → 选「存为草稿」→ 进入反馈管理草稿列表 → 「继续完善」用对话把边界谈清楚 → 提交到运营收件箱 → 运营处理（开始处理 / 标记完成 / 不做）→ 创建 GitHub Issue → 看板拖拽跟踪状态。
2. 弹窗也可「直接提交」，跳过草稿直接进入运营收件箱（状态 = 待处理）。

### 路径 B · PM 主动设计
1. PM 设计工作台新建设计（选类别 + 填背景）→ 进入设计详情全屏页，用 AI 对话 + 原型画布迭代 → 推送到运营收件箱 → 生成「设计方案」条目，与来源反馈互相打标。
2. 若是从收件箱某条反馈点「用 PM 设计工作台深化」进入，会自动带上下文并建立关联。

## R4 页面详细规格

### R4.1 快速反馈（提交弹窗）
- 唤起：浮层覆盖当前页面，背景暗化，不销毁用户当前页面状态。
- 顶部「这是什么」二选一：⚠ 缺陷 / 💡 需求；切换类型切换下方字段集。
- 结构化内容区始终以表单展示，可直接填，也可点「🎙 长语音描述」：录音中态（红色提示条 + 停止按钮）→ 停止后「AI 整理中」态 → 自动把整理结果填入字段，用户可再编辑。[现状] 录音与整理走真 ASR/结构化接口；原型阶段用固定模板 + 约 0.9s 延迟模拟。
- 字段集：
  | 类型 | 字段（顺序） | 控件 |
  |---|---|---|
  | 缺陷 | 标题 / 复现频率·环境 / 期望结果 / 实际结果 / 复现步骤 | 前四项单行输入，复现步骤多行文本域，AI 填充时是编号步骤 |
  | 需求 | 标题 / 使用场景 / 期望能力 / 优先级·影响范围 | 均为单行输入 |
- 附件区在字段下方：已上传文件以「📄 文件名 大小 ✕」列出；未达上限时显示拖拽/点击上传区；上限 5 个，超过后上传入口自动隐藏。[现状] 现有上限 4 张图片 → 本轮放宽为 5 个文件。
- 底部左侧「更复杂？直接在 PM 设计工作台从头设计 →」链接：直接跳转工作台首页，不经过草稿。
- 底部右侧「存为草稿」（次级）/「直接提交」（主按钮）：标题为空时两个按钮均视觉禁用（opacity 0.45）。
- 「我提过的」Tab：只读列表，仅展示已提交到收件箱的条目及状态（草稿不计入）；弹窗高度在两 Tab 间不变（`min(680px, 88vh)`），内容区各自滚动；无记录时「还没有提交记录。」
- 提交后：「存为草稿」→ 写入草稿列表并跳转反馈管理页；「直接提交」→ 写入收件箱（待处理）并跳转收件箱、自动打开该条详情 drawer。两种提交都清空表单与附件。

### R4.2 反馈管理（草稿）
- 存放所有「存为草稿」条目；导航项右上角徽标显示草稿数。
- 「＋ 新建反馈草稿」不是内嵌表单：跳转到快速反馈弹窗（提交 Tab），复用同一套表单/语音/附件能力——两处入口创建体验完全一致，不重复实现两套 UI。
- 草稿卡片：图标（含附件 📎 / 否则 💬）、类型标签、标题（第一条用户消息首行）、创建时间 · 对话条数 · 附件提示。
- 点卡片任意位置（除按钮）→ 右侧编辑 drawer：可切换类型；正文文本域可直接编辑（会把多轮对话折叠成单条文本，简化处理，见 R11）；含附件时只读列出文件名与大小；底部「删除草稿」（左，红字）/「保存」（次级，只更新文本和类型，不离开）/「继续完善 →」（主）。
- 卡片行内也有「删除」「直接提交」「继续完善 →」，效果与 drawer 一致。
- 继续完善（细化边界）：更大的浮层，左侧固定展示草稿原文（类型、标题、截图占位、原文），右侧「设计协作」对话区：首次打开自动追加一条 AI 澄清问题（「这个需求/问题的边界在哪：只影响当前场景，还是所有相关入口都要一起改？优先级怎么排？」）；用户每次发送追加一条固定回执（「AI：已记录，还有想补充的吗？」，见 R11）。右下角「先关闭」/「准备好，提交到收件箱」；提交后草稿从列表移除并进入收件箱。
- 草稿为空显示「暂无草稿。」

### R4.3 运营收件箱
- 数据源合并三类：用户反馈（缺陷/需求）、系统异常（[现状] `live-system-errors`）、PM 设计方案。
- 视图切换 列表 ☰ / 看板 ▦，**默认看板**。类型筛选 Chip：全部 / 缺陷 / 需求 / 系统异常 / 设计方案，互斥单选。
- 列表视图：表格，列 = 状态 / 标题（含「严重」红标、「源自 X」或「已生成 X」关联标）/ 类型 / GitHub / 数量或时间；下方状态子筛选（全部/待处理/进行中/已完成/不做）+ 搜索框。
- 看板视图：四列固定顺序 待处理 → 进行中 → 已完成 → 不做，每列显示条数；卡片原生 `draggable`，拖到另一列触发状态迁移，悬停列背景轻微变色提示可放置。
- 详情 drawer：点任意行/卡片从右侧滑出（`top: 54px` 贴导航栏下方，`right: 0` 贴右边框，到视口底部），左侧遮罩点击关闭；展示编号、类型标签、状态标签、标题、正文、元信息（系统异常：位置/次数/影响用户；其余：提交人/时间）、GitHub 状态、关联标记、理由（若已不做）、操作按钮、动态时间线。
- 状态机（四态，全类型统一）：
  | 状态 | 含义 | 可用操作 |
  |---|---|---|
  | 待处理 backlog | 刚进入收件箱 | 开始处理（→进行中）/ 创建 GitHub Issue（未关联时）/ 用 PM 设计工作台深化（仅反馈类、未生成方案时）/ 不做…（需理由） |
  | 进行中 doing | 已排期或开发中 | 标记已修复（→已完成）/ 退回待处理 / 不做… |
  | 已完成 done | 已上线/已修复 | 重新打开（→待处理） |
  | 不做 archived | 决定不处理，必须有理由 | 重新打开（→待处理） |
- 转「不做」强制校验：点「不做…」不立即变更，展开理由文本域，「确认不做」在理由为空时置灰；确认后状态变为不做并把理由写入时间线。[现状] 与 `feedback-loop` 的 `TRIAGE_REASON_REQUIRED` 同一条规则。
- GitHub 联动：展示「Issue/PR 状态 + 链接文案」如 `Issue #142 · Open`、`PR #145 · Draft`、`PR #130 · Merged`。[现状] 真栈已建 Issue / 拉 linked PR；原型阶段随机编号模拟。
- 反馈 ↔ 设计方案关联：反馈已生成方案 → 标题旁「已生成 D-2」；设计方案来自反馈 → 「源自 B-3」。只读文本标记（可点击跳转留到 R12）。

### R4.4 PM 设计工作台
- 首页：标题下三张快捷入口卡（移动端设计 / UI 原型 / 线框图），点任一 = 打开「新建设计」弹窗并预选该类别。「我的设计项目」区块：「＋ 新建设计」（默认预选第一个类别）+ 搜索框（按名称过滤）。
- 项目卡片网格（3 列）：缩略图标 + 名称 + 类别·更新时间、关联反馈标记（若有）、推送状态标签（✓ 已推送 绿 / 未推送 橙）、右下角「编辑」「删除」。点卡片主体进入设计详情全屏页。空态「还没有设计项目。」
- 新建设计弹窗：类别单选、名称（必填，为空时创建按钮置灰）、背景/上下文文本域（可选）。点「创建并进入设计」：① 关闭弹窗，约 1.1s「生成中」过渡（旋转指示器 + 骨架卡，文案「正在把「XX」整理成设计稿…」）；② 自动创建项目（默认 3 个画布页：草稿页 1/2/3）并进入详情全屏页。「编辑」复用同一弹窗，标题「编辑设计」，保存只更新名称/类别/背景，不触发过渡、不跳转。
- 设计详情全屏页（Claude Code 风格深色 IDE）：顶部条：返回工作台、面包屑（工作台 / 项目名）、关联反馈标记、推送状态按钮，无关闭按钮。左侧固定 360px 对话面板（每个项目独立对话历史；无历史时一条默认引导语；发送后追加用户消息 + 固定回执「好的，我记下了这个调整，稍后会更新原型画布。」）。右侧「原型画布 / 说明与验收标准」两 Tab：画布 Tab 下是画布页横向标签条 + 居中模拟手机画布（头部/主内容区/操作区/提示信息占位块）；说明 Tab 展示「问题与目标」（新建时的背景）与「验收标准」（固定三条：明确问题与目标范围 / 给出交互方案与边界情况处理 / 列出验收标准供工程对齐），若关联反馈显示反馈编号。底部深蓝状态条：模型名 · 设计系统名 · 当前类别 · 所有者/更新时间（纯展示）。
- 「推送到收件箱」/「已推送到收件箱」：打开推送确认弹窗（可填给工程的说明），确认后：项目标记已推送，生成一条「设计方案」收件箱条目（待处理），若项目来自某条反馈深化则原反馈标「已生成 D-X」；随后展示推送成功页（大号 ✓ + 方案编号/标题/关联反馈 + 后续流程说明 + 「继续设计下一个」/「查看收件箱」两个出口）。
- 从收件箱深化：详情 drawer 中反馈类条目在待处理/进行中且未生成方案时出现「用 PM 设计工作台深化」；点击自动新建设计项目（名称=反馈标题，问题描述=反馈正文，类别默认「线框图」）并跳转工作台首页。

## R5 角色与权限
- 普通用户：快速反馈（提交/存草稿）、「我提过的」。
- PM / 运营：反馈管理、运营收件箱、PM 设计工作台。[现状] 落在 `/platform-admin/*` 组织管理员视角。
- [待确认] 系统异常是否恢复「仅平台运维可见」（PDF 列为后续迭代）。

## R6 数据与状态
- 见 R1 核心数据对象。草稿是**客户端/用户私有**的中间态，不进收件箱计数；收件箱条目是三类来源的统一投影。
- [设计] 设计项目的 `chat[]` 与草稿的 `chat[]` 都是原型演示用固定回执；真栈化时应接 deep-agent-service。

## R7 异常与边界
- 标题为空 → 提交/存草稿视觉禁用。附件超过 5 个 → 上传入口隐藏。不做无理由 → 确认按钮禁用。
- 直接提交失败 → [现状] 弹层明说「这条反馈没有被保存」，不切标签页（UC-F1 V3 继续有效）。

## R8 界面线索（供 ui-prototyper）
- 四块屏：快速反馈弹窗（改）、反馈管理草稿（新）、运营收件箱（改，列表 + 看板 + drawer）、PM 设计工作台（新：首页 / 新建弹窗 / 生成中过渡 / 详情全屏页 / 推送确认 / 推送成功页）。
- 原型确认缺失：草稿列表、编辑 drawer、继续完善浮层、看板、详情 drawer（贴边）、设计工作台全部。
- 原型待补：现有弹窗只有标题/正文 → 补结构化字段集、存草稿、5 文件上传、工作台链接。
- 现有后台 `feedback-screen` 是三 tab + 左右两列 → 收件箱统一四态看板；[待确认] 是替换还是并存。

## R9 非功能

## R10 验收标准 Checklist（PDF §8 逐字）
