## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-16.1 / 构造数字专家（原型子标签 **`专家设定`**）
- **Actor**：**研究员**、**引导师**
- **目标**：[Backlog] 在约不到真人时，用已入库材料构造的数字专家做预演；
  虚拟来源永远单独计数，不能冒充真人洞察。
- **本用例结果**：研究项目下存在 N 个数字专家（原型示例：**5 个**），
  每个都能展开它**由哪些材料构成**（原型：「由 12 场真人访谈构造」），
  且带**探索性**强标记；它们与真人访谈**同列表混排**。
- **系统边界**：数字专家的创建与材料集绑定、知识边界声明、试问校验（是否会编）、
  **强标记与混排展示**、**虚拟身份的服务端标识**（供 UC-16.2 的强制约束读取）。
- **不属于本 UC 的边界**：单条推演的输出结构与四出口（UC-16.2）、
  与真人的对照与分歧（UC-16.3）、访谈模板（UC-16.4）。
- **核心数据对象**：数字专家、**材料集**（真人访谈场次 / 洞察库 / 转写 / 组织层条目）、
  **知识边界声明**、构造来源计数（如「12 场」）、探索性标记、试问记录。
- **[设计 · 架构对齐] 材料集只能通过 Context API 声明与取用**：
  「材料范围」是一份 **QueryContext 的约束**（`projectIds` / `allowedSensitivity` /
  `timeRange` / `evidencePolicy`），实际取材走 **Context Pack**；
  **不得**把材料集实现为一次性导出的文本块或直查 `segments` 的自定义 SQL——
  那样会绕过权限传播与撤回级联，撤回一份材料后数字专家仍会记得它。
- **[设计 · 架构对齐] 数字专家本身是 `synthesized` 的产出方**：
  其一切输出（试问回答、推演）**必须带 `synthesized` 标记**并可由
  Context Pack 的 `items[].sourceType` 区分（完整规则见 **UC-16.2 R7**）。
- **[设计 · 架构对齐] 材料被撤回时数字专家必须同步失效**：
  按 UC-17.2 的级联失效，构成材料集的 Segment 被撤回后，
  该数字专家**必须重新构造或标为「材料已变更 · 待复核」**，
  不得继续使用已撤回材料形成的知识边界。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“组织大脑、访谈、上传 Agent”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [Backlog] 研究员需要预演一场访谈。
  - 系统从 **数字专家** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **研究员操作**：在 `虚拟` / `专家推演` → **`专家设定`** 下新建一个数字专家，
   选定**材料范围**（[待确认] 可选材料类型枚举——`专家设定` 子标签内部**未探明**，
   不得据「由 12 场真人访谈构造」一句反推出完整枚举）。
   **系统响应**：校验身份与材料可见性；**记录构造来源计数**，界面固定呈现
   [原型]「**由 N 场真人访谈构造**」。
   [待确认] 材料选择界面的具体控件与可选材料类型枚举（`专家设定` 子标签内部未探明）。
2. **研究员操作**：标明它的**知识边界**与「不知道什么」。**系统响应**：把边界声明持久化，
   并作为 UC-16.2 推演时**「不确定」字段**的判定输入之一。
   [待确认] 知识边界的表达形式（自由文本 / 结构化维度）——`专家设定` 内部未探明。
3. **研究员操作**：**试问几个问题看是否会编**。**系统响应**：按 UC-16.2 的输出结构返回，
   研究员据此判断该专家是否可用；试问记录留存。
4. **系统处理（强标记与混排，D-25）**：[原型] 数字专家在**访谈列表中与真人访谈同列表混排**，
   并携带**强标记**：类型「**数字人**」、构造来源「**由 12 场真人访谈构造**」、
   性质「**标为探索性**」；列表动作为 `[打开访谈]` `[再跑一轮]`。
5. **系统处理（服务端标识，D-25 后半）**：为该专家及其一切产物打上**虚拟来源标识**，
   该标识是 R7「虚拟结论不进决策依据」在服务端强制的**唯一依据**，
   **不可被前端覆盖、不可被人工去除**。
6. **系统处理（计数隔离）**：[原型] 数字专家**不占用访谈场次计数**——
   访谈总数、场次统计、洞察来源分布中虚拟与真人**分开计数**。
7. **系统收口**：校验 AC1「每个数字专家都能看到它由哪些材料构成」与
   AC2「虚拟来源标识在服务端存在且不可移除」；记录操作者、时间、对象、结果与来源。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] 目标数据为空时展示空状态、原因和下一步入口，不生成示例数据冒充真实结果。系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
  - A2：[原型] **再跑一轮**——`[再跑一轮]` 在**同一专家、同一材料集**上重新推演；
    新一轮不覆盖旧轮次，两轮可对比（轮次号如「3 轮压力提问」）。
  - A3：[设计] **材料集变化后**，已有推演结果标为「基于旧材料集」，
    不自动重跑也不静默失效。
- **异常流程**：
  - E1：[Backlog] 材料不足时拒绝构造，而不是编一个。失败不得被呈现为成功，也不得产生无法追溯的半成品。
    [待确认] 「材料不足」的判定阈值（最少场次数 / 最少引述条数）——需产品与研究方法负责人给出。
  - E1b：[设计] 材料中含**拒绝 AI 分析**的受访者内容时（[原型] 受访者授权四项之一），
    该部分**必须排除在材料集之外**；若排除后材料不足，按 E1 拒绝构造。
  - E1c：[设计] 材料中的内容**被撤回**时（UC-17.2），相关片段立即退出该专家的材料集，
    已有推演结果中引用它的部分标为「证据已撤回」。
  - E2：[原型] 数字专家的回答必须能追到材料段落。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E4：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E5：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

- **研究员**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **引导师**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **观察者**：默认不能发起或修改；仅当内容已发布且授权范围允许时只读查看脱敏结果。
- **项目经理**：可查看项目级状态与审计摘要；是否可代替业务 Actor 执行写操作需由角色模板显式授权。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。

- **正常后置条件**：
  - 形成与本 use case 对应的正式记录或明确状态，并可从来源页面再次打开。
  - 所有跨模块回流均携带来源资源、版本、操作者/触发者、时间和可见范围。
  - [原型验收] AC1a：每个数字专家都显示**构造来源计数**（原型：「由 12 场真人访谈构造」）。
  - [设计验收] AC1b：该计数**可下钻到具体场次/条目**——原型未渲染下钻，属新增设计。
  - [裁决验收] AC2（**D-25**）：虚拟来源标识在**服务端**存在且**不可移除**；
    列表中数字人与真人**同列表混排**且携带三项强标记（数字人 / 由 N 场构造 / 探索性）。
  - [原型验收] AC3a：数字专家**不占用访谈场次计数**（范围硬约束原文）。
  - [Backlog验收] AC3b：虚拟与真人在各处统计中分开计数（原型未渲染来源分布统计）。
- **失败后置条件**：
  - 不创建“看似成功”的正式记录；可重试内容保留为草稿，失败事件进入可观测日志。
  - 材料不足时**不产生一个可用的数字专家**，而不是产生一个「弱版本」。
- **不包含**（**范围硬约束 · 原型原文：只需要问题与文字推演**）：
  - **不模拟对话过程** —— 没有多轮拟人对话、没有「现场感」的逐句往返。
  - **不生成语音** —— 无 TTS、无音频产物。
  - **不占用访谈场次计数** —— 不进入访谈排期、不生成访谈日程、不需要受访者授权流程。
  - 虚拟结论冒充真人洞察、材料不足时编造人格。
  - **单条推演的输出结构与四出口**（UC-16.2）、**与真人的对照与分歧**（UC-16.3）、
    **访谈模板反向沉淀**（UC-16.4）。
  - 不扩展到本 use case 未声明的跨组织、跨客户或公开发布能力。

## R7 业务规则（不随具体实现变化的硬性约束）

- [Backlog] 材料不足时拒绝构造，而不是编一个。
- [原型] 数字专家的回答必须能追到材料段落
  （引用格式见 UC-16.2：「访谈 10 · Weber 00:31:22『我们法务只认合同』／
  组织层：审批中位数 11 个月」）。
- **[原型 · 范围硬约束]** 「只需要问题与文字推演。
  **不模拟对话过程、不生成语音，也不占用访谈场次计数。**」
- **[裁决 D-25 · 两条，缺一不可]**
  - **① 混排 + 强标记（展示层）**：数字专家与真人访谈**在同一列表中混排**，
    并强制携带「数字人」「由 N 场真人访谈构造」「标为探索性」三项标记。
  - **② 服务端强制（数据层）**：「**虚拟结论不能作为强洞察、不进决策依据**」
    必须由**服务端**拒绝，**不只是视觉标记**——
    虚拟来源标识不可被前端覆盖、不可被人工去除；
    任何把虚拟产物写入强洞察、决策依据、组织层晋升候选的请求**一律拒绝并记安全审计**。
- [设计] **拒绝 AI 分析的受访者内容不得进入材料集**（受访者四项同意之一，见 UC-6.3 / UC-17.2）。
- [设计] **材料集变化不追溯已有推演**：旧结果标为「基于旧材料集」，不静默失效也不自动重跑。
- AC1：每个数字专家都能看到它由哪些材料构成。
- AC2：虚拟来源标识服务端存在且不可移除；列表混排 + 三项强标记。
- AC3：不占用访谈场次计数。
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- AI/Agent 的写回、覆盖、发布或高影响工具调用必须遵守原型中的批准点；未经确认只保留为草稿或候选。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态）：AC1 —— 打开任一数字专家，断言返回其**构造来源计数**（如 12 场）
  且可下钻到具体场次清单；每个引用都能追到材料段落。
- V1b（成功态 · **D-25 展示层**）：请求访谈列表，断言数字人条目与真人条目**在同一列表中返回**，
  且数字人条目携带三项标记字段（`is_virtual` / `built_from_count` / `exploratory`），
  界面在类型列、描述行、状态列三处呈现。
- V1c（成功态 · **D-25 服务端层**）：AC2 —— 取一条数字专家产物，逐一尝试
  ① 标为强洞察 ② 作为决策依据引用（UC-14.4）③ 提名进组织层晋升队列（UC-14.5），
  断言**三者全部被服务端拒绝**并各留一条安全审计；
  再尝试通过接口置空/篡改 `is_virtual` 字段，断言被拒。
- V1d（成功态）：AC3 —— 创建一个数字专家后，断言访谈**场次计数未增加**，
  且洞察来源分布中虚拟与真人分开统计。
- V1e（校验失败态）：材料集中只含被标「拒绝 AI 分析」的受访者内容时，
  断言构造被拒绝（E1/E1b），且未产生任何数字专家记录。
- V2（权限态）：逐一使用 研究员、引导师、观察者、项目负责人、未授权用户访问；
  返回数据和可执行动作严格符合 R5。
- V3（空态）：无目标数据时显示真实空态与下一步，不生成伪数据。
- V4（依赖失败）：模拟网络/外部依赖失败，输入和最近成功数据保留，错误可解释且可重试。
- V5（并发态）：两名用户修改同一资源时不静默覆盖，并可识别最终版本。
- V6（审计态）：关键动作可按操作者、时间、对象和结果检索；越权尝试也有安全审计记录。
