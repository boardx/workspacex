## 一、本阶段目标与为什么是这个顺序

**一句话**：让一场项目的成果**跨项目复用**，并让整套系统**经得起审计**——
组织大脑与知识晋升、客户只读门户、数字专家虚拟推演、审计合规与数据治理。

**为什么排最后**：本阶段的三件事都需要「**已经有多个项目的真实产出**」作为输入。
- 组织大脑的 Claim 聚合、去重、冲突并存，在只有一个项目时无从验证。
- 知识晋升的**严格准入**（D-32：支撑过一个被签字的决策 + 复盘中被验证）
  依赖 phase-02 的签署与验收链路已经跑通。
- 客户门户与数字专家是**对外面**，必须在内部数据模型与权限稳定之后才能开放。

**唯一的例外**：`17-gov` 的一部分**不能等到最后**——
D-13 已把 `UC-17.2` 的最小切片（待删除队列 + 退出检索 + 报告段落标失效 + 回执）
**前置进 phase-1**，因为「删除能演示」是 file-first 的验收前提。
这也是本阶段 `uc-17-2` 已从 8 点降为 **3 点**的原因。

**阶段内顺序**：**治理先行 → 跨项目复用 → 对外与预演**。
先把审计、撤回、留存、管理员边界立住，再谈把知识拿出来用，最后才把界面开给客户与虚拟角色。

## 四、口径说明（给 requirement-author 的读法约定）

### 4.1 四标记

| 标记 | 含义 | 生成 feature 时怎么处理 |
|---|---|---|
| `[原型]` | `WorkspaceX Standalone.html` **运行态实际存在**的行为，有界面可查（`proto-02` 大脑 7 子标签 / `proto-03` 后台 9 子模块密度最高） | 可直接落 `user_visible_behavior` |
| `[Backlog]` | `Backlog Use Case.html` 的**文档要求**，原型未必实现 | 可落 feature，UI 部分**须先补画**；`verification` 只写 API / 逻辑断言 |
| `[设计]` | 依据前两者反推补全，**需人类确认** | 落 feature 时标注待确认；`has_ui` 阶段进不了 `new-sprint` |
| `[待确认]` | 不应由实现者决定（阈值 / 权限边界 / 合规口径） | **不得自行取默认值**。查 `DECISIONS-OPEN.md` 对应 O-nn；本阶段有多条属 ⚪ 信息缺口（O-38/39/40），**必须挂阻塞** |

### 4.2 缺失三态（成本差一个数量级，务必区分）

| 状态 | 含义 | 补齐方式与成本 | 本阶段典型 |
|---|---|---|---|
| **未探明** | 原型档案**尚未点进那个屏** | **补抽取**。低成本，**不占人类裁决名额**（`DECISIONS-OPEN.md` 附录 B） | 数字专家 `专家设定` 子标签内部（材料类型枚举 / 知识边界表达形式 / 试问界面）、`采纳与标注` 子标签内部（`uc-16-1`、`uc-16-3`） |
| **原型待补** | 主屏存在，但**按钮已渲染、目标屏未见**（行为未接线），或下钻层缺失 | **补接线 / 局部补画**。中等成本 | `uc-14-5` 的 `[我来审]` `[去合并]` `[派 Scout 复核]` 三个按钮已渲染、目标屏均未见 |
| **原型确认缺失** | **枚举完毕后确认不存在** | **补画整屏 + 产品/设计确认**。高成本，**卡 `ui-signoff`** | `15-portal` 客户门户（D-22 已裁定 **A：补画原型后进 phase-3**） |

> **硬规则**（`DECISIONS-FINAL.md` 通用规则第 2 条）：**不得把「未探明」写成「原型没做」**。
> ⚠ 本阶段是**三态判定最容易出错的阶段**：`14-brain` 与 `17-gov` 的原型密度很高
> （大脑 7 子标签、后台 9 子模块均已抽取），**两模块 UC 中「原型确认缺失」为 0**——
> 它们的缺口全是「待补」（按钮无目标屏）与「未探明」。把这些写成「确认缺失」会
> 凭空制造大量补画工作量，并把本阶段的 sign-off 风险严重高估。

### 4.3 本阶段必须遵守的口径

- **D-32 知识晋升严格准入**：支撑过**一个被签字的决策** + **复盘中被验证**，才够格晋升。两个条件都是硬门槛。
- **D-33 过期知识**：转「**待复核**」态，**仍在检索范围内**，引用时提示已过期；
  但**不参与定题强度计算**。（三件事，缺一不可。）
- **D-25 数字专家**：与真人访谈**同列表混排 + 强标记**；但「虚拟结论不能作为强洞察、
  不进决策依据」必须**服务端强制**，不只是视觉标记。
- **D-16 脱敏两级**：组织层内用**可逆映射 + 权限门控**（支持审计回溯）；
  跨组织输出时做**不可逆聚合**，需定义最小聚合样本量（对照 phase-02 `uc-12-3` 的「样本 <8 标不可推断」）。
- **D-17 「出域」= 出组织**（第三方 API）；phase-1 只做闭源/自托管二分。
  「**出法域**」（数据驻留路由）**列入本阶段的 17-gov**。
- **D-15 撤回两级 SLA**：逻辑失效即时（**≤5 分钟**）；物理删除 **≤30 天**并出回执。**「24 小时」已废弃**。
- **D-18 管理员权力边界**：个人层只见计数；项目层可读但每次访问**写审计日志且对项目负责人可见**。
- **D-40 保留意见**：对客户可见，**去署名**（`15-portal` 的直接约束）。
- **D-03a 三字段消歧**：本阶段基本不引用 `agenda_segment` / `design_facet` / `method_stage`；
  若在 `14-brain` 的方法沉淀中出现，须按对应基数选正确字段名。

### 5.3 `verification` 优先级（D-35：A + B 并行）

```
① round-trip / 纯函数断言        ← 最优先
② API 断言（含 SQL / RLS 断言）
```

  但**前提是 phase-02 已按 `data-testid` 规范给这两个元素命名**。
  更强的断言是 Context Pack **重放**（同一 run id 重放得到同一 `items[]`，纯函数级），

  断言 API 返回拒绝。**不要只断言页面上有标记。**
- **`uc-17-2` 撤回 SLA**：把时钟推进 → 断言逻辑失效 ≤5 分钟、物理删除 ≤30 天出回执（API + 定时任务断言）。

  （`FORCE ROW LEVEL SECURITY`；用 owner 连接会静默旁路 RLS，测试假通过）。

> ⚠ **原型零 `data-testid`**。UI 断言在 `uiux-standards` 的 `data-testid` 命名规范落地前
> **写不出稳定选择器**。本阶段对 phase-02 的 testid 有**跨阶段依赖**（见上文 `uc-14-6`），
