> 所属：阶段三 · 跨项目与对外 / M14 组织大脑

> **横向复用**的原型依据为 `大脑 → 三层关系总览` 的「另外两条流动：**横向复用 · 项目→项目**：

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-14.2 / 跨项目调用
- **Actor**：**方法负责人**、**引导师**、**项目经理**
- **目标**：[Backlog] 把一场项目的结论沉淀成跨项目可复用的知识：下一次做同类项目时，能直接调出上次的判断与教训。
- **本用例结果**：[Backlog] 用户通过“跨项目调用”完成从“新项目筹备或现场检索”到可追踪业务结果的闭环。
- **系统边界**：组织知识分层、写回队列、去重冲突、跨项目检索与方法教训。
- **核心数据对象**：**[设计 · 架构对齐]** 「组织知识节点」＝ `claims`、
  「项目来源」＝ `claim_evidence` → `segments` → `artifact_versions`（不可变版本）、
  「过期策略」＝ `valid_from` / `valid_to`、「冲突组」＝ `status = contested`
  （字段定义与五态↔`status` 对应表见 **UC-14.5 R1 / R10**，本 UC 不另建状态字段）；
  复用引用、方法教训。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“知识图谱、成果沉淀（写回来源）”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [Backlog] 新项目筹备或现场检索。
  - 系统从 **研究 / 对话** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **方法负责人操作**：按场景与行业检索过往结论，带项目出处与时间。**系统响应**：校验当前身份、项目范围、必填数据与资源版本；成功后更新界面和业务记录，并保留可追溯来源。
2. **方法负责人操作（自然语言提问）**：[原型] 直接用一句话提问
   （示例：「我们以前在欧洲做过资质相关的尽调吗？」）。**系统响应**：返回**带来源的回答**——
   [原型] 命中项**按相关度排序**、**全部可溯源到原始材料**，每条至少显示：
   相关度、条目名与状态（生效 / 待复核）、**适用范围**、**有效期剩余**、**被 N 个决策引用**，
   并提供 `[引入当前项目]`；检索过程的可审查性由 **UC-14.6** 承接。
3. **方法负责人操作（纵向调用）**：可直接引用为会前洞察，标明是复用的。**系统响应**：校验当前身份、项目范围、必填数据与资源版本；成功后更新界面和业务记录，并保留可追溯来源。
4. **方法负责人操作（横向复用 · 项目→项目）**：[原型] 从**另一个项目**直接借用一条尚未晋升的结论，
   **不经组织层**。**系统响应**：允许借用，但**必须给该引用打「未沉淀」标**，
   并在引用处显示**源项目名与时间**；[原型] 系统统计横向复用次数（原型：「本月 9 次」）。
   借用**不改变源条目的状态**，也**不构成晋升**（晋升仍须走 UC-14.5 的 D-32 准入）。
5. **方法负责人操作**：过期知识（超过设定时限）自动标灰。**系统响应**：[裁决 D-33]
   过期条目转「待复核」，**仍出现在检索结果中**并标「可能已过期」，
   但**不参与定题强度计算**；校验当前身份、项目范围、必填数据与资源版本后更新记录。
6. **系统收口**：校验 AC1“复用的结论在新项目里能看出来自哪个项目”与
   AC2「横向复用的引用必须带『未沉淀』标」；满足后记录操作者、时间、对象、结果与来源，
   并刷新相关列表、图谱、看板或通知状态。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[Backlog] 跨客户复用要检查授权范围，未授权只出脱敏聚合。系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
  - A2：[原型] **横向复用后补沉淀**——「未沉淀」的引用可随时提名进晋升队列（UC-14.5）；
    晋升成功后该引用的「未沉淀」标自动摘除并改为指向组织层条目。
  - A3：[原型] **自然语言提问零命中/弱命中**——返回「组织层没有直接答案」并给出
    大脑自省的三类线索（冲突 / 过期 / **缺口**，原型示例「波兰无一手材料，
    建议先做桌面研究」），**不得用弱命中拼凑一个像样的答案**。
  - A4：[原型] **引入当前项目**——`[引入当前项目]` 把命中条目挂进当前项目的图谱，
    保留指向组织层的引用关系（不复制内容），源条目状态变化时引用侧同步。
- **异常流程**：
  - E0：[设计] 横向复用时**源项目对当前用户不可见** → 拒绝借用并说明是项目层限制；
    **不得以「组织层没有」为由绕过项目隔离**。
  - E1：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

- **方法负责人**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **引导师**（项目角色）：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **项目负责人**（组织角色；原文档写作「项目经理」，按 `uc-0-3` 正名）：
  可在被授权范围内参与流程并查看与自身角色相关的结果。
- **横向复用的额外约束**：借用方必须**同时**对源项目与目标项目持有项目角色；
  组织角色（含管理员）**不因组织身份获得跨项目借用权**（`uc-0-3` AC1）。
- **观察者**：默认不能发起或修改；仅当内容已发布且授权范围允许时只读查看脱敏结果。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。

## R7 业务规则（不随具体实现变化的硬性约束）

- [Backlog] 跨客户复用要检查授权范围，未授权只出脱敏聚合；
  **跨组织输出必须是不可逆聚合并满足最小聚合样本量**（D-16，规则详见 UC-14.5 R7）。
- [原型] **横向复用允许但必须显标「未沉淀」**：项目→项目直接借用不经组织层，
  引用处必须同时显示源项目与「未沉淀」标；**不得把横向复用呈现得与组织层引用等同**。
- [设计] **横向复用不改变源条目状态、不构成晋升**；也**不绕过项目隔离**——
  借用方须对源项目持有项目角色。
- [原型] **自然语言提问必须带来源**：回答中的每一条结论都可溯源到原始材料；
  无来源支撑的内容不得输出（对照 UC-14.6 的「未挂来源标灰」）。
- **[设计 · 架构对齐] 跨项目检索只能经 Context API 取 Context Pack**：
  自然语言提问、纵向调用、横向复用三条路径**一律不得直查** `claims` / `segments` / 向量表。
  命中项的「相关度」＝ `items[].score`，「为什么召回」＝ `retrievalReasons`，
  「为什么这条能给你看」＝ `permissionDecisionId`，未命中的须可从 `omissions` 复核。
- **[设计 · 架构对齐] 检索是 query-planned hybrid，不是 graph-first**：
  「按场景与行业检索过往结论」这类查询必须同时走
  **PostgreSQL FTS（一等通道）**、pgvector、图关系、元数据、Claim 五路并行召回后融合。
  ⚠ 只走图会让**刚上传、尚未完成实体链接的新材料直接漏召回**——
  而「新项目筹备时找到上个项目刚沉淀的东西」正是本 UC 的核心场景。
- **[设计 · 架构对齐] 跨项目权限在 SQL/RLS 层强制**：
  横向复用的「借用方须对源项目持有项目角色」不是应用层 if，是 RLS 策略；
  ⚠ 应用连接**不得使用表 owner 身份**（PG 中表 owner 默认不受 RLS 约束）。
- **[已裁决 O-16] 跨组织输出的两个数**：最小聚合样本量 **8**（低于即拒绝输出）；
  普遍性断言的强证据下限 **独立受访者 5 人**；计数口径 **独立受访者人数**（详见 UC-14.5 R7）。
- [裁决 D-33] 过期知识转「待复核」后**仍可被检索到并被引用**，引用时必须提示已过期，
  但**不参与定题强度计算**。
- AC1：复用的结论在新项目里能看出来自哪个项目。
- AC2：横向复用的引用带「未沉淀」标。
- AC3：自然语言提问的回答全部可溯源。

- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态）：AC1：复用的结论在新项目里能看出来自哪个项目。
- V1b（成功态）：AC2 —— 从项目 A 横向借用一条**未晋升**的结论到项目 B，断言：
  ① 引用类型为「未沉淀」且携带源项目标识；② 源条目状态未变、未进入晋升队列；
  ③ 横向复用计数 +1；④ 借用方对项目 A 无项目角色时借用被拒且原因标明为项目层限制。
- V1c（成功态）：AC3 —— 自然语言提问返回的每条命中都含可点击的原始材料链接，
  且字段完整（相关度 / 状态 / 适用范围 / 有效期剩余 / 被引用决策数）；
  零命中时返回「组织层没有直接答案」+ 缺口提示，回答中不含无来源内容。
- V1d（成功态 · D-33）：把一条命中条目置为过期，断言它仍在结果中、带过期提示、
  且定题强度计算结果不含它。
- V2（权限态）：逐一使用 方法负责人、引导师、项目负责人、观察者、未授权用户访问；返回数据和可执行动作严格符合 R5。
- V3（空态）：无目标数据时显示真实空态与下一步，不生成伪数据。
- V4（依赖失败）：模拟网络/外部依赖失败，输入和最近成功数据保留，错误可解释且可重试。
- V5（并发态）：两名用户修改同一资源时不静默覆盖，并可识别最终版本。
- V6（审计态）：关键动作可按操作者、时间、对象和结果检索；越权尝试也有安全审计记录。
