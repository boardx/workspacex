# 原始需求（细化）— UC-14.6 检索可审查

> 所属：阶段三 · 跨项目与对外 / M14 组织大脑
> 来源：原型 `大脑 → AI 读到了什么` 子标签（「这次回答检索了哪些片段、注入到系统提示的哪一段」、
> 五种筛选动作、被丢弃的低相关 14 条、上下文预算 14.9k/120k、装配后的系统提示四段注入）；
> **验收锚点**取自 `项目 → 成果沉淀 → 洞察报告 → 报告工作台`（「**每句都会挂来源，
> 未挂来源的标灰**」＋ 每节的**来源角标**）。
> **补写缘由**：原 M14 三份 UC 把「跨项目调用」写成一次检索动作，
> **没有任何关于「检索过程本身可被审查」的需求**。而原型把它做成了组织大脑的信任基础：
> 召回了什么、降权了什么、排除了什么、丢弃了什么，全部要能翻出来。本 UC 是 D-24 MVP 三件之第三件。

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **13**；建议迭代 **阶段三 · 迭代 11 · 跨项目复用**。
>
> **[裁决 D-24]** 「检索可审查」的**验收锚点用报告工作台的「来源角标 + 未挂来源标灰」**
> （真实 UI，可写成可执行 verification），**不要只锚在抽象的「AI 读到了什么」屏**。
>
> **[设计 · 架构对齐] 本 UC ＝ Context Pack 的可审查面**
> （见 `docs/architecture/context-engine.md` 第四节）。对应关系是**一一对应，不是类比**：
> - 「五种筛选动作」（召回 / 降权 / 排除 / 成对 / 线索）＝ **`items[].retrievalReasons` 的取值域**；
> - 「被丢弃的低相关 N 条」＋「超预算被裁剪的片段」＝ **`omissions`**；
> - 「为什么这条能给你看」＝ **`items[].permissionDecisionId`**；
> - 「装配后的系统提示只读快照」＋检索会话 ＝ **`context_packs` 表的一行**；
> - 冲突成对注入 ＝ `claims[].supportingSegmentIds` / `contradictingSegmentIds`。
>
> **[设计 · 架构对齐] 检索策略 ＝ query-planned hybrid，不是 graph-first。**
> 架构已**推翻**「graph-first, vector-second」——它对刚上传、尚未完成实体链接的新材料**会直接漏召回**。
> **PostgreSQL FTS 是一等检索通道**（精确原话 / 编号 / 姓名 / 术语，图与向量都不擅长）。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-14.6 / 检索可审查
- **Actor**：**任何调用 AI 的人**（引导师 / 研究员 / 项目负责人）、**方法负责人**（调权重）、
  **合规负责人**（审查注入内容）。
- **目标**：[原型] 让一次 AI 回答的**取材过程可被完整还原**——组织层这次是怎么被筛的、
  哪些被降权、哪些被排除、哪些被丢弃、最终装配成什么样的系统提示——
  并让下游产物（报告、结论）**每一句都能看到它挂的来源**。
- **本用例结果**：任一次 AI 调用都留下可只读审查的检索记录与装配后的系统提示；
  报告工作台里每一节都显示来源角标，**未挂来源的内容显式标灰**。
- **系统边界**：检索召回与五种筛选动作、被丢弃片段的可审查、反对证据强制保留、
  上下文预算、系统提示装配与只读审查、来源角标与未挂来源标灰、三个出口动作。
- **核心数据对象**：**[设计 · 架构对齐] 「检索会话」＝ `context_packs` 表的一行**，
  其内容即一份 **Context Pack**：
  - `items[]` —— 候选片段（`segmentId` / `content` / `sourceType` / `artifactVersionId` /
    `anchor`{页码·bbox·时间码·messageId·surveyQuestionId} / **`retrievalReasons`** /
    `score` / **`permissionDecisionId`**）；
  - `claims[]` —— 注入的组织层结论（`statement` / `status` / `supportingSegmentIds` /
    `contradictingSegmentIds`），`status` 取值见 **UC-14.5 R10 的五态↔status 对应表**；
  - **`omissions[]`** —— 丢弃集 + 超预算裁剪集，**这就是「被丢弃必须可审查」的载体**；
  - `query` —— QueryContext（含 `tenantId` / `principalId` / `projectIds` / `task` /
    `allowedSensitivity` / `tokenBudget` / `evidencePolicy`）。

  其余对象：筛选动作记录、上下文预算、系统提示快照、来源引用、报告节的来源角标。
  **硬约束：不得在 Context Pack 之外另建一套「检索记录」表**——
  「AI 读到了什么」审查的就是 `context_packs` 这一行，两者是同一份数据。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 调用者对目标项目有项目角色；被检索的组织层条目处于 **生效** 或 **待复核** 态（UC-14.5）。
  - 组织层与项目图谱可用；不可用时必须显式降级并在界面说明，**不得静默用空上下文回答**。
- **触发条件**：
  - [原型] 任一次会带上下文的 AI 调用（对话、报告生成、研究、画布起草、访谈副驾驶）。
  - [原型] 用户点开 `大脑 → AI 读到了什么`，或在报告工作台点某节的来源角标。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **系统处理（召回）**：[原型] 从**组织大脑 · 项目图谱 · 当前转录**三个来源取候选。
   组织层**只取「生效」与「待复核」两态**（UC-14.5 定义）；命中数与命中条目可列出，
   其中已过期的条目**在提示里打标**。
2. **系统处理（五种筛选动作，逐条记录且可回看）**：
   - **召回**：只取生效 + 待复核；[裁决 D-33] 待复核条目**仍进候选**，但**不参与定题强度计算**。
   - **降权**：[原型] 适用范围不匹配的条目（如「波兰不在范围内」）**不排除**，
     标为「**跨范围引用**」后降权**保留**。
   - **排除**：[原型] **已撤销**条目**永久排除**；但它的**反例文本作为「教训」另行召回**。
   - **成对**：[原型] 冲突事实的两条**同时注入**证据段，**引擎不替人选**，由人裁决。
   - **线索**：[原型] 图谱路径**只给固定加成，不单独决定结果**；
     仅由图召回且重排分低的候选被丢弃。
3. **系统处理（丢弃集可审查）**：[原型] 相关度 **低于 0.45** 的候选进入「**被丢弃**」集合，
   计数与内容**可点开审查是否漏掉关键内容**——**不得静默丢弃**。
4. **系统处理（反对证据强制保留）**：[原型] 证据片段中的**反对证据被强制保留、不做筛除**，
   并在注入段中显式标注条数（如「9 条，含 1 条反对」）。
5. **系统处理（预算）**：[原型] 计算并显示**上下文预算**（原型示例 `14.9k / 120k`），
   按段落给出占用（客户与项目上下文 / 方法 / 证据片段 / 历史决策与复盘）。
   超预算时按 R7 的优先级裁剪，**且裁剪动作本身进入丢弃集可审查**。
6. **系统处理（装配）**：[原型] 生成**装配后的系统提示**并保存为**只读快照**，
   固定四段注入 + 硬约束段：
   `# 角色` / `# 客户与项目上下文 ← 组织大脑` / `# 方法 ← Skill 库` /
   `# 证据 ← 项目图谱` / `# 硬约束`；并标注是否已脱敏。
   [原型] 硬约束原文必须可见，例如「不得写入决策节点；不得引用未在上文列出的证据；
   客户机密材料只能由本地模型处理。」
7. **用户操作（审查与出口）**：[原型] 三个出口——
   `[看这次的完整调用日志]` / `[调整检索权重]` / `[固定这段上下文到本项目]`。
8. **系统收口（下游可见性 = 验收锚点）**：[原型] 由该次上下文生成的产物在**报告工作台**中
   **每节显示来源角标**（如「决策 7/25 12:30 ｜ 投票 10/12 ｜ 研究 9 来源」），
   且「**每句都会挂来源，未挂来源的标灰**」。
   [设计] 点角标可回到本 UC 的检索记录——**引用展开层未探明**（D-23 已列为待补抽取三处之一），
   该跳转行为无原型依据。
9. **系统收口**：校验 AC1「任一条 AI 结论都能还原它当时看了什么」（承接 UC-17.1 的同名 AC1）；
   记录调用者、时间、模型、检索会话 ID 与系统提示快照 ID 进审计。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] `[调整检索权重]`——方法负责人调整权重后**重跑检索**并生成**新的**检索会话，
    旧会话保留不覆盖（可对比）。
  - A2：[原型] `[固定这段上下文到本项目]`——把本次装配结果固定为项目级上下文包，
    后续调用复用；固定动作留痕，且被固定的内容**仍受知识状态变化影响**（撤销条目必须失效）。
  - A3：[原型] **冲突成对时不自动裁决**——两条同时注入，界面提示由人判断
    （与 UC-14.1 的成对召回三出口一致）。
  - A4：[设计] 检索零命中时展示真实空态、说明为什么没命中（如适用范围过窄）
    与下一步入口，**不得编造上下文**。
- **异常流程**：
  - E1：[设计] 组织层不可用 → 明确降级为「仅项目图谱 + 当前转录」，
    在界面与系统提示中都标注缺失来源；**不得静默回答**。
  - E2：[设计] 超上下文预算 → 按 R7 优先级裁剪，被裁剪片段进入丢弃集并可审查；
    若裁剪后仍超限则**明确失败**，不得截断硬约束段。
  - E3：[原型] 被引用条目在生成期间**被撤回/撤销**（UC-17.2 的撤回数据流）→
    该片段立即退出检索范围，已生成内容的对应段落标为「证据已撤回」（**不静默删除**）。
  - E4：[设计] 用户无权查看某条被召回的原文（团队可见性范围、脱敏门控）→
    检索记录中该条**以脱敏/占位形式呈现**，但**条目存在这一事实必须可见**，
    否则「可审查」不成立；查看原文走权限门控并留痕。
  - E5：[设计] 请求超时或依赖不可用时保留最后一次成功的检索记录，明确失败原因并可重试；
    失败不得被呈现为成功。

## R5 权限与可见性

- **调用者**：可查看**自己发起的**调用的完整检索记录、丢弃集与装配后的系统提示（只读）。
- **项目负责人**：可查看本项目内全部调用的检索记录。
- **方法负责人**：可跨项目查看检索记录，且是**唯一**可执行 `[调整检索权重]` 的角色。
- **合规负责人**：可查看全部检索记录与注入内容（用于审查是否有越权注入），访问留痕。
- **观察者 / 客户**：**不可见**检索记录与系统提示；仅可见已发布产物上的**脱敏后来源角标**
  （能看到「有 N 处引用」，不能展开到原始材料）。
- **agent**：可读取被注入的上下文，**不可修改筛选结果、不可删除丢弃集、不可编辑硬约束段**。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。
- 检索记录中条目的可见性仍受 `uc-0-3` 两层交集鉴权与资源可见性范围约束。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 每次调用产生一条**不可篡改**的检索记录 + 一份**只读**的系统提示快照。
  - [原型验收] AC1（**主验收锚点**）：报告工作台中**每一节都显示来源角标**，
    且**未挂来源的内容被标灰**。
  - [设计验收] AC1b：点角标可下钻到本次检索记录中的对应片段
    （**引用展开层未探明**，该下钻行为无原型依据）。
  - [原型验收] AC2：五种筛选动作（召回/降权/排除/成对/线索）**逐条可见**，
    每条给出条数与理由（如「2 条适用范围不匹配 · 标为跨范围引用后降权保留」）。
  - [原型验收] AC3：**被丢弃的低相关片段（相关度 < 0.45）可点开审查**，不得静默丢弃。
  - [原型验收] AC4：**反对证据不被筛除**，且注入段显式标注反对条数。
  - [原型验收] AC5：装配后的系统提示**可只读审查**，含四段注入与**硬约束原文**。
  - [原型验收] AC6：上下文预算（已用 / 上限）可见。
- **失败后置条件**：不产生「没有检索记录的回答」；失败事件进入可观测日志。
- **不包含**：
  - 检索权重的**自动学习/自适应调参**（本 UC 只做人工 `[调整检索权重]`）。
  - **推演链编辑器**、**个人判断偏好开关**（偏好会影响系统提示装配，但开关本体后置，
    见 UC-14.4 R6 的模块级 backlog）。
  - 让 AI 自行裁决冲突证据、自行删除丢弃集、自行改写硬约束段。
  - 向客户/观察者暴露检索过程与原始片段。

## R7 业务规则（不随具体实现变化的硬性约束）

- [原型] **召回集边界**：组织层**只取「生效」与「待复核」两态**；
  **已撤销永久排除**，其**反例文本另行以「教训」召回**。
- [原型] **降权不等于排除**：适用范围不匹配的条目**必须保留**并标「跨范围引用」。
- [原型] **成对召回不替人选**：冲突的两条同时注入，系统**不得**择一。
- [原型] **图谱线索只给固定加成**，**不单独决定结果**。
- **[设计 · 架构对齐] 检索策略是 query-planned hybrid，禁止 graph-first**：
  按 Query 类型规划后**并行召回五路**——
  **① PostgreSQL FTS（一等通道，精确原话/编号/姓名/术语）**、② pgvector 语义、
  ③ 图关系路径、④ 元数据（项目/来源/时间/研究方法/受访者群体）、⑤ 已审核 Claim ——
  再做 RRF 或加权融合 → rerank → 去重与来源多样性与**支持/反驳平衡** →
  按 token budget 压缩 → 返回文本 **+ 引用锚点 + 遗漏说明**。
  上文第 2 步的「图谱线索只给固定加成」正是这条策略在图这一路上的表现，**不得升级为主策略**。
- **[设计 · 架构对齐] 权限过滤发生在 SQL/RLS 层，不在应用层**：
  召回的第一步就是租户与项目过滤，**不是先召回再过滤**。
  ⚠ **pgvector 的过滤召回率必须单独评测**——近似索引叠加权限/租户/项目过滤时
  可能「先近似召回再过滤」导致返回不足；须使用过滤列索引、分区或 iterative scans，
  并建立**带权限过滤的 recall 测试集**。
- **[设计 · 架构对齐] 图投影阶段一不启用 Apache AGE**：
  第 ③ 路用 **`ontology_edges` + recursive CTE** 实现；
  确有复杂路径性能需求再评估 AGE（须锁定兼容 PG 版本并维护自建镜像）。
- **[设计 · 架构对齐] AI 取上下文只能通过 Context API 取 Context Pack**——
  任何 agent / skill / 报告生成器**不得绕过 Context API 直查 `segments`、`claims` 或向量表**。
  绕过即无 `permissionDecisionId`、无 `omissions`、无可审查性，本 UC 直接失效。
- **[设计 · 架构对齐] 权限必须传播到摘要**：由多条来源合成的注入内容，
  其可见性**取所有来源权限的最严格结果**，避免摘要造成越权信息洗白。
- [原型] **反对证据强制保留、不做筛除**——这是与 UC-14.4「依据强度必须含反对」同源的硬约束。
- [原型] **被丢弃必须可审查**：低于相关度阈值（原型 0.45）的候选保留在丢弃集中并可点开。
- [原型] **系统提示可只读审查**：四段注入 + 硬约束段；**硬约束段不可被裁剪、不可被 AI 改写**。
- [原型] **硬约束原文示例（须逐字可见）**：「不得写入决策节点；不得引用未在上文列出的证据；
  客户机密材料只能由本地模型处理。」——第三条与 D-17 的闭源/自托管二分联动。
- [裁决 D-33] 待复核（已过期）条目**在检索范围内、引用时提示**，
  但**不参与定题强度计算**。
- [原型] **未挂来源必须标灰**：产物中无来源支撑的句子不得与有来源的句子视觉等同。
- [设计] **裁剪优先级**（超预算时）：硬约束段 > 方法段 > 证据段（反对证据优先保留）>
  历史决策与复盘 > 客户与项目上下文；被裁剪片段进入丢弃集。
- [设计] 检索记录与系统提示快照**不可篡改、不可删除**（按 UC-17.3 的审计保留期存储）。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。

  （对应 QueryContext 的 `task`：search / answer / research / decision-support）。
- **[已裁决 O-36]** 上下文预算上限（原型 120k）**随模型上下文窗口推导**，不写死；
  超限时**按相关度截断**，且**被截断项必须记录进 Context Pack 的 `omissions`**
  （与「被丢弃必须可审查」同一条规则，不另开口子）。

## R9 非功能约束

- **性能/规模预期**：[设计] 检索与筛选记录的落库**不得阻塞回答返回**（异步写入，但必须最终一致，
  且回答返回时检索会话 ID 已确定）；检索记录页首屏 1 秒内可见，丢弃集按需分页加载。
- **安全/隐私/合规**：系统提示快照可能含客户数据，按最高敏感级存储并受权限门控；
  [原型] 含客户机密时**只能由本地/自托管模型处理**（硬路由，见 D-17）；
  脱敏后的注入内容与原文的映射按 UC-14.5 R7 的可逆映射规则处理。
- **兼容与降级要求**：响应式 Web；移动端至少保证来源角标可见并可下钻。
  组织层不可用时**显式降级并标注**，绝不静默使用空上下文。

## R10 已知约束 / 依赖

- **内部依赖**：**UC-14.5**（召回集由五态定义、适用范围决定降权、撤销决定排除）、
  **UC-14.4**（历史决策与复盘注入段）、UC-9.x（项目图谱）、03-skill（方法段）、
  UC-10.2/10.3（报告工作台的来源角标与缺料提示）、UC-17.2（撤回后片段退出检索）。
- **被依赖**：**UC-17.1 的 AC1**「任一条结论都能还原它当时看了什么」**由本 UC 承接实现**
  （D-34 A′：UC-17.1 不重复造检索还原能力，交叉引用本 UC）；UC-14.2（跨项目调用）。
- **跨模块契约**：检索会话 ID（＝ `packId`）、片段引用（`segmentId` + `artifactVersionId`，
  指向**不可变版本**）、系统提示快照 ID 必须与审计事件、报告来源角标使用**同一套标识**。
- **[设计 · 架构对齐] 与 Context Engine 的映射**（实现时逐条对齐，不得另起炉灶）：

  | 本 UC 的业务概念 | Context Pack 字段 |
  |---|---|
  | 检索会话 / 「AI 读到了什么」 | `context_packs` 一行（`packId` + `query`） |
  | 召回 / 降权 / 排除 / 成对 / 线索（五种筛选动作） | `items[].retrievalReasons` 的**取值域** |
  | 被丢弃 · N 条低相关 + 超预算裁剪 | `omissions[]` |
  | 「为什么这条能给你看」/ 脱敏占位呈现 | `items[].permissionDecisionId` |
  | 来源角标可下钻到页码/时间码/消息 | `items[].anchor` |
  | 冲突成对注入 | `claims[].supportingSegmentIds` / `contradictingSegmentIds` |
  | 组织层条目的五态 | `claims[].status`（对应表见 **UC-14.5 R10**） |

  **架构侧「首批完成门槛」第 ⑥ 条「每次 Agent 运行能重放当时使用的 Context Pack」
  由本 UC 承接**；第 ① 条「100% AI 引用可定位到原文件页码/时间码/消息」是本 UC 的 AC1b 前提。
- **技术约束**：[Backlog] 产品为响应式网页；完整离线模式与原生移动端在范围外。
- **[设计 · 架构对齐] 编排边界**：本 UC 的检索**不使用 LangGraph**。
  LangGraph 只用于**深度研究 / 人工确认（HITL）/ 多阶段生成**；
  检索是单次请求内的并行召回 + 融合，摄取则走**持久任务系统**（PG outbox + worker）。
- **[已裁决 O-36]** 相关度阈值按任务类型可配；预算上限随模型窗口推导、超限截断项进 `omissions`（见 R7）。
- **[已裁决 O-01]** 检索记录的保留期**并入 UC-17.3 的审计保留期参数 ＝ 1095 天（3 年）**，
  不单设一套（允许区间仍 `[待确认 · 待合规]`）。

## R11 切分提示（给 requirement-author）

## R12 AI Ready 验收线索

- V1（成功态 · **主锚点**）：AC1 —— 在报告工作台生成一节内容，断言：
  ① 该节渲染出**来源角标**且角标数与检索记录中该节引用的片段数一致；
  ② 构造一句无来源支撑的内容，断言它被渲染为**标灰**样式（`data-testid` 可断言）；
  ③ 点击来源角标可跳到本次检索会话中的对应片段。
- V2（成功态）：AC2 —— 请求检索记录接口，返回体中**五种筛选动作各自成组**，
  每组含条数与理由文本；构造「适用范围不匹配」的条目，断言它出现在**降权组**且标
  「跨范围引用」，**不在排除组**。
- V3（成功态）：AC3 —— 构造若干相关度 < 0.45 的候选，断言它们出现在**丢弃集**且可逐条展开；
  丢弃集为空时显示真实空态。
- V4（成功态）：AC4 —— 候选中含反对证据时，断言反对证据**必然出现在注入段**，
  且注入段元数据标注了反对条数；尝试通过参数筛除反对证据的调用被拒绝。
- V5（成功态）：AC5 —— 读取系统提示快照，断言含四段注入标题与**硬约束段原文**；
  尝试写接口修改快照被拒绝（只读）。
- V6（成功态）：AC6 —— 检索记录返回上下文预算的已用值与上限值。
- V7（成功态 · D-33）：把一条条目置为已过期（待复核），断言它**仍出现在召回组**、
  携带过期标记，且定题强度计算结果不含它。
- V8（成功态 · 排除）：把一条条目置为已撤销，断言它**不在任何注入段**，
  但其反例文本以「教训」类型出现在召回组。
- V9（成功态 · 成对）：构造两条冲突条目，断言**两条同时出现在证据段**，系统未择一。
- V10（权限态）：逐一以调用者、项目负责人、方法负责人、合规负责人、观察者、
  未授权用户访问检索记录与 `[调整检索权重]`，返回严格符合 R5；
  观察者请求检索记录被拒，但可见产物上的脱敏来源角标。
- V11（空态）：零命中时显示真实空态与原因说明，回答中不出现编造的上下文。
- V12（依赖失败）：模拟组织层不可用，断言回答仍返回但界面与系统提示均标注来源缺失；
  模拟超预算，断言裁剪按 R7 优先级执行且硬约束段未被裁剪。
- V13（并发/撤回态）：生成过程中撤回一条被引用的片段，断言该片段退出检索范围，
  已生成段落标为「证据已撤回」而非被静默删除。
- V14（审计态）：调用、权重调整、上下文固定、原文回溯四类事件均可按操作者、时间、对象检索。
- V15（成功态 · **[设计 · 架构对齐] Context Pack 契约**）：任取一次 AI 调用，读取其 `context_packs` 行，断言：
  ① 每个 `items[]` 都有非空 `retrievalReasons`，且取值**全部落在五种筛选动作的枚举内**；
  ② 每个 `items[]` 都有非空 `permissionDecisionId` 与可定位的 `anchor`；
  ③ 被丢弃与被裁剪的片段**全部出现在 `omissions[]`**，条数与界面「被丢弃 · N 条」一致；
  ④ 不存在 `context_packs` 之外的第二套检索记录表。
- V16（成功态 · **query-planned hybrid**）：构造四类查询各一条并断言召回路径：
  ① **精确原话/编号/姓名**（如某受访者原句、文件编号）→ **PostgreSQL FTS 命中**，
  且**在实体链接尚未完成的新上传材料上同样命中**（这是推翻 graph-first 的直接验收）；
  ② 语义近义查询 → pgvector 命中；③ 「谁决定了什么」结构查询 → 图路径命中；
  ④ 时间/来源限定 → 元数据命中。断言四路可并行且融合后无重复片段。
- V17（安全态 · **RLS 与过滤召回率**）：
  ① 以无权用户发起检索，断言跨租户/跨项目片段**零泄漏**（架构首批门槛第 ② 条）；
  ② 用**带权限过滤的 recall 测试集**断言 pgvector 在叠加过滤后的召回率不低于约定基线，
  验证没有出现「先近似召回再过滤导致返回不足」；
  ③ 断言应用数据库连接**不是表 owner 角色**（owner 默认不受 RLS 约束）。
- V18（安全态 · **绕过 Context API**）：直接以 agent 身份调用 `segments` / `claims` /
  向量表的读接口，断言**被拒绝**；只有经 Context API 的请求可拿到上下文。
- V19（安全态 · **摘要不得洗白权限**）：构造一条由「高密级 + 低密级」两来源合成的注入内容，
  断言其对**只持有低密级权限**的用户不可见（取最严格结果），且该排除写入 `omissions`。
