# `group-checkin` — 不变量

1. **"到场"判定口径只有一种**：点过加入链接即到场（Q2 已裁决候选 A），不做心跳/在线判定。
   （怎么断言：`recordCheckinEvent` 被调用后 `arrived` 立即变 `true` 且不会因为用户后续断开连接
   而自动回退为 `false`——没有任何定时任务或心跳机制会撤销一次已记录的到场。）
2. **到场事件的合法性完全信任 phase-01 01-auth 的链接校验结果，本束不重复校验**。
   （怎么断言：审查 `recordCheckinEvent` 的实现，确认它不包含 token 签名/有效期的校验逻辑，
   这部分逻辑只应该出现在 01-auth 的实现里。）
3. **二维码不经过后端**（Q4 已裁决候选 A）。（怎么断言：`packages/contracts/src/live-collab-checkin.ts`
   落地后，审查其中不包含任何"生成二维码图片"的端口定义。）
4. **"看加入页"是站内预览，不离开现场协作 Tab**（Q5 已裁决候选 A）。（怎么断言：点击"看加入页"
   按钮后，浏览器 URL 不变、不打开新标签页，预览内容渲染在当前页面内的一个面板/弹层里。）
5. **到场数据模型是单一事实源**：`viewer-role` 束的"缺N人"状态后缀必须读取本束这份数据，
   不得另建一份到场计数。（怎么断言：审查 F01 状态后缀渲染逻辑的数据来源，确认它调用的是
   `getGroupCheckinBoard` 或其派生的同一份查询，不是另一个独立计算的到场数字。）

## [待定] 未决项（不阻塞开工，需人类在签核时一并给答案）

  "作为引导师……"这一个视角，没有提组长/观察者的可见性，`ui.md` 的视角/态矩阵已标出这两格是空的。
- 到场事件的写入时机：是"点开链接的瞬间"还是"链接页面加载完成/参与者确认进入"之后——
  两者在网络慢的场景下会有细微差别，requirements 原文未区分，实现时口径不一致会导致到场数漂移。
