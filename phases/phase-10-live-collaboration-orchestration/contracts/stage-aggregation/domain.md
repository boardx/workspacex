# `stage-aggregation` — 不变量

1. **看板/知识图谱卡片的领域字段形状由 phase-02 单一定义，本束不重新声明**。（怎么断言：
   `packages/contracts/src/live-collab-stage-aggregation.ts` 落地后，审查其中看板卡片/决策树节点
   相关的类型是否直接引用 phase-02 的契约文件，而不是本束自己重新写一份同构但独立的类型定义——
   两份同构定义即便字段一致也算违反"同一事实不得声明两处"。）
2. **phase-02 对应束未签核期间，`getKanbanBoard`/`getDecisionGraph` 只返回"未就绪"，不返回
   任何看起来像真实数据的字段**。（怎么断言：在 phase-02 看板/知识图谱束状态仍为 `not_started`
   或未签核时调用这两个端口，断言响应体里没有 `cards`/`nodes` 等看似真实的数据字段，只有
   `{ready: false, blockedBy}`。）
3. **广播/派发动作是独立于 phase-02 数据的动作型端口**，其成功与否不依赖看板/图谱数据是否就绪。
   （怎么断言：在 `getKanbanBoard` 返回未就绪的同时，`broadcastToGroupLeads` 仍能正常返回成功——
   两者互不阻塞。）
4. **只有引导师能访问本束两个聚合视图**（沿用 `viewer-role` 束的角色矩阵，本束不重新定义）。
   （怎么断言：以组长/组员身份调用 `getKanbanBoard`/`getDecisionGraph`，断言被拒绝而不是返回
   一个"未就绪"响应——权限拒绝要发生在"是否就绪"判断之前。）
