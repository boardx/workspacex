# `module-routing` — 不变量

1. **模块卡片统一形态字段集只有一份定义**（Q3 已裁决）：可见性徽标+状态徽标+摘要+负责人头像+
   "打开模块"按钮。（怎么断言：审查 `getModuleCards` 契约返回的每个 `cards[]` 元素，字段集与
   `packages/contracts/src/live-collab-module-routing.ts` 里声明的一致，四个模块不各自夹带额外字段。）
2. **本束不重新实现任一模块的内部领域逻辑**：对话/访谈/研究/问卷的数据只读取，不在本束写入。
   （怎么断言：审查本束代码，确认没有直接写四个下游模块各自的数据表，只有只读查询 + 路由跳转。）
3. **角色可见性判定复用 `viewer-role` 束的共享服务，不另建一套**。（怎么断言：`getModuleCards`
   的权限拒绝路径返回的错误码与 `viewer-role` 束的 `VIEWER_SCOPE_DENIED` 一致，不是本束自定义
   的另一个错误码。）
4. **跨模块跳转必须携带项目/分组/环节上下文**（`03-module-routing.md` 编排层硬约束）。
   （怎么断言：从任一模块卡片点击"打开模块"后，落地页面能正确显示"属于哪个项目/分组/环节"，
   不是一个脱离上下文的通用模块首页。）
5. **checklist/需要知道/已生成产出三类字段在契约补齐前不得渲染编造数据**（同 F963 处置纪律）。
   （怎么断言：审查本场状态右侧栏组件源码，这三块的数据来源必须能追溯到明确的 mock/占位标记，
   不是硬编码的看似真实的内容。）
