# 原始需求 — 分组签到

> 来源：原型截图 7（"分组与签到"页）+ 文本抽取里"分组与签到 11/12 已到 · 每组一条加入链接，打开即进，不需要注册"。这是全仓库**全新领域**，此前没有任何 UC/feature 提到过。

## 用户故事

- 作为引导师，切到"主持台·全场 → 分组与签到"，看到 4 张分组卡片：组号、组名（当前议题）、"M/N 已到"进度、复制链接按钮、二维码按钮，以及组内每个成员的姓名+角色徽标（组长/已到/未到）。
- 作为一个还没进场的参与者，我拿到组长/引导师转发的一条链接，点开直接进这个分组的现场协作视角，**不需要注册**（呼应 `uc-1-2-用分组链接免注册进场.md`，phase-00/01-auth 已有这个能力域，本 phase 只是把它在"分组与签到"页里可视化）。
- 作为引导师，顶部有"看加入页"按钮，能看到给参与者展示的加入入口长什么样。

## 明确复用 vs 新建

- **复用**：免注册进场的链接生成/校验机制——`phases/phase-01-run-a-project/requirements/01-auth/uc-1-2-用分组链接免注册进场.md` 已经 spec 过，本 phase 不重新定义链接生成/校验逻辑，只消费它。
- **新建**：把"每组一条链接 + 二维码 + 到场进度 + 成员到场状态列表"聚合展示在现场协作 Tab 里——这个聚合视图本身、以及"到场状态"（已到/未到）这个字段，需要确认是否已有仓储字段可用，还是要新增。这是本 phase 要交付的编排/聚合层。

## 需要人类确认的点（requirement-author 生成 feature 时列为待确认，不要自己拍板）

- 二维码生成是前端本地生成还是服务端出图？
- "看加入页"打开的是参与者视角的预览，还是一个真实的独立 URL？
