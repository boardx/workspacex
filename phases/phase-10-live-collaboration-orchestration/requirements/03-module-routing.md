# 原始需求 — 分组五模块侧栏 + 全场三视图聚合（编排层）

> 来源：原型截图 2-6（分组视角五模块：与AI的对话/用户访谈/深度研究/问卷/本组图谱）与截图 8-9（主持台全场：知识图谱决策推演、看板）。

## 分组视角 · 五模块侧栏

用户故事：作为组员，切到我所在的分组视角，左侧看到 5 个能力 tab（图标+名称+计数）：`CH 与AI的对话(24)` `IT 用户访谈(2)` `DR 深度研究(1)` `SV 问卷(1)` `KG 本组图谱`。点开任意一个，中间主区域切换成该模块的卡片列表（统一形态：卡片 + "新建 XX"占位），右侧"本场状态"侧栏（环节倒计时、本组 checklist、"需要知道"提示、"已生成产出"列表）始终保持不变。

**编排层要交付的东西**（不重造各模块领域逻辑）：
1. 侧栏 tab 结构 + 计数徽标——计数从各自模块的真实接口来（对话数、访谈数、研究数、问卷数），不是编排层自己维护的字段。
2. 点开某个 tab 后，中间区域怎么路由到已有模块组件——`与AI的对话` 应该复用 phase-01 08-chat 已有的对话组件/接口；`用户访谈`复用 phase-07；`深度研究`复用 phase-06；`问卷`复用 phase-09；`本组图谱`消费 phase-02 的知识图谱数据（该 phase `not_started`，此模块在其契约签核前只能是 UI 骨架+mock）。
3. 卡片的统一视觉形态（状态徽标+摘要+负责人头像+"打开模块"按钮）——这是编排层定义的展示规范，各模块只需要提供符合这个形态的数据字段。
4. "本场状态"右侧栏——环节倒计时复用 F963 的真实数据源；"本组进度"checklist、"需要知道"提示、"已生成产出"列表目前全仓无来源，属于本 phase 需要新建契约字段的部分（不能编造假数据糊弄过去）。

## 主持台·全场 · 三视图聚合

1. **看板**：4 个分组的实时卡片网格（当前议题、时间戳、一句 AI 摘要引述、进度条、"听这组"/"推提示给组长"操作、"广播提示给所有组长"）。消费 phase-02 F02 看板领域数据 + phase-01 canvas/recording 束的实时引述数据；phase-02 `not_started` 期间此视图停在 UI 骨架阶段。
2. **知识图谱·决策推演**：决策树（节点状态：领先/在议待决/冲突/已否决/待验证）+ 待决岔口列表 + 图谱推演预测卡 + "下一步可开展的工作"派发卡片组。消费 phase-02 F11/F15/F16/F17；同上，`not_started` 期间只能 UI 骨架。
3. **分组与签到**：见 `02-group-checkin.md`，本 phase 自己 owns。

## 编排层的路由/权限硬约束

- 所有"点开模块"的路由必须带上当前项目/分组/环节的上下文，不能让用户跳转后失去上下文（比如从"本组图谱"点"发起访谈"跳到访谈模块后，访谈要能带着"属于哪个项目哪个分组哪个环节"的标记）。
- 角色可见性矩阵（引用 `01-viewer-role.md`）在每个模块的路由入口也要生效：组员看不到别组的模块数据，即使猜到 URL。
