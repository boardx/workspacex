# 原始需求 — 视角切换器 + 角色可见性矩阵

> 来源：人类会话转述的原型截图 7（视角下拉菜单展开态）+ `00-project/prototype-raw-text-extract.txt` 里 `视角 引导师 组长 组员 观察者` 与 `{{ roleBadge }} 视角 {{ role...` 的模板占位符（说明原型本身角色徽标是动态渲染的，不是写死文案）。

## 用户故事

- 作为**引导师**，我打开某个正在进行的项目的"现场协作"Tab，默认看到"主持台·全场"视角，我能从一个下拉里切到任意一个分组去看/听/介入，也能切回全场；下拉里每个分组要显示该组当前的一句话状态（"推演中" / "缺1人" / "需介入"）。
- 作为**组长**，我打开这个 Tab，只能看到我自己那一组的视角，看不到"主持台·全场"选项，也切不到别的组。
- 作为**组员**，同组长，但组内某些动作（如批量确认写回，属 phase-02）我没有权限触发，界面上要么不显示要么显示为禁用+说明。
- 作为**观察者**，进来是只读的——具体是"能看全场只读"还是"只能看被分配的一个分组只读"，这一点原型截图证据不足，**需要在契约设计阶段由人类裁定**，本文档不预判，requirement-author 生成 feature 时把它列为待确认项，不要自己选一个答案写死。

## R1 已知硬约束（服务端强制，不是前端隐藏）

- 视角切换器展示哪些选项、点击后是否真的能拿到数据，必须在服务端按角色 + 分组成员关系判定，不能只在前端过滤下拉选项——否则组员改个 URL 参数就能看到别组的原始转写。
- 顶部提示条"引导师视角：同一个界面，你有全部权限：四组对话、原始转写、切环节与介入"这句文案本身就是在向用户解释权限差异，其它角色应该有对应的、如实的提示条文案（不能对组长/组员也显示"你有全部权限"）。

## R2 需要的能力（大白话，交给 requirement-author 拆 feature）

1. 一个视角切换器组件：引导师能看到"主持台·全场 + 每个分组"选项；组长/组员只能看到"自己的分组"（甚至可能不需要下拉，直接锁定）；观察者的选项集合待人类裁定。
2. 每个分组选项旁边的状态后缀（"推演中"/"缺1人"/"需介入"）——这些状态从哪个真实字段来，需要先确认：分组签到人数（本 phase 新建，见 02-group-checkin.md）可以支撑"缺1人"；"需介入"目前全仓无来源（同 00-overview.md 的硬前置），不能编造。
3. 角色徽标展示（引导师/组长/组员/观察者）——从当前用户在该项目/该分组的真实角色关系读取，不是前端写死。
4. 顶部提示条文案按角色区分，如实描述该角色实际拥有的权限，不能所有角色共用引导师那句话。
