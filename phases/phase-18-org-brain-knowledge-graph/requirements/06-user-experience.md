# 06 · 用户、价值与 9 分体验标准

> 出处：人类 2026-09-24：「你要考虑到谁是用户，如何让用户的体验可以达到 9 分，容易使用，获得价值。」
> 元数据：估点 **5**（与 `../feature_list.json` 中 spec_ref 指向本文件的 feature 点数之和对账，由 validate-fl 核对）。
> 本文件定三件事：**谁在用**、**什么时刻让他觉得值**、**怎样算 9 分**。
> 其余 UC（uc-18-1…6）的界面与规则如果和本文件冲突，**以本文件为准**，并回改该 UC。

## R1 谁是用户

本阶段只有两级作用域：会话和个人空间。所以用户是**一个人用 AI 工作**的场景，不是团队协作。

| 画像 | 典型的人 | 他在做什么 | 他最怕什么 |
|---|---|---|---|
| **P1 天天和 AI 聊工作的人**（主用户） | 投资经理、研究员、咨询顾问、产品经理 | 一个项目 / 一件事会断断续续聊很多次，每次都要重新交代背景 | 「又要从头讲一遍」；为了让 AI 记住东西而多干活 |
| **P2 较真的专业用户** | 投后、法务、合规、写报告的人 | AI 的每句话都可能进正式材料 | 「AI 记错了，我还不知道」；敏感信息被别人看到 |
| P3 组长 / 项目负责人（下一阶段） | 带团队的人 | 把个人确认过的知识汇成团队的 | 本阶段不服务，但设计不能堵死这条路 |

**设计取舍的顺序**：先让 P1 **零负担地获益**，再让 P2 **放心**。
P1 如果要花力气维护「知识库」，他就不会用；P2 如果看不到来源、改不了错，他就不敢用。

## R2 价值时刻（用户在哪一刻觉得「值」）

| # | 时刻 | 用户心里那句话 | 本阶段怎么做到 |
|---|---|---|---|
| **M1** | 开新会话，不用重新交代背景 | 「它记得我们之前定过的事」 | 个人空间知识跨会话召回（uc-18-4），回答里标「来自你 9/20 的对话」 |
| **M2** | 问「谁定的、为什么」，答得出来还有出处 | 「不用翻聊天记录了」 | 图 + 向量混合召回，引用能点回原话（uc-18-2） |
| **M3** | 自己前后说法矛盾，被及时提醒 | 「幸好它指出来了」 | 新消息与已确认的内容冲突时，在对话里轻提示（uc-18-6） |
| **M4** | 发现 AI 记错了，一下就改掉 | 「我能管住它」 | 每条记忆「对 / 不对」一键；对话里说「忘掉 X」也行（uc-18-3、uc-18-6） |
| **M5** | 确定只有自己看得到 | 「放心写」 | 面板头部常驻「仅你可见 / 会话成员可见」 |

**首次价值时间（time-to-value）**：用户什么都不用做。第一次在新会话里被「记起来」（M1），就是第一次获益。
所以本阶段**不设任何必须完成的设置步骤**。

## R3 体验原则（每条都能在界面上验证）

1. **零负担获益**：记忆自动形成，未确认的内容也能被召回（标「未确认」），价值不以用户确认为前提。
2. **价值出现在对话里，不藏在面板里**：记下了什么、用了什么，都在回答的原位轻量展示；面板是管理用的，不是必经之路。
3. **说人话**：界面上不出现「实体、结论、三态、晋升、L0 / L1、本体」。用词表见 R5。
4. **一步改错**：任何一条记忆，纠正或忘掉最多 2 次点击，或者一句话。
5. **打扰要克制**：只在两种情况主动出声——记下了新东西（一行灰字）、出现矛盾（一张可忽略的卡片）。其余时候安静。
6. **来源永远一跳可达**：每条被用到的记忆都能点回原话。
7. **隐私写在明处**：谁能看见，面板头部常驻说明。
8. **不拖慢对话**：记忆整理在后台做，发消息的速度不变。

## R4 9 分标准（体验评测集，仿 `evidence/design-parity-eval/` 的做法）

十个维度，每维 1 分，按通过条数 / 总条数折算，总分是十维之和。**阶段退出门槛：≥ 9.0。**
每条检查都是真浏览器里一个用户看得见的结果，落在 `apps/web/e2e/kg-experience-eval/`（F15）。

| 维 | 名称 | 检查（节选，完整清单在评测集里冻结） |
|---|---|---|
| **E1** | 零负担 | 新用户不做任何设置，聊 3 轮后开新会话，回答里出现「来自你之前的对话」；全过程用户点击数 = 0 |
| **E2** | 记得住 | 固定 20 题回忆评测（人名、决定、数字、日期、原因）：答对率 ≥ 90%，每条带引用 |
| **E3** | 答得对 | 关系类题（谁定的 / 为什么 / 被什么取代）：hybrid 比纯向量多答对 ≥ 20% |
| **E4** | 有出处 | 回答里 100% 的记忆引用可点，点开就是原话，且原话被高亮 |
| **E5** | 改得快 | 纠正一条记忆 ≤ 2 次点击；说「忘掉 X」后，下一轮就不再提 X |
| **E6** | 看得懂 | 界面文案不含 R5 禁用词（自动扫描）；状态不只靠颜色区分（带文字） |
| **E7** | 会提醒 | 前后矛盾的说法，在第二次出现时的回答里出现冲突提示卡；忽略后同一冲突不再重复打扰 |
| **E8** | 不打扰 | 一轮对话里主动提示最多 1 条；「已记下」提示是单行，不遮挡正文 |
| **E9** | 放心 | 面板常驻可见范围说明；另一个账号访问同一条记忆返回 403，界面显示「无权查看」 |
| **E10** | 不卡顿 | 开启记忆前后，发消息到首字的时间差 ≤ 100ms；图或向量故障时对话照常，只多一行说明 |

**冻结规则**（沿用设计工作台评测集）：用例与检查在 R0 冻结，之后只能修评测自身的 bug，并写明理由；不许为了分数放宽检查。
R0 基线在 F02–F09 合入后跑一次；之后每一轮修一个差距，并记录分数，直到 ≥ 9.0。

## R5 用词表（界面上说什么）

| 内部术语（只在代码和文档里用） | 界面文案 |
|---|---|
| 知识面板 / knowledge | **记忆** |
| 实体（object） | 人和事（按类型显示：人物、公司、项目、产品、概念、术语、指标、事件） |
| 结论（claim） | **记下的一条**（按类型显示：事实、猜测、决定、待办、风险） |
| 三态·待确认（pending） | **AI 记下的** |
| 三态·已确认（confirmed） | **你确认过** |
| 三态·冲突（conflict） | **有矛盾** |
| 晋升到个人空间（promote L0→L1） | **记到我的长期记忆** |
| L1 召回标签 | **来自你 {日期} 的对话** |
| 撤销（revoke） | **忘掉这条** |
| 图检索 / 向量检索不可用 | 「这次没能查全你的记忆（关联查询暂不可用），回答可能不完整」 |

## R6 对前几份需求的修订（U-1…U-6，签核时一并确认）

| # | 修订 | 影响 |
|---|---|---|
| **U-1** | 回答下方新增「已记下 N 条 · 查看 · 撤销」单行提示（价值出现在对话里） | uc-18-1 R8；契约 `ThreadCapture` 读模型 |
| **U-2** | 每条记忆「对 / 不对」一键；列表支持「全部确认」 | uc-18-3；契约 `applyHumanAction` 加 `confirmClaims`（批量） |
| **U-3** | 「记到我的长期记忆」对 AI 记下但没确认的条目也可以用：人点这个按钮，本身就算确认（同一个人的同一动作）。只有「有矛盾」和「来源已删」仍然拒绝 | uc-18-4 R2/R7、V3；不变量 I-9 |
| **U-4** | 新 UC-18.6：对话里说「记住 … / 忘掉 … / 你记得 X 什么」。AI 只生成一张确认卡，人点一下才生效（人的动作仍然是人做） | 新增 uc-18-6；契约不新增操作，卡片执行时复用 `applyHumanAction` / `promoteToPersonal` |
| **U-5** | 矛盾主动提示：新内容与「你确认过」的记忆冲突时，回答下方出现一张可忽略的卡片（保留哪条 / 两条都留 / 忽略） | uc-18-1 A3 → uc-18-6；契约 `KgConflictPrompt` |
| **U-6** | 面板头部常驻可见范围：「仅你可见」/「会话成员可见」 | uc-18-3 R5；`getThreadKnowledge.out.visibility` |
