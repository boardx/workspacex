# UC-18.1 会话知识入图

> 所属：Phase 18 · 作用域 L0（chat session）。架构：context-engine §二、ADR-114。
> 元数据：估点 **26**（与 `../feature_list.json` 中 spec_ref 指向本文件的 feature 点数之和对账，由 validate-fl 核对）。

## R1 概览
- **名称**：会话里的消息和附件，自动抽取成实体、结论和关系，写入本会话的知识图谱与向量索引。
- **Actor**：会话参与者（发消息 / 传附件的人）、抽取 Agent（后台，只提交候选）。
- **目标**：不需要人整理，对话里出现的「谁、什么、决定了什么、依据是什么」自动变成可检索的结构。
- **系统边界**：chat 消息与附件摄取 → 抽取 → `ontology_actions` 执行器 → canonical 表 → AGE 投影 + 向量。

## R2 前置条件 / 触发条件
- 前置：会话存在且未归档；附件已完成摄取（`INDEXED`，uc-22-2）。
- 触发（任一）：
  - 一条用户消息或 assistant 回复落库；
  - 一个附件进入 `INDEXED`；
  - 用户在会话里点「重新整理本会话知识」。

## R3 主流程
1. 系统把触发源放进持久任务队列（PG outbox），**不阻塞发消息**。
2. 抽取 Agent 读取该消息或附件的 segments，产出候选：
   - **实体**（`ontology_objects`）：人、组织、项目、产品、概念、术语、数字指标、日期事件。封闭枚举，见 R7。
   - **结论**（`claims`）：事实、假设、决定、待办、风险。`status=proposed`，`created_by=model`。
   - **关系**（`ontology_edges`）：实体↔实体、结论↔实体（`about`）、结论↔结论（五类语义，沿用 uc-9-1）。
   - **证据**（`claim_segments`）：每条结论必须挂至少一个 supporting segment，即原消息或附件片段。
3. 候选以 `ontology_actions` 提交。执行器做以下事情：
   - 校验枚举、作用域和证据锚点；
   - **实体解析**：与本会话已有实体按名称、别名和向量相似度合并；
   - 在同一事务里写 canonical 表 + `provenance_events` + outbox。
4. 投影 worker 幂等 upsert 到该 org 的 AGE 图；向量 worker 为新实体 / 结论写 embedding。
5. 会话侧栏的「知识」计数更新（uc-18-3）。

## R4 备选与异常
- **A1 纯寒暄或无信息量的消息**：不产生任何候选，这是正常结果，不报错。
- **A2 同一事实在后文被改口**：新结论 `supersedes_claim_id` 指向旧结论，旧结论转 `superseded`，保留可追溯。
- **A3 与已有结论矛盾且无法判断谁对**：两条都转 `contested`，并存，写一条 contradicting 证据。
- **E1 抽取模型调用失败**：任务按退避重试 3 次，之后标 `failed`，会话侧栏显示「有 N 条消息未能整理」，并提供重试入口。消息本身不受影响。
- **E2 执行器校验拒绝**（枚举外的类型、无证据锚点、跨作用域引用）：该 action 记 `rejected` 及原因，不落表，可在审计里查。
- **E3 AGE 投影失败**：canonical 已落，outbox 重试；重试期间图路查询在 omissions 里标「图投影滞后」。
- **E4 向量服务不可用**：只缺向量那一路，其余照写；恢复后补写。
- **E5 附件属于受限来源**（未授权 / 撤回中）：不抽取，记原因。

## R5 权限与可见性
- 抽取产物的作用域 = 源消息所在会话（L0）。可见性与会话一致，不得高于源材料（context-engine §五「交集取最严」）。
- 抽取 Agent 以系统身份运行，但 action 必须带发起源（消息 id / 附件版本 id）。**不能**以任何人的身份做确认。
- 会话外的任何人（包括组织管理员）不因本 UC 获得新的可见性。

## R6 后置条件 / 不包含
- 后置：本会话的图与向量索引包含该消息抽出的内容；每个节点可回溯到消息或附件锚点。
- 不包含：
  - 跨会话合并实体（那是 L1，uc-18-4）；
  - 人工编辑（uc-18-3）；
  - 项目 / 组织层图谱。

## R7 业务规则
1. `object_kind` 封闭枚举：`person / organization / project / product / concept / term / metric / event`。新增走 ADR。
2. `claim_kind` 封闭枚举：`fact / hypothesis / decision / todo / risk`。
3. 无证据锚点的结论**不得入库**。
4. 模型产出的一切 `created_by=model`，`status` 最高到 `proposed`。转 `accepted` 只能由人（uc-18-3）。
5. 同一消息同一 pipeline 版本重复处理结果不变（幂等键 = 源 id + pipeline 版本）。

## R8 界面线索
- 会话头部或侧栏的「知识」入口带计数与「整理中 / 失败 N 条」状态（截图待 ui-prototyper 产出）。

## R9 非功能约束
- 发消息的延迟不受入图影响（异步）。
- 单条消息入图 P95 < 30 秒（门槛待 S0-4 确认）。
- 隐私：抽取调用的模型遵守组织模型路由策略；`personal-local` 组织只用本地模型。

## R10 依赖
- uc-22-2（附件摄取与 segments）、context-pack I-12、ADR-114、`chat-context-engine` 束。

## R11 切分提示
- ① 表与执行器（`ontology_objects / ontology_actions / claims 扩列 / ontology_edges 扩列`）
- ② 抽取 Agent + 实体解析
- ③ AGE 投影 worker + 重建脚本
- ④ 向量 worker（`object_embeddings` + HNSW）

## R12 AI Ready 验收线索
- V1 发一条含「张三决定下周一上线 v2」的消息 → 30 秒内本会话出现实体「张三」「v2」和结论（decision），结论挂着该消息锚点。
- V2 同一消息重复触发三次，实体 / 结论 / 边的行数不变。
- V3 用模型身份直接 INSERT `claims` 被 RLS / 执行器拒绝。
- V4 停掉 AGE → 消息仍能发、canonical 仍落；恢复后 `graph:rebuild` 使 AGE 与 canonical 一致。
