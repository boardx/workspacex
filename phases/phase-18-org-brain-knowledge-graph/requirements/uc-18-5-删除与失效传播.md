# UC-18.5 删除与失效传播

> 所属：Phase 18 · L0 / L1。承接 uc-22-4（删除 6 类级联），把桩 `invalidateOntologyEdges` 做成真实现。

## R1 概览
- **名称**：删除消息、附件或整个会话时，由它们派生的实体、结论、边、向量、AGE 节点和 L1 晋升副本全部失效。
- **Actor**：会话所有者（删除者）、系统（级联执行）。
- **目标**：删掉的东西不会再被 AI 说出来。
- **系统边界**：chat / files 删除 → 失效级联 → canonical（软失效）→ AGE / 向量 → Context Pack 召回过滤。

## R2 前置条件 / 触发条件
- 触发（任一）：
  - 删除一条消息；
  - 删除或撤回一个附件（uc-22-4）；
  - 删除一个会话；
  - 用户在知识视图删除一条结论（uc-18-3，只影响该结论及其晋升副本）。

## R3 主流程
1. 删除动作提交后，系统找出所有**仅由**被删源支撑的结论，以及被删源作为证据的 `claim_segments`。
2. 处理结论与证据：
   - 仅由被删源支撑的结论 → `superseded` + `revoked_at` + `revocation_reason=source_deleted`；
   - 仍有其他证据支撑的结论 → 只去掉该条证据，结论保留，证据数更新。
3. 相关 `ontology_edges` → `status=invalidated`（软失效，替换现在的按 segment 硬删）。
4. 向量：失效行的 embedding 退出召回（删除或标记，与 uc-22-4 的 pgvector 级联同口径）。
5. AGE：投影 worker 删除对应节点和边。
6. L1：`derived_from` 指向失效 L0 结论的副本同样失效。
7. 全部在 5 分钟内完成（S4）。完成后写一条级联审计事件。

## R4 备选与异常
- **A1 实体再无任何结论引用**：实体标记为孤立，不再出现在图视图与召回中，但保留审计。
- **E1 级联某一步失败**（例如 AGE）：canonical 的失效已提交，召回以 canonical 为准，因此内容**已经**不会被召回；AGE 由 outbox 重试，并在运维视图告警。
- **E2 删除的是别人的消息**：沿用 chat 的删除权限，本 UC 不新增权限。

## R5 权限与可见性
- 谁能删沿用 chat / files 现有规则。级联由系统执行，不需要额外权限。

## R6 后置条件 / 不包含
- 后置：任何召回路径（FTS、向量、图、claim）都拿不到被删源派生的内容；审计可查。
- 不包含：法律保全（legal hold）例外（phase-03 17-gov）。

## R7 业务规则
1. 召回的权威过滤在 canonical（`revoked_at` / `status`），**不依赖** AGE 或向量已清理。投影滞后不会泄漏。
2. 失效是软的（行保留）；审计链不断。
3. `invalidateOntologyEdges` 端口契约与实现一致：软失效，返回 `invalidatedEdgeIds`。

## R8 界面线索
- 知识视图里，失效条目消失；如果用户正打开来源抽屉，提示「来源已删除」。

## R9 非功能约束
- 逻辑失效 ≤ 5 分钟（与 uc-22-4 同一 SLA 数值，引用该处，不另写数字）。

## R10 依赖
- uc-22-4、`files` 束（`OUTBOUND_PORTS.invalidateOntologyEdges`）、uc-18-1 / uc-18-4。

## R11 切分提示
- ① `invalidateOntologyEdges` 真实现 + `ontology_edges.status`
- ② 结论 / 证据级联
- ③ AGE 与向量清理 + L1 副本失效

## R12 AI Ready 验收线索
- V1 删除「张三决定上线 v2」那条消息 → 5 分钟内该结论 `revoked_at` 非空，召回为空，AGE 中不再有该边。
- V2 一条结论有两个来源，删掉其中一个 → 结论仍在，证据数由 2 变 1。
- V3 停掉 AGE 再删除 → 召回立即为空（canonical 过滤），AGE 恢复后自动清理。
- V4 L0 结论失效 → 其 L1 副本同时失效。
