## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-13.5 / 快照绑定契约（13-deliv 绑定点与门禁链）
- **Actor**：**引导师**、**项目经理**、**签署人**、**发布人**、**组长**；
  以及以系统身份消费本契约的 **UC-13.1 / UC-13.2 / UC-13.4** 与下游模块。
- **目标**：[原型] 让 13-deliv 三处"指向某一版内容"的动作（引用依据 / 锁定产出 / 发布结论）
  **绑定的都是同一种东西——固定快照**，并且**必须按同一条门禁链依次过闸**，
  不出现某一屏松一点、另一屏严一点的漂移。
- **本用例结果**：13-deliv 内任何一处建立的绑定，都可回答三个问题：
  绑的是哪一版（固定快照 ID + 版本号）、它过了哪几道闸（定版 / 验收 / 引用 / 发布）、
  绑定之后源怎么变都不影响它。
- **系统边界**：
  - **在边界内**：13-deliv 三处**绑定点**的清单与统一约束；四段**门禁链**的顺序与阻断规则；
    **引用一经建立即固定**的行为；上游证据事后被撤回时的标注与通知路径。
  - **在边界外（由 `uc-0-1` 定义，本文不重复）**：草稿 / 实时关联 / 固定快照**三模式**的语义、
    快照的**不可变存储**与定版流程、Artifact 与版本数据模型、Studio 侧回流。
- **核心数据对象**：绑定关系（绑定点类型 + 目标快照 ID + 版本号 + 建立人 + 建立时间）、
  门禁状态（已定版 / 已验收 / 可引用 / 可发布）、引用记录、撤回标注。
  **本用例不新增快照本身的任何字段**——快照对象归 `uc-0-1`。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

### 要点一 · 13-deliv 全模块的绑定点清单

1. **系统处理**：维护本模块**唯一的绑定点清单**，共三处，**每一处都必须绑定固定快照**：
   | # | 绑定点 | 所在用例 | 原型证据 | 绑定对象 |
   |---|---|---|---|---|
   | B1 | **决策依据** | UC-13.1 | `依据 v2 · 第 3 节`、`依据 v2 · 第 5 节` | 固定快照的某一节 |
   | B2 | **产出物锁定快照** | UC-13.2 | 「可继续编辑 · **已锁定快照**」 | 固定快照（该版） |
   | B3 | **发布绑定版本** | UC-13.4 | 「**必须绑定一个确定的产出版本 · 绑定 v2**」`[发布结论 · 绑定 v2]` | 固定快照 |
2. **系统响应**：三处的绑定接口共用同一条校验——目标必须是**固定快照**；
   目标若是**实时关联**或**草稿**，一律拒绝并提示先定版（定版流程见 `uc-0-1`，本文不重述）。
3. **系统响应**：绑定成功后写入统一的绑定关系记录（绑定点类型 B1/B2/B3、快照 ID、版本号、
   节次（B1 适用）、建立人、建立时间），三处**共用同一套标识**，可互相交叉查询。

### 要点二 · 门禁链（四段递进前置）

4. **系统处理**：对任一内容，按下面**四段递进**判定其当前能做什么，
   **任一段未过即阻断下一段，不得跳段放行**：

   ```
   ① 定版（固定快照）   —— 由 uc-0-1 定义与执行
        ↓ 未过 → 不可提交验收
   ② 验收（UC-13.2）    —— 「验收后才会成为可被决策引用的证据」
        ↓ 未过 → 不可被引用为决策依据
   ③ 可被决策引用（UC-13.1）
        ↓ 未过 → 该决策不成立，不进台账
   ④ 可发布（UC-13.4）  —— 且发布本身另有前置检查与发布授权
   ```

5. **系统响应**：每一段的拒绝都必须**说明卡在哪一段**并给出该段的入口——
   卡在①给定版入口，卡在②给产出物验收入口，卡在③给签署入口，卡在④给前置检查详情。
6. **系统响应**：**定版是必要条件、不是充分条件**——已定版但未验收的快照，
   在"引用为决策依据 / 加入报告正式版 / 写回图谱与组织大脑"三类入口上仍被拒绝。
7. **系统响应**：门禁状态**只进不退**地由人的动作推进（定版、验收、签署、发布），
   **不得由系统自动补齐**任何一段；不存在"管理员一键放行"的绕行入口。

### 要点三 · 引用一经建立即固定

8. **系统处理**：绑定建立后，该引用**固定在当时那一版**，**不随源更新**
   （[原型]「**决策绑定的是当时的快照**」「**旧版仍被引用是正常的**」）。
   源升到 v3 不改变已绑定在 v2 上的决策、产出记录与发布记录。
9. **系统响应**：界面上对"源已有更新版本"的情况**只提示、不自动改绑**；
   改绑必须是显式的人为动作，并作为一次新的绑定记录（旧绑定保留在历史中）。
10. **系统处理**：上游证据在绑定建立后被**撤回**时——**不修改快照内容**，
    只在**引用处标注**「证据已撤回」，并**通知拍板人复核**，由人决定是否更正结论；
    系统**不自动改结论、不自动解绑**（对齐 `uc-0-1` **E5** 与 **D-19**）。
11. **系统收口**：把绑定建立、改绑、撤回标注、复核通知写入审计，并显示动作影响范围
    （该快照被哪些决策、产出记录与发布记录引用）。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] **一份快照被多处绑定**——同一个 `v2` 可同时被 B1（多条决策的依据）、
    B2（产出锁定）与 B3（发布）引用；各绑定点独立记录，互不影响。
  - A2：[设计] **升版后重新绑定**——源产生 v3 并完成验收后，可显式新建指向 v3 的绑定；
    原指向 v2 的绑定**保留**（「旧版仍被引用是正常的」）。
  - A3：[设计] **跨用例查询**——从一个快照出发可列出其全部引用处；从一处引用出发可回到快照。
- **异常流程**：
  - E1：[原型] **绑定非快照**——目标为草稿或实时关联时拒绝绑定，提示先定版并给出定版入口。
  - E2：[原型] **跳段放行尝试**——直接对未验收的快照调用"引用为依据 / 发布"接口时拒绝，
    错误必须指明**卡在门禁链的第几段**。
  - E3：[设计] **源更新导致的静默漂移**——任何实现都不得让已建立的绑定自动指向新版本；
    检测到此类漂移应视为缺陷并在验收中断言（见 R12 V4）。
  - E4：[设计] **删除被引用的快照**——请求一律拒绝（快照不可删由 `uc-0-1` 定义），
    并回显该快照当前被哪些绑定点引用。
  - E5：[设计] **证据撤回后的处理**——不修改快照、不自动解绑、不自动改结论；
    只标注 + 通知拍板人复核；若该结论已发布给客户，走 D-19 的人工确认后替换流程。
  - E6：[设计] 并发建立绑定时不产生重复绑定记录；同一绑定点对同一目标重复提交视为幂等。
  - E7：[设计] 请求超时或依赖不可用时保留输入与最后成功状态，明确失败原因并可安全重试；
    **不得产生指向不存在快照的悬空绑定**。

## R5 权限与可见性

- **引导师 / 项目经理**：可查看本项目全部绑定关系与门禁状态；可在各自用例内建立绑定。
- **签署人**：在 UC-13.1 内建立 B1 绑定（受签署授权矩阵约束）。
- **发布人**：在 UC-13.4 内建立 B3 绑定（受发布授权约束）。
- **组长**：可查看本组产出的绑定与门禁状态；不可验收、不可发布。
- **组员**：可查看已发布内容中呈现的版本号；不可建立任何绑定。
- **观察者**：只读已发布内容及其绑定的版本号；不可见未发布的绑定关系与门禁明细。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。
- 门禁判定与绑定校验**必须在服务端执行**；界面禁用只是表现，不构成安全控制。

## R7 业务规则（不随具体实现变化的硬性约束）

### 边界声明（最重要的一条）

- **本用例是引用层，不是定义层**：快照的语义——**三模式绑定（草稿 / 实时关联 / 固定快照）**、
  **不可变**、**引用资格门控**——由 **`phase-1/00-core/uc-0-1` 唯一定义**。
  本文**只引用不重复定义**；两者若出现表述差异，**一律以 `uc-0-1` 为准**，
  并把本文视为需要修订的一方。

### 三条实质约束

- **① 绑定点必须绑固定快照**：13-deliv 的三处绑定点——**UC-13.1 决策依据**（`依据 v2 · 第 N 节`）、
  **UC-13.2 产出物锁定快照**、**UC-13.4 发布绑定版本**（`绑定 v2`）——**都必须绑定固定快照**，
  **不得绑定实时关联或草稿**。
- **② 门禁链递进前置**：**定版（固定快照，`uc-0-1`）→ 验收（UC-13.2）→ 可被决策引用（UC-13.1）
  → 可发布（UC-13.4）**。四段是**递进前置**，**任一段未过即阻断下一段；不得跳段放行**。
  其中「**验收后才会成为可被决策引用的证据**」意味着**定版是必要条件、不是充分条件**。
- **③ 引用一经建立即固定在该版本，不随源更新**（[原型]「决策绑定的是当时的快照」
  「旧版仍被引用是正常的」）。上游证据事后被撤回时**不修改快照内容**，
  只在**引用处标注**并**通知拍板人复核**（对齐 `uc-0-1` **E5** 与 **D-19**），
  系统不自动改结论、不自动解绑。

### 通用

- 所有门禁与绑定判定必须在服务端执行；隐藏或禁用入口只是界面表现，不构成安全控制。
- 建立绑定、改绑、撤回标注、复核通知都必须记录审计事件，并显示动作影响范围。
- 不存在任何角色的绕行入口（含管理员）——绕行请求一律拒绝并写安全审计。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 门禁状态判定应是一次查询即可返回的轻量操作（每次绑定/引用都要跑），
    1 秒内返回；不得为判定而遍历全项目历史。
  - [设计] "某快照被谁引用"的反查须有索引支撑，随引用数增长保持可用。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离；门禁判定与绑定校验一律服务端执行。

## R12 AI Ready 验收线索

- V1（绑定点 · 全绑快照）：对 B1（引用为决策依据）、B2（锁定产出快照）、B3（发布绑定版本）
  三个接口分别传入**草稿模式**与**实时关联模式**的目标，**六次调用全部返回拒绝**，
  错误信息均指向「需先定版为固定快照」；传入固定快照时三次调用全部成功。
- V2（门禁链 · 不得跳段）：对一个**已定版但未验收**的快照，
  调用「引用为决策依据」返回拒绝且错误标明卡在**第②段 验收**；
  完成验收后同一调用成功。对一个**未被签署引用**的内容调用发布接口，
  按 UC-13.4 前置检查被拒绝且错误标明卡在**第④段之前**。
- V3（门禁链 · 无绕行）：以项目管理员/组织管理员身份调用带"强制/跳过校验"参数的绑定接口，
  返回拒绝并写入安全审计；接口不存在跳过门禁的合法参数组合。
- V4（引用固定性 · 核心）：建立指向 v2 的绑定后把源升到 v3，
  重新读取该绑定仍返回 `version=v2` 与同一 `snapshot_id`，
  且按该绑定读取的内容与 v2 定版时**字节一致**；全库断言不存在自动改绑记录。
- V5（撤回标注）：把某绑定的上游证据置为已撤回，
  断言：快照内容**未变**（字节一致）、绑定**未解除**、结论**未被自动修改**，
  引用处返回 `evidence_revoked=true` 标注，且拍板人收到复核通知。
- V6（反查）：给定一个快照 ID，反查接口返回其全部引用处（含绑定点类型 B1/B2/B3、
  宿主对象 ID）；给定一处引用，可反查回该快照。
- V7（不可删）：对被引用的快照调用删除接口返回拒绝，
  响应中回显当前引用它的绑定点清单，并写入安全审计。
- V8（幂等/并发）：同一绑定点对同一目标重复提交只产生一条绑定记录；
  并发建立绑定不产生重复或悬空记录。
- V9（权限态）：逐一使用 引导师、项目经理、签署人、发布人、组长、组员、观察者、未授权用户访问；
  门禁状态与绑定关系的返回严格符合 R5；观察者只拿到已发布内容的版本号。
- V10（依赖失败）：模拟门禁判定依赖不可用，绑定接口返回失败并**阻断**，
  不得返回成功或"待校验"的中间态。
- V11（一致性 · 反漂移）：对三处绑定点的绑定关系记录做结构断言——
  字段名、快照 ID 格式、版本号写法完全一致，不存在三套各自的表示法。
