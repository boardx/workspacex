## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-13.1 / 候选决策与签署
- **Actor**：**引导师**（提取复核与发起转签）、**项目经理**（维护签署授权矩阵）、
  **合伙人**（路径类决策的签署人）、**Echo**（AI 提取者，只提取不拍板）
- **目标**：[原型] 三个半小时现场里说过的话，凡是"像结论"的都要被捞出来，交给**有此类决策签署授权**
  的人拍板；拍板前必须能**回到原话**，拍板后进决策台账，不可静默修改。
- **本用例结果**：[原型]「候选决策 · 来自转写」中的每条候选只有三种去向——由有授权者签署后进入
  决策台账（带签字人与时间，原型实例「周宁 签字 · 7/25 12:30」）、被 `[请他签署]` 转给有授权的人、
  或留在**疑似结论池**（「像结论但没人拍板」）**不进台账**。
- **系统边界**：转写时间码引用、候选决策提取、原始音频回听、签署授权矩阵
  （**决策分类 × 授权人 × 有效期**）、签署与决策台账、疑似结论池与人工提升。
- **核心数据对象**：候选决策、转写时间码区间、依据引用（固定快照 `artifact@vN` + 节次）、
  提取者标记、签署授权（决策分类 / 授权人 / 有效期）、签署记录、决策台账条目、疑似结论。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式身份，且拥有目标项目的访问权。
  - [原型] 本场已产生**带时间码的转写文本**与对应的**原始音频**——「签署前可回听」直接依赖它，
    二者任一不可用时界面必须明确显示不可用状态（不是静默隐藏）。
  - [原型] 候选决策所引用的依据已是**固定快照**（原型实例 `依据 v2 · 第 3 节`）
    且已通过 **UC-13.2 验收**；未验收的产出不具备被决策引用的资格（见 R7）。
  - [设计] 项目内已配置**签署授权矩阵**：哪一类决策由谁签、授权到什么时候。
    ⚠ **原型只有两句运行态文案**——「须周宁签署（**合伙人 · 路径类决策**）」与
    「你有此类决策签署授权 · **有效期至 8/31**」。
    把它们抽象成一个**可配置的授权矩阵对象**（分类 × 授权人 × 有效期），
    以及该矩阵的**配置界面**，全是本文推论：**配置面属原型确认缺失**
    （项目设置六个子标签已完整抽取，无签署授权配置页）。
  - 涉及录音与原始转写的读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] Echo 从本场转写中识别出结论性表述，写入「候选决策 · 来自转写」列表。
  - [原型] 用户进入 `项目 → [进入项目] → 成果沉淀 → 结论与决策`（成果沉淀首页同名分区为同一数据）。
  - [原型] 授权人收到 `[请他签署]` 产生的待签通知（子标签徽标「结论与决策 **1 待签**」）后进入。
  - [设计] 有授权者把疑似结论池中的一条**提升**为候选决策。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **系统处理（Echo）**：持续读取本场转写，抽出结论性表述生成候选决策。**系统响应**：每条候选必须
   写齐三个锚点——**转写时间码区间**（原型实例 `转写 10:24:18–10:25:02`、`转写 11:48:30–11:49:11`）、
   **依据版本 + 节次**（原型实例 `依据 v2 · 第 3 节`、`依据 v2 · 第 5 节`）、**提取者标记**（`Echo 提取`）；
   三者缺一不得进入候选列表。
2. **系统处理**：按"有没有人拍板"分流。**系统响应**：能定位到明确拍板动作的进入「候选决策」列表；
   [原型] 判为「**像结论但没人拍板**」的进入**疑似结论池**，在分区底部聚合为一行
   「另有 **3 条**被 Echo 判为『像结论但没人拍板』，**不进台账**」`[查看]`。
3. **用户操作**：点开一条候选，点击其时间码区间**回听原话**。**系统响应**：按该区间定位并播放原始音频，
   同步高亮对应转写文本；音频或转写不可用时明确报错并**禁用签署入口**，
   不得静默降级为"只看文字也能签"（见 E3）。
4. **系统处理**：渲染签署入口前做**授权判定**。**系统响应**：按「**决策分类 × 当前用户 × 有效期**」
   三元组查签署授权矩阵，产生两态之一——
   - [原型] **无此类授权**：显示应签人与其分类，如「须周宁签署（**合伙人 · 路径类决策**）」，
     当前用户只得到 `[请他签署]`，不提供任何代签或临时提权入口。
   - [原型] **有此类授权且在有效期内**：显示「你有此类决策签署授权 · **有效期至 8/31**」，给出 `[签署]`。
5. **用户操作（无授权者）**：点 `[请他签署]`。**系统响应**：把该候选连同时间码区间、依据版本节次与
   回听入口一并转给授权人，生成待签任务与通知，成果沉淀子标签显示「结论与决策 **1 待签**」。
6. **用户操作（有授权者）**：回听后点 `[签署]`。**系统响应**：**在服务端**复核决策分类匹配与授权有效期；
   通过则写入决策台账，记录签字人与签署时间（原型实例「周宁 签字 · 7/25 12:30」）、
   所依据的快照版本与节次、签署时所用授权及其有效期；分类不匹配或授权过期一律拒绝并留痕（见 E2）。
7. **用户操作**：在疑似结论行点 `[查看]`。**系统响应**：列出疑似条目及其时间码与判定理由；
   [设计] 有授权者可把其中一条**提升为候选决策**，提升事件入审计。疑似结论在被提升并签署前
   **不进台账、不可被任何模块引用为依据**。
8. **系统收口**：校验 AC1「每条决策都能追到**是谁在第几分钟说的**」；刷新决策台账、成果沉淀首页
   「成果去向：**决策记录 3**」计数、以及 UC-13.4 发布分区的可发布性；把签署事件写入
   `成果沉淀 → 审计与反馈`（原型审计原文：「12:06:41 决策 林可签署『首批只做德国、荷兰』
   **依据 v2 · 授权有效期内**」）。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] **疑似结论路径**——Echo 判为「像结论但没人拍板」的表述**不进台账**、单列在疑似结论池，
    保留「可查看、可人工提升为候选决策」两个出口；未提升前不可被引用为决策依据。
  - A2：[原型] **转签路径**——当前用户无此类决策授权时唯一出口是 `[请他签署]`；
    系统不提供代签、临时提权或"本次例外"的绕行入口。
  - A3：[设计] **依据未验收**——候选引用的产出尚未通过 UC-13.2 验收时，候选仍可展示与回听，
    但签署入口禁用并提示「依据尚未验收，不能作为决策证据」，同时给出跳转产出物验收的入口。
  - A4：[原型/补全] 本场尚无候选决策时展示真实空态、原因与下一步入口，不生成示例数据冒充真实结果；
    不得丢失当前上下文。
- **异常流程**：
  - E1：[原型] **像结论但没人拍板的表述不进台账**，单独列出；系统不得因"看起来是结论"自动入账，
    也不得把疑似结论混入可引用依据的候选集。
  - E2：[Backlog] **签署授权有有效期，过期需重新授权**（Backlog UC-13.1 `edge` 原文）；
    [原型] 「有效期至 8/31」这一**运行态文案**可证有效期字段存在。
    [设计] 过期即**拒绝签署**并提示需重新授权；判定在服务端，越权/过期尝试写安全审计。
    ⚠ **过期态（拒绝签署）在原型中从未渲染**——只有「授权有效期内」的正常态。
  - E3：[设计] **回听不可用**——原始音频缺失、转码未完成或时间码越界时，明确说明原因、
    **禁用签署**，并提供重试与"申请补传音频"的出口；**不得静默降级**为仅凭文本签署。
    ⚠ [原型] 可证的只有一句「**签署前可回听**」；
    **回听的失败态与「回听不可用 → 禁用签署」这条联动，原型确认缺失**——
    候选决策分区已完整抽取，无任何不可用态。
  - E4：[设计] **已签署决策要求修改**时不得静默改写；只能新增一条"更正决策"并标注被替代关系，
    原条目在台账与审计中保留。
  - E5：[设计] 依据快照在签署后被撤回（证据撤回）时，**不修改已签决策，也不修改快照内容**；
    在引用处标注「证据已撤回」并通知拍板人复核（对齐 `phase-1/00-core/uc-0-1` E5 与 D-19）。
  - E6：[设计] 同一候选被两名授权者并发签署时只落一条签署记录，另一方收到「该决策已被签署」提示，
    不产生两条同内容决策。
  - E7：[设计] 请求超时、网络中断或转写/音频服务不可用时，保留用户当前输入与最后成功数据，
    明确失败原因并提供安全重试；失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E8：[设计] 权限或签署授权在操作过程中被撤回时立即终止后续写操作；已完成签署按审计规则保留，
    未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

- [原型] **签署授权与角色正交**：**角色决定看得见什么，授权矩阵决定签得了什么**；两者都在服务端判定。
  引导师身份本身不蕴含任何签署授权。
- **引导师**：可查看全部候选决策与疑似结论、回听全场原始音频、发起 `[请他签署]`；
  **能否 `[签署]` 完全取决于授权矩阵**。
- **项目经理**：同引导师；另可维护本项目的签署授权矩阵（决策分类、授权人、有效期）。
- **合伙人**：[原型] 持有**路径类决策**等高影响分类的签署授权，可在有效期内直接签署。
- **组长 / 组员**：可查看已签署的决策台账条目与其签字人、时间；不可签署；
  不可回听非本组的原始转写。
- **观察者**：[原型] **只读**——仅可见**已发布**的结论与签字人、时间；原始转写、回听入口、
  疑似结论池一律不可见（接口层不返回，不是前端隐藏）。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 决策台账中每条决策都带：结论文本、**转写时间码区间**、**依据快照版本与节次**、**提取者**、
    **签字人与签署时间**、签署时所用授权及其有效期。
  - 成果沉淀首页「成果去向：**决策记录 3**」与子标签徽标「结论与决策 N 待签」如实更新。
  - 签署事件同步进入 `成果沉淀 → 审计与反馈` 的四类事件时间线（决策类），且**不可删除**。
  - [Backlog验收] AC1：每条决策都能追到**是谁在第几分钟说的**（Backlog UC-13.1 `ac` 原文）；
    [原型] 转写时间码区间与「签署前可回听」文案可佐证。
  - [原型验收] AC2：签署入口的可用性由「**决策分类 × 授权人 × 有效期**」三元组唯一决定。
  - [Backlog验收] AC3：像结论但没人拍板的表述不进台账、单独列出（Backlog UC-13.1 `edge` 原文）；
    [原型] 「另有 3 条被 Echo 判为『像结论但没人拍板』，不进台账 [查看]」可佐证。
    [设计] 也不出现在任何"可引用依据"选择器里。
- **失败后置条件**：
  - 不创建"看似已签"的决策记录；越权或过期签署尝试必须留下安全审计记录。
- **不包含**：
  - 静默修改已签署决策（更正只能新增条目 + 标注被替代）。
  - 电子签名法律效力认定、CA 证书与数字签名密钥体系（[待确认]，见 R10）。
  - 产出物验收（属 UC-13.2）与发布动作本身（属 UC-13.4）。
  - 不扩展到本 use case 未声明的跨组织、跨客户或公开发布能力。

## R7 业务规则（不随具体实现变化的硬性约束）

- [Backlog] **指定签署人，签前可回听原话**（Backlog UC-13.1 `flow` 原文）；
  [原型] 候选决策分区常驻文案「**签署前可回听**」。
  [设计] 回听不可用时**禁用签署**，**不得静默降级**为仅凭转写文本签署
  ——**该联动原型确认缺失**，见 R4·E3。而 R11 把它列为「价值核心」，落地前须先补画。
- [原型] **每条候选必须带三锚点**：转写时间码区间 + 依据快照版本与节次 + 提取者标记，缺一不入列表。
- [原型] **签署授权是「决策分类 × 授权人 × 有效期」三元组**：授权**带有效期**
  （原型实例「有效期至 8/31」），**过期即失效**，需重新授权；判定必须在**服务端**执行；
  越权签署被拒绝并写入安全审计（留痕）。
- [原型] **疑似结论不进台账**：被判为「像结论但没人拍板」的表述单列、可查看、可人工提升为候选决策，
  但在被提升并签署前**不可被任何模块引用为依据**。
- [原型] **验收后才会成为可被决策引用的证据**——定版为**固定快照**是必要条件、**不是充分条件**；
  候选决策所引用的产出还须经 **UC-13.2 验收**后才获得证据资格。
  快照语义（三模式绑定 / 不可变 / 引用资格门控）由 `phase-1/00-core/uc-0-1` **唯一定义**，
  本文只引用、不重复定义；13-deliv 全模块的绑定点与门禁链见 **UC-13.5**。
- [原型] **决策绑定的是当时的快照**：`依据 v2 · 第 3 节` 一经签署即固定在 v2，不随源更新；
  源升到 v3 不改变已签决策的依据（「旧版仍被引用是正常的」）。
- [设计] **已签决策不可静默修改**：更正只能通过新增"更正决策"条目 + 标注被替代关系完成。
- [原型] AI（Echo）**只提取、不拍板**：候选决策必须标识为机器提取（`Echo 提取`），
  且在被人签署前不产生任何业务效力。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 提取、回听、请他签署、签署、提升疑似结论、越权尝试都必须记录审计事件，并显示动作影响范围。

## R8 界面线索

- **前端入口**：[原型] `项目 → [进入项目] → 成果沉淀 → 结论与决策`；同一数据亦呈现在
  **成果沉淀 · 首页**的「**候选决策 · 来自转写**」分区。子标签带计数徽标「结论与决策 **1 待签**」。
- **信息架构**：[原型] 成果沉淀五个子标签——洞察报告 · 对话生成 ｜ **结论与决策 1 待签** ｜
  产出物 4 ｜ 行动项 3/11 ｜ 审计与反馈 214。本用例占「结论与决策」。
- **推荐交互**（以下均为 [原型] 已画）：
  - 分区标题旁的口径说明：「每条带引用位置，**签署前可回听**」。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。
  - [设计] **回听定位**：点击时间码到音频开始播放应在 2 秒内完成；应支持按区间取片段，
    不得为播放 44 秒片段而下载整场 3 小时 30 分录音。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
  - [设计] 回听音频的访问地址必须是**短时效、按授权签发**的，不得是可长期分享的公开链接。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R10 已知约束 / 依赖

- **内部依赖**：
  - **实时转写与原始音频存储**（时间码区间 + 回听），无此二者本用例的核心硬约束无法成立。
  - **UC-13.2 产出物验收**——依据的证据资格闸门（「验收后才会成为可被决策引用的证据」）。
  - **`phase-1/00-core/uc-0-1`**（快照绑定协议，唯一定义方）与 **UC-13.5**（13-deliv 绑定点与门禁链）。
  - 签署授权矩阵的角色数据源：`phase-1/00-core/uc-0-3` 组织角色 × 项目角色两层正交模型。
- **被依赖**：UC-13.4 发布（发布内容含已签结论与签字人）、10-report 报告的「决策」来源角标、
  09-kg 决策入图、14-brain 决策台账与知识晋升（D-32：「支撑过一个被签字的决策」才够格晋升）。

## R11 切分提示（给 requirement-author）

- 建议先拆「候选决策数据模型（三锚点）→ Echo 提取与疑似结论分流 → **回听服务与签署禁用门控** →
  **签署授权矩阵（分类 × 授权人 × 有效期）** → 签署与决策台账 → 疑似结论提升 → 审计/通知 → 自动化验收」。
- **「回听门控」与「授权矩阵」是本用例的两个价值核心**，必须各自成 feature 并有独立验收，
  不能并进"签署服务"里一起做——它们是两条独立的拒绝路径。
- 单个 feature 应能在一次会话内实现并验证，不应把本 use case 的全部前后端与所有异常态塞进一个 feature。
- **优先级 / 先后依赖**：P0；**8 点**；阶段二 · 迭代 7 · 成果可交付；
  依赖实时转写与原始音频可用，且需在 UC-13.2 验收闸门之后接入证据资格判定。
- 对 P0 必做链路优先实现成功态、权限态与数据闭环，异常态不得延期到上线后。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态 · AC1）：决策台账接口对每条已签决策返回 `transcript_start`、`transcript_end`、
  `basis_artifact_version`、`basis_section`、`extracted_by`、`signed_by`、`signed_at` 七个字段且非空；
  用 `transcript_start`/`transcript_end` 请求音频片段接口能取到对应区间的音频流。
- V2（硬约束 · 回听）：把该决策对应的原始音频置为不可用后调用签署接口，**返回拒绝**且错误信息指向
  「无法回听」；界面签署按钮为禁用态，且不存在任何绕过路径（直接调接口同样被拒）。
- V3（授权态 · 403）：用**不持有该决策分类签署授权**的用户调用签署接口，返回 **403**，
  并在安全审计中新增一条越权尝试记录（含操作者、时间、候选 ID、被拒原因）；
  该用户的候选详情接口只返回 `can_sign=false` 与 `[请他签署]` 动作。
- V4（有效期态）：把某授权的 `valid_until` 改到当前时间之前，同一用户对同类决策调用签署接口
  返回拒绝，错误指向「授权已过期」；界面显示的过期态文案与"从未授权"态不同。
- V5（疑似结论）：疑似结论列表接口返回条目的 `in_ledger=false`；用其 ID 调用
  「引用为决策依据」接口返回拒绝；决策台账列表接口的返回集不含这些 ID。
  把一条疑似结论提升为候选后，其 ID 出现在候选列表且审计中有一条提升事件。
- V6（证据资格）：对**未通过 UC-13.2 验收**的产出版本调用「引用为决策依据」接口返回拒绝，
  错误指向「需先验收」；该版本通过验收后同一调用成功。
- V7（快照固定）：签署后把依据 Artifact 升到 v3，再读该决策的依据字段仍为 `v2 · 第 3 节`，
  且按该引用读取的内容与 v1 定版时字节一致。
- V8（不可静默修改）：对已签署决策调用更新/删除接口全部返回拒绝；只能通过「新增更正决策」接口写入，
  新条目携带 `supersedes` 指向原条目，原条目仍可读。
- V9（并发态）：两名有授权者同时签署同一候选，只产生一条签署记录，另一方收到「已被签署」提示。
- V10（权限态）：逐一使用 引导师、项目经理、合伙人、组长、组员、观察者、未授权用户访问；
  观察者接口不返回原始转写内容、回听地址与疑似结论池，只返回已发布结论及其签字人与时间。
- V11（空态）：本场尚无候选决策时显示真实空态与下一步，不生成伪数据。
- V12（审计态）：提取、回听、请他签署、签署、提升疑似结论五类事件可按操作者、时间、对象检索；
  签署事件的审计行含「依据 vN · 授权有效期内」信息（对齐原型审计流水），且**不可删除**。
