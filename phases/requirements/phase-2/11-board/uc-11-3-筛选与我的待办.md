>
> **[人类已拍板 2026-07-27 · D-29]** 本用例是**看板内的筛选视图**；
> **UC-11.5「我的今天」是独立的语义分区视图**。两者**并存、不互相取代**——
> 同一批卡的两种组织方式，状态源是同一套 `status` enum。
> **[D-39]**「我的」筛选按**负责人（人）**过滤；agent 执行中的卡通过「**执行者**」字段单独可筛。
>
> **[本次修订新增 · `scope` 维度]** 筛选不是一维四项，而是 **`scope` × `filter` 二维**：
> - **`scope`（作用域）**：`project`（限定单个项目）｜ `global`（跨全部有权项目）。
>   项目内视图 `scope` 锁定为当前项目并不渲染切换器；全局视图默认 `global`。
> - **`filter`（口径）**：[原型] **逐字四项** `全部 ｜ 我的 ｜ 现场 ｜ 逾期与今天`。
>
> 同一个 `filter` 在两个 `scope` 下**语义相同、范围不同**（如 `我的` 在 `global` 下＝
> 我在所有项目里负责的卡）。`scope` 与 `filter` 是**正交的两个字段，禁止合并成一个枚举**。
> 本文中凡出现 `scope` 一律指作用域，四项口径一律称 `filter`。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-11.3 / 筛选与我的待办
- **Actor**：**项目经理**、**引导师**、**组长**、**组员**
- **目标**：[原型] 人多任务多时，在同一块看板上用一行筛选把范围收窄到「跟我有关的」「现场的」
  「今天要处理的」，列结构不变、只变卡集合。
- **本用例结果**：用户在看板顶部切换 `filter`（并在全局视图下可另选 `scope`）后，
  四列（或五列）中的卡集合与各列计数同步收窄，
  列结构与 `status` enum 不变；组员进入时默认已应用「我的 + 本组」范围。
- **系统边界**：**`scope` 维度（`project` / `global`）**、看板顶部 `filter` 栏
  （全部 / 我的 / 现场 / 逾期与今天）、**二者的二维组合语义**、统一标签筛选、
  按角色的默认筛选范围、筛选与列计数的联动、筛选状态的保持与分享。
  **不含**语义分区视图（属 UC-11.5）、不含状态机（UC-11.1）。
- **核心数据对象**：
  - **`scope`（作用域）**：`project`（含具体 `project_id`）｜ `global`（跨全部有权项目）。
    **这是筛选的第一维**，决定「在多大范围里找」。
  - **`filter`（口径）**：`all` / `mine` / `onsite` / `overdue_or_today`，
    对应原型逐字四项 `全部 / 我的 / 现场 / 逾期与今天`。**这是筛选的第二维**，
    决定「在那个范围里要哪一批」。
  - **次级条件（可叠加）**：`owner_is_me`、`executor`（人 / 某 agent / 全部）、
    `source_kind[]`（六类来源徽标）、`tag[]`（统一标签）、`group_id`、`due_window`。
  - **默认筛选策略**：角色 → 进入看板时预置的 `scope` + `filter` + 次级条件
    （组员默认「我的 + 本组」）。
  - **筛选结果计数**：各列卡数 + 底注逾期/今天到期计数，随 `scope × filter` 实时重算。
  - **最终结果集** = `scope` ∩ `filter` ∩ 次级条件 ∩ **权限可见集**（四者相交，见 R7）。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“各模块的任务产生点（图谱、报告、访谈、会前任务）”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] 人多任务多时，用户在看板顶部点击 `全部 ｜ 我的 ｜ 现场 ｜ 逾期与今天` 中的一项。
  - [设计] 或用户进入看板——系统按其项目角色自动应用默认筛选范围（组员默认「我的 + 本组」）。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

0. **系统确定 `scope`（第一维）**：
   - **项目内视图**（`项目 → [进入项目] → 待办`）：`scope` 恒为 `project` 且**锁定为当前项目**，
     **不渲染 scope 切换器**——这一屏本来就只讲一个项目。
   - **全局视图**（`任务 → 项目看板`）：`scope` 默认 `global`（跨全部有权项目），
     [设计] 可下拉切到某个具体项目（等价于 `project`）。
   - **系统响应**：`scope` 只决定「在多大范围里找」，**不改变 `filter` 的语义**，
     也不改变列结构。项目内视图接口收到 `scope=global` 时必须拒绝（400），不得静默升维。
1. **系统预置默认筛选**：用户进入看板时按项目角色应用默认范围——
   项目经理/引导师默认「全部」；组长默认「本组」；[原型] **组员默认只看自己和本组的**。
   默认范围在筛选栏上明示为已选中态，用户可手动放宽到其权限允许的最大范围（不能超出 R5）。
2. **用户操作**：点击 `filter` 项（第二维）。**系统响应**：在**当前 `scope` 之内**
   按四种口径重算卡集合，**列结构与 `status` enum 不变**，只变每列的卡集合——
   - `全部`：当前视图作用域内该用户有权见的全部卡。
   - **`我的`**：**[D-39] 按 `owner`（负责人，恒为人）等于当前用户过滤**。
     注意：**不按执行者过滤**——一张负责人是我、执行者是 Scout 的卡属于「我的」；
     一张负责人是别人、执行者是我的卡不属于「我的」。
   - `现场`：按 `source_kind = 现场` 过滤（六类来源徽标之一）。
   - `逾期与今天`：按 `due_at < 今天` 或 `due_at = 今天` 过滤，对应底注计数 `逾期 1 · 今天到期 2`。

   **`scope` × `filter` 的八种组合语义**（口径相同、范围不同）：

   | `filter` | `scope = project` | `scope = global` |
   |---|---|---|
   | **全部** | 本项目内我有权见的全部卡 | 我有权见的全部项目的全部卡 |
   | **我的** | 本项目内 `owner = 我` 的卡 | 我在**所有项目**里负责的卡 |
   | **现场** | 本项目内 `source_kind = 现场` 的卡 | 所有项目的现场型卡 |
   | **逾期与今天** | 本项目内今天该处理的卡 | 我有权见的所有项目里今天该处理的卡 |

   [设计] `scope = global` 时卡片必须**额外显示所属项目名**，否则跨项目的卡无法区分归属。
3. **用户操作**：叠加**统一标签筛选**（`tag[]`，与其它模块共用同一套标签体系）与
   **执行者筛选**（[D-39] `executor` 为某 agent / 为人 / 全部），与第 2 步的四种口径**可组合**，
   多条件之间取交集。**系统响应**：交集为空时显示真实空态并给出「清除筛选」出口。
4. **系统响应**：每次筛选变更后**同步重算各列计数与底注逾期/今天到期计数**，
   与卡集合来自同一次查询；**未接受的 `inbox` 卡不进入任何筛选口径的列计数**（见 UC-11.2 R7）。
5. **系统保持筛选态**：筛选条件写入 URL query 并在会话内保持，刷新、返回、分享链接后条件不丢；
   [设计] 分享给他人时对方按**自己的权限**重新求交集，**不得因为链接携带条件而越权看到卡**。
6. **系统收口**：筛选是读操作，**不写业务审计**；但越权尝试（请求超出自己权限的范围）
   必须写安全审计。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] **观察者不可见待办看板**——观察者进入项目时该标签不渲染，接口直接 403，
    不是「渲染一个空看板」。
  - A2：[设计] 筛选交集为空时显示「当前筛选下没有卡」+ 当前生效的条件清单 + 一键清除，
    **不生成示例卡**、也不静默回退到「全部」。
  - A3：[设计] 用户手动放宽到超出其权限的范围时，界面只提供其权限内的选项；
    直接改 URL 参数的越权请求按 R5 裁剪结果而非报错泄露存在性。
- **异常流程**：
  - E1：[设计] 筛选请求超时或失败时保留上一次成功的卡集合并显式标「筛选未生效」，
    **不得展示旧数据却假装是新筛选结果**。
  - E2：[设计] 筛选期间有卡被他人改状态时，下一次轮询/推送刷新卡集合与计数；
    不做静默局部更新导致计数与卡集合不一致。
  - E3：[设计] 权限在浏览过程中被撤回时立即刷新卡集合，已不可见的卡从界面移除并提示原因。

## R5 权限与可见性

- **项目经理 / 引导师**：可筛全项目范围；「我的」按其本人负责人身份过滤。
- **组长**：筛选范围上限为本组 + 分派给自己的卡；不能通过筛选看到别组卡。
- **组员**：**默认且上限均为「自己 + 本组共享」**；「我的」进一步收窄到 `owner = 自己`。
- **观察者**：**不可见待办看板**，筛选接口对其直接拒绝。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。
- **筛选不是权限**：筛选只在用户已有权限的卡集合内做投影；
  放宽筛选**不能**扩大可见范围，服务端必须先按权限裁剪再按筛选过滤。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 卡集合与各列计数、底注逾期/今天到期计数在筛选后保持一致。
  - 筛选条件可持久化到 URL 并在会话内保持。
  - [Backlog验收] AC1：切换筛选时列内计数同步更新（Backlog UC-11.3 `ac` 原文）。
  - [设计验收] AC2：「我的」筛选的结果集恒等于 `owner = 当前用户` 的卡集合，
    与 `executor` 字段无关。
  - [设计验收] AC3：任何筛选组合下返回的卡都是当前用户本就有权见的卡；
    放宽筛选不会让结果集超出权限集合。
  - [设计验收] AC4（**`scope` × `filter` 正交**）：对同一个 `filter`，
    `scope = project(A)` 的结果集恒等于 `scope = global` 结果集中**归属项目 A 的那个子集**——
    换 `scope` 只换范围，不换判定口径。
  - [设计验收] AC5：`filter` 四项的文案与顺序恒为 `全部 / 我的 / 现场 / 逾期与今天`，
    不存在第五项；`scope` 与 `filter` 在接口层是两个独立参数。
- **失败后置条件**：
  - 不展示「看似筛过」实则是旧结果的卡集合；筛选失败必须显式可见。
- **不包含**：
  - **「我的今天」语义分区视图（属 UC-11.5）**——[D-29] 两者**并存不互斥**：
    本用例是**看板内的筛选视图**（列结构不变、只收窄卡集合），
    UC-11.5 是**独立的语义分区视图**（换一套按「谁该动、在等谁」的分区组织方式）。
    **两者不互相取代**，读同一套 `status` enum 与同一批卡。
  - 状态机与列投影（UC-11.1）、汇入与接受（UC-11.2）、提醒与催办（UC-11.4）。
  - 自定义筛选器的保存与命名、跨项目的聚合筛选（[待确认] 是否需要）。
  - 完整项目管理套件、第三方 IM 通知。

## R7 业务规则（不随具体实现变化的硬性约束）

- **[原型 · 逐字约束] 四种筛选口径**：`全部` ｜ `我的` ｜ `现场` ｜ `逾期与今天`。
  **文案、顺序、数量三者均为原型明确行为**，不得改写为「未完成/已完成」之类的等价物，
  也不得增删第五项。次级条件（统一标签、执行者）另置一层，多条件取交集。
- **[设计 · 硬约束] 筛选器 = `scope` × `filter` 二维正交**：
  `scope ∈ {project, global}` 决定**范围**，`filter ∈ {全部, 我的, 现场, 逾期与今天}` 决定**口径**。
  - 两者是**两个独立字段**，**禁止合并成一个枚举**（如禁止出现 `global_mine` 这类取值）；
  - 同一个 `filter` 在两个 `scope` 下**语义完全相同**，只有范围不同——
    `我的` 永远是 `owner = 我`，不因 `scope` 变化而改判定；
  - **项目内视图的 `scope` 锁定为当前项目**，接口收到 `scope=global` 必须拒绝；
    全局视图默认 `global`，可下切到某个 `project`；
  - `scope` **不是权限机制**：`global` 只是「跨我有权的全部项目」，
    不会因为选了 `global` 而看到无权项目的卡。
- **[D-39 · 硬约束]「我的」按负责人（人）过滤**：`我的` = `owner = 当前用户`。
  **agent 执行中的卡通过「执行者」字段单独可筛**，不混进「我的」口径。
  这与 UC-11.5「AI 正在替我跑」分区口径一致：那一区按 `executor` 归属，负责人仍是我。
- **[D-29] 筛选视图与语义分区视图并存**：本用例改变的是**卡集合**，
  UC-11.5 改变的是**组织方式**；同一批卡可以同时出现在两处，状态源是同一套 `status` enum，
  **禁止为两个视图各建一套状态或各存一份卡**。
- **[D-27] 未接受的 `inbox` 卡不进任何筛选口径的列计数**（含「我的」与「逾期与今天」），
  只在收件箱入口计数。
- **[原型] 组员默认只看自己和本组的**——这是**默认值**，不是权限上限的全部；
  权限上限另由 R5 规定。
- **[原型] 观察者不可见待办看板。**
- **筛选先裁权限、后过滤**：服务端必须先按角色裁剪可见集合再应用筛选条件，
  顺序颠倒会导致越权；隐藏筛选项不构成安全控制。
- 筛选是读操作不写业务审计；越权尝试写安全审计。

## R8 界面线索

- **前端入口**：[原型·**仅项目内视图**] 项目内待办看板顶部一行筛选：
  `筛选：全部 ｜ 我的 ｜ 现场 ｜ 逾期与今天`，右侧 `[＋ 新建待办]`。
  [设计] 项目内视图与全局视图**共用同一行 `filter`**。
  ⚠ **跨作用域断言，原型无据**：**全局**「任务 → 项目看板」顶部是
  「**维度切换：按行动方 / 按项目**」，**没有这四项筛选**。
  「共用同一行 filter」是本文的设计推论，须人类确认。
- **原型明确的界面元素**：
  - [原型] 四个 `filter` 项为**互斥单选**呈现（原型是一行并列文字），文案与顺序逐字固定；
    [设计] 标签筛选与执行者筛选作为可叠加的次级条件，需与四项主口径视觉分层。
  - [原型] 底注 `逾期 1 · 今天到期 2` 随筛选变化。
  - [设计] 折叠的 `inbox` 入口「收件箱 N」与筛选栏同排，但**不参与四项主口径的互斥**。
- **`scope` 切换器（[设计]）**：
  - 只在**全局视图**渲染，形态为项目下拉（含「全部项目」= `global`）；
    项目内视图**不渲染**该控件。
  - 与 `filter` 胶囊**视觉分离**，让用户看得出「范围」和「口径」是两件事。
  - `scope = global` 时每张卡需**加显所属项目名**，否则跨项目卡无法区分归属。
  - 非默认 `scope` 或非 `全部` 的 `filter` 生效时，页头需显式提示当前筛选并给一键清除——
    避免用户把筛过的空看板误读成「没有任务」。
- **必须呈现的状态**：
  - 默认态（角色默认筛选已应用且明示）、加载态、**筛选空态**（含条件清单与清除出口）、
    依赖失败态（筛选未生效）、无权限态（观察者）、成功态。

  需补确认的是：① 标签筛选与执行者筛选的控件位置（原型未画次级筛选）；
  ② 筛选空态的文案与清除出口形态；③ **`scope` 切换器的形态、默认值与卡上项目名的展示位置**
  ——`proto-02-batch2.md` 的「项目看板」标题写死为「项目看板·欧洲市场进入」，
  是否存在跨项目视图**未点开验证**，属**未探明**（不等于原型没做）。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 切换筛选应在 1 秒内给出结果；超过 1 秒显示加载态，且**不得先显示旧结果再悄悄替换**。
  - [设计] 筛选查询必须走服务端（带索引），不允许把全项目卡拉到前端再本地过滤——
    那会同时破坏性能与权限裁剪。
  - [设计] 卡集合与三处计数在一次响应内返回，避免两次请求造成计数漂移。
- **安全/隐私/合规**：
  - **服务端必须先按角色裁剪可见集合，再应用筛选条件**；顺序颠倒即越权。
  - 最小权限、组织/项目/小组隔离、敏感字段脱敏；筛选参数不得携带个人敏感数据。
- **兼容与降级要求**：
  - 响应式 Web；移动端保证四项主口径可用，次级筛选可折叠。
  - 实时通道不可用时降级为轮询并显示「非实时」，计数标注最后更新时间。

## R10 已知约束 / 依赖

- **内部依赖**：**UC-11.1**（`status` enum、列投影、三处计数）、**UC-11.2**（`inbox` 不计数规则）、
  身份与权限内核、**统一标签体系**（与其它模块共用同一套标签，不在本模块另建）。
- **并存关系（非依赖）· [D-29]**：**UC-11.5「我的今天」与本用例并存不互斥**——
  本用例是看板内的筛选视图（列结构不变、收窄卡集合），UC-11.5 是独立的语义分区视图
  （换一套按「谁该动」的组织方式）。二者读同一套 `status` enum 与同一批卡，
  **不得互相取代，也不得各自维护一份卡或一套状态**。实现上可并行，无先后依赖。
- **[D-39] 字段契约**：`owner`（人）与 `executor`（人或 agent）是两个独立字段，
  筛选层必须分别暴露；任何把二者合并为一个「负责人/执行人」字段的实现都违反裁决。
- **`scope` 契约**：`scope` 的取值域（`project` / `global`）与项目可见集判定来自
  phase-00 身份与权限内核，**不在本模块另定义**；`global` 的范围恒等于
  「当前用户有权访问的全部项目」的并集。
- **技术约束**：[原型] 产品为响应式网页（原型含移动端对照屏）；[Backlog] 完整离线模式、原生移动端、第三方 IM 为范围外。
- **[待确认]** 是否支持保存自定义筛选器（命名 + 复用）——原型只有四项固定口径。
- **[待确认]** **全局视图的 `scope` 切换器在原型中未探明**：`proto-02-batch2.md` 的「项目看板」
  标题写死为单一项目，跨项目视图**未点开验证**。本文按「存在 `global`」设计，
  **需人类确认；不得据此断言原型没做**。
- **[待确认]** `scope = global` 时是否允许跨项目拖动改列（本文按「不允许」保守处理）。
- **[待确认]** 「逾期与今天」的时区口径：按用户时区还是项目时区判定「今天」——
  `scope = global` 下卡可能跨多个时区的项目，此项必须先定稿才能实现。

## R11 切分提示（给 requirement-author）

- 建议拆分：
  ① **权限裁剪 + 筛选过滤的执行顺序**（服务端，先裁权限后过滤）；
  ② **`scope` 维度**（`project` / `global` 的范围求解、项目内视图锁定、卡上项目名）；
  ③ 四项 `filter` 主口径的查询实现（含「我的」按 `owner` 而非 `executor`）；
  ④ 标签与执行者的次级筛选叠加（交集）；
  ⑤ 角色默认筛选范围；
  ⑥ 筛选与三处计数的联动；
  ⑦ 筛选态（`scope` + `filter` + 次级条件）持久化到 URL 与分享时的权限重求交。
- **①、②、③ 必须各自有断言级验收**——「我的」口径搞错成按执行者过滤会直接违反 D-39；
  `scope` 与 `filter` 若被合并成一个枚举，后续加作用域会全量返工。
- **优先级 / 先后依赖**：P1；**5 点**（`scope` 维度为本次修订新增；Backlog 原估点 **3**）；

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（计数联动 · AC1）：造一批卡后依次切换四项筛选，
  断言每次响应中各列 `count` 等于该列返回卡数组长度，且底注 `逾期 N · 今天到期 M`
  与卡集合中 `due_at` 的实际统计相等。
- V2（「我的」口径 · AC2 · D-39）：造三张卡——
  ① `owner=我, executor=我`；② `owner=我, executor=Scout(agent)`；③ `owner=他人, executor=我`。
  以我的身份调「我的」筛选，断言结果集**恰为 {①, ②}**，**不含 ③**。
- V3（执行者筛选 · D-39）：对同一批卡调 `executor` 筛选（值为 Scout），
  断言结果集**恰为 {②}**，且该卡的 `owner` 仍返回为我——证明两个字段独立可筛。
- V4（现场筛选）：断言 `现场` 筛选的结果集恰为 `source_kind = 现场` 的卡集合。
- V5（逾期与今天）：把系统时间固定在某日，断言该筛选结果恰为
  `due_at <= 今日` 的未完成卡集合，且与底注计数一致。
- V6（多条件交集）：同时应用 `我的` + `现场` + 某标签，
  断言结果集等于三个条件各自结果集的交集（可用集合运算在测试里独立算出对照）。
- V7（inbox 不计数 · D-27）：造 3 张 `inbox` 卡且负责人为我，
  断言在「我的」与「逾期与今天」筛选下的列计数均不含这 3 张。
- V8（权限先于筛选 · AC3）：以组员身份把筛选放宽到「全部」（直接改请求参数），
  断言返回集合仍不超出「自己 + 本组」；再取一张别组卡 ID 直接请求，断言 403/404。
- V9（角色默认）：以组员身份首次进入看板，断言响应中默认筛选条件已是「我的 + 本组」
  且界面标记为已选中。
- V10（观察者）：以观察者身份调看板与筛选接口，断言返回 403（而非空列表），
  且项目内该标签不在导航响应中。
- V11（空态）：应用一组必然为空的筛选组合，断言返回空数组 + 空态标识 + 当前条件清单，
  **不返回任何示例卡**、也不自动回退到「全部」。
- V12（筛选态持久化）：带筛选参数的 URL 刷新后条件不丢；
  把该 URL 交给一个权限更小的用户打开，断言其结果集按自己的权限重新求交，未泄露越权卡。
- V13（与 UC-11.5 并存 · D-29）：同一批卡分别调本用例的筛选接口与 UC-11.5 的分区接口，
  断言两者返回的卡的 `status` 取自同一字段、同一取值域，
  且同一张卡可同时出现在「我的」筛选结果与「今天该我推进」分区中——**两个视图不互斥**。
- V14（安全审计）：越权筛选尝试写安全审计记录，可按操作者与时间检索。
- V15（`scope` × `filter` 正交 · AC4）：同一用户在项目 A、B 各有卡；对 `filter = 我的`
  分别调 `scope=global` 与 `scope=project(A)`，
  断言后者的卡 ID 集合**恰等于**前者中归属 A 的子集；对其余三个 `filter` 重复同一断言。
- V16（接口参数独立 · AC5）：断言筛选接口的 `scope` 与 `filter` 是**两个独立参数**；
  构造合并式取值（如 `filter=global_mine`）断言返回 400。
- V17（项目内视图锁定 `scope`）：对项目内看板接口传 `scope=global`，断言返回 400；
  不传 `scope` 时断言服务端按当前项目求解，且响应回显的 `scope` 为 `project` + 该项目 ID。
- V18（`global` 不越权）：用户对项目 C 无权限；在 `scope=global` + `filter=全部` 下
  断言结果集不含任何 C 的卡。
- V19（`global` 显示项目名）：`scope=global` 的响应中每张卡带非空的 `project_id` 与项目名；
  `scope=project` 时该字段可省略。
- V20（`filter` 四项逐字 · AC5）：读取筛选行配置接口/DOM，断言四项文案与顺序恒为
  `全部 / 我的 / 现场 / 逾期与今天`，且不存在第五项。
