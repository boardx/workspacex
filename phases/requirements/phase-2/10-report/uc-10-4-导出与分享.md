## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-10.4 / 导出与分享
- **Actor**：**引导师**、**项目经理**、**客户**
- **目标**：把一份内部写成的洞察报告变成**可以交出去的东西**——导出文件或只读链接，
  并且分**客户版 / 内部版**两种口径；交出去之后，还要能处理「**证据后来被撤回了**」这件事。
- **本用例结果**：报告的某个版本被发布/导出，**绑定一份固定快照**，接收方按其角色看到相应口径的内容；
  发布记录含发布人、范围、时间、绑定版本；后续证据撤回**对内可见、对外走人工确认后替换**。
- **系统边界**：`[导出 / 分享]` 与 `[预览客户版]` 入口、客户版 / 内部版口径差异、
  只读链接（有效期与撤销）、发布与固定快照绑定、访问留痕、**D-19 撤回后的对内标注与对外替换流程**。
- **核心数据对象**：发布记录（版本 + 快照 ID + 范围 + 发布人 + 时间）、只读分享链接、
  导出任务与产物、访问日志、**待人工确认的替换队列**、保留意见（去署名）。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“知识图谱、访谈、实时转录、成果沉淀”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **前置条件（补充）**：
  - [原型] 报告**无未挂来源的灰态段落**（UC-10.2 硬约束）。
  - [原型] 报告**无未补齐的缺料项**（UC-10.3 门禁链第 2 段）——否则不得对客户发布。
  - 发布者具备**发布授权**（原型：「发布人：林可 · 引导师（**有发布授权**）」）。
- **触发条件**：
  - [原型] 用户在**报告工作台右栏顶部**点 `[导出 / 分享]`（与 `[重写这一版]` 并列）。
  - [原型] 用户在**成果沉淀首页**点 `[导出报告 / 分享链接]`。
  - [设计] 用户在**成果沉淀首页**点 `[预览客户版]`（**原型待补**：按钮存在但点击无反应，
    见 R8「原型待补」条；按钮之后的行为一律 `[设计]`）。
  - [设计] 上游证据被撤回（UC-10.5）时，系统对已发布内容生成一条**待人工确认的替换项**，
    由本用例的替换流程承接。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **用户操作**：在报告工作台右栏顶部点 `[导出 / 分享]`。**系统响应**：先跑发布前置检查——
   ① 灰态段落数为 0（UC-10.2）② 缺料项已清零（UC-10.3）③ 当前用户有发布授权；
   任一不通过则阻断并指向具体阻塞项（哪几段没来源、哪几块缺料、缺什么授权）。
2. **用户操作**：选择**口径**（客户版 / 内部版）与**出口**（导出文件 / 只读链接）。
   **系统响应**：按口径渲染差异——

   | | 内部版 | 客户版 |
   |---|---|---|
   | 结论与依据 | 全部 | 全部 |
   | **分歧与保留意见** | **含分歧全文 + 提出人署名** | [D-40] **保留意见随结论一起发布，但去掉署名**——显示「1 条保留意见」及其内容，**不显示提出人** |
   | 原始转写 / 私聊 | 可见 | **不可见** |
   | 过程性材料（各组画布草稿、被推翻的假设） | 可见 | 不可见 |
   | 来源角标 | 完整可展开 | 保留可追溯性，但不暴露未脱敏的原始材料 |

   [设计] 用户可先点 `[预览客户版]` 在发布前看到客户实际会看到的样子
   （**原型待补**——该按钮未接线，见 R8）。
3. **用户操作**：确认发布范围与出口，点发布。**系统响应**：[原型] **发布必须绑定一个确定的产出版本**
   ——把本次发布绑定到该报告的**固定快照**；快照的不可变语义（不可变、不可删除、只能新增版本 +
   标注被替代）**统一由 `phase-1/00-core/uc-0-1` 定义，本文不重复定义**，只声明发布必须引用它。
   发布记录写入：绑定版本号与快照 ID、发布范围（如「项目成员 ＋ 客户方 3 人」）、
   发布人及其授权、发布时间。
4. **系统处理（出口生成）**：
   - **导出**：生成文件产物；导出任务显示排队/运行/完成/失败，产物与快照 ID 关联。
   - **只读链接**：生成外部可访问的只读链接，**可设有效期并可单独撤销**；
     链接指向的是快照，不是工作版本，因此源报告后续改动不影响已发出的链接内容。
5. **系统处理（访问留痕）**：记录**谁在什么时候看过**——每次通过链接的访问写入访问日志
   （访问者标识、时间、IP/来源、访问的快照版本），可在项目级「审计与反馈」检索。
6. **系统处理（证据撤回后的分叉，D-19）**：当已发布内容引用的证据被撤回（详见 UC-10.5）：
   - **对内**：在引用处显示「**证据已撤回**」标注，对内部角色**立即可见**，正文不自动删除。
   - **对外**：**已发布给客户的内容不自动改写**，改为生成一条**待人工确认的替换项**进替换队列；
     由**有发布授权的人**确认后才执行替换，替换动作**留痕**（谁、何时、把哪一段换成什么、为什么）。
   - 两条路都不允许静默：既不静默改动已发布内容，也不对内隐藏撤回事实。
7. **系统收口**：校验 AC1「客户版里不出现任何未脱敏的原始材料」与 AC2「发布必须绑定固定快照」；
   记录发布、撤销分享、导出、访问、替换五类事件进项目级审计，并回写 UC-10.1 清单行状态为「已发布」。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] **只预览不发布**——`[预览客户版]` 只渲染客户口径，不产生发布记录、不绑定快照、
    不生成链接。（**原型待补**，见 R8；这三条边界是设计推论，不是原型已实现的行为。）
  - A2：[Backlog] **撤销分享**——已发出的只读链接可**单独撤销**（Backlog UC-10.4 `edge`；
    **原型确认缺失**，两处分享按钮均无撤销界面）；[设计] 撤销后链接立即失效，
    但已发布版本与其快照按审计规则保留（对应 UC-10.1「已发布报告不可删除，只能停止分享」）。
  - A3：[设计] **同一版本多次分享**——可对同一快照生成多条链接给不同接收方，各自独立设有效期
    与撤销，访问日志按链接区分。
  - A4：[设计] **发布新版本**——发布 v4 后 v3 的链接是否自动失效由发布者选择：
    「替换旧链接」或「两版并存」；默认**不自动失效**，因为「旧版仍被引用是正常的」（`uc-0-1`）。
  - A5：[设计] 报告为空或所有节均无内容时展示空态与原因，不生成示例内容冒充真实结果。
- **异常流程**：
  - E1：[Backlog] **链接可设有效期并单独撤销**（Backlog UC-10.4 `edge` 原文）；
    [设计] 过期或已撤销的链接访问时返回明确的失效说明页，
    **不暴露报告任何内容**，也不泄露报告是否存在之外的信息。
  - E2：[原型] 报告仍有灰态段落或未补齐缺料时，发布被阻断（见 R3 第 1 步），
    界面列出具体阻塞项与跳转入口。失败不得被呈现为成功。
  - E3：[设计] 导出任务失败时不产生半份文件；已生成的部分产物必须清理，
    任务状态显式为「失败」并可重试。
  - E4：[设计] **证据撤回但人工确认迟迟未做**——替换项在队列中超期时升级通知给
    **项目负责人与合规负责人**（[D-f] 以 `uc-10-5` R4·E3 为准，两处已统一）；
    期间对外内容维持原样（D-19 明确不自动改写），对内标注持续可见。
  - E5：[设计] 发布过程中权限被撤回时立即终止；已完成的快照绑定按审计规则保留，
    未完成的链接不生成。
  - E6：[设计] 并发发布同一报告时只产生一条发布记录，另一方收到「已被他人发布」提示并可查看。

## R5 权限与可见性

- **引导师**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **项目经理**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **客户**：只读已向其发布的结论、产出、报告、进度与脱敏聚合；只能通过反馈入口新增意见，不能改动项目正式内容。
- **观察者**：默认不能发起或修改；仅当内容已发布且授权范围允许时只读查看脱敏结果。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 存在一条发布记录，含**绑定的固定快照 ID**、版本号、范围、发布人、时间。
  - 只读链接可访问、可设有效期、可单独撤销；每次访问有留痕。
  - 所有跨模块回流均携带来源资源、版本、操作者/触发者、时间和可见范围。
  - [Backlog验收] AC1：客户版里不出现任何未脱敏的原始材料（Backlog UC-10.4 `ac` 原文）。
  - [设计验收] AC2：发布绑定的是固定快照；源报告后续改动不影响已发出的链接内容
    （快照语义由 `uc-0-1` 定义；**原型导出/分享面板未探明**）。
  - [D-40 验收] AC3：客户版含保留意见的内容与条数，但**不含提出人姓名**。
  - [D-19 验收] AC4：证据撤回后，对内引用处出现「证据已撤回」标注；
    对外已发布内容**字节不变**，同时替换队列中出现一条待人工确认项。
- **失败后置条件**：
  - 不创建“看似成功”的发布记录或链接；导出失败不留半份产物，失败事件进入可观测日志。
- **不包含**：
  - **导出配置面板的具体选项**（格式 / 范围 / 水印 / 页眉页脚等）——**下钻未探明**，
    待补抽取后再定；本用例只保证「导出」这个出口存在且受同一套门禁约束。
  - **引用展开层**（点来源角标之后的一层）与**版本历史**——同为未探明下钻。
  - 客户门户的账号体系与反馈回流（15-portal，D-22 已裁定进 phase-3）。
  - 无来源生成真实结论、静默覆盖已发布版本。
  - 不扩展到本 use case 未声明的跨组织、公开发布能力。

## R7 业务规则（不随具体实现变化的硬性约束）

- **[D-19] 证据撤回后的对内 / 对外二分（本用例第一硬约束）**：
  报告段落所引证据被撤回时——
  - **对内**：在**引用处**可见「**证据已撤回**」标注，内部角色立即可见，正文不自动删除、不隐藏。
  - **对外**：**已发布给客户的内容不自动改写**，必须走「**人工确认后替换**」流程；
    由有发布授权的人确认后才替换，**替换动作留痕**（操作者、时间、原文、替换后文本、理由）。
  - **两个方向都禁止静默**：不得静默改动已发布内容，也不得对内隐藏撤回事实。
  - 详细触发与影响面计算见 **UC-10.5**；本用例负责对外替换队列与确认闸门。
- [设计] **发布必须绑定固定快照**——发布记录必须引用一个不可变快照 ID，
  快照语义**由 `phase-1/00-core/uc-0-1` 统一定义，本文不重复定义**。
  链接与导出产物解析的都是快照，不是工作版本。
- [原型] **发布前置门禁**：有灰态段落（UC-10.2）或未补齐缺料（UC-10.3）时不得对客户发布；
  该判定必须复用 UC-10.3 的同一个门禁服务，不得另写一份。
- [原型] **发布人必须有发布授权**（原型：「发布人：林可 · 引导师（有发布授权）」）；
  授权在服务端校验，且授权可以有有效期。
- **[D-40] 保留意见对客户可见但去署名**：客户版**随结论一起发布**保留意见的内容与条数
  （显示「1 条保留意见」），**不显示提出人**。既不许因为对外就删掉保留意见，
  也不许把提出人姓名带出去。
- [Backlog] **客户版自动去掉过程、分歧与原始转写**（Backlog UC-10.4 `flow` 原文）。
  [设计] **客户版与内部版的差异是口径差异，不是两份内容**：两者渲染自同一快照，
  差异由发布口径规则决定；不得为客户版另存一份可独立漂移的正文。
  （[原型] 可佐证的是报告工作台的口吻快捷指令 `[内部版（含分歧）]` / `[客户董事会版]`。）
- [Backlog] **客户版里不出现任何未脱敏的原始材料**（Backlog UC-10.4 `ac` 原文，即 AC1）；
  [设计] 具体到不出现原始转写、私聊与过程性材料。
- [Backlog] **链接可设有效期并单独撤销**（Backlog UC-10.4 `edge` 原文）；
  [设计] 撤销后立即失效，但发布记录与快照保留。
  ⚠ **原型确认缺失**：成果沉淀首页只有一个 `[导出报告 / 分享链接]` 按钮，
  报告工作台只有一个 `[导出 / 分享]` 按钮，**均无有效期或撤销的界面**。
  「有效期三档 + 单独撤销 + 全部重置」是 **proto-08 的项目邀请链接**规则，
  那是**另一个对象**（进场身份链接），不能挪用为报告分享链接的原型依据。
- [设计] **每次访问留痕**：谁、何时、通过哪条链接、看的哪个快照版本。
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- AI/Agent 的写回、覆盖、发布或高影响工具调用必须遵守原型中的批准点；未经确认只保留为草稿或候选。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R8 界面线索

- **前端入口**（原型中已存在的三个按钮）：
  - [原型] **报告工作台右栏顶部 `[导出 / 分享]`**（与 `[重写这一版]` 并列，紧贴版本头 `v3 草稿`）
    ——路径：项目 → [进入项目] → 成果沉淀 → 洞察报告 → `[打开]` 报告工作台。
  - [原型] **成果沉淀首页 `[预览客户版]`**（与 `[发布结论 · 绑定 v2]` 并列）。
    ⚠ **该按钮在原型中点击无反应（空按钮，未接线到任何屏）**——按钮位置与上下文可签，
    **但它背后的预览屏属「原型待补」**，与「下钻未探明」是两回事：

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态 · AC1）：对同一快照分别请求客户版与内部版渲染，断言客户版响应体中
  **不含**原始转写文本、私聊内容、未脱敏原始材料与过程性材料的任一字段；
  内部版含上述内容。用关键词与字段名双重断言，不只看界面。
- V2（成功态 · AC2 快照绑定）：发布 v3 生成只读链接后，修改源报告并升到 v4；
  再次访问原链接，返回内容与发布时**字节一致**，且响应体中的 `snapshot_id` 不变。
- V3（成功态 · D-40 去署名）：内部版含一条保留意见及其提出人姓名；
  客户版响应体中**含该保留意见的正文与「1 条保留意见」的计数**，
  但**不含提出人姓名/用户 ID 的任何形式**。两侧保留意见条数相等。
- V4（硬约束 · D-19 对内）：撤回某条被已发布段落引用的证据后，以内部角色读取该报告，
  断言该引用处返回 `evidence_status = "withdrawn"` 且渲染出「证据已撤回」标注，
  正文内容未被删除。
- V5（硬约束 · D-19 对外不自动改写）：同一撤回发生后，立即以客户身份访问已发布链接，
  断言返回内容与撤回前**字节一致**（未自动改写、未自动隐藏）；
  同时断言替换队列中新增一条待人工确认项，指向该报告、版本、节号与被撤回证据。
- V6（硬约束 · D-19 替换需授权 + 留痕）：以**无发布授权**账号确认替换 → 返回 403；
  以**有发布授权**账号确认 → 替换生效，且审计中存在一条含
  操作者 / 时间 / 原文 / 替换后文本 / 理由 五要素的替换事件。
- V7（硬约束 · 发布前置门禁复用）：制造一个有灰态段落的报告与一个有未补齐缺料的报告，
  分别调用发布接口，均返回拒绝；断言两次拒绝与 UC-10.3 升版接口的拒绝来自**同一门禁服务**。
- V8（硬约束 · 发布授权）：无发布授权的引导师调用发布接口返回 403 并记审计；
  有授权者成功，发布记录中 `publisher` 与 `authorization` 非空。
- V9（链接有效期与撤销 · E1）：设置有效期后到期访问返回失效页且响应体**不含报告任何正文**；
  手动撤销后立即访问同样失效；断言撤销后发布记录与快照仍可在内部检索到。
- V10（访问留痕）：通过链接访问 3 次后，访问日志返回 3 条记录，每条含访问者标识、时间、
  链接 ID 与被访问的 `snapshot_id`。
- V11（口径同源）：客户版与内部版响应体中的 `snapshot_id` 相同——证明二者渲染自同一快照，
  不存在两份独立正文。
- V12（权限态）：逐一使用 引导师、项目经理、组长、组员、观察者、客户、未授权用户访问；

- V13（空态）：报告无任何已发布版本时，分享面板显示空态与「先发布一个版本」引导，

- V14（异常 E3）：注入导出失败，断言无产物残留、任务状态为「失败」且可重试。
