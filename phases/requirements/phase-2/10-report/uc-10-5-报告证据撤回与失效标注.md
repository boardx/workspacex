## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-10.5 / 报告证据撤回与失效标注
- **Actor**：**受访者 / 数据主体**（发起撤回）、**合规负责人**（执行删除队列）、
  **引导师**、**项目经理**（处理影响面）、**有发布授权的人**（确认对外替换）、
  **决策拍板人**（被通知复核）
- **目标**：一条证据（转写片段 / 访谈 / 研究 / 画布便签 / 投票 / 决策……）被撤回后，
  系统必须**在 5 分钟内让它逻辑失效**、**算清楚它影响了哪些报告的哪些节**、
  **对内如实标注、对外不擅自改写**，并在 30 天内完成物理删除且出回执。
- **本用例结果**：受影响的报告段落在**引用处**出现「证据已撤回」标注、段落降级为「待复核」；
  已发布给客户的版本**字节不变**，改为进入「人工确认后替换」队列；
  该证据**退出检索范围**但审计留痕保留；到期出具物理删除回执。
- **系统边界**：撤回触发接入、逻辑失效（≤5 分钟）、**主题矩阵与各处证据强度重算**、
  影响面反查（报告 × 版本 × 节号）、
  对内失效标注与段落降级、对外替换队列的产生（**确认与替换动作本身在 UC-10.4**）、
  快照不可变的处理方式、决策拍板人通知、退出检索、物理删除（≤30 天）与回执。
- **核心数据对象**：证据对象与其 `source_ref`、撤回事件、删除队列项、
  影响面清单（报告 ID × 版本号 × 节号 × 段落 ID）、失效标注、段落复核状态、
  对外替换队列项、检索索引条目、审计留痕、删除回执。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 该证据已被至少一份报告引用，或系统需要确认它未被任何报告引用。
  - 引用关系以 UC-10.2 定义的统一 `source_ref` 结构存在，可反查
    （报告侧只存引用不复制正文，这是反查可行的前提）。
  - 已定版的报告版本已绑定固定快照（`phase-1/00-core/uc-0-1`）。
- **触发条件**（任一即触发）：
  - **上游证据被撤回**——受访者撤回同意、研究员撤回一份研究、组长撤下一张画布便签、
    投票作废、转写片段被删除、决策被推翻并撤回其证据资格。七类取材来源都可能触发：
    **转写 / 访谈 / 研究 / 画布便签 / 投票 / 决策 / 对话**。
  - **被 UC-17.2 的删除队列命中**——合规侧把某个数据主体或某批材料放进待删除队列，
    队列命中的每一条证据都按本用例处理。
  - [设计] 证据所属的项目/组织执行数据主体删除请求（DSR）时批量触发。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **触发方操作**：受访者撤回同意 / 合规负责人把材料放入 UC-17.2 待删除队列 /
   研究员撤回一份研究。**系统响应**：生成一条**撤回事件**，记录证据 ID、撤回来源、
   撤回人、时间、撤回原因类别；事件立即进入处理管道，**不排队等夜间批处理**。
2. **系统处理（逻辑失效，D-15 第一级 SLA · ≤5 分钟）**：把该证据标记为 `withdrawn`，
   **在 5 分钟内**完成四件事：① 该证据**退出检索范围**（不再被任何检索、AI 取材、
   Context Pack 组装命中）② 所有指向它的 `source_ref` 被标记为失效
   ③ 新的报告生成不得再引用它 ④ **主题矩阵重算强度**（见第 3 步）。
   **这一级不删除任何字节，只是让它对业务不可用。**
3. **系统处理（主题矩阵重算强度，proto-04 第 02 步）**：[原型] 原话——
   「来自该场的 **7 条引述退出检索，主题矩阵重算强度**」。撤回一条证据后，
   凡是**把该证据计入过强度的聚合结构**都必须**重算**，不是打个标记了事：
   - **主题矩阵 / 主题聚合**（访谈与开放题归并出的「主题 × 提及计数 / 强度」）：
     被撤回的引述从计数中**扣除**，主题强度随之下降；某主题的支撑归零时，
     该主题降级而**不是**静默消失（要能看出它曾经存在过、因何降级）。
   - **UC-10.2 的节状态**：`N 条强证据` 的 N 随之减少；证据归零时该节转 `待补`；
     若撤回的是冲突双方之一，`N 处冲突` 也须重算（冲突可能因此消解，
     但**消解必须显式记录**，不得让正文里原有的冲突口径悄悄失去依据）。
   - **定题强度 / 决策树节点的证据计数**（09-kg「已有证据数」）同样重算。
   重算是**即时级**（并入 5 分钟 SLA），且重算前后的强度值都要留痕，可解释「为什么变了」。
4. **系统处理（影响面计算）**：**反查所有引用该证据的报告段落**，产出一份影响面清单，
   每条至少包含：

   | 字段 | 说明 |
   |---|---|
   | 报告 ID 与名称 | 哪一份报告 |
   | **版本号 vN** | 哪一版（工作版本 / 已定版快照 / 已发布版本各自列出） |
   | **节号与标题** | 影响第 03 节 / 第 04 节 |
   | 段落 ID | 精确到段落，不是整节 |
   | 该版本的对外状态 | 未发布 / 已发布给客户（决定走第 6 步还是第 7 步） |
   | 该段落是否为该节唯一证据 | 决定降级后是否整节变「待补」 |

   清单对引导师与项目经理可见，并可导出。
5. **系统处理（对内标注，D-19 对内）**：在**每一处引用位置**（来源角标处）加上
   「**证据已撤回**」标注，**对内部角色立即可见**；对应段落**降级为「待复核」**；
   **不自动删除正文**，也不自动重写。若该段落因此失去全部来源，
   按 UC-10.2 的标灰门禁转为灰态，从而**自动阻断后续发布**。
6. **系统处理（对外分叉，D-19 对外）**：对**已发布给客户**的版本——
   **不自动改写、不自动下线、不静默隐藏**。系统改为生成一条
   **「待人工确认的替换项」**进替换队列（队列与确认闸门在 **UC-10.4**），
   由**有发布授权的人**确认后才执行替换，替换动作留痕
   （操作者 / 时间 / 原文 / 替换后文本 / 理由）。确认前，客户看到的内容保持原样。
7. **系统处理（已定版快照）**：**撤回不修改快照字节**——已定版快照按 `uc-0-1` 是不可变的，
   本用例**只在引用处加标注**，不动快照内容。若该快照**支撑过已签字的决策**，
   **通知拍板人复核，不自动改结论**（对齐 `uc-0-1` E5）；通知含影响面清单与复核入口。
8. **用户操作**：引导师/项目经理处理影响面——补新证据、改写受影响节、或标记为「已复核·维持原结论」。
   **系统响应**：段落从「待复核」恢复正常需**显式人工动作**，不因时间流逝自动恢复；
   补齐新证据后走 UC-10.3 的缺料/升版门禁。
9. **系统处理（物理删除，D-15 第二级 SLA · ≤30 天 + 回执）**：在约定期限内完成证据原件的
   物理删除，并**出具删除回执**（证据 ID / 删除范围 / 完成时间 / 执行方 / 校验方式）。
   **审计留痕不随之删除**——留痕中保留「有一条证据在此被撤回并删除」的事实与其元数据，
   但不保留被删内容本身。
10. **系统收口**：记录撤回、逻辑失效、影响面计算、对内标注、对外替换项生成、拍板人通知、
   物理删除与回执八类事件进审计，并刷新受影响报告在 UC-10.1 清单行的状态与待补块数。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] **证据未被任何报告引用**——影响面清单为空，跳过第 4–7 步，
    直接走逻辑失效与物理删除；仍产生完整审计记录。
  - A2：[设计] **部分撤回**——只撤回一段转写中的某个片段或访谈中的某几问，
    影响面按片段粒度计算，未被撤回的部分继续有效。
  - A3：[设计] **撤回被撤销**（受访者反悔、误操作）——在物理删除**执行前**可恢复：
    证据重新进入检索范围，失效标注移除，段落「待复核」由人工确认后清除；
    **物理删除执行后不可恢复**，此时只能作为新证据重新采集。
  - A4：[设计] **批量撤回**——UC-17.2 删除队列一次命中多条证据时，影响面按报告聚合呈现
    （「本次撤回影响 3 份报告的 7 个段落」），避免刷屏式逐条通知。
- **异常流程**：
  - E1：[设计] **5 分钟 SLA 无法达成**（索引服务不可用）——**按 fail-closed 处理**：
    该证据所属的整个来源类别临时退出检索与 AI 取材，并告警给合规负责人；
    **绝不允许因为索引没更新就继续被检索命中**。
  - E2：[设计] **影响面反查失败或不完整**——不得声称「无影响」；标记为「影响面待确认」，
    阻断该证据相关报告的**升版与对外发布**，并升级给项目负责人人工核查。
  - E3：[设计] **对外替换项长期未确认**——超期后升级通知项目负责人与合规负责人；
    期间对外内容维持原样（D-19 明确不自动改写），对内标注持续可见。
  - E4：[设计] **物理删除失败或超 30 天**——必须显式记为「删除逾期」并告警合规负责人，
    **不得出具虚假回执**；逾期期间该证据仍保持逻辑失效。
  - E5：[设计] **被撤回证据支撑过已签字决策**——见 R3 第 7 步：通知拍板人复核，
    系统**不自动推翻决策、不自动改结论**；决策台账中该决策标注「依据已变化 · 待复核」。
  - E6：[设计] **权限在处理过程中被撤回**——立即终止后续写操作；
    已完成的失效标注与审计按规则保留。

## R5 权限与可见性

- **受访者 / 数据主体**：可对自己的材料发起撤回；只能看到自己的撤回进度与删除回执，
  **看不到影响面清单中的项目内容**。
- **合规负责人**：可执行 UC-17.2 删除队列、查看全部撤回事件与 SLA 达成情况、接收逾期告警；
  可查看影响面清单的**元数据**（哪份报告、哪一节），按 D-18 每次访问写审计日志。
- **引导师 / 项目经理**：可查看本项目的完整影响面清单，处理受影响段落，
  发起补证据与重写；**不可**直接清除「证据已撤回」标注。
- **有发布授权的人**：唯一可确认对外替换的角色（替换动作在 UC-10.4）。
- **决策拍板人**：收到复核通知，可查看被影响的决策与其依据变化。
- **组长 / 组员**：只能看到与自己相关的受影响段落，看不到全项目影响面。
- **观察者 / 客户**：**看不到撤回事实本身**，也看不到「证据已撤回」标注
  ——对外内容在人工确认替换前保持原样（D-19）。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，
  不能只依赖前端隐藏。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 被撤回证据在 ≤5 分钟内逻辑失效并退出检索范围；≤30 天内物理删除并出回执。
  - 每一处引用位置对内可见「证据已撤回」标注，对应段落为「待复核」，正文未被自动删除。
  - 已发布给客户的内容**字节未变**，替换队列中存在对应的待人工确认项。
  - 已定版快照**字节未变**；若支撑过已签字决策，拍板人已收到复核通知。
  - 审计留痕完整且不可删除。
  - **主题矩阵、节状态计数、定题强度与图谱节点证据数已重算**，重算前后值均留痕。
  - [D-15 验收] AC1：逻辑失效 ≤5 分钟；物理删除 ≤30 天并出回执。
  - [D-19 验收] AC2：对内标注可见；对外内容不自动改写，只进人工确认队列。
  - [验收] AC3：影响面清单精确到「报告 × 版本 × 节号 × 段落」，不是「有影响」这种粗结论。
  - [验收] AC4：撤回后该证据不再被任何检索与 AI 取材命中，但审计仍可查到它曾存在。
- **失败后置条件**：
  - 不出具未完成的删除回执；SLA 未达成必须显式告警并保持逻辑失效状态。
  - 影响面计算失败时不得声称「无影响」，按 E2 阻断相关升版与发布。
- **不包含**：
  - **对外替换的确认与执行动作本身**（属 UC-10.4 的替换队列与确认闸门，本用例只负责产生该项）。
  - UC-17.2 删除队列的管理界面与合规策略配置（属 17-gov）。
  - 知识五态机的过期/待复核流转（属 14-brain，见 R7 与 D-33 的区分）。
  - **撤回标注在报告段落上的具体视觉表现**——属**引用展开层下钻，未探明**，见 R8。

## R7 业务规则（不随具体实现变化的硬性约束）

- **[D-15] 两级 SLA，废弃「24 小时」口径**：
  - **第一级 · 逻辑失效即时（≤5 分钟）**：退出检索范围、引用标失效、不可再被取材。
  - **第二级 · 物理删除 ≤30 天，并出具删除回执**。
  - 两级是**先后关系不是替代关系**；只做物理删除不做逻辑失效不合格，反之亦然。
- [设计] **删除必须级联失效全部派生物**（`docs/architecture/context-engine.md` 第五节：
  「删除原始材料时级联失效 OCR、embedding、图边、摘要、缓存」）。
  「退出检索范围」不是给一张表打个标记就算数——**证据平面一条原件被撤回，
  知识平面与服务平面上由它派生出的每一件东西都必须同步失效**，逐项如下：
  | 派生物 | 表 | 失效动作 |
  |---|---|---|
  | OCR / ASR 转写结果 | `derived_representations` | 标失效，不再作为检索输入 |
  | embedding 向量 | 按 model/version 分区的向量表 | **从向量索引中移除**（不是仅标记——留在索引里就会被近似召回） |
  | 图边 / 实体关系 | `ontology_edges` | 由该证据支撑的边失效 |
  | Claim 证据链 | `claim_evidence` | 该行失效；受影响 Claim 重算强度（见下条） |
  | 摘要 / 综合内容 | `synthesized` 类 artifact | 标「依据已变化」，进人工复核队列 |
  | 检索与 Context Pack 缓存 | 缓存层 | **主动失效**，不等 TTL 自然过期 |
  | 文件浏览器中的文件 | `artifact_versions` + 对象存储 | 第二级物理删除后，`22-files` 里那份**必须真的消失** |
  **验收要求**：以上每一项都必须**可验证失效**，而不是「相信它失效了」——
  对应架构侧首批完成门槛第 4 条。任一项遗漏即视为撤回未完成。
  ⚠ **embedding 是最容易漏的一项**：向量索引的近似召回可能在权限/状态过滤之前发生，
  只在业务表打 `withdrawn` 标记而不动索引，撤回的内容仍会被召回。
- [设计] **`claim_evidence` 的 contradicting 行例外**：与 09-kg `uc-9-1` R7 的
  「反对证据不可删」并不冲突——反对证据的**不可删**约束的是**业务侧删除动作**，
  而本条约束的是**合规撤回**。合规撤回优先级更高：受访者撤回同意时，
  其反对证据同样失效，但**失效动作本身必须留痕**，使「这里曾有一条反对证据、
  因合规撤回而失效」在审计中可见——不得让它无声消失，造成「只剩支持方」的假共识。
- **[D-19] 对内可见 / 对外不自动改写**：
  - 对内：引用处必须出现「证据已撤回」，**不得对内隐藏撤回事实**。
  - 对外：已发布给客户的内容**不自动改写**，走「人工确认后替换」，替换留痕。
  - **两个方向都禁止静默**。
- **快照不可变**：撤回**不修改快照字节**，只在引用处加标注（对齐 `uc-0-1` E5 与 R7
  「固定快照不可变、不可删除」）。快照语义由 `phase-1/00-core/uc-0-1` 统一定义，本文不重复定义。
- **已签字决策不自动改**：若被撤回证据支撑过已签字决策，**通知拍板人复核，不自动改结论**
  （`uc-0-1` E5）。系统可以标注「依据已变化」，但推翻结论必须是人的动作。
- **[原型] 聚合强度必须重算，不能只打标记**：被撤回的证据必须从**主题矩阵**、
  UC-10.2 的**节状态计数**（`N 条强证据` / `N 处冲突`）、**定题强度**与
  09-kg 决策树节点的**已有证据数**中**扣除并重算**（proto-04 第 02 步原话
  「主题矩阵重算强度」）。重算并入 5 分钟 SLA；**只把证据标失效而不重算强度视为未完成**——
  否则结论会继续靠一条已经不存在的证据显示为「强」。
- **段落不自动删除**：对内标注后段落降级为「待复核」，正文保留；
  恢复正常必须经**显式人工复核**，不因时间流逝自动恢复。
- **退出检索但留痕不可删**：撤回后该证据退出检索范围与 AI 可读上下文；
  但**审计留痕不可删除**——留的是「曾有一条证据被引用并撤回」的事实与元数据，不是被删内容。
- **[D-33] 撤回 ≠ 过期，两者状态不得混用**：

  | | **过期**（D-33） | **撤回**（本用例） |
  |---|---|---|
  | 状态 | 转「**待复核**」态 | `withdrawn` |
  | 是否在检索范围内 | **仍在**检索范围内 | **退出**检索范围 |
  | 引用时 | 可引用，**提示已过期** | 不可新引用，已有引用标「证据已撤回」 |
  | 定题强度计算 | **不参与** | 不参与（已不可见） |
  | 原件 | 保留 | ≤30 天物理删除 |
  | 可逆性 | 复核后可恢复有效 | 物理删除前可撤销，删除后不可逆 |

  实现上**不得复用同一个状态字段的同一取值**表达这两件事；
  把过期误当撤回会导致知识被误删，把撤回误当过期会导致合规事故。
- **影响面必须精确到段落**：只报「有影响」而不给出报告 × 版本 × 节号 × 段落的实现视为未完成。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 撤回、逻辑失效、影响面计算、标注、通知、替换项生成、物理删除与回执**全部记审计**，
  并显示动作影响范围。
