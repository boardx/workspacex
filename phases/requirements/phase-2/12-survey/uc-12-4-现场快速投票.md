## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-12.4 / 现场快速投票
- **Actor**：**研究员**、**引导师**、**参与者**
- **目标**：[原型] 会前用问卷拿到面上的分布，会中用小问卷做快速收敛，结果自动进洞察库与图谱。
- **本用例结果**：[原型] 引导师从当前假设一键发起 60 秒投票，结果回主持台并**写入知识图谱**，
  作为对应**待验证节点**的证据与优先级依据；同时进入报告取材，以来源角标呈现（如「投票 10/12」）。
- **系统边界**：投票发起与倒计时、参与与匿名口径、结果回主持台、**回流决策树节点**、**回流报告取材**。
- **核心数据对象**：投票（题干、选项、时长 60 秒、匿名与否）、投票批次、投票结果分布、参与状态、
  **关联的决策树/知识图谱节点**、来源角标计数。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“登录管理（匿名回收）、洞察库”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] 现场需要收敛，引导师从当前假设一键发起投票。
  - [原型] **图谱派发**：主持台「下一步可以开展的工作」中的 **`VT 全场投票：先验哪条`** 卡片被点 **`[开展]`**
    —— 该卡的字段为「【定优先级】在收敛前把资源集中到一条待验证假设上 · **60 秒 · 引导师** ·
    **验证 → 主决策**」（与 UC-9.3 对齐，见 R7.1）。
  - 系统从 **主持台 / 组内投票** 进入本流程，并携带当前组织、项目、小组、角色、
    以及**被验证的图谱节点标识**。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **引导师操作**：从当前假设一键生成投票（或在主持台点 `VT 全场投票 · [开展]`），设为 60 秒倒计时。
   **系统响应**：以待验证假设为题干生成选项，创建投票并**带上被验证的图谱节点标识**；
   校验发起人是引导师、投票属当前场次；向在场参与者推送投票，倒计时常驻显示。
2. **参与者操作**：在 60 秒内投票（移动端可完成）。
   **系统响应**：按人幂等接收，匿名投票**只落分布不落个人选择**；实时更新参与计数（如 `10/12 已投`）。
3. **系统处理**：倒计时结束或全员投完，结果回主持台并**写入知识图谱**。
   **系统响应**：把结果分布挂到被验证的图谱节点上，作为该节点的**证据与优先级依据**
   （对应卡片的「【定优先级】在收敛前把资源集中到一条待验证假设上 · 验证 → 主决策」），
   携带来源投票 ID、参与人数、时间与触发人。
4. **系统处理**：结果同时进入**报告取材**。
   **系统响应**：作为报告取材七类之一（对话 / 访谈 / 研究 / 画布 / **投票** / 转写 / 决策），
   在报告工作台以来源角标呈现，原型实例：**`来源角标：决策 7/25 12:30 ｜ 投票 10/12 ｜ 研究 9 来源`**；
   未挂来源的段落按报告侧规则标灰。
5. **引导师操作**：查看未投的人此刻在哪个模块里忙着。
   **系统响应**：给出未投名单及其当前所在模块；匿名投票下**只暴露「谁没投」，不暴露「谁投了什么」**。
6. **系统收口**：校验 AC1「投票结果作为切环节的依据被记录」；
   记录发起、参与计数、结束、图谱写入、报告取材五类事件的操作者/触发者、时间、对象与结果进审计；
   刷新主持台、知识图谱与看板（图谱派发的工作类型完成后回写卡片状态）。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[Backlog] 匿名投票不显示个人选择，只给分布（Backlog UC-12.4 `edge` 原文；
    **投票屏未渲染，原型无据**）。
  - A2：[设计] 60 秒到点仍有人未投：按已投票数出结果并**在结果上标注参与率**（如 `10/12`），
    不静默按满员计算；引导师可选择延时一次或直接收口。
  - A3：[设计] 投票平局或分布无区分度时，图谱节点上记录「未收敛」而不是强行选一条；
    该节点的优先级不被本次投票改变。
- **异常流程**：
  - E1：[设计] 投票发起时未指定被验证的图谱节点——**拒绝发起**并提示必须指向一个待验证节点
    （图谱派发的工作类型必须可回流，见 R7.1）。
  - E2：[设计] 关联的图谱节点在投票期间被删除或合并时，结果仍保留并挂到合并后的节点；
    找不到承接节点时结果标为「孤立证据」待人工挂载，**不得静默丢弃**。
  - E3：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。
  - E4：[设计] 参与者重复提交按最后一次生效，投票人数不重复计数。
  - E5：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。
  - E6：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

- **研究员**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **引导师**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **参与者**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **观察者**：默认不能发起或修改；仅当内容已发布且授权范围允许时只读查看脱敏结果。
- **项目经理**：可查看项目级状态与审计摘要；是否可代替业务 Actor 执行写操作需由角色模板显式授权。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。
- **匿名参与者**：权限绑定到本场、本组和临时身份；项目结束后不得自动升级为正式账号权限。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 形成与本 use case 对应的正式记录或明确状态，并可从来源页面再次打开。
  - 所有跨模块回流均携带来源资源、版本、操作者/触发者、时间和可见范围。
  - [Backlog验收] AC1：投票结果作为切环节的依据被记录（Backlog UC-12.4 `ac` 原文；
    **原型无投票结果屏**，见 R8）。
  - [设计验收] AC2：投票结果**挂在被验证的图谱/决策树节点上**，作为该节点的证据与优先级依据，
    可从节点点回本次投票的原始分布。
  - [设计验收] AC3：投票结果作为**报告取材七类之一（投票）**出现在报告工作台的来源角标
    （原型实例「投票 10/12」），计数与实际参与数同源。
  - [设计验收] AC4：匿名投票下不存在从结果回到个人选择的任何路径。
- **跨模块回流**：
  - 投票结果 → **知识图谱 / 决策树节点**（证据 + 优先级依据）。
  - 投票结果 → **报告取材**（七类之一，来源角标「投票 N/M」）。
  - 图谱派发卡片状态 → **看板**（`[开展]` 派发出的工作完成后回写卡片）。
- **失败后置条件**：
  - 不创建“看似成功”的正式记录；可重试内容保留为草稿，失败事件进入可观测日志。
  - 图谱写入失败时结果不丢失，标为待回流可重试，**不得显示为已写入图谱**。
- **不包含**：
  - 复杂统计建模、匿名答卷反向识别个人。
  - 决策树节点本身的编辑与推演（属 09 模块）；报告工作台的渲染（属 10-report）。
  - 不扩展到本 use case 未声明的跨组织、跨客户或公开发布能力。

## R7 业务规则（不随具体实现变化的硬性约束）

### R7.1 现场投票是图谱派发的一种工作类型（与 UC-9.3 对齐）

- [原型] 主持台「下一步可以开展的工作」中，**`VT 全场投票：先验哪条`** 与
  `DR 深度研究` / `IT 访谈` / `UX 原型` / `LG 测算` **并列为可派发的工作类型**，
  卡片字段完全同构：**执行模块 / 预计耗时（60 秒）/ 负责人（引导师）/
  收益标签（【定优先级】）/ 验证目标节点（验证 → 主决策）**，点 **`[开展]`** 派发。
- [设计] 因此**现场投票必须实现为图谱派发链路的一个工作类型**，与其它类型共用同一套派发与回流契约，
  **不得实现成一个孤立的现场小工具**。每次投票必须指向一个待验证节点（否则拒绝发起，见 E1）。

### R7.2 投票结果回流为决策证据

- [设计] 投票结果**回流为决策树节点的证据与优先级依据**：结果分布挂到被验证的节点上，
  对应收益标签「【定优先级】在收敛前把资源集中到一条待验证假设上」；
  节点侧可点回本次投票的原始分布。
- [设计] 投票是**优先级依据，不是结论**：它决定「先验哪条」，不直接把某条假设判成立或不成立；
  节点的成立与否仍由该条待验证假设自己的证据决定。
- [设计] 投票结果是**报告取材七类之一（投票）**，与对话 / 访谈 / 研究 / 画布 / 转写 / 决策并列，
  在报告工作台以来源角标呈现，原型实例 **`投票 10/12`**；角标计数与实际参与数同源，不各记一份。

### R7.3 匿名与参与

- [Backlog] 匿名投票不显示个人选择，只给分布（Backlog UC-12.4 `edge` 原文；**原型无投票屏**）。
  （**同 R4·A1，同一条规则**；R4 只写现场处置，本处是规则本体。）
- [设计] 匿名投票下可知「谁没投」（用于现场催促），不可知「谁投了什么」——
  与 UC-12.2 的催填口径、UC-12.3 的匿名分析口径一致，由服务端强制。
- [Backlog] AC1：投票结果作为切环节的依据被记录（Backlog UC-12.4 `ac` 原文）。
  （E-10：此处原挂的孤立 `AC1：…` 与 R6 的 AC1 重复，已合并为同一条并注明来源。）

### R7.4 通用
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- AI/Agent 的写回、覆盖、发布或高影响工具调用必须遵守原型中的批准点；未经确认只保留为草稿或候选。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 60 秒投票属现场实时场景：推送与计数更新延迟应在 1 秒内可感知；
    倒计时以服务端时间为准，客户端不得各算各的。
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态 · AC1）：一场 60 秒投票结束后，该场次的环节切换记录中可查到本次投票 ID 作为依据。
- V2（派发链路 · R7.1）：主持台「下一步可以开展的工作」返回的 `VT 全场投票` 卡片，
  其字段结构与 `DR / IT / UX / LG` 卡片**完全同构**（执行模块 / 耗时 / 负责人 / 收益标签 / 验证目标节点）；
  点 `[开展]` 走的是同一个派发接口。
- V3（派发链路 · 必须指向节点）：发起投票时不带 `验证目标节点` 的请求**返回拒绝**。
- V4（回流图谱 · AC2）：投票结束后，被验证的图谱/决策树节点上出现一条来源为本次投票的证据，
  携带投票 ID、参与数、时间、触发人；从该节点请求原始分布返回与投票结果一致的分布。
- V5（回流图谱 · 是优先级依据不是结论）：投票结果写入后，被验证假设的成立/不成立状态**未被改变**，
  变化的只是其优先级排序。
- V6（回流报告 · AC3）：报告工作台对应段落的来源角标含 `投票 N/M`，
  且 N/M 与投票接口返回的参与数/应到数逐项相等（同源，非各记一份）。
- V7（回流失败不谎报）：模拟图谱写入失败，投票结果仍保留，回流状态为「待回流」，
  界面**不显示已写入图谱**，恢复后重试不产生重复证据。
- V8（匿名 · AC4）：匿名投票下，按人查选择 / 按选择查人的接口**均返回拒绝**；
  未投名单接口仍正常返回（可知谁没投）。
- V9（幂等）：同一参与者连续提交三次不同选项，最终计入最后一次，参与人数恒为 1。
- V10（倒计时与参与率）：60 秒到点时结果按已投票数结算，结果对象上带参与率字段（如 `10/12`），
  不按满员计算；倒计时以服务端时间为准。
- V11（节点变更）：投票期间删除关联节点，结果不丢失，标为「孤立证据」待人工挂载。
- V12（权限态）：逐一使用 引导师、研究员、参与者、观察者、未授权用户访问；
  只有引导师可发起与收口投票，观察者只读分布，返回数据和可执行动作严格符合 R5。
- V13（空态）：无投票时显示真实空态与下一步，不生成伪数据。
- V14（依赖失败）：实时通道不可用时降级为轮询并标「非实时」；已投数据不丢失，不伪装已同步。
- V15（并发态）：两名用户同时收口同一场投票时只产生一份结果，并可识别最终版本。
- V16（审计态）：发起、参与计数、结束、图谱写入、报告取材五类事件均可按操作者/触发者、
  时间、对象和结果检索；越权尝试也有安全审计记录。
