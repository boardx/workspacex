# 原始需求（细化）— UC-12.3 交叉分析

> 所属：阶段二 · 让推演与成果可见 / M12 问卷  
> 来源：`Backlog Use Case.html` 的 UC-12.3；UI 线索来自 `WorkspaceX Standalone.html`。
> 真实原型路径：**项目内** `项目 → [进入项目] → 研究洞察 → 问卷`（打开一份问卷进入分析屏）；
> **全局** 一级导航 `问卷`（问卷 Studio，同一套分析界面）；
> 会后反馈聚合见 `项目 → [进入项目] → 成果沉淀 → 审计与反馈` 的「参与者反馈」块。  

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **5**；建议迭代 **阶段二 · 迭代 8 · 报告与问卷**；模块 12-survey 合计 **24** 点（12.1=6 / 12.2=8 / 12.3=5 / 12.4=5）；**phase-2 五模块合计 158 点**。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-12.3 / 交叉分析
- **Actor**：**研究员**、**引导师**、**参与者**
- **目标**：[原型] 会前用问卷拿到面上的分布，会中用小问卷做快速收敛，结果自动进洞察库与图谱。
- **本用例结果**：[Backlog] 研究员在分析屏**按角色/组织/场景切分**看差异，
  **AI 给出挂着题目与样本量的候选结论**，**确认后入洞察库**且能点回原始分布
  （Backlog UC-12.3 `flow`/`ac` 原文）。
  ⚠ **原型确认缺失**：`回收与分析` 标签**已被点进并完整抽取**，实际只渲染了
  `回收中 · 34 / 48` + `[催收 14 人]` + 主题聚合两行——proto-09 明写
  「按角色/组织/场景的切分维度、AI 候选结论挂样本量、『样本 < 8 标不可推断』、确认入洞察库
  ——**这些在本屏未渲染**」。因此这一整批断言是**已探明区内的确认缺失**，
  **不是「未探明」**（说未探明等于预设它存在）。
  [原型] **会后反馈问卷**另有一条固定聚合口径，
  聚合结果推送到**后台 Skill 改进队列**。
- **系统边界**：分析切分与下钻、最小样本量保护、AI 候选结论与人工确认、洞察库回流、
  **会后反馈聚合与 Skill 改进回流**。发布回收见 UC-12.2。
- **核心数据对象**：问卷（含**匿名/实名**属性，决定分析口径）、版本、题目、答卷、
  **分析切分**（切分维度 + 样本量 + 可推断标记）、候选结论、洞察、
  **会后反馈聚合指标**（整体满意度 / 目标达成率 / AI 主持有用性 + 开放题原文摘录）、Skill 改进项。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“登录管理（匿名回收）、洞察库”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [Backlog] 回收达到阈值（Backlog UC-12.3 `trigger` 原文）；[设计] `回收中` 或 `已截止` 的问卷均可分析。
  - [原型] 打开一份问卷进入**问卷工作台的分析屏**（与全局 `问卷 Studio` 是同一套分析界面，见 UC-12.1 R7.1）。
  - [原型] **会后反馈问卷**回收完成后自动触发聚合，结果落在「成果沉淀 → 审计与反馈」的参与者反馈块。
  - 进入时携带当前组织、项目、范围、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **研究员操作**：在分析屏按**角色 / 组织 / 场景**切分，看各分群的差异。
   **系统响应**：按切分维度计算分布，**每个分群旁标出其样本量**；
   样本量 < 8 的分群**标为「不可推断」**并**只显示聚合、不展开明细**（R7.2）。
2. **系统处理**：AI 生成候选结论，**每条必须挂上支撑它的题目与样本量**。
   **系统响应**：候选结论标机器产出角标；样本不足的切分不得被 AI 用作结论依据，
   来源不足时明确说「证据不足」而不是给一个软化的结论。
3. **研究员操作**：逐条审阅并确认候选结论。
   **系统响应**：确认后写入**洞察库**，携带来源问卷 ID、版本、题目 ID、切分条件、样本量与确认人；
   洞察详情提供「点回原始分布」的下钻入口（AC1）。未确认的候选只留在候选区，不进洞察库。
4. **系统处理（会后反馈专用聚合）**：会后反馈问卷回收完成后自动聚合，产出三项固定指标与开放题原文摘录。
   [原型] 原文呈现：**`参与者反馈：4.6 整体满意度/5 ｜ 92% 认为目标已达成 ｜ 3.9 AI 主持有用性/5`**，
   下方附开放题摘录，例：**`"AI 提醒收敛那次很关键，但打断得稍早。"`**。
5. **系统处理**：把会后反馈中指向 AI 主持行为的条目**推送到后台 Skill 改进队列**。
   [原型] 呈现为条目后缀 **`已推送到后台 Skill 改进队列`**——推送成功与否必须在界面可见，
   不得只在后台静默入队。推送内容携带来源项目、问卷、条目原文与时间。
6. **系统收口**：校验 AC1「洞察库里的问卷结论能点回原始分布」；
   记录切分、下钻、AI 生成、人工确认、入库、Skill 改进推送六类事件的操作者/触发者、时间、对象与结果进审计；
   刷新洞察库、图谱与「研究洞察」子标签的洞察计数（如 `4 条洞察` / `3 条洞察已入库`）。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] **匿名问卷的分析路径**：只允许看聚合与分布，任何要求返回「某人答了什么」的下钻
    一律拒绝；分群下钻到样本不足时**只显示聚合、不显示明细**。
  - A2：[设计] **实名问卷的分析路径**：可下钻到个人，但仍受最小样本量与脱敏策略约束
    （组织层内用可逆映射 + 权限门控，见 R9）。
  - A3：[设计] 目标数据为空时展示空状态、原因和下一步入口，不生成示例数据冒充真实结果。
  - A4：[设计] 会后反馈的开放题若无内容，只呈现三项量化指标并明确「无开放题反馈」，不编造摘录。
- **异常流程**：
  - E1：[Backlog] 样本量低于 8 的切分**标为不可推断**（Backlog UC-12.3 `edge` 原文）——
    [设计] 标记 + 明细不返回，二者缺一不可。**原型确认缺失**，见 R1。
  - E2：[设计] 对匿名问卷调用个人级反查接口时**服务端返回拒绝**并记安全审计，
    不是前端隐藏入口（对齐 D-16 的权限门控要求）。
  - E3：[设计] 组合多个切分条件使某一格样本降到 < 8 时，该格同样受保护，
    **不得通过多次窄切分做差分推断出个人**（差分攻击防护）。
  - E4：[设计] Skill 改进队列不可用时，聚合结果仍产出并保留，推送状态标为「待推送」可重试，
    **不得显示为已推送**。
  - E5：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。
  - E6：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。
  - E7：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

- **研究员**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **引导师**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **参与者**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **观察者**：默认不能发起或修改；仅当内容已发布且授权范围允许时只读查看脱敏结果。
- **项目经理**：可查看项目级状态与审计摘要；是否可代替业务 Actor 执行写操作需由角色模板显式授权。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 形成与本 use case 对应的正式记录或明确状态，并可从来源页面再次打开。
  - 所有跨模块回流均携带来源资源、版本、操作者/触发者、时间和可见范围。
  - [Backlog验收] AC1：洞察库里的问卷结论能点回原始分布（Backlog UC-12.3 `ac` 原文；
    **原型「回收与分析」屏未渲染该能力**，见 R8）。
  - [原型验收] AC2：**会后反馈聚合产出三项固定指标**（整体满意度 / 5、目标已达成占比、AI 主持有用性 / 5）
    与开放题原文摘录，并显示在「审计与反馈」的参与者反馈块。
  - [设计验收] AC3：会后反馈中指向 AI 主持行为的条目**已推送到后台 Skill 改进队列**且推送状态可见。
  - [设计验收] AC4：任何样本量 < 8 的分群都带「不可推断」标记，且其明细不返回。
  - [设计验收] AC5：匿名问卷的任何个人级反查请求均被拒绝。
- **跨模块回流**（R10 契约的后置实现）：
  - 确认的候选结论 → **洞察库**（携带题目、切分条件、样本量、来源问卷版本）。
  - 会后反馈的 AI 主持相关条目 → **后台 Skill 改进队列**（Skill 的迭代输入）。
  - 问卷结论 → 报告工作台的来源角标（原型实例「问卷 34 份」），作为报告取材七类之一。
- **失败后置条件**：
  - 不创建“看似成功”的正式记录；可重试内容保留为草稿，失败事件进入可观测日志。
  - 聚合或推送失败时不产生半条 Skill 改进项，也不把失败显示为成功。
- **不包含**：
  - 复杂统计建模、匿名答卷反向识别个人。
  - **跨组织的聚合输出**（受 D-16 约束，需不可逆聚合与最小聚合样本量，不在本用例范围）。
  - Skill 改进队列本身的处理流程（属后台能力平面）。
  - 不扩展到本 use case 未声明的跨组织、跨客户或公开发布能力。

## R7 业务规则（不随具体实现变化的硬性约束）

### R7.1 匿名 / 实名决定分析口径

- [设计] 问卷的**匿名 vs 实名**属性在创建时确定且**不可改**（口径统一见 UC-12.1 R7.3，
  该处已标 `[设计]`；**D-d 裁定两处统一为 `[设计]`**）。[原型] 匿名/实名属性本身在问卷列表可见
  （「匿名 · 12 题」「实名 · 6 题」）。它**直接约束本用例的分析口径**：
  - **匿名问卷不得反查个人**——服务端不存在从答卷回到个人的路径，反查接口一律拒绝并记安全审计。
  - 分群下钻**到样本不足时只显示聚合、不显示明细**，匿名与实名问卷同样适用。
  - 实名问卷可下钻到个人，但受脱敏策略与权限门控约束。

### R7.2 最小样本量保护（对齐 D-16）

- [Backlog] **样本量低于 8 的切分标为不可推断**（Backlog UC-12.3 `edge` 原文；**原型确认缺失**）。
  这条同时是**统计纪律**与**隐私保护**：
  - 标记：该分群在界面上明确标「不可推断」，AI 不得基于它出结论。
  - 阻断：该分群的**明细不返回**（只给聚合计数），防止小样本等同于点名。
- [设计] **对齐 D-16 的跨组织最小聚合样本量**：D-16 要求跨组织输出做不可逆聚合并定义最小聚合样本量，
  本用例的 `< 8 不可推断` 即该阈值在问卷分析侧的取值锚点；两处**必须用同一个可配置阈值**，
  不得各写各的常数。跨组织输出场景本身不在本用例范围（见 R6 不包含）。
- [设计] 多次窄切分的**差分推断**同样受阻断：任一格样本 < 8 即受保护，不得靠组合条件绕过。

### R7.3 会后反馈聚合与 Skill 回流

- [原型] 会后反馈的聚合口径固定为三项量化指标 + 开放题原文摘录，原文：
  **`参与者反馈：4.6 整体满意度/5 ｜ 92% 认为目标已达成 ｜ 3.9 AI 主持有用性/5`**。
- [原型] 指向 AI 主持行为的开放题条目**推送到后台 Skill 改进队列**，原型实例：
  **`"AI 提醒收敛那次很关键，但打断得稍早。" 已推送到后台 Skill 改进队列`**。
- [设计] 推送是**产品内可见的状态**，不是隐式后台行为；失败可重试且不得显示为已推送。
- [设计] 开放题摘录**引用原文，不改写**；如需摘要另起一行并标机器产出。

### R7.4 开放题的统计口径

- [原型] 开放题除主题聚合外还有一项**质量统计：字数中位数**，原文
  **「客户侧 11/12 已回收，是质量最高的一批；**开放题字数中位 96 字**」**
  ——「质量最高的一批」这个判断**就是靠字数中位数支撑的**，因此它是分析口径的一部分，
  不是装饰性数字。回收侧的呈现见 UC-12.2 R7.4（客户侧单列），
  **本用例负责它在分析屏中的口径**：
  - **取中位数不取平均值**（少数长答会把平均值拉飞，中位数才反映典型作答深度）。
  - 可**按分群拆开**（如客户侧 96 字 vs 内部侧），与回收率并列作为**样本质量指标**，
    帮助判断某个分群的结论有多可信。
  - **字数中位数不是可推断性判据**——可推断与否只由样本量阈值（R7.2，< 8 不可推断）决定；
    **不得出现「字数够长所以样本虽小也可推断」这类绕过**。
- [设计] 空答与极短答（如仅标点）需有明确的计入口径，且该口径在界面上可查，
  否则不同人算出的中位数对不上。

### R7.5 洞察回流

- [Backlog] AI 候选结论**每条挂题目与样本量**（Backlog UC-12.3 `flow` 原文；**原型确认缺失**）；
  [设计] 无法挂上来源的结论不得进入候选区。
- [Backlog] AC1：洞察库里的问卷结论能点回原始分布（Backlog `ac` 原文）。
  （E-10：此处原挂的孤立 `AC1：…` 与 R6 的 AC1 重复，已合并为同一条并注明来源。）

### R7.6 通用
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- AI/Agent 的写回、覆盖、发布或高影响工具调用必须遵守原型中的批准点；未经确认只保留为草稿或候选。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R8 界面线索

- **前端入口**：
  - [原型] `项目 → [进入项目] → 研究洞察 → 问卷` → `[打开问卷]` → **问卷工作台 · 分析屏**
    （与全局 `问卷 Studio` 同一套分析界面，UC-12.1 R7.1）。
  - [原型] **会后反馈聚合**的呈现位置：`项目 → [进入项目] → 成果沉淀 → 审计与反馈` 的「参与者反馈」块。
  - [原型] 结论去向：洞察库、知识图谱、报告工作台的来源角标（「问卷 34 份」）。
- **信息架构**：
  - [原型] 工作台 `回收与分析` 标签**已探明的一层**：`回收中 · 34 / 48`、`[催收 14 人]`、
    **主题聚合**（开放题归并成主题 + 提及计数）：`责任归属不清　21` / `缺本地案例　18`。
  - [Backlog] 分析屏在其之上应承载：按角色/组织/场景切分 → 每个分群带样本量 →
    AI 候选结论（挂题目与样本量）→ 确认入库。
    ⚠ **这一层是原型确认缺失，不是未探明**（见 R10）——该屏已点进，只是没画，需**补画**后定稿。
  - [原型] 「审计与反馈」参与者反馈块的呈现形态（逐字）：
    `参与者反馈：4.6 整体满意度/5 ｜ 92% 认为目标已达成 ｜ 3.9 AI 主持有用性/5`
    `  "AI 提醒收敛那次很关键，但打断得稍早。"  已推送到后台 Skill 改进队列`
- **推荐交互**：

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态 · AC1）：确认一条候选结论入洞察库后，该洞察记录的 `source` 含
  问卷 ID + 版本 + 题目 ID + 切分条件 + 样本量；按该来源请求原始分布返回非空且与分析屏数值一致。
- V2（最小样本量 · 标记）：构造样本量 7 的分群，分析接口对该分群返回 `inferable=false`
  并带「不可推断」标记；样本量 8 的分群返回 `inferable=true`。
- V3（最小样本量 · 明细阻断 · AC4）：对样本量 < 8 的分群请求**明细**，
  接口**不返回明细数据**（返回拒绝或仅聚合），前端也无法通过任何参数取到。
- V4（最小样本量 · 差分防护）：用多个窄切分条件组合出样本量 < 8 的格子，同样被阻断，
  无法通过多次请求做差分还原出个人。
- V5（阈值同源）：把最小样本量配置改为 10 后，样本量 9 的分群随即变为「不可推断」——
  证明阈值来自配置而非硬编码，且与 D-16 的跨组织最小聚合样本量为同一配置项。
- V6（匿名口径 · AC5）：对**匿名**问卷调用任何个人级反查接口
  （按人查答卷 / 按答卷查人）**均返回拒绝**，并产生一条安全审计记录；
  绕过前端直接调接口结果相同。
- V7（匿名口径 · 聚合仍可用）：同一份匿名问卷的聚合分布与分群计数正常返回，
  证明拒绝的是反查而不是整体分析。
- V8（AI 候选来源）：AI 生成的每条候选结论都带非空的题目 ID 列表与样本量；
  构造一个来源不足的场景，AI 返回「证据不足」而不是给出结论。
- V9（未确认不入库）：未经人工确认的候选结论不出现在洞察库查询结果中。
- V10（会后反馈聚合 · AC2）：会后反馈问卷回收完成后，聚合接口返回三项指标
  —— 整体满意度（如 `4.6/5`）、目标已达成占比（如 `92%`）、AI 主持有用性（如 `3.9/5`）
  —— 三项字段均非空且可独立读取；开放题摘录为**原文**，与答卷原始文本逐字相等。
- V11（Skill 回流 · AC3）：指向 AI 主持行为的开放题条目在 Skill 改进队列中可检索到对应项，
  且该条目在「审计与反馈」界面显示「已推送到后台 Skill 改进队列」；
  推送项携带来源项目、来源问卷、条目原文与时间。
- V12（Skill 回流 · 失败不谎报）：模拟 Skill 改进队列不可用，聚合结果仍保留，
  推送状态为「待推送」且**界面不显示已推送**；恢复后重试成功且不产生重复项。
- V12a（开放题字数中位数 · R7.4）：构造字数为 `[10, 20, 96, 400, 2000]` 的五份开放题答卷，
  断言接口返回的 `open_text_median_chars` 为 **96**（中位数，**不是平均值** 505）；
  按分群请求时可分别返回客户侧与整体两个口径。
- V12b（字数不得绕过样本量阈值）：构造一个样本量 5、开放题字数中位 300 字的分群，
  断言该分群仍为 `inferable=false`——**字数长度不参与可推断性判定**。
- V13（权限态）：逐一使用 研究员、引导师、参与者、观察者、未授权用户访问；返回数据和可执行动作严格符合 R5；
  观察者只读脱敏结果，无法下钻明细。
- V14（空态）：回收为空时显示真实空态与下一步，不生成伪数据；会后反馈无开放题时不编造摘录。
- V15（依赖失败）：模拟网络/外部依赖失败，输入和最近成功数据保留，错误可解释且可重试。
- V16（并发态）：两名用户同时确认同一条候选结论时不产生两条洞察，并可识别最终版本。

  时间、对象和结果检索；对匿名问卷的反查尝试有安全审计记录。
