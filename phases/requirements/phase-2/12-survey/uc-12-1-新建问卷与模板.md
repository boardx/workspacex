## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-12.1 / 新建问卷与模板
- **Actor**：**研究员**、**引导师**、**参与者**
- **目标**：[原型] 会前用问卷拿到面上的分布，会中用小问卷做快速收敛，结果自动进洞察库与图谱。
- **本用例结果**：[原型] 用户经 `[＋ 新建问卷]` 或 `[从模板新建]` 产出一份处于 **草稿** 态的问卷，
  已确定 **匿名 / 实名** 属性、题目与逻辑、所属**范围**（本项目 / 不属于任何项目）与标签，
  并在编辑期即受质量门禁的题目侧校验（诱导性表述提示）约束；可继续走 UC-12.2 发布。
- **系统边界**：问卷模板、题目与逻辑、问卷状态机、匿名/实名属性、范围与标签、
  与报告模板的绑定关系；发放、回收、交叉分析与现场投票分别见 UC-12.2 / 12.3 / 12.4。
- **核心数据对象**：
  - **问卷**：标题与**版本**（[原型] 头部 `会前预习问卷 v2`）、**状态**（`草稿` / `待发出` / `回收中` / `已截止` 四态，见 R7）、
    **匿名或实名**（创建时确定，创建后不可改）、题数与预计用时（[原型] `12 题 · 5 分钟`）、发出人、
    **范围**（本项目 / 不属于任何项目）、标签、截止日、
    **对应报告模板**（[原型] 头部一等元数据：`对应报告模板「客户体验诊断」`）、**触发时机**（详见 UC-12.2）。
  - **题目**：题干 + **`→ 报告章节` 映射标注**（[原型] `Q1 … → 阻碍分布`）——
    映射是题目的**一等字段**，不是事后补的关联；题型 / 跳转逻辑 / 必答与选项配置见 R10 未探明清单。
  - **报告章节**：隶属于绑定的报告模板，每节记录其**供料题目**（[原型] `阻碍分布　映射 Q1`）
    或**缺口**（[原型] `按规模分群差异　缺分群字段`）。
  - **报告章节 ↔ 题目双向映射表**：本模块质量门禁阻断二的载体，见 R7.5。
  - **问卷模板**（`问卷 Studio` 的「问卷模板」标签页）、版本、逻辑（跳转/必答/可跳过）。
  - 发布批次、答卷、名单、分析切分、投票（后续 UC 使用，此处仅定义归属）。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“登录管理（匿名回收）、洞察库”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**（[原型] 两条创建路径 + 两个入口）：
  - [原型] 项目内：`项目 → [进入项目] → 研究洞察 → 问卷` 页顶部的 **`[＋ 新建问卷]`**（空白新建）
    或 **`[从模板新建]`**（套用问卷模板）。
  - [原型] 全局：一级导航 `问卷`（问卷 Studio）→ **`[＋ 新建问卷]`**；模板来自「问卷模板」标签页。
  - [原型] 已截止问卷的 **`[复制为新问卷]`** 也进入本流程（复用题目，生成新的草稿，见 UC-12.2）。
  - 进入时携带当前组织、项目、范围（本项目 / 不属于任何项目）、角色与资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **研究员操作**：在问卷列表选 **`[从模板新建]`** 或 **`[＋ 新建问卷]`**。
   **系统响应**：`[从模板新建]` 时打开问卷模板选择器，选定后**把模板的题目与其绑定的报告骨架一并带入**（AC1）；
   `[＋ 新建问卷]` 时创建空白问卷。两条路径都立即生成一份 **`草稿`** 态问卷并落在当前**范围**下。
2. **研究员操作**：填写标题、选择 **匿名 / 实名**、选择范围（**本项目 / 不属于任何项目**）与标签。
   **系统响应**：把匿名/实名写入问卷并**在此后置为只读**（R7 硬约束）；界面用「匿名 · 12 题」这一行
   把该属性与题数常驻显示；范围与标签进入统一的范围切换器与标签筛选口径。
3. **研究员操作**：在工作台的 **`问卷设计`** 标签加题、设题型、必答与跳转逻辑；标记敏感题；
   **给每道题指定它供料的 `→ 报告章节`**（[原型] `Q1 你们上一次评估储能方案卡在哪一步？ **→ 阻碍分布**`）。
   **系统响应**：逐题做**编辑期校验**——① 题目**诱导性表述**检测，命中即在该题就地提示
   （原型实例「Q7 诱导性表述」），并计入该问卷的质量门禁项；② **未指定报告章节的题目**标为「未映射」，
   同样计入门禁项；③ 题数超过 12 题时提示回收率会下降（不阻断）；④ 敏感题必须允许跳过，否则不允许被标为必答。
4. **研究员操作**：点 **`[叫 AI 帮我补充题目 →]`** 让 AI 补题。
   **系统响应**：AI 生成的题目一律落草稿并标机器产出，**必须与人写的题走同一套诱导性表述检测**
   （生成 → 检测 → 阻断，见 R7.5）；AI 补的题同样要指定 `→ 报告章节`，不得以「AI 生成」为由跳过映射。
5. **研究员操作**：切到 **`报告模板`** 标签，查看该问卷对应的报告模板与其**报告章节**清单，
   按需 `[➕ 新增报告章节]`。
   **系统响应**：逐章节显示其**供料状态**——已映射的显示映射到哪几道题
   （[原型] `阻碍分布　映射 Q1` / `决策链与否决点　映射 Q2`）；
   **没有题目供料的显示缺口**（[原型] `按规模分群差异　**缺分群字段**`），该缺口即门禁阻断项。
   这里是**报告章节 ↔ 题目双向映射表**的编辑面，也是质量门禁阻断二的真正载体（R7.5）。
6. **系统处理**：持续自动保存草稿（[原型] 底部 `自动保存 34:12 · 后台运行中`）；
   问卷停留在 `草稿` 态，列表行显示 `[继续编辑]`。
7. **系统收口**：校验 AC1「套模板新建的问卷自动带题目与报告骨架」；
   记录创建者、时间、模板来源（模板 ID / 被复制的源问卷 ID）、范围、匿名实名属性
   与**双向映射的当前完成度**进审计；刷新问卷列表与「研究洞察」子标签的问卷计数。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[Backlog] 超过 12 题时提示回收率会下降（Backlog UC-12.1 `edge` 原文）——
    [设计] **只提示不阻断**，不得丢失已编辑题目。
    ⚠ **原型确认缺失**：问卷设计屏已探明，只渲染 Q1、Q2 两题（标称 12 题），**无题数提示**。
  - A2：[Backlog] 敏感题必须可跳过（Backlog UC-12.1 `edge` 原文）——
    [设计] 被标为敏感的题不允许同时是必答题，冲突时提示并要求二选一。
    ⚠ **原型确认缺失**：问卷设计屏**无敏感题标记**，题型/必答配置本身亦未渲染。
  - A3：[原型] **`[从模板新建]`**：模板题目与报告骨架一并带入后即可自由增删改，
    改动只落在新问卷上，**不回写模板**。
  - A4：[原型] **`[复制为新问卷]`**（从 `已截止` 的问卷发起）：复制题目、逻辑与报告模板绑定，
    **不复制答卷、回收进度与洞察**；新问卷从 `草稿` 态开始，匿名/实名属性随源问卷带入后仍不可改。
  - A5：[设计] AI 生成题目（原型「客户续约意愿诊断 · 草稿 · AI 生成」）：生成结果一律落 `草稿`，
    标机器产出角标，必须由人逐题确认；AI 生成的题目同样过诱导性表述检测。
- **异常流程**：
  - E1：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。
  - E4：[设计] 试图修改已创建问卷的**匿名/实名**属性时，接口拒绝并提示「匿名/实名在创建时确定，
    如需更改请用 `[复制为新问卷]` 重建」——不得提供任何绕过路径。
  - E5：[设计] 所选问卷模板已被归档或删除时，`[从模板新建]` 明确失败并给出可选替代模板，
    不得静默生成一份空白问卷冒充套模板结果。

## R5 权限与可见性

- **研究员**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **引导师**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **参与者**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **观察者**：默认不能发起或修改；仅当内容已发布且授权范围允许时只读查看脱敏结果。
- **项目经理**：可查看项目级状态与审计摘要；是否可代替业务 Actor 执行写操作需由角色模板显式授权。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 形成与本 use case 对应的正式记录或明确状态，并可从来源页面再次打开。
  - 所有跨模块回流均携带来源资源、版本、操作者/触发者、时间和可见范围。
  - [Backlog验收] AC1：套模板新建的问卷自动带题目与报告骨架（Backlog UC-12.1 `ac` 原文）。
  - [设计验收] AC2：新建的问卷落在 `草稿` 态，列表行动作为 `[继续编辑]`，尚未产生任何可填写链接。
  - [设计验收] AC3：匿名/实名属性一经创建即不可变更，写接口对该字段的任何更新返回拒绝。
  - [设计验收] AC4：问卷所属**范围**（本项目 / 不属于任何项目）与标签写入后，
    在项目内问卷列表与全局 `问卷 Studio` 的范围切换器下都能被同一套筛选命中。
  - [原型验收] AC5：每道题都带 `→ 报告章节` 映射字段；每个报告章节都能读出其供料题目或缺口，
    两侧构成一张可查询的**双向映射表**。
  - [设计验收] AC6：AI 经 `[叫 AI 帮我补充题目 →]` 生成的题目与人写的题走同一套诱导性检测，
    且同样带 `→ 报告章节` 字段（可为空但会被标「未映射」）。
- **失败后置条件**：
  - 不创建“看似成功”的正式记录；可重试内容保留为草稿，失败事件进入可观测日志。
- **不包含**：
  - 复杂统计建模、匿名答卷反向识别个人。
  - **发布与回收本身**（属 UC-12.2）：本用例只做编辑期提示，不做发布阻断判定。
  - 为项目内问卷单独实现一套编辑/分析界面（R7 硬约束禁止）。
  - 不扩展到本 use case 未声明的跨组织、跨客户或公开发布能力。

## R7 业务规则（不随具体实现变化的硬性约束）

### R7.1 单一界面硬约束（本模块头号约束）

- [原型] **「打开任意一份进入问卷工作台——和全局『问卷 Studio』是同一套编辑与分析界面。」**
  → 项目内问卷与全局问卷 Studio **必须是同一套 UI 与同一套数据模型**；
  **不得实现成两套界面、两张表或两条 API**。项目内视图与全局视图的差别**只在范围过滤**，不在能力。

### R7.2 问卷四态机

- [原型] 问卷状态的四个取值：**`草稿` / `待发出` / `回收中` / `已截止`**
  （原型列表筛选行「全部 4 / 草稿 1 / 回收中 1 / 已截止 2」与四条实例逐个可证）。
  [设计] 该枚举**封闭**（「恰为四态」属闭合性设计约束）。各态允许的动作：

  | 状态 | 含义（[原型] 实例） | 允许动作 | 禁止 |
  |---|---|---|---|
  | `草稿` | 「内部：本地团队能力自评 · 实名 · 9 题 · **草稿**」 | **`[继续编辑]`**、删除、提交发布（须先过 UC-12.2 双阻断） | 生成填写链接、催填 |
  | `待发出` | 「会后反馈 · 现场节奏与产出 · **待发出**；绑定在环节 7 结束后触发，题目已定，尚未发出」 | **`[改触发时机]`**、`[打开问卷]`、撤回为草稿 | 改题目主干（改题须先退回草稿）、催填 |
  | `回收中` | 「坊前问卷 · 欧洲业务最大阻碍 · **回收中** · 34/48」 | **`[催未交的 N 人]`**、`[打开问卷]`、看回收明细、提前截止 | 改题目、改匿名/实名 |
  | `已截止` | 「供应商满意度基线 · **已截止** · 41/45 ｜ 3 条洞察已入库」 | **`[复制为新问卷]`**、`[打开问卷]`、看分析、归档 | 收新答卷、重开回收 |

- [设计] 状态迁移**只允许单向**：`草稿 → 待发出 → 回收中 → 已截止`；
  `待发出 → 草稿` 是唯一允许的回退（撤回未发出的问卷）；`已截止` 不可逆，
  需要再收一轮只能 `[复制为新问卷]`。状态由服务端裁决，前端不得自行改写。

### R7.3 匿名 vs 实名

- [原型] 每份问卷在列表上都带 **`匿名`** 或 **`实名`** 标记（「匿名 · 12 题」「实名 · 6 题」）。
- [设计] 该属性**在创建时确定，创建后不可更改**（改要走 `[复制为新问卷]`）。它同时决定三件事：
  ① **可见性**——匿名问卷的回收明细只显示「谁未交」的名单口径，不显示「谁答了什么」；
  ② **脱敏**——匿名答卷不落个人标识，见 UC-12.2 R7；
  ③ **分析口径**——匿名问卷不得反查个人，分群下钻受最小样本量保护，见 UC-12.3。

### R7.4 范围与标签

- [原型] 问卷列表带**范围切换：本项目 | 不属于任何项目**，与研究 / 访谈 / 原型四个 Studio 的范围切换器**一致**。
- [原型] **统一标签筛选**：`全部标签 | 客户 | 内部 | 高优先级 | 已归档`，与其它 Studio 同一套标签体系；
  项目内列表另有按状态的快捷筛选「全部 4 / 草稿 1 / 回收中 1 / 已截止 2」。

### R7.5 报告章节 ↔ 题目双向映射（本用例的核心结构）

- [原型] 硬规则原文：**「每个问卷发布前必须映射到一个报告模板 —— 没映射完的题不能发布。」**
- [原型] 这条**远不止「绑定了一个报告模板」**。原型的两个标签页各承载映射的一侧，构成一张**双向映射表**：

  | 侧 | 承载页 | [原型] 呈现 | 未完成时 |
  |---|---|---|---|
  | **题目侧** | `问卷设计` | 每道题天生带 `→ 报告章节` 标注：`Q1 … → 阻碍分布`、`Q2 … → 决策链` | 该题标「未映射」 |
  | **章节侧** | `报告模板` | 每个报告章节记录其供料题目：`阻碍分布　映射 Q1`、`决策链与否决点　映射 Q2` | 该节标缺口：`按规模分群差异　**缺分群字段**` |

- [设计] **判定口径**：
  - 题目侧完整 ＝ 每道题都映射到某个报告章节（没有孤儿题）。
  - 章节侧完整 ＝ 每个报告章节都至少有一道题供料（没有缺料章节）。
  - **任一侧未映射完即构成质量门禁阻断项**，在发布期阻断（UC-12.2 R7.1 阻断二）。
- [设计] 缺口报错必须**指名是哪个章节缺哪一类字段**（如「按规模分群差异 → 分群字段」），
  不能只报「映射不完整」这种无法据以修改的笼统错误。
- [设计] `[➕ 新增报告章节]` 会新增一个**天然缺料**的章节，因而**立刻新增一个阻断项**——
  新增章节不是无代价动作，界面须明示这一后果。
- [设计] 映射关系是问卷的一等数据：`[从模板新建]` 与 `[复制为新问卷]` 都必须把映射一并带过来；
  换绑报告模板会使章节侧全部失配，须重新映射。

### R7.6 编辑期质量规则

- [原型] **题目诱导性表述**在编辑期即检测并就地提示（原型实例「Q7 诱导性表述」）；
  它是 UC-12.2 发布双阻断的第一类，**在本用例只提示、不阻断编辑**。
- [原型] **`[叫 AI 帮我补充题目 →]`** 是 AI 生成题目的入口，**与诱导性检测配对**：
  生成 → 检测 → 阻断。AI 补的题与人写的题**过同一套检测、同样必须指定 `→ 报告章节`**，
  不因来自 AI 而豁免任何一项。
- [Backlog] 超过 12 题时提示回收率会下降（Backlog `edge` 原文；**原型确认缺失**，见 R4·A1）；
  [设计] 只提示不阻断。
- [Backlog] 敏感题必须可跳过（Backlog `edge` 原文；**原型确认缺失**，见 R4·A2）；
  [设计] 敏感题不得同时为必答。
- [原型] 每份问卷都要对应一个**报告模板**（[原型] 头部一等元数据 `对应报告模板「客户体验诊断」`）；
  绑定在创建期建立，**双向映射完整性**在发布期阻断（UC-12.2）。
- [Backlog] AC1：套模板新建的问卷自动带题目与报告骨架（Backlog UC-12.1 `ac` 原文）。
  （E-10：此处原挂的孤立 `AC1：…` 与 R6 的 AC1 重复，已合并为同一条并注明来源。）

### R7.7 通用
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- AI/Agent 的写回、覆盖、发布或高影响工具调用必须遵守原型中的批准点；未经确认只保留为草稿或候选。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。

  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态 · AC1）：走 `[从模板新建]` 选定模板 T 后，新问卷的题目集合等于 T 的题目集合，
  且 `report_template_id` 非空并等于 T 绑定的报告模板 —— 接口断言，不看截图。
- V2（状态机）：新建问卷的 `status` 返回 `draft`；对同一问卷依次请求
  `draft→pending_send→collecting→closed` 全部成功；请求 `closed→collecting`、`collecting→draft`
  返回拒绝且错误码标明「状态迁移不允许」。
- V3（状态机 · 动作可见性）：四态各取一份问卷读列表接口，断言返回的 `actions` 数组**至少包含**
  各自的主动作：`草稿`→继续编辑类动作 / `待发出`→`[改触发时机]` /
  `回收中`→`[催未交的 N 人]` / `已截止`→`[复制为新问卷]`（各态均含 `[打开问卷]`）；
  并断言**不包含该态的禁止动作**（见 R7.2 表的「禁止」列）。
  ⚠ **[D-g] 此前的「恰为…不多不少」断言已放宽**：草稿态的行内动作在原型中有**两种文案**——
  **全局问卷 Studio / 项目列表用 `[继续设计]`**（proto-01「客户续约意愿诊断 草稿…[继续设计]」），
  **项目内问卷列表用 `[继续编辑]`**（proto-05「内部：本地团队能力自评…草稿 [继续编辑]」）。
  写死「恰为 `[继续编辑]`」会把**正确实现判错**。文案统一与否属 **[待确认]**，见 R10。
- V4（不可变属性）：对已创建问卷 PATCH `anonymity` 字段（匿名↔实名两个方向各一次），
  **均返回拒绝**，且读回的值未变。
- V5（单一界面 · R7.1）：项目内创建的问卷 P，在全局 `问卷 Studio` 切到对应范围能读到**同一个 ID**；
  在任一侧改标题，另一侧读到的是改后的值（同一条记录，非副本）。
- V6（范围与标签）：范围切到「不属于任何项目」时，项目内问卷不在结果集中；
  标签筛选「客户」返回集与研究 Studio 同标签的口径一致（同一套标签实现）。
- V7（编辑期质量）：提交一条含诱导性表述的题目，编辑接口返回该题的告警项且 `blocking=false`（编辑不阻断）；
  同一告警项在 UC-12.2 的发布预检中 `blocking=true`。
- V7a（双向映射 · 题目侧 · AC5）：每道题的读接口返回 `report_section_id` 字段；
  把某题的该字段置空，映射完整性接口即报出一条「未映射题目」项并指名是哪一题。
- V7b（双向映射 · 章节侧 · AC5）：报告章节读接口返回其 `mapped_questions` 数组；
  「阻碍分布」返回 `[Q1]`、「决策链与否决点」返回 `[Q2]`、「按规模分群差异」返回空数组
  且带缺口描述指名缺分群字段。
- V7c（双向映射 · 一致性）：把 Q1 的映射从「阻碍分布」改到「决策链与否决点」后，
  两侧同时更新——「阻碍分布」的 `mapped_questions` 变空并报缺口，「决策链与否决点」含 Q1 与 Q2。
- V7d（新增章节即新增阻断）：调 `[➕ 新增报告章节]` 新增一节后，
  映射完整性接口的未清项数 **+1**，且新增项指向该新章节。
- V7e（AI 补题不豁免 · AC6）：经 `[叫 AI 帮我补充题目 →]` 生成一条含诱导性表述的题目，
  检测结果与人工录入同一条题目**完全一致**（同一套检测）；该题的 `report_section_id` 为空时
  同样被计为「未映射题目」。
- V7f（映射随创建路径带走）：`[从模板新建]` 与 `[复制为新问卷]` 产出的新问卷，
  其题目的 `report_section_id` 与章节侧的 `mapped_questions` 与源一致，不丢映射。
- V8（12 题提示）：加到第 13 题时返回回收率提示，且**问卷仍可保存**（只提示不阻断）。
- V9（敏感题）：把一道标记为敏感的题设为必答，接口返回拒绝并指明冲突字段。
- V10（复制）：对 `已截止` 问卷调 `[复制为新问卷]`，新问卷题目数与源相同、
  `responses` 计数为 0、`insights` 为空、`status=draft`。
- V11（权限态）：逐一使用 研究员、引导师、参与者、观察者、未授权用户访问；返回数据和可执行动作严格符合 R5。
- V12（空态）：范围内没有任何问卷时显示真实空态与 `[＋ 新建问卷]` 下一步，不生成伪数据。
- V13（依赖失败）：模板服务不可用时 `[从模板新建]` 明确失败，**不产生空白问卷**；已填输入保留。
- V14（并发态）：两名用户修改同一问卷题目时不静默覆盖，并可识别最终版本。
- V15（审计态）：创建、套模板、复制、状态迁移四类事件均可按操作者、时间、对象和结果检索；
  越权尝试也有安全审计记录。
