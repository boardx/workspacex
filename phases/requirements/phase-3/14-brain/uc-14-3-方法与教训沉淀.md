## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-14.3 / 方法与教训沉淀
- **Actor**：**方法负责人**、**引导师**、**项目经理**
- **目标**：[Backlog] 把一场项目的结论沉淀成跨项目可复用的知识：下一次做同类项目时，能直接调出上次的判断与教训。
- **本用例结果**：[Backlog] 用户通过“方法与教训沉淀”完成从“复盘完成”到可追踪业务结果的闭环。
- **系统边界**：组织知识分层、写回队列、去重冲突、跨项目检索与方法教训。
- **核心数据对象**：**[设计 · 架构对齐]** 「组织知识节点」「方法教训」＝ `claims`
  （资产类型分别为「被验证的方法」「反例与教训」），来源＝ `claim_evidence` → `segments` →
  `artifact_versions`；「过期策略」＝ `valid_from` / `valid_to`。
  字段定义与五态↔`status` 对应表见 **UC-14.5 R1 / R10**，本 UC 不另建状态字段。
  其余：项目来源、冲突组、复用引用。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“知识图谱、成果沉淀（写回来源）”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [Backlog] 复盘完成。
  - 系统从 **复盘 → 沉淀** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **方法负责人操作**：记录哪个环节超时、哪条 AI 建议被否、哪些假设被推翻。**系统响应**：校验当前身份、项目范围、必填数据与资源版本；成功后更新界面和业务记录，并保留可追溯来源。
2. **方法负责人操作**：汇总成蓝本改动建议与方法教训条目。**系统响应**：校验当前身份、项目范围、必填数据与资源版本；成功后更新界面和业务记录，并保留可追溯来源。
3. **方法负责人操作（沉淀的唯一入口 · 两条去向）**：[原型] **要沉淀就在复盘里「提交回蓝本」**——
   系统在复盘页给出两条并列去向，二者可同时选：
   - **去向 A · 沉淀为知识条目**：把方法/教训提名进 **UC-14.5 晋升队列**；
     [原型] 方法类条目**批准后自动在 Skill 库生成一条可调用 skill**（跨 03-skill）。
   - **去向 B · 提交回蓝本**：把本次的偏离与改动汇总为**蓝本改动建议**并提交
     （对照推演链的 `[把偏离写回模板 v3]` 与 UC-2.3「把一次项目的改动提回蓝本」）。
     **系统响应**：显示**当前偏离清单**（原型示例：「多了一个分支条件、少了一步竞品对照」），
     逐条可选择 `写回蓝本` 或 `只在本项目保留`；写回**生成蓝本新版本**，
     [原型] **已开过的项目锁在自己的版本上**，不被追溯修改（快照绑定，D-30）。
4. **系统处理**：每条写回蓝本的规则**永久保留其教训溯源**——记录它由哪几次复盘、
   哪几场项目改出来；[Backlog] **教训必须挂具体场次**，不接受空泛结论。
5. **系统收口**：校验 AC1“蓝本里能看到某条规则是被哪几次教训改出来的”与
   AC2「复盘中未选任一去向的产物不构成沉淀」；满足后记录操作者、时间、对象、结果与来源，
   并刷新相关列表、图谱、看板或通知状态。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] 目标数据为空时展示空状态、原因和下一步入口，不生成示例数据冒充真实结果。系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
  - A2：[原型] **只在本项目保留**——偏离逐条可选择不写回蓝本，此时该改动只作用于本项目实例，
    并在项目内标注「与蓝本 vN 存在 N 处偏离」。
  - A3：[Backlog] **蓝本改动建议需蓝本负责人审批**（对照 UC-2.3）——提交后进入待审队列，
    审批通过才生成新版本；被驳回时理由归档且不可覆盖。
  - A4：[设计] 教训条目未通过 UC-14.5 的 D-32 准入（无签字决策 / 复盘未验证）时，
    可先按「项目内共享」入库，**不进组织层**。
- **异常流程**：
  - E0：[设计] 提交回蓝本时蓝本已被他人升版 → 提示版本已变化，展示三方差异
    （本项目偏离 / 旧蓝本 / 新蓝本），要求重新确认；**不得静默覆盖他人的改动**。
  - E1：[Backlog] 教训必须挂具体场次，不接受空泛结论。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E4：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

- **方法负责人**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **蓝本负责人**：[Backlog] **提交回蓝本的审批人**；只有他能让改动建议生成蓝本新版本。
- **引导师**（项目角色）：可在被授权范围内参与流程并查看与自身角色相关的结果；可提交改动建议。
- **项目负责人**（组织角色；原文档写作「项目经理」，按 `uc-0-3` 正名）：
  可在被授权范围内参与流程并查看与自身角色相关的结果。
- **agent**：可汇总复盘素材、可起草改动建议；**不可提交回蓝本、不可审批**。
- **观察者**：默认不能发起或修改；仅当内容已发布且授权范围允许时只读查看脱敏结果。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。

## R7 业务规则（不随具体实现变化的硬性约束）

- [Backlog] 教训必须挂具体场次，不接受空泛结论。
- [原型] **「要沉淀就在复盘里『提交回蓝本』」**（蓝本设计器原文）。
  [设计] 由此推出的强化口径——**没有复盘就没有沉淀入口，系统不提供绕过复盘的写回路径**；
  原型只给出一句说明，未表明其它路径被禁止。
- [原型] **写回蓝本不追溯已开项目**：改动生成新版本，已开过的项目锁在自己的版本上（D-30）。
- [设计] **规则的教训溯源不可抹除**：蓝本中每条由教训改出的规则永久保留其来源场次列表。
- [原型] **方法晋升生成 skill**：方法类条目在 UC-14.5 批准后自动在 Skill 库生成可调用 skill，
  并须走 03-skill 的上线门禁（安全扫描 + 方法论审核）。
- **[设计 · 架构对齐] 教训资产 ＝ 反例库的数据形态**：
  被推翻的知识**不删除**，`status = superseded` 且**记录永久保留**，转为教训资产。
  检索行为分两半（详见 UC-14.5 R7）：**已撤销条目本身永久排除**，
  **但其反例文本作为教训另行召回**，Context Pack 中 `retrievalReasons` 标「反例/教训」
  并显示「此条已被撤销」。教训与被它推翻的原条目通过 `supersedes_claim_id` 关联，**不得断链**。
- **[设计 · 架构对齐] 教训与方法的溯源 ＝ `provenance_events`**：
  「某条规则被哪几次教训改出来」是 append-only 血缘的查询结果，
  不是一个可被覆盖的冗余字段；血缘事件**不可篡改、不可删除**。
- **[设计 · 架构对齐] 沉淀内容取上下文只能经 Context API 取 Context Pack**，
  不得绕过直查库；复盘素材的召回理由须落在 `retrievalReasons`，遗漏须可从 `omissions` 复核。
- **[已裁决 O-16] 教训的证据计数口径 ＝ 独立受访者人数**（同一人多条引述只计 1）；
  写成普遍性断言须 ≥**5 名独立受访者**；跨组织输出受**最小聚合样本量 8** 约束。
- AC1：蓝本里能看到某条规则是被哪几次教训改出来的。
- AC2：复盘产物必须显式选择去向。
- AC3：写回蓝本生成新版本且不追溯已开项目。
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- AI/Agent 的写回、覆盖、发布或高影响工具调用必须遵守原型中的批准点；未经确认只保留为草稿或候选。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态）：AC1：蓝本里能看到某条规则是被哪几次教训改出来的
  —— 断言规则详情返回**教训场次列表**（含项目名与复盘时间），且列表不可被编辑抹除。
- V1b（成功态）：AC2 —— 复盘产物未选去向时，断言它不出现在晋升队列、
  不出现在蓝本改动建议队列、不被跨项目检索到。
- V1c（成功态）：AC3 —— 提交一条偏离回蓝本，断言：① 生成蓝本 v(N+1)；
  ② 已开过的项目实例仍绑定 vN 且内容未变；③ 新建项目套用到 v(N+1)。
- V1d（成功态）：方法类教训经 UC-14.5 批准后，断言 Skill 库出现对应 skill。
- V2（权限态）：逐一使用 方法负责人、蓝本负责人、引导师、项目负责人、观察者、agent、
  未授权用户访问；返回数据和可执行动作严格符合 R5；
  **agent 调用「提交回蓝本」接口被服务端拒绝**。
- V3（空态）：无目标数据时显示真实空态与下一步，不生成伪数据。
- V4（依赖失败）：模拟网络/外部依赖失败，输入和最近成功数据保留，错误可解释且可重试。
- V5（并发态）：两名用户修改同一资源时不静默覆盖，并可识别最终版本。
- V6（审计态）：关键动作可按操作者、时间、对象和结果检索；越权尝试也有安全审计记录。
