## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-14.1 / 结论写回与去重
- **Actor**：**方法负责人**、**引导师**、**项目经理**
- **目标**：[Backlog] 把一场项目的结论沉淀成跨项目可复用的知识：下一次做同类项目时，能直接调出上次的判断与教训。
- **本用例结果**：[Backlog] 用户通过“结论写回与去重”完成从“项目发布结论后”到可追踪业务结果的闭环。
- **系统边界**：组织知识分层、写回队列、去重冲突、跨项目检索与方法教训。
- **核心数据对象**：组织知识节点、项目来源、冲突组、复用引用、过期策略、方法教训。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“知识图谱、成果沉淀（写回来源）”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [Backlog] 项目发布结论后。
  - 系统从 **组织大脑 → 写回队列** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **方法负责人操作**：把已确认节点按主题挂到组织知识树上。**系统响应**：校验当前身份、项目范围、必填数据与资源版本；成功后更新界面和业务记录，并保留可追溯来源。
2. **方法负责人操作**：与已有知识比对：一致的累加来源，冲突的并列保留。**系统响应**：校验当前身份、项目范围、必填数据与资源版本；成功后更新界面和业务记录，并保留可追溯来源。
3. **系统处理（冲突 · 成对召回）**：[原型] 检出冲突时**不自动合并、不择一**，
   把两条**并列成对**展示，各自带**置信度、被引用决策数、样本量**
   （原型示例：「德国 · 资质重新审查时长：4–6 个月（置信 0.7 · 被 5 决策引用）
   vs 7–9 个月（置信 0.8 · 仅 1 例）」）。
   **方法负责人操作**：从**三个出口**中选一，系统按所选出口执行并留痕：
   - **① 并成带条件的一条** —— 合并为一条带适用条件的条目，两条原记录转为**被替代**
     （不删除，历史决策仍可引用旧快照）；合并结果须重新走 UC-14.5 的三项必填。
   - **② 保留两条，标注适用差异** —— 两条同时保留，各自补写**适用范围**以区分；
     [原型] 此后它们在检索中**成对注入**，由人裁决（见 UC-14.6 R7）。
   - **③ 派 agent 补样本** —— 生成一条研究任务（原型示例 `[派 Scout 补第三个样本]`），
     冲突组保持未决状态并显示「等待第三个样本」，**不得因未决而丢弃任一条**。
4. **系统处理**：写回后原项目仍可追溯。系统记录触发原因，校验数据、权限与幂等条件，更新业务状态，并向有权用户反馈结果。
5. **系统收口**：校验 AC1“同一结论在两个项目里被验证过时能看到两处来源”与
   AC2「冲突组必须由人从三个出口中选择，系统不得自动裁决」；满足后记录操作者、时间、对象、
   结果与来源，并刷新相关列表、图谱、看板或通知状态。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] 目标数据为空时展示空状态、原因和下一步入口，不生成示例数据冒充真实结果。系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
  - A2：[原型] **冲突组长期未决**——超过阈值仍未选出口时，冲突组进入
    「大脑的自省 · 冲突」清单（原型：「两项目记录相差 3 个月未归并」）并提醒方法负责人，
    **仍不自动裁决**。
  - A3：[原型] 写回的候选来自 agent 提名时，条目打「需人工确认」标，
    在人确认前不进入 UC-14.5 的任何后续状态。
- **异常流程**：
  - E1：[原型] 冲突不自动合并，等方法负责人裁决。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[原型] 客户敏感信息按脱敏规则处理后再写回。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E4：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E5：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

- **方法负责人**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组；
  **是唯一可对冲突组选出口的角色**。
- **引导师**（项目角色）：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **项目负责人**（组织角色；原文档写作「项目经理」，按 `uc-0-3` 正名）：
  可在被授权范围内参与流程并查看与自身角色相关的结果。
- **观察者**：默认不能发起或修改；仅当内容已发布且授权范围允许时只读查看脱敏结果。
- **agent**：可提名写回候选、可提供冲突组的补充样本；**不可选择冲突出口、不可执行合并**。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 形成与本 use case 对应的正式记录或明确状态，并可从来源页面再次打开。
  - 所有跨模块回流均携带来源资源、版本、操作者/触发者、时间和可见范围。
  - [原型验收] AC1：同一结论在两个项目里被验证过时能看到两处来源。
  - [原型验收] AC2：**冲突组必须由人从三个出口中选择**（并成带条件的一条 / 保留两条标注适用差异 /
    派 agent 补样本），系统与 agent 均不得自动裁决；未选出口前两条**都不丢失**。
- **失败后置条件**：
  - 不创建“看似成功”的正式记录；可重试内容保留为草稿，失败事件进入可观测日志。
- **不包含**：
  - 跨客户未授权原文复用、自动裁决冲突。
  - **晋升准入与批准前必填三项**——归 **UC-14.5**，本 UC 只负责把候选送进队列。
  - **写回后的检索/召回行为**——归 **UC-14.6**。
  - 不扩展到本 use case 未声明的跨组织、跨客户或公开发布能力。

## R7 业务规则（不随具体实现变化的硬性约束）

- [原型] 冲突不自动合并，等方法负责人裁决。
- [原型] **冲突成对，引擎不替你选**：冲突两条**并列保留并成对参与检索**（见 UC-14.6 R7），
  三个出口只能由人选择；**「派 agent 补样本」不是裁决**，冲突组在补到样本前保持未决。
- [原型] **合并不删除旧条目**：选「并成带条件的一条」后，两条原记录转为**被替代**，
  历史决策绑定的旧快照仍可引用（D-30）。
- [原型] 客户敏感信息按脱敏规则处理后再写回；**脱敏闸门的完整规则见 UC-14.5 R7（D-16）**。
- AC1：同一结论在两个项目里被验证过时能看到两处来源。
- AC2：冲突组由人从三个出口中选择，系统不得自动裁决。

- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R10 已知约束 / 依赖

- **内部依赖**：[原型] 知识图谱、成果沉淀（写回来源）；**UC-14.5**（写回候选进入五态机）。
- **被依赖**：**UC-14.6**（冲突组的「成对注入」直接消费本 UC 的冲突组数据）。
- **跨模块契约**：身份与权限、来源引用、版本、任务状态、审计事件和通知必须使用统一标识，避免同一对象在各模块成为不可关联的副本。
  **冲突组 ID** 必须在写回、晋升队列、检索三处共用同一标识。
- **技术约束**：[Backlog] 产品为响应式网页；完整离线模式、原生移动端、第三方 IM 与产品内自助计费在 backlog 中明确为范围外。
- **[待确认]** 单项目并发人数、组织数、材料量、音频时长和历史数据量尚未给出；容量与压测指标需在开发前定稿。
- **[待确认]** 通知渠道、消息模板、语言与时区策略未统一定义；本文仅承接原型明确写出的产品内/邮件行为。

## R11 切分提示（给 requirement-author）

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态）：AC1：同一结论在两个项目里被验证过时能看到两处来源。
- V1b（成功态）：AC2 —— 构造一个冲突组，断言：
  ① 未选出口前两条都存在且都可被检索到（成对）；
  ② 选「并成带条件的一条」后，两条原记录状态为**被替代**且未被删除，合并结果缺三项必填时无法生效；
  ③ 选「保留两条，标注适用差异」后，两条各自持有不同适用范围，且在检索中成对注入；
  ④ 选「派 agent 补样本」后生成一条任务，冲突组仍为未决且两条均未丢失；
  ⑤ 以 agent 身份调用「选出口」接口被服务端拒绝。
- V2（权限态）：逐一使用 方法负责人、引导师、项目经理、观察者、未授权用户访问；返回数据和可执行动作严格符合 R5。
- V3（空态）：无目标数据时显示真实空态与下一步，不生成伪数据。
- V4（依赖失败）：模拟网络/外部依赖失败，输入和最近成功数据保留，错误可解释且可重试。
- V5（并发态）：两名用户修改同一资源时不静默覆盖，并可识别最终版本。
- V6（审计态）：关键动作可按操作者、时间、对象和结果检索；越权尝试也有安全审计记录。
