# 原始需求（细化）— UC-14.5 知识五态机与晋升

> 所属：阶段三 · 跨项目与对外 / M14 组织大脑
> 来源：原型 `大脑 → 晋升队列` 子标签（「4 条待审 · 同期 11 条降级或过期」、五态与三出口、
> 四条候选含**脱敏闸门**、「反方向：降级与过期」）；`大脑` 常驻头部的**一条规则**
> 「知识不因为『被写下来』就进组织大脑。只有支撑过一个被签字的决策、并在复盘中被验证的判断，
> 才够格晋升。」；`大脑 → 三层关系总览` 的「晋升·唯一入口」与「时效衰减·自动降级」。
> **补写缘由**：原 M14 三份 UC 把「写回组织大脑」写成一个动作，**没有状态机、没有准入闸门、
> 没有必填三项、没有脱敏闸门**。按原文档实现会得到一个「只涨不减」的知识库——
> 恰恰是原型明确点名要避免的失败模式。本 UC 是 D-24 MVP 三件之第二件。

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **13**；建议迭代 **阶段三 · 迭代 11 · 跨项目复用**。
>
> **[裁决 D-32]** 晋升**严格准入**：支撑过一个被签字的决策 **且** 复盘中被验证，才够格晋升。
> **[裁决 D-33]** 过期转「待复核」仍在检索范围内，引用时提示，但**不参与定题强度计算**。
> **[裁决 D-16]** 脱敏两级：组织层内**可逆映射 + 权限门控**；跨组织输出做**不可逆聚合**。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-14.5 / 知识五态机与晋升
- **Actor**：**方法负责人**（晋升审批人）、**提名人**（项目成员）、**复核负责人**、
  **合规负责人**（脱敏闸门）；**agent 为受限提名方**（可提名，不可自行晋升）。
- **目标**：[设计] 让「项目层的判断进组织层」成为一道**有闸门、可反向、可审计**的状态迁移，
  而不是一次写入动作——并让组织层能**主动缩小**（降级/过期/撤销），而不是只涨不减。
- **本用例结果**：每条组织层知识都处于五态之一，携带**适用范围 / 有效期 / 复核负责人**三项必填，
  可追到它支撑过的决策与复盘结论；被推翻或过期时按规则降级并级联打标。
- **系统边界**：五态机与三出口、晋升准入校验、批准前必填三项、有效期默认值与到期降级、
  AI 提名的人工确认、脱敏闸门（两级）、方法晋升生成 skill、降级/撤销的级联打标。
- **核心数据对象**：知识条目、状态、资产类型、适用范围、有效期、复核负责人、
  支撑决策引用、复盘结论、原文↔脱敏稿映射、版本关系（被替代/替代）、级联打标记录。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 候选条目已存在于项目层，且**可追到原始材料**（来源引用完整）。
  - 若走 D-32 准入：其支撑的决策在 **UC-14.4 台账中已签字**，且复盘状态为**已验证**。
  - 客户机密类候选：脱敏能力可用；不可用时闸门保持关闭而非放行。
- **触发条件**：
  - [原型] 有人（或 agent）**提名**一条项目层条目进入晋升队列。
  - [原型] **复盘结论录入为「已验证」**（UC-14.4 R3 第 5 步）后自动生成晋升候选。
  - [原型] **有效期到期**（时效衰减定时任务）→ 触发反方向的「转待复核」。
  - [原型] 支撑它的决策被标为**被推翻** → 触发降级/撤销。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **提名人 / agent 操作**：提名一条项目层条目。**系统响应**：条目进入 **候选** 态，
   记录提名人、来源项目、提名时间；[原型] agent 提名的条目**额外打「需人工确认」标**。
2. **系统处理（准入校验，D-32）**：校验两个硬条件——
   ① 它**支撑过至少一个已签字的决策**（读 UC-14.4 台账）；
   ② 该决策的**复盘结论为「已验证」**。
   两者同时满足 → 转 **已验证** 态；否则停在候选并明确显示缺哪一条
   （[原型] 「复盘结论：尚未复盘 · 8/08 到期 → 可先按『项目内共享』入库」）。
3. **方法负责人操作**：审阅候选详情——[原型] 每条候选必须回答三个问题：
   **它支撑过哪个决策 / 复盘结论是什么 / 多久之后需要重新检查**；
   并查看「与已有条目的关系」（[原型]「将成为『资质转让时长』v3，v2 转为被替代」）。
4. **方法负责人操作**：填写**批准前必填三项**，缺任一项**不得进入生效**：
   - **适用范围**（[原型] 如「跨境并购 / 德国·荷兰 / 需持照经营行业」，可 `[＋]` 追加维度）；
   - **有效期**（[原型] 单选 6 / 12 / 24 个月 / 自定义，**按资产类型给默认值**，见 R7）；
   - **复核负责人**（[原型] 指定到人）。
   **系统响应**：三项齐备后允许 `[批准晋升]`，条目转 **已批准**。
5. **系统处理（脱敏闸门，D-16）**：若资产类型为**客户机密**，条目**卡在脱敏闸门**，不得直接批准：
   - [原型] AI **起草脱敏稿**，与原条目并排展示（原条目留在项目层 / 脱敏条目可进组织层）；
   - [原型] 出口三选一：`[采纳脱敏稿并晋升]` `[我自己改写]` `[只留在项目层]`；
   - [原型] **脱敏稿必须由人确认**；**原文与脱敏稿双向关联**，审计时可从脱敏稿追回原文与客户。
   - [裁决 D-16] 组织层内为**可逆映射 + 权限门控**（有权者可回溯原文，回溯动作留痕）；
     **跨组织输出**时改用**不可逆聚合**，且需满足**最小聚合样本量**（见 R7 [待确认]）。
6. **系统处理**：已批准且三项齐备 → 转 **生效**，进入 AI 检索范围（UC-14.6 的召回集）。
   [原型] 若资产类型为**方法**，晋升后**自动在 Skill 库生成一条可调用的 skill**，
   并成为同类场景下 agent 的默认方法（跨模块写入 03-skill）。
7. **系统处理（时效衰减）**：有效期到期 → 转 **待复核**。
   [裁决 D-33] 待复核条目**仍在检索范围内**，引用时 AI 必须提示「可能已过期」，
   但**不参与定题强度计算**；同时按自动化规则给复核负责人建一条复核任务。
8. **系统处理（反方向）**：出口三取值——
   **被替代**（有新版本，[原型]「旧版仍被历史决策引用」属正常，不得断链）、
   **被撤销**（[原型] 转为**反例资产不删除**）、**驳回**（[原型] 无决策引用）。
   被撤销/降级时**级联打标**：给所有引用过它的项目与决策打标。
9. **系统收口**：校验 AC1「无三项必填不得生效」与 AC2「无签字决策 + 已验证复盘不得晋升」；
   记录操作者、时间、对象、结果与来源，刷新队列计数与健康度数字（晋升数 / 同期降级过期数）。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] **先按「项目内共享」入库**——准入未满足（尚未复盘）时的降级路径：
    条目可在项目层共享但**不进组织层、不进跨项目检索**。
  - A2：[原型] **退回**——`[退回]` 把候选打回提名人，须附理由；理由归档不可覆盖。
  - A3：[原型] **AI 提名走人工确认**——Ava 提名的条目显示 `[我来审]`，
    **在人确认前不得进入任何后续状态**。
  - A4：[原型] **冲突合并**——两条相互冲突的条目（如「审查时长差 3 个月」）不自动合并，
    出口 `[去合并]` 交人判断保留哪条或并成带条件的一条（与 UC-14.1 的成对召回三出口一致）。
  - A5：[设计] 队列为空时展示真实空态与「候选从哪里来」的说明，不生成示例条目。
- **异常流程**：
  - E1：[原型] **AI 试图自行晋升**——服务端拒绝任何非人类主体的状态迁移到「已批准」及以后，
    记安全审计。
  - E2：[设计] 三项必填缺失仍调用批准接口 → 服务端拒绝并逐项指出缺失，
    **不得由前端校验兜底**。
  - E3：[设计] 脱敏能力不可用（模型/服务故障）→ 闸门**保持关闭**，条目停在已批准前，
    明确提示不可用；**严禁跳过脱敏直接晋升**。
  - E4：[设计] 晋升过程中其支撑决策被改判为「被推翻」→ 中止晋升并把条目打回候选，附原因。
  - E5：[设计] 同一条目被两人并发批准 → 只有一次成功，另一方看到已生效版本与差异。
  - E6：[设计] 请求超时或依赖不可用时保留已填的三项内容，明确失败原因并可安全重试；
    不产生「看似已生效」的条目。

## R5 权限与可见性

- **方法负责人**：可读全部候选、可批准/退回/驳回、可填三项必填；不可绕过 D-32 准入。
- **提名人（项目成员）**：可提名、可看自己提名条目的状态与退回理由；不可批准。
- **复核负责人**：对其负责的条目可发起复核、可申请延期或提起撤销；到期任务默认派给他。
- **合规负责人**：对脱敏闸门有终审权；有权按权限门控**回溯脱敏稿对应的原文**（回溯必留痕）。
- **观察者 / 客户**：仅可见**已生效且脱敏后**的条目内容；不可见候选队列、原文、退回理由。
- **agent**：可提名、可提供复盘素材与脱敏稿草稿；**不可执行任何进入「已批准」及以后的迁移**。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。
- 组织层条目仍受 `uc-0-3` 的**资源可见性范围**约束（全组织可用 / 仅某团队）。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 每条组织层条目都处于五态之一，且**生效态条目 100% 具备三项必填**。
  - [原型验收] AC1：**缺适用范围 / 有效期 / 复核负责人任一项，条目无法进入生效态**。
  - [原型验收] AC2（D-32）：**未支撑过已签字决策**或**复盘未判为已验证**的条目无法晋升。
  - [原型验收] AC3：**AI 提名的条目在人工确认前不进入已批准态**。
  - [原型验收] AC4（D-16）：客户机密条目未经人确认脱敏稿不得进入组织层；
    脱敏稿与原文双向关联，有权者可审计回溯。
  - [原型验收] AC5：**方法类**条目批准后在 Skill 库出现一条对应的可调用 skill。
  - [裁决验收] AC6（D-33）：待复核条目仍出现在检索结果中且被标「可能已过期」，
    但其权重**不计入定题强度**。
  - [原型验收] AC7：被撤销的条目**不被删除**，转为反例资产，且所有引用它的项目已打标。
- **失败后置条件**：不产生「看似生效」的条目；三项必填的部分输入保留为草稿；
  失败事件进入可观测日志与安全审计。
- **不包含**：
  - **知识库健康度看板**（指标本身在本 UC 中作为计数产出，但**独立看板界面**后置，
    见 UC-14.4 R6 的模块级 backlog）。
  - **反例库浏览界面**与**版本谱系浏览界面**（数据关系在本 UC 内建立，界面后置）。
  - 自动晋升、按规则批量批准、AI 代填三项必填。
  - 跨组织的知识共享市场（跨组织仅允许不可逆聚合输出，见 R7）。

## R7 业务规则（不随具体实现变化的硬性约束）

- [原型] **一条规则（模块级最高约束）**：「知识不因为『被写下来』就进组织大脑。
  只有**支撑过一个被签字的决策**、并在**复盘中被验证**的判断，才够格晋升。」（= D-32）
- [原型] **批准前必填三项**：适用范围 / 有效期 / 复核负责人；
  **缺任一项都无法进入生效状态**，校验在服务端。
- [原型] **有效期默认值按资产类型**：**行业事实 6 个月 / 监管 12 个月 / 方法 24 个月**；
  可在允许区间内改，改动需记录改动人与理由。
- [原型] **AI 不能自行晋升**：agent 只能提名；进入「已批准」及以后的迁移只能由人执行。
- [原型] **适用范围不是硬围栏**：「范围外的项目仍可检索到，但会标『跨范围引用』并降权」
  （与 UC-14.6 的降权动作一致）。
- [裁决 D-33] **过期不等于失效**：到期转「待复核」，**仍在检索范围**、引用时提示，
  但**不参与定题强度计算**。
- [裁决 D-16] **脱敏两级**：组织层内**可逆映射 + 权限门控**（原文与脱敏稿双向关联、
  回溯动作留痕）；**跨组织输出**必须**不可逆聚合**，且低于**最小聚合样本量**时不得输出
  （对照 12-3 的「样本 <8 标不可推断」）。
- [原型] **脱敏稿由 AI 起草、必须人确认**；未确认的脱敏稿不构成晋升依据。
- [原型] **方法晋升生成 skill**：方法类条目批准后在 Skill 库生成可调用 skill，
  并按 03-skill 的上线门禁（安全扫描 + 方法论审核）处理。
- [原型] **组织层必须能缩小**：降级/过期/撤销与晋升是同一等公民；
  被撤销条目**转反例资产不删除**，并**级联打标**到所有引用过它的项目与决策。
- [原型] **被替代不断链**：旧版本仍可被历史决策引用——「决策绑定的是当时的快照」（D-30）。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 提名、准入判定、批准、退回、驳回、脱敏确认、到期降级、撤销与级联打标，全部记审计事件。
- [待确认] **最小聚合样本量**的具体数值（跨组织不可逆聚合的下限）——须由合规负责人给出。
- [待确认] 有效期的**允许区间**与自定义上限；到期宽限期是否与 UC-17.3 的删除宽限期共用参数。

## R8 界面线索

- **前端入口**：[原型] `大脑 → 晋升队列`；项目侧的提名入口在 `项目 → 成果沉淀 → 写回组织大脑`。
- **信息架构**：[原型] 头部「4 条待审 · 同期 11 条降级或过期」→ 五态与三出口计数条 →
  候选卡片列表 → 「反方向：降级与过期」区 → 「晋升的健康度」区。
- **推荐交互**：
  - [原型] **五态计数条**：候选 4 → 已验证 2 → 已批准 1 → 生效 604 → 待复核 14；
    出口另计：被替代 7 ｜ 被撤销 41 ｜ 驳回 9。
  - [原型] 候选卡片固定四段：**支撑过哪个决策 / 复盘结论 / 与已有条目的关系 /
    批准前必填三项**；动作 `[批准晋升] [退回]`。
  - [原型] 脱敏闸门为**并排双栏**（原条目 · 留在项目层 ｜ 脱敏条目 · 可进组织层），
    动作 `[采纳脱敏稿并晋升] [我自己改写] [只留在项目层]`。
  - [原型] 有效期为单选组并**预选资产类型对应的默认值**，旁注默认值来由。
  - [设计] 三项必填未齐时 `[批准晋升]` 禁用，并逐项高亮缺失——但**禁用只是提示，
    服务端仍须独立校验**。
- **必须呈现的状态**：默认态、加载态、空态、校验失败态（三项缺失/准入不足）、
  依赖失败态（脱敏服务不可用）、无权限态、成功态。
- **原型参考**：`phases/requirements/WorkspaceX Standalone.html` — 大脑 → 晋升队列
- **UI sign-off**：[原型] 晋升队列主屏、四类候选卡、脱敏闸门双栏**均已存在，不必补画**；
  **原型待补**：`[我来审]` `[去合并]` `[派 Scout 复核]` **三个按钮已渲染、目标屏均未见**
  （按钮在、行为未接线），需补接线/补画。

## R9 非功能约束

- **性能/规模预期**：[设计] 生效条目规模按千级设计（原型 604 条），检索与状态迁移均需分页；
  到期扫描为定时批处理，**降级必须在有效期到达当日内生效**，不得滞后。
- **安全/隐私/合规**：脱敏映射表按最高敏感级存储并单独权限门控；回溯原文属高危读取，
  必须写审计并对合规负责人可见（对照 D-18 的管理员边界）。
  客户机密条目的处理必须走「只走自托管/本地模型」的硬路由（对照 D-17 与后台模型管理）。
- **兼容与降级要求**：响应式 Web；脱敏服务不可用时闸门保持关闭而非放行；
  skill 生成失败不得阻断知识条目本身的生效，但须留一条待补任务。

## R11 切分提示（给 requirement-author）

- 建议先拆「知识条目与五态机 enum → 准入校验（D-32）→ 批准前必填三项 →
  有效期默认值与到期降级（D-33）→ AI 提名的人工确认 → 脱敏闸门（两级，D-16）→
  方法晋升生成 skill → 降级/撤销的级联打标 → 队列 UI → 审计 → 自动化验收」。
- **准入校验（D-32）必须独立成 feature 并有独立验收**：它是整个组织大脑可信度的闸门。
- **脱敏闸门必须独立成 feature**，且组织层可逆映射与跨组织不可逆聚合**分成两个 feature**，
  两者的失败语义不同（前者可回溯、后者不可回溯）。
- **级联打标必须独立成 feature**，与 UC-14.4 R3 第 6 步共用同一实现。
- **优先级 / 先后依赖**：P0；13 点；阶段三 · 迭代 11；**依赖 UC-14.4 先落地**，
  **必须先于 UC-14.6**（检索的召回集由本 UC 的状态定义）。

## R12 AI Ready 验收线索

- V1（成功态）：AC1 —— 三项必填逐一置空调用批准接口，**三次全部被服务端拒绝**并指明缺项；
  三项齐备后条目状态迁移到生效。
- V2（成功态）：AC2（D-32）—— 构造三种候选：①无支撑决策 ②有决策但未签字 ③已签字但复盘未验证，
  **三者均无法晋升**；第四种（已签字 + 复盘已验证）可晋升。
- V3（成功态）：AC3 —— 以 agent 身份提名并尝试直接迁移到「已批准」，被拒；
  人点 `[我来审]` 确认后方可迁移。
- V4（成功态）：AC4（D-16）—— 客户机密条目在脱敏稿未经人确认时批准被拒；
  确认后组织层可见脱敏稿，且有权者可由脱敏稿**回溯到原文与客户**，回溯产生审计记录；
  无权者回溯被拒。跨组织输出接口在样本量低于阈值时拒绝输出。
- V5（成功态）：AC5 —— 批准一条方法类条目后，查询 Skill 库存在对应 skill 且可被 agent 调用。
- V6（成功态）：AC6（D-33）—— 把一条条目的有效期改为已过期，断言：
  ① 它仍出现在检索结果中；② 结果携带「可能已过期」标记；③ 定题强度计算结果**不含它的权重**。
- V7（成功态）：AC7 —— 撤销一条条目，断言：记录未被删除、类型转为反例资产、
  引用过它的项目全部被打标。
- V8（权限态）：逐一以方法负责人、提名人、复核负责人、合规负责人、观察者、agent、
  未授权用户调用批准/回溯/读队列接口，返回严格符合 R5。
- V9（空态）：队列为空时显示真实空态与来源说明，不生成伪候选。
- V10（依赖失败）：模拟脱敏服务不可用，闸门保持关闭，条目不进入组织层，已填三项保留。
- V11（并发态）：两会话同时批准同一条目，仅一次成功，另一方看到已生效版本。
- V12（审计态）：提名、准入判定、批准、退回、脱敏确认、原文回溯、到期降级、撤销级联
  八类事件均可按操作者、时间、对象检索；agent 越权迁移的尝试有安全审计记录。
