## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-16.4 / 访谈模板反向沉淀
- **Actor**：**研究员**（提交沉淀）、**方法负责人**（审定模板变更）
- **目标**：[原型] 让访谈模板**从真实项目里长出来**——一次访谈跑完后，
  把「哪些问法有效、哪些段落超时、哪些数据字段缺了」沉淀回模板，
  使模板标签页能如实标注它「**来自 N 场项目**」。
- **本用例结果**：模板库中每个模板都携带**来源场次**与**用过 N 次**两个真实计数；
  某条问法可追溯到它是被哪几场访谈改出来的。
- **系统边界**：从已完成访谈提取模板候选、模板变更建议与审定、
  模板的**来源场次溯源**与**使用计数**、新模板的创建。
- **不属于本 UC 的边界**：模板的正向创建与编辑（UC-6.1）、
  用模板新建访谈（UC-6.1 / UC-6.2）、方法类知识晋升为 skill（UC-14.5）。
- **核心数据对象**：访谈模板（提纲结构 / 每段时长 / 要收集的数据字段 / 题量）、
  **来源场次引用**、使用计数、模板变更建议、审定记录。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 至少一场访谈已完成并有可用的提纲执行数据（每段实际用时、覆盖状态、被采纳的追问）。
  - 请求者对该访谈与目标模板均有访问权。
- **触发条件**：
  - [设计] 一场访谈**结束并完成单场复盘**后，系统提示「是否把本场经验沉淀回模板」。
  - [原型] 研究员在 `访谈` → `访谈模板` 标签主动发起 `[＋ 新建模板]` 或 `[编辑]`。
  - [设计] 同一模板被连续多场访谈**以相同方式偏离**时，系统主动提示沉淀。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **系统处理（提取候选）**：从已完成访谈中提取模板候选素材：
   - [原型] **每段的「要问出什么」与开场问法**（研究设计标签的大纲结构）；
   - [原型] **每段计划时长 vs 实际用时**（现场记录左栏：「已用 **6:20 / 5 分**」）；
   - [原型] **提纲覆盖状态**（「3/6 完成」）与 **RQ 目标覆盖五态**；
   - [原型] **被采纳的 AI 追问**（AI 副驾驶 `[使用]` / `[编辑后用]` 的问法）；
   - [设计] **要收集的数据字段**中实际缺失的项。
2. **研究员操作**：选择沉淀去向：
   - **A · 改进已有模板** —— 生成一条**模板变更建议**（如「第 03 段从 20 分调到 25 分」
     「新增开场问法：…」「补一个数据字段：本地化率」）；
   - **B · 另存为新模板** —— [原型] 走 `[＋ 新建模板]`，
     新模板的**来源场次**自动指向本场访谈。
3. **方法负责人操作**：审定模板变更建议。**系统响应**：通过则生成模板新版本；
   [设计] 与蓝本一致——**已开过的访谈锁在自己的模板版本上**，不被追溯修改（D-30）。
   驳回须附理由，理由归档不可覆盖。
4. **系统处理（溯源与计数）**：模板持久化两类真实计数，**不得手工填写**：
   - [原型] **来源场次** —— 标签页文案「访谈模板（**来自 3 场项目**）」的数据来源；
   - [原型] **使用计数** —— 模板行的「**用过 9 次 / 14 次 / 6 次**」。
5. **系统处理（跨模块）**：[设计] 若该模板改进同时构成一条**可复用方法**，
   可提名进 **UC-14.5 晋升队列**；晋升批准后按 UC-14.5 R7 在 Skill 库生成可调用 skill。
   **本 UC 不自行晋升**，只提名。
6. **系统收口**：校验 AC1「模板能看出它来自哪几场项目」与
   AC2「某条问法可追溯到改出它的访谈场次」；记录操作者、时间、对象、结果与来源。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] **只在本场保留** —— 研究员可选择不沉淀，改动仅作用于本场访谈；
    此时该场访谈标注「与模板 vN 存在 M 处偏离」。
  - A2：[设计] **批量沉淀** —— 多场访谈对同一模板的相同偏离可合并为一条变更建议，
    其来源场次为多场。
  - A3：[设计] 模板库为空时展示真实空态与「从一场访谈沉淀第一个模板」式的入口（文案待定），
    不生成示例模板。
- **异常流程**：
  - E1：[设计] 访谈数据不足以支撑沉淀（如提纲未执行、无实际用时）→
    拒绝生成候选并说明原因，**不编造一个模板**（与 UC-16.1 E1 同源约束）。
  - E2：[设计] 沉淀素材中含**拒绝 AI 分析**或**已撤回**的受访者内容 →
    该部分必须排除；若排除后素材不足，按 E1 处理。
    **模板中不得残留任何可识别到具体受访者的原话**（见 R7）。
  - E3：[设计] 模板在审定期间被他人升版 → 提示版本已变化并展示三方差异，
    要求重新确认；**不得静默覆盖**。
  - E4：[设计] 请求超时或依赖不可用时保留已填内容，明确失败原因并可安全重试；
    不产生「看似已沉淀但模板未变」的半成品。

## R5 权限与可见性

- **研究员**：可对自己参与的访谈发起沉淀、提交模板变更建议、另存为新模板；不可直接改已发布模板。
- **方法负责人**：模板变更的**审定人**；可驳回（须附理由）、可生成新版本。
- **引导师 / 项目负责人**：可查看模板及其来源场次与使用计数。
- **观察者 / 客户**：**不可见**模板库与沉淀流程。
- **agent**：可起草模板变更建议、可归纳有效问法；**不可提交沉淀、不可审定**。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。
- 模板受 `uc-0-3` 的**资源可见性范围**约束（全组织可用 / 仅某团队）。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 模板库中每个模板都携带**真实的来源场次与使用计数**，二者由系统维护。
  - [原型验收] AC1a：模板标签页显示「**来自 N 场项目**」、模板行显示「**用过 N 次**」。
  - [设计验收] AC1b：两个计数均为**系统维护的真实计数**且**可下钻到具体场次**
    （原型未渲染下钻，也未表明计数的来源与可写性）。
  - [设计验收] AC2：模板中的某条问法/某段时长可**追溯到改出它的访谈场次**。
  - [设计验收] AC3：模板升版**不追溯已开过的访谈**。
  - [设计验收] AC4：模板中**不含可识别到具体受访者的原话或个人信息**。
- **失败后置条件**：不产生「看似已沉淀」的模板变更；失败事件进入可观测日志。
- **不包含**：
  - **模板的正向创建与编辑器本体**（UC-6.1）、**用模板新建访谈**（UC-6.1/6.2）。
  - **自动沉淀**：系统可提示、可起草，但**提交与审定必须由人**。
  - **方法晋升与 skill 生成**（UC-14.5）——本 UC 只提名。
  - 跨组织共享模板。

## R7 业务规则（不随具体实现变化的硬性约束）

- [原型] **模板携带两个计数**：标签页「访谈模板（**来自 3 场项目**）」与
  模板行「**用过 N 次**」在原型中已渲染。
  [设计] 二者必须是**系统维护的真实计数**，**不得手工填写或伪造**（原型未表明其来源与可写性）。
- [设计] **溯源不可抹除**：模板中每条由沉淀改出的内容永久保留其来源场次引用
  （与 UC-14.3「规则的教训溯源不可抹除」同源）。
- [设计] **沉淀必须经人提交与审定**：agent 可起草，**不得自动改模板**。
- [设计] **模板升版不追溯**：已开过的访谈锁在自己的模板版本上（D-30）。
- **[设计 · 合规硬约束] 模板中不得残留可识别到具体受访者的内容**：
  沉淀出的问法与字段必须是**去个体化**的方法性内容；
  含「拒绝 AI 分析」或已撤回的素材一律排除（UC-6.3 / UC-17.2）。
- [设计] **驳回理由归档不可覆盖**（与 UC-17.1 的「退回理由已归档不可覆盖」一致）。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 沉淀提交、审定、驳回、模板升版四类动作必须记审计事件并显示影响范围。
- [待确认] 「素材不足」的判定阈值；同一偏离出现几次后系统主动提示沉淀。

## R8 界面线索

  [原型] `[＋ 新建模板]`、模板行的 `[编辑]` `[用它新建]`；
  [设计] 访谈完成后的**单场复盘**页提供「沉淀回模板」入口。
- **信息架构**：[原型] 模板库列表 —— 每行「模板名 ｜ **用过 N 次** ｜ 一句话说明 ｜
  **N 题 · X–Y 分** ｜ `[编辑]` `[用它新建]`」；筛选「全部标签 / 客户 / 内部 / 高优先级」。
- **推荐交互**：
  - [原型] 标签页文案本身携带溯源信息（「来自 3 场项目」），**应可点击展开到场次清单**。
  - [设计] 变更建议以**逐条 diff** 呈现（原值 → 建议值 + 来源场次 + 理由），

## R9 非功能约束

- **性能/规模预期**：[设计] 模板库规模为十级（原型 5 个），列表一次加载即可；
  来源场次与使用计数应为增量维护，不做全表扫描。
- **安全/隐私/合规**：沉淀素材的抽取必须在**受访者授权范围内**进行；
  去个体化是硬要求（R7），实现上应有自动 PII 检查 + 人工确认双轨
  （对照原型「已自动遮盖：一个邮箱地址与一个手机号」的 PII 遮盖机制）。
- **兼容与降级要求**：响应式 Web；PII 检查服务不可用时**阻断沉淀**，不得放行。

## R11 切分提示（给 requirement-author）

- 建议先拆「**模板的两个溯源字段（来源场次 / 使用计数）** → 从已完成访谈提取候选素材 →
  **变更建议与逐条 diff** → 审定与升版（不追溯）→ **去个体化 PII 闸门** →

- **两个计数字段应与 06-itv 的模板对象一并实现**，不要在 M16 复制一套模板表。
- 若 requirement-author 选择合并进 UC-6.1，上述拆分与验收原样保留。
- **优先级 / 先后依赖**：P1；**3 点**；阶段三 · 迭代 12 · 对外与预演；
