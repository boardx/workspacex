> 所属：阶段三 · 跨项目与对外 / M16 数字专家与虚拟推演

> **原型载体（已确认存在）**：`访谈` → `[打开访谈]` → `虚拟` / `专家推演` →

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-16.3 / 虚拟与真人对照（原型子标签 **`采纳与标注`** + **「三位专家的分歧」**）
- **Actor**：**研究员**、**引导师**
- **目标**：[原型] 让虚拟层的**分歧**成为真人访谈的问题来源（原型原话「分歧本身就是要去问真人的地方」）；
  [Backlog] 并在真访谈完成后标出**预演猜错的地方**作为材料补充信号；
  [Backlog] 虚拟来源永远单独计数，不能冒充真人洞察。
- **本用例结果**：① 同一问题下多位专家的立场并列，冲突被显式标出
  （[原型]「**与 V1 直接冲突**」）；② 冲突可一键写成**指定真人访谈的必问题**；
  ③ 真访谈完成后可标注哪些虚拟判断**被真人推翻**，回流为材料补充信号。
- **系统边界**：**采纳与标注队列（待判）**、**分歧识别与并列展示**、
  `[把这处冲突写成访谈 N 的必问题]` 出口、**被真人推翻的标注**与其回流。
- **不属于本 UC 的边界**：数字专家构造（UC-16.1）、单条推演与其六字段（UC-16.2）、
  真人访谈的证据矩阵（UC-6.5）。
- **核心数据对象**：采纳队列项（待判 / 已采纳 / 已驳回）、**分歧组**（含冲突关系标注）、
  必问题写入记录、**被真人推翻标记**、材料补充信号。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“组织大脑、访谈、上传 Agent”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [Backlog] 真访谈完成后。
  - 系统从 **洞察与报告** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **系统处理（采纳队列）**：[原型] UC-16.2 的 `[送去采纳]` 把推演卡送入
   **`采纳与标注`** 子标签，状态为「**待判**」（原型：`采纳与标注 4 待判`）。
   [设计] **待判不是洞察**——在人做出判断之前，它不进入任何洞察或证据统计（子标签内部未探明，属推断）。
2. **系统处理（分歧识别）**：[原型] 同一问题下多位专家的立场**并列展示**，
   并显式标出冲突关系：
   ```
   V1 实际由业主承担，合同条款只是形式
   V2 EPC 会接受有限共担，但要换来排他与预付
   V3 责任在流程：审批延误不可归责于任何一方 —— 与 V1 直接冲突
   ```
   **系统不替人裁决分歧**（与 UC-14.1 的成对召回同源约束）。
3. **研究员操作（分歧 → 真人必问题）**：[原型] 点
   **`[把这处冲突写成访谈 13 的必问题]`**。
   **系统响应**：把该分歧写成**指定真人访谈**提纲中的一条**必问**题
   （对照 UC-6.4 左栏提纲的「**必问** · 替代方案与不作为」），
   并携带各方立场作为该问题的判定目标。
   > [原型 原话]「**分歧本身就是要去问真人的地方**」——
   > 这是本 UC 的价值主张：虚拟层的作用不是给答案，是**指出该去问什么**。
4. **研究员操作（真访谈完成后 · 标注被推翻）**：把真人回答与原虚拟立场对照，
   标出**预演猜错的地方**。**系统响应**：[设计] 给对应推演卡打**「被真人推翻」**标记，
   保留原卡不删除（对照 UC-16.2 的「会被推翻」字段——此处正是那个条件被触发）。
5. **系统处理（材料补充信号）**：被推翻的判断回流为**材料补充信号**——
   指出数字专家的材料集在哪一块存在缺口，供 UC-16.1 补材料后 `[再跑一轮]`。
6. **系统收口**：校验 AC1「能看出哪些判断是被真人推翻的」与
   AC2「分歧可一键写成指定访谈的必问题」；
   记录操作者、时间、对象、结果与来源。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[Backlog] 对照结论只用于改进方法，不写回客户报告。系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
- **异常流程**：
  - E1：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

- **研究员**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **引导师**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **观察者**：默认不能发起或修改；仅当内容已发布且授权范围允许时只读查看脱敏结果。
- **项目经理**：可查看项目级状态与审计摘要；是否可代替业务 Actor 执行写操作需由角色模板显式授权。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 形成与本 use case 对应的正式记录或明确状态，并可从来源页面再次打开。
  - 所有跨模块回流均携带来源资源、版本、操作者/触发者、时间和可见范围。
  - [设计验收] AC1：能看出哪些判断是被真人推翻的（被推翻的卡保留且带标记，不删除）。
    ——「被真人推翻」标记在原型中**未见**（`采纳与标注` 子标签内部未探明），属新增设计。
  - [原型验收] AC2：**分歧被显式标出**（如「与 V1 直接冲突」），且可一键
    `[把这处冲突写成访谈 N 的必问题]`，写入指定真人访谈的提纲并标为**必问**。
  - [设计验收] AC3：**采纳队列的「待判」状态不构成洞察**——待判项不进入任何洞察计数、
    证据矩阵或决策依据。
  - [裁决验收] AC4（**D-25**）：即使被采纳，虚拟产物仍**不能成为强洞察、不进决策依据**
    （服务端强制，见 UC-16.2 R7）。
- **失败后置条件**：
  - 不创建“看似成功”的正式记录；可重试内容保留为草稿，失败事件进入可观测日志。
  - 写必问题失败时不产生「以为写进去了但访谈提纲里没有」的静默丢失。
- **不包含**：
  - 虚拟结论冒充真人洞察、材料不足时编造人格。
  - **对照结论写回客户报告**（见 R7）。
  - **系统自动裁决分歧**——分歧只被标出与提问，不被系统合并或择一。
  - 数字专家构造（UC-16.1）、单条推演（UC-16.2）、真人证据矩阵（UC-6.5）。
  - 不扩展到本 use case 未声明的跨组织、跨客户或公开发布能力。

## R7 业务规则（不随具体实现变化的硬性约束）

- [Backlog] **对照结论只用于改进方法，不写回客户报告**。
  其**实现形态**即「分歧 → 真人必问题 → 材料补充信号」这条闭环：
  [原型 原话]「**分歧本身就是要去问真人的地方**」。
- [原型] **系统不替人裁决分歧**：多位专家的冲突立场并列保留并标注冲突关系，
  不合并、不择一（与 UC-14.1 冲突成对召回同源）。
- [设计] **「待判」不是洞察**：采纳队列中的项在人判断前不进入任何洞察或证据统计。
  （原型只给出子标签标题「采纳与标注 4 待判」，其语义为推断。）
- [裁决 D-25] **即便被采纳，虚拟产物仍不得成为强洞察或决策依据**——服务端强制，
  采纳动作不改变虚拟来源标识。
- [设计] **被推翻的卡不删除**：保留原卡并打「被真人推翻」标记，
  它是 UC-16.2「会被推翻」条件的实际触发记录，也是材料缺口的证据。
- [设计] **必问题必须写到具体某一场访谈**（原型：「访谈 13」），不允许写成全局待办。
- AC1：能看出哪些判断是被真人推翻的。
- AC2：分歧可一键写成指定访谈的必问题。
- AC3：待判不构成洞察。
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- AI/Agent 的写回、覆盖、发布或高影响工具调用必须遵守原型中的批准点；未经确认只保留为草稿或候选。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

- **「待判不构成洞察」独立验收**：它是防止虚拟结论悄悄变成证据的第一道闸。
- 单个 feature 应能在一次会话内实现并验证，不应把本 use case 的全部前后端与所有异常态塞进一个 feature。
- **优先级 / 先后依赖**：P1；**3 点**；阶段三 · 迭代 12 · 对外与预演；
  先满足“组织大脑、访谈、上传 Agent”与 **UC-16.1 / UC-16.2 / UC-6.2**。
- 对 P1 能力可在主链路稳定后实现，但合入时仍需覆盖本文全部验收状态。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态）：AC1 —— 把一条虚拟立场标为「被真人推翻」，断言：
  ① 原推演卡**未被删除**且带该标记；② 可跳到推翻它的真人引述；
  ③ 生成一条指向其材料集的补充信号。
- V1b（成功态 · **本 UC 主锚点**）：AC2 —— 构造三位专家对同一问题的立场，
  断言 ① 三条**并列返回**、系统未合并或择一；② 冲突关系被显式标注（如「与 V1 直接冲突」）；
  ③ 点 `[把这处冲突写成访谈 13 的必问题]` 后，**访谈 13 的提纲中出现一条标为「必问」的问题**，
  且携带各方立场作为判定目标。
- V1c（成功态）：AC3 —— 队列中处于「待判」的项，断言其**不出现在**洞察计数、
  证据矩阵与决策依据可选项中；采纳后仍受 D-25 约束（见 V1d）。
- V1d（权限/安全态）：AC4 —— 对**已采纳**的虚拟产物尝试标为强洞察或作为决策依据引用，
  断言**仍被服务端拒绝**（采纳不改变虚拟来源标识）。
- V2（权限态）：逐一使用 研究员、引导师、观察者、项目负责人、未授权用户访问；
  返回数据和可执行动作严格符合 R5。
- V3（空态）：无目标数据时显示真实空态与下一步，不生成伪数据。
- V4（依赖失败）：模拟网络/外部依赖失败，输入和最近成功数据保留，错误可解释且可重试。
- V5（并发态）：两名用户修改同一资源时不静默覆盖，并可识别最终版本。
- V6（审计态）：关键动作可按操作者、时间、对象和结果检索；越权尝试也有安全审计记录。
