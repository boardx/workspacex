## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-17.1 / 全链路审计（**两级：项目级 + 组织级**）
- **Actor**：**合规负责人**（组织级跨项目检索）、**项目负责人**（项目级时间线）、
  **组织管理员**（其访问本身被审计，见 UC-17.5）
- **目标**：[Backlog] 谁读了什么、AI 用了什么、数据什么时候删——都要可查，且默认最小授权。
- **本用例结果**：
  - **项目级（已存在）**：每个项目有一条**四类事件同一时间线**的**不可删除**审计记录，
    可分类计数筛选并导出 CSV/JSON；
  - **组织级（需新建）**：合规负责人可**跨项目**按项目 / 人 / 时间检索并导出。
- **系统边界**：审计事件模型（四类）、**项目级时间线**、**组织级跨项目检索屏**、
  分类计数筛选、导出、不可删除与保留期。
- **不属于本 UC 的边界**：**AI 结论的输入还原**（→ **UC-14.6**）、
  **管理员访问边界与「看我的访问记录」**（→ **UC-17.5**）、
  **授权撤回与删除**（→ UC-17.2）、**审计保留期参数**（→ UC-17.3）。
- **核心数据对象**：审计事件（类型 / 时间 / 操作者 / 对象 / 结果 / 上下文引用）、
  事件分类计数、导出任务、跨项目检索索引。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“全模块埋点”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [Backlog] 任何读取或 AI 调用发生。
  - 系统从 **审计与反馈** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **系统处理（埋点）**：记录人与 agent 的每次读取、调用、导出，
   归入 [原型] **四类事件**：**角色变更 / 版本 / Agent 调用 / 决策**。
2. **项目级 · 系统响应（已存在，写实）**：[原型] `项目 → 成果沉淀 → 审计与反馈` 呈现
   **四类事件同一条时间线**，**不可删除**；头部为**分类计数筛选**
   「全部 214 ｜ 角色变更 8 ｜ 版本 11 ｜ Agent 调用 183 ｜ 决策 12」，
   并提供 **`[导出 CSV / JSON]`**。条目原文（含**条目内硬规则**）：
   ```
   12:06:41 决策  林可签署「首批只做德国、荷兰」    依据 v2 · 授权有效期内
   11:52:09 版本  高琳提交第 2 组 v2                v1 退回理由已归档，不可覆盖
   11:20:33 调用  Ava → Ledger · 现金流对比（深度 2） 412k token · 人已批准
   10:14:52 版本  林可退回第 2 组 v1，附理由        v1 转为只读快照
   09:41:07 角色  授予客户方王毅「观察者」＋ 第 2 组原始内容临时读权
                  环节 3 结束自动失效
   ```
   条目内的四条硬规则见 **R7**：退回理由**已归档不可覆盖** ｜ v1 **转为只读快照** ｜
   临时读权**环节结束自动失效** ｜ Agent 调用记 **token + 深度 + 人已批准**。
3. **组织级 · 合规负责人操作（需新建）**：在后台按 **项目 / 人 / 时间** 跨项目检索审计事件。
   **系统响应**：返回聚合结果并支持导出；检索行为**本身也写审计**。
4. **系统处理（不可删除）**：[原型] 审计日志**任何人不可删**——
   无删除接口、无管理员例外、无「清理」入口；到期由 UC-17.3 的**审计保留期**统一处置。
5. **系统处理（交叉引用，D-34 A′）**：Agent 调用类事件必须携带**检索会话 ID**，
   可一键跳到 **UC-14.6** 的「这次读到了什么」——
   原 AC1「任一条结论都能还原它当时看了什么」**由 UC-14.6 承接实现**，本 UC 只保证可跳转。
6. **系统收口**：校验 AC1′「项目级四类事件同屏、不可删、可筛可导出」与
   AC2「组织级可跨项目按项目/人/时间检索并导出」；记录操作者、时间、对象、结果与来源。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] 审计日志本身只读，任何人不可删。系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
- **异常流程**：
  - E1：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

- **合规负责人**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **项目经理**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **受访者**：可查看/确认自身授权并提出撤回；不能访问项目内部材料或其他受访者数据。
- **观察者**：默认不能发起或修改；仅当内容已发布且授权范围允许时只读查看脱敏结果。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。

## R7 业务规则（不随具体实现变化的硬性约束）

- [原型] **审计日志本身只读，任何人不可删**（原型原文：「四类事件同一条时间线，**不可删除**」）。
  [设计] 由此推出的实现约束——**无删除接口、无管理员例外、无清理入口**。
- [原型] **四类事件同一条时间线**：角色变更 / 版本 / Agent 调用 / 决策，
  不得拆成四个互不相通的列表。
- **[原型 · 条目内硬规则，四条]**
  - **退回理由已归档，不可覆盖** —— 退回附的理由是审计对象，任何后续提交都不能改写它。
  - **被退回版本转为只读快照** —— v1 退回后不可再编辑，只能提交新版本 v2。
  - **临时读权环节结束自动失效** —— 授予与失效两条事件都必须出现在时间线上（见 UC-15.1）。
  - **Agent 调用必须记 token 用量 + 调用深度 + 人已批准** ——
    三项在原型条目中均已渲染（「412k token · 深度 2 · 人已批准」）；
    [设计] 「三项缺一即视为埋点不合格」是由此推出的验收口径。
- [裁决 D-34 A′] **两级审计各司其职**：项目级是**时间线**（看一场项目里发生了什么），
  组织级是**检索**（跨项目按人/时间查）；**同一份事件数据，两种视图**，不得各存一套。
- [设计] **审计检索本身也写审计**：谁查了谁的记录必须可查（与 UC-17.5 的管理员边界联动）。
- [设计] **审计事件不可篡改**：写入后字段只读；存储层建议追加写 + 完整性校验。
- AC1′：项目级四类事件同屏、不可删、可筛可导出。
- AC2：组织级可跨项目按项目/人/时间检索并导出。
- AC3：条目内四条硬规则成立。
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- AI/Agent 的写回、覆盖、发布或高影响工具调用必须遵守原型中的批准点；未经确认只保留为草稿或候选。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R11 切分提示（给 requirement-author）

- 建议先拆“**统一审计事件模型（四类）** → 各模块埋点接入 →
  **项目级时间线 + 分类计数筛选 + 导出**（已有 UI，按原型写实）→
  **组织级跨项目检索屏**（需补画）→ 不可删除与完整性 → 自动化验收”。
- **「条目内四条硬规则」应各自归属到产生它的模块**（退回理由/只读快照 → 13-deliv；
  临时读权失效 → UC-15.1；Agent 调用三项 → 04-agent），
  本 UC 只验收「它们在时间线上如实呈现」。
- **「不可删除」独立成 feature 并有独立的接口枚举验收**：断言不存在任何删除路径。
- ⚠ 不要拆出「把项目级审计搬到后台」的 feature——D-34 A′ 明确别搬走。
- 单个 feature 应能在一次会话内实现并验证，不应把本 use case 的全部前后端与所有异常态塞进一个 feature。
- **优先级 / 先后依赖**：P0；**5 点**；阶段三 · 迭代 10 · 治理先行；先满足“全模块埋点”；
  **必须先于 UC-17.5 与 UC-17.7**（两者都消费本 UC 的事件）。
- 对 P0 必做链路优先实现成功态、权限态与数据闭环，异常态不得延期到上线后。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态）：**AC1′（项目级）** —— 在一个项目中依次触发四类事件
  （改一次角色 / 退回一个版本 / 跑一次 agent / 签一条决策），断言：
  ① 四条都出现在**同一条时间线**上；② 分类计数各 +1 且筛选结果正确；
  ③ `[导出 CSV / JSON]` 导出的记录数与筛选结果一致。
- V1b（成功态）：**AC2（组织级）** —— 以合规负责人身份跨两个项目按人 + 时间范围检索，
  断言返回两个项目的事件；导出成功；**该次检索本身产生一条审计记录**。
- V1c（成功态）：**AC3（条目内四条硬规则）** ——
  ① 退回一个版本并附理由后，尝试修改该理由被拒；
  ② 被退回的 v1 尝试编辑被拒（只读快照）；
  ③ 临时读权在环节结束后自动失效，且**授予与失效两条事件都在时间线上**；
  ④ Agent 调用事件含 `token` / `depth` / `approved_by`（人）三项，缺任一项埋点判为不合格。
- V1d（交叉引用）：取一条 Agent 调用事件，断言它携带**检索会话 ID**且可跳到 UC-14.6 的记录；
  「结论还原」的完整验收在 UC-14.6 的 V1–V5。
- V1e（安全态 · 不可删除）：**枚举全部接口**，断言不存在任何删除或清空审计的路径；
  以组织管理员、合规负责人身份直接构造删除请求均被拒并记安全审计。
- V2（权限态）：逐一使用 合规负责人、项目负责人、组织管理员（无项目角色）、观察者、
  未授权用户访问项目级与组织级两个入口；返回数据和可执行动作严格符合 R5。
- V3（空态）：无目标数据时显示真实空态与下一步，不生成伪数据。
- V4（依赖失败）：模拟网络/外部依赖失败，输入和最近成功数据保留，错误可解释且可重试。
- V5（并发态）：两名用户修改同一资源时不静默覆盖，并可识别最终版本。
- V6（审计态）：关键动作可按操作者、时间、对象和结果检索；越权尝试也有安全审计记录。
