# 原始需求（细化）— UC-20.3 机密数据的模型路由

> 所属：阶段一 · 能跑完一场项目 / **M20 模型管理**（新增模块 20-model）
> 来源：**运行态原型**（同一条硬约束在**五处**独立出现，是本产品最强的一条数据边界）：
> ① 后台 → AI 能力 → **模型管理** 的自托管组说明：
>    「权重跑在自己的 GPU 上，**客户机密材料只走这一类**」；
> ② 后台 → AI 能力 → **MCP 服务器** 的安全策略开关：
>    「✓ **客户机密材料仅允许本地模型处理**」；
> ③ 对话屏 **批准卡**：「要读的数据：项目库 ＋ 电价曲线 · **含机密，仅本地模型**」，
>    同卡显示「模型：gpt-5.2 ＋ **本地 qwen3-32b** `[改]`」；
> ④ 大脑 → **AI 读到了什么** 的系统提示装配：
>    「硬约束原文：不得写入决策节点；不得引用未在上文列出的证据；
>    **客户机密材料只能由本地模型处理。**」；
> ⑤ 蓝本设计器 **【模型策略】**：「现场 sonnet-4.6（低延迟优先）｜ 会后整理 opus-4.6（质量优先）｜
>    **机密材料 仅本地 qwen3**」。
> 另：后台「成员与配额」的按任务类型降级矩阵中，「**含客户机密 → 禁止降级**
> （替代模型不满足隐私与部署要求）」。

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **5**；建议迭代 **迭代 2 · 能挂能力**。
>
> **[人类已拍板 · D-17]** 「**出域 ＝ 出组织**（第三方 API）」；phase-1 **只做闭源/自托管二分**；
> 「出法域」（数据驻留路由）列入 **phase-3 的 17-gov**。本用例严格按此边界书写。
> **[编号提示 · 待确认]** `UC-9.x` 与 phase-2 的 `09-kg`（UC-20.1～9.5）冲突，需全局重编号裁决。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-20.3 / 机密数据的模型路由
- **Actor**：**系统**（路由执行者）、**批准人**（引导师 / 项目负责人，在批准卡上确认）、
  **组织管理员**（配置机密判定与开关）
- **目标**：[原型] 让「**客户机密材料只能由本地模型处理**」成为**系统强制的硬路由**，
  而不是提示或约定——任何一次会把机密内容送给闭源 API 的调用都必须**在服务端被阻断**。
- **本用例结果**：每一次模型调用在发起前完成「**内容机密判定 → 模型类型约束 → 路由或拒绝**」；
  批准卡上如实显示「含机密，仅本地模型」；系统提示中带同一条硬约束；
  含机密的任务**禁止降级**。
- **系统边界**：机密标记的来源与传递、调用前的机密判定、**硬路由执行点**、
  批准卡的机密提示、系统提示的硬约束注入、含机密任务的禁止降级、
  违规尝试的拦截与留痕。
- **核心数据对象**：机密标记（材料级 / 项目级 / 片段级）、模型类型（闭源 API / 开源自托管）、
  路由决策记录、批准记录、系统提示硬约束段、拦截事件。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 组织内**至少有一个已启用的开源自托管模型**（UC-20.2）；否则含机密的任务
    **一律明确失败**（见 R4 E1），不得回落到闭源模型。
  - 材料/项目/片段上存在可判定的**机密标记**。
    **[待确认]** 机密标记从哪来——上传时人工标、按项目统一标、还是 AI 识别？
    这是本用例最关键的未决项（见 R10）。
  - [21-mcp] 安全策略开关「客户机密材料仅允许本地模型处理」处于开启态
    （[设计] 该开关**默认开且建议不可关**，见 R7）。
- **触发条件**：
  - 任何一次模型调用发起前——包括 agent 回答、skill 执行、私聊（UC-4.3）、
    试跑、改进提案生成（UC-3.6）、报告生成、转录与综合等。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **系统处理**：在组装本次调用的上下文时，**逐项判定机密性**。
   **系统响应**：把将要送入模型的内容按来源分类（项目材料 / 转写 / 客户资料 /
   知识条目 / 用户输入…），对每一项查其机密标记。
   [设计] 判定必须发生在**上下文装配完成后、模型调用发起前**——
   这是唯一能覆盖全部路径的执行点。
2. **系统处理**：**硬路由**。
   **系统响应**：
   - 上下文中**含任一机密项** → **只允许调用「开源自托管」类模型**；
     候选集 = UC-20.2 的 `已启用` ∩ `开源自托管`。
   - 上下文中**不含机密项** → 候选集 = UC-20.2 的 `已启用`（闭源与自托管均可）。
   - **拒绝而非降级**：若含机密但无可用自托管模型，**明确失败**并说明原因，
     **绝不回落到闭源模型**。
3. **系统处理**：在**系统提示**中注入同一条硬约束。
   **系统响应**：[原型] 大脑「AI 读到了什么」显示装配后的系统提示包含
   `# 硬约束` 段，其原文含「**客户机密材料只能由本地模型处理**」
   （同段另有「不得写入决策节点；不得引用未在上文列出的证据」）。
   [设计] **提示层的约束是第二道，不能替代第一道的服务端路由**——
   两道都要有（提示可被模型忽略，路由不可）。
4. **系统处理**：需要人批准的动作上，在**批准卡**如实呈现。
   **系统响应**：[原型] 批准卡显示三行关键信息：
   - `模型：gpt-5.2 ＋ **本地 qwen3-32b** [改]`
   - `token 预算：800k（约 ￥9.6）`
   - `要读的数据：项目库 ＋ 电价曲线 · **含机密，仅本地模型**`
   [设计] 「含机密，仅本地模型」是**系统判定结果的展示**，不是人手填的标签；
   `[改]` 打开的模型切换面板中，**闭源模型在含机密时不可选**。
   **[待确认]** 原型批准卡同时列出 `gpt-5.2` 与 `本地 qwen3-32b` 两个模型——
   说明存在**分段路由**：非机密部分走闭源、机密部分走本地？
   还是「主模型 + 机密专用模型」？**这个组合语义需产品确认**（见 R10）。
5. **系统处理**：**含机密的任务禁止降级**。
   **系统响应**：[原型] 按任务类型的降级矩阵中「**含客户机密 → 禁止降级**
   （替代模型不满足隐私与部署要求）」——
   即使组织级/成员级/agent 级阈值已触发，含机密的调用**不降级**；
   超限时走「请人批准」或「明确失败」，见 UC-4.1 R7。
6. **系统处理**：**记录路由决策**。
   **系统响应**：每次调用记录：是否判定含机密、依据哪些标记、候选集、实际选用的模型、
   是否发生拒绝。该记录进入 UC-4.4 的 tool-call / 调用链审计。
7. **系统处理**：**拦截违规尝试**。
   **系统响应**：任何绕过路由的尝试（直接指定闭源模型、篡改机密标记、
   通过 API 直调）都被服务端拒绝并计入 UC-4.4 的**越权调用拦截计数**
   （[原型] 后台数据总览的「越权调用尝试 …… 已拦截 7 次」）。
8. **系统收口**：校验 AC1「**含机密的上下文只可能被自托管模型处理**」、
   AC2「无可用自托管模型时明确失败而非回落闭源」、
   AC3「批准卡如实显示机密判定结果且闭源模型不可选」、
   AC4「含机密任务不降级」；路由决策全量留痕。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] 蓝本【模型策略】预设了「机密材料 仅本地 qwen3」——
    [设计] 这是**默认选择**，但**不构成豁免**：即使蓝本没配，路由仍强制生效。
  - A2：[设计] 用户可主动把一次调用标为「含机密」以收紧路由；
    **反向（把系统判定的机密取消）必须走显式的解密/降密流程并留痕**，
    不得由发起人随手取消。
  - A3：[设计] 若上下文中只有少量机密项，提供「**剔除机密项后用闭源模型**」的出口——
    但必须让人看到剔除了什么、结论可能因此受限。
    **[待确认]** 是否提供该出口。本文按「提供但需人确认」处理。
  - A4：[设计] 数字专家/虚拟结论等非真实客户数据不视为机密（对照 D-25），
    但其**输入材料**若含机密仍受本路由约束。
- **异常流程**：
  - E1：[设计 · 关键] **无可用自托管模型**（一个都没启用，或全部依赖失败）时——
    含机密的调用**一律明确失败**，界面给出可读原因
    （「本次内容含客户机密，需本地模型处理，当前无可用本地模型，请联系管理员」）；
    **绝不回落到闭源模型**，也不静默丢弃机密内容后继续。
  - E2：[设计] 机密判定**不确定**（标记缺失或冲突）时，**从严处理**——
    按「含机密」路由。宁可用本地模型跑，也不冒出域风险。
  - E3：[设计] 自托管模型在调用中途不可达时，本次调用失败并保留输入，
    **不切换到闭源模型重试**。
  - E4：[设计] 批准卡上人点 `[改]` 尝试改成闭源模型时被拒绝，并说明「本次含机密，
    仅本地模型可选」。
  - E5：[设计] 机密标记在调用发起后被变更时，以**发起时**的判定为准并留痕；
    已完成的调用不追溯，但新调用按新标记执行。
  - E6：[设计] 请求超时或依赖不可用时保留输入与最后成功状态，明确失败并可安全重试。
  - E7：[设计] 权限在过程中被撤回时立即终止后续操作；已完成步骤按审计规则保留。

## R5 权限与可见性

- **系统**：路由的唯一执行者；**任何角色都不能豁免**（含组织管理员）。
- **组织管理员**：可配置机密判定规则与 21-mcp 的安全开关；
  [设计] **不得关闭「客户机密材料仅允许本地模型处理」**（见 R7）；
  可查看全组织的路由决策与拦截记录。
- **批准人**（引导师 / 项目负责人）：在批准卡上看到「含机密，仅本地模型」并决定是否执行；
  **不能改变路由结果**，只能批准或取消。
- **能力维护者**：配 agent/skill 时可见「该模型是否可用于机密场景」的标记（UC-20.2 AC3）；
  不能为某个 agent 开豁免。
- **引导师 / 组长 / 组员**：在对话中看到批准卡的机密提示；
  [设计] 应能看到「本次为什么只用本地模型」的简要解释。
- **观察者**：不可见机密内容与路由细节。
- **[D-18] 管理员权力边界**在本用例不放宽：能看路由决策**元数据**，
  不等于能读机密内容本身。
- 未登录、链接失效或未列出的角色：默认无权限；接口不得返回越权数据。

## R7 业务规则（不随具体实现变化的硬性约束）

- **[原型 · 本产品最强的一条数据边界] 客户机密材料只能由本地（开源自托管）模型处理。**
  该约束在原型中**五处独立出现**（模型管理 / MCP 安全策略 / 批准卡 / 系统提示 / 蓝本模型策略）。
- **[设计]** 实现时**必须是服务端强制路由**，不是提示、不是默认值、**不是可关闭的开关**。
  ⚠ **口径更正**：此前把这句并入 `[原型]` 是错的——原型里它**恰恰是一个可勾选开关**：
  MCP 安全策略第 3 条 `✓ 客户机密材料仅允许本地模型处理`，与第 4 条
  `☐ 允许 agent 自行发现新 MCP 服务器（默认关）` **形态完全相同**。
  「不可关闭」是本文的收紧主张，与 R10 的 `[待确认]`（是否允许关闭）**属同一个未决项**，
  须由人类裁决，不得由实现者按 `[原型]` 直接落地。
- **[设计] 两道防线缺一不可**：
  ① **服务端硬路由**（候选集收窄到自托管，闭源调用被阻断）；
  ② **系统提示硬约束**（注入 `# 硬约束` 段的原文）。
  提示层可被模型忽略，因此**不能只有第 ②**。
- **[设计] 拒绝优先于降级**：含机密且无可用自托管模型时**明确失败**；
  **绝不回落闭源、绝不静默丢弃机密内容后继续**。
- **[原型] 含客户机密 → 禁止降级**（替代模型不满足隐私与部署要求）。
- **[设计] 判定不确定时从严**（按含机密处理）。
- **[设计]** 「含机密，仅本地模型」是**系统判定结果**，不由人手填；
  取消机密标记须走显式流程并留痕。
- **[设计]** 该路由**无角色豁免**——组织管理员亦不能为某次调用开绿灯。
- **[设计]** 21-mcp 的开关「客户机密材料仅允许本地模型处理」**默认开**；
  **[待确认]** 是否允许关闭。本文按**不允许关闭**（只读展示为常开）处理，需人类确认。
- **[D-17]** 「出域 ＝ 出组织」——闭源 API 调用即出域；phase-1 只做闭源/自托管二分。
- 每次路由决策与每次拦截都必须留痕，进入 UC-4.4 的审计与越权拦截计数。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 机密判定必须在上下文装配路径上同步完成，
    增加的时延应控制在**百毫秒级**，不得成为对话响应的瓶颈。
  - [设计] 判定结果可在同一次调用内缓存，但**不得跨调用缓存**（标记可能已变）。
- **安全/隐私/合规**：
  - **本用例本身就是一条合规控制**，其失效等同数据泄露；
    实现上应有**独立的集成测试与回归**，且路由代码路径不允许被功能开关绕过。
  - 路由决策记录中**不得包含机密内容原文**，只记标记与依据。
  - 拦截事件进入 UC-4.4 的越权调用计数并在后台数据总览可见。
  - [D-14] 路由决策的留痕保留期按「留痕保留期 / 审计保留期」参数执行。
- **兼容与降级要求**：
  - 响应式 Web；批准卡在**移动端必须完整可读**（现场批准多在手机上完成）。
  - **本用例不允许任何形式的功能降级**：路由服务不可用时，含机密的调用一律失败。

## R11 切分提示（给 requirement-author）

- 建议拆分顺序：
  1. **单一路由执行点**（上下文装配后、模型调用前）——先把「所有调用都必须经过这里」
     的架构约束立住
  2. 机密判定（消费标记 + 不确定时从严）
  3. **硬路由：候选集收窄到自托管 + 闭源调用阻断**
  4. **无可用自托管模型时明确失败**（不回落）
  5. 系统提示硬约束注入 + 「AI 读到了什么」的只读审查
  6. 批准卡的「含机密，仅本地模型」展示 + `[改]` 面板候选收窄

## R12 AI Ready 验收线索

- V1（硬路由态）：AC1 —— 构造一次含机密材料的调用，
  实际选用的模型必为开源自托管；直接构造请求指定闭源模型 ID 时被服务端拒绝。
- V2（拒绝优先）：AC2 —— 停用全部自托管模型后发起含机密调用，
  返回明确失败与可读原因；**审计中不存在任何向闭源 API 的出站记录**。
- V3（批准卡态）：AC3 —— 含机密的批准卡显示「含机密，仅本地模型」；
  点 `[改]` 后候选列表**只有自托管模型**；尝试提交闭源模型被拒。
- V4（禁止降级）：AC4 —— 在组织级已达降级阈值的情况下发起含机密调用，
  **不降级**；超限时走请人批准或明确失败。
- V5（提示层）：AC5 —— 在「AI 读到了什么」中可只读审查系统提示，
  `# 硬约束` 段包含「客户机密材料只能由本地模型处理」原文。
- V6（拦截计数）：AC6 —— 反复尝试绕过路由，拦截次数在后台数据总览的
  「越权调用尝试」中递增。
- V7（从严态）：机密标记缺失或冲突时按含机密处理（走自托管）。
- V8（中途失败）：自托管模型在调用中途不可达时本次调用失败，
  **不切换到闭源模型重试**。
- V9（无豁免）：以组织管理员身份尝试为某次调用开豁免被拒绝并记审计。
- V10（留痕态）：每次调用有路由决策记录（是否含机密、依据、候选集、实际模型），
  且记录中**不含机密内容原文**。
- V11（权限态）：逐一使用 组织管理员 / 批准人 / 能力维护者 / 引导师 / 组员 / 观察者 /
  未授权用户访问，可读数据与可执行动作严格符合 R5。
- V12（旁路检测）：全量扫描代码中发起模型调用的路径，
  断言**没有任何一条绕过统一路由执行点**（可用架构测试/依赖规则实现）。
