## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-2.4 / 蓝本版本与锁定
- **Actor**：**方法负责人**（发布/归档/回滚）、**引导师**（读版本、按版本新建项目）
- **目标**：[原型] 让蓝本可以放心地改——**「改动生成 v5，已开过的项目锁在自己的版本上」**。
  改蓝本永远不会追溯性地改动任何已经开过的项目。
- **本用例结果**：[原型] 每次发布生成 v(n+1) 并记录改了哪几项设计配置；旧版自动归档但
  **已建实例记着自己用的是哪个版本**；每个项目页显示自己用的蓝本与版本（如 `蓝本 HMW 定题 v4`）。
- **系统边界**：**蓝本列表页**（版本、状态、元数据、行操作）、版本发布与归档、
  **快照绑定与锁定**、回滚、项目页的版本显示。
- **核心数据对象**：蓝本、**蓝本版本**（含版本差异：改了哪几项设计配置）、
  **项目蓝本快照**（项目 → 版本的不可变引用）、蓝本列表元数据（用过 N 次 / 满意度 /
  完成度 n/N / 议程环节数与时长）。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“登录管理（谁能编辑与发布蓝本）”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] 蓝本被修改并发布。
  - 系统从 **蓝本列表** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **系统处理**：发布生成 **v(n+1)**，记录**改了哪几项设计配置**（不是「改了哪些环节」——
   见术语三分）。[原型] 设计器版本条同步为 `v5 已发布`，并始终呈现语义提示句
   **「改动生成 v5，已开过的项目锁在自己的版本上」**。
2. **系统处理**：**旧版自动归档**。[已裁决 O-18 ③] 同一后台的画布模板对此有明确原话：
   「**发布新版本时旧版自动归档，但已经建出来的画布不会被改动——它们记着自己用的是哪个版本。
   归档只影响『还能不能新建』。**」
   **裁决（O-18 ③）：蓝本与画布模板同规则，直接复用 O-10 的裁决。** 具体为：
   - **归档禁止「新增绑定」**：归档版本不再出现在新建项目的可选蓝本列表里；
   - **但不禁止「已绑定 `agenda_segment` 的实例化」**：已套用该蓝本的项目照常运行，
     现场切到某个议程环节时**仍可新建画布 / 产出实例**，实例固化归档时的版本号。
     ⚠ 这一条是**防现场跑挂**的关键——若归档即禁止实例化，一场正在进行的工作坊
     切到某环节时会直接失败。
3. **引导师操作**：打开一个进行中的项目。**系统响应**：[原型] 项目仍按**自己绑定的版本快照**
   运行，结构不变；项目头部显示 `蓝本 HMW 定题 v4`（原型项目列表真实字段）。
4. **引导师操作**：新建项目。**系统响应**：默认用**最新已发布版本**；已归档版本不出现在可选列表。
5. **方法负责人操作**：在**蓝本列表页**查看与管理。**系统响应**：[原型] 每行呈现完整元数据与操作：

   | 字段 | 原型示例 | 说明 |
   |---|---|---|
   | 名称 | `HMW 定题项目` | — |
   | 状态与版本 | `已发布 v4` / `草稿` | 草稿态不显示版本号 |
   | **议程环节数 · 时长** | `7 环节·3.5h`、`28 环节·5d`、`4 环节·90m`、`16 环节·2d` | **随时长档位变，不是 16 项** |
   | **用过 N 次** | `用过 12 次` / `21 次` / `3 次` | 试跑不计入（见 UC-2.1 第 8 步） |
   | **满意度评分** | `满意度 4.6` / `4.1`（5 分制） | [已裁决 O-37 ③] **＝ 项目复盘时引导师给的 1–5 分的均值**，显示时**必须标注样本量**；样本量过少时显示「样本不足」而非一个看似精确的小数。具体最小样本量待产品给数，但「低于最小样本量不显示分数」这条口径已定 |
   | **设计配置完成度** | `16/16 环节已配`、`15/16`、`13/16`、`12/16`、`9/16` | **＝ 设计配置项的完成度**；文案中的「环节」按 D-03 应正名为「项」。**分母取自配置项定义表**（原型标 16、实际枚举 15，见 UC-2.1 ⚠） |
   | 草稿态提示 | `试跑一场后才能发布`、`场地与打印素材两节待清空` | 发布门槛与待办说明 |
   | **行操作** | **`[编辑设计 →]` `[⧉ 复制]` `[× 删除]`** | 复制产生独立新蓝本。[已裁决 O-18 ①] **`[× 删除]` 仅对从未被任何项目套用过的蓝本可用**；已被套用过的蓝本**不可删除、只可归档**，该按钮替换为 `[归档]` |

   页头统计：`项目蓝本（7 个 · 5 已发布 · 2 草稿）`。

6. **系统收口**：校验 AC1「每个项目页能显示自己用的是哪个蓝本版本」。
7. **系统收口**：校验 AC2「**已开过的项目锁在自己的版本上**」——发布新版后，
   存量项目的绑定版本与结构均不变。
8. **系统收口**：校验 AC3「归档只影响能不能新建，不影响已建项目」；
   记录操作者、时间、对象、结果与来源。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] **回滚只允许回到未被任何进行中项目使用的版本**；不满足时明确列出
    「哪些进行中项目正用着该版本」，不得只给一句失败提示。
  - A2：[原型] **`[⧉ 复制]`**：产出一份独立的新蓝本草稿，不与源蓝本共享版本线。
  - A3：[已裁决 O-18 ①] **`[× 删除]`**：已被项目套用过的蓝本能否删除、快照如何处理。
    **裁决**：**已被套用过的不可删除，只可归档**（快照必须保持可达，D-30）；
    **从未被套用过的可以物理删除**。因此该动作**可以实现**，但必须先查引用计数：
    引用数 > 0 → 隐藏 `[× 删除]`、显示 `[归档]`，并在确认框列出「有 N 个项目仍引用此蓝本」；
    引用数 = 0 → 允许删除，仍需二次确认并写审计。
    **不存在「删除后快照如何处理」的分支**，因为有快照的蓝本删不掉。
- **异常流程**：
  - E1：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R7 业务规则（不随具体实现变化的硬性约束）

**快照绑定（本用例的核心）**
- [原型] **改动生成 v(n+1)，已开过的项目锁在自己的版本上。** 项目 → 蓝本版本的引用是
  **不可变快照**，一经绑定不随蓝本后续发布漂移（对齐 UC-0.1「固定快照不可变」与裁决 D-30）。
- [原型] **已建实例记着自己用的是哪个版本**——版本信息存在实例侧，不是运行时从蓝本反查。
- [原型] **归档只影响「还能不能新建」**，不影响已建项目的打开、编辑与运行。
- [设计] 版本号**单调递增、不复用、不缺号**；发布失败不占号（见 UC-2.1/E6）。
- [设计] 每个版本必须记录**版本差异（改了哪几项设计配置）**，供列表与项目页溯源。

**回滚**
- [Backlog] **回滚只允许回到未被任何进行中项目使用的版本。**——逐字出自 `Backlog Use Case.html` 的 UC-2.4；
  「回滚」二字在 proto-01~10 中**零命中**，原型既无回滚入口也无版本历史屏（见 R8 待补）。
- [已裁决 O-18 ②] 回滚是**新建一个内容等同旧版的新版本**，还是把旧版重新置为当前版？
  **裁决（O-18 ②）**：**新建一个内容等同旧版的新版本**——版本号**只增不减，历史线性**。
  例：当前 v5，要回到 v3 的内容 → 生成 **v6（内容 = v3）**，记录 `rolled_back_from: v3`。
  理由：与「快照不可变」一致；若把旧版重新置为当前版，同一版本号会在不同时间指代
  不同的「当前」，审计将无法回答「那天套用的是哪一版」。

**列表与元数据**
- [原型] 「用过 N 次」统计**已套用该蓝本新建的项目数**；试跑实例不计入。
- [原型] 草稿态蓝本不显示版本号，只显示完成度与发布门槛提示。
- [设计] `[⧉ 复制]` 得到独立蓝本（草稿态、v 无、用过 0 次、满意度空），不与源蓝本共享版本线。

- AC1：每个项目页能显示自己用的是哪个蓝本版本。
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- AI/Agent 的写回、覆盖、发布或高影响工具调用必须遵守原型中的批准点；未经确认只保留为草稿或候选。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

    **删除的确认与影响范围提示**——在已探明区域内**确认缺失**，需补画。
  - [裁决 D-36] 七种必现状态 sign-off 时豁免逐屏设计，按 `uiux-standards` 统一实现。

## R9 非功能约束

  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。

  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R10 已知约束 / 依赖

- **内部依赖**：
  - **UC-2.1**（发布动作产生版本）、**UC-2.2**（套用时写入快照引用）。
  - **UC-0.1 版本与快照内核**：本用例是「固定快照不可变」在蓝本域的具体落地。
  - [原型] 登录管理与角色（谁能发布、归档、回滚、删除蓝本）。
- **[已裁决 O-18 ①]** **已被项目套用过的蓝本能否删除**（列表行有 `[× 删除]` 按钮，
  但未探明其约束）。三种可能：① 禁止删除（改为归档）；② 允许删除但保留版本快照；
  ③ 允许删除并级联失效已套用项目。
  **裁决（O-18 ①）**：**已被项目套用过的蓝本不可删除，只可归档。**
  理由：D-30「引用必须指向不可变快照」已隐含此约束——**快照必须保持可达**，
  删除即让引用悬空。③ 与「已开过的项目锁在自己的版本上」直接冲突，已排除。
  UI 处置：`[× 删除]` 按钮**仅对从未被任何项目套用过的蓝本可用**；
  已被套用的蓝本，该按钮替换为 `[归档]`，并在确认框中说明「有 N 个项目仍引用此蓝本」。
- **[已裁决 O-18 ①]** 承上：**删除后已套用项目的快照如何处理**。
  **裁决**：本问题**因「不可删除」而消解**——不存在「已套用蓝本被删除」的状态。
  快照语义随之确定为**引用不可变版本**（不是深拷贝）：
  项目持有 `blueprint_version_id`，版本记录**永不删除**（可归档，归档不影响可达性），
  项目页的 `蓝本 … v4` 恒可解析到真实版本。
  仅当蓝本**从未被套用**时才允许物理删除，此时无引用需要保护。
- **[已裁决 O-18 ③ / O-10]** **归档规则是否与画布模板完全一致**——「发布新版本时旧版自动归档，
  归档只影响还能不能新建」这句原话出自**画布模板**章节；蓝本侧只有「已开过的项目锁在
  自己的版本上」，二者高度类似但未在蓝本处逐字确认。
  **裁决（O-18 ③）**：**与画布模板同规则，直接复用 O-10 的裁决。**
  O-10 的裁决内容：**归档禁止「新增绑定」，但不禁止「已绑定 `agenda_segment` 的实例化」**。
  映射到蓝本域：
  - 归档后的蓝本**不再出现在 UC-2.2 的「可套用蓝本」选择器**里（＝禁止新增绑定）；
  - **已套用该蓝本的项目照常运行**，包括在现场切到某个议程环节时**新建画布/产出实例**
    （＝存量绑定仍可实例化）——这条是防「现场跑挂」的关键，不可省。
  - 实例固化**归档时的版本号**。
  - 归档确认框须提示「有 N 个项目 / N 个议程环节仍绑定此蓝本」。
- **[已裁决 O-18 ②]** **回滚的实现语义**：新建等同旧版内容的新版本（保留历史线性）vs
  把旧版重新置为当前版（版本号回退）。原型只给了约束「只能回到未被任何进行中项目使用的版本」，
  未给语义。
  **裁决（O-18 ②）**：**回滚 = 新建一个内容等同旧版的新版本**（历史线性向前，版本号只增不减）。
  理由：与「快照不可变」一致——把旧版重新置为当前版会让**同一个版本号在不同时间指向不同的
  「当前」语义**，审计时无法回答「那天套用的到底是哪一版」。
  例：v5 有问题要回到 v3 的内容 → 产生 **v6，内容等同 v3**，并在版本记录中标注 `rolled_back_from: v3`。
  推论：原型约束「只能回到未被任何进行中项目使用的版本」是对**回滚来源版本**的限制，
  与新版本号的生成无关。
- **[已裁决 O-37 ③]** **满意度评分（4.6/4.1）的数据来源与算法**——是项目参与者反馈
  （对照项目「审计与反馈」的 `4.6 整体满意度/5`）的聚合，还是蓝本单独打分？
  样本量少时如何显示。
  **裁决（O-37 ③）**：**＝ 项目复盘时引导师给的 1–5 分的均值**（不是全体参与者的满意度，
  那是项目侧的另一个指标），**显示时标注样本量**；**低于最小样本量时显示「样本不足」
  而不是百分比/分数**。最小样本量的具体数值待产品给出，但**「不足即不显示」这条口径已定**，
  实现可先按参数化阈值落地。
- **[待确认]** 是否需要**版本历史屏**（列出各版本及其改了哪几项设计配置）；
  若需要，属本用例还是独立 UC。
- **[已裁决 O-18 ④]** 蓝本的可见范围（原型 agent/画布模板有「全组织可用 / 仅能源组」的范围概念，
  蓝本侧未探明是否同样有团队级可见性）。
  **裁决（O-18 ④）**：**与 agent / 画布模板对齐，蓝本同样具备可见性范围，
  支持「全组织 / 仅某团队」两档。**
  这也闭合了 `uc-0-3` R7 中「skill 与项目蓝本是否同样具备可见性范围」的反推项之蓝本一半
  （skill 侧不在本用例范围）。
  注意与 MCP 的授权范围**不是同一维度**（MCP 用「仅项目负责人 / 全体成员 / 待安全评审」），
  **禁止合并成同一字段**（见 `uc-0-3` R7）。
  团队为**单一归属**（O-12），故「仅某团队」的判定是一次相等比较，不需要集合运算。
- **跨模块契约**：身份与权限、来源引用、版本、任务状态、审计事件和通知必须使用统一标识，避免同一对象在各模块成为不可关联的副本。
- **技术约束**：[原型] 产品为响应式网页；完整离线模式、原生移动端、第三方 IM 与产品内自助计费在 backlog 中明确为范围外。
- **[已裁决 O-34]** 容量基线（保守值，来自一场线下工作坊的物理上限）：单项目在场 **60 人**（8–10 组 × 6 人 + 引导师团队）、组织并发项目 **20**、单场音频 **8 小时**、单项目材料 **5 GB**、历史 **3 年 × 200 项目**。⚠ **无本项目实测依据，需产品确认**；确认前各 UC **不写性能类 AC**，不阻塞开工
- **[已裁决 O-33]** 通知平面**单点定义在 `.harness/instructions/` 的通知规范**，各 UC 只引用不重复定义。默认：产品内通知**必选**；邮件**默认开启可关**；短信仅用于现场进场验证码；免打扰**默认关闭**（B 端工具，静默会误事）；到期提醒 **09:00 用户时区**；催办冷却 **4 小时**；组员**可以**催同组同伴；**「今天」一律按用户时区**
- **[已裁决 O-35]** ① 模型选择与提示词版本**走蓝本第 12 项「Agent 编排」与模型策略三档，不在各 UC 各自指定**；② 人工复核责任人**恒为该产出的负责人**（与 D-39「负责人恒为人」一致）；③ **质量阈值一律不用分数，改用结构性断言**（如「每条洞察必须挂 ≥1 条来源，未挂来源标灰」）。「材料不足」的最小量（建议 ≥3 场访谈 或 ≥20 条引述）**需研究方法负责人给出**

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态 · AC1）：项目页与项目列表行均显示 `蓝本 <名称> v<N>`，与该项目绑定的快照一致。
- V2（成功态 · AC2 · 核心）：用 v4 建项目 A → 蓝本发布 v5 → 断言 A 的绑定版本仍为 v4，
  且 A 的议程环节、分组、输出物等**逐项与 v4 快照一致**；再发布 v6，A 仍不变。
- V3（成功态 · AC3）：v4 归档后，新建项目的可选列表不含 v4；
  而项目 A 打开、编辑、运行**全部正常**。
- V4（成功态 · AC4）：构造一份 `已发布 v3 · 9 环节·1d · 用过 6 次 · 满意度 4.5 · 15/16` 的蓝本，
  断言列表行六个字段各就各位；特别断言 `9`（议程环节数）与 `15/16`（设计配置完成度）
  在接口与 UI 上是**两个独立字段**。
- V5（成功态 · AC5）：`[⧉ 复制]` 后新蓝本为草稿态、无版本号、用过 0 次、满意度空，
  且改动新蓝本不影响源蓝本。
- V6（版本差异）：发布 v5 时改了第 2、9、14 三项设计配置，
  断言版本记录里**恰好列出这三项**。
- V7（回滚约束）：尝试回滚到**正被进行中项目使用**的版本被拒绝并说明原因；
  回滚到未被使用的版本成功。
  [已裁决 O-18 ②] 断言回滚语义：当前 v5、回滚到 v3 后，**产生 v6 且内容逐字段等于 v3**，
  v3 与 v5 记录**均保持不变**，版本记录中含 `rolled_back_from = v3`；
  **不存在「当前版本指针被改回 v3」的状态**。
- V7b（不可删除 · O-18 ①）：[设计] 对**已被项目套用过**的蓝本调用删除接口 → 拒绝，
  错误指向「请改用归档」，且列出仍在引用它的项目数；
  对**从未被套用**的蓝本调用删除接口 → 成功。删除接口不得存在任何强制参数可绕过此判定。
- V7c（归档语义 · O-18 ③ / O-10）：[设计] 归档 v4 后断言三件事：
  ① 新建项目的可选版本列表**不含 v4**（禁止新增绑定）；
  ② 已用 v4 的项目 A **打开、编辑、运行正常**；
  ③ **在项目 A 中推进到某个议程环节时，仍能新建该环节绑定的画布 / 产出实例**，
  且实例记录的版本号为 v4（存量绑定可实例化，防现场跑挂）。
- V7d（可见性范围 · O-18 ④）：[设计] 把某蓝本标为「仅能源组」后，
  非能源组成员的可套用蓝本列表中不含它，且直接按 ID 套用被拒并标明为**组织层**限制
  （对照 `uc-0-3` V3）。
- V8（版本号完整性）：连续发布与失败混合执行后，版本号单调递增、无缺号、无复用。
- V9（新建默认版本）：新建项目默认选中**最新已发布版本**，非最新版需显式选择。
- V10（权限态）：逐一使用 引导师、方法负责人、观察者、未授权用户访问；返回数据和可执行动作严格符合 R5。
- V3（空态）：无目标数据时显示真实空态与下一步，不生成伪数据。
- V4（依赖失败）：模拟网络/外部依赖失败，输入和最近成功数据保留，错误可解释且可重试。
- V5（并发态）：两名用户修改同一资源时不静默覆盖，并可识别最终版本。
- V6（审计态）：关键动作可按操作者、时间、对象和结果检索；越权尝试也有安全审计记录。
