# 原始需求（细化）— UC-6.0 访谈 Studio 列表与范围

> 所属：阶段一 · 能跑完一场项目 / M6 访谈  
> 来源：`WorkspaceX Standalone.html` 一级导航 **`访谈`（访谈 Studio）**；
> 说明页「最新一轮重构：Workshop 变编排器，**Studio 独立成台**」。  

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **5**；建议迭代 **迭代 3 · 能采集**。
>
> **补写缘由**：原 5 份 M6 用例的 R8 一律写「Studio → 访谈；**项目工作台 → 用户访谈**」，
> 把访谈默认当成项目的下级对象。**这与原型相反**：
> - 原型副标题原文：「**访谈 Studio · 独立发起，不依赖项目**」
> - 列表口径：「**访谈 · 22 场 —— 跨项目的全部访谈**」
> - 范围切换器：`研究项目 · 采购决策如何形成` ｜ **`不属于任何项目`**
> - 访谈详情底部：「产出留在研究项目 …；**需要时再挂到某个项目环节**」`[挂到项目环节…]`
>
> 没有这一层，`project_id` 会被当成必填外键，后面所有 UC 的查询与权限都要返工。
> 本用例把**范围模型**单独拎出来定死，其余 UC 的 R8 引用它。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-6.0 / 访谈 Studio 列表与范围
- **Actor**：**研究员**（主）、**项目负责人**、**观察者**
- **目标**：[原型] 让访谈成为**一等对象**——可以独立发起、跨项目汇总、事后再挂到某个项目环节，
  而不是必须先有项目才能约访谈。
- **本用例结果**：研究员进入访谈 Studio，看到**跨项目的全部访谈**，可按范围切换，
  可新建访谈（`选模板 → 选对象 → 生成提纲`）与新建模板，可把某场访谈的产出挂到项目环节。
- **系统边界**：访谈列表与筛选、**范围切换器**、`project_id` 可空的数据模型与权限投影、
  两个标签页（访谈 / 访谈模板）、新建入口、挂载到项目环节。
- **核心数据对象**：**访谈场次（`project_id` 可空）**、研究项目、项目、项目环节、
  挂载关系（访谈产出 → 项目环节）、访谈模板。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已登录且属于某组织；具备该组织内访谈资源的访问权。
  - 依赖能力「登录管理（授权与可见性）」可用，或界面能明确显示其不可用状态。
- **触发条件**：
  - [原型] 用户点一级导航的 **`访谈`**（左栏 `STUDIO` 分组下：研究 · **访谈** · 问卷 · 原型）。
  - [设计] 或从项目工作台进入——此时**范围预置为本项目**，但仍可切走。
    **[口径更正]** 「**用户访谈**」这个区块名在原型档案中 **0 命中**，属虚构。
    项目工作台真实存在的是 `研究洞察` 标签下的子标签
    `研究总览 ｜ 对话 6 ｜ 问卷 34/48 ｜ **用户洞察 9/22** ｜ 深度研究 4`——
    与访谈最接近的是「**用户洞察**」，但它是**洞察**不是访谈列表。
    **[原型确认缺失]** 项目工作台侧没有任何直达访谈 Studio 的入口，需补画原型。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **研究员操作**：进入访谈 Studio。**系统响应**：[原型] 展示
   副标题「**访谈 Studio · 独立发起，不依赖项目**」与列表头
   「**访谈 · 22 场 —— 跨项目的全部访谈。打开任意一场进入全屏管理：时间、提纲、要收集的数据、洞察。**」
2. **研究员操作 —— 切换范围**：[原型] 顶部**范围切换器**至少两档：
   - **`<某研究项目 / 某项目>`**（示例：`研究项目 · 采购决策如何形成`）
   - **`不属于任何项目`**
   **系统响应**：按范围过滤列表。**「不属于任何项目」是一等选项**，
   对应 `project_id IS NULL` 的访谈，**不是「未分类」这种兜底桶**。
3. **系统处理 —— 数据模型（[设计]，本用例最重要的产出）**：
   - 访谈场次的 `project_id` **可空（nullable）**；`research_project_id` 同样可空。
   - **权限投影分两种**：
     - `project_id` 非空 → 继承该项目的成员与角色可见性；
     - `project_id` 为空 → 归属**创建者所在组织 + 显式协作者**，
       **不因为不属于任何项目就变成全组织可见**（这是最容易出的越权）。
   - **访谈模板同样跨项目**：模板库是组织级资产，`project_id` 恒空（见 UC-6.1）。
   - **挂载是后置且可选的**：`访谈产出 → 项目环节` 是**独立的挂载关系**，
     不是把访谈搬进项目；一场访谈可挂到多个环节，也可以永不挂载。
4. **研究员操作 —— 浏览列表**：[原型] 每行结构：
   `<受访者/对象> ｜ <所属项目或研究项目> · <负责人> ｜ <状态> ｜ <一句话进展> ｜ <计量> ｜ <动作>`
   状态取值 `执行 / 完成 / …`；动作 `[打开访谈] [进入现场] [看洞察] [再跑一轮]`。
   **系统响应**：按范围与筛选返回；`[打开访谈]` 进访谈详情六标签，`[进入现场]` 直达 UC-6.4。
5. **研究员操作 —— 筛选与标签页**：[原型] 标签页 `访谈` ｜ **`访谈模板`（来自 3 场项目）**；
   筛选 `全部标签 / 客户 / 内部 / 高优先级 / 已归档`。
6. **研究员操作 —— 新建**：[原型] 两个入口 `[＋ 新建模板]` `[＋ 新建访谈]`；
   后者的向导是 **`选模板 → 选对象 → 生成提纲`**（→ UC-6.2）。
   **系统响应**：新建时**范围默认继承当前切换器的取值**，且可在向导里改。
7. **研究员操作 —— 挂到项目环节**：[原型] 访谈详情底部
   「产出留在研究项目 · 采购决策如何形成；**需要时再挂到某个项目环节**」`[挂到项目环节…]` `[保存]`。
   **系统响应**：建立挂载关系并按 Context Pack / Artifact 契约传递
   （**正式产出与决策只能绑定固定快照**，D-38 / D-30）；挂载可解除且留痕。
8. **系统收口**：校验 AC1「范围切换器可在『本项目』与『不属于任何项目』间切换且列表正确过滤」。
9. **系统收口**：校验 AC2「`project_id` 为空的访谈不对无关成员可见」。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] **从项目工作台进入**时范围预置为该项目，但切换器仍可用——
    研究员可以在项目上下文里看跨项目的历史访谈作参考。
  - A2：[原型] **数字人 / 虚拟访谈条目与真人访谈混排**（原型示例行：
    `DE 德国采购总监 · 数字人 · 由 12 场真人访谈构造 · 标为探索性 · [打开访谈] [再跑一轮]`）。
    **phase-1 只做列表展示 + 探索性隔离标记**；构造能力归 **phase-3 的 16-persona**。
    列表必须**强标记**且计数与真人访谈**分列**（D-25，见 UC-6.5）。
  - A3：[设计] 一场访谈可**先无项目、后挂载**；也可**解除挂载**回到「不属于任何项目」。
- **异常流程**：
  - E1：[设计] **挂载目标环节被删除或归档**时，挂载关系标为失效并提示重新选择，
    **不静默丢弃产出**。
  - E2：[设计] **切换范围时有未保存的筛选/搜索**——保留用户输入，不重置。
  - E3：[设计] 用户对某范围无权限时，切换器里该项**不显示**（而不是显示后报错），
    避免通过枚举切换器探测项目存在性。
  - E4：[设计] 请求超时、网络中断或依赖不可用时，保留当前范围与筛选，明确失败原因并可重试。
  - E5：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留。

## R5 权限与可见性

- **研究员（创建者）**：对自己创建的访谈有完整权限，无论其是否挂项目。
- **项目成员**：仅能看到 `project_id` 指向自己所在项目的访谈；
  **看不到**其他项目的访谈与「不属于任何项目」的他人访谈。
- **项目负责人**：可查看本项目下的访谈状态与审计摘要；
  **不得**因为职位而自动获得跨项目或无项目访谈的读权。
- **观察者**：只读，且仅限**已发布产出与脱敏聚合**；
  原始转写、受访者联系方式、AI 建议一律不可见。
- **受访者**：**在本用例中零可见性**——受访者从不进入访谈 Studio。
- **管理员（D-18）**：个人层只见计数；项目层可读但每次访问写审计日志且**对项目负责人可见**。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。
- **服务端强制**：范围过滤必须在服务端做；**不得**返回全量再由前端按 `project_id` 过滤。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 访谈列表按当前范围正确呈现；跨项目汇总口径（`22 场`）可复现。
  - [原型验收] **AC1**：范围切换器至少两档 `<某项目/研究项目>` 与 **`不属于任何项目`**，
    切换后列表正确过滤。
  - [设计验收] **AC2**：`project_id` 为空的访谈**不对无关成员可见**；
    直接按 ID 请求也被拒绝。
  - [原型验收] **AC3**：`[＋ 新建访谈]` 走 `选模板 → 选对象 → 生成提纲` 三步；
    新建时范围默认继承切换器取值且可改。
  - [原型验收] **AC4**：访谈详情底部可 `[挂到项目环节…]`，挂载后仍可解除，全程留痕；
    正式产出绑定的是**固定快照**。
  - [原型验收] **AC5**：虚拟 / 数字人条目与真人访谈混排但**强标记**，计数分列。
- **失败后置条件**：
  - 不产生「看似属于某项目实则未挂载」的访谈；挂载失败时明确提示，不静默成功。
- **不包含**：
  - **强制访谈必须属于某个项目**——这正是本用例要推翻的假设。
  - **虚拟人的构造能力**（专家设定 / 提问与推演 / 采纳与标注）——属 phase-3 的 16-persona。
  - 研究 Studio / 问卷 Studio / 原型 Studio 的列表（各自独立用例，本文只定共用的范围模型）。
  - 不扩展到本 use case 未声明的跨组织、跨客户或公开发布能力。

## R7 业务规则（不随具体实现变化的硬性约束）

- **[原型 · 原文] 「访谈 Studio · 独立发起，不依赖项目」**；列表是「**跨项目的全部访谈**」。
- **[设计] `project_id` 可空**，且「不属于任何项目」是**一等范围**，不是兜底分类。
- **[设计] 无项目 ≠ 全组织可见**：`project_id` 为空时可见性归创建者 + 显式协作者。
- **[原型] 挂载是后置且可选的**：`[挂到项目环节…]`；挂载可解除，产出不因解除而丢失。
- **[原型 + D-38] 正式产出与决策只能绑定固定快照**（Context Pack / Artifact 契约）。
- **[原型 + D-25] 虚拟来源混排但强标记，计数与真人分列**；
  phase-1 只展示与隔离，不构造。
- 范围过滤必须在**服务端**执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 跨项目列表必须分页或增量加载；`22 场` 是原型示例，实际可能是数百场。
  - [设计] 范围切换应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态。
- **安全/隐私/合规**：
  - 最小权限、组织/项目隔离；**跨项目汇总是本用例最大的越权风险面**，
    每个列表查询都必须带服务端范围断言。
  - 受访者姓名与联系方式属个人数据，列表默认只显示对象描述，联系方式需进详情且留痕。
- **兼容与降级要求**：
  - 响应式 Web；移动端范围切换器折叠为下拉，列表行降级为两行卡片。

## R10 已知约束 / 依赖

- **内部依赖**：登录管理（授权与可见性）；组织 / 项目 / 研究项目的对象模型。
- **被依赖**：**UC-6.1 ~ UC-6.7 全部**——它们的 R8 都引用本用例的范围模型；
  各 UC 原写的「项目工作台 → 用户访谈」中，「用户访谈」是**虚构区块名**（档案 0 命中），
  应理解为**待补画的入口之一**，不是归属关系，也不构成原型依据。
- **跨模块契约**：`访谈产出 → 项目环节` 的挂载走 **Context Pack ＋ Artifact**（D-38）；
  正式产出与决策**只能绑定固定快照**（D-30）。
- **[待确认]** **范围切换器的完整档位**。原型只显示两档（当前研究项目 / 不属于任何项目），
  是否还有「全部」「按项目分组」等档位**未探明**。
- **[待确认]** 一场访谈能否**同时**归属研究项目与业务项目（原型两处措辞不同：

## R12 AI Ready 验收线索

  断言被拒绝并写审计；以创建者身份请求成功。

- **V4（成功态 · AC4）**：把一场无项目访谈 `[挂到项目环节…]`，
  断言① 挂载关系建立且该项目成员可见；② 解除挂载后回到无项目状态且产出仍在；
  ③ 正式产出引用的是**固定快照 ID**，快照内容不可变。
- **V5（成功态 · AC5）**：列表中虚拟条目带强标记；统计接口返回真人与虚拟两个独立计数。
