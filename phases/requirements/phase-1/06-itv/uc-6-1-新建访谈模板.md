# 原始需求（细化）— UC-6.1 新建访谈模板

> 所属：阶段一 · 能跑完一场项目 / M6 访谈  
> 来源：`Backlog Use Case.html` 的 UC-6.1；UI 线索来自 `WorkspaceX Standalone.html`。  

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **8**（原 5；+3 = 模板库列表与「用过 N 次」统计、`来自 3 场项目` 的反向抽取）；建议迭代 **迭代 3 · 能采集**。
>
> **✅ 原型已探明**：`访谈` → 标签页 **`访谈模板`**（列表见 R8）+ 访谈详情的模板套用。
> 模板的定位由原型一句话钉死：**「模板决定提纲结构、每段时长和要收集的数据字段；新建访谈时套用。」**

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-6.1 / 新建访谈模板
- **Actor**：**研究员**、**引导师**、**组长**、**受访者**
- **目标**：[原型] 从模板到执行到回流的一条链：设计大纲 → 约人 → 现场记录 → 转写回流 → 出洞察。
- **本用例结果**：[Backlog] 用户通过“新建访谈模板”完成从“研究员在访谈 → 模板”到可追踪业务结果的闭环。
- **系统边界**：**访谈模板库列表**（含使用次数、题数、时长区间、编辑与套用）、
  模板编辑（分段 / 时长 / 结构化字段与标签）、**从已办访谈反向抽取模板**、模板套用。
- **核心数据对象**：访谈模板（**提纲结构 + 每段时长 + 要收集的数据字段**）、
  模板使用计数、模板来源（原创 / 从项目抽取）、标签、访谈场次。
- **模板的三样东西（[原型] 原文）**：模板决定 ① **提纲结构** ② **每段时长** ③ **要收集的数据字段**。
  第三项常被漏掉——它是 UC-6.5 证据矩阵能成列的前提。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“实时转录、上传 Skill（访谈 AI）”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] 研究员在访谈 → 模板。
  - 系统从 **新建访谈模板** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

0. **研究员操作 —— 进入模板库**：[原型] `访谈` 页有两个标签页：`访谈` ｜ **`访谈模板`（来自 3 场项目）**。
   切到 `访谈模板` 看到**模板列表**，每行是「名称 · **用过 N 次** · 一句话说明 · **题数** · **时长区间**」，
   行尾两个动作 **`[编辑]` `[用它新建]`**，页头 `[＋ 新建模板]`，筛选 `全部标签 / 客户 / 内部 / 高优先级`。
   **系统响应**：`用过 N 次` 由实际套用次数统计得出，**不是手填字段**。
   [设计] 标签页上的「**来自 3 场项目**」**可能**说明模板可以从已办访谈反向抽取——
   该括注语义未定，不构成原型证据（见 R4/A3）——
   即模板库有两个来源：**原创新建**与**从已有访谈沉淀**，列表需能区分。
1. **研究员操作**：填名称与访谈目标。**系统响应**：校验当前身份、项目范围、必填数据与资源版本；成功后更新界面和业务记录，并保留可追溯来源。
2. **研究员操作**：助手按目标推演分段与时长，人可改名、增删、调时长、拖排序。**系统响应**：校验当前身份、项目范围、必填数据与资源版本；成功后更新界面和业务记录，并保留可追溯来源。
3. **研究员操作**：定要收集的结构化字段与标签。**系统响应**：校验当前身份、项目范围、必填数据与资源版本；成功后更新界面和业务记录，并保留可追溯来源。
4. **研究员操作**：保存后新建访谈可直接套用——[原型] 入口有两个：模板行尾的 **`[用它新建]`**，
   以及新建访谈三步向导的**第一步「选模板」**（UC-6.2）。
   **系统响应**：把**提纲结构 + 每段时长 + 数据字段**一次性带入新访谈；
   **套用后与模板脱钩**（本场的修改不回写模板，模板的修改不追改已建访谈），
   但记录来源模板与版本以便追溯。
5. **系统处理 —— 反向抽取（[设计]，唯一线索是括注 `来自 3 场项目`，语义未定）**：从若干已办访谈中沉淀出模板。
   **系统响应**：抽取结果是**草案**，必须由研究员确认后才进模板库；
   抽取来源（哪几场访谈）需可追溯并在模板详情可见。
6. **系统收口**：校验 AC1“套用模板新建的访谈自动带上分段与字段”；满足后记录操作者、时间、对象、结果与来源，并刷新相关列表、图谱、看板或通知状态。
7. **系统收口**：校验 AC2“模板列表的『用过 N 次』与实际套用次数一致”。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] 合计时长超出研究计划参数（示例 60 分钟；多人场 90 分）时提示压缩。
    **取项目参数而非写死 60**（见 UC-6.2 第 7 步）。
  - A2：[原型] **`[编辑]` 已被用过的模板**：编辑产生新版本，**已建访谈不受影响**；
    列表上的 `用过 N 次` 是该模板全部版本的累计。
  - A3：[设计] **从已办访谈反向抽取**成模板；抽取结果为草案，需人工确认。
    **[口径降级]** 本条整个功能建立在标签页括注「**来自 3 场项目**」这一个语义未定的字符串上——
    它同样可以只是「本库模板取自 3 个项目」的来源说明，**不足以证明存在反向抽取动作**。
    档案中无抽取入口、无抽取向导、无草案确认屏。降为 [设计]，需人类确认。
- **异常流程**：
  - E1：[设计 · 跨模块借证] 助手会指出提纲里的**诱导性问题**。
    **注**：「诱导」在档案中只命中**问卷**侧；访谈侧的对应物是研究设计屏的
    **质量提示 `2 段还需你改问法`**（proto-07），既没写「诱导」也没给出问题类型。
    「诱导性体检」是从问卷侧借来的推断，需人类确认。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E4：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

- **研究员**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **引导师**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **组长**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **受访者**：可查看/确认自身授权并提出撤回；不能访问项目内部材料或其他受访者数据。
- **观察者**：默认不能发起或修改；仅当内容已发布且授权范围允许时只读查看脱敏结果。
- **项目经理**：可查看项目级状态与审计摘要；是否可代替业务 Actor 执行写操作需由角色模板显式授权。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 形成与本 use case 对应的正式记录或明确状态，并可从来源页面再次打开。
  - 所有跨模块回流均携带来源资源、版本、操作者/触发者、时间和可见范围。
  - [原型验收] **AC1**：套用模板新建的访谈自动带上**分段、每段时长与要收集的数据字段**三样。
  - [原型验收] **AC2（新增）**：模板列表每行显示 **`用过 N 次` / 题数 / 时长区间**，
    并有 `[编辑]` `[用它新建]`；`用过 N 次` **由实际套用次数统计**，不可手填。
  - [原型验收] **AC3a（新增）**：`访谈模板` 标签页标注来源（示例「**来自 3 场项目**」），
    从已办访谈抽取的模板可追溯到其来源访谈，且抽取结果**经人确认才入库**。
  - [设计验收] **AC4（新增）**：套用后模板与访谈**脱钩**——改模板不追改已建访谈，改访谈不回写模板。
- **失败后置条件**：
  - 不创建“看似成功”的正式记录；可重试内容保留为草稿，失败事件进入可观测日志。
- **不包含**：
  - 自动替代研究员作最终研究判断、无授权录制。
  - 不扩展到本 use case 未声明的跨组织、跨客户或公开发布能力。

## R7 业务规则（不随具体实现变化的硬性约束）

- **[原型 · 原文] 「模板决定提纲结构、每段时长和要收集的数据字段。」** 三样缺一不可。
- [原型] 合计时长超出研究计划参数时提示压缩（取参数值，不写死 60）。
- [设计 · 跨模块借证] 助手会指出提纲里的**诱导性问题**（与 UC-6.2/E1 的「研究问题不能直接照着问」是两条不同的体检）。
  访谈侧原型只有质量提示 `2 段还需你改问法`；「诱导」二字只出现在问卷侧。
- [原型] **`用过 N 次` 是统计值**，由套用行为累计，不可手填、不可编辑。
- [设计] **模板可从已办访谈反向抽取**；抽取结果是草案，**经人确认才入模板库**，来源可追溯。
  **[原型确认缺失]** 唯一依据是括注「来自 3 场项目」，语义未定；模板库列表已完整渲染，**无抽取入口**。
- [设计] **套用即脱钩**：模板与已建访谈互不追改，仅保留来源引用。
- AC1：套用模板新建的访谈自动带上分段与字段。
- AC2：`用过 N 次` 与实际套用次数一致。

- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R8 界面线索

- **前端入口**：[原型] **访谈 Studio → 标签页 `访谈模板`**；页头 `[＋ 新建模板]`；
  以及新建访谈三步向导第一步「选模板」（UC-6.2）。
  **范围切换器**：`本项目 ｜ 不属于任何项目` —— 模板库是**跨项目资产**（见 **UC-6.0**）。
- **信息架构**：`访谈` 页两个标签页：`访谈` ｜ **`访谈模板`（来自 3 场项目）**。
- **模板库列表（[原型] 原样）**：
  ```
  访谈模板 · 5 —— 模板决定提纲结构、每段时长和要收集的数据字段；新建访谈时套用
    [＋ 新建模板]   筛选：全部标签 / 客户 / 内部 / 高优先级
    采购决策链    用过 9 次   谁拍板、谁能否决、卡在哪一步 · 12 题 · 45–60 分  [编辑][用它新建]
    JTBD 深访     用过 14 次  还原上一次真实购买的完整经过 · 9 题 · 60 分      [编辑][用它新建]
    竞品切换动因  用过 6 次   为什么换、为什么没换 · 8 题 · 40 分              [编辑][用它新建]
  ```
  - 每行五要素：**名称 ｜ 用过 N 次 ｜ 一句话说明 ｜ 题数 ｜ 时长区间**；两个动作 `[编辑]` `[用它新建]`。
  - 头部计数 `访谈模板 · 5`（原型称有 5 个模板，档案里列出 3 个，另 2 个未抽取到具体行——
    **属未探明的行数据，不是「原型只做了 3 个」**）。
  - **时长是区间**（`45–60 分`）不是单值；题数是整数。
- **模板编辑器（[设计]，按 UC-6.2 大纲编辑器同构）**：名称与访谈目标 → 分段（名称 / 时长 / 顺序可拖）
  → **要收集的结构化字段与标签** → 保存。助手在保存前指出**诱导性问题**。
- **推荐交互**：
  - [设计] `[用它新建]` 直接跳进三步向导的第二步（模板已选定），少一次点击。
  - [设计] 模板详情显示「被哪些访谈用过」与「从哪几场访谈抽取而来」两条溯源链。
  - [设计] 采用分步表单或右侧配置面板，必填、依赖与完成度持续可见。
- **必须呈现的状态**：默认态、加载态、空态、校验失败态、依赖失败态、无权限态、成功态；
  **空模板库**需给「从已有访谈抽取」与「新建模板」两个出口，**不预置示例模板**。
- **原型参考**：`WorkspaceX Standalone.html` — `访谈 → 访谈模板` 标签页
- **UI sign-off**：实现前需由产品/设计确认入口、角色视图、危险动作和响应式布局。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R10 已知约束 / 依赖

- **内部依赖**：访谈 AI Skill（推演分段与时长、诱导性体检）；**UC-6.0 访谈 Studio 范围模型**
  （模板库是跨项目资产，`project_id` 可空）。
- **被依赖**：**UC-6.2**（三步向导第一步 + 大纲结构来源）、**UC-6.5**（模板定义的数据字段是证据矩阵的列）。
- **跨模块契约**：身份与权限、来源引用、版本、任务状态、审计事件和通知必须使用统一标识，避免同一对象在各模块成为不可关联的副本。
- **技术约束**：[原型] 产品为响应式网页；完整离线模式、原生移动端、第三方 IM 与产品内自助计费在 backlog 中明确为范围外。
- **[待确认]** 单项目并发人数、组织数、材料量、音频时长和历史数据量尚未给出；容量与压测指标需在开发前定稿。
- **[待确认]** 通知渠道、消息模板、语言与时区策略未统一定义；本文仅承接原型明确写出的产品内/邮件行为。
- **[待确认]** 数据驻留地区、加密密钥策略、法定留存和删除证明格式需由合规负责人确认。
- **[待确认]** 模板的**可见范围**：组织级共享 / 团队私有 / 个人草稿三档如何取舍，谁能编辑他人模板。
- **[待确认]** **反向抽取的触发方式**（人工发起 vs 系统建议）与「几场访谈才够抽一个模板」的门槛。
- **[未探明 · 待补抽取]** 模板列表 5 个模板中另外 2 个的行数据；模板 `[编辑]` 面板内部。
  **未探明 ≠ 原型没做。**

## R11 切分提示（给 requirement-author）

- 建议先拆“领域数据与权限 → 主流程服务 → 页面与状态 → 跨模块回流 → 审计/通知 → 自动化验收”。
- 单个 feature 应能在一次会话内实现并验证，不应把本 use case 的全部前后端与所有异常态塞进一个 feature。
- 建议切成：① 模板数据模型（结构 + 时长 + 数据字段 + 来源）② 模板库列表与筛选（含 `用过 N 次` 统计）
  ③ 模板编辑器与诱导性体检 ④ 套用与脱钩 ⑤ **从已办访谈反向抽取**（可后置到迭代 4）。
- **优先级 / 先后依赖**：P0；**8 点**；迭代 3 · 能采集；**必须先于 UC-6.2**（向导第一步依赖它）。
- 对 P0 必做链路优先实现成功态、权限态与数据闭环，异常态不得延期到上线后。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态 · AC1）：用某模板新建访谈，断言新访谈带上了**分段、每段时长、要收集的数据字段**三样，
  且三样均与模板一致。
- V2（成功态 · AC2）：连续套用同一模板 3 次，断言列表的 `用过 N 次` 递增 3；
  尝试直接写该字段的接口被拒绝（统计值不可手填）。
- V3（成功态 · AC3）：从 3 场已办访谈抽取模板，断言结果为**草案**、需确认才入库、
  入库后模板详情可列出这 3 场来源访谈。
- V4（成功态 · AC4）：套用后修改模板，断言已建访谈不变；修改已建访谈，断言模板不变；
  两者之间仍保留来源引用。
- V5（校验失败态）：写入一条诱导性问法，断言助手指出并给出修改建议。
- V6（权限态）：逐一使用 研究员、引导师、组长、受访者、观察者、未授权用户访问；返回数据和可执行动作严格符合 R5。
- V7（空态）：模板库为空时显示真实空态与两个出口（新建 / 从已有访谈抽取），**不预置示例模板**。
- V8（依赖失败）：AI 推演分段服务不可用时仍可手工建模板，错误可解释且可重试。
- V9（并发态）：两名用户修改同一模板时不静默覆盖，并可识别最终版本。
- V10（审计态）：模板创建、编辑、抽取确认、套用均可按操作者、时间、对象和结果检索；
  越权尝试也有安全审计记录。
