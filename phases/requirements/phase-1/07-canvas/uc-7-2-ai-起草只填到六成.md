## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-7.2 / AI 起草留白规则
- **Actor**：**引导师**、**组长**、**组员**、**AI（画布协作者：Ava 等 agent）**
- **目标**：[原型] AI 按本组录音与材料往模板格子里填草稿，但**空格子保持空白，不替人填**——
  留白与引述是硬性的产品语义，不是文案建议。
- **本用例结果**：[设计] 用户通过 AI 起草得到一张**部分填充、每条都可回溯到原话、每个分区都留有空位**
  的画布草稿；AI 的每处落笔都带 AVA 角标且可一键回滚。
- **系统边界**：AI 起草服务、留白规则校验与提示、原始引述与时间码绑定、AI 落笔角标与回滚、
  画布写权限模式（直接落笔 / 提交建议待接受）。
- **核心数据对象**：画布实例、便签/节点、草稿标记、**原始引述**（转录片段 id + 时间码 + 原文）、
  AVA 角标（作者 = agent 标识）、回滚点、画布 AI 写权限模式。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“项目模板（**议程环节**绑定）、实时转录（素材来源）”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] 本组录音进行中且模板已推送。
  - 系统从 **本组画布** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **AI 操作**：按本组录音与材料，自动往模板格子里填草稿。**系统响应**：校验取材范围（只取本组）、
   画布的 AI 写权限模式与身份；按模式落笔或落候选（见第 5 步）。
2. **系统处理（留白规则 ①）**：**每个分区至少留一格空**——AI 在每个 `##` 分区里生成的便签数
   必须小于该分区的可容纳格数，至少保留一个空位给人。若模板分区无固定格数，则该分区
   [设计] 至少保留一处可见的空白落位区。
3. **系统处理（留白规则 ②）**：**每条草稿必须附原始引述**——每张 AI 便签/节点都绑定
   ①转录片段 id ②时间码 ③原文引述；缺任一项的草稿**不得以「已填」形态呈现**，只能标为
   「无来源 · 待补」。[原型] 每条草稿保留时间码，**点一下能听回那句话**。
4. **系统处理（提示不阻断）**：任一规则被突破时，画布上给出**明确提示与一键留白入口**
   （如「本分区已被 AI 填满，建议留一格给现场」`[清一格]`），但**不阻断写入**——
   人可以选择接受这个填满的结果。
5. **系统响应（写权限模式，D-10）**：
   - **默认「直接落笔」**：AI 改动直接生效，每处落笔带 **AVA 角标**，
     [原型] 右栏汇总「Ava 补了 3 张便签、改了 1 条连线标签，都带 AVA 角标」`[看改动]` `[回退]`；
     **一键回滚**必须能把该轮 AI 落笔整体撤回到落笔前状态。
   - **可按画布切换为「提交建议待接受」**：AI 改动落为候选，不进入画布正文，需人逐条或批量接受。
   - 模式是**画布级配置**（不是全局），由引导师/组长设置，变更记审计。
6. **系统收口**：校验 AC1「每个格子都能看到它是从哪句话来的」——含时间码回听。
7. **系统收口**：校验 AC2「留白规则被突破时界面明确提示，但不阻断」与
   AC3「AI 的每处落笔都带 AVA 角标且可一键回滚」；满足后记录操作者/触发 agent、时间、对象、
   结果与来源，并刷新相关列表、图谱、看板或通知状态。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] 只从本组录音取材，不跨组混用。系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
- **异常流程**：
  - E1：[原型] 组长未确认的内容不进产出，也不写回组织大脑。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E4：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R7 业务规则（不随具体实现变化的硬性约束）

### 留白规则（[D-11] 取代原「六成」口径）

- [设计] **规则①：每个分区至少留一格空**。AI 一轮起草后，每个 `##` 分区必须至少有一个空位。
- [设计] **规则②：每条草稿必须附原始引述**。引述三件套（转录片段 id + 时间码 + 原文）缺一不可；
  缺失的草稿只能以「无来源 · 待补」形态存在，不计入「已填」。
- [设计] **两条规则只提示、不阻断**。系统给出提示与一键留白入口，最终由人决定是否接受填满的结果；
  **不得以规则为由拒绝写入或静默删除 AI 内容**。
- [原型] **空格子保持空白，不替人填**——留白是产品语义，不是性能取舍。
- **[已裁决 O-32] 「完成度」的判定口径 ＝ 已完成项 / 已定义项**：
  **分母来自模板的分区定义表**（模板注册表，见 UC-7.1），**不加权、不估算**；
  「无来源 · 待补」的草稿**不计入分子**（与规则②一致）。
  这与 D-11 对「六成」的处理同构——**用可复现的结构化规则，不用统计比较**。
- **[已裁决 O-32] 「缺料」＝ 骨架中标为必需的项没有挂任何来源**（不是「这节写得短」）；
  在画布侧表现为：必填分区无便签、或分区内草稿全部为「无来源 · 待补」。

### 上下文获取与编排（[设计]，Context Engine）

- **AI 起草的上下文只能通过 Context API 取 Context Pack**，
  **不得绕过直查** `segments` / 向量库 / 对象存储；每次起草留一条可重放的 `context_packs` 记录。
- 「每个格子都能看到它是从哪句话来的」（AC1）在架构上＝ Pack item 的
  **`segmentId` + `anchor`（时间码）**，须原样固化到便签的来源字段，**100% 可定位**。
- **[已裁决 O-05]** 拒绝「交给 AI 分析」的受访者片段**不进起草输入**
  （per-speaker 前置过滤，不是出口遮盖）。
- **[已裁决 O-36]** Context Pack 相关度阈值默认 **0.45**（可配、按任务类型）；
  上下文预算随模型窗口推导，超限按相关度截断并把被截断项记入 `omissions`。
- **[设计] 编排边界**：单轮起草走在线推理；多阶段生成与人工确认可用 **LangGraph**
  （动态 `interrupt()` 做 HITL，节点恢复时副作用必须幂等）；
  **画布解析与索引等摄取型任务一律走持久任务系统**。
- **[设计] file-first**：AI 落笔与回滚都作用在 **mermaid 源码 `.md`** 上并产生
  **新的不可变版本**（SHA-256），原版本永不覆盖——这正是「一键回滚原子性」的实现底座；
  文件在 22-files 中可见可下载。

### AI 写权限（[D-10]）

- [原型] **默认直接落笔**：改动即时生效，带 **AVA 角标**（作者 = 具体 agent，不是笼统的「AI」），
  并提供 `[看改动]` `[回退]` 两个出口。
- [设计] **一键回滚必须是原子的**：回滚一轮 AI 落笔时，该轮新增/修改/删除全部撤销，
  不得留下半撤销状态；回滚本身记审计。
- [设计] **可按画布改为「提交建议待接受」**：该模式下 AI 内容不进正文，只进候选区。
- [原型] 只从本组录音取材，不跨组混用。
- [原型] 组长未确认的内容不进产出，也不写回组织大脑。
- AC1：每个格子都能看到它是从哪句话来的。
- AC2：留白规则被突破时明确提示，不阻断。
- AC3：AI 每处落笔带 AVA 角标且可一键回滚。
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- AI/Agent 的写回、覆盖、发布或高影响工具调用必须遵守原型中的批准点；未经确认只保留为草稿或候选。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R11 切分提示（给 requirement-author）

- 建议先拆“领域数据与权限 → 主流程服务 → 页面与状态 → 跨模块回流 → 审计/通知 → 自动化验收”。
- 单个 feature 应能在一次会话内实现并验证，不应把本 use case 的全部前后端与所有异常态塞进一个 feature。
- **建议切法（本 UC）**：① 引述三件套数据模型与 Markdown 往返保真 → ② 留白两规则的校验器
  （纯函数，可 Node 单测）→ ③ 提示与一键留白 UI → ④ AVA 角标与轮次级回滚 →
  ⑤ 画布级写权限模式开关 → ⑥ 验收。
- **② 与 ④ 各自独立成 feature**：留白校验器是纯逻辑，回滚是事务性写，两者验收方式完全不同。
- **优先级 / 先后依赖**：P0；5 点；迭代 4 · 能推演；先满足“UC-7.1 模板库与技术底座、实时转录（素材来源）”。
- 对 P0 必做链路优先实现成功态、权限态与数据闭环，异常态不得延期到上线后。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证。
**[D-08 + D-35] 优先写纯函数层的规则断言与 round-trip 断言**，绕开原型零 `data-testid` 的难题。

- **V1（规则① · Node 可跑）**：把一份「每个分区都被填满」的模板文本喂给留白校验器，
  对每个 `##` 分区各返回一条「分区已满」提示；把一份合规文本喂进去，返回空提示列表。
- **V2（规则② · Node 可跑）**：构造一条无引述的 AI 草稿，校验器标其为「无来源 · 待补」；
  该条在「已填格数」统计中不计入。
- **V3（不阻断态）**：在两条规则均被突破的情况下调用写入接口，**接口成功返回**且内容真实写入，
  同时响应体带 `warnings` 列表——**断言「有提示」与「未阻断」同时成立**。
- **V2b（完成度与缺料 · [已裁决 O-32]）**：
  ① 完成度接口返回 `已完成项 / 已定义项`，**分母与模板分区定义表条数严格相等**（不加权）；
  ② 把某必需分区的全部草稿改为「无来源 · 待补」，断言该分区被判为**缺料**且不计入分子；
  ③ 断言判定**不使用任何跨组统计比较**。
- V4（成功态）：AC1 —— 任取一张 AI 便签，接口返回其转录片段 id、时间码与原文；
  按时间码请求音频片段可回听。
- **V4b（架构态 · [设计] Context API）**：断言起草路径只经 Context API——
  ① 每次起草有一条可重放的 `context_packs` 记录；
  ② 便签来源字段的 `segmentId` + `anchor` 与该 Pack 中的 item 一致；
  ③ **100% 便签可定位**到 22-files 中的 `transcript.jsonl` 与音频时间码；
  ④ **[已裁决 O-05]** 拒绝 AI 分析的受访者片段不出现在该 Pack 中。
- **V5b（架构态 · [设计] file-first 回滚）**：一轮落笔后断言对象存储中新增一个
  **mermaid 源码 `.md` 版本**（新 SHA-256），前一版本内容未被覆盖；
  回滚即指向前一版本，且两版本在 22-files 中都可下载。
- **V5（角标与回滚态）**：一轮 AI 落笔后，① 所有新增/修改对象的 `author` 为具体 agent 标识
  （不是 `system` / `ai`）；② 调用回滚接口后画布内容与落笔前**逐字节一致**；
  ③ 回滚事件在审计中可检索。
- **V6（写权限模式态）**：把画布切到「提交建议待接受」后触发 AI 起草，画布正文不变，
  候选区出现 N 条待接受项；接受其中 1 条后正文只增加该条。
- V7（权限态）：逐一使用 引导师、组长、组员、观察者、未授权用户访问；返回数据和可执行动作严格符合 R5。
- V8（取材范围态）：为第 2 组触发起草，产出的所有引述均指向第 2 组的转录片段，无第 1/3/4 组来源。
- V9（空态）：本组尚无转录与材料时显示真实空态与下一步，**不生成任何便签**。
- V10（依赖失败）：模拟转录服务/模型不可用，画布已有内容不变，错误可解释且可重试。
- V11（审计态）：AI 落笔、回滚、写权限模式变更可按操作者/触发 agent、时间、对象检索。
