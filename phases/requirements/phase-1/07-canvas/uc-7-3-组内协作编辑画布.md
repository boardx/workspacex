## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-7.3 / 组内协作编辑画布
- **Actor**：**引导师**、**组长**、**组员**
- **目标**：[原型] 组员从议程进入本组画布，在同一张画布上协作编辑（便签 / 节点 / 连线 /
  `[源码]` 视图 / Markdown ⇄ mermaid ⇄ 画布三段互转），并能看到本**议程环节**各组画布与同步状态。
  AI 起草的留白规则见 **UC-7.2**（D-11 已改写，不再使用「六成」口径）。
- **本用例结果**：[Backlog] 用户通过“组内协作编辑画布”完成从“组员在本组画布上工作”到可追踪业务结果的闭环。
- **系统边界**：画布编辑器（工具条 / 缩放平移 / 选中检查器 / `[源码]` 视图）、
  Markdown ⇄ mermaid ⇄ 画布三段互转、便签几何归区导出、组画布列表与四组状态、
  文档↔画布同步三态、便签级 LWW、结构性冲突条与人工裁决。
- **核心数据对象**：画布实例、便签、节点、连线、**分区框**（模板 `##` 段落对应的几何框）、
  **组画布状态**（进行中 / 你在这组 / 只读 / 落后）、**同步状态**（已同步 / 待同步 / 画布领先）、
  作者与临时身份、版本、布局快照、冲突记录。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“项目模板（环节绑定）、实时转录（素材来源）”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] 组员在本组画布上工作。
  - 系统从 **本组画布** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **组员操作**：[原型] 从议程进入画布（面包屑「‹ 回到议程·环节 3 ｜ 画布来自 Kickoff 项目·假设风暴」）。
   **系统响应**：[原型]「环节里绑定了模板与 skill，组员打开就是这张画布，不用自己找」；
   左栏同时列出**本议程环节各组画布**（带四态）、**本项目画布**（带同步三态）、**本议程环节绑定的 skill**。
2. **组员操作**：[原型] 用工具条作业——`选择 ｜ ＋便签 ｜ ＋节点 ｜ 连线 ｜ 删除 ｜ [源码] ｜ ＋ − ⤢`；
   贴便签、连关系、标致命假设。**系统响应**：校验当前身份与本组归属；
   [原型] 交互口径固定为「**滚轮缩放 · alt 拖拽平移 · 拖节点连线按边界锚点重算**」。
3. **组员操作**：[原型] 把便签拖进某个分区框。**系统响应**：按**几何归区**判定它属于哪个 `##` 段落
   （落在框外的归**最近的框**），并更新完成度（如已填 5/9 格）。
4. **组员操作**：[原型] 点 `[源码]` 查看当前画布对应的 Markdown / mermaid 文本，并可**直接手改**。
   **系统响应**：手改后重新解析回画布；三段（Markdown / mermaid 文本 / 画布对象）任一段的修改
   都能传导到另外两段。
5. **系统处理**：[原型] 谁贴的便签带临时身份标记（匿名成员用临时名字）；每次改动即时同步给同组其他人。
   **并发按粒度分流（D-09）**：
   - **便签级（同一张便签的文本、颜色、位置）** → **LWW 最后写入生效**，保留改动历史，不弹冲突。
   - **结构性冲突（文档侧与画布侧同时改了结构：分区增删、节点/连线增删、便签跨区移动）**
     → 不自动合并，进入第 6 步。
6. **系统响应（冲突条，[原型] 状态 4.4）**：画布**顶部出现冲突条**，
   [原型]「说清两侧各改了什么」，出口**三选一**：
   `[并排比较]` / `[保留文档]` / `[保留画布]`；**无论选哪个，另一侧都存为一个版本**，不丢弃。
   裁决前该画布进入待裁决态，禁止继续产生新的结构性写入。
7. **系统处理（同步三态）**：[原型] 标题区与左栏常驻显示 `已同步 / 待同步 / 画布领先` 三态之一。
8. **系统收口**：校验 AC1「画布节点与证据卡能一键回流成果沉淀」、
   AC2「便签拖进哪个分区框就导出到那个 `##` 段落」、AC3「冲突条三个出口都保留另一侧版本」；
   满足后记录操作者、时间、对象、结果与来源，并刷新相关列表、图谱、看板或通知状态。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] 目标数据为空时展示空状态、原因和下一步入口，不生成示例数据冒充真实结果。
    （原型每屏均填满样例数据，**零空态**，本条无原型依据。）系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
  - A2：[原型] **只读组画布**——打开别组画布时以 `只读` 态呈现，工具条写操作全部禁用。
  - A3：[原型] **`[另存布局快照]`**——因为坐标不写回 Markdown，用户想固定当前排布时，
    可另存一份布局快照作为补偿；快照与内容版本分开存放，不影响文本往返。
- **异常流程**：
  - E1：[原型] 匿名成员也能贴，身份用临时名字。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[原型] **便签级**冲突编辑按最后写入生效并留历史（LWW）。
  - E2b：[原型] **结构性冲突**不适用 LWW——走顶部冲突条人工裁决，
    三个出口 `[并排比较]` / `[保留文档]` / `[保留画布]`，**另一侧存版本**。
    裁决未完成前不得静默采纳任何一侧。
  - E2c：[原型] 文档里写了**被白名单关闭**的 mermaid 类型时，不渲染但不丢内容；
    画布顶部提示「**有 N 条语法被忽略**」，可点 `[源码]` 查看原文（详见 UC-7.1 R7）。
  - E2d：[设计] 便签**落在所有分区框之外**时不报错——归**最近的框**，
    并在便签上给出可撤销的归区提示。
  - E3：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E4：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E5：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R7 业务规则（不随具体实现变化的硬性约束）

### 由 mermaid 语法特性直接推导的三条硬规则（[D-08]，不得当作实现细节改写）

- **① 便签按几何归区**：[原型]「便签按几何归区：**拖进哪个分区框，导出就归到那个 `##` 段落**；
  **落在框外的归最近的框**。」归区判定以几何包含为准，与创建顺序、创建者、便签内容无关；
  便签换区后再导出，必须出现在新分区的 `##` 段落下。
- **② 坐标不写回 Markdown**：[原型]「**mermaid 语法里没有坐标位**。写回只保留结构，
  重新渲染时由 mermaid 自动布局。」因此：
  - 同一份 Markdown 两次渲染的**节点坐标可以不同**，这是正确行为，不是 bug；
  - 任何需求、验收、缺陷都**不得以「重开后位置变了」为失败判据**；
  - 补偿手段是 [原型] **`[另存布局快照]`**——布局快照是独立于文本的旁路数据，
    只影响本次打开的初始排布，不参与 Markdown 往返。
- **③ mermaid 图表类型白名单**：[原型] 后台可配 12 类（清单见 UC-7.1 R7）。
  **关掉的类型仍可书写但不渲染**，画布顶部提示「**有 N 条语法被忽略**」，
  被忽略的源码原样保留、可在 `[源码]` 视图查看。

### 并发与冲突（[D-09] 分粒度）

- **便签级 → LWW**：[原型] 冲突编辑按最后写入生效并留历史。适用范围：同一张便签的文本、
  颜色、位置、归属分区。不弹冲突条，但改动历史必须可查。
- **结构性冲突 → 人工裁决**：文档侧与画布侧同时修改结构（分区增删、节点/连线增删、
  便签跨区移动）时，**不自动合并、不静默覆盖**。
  [原型] 画布顶部出现**冲突条**，说清两侧各改了什么，出口**三选一**：
  | 出口 | 语义 |
  |---|---|
  | `[并排比较]` | 打开两侧差异视图后再选保留哪一侧 |
  | `[保留文档]` | 采纳文档侧结构，**画布侧存为一个版本** |
  | `[保留画布]` | 采纳画布侧结构，**文档侧存为一个版本** |
- [设计] **另一侧必存版本**是硬约束：三个出口任意一个都不得丢弃另一侧内容。
- [设计] 待裁决期间禁止新的结构性写入；便签级 LWW 写入不受影响。

### 状态取值（[原型]，为一等 enum，不得增删取值）

- **组画布状态**（左栏「本环节各组画布」，即本**议程环节**各组画布）：`进行中` / `你在这组` / `只读` / `落后`。
  「落后」的判定口径 [待确认]（原型示例：第 4 组 4 便签 vs 其它组 6–12 便签）。
- **同步状态**（左栏「本项目画布」与标题区）：`已同步` / `待同步` / `画布领先`。
  「画布领先」= 画布侧已改但尚未写回文档侧。

- [原型] 匿名成员也能贴，身份用临时名字。
- AC1：画布节点与证据卡能一键回流成果沉淀。
- AC2：便签换区后导出到正确的 `##` 段落。
- AC3：结构性冲突三出口都保留另一侧版本。
- AC4：四组画布状态与同步三态始终可见。

- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

  - **标题区**：画布名 ｜ ```` ```mermaid · flowchart LR ```` ｜ 同步态 ｜ 协作头像（人 + AI）。
  - **冲突条**：位于画布**顶部**，仅在结构性冲突时出现（见 R7）。

### 优先级最高：round-trip 断言（Node 可跑，不依赖 testid）

- **V1（AC2 · 便签换区 round-trip）**：取一份 `模板: swot` 的 Markdown，其中便签 X 在
  `## 优势` 段落 → 渲染成画布对象 → 把 X 的坐标改到 `## 威胁` 分区框内 → 导出 Markdown ——
  断言 **X 出现在 `## 威胁` 段落下，且不再出现在 `## 优势` 下**，其余内容逐字不变。
- **V2（AC2 · 框外归最近框）**：把便签 Y 放到所有分区框之外、几何上最靠近 `## 机会` 框 →
  导出 —— 断言 Y 归入 `## 机会`。
- **V3（结构 round-trip）**：对 13 种 mermaid 图各取一份夹具，
  `mermaid 文本 → DiagramModel → mermaid 文本`，断言**逻辑结构等价**
  （节点集合、边集合、标签、形状一致）。
- **V4（坐标不写回，R7 ②）**：渲染一份 flowchart → 在画布上大幅拖动所有节点 → 导出 —— 断言
  导出的 mermaid 文本**与原文本逻辑等价且不含任何坐标信息**；
  再次渲染时坐标由自动布局决定，**不得断言坐标相等**。
- **V5（布局快照）**：`[另存布局快照]` 后重开画布，节点回到快照位置；
  同时断言该快照**未改变** Markdown 文本一个字节。

### 状态与冲突

- **V6（AC3 · 冲突三出口）**：制造一次文档↔画布结构性冲突 → 断言顶部冲突条出现且列出两侧改动 →
  分别对三个出口各跑一遍：每次裁决后 ① 采纳侧生效 ② **另一侧存在一个可读取的版本** ③ 冲突条消失。
- **V7（LWW 便签级）**：两名组员同时改同一张便签文本 → 最终值为最后写入者的值，
  且**改动历史中能查到被覆盖的那次**；全程**不出现冲突条**。
- **V8（AC4 · 状态 enum）**：组画布列表接口对每张画布返回
  `进行中|你在这组|只读|落后` 之一；项目画布列表返回 `已同步|待同步|画布领先` 之一；
  取值超出枚举即失败。
- **V9（白名单忽略提示）**：白名单关闭某类型时，画布接口返回 `ignored_syntax_count = N`，
  且 `[源码]` 视图仍能读到被忽略的原文（详见 UC-7.1 V4）。
