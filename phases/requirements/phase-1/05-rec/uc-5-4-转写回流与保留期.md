# 原始需求（细化）— UC-5.4 转写回流与保留期

> 所属：阶段一 · 能跑完一场项目 / M5 实时转录  
> 来源：`Backlog Use Case.html` 的 UC-5.4；UI 线索来自 `WorkspaceX Standalone.html`。  

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P1**；估点 **5**（原 3；+2 = 保留期参数化与同意书动态渲染）；建议迭代 **迭代 5 · 收尾项**。
>
> **[人类已拍板 2026-07-27 · D-14]** 留存期**统一为一套可配置策略**，共**五个独立参数**：
> **材料保留期 / 留痕保留期 / 删除宽限期 / 知识有效期 / 审计保留期**。
> 本用例只负责其中的 **`材料保留期`**（录音、逐字稿、原始材料）。
> - 每个参数**各有默认值，且项目级可覆盖**。
> - **同意书文案必须按项目动态渲染**——否则告知受访者的天数与系统实际执行的天数会不一致，
>   这是合规上的实质性缺陷，不是文案问题。
> - ⚠ **各参数的默认值与允许区间仍需合规负责人给出**（D-14 原文）。在此之前实现方不得自选数值。
>
> **本文已删除所有写死的天数表述。** 原型里出现的「180 天」共 **四处**（早期稿本只数到两处，已更正）：
> ① 受访者授权屏「录音——只在这场访谈中录，存于远洋的服务器，**180 天后自动删除**」（proto-04）；
> ② 研究计划参数「**数据保留 180 天 · 禁止用于训练**」（proto-07）；
> ③ 后台 MCP 安全策略「涉客户数据的工具调用全量留痕 **180 天**」（proto-03，属**留痕保留期**，非材料保留期）；
> ④ **项目 → 设置 → 产出与留存 →「转录留存 **180 天**」**（proto-08）——
>    **这一处才是本用例最直接的载体**：它就是转写的保留期在项目级的配置面，早期稿本整个漏了。
> 四处分属**不同参数**（①② 材料保留期 · ③ 留痕保留期 · ④ 转录/材料保留期的项目级覆盖值），
> 它们都是**某个项目的当前取值示例**，**不是产品常量**，一律按对应参数读取后渲染。
> **[待确认]** ④ 与 ①② 是否同一个参数的不同呈现（项目级覆盖 vs 项目内消费方），需合规/产品确认。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-5.4 / 转写回流与保留期
- **Actor**：**引导师**、**组长**、**受访者**
- **目标**：[原型] 多路并行录音转文字，先出文字不猜说话人；结束后再指派身份。转写是访谈、画布、图谱的原料。
- **本用例结果**：[Backlog] 用户通过“转写回流与保留期”完成从“转写完成”到可追踪业务结果的闭环。
- **系统边界**：逐字稿归档进项目材料库、**材料保留期的参数化与项目级覆盖**、
  到期删除与删除证明、**同意书文案的动态渲染**、撤回联动。
- **核心数据对象**：录音轨、转写段、时间码、引述、打点、**留存策略（五参数）**、
  **`材料保留期` 的组织默认值与项目覆盖值**、同意书模板与渲染实例。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“登录管理（授权与可见性）”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] 转写完成。
  - 系统从 **材料库 / 设置** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **引导师操作**：[设计] 逐字稿入项目材料库，按**议程环节**归档——
   即每份逐字稿在落库时记录它产生于哪个**议程环节**（区别于蓝本的 **16 项设计配置**
   与推演流水线的 **9 个方法环节**，术语三分见 D-03），材料库按该字段分组呈现。
   **[原型确认缺失]** 材料准备子标签只写实了「材料准备 **9 份**」的计数，
   **未见按议程环节分组的材料库视图**，也未见逐字稿在其中的条目形态；归档维度为推断。
   **系统响应**：校验当前身份、项目范围、必填数据与资源版本；
   逐字稿条目须携带：来源议程环节 id、来源录音/访谈 id、时间范围、生效的保留期与其解析依据；
   成功后更新界面和业务记录，并保留可追溯来源。
2. **系统处理 —— 保留期取值**：每份转写与录音在落库时**解析出生效的 `材料保留期`**，
   取值顺序为「**项目级覆盖值 → 组织默认值**」，并把**解析结果与解析依据**一起写进该材料的元数据
   （记录用了哪一级、当时的数值是多少）。
   - 到期时间 = 落库时间 + 生效材料保留期，**在材料上固化**，事后修改参数不追溯已落库材料的到期时间
     （否则受访者当初被告知的天数会被悄悄改变）；确需追溯调整时走显式的变更审批并通知受访者。
   - [原型] 该参数在**研究计划参数**面板上与「**禁止用于训练**」开关同处一屏
     （原型原文：`数据保留 <材料保留期> · 禁止用于训练`）。
3. **系统处理 —— 同意书动态渲染**：受访者授权页（UC-6.3）的录音条目文案**必须由 `材料保留期` 渲染**，
   如「只在这场访谈中录，存于 `<数据控制方>` 的服务器，`<材料保留期>` 后自动删除」。
   - **禁止硬编码任何天数**；模板变量至少包含 `材料保留期`、`数据控制方`、`联系人`、`合规邮箱`。
   - 每份**已提交的同意书要存下当时的渲染实例**（快照），作为「当时告知了什么」的证据；
     后续项目改参数不得回溯改写已签同意书。
4. **系统处理 —— 到期删除**：到达到期时间后按 `删除宽限期` 进入待删除队列，随后物理删除并出**删除证明**；
   全程**禁止用于训练**（此为独立开关，与保留期并列，不因保留期未到而放宽）。
5. **系统收口**：校验 AC1“能看到每份转写的保留期与删除时间”；满足后记录操作者、时间、对象、结果与来源，并刷新相关列表、图谱、看板或通知状态。
6. **系统收口**：校验 AC2“同意书文案与该项目实际生效的材料保留期一致”。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] 目标数据为空时展示空状态、原因和下一步入口，不生成示例数据冒充真实结果。系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
- **异常流程**：
  - E1：[原型] 受访者事后撤回授权时连带处理引述——**按 UC-6.3 的五步撤回流与 D-15 两级 SLA 执行**：
    逻辑失效（退出检索、报告段落标「证据已撤回」）**即时 ≤5 分钟**，物理删除并回执 **≤30 天**。
    **已废弃「24 小时」口径**。注意第 3 步是**标失效不静默删除**，第 4 步若支撑过已签字决策则
    **通知拍板人复核而非自动改结论**。
  - E2：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E4：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。
  - E5：[设计] **项目未设置覆盖值**时回落组织默认值；**组织默认值缺失**时**拒绝开始录制**并提示去配置，
    不得用一个隐含常量兜底。
  - E6：[设计] **同意书渲染变量缺失**（如未配置合规邮箱）时**不得发出授权链接**，
    在研究员侧显式报错并指向配置入口——发出一份告知不完整的同意书比不发更糟。
  - E7：[设计] 到期删除任务失败时材料**保持不可读**（先逻辑失效）并告警重试，
    不得因删除失败而让材料继续可访问，也不得在未真正删除时发出删除证明。

## R5 权限与可见性

- **引导师**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **组长**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **受访者**：可查看/确认自身授权并提出撤回；不能访问项目内部材料或其他受访者数据。
- **观察者**：默认不能发起或修改；仅当内容已发布且授权范围允许时只读查看脱敏结果。
- **项目经理**：可查看项目级状态与审计摘要；是否可代替业务 Actor 执行写操作需由角色模板显式授权。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 形成与本 use case 对应的正式记录或明确状态，并可从来源页面再次打开。
  - 所有跨模块回流均携带来源资源、版本、操作者/触发者、时间和可见范围。
  - [原型验收] AC1a：能看到转写的保留期——[原型] **项目 → 设置 → 产出与留存 → 「转录留存 180 天」**。
  - [Backlog验收] AC1b：能看到**每份**转写的**删除时间**——档案只有项目级的一个留存期数值，
    **没有逐份转写的保留期/删除时间呈现**。属 Backlog 要求，需补画原型。
  - [设计验收] **AC2（新增，D-14）**：受访者授权页显示的保留期**等于**该项目生效的 `材料保留期`；
    把项目覆盖值改掉后，**新发出的**同意书文案随之变化，而**已提交的**同意书快照不变。
  - [设计验收] **AC3（新增，D-14）**：`材料保留期` 是五个留存参数之一，有组织默认值、可项目级覆盖；
    代码中不存在写死的保留天数常量。
  - [设计验收] **AC4（新增）**：到期后材料先逻辑失效再物理删除，并产出可检索的删除证明；
    「禁止用于训练」在整个生命周期内恒成立。
- **失败后置条件**：
  - 不创建“看似成功”的正式记录；可重试内容保留为草稿，失败事件进入可观测日志。
- **不包含**：
  - 完整离线录音工作站、未经授权的**跨场次**声纹身份库（边界见 UC-5.2 头部）。
  - 不扩展到本 use case 未声明的跨组织、跨客户或公开发布能力。

## R7 业务规则（不随具体实现变化的硬性约束）

- [原型] 受访者事后撤回授权时连带处理引述，按 UC-6.3 五步撤回流 + D-15 两级 SLA（即时 ≤5 分钟 / 物理删除 ≤30 天）。
- **[人类已拍板 D-14] 保留期是参数，不是常量**：`材料保留期` 有组织默认值、项目级可覆盖；
  **禁止在代码或文案中写死天数**。
- **[人类已拍板 D-14] 同意书文案按项目动态渲染**；已提交的同意书保存渲染快照，不可回溯改写。
- [设计] 到期时间在材料落库时**固化**，参数变更不追溯已落库材料。
- [原型] **禁止用于训练**是与保留期并列的独立开关，全生命周期恒成立。
- AC1：能看到每份转写的保留期与删除时间。
- AC2：同意书文案与该项目实际生效的材料保留期一致。

- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。

  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。

## R10 已知约束 / 依赖

- **内部依赖**：[原型] 登录管理（授权与可见性）。
- **跨模块契约**：身份与权限、来源引用、版本、任务状态、审计事件和通知必须使用统一标识，避免同一对象在各模块成为不可关联的副本。
- **技术约束**：[原型] 产品为响应式网页；完整离线模式、原生移动端、第三方 IM 与产品内自助计费在 backlog 中明确为范围外。
- **[待确认]** 单项目并发人数、组织数、材料量、音频时长和历史数据量尚未给出；容量与压测指标需在开发前定稿。
- **[待确认]** 通知渠道、消息模板、语言与时区策略未统一定义；本文仅承接原型明确写出的产品内/邮件行为。
- **[待确认]** 数据驻留地区、加密密钥策略、法定留存和删除证明格式需由合规负责人确认。
- **[待确认]（阻断验收，D-14 原文）** **五个留存参数各自的默认值与允许区间**——
  材料保留期 / 留痕保留期 / 删除宽限期 / 知识有效期 / 审计保留期。
  没有这组数值就写不出 AC1 与 AC4 的可执行 verification；实现方**不得**自选数值当作验收线。
  （原型出现的「180 天」是示例项目的取值，不构成默认值。）
- **跨模块契约**：`材料保留期` 的读取接口由 00-core / 17-gov 的留存策略内核提供，
  本用例只是消费方；同意书模板渲染由 UC-6.3 消费同一个接口，两处**必须取同一个值**。

## R11 切分提示（给 requirement-author）

- 建议先拆“领域数据与权限 → 主流程服务 → 页面与状态 → 跨模块回流 → 审计/通知 → 自动化验收”。
- 单个 feature 应能在一次会话内实现并验证，不应把本 use case 的全部前后端与所有异常态塞进一个 feature。
- 建议切成「留存策略参数读取与项目级覆盖」「到期时间固化与到期删除 + 删除证明」
  「同意书动态渲染与渲染快照」三个 feature；前者是后两者的前置。
- **优先级 / 先后依赖**：P1；**5 点**；迭代 5 · 收尾项；先满足“登录管理（授权与可见性）”与留存策略内核。
- 对 P1 能力可在主链路稳定后实现，但合入时仍需覆盖本文全部验收状态。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态）：AC1：能看到每份转写的保留期与删除时间（数值来自参数解析，元数据里记录了取自哪一级）。
- V2（成功态）：AC2——把项目级 `材料保留期` 覆盖值改为另一个数，断言：
  ① 新生成的授权页文案显示新数值；② 已提交同意书的渲染快照仍显示旧数值；
  ③ 已落库材料的到期时间不变。
- V3（成功态）：AC3——全仓检索确认不存在写死的保留天数常量；
  清空项目覆盖值后回落组织默认值；清空组织默认值后开始录制被拒绝并给出配置入口。
- V4（成功态）：AC4——把某份材料的到期时间调到过去，断言它先变为不可读、进待删除队列，
  宽限期后物理删除并产出可检索的删除证明。
- V5（权限态）：逐一使用 引导师、组长、受访者、观察者、未授权用户访问；返回数据和可执行动作严格符合 R5。
- V6（空态）：无目标数据时显示真实空态与下一步，不生成伪数据。
- V7（依赖失败）：模拟删除任务失败，断言材料保持不可读、发出告警并重试，**不产出删除证明**。
- V8（并发态）：两名用户修改同一资源时不静默覆盖，并可识别最终版本。
- V9（审计态）：关键动作可按操作者、时间、对象和结果检索；越权尝试也有安全审计记录。
  参数变更、到期删除、删除证明发放三类事件均可独立检索。
