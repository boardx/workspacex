# 原始需求（细化）— UC-5.2 结束后指派说话人

> 所属：阶段一 · 能跑完一场项目 / M5 实时转录  
> 来源：`Backlog Use Case.html` 的 UC-5.2；UI 线索来自 `WorkspaceX Standalone.html`。  

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **8**（原 5；+3 = 转写异常两态的处理出口，见 R3/R4）；建议迭代 **迭代 3 · 能采集**。
>
> **⚠ 「声纹」一词必须拆成两件事（本文最关键的一条口径）**
> - 原型访谈现场（`访谈 → [打开访谈] → 记录`）原文：「先只出文字，不猜是谁说的；
>   **结束后可用声纹或手动指派**把段落归到受访者。」
> - `DECISIONS-FINAL.md` 合规节裁决：说话人识别取 **diarization**，**无声纹身份库**，人工映射真名。
> - 两者**不矛盾**，因为「声纹」在两处指的不是同一个东西：
>   - ✅ **本场内声纹聚类**（同一段音频里把相似音色归为同一个匿名声道）——
>     这是 diarization 的实现手段，**特征只在本场次内存在、随本场音频一起删**，**保留**。
>   - ❌ **跨场次声纹身份库**（把「这个音色 = 周宁」持久化，下一场自动认人）——
>     UC-5.1 R6 明确排除，**不做**。
> - **[已裁决 O-14]** 上述边界确认成立：**本场内聚类保留 / 跨场次身份库排除**。
>   **销毁时点**：**说话人指派完成（即本 UC-5.2 结束）立即销毁本场声纹 embedding，
>   最迟不超过本场结束后 7 天**（兜底，覆盖「指派迟迟未做」的场景）。
>   声纹特征**纳入 UC-17.2 的撤回与删除范围**。理由：指派完成后 embedding 已无业务用途
>   （映射关系已固化为真名标签），继续保留只有风险没有收益。
>   ⚠ 注意这**不再是**「与音频同生命周期」——embedding 的存活期**远短于**材料保留期（180 天）。
> - 原文档 R3 第 1 步的「系统按**声纹**给出候选说话人，人来确认」表述不精确：
>   声纹聚类给出的是**匿名声道**，**候选人名单来自本场在场名单**，两者已在 R3 拆开写。
>
> **原型状态**：本用例的入口已探明——`记录` 标签状态条上有计数「**逐字稿校对 14**」，
> 逐字稿行内也有 `[修正发言人]` 操作；但**点进「逐字稿校对」后的完整校对屏尚未抽取**。
> R8 中标 [原型] 的是已见的入口与行内操作，标 [设计] 的是反推的校对屏布局。
> **未探明 ≠ 原型没做**，不得据此裁掉需求。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-5.2 / 结束后指派说话人
- **Actor**：**引导师**、**组长**、**受访者**
- **目标**：[原型] 多路并行录音转文字，先出文字不猜说话人；结束后再指派身份。转写是访谈、画布、图谱的原料。
- **本用例结果**：[Backlog] 用户通过“结束后指派说话人”完成从“录音结束或转写完成”到可追踪业务结果的闭环。
- **系统边界**：**匿名声道 → 真人身份的人工映射**、争议标记、指派结果的全量回填与撤销。
- **核心数据对象**：录音轨、转写段、**匿名声道（说话人 A/B/C）**、**声道↔人 映射记录**、时间码、引述、打点、留存策略。
- **本用例的实质**：UC-5.1 交付的是**匿名声道**——系统知道「有三个不同的人在说话」，但**不知道他们是谁**。
  本用例把「说话人 A」绑到「周宁」，绑定动作**永远由人做**，系统只提供候选排序与批量操作。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“登录管理（授权与可见性）”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] 录音结束或转写完成。
  - 系统从 **逐字稿校对** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **系统处理**：系统按 **diarization（本场内声纹聚类）** 列出本场的**匿名声道**（说话人 A / B / C …），
   每个声道给出发言时长占比、首次出现时间码与若干代表片段，并给出**候选人名单**——
   候选来自**本场的在场名单**（项目分组名单 / 访谈的 `受访者` 名单 / 线程成员），
   **不来自任何跨场次声纹身份库**。系统记录触发原因，校验数据、权限与幂等条件，
   更新业务状态，并向有权用户反馈结果。
2. **引导师操作**：把某个匿名声道**指派**给名单里的某个人（一次操作覆盖该声道的全部段落），
   也可对单段做例外修正。**系统响应**：校验当前身份、项目范围、必填数据与资源版本；
   成功后更新界面和业务记录，并保留可追溯来源。
3. **引导师操作**：确认后回填到所有引用了该段的地方（引述出处、洞察来源角标、报告来源、图谱节点）。
   **系统响应**：全量回填并保持可撤销；回填是**指向同一条映射记录的引用**，不是复制副本。
4. **引导师操作**：未确认的段落保持匿名，不阻塞使用。**系统响应**：匿名段落照常可检索、可引用，
   引述出处显示「出处待补」。
5. **系统处理**：[原型] **转写异常两态**必须在逐字稿上就地可见，并各有处理出口
   （原型逐字稿原文即带这两种标注）：
   - **`识别置信度低 · 待校对`** —— 文字本身可能识别错（如原型 `00:32:05` 那句德语混写）。
     出口：**[原型确认缺失]** —— 档案的行内操作条只有
     `[标为引述] [标痛点] [标机会] [修正发言人] [加研究笔记]` **五个按钮，没有文本编辑入口**。
     早期稿本写的 `[编辑文本]` 是**伪造按钮**，已删除。
     [设计] 需补一个人工修正文本的出口；未校对前该段**不得被抽为引述**。
   - **`发言人不确定 · 两人同时说话 · 待人工指派`** —— 说话人分离错乱（原型 `00:32:30`）。
     出口：**拆分**（切成两段分别指派）或 `[修正发言人]`；
     **未拆分前不得被指派给单一说话人，也不得被抽为引述**。
   这两态正是 UC-5.1/E7（后台反馈「多人同时说话识别错乱」7 票）在界面上的出口，
   状态条计数「**逐字稿校对 14**」即这两类待处理项的合计。
6. **系统处理**：[原型] **PII 自动遮盖**——逐字稿中被识别为邮箱、手机号等个人标识的片段
   自动显示为「**已自动遮盖：一个邮箱地址与一个手机号 · 查看原文需权限**」。
   指派与校对**不需要**解遮盖即可完成；查看原文是独立的授权动作并留痕（详见 UC-5.1 R7 与 17-gov）。
7. **系统收口**：校验 AC1“指派后引述自动补上出处，且能撤销”；满足后记录操作者、时间、对象、结果与来源，并刷新相关列表、图谱、看板或通知状态。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] 匿名参与者只显示临时名字。系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
- **异常流程**：
  - E1：[Backlog] 同一段被多人认领时保留争议标记。（「争议」在原型档案中 0 命中；
    档案的对应态是 `发言人不确定 · 两人同时说话 · 待人工指派`，语义是**未定**而非**争议**。）失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E4：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

- **引导师**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **组长**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **受访者**：可查看/确认自身授权并提出撤回；不能访问项目内部材料或其他受访者数据。
- **观察者**：默认不能发起或修改；仅当内容已发布且授权范围允许时只读查看脱敏结果。
- **项目经理**：可查看项目级状态与审计摘要；是否可代替业务 Actor 执行写操作需由角色模板显式授权。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。
- **匿名参与者**：权限绑定到本场、本组和临时身份；项目结束后不得自动升级为正式账号权限。

  - [原型验收] **AC4（新增）· [已裁决 O-39]**：PII 五类（邮箱 / 手机号 / 身份证号 /
    银行卡号 / 详细住址）在逐字稿中自动遮盖；指派与校对**不需要解遮盖即可完成**。
  - [原型验收] **AC3（新增）**：`识别置信度低 · 待校对` 与 `发言人不确定 · 两人同时说话 · 待人工指派`
    两态在逐字稿上就地可见、各有出口，且**在处理前都不可被抽为引述**；
    状态条的「逐字稿校对 N」计数与两类待处理项的实际数量一致。
  - [原型验收] **AC4（新增）**：邮箱与手机号在逐字稿中自动遮盖，显示「查看原文需权限」；
    无权限者无论通过界面还是接口都取不到原文。
- **失败后置条件**：
  - 不创建“看似成功”的正式记录；可重试内容保留为草稿，失败事件进入可观测日志。
- **不包含**：
  - 完整离线录音工作站、**未经授权的声纹身份库**。
  - **系统自动认定说话人身份**——系统只给候选与排序，**绑定动作永远由人做**，没有「自动指派」开关。
  - **跨场次的声纹比对**（「这个声音上次是谁」）。
  - 不扩展到本 use case 未声明的跨组织、跨客户或公开发布能力。

## R7 业务规则（不随具体实现变化的硬性约束）

- **[人类已拍板 + 已裁决 O-14]** 说话人候选**只基于本场内的 diarization 匿名声道 + 本场在场名单**；
  **本场内声纹聚类允许**，**跨场次声纹身份库禁止**。
  **销毁时点硬约束**：本场声纹 **embedding 在本 UC 的指派完成动作提交时立即销毁**，
  并有**兜底定时任务**在本场结束后第 7 天无条件销毁（无论指派是否完成）。
  销毁是**物理删除 + 写审计事件**，不是打标记；声纹特征纳入 UC-17.2 撤回与删除范围。
- **[设计]（Context Engine）** 声纹 embedding 属 `derived_representations`，
  其销毁必须**级联失效**任何以它为输入的派生物与缓存；销毁后重跑 diarization
  只能产生**新的派生版本**，不得复活旧特征。
- [设计] **真名映射必须由人确认**：系统不得把任何候选自动落成已确认的指派。
- [原型] **两种转写异常态在处理前都不可被抽为引述**：`识别置信度低 · 待校对`、`两人同时说话 · 待人工指派`。
- [原型] **PII（邮箱 / 手机号）在逐字稿中默认遮盖**，查看原文是独立授权动作且留痕。
- [原型] 同一段被多人认领时保留争议标记。
- [原型] 匿名参与者只显示临时名字。
- [设计] **[已裁决 O-13]** 重叠段落未拆分前不可指派、不可引述；其存储状态必须是
  **「两人同时说话 · 待人工指派」**，**不得被静默归给单一说话人**——
  本 UC 是该状态的**唯一解除出口**，解除动作必须由人完成并留痕。
- **[设计]（Context Engine · 服务平面）** 指派候选排序若使用 AI，
  **只能通过 Context API 取 Context Pack**（本场在场名单 + 本场转写 Segment），
  不得绕过直查 `segments` 或向量库；每次调用留一条 `context_packs` 记录可重放。
- [设计] 指派与撤销都是**可逆且留痕**的：撤销后所有回填处同步退回「出处待补」，不留脏数据。
- AC1：指派后引述自动补上出处，且能撤销。

- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R8 界面线索

- **已探明的部分（[原型]）**：
  - **三个入口**：① 访谈 `记录` 标签状态条「转写处理 1 失败 ｜ **逐字稿校对 14**」；
    ② 实时转录区的 **`[结束后指派说话人]`** 按钮；

  - **逐字稿行内操作条**：`[标为引述] [标痛点] [标机会] [修正发言人] [加研究笔记]`，
    以及「点时间码跳回音频 · 选中可标为引述」与 `[搜索]`。
  - **行内状态标注**：`已标为引述 · 支持 RQ2`、`P-11 Kraus 附和 · 非独立证据`、
    `识别置信度低 · 待校对`、`发言人不确定 · 两人同时说话 · 待人工指派`、
    `已自动遮盖：一个邮箱地址与一个手机号 · 查看原文需权限`。
- **⚠ 未探明（待补抽取）**：点击「逐字稿校对 14」之后的**完整校对屏**。
  以下布局按已见的行内操作反推，标 **[设计]**；**未探明 ≠ 原型没做**。
- **前端入口**：[原型] 访谈 `记录` 标签；项目工作台右侧转录栏；任务看板的 `[转写]` 待办；
  本用例具体页面为 **逐字稿校对**（入口已探明，屏内未探明）。
- **信息架构**：[原型] 对话右栏五标签 转录 / 执行 / 洞察 / 产物 / **材料**（见 UC-5.1 R8）。
- **推荐交互**：
  - [设计] 左侧列出本场**匿名声道卡**（说话人 A / B / C，含时长占比、首次出现时间码、代表片段试听），

  - [设计] 采用分步表单或右侧配置面板，必填、依赖与完成度持续可见。
  - [设计] 不可逆或高影响动作使用确认对话框，明确对象、影响范围与后果。
- **必须呈现的状态**：
  - 默认态、加载态、空态、校验失败态、依赖失败态、无权限态、成功态。
  - 涉及后台任务时显示排队/运行/需批准/完成/失败/已取消，并允许查看最近一次成功结果。

## R9 非功能约束

- **性能/规模预期**：

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态）：AC1：指派后引述自动补上出处，且能撤销——撤销后所有回填处同步退回「出处待补」。
- V2（安全态）：**AC2 [已裁决 O-14]**——候选人接口返回的候选**全部在本场在场名单内**；
  代码与数据模型检索确认**不存在跨场次**的声纹特征表或比对调用。
- V2b（安全态 · **[已裁决 O-14]**）：**embedding 销毁时点**——
  ① 完成一次说话人指派后立即查询，断言该场次的声纹 embedding 记录数为 **0**（物理删除，非软删）；
  ② 构造一场「指派未完成」的场次，把时间推进到本场结束后第 8 天，运行兜底任务，
  断言 embedding 同样为 0，且写有一条销毁审计事件；
  ③ 断言销毁后重跑 diarization 只产生**新的派生版本**，旧特征未复活。
- V3（成功态）：AC3——对 `识别置信度低 · 待校对` 与 `两人同时说话 · 待人工指派` 两类段落，
  调用抽引述接口均被拒绝；前者经**人工文本修正出口**（[设计]，档案行内操作条无此按钮）、后者经拆分/`[修正发言人]` 处理后解锁；
  处理过程中「逐字稿校对 N」计数同步递减。
- V4（安全态）：AC4——含邮箱与手机号的逐字稿段落默认返回遮盖串；
  无权限账号请求原文接口被拒绝并写审计；有权限账号取到原文同样写审计。
- V5（权限态）：逐一使用 引导师、组长、受访者、观察者、未授权用户访问；返回数据和可执行动作严格符合 R5。
- V6（空态）：无目标数据时显示真实空态与下一步，不生成伪数据。
- V7（依赖失败）：模拟网络/外部依赖失败，输入和最近成功数据保留，错误可解释且可重试。
- V8（并发态）：两名用户同时指派同一声道时不静默覆盖；同一段被多人认领时保留**争议标记**且双方可见。
- V9（审计态）：关键动作可按操作者、时间、对象和结果检索；越权尝试也有安全审计记录。
  每一次指派与撤销都记录「谁把哪个声道绑到了谁、什么时候」。
