# 原始需求（细化）— UC-5.1 开启多路录音并实时出字

> 所属：阶段一 · 能跑完一场项目 / M5 实时转录  
> 来源：`Backlog Use Case.html` 的 UC-5.1；UI 线索来自 `WorkspaceX Standalone.html`。  

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **13**（原 8；+2 = 同路多人抢话错误率标准 + 对话线程转录 + 右栏五标签与常驻控件；
> +3 = **PII 自动遮盖**，见 R3 第 6 步）；建议迭代 **迭代 3 · 能采集**。
>
> **[人类已拍板 2026-07-27 · `DECISIONS-FINAL.md` 合规节]** 说话人识别取 **diarization（说话人分离）**：
> 系统只把音频切成若干**匿名声道**（说话人 A / B / C），**不建跨场次声纹身份库**，真名由人工映射（UC-5.2）。
> 本条与 R6「不包含未经授权的声纹身份库」互为一体。
> ⚠ **精确边界见 UC-5.2 头部**：原型访谈现场写「结束后可用**声纹**或手动指派」，
> 指的是**本场内声纹聚类**（diarization 的实现手段，特征随本场音频销毁），**允许**；
> 被排除的是**跨场次声纹身份库**（「这个音色 = 谁」的持久化）。该边界本身标 **[待确认]**。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-5.1 / 开启多路录音并实时出字
- **Actor**：**引导师**、**组长**、**受访者**
- **目标**：[原型] 多路并行录音转文字，先出文字不猜说话人；结束后再指派身份。转写是访谈、画布、图谱的原料。
- **本用例结果**：[Backlog] 用户通过“开启多路录音并实时出字”完成从“引导师或组长点开始录音”到可追踪业务结果的闭环。
- **转写发生在三个场景，同一套能力**：
  - [原型] **项目现场**：主持台「四组并行 · 每组一路录音，实时喂给本组的推演模板」。
  - [原型] **访谈现场**：访谈 Studio 的某一场访谈（`[进入现场]`）。
  - [原型] **对话线程**：线程列表卡片与线程头显示「**● 转录中**」（如「欧洲储能进入策略 · 假设梳理 ● 转录中」），
    线程内出现**转录卡**「会议转录中 28:14 … `[查看转录]` `[停止录音]`」。
    → 转写**不是项目与访谈独有**，对话线程同样是一等录制载体，`source_type` 至少三取值：`workshop / interview / thread`。
- **系统边界**：多路音频采集、麦克风权限、实时转写、**说话人分离（diarization）**、时间码、引述与留存。
- **核心数据对象**：录音轨、转写段、**匿名声道（说话人 A/B/C）**、时间码、引述、打点、留存策略。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“登录管理（授权与可见性）”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
  - [原型] **进场时申请麦克风权限**：组员链接落地页明写「进入后会申请**麦克风权限**，
    用于本组讨论的实时转录。**可以随时关掉**」——即权限是进场动作的一部分，且用户保有随时撤销的出口。
- **触发条件**：
  - [原型] 引导师或组长点开始录音。
  - 系统从 **现场记录 / 访谈记录 / 对话线程** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **参与者操作 / 浏览器交互**：进入本组（或线程/访谈）时，系统弹出**麦克风权限**申请，
   并同屏说明用途「用于本组讨论的实时转录」。**系统响应**：[原型] 授予后开始采集；
   **拒绝或事后关闭**时，该人本路降级为「未录制」并在界面显式标出，**不得静默继续采集**，
   也不得因此阻断其参与其它协作动作；权限状态随时可在同一处切回。
2. **引导师操作**：每组一路，互不混用；开始前检查授权是否齐全。**系统响应**：校验当前身份、项目范围、必填数据与资源版本；成功后更新界面和业务记录，并保留可追溯来源。
3. **引导师操作**：转录带时间码滚动出现，延迟标在界面上。**系统响应**：校验当前身份、项目范围、必填数据与资源版本；成功后更新界面和业务记录，并保留可追溯来源。
4. **引导师操作**：说话人未识别时只出文字，右上角明确标注。**系统响应**：[原型] 系统按 **diarization** 把音频切成
   匿名声道（说话人 A/B/C），**只出文字不猜真名**；未定稿的最后一段标「**正在识别**」中间态；
   真名映射留到 UC-5.2 由人工完成。
5. **系统处理**：[原型] 在**对话线程**场景下，线程卡片与线程头同步显示「**● 转录中**」，
   线程内落一张**转录卡**（含累计时长、最近一条逐字稿、`[查看转录]` `[停止录音]`）。
   系统记录触发原因，校验数据、权限与幂等条件，更新业务状态，并向有权用户反馈结果。
6. **系统处理**：[原型] **PII 自动遮盖**——转写落库时自动识别并遮盖**邮箱地址与手机号**，
   逐字稿上就地显示「**已自动遮盖：一个邮箱地址与一个手机号 · 查看原文需权限**」。
   规则：① 遮盖发生在**入库前**，原文单独加密存储，默认读接口不返回；
   ② 查看原文是独立授权动作并写审计（对齐 D-18 的管理员权力边界与 D-16 的两级脱敏）；
   ③ 遮盖后的文本照常参与检索、引述与 AI 归纳，**不因遮盖而丢句**；
   ④ **[待确认]** 需遮盖的 PII 类型全集（原型只举了邮箱与手机号；身份证号、银行账号、
   地址、客户名等是否纳入，由合规负责人定稿）。
7. **系统收口**：校验 AC1“4 路同时录不串台”；满足后记录操作者、时间、对象、结果与来源，并刷新相关列表、图谱、看板或通知状态。
8. **系统收口**：校验 AC2“每句都能点时间码跳回音频”；满足后记录操作者、时间、对象、结果与来源，并刷新相关列表、图谱、看板或通知状态。
9. **系统收口**：校验 AC3“**同一路内多人抢话时的说话人分离错误率**不超过约定阈值”，
   超阈值时按 E7 降级；满足后记录操作者、时间、对象、结果与来源。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] 目标数据为空时展示空状态、原因和下一步入口，不生成示例数据冒充真实结果。系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
  - A2：[原型] **参与者随时关掉麦克风**——本路立即停止采集并在转写流中留一条可见的「录制已暂停」标记，
    已产生的转写段不回收；重新开启后续接同一条转写，时间轴上留出缺口而不是拼接成连续假象。
- **异常流程**：
  - E1：[原型] 未授权的人不被录也不进转写。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[Backlog] 断网时本地缓存，恢复后补传并标出缺口。（原型无断网态屏，「断网」档案 0 命中。）失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[Backlog] 外语时显示原文与译文两行。（档案只写实了状态条 `德→中 · 延迟 1.8s`，
    **逐字稿本身是单行**，未见原文/译文双行呈现。）失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E4：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E5：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E6：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。
  - E7：[原型自承缺陷 → [设计] 补] **同一路内多人同时说话（抢话）时说话人分离错乱**。
    原型后台「反馈与迭代」把它记为在办缺陷：「[缺陷] **多人同时说话时说话人识别错乱** 7 票 ——
    周宁：项目里三个人抢话，转录把两个人合成了一个」。
    → 这与 AC1「4 路同时录不串台」**不是同一件事**：AC1 只覆盖**跨路串台**（第 1 组的话跑到第 2 组），
    E7 是**同一路内的声道合并/误切**。处理口径：
    - 系统必须**能自识别重叠语音**（overlap detection），把重叠区间标为「**多人同时**」而不是硬派给某一个声道；
    - **[原型] 界面出口已存在**：访谈 `记录` 标签的实时逐字稿上就地标注
      「**发言人不确定 · 两人同时说话 · 待人工指派**」，另有一态「**识别置信度低 · 待校对**」，
      两者合计进状态条计数「**逐字稿校对 14**」，处理出口在 UC-5.2。
    - 被标为「多人同时」的段落**默认不可直接抽为引述**，需 UC-5.2 人工拆分后才解锁；
    - 错误率超过阈值时，界面在该时间段给出「识别置信度低 · 待校对」的显式提示，
      **不得静默产出一个看似确定的说话人**。
    - **[待确认]** 可接受的错误率标准由产品与合规共同定稿，建议以下三个数字一并给出：
      ① **说话人混淆率（DER 中的 speaker confusion）** 在「同一路 ≥3 人、重叠语音占比 ≤15%」的基准场景下的上限；
      ② **重叠语音漏检率**上限；③ 触发「建议人工校对」提示的置信度阈值。
      在标准定稿前，实现方**不得**自行选定数值当作验收线。

## R5 权限与可见性

- **引导师**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **组长**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **受访者**：可查看/确认自身授权并提出撤回；不能访问项目内部材料或其他受访者数据。
- **观察者**：默认不能发起或修改；仅当内容已发布且授权范围允许时只读查看脱敏结果。
- **项目经理**：可查看项目级状态与审计摘要；是否可代替业务 Actor 执行写操作需由角色模板显式授权。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 形成与本 use case 对应的正式记录或明确状态，并可从来源页面再次打开。
  - 所有跨模块回流均携带来源资源、版本、操作者/触发者、时间和可见范围。
  - [Backlog验收] AC1：4 路同时录不串台（**跨路**隔离）。
    （档案只在报告取材计数里出现「转写 4 路」这一数字，**没有多路录音界面、没有串台/隔离的呈现**。）
  - [原型验收] AC2：每句都能点时间码跳回音频。
  - [设计验收] **AC3（新增，补 E7 的缺口）**：**同一路内多人抢话**时，重叠语音被标为「多人同时」而非合并成一个说话人；
    说话人混淆率不高于约定阈值（**阈值本身 [待确认]**，见 E7），超阈值段落自动挂「建议人工校对」。
  - [设计验收] **AC4（新增）**：对话右栏五标签（转录 / 执行 / 洞察 / 产物 / 材料）齐备且带计数，
    `搜索逐字稿`、`自动跟随`、`正在识别`、常驻时间码四项均可见可用（见 R8）。
  - [设计验收] **AC5（新增）**：在**对话线程**中开启录音后，线程卡片与线程头出现「● 转录中」，
    停止后消失；线程内转录卡可打开完整逐字稿。
  - [设计验收] **AC6（新增）**：进场时申请麦克风权限并说明用途；用户拒绝或事后关闭时本路不再采集，
    界面显式标出，不产生任何新的转写段。
  - [原型验收] **AC7（新增）**：邮箱与手机号在入库前自动遮盖，逐字稿显示
    「已自动遮盖：… · 查看原文需权限」；默认读接口不返回原文，查看原文写审计。
- **失败后置条件**：
  - 不创建“看似成功”的正式记录；可重试内容保留为草稿，失败事件进入可观测日志。
- **不包含**：
  - 完整离线录音工作站、**未经授权的声纹身份库**（本用例只做 diarization 的匿名声道，见头部拍板）。
  - **跨场次的声纹比对与身份自动识别**——任何「上次这个声音是谁」的推断都不在范围内。
  - 不扩展到本 use case 未声明的跨组织、跨客户或公开发布能力。

## R7 业务规则（不随具体实现变化的硬性约束）

- [原型] 未授权的人不被录也不进转写。
- [原型] 断网时本地缓存，恢复后补传并标出缺口。
- [原型] 外语时显示原文与译文两行。
- **[人类已拍板]** 说话人识别**只用 diarization**（音频内说话人分离），产出**匿名声道**；
  **本场内聚类允许，跨场次声纹身份库禁止**（边界见 UC-5.2 头部，标 [待确认]）；
  真名一律由人工映射（UC-5.2）。
- [原型] **进场即申请麦克风权限并说明用途，且用户可随时关掉**；未取得权限不得采集。
- [设计] **重叠语音不得被强行归属**：抢话区间标「多人同时」，未拆分前不可作为引述来源。
- [原型] 转写是**三种载体共享**的能力：项目现场 / 访谈现场 / 对话线程；三者共用同一套转写段与时间码模型。
- [原型] **PII（邮箱 / 手机号）在入库前自动遮盖**；查看原文需独立授权并留痕。遮盖不影响检索与引述。
- [原型] **未完成授权的人不会被录音或转写**——访谈在场列表原文：
  「P-12 · 未到场 · **授权未完成，不会被录音或转写**」，配 `[去授权]` 出口。这是 UC-6.3 硬约束在录制侧的落地。
- AC1：4 路同时录不串台。
- AC2：每句都能点时间码跳回音频。
- AC3：同路多人抢话的说话人分离错误率不超过约定阈值（阈值 [待确认]）。

- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R8 界面线索

- **前端入口**：[原型] **对话线程右栏**（会议进行中 · 显示转录）；项目工作台右侧转录栏；访谈现场页；
  本用例具体页面为 **现场记录 / 访谈记录 / 对话线程右栏**。
- **信息架构 —— 对话右栏五标签（[原型]，取代文档原写的「来源」）**：
  `转录` ｜ `执行 2/4` ｜ `洞察 6` ｜ `产物 3` ｜ **`材料 12`**
  - 第五个标签在原型里叫「**材料**」，不是「来源」；`DECISIONS-FINAL` 画布与对话节已明确
    「文档的『来源』＝原型的『材料』」，本文按**材料**书写，实现时 `data-testid` 亦用 `material`。
  - 除 `转录` 外，四个标签均带**计数徽标**，计数为 0 时显示真实空态，不隐藏标签。
- **转录标签页内的四个常驻控件（[原型]，缺一不可）**：
  1. **`搜索逐字稿`** 输入框 —— 在本场转写内全文检索，命中高亮并可跳转。
  2. **`自动跟随`** 开关 —— 打开时视图随最新一句滚动；用户手动上滚时自动置为关闭并给出「回到最新」出口。
  3. **`正在识别`** 中间态 —— 最新一句在定稿前以「（正在识别）」标注，如原型的
     「周宁 14:31:05 …（**正在识别**）」；该状态下的文本**不得被抽为引述、不得进入检索与 AI 归纳**。
  4. **时间码常驻** —— 头部显示本场累计时长（原型：`28:14`），每一句前常驻绝对时间码

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R10 已知约束 / 依赖

- **内部依赖**：[原型] 登录管理（授权与可见性）。
- **跨模块契约**：身份与权限、来源引用、版本、任务状态、审计事件和通知必须使用统一标识，避免同一对象在各模块成为不可关联的副本。
- **技术约束**：[原型] 产品为响应式网页；完整离线模式、原生移动端、第三方 IM 与产品内自助计费在 backlog 中明确为范围外。
- **[待确认]** 单项目并发人数、组织数、材料量、音频时长和历史数据量尚未给出；容量与压测指标需在开发前定稿。
- **[待确认]** 通知渠道、消息模板、语言与时区策略未统一定义；本文仅承接原型明确写出的产品内/邮件行为。
- **[待确认]** 外部服务供应商、失败重试次数、费用上限与服务等级尚未指定。

- **[待确认]（阻断验收）** **同路多人抢话的可接受错误率标准**（见 R4/E7 的三个数字）。

## R11 切分提示（给 requirement-author）

- 建议先拆“领域数据与权限 → 主流程服务 → 页面与状态 → 跨模块回流 → 审计/通知 → 自动化验收”。
- 单个 feature 应能在一次会话内实现并验证，不应把本 use case 的全部前后端与所有异常态塞进一个 feature。
- 建议把「**右栏五标签外壳 + 四个常驻控件**」「**对话线程转录载体**」「**麦克风权限与随时关闭**」
  「**重叠语音检测与低置信提示**」各切成独立 feature；其中最后一个的验收命令依赖 [待确认] 的错误率标准，
  应显式标记为 **blocked_on_decision**，不得先落一个自选阈值把它标成 passing。
- **优先级 / 先后依赖**：P0；**13 点**；迭代 3 · 能采集；先满足“登录管理（授权与可见性）”。
- 「PII 自动遮盖」与 17-gov 的 UC-17.2 共用同一套脱敏内核（D-16 两级脱敏），
  本用例只负责**转写侧的接入点**，不要在这里再造一套遮盖规则。
- 对 P0 必做链路优先实现成功态、权限态与数据闭环，异常态不得延期到上线后。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态）：AC1：4 路同时录不串台——4 路各注入一段已知音频，断言任一路的转写段中不含其它路的内容。
- V2（成功态）：AC2：每句都能点时间码跳回音频。
- V3（成功态）：AC3——注入一段「3 人抢话」的基准音频（对照原型反馈附的 40 秒片段），
  断言重叠区间被标为「多人同时」、说话人混淆率不超过约定阈值、超阈值段挂「建议人工校对」。
  **阈值未定稿前本项不可判定为通过。**
- V4（成功态）：AC4——右栏渲染五个标签（转录/执行/洞察/产物/**材料**）并带计数；
  `搜索逐字稿` 命中高亮；`自动跟随` 开关切换生效；最新一句带「正在识别」且不可被抽为引述；每句带时间码。
- V5（成功态）：AC5——在对话线程开启录音后线程卡片与线程头出现「● 转录中」，停止后消失。
- V6（成功态）：AC6——拒绝麦克风权限时不产生任何转写段，界面显式标出「未录制」；
  录制中关闭麦克风后转写流出现「录制已暂停」标记且不再增长。
- V7（安全态）：AC7——注入含邮箱与手机号的音频/文本，断言默认读接口返回遮盖串、
  逐字稿显示「查看原文需权限」；无权限账号请求原文被拒并写审计。
- V8（权限态）：逐一使用 引导师、组长、受访者、观察者、未授权用户访问；返回数据和可执行动作严格符合 R5。
  另断言：授权未完成的参与者（原型 P-12）**不产生任何录音与转写段**。
- V9（空态）：无目标数据时显示真实空态与下一步，不生成伪数据。
- V10（依赖失败）：模拟网络/外部依赖失败，输入和最近成功数据保留，错误可解释且可重试；
  断网后本地缓存并在恢复时补传，转写流上显式标出缺口而不是拼接成连续假象。
- V11（并发态）：两名用户修改同一资源时不静默覆盖，并可识别最终版本。
- V12（审计态）：关键动作可按操作者、时间、对象和结果检索；越权尝试也有安全审计记录。
- V13（安全态）：全链路检查不存在任何**跨场次**声纹比对接口或持久化声纹身份特征；
  说话人一律以匿名声道标识存储，真名仅来自 UC-5.2 的人工映射记录；
  本场内聚类特征在本场音频删除时一并销毁。
