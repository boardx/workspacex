# 原始需求（细化）— UC-5.3 标记引述与打点

> 所属：阶段一 · 能跑完一场项目 / M5 实时转录  
> 来源：`Backlog Use Case.html` 的 UC-5.3；UI 线索来自 `WorkspaceX Standalone.html`。  

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **5**（原 3；+2 = **AI 自动打点**及其人工确认闸门，见 R3 第 4–5 步）；建议迭代 **迭代 3 · 能采集**。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-5.3 / 标记引述与打点
- **Actor**：**引导师**、**组长**、**受访者**
- **目标**：[原型] 多路并行录音转文字，先出文字不猜说话人；结束后再指派身份。转写是访谈、画布、图谱的原料。
- **本用例结果**：[Backlog] 用户通过“标记引述与打点”完成从“现场听到关键一句”到可追踪业务结果的闭环。
- **系统边界**：多路音频采集、实时转写、说话人指派、时间码、引述与留存。
- **核心数据对象**：录音轨、转写段、说话人、时间码、引述、打点、留存策略。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“登录管理（授权与可见性）”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] 现场听到关键一句。
  - 系统从 **实时转录** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **引导师 / 研究员操作**：选中文字标为引述，或点 **`[标记此刻]`**。
   [原型] 逐字稿行内操作条共五个：`[标为引述] [标痛点] [标机会] [修正发言人] [加研究笔记]`；
   访谈实时转录区另有 `[标记此刻]` 与 `[选中标为引述]`。
   **系统响应**：校验当前身份、项目范围、必填数据与资源版本；成功后更新界面和业务记录，并保留可追溯来源。
2. **引导师操作**：引述进证据库，带时间码与来源。**系统响应**：校验当前身份、项目范围、必填数据与资源版本；成功后更新界面和业务记录，并保留可追溯来源。
3. **引导师操作**：可直接挂到某条假设或画布节点，**或挂到某个研究问题（RQ）**。
   [原型] 逐字稿上的引述行显示为「**已标为引述 · 支持 RQ2** ｜ P-10 个人经历」——
   即引述与 RQ 之间是**显式绑定关系**，且同时记录**证据性质**（个人经历 / 二手转述 / 观点）。
   该绑定是 UC-6.4 目标覆盖度与 UC-6.5 证据矩阵的输入。
   **系统响应**：校验当前身份、项目范围、必填数据与资源版本；成功后更新界面和业务记录，并保留可追溯来源。
4. **系统处理 —— [原型] AI 自动打点**：AI 在转写流中主动识别关键时刻并就地打点，
   原型原文：对话右栏转录里的一句标注「**（Ava 标记为决策点 `[看洞察]`）**」。
   规则：
   - **必须标识为机器产出**：打点上带 agent 角标与名字（如 `Ava`），与人工打点在视觉与数据上都可区分
     （`origin: ai | human`），**不得混入人工打点计数**。
   - **必须可追溯**：每个 AI 打点带触发依据与出口（原型的 `[看洞察]`），点开可看到它据以判断的原文片段。
   - **必须有人工确认闸门**：AI 打点默认落**候选态**，不直接进证据库、不直接进报告与决策链；
     经人确认后才转为正式打点并计入证据。对齐 D-27「AI 生成的卡一律落 inbox 草稿态」与
     UC-6.4「AI 不会因为听到关键词就替你标完成，勾选权在你」。
   - **拒绝也要留痕**：人工忽略/否决某个 AI 打点时记录该决定，供 agent 改进反馈（后台「消息级评价」链路）。
   **系统响应**：更新候选列表与角标计数，不改变任何已确认证据。
5. **引导师操作**：逐条**确认 / 编辑后确认 / 忽略** AI 打点。
   **系统响应**：确认后按第 2–3 步入库并补齐时间码、来源与 RQ 绑定；忽略后从候选列表移除但保留审计记录。
6. **系统收口**：校验 AC1“引述在报告里能一路追回原始音频位置”；满足后记录操作者、时间、对象、结果与来源，并刷新相关列表、图谱、看板或通知状态。
7. **系统收口**：校验 AC2“AI 打点在人工确认前不进证据库”；满足后记录操作者、时间、对象、结果与来源。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] 目标数据为空时展示空状态、原因和下一步入口，不生成示例数据冒充真实结果。系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
- **异常流程**：
  - E1：[Backlog] 未指派说话人的引述先入库，出处待补。（「出处待补」档案 0 命中；
    档案里未指派段的表述是 `发言人不确定 · 待人工指派`。）失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E4：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。
  - E5：[原型] **两类转写异常段落不可被标为引述**（见 UC-5.2）：
    `识别置信度低 · 待校对`、`发言人不确定 · 两人同时说话 · 待人工指派`。
    尝试标记时给出明确原因与「去校对」出口，**不得先入库再说**。
  - E6：[原型] **`正在识别` 的中间态文本不可被标为引述**；需等该句定稿。
  - E7：[设计] AI 打点的依据片段在事后被撤回（UC-6.3 五步撤回）或被校对改写时，
    对应的候选打点自动失效并从候选列表移除；已确认的打点按撤回流程标「证据已撤回」，**不静默删除**。

## R5 权限与可见性

- **引导师**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **组长**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **受访者**：可查看/确认自身授权并提出撤回；不能访问项目内部材料或其他受访者数据。
- **观察者**：默认不能发起或修改；仅当内容已发布且授权范围允许时只读查看脱敏结果。
- **项目经理**：可查看项目级状态与审计摘要；是否可代替业务 Actor 执行写操作需由角色模板显式授权。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 形成与本 use case 对应的正式记录或明确状态，并可从来源页面再次打开。
  - 所有跨模块回流均携带来源资源、版本、操作者/触发者、时间和可见范围。
  - [原型验收] AC1：引述在报告里能一路追回原始音频位置
    （[原型] 逐字稿「点时间码跳回音频」+ 报告来源角标「转写 00:33」两端都写实）。
  - [设计验收] **AC2（新增）**：**AI 自动打点带机器角标、落候选态，人工确认前不进证据库**、
    不进报告、不进决策链；确认与忽略均留痕。
  - [原型验收] **AC3（新增）**：引述可绑定到 RQ，逐字稿上显示「已标为引述 · 支持 RQ2」，
    该绑定被 UC-6.4 覆盖度与 UC-6.5 证据矩阵直接消费。
  - [原型验收] **AC4（新增）**：`正在识别`、`待校对`、`待人工指派` 三种状态的段落均无法被标为引述。
- **失败后置条件**：
  - 不创建“看似成功”的正式记录；可重试内容保留为草稿，失败事件进入可观测日志。
- **不包含**：
  - 完整离线录音工作站、未经授权的**跨场次**声纹身份库。
  - **AI 自主入库**：AI 不得在无人确认的情况下把任何打点或引述写进证据库、报告或决策链。
  - 不扩展到本 use case 未声明的跨组织、跨客户或公开发布能力。

## R7 业务规则（不随具体实现变化的硬性约束）

- [原型] 未指派说话人的引述先入库，出处待补。
- **[原型] AI 打点是候选，不是结论**：AI 可主动标「决策点」等打点，但必须
  ① 带机器角标与可追溯依据；② 默认候选态；③ 经人确认才入证据库。
  与 UC-6.4 的「AI 不会因为听到关键词就替你标完成，勾选权在你」同源，是同一条硬约束的两处落地。
- [原型] **引述与 RQ 显式绑定**，并记录证据性质（个人经历 / 二手转述 / 观点）。
- [原型] **不确定的文本不可成为证据**：`正在识别`、`识别置信度低 · 待校对`、
  `两人同时说话 · 待人工指派` 三态段落一律不可被标为引述。
- AC1：引述在报告里能一路追回原始音频位置。
- AC2：AI 打点在人工确认前不进证据库。

- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

- **前端入口**：[原型] 项目工作台右侧转录栏；对话线程右栏 `转录` 标签；

- **打点与引述的入口（[原型]，逐条对齐原型措辞）**：
  - 实时转录区顶部：`[标记此刻]`；底部：`[选中标为引述]`、`[结束后指派说话人]`。
  - 下栏实时逐字稿行内操作条：`[标为引述] [标痛点] [标机会] [修正发言人] [加研究笔记]`，
    并提示「点时间码跳回音频 · 选中可标为引述」，配 `[搜索]`。
  - 已标记的行就地变为「**已标为引述 · 支持 RQ2** ｜ P-10 个人经历」。
- **AI 自动打点的呈现（[原型]）**：转录行内追加「**（Ava 标记为决策点 `[看洞察]`）**」。
  - 角标必须带 agent 名字，与人工打点视觉可分；
  - `[看洞察]` 是**依据出口**，点开显示 AI 据以判断的原文片段与理由；
  - 候选态需有明显的「未确认」外观，并提供 `[确认] [编辑后确认] [忽略]` 三个出口

- **推荐交互**：

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R10 已知约束 / 依赖

- **内部依赖**：[原型] 登录管理（授权与可见性）。
- **跨模块契约**：身份与权限、来源引用、版本、任务状态、审计事件和通知必须使用统一标识，避免同一对象在各模块成为不可关联的副本。
- **技术约束**：[原型] 产品为响应式网页；完整离线模式、原生移动端、第三方 IM 与产品内自助计费在 backlog 中明确为范围外。
- **[待确认]** 单项目并发人数、组织数、材料量、音频时长和历史数据量尚未给出；容量与压测指标需在开发前定稿。
- **[待确认]** 通知渠道、消息模板、语言与时区策略未统一定义；本文仅承接原型明确写出的产品内/邮件行为。
- **[待确认]** 数据驻留地区、加密密钥策略、法定留存和删除证明格式需由合规负责人确认。

## R11 切分提示（给 requirement-author）

- 建议先拆“领域数据与权限 → 主流程服务 → 页面与状态 → 跨模块回流 → 审计/通知 → 自动化验收”。
- 单个 feature 应能在一次会话内实现并验证，不应把本 use case 的全部前后端与所有异常态塞进一个 feature。
- 建议把「人工打点与引述入库」「引述↔RQ 绑定」「**AI 自动打点与确认闸门**」切成三个 feature；
  第三个必须先有前两个的证据模型，否则 AI 候选无处落地。
- **优先级 / 先后依赖**：P0；**5 点**；迭代 3 · 能采集；先满足“登录管理（授权与可见性）”与 UC-5.1。
- 对 P0 必做链路优先实现成功态、权限态与数据闭环，异常态不得延期到上线后。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态）：AC1：引述在报告里能一路追回原始音频位置。
- V2（成功态）：AC2——构造一条 AI 打点，断言：① 返回体带 `origin: ai` 与 agent 名；
  ② 未确认时查询证据库**取不到**它、报告与决策链引用它被拒绝；③ 人工确认后才可被引用；
  ④ 忽略动作在审计中可检索。
- V3（成功态）：AC3——把一条引述绑到 RQ2，断言 UC-6.4 的覆盖度视图与 UC-6.5 的证据矩阵同步反映该绑定。
- V4（校验失败态）：AC4——对 `正在识别` / `待校对` / `待人工指派` 三种段落调用标为引述接口均被拒绝，
  且返回可读原因与「去校对」出口。
- V5（权限态）：逐一使用 引导师、组长、受访者、观察者、未授权用户访问；返回数据和可执行动作严格符合 R5。
- V6（空态）：无目标数据时显示真实空态与下一步，不生成伪数据。
- V7（依赖失败）：模拟网络/外部依赖失败，输入和最近成功数据保留，错误可解释且可重试。
