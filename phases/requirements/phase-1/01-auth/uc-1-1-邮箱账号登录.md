# 原始需求（细化）— UC-1.1 邮箱账号登录

> 所属：阶段一 · 能跑完一场项目 / M1 登录管理  
> 来源：`Backlog Use Case.html` 的 UC-1.1；UI 线索来自 `WorkspaceX Standalone.html` 登录页
> （`proto-04` 场景视图·登录：工作邮箱 ｜ 密码 `[显示]` `[忘记密码？]` `[登录]`）。  

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **5**（原 3；+2 为密码认证与「忘记密码」找回流程，
> 已抵扣移出的社交登录与 SSO）；建议迭代 **迭代 1 · 能进场**。
>
> **[人类已拍板 2026-07-27]**
> - **D-0.3**：认证方式为**邮箱 + 密码**，注册时做**邮箱验证链接**；**不做验证码（OTP）**。
>   密码须有「忘记密码」找回流程。
> - **D-02**：phase-1 **只做邮箱 + 密码**；**社交登录（Google / 飞书）与企业 SSO 移出 phase-1**
>   （原型上这三个按钮标记为 later）。原 AC1「同一人用两种方式登录进的是同一个账号」
>   **随之失效**，已改写为密码登录相关的可验收断言。
> - **UC-0.3**：角色采用**两层正交模型**（组织角色 × 项目角色）。原文档的「项目经理」
>   ＝ **组织角色「项目负责人」**，不是项目角色。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-1.1 / 邮箱账号登录
- **Actor**：**组织成员**（组织角色为管理员 / 项目负责人 / 顾问三者之一）
- **目标**：[原型] 正式成员用**工作邮箱 + 密码**进入产品；现场组员走 UC-1.2 的免注册进场，不在本用例。
  登录后的身份决定他在项目里能看到什么（判定规则见 UC-1.4 与 UC-0.3）。
- **本用例结果**：[原型] 用户以邮箱 + 密码完成认证，获得有效会话，落到「全部项目」列表，
  只显示他有权访问的项目；全过程可审计。
- **系统边界**：密码认证、会话与设备管理、忘记密码找回、组织停用降级、权限网关入口。
- **核心数据对象**：账号、密码凭据、组织成员、会话、设备会话、密码重置令牌。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户可访问登录或加入入口；需要登录后执行的管理动作必须已有有效身份与对应项目权限。
  - 本模块无前置业务模块；认证入口、链接存储和权限网关自身必须可用。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] 正式成员打开产品，未登录。
  - 系统从 **登录页** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **用户操作**：[原型] 在登录页填写**工作邮箱**与**密码**（密码框带 `[显示]` 切换）并点 `[登录]`。
   **系统响应**：服务端校验邮箱是否存在、密码哈希是否匹配、邮箱是否已验证、账号与组织是否处于可用状态；
   任一不通过按 E1/E2/E3 处理，且**失败提示不区分「邮箱不存在」与「密码错误」**（防枚举）。
2. **系统处理**：认证通过后建立会话。[Backlog] 会话有效期 **30 天**；记录设备指纹与登录地点，
   写入设备会话列表，供「设置 → 设备」踢下线。
   **来源说明**：这三项（30 天、设备指纹、踢下线）**全部出自 `Backlog Use Case.html`**。
   原型登录页只有邮箱 / 密码 / `[显示]` / `[忘记密码？]` / `[登录]` 五个元素，
   「踢」「设备会话」在 proto-01~10 中**零命中**——**原型确认缺失**（见 R8 sign-off）。
   30 天这个具体数字**不得当作原型证据实现**。
3. **用户操作**：[设计] 首次登录（或资料不完整时）补全姓名；所属组织在注册时已确定
   （UC-1.5 创建组织 / UC-1.6 受邀加入），**登录环节不再让用户自选组织**。
4. **用户操作**：[原型] 落到「全部项目」列表，只显示他有权访问的项目
   （可见范围由 UC-0.3 两层交集判定，不在本用例实现）。
5. **系统收口**：校验 AC1「邮箱 + 密码是 phase-1 唯一的正式成员认证路径——
   密码正确即进入本人账号；社交登录与 SSO 入口在 phase-1 不可用」；
   记录操作者、时间、结果与来源进审计。
6. **系统收口**：校验 AC2「登录态 30 天有效，可在设置里踢掉其它设备」（[Backlog]，非原型证据）；
   刷新设备会话列表与最近登录记录。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] **组织被停用时登录成功但只读**——会话正常建立，所有写操作被服务端拒绝，
    界面顶部常驻「组织已停用 · 只读」说明条。
    **来源说明**：「停用」在 proto-01~10 中**零命中**，`Backlog Use Case.html` 中**也没有**——
    这一整条是本文凭空反推的设计，含那句说明条文案，**需人类确认后才可实现**。系统不得丢失当前上下文，且需提示用户当前走的是哪条替代路径。
  - A2：[原型] **忘记密码找回**——用户点登录页的 `[忘记密码？]`：
    1) 输入工作邮箱 → 2) 系统**无论邮箱是否存在都返回相同的「若该邮箱已注册，重置邮件已发出」**
    （防枚举） → 3) 已注册邮箱收到**一次性重置链接**（[设计] 有效期 1 小时，一次性使用）→
    4) 用户设新密码，密码强度按策略校验 → 5) 重置成功后**吊销该账号全部既有会话**并要求重新登录，
    同时向该邮箱发出「密码已修改」通知。全流程写审计。
    [待确认] 重置链接有效期与是否强制通知，需与 UC-1.5 的邮箱验证链接策略统一定稿。
  - A3：[设计] 用户已注册但**邮箱未验证**时，不建立会话，改为提示并提供「重发验证邮件」入口
    （承接 UC-1.5 R7「邮箱未验证的账号不可登录」）。
  - A4：[设计] 用户账号已存在但**尚无组织归属**（UC-1.5 A3）时，登录成功但强制落到「创建组织」步骤。
- **异常流程**：
  - E1：[设计] **密码错误**：统一提示「邮箱或密码不正确」，不区分原因；
    连续失败达阈值后对该账号/IP 限速，再超阈值临时锁定并邮件告知本人。
    [待确认] 失败阈值、锁定时长与解锁路径。
  - E2：[设计] **账号被停用 / 已从组织移除**：明确拒绝并说明联系管理员，不建立会话。
  - E3：[设计] 请求超时、网络中断或依赖（邮件服务、认证服务）不可用时，保留用户当前输入与最后成功数据，
    明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E4：[设计] 密码重置链接过期或已使用时，提示重新申请，不泄露账号是否存在。
  - E5：[设计] 权限在操作过程中被撤回、或会话被其它设备踢下线时，立即终止后续写操作；
    已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新登录。
  - E6：[设计] 同一账号在多设备并发登录不冲突；但密码修改或主动踢设备后，
    被吊销的会话下一次请求即失效（不等 30 天自然过期）。

## R5 权限与可见性

> 按 **UC-0.3 两层正交模型**重写：**组织角色**（管理员 / 项目负责人 / 顾问 + 团队归属）
> 决定「能用什么资源」；**项目角色**（引导师 / 组长 / 组员 / 观察者）决定「在某场项目里能看什么、做什么」。
> 本用例只产生**组织身份与会话**，不授予任何项目角色。

### 组织角色（[原型]，本用例的登录主体）

| 组织角色 | 登录后可见 / 可做 |
|---|---|
| **管理员** | 登录后可进后台（Agent / Skill / 模型 / MCP / 画布模板 / 项目蓝本 / 成员与配额 / 反馈）。**登录本身不授予任何项目内容读取权**（UC-0.3 R7「管理员不是超级用户」） |
| **项目负责人** | 登录后落到「全部项目」，只显示其有权访问的项目；可创建与管理项目 |
| **顾问** | 登录后落到「全部项目」，只显示其被授予项目角色的项目；不进后台 |

- **团队归属**（[原型] 能源组 / 平台组 / 供应链组）随会话一并解析，
  用于「全组织可用 / 仅某团队」的资源过滤（判定在 UC-0.3，本用例只保证会话里带上这两层身份）。
- **项目角色**：本用例**不涉及**。免注册的现场组员/组长走 UC-1.2，项目角色由链接授予。
- **未登录、邮箱未验证、账号或组织被停用**：默认无权限；
  接口不得返回越权数据，不能只依赖前端隐藏。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 会话建立，且会话上下文中同时携带**组织 ID、组织角色、团队归属**三项，供 UC-0.3 判定使用。
  - 登录、登出、密码重置、踢设备四类事件均已写审计。
  - [设计验收] **AC1（改写自原 AC1）**：phase-1 的正式成员认证**只有邮箱 + 密码一条路径**——
    密码正确即进入本人账号；登录页的社交登录与 SSO 入口在 phase-1 **不可用**（标记为 later），
    且不存在任何绕过密码建立会话的接口。
  - [Backlog验收] AC2：登录态 30 天有效，可在设置里踢掉其它设备。
    （**AC 内容来自 Backlog，不是原型**；对应的设备会话列表在原型中是**原型确认缺失**。）
  - [设计验收] **AC3**：忘记密码可端到端走通——重置成功后旧密码失效、
    该账号全部既有会话被吊销、用户须用新密码重新登录。
- **失败后置条件**：
  - 不创建“看似成功”的会话；可重试内容保留为草稿，失败事件进入可观测日志。
- **不包含**：
  - **社交账号登录（Google / 飞书）**——[人类已拍板 D-02] 移出 phase-1，原型按钮标记为 later。
  - **企业 SSO**——同上，移出 phase-1。
  - 邮箱验证码（OTP）登录——[人类已拍板 D-0.3] 不做。
  - 注册与组织创建（见 UC-1.5）、组织成员邀请与激活（见 UC-1.6）。
  - 计费账号、原生移动端登录。
  - 不扩展到本 use case 未声明的跨组织、跨客户或公开发布能力。

## R7 业务规则（不随具体实现变化的硬性约束）

- [人类已拍板] **认证方式为邮箱 + 密码**；phase-1 **不提供**社交登录、企业 SSO 与邮箱验证码登录。
- [人类已拍板] **邮箱验证在注册环节完成**（UC-1.5 / UC-1.6 的验证链接）；
  **邮箱未验证的账号不可登录**。
- [设计] **必须有忘记密码找回流程**：邮箱 → 一次性重置链接 → 设新密码 → 吊销全部既有会话。
- [设计] **防枚举**：登录失败不区分「邮箱不存在」与「密码错误」；
  找回密码无论邮箱是否注册都返回同一文案与同一响应时间量级。
- [设计] 密码必须**加盐哈希**存储，永不明文记录、回显或写日志；传输强制 HTTPS。
- [设计] **组织被停用时登录成功但只读**——不阻断登录，阻断写操作。（原型与 Backlog 均无此条。）
- [Backlog] **登录态 30 天有效**，可在设置里踢掉其它设备；被踢会话下一次请求即失效。
  （出自 `Backlog Use Case.html`；原型无设备会话概念。**30 天是 Backlog 数字，不是实测值**。）
- [设计] 会话必须携带组织 ID、组织角色、团队归属；**登录不授予任何项目角色**。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 登录成功、登录失败、密码重置、会话吊销、组织停用降级都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R10 已知约束 / 依赖

- **内部依赖**：**UC-1.5**（创建组织与首个管理员账号）、**UC-1.6**（组织成员邀请与激活）——
  没有它们就没有可登录的账号；**UC-0.3**（两层角色模型）提供会话里要带的身份字段。
- **被依赖**：所有需要正式成员身份的模块。
- **跨模块契约**：账号、组织、组织成员、角色、团队必须使用统一标识；
  会话上下文必须能被 UC-0.3 的鉴权中间件直接消费。
- **技术约束**：[原型] 产品为响应式网页；完整离线模式、原生移动端、第三方 IM 与产品内自助计费为范围外。
- **[待确认]** **密码强度策略**（长度、字符类、是否查弱口令库、是否强制定期更换）与
  **是否提供二次验证（MFA）**——与 UC-1.5 R9 的同一条待确认项合并定稿。
- **[待确认]** 登录失败阈值、限速窗口、账号锁定时长与解锁路径。
- **[待确认]** 密码重置链接有效期（暂定 1 小时）与「密码已修改」通知是否强制。
- **[待确认]** 社交登录与企业 SSO 的**回归时点**（phase-2 还是 phase-3），
  以及回归时是否按邮箱合并到已有账号——原 E2「社交账号邮箱已存在时合并到同一账号」
  的规则**移交给该阶段**，phase-1 不实现但不作废。
- **[待确认]** 通知渠道、消息模板、语言与时区策略未统一定义。
- **[待确认]** 数据驻留地区、加密密钥策略、法定留存和删除证明格式需由合规负责人确认。

## R11 切分提示（给 requirement-author）

- 建议先拆「密码凭据模型与哈希 → 登录接口与防枚举/限速 → 会话与 30 天有效期 →
  设备会话列表与踢下线 → 忘记密码找回四步 → 组织停用只读降级 → 审计 → 自动化验收」。
- **「忘记密码找回」必须独立成 feature**，并带「重置后旧会话全部失效」的独立验收——
  它是 D-0.3 认证改口径后新增的必做链路，不是可选项。
- **防枚举（登录失败与找回密码的统一响应）** 建议单独成 feature，用接口断言验收。
- **优先级 / 先后依赖**：P0；**5 点**；迭代 1 · 能进场；**必须晚于 UC-1.5**（先有账号才能登录），
  **早于所有需要正式成员身份的 feature**。
- 对 P0 必做链路优先实现成功态、权限态与数据闭环，异常态不得延期到上线后。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态）：**AC1** —— 用正确的邮箱 + 密码登录成功并返回会话；
  接口层不存在任何社交登录 / SSO 的可用端点（phase-1 请求这些端点返回「未启用」）。
- V2（成功态）：**AC2** —— 会话有效期为 30 天；在设置里踢掉另一设备后，
  该设备的下一次请求即被拒绝（不等自然过期）。
- V3（成功态）：**AC3** —— 走完忘记密码全流程后，旧密码登录失败、新密码登录成功、
  重置前建立的全部会话均失效。
- V4（安全态）：登录时「邮箱不存在」与「密码错误」返回**完全相同**的状态码与文案；
  找回密码时「邮箱已注册」与「未注册」返回完全相同的响应。
- V5（安全态）：连续失败达阈值后触发限速/锁定；密码在任何日志、响应体与数据库中都不以明文出现。
- V6（权限态）：登录后的会话携带组织 ID、组织角色、团队三项；
  以**管理员**身份登录后访问其无项目角色的项目内容，被拒绝（承接 UC-0.3 AC1）。
- V7（空态）：新账号无任何项目时，「全部项目」显示真实空态与下一步，不生成伪数据。
- V8（依赖失败）：模拟邮件服务不可用，忘记密码流程明确失败并保留输入，不产生"看似已发送"的假成功。
- V9（降级态）：组织被停用后，该组织成员仍能登录，但所有写接口一律拒绝且界面显示只读说明条。
- V10（审计态）：登录成功、登录失败、密码重置、会话吊销四类事件均可按操作者、时间、结果检索；
  越权与枚举尝试也有安全审计记录。
