## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-1.3 / 生成与撤销邀请链接
- **Actor**：**引导师**（生成、分发、撤销）；**项目负责人**（组织角色，可查看）；
  **免注册参与者**（链接的使用者，其进场流程在 UC-1.2）
- **目标**：[原型] 让引导师把人**按身份请进这场项目**——
  「打开即带身份进场，**不需要提前注册**」「每组一条加入链接，打开即进」；
  并能在链接外泄或换人时**单独撤销**或**一次重置全部**。
- **本用例结果**：[原型] 项目拥有一份**参与者名单**（含身份、组别与确认状态）、
  一条可配身份与有效期的**主链接**（含邀请码与二维码）、以及**每组一条分组链接**；
  引导师可按组查看到场状态与全场计数；撤销后新访问即刻失效。
- **系统边界**：参与者名单与邀请（邮箱/手机号）、身份指派、链接与令牌的生成与有效期、
  分发（复制 / 二维码 / 邀请码 / 群发）、撤销与全部重置、使用记录、签到名单与到场状态。
- **核心数据对象**：参与者名单条目、邀请链接（主链接 / 分组链接）、邀请码、一次性令牌、
  小组、项目角色、确认状态与到场状态、链接使用记录。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户可访问登录或加入入口；需要登录后执行的管理动作必须已有有效身份与对应项目权限。
  - 本模块无前置业务模块；认证入口、链接存储和权限网关自身必须可用。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] 引导师在 **项目 → 设置 → 参与者与邀请**（管理面）；
    或在 **现场协作 → 分组与签到**（现场面）临时复制某组链接。
  - 系统进入本流程时携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **引导师操作**：[原型] 在「参与者与邀请」用输入框**按邮箱或手机号邀请**
   （占位文案「**邮箱或手机号，逗号分隔**」，支持批量），并为这批人**选一个身份**。
   [原型] **身份四选：组员 / 组长 / 观察者（只读）/ 协同引导师**。
   **系统响应**：校验当前身份与项目权限、解析并去重收件人、写入参与者名单为「邀请已发」，
   发出邀请；名单顶部计数刷新（[原型]「参与者 **9 / 12 已确认**」）。
2. **引导师操作**：[原型] 配置**主链接** `wsx.app/w/kickoff-8f21?r=member`——
   选**进场身份**（同上四选）与**有效期三档：24 小时 / 7 天 / 一次性**，
   再 `[复制]` 或出 `[二维码]`。
   **系统响应**：按身份与有效期签发令牌，链接与二维码即时可用；配置变更即时生效。
3. **引导师操作**：[原型] 分发——`[群发邀请]`（按参与者名单批量发出）；
   或直接给出**邀请码 `KCK-8F21-EU24`** 供口头/投屏传达。
   **系统响应**：逐条记录送达结果；失败项可单独重试，**不得静默成功**。
4. **引导师操作**：[原型] 使用**分组链接**——每组一条，打开直接进本组工作台：
   `wsx.app/w/kickoff-8f21/g/1` `[复制]`（第 2–4 组同构）。
   **系统响应**：链接携带**项目 + 组号 + 角色**三元组，由 UC-1.2 解析。
5. **引导师操作**：[原型] 撤销——**链接可单独撤销**；或 `[重置全部]` 一次性作废全部链接。
   （原型硬规则原文只有一句「链接可单独撤销」，`[重置全部]` 是屏上按钮。）
   **系统响应**：二次确认后立即作废对应令牌；[设计] **已在场者不被踢出**，仅新访问失效（见 E1）。
   **来源说明**：「已在场者不被踢出」**原型从未说过**，Backlog 也无此句，是本文反推的设计。
6. **系统处理**：[原型] 参与者进场后，名单状态由「邀请已发」变为「**已确认**」，
   并在现场面的「分组与签到」显示到场状态与计数。
7. **系统收口**：校验 AC1「每组一条链接，打开直接进对应组」；
   记录操作者、时间、对象、结果与来源，并刷新名单与到场计数。
8. **系统收口**：校验 AC2「撤销后 5 秒内新访问失效」（[Backlog]——**5 秒这个时限出自
   `Backlog Use Case.html`**，原型只有「链接可单独撤销」一句、**无任何时限**）；同上记录并刷新。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] **未接受的邀请可重发**——名单上显示「陈默 · **邀请已发 2 天**」并给 `[重发]`
    （与后台成员邀请的「待接受邀请 · 已发送 2 天 · `[重发]`」同构，见 UC-1.6）。
  - A2：[原型] **两条分发路径并存**：按名单定向邀请（邮箱/手机号）与开放式主链接/邀请码。
    同一人两条路径都到达时不产生重复名单条目，以手机号/邮箱去重。
  - A3：[原型] **观察者链接**：进场身份选「观察者（只读）」时，
    链接携带只读角色，**只读已发布内容**（见 R7）。
  - A4：[设计] 名单为空或尚未分组时展示真实空态、原因和下一步入口，
    不生成示例数据冒充真实结果。
- **异常流程**：
  - E1：[设计] **撤销后已在场的人不被踢出，但重开链接失效**。
    （原型只写「链接可单独撤销」，**没有对已在场会话作任何表述**；本条是反推，需人类确认。）
  - E2：[设计] **一次性链接被用过即失效并记录使用者**——
    「用过即失效」有原型依据（有效期三档含「一次性」）；
    **「记录使用者」在原型中不存在（原型确认缺失，非未探明）**，故标 **[设计]**，
    需人类确认呈现位置并补画。
  - E3：[设计] 邮箱/手机号格式非法或含重复项时，逐条标出问题项并允许改正后重提，
    不整批失败也不静默丢弃。
  - E4：[设计] 群发时部分收件人送达失败——明确列出失败项与原因并支持单条重试；
    **不得把部分失败呈现为整批成功**。
  - E5：[设计] 请求超时、网络中断或依赖（短信/邮件）不可用时，保留用户当前输入与最后成功数据，
    明确失败原因，并提供安全重试。
  - E6：[设计] 两名引导师并发修改同一条链接配置或同时 `[重置全部]` 时不得静默覆盖；
    提示版本已变化并允许刷新、对比或重新提交，最终状态唯一且可识别。
  - E7：[设计] 权限在操作过程中被撤回时立即终止后续写操作；
    已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

> 按 **UC-0.3 两层正交模型**重写。

| 层 / 角色 | 在本用例中的权限 |
|---|---|
| **项目角色 · 引导师** | 邀请、身份四选、配主链接与有效期、复制、二维码、邀请码、群发、单条撤销、`[重置全部]`、`[重发]`；查看签到名单与全场到场计数 |
| **项目角色 · 协同引导师** | **[待确认]**——见下方专条；在裁决前**不得默认按等同引导师实现** |
| **项目角色 · 组长** | [设计] 可查看**本组**的加入链接与本组到场状态；**不可**撤销或重置，不可见别组链接 |
| **项目角色 · 组员** | 不可见任何链接管理入口；只作为链接的使用者（UC-1.2） |
| **项目角色 · 观察者** | **只读**：不可见邀请链接、令牌与参与者手机号；到场信息至多以**脱敏聚合**形式（如「11/12 已到」）呈现 |
| **组织角色 · 项目负责人** | 在其负责的项目中可查看链接与签到状态；是否可撤销 [待确认] |
| **组织角色 · 管理员** | **不因管理员身份获得链接读取权**（UC-0.3 R7 / D-18）；审计目的访问须留痕且对项目负责人可见 |

> **[待确认] 「协同引导师」的角色学归属**
> [原型] 本屏的**身份四选**是：组员 / 组长 / 观察者（只读）/ **协同引导师**，
> 而 `uc-0-3` 的项目角色只有四个：引导师 / 组长 / 组员 / 观察者——**两套不完全重合**。
> 须人类裁决：协同引导师是**第五个独立项目角色**（有独立权限行），
> 还是**「引导师」角色的一个实例**（一场可有多名引导师，权限相同）？
> ⚠ 这直接决定 **RBAC 表是四行还是五行**，也决定本表和 UC-1.4 的四视角表要不要扩成五行。
> **裁决前实现者不得自行选择**。同一条同步记在 UC-1.4 R5 / R10。

- **未登录、链接失效或未列出的角色**：默认无权限；
  接口不得返回越权数据（尤其是**令牌明文与参与者手机号**），不能只依赖前端隐藏。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 形成与本 use case 对应的正式记录或明确状态，并可从来源页面再次打开。
  - 所有跨模块回流均携带来源资源、版本、操作者/触发者、时间和可见范围。
  - [原型验收] **AC1**：每组一条链接，打开直接进对应组。
  - [Backlog验收] **AC2**：撤销后 5 秒内新访问失效。
    （**5 秒来自 Backlog，原型无时限**；撤销动作本身有原型依据，时限没有。）
  - [原型验收] **AC3**：**有效期三档**（24 小时 / 7 天 / 一次性）各自生效。
  - [原型验收] **AC4**：**进场身份四选**（组员 / 组长 / 观察者 / 协同引导师）
    分别产出携带对应角色的链接；**观察者链接只读已发布内容**。
  - [原型验收] **AC5**：`[重置全部]` 一次作废全部链接；单条撤销只作废该条，不波及其它。
  - [原型验收] **AC6**：名单计数（「9 / 12 已确认」）随邀请与进场实时刷新；
    未接受的邀请显示已发送天数并可 `[重发]`。
- **失败后置条件**：
  - 不创建“看似成功”的正式记录；部分失败不得呈现为整批成功；
    可重试内容保留为草稿，失败事件进入可观测日志。
- **不包含**：
  - 组织级的成员邀请与激活（那是后台「成员与配额」，见 **UC-1.6**）——
    本用例只管**项目内**的参与者与链接。
  - 免注册参与者的**进场流程本身**（手机号验证、名单核对、落进小组工作台）——见 **UC-1.2**。
  - 企业 SSO、社交登录、计费账号、原生移动端登录。
  - 不扩展到本 use case 未声明的跨组织、跨客户或公开发布能力。

  > ⚠ **不再列为「不包含」**：有效期三档、二维码、群发、单条撤销、全部重置、邀请码、
  > 分组链接——这六项**原型已完整存在**（见 R8 载体一），属本用例范围内的必做项。

## R7 业务规则（不随具体实现变化的硬性约束）

- [原型] **每组一条加入链接**，「打开即进，**不需要提前注册**」；链接携带**项目 + 组号 + 角色**。
- [原型] **进场身份四选**：组员 / 组长 / **观察者（只读）** / **协同引导师**
  （协同引导师的角色学归属 [待确认]，见 R5）。
- [原型] **有效期三档**：**24 小时 / 7 天 / 一次性**。
- [原型] **链接可单独撤销**；另有 `[重置全部]` 一次作废全部。
- [设计] **撤销后已在场的人不被踢出，但重开链接失效**——原型只有「链接可单独撤销」，
  对已在场会话的处置**未作任何表述**；本条为反推，需人类确认（并与 R10 的会话保留时长一并定）。
- [原型] **观察者链接只读已发布内容**——与 UC-1.4 四视角的观察者权限一致；
  只读约束必须落在**服务端的角色判定**上，不得为链接单做一套过滤。
- [原型] **邀请码**与链接并存（`KCK-8F21-EU24`），是同一授权的另一种载体，
  受同一套身份与有效期约束。
- [设计] **一次性链接被用过即失效并记录使用者**——「用过即失效」有原型依据（有效期三档含「一次性」）；
  **「记录使用者」在原型中确认缺失**，呈现位置 [待确认]。
- [设计] **群发不得静默部分失败**：逐条记录送达结果，失败项可单独重试。
- [设计] **令牌明文与参与者手机号不得出现在无权角色的响应体中**（对照 UC-1.2 的掩码规则）。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 生成、群发、重发、撤销、重置全部、一次性链接被使用，都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态）：**AC1** —— 每组一条链接；用第 3 组的链接进场，落地在第 3 组
  （名单内本人属第 3 组时）；四条链接互不串组。
- V2（成功态）：**AC2**（[Backlog] 口径，5 秒非原型数字）—— 撤销某条链接后，
  **5 秒内**用该链接发起的新访问被拒绝。
- V3（成功态）：**分组与签到屏** —— 屏上同时可见：每组的加入链接 + `[复制]` + `[二维码]`、
  按组的签到名单、到场状态（组长/已到/未到）、每组 n/m、全场计数、`[看加入页]`。
  某人进场后，其状态由「未到」变「已到」，本组 n/m 与全场计数同步 +1。
- V4（成功态）：一次性链接被使用后立即失效，且**使用记录中可查到使用者与使用时间**
  （呈现位置 [待确认]，但**记录本身必须存在且可检索**）。
- V5（成功态）：**有效期三档**（24 小时 / 7 天 / 一次性）分别生效——
  超过有效期的链接被拒绝，且提示为「找引导师重发」而非报错页。
- V5b（成功态）：**身份四选** —— 分别以组员 / 组长 / 观察者 / 协同引导师
  （第四项待裁决后补）签发主链接，进场后的项目角色与所选身份严格一致；
  **观察者链接进场后只能读到已发布内容**，与 UC-1.4 观察者视角的可见面**逐项相同**。
- V5c（成功态）：**参与者名单** —— 用「邮箱或手机号，逗号分隔」批量邀请后，
  名单新增对应条目且状态为「邀请已发」并显示天数；`[重发]` 可再次发出；
  进场后状态变「已确认」，顶部计数（如 9 / 12）同步刷新。
- V5d（成功态）：**邀请码** `KCK-8F21-EU24` 与主链接等效——
  用邀请码进场得到的身份与有效期约束与链接完全一致。
- V6（权限态）：逐一使用 **引导师 / 组长 / 组员 / 观察者 / 项目负责人 / 管理员（无项目角色）/
  未授权用户** 访问链接管理接口；返回数据与可执行动作严格符合 R5，
  且**令牌明文与参与者手机号从不出现在观察者与组员的响应体中**。
- V7（撤销语义）：**单条撤销**只作废该条链接，其余链接仍可用；
  `[重置全部]` 一次作废全部。两种情况下**已在场者都不被踢出**（[设计] 口径，原型未表述，
  待 R10 裁决后可能翻转），其现有会话继续可用；仅新访问失效。
- V8（空态）：尚未分组或名单为空时显示真实空态与下一步入口，不生成伪数据。
- V9（依赖失败）：模拟网络/外部依赖（短信、二维码服务）失败，输入和最近成功数据保留，
  错误可解释且可重试；不产生"看似已群发"的假成功。
- V10（并发态）：两名引导师同时重置全部链接时不静默覆盖，最终状态唯一且可识别。
- V11（审计态）：生成、群发、撤销、全部重置、一次性链接被使用五类事件
  均可按操作者、时间、对象和结果检索；用已撤销令牌的访问尝试也有安全审计记录。
