# 原始需求（细化）— UC-0.1 把 Studio 产出保存回项目（Artifact 与三模式绑定）

> 所属：阶段零 · 共享内核 / M0 跨工具协议
> 来源：`WorkspaceX Standalone.html` 说明页「最新一轮：Workshop 变编排器，Studio 独立成台」章节；
> 四个 Studio（研究/访谈/问卷/原型）底部统一的「产出留在本项目；需要时再挂到某个项目环节」
> ＋ `[挂到项目环节…]` `[保存]`；画布屏同步三态；任务看板「验收后才会成为可被决策引用的证据」；
> 大脑「决策绑定的是当时的快照」「旧版仍被引用是正常的」。
> **原型说明页把本协议的定义指向「UML 文档第 13 节」，该文档不在仓库中**——本文是依据上述
> 原型证据链反推的设计稿，需人类确认后才可作为权威。

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **13**；建议迭代 **阶段零 · 共享内核**。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-0.1 / 把 Studio 产出保存回项目
- **Actor**：**引导师**、**项目经理**、**研究员**、**组长**
- **目标**：[原型] 专业工作发生在四个 Studio 里，成果必须能回流到项目，并且**回流方式决定了这份成果
  能被拿来干什么**——是随手草稿、是随源变动的活引用、还是可以拿去签字的定版。
- **本用例结果**：[设计] 用户在 Studio 完成一段工作后，选择三种保存模式之一把产出挂到项目（或某个
  项目环节），项目侧的「已回流的产出与版本」立即反映该选择，且产出的可引用资格由模式唯一决定。
  **来源说明**：三模式（草稿 / 实时关联 / 固定快照）与「已回流的产出与版本」两个词组**只出现在说明页
  的一段文字里**；运行态 Studio 底部实测只有 `[挂到项目环节…]` `[保存]` 两个按钮，**无模式选择器、
  无项目侧列表屏**。「立即反映」「可引用资格由模式唯一决定」是本文反推的设计，
  **原型待补**（按钮在，点击后的选择流程未接线）——与 R8 sign-off 一致。
- **系统边界**：Artifact 对象与版本、三模式绑定、项目环节挂载、引用资格判定、快照不可变存储。
- **核心数据对象**：Artifact、Artifact 版本、固定快照、绑定关系（模式 + 项目 + 环节）、引用记录、
  回流事件。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户在四个 Studio（研究 / 访谈 / 问卷 / 原型）之一中已产生可保存的内容。
  - [原型] Studio 可**独立发起、不依赖项目**（范围切换器「本项目 ｜ 不属于任何项目」），
    因此保存动作在无项目归属时同样必须可用。
  - 若要绑定到某个项目环节，用户需对该项目该环节有写权限。
- **触发条件**：
  - [原型] 用户点击 Studio 底部的 `[保存]` 或 `[挂到项目环节…]`。
  - [原型] 系统自动保存（「自动保存 34:12 · 后台运行中」）——自动保存**只写草稿模式**，
    不改变已有绑定。
  - [设计] 下游动作反向触发：产出被提交验收、被决策引用、被加入报告正式版时，
    系统要求其必须已是固定快照，否则阻断并提示先定版。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **用户操作**：在 Studio 中完成一段工作，点击 `[保存]`。**系统响应**：把当前内容写入该 Artifact 的
   **工作版本**（最新版），记录自动保存时间；此时默认为**草稿**模式，不出现在项目的
   「已回流的产出与版本」里。
2. **用户操作**：点击 `[挂到项目环节…]`，选择目标项目与环节。**系统响应**：校验用户对该项目该环节的
   写权限与该环节是否允许此类产出；通过后展示三种绑定模式供选择，并说明每种模式的后果。
3. **用户操作**：选择绑定模式——**草稿** / **实时关联** / **固定快照**。**系统响应**：
   - 选**草稿**：仅本人可见，项目侧不出现，不可被任何下游引用。
   - 选**实时关联**：项目侧出现该产出，内容指向 Artifact 的**当前最新版**；Studio 里改动后项目侧
     同步变化；项目侧标注「实时 · 随源变动」。
   - 选**固定快照**：系统对当前内容做**不可变复制**，生成 `artifact@vN`，记录定版人、定版时间与
     其 Context Pack 引用清单；此后源如何改动都不影响该快照。
4. **系统收口**：把绑定关系（Artifact + 模式 + 项目 + 环节 + 版本）写入项目的
   「已回流的产出与版本」，并向该环节的相关任务卡挂上来源链接。
5. **系统收口**：校验 AC1「**只有固定快照可以被决策引用、进验收、进报告正式版、写回图谱与组织大脑**」；
   对非快照模式的产出，下游引用入口保持禁用并说明原因。
6. **系统收口**：记录回流事件（操作者、时间、Artifact、模式、目标环节、版本号）进审计；
   刷新项目侧列表与相关任务、报告、图谱的来源标记。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] **无项目归属保存**——用户在「不属于任何项目」范围下保存，产出仅存在于 Studio 与个人
    工作区；事后可再用 `[挂到项目环节…]` 补绑，补绑时同样要选模式。
  - A2：[设计] **模式升级**——实时关联可随时升级为固定快照（定版）；升级即生成新的不可变版本，
    原实时关联关系保留或替换由用户选择。
  - A3：[设计] **模式降级被禁止**——固定快照不可降级为实时关联或草稿；已定版的内容只能新增版本，
    不能撤销其快照身份（因为可能已被引用）。
  - A4：[设计] 同一 Artifact 可**同时**以固定快照绑定到多个环节/项目（不同版本），
    项目侧各自显示自己绑定的版本号。
- **异常流程**：
  - E1：[设计] 用户试图把**实时关联**的产出提交验收或加入报告正式版时，系统阻断，
    明确提示「需先定版为固定快照」，并提供一键定版入口。
  - E2：[设计] 用户对目标环节无写权限，或该环节已关闭/已归档时，绑定失败并说明原因；
    当前内容保留为草稿不丢失。
  - E3：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功保存的版本，
    明确失败原因，并提供安全重试；自动保存失败必须显式提示，不得静默。
  - E4：[设计] 同一 Artifact 被并发定版时不得产生两个同号版本；系统提示版本已变化，
    允许刷新、对比或重新定版。
  - E5：[设计] 快照所引用的上游证据在定版后被撤回时，**不修改快照内容**，改为在引用处标注
    「证据已撤回」；若该快照已支撑过已签字决策，通知拍板人复核而不是自动改结论。
  - E6：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成的定版按审计规则保留，
    未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

- **引导师 / 项目经理**：可对本项目内任意环节绑定与定版；可查看全部已回流产出与其版本谱系。
- **研究员 / 组长**：可对自己有写权限的环节绑定与定版；可查看本项目已回流产出。
- **组员**：默认只能查看已绑定到本组环节的产出；不可定版。
- **观察者**：默认只读已发布且已脱敏内容；看不到草稿模式的任何产出。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。
- [设计] **草稿模式的产出仅创建者可见**，项目管理员与组织管理员均不可见——与个人层
  「管理员只见计数」的硬约束保持一致。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 项目的「已回流的产出与版本」如实反映每个产出的绑定模式与版本号。
  - 所有跨模块回流均携带来源资源、版本、操作者、时间和可见范围。
  - [设计验收] AC1：只有固定快照可以被决策引用、进验收、进报告正式版、写回图谱与组织大脑。
  - [设计验收] AC2：固定快照定版后内容不可变；源 Artifact 的后续改动不影响任何已定版快照。
  - [设计验收] AC3：项目侧每条已回流产出都能看出它是哪种模式、绑定的是哪个版本、由谁在何时定版。
- **失败后置条件**：
  - 不创建「看似成功」的绑定记录；未完成的内容保留为草稿，失败事件进入可观测日志。
- **不包含**：
  - 并行版本分支与分支合并（[原型] 原型 Studio 明确「不维护并行分支」）。
  - 版本并排比较（[原型] 原型 Studio 明确「不做版本并排比较」；产出物验收侧的
    v1↔v2 逐分区对比属 UC-13.2 范围）。
  - 跨组织、跨客户的产出共享与公开发布。

## R7 业务规则（不随具体实现变化的硬性约束）

- [原型] **正式产出与决策只能绑定固定快照**。
- [原型] 「产出留在本项目；需要时再挂到某个项目环节」——Studio 产出默认不自动进入项目。
- [原型] 「验收后才会成为可被决策引用的证据」——定版是必要条件，不是充分条件；
  需要验收的产出还须经 UC-13.2 验收后才获得证据资格。
- [原型] 「决策绑定的是当时的快照」「旧版仍被引用是正常的」——引用一旦建立即固定在该版本，
  不随源更新。
- [设计] 固定快照**不可变、不可删除**；纠错只能通过新增版本 + 标注被替代来完成。
- [设计] 每个固定快照必须记录其**定版时的 Context Pack 引用清单**（见 UC-0.2），
  以支撑「这条结论当时看了什么」的审计要求。
- [设计] 自动保存只写草稿，**永不改变已有绑定模式，也永不产生新的固定快照**。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何定版、绑定、解绑、替代动作都必须记录审计事件，并显示动作影响范围。

## R8 界面线索

- **前端入口**：[原型] 四个 Studio 共用外壳的**底部「保存到项目」区**——
  `自动保存 34:12 · 后台运行中` ／ `产出留在本项目；需要时再挂到某个项目环节` ／
  `[挂到项目环节…]` `[保存]`；项目侧入口为**「已回流的产出与版本」**分区。
- **信息架构**：[原型] 项目页只留五类内容：目标与环节 / 我的待办 / 本环节允许的工具 /
  **已回流的产出与版本** / 评审与发布。
- **推荐交互**：
  - [设计] 三种模式在选择时必须**并列展示各自后果**（能不能被决策引用、会不会随源变动），
    不能只给三个单选按钮。
  - [设计] 项目侧列表用明确徽标区分三态：`草稿` / `实时 · 随源变动` / `已定版 vN`。
  - [原型] 参照画布屏的同步三态（已同步 / 待同步 / 画布领先）表达实时关联的偏移状态。
- **必须呈现的状态**：
  - 默认态、加载态、空态、校验失败态、依赖失败态、无权限态、成功态。
  - 定版进行中显示排队/运行/完成/失败，并允许查看最近一次成功定版。
  - 同时显示草稿状态、当前版本、来源版本和最后修改人。
- **原型参考**：
  - `phases/requirements/WorkspaceX Standalone.html` — 说明页「最新一轮」章节、四个 Studio 底部区
- **UI sign-off**：**原型待补**——底部 `[挂到项目环节…]` `[保存]` 两个按钮**已探明确实存在**，
  但点进去之后的三模式选择器**没有任何屏**；项目侧「已回流的产出与版本」分区同样只见于说明页文字、
  运行态无对应屏。二者都不是「回去再抽一次就有」（未探明），而是**需要补画原型并接线**，
  实现前须由产品/设计确认。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 定版（快照复制）应在 3 秒内完成并给出反馈；超过 10 秒转为后台任务并允许离开页面。
  - [设计] 项目侧「已回流的产出与版本」必须分页或增量加载。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - [设计] 草稿模式内容不进入任何检索范围，也不进入 AI 的可读上下文。
- **兼容与降级要求**：
  - 响应式 Web；移动端至少保证查看已回流产出与其版本。
  - 实时通道不可用时，实时关联模式降级为轮询并显示「非实时」，不得伪装已同步。

## R10 已知约束 / 依赖

- **内部依赖**：登录管理（权限判定）、项目模板（环节定义）、UC-0.2 Context Pack（引用清单来源）。
- **被依赖**：研究 / 访谈 / 问卷 / 原型四个 Studio、13-deliv 产出物验收、10-report 报告引用、
  09-kg 证据入图、14-brain 知识晋升——**全部依赖本协议**，因此必须先于它们落地。
- **跨模块契约**：身份与权限、来源引用、版本、任务状态、审计事件和通知必须使用统一标识。
- **[待确认]** 原型说明页指向的「UML 文档第 13 节」不在仓库中；本文为反推设计，
  **需与该文档核对或由人类确认本文取代它**。
- **[待确认]** 四个模块各自的版本策略是否统一（提交/退回各定一版不可删 · 三模式快照 ·
  只留最新不并排 · 发布归档但实例记版本），还是承认差异。
- **[待确认]** 固定快照的存储成本与保留期：快照不可删与材料保留期（180 天）如何共存。

## R11 切分提示（给 requirement-author）

- 建议先拆「Artifact 与版本数据模型 → 三模式绑定服务 → 快照不可变存储 → 项目侧回流列表 →
  下游引用资格门控 → 审计与通知 → 自动化验收」。
- **引用资格门控（第 5 步）是本用例的价值核心**，必须单独成 feature 并有独立验收，
  不能混在绑定服务里。
- **优先级 / 先后依赖**：P0；13 点；阶段零共享内核；必须先于任何 Studio 类 feature 完成。

## R12 AI Ready 验收线索

- V1（成功态）：AC1 —— 对实时关联模式的产出调用「加入报告正式版 / 提交验收 / 引用为决策依据」
  接口，全部返回拒绝且错误信息指向「需先定版」；对固定快照调用同样接口全部成功。
- V2（成功态）：AC2 —— 定版生成 `artifact@v1` 后修改源 Artifact 并再次读取 `v1`，内容字节一致。
- V3（成功态）：AC3 —— 项目侧列表接口对每条产出返回 `mode` / `version` / `pinned_by` / `pinned_at`
  四个字段且非空（草稿模式除外）。
- V4（权限态）：逐一使用 引导师、项目经理、研究员、组长、组员、观察者、未授权用户访问；
  草稿模式产出仅创建者可读，其余角色（含管理员）返回 404 而非 403。
- V5（空态）：项目无任何已回流产出时显示真实空态与下一步，不生成伪数据。
- V6（并发态）：两名用户同时对同一 Artifact 定版，只产生一个新版本号，另一方收到版本已变化提示。
- V7（审计态）：每次定版与绑定可按操作者、时间、Artifact、模式检索；越权尝试也有安全审计记录。
- V8（不可变性）：尝试通过任何接口修改或删除已定版快照，全部被拒绝并记录审计事件。
