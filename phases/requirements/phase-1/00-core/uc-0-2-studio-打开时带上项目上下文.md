# 原始需求（细化）— UC-0.2 Studio 打开时带上项目上下文（Context Pack）

> 所属：阶段零 · 共享内核 / M0 跨工具协议
> 来源：`WorkspaceX Standalone.html` 说明页「共用一套外壳：顶部项目上下文条、左侧历史与 Tool Library、
> 中央专业区、**右侧上下文包与证据**、底部保存到项目三模式」；大脑「AI 读到了什么」屏的
> 四段注入结构、五种筛选动作、上下文预算与可只读审查的系统提示。
> **原型说明页把本协议的定义指向「UML 文档第 13 节」，该文档不在仓库中**——本文是依据上述
> 原型证据链反推的设计稿，需人类确认后才可作为权威。

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **13**；建议迭代 **阶段零 · 共享内核**。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-0.2 / Studio 打开时带上项目上下文
- **Actor**：**引导师**、**项目经理**、**研究员**、**组长**
- **目标**：[原型] 用户在某个项目环节里打开 Studio 时，不需要自己去找材料——系统按
  「项目 + 环节 + 角色 + 当前用户」装配一个**上下文包（Context Pack）**送进来，
  并且**用户能看见这次带进来了什么、丢掉了什么**。
- **本用例结果**：Studio 右侧「上下文包与证据」栏如实列出本次装配的内容与来源；该 Context Pack
  同时是本次 Studio 内 AI 的可读范围上限，也是产出 Artifact 定版时的引用清单来源。
- **系统边界**：上下文装配、来源与版本标注、权限过滤、预算裁剪、可审查性、引用完整性校验。
- **核心数据对象**：Context Pack、上下文条目（资源 + 版本 + 来源 + 可见范围 + 相关度）、
  筛选动作记录、预算配额、装配快照。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已登录且对目标项目/环节有访问权限。
  - [原型] Studio 可独立发起（「不属于任何项目」），此时 Context Pack 仅含个人层与组织层
    可访问内容，项目层为空。
- **触发条件**：
  - [原型] 用户从项目环节进入某个 Studio，或在 Studio 内切换范围（本项目 ↔ 不属于任何项目）。
  - [设计] Studio 内发起一次 AI 调用时，按当前 Context Pack 装配系统提示。
  - [设计] 上游材料发生变化（新证据入库、证据被撤回、知识条目过期）时，
    提示用户 Context Pack 可刷新，但**不自动改写已装配的内容**。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **用户操作**：从项目环节点击进入某个 Studio。**系统响应**：读取该环节的目标、产出要求与
   「本环节允许的工具」，据此确定要装配哪些类别的上下文。
2. **系统处理**：按**权限优先**原则召回候选内容——项目层证据与产出、组织层已生效知识、
   当前用户个人层中**已显式开启**的判断偏好；**个人层私有笔记一律不进**。
3. **系统处理**：对候选执行五种筛选动作并**逐条留痕**：
   - **召回**：[原型] 只取「生效」与「待复核」两态；已过期条目仍召回但打「可能已过期」标。
   - **降权**：[原型] 适用范围不匹配的不排除，标为「跨范围引用」后降权保留。
   - **排除**：[原型] 已撤销条目永久排除；其反例文本作为「教训」另行召回。
   - **成对**：[原型] 冲突事实两条同时注入，由人裁决，引擎不替人选。
   - **线索**：[原型] 图谱路径只给固定加成，不单独决定结果。
4. **系统处理**：按**上下文预算**裁剪（[原型] 示例 14.9k / 120k），超出预算的低相关条目丢弃，
   但**丢弃清单必须保留且可点开审查**（[原型]「被丢弃 · 14 条低相关，相关度低于 0.45，
   可点开审查是否漏掉关键内容」）。
5. **系统响应**：在 Studio 右侧「上下文包与证据」栏按段展示装配结果，每条标出**来源资源、版本、
   相关度、被施加的筛选动作**；顶部项目上下文条显示当前项目与环节。
6. **用户操作**：查看装配后的系统提示（[原型]「可只读审查」）、调整检索权重、
   或把这段上下文固定到本项目。**系统响应**：按用户调整重新装配并记录调整事件。
7. **系统收口**：校验 AC1「**本次 Studio 内 AI 产出所引用的每一条证据，都必须存在于本次
   Context Pack 中**」；引用未列出的证据一律拒绝并记录。
8. **系统收口**：产出定版为固定快照时（UC-0.1 第 3 步），把本次 Context Pack 的引用清单
   随快照一同固化，形成「这条结论当时看了什么」的审计依据。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] **无项目归属**——范围切为「不属于任何项目」时，项目层为空，
    仅装配组织层与个人层偏好；界面明确说明当前无项目上下文。
  - A2：[原型] **固定上下文到本项目**——用户认为这次装配的上下文好用，可将其固定，
    后续同环节打开时复用同一装配基线。
  - A3：[原型] **调整检索权重**——用户可调权后重新装配；每次调整留痕，不可静默生效。
  - A4：[设计] **手动增补**——用户可手工把某条材料加入 Context Pack；手工加入项标注
    「人工指定」且不受相关度阈值裁剪。
- **异常流程**：
  - E1：[设计] 候选为空（新项目、无任何材料）时显示真实空态并给出下一步建议，
    **不得生成伪上下文**，也不得让 AI 在无证据情况下给出带引用的结论。
  - E2：[设计] 预算不足以装下全部**人工指定**条目时，明确报错让用户取舍，
    不静默丢弃人工指定项。
  - E3：[设计] 请求超时、依赖不可用时保留上次成功装配的 Context Pack，
    明确标注「上下文可能已过时」，并提供安全重试。
  - E4：[设计] 装配过程中用户权限被撤回时立即终止，已展示内容清空，
    不得残留越权内容在前端。
  - E5：[设计] 上游证据在 Studio 使用期间被撤回时，实时在上下文栏标注「证据已撤回」，
    并阻断以该证据为依据的新产出定版。

## R5 权限与可见性

- **引导师 / 项目经理**：可查看本项目范围内完整 Context Pack 与筛选留痕。
- **研究员 / 组长**：可查看其有权访问范围内的 Context Pack。
- **组员**：仅本组范围；跨组内容不进其 Context Pack。
- **观察者**：默认只读已发布且已脱敏内容；不得通过 Context Pack 间接读到原始转写或私聊。
- **组织管理员**：[原型] **个人层内容一律不可见**（只见计数）；不得通过任何 Studio 的
  Context Pack 绕过这条边界。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - Studio 右侧上下文栏如实反映本次装配，含被丢弃清单。
  - [设计验收] AC1：AI 产出引用的每条证据都能在本次 Context Pack 中找到；引用未列出的证据被拒绝。
  - [设计验收] AC2：每条上下文条目都带 (资源 ID, 版本, 来源, 可见范围, 相关度, 筛选动作)
    六元组，无一缺失。
  - [设计验收] AC3：被丢弃的低相关条目可展开审查，数量与阈值可见。
  - [原型验收] AC4：装配后的系统提示可只读审查，且分段结构与来源标注清晰。
- **失败后置条件**：
  - 不产生「看似完整」的上下文；装配失败时明确标注并阻断依赖它的 AI 调用。
- **不包含**：
  - 个人层私有笔记进入任何 Context Pack（[原型] 硬约束）。
  - 跨组织、跨客户的上下文装配（跨范围引用仅限已脱敏的组织层聚合）。
  - 检索算法本身的调优与向量索引实现细节（属技术方案，不属本用例）。

## R7 业务规则（不随具体实现变化的硬性约束）

- [原型] **反对证据被强制保留、不做筛除**。
- [原型] **冲突事实成对注入，由人裁决，引擎不替人选**。
- [原型] **已撤销条目永久排除**，但其反例文本作为「教训」另行召回。
- [原型] **个人层私有内容默认不进项目、不进 AI 检索范围**；只有本人显式升到项目层才可见。
- [原型] **客户机密材料只能由本地模型处理**——Context Pack 含机密条目时，
  本次调用的模型选择被限制在自托管模型内。
- [设计] **引用完整性**：AI 不得引用未在 Context Pack 中列出的证据（对应原型系统提示硬约束原文）。
- [设计] **被丢弃不等于不存在**：任何因预算或阈值被丢弃的内容都必须可审查，不得静默消失。
- [设计] Context Pack 一经用于产出定版即**随快照固化**，此后上游变化不改写它。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- AI 读取行为必须留痕，包含读了什么、丢了什么。

## R8 界面线索

- **前端入口**：[原型] 四个 Studio 共用外壳的**顶部项目上下文条**与**右侧「上下文包与证据」栏**；
  深度审查入口为大脑的**「AI 读到了什么」**屏。
- **信息架构**：[原型] Studio 外壳五区——顶部项目上下文条 / 左侧历史与 Tool Library /
  中央专业区 / 右侧上下文包与证据 / 底部保存到项目。
- **推荐交互**：
  - [原型] 按段展示（客户与项目上下文 / 方法 / 证据片段 / 历史决策与复盘 / 被丢弃），每段带 token 数。
  - [原型] 显示上下文预算占用（如 14.9k / 120k）。
  - [原型] 五种筛选动作各自可展开说明本次命中了什么、降了什么权、排除了什么。
  - [原型] 出口按钮：`[看这次的完整调用日志]` `[调整检索权重]` `[固定这段上下文到本项目]`。
- **必须呈现的状态**：
  - 默认态、加载态、空态、校验失败态、依赖失败态、无权限态、成功态。
  - 装配中显示进度；装配失败时明确阻断依赖它的 AI 调用入口。
  - 含过期条目时显示「可能已过期」，含跨范围条目时显示「跨范围引用」。
- **原型参考**：
  - `phases/requirements/WorkspaceX Standalone.html` — 大脑「AI 读到了什么」屏（本用例最完整的参考）
- **UI sign-off**：**原型确认缺失**——大脑侧的「AI 读到了什么」屏**完整存在且已逐段抽取**，
  但 Studio 侧的「上下文包与证据」栏只出现在说明页的外壳描述文字里；
  研究 / 问卷 / 原型三个 Studio 的运行态外壳（含范围切换器、自动保存条、底部保存区）
  **已完整探明，其中没有这一栏**。不是未探明，需补画原型并由产品/设计确认两者的关系。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] Context Pack 装配应在 3 秒内给出可感知反馈；超过 10 秒转后台任务并允许离开页面。
  - [设计] 上下文栏必须分段增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、敏感字段脱敏、AI 读取留痕。
  - [原型] 含客户机密时强制本地模型路由，且该约束必须体现在装配后的系统提示中。
- **兼容与降级要求**：
  - 响应式 Web；移动端至少保证查看本次上下文摘要与来源。
  - 检索服务不可用时明确失败并阻断 AI 调用，**不得降级为"无上下文直接生成"**。

## R10 已知约束 / 依赖

- **内部依赖**：登录管理（权限）、项目模板（环节定义）、实时转录 / 访谈 / 画布（证据来源）、
  组织大脑（知识召回与五态机）、模型管理（机密路由）。
- **被依赖**：四个 Studio、UC-0.1（引用清单来源）、17-1 全链路审计（「任一条结论都能还原
  它当时看了什么」直接依赖本用例的装配快照）。
- **跨模块契约**：身份与权限、来源引用、版本、审计事件必须使用统一标识。
- **[待确认]** 原型说明页指向的「UML 文档第 13 节」不在仓库中；本文为反推设计。
- **[待确认]** 上下文预算的具体数值（原型示例 120k）是全局固定、按模型能力推导，还是按项目可配。
- **[待确认]** 相关度阈值（原型示例 0.45）由谁维护、能否按环节调整。
- **[待确认]** Context Pack 装配快照的留存期——它是审计依据，但体量可能很大。

## R11 切分提示（给 requirement-author）

- 建议先拆「Context Pack 数据模型与六元组 → 权限过滤召回 → 五种筛选动作与留痕 →
  预算裁剪与丢弃清单 → 上下文栏 UI → 引用完整性校验 → 与定版的固化 → 自动化验收」。
- **引用完整性校验（第 7 步）与丢弃清单可审查（第 4 步）是本用例最容易被实现者省略的两项**，
  必须各自独立成 feature 并有独立验收。
- **优先级 / 先后依赖**：P0；13 点；阶段零共享内核；与 UC-0.1 同批，必须先于任何 Studio 类 feature。

## R12 AI Ready 验收线索

- V1（成功态）：AC1 —— 构造一次 AI 调用，使其尝试引用一条不在 Context Pack 中的证据，
  接口拒绝并记录；引用包内证据则通过。
- V2（成功态）：AC2 —— 上下文条目接口对每条返回六元组且无一为空。
- V3（成功态）：AC3 —— 被丢弃条目可通过接口列出，返回数量与所用阈值。
- V4（权限态）：以组织管理员身份装配 Context Pack，返回结果中不含任何用户的个人层私有笔记；
  以观察者身份装配，不含原始转写与私聊。
- V5（空态）：全新无材料项目装配返回真实空态，且以该包发起的 AI 调用被阻断而非生成无来源结论。
- V6（依赖失败）：模拟检索服务不可用，AI 调用入口被阻断并提示，不出现"无上下文直接生成"。
- V7（并发态）：装配过程中上游证据被撤回，上下文栏实时标注「证据已撤回」，
  且以该证据为依据的定版被阻断。
- V8（审计态）：任取一条已定版结论，可还原其定版时的完整 Context Pack 引用清单
  （对应 UC-17.1 AC1「任一条结论都能还原它当时看了什么」）。
- V9（机密路由）：Context Pack 含标记为客户机密的条目时，模型选择接口只返回自托管模型。
