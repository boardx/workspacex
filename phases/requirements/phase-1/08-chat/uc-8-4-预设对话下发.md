## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-8.4 / 预设对话下发
- **Actor**：**引导师**、**组长**、**组员**、**观察者**
- **目标**：[Backlog] 引导师预先写好开场提示与内置 skill 的**对话预设**并下发给各组，
  被下发者打开即用、不必自己配；预设的使用次数可统计。
- **本用例结果**：[Backlog] 用户通过“预设对话下发”完成从“引导师想让各组一上手就有得用”到可追踪业务结果的闭环。
- **系统边界**：对话列表、全屏对话、参与者与上下文配置、产出落地、可见性。
- **核心数据对象**：对话、消息、参与者、上下文引用、可见范围、产出、来源。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“上传 Skill、上传 Agent、登录管理”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [Backlog] 引导师想让各组一上手就有得用。
  - 系统从 **预设对话与技能** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **引导师操作**：写好开场提示与内置 skill，选下发对象（全场 / 指定组 / 指定角色）。
   **系统响应**：校验当前身份与项目范围；校验所选 skill 与 agent 在下发对象的**可见性范围内**
   （见 `00-core/uc-0-3`），越范围的直接拒绝而不是下发后失败。
2. **组长/组员操作**：[Backlog] 在自己视角点开即用，不需要自己配。
   **系统响应**：[Backlog] 打开即带好开场提示、agent 与 skill，被下发者不需要任何配置动作。
   **[原型确认缺失]** 对话屏与组员入口均已完整探明，**未见任何预设对话的接收入口或「打开即用」态**；
   需补画原型。（原「画布屏『环节里绑定了模板与 skill，组员打开就是这张画布』」的援引属
   **跨屏类比**，画布≠对话，已删除。）
3. **系统处理**：[Backlog] **预设本身可见，各人开始后生成各自私有的对话**——
   预设是模板，开始后是实例；实例的可见范围由 **UC-8.5** 判定。
4. **系统收口**：校验 AC1「能统计每个预设被用了多少次」——计数必须是**真实使用实例数**，
   不得按下发人数估算；满足后记录操作者、时间、对象、结果与来源，并刷新相关列表、图谱、看板或通知状态。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[Backlog] 预设本身可见，各人开始后生成各自私有的对话。系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
- **异常流程**：
  - E1：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

- **引导师**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **组长**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **组员**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **观察者**：默认只读已发布且已脱敏内容；不能输入、控制全场、读取私聊或原始转写，单独授权除外且必须留痕。
- **项目负责人**（**组织角色**；原文档所称「项目经理」，按 `00-core/uc-0-3` 正名）：
  可查看项目级状态与审计摘要；**内容读取仍需其持有项目角色**；是否可代替业务 Actor
  执行写操作需由角色模板显式授权。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。
- **[口径统一]** 本模块四个角色的完整语义与两层（组织 × 项目）交集判定见 **UC-8.5**
  与 `00-core/uc-0-3`；本 UC 只调用其判定结果，不重复定义。

## R6 后置条件 / 不包含

## R7 业务规则（不随具体实现变化的硬性约束）

- [Backlog] **预设本身可见，各人开始后生成各自私有的对话**——预设 ≠ 实例，两者可见性分开判定。
- [设计] **下发不得突破可见性范围**：预设里引用的 agent / skill 若对下发对象不可见，
  下发时即拒绝（对齐 `uc-0-3` 的资源可见性范围）。
- [设计] 预设实例继承 UC-8.2 的全部规则（AI 主动发言必带来源、高影响动作走批准卡）；
  **预设不得预先批准任何高影响动作**。
- AC1：能统计每个预设被用了多少次（真实实例数）。
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- AI/Agent 的写回、覆盖、发布或高影响工具调用必须遵守原型中的批准点；未经确认只保留为草稿或候选。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态）：AC1 —— 三个人各自开始同一预设，使用计数为 3（**实例数**，不是下发人数）；
  下发给 10 人但只有 3 人开始时，计数仍为 3。
- **V1b（预设 ≠ 实例）**：预设对被下发者可见，但 A 开始后生成的对话实例对 B 不可见
  （判定依据来自 UC-8.5）。
- **V1c（范围校验）**：预设引用一个「仅能源组」的 agent 并下发给非能源组 —— **下发接口即拒绝**，
  错误标明是组织层可见性限制。
- V2（权限态）：逐一使用 引导师、组长、组员、观察者、未授权用户访问；返回数据和可执行动作严格符合 R5。
- V3（空态）：无目标数据时显示真实空态与下一步，不生成伪数据。
- V4（依赖失败）：模拟网络/外部依赖失败，输入和最近成功数据保留，错误可解释且可重试。
- V5（并发态）：两名用户修改同一资源时不静默覆盖，并可识别最终版本。
- V6（审计态）：关键动作可按操作者、时间、对象和结果检索；越权尝试也有安全审计记录。
