## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-8.2 / 全屏对话窗口
- **Actor**：**引导师**、**组长**、**组员**、**观察者**、**AI 团队（多个 agent 同席）**
- **目标**：[原型] 所有干活都发生在对话里。对话屏要同时做到三件事：
  ① 让人看见**谁在场、谁在跑批**；② 让 AI 的每一次工具调用、每一条结论**可展开、可追溯**；
  ③ 在高影响动作前**停下来等人批准**。
- **本用例结果**：[Backlog] 用户在一个线程里完成「提问 → AI 多 agent 协作 → 看工具调用链 →
  拿到产物卡 → 批准高影响动作 → 产出落地」的闭环，全过程的模型、预算、数据范围与来源都可见。
- **系统边界**：AI 团队面板与在场状态、消息流与五类卡片（AI 消息 / 产物卡 / 批准卡 / 转录卡 /
  进度卡）、工具调用链展开、引用角标、消息头角标、输入区（agent 与 skill 选择、改派、建议条）、
  右侧栏五标签。
- **核心数据对象**：对话、消息、**agent 及其在场状态**、**工具调用记录**（函数签名 / 参数 /
  命中数 / 运行态 / token）、**产物（Artifact）**、**批准请求**（调用链 / 模型 / token 预算 /
  数据范围 / 出口）、转录会话、后台任务、引用（编号 / 出处 / 页码或时间段）、可见范围。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“上传 Skill、上传 Agent、登录管理”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] 点开一张对话卡。
  - 系统从 **全屏对话** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

### 二、中栏：消息流与五类卡片

3. **系统响应（AI 消息头）**：[原型] 每条 AI 消息头显示 `agent 名 · 角色`、
   本次使用的 `skill:`（如 `skill: MECE 假设拆解`）、思考摘要（`▸ 思考了 8.2 秒 · 4 步`），
   以及**状态角标**（见第 8 步）。
4. **用户操作**：展开「**工具调用**」区。**系统响应**：[原型] 折叠头显示汇总
   「`工具调用 · 3` ｜ `读了 64 条 · 12.4k token`」；展开后**逐条**列出每次调用的
   **函数签名与参数**及其**逐条运行态**：

   ```
   graph.search(project:"远洋", type:["假设","证据"])      64 命中
   brain.recall("资质尽调清单")                            复用 1 份
   mcp:行业数据库.query_market(region:"DE")                运行中
   ```

   每条至少含：**函数签名 + 实参**、**结果计数或复用标记**、**运行态**（完成 / 复用 / 运行中 / 失败）。
5. **系统响应（产物卡）**：[原型] AI 产出结构化内容时在消息流中生成**产物卡**，含：

   - **`[全屏编辑]`** 入口；
   - **结构摘要**（`flowchart LR · 6 节点`）；
   - **数据链提示** ```` ```mermaid → DiagramModel → fabric ````（对齐 07-canvas D-08）；
   - **语义标注**（`3 个致命假设已标红`）；
   - **后续动作** `[派给 Scout 验证]` `[加入报告]`。
6. **系统响应（批准卡 · 高影响动作的人类闸门）**：[原型] 当 agent 要执行高影响动作时，

   | 项 | 原型内容 |

   | 标题与状态 | 「Ledger 想执行一个动作，等你批准」·**已暂停** |
   | **调用链** | `▸ 调用链 Ava → Ledger`（可展开，对齐 agent 互调留痕） |
   | **模型** | `gpt-5.2 ＋ 本地 qwen3-32b`　`[改]` |
   | **token 预算** | `800k（约 ￥9.6）` —— 必须同时给**用量**与**折算金额** |
   | **要读的数据** | `项目库 ＋ 电价曲线 · 含机密，仅本地模型` |

   卡底部固定说明：[原型]「**批准后转后台任务，约 6 分钟回到本线程**」+ `[看任务队列]`。
7. **系统响应（转录卡与进度卡）**：
   - [原型] **转录卡**：`会议转录中 28:14` + **实时文字**（「周宁：客户董事会给的窗口是十八个月…」）

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] 观察者无输入区，显示只读说明；[原型] 观察者视角下**原始转写、私聊与任何操作按钮
    都关掉了**——批准卡、`[改派]`、`[全屏编辑]`、`[停止录音]` 等一律不渲染（不是禁用，是不出现）。
  - A2：**[原型待补]** 批准卡上 `[改参数再跑]` **只有按钮字面**——与 `[预览客户版]` 同型，
    档案里批准卡只渲染了三个按钮，点击后的行为从未出现。
    下述为 [设计]：打开参数面板（模型、token 预算、数据范围），
    改完后重新生成一张新的批准卡，**原卡保留为历史**，不就地改写。
  - A3：**[原型待补]** 批准卡上 `[不用了]` 同为空按钮。
    下述为 [设计]：该动作终止，线程继续；终止事件记审计。
  - A4：[原型] 批准通过后动作**转后台任务**，线程不阻塞；任务完成后**回到本线程**发一条结果消息，
    `[看任务队列]` 可跳到 11-task。
  - A5：[原型] **单个 agent 关闭主动插话**后，该 agent 只在被 `@` 呼叫时发言。
- **异常流程**：
  - E1：[原型] 研究阶段不显示现场转录，改显示来源与材料——右栏「转录」标签隐藏或置空，
    默认落在「材料」标签。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E1b：[原型] **工具调用失败**时，调用链中该条显示失败态与原因，
    **不得只显示汇总数而隐藏失败条**；基于失败调用得出的结论必须标为不完整。
  - E1c：[原型 · 说明页规则 3] **超额降级分级处理**：普通生成**自动降级并标注**
    （消息头出现 `降级运行 · sonnet`）；研究 / 财务 / 合规 / 决策辅助类**先问人**；
    **含机密或无合格替代时不降级、明确失败**——宁可报错也不给低质量伪结果。
  - E1d：[设计] AI 主动发言**取不到来源**时**不发言**（规则 1 的硬性推论），
    不得发出无来源的主动补充。
  - E1e：[设计] 批准卡在**超时或线程被归档**后自动失效，标为「已过期 · 未执行」，不得静默执行。
  - E2：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E4：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

- **引导师**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **组长**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **组员**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **观察者**：默认只读已发布且已脱敏内容；不能输入、控制全场、读取私聊或原始转写，单独授权除外且必须留痕。
- **项目负责人**（**组织角色**；原文档所称「项目经理」，按 `00-core/uc-0-3` 正名）：
  可查看项目级状态与审计摘要；**内容读取仍需其持有项目角色**；是否可代替业务 Actor
  执行写操作需由角色模板显式授权。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。
- **[口径统一]** 本模块四个角色的完整语义与两层（组织 × 项目）交集判定见 **UC-8.5**
  与 `00-core/uc-0-3`；观察者视角下输入区、批准卡、`[改派]`、`[全屏编辑]`、`[停止录音]` 等**不渲染**（不是禁用），原始转写与私聊**服务端不下发**。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 形成与本 use case 对应的正式记录或明确状态，并可从来源页面再次打开。
  - 所有跨模块回流均携带来源资源、版本、操作者/触发者、时间和可见范围。
  - [原型验收] AC1：从任一入口打开，标题、组名、措辞都与上下文一致。
  - [原型验收] AC2：批准卡出现时动作**已暂停**；在人点下三个出口之一前，动作绝不执行。
  - [原型验收] AC3：工具调用链每条都可展开到**函数签名 + 实参 + 命中数 + 运行态**。
  - [原型验收] AC4：AI 主动发言必带来源；取不到来源则不发言。
  - [原型验收] AC5：降级与待复核标在**发生它的那条消息头**上，不折叠进别处。
- **失败后置条件**：
  - 不创建“看似成功”的正式记录；可重试内容保留为草稿，失败事件进入可观测日志。
- **不包含**：
  - 第三方 IM 同步、未授权跨组读取。
  - **AI 未经批准执行高影响动作**——批准卡是硬闸门，不存在「默认批准」「记住我的选择」。
  - Agent 市场本身的浏览、评分与安装流程（本 UC 只提供 `＋ 从 Agent 市场加入` 入口，
    市场属 04-agent）。
  - 不扩展到本 use case 未声明的跨组织、跨客户或公开发布能力。

## R7 业务规则（不随具体实现变化的硬性约束）

### AI 在场与主动发言

- [原型] **AI 团队面板常驻**，agent 在场状态三取值：**在场 / 跑批中 / 空闲**（enum，不得增删）。
  每个 agent 必须有**职责一句话**，不得只显示名称。
- [原型 · 规则 1] **AI 主动插话默认开**；**单个 agent 可关**；
  **主动发言必须带来源**——无来源不发言。
- [设计] agent 的可加入范围受 04-agent 的可见性范围（全组织可用 / 仅某组）约束，
  见 `00-core/uc-0-3`。

### 可追溯性（三层，缺一不可）

- [原型] **工具调用层**：展开后必须给出**每次调用的函数签名与实参**、**命中数或复用标记**、
  **逐条运行态**（原型实例：`64 命中` / `复用 1 份` / `运行中`）；
  汇总行给出**调用数**与**读取量**（`读了 64 条 · 12.4k token`）。
- [原型] **引用层**：引用角标 = **编号 + 出处全称 + 页码或转录时间段**，三段缺一不可。
- [原型] **产物层**：产物卡必须带 `[AI]` 标、结构摘要与语义标注，且可 `[全屏编辑]` 追到原件。

### 批准卡（高影响动作的人类闸门，**产品信任核心**）

- [原型] 触发批准时**动作已暂停**，在人做出选择前**绝不执行**。
- [原型] 批准卡必须**同时**披露：**调用链**（谁调的谁）、**模型**（含是否走本地模型）、
  **token 预算与折算金额**、**要读的数据及其密级**、**三个出口**。
- [原型] **含机密的数据只能给本地模型**（原型：「项目库 ＋ 电价曲线 · 含机密，**仅本地模型**」）；
  该约束必须由**服务端强制**，不是界面提示。
- [原型] 批准后**转后台任务**并给出预计回归时间（「约 6 分钟回到本线程」），
  提供 `[看任务队列]` 跳转；线程不阻塞。
- [设计] `[改参数再跑]` 生成新卡、原卡存档；`[不用了]` 终止并记审计；两者都不得就地改写原卡。
  **[原型待补]** 这两个按钮在档案里只有字面，点击后的行为从未渲染（与 `[预览客户版]` 同型）。

### 状态可见性（[原型 · 状态 4.5]「不变量放在它发生的地方」）

- [原型] `降级运行 · <模型名>` 与 `待复核 N` 标在**该条消息头**上。
- [原型 · 规则 3] 降级分级：普通生成自动降级并标注；研究 / 财务 / 合规 / 决策辅助先问人；
  **含机密或无合格替代时不降级、明确失败**。
- [原型] 右栏**五标签**（转录 / 执行 / 洞察 / 产物 / 材料）**均带计数**，计数须与真实数据一致。

- [原型] 研究阶段不显示现场转录，改显示来源与材料。
- [原型] 观察者无输入区，显示只读说明；观察者视角下操作按钮**不渲染**。
- AC1：从任一入口打开，标题、组名、措辞都与上下文一致。
- AC2：批准卡是硬闸门。
- AC3：工具调用链逐条可展开到签名与实参。
- AC4：AI 主动发言必带来源。
- AC5：降级与待复核标在消息头。
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- AI/Agent 的写回、覆盖、发布或高影响工具调用必须遵守原型中的批准点；未经确认只保留为草稿或候选。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证。
**[D-35] 逻辑层优先用 API 断言**（批准闸门、调用链字段、来源约束都可在服务端断言），
UI 层按统一 `data-testid` 命名规范补 E2E。

### 信任核心：批准闸门（优先级最高）

- **V1（AC2 · 闸门态）**：触发一个高影响动作 → 断言 ① 动作**未执行**（目标系统无副作用）；
  ② 批准请求状态为 `已暂停`；③ 响应体含**调用链 / 模型 / token 预算与金额 / 数据范围 / 三出口**
  五组字段，缺一即失败。
- **V2（三出口）**：对同一批准请求分别跑三个出口——`[批准执行]` 后动作执行且**产生一条后台任务**；
  `[改参数再跑]` 生成**新的**批准请求且原请求存档为「已改参」；`[不用了]` 后动作永不执行且记审计。
- **V3（机密数据强制）**：构造一个「含机密」的数据范围并把模型改为云端模型 →
  **服务端拒绝**，错误指向「含机密仅本地模型」；此断言必须在 API 层成立，不依赖界面禁用。
- **V4（过期态）**：批准请求超时后调用批准接口被拒绝，状态为 `已过期 · 未执行`。

### 可追溯性

- **V5（AC3 · 调用链）**：展开接口对每条工具调用返回
  `function` / `args` / `hit_count 或 reuse_flag` / `status`，四项非空；
  汇总行的调用数与明细条数相等，读取量与各条之和一致。
- **V6（AC4 · 主动发言必带来源）**：构造一个取不到来源的主动补充场景 →
  断言**没有任何消息被发出**（不是发一条空来源消息）；关闭该 agent 的主动插话后，
  同场景下它只在被 `@` 时发言。
- **V7（引用角标三段）**：任取一条引用，返回 `index` / `source_full_name` /
  `page 或 transcript_range` 三项均非空。

### 状态与版面

- **V8（AC5 · 角标位置）**：触发一次降级生成 → 该条消息的 `badges` 含 `降级运行 · <模型名>`；
  其它消息不含。`待复核 N` 的 N 与 UC-8.1 线程卡上的「N 条待复核」**数值相等**。
- **V9（右栏五标签）**：右栏接口返回**恰好五个**标签 `转录/执行/洞察/产物/材料`，
  且每个标签的计数与其列表长度一致（`执行` 为 `已完成/总数` 形式）。
- **V10（AI 团队三态）**：面板接口对每个 agent 返回 `在场|跑批中|空闲` 之一
  与**非空的职责一句话**；取值超出枚举或职责为空即失败。
- **V11（改派提示）**：改派提示的响应体必须含 `reason` 字段且非空（原型例：「有行业数据库授权」）。
