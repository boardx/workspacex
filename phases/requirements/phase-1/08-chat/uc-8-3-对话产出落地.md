## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-8.3 / 对话产出落地
- **Actor**：**引导师**、**组长**、**组员**、**观察者**
- **目标**：[原型] 所有干活都发生在对话里：卡片列表管理线程，全屏窗口做事，挂载 skill、看工具调用、按角色控制可见性。
- **本用例结果**：对话中得到的结论被封装成一个 **Artifact**，按 `uc-0-1` 的三模式之一
  绑定到项目/环节；**该模式唯一决定这条产出能被拿来干什么**。
- **系统边界**：对话侧的落地动作入口、Artifact 封装（含出处回链）、三模式绑定的对话侧调用、
  引用资格门控在对话侧的表现、右栏「产物」标签。
- **核心数据对象**：对话、消息、**Artifact 与其版本**、**绑定模式**（草稿 / 实时关联 / 固定快照）、
  出处回链（对话 id + 消息 id + 引用清单）、可见范围。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“上传 Skill、上传 Agent、登录管理”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] 对话里得到可用结论。
  - 系统从 **全屏对话 → 动作按钮** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **用户操作**：在对话里选定一条结论或一张产物卡，触发落地动作。
   **系统响应**：按场景给出动作集——
   - [原型] **现场**：`贴到本组画布` / `转给全场` / `让研究模块补证据`；
   - [原型] **研究**：`存为洞察` / `加入报告` / `开一场深度研究`；
   - [原型] **产物卡自带**：`[派给 Scout 验证]` `[加入报告]`。
2. **系统处理**：把该结论封装成 **Artifact**，并写入**出处回链**——
   对话 id + 消息 id + 该消息的引用清单（编号 / 出处全称 / 页码或转录时间段，见 UC-8.2）。
   [设计 · 跨屏借证] 未挂来源的结论**标灰**，见 R7。
   **注**：「每句都会挂来源，未挂来源的标灰」原文出自 **洞察报告工作台**左栏（proto-05），
   **不在对话侧**。对话侧是否同样标灰属推断，需人类确认。
3. **用户操作**：选择**绑定模式**（[D-38] 复用 `00-core/uc-0-1`，本 UC 不另立机制）：

   | 模式 | 语义 | 能被拿来干什么 |
   |---|---|---|
   | **草稿** | 仅创建者可见，项目侧不出现 | 不可被任何下游引用 |
   | **实时关联** | 项目侧出现，内容指向 Artifact 的**当前最新版**，随源变动 | 可查看、可讨论；**不可进正式产出与决策** |
   | **固定快照** | 对当前内容做**不可变复制**，生成 `artifact@vN`，记录定版人 / 定版时间 / Context Pack 引用清单 | **正式产出与决策只能绑定它** |

   **系统响应**：三种模式在选择时必须**并列展示各自后果**，不能只给三个单选按钮。
4. **系统处理（引用资格门控）**：把该产出用于「**加入报告正式版 / 提交验收 / 引用为决策依据 /
   写回图谱与组织大脑**」时，**服务端强制要求它已是固定快照**；不是则阻断，
   提示「需先定版为固定快照」并给出一键定版入口。
   [原型] 另有一道门：**「验收后才会成为可被决策引用的证据」**——定版是必要条件，不是充分条件。
5. **系统响应**：[原型] 产出在**右栏「产物」标签**里可查（见 UC-8.2 的五标签），
   每条显示其**绑定模式徽标**：`草稿` / `实时 · 随源变动` / `已定版 vN`。
6. **系统收口**：校验 AC1「每个产出都带出处，能追回这条对话」、
   AC2「只有固定快照能进正式产出与决策」、AC3「未挂来源的结论标灰且不能直接进报告」；
   满足后记录操作者、时间、对象、结果与来源，并刷新相关列表、图谱、看板或通知状态。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] 目标数据为空时展示空状态、原因和下一步入口，不生成示例数据冒充真实结果。
    （原型每屏均填满样例数据，**零空态**，本条无原型依据。）系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
- **异常流程**：
  - E1：[设计 · 跨屏借证] 未挂来源的结论标灰，不能直接进报告（原文在**报告工作台**，不在对话侧）。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E4：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

- **引导师**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **组长**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **组员**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **观察者**：默认只读已发布且已脱敏内容；不能输入、控制全场、读取私聊或原始转写，单独授权除外且必须留痕。
- **项目负责人**（**组织角色**；原文档所称「项目经理」，按 `00-core/uc-0-3` 正名）：
  可查看项目级状态与审计摘要；**内容读取仍需其持有项目角色**；是否可代替业务 Actor
  执行写操作需由角色模板显式授权。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。
- **[口径统一]** 本模块四个角色的完整语义与两层（组织 × 项目）交集判定见 **UC-8.5**
  与 `00-core/uc-0-3`；本 UC 只调用其判定结果，不重复定义。

## R7 业务规则（不随具体实现变化的硬性约束）

- [原型] **未挂来源的结论标灰，不能直接进报告**——「标灰」是服务端可判定的状态，
  不是纯视觉；它同时是 14-brain「检索可审查」的验收锚点。
- [原型 · 承接 `uc-0-1`] **正式产出与决策只能绑定固定快照**。
- [原型 · 承接 `uc-0-1`] **「验收后才会成为可被决策引用的证据」**——
  定版是必要条件，需要验收的产出还须经 UC-13.2 验收后才获得证据资格。
- [设计 · 承接 `uc-0-1`] **固定快照不可变、不可删除**；纠错只能新增版本 + 标注被替代。
- [设计 · 承接 `uc-0-1`] **草稿模式产出仅创建者可见**，项目管理员与组织管理员均不可见。
- [设计 · 承接 `uc-0-1`] **模式不可降级**：固定快照不能退回实时关联或草稿。
- [设计] **出处回链是落地的前置条件**：Artifact 必须携带对话 id、消息 id 与引用清单；
  缺失时只能落草稿，不得定版。
- AC1：每个产出都带出处，能追回这条对话。
- AC2：只有固定快照能进正式产出与决策。
- AC3：未挂来源的结论标灰且不能直接进报告。

- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

**[D-35] 门控类断言全部在 API 层**，不依赖界面禁用。

- **V1（AC2 · 门控态 · 优先级最高）**：对**实时关联**模式的对话产出调用
  「加入报告正式版 / 提交验收 / 引用为决策依据 / 写回图谱」四个接口 —— **全部拒绝**，
  错误指向「需先定版为固定快照」；对**固定快照**调用同样四个接口 —— 全部成功。
  草稿模式同样四个接口全部拒绝。
- **V2（成功态 · AC1 · 出处回链）**：任取一条落地产出，接口返回其
  `conversation_id` / `message_id` / `citations[]` 三项非空，且能据此定位回原消息。
- **V3（AC3 · 标灰门）**：构造一条无引用的结论 → 落地接口只允许落草稿；
  调用「加入报告」被拒绝，产出在列表中的 `has_source = false`。
- **V4（快照不可变）**：定版 `artifact@v1` 后修改源内容并重读 `v1`，**内容字节一致**；
  尝试修改或删除 `v1` 被拒绝并记审计。
- **V5（模式徽标）**：右栏产物列表对每条返回 `mode` / `version` / `pinned_by` / `pinned_at`
  （草稿模式除外），徽标文案与 `mode` 一一对应。
- **V6（权限态）**：逐一使用 引导师、组长、组员、观察者、未授权用户访问；
  **草稿模式产出仅创建者可读**，其余角色（含管理员）返回 404 而非 403。
- V7（空态）：线程无产出时右栏「产物」计数为 0 且显示真实空态，不生成伪产出。
- V8（依赖失败）：模拟报告/图谱服务失败，产出与其绑定关系不变，错误可解释且可重试。
- V9（并发态）：两名用户同时对同一 Artifact 定版，只产生一个新版本号，另一方收到版本已变化提示。
- V10（审计态）：落地、定版、绑定、解绑四类动作可按操作者、时间、对象和结果检索；
  越权尝试也有安全审计记录。
