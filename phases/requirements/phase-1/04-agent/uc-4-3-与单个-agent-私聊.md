# 原始需求（细化）— UC-4.3 与单个 Agent 私聊

> 所属：阶段一 · 能跑完一场项目 / M4 上传 Agent
> 来源：`Backlog Use Case.html` 的 UC-4.3；UI 线索来自 `WorkspaceX Standalone.html`。
> **运行态原型（入口为推断，私聊能力属原型确认缺失）**：对话屏「**本线程的 AI 团队 · 6** `[编制]`」
> 逐行列出 agent（`AV Ava · 战略分析师 ｜ 在场 ｜ 拆问题、标致命假设、给结论先行` 等六行）
> ——**「点某个 agent 即进入私聊」是本文的推断，原型未渲染任何私聊入口**；
> agent 行已带**三态**（在场 / 跑批中 / 空闲）；
> 后台 Agent 管理行内有 `[试跑]`（与私聊是**两回事**：试跑在后台验证配置，私聊在项目里问事）。
> ⚠ 档案里「私聊」仅 3 处，均指**组员私聊（人与人）**——组长「能看第 2 组的全部对话与组员私聊」，
> 与「人与 agent 的私聊」不是同一件事；「滑出」「不进主线程」**全档案 0 命中**。
> 因此本文的私聊核心行为一律标 `[Backlog]`，**对话屏已完整探明而未见私聊入口 ＝ 原型确认缺失**。

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P1**；估点 **3**（不变）；建议迭代 **迭代 5 · 收尾项**。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-4.3 / 与单个 Agent 私聊
- **Actor**：**引导师**、**组长**（受权时）、**顾问/项目负责人**（作为线程参与者）
- **目标**：[Backlog] 点 AI 团队里某个 agent，右侧滑出与它的**独立对话**，显示它挂载的 skill；
  **对话不进主线程**，可把结论转到主线程。
- **本用例结果**：形成一条与主线程隔离的私聊记录；被转出的结论落到主线程并**带出处**
  （来自哪次私聊、哪个 agent、哪个 skill 版本）。
- **系统边界**：私聊面板、agent 的 skill 清单展示、私聊上下文范围、结论转出与出处携带、
  私聊的权限与留痕。
- **核心数据对象**：私聊会话、消息、agent、skill 挂载（带版本）、转出记录与出处引用、
  工具调用链、审计事件。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 目标 agent 处于 `运行中` 且**可见性范围覆盖当前用户**（UC-4.1）。
  - 当前用户是该线程/项目的合法参与者。
  - [设计] agent 的模型在 20-model 已启用；其工具白名单引用的 MCP 未被隔离（21-mcp）——
    否则私聊仍可开启但需**明确告知能力受限**。
- **触发条件**：
  - [Backlog] 在对话屏「本线程的 AI 团队」列表里**点某个 agent**
    （列表本身 [原型] 存在；「点它进私聊」原型未渲染，属**原型确认缺失**）。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **参与者操作**：点 AI 团队里某个 agent。
   **系统响应**：[Backlog] 右侧滑出与它的**独立对话**，并**显示它挂载的 skill**
   （[原型] 后台侧的计数依据：Ava 12 skills / Scout 8 / Echo 5 / Ledger 6）。
   [设计] 同时显示该 agent 的职责一句话、当前状态（在场/跑批中/空闲）、
   使用的模型（含**降级运行**标注，如 `降级运行 · sonnet`）。
2. **参与者操作**：在私聊里提问。
   **系统响应**：[Backlog] **对话不进主线程**——私聊消息不出现在主线程消息流里，
   也不计入主线程的转录与洞察。
   [设计] 私聊仍受 **UC-4.1 的三层权限**约束
   （MCP 授权范围 × agent 工具白名单 × 任务权限包 R1/R2/R3）——
   **私聊不构成提权**；高风险动作照样弹批准卡。
   [设计] 私聊仍受 **UC-4.2 的项目级 AI 权限**约束
   （如本场关掉「AI 直接在小组画布落笔」，私聊里也不能直接落笔）。
3. **参与者操作**：把某条结论**转到主线程**。
   **系统响应**：[Backlog] 转过去时**带出处**——注明来自与某 agent 的私聊、
   何时、基于哪些 skill（**带版本**）与哪些数据。
   [设计] 转出的内容在主线程中仍标识为**机器产出**，并可点回私聊原文（受权限约束）。
4. **系统收口**：校验 AC1「单聊内容与主线程隔离，转过去时带出处」；
   记录操作者、时间、对象、结果与来源进审计，刷新主线程与相关列表。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] **观察者不可发言，仅可读已发布内容**——观察者无私聊入口。
  - A2：[设计] 与 `跑批中` 的 agent 私聊时，明确提示它正在跑后台任务，
    并给出 `[看任务队列]`（对照 [原型] 批准卡的同名入口）；私聊可继续但可能排队。
  - A3：[设计] 私聊可整条丢弃（不转出任何结论）；丢弃不影响审计留痕。
  - A4：[设计] 无可私聊 agent（团队为空或全部不可见）时展示真实空态与下一步，
    **不生成示例对话**。
- **异常流程**：
  - E1：[设计] agent 在私聊过程中被换出编制（UC-4.2）时，**私聊不被中断**——
    私聊是点对点会话，独立于线程编制；但需提示「它已不在本线程在场名单里」。
  - E2：[设计] agent 依赖失败（模型停用 / MCP 隔离 / 限流中）时，
    私聊**明确失败或明确降级并标注**，不得静默换模型、不得静默跳过工具调用。
  - E3：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，
    明确失败原因并提供安全重试。
  - E4：[设计] 转出到主线程时目标线程已归档/只读，转出被拒并保留私聊内容。
  - E5：[设计] 同一资源被并发修改时不得静默覆盖；提示版本已变化并允许刷新后重提。
  - E6：[设计] 权限在过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留。

## R5 权限与可见性

- **引导师**：可与本线程任意在场/编制内 agent 私聊，可转出结论。
- **协同引导师**：**[待确认]** 权限口径未定——proto-08「参与者与邀请」只证明
  **身份选项存在**（组员 ｜ 组长 ｜ 观察者（只读）｜ 协同引导师），**从未给出任何权限语义**。
  按 `uc-1-3` L111 的禁令：**裁决前不得默认按等同引导师实现**。
  **[待确认]** 是否为第五种项目角色（见 UC-3.2 R5 同一未决项）。
- **组长**：[设计] 可与下发给本组的 agent 私聊；转出目标限本组线程。
- **组员**：[设计] 默认**不可**私聊（与 UC-3.3「组员只能用引导师下发的」同源）；
  是否开放由引导师/角色模板决定。**[待确认]**。
- **观察者（只读）**：[原型] 不可发言，仅可读已发布内容；**无私聊入口**。
- **能力维护者**：在后台用 `[试跑]` 验证 agent 配置——**这不是私聊**，
  两者的上下文、留痕与转出能力都不同，不得复用同一实现而混淆审计归属。
- **项目负责人**：可查看私聊的**审计摘要**（谁在何时与哪个 agent 私聊、
  是否转出、调用了哪些工具）；
  [D-18] **不得因管理身份直接读取私聊正文**——私聊正文属个人/项目层内容，
  管理员读项目内容须留痕且对项目负责人可见。
  **[待确认]** 私聊正文归属「个人层」还是「项目层」——直接决定管理员能不能看。
- **可见性范围**：只有可见性范围覆盖当前用户的 `运行中` agent 才可私聊。
- 未登录、链接失效或未列出的角色：默认无权限；接口不得返回越权数据。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 私聊记录存在且**与主线程隔离**；转出的结论在主线程中**带完整出处**。
  - [Backlog验收] AC1：单聊内容与主线程隔离，转过去时带出处。
  - [设计验收] AC2：私聊**不构成提权**——三层权限与项目级 AI 权限在私聊中同样生效。
  - [设计验收] AC3：私聊中的工具调用同样进入 **tool-call 级审计**（UC-4.4）。
- **失败后置条件**：
  - 不产生「以为转出了其实没进主线程」或「转出内容无出处」的状态；
    失败事件进可观测日志。
- **不包含**：
  - **Agent 自主扩大权限**、未经批准的高风险动作。
  - Agent 的注册、工具白名单与发布——见 **UC-4.1**。
  - 线程级团队编制与按状态载入——见 **UC-4.2**。
  - 行为审计与 agent 互调留痕——见 **UC-4.4**。
  - 后台的 `[试跑]`——属 UC-4.1。
  - 主线程的转录、洞察、产物三栏——属 08-chat。

## R7 业务规则（不随具体实现变化的硬性约束）

- [Backlog] **对话不进主线程**；转到主线程时**必须带出处**。
- [原型] **观察者不可发言，仅可读已发布内容。**
- **[设计] 私聊不构成提权**——UC-4.1 的三层权限（MCP 授权 × 工具白名单 × 任务权限包）
  与 UC-4.2 的项目级 AI 权限在私聊中同样生效。
- **[设计]** 私聊中的高影响动作照样走批准点，未经确认只保留为草稿或候选。
- **[设计]** 转出的结论必须记录 **agent + skill 版本 + 数据来源**，可回溯。
- **[设计]** 依赖失败时明确失败或明确降级并标注，**不静默换模型、不静默跳过工具调用**。
- AC1：单聊内容与主线程隔离，转过去时带出处。
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 私聊发起、转出、工具调用都必须记录审计事件，并显示动作影响范围。

## R8 界面线索

- **前端入口**：[原型] 对话屏「**本线程的 AI 团队 · 6**」列表存在
  （已带三态与一句话能力描述）；[Backlog] 「点某个 agent 进私聊」——
  该入口**原型确认缺失**，需补画。
- **信息架构**：[Backlog] 私聊为**右侧滑出**的独立面板，与主线程并存不替换
  （「滑出」在原型档案 0 命中）。
- **推荐交互**：
  - [设计] 面板顶部固定显示：agent 缩写角标 + 名字 + 职责 + **状态** + 模型
    （含 `降级运行 · sonnet` 标注）+ **它挂载的 skill 清单**（原型明确要求显示）。
  - [设计] 每条结论旁提供 `[转到主线程]`；转出前预览将携带的出处。
  - [设计] 与 `跑批中` agent 私聊时顶部给出 `[看任务队列]`。
  - [设计] 私聊消息与主线程消息在视觉上明确区分，避免误以为已同步。
- **必须呈现的状态**：默认态、加载态、空态、校验失败态、
  依赖失败态（模型停用 / MCP 隔离或限流）、无权限态（观察者/组员）、成功态。
  （七种必现状态按 D-36 统一规范实现。）
- **原型参考**：
  - `phases/requirements/WorkspaceX Standalone.html` — 对话屏「本线程的 AI 团队 · 6」
- **UI sign-off**：
  - **AI 团队列表已存在，可直接签**（但它只是列表，不等于私聊入口）。
  - **私聊入口与面板 ＝ 原型确认缺失**——对话屏（左栏 AI 团队 / 中栏消息流 / 输入区 /
    右栏五标签）已完整探明，**未见任何人与 agent 的私聊入口或面板**；
    档案中的「私聊」全部指组员之间的人际私聊。
    右侧滑出布局、skill 清单呈现、`[转到主线程]` 的位置与出处预览**均需补画原型**，
    不是「回去再抽一次就有」。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 面板滑出与历史加载应在 1 秒内可感知；私聊历史分页加载。
  - [设计] 私聊与主线程共用同一套模型调用与配额，计入该 agent 的用量与降级判定。
- **安全/隐私/合规**：
  - 私聊正文按其归属层（个人层 / 项目层，**[待确认]**）适用相应的可见性与留存策略。
  - [D-14] 私聊内容的留存期按「材料保留期 / 留痕保留期」参数执行，项目级可覆盖。
  - 私聊中的工具调用**全量留痕**；涉客户数据的调用留痕 180 天（21-mcp 安全策略）。
  - 含客户机密的私聊内容按 UC-9.3 硬路由，**只走自托管模型**。
- **兼容与降级要求**：
  - 响应式 Web；移动端至少保证查看私聊与转出两个动作。
  - 实时通道不可用时降级为轮询并显示「非实时」；断网保留未提交输入但不得伪装已同步。

## R11 切分提示（给 requirement-author）

- 建议拆分顺序：私聊会话模型与隔离 → 面板与 skill 清单展示 → 三层权限与项目级 AI 权限
  在私聊中的生效 → 转出到主线程并携带出处 → 依赖失败与降级标注 → 审计（含 tool-call）→
  自动化验收。
- 「私聊不构成提权」应单独成 feature 并有**越权尝试被拒绝**的验收。
- **优先级 / 先后依赖**：P1；3 点；迭代 5；依赖 UC-4.1、UC-4.2。

## R12 AI Ready 验收线索

- V1（成功态）：AC1 —— 与某 agent 私聊后把一条结论转到主线程；
  主线程该条带完整出处（agent + skill 版本 + 时间 + 数据来源），且私聊内容未出现在主线程。
- V2（提权态）：AC2 —— 在私聊里请求一个不在该 agent 工具白名单内的工具，被拒绝；
  把项目级「AI 直接在小组画布落笔」关掉后，私聊里也无法直接落笔。
- V3（审计态）：AC3 —— 私聊中的每次工具调用都出现在 UC-4.4 的 tool-call 级审计里。
- V4（隔离态）：私聊消息不进入主线程的转录、洞察、产物三栏，也不计入线程消息数。
- V5（权限态）：观察者无私聊入口且接口拒绝；组员默认不可私聊；
  逐一使用 引导师 / 协同引导师 / 组长 / 组员 / 观察者 / 未授权用户验证符合 R5。
- V6（可见性态）：标为「仅能源组」的 agent 对平台组成员不可私聊，接口不返回其存在性。
- V7（依赖失败态）：把该 agent 的模型停用，私聊明确失败或明确降级并标注，不静默换模型。
- V8（跑批态）：与 `跑批中` 的 agent 私聊时给出明确提示与 `[看任务队列]`。
- V9（换出态）：私聊过程中该 agent 被换出编制，私聊不中断但提示「已不在在场名单」。
- V10（空态）：无可私聊 agent 时显示真实空态与下一步，不生成示例对话。
- V11（转出失败态）：目标线程已归档时转出被拒并保留私聊内容。
- V12（审计态·全量）：私聊发起、转出、工具调用可按操作者、时间、agent、skill 版本检索。
