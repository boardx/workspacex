# 原始需求（细化）— UC-4.2 按状态载入 Agent

> 所属：阶段一 · 能跑完一场项目 / M4 上传 Agent
> 来源：`Backlog Use Case.html` 的 UC-4.2；UI 线索来自 `WorkspaceX Standalone.html`。
> **运行态原型**：
> **① 线程级 AI 团队编制**（对话屏右上/侧栏）：
> ```
> 本线程的 AI 团队 · 6    [编制]
>   AV Ava · 战略分析师    在场    拆问题、标致命假设、给结论先行
>   AT Atlas · 流程诊断    在场    把业务流拆成任务，标可自动化环节
>   SC Scout · 同行情报    在场    找同行 AI 落地案例与一手材料，带引用
>   LG Ledger · 收益测算   跑批中  算人天节省、单位成本与回本周期
>   WD Warden · 风险与合规 在场    数据出域、隐私、模型使用红线
>   EC Echo · 访谈综合     空闲    转录一线访谈、抽引述、合并同类观点
>   ＋ 从 Agent 市场加入
> ```
> 线程列表「欧洲储能进入策略 · 假设梳理 ● 转录中 **4 个 agent**」；线程头部「**团队 4**」。
> **② 配置面 —— 蓝本第 12 项「Agent 编排 **4 个**」**（16 项设计配置的「AI 能力」组，
> 与第 13 项「Skill 绑定 11 个」并列）；蓝本「套用后会初始化什么」里的
> 「现场：**按状态载入的 agent 与 skill**」。
> **③ 项目级 AI 权限开关**（批次 8：`项目 → [进入项目] → 设置 → **AI 权限**`，3 项 · 1 项已关）：
> `Facilitator 主动提议收敛` ｜ `实时转录与语音转便签` ｜ `AI 直接在小组画布落笔`。
> **④ 改派提示**（对话输入区上方）：
> 「**这条更适合 Scout：它有行业数据库授权**，改派后本轮由它回答 `[改派]` `[×]`」。
> **⑤ 项目实例级议程环节编排**（批次 8：`设置 → 工作流编排`）议程环节行的绑定槽里出现
> 「25m · **Scout 简报**」——即 agent 也可绑在议程环节上。

> **[术语正名 · D-03]** 本文严格区分三个互不相同的概念：
> **16 项设计配置**（蓝本设计器的固定维度，Agent 编排是**第 12 项**）·
> **N 个议程环节**（随时长档位变化：半天 7 / 一天 11 / 两天 14 / 三天 19，
> 也随所选工作流模板变化）· **9 个方法环节**（推演流水线横轴 PESTEL→PRD，与本用例无关）。
> **本用例的「环节」一律指「议程环节」**——载入规则的触发源是**议程环节的切换与状态变化**，
> 不是蓝本 16 项、也不是推演流水线九环节。
> 唯一例外：头部原型引文里 Atlas 的职责描述「标可自动化**环节**」是**业务流程环节**，
> 属原型原文，不作正名。

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **8**（原 5，因线程级编制 + 蓝本第 12 项配置面 +
> 项目级 AI 权限 + 基于 MCP 授权的改派路由上调）；建议迭代 **迭代 2 · 能挂能力**。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-4.2 / 按状态载入 Agent
- **Actor**：**引导师**（现场主持人 / 编制者）、**能力维护者**（蓝本第 12 项默认值的维护者）、
  **参与者**（对话中被改派提示的人）
- **目标**：[Backlog] 让「谁在场」随现场状态自动变化——蓝本里写好触发条件 → 载入哪些 agent；
  现场状态一变（切**议程环节**、某组停滞、投票进行中）就换人换技能，并写明「因什么载入」。
  ⚠ 口径说明：**「因什么载入」在原型档案 0 命中**——原型只写实了「AI 团队 · 6」的静态列表
  与三态徽标，没有任何载入原因的呈现。
- **[原型] 载入有三个粒度**（与 UC-3.2 的 skill 三级绑定同构）：
  1. **蓝本/模板级** —— 蓝本第 12 项「Agent 编排」定义**按状态载入的规则**（原型：4 个）；
  2. **项目实例级** —— `设置 → 工作流编排` 的**议程环节**行可直接绑 agent（原型：「Scout 简报」），
     且 `设置 → AI 权限` 提供**项目级行为开关**；
  3. **线程级** —— 对话屏「本线程的 AI 团队 · 6」＋ `[编制]`，可临时增减。
- **本用例结果**：每条对话线程持有一份「当前在场的 AI 团队」及其**三态**；
  线程列表与头部显示 agent 计数（原型：4）；每次载入/换出都可解释原因。
- **系统边界**：载入规则模型、状态事件监听、规则求值与优先级、线程级团队编制、
  三态呈现、项目级 AI 权限开关、改派路由、可解释性（因什么载入）。
- **核心数据对象**：载入规则（触发条件 → agent 集合 × 优先级）、线程 AI 团队、
  agent 在场态（在场 / 跑批中 / 空闲）、项目级 AI 权限开关、改派建议、载入日志。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 存在至少一个 `运行中` 且可见性范围覆盖本项目/本团队的 agent（UC-4.1）。
  - 蓝本第 12 项已配载入规则，或项目实例级已在**议程环节**行绑了 agent，或线程手工编制过。
  - 项目已套用工作流模板并有可推进的**议程环节**（UC-3.2 / UC-2.2）。
- **触发条件**：
  - [Backlog] **现场状态变化**——切**议程环节**、某组停滞、投票进行中。
  - [原型] 引导师在对话屏点 `[编制]` 手工调整线程 AI 团队。
  - [原型] 引导师点 `＋ 从 Agent 市场加入` 临时加入一个 agent。
  - [设计] 组长切换**议程环节**状态（[原型 · 批次 8]「组长切换环节状态后，
    三种视角的首屏立刻跟着换」）同样触发重新求值。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

### 阶段一 · 配置载入规则（蓝本第 12 项）

1. **能力维护者/引导师操作**：在**蓝本设计器 → 12 Agent 编排**里定义规则——
   「**触发条件 → 载入哪些 agent**」（[原型] 蓝本目录显示「12 Agent 编排 **4 个**」，
   即本蓝本配了 4 条编排项）。
   **系统响应**：校验被引用的 agent 处于 `运行中` 且可见性范围覆盖本蓝本的使用者；
   记录 agent 版本。
   **[未探明]** 「4 个」指 4 条规则还是 4 个 agent——**配置面板内部未探明**，见 R8。
2. **能力维护者/引导师操作**：为规则设**优先级**。
   **系统响应**：[Backlog] **同时命中多条规则时按优先级取前 4 个，避免刷屏**
   （「取前 4」「刷屏」原型档案 0 命中；[原型] 对话屏确有「团队 4」「4 个 agent」的计数，
   但那是**在场计数的示例数据**，不构成裁剪规则的证据）。

### 阶段二 · 项目实例级覆盖

3. **引导师操作**：在 `项目 → 设置 → 工作流编排` 的**议程环节**行绑定槽里直接绑 agent
   （[原型]「02 现状共识 25m · **Scout 简报**」）。
   **系统响应**：[原型 · 硬规则]「改动只影响这场项目，**不会动后台的模板本体**」
   （继承语义与 UC-3.2 完全一致）。
4. **引导师操作**：在 `项目 → 设置 → **AI 权限**` 里开关**项目级 AI 行为**。
   **系统响应**：[原型] 三个开关（本场 3 项 · **1 项已关**）：
   - `Facilitator 主动提议收敛`
     —— 对应说明页规则「AI 主动插话：默认开，**单个 agent 可关**」的**项目级**落法；
   - `实时转录与语音转便签`
     —— 对应现场转录与画布 skill 的总开关；
   - `AI 直接在小组画布落笔`
     —— 对应 [D-10]「AI 画布写权限：**默认直接落笔**（带 AVA 角标 + 可一键回滚），
       可按画布改为『提交建议待接受』」。
   **[人类需注意的粒度]** [原型] 这三项是**项目级**开关，**既不是全局、也不是单画布级**。
   [设计] 因此 AI 行为权限至少有**三个粒度**，且**收紧优先**（任一层关闭即关闭）：
   | 粒度 | 位置 | 例 |
   |---|---|---|
   | **组织/agent 级** | UC-4.1 R3 第 6 步 | 「需要批准的 agent 默认不主动插话」；单个 agent 可关插话 |
   | **项目级** | 本用例（`设置 → AI 权限`） | 本场关掉「AI 直接在小组画布落笔」 |
   | **画布/线程级** | 07-canvas / 本用例 `[编制]` | [D-10] 可按画布改为「提交建议待接受」；引导师可静音全部主动插话 |
   **[已裁决 O-23]** 原问题：三个粒度的**合成规则**（此前按「收紧优先」处理，需确认）
   与三个开关的默认值。
   **裁决（O-23）**：**合成规则 ＝ 取交集（收紧优先），且不可被下层放宽**——
   `有效权限 = 组织/agent 级 ∩ 项目级 ∩ 画布/线程级`，**任一层收紧即生效**；
   下层**只能更严，不能更松**（项目级关掉的，画布级不能打开）。
   同一规则适用于 D-07 的三层权限模型
   （`有效权限 = MCP授权范围 ∩ agent工具白名单 ∩ 任务权限包`，见 UC-4.1 R7）。
   理由：这是唯一在安全上可辩护的合成方式。
   **三个 AI 权限开关默认全关**——AI 默认不主动动作，需项目显式开启，
   与 D-27「AI 生成的卡一律落 inbox 草稿态」的保守取向一致。
   ⚠ 实现上必须是**服务端求交**，不得由任一层自行决定最终值。

### 阶段三 · 运行时载入与呈现

5. **系统处理**：监听现场状态事件（切**议程环节** / 某组停滞 / 投票进行中 / 转录开始…），
   对载入规则求值。
   **系统响应**：[Backlog] 现场状态一变就**换人换技能**，并**写明「因什么载入」**；
   命中多条时按优先级取前 4 个。
6. **系统处理**：把求值结果投影为**线程级 AI 团队**。
   **系统响应**：[原型] 对话屏呈现「**本线程的 AI 团队 · 6** `[编制]`」，
   每个 agent 一行：`缩写角标 ｜ 名字 · 职责 ｜ **状态** ｜ 一句话能力描述`。
   [原型] **状态三取值**：
   - **在场**——已载入、可随时发言（Ava / Atlas / Scout / Warden）；
   - **跑批中**——正在执行后台任务（Ledger；对照批准卡「批准后转后台任务，
     约 6 分钟回到本线程」）；
   - **空闲**——在编制内但当前无任务（Echo）。
   [设计] **注意计数口径**：侧栏「AI 团队 · **6**」是**编制人数**，
   而线程列表/头部的「**4 个 agent**」「团队 **4**」是**当前在场数**，两者不等，
   实现时必须分别标注，不得混用。
7. **引导师操作**：点 `[编制]` 手工调整团队；或 `＋ 从 Agent 市场加入` 临时加入。
   **系统响应**：手工编制**覆盖**本轮规则求值结果，直到下一次状态变化或引导师复位；
   [Backlog] 引导师可**手动加载或静音全部主动插话**
   （「静音」原型档案 0 命中；原型只有说明页的「AI 主动插话默认开，**单个 agent 可关**」
   与项目设置的「Facilitator 主动提议收敛」开关，均非「引导师一键静音全部」）。
   **[未探明]** `[编制]` 与 `＋ 从 Agent 市场加入` 点开后的面板未抽取，见 R8。
8. **系统处理**：**下一议程环节要换的 agent 提前提示**（[Backlog] `Backlog Use Case.html`
   的 UC-4.2 原文；原型无此呈现）。
   [设计] 提示落在主持台，让引导师有准备时间。
9. **系统处理**：**改派路由**——[原型] 对话输入区上方出现
   「**这条更适合 Scout：它有行业数据库授权**，改派后本轮由它回答 `[改派]` `[×]`」。
   **系统响应**：
   - **判据是 MCP 授权集**——「它有**行业数据库**授权」直接对应 21-mcp 的
     「行业数据库（Wind＋Statista）· 28 工具 · 全体成员 · ● 已连接」。
     [设计] 改派建议 ＝ 把当前问题所需的工具/数据源，与在场各 agent 的
     **三层权限求交结果**（UC-4.1 R3）比对，选出唯一有该授权的 agent。
   - **[设计] 改派是建议不是自动执行**——必须人点 `[改派]`；`[×]` 可忽略。
   - **[设计]** 改派理由必须写出**具体授权名**（如「行业数据库授权」），不得只说「更合适」。
10. **系统收口**：校验 AC1「主持台能看到当前载入了谁、**为什么**、下一步会换成谁」、
    AC2「线程 AI 团队的三态与计数口径正确」、AC3「项目级 AI 权限开关关闭后对应行为立即停止」；
    记录载入原因、触发事件、被换出的 agent、优先级裁剪结果进审计。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[Backlog] 引导师可**手动加载**或**静音全部主动插话**。
  - A2：[原型] `＋ 从 Agent 市场加入`——从组织 Agent 库（[D-06 同源] phase-1 不含外部市场）
    临时加入一个 agent 到本线程。
  - A3：[设计] 引导师可把手工编制**复位**为规则求值结果。
  - A4：[设计] 线程无任何 agent 时展示真实空态与「从 Agent 市场加入」入口，
    **不自动塞一个默认 agent**。
  - A5：[设计] 项目级 AI 权限某项被关闭时，依赖它的 agent/skill 在编制列表里标为
    「本场已关闭」并说明去哪里开，**不静默不工作**。
- **异常流程**：
  - E1：[Backlog] **同时命中多条规则时按优先级取前 4 个，避免刷屏**；
    [设计] 被裁剪掉的 agent 必须可查（「本可载入但被优先级裁剪」），不得静默丢弃。
  - E2：[设计] 规则引用的 agent 已不在 `运行中`（被退回/依赖失败）时跳过该 agent
    并在主持台明确提示，**不静默降级为别的 agent**。
  - E3：[设计] agent 的可见性范围不覆盖当前项目/团队时不得载入（如 Ledger「仅能源组」
    不能被平台组的项目载入）。
  - E4：[设计] `跑批中` 的 agent 在**议程环节**切换时**不被强制换出**——
    后台任务跑完仍要回到本线程（[原型]「批准后转后台任务，约 6 分钟回到本线程」）；
    换出只影响它是否继续主动发言。
  - E5：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，
    明确失败原因并提供安全重试。
  - E6：[设计] 同一蓝本/项目编排被并发修改时不得静默覆盖；提示已变化并允许刷新后重提。
  - E7：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留。
  - E8：[设计] 实时通道不可用导致状态事件延迟时，**必须显示「非实时」并给出最后更新时间**，
    不得让引导师以为团队已切换。

## R5 权限与可见性

- **引导师**：可配规则（蓝本/项目实例）、可 `[编制]`、可手动加载/静音、可改派、
  可开关**项目级 AI 权限**三项。
- **协同引导师**：原问题——权限口径未定；proto-08「参与者与邀请」的**身份四选**
  （组员 ｜ 组长 ｜ 观察者（只读）｜ 协同引导师）只证明**选项存在**，**从未给出权限语义**；
  它是否为第五种项目角色（见 UC-3.2 R5 同一未决项）。
  **[已裁决 O-03]**：**协同引导师 ＝ 引导师的多实例**，**项目角色仍为四种**。
  一场项目可有多名引导师，其中一名为**主持人**，**最终确认权归主持人**（依据 `uc-6-4` R5）。
  故其在本用例中**与引导师同权**（可配规则、可 `[编制]`、可加载/静音/改派），
  但**项目级 AI 权限三开关的变更须由主持人确认**（它改变全场 AI 行为边界）。
- **能力维护者**：维护蓝本第 12 项的默认规则；决定哪些 agent 进入可载入池（经 UC-4.1 发布）；
  **不代替引导师做现场编制**。
- **审核人**：不参与载入；其职责止于 agent 发布（UC-4.1 R5）。
- **组长**：[原型] 可切换**议程环节**状态（从而间接触发重新载入）；可见本组在场的 agent；
  **不能改编制**。
- **组员**：只看到载入到自己对话里的 agent；不可编制、不可改派。
  **[待确认]** 组员是否能看到改派提示。
- **观察者（只读）**：[原型]「观察者链接只读已发布内容」；
  [设计] 可见在场 agent 名单，不可见规则、不可操作。
- **项目负责人**：可查看编制与载入日志；写操作需显式授权。

  9. 依赖失败与实时降级（非实时标注）
  10. 审计 + 自动化验收
- 第 2、4、7、8 四项应各自成 feature：它们分别对应「自动换人」「可解释」「项目级权限」
  「授权驱动的路由」四个独立可验收的行为。
- **优先级 / 先后依赖**：P0；8 点；迭代 2；依赖 UC-4.1、UC-3.2、UC-21.1。

## R12 AI Ready 验收线索

- V1（成功态）：AC1 —— 切**议程环节**后主持台显示当前载入了谁、**因什么载入**、
  下一**议程环节**将换成谁；每条载入记录可点开看触发事件与命中规则。
- V2（裁剪态）：AC5 —— 构造同时命中 6 条规则的状态，只载入前 4 个，
  被裁剪的 2 个可在「本可载入但被优先级裁剪」中查到。
- V3（计数态）：AC2 —— 编制 6 个 agent、其中 4 个在场时，
  侧栏显示「AI 团队 · 6」、线程头部显示「团队 4」，两个接口字段分别返回且不混用。
- V4（三态）：Ledger 触发后台任务时状态变为 `跑批中`，任务完成后回到本线程；
  切**议程环节**不强杀它。
- V5（项目权限态）：AC3 —— 在 `设置 → AI 权限` 关掉「AI 直接在小组画布落笔」，
  AI 在本场画布上只能提交建议待接受；关掉「Facilitator 主动提议收敛」后该行为立即停止；
  开关变更留痕且对项目成员可见。
- V6（粒度态）：agent 级已关插话但项目级已开时，**仍不插话**（收紧优先）。
- V7（改派态）：AC4 —— 提出一个需要行业数据库的问题，出现
  「这条更适合 Scout：它有行业数据库授权」的建议；**不点 `[改派]` 则不改派**；
  把行业数据库 MCP 置为已隔离后，该建议不再出现。
- V8（可见性态）：Ledger 标为「仅能源组」时，平台组的项目无法载入它，
  规则命中亦被跳过并在主持台提示。
- V9（依赖失败态）：把某规则引用的 agent 退回为 `待审核`，载入时跳过并明确提示，
  **不静默换成别的 agent**。
- V10（实时降级态）：断开实时通道，界面显示「非实时」与最后更新时间，
  不出现「已切换」的假象。
- V11（幂等态）：同一状态事件重复投递，团队不重复载入、计数不翻倍。
- V12（权限态）：逐一使用 引导师 / 协同引导师 / 能力维护者 / 组长 / 组员 / 观察者 /
  未授权用户访问，可读数据与可执行动作严格符合 R5。
- V13（空态）：线程无任何 agent 时显示真实空态与加入入口，不自动塞默认 agent。
- V14（审计态）：载入、换出、编制变更、AI 权限开关变更、改派可按操作者、时间、
  线程、触发事件检索。
- V15（三粒度求交 · O-23）：agent 级允许插话、项目级关闭「AI 主动提议收敛」→
  该行为**关闭**；再在画布/线程级尝试打开 → **无法放宽**，仍关闭。
- V16（默认全关 · O-23）：新建项目时三个 AI 权限开关默认值均为**关**。
- V17（停用不进池 · O-22④）：把某 agent 停用 → 它从可载入池消失；
  已锁版本的在跑项目不受影响。
- V18（锁版本载入 · O-22⑤）：现场载入的是**项目开工时锁定的 agent 版本**，
  后台改动不影响运行期。
- V19（并发排队 · O-22②）：并发已满时命中载入规则 → 任务**排队**并显示位次，
  不出现「载入失败」。
