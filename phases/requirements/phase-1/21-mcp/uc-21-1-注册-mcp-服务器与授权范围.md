# 原始需求（细化）— UC-21.1 注册 MCP 服务器与授权范围

> 所属：阶段一 · 能跑完一场项目 / **M21 MCP 服务器**（新增模块 21-mcp）
> 来源：**运行态原型** 后台 → AI 能力 → **MCP 服务器（6 台 · 5 台已连接 · 1 台隔离待评审）**：
> ```
> [＋ 添加服务器]   表头：服务器 ｜ 端点 ｜ 工具 ｜ 授权范围 ｜ 状态
> 客户 CRM（Salesforce 桥接）    mcp://crm.internal:7301   12 工具  仅项目负责人  ● 已连接
> 行业数据库（Wind＋Statista）   mcp://data.wsx.cn:443     28 工具  全体成员      ● 已连接
> 交付物知识库（历史项目全文检索）mcp://kb.internal:7310    6 工具   全体成员      ● 已连接
> 企业微信（通知与审批推送）      mcp://wecom.gw:8080       4 工具   全体成员      ● 限流中
> 欧盟法规库（第三方·未审计）     mcp://eu-reg.vendor.eu    9 工具   待安全评审    ● 已隔离
> ```
> **本模块被消费的四处证据**：
> ① 对话屏工具调用明细 `mcp:行业数据库.query_market(region:"DE")　运行中`
>    ——MCP 工具在调用链里以 `mcp:<服务器>.<工具>` 命名空间出现（UC-4.4）；
> ② 对话屏改派提示「这条更适合 Scout：**它有行业数据库授权**」——授权集驱动路由（UC-4.2）；
> ③ 后台 Agent 管理待审核项「**工具白名单里有一条越权申请待确认**」——白名单条目对照授权范围（UC-4.1）；
> ④ 任务屏「等待输入 R2『核对客户方联系人与决策链』**阻塞：Echo 请求读取「客户 CRM」，
>    权限包里没有** `[去授权]`」＋「我的今天」的「**R1·授权** Echo 请求读取「客户 CRM」以核对联系人
>    —— 是否把 CRM 读取权限加入**这次任务的权限包**？」
>    ——第三层「任务权限包」的真实运行态。
> **补写缘由**：原需求文档对 MCP 管理**零覆盖**，而 UC-4.1 的「能读哪些数据」、
> UC-4.2 的改派路由、UC-4.4 的越权拦截全都以它为数据源。不建这个模块，三层权限模型缺第一层。

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **8**；建议迭代 **迭代 2 · 能挂能力**（须早于 UC-4.1 的工具白名单）。
>
> **[人类已拍板 · D-07]** MCP 管理进 phase-1，最小子集 ＝ **注册 ＋ 授权范围 ＋ 默认隔离**；
> **丢掉调用量统计**（被砍项写入 R6）。
> **[人类已拍板]** 权限模型**三层**：
> **① MCP 授权范围（本用例） × ② agent 工具白名单（UC-4.1） × ③ 任务权限包 R1/R2/R3（00-core）**。
> **[编号提示 · 待确认]** `UC-10.x` 与 **phase-2 的 `10-report`（UC-21.1～10.4）冲突**，
> `20-model` 与 `09-kg` 同理。**需人类裁决全局重编号方案**，本文按协调方指定的编号书写。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-21.1 / 注册 MCP 服务器与授权范围
- **Actor**：**组织管理员**（注册与授权）、**安全评审人**（放行隔离服务器，见 UC-21.2）、
  **能力维护者**（在 agent 工具白名单里引用这些工具，见 UC-4.1）
- **目标**：[原型] 把外部/内部的能力源以 MCP 服务器形式接进组织，
  声明它有多少个工具、**开放给谁**、当前连得上连不上——
  从而为「agent 能读哪些数据」提供**权威的第一层来源**。
- **本用例结果**：MCP 服务器清单中新增一条记录，带**端点、工具清单、授权范围、连接状态**；
  其工具随即可被 agent 工具白名单引用（受授权范围约束）；
  新注册的服务器**默认隔离**，须经人工评审放行（UC-21.2）。
- **系统边界**：服务器注册、端点与凭据、**工具发现与清单**、**授权范围**、
  连接状态监测、默认隔离、工具命名空间、被消费方（agent 白名单 / 调用链 / 改派路由）的契约。
- **核心数据对象**：MCP 服务器、端点、凭据、**工具**（名称 / 签名 / 参数 schema /
  是否涉客户数据）、**授权范围**、连接状态、隔离与放行记录、审计事件。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 当前用户是**组织管理员**。
  - 目标 MCP 服务器已部署且端点可达（内网如 `mcp://crm.internal:7301`
    或公网如 `mcp://data.wsx.cn:443`）。
  - [UC-21.2] 安全策略开关「**新服务器默认隔离，需人工评审后放行**」处于开启态。
- **触发条件**：
  - [原型] 管理员在后台 → AI 能力 → MCP 服务器点 **`[＋ 添加服务器]`**；
  - [设计] 或对已注册服务器修改授权范围 / 重新发现工具 / 处置连接异常。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **组织管理员操作**：点 `[＋ 添加服务器]`，填**服务器名称、说明、端点、凭据**。
   **系统响应**：[原型] 名称带括号说明（如「客户 CRM（**Salesforce 桥接**）」
   「行业数据库（**Wind＋Statista**）」「交付物知识库（**历史项目全文检索**）」
   「企业微信（**通知与审批推送**）」「欧盟法规库（**第三方·未审计**）」）——
   [设计] 说明字段是给人判断「这台服务器是干什么的、可不可信」的关键信息，**必填**。
   凭据加密存储、**永不回显**（与 UC-9.1 同一安全约束）。
2. **系统处理**：**工具发现**——连上服务器枚举其提供的工具。
   **系统响应**：[原型] 列表显示工具数（12 / 28 / 6 / 4 / 9 工具）。
   [设计] 每个工具需记录：**工具名、函数签名、参数 schema**，
   并标注**是否涉客户数据**（决定 UC-21.2 的「全量留痕 180 天」是否适用）。
   工具在系统内的唯一命名为 **`mcp:<服务器>.<工具>`**
   （[原型] 调用链里的 `mcp:行业数据库.query_market`）——
   **这是与内建工具（`graph.` / `brain.`）区分的命名空间**，UC-4.4 依赖它。
3. **系统处理**：**新注册的服务器默认置为 `已隔离`**。
   **系统响应**：[原型] 安全策略「✓ **新服务器默认隔离，需人工评审后放行**」；
   隔离态的服务器**其工具不可被任何 agent 调用**，也不进入工具白名单可选池。
   放行流程见 **UC-21.2**。
4. **组织管理员操作**：设置**授权范围**。
   **系统响应**：[原型] 已观察到的取值：
   - **`仅项目负责人`**（原型：客户 CRM —— 客户数据，收紧）；
   - **`全体成员`**（原型：行业数据库 / 交付物知识库 / 企业微信）；
   - **`待安全评审`**（原型：欧盟法规库 —— 第三方·未审计）。
   **[设计 · 重要建模提示]** 「待安全评审」在原型里出现在**授权范围列**，
   但它在语义上是**评审状态**而非**授权对象**——
   本文按「**授权范围**（谁能用）与**评审状态**（能不能用）是两个正交字段」建模，
   界面上可合并展示。**[待确认]** 需产品确认原型是合并列还是真的三取值。
   **[设计]** 授权范围的取值应与 `uc-0-3` 的角色本体对齐；
   [待确认] 是否还需要「仅某团队」一档（对照 agent / skill 的可见性范围）。
5. **系统处理**：**连接状态**监测。
   **系统响应**：[原型] 三取值 **`● 已连接` / `● 限流中` / `● 已隔离`**。
   [设计] 语义分别为：
   - `已连接`——可正常调用；
   - `限流中`——[原型] 企业微信处于此态；调用会被节流，**必须明确告知调用方而非静默排队**；
   - `已隔离`——不可调用（新注册默认态，或被评审判定隔离）。
   [设计] 另需 `不可达` / `凭据失效` 两种失败态（原型未见，但监测必然产生），
   **[待确认]** 是否并入 `已隔离` 显示。
6. **系统处理**：把服务器与工具投影给三个消费方。
   **系统响应**：
   - **UC-4.1 工具白名单**：候选池 ＝ `已连接`（或 `限流中`）∩ 授权范围覆盖该 agent 使用者
     的服务器的工具；超出授权范围的申请以「**越权申请待确认**」形态保留待审核人裁决；
   - **UC-4.2 改派路由**：agent 的「有哪些授权」即其白名单在本清单上的投影
     （[原型]「它有**行业数据库**授权」）；
   - **UC-4.4 审计**：调用链以 `mcp:<服务器>.<工具>` 记录函数签名、参数、命中数、运行态。
7. **系统处理**：**第三层「任务权限包」的运行态对接**。
   **系统响应**：[原型] 即使服务器已连接且 agent 白名单里有该工具，
   **单次任务仍可能缺权限**——任务屏原文：
   「等待输入 R2『核对客户方联系人与决策链』**阻塞：Echo 请求读取「客户 CRM」，
   权限包里没有** `[去授权]`」；
   「我的今天」的授权分区：「**R1·授权** Echo 请求读取「客户 CRM」以核对联系人 ——
   **是否把 CRM 读取权限加入这次任务的权限包？**」
   [设计] 因此本用例需向任务模块暴露「**申请把某工具加入本次任务权限包**」的接口，
   授权动作由**人**在任务侧完成，**agent 不能自行加**。
8. **系统收口**：校验 AC1「MCP 清单中每台服务器都能看到端点、工具数、授权范围与连接状态」、
   AC2「**新注册的服务器默认隔离，其工具不可被调用**」、
   AC3「**授权范围之外的成员无法通过任何 agent 使用该服务器的工具**」；
   记录注册、工具发现、授权范围变更、状态变化进审计。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] **重新发现工具**——服务器升级后工具增减，需可手动触发重新枚举；
    新增工具**默认不进任何已有白名单**（避免权限静默扩大）；
    删除的工具在引用它的 agent 上标为「工具已不存在」。
  - A2：[设计] 修改授权范围（收紧或放宽）时，**列出受影响的 agent 与进行中任务**；
    收紧立即生效，放宽亦需留痕。
  - A3：[设计] 清单为空时展示真实空态与 `[＋ 添加服务器]`，**不预置示例服务器**
    （原型每屏都填满样例数据，零空态）。
  - A4：[设计] 支持按状态与授权范围筛选（原型标题行已给出「6 台 · 5 台已连接 ·
    1 台隔离待评审」的分组计数）。
- **异常流程**：
  - E1：[设计] 端点不可达或凭据无效时**注册失败**，不落半截记录；
    已注册的服务器转不可达时状态变更并通知管理员，
    引用其工具的 agent 明确告知能力受限（UC-4.1 E3），**不静默跳过工具调用**。
  - E2：[原型] `限流中` 时调用被节流——[设计] 必须**明确告知调用方**
    （对话里显示「企业微信限流中，通知延迟」），不得静默丢弃或无限排队。
  - E3：[设计] `已隔离` 的服务器被调用时**直接拒绝并计入越权拦截计数**（UC-4.4）。
  - E4：[设计] 工具的参数 schema 变更导致已有白名单条目失配时，
    该条目标为「签名已变更，需重新确认」，**不自动接受新签名**。
  - E5：[设计] 涉客户数据的工具在留痕不可用时**调用必须失败**
    （对照 UC-4.4 R7「没有留痕就没有调用」与 UC-21.2 的 180 天留痕开关）。
  - E6：[设计] 请求超时或依赖不可用时保留已填内容，明确失败并可安全重试。
  - E7：[设计] 同一服务器被并发配置时不得静默覆盖；提示已变化并允许刷新后重提。
  - E8：[设计] 权限在过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留。

## R5 权限与可见性

- **组织管理员**：唯一可注册、配置、设置授权范围、处置连接异常的角色；
  **凭据仅其可见且系统内不回显**；端点对非管理员**不可见**（内网地址属敏感信息）。
- **安全评审人**：[原型]「待安全评审」的处置者——对隔离服务器行使放行/维持隔离（UC-21.2）。
  **[待确认]** 该角色与 UC-3.1 的**审核人**是否同一职能——
  本文按**两个独立职能**（安全评审 vs 方法论审核）书写，可由同一人兼任但不得自审自批。
- **能力维护者**：可**只读**服务器名称、说明、工具清单与授权范围，
  用于配 agent 工具白名单；**不可见端点与凭据**；不可改授权范围。
- **审核人**（UC-3.1）：审核 agent 发布时可见其白名单条目与对应的授权范围，
  用于裁决「越权申请」。
- **项目负责人**：[原型] 是 `仅项目负责人` 这一授权范围的**受益角色**；
  可在任务侧决定是否把某工具加入本次任务的权限包（第 ③ 层）。
- **引导师 / 组长 / 组员**：不可见 MCP 管理屏；
  仅在调用链明细中看到 `mcp:<服务器>.<工具>` 与其运行态。
- **观察者**：不可见。
- **agent 自身**：[原型 · UC-21.2] 开关「**允许 agent 自行发现新 MCP 服务器**」**默认关**——
  即 **agent 不能自己找服务器、不能自己扩权**，这是 UC-4.1 R6「Agent 自主扩大权限」
  这条不包含的落地点。
- 未登录、链接失效或未列出的角色：默认无权限；接口不得返回越权数据，
  **尤其不得返回端点与凭据**。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - MCP 清单中存在该服务器，字段齐备（端点、说明、工具清单、授权范围、连接状态）。
  - 其工具以 `mcp:<服务器>.<工具>` 命名空间可被引用与审计。
  - [原型验收] AC1：清单中每台服务器都能看到**端点、工具数、授权范围、状态**四列。
  - [原型验收] AC2a：**新注册的服务器默认 `已隔离`**
    （安全策略开关一文案 ＋ 清单里 `待安全评审 · ● 已隔离` 的行）。
  - [设计验收] AC2b：隔离态服务器的工具不可被任何 agent 调用，也不进入白名单可选池
    （与 `uc-21-2` 同一条规则，两处统一为 `[设计]`）。
  - [设计验收] AC3：**授权范围之外的成员无法通过任何 agent 使用该服务器的工具**——
    在服务端拒绝，并计入越权拦截计数。
    **[原型证据]** 后台数据总览：「`[中]` 越权调用尝试 —— 一个自建 agent 尝试访问
    **未授权的 MCP「客户 CRM」**，**已拦截 7 次**」。
    客户 CRM 是**已注册、`● 已连接`、授权范围「仅项目负责人」**的服务器——
    该拦截正是**授权范围（本用例）**的执行结果。
    ⚠ 此前 `uc-21-2` 把这条当作它开关四（agent 自行发现新 MCP）的证据，属**证据错配**，已归还本用例。
  - [设计验收] AC4：工具的**函数签名与参数 schema**被完整记录，
    使 UC-4.4 能留下「函数签名 + 参数 + 命中数 + 运行态」四要素。
  - [设计验收] AC5：新发现的工具**默认不进任何已有白名单**。
- **失败后置条件**：
  - 不产生「注册成功但连不上」或「隔离态却可被调用」的状态；失败进可观测日志。
- **不包含**（**[D-07] 被砍项，明确列出以免实现方误做**）：
  - **调用量统计** —— 原型的「工具调用量·近 7 天：行业数据库/query_market 2,140 ｜
    交付物知识库/search 1,306 ｜ 客户 CRM/get_account 412」**不在 phase-1 范围**；
    实现时该区块留空或显示「—」，**不得为了填满界面而造数**。
    **注意区分**：UC-4.4 的**异常检测所需实时用量判据**属安全能力，**保留**；
    面向展示的统计报表不做。
  - **安全策略四开关的实现与放行评审流程** —— 见 **UC-21.2**。
  - **agent 工具白名单** —— 见 **UC-4.1**（本用例只提供其候选池与越权判据）。
  - **任务权限包 R1/R2/R3 的实现** —— 属 00-core / 11-board；
    本用例只暴露「申请加入本次任务权限包」的接口。
  - **MCP 服务器的自建与运维**（部署、扩容、健康自愈）——属基础设施，不在产品范围。
  - **agent 自行发现新 MCP** —— 默认关且 phase-1 不实现（见 UC-21.2）。
  - 机密数据的模型路由 —— 见 **UC-9.3**（本用例的工具产出若含机密，受其约束）。

## R7 业务规则（不随具体实现变化的硬性约束）

- **[原型] 新服务器默认隔离，需人工评审后放行**（UC-21.2 的第一个开关）。
- **[原型] 授权范围**至少两取值：`仅项目负责人` / `全体成员`；
  另有 `待安全评审` 的展示态（[设计] 建模为独立的评审状态字段）。
- **[原型] 连接状态**三取值：`已连接` / `限流中` / `已隔离`。
- **[人类已拍板] 三层权限**：**MCP 授权范围 × agent 工具白名单 × 任务权限包 R1/R2/R3**；
  **有效权限 ＝ 三层求交**，本用例是第 ① 层，**注册不等于授权，授权不等于可调用**。
- **[原型] agent 不能自行发现新 MCP 服务器**（默认关）——agent 无法自行扩大第 ① 层。
- **[原型]** 工具在系统内的命名空间为 **`mcp:<服务器>.<工具>`**，与内建工具可区分。
- **[设计]** 端点与凭据对非管理员不可见；凭据加密存储、永不回显、永不进日志与审计明文。
- **[设计]** 新发现的工具**默认不进任何已有白名单**；签名变更需重新确认。
- **[设计]** 授权范围收紧**立即生效**（含进行中的任务）。
- **[设计]** `已隔离` 的服务器被调用时直接拒绝并计入越权拦截计数（UC-4.4）。
- **[设计]** 涉客户数据的工具在留痕不可用时**调用必须失败**。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 注册、工具发现、授权范围变更、状态变化、放行都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 清单量级参照原型 6 台；单台工具数最多 28，工具清单无需分页但需搜索。
  - [设计] 连接状态监测为准实时（分钟级）；状态变化需主动通知管理员与受影响的 agent 维护者。
  - [设计] 工具发现应在 10 秒内返回或明确超时。
- **安全/隐私/合规**：
  - **端点与凭据对非管理员不可见**；凭据加密存储、永不回显。
  - [UC-21.2] **涉客户数据的工具调用全量留痕 180 天**——本用例需在工具级标注
    「是否涉客户数据」，否则该策略无法落地。
  - [D-17] 第三方 MCP（如原型的「欧盟法规库（第三方·未审计）」）意味着数据出组织，
    须与 UC-9.3 的机密路由联动：**含机密的内容不得经由第三方 MCP 出域**。
    **[待确认]** 是否需要在工具级标注「是否出组织」。
  - 越权调用拦截计数进 UC-4.4 与后台数据总览。
- **兼容与降级要求**：
  - 响应式 Web；后台以桌面端为主。
  - `限流中` 必须明确告知调用方；**不可用时明确失败**，不得静默跳过工具调用
    （否则 AI 会在缺数据的情况下给出结论）。

## R11 切分提示（给 requirement-author）

- 建议拆分顺序：
  1. MCP 服务器领域模型（端点 / 凭据 / 说明 / 授权范围 / 连接状态）
  2. 凭据加密存储与端点对非管理员不可见（**安全优先，先做**）
  3. **工具发现与工具模型**（工具名 / 签名 / 参数 schema / 是否涉客户数据）
     ＋ `mcp:<服务器>.<工具>` 命名空间
  4. **新注册默认隔离**（其工具不可调用、不进白名单池）
  5. **授权范围的服务端判定**（第 ① 层）＋ 越权拒绝与拦截计数
  6. 连接状态监测（含 `限流中` 的明确告知）
  7. 三个消费方的契约接入（UC-4.1 白名单池 / UC-4.2 改派授权集 / UC-4.4 调用链）
  8. 任务权限包申请接口（`[去授权]`）
  9. 授权范围变更的受影响清单与立即生效
  10. 审计 + 自动化验收
- 第 4、5 项是安全内核，应各自成 feature 并有**隔离态调用被拒**「范围外成员被拒」的强验收。
- **优先级 / 先后依赖**：P0；8 点；迭代 2；**必须先于 UC-4.1 的工具白名单**。

## R12 AI Ready 验收线索

- V1（成功态）：AC1 —— 注册一台服务器后，清单显示其端点、工具数、授权范围与连接状态四列。
- V2（默认隔离）：AC2 —— 新注册的服务器状态为 `已隔离`；
  其工具不出现在 agent 工具白名单的可选池；直接调用被拒绝并计入越权拦截。
- V3（授权范围）：AC3 —— 把某服务器授权范围设为 `仅项目负责人`：
  以普通顾问身份触发引用其工具的 agent 调用被拒绝，理由指向第 ① 层；
  以项目负责人身份触发则通过。
- V4（三层求交）：把授权范围放开但 agent 白名单里没有该工具 → 仍被拒；
  白名单里有但任务权限包里没有 → 任务阻塞并出现 `[去授权]`
  （对应原型的「Echo 请求读取「客户 CRM」，权限包里没有」）。
- V5（工具四要素）：AC4 —— 通过 MCP 工具发起一次调用，UC-4.4 的审计中记录
  `mcp:<服务器>.<工具>` 的函数签名、参数、命中数、运行态。
- V6（新工具不自动进白名单）：AC5 —— 服务器新增一个工具，重新发现后，
  已有 agent 的白名单**不含**它，需人工添加。
- V7（限流态）：把服务器置为 `限流中`，调用方**明确收到限流告知**，不静默排队或丢弃。
- V8（不可达态）：把端点置为不可达，引用其工具的 agent 明确告知能力受限，
  **不静默跳过工具调用**。
- V9（签名变更）：修改某工具的参数 schema，引用它的白名单条目标为「签名已变更，需重新确认」，
  在确认前该工具不可用。
- V10（凭据与端点保密）：以能力维护者身份请求服务器详情，
  返回体**不含端点与凭据**；界面亦不显示。
- V11（权限态）：逐一使用 组织管理员 / 安全评审人 / 能力维护者 / 审核人 / 项目负责人 /
  引导师 / 组员 / 观察者 / 未授权用户访问，可读数据与可执行动作严格符合 R5。
- V12（agent 不能自扩权）：模拟 agent 尝试注册或发现新 MCP 服务器，被拒绝并记安全审计。
- V13（空态）：清单为空时显示真实空态与 `[＋ 添加服务器]`，不预置示例服务器。
- V14（不造数态）：工具调用量区块为空或「—」，不出现编造的统计数字。
- V15（审计态）：注册、工具发现、授权范围变更、状态变化可按操作者、时间、服务器检索。
