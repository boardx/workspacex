## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-21.2 / MCP 安全策略与放行评审
- **Actor**：**组织管理员**（策略配置）、**安全评审人**（对隔离服务器行使放行/维持隔离）
- **目标**：[原型] 用**四个开关**把 MCP 这条「外部能力入口」管住——
  新东西默认不可用、涉客户数据的调用留够久、机密不出自托管、
  **AI 不能自己给自己找新工具**。
- **本用例结果**：组织持有一份**四开关**的安全策略配置；
  隔离中的服务器有明确的**评审 → 放行**路径；四条策略在运行时**被服务端强制执行**，
  违规尝试被拦截并计数。
- **系统边界**：四个安全开关的配置与生效、放行评审流程（评审人 / 结论 / 理由 / 留痕）、
  隔离态的运行时阻断、涉客户数据的留痕执行、机密路由的委派（UC-20.3）、
  agent 自行发现的禁止与拦截计数。
- **核心数据对象**：安全策略（四开关）、评审记录（评审人 / 时间 / 结论 / 理由 / 证据）、
  隔离状态、留痕策略（180 天）、拦截事件与计数、审计事件。

## R2 前置条件 / 触发条件

- **前置条件**：
  - MCP 服务器清单存在（UC-21.1）。
  - 当前用户是**组织管理员**（配置开关）或**安全评审人**（执行放行评审）。
  - [UC-20.2] 组织内至少有一个已启用的开源自托管模型——否则第三条开关
    「客户机密材料仅允许本地模型处理」会导致含机密的任务全部失败（这是**预期行为**，
    见 UC-20.3 E1，但需管理员知情）。
- **触发条件**：
  - [原型] 管理员在后台 → AI 能力 → MCP 服务器页面底部开关区调整策略；
  - [设计] 有服务器处于 `已隔离 · 待安全评审` 时，评审人进入评审。
    ⚠ 原型**只有两个静态字段**（授权范围 `待安全评审` ＋ 状态 `● 已隔离`）：
    **无评审角色、无评审入口、无评审屏**，评审流程整体为设计补全。
  - [设计] 任一策略被触发（隔离态被调用、agent 尝试自行发现）时的运行时拦截。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

### 开关一 · 新服务器默认隔离，需人工评审后放行（[原型] 默认 ✓ 开）

1. **系统处理**：任何新注册的 MCP 服务器（UC-21.1 R3 第 3 步）**自动置为 `已隔离`**，
   授权范围显示为 `待安全评审`。
   **系统响应**：隔离态下——
   - 其工具**不进入** agent 工具白名单可选池；
   - 已存在的白名单引用**失效**；
   - 任何调用尝试**被服务端拒绝**并计入越权拦截计数（UC-4.4）。
2. **安全评审人操作**：[设计] 对隔离服务器发起评审（**入口原型确认缺失**）。
   **系统响应**：[设计] 评审面板需呈现判断依据——
   服务器说明（[原型] 如「**第三方·未审计**」是隔离的直接理由）、端点（内网/外网）、
   工具清单与各工具的参数 schema、**是否涉客户数据**、**是否出组织**。
3. **安全评审人操作**：[设计] 给出结论——`放行` / `维持隔离` / `有条件放行`
   （**三种结论在原型档案 0 命中**，是本文提出的设计）。
   **系统响应**：
   - `放行` → 状态转 `已连接`，并**要求同时设定授权范围**
     （不允许「放行了但范围没定」的空档）；
   - `维持隔离` → 记录理由，服务器保持不可用；
   - [设计] `有条件放行` → 只放行**部分工具**（如只放只读工具，不放写操作工具）。
     **[待确认]** 是否支持工具级放行粒度。
   所有结论必须**填理由**并留痕，**不可删除**。
4. **系统处理**：放行后的工具进入白名单可选池；
   [设计] **已放行不等于自动加入任何白名单**——仍需能力维护者显式添加（UC-21.1 A1 同源）。
5. **组织管理员操作**（可选）：把某台已放行的服务器**重新隔离**。
   **系统响应**：立即生效，列出受影响的 agent 与进行中任务；进行中的调用被终止并明确失败。

### 开关二 · 涉客户数据的工具调用全量留痕（[原型] 默认 ✓ 开；**天数读 O-01 参数**）

6. **系统处理**：对标注为**涉客户数据**的服务器（UC-21.1 R3 第 2 步的标记），
   其每一次调用**全量留痕**——请求参数、返回摘要、调用者、agent、时间、所属项目。
   **[已裁决 O-19 · 粒度]** 原问题：「涉客户数据」按服务器整体标注还是按工具逐个标注。
   **裁决（O-19）**：**按服务器整体标注**，**工具级粒度留 phase-2**。
   **[已裁决 O-19 / O-01 · 天数]** 原问题：180 天是原型开关文案里的**一个取值**，
   原型未说明它是**硬编码默认值**还是**示例值 / 可配置项**；与 [D-14] 五参数的关系未定。
   **裁决（O-19）**：**180 天不硬编码**，**直接读 O-01 的「留痕保留期」参数**
   （O-01 裁定默认 **180 天**，项目级可覆盖，区间由合规负责人收窄）——**一处配置、多处消费**。
   界面文案随参数动态渲染，**不得写死「180 天」**。
   [设计] 与 UC-4.4 的 tool-call 记录是**同一份数据的加严策略**（字段更全），不是另建一套；
   **[设计 · 架构对齐]** 该留痕的落点是 Context Engine 的 **`provenance_events`** 表
   （append-only 血缘，见 `docs/architecture/context-engine.md` 第二节）——
   MCP 工具调用**属于 provenance 事件**，与 17-gov 全链路审计共用同一份数据。
   **[硬前置]** 承接 UC-4.4 R7：**留痕写入失败则该次调用必须失败**——
   「没有留痕就没有调用」。
7. **系统处理**：留痕内容按 [D-16] 脱敏策略展示——
   敏感参数默认脱敏，有权者展开原值且展开动作本身留痕。

### 开关三 · 客户机密材料仅允许本地模型处理（[原型] 默认 ✓ 开）

8. **系统处理**：该开关的**执行体是 UC-20.3**——本用例只负责**开关的存在、默认值与展示**。
   **系统响应**：含机密的上下文只能被开源自托管模型处理；
   闭源 API 调用被服务端阻断；含机密任务禁止降级。
   **[已裁决 O-19]** 原问题：本开关是否允许关闭（此前只能给出「建议不允许关闭」）。
   **裁决（O-19）**：**开关三不允许关闭**，以**只读常开**呈现（带锁形图标与说明）。
   理由：它是 **O-17（机密标记）与 D-17（出域＝出组织）的执行点**，关掉即机密外发；
   它也是本产品最强的一条数据边界，在原型中**五处独立出现**（见 UC-20.3 头部）。

### 开关四 · 允许 agent 自行发现新 MCP 服务器（[原型] **默认关 ☐**）

9. **系统处理**：默认关闭时，**agent 不得注册、发现或连接任何未经管理员登记的 MCP 服务器**。
   **系统响应**：[设计] 任何此类尝试**被拒绝并计入越权拦截计数**。
   ⚠ **执行证据 ＝ 原型确认缺失**：开关区四行已完整渲染，
   但原型**没有任何「agent 尝试发现新服务器被拦截」的记录或计数**。
   后台数据总览的「越权调用尝试 —— 自建 agent 访问未授权的 MCP『客户 CRM』，已拦截 7 次」
   **不是本开关的证据**——客户 CRM 是**已注册、已连接**、授权范围「仅项目负责人」的服务器，
   该拦截属于**授权范围的执行（UC-21.1）**，与「发现**新**服务器」是两回事。
   **[人类已拍板对应项]** 这条开关就是 **UC-4.1 R6「Agent 自主扩大权限」**这条
   「不包含」的**技术落地点**。
10. **组织管理员操作**（不建议）：打开该开关。
    **系统响应**：[设计] 必须给出**强警告**并说明后果
    （AI 将可自行接入未经评审的外部能力源）；
    即使打开，**新发现的服务器仍走开关一的默认隔离**——两条策略叠加，
    agent 发现 ≠ agent 可用。
    **[已裁决 O-19]** 原问题：phase-1 是否直接**不提供打开的能力**（只读展示为常关）。
    **裁决（O-19）**：**phase-1 不提供打开能力**——开关四**只读展示为常关**。
    理由：原型无执行证据，做了也无法验收。因此本步第 10 条的「打开」路径
    **phase-1 不实现**，仅保留为 phase-2 的设计说明。

11. **系统收口**：校验 AC1「四个开关存在、默认值与原型一致、且在服务端被强制执行」、
    AC2「隔离态的服务器其工具不可被调用」、AC3「涉客户数据的调用全量留痕 180 天，
    留痕失败则调用失败」、AC4「agent 无法自行发现或接入新 MCP，尝试被拦截并计数」；
    策略变更与评审结论全量留痕。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] 评审可**退回补充材料**——要求注册人补充服务器说明、供应商审计报告等，
    退回理由留痕。
  - A2：[设计] 评审结论可**设有效期**（如「放行 12 个月，到期需复审」），
    对照 [D-14] 的留存策略思路与知识晋升的有效期机制。
    **[待确认]** 是否需要。
  - A3：[设计] 无隔离服务器时，待评审列表展示真实空态
    （大意：当前没有待评审的服务器；**文案待定，非原型原文**），**不生成示例条目**。
    ⚠ 原型每屏都填满样例数据、**零空态**；且原型**没有「评审队列」这个对象**——
    只有清单标题行的「1 台隔离待评审」这一个计数，本文已删去「评审队列」一词。
  - A4：[设计] 策略开关的每次变更都应在**后台数据总览**留下一条可见记录
    （策略变更是高影响动作）。
- **异常流程**：
  - E1：[设计] 评审人同时是注册人时**不得自审自批**（与 UC-3.1 A4 同源）；
    组织内无第二名评审人时明确阻断并提示。
  - E2：[设计] 放行时未设定授权范围 → 拒绝放行（不允许「已连接但范围未定」）。
  - E3：[已裁决 O-19 · 关键] 原问题：开关一（新服务器默认隔离）是否允许关闭。
    **裁决（O-19）**：**允许关闭，但需组织管理员二次确认并留痕**——
    确认框必须说明「此后新注册的 MCP 将立即可用，不经评审」，
    关闭动作本身写入审计与 `provenance_events`，并在后台数据总览可见。
  - E4：[已裁决 O-19] 原问题：开关二（涉客户数据留痕）是否允许关闭。
    **裁决（O-19）**：**允许关闭，但需组织管理员二次确认并留痕**（同 E3）。
    ⚠ 与开关三不同：**开关三（机密仅本地）不允许关闭**（见 R3 第 8 步），
    **开关四 phase-1 不提供打开能力**。
  - E5：[设计] 留痕存储不可用时，涉客户数据的工具调用**一律失败**（硬前置）。
  - E6：[设计] 已放行的服务器被供应商变更端点或工具集时，
    [设计] 触发**重新评审**（签名变更需重新确认，UC-21.1 E4）。
  - E7：[设计] 请求超时或依赖不可用时保留已填内容，明确失败并可安全重试。
  - E8：[设计] 权限在过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留。

## R5 权限与可见性

- **组织管理员**：可查看与调整安全策略开关（受 R7 的「哪些不可关」约束）；
  可重新隔离已放行的服务器；可查看全部评审记录与拦截计数。
- **安全评审人**：对隔离服务器行使 `放行` / `维持隔离` / `有条件放行`；
  必须填理由；**不得自审自批**。
  **[已裁决 O-21]** 原问题：该角色与 UC-3.1 的**审核人**是否同一职能。
  **裁决（O-21）**：审核职能**拆成两种**——
  **① 方法论审核人**（skill 内容 + 知识晋升，看方法对不对）；
  **② 安全评审人**（MCP 放行 + agent 越权申请，看权限给不给）。
  两者**均由组织管理员指派**，**不得自审自批**；可由同一自然人兼任，
  但**同一事项上只能行使其中一种职能**。
  **agent 越权申请**（UC-4.1）须 **安全评审人 + 组织管理员会签**——它实际在扩大 MCP 授权范围。
- **能力维护者**：可**只读**安全策略（用于理解「为什么这个工具用不了」）；
  不可改开关、不可评审。
- **审核人**（UC-3.1）：审核 agent 发布时可见相关服务器的评审状态，
  用于裁决工具白名单里的「越权申请」。
- **引导师 / 组长 / 组员 / 观察者**：不可见本屏；
  仅在调用被拒时看到可读的拒因（不泄露服务器端点等敏感信息）。
- **agent 自身**：**无任何权限**——不能改策略、不能发起评审、不能自行发现服务器。
- **[D-18] 管理员权力边界**在本用例不放宽：可见策略与元数据，
  不等于可读涉客户数据的留痕正文（留痕正文按脱敏与权限门控展示）。
- 未登录、链接失效或未列出的角色：默认无权限；接口不得返回越权数据。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 组织持有四开关的安全策略配置，默认值与原型一致（前三开、第四关）。
  - 隔离服务器有完整评审记录（评审人 / 时间 / 结论 / 理由），**不可删除**。
  - [原型验收] AC1a：**四个开关存在且默认值正确**（前三 ✓ 开、第四 ☐ 关）。
  - [设计验收] AC1b：四个开关**在服务端强制执行**（不是纯展示）——原型只渲染了勾选状态，
    执行行为无界面证据。
  - [原型验收] AC2a：**新服务器默认隔离**（开关一文案 ＋ 清单里的 `待安全评审 · ● 已隔离` 行）。
  - [设计验收] AC2b：隔离态的服务器其工具不可被任何 agent 调用，尝试被拒绝并计入拦截计数。
    ——**与 `uc-21-1` R7 同一条规则，统一标 `[设计]`**（原此处标 `[原型]` 与之矛盾，档案无据）。
