# Team / Enterprise 设计签核材料

Issue #6099。这是后续阶段的设计交付，`covers` 未认领运行时 feature。商业规则来源为 `docs/superpowers/specs/2026-11-01-cn-us-pricing-design.md`；个人支付的签核不会自动覆盖本束。

## ① UI

沿用用户已采用的 `../../ui-preview/pricing-v1/README.md`：组织账户的共享余额、订阅期限、已用／已购席位和增员弹窗；平台 Team 列表的 Enterprise 标识、升级确认和添加额度弹窗。商业 Team 是 `organizations.kind=organization`，不是组织内 `teams` 分组；实际入口复用平台 organizations 目录。

真实接线补充文字：增员展示服务端报价及共同到期日，首期额度标为预计、到账后显示实际值；开通时席位不足须明确确认总席位及总价。Team购买额外额度不延长订阅；平台“添加额度”严格保留已采用原型的Enterprise专属范围和整数／原因表单。Enterprise组织账户显示实际Enterprise／人工管理，不显示虚构的下一期扣款或默认月额度，额度入口提示联系平台管理员；已发旧批次保留原到期事实。升级处理中或失败保留当前真实套餐。沿用既有布局和错误／加载／无权限状态。

核心输入的原型消费增量截图见`../../ui-preview/team-contract-v1/README.md`，只作材料层验证，不等于完整API已完成或真实权限通过。

## ② 用例

材料为 `usecases.md`、`domain.md` 和 `coverage.md`。已确认商业规则保持不变：基础席位不随实际人数下降减价、补差价同日到期、首期额度按剩余月度窗折算、到期只挡新团队 AI、Enterprise 平台管理员开通与加额度。下列具体执行规则仍是本束提案，须随本文件由人确认：

1. **核心成员口径**：每个实际组织成员占一席，四类 `orgRole` 均计入；纯项目来宾不产生组织成员关系时不计入。邀请尚未核销不占位，核销事务竞争最后一席，失败不消费邀请。既有超席成员不移除；首次开通须购买足够容量，续费保留已购容量。首次支付意图创建后，待购容量也限制新增入组，避免未开通组织在付款过程中超席；报价本身不占位。
2. **折算精度**：微信补价沿用原建议的向上取最小货币单位；Stripe 使用固定版本、固定折算时刻的真实账单预览，显示其实际整数金额，不强行用另一套公式重算。实际首期额度按权威到账时刻向下取到 0.01 credit，支付前明确为预计值。
3. **Enterprise 生效**：不自动新增Enterprise默认月度额度、不创建自助账单或虚构期限；开通后组织 AI 不再受旧 Team 到期日和 Team 收费席位上限限制。旧已发额度按原批次有效期保留；已付年费尚未发放的基础及增员窗口如何处理待用户答，取消未来续费不能被默认解释为停止已付额度。仅当前代际已生效Enterprise可由平台手动加永久额外额度；Team使用已采用的购买额度入口，不能借平台接口绕过该范围。升级前处理本应用所属 Team 的待支付变更并核实停止未来 Stripe 续费；失败显示处理中／失败，不显示已升级。
4. **付款归属**：Team 开在明确选择的组织下，不把个人 Pro 或个人余额迁移成组织权益；个人 Pro 的续费独立，购买前告知这一点。微信过期后手动购买新期限；连续 Stripe 续费保留原购买锚点及全部已购增员数量。

## ③ API

`api.md` 描述拟议接口及约束。`packages/contracts/src/billing-team.ts` 已物化严格输入、Team付费期限、四类quote、组织目录、组织权益/月度授予、升级输入及手动额度收据，原型消费目录/quote/权益/手动额度schema；完整历史、支付恢复、平台摘要/operations以及未决已付未来窗口政策仍待完成。正式人工签核前须补齐可执行响应/操作定义与原型反例并完成一致性复核，依据[契约设计执行书](../../../../.harness/instructions/contract-design.md)。当前草案不请求正式签核，不允许据此开始运行时接线。

可执行设计须复用现有身份guards、`platform-organizations.ts`的Plan／版本／审计和组织钱包；不另建第二个Enterprise布尔值或权限体系。`platform-organizations.ts`为关联可执行契约，不虚构同名已签核契约束。

签核前须完成独立一致性复核。任何修订另留审查记录；本文件唯一记录人工签核状态，agent 不自行改为 confirmed。本设计不授权生产部署、计费 epoch 激活或旧账清理。

第③件进展补充：组织权益/当前月度授予及共享钱包约束已物化，原型已消费模拟权益。新识别的累计赠送两位精度数据库/写入适配是Team销售前置条件，材料只拓宽共享响应契约以保留0.01，未执行迁移。仍待完整目录/历史/恢复/平台摘要/operations及已付未来窗口决定，status保持pending。
