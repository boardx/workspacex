# 双向覆盖与验证计划

| 出口／内部端口 | 用例 | 实现前固定的验证 |
|---|---|---|
| Catalog、Checkout 输入输出、订阅／赠送读模型 | PC1/PC2/PC4/PC5/PC6 | `pnpm --filter @repo/contracts exec vitest run tests/billing-pricing.test.ts`；金额分单位、地区币种、重复 SKU、不可信付款人／金额、付款年周期与月额度分离、Free 30 天及到期剩余 0 |
| 签名回调与可信支付读取 | PC3/PC4/PC5 | 扩展现有 provider／webhook 真实数据库测试：金额与环境篡改、重复／乱序、事务回滚、超时同一订单恢复 |
| 年度权益与月度批次分配 | PC5/PC7 | 新增真实 PostgreSQL 场景：12 周期连续、月末／闰年、未来不可授予、停机恢复、到期与消费并发、原钱包守恒 |
| 注册完成赠送 | PC6/PC7 | 新增注册真实链路：新用户一次、旧用户不赠、并发重放一次、30 天边界、赠送与充值／欠款分别保留 |
| 当前账户、历史与管理入口 | PC8 | 浏览器＋API＋数据库证据：付款结束与额度结束分别显示，历史沿用真实快照，其他付款人越权失败 |
| 旧订阅清理 | PC9 | 测试数据 dry-run→执行→复跑；外部取消失败、待付款旧订单、迟到旧事件，均有明确审计结果 |

反向：PC1–PC9 全部对应上表；Schema 每个 operation 均有 UC；旧读与回调操作不复制定义；新权益读模型使用独立路径，旧响应保持原 schema。当前仅第一行是本 issue 的可执行 schema 验证，其余测试在运行时 feature 开工前编写并先观察失败，不以 schema 测试冒充真实支付完成。

## 独立交付拆分

1. 商品目录及新充值包：精确中美金额、版本、币种及历史快照兼容。
2. Pro 月付：CN 微信一次性、US Stripe 自动续费、重复事件不多发。
3. Pro 年付：年度支付、按原购买日逐月授予及停机恢复。
4. Free：仅新用户一次 1,000、到账 30 天到期、真实注册链路与并发验证。

每项独立 issue／PR，串行复用同一 worktree。CI 以各 PR 当前 head 判定；#6087 的 UI 验证不能代替本阶段运行时验收。
