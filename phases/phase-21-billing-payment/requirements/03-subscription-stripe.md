# 03 — Stripe 订阅（升级 / 管理 / 状态同步）

估点 **16**（= 订阅读模型 5 + webhook 同步 5 + 订阅 UI 6；与 `../feature_list.json` 机械对账，改点必改此数）。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case 名称**：订阅升级与订阅管理（Stripe）
- **Actor**：终端用户；外部系统（Stripe 托管页与 webhook）；运维（配置密钥与链接）
- **目标**：免费用户可升级订阅、已订阅用户可管理账单；订阅状态在系统内**以 webhook 为权威**保持同步。
- **系统边界**：`apps/web` 升级/管理入口 → `apps/api` 订阅域 → Stripe 托管页、Billing 门户与 webhook。

## R2 前置条件 / 触发条件

- **前置条件**：用户已登录；部署启用 Stripe 渠道且配置完整（未启用时见 E1）。
- **触发条件**：
  - 用户点「升级」或「管理订阅」；
  - 用户从 Stripe 托管页回跳到系统；
  - Stripe webhook 到达。

## R3 主流程

### 升级（免费 → 订阅）

1. 免费用户打开升级弹窗 → 系统返回订阅支付链接（携带用户引用信息与语言等预填参数）。
2. 用户点击跳转到 Stripe 托管支付页，完成订阅后**回跳**系统。
3. 系统读取该用户订阅状态并展示：`active`/`trialing` 显示为已订阅（如 Pro 标识），其他显示为未订阅。
4. 回跳后状态可能滞后 → 由 webhook（步骤 6）兜底刷新，界面稍后自动保持一致。

### 管理（已订阅用户）

5. 已订阅用户点「管理订阅」→ 系统创建 Stripe Billing 门户会话并返回链接 → 跳转；回跳后刷新状态。

### 状态同步（webhook）

6. Stripe 事件到达 → **验签** → 更新系统内订阅记录（状态、当前周期、试用起止、客户/订阅标识等）→ 用户界面按新状态展示。
   - 至少覆盖：订阅创建、订阅更新（升降级/续费）、订阅取消（具体事件清单由契约设计定）。

## R4 备选流程与异常流程

- **E1 支付链接/密钥未配置**：入口隐藏或明确报错；不得跳转到无效地址。
- **E2 回跳后状态未更新**（webhook 慢或缺失）：以 webhook 为权威；界面短暂显示"同步中"可接受，但**不得把已订阅显示为免费**。
- **E3 webhook 验签失败**：拒绝 + 留痕；不得更新任何订阅状态。
- **E4 重复/重放 webhook**：幂等更新（按事件 id 去重），不产生重复订阅记录。
- **E5 用户取消订阅**：webhook 更新后系统界面回到对应状态；生效时机（立即或到期）按 Stripe 语义，**UI 必须把生效时点讲清楚**。
- **E6 用户已有订阅仍打开升级弹窗**：按钮切换为「管理订阅」，不重复售卖。

## R5 权限与可见性

- **终端用户**：仅能查看/发起自己的订阅操作。
- **平台管理员**：本阶段**不提供**代替用户修改 Stripe 订阅的能力（不包含）。
- **未登录**：全部订阅接口不可用。

## R6 后置条件 / 不包含

- **后置条件**：系统内订阅记录与 Stripe 侧一致；用户界面展示正确的计划状态。
- **不包含**：自建多层级订阅计划/试用策略（按 Stripe 侧既有配置）、发票与税务、企业主体账单、按席位计费。

## R7 业务规则（硬性约束）

1. **webhook 是订阅状态的唯一权威**；前端回跳读取只是展示手段。
2. webhook 必须验签；事件按 id 幂等。
3. 订阅状态字段只由 webhook 处理路径写入（不允许用户侧接口直接改状态）。

## R8 界面线索（has_ui 阶段必填）

- **前端入口**：用户菜单「升级 / 我的订阅」；已订阅用户在菜单展示计划标识。
- **升级弹窗构成**：计划说明、升级按钮（跳转）、已订阅时切换为管理入口。
- **参考实现（竞品路径，供 UI 先行对照）**：
  - `boardx-web/src/components/ui-user/UpgradePlanDialog.tsx`
  - `boardx-web/src/components/ui-user/UserMenu.tsx`（订阅状态展示与入口）
  - 截图待 UI 先行阶段产出到 `ui-preview/`。

## R11 切分提示（给 requirement-author）

- 建议粒度：订阅链接与跳转（含管理页）、webhook 状态同步（含验签与幂等）、界面状态展示，各成 1 个 feature。
- 先后依赖：webhook 处理依赖订阅模型契约先行定稿。

## R12 AI Ready 验收线索（收尾自检）

- 成功态：免费用户取链接 → 跳转 → 回跳显示已订阅；已订阅用户进入管理页；webhook 更新状态可见；
- 异常态：未配置不跳转无效地址、webhook 验签失败不更新、重放不重复写入、已订阅不重复售卖；
- 权限态：他人订阅不可见、未登录不可用、管理员无代改能力。
