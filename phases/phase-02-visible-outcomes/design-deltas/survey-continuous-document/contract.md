# Survey 连续文档交互设计增量

Status: confirmed by human in the coord-survey conversation on 2026-08-13.

本文件是本次 UI 增量的唯一规范来源。既有 `contracts/survey/` 契约束保持不变；本增量只补充问卷浏览、章节输出配置与报告浏览的交互语义。

## 1. 问卷设计页

- 中间编辑区按题目顺序连续渲染全部问题，不因目录选择而卸载其他问题。
- 每道题都有稳定的 DOM 锚点，题目目录只负责平滑滚动到对应题目。
- 用户直接滚动中间内容时，目录高亮自动同步到当前可见题目。
- 右侧 AI 助手以当前可见题目作为“当前问题”上下文，但不得自动覆盖题目内容。
- 只读模式保留连续浏览与目录跳转，继续禁用编辑操作。

## 2. 报告模板页

- 每个报告章节独立保存 `output`，可选 `text | chart | image`。
- 章节选择为 `chart` 时，必须继续选择具体图表类型 `chartType`：
  - `gap-matrix`：差距矩阵
  - `capability-table`：能力表
  - `grouped-bar`：分组柱状图
  - `line`：折线图
  - `radar`：雷达图
- `output` 为 `text` 或 `image` 时不显示图表类型选择器，`chartType` 允许为空。
- 切换章节后，各章节的输出方式与图表类型保持各自设置，不得互相覆盖。
- 当前章节右侧预览同步显示其输出方式和具体图表类型。

## 3. 分析报告页

- 报告正文按模板章节顺序连续渲染全部章节，不因目录选择而卸载其他章节。
- 左侧报告目录只负责平滑滚动到对应章节。
- 用户直接滚动报告正文时，目录高亮自动同步到当前可见章节。
- 管理层摘要中的成熟度、能力缺口表和事实/推断/建议组件仍属于摘要章节；其他章节继续呈现各自正文。
- 导出、分享与重新生成按钮仍作用于完整报告，而非当前章节。

## 4. 可访问性与响应式边界

- 目录按钮继续使用原生 `button`，当前项通过 `aria-current="location"` 表达。
- 平滑定位使用 `scrollIntoView`；在系统请求减少动态效果时使用非动画定位。
- 桌面端目录与辅助栏保持可见；窄屏继续按现有单列顺序重排，不引入新的一级导航。
- 问题和报告章节必须使用稳定 `data-testid`，以便端到端验证连续渲染和锚点跳转。

## 5. 数据模型增量

`packages/contracts/src/survey.ts` 的 UI 原型模型增加：

```ts
export const SurveyChartTypeSchema = z.enum([
  "gap-matrix",
  "capability-table",
  "grouped-bar",
  "line",
  "radar",
]);

// SurveyReportSectionSchema
chartType: SurveyChartTypeSchema.optional(),
```

本增量不声明真实 HTTP 路由，不新增服务端操作、错误码或持久化保证。

## 6. 验收场景

1. 打开设计页时，Q01 与 Q16 同时存在于文档；点击 Q16 目录项会定位 Q16，滚回 Q01 后目录高亮回到 Q01。
2. 在“关键发现”选择“图表 / 雷达图”，切换到“业务含义”选择“文本”，再次切回时两章设置保持独立。
3. 选择“文本”或“图片”时图表类型选择器隐藏；重新选择“图表”时可选择五种具体类型之一。
4. 打开报告页时八个章节同时存在；点击“能力缺口”目录项定位该章，继续向下滚动可直接看到后续章节。
5. 只读模式下仍可完成问卷与报告的连续浏览和目录跳转。

## 7. 明确排除

- 本轮不实现题目或章节拖拽排序。
- 本轮不实现真实 AI 生成、报告导出、分享或服务端持久化。
- 本轮不引入虚拟列表、滚动分页或新的前端依赖。
