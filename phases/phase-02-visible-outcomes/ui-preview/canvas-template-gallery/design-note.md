# design-note · canvas-template-gallery

我（ui-prototyper）在这份原型里做的设计取舍。**每一条人类签核时都可以推翻**——
这份原型本身就是给人拍板用的材料，不是既成事实。

## 背景（已核实，不再调查）
- `packages/fabric-markdown` 里 19 个工作坊模板（`registerTemplate`）+ `interactions/mindmap-editor.ts`
  的 Tab/Enter 编辑**代码 100% 已迁移就绪**，与参考实现 `projects/fabric-markdown` 逐字一致。
- 缺的**不是能力，是入口**：零处产品 UI 引用它们。现有画布 `canvas-main.tsx` 永远从同一段硬编码
  `INITIAL_SOURCE_MD`（「谁在买储能」示例）起手。本原型接的就是这个自然入口点——把「永远同一个起点」
  换成「可以选一个模板起点」。

## 取舍一：交互形态选「模态」，不选独立页 / 常驻侧栏
- **候选**：(A) 模态对话框；(B) 独立路由页 `/projects/:id/canvas/new`；(C) 画布左栏常驻模板区。
- **选 A**，理由：新建画布是一次**聚焦、短暂**的动作，模态把用户留在项目画布上下文里（不跳走、不丢当前状态），
  与同目录**既有的** `template-apply-dialog.tsx`（也是模态）保持一致的心智，不另起一套导航。
- **推翻条件**：若产品希望「新建画布」是一个可分享 URL 的正式流程（比如从项目首页直接进），
  应改成 B。原型里预览页把模态**平铺**呈现是为了截图，真实接入时它是覆盖层。

## 取舍二：入口落点 = 项目画布页「新建画布」按钮
- 现状 `canvas-main.tsx` 没有「新建」动作，只有一块固定示例。原型主张在画布工具区加一个「＋ 新建画布」，
  点开本模态。**本轮不真的改 `canvas-main.tsx`**（那要动真实画布逻辑，超出「只做 UI 原型」的范围）——
  原型在 `/preview/...` 独立演示，接线位置留给签核后由 worker 落。

## 取舍三：分类分四组（展示层新造事实）
- 注册表**没有**分类字段。四组是我按模板用途归的：**用户研究 / 战略分析 / 叙事沟通 / 从空白起手**。
  归属写在 `lib/mock/canvas-templates.ts` 的 `CATALOG_META`，是画廊独有的展示事实——**不是**契约。
- **不造第二份权威**：key 列表仍从 `listTemplates()` 取（`coverageGap()` 断言无遗漏）、中文标题仍从
  `getTemplate(key).title` 取。我只新增了「分类 / 一句话 blurb / 图标字形」这三样画廊独有的字段。
- **推翻条件**：分类边界、每张卡的 blurb 文案都可能不准（我不是领域专家），签核时最该核对这块。

## 取舍四：缩略图用单字形 emoji 占位，不渲染完整画布缩略图
- **候选**：(A) 每张卡渲染一个迷你 CanvasStage 缩略；(B) 单字形图标占位。
- **选 B**，理由：21 张卡同时挂 21 个 fabric canvas，性能与实现成本都高，而画廊的目的是「快速识别+选择」，
  一个可识别的图标 + 中文名 + 一句话已足够。真实缩略图的收益（预览布局）留到「hover 预览」再谈。
- **推翻条件**：若用户强烈需要「选之前先看到画布长什么样」，可后续给热门模板补静态缩略图。

## 取舍五：「示例内容」开关 + 只备两个拟真种子
- 画廊头部有 `示例内容` 开关（默认开）。开=选中的模板带拟真内容起手；关=空框起手。
- 只有 **persona** 和 **journey-map** 备了拟真种子（王敏·园区能源主管 / 储能采购旅程），
  与本阶段「谁在买储能」示例同一场景，好让签核看到**真实信息密度**；其余模板选中后是干净框架。
- **推翻条件**：真实产品里「新建」大概率应是**空框**起手（用户自己填），示例内容更像「模板预览」。
  签核可决定：新建默认空框，示例内容仅在卡片 hover 预览时展示。

## 取舍六：七态怎么落到「选模板」这个场景
选模板天然没有传统 CRUD 的全部异常态，我做了如下映射（既有原型是 happy-path 零异常，这里刻意补齐）：
- **加载**：模板注册表/引擎加载中 → skeleton。
- **空**：搜索/筛选无结果（真实里也可能是「组织禁用了内置模板」）。
- **校验失败**：从「空白快建」但没给画布起名 → `err-name`。（这是我给「选模板」造的一个合理写入校验点，
  因为选模板本身没有表单校验；若产品不要求起名，此态可删。）
- **依赖失败**：fabric-markdown 引擎初始化失败 → 诚实错误框 + 重试，且明示「你已有的画布不受影响」。
- **无权限**：观察者视角不能新建（真实权限在服务端，这里只做界面投影）。
- **成功**：真实 CanvasStage 渲染出模板框架。

## R5 多角色视角
项目角色四种（引导师/组长/组员/观察者）都能在预览页顶栏切换。前三者可新建画布；观察者进入 denied 态。
⚠ 视角切换是**预览手段**，不是权限实现——真实权限在服务端，原型只做界面投影（沿用项目工作台四视角成例）。

## 危险动作
本原型**没有**删除/发布/签署/外发/撤回等危险动作——新建画布是纯增量、无破坏性，故不涉及二次确认。
（「空白快建」若未来允许覆盖当前画布，则需补二次确认；本原型是「新开一张」，不覆盖。）

## 已知局限
1. **卡片标题双语不一致**：`cnHead()` 取标题的中文头，但纯拉丁词开头的（HMW/PESTEL/SWOT/MVP/AI…）
   取不到中文头，回退成完整双语标题。视觉上略不齐。修法：给这几个模板在展示层补一个纯中文短名——
   但那会是标题的第二份副本，**违反「同一事实不得声明在两处」**，故本轮不做，等签核决定要不要在
   `BUILTIN_CANVAS_TEMPLATES` 旁边加一列纯中文短名（单一事实源）。
2. **未接后端写路径**：选了哪个模板不落库（后端目前也没有这个写路径）。真实接入时，「新建画布」应
   创建一份 canvas artifact，初始 markdown = `starterMarkdownFor(key)`——这条写路径本轮不新建。
3. **示例内容仅两个模板**：其余 17 个模板选中后是空框，签核看不到它们的拟真密度。若需要，可逐个补种子。
4. **模态在预览页是平铺的**：为截图方便，没有做真实的遮罩+ESC 关闭+焦点陷阱。真实接入需补齐无障碍细节。
