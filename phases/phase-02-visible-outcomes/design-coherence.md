# Phase 02 阶段一致性复核

本阶段当前只有 `survey` 一个契约束。本复核不重复束内 UI、用例和契约检查，只核对它与现有共享能力的边界。所有项目保持未勾选，等待人类逐项确认。

## XC-01 · 身份与访问边界

- [ ] 问卷受访身份、组织身份和角色权限复用现有 identity/auth 契约，不在 Survey 内创建第二套用户、角色或会话模型。
- [ ] 匿名答卷只代表提交者不展示真实身份，不绕过问卷访问范围、截止时间、每人限答和质量控制规则。

## XC-02 · 文件与报告产出边界

- [ ] PDF、Word 和单份答卷导出复用既有 Artifact/File 产出物链路；Survey 不直接写对象存储，也不另造文件权限模型。
- [ ] 报告模板只声明章节结构、分析方法和输出约束，不保存一份与原始答卷脱离的事实副本。

## XC-03 · 契约与数据单源

- [ ] 问题、答卷、工作流步骤和报告章节以 `packages/contracts/src/survey.ts` 为单一契约源，页面不另建同义枚举或 Schema。
- [ ] 回收统计、质量标记和报告指标均由同一份答卷模型派生，设计、发布、答卷与报告页面之间不存在手工同步的第二份状态。

## XC-04 · 路由与 UI 所有权

- [ ] `/studio/survey` 只重定向到新版五步工作流；旧 Survey 组件不再作为第二套可达主界面。
- [ ] 五个步骤通过 URL `step` 参数可直接访问，非法步骤回落到问卷设计页；加载、空、错误和只读状态保持同一路由语义。

## XC-05 · AI 与分析边界

- [ ] AI 助手只生成可预览的题目或章节建议，未经用户保存不得改变权威问卷模型。
- [ ] 自动分析明确区分事实、推断与建议；模板约束和模拟数据不得被表述为真实组织结论。

## 人类确认动作

请先确认 `contracts/survey/design-signoff.md` 的 UI、用例与 API 契约，再逐项确认 XC-01～XC-05。只有人类可以把本文件和束级签核文件的 `status` 改为 `confirmed`，并填写 `confirmed_by`、`confirmed_at`。
