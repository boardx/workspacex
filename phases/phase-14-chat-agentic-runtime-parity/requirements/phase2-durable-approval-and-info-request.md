# Phase 2 — 交互模型新增：持久授权审批 + 主动补信息卡

> 依赖 Phase 1 的成本摘要（审批卡里要展示预计成本，走 Phase 1 建的成本管道）。
> 复用现有 HITL（人在环）卡片骨架，扩展语义，不重新发明一套交互模式。

## 需求 1：审批卡加"一直允许"持久授权

**用户故事**：作为反复批准同一类操作（比如"读取 CRM 数据"）的用户，我不想每次任务都重新点
一次批准，我想说一次"以后这类操作都不用再问我"，Agent 记住这个授权。

**现状**：活体 `agent-approval-panel.tsx` 是"批准/编辑并批准/拒绝"三态，mock 原型
`approval-card.tsx` 是"批准执行/改参数/不用了"——两者都没有持久授权概念，每次都要重新决策。

**期望行为**：
- 审批卡在现有按钮基础上，加一个"一直允许"选项（三态变四态：仅此次允许 / 一直允许 / 编辑并
  批准 / 拒绝，具体文案由 UI 先行阶段定）。
- 选"一直允许"后，写入一条持久授权记录（按"操作类型 + 数据范围"这个粒度，而不是无限泛化到
  "以后什么都不用问"）。
- 下次同一用户在同一粒度下触发相同类型操作时，直接跳过审批卡、自动放行，但仍要在执行轨迹里
  留痕"因已授权自动通过"，保证可审计。
- 用户需要能在某处（可以是设置页，不强制在本 phase 做新页面）撤销一条已授权记录。

## 需求 2："补一个信息就能更准"主动信息请求卡

**用户故事**：作为在跑分析任务的用户，我希望 Agent 在发现关键信息缺口时主动告诉我"缺了什么、
补上能让结果更准"，并让我用最省事的方式补上（从已有材料里选，或者上传新的，或者干脆跳过），
而不是等结果出来才发现是错的。

**现状**：最接近的是 `fill-params-card.tsx`（被动 interrupt 表单，AI 猜字段、用户确认/编辑），
但没有独立的"主动信息请求"卡片外壳，也没有"上传/从材料里选/跳过"三个动作。

**期望行为**：
- 新增一种 HITL 卡类型（复用 `agent-interrupts/` 现有三卡的管道和视觉语言，不是另起炉灶），
  在 Agent 判断某个信息缺口会显著影响结果质量时触发。
- 卡片内容：一句话说明缺什么、为什么重要（如 mockup 里"这27家店有6家做过促销但系统没记录"）。
- 三个动作：从已挂载材料里选一个文件、上传新文件、跳过（明确告知用户跳过的后果，不强制堵住
  流程）。
- 跳过后 Agent 继续执行，但后续产出物里应该能看到"该信息未提供，可能影响准确性"之类的免责
  标注（具体呈现方式留给 UI 先行阶段定）。
