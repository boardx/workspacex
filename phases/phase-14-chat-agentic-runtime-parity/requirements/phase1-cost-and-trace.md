# Phase 1 — 数据/协议层补洞：成本预算追踪 + 工具执行摘要

> 背景：对比设计 mockup（"华东区 Q3 销售下滑归因"运行态）与 `/chat` 活体实现后确认的两项
> 数据层缺口。两者都不需要新的 UI 交互概念，只是把已有面板（plan-control 进度条、
> agent-tool-chain 工具轨迹）挂上目前缺失的数据源。这是三阶段计划的第一阶段，
> 是 Phase 2（持久授权 + 主动补信息卡）与 Phase 3（待处理侧栏）的前置依赖之一。

## 需求 1：Run 级成本/预算追踪

**用户故事**：作为在跑一个 Deep Agent 任务的用户，我想在任务执行过程中随时看到"这一轮任务
目前花了多少钱、占我本月预算的百分比"，这样我可以在成本失控前主动暂停或调整任务范围。

**现状**：全仓 grep 确认活体 chat/plan-control 代码里没有任何 run 级成本追踪组件。已有的
"预算"概念仅限于：(a) admin 侧组织/成员配额策略（`limit-policy-tab.tsx`，管理员视角，非
对话内实时反馈）；(b) mock 原型审批卡里单次动作的预估 token 成本（非累计、非活体）。

**期望行为**：
- 一次 run（从用户发起任务到当前时刻）产生的模型调用成本，按 token 用量 × 定价实时累加，
  在 plan-control 进度条附近（或紧邻处）以"¥X.X"展示。
- 同时展示这笔花费占用户/组织当月预算的百分比（复用已有的组织配额策略作为分母，不重新发明
  一套预算体系）。
- 数值随任务执行更新（不要求逐 token 实时刷新，跟随现有 3 秒轮询节奏即可）。
- 预算数据来源应该是真实的 run 账本（`agent_run_steps` / `getPlanLedger` 同一套数据管道
  能延伸出成本字段），不是又一份写死的 mock。

**边界**：这一步只做"看得到花了多少"，不做"超预算自动暂停/拦截"（那是另一个需求，不在本
phase 范围）。

## 需求 2：工具执行结果的结构化摘要（含行数等量化信息）

**用户故事**：作为在看 Agent 执行轨迹的用户，我想在"已读取 XX 数据源"这类工具调用记录旁
看到量化信息（比如"共 41,208 行"），而不只是一句定性描述，这样我能快速判断这次读取的数据
规模对不对、有没有漏读或读多了。

**现状**：`agent-tool-chain.tsx` / `copilotkit-v2-tool-renderers.tsx` 已经有可展开的工具调用
轨迹 UI，交互形态齐备，但底层工具结果协议只有 `content: string`，不携带任何结构化摘要字段
（行数、字节数、命中数等），所以现在做不出"共 X 行"这类描述。

**期望行为**：
- 后端工具执行结果（至少覆盖读取类工具：读文件、查数据库/表、检索类）在返回给前端的 payload
  里附带一个可选的结构化摘要字段（如 `summary: { rows?: number; bytes?: number; hits?: number }`），
  没有摘要的工具类型不强制填。
- 前端 `agent-tool-chain.tsx` 折叠态摘要行、`copilotkit-v2-tool-renderers.tsx` 的 per-tool 卡片，
  在摘要字段存在时展示量化信息（如"读取 41,208 行"），字段缺失时回退到现有的纯文字描述，
  不能因为字段缺失而报错或空白。

**边界**：这一步只做协议扩展 + 展示，不要求对所有工具类型都补全摘要——先覆盖读取类高频工具，
其余工具类型可以后续 phase 或独立 issue 补齐。

## 不在本 phase 范围内（留给 Phase 2 / Phase 3）
- 审批卡"仅此次允许/一直允许/拒绝"三级持久授权（Phase 2）
- "补一个信息就能更准"主动信息请求卡（Phase 2）
- 右侧栏"待你处理" tab（Phase 3，依赖 Phase 2 的持久化审批数据作真实数据源）
- 面包屑短语 / agent-mode 选择器等视觉对齐（Phase 3）
