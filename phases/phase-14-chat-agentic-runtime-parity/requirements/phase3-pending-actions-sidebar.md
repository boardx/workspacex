# Phase 3 — 结构性 UI：待处理侧栏 + 视觉对齐

> 依赖 Phase 2：待处理 tab 的数据源就是 Phase 2 产生的持久授权请求 / 主动信息请求这些
> 真正等待用户处理的项目。人类在 #728 D9 已经裁决过：不能上一个后端硬编码 0 的 tab——
> 上一次"执行/洞察"两个假 tab 就是因为这个被砍掉的，本 phase 必须避免重蹈覆辙。

## 需求 1：右侧栏"待你处理" tab

**用户故事**：作为在跑任务的用户，我想在一个地方看到所有等我处理的事项（待批准的操作、
等我补充的信息），而不是散落在对话流里往上翻找。

**现状**：`chat-read-screen.tsx` 右栏只有"产物"和"材料"两个 tab，均有真实数据源。

**期望行为**：
- 新增"待你处理" tab，数量徽标 = 当前未处理的审批请求数 + 未处理的信息请求数之和
  （数据源来自 Phase 2 的持久授权表和信息请求记录，禁止硬编码或写死占位数字）。
- tab 内列表按时间倒序展示每条待处理项，点击跳转/定位到对话流里对应的卡片（不是在侧栏里
  重新实现一遍完整交互，侧栏是入口和总览，处理动作还是在原卡片上完成）。
- 全部处理完时 tab 显示空态，不显示误导性的固定数字。

## 需求 2：视觉对齐（面包屑 / agent-mode 选择器）

**背景**：这两项目前有可用的底层数据或替代实现（plan-control 进度条已有
`currentStepLabel/stepIndex/stepTotal`；`AgentPicker` 已能选具体 agent），差距主要在呈现
形式，不是从零开发。

**期望行为**：
- 面包屑：把 plan-control 现有的阶段信息，改造成"第 N 步·正在 XX"这种短语式呈现，挂在任务
  标题栏，替代/补充现有进度条展示位置（不要求推翻现有进度条，可以共存或合并视觉呈现，具体
  由 UI 先行阶段定稿）。
- agent-mode 选择器：这是当前完全没有的新概念（"通用 Deep Agent" vs 具体 agent），需要先
  确认产品语义再决定是新增独立选择器还是扩展现有 `AgentPicker`——**这一条设计上有开放问题，
  UI 先行阶段需要人类明确这个"模式"到底代表什么（是切换 agent 人格/权限档位，还是别的），
  不要在没有澄清前直接照抄 mockup 文案**。
