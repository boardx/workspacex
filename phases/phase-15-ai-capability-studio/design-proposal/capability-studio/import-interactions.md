# 导入弹窗交互状态矩阵（提案）

> 本文仅定义交互提案，不代表现有 API、权限或版本契约已实现/签核。默认行为始终是“新建能力”，不会覆盖既有草稿。

## 1. 导入目标模式

| 模式 | 默认 | 用户看到什么 | 可点操作 | 后端必须确认 |
|---|---:|---|---|---|
| 新建能力 | 是 | “将创建新的 Skill/Agent/MCP/Model 草稿” | 继续预检、取消 | 名称冲突、能力类型、可创建范围 |
| 覆盖既有草稿 | 否 | 目标草稿、当前 revision、将被替换/合并的文件 | 选择草稿、查看差异、确认覆盖、返回新建 | 草稿存在、可编辑性、精确 revision、并发冲突、覆盖策略 |
| 覆盖已发布版本 | 禁止直接执行 | 引导“从已发布版本创建新草稿” | 创建派生草稿、取消 | 已发布版本身份及派生关系 |

覆盖既有草稿必须由用户显式切换，不能因同名自动进入。提交时携带精确 `draftRevision`；revision 已变化时停止覆盖并要求重新预检。

## 2. GitHub 来源状态

| 状态 | 用户看到什么 | 可点操作 | 保留什么输入 | 后端必须确认什么 |
|---|---|---|---|---|
| 初始 | 来源类型、GitHub 地址、ref；默认新建 | 输入地址、选择已有连接、下一步、取消 | 尚无 | 可用来源类型；不得假设用户拥有任何连接或权限 |
| 仓库地址有效 | 识别为整个仓库；显示 owner/repo 和 ref | 预检、修改、取消 | URL、ref、连接选择、目标模式 | 仓库可访问；ref 可解析；resolved commit SHA |
| 目录地址有效 | 识别出的仓库、目录路径和 ref | 预检、修改路径 | URL、目录、ref、连接、目标模式 | 路径存在且为目录；resolved commit SHA；目录边界 |
| 单文件地址有效 | 文件名、路径、识别出的候选能力类型 | 预检、修改来源 | URL、文件路径、ref、连接、目标模式 | 文件存在且可读；是否允许该文件独立导入 |
| ref 未填写 | 明确提示将使用仓库默认分支，但尚未解析 | 继续预检、手动填写 | 其他全部输入 | 实际默认分支及 resolved commit SHA |
| ref 无效 | 字段级错误：“分支、Tag 或 Commit 不存在/不可读取” | 修改 ref、重试预检 | URL、连接、目标模式及用户输入的 ref | 区分不存在、不可访问和暂时失败 |
| URL 无效 | 指出格式或不支持的 GitHub 页面类型 | 修改、粘贴示例 | 原始 URL、其他字段 | 不创建导入任务 |
| 未选择连接 | 公共仓库可继续；私有来源提示选择已有连接 | 选择连接、刷新连接列表、取消 | URL、ref、目标模式 | 仓库是否确实公开；有哪些连接对当前用户可见 |
| 已有私有连接可用 | 只显示后端返回的连接名称及作用域摘要，不展示凭据 | 选择连接、预检 | URL、ref、目标模式、连接 ID | 连接有效、允许读取目标仓库；凭据不得返回前端 |
| 连接失效或拒绝 | “连接无法读取此来源”，避免误报仓库不存在 | 更换连接、重新授权入口、取消 | URL、ref、目标模式 | `expired`、`revoked`、`scope-denied` 等稳定错误类别 |
| 多个连接可用 | 连接选择列表，不自动猜测身份 | 选择一个连接、预检 | 所有表单输入 | 每个连接的安全显示名和可用状态 |

## 3. ZIP 文件预检状态

| 状态 | 用户看到什么 | 可点操作 | 保留什么输入 | 后端必须确认什么 |
|---|---|---|---|---|
| 未选择文件 | ZIP 拖放区、大小/格式约束 | 选择文件、切换 GitHub、取消 | 目标模式、目标草稿 | 实际大小、格式及上传限制 |
| 本地选择完成 | 文件名、大小、校验中状态 | 移除、替换、开始预检 | 已选文件、目标模式 | 上传接收成功；内容哈希 |
| 上传中 | 确定进度或不确定进度提示 | 取消上传 | 文件名、目标模式 | upload ID、取消能力、完整性 |
| ZIP 无效 | 损坏、非 ZIP、加密或格式不支持的明确原因 | 替换文件、取消 | 目标模式；不必重新选择目标草稿 | 错误类别；不得开始导入任务 |
| 安全预检失败 | 路径穿越、符号链接、文件数/解压体积超限等风险摘要 | 替换 ZIP、下载失败清单（若允许） | 文件名、哈希、目标模式 | 安全规则、拒绝项路径；不得解压到工作区 |
| 结构为空 | “未找到可导入能力”及扫描范围 | 替换文件、返回 | 文件名、目标模式 | 扫描已完成；不是解析服务故障 |
| 预检成功 | 根目录、候选文件、能力类型、依赖与警告 | 选择候选、继续、替换 | ZIP 哈希、预检结果、目标模式 | 不可变预检 ID、文件清单及内容摘要 |
| ZIP 已变化 | 文件内容与预检哈希不一致 | 重新预检、替换 | 新文件和目标模式 | 禁止复用旧预检结果 |

ZIP 预检不得直接写入正式草稿。正式导入必须引用预检 ID 和内容哈希。

## 4. 多候选选择

仓库、目录或 ZIP 中发现多个能力时，不自动全部导入。

| 状态 | 用户看到什么 | 可点操作 | 保留什么输入 | 后端必须确认什么 |
|---|---|---|---|---|
| 单候选 | 类型、名称、入口文件、依赖摘要 | 继续、返回修改 | 来源、ref/SHA、连接或 ZIP 预检 ID | 候选身份和文件边界 |
| 多候选未选择 | 按能力分组的候选列表；默认均不选 | 单选、多选、查看文件、返回 | 来源及全部预检结果 | 稳定 candidate ID；候选间文件冲突 |
| 部分候选选择 | 已选数量、未选数量、目标草稿计划 | 增减选择、继续 | 当前选择、来源、目标模式 | 每个候选仍属于同一预检快照 |
| 候选存在依赖 | 依赖项和“将一并导入/仅建立引用”提示 | 查看依赖、按允许策略选择 | 当前选择 | 依赖是否可导入、已存在或缺失；策略需由正式契约确认 |
| 候选冲突 | 同名、共享文件或目标草稿冲突 | 改名、取消冲突项、返回 | 非冲突选择和用户改名 | 名称唯一性、文件所有权、冲突类别 |
| 候选已过期 | 来源在选择期间变化 | 重新预检 | URL、ref、连接、目标模式；候选选择作为参考 | resolved SHA/ZIP 哈希是否仍匹配 |

## 5. 异步导入任务

每个所选候选形成独立任务项；批次提供汇总状态。页面刷新后应能通过 batch ID 恢复。

| 状态 | 用户看到什么 | 可点操作 | 保留什么输入 | 后端必须确认什么 |
|---|---|---|---|---|
| `queued` | 排队位置或“等待执行”；候选逐项列出 | 取消尚未开始项、关闭弹窗后后台继续 | batch ID、任务项、来源快照、目标模式 | job ID、幂等键、快照锁定、是否允许取消 |
| `running` | 当前阶段：读取、解析、校验、写入草稿；逐项进度 | 查看详情、取消可取消阶段、关闭 | 与 `queued` 相同，加阶段日志引用 | 当前阶段、心跳、取消边界；不得用前端计时模拟 |
| `partial` | 成功、失败、取消项分别统计；成功项草稿链接 | 查看成功项、仅重试失败项、关闭 | 全部任务结果、失败输入、来源快照 | 每项最终状态、已创建草稿 ID、失败是否可重试 |
| `failed` | 批次无成功项或批次级失败；显示稳定错误分类 | 仅重试失败项、返回修改来源、关闭 | 原始来源、候选选择、目标映射、错误详情 | 失败发生阶段、是否可重试、是否产生任何副作用 |
| `cancelled` | 已取消项与取消前已完成项分开显示 | 返回修改、重新建立任务；失败项若存在可单独重试 | 已完成结果、原始输入、取消原因 | 每项真实终态；取消不得回滚已明确完成的独立项 |
| 全部成功 | 每项新草稿 ID/revision、来源 SHA/ZIP 哈希 | 打开草稿、继续编辑、完成 | 批次证据和结果映射 | 草稿已持久化；来源与 revision 可追踪 |

`partial` 是有效的业务终态，不应显示成整批故障，也不能把正常排队显示为失败。

## 6. “仅失败项重试”规则

- 重试按钮只包含 `failed` 且后端标记为可重试的任务项。
- `succeeded`、`running`、`queued`、`cancelled` 项不得被隐式重新提交。
- 重试沿用原始来源快照：GitHub 使用 resolved commit SHA，ZIP 使用内容哈希和预检 ID。
- 每次重试生成新的 attempt ID，但保留原 job ID/lineage，便于审计。
- 已产生目标草稿的失败任务必须由后端返回副作用状态；前端不能自行判断是新建还是续写。
- 若用户修改 URL、ref、ZIP、候选、目标草稿或覆盖策略，应创建新批次，不属于“重试”。
- 因权限或连接失效导致的失败，只有后端重新确认访问条件后才能重试。
- 重试前目标草稿 revision 已变化时，停止执行并进入冲突处理，不静默覆盖。

## 7. 最低版本一致性要求

提交异步任务时至少冻结并回显：

```text
source:
  github: repository + resolvedCommitSha + path + connectionId
  或 zip: uploadId + contentHash + preflightId

selection:
  candidateIds[]

target:
  mode: create | overwrite-draft
  draftId?: string
  expectedDraftRevision?: string

execution:
  batchId
  jobId per candidate
  idempotencyKey
  attemptId
```

其中 `connectionId` 仅作为引用传递；UI 不读取或保存私有连接凭据。所有“可创建、可覆盖、可取消、可重试”能力均必须由后端明确返回，不能根据角色名称在前端臆造。
