# 原始需求 — 图片与图标可访问性补全

估点 **2**

> 来源：2026-08-23《WorkspaceX 十分制评估》P1 缺口「图片可访问性」+《十分冲刺 Backlog》IT-05。

## R1 概览
- **Use Case 名称**：补全图片/图标的可访问性标注
- **Actor**：使用读屏器的用户
- **目标**：`alt=` 目前只出现在 4 个文件，绝对数偏低，即便大多数图片走 avatar/图标组件、语义上可豁免，这个数字仍需要人工抽查确认而不能假设"应该没问题"。目标是全站扫描图片与图标，区分"有意义图片需要 alt 文本"与"纯装饰图标需要 aria-hidden"两类，逐一补齐。
- **系统边界**：全仓 `<img>`、`next/image` 用法，以及 `lucide-react` 图标的使用点；`apps/web/scripts/lint-design.sh` 的 U7a 规则

## R2 前置条件 / 触发条件
- **前置条件**：`lint-design.sh` 已有 U7a 规则（当前实现范围需先确认，可能只覆盖裸 `<img>` 未覆盖 `next/image`）
- **触发条件**：本 feature 开工时做全仓扫描

## R3 主流程
1. 扫描全仓所有 `<img>`、`next/image` 的 `Image` 组件使用点，以及所有 `lucide-react` 图标使用点
2. 逐一分类：a) 承载信息的图片（如用户上传的附件预览）——需要有意义的 `alt`；b) 纯装饰性图标（如按钮旁的箭头图标）——需要 `aria-hidden="true"` 或等价处理，避免读屏器重复朗读冗余信息
3. 补齐缺失标注；对于 avatar 类组件，确认其内部实现是否已经统一处理了 alt（如用用户名作为 alt），如果没有则补上
4. 扩展 `lint-design.sh` 的 U7a 规则，确保覆盖 `next/image` 而不仅是裸 `<img>`
5. 引入 axe-core 的 `image-alt` 规则作为自动化回归

## R4 备选流程与异常流程
- **备选流程**：
  - A1：图片正在加载或加载失败时——alt 文本仍需存在，作为占位描述
- **异常流程**：
  - E1：某张图片的语义在当前上下文里难以用一句话描述清楚（如复杂的数据可视化截图）——alt 应描述图片的用途而非试图逐像素描述内容，必要时配合相邻文字说明
  - E2：动态生成的图片（如用户头像的首字母占位图）——alt 需要动态生成而不是写死一个通用文案

## R5 权限与可见性
- 无业务权限差异

## R6 后置条件 / 不包含
- **后置条件**：全仓图片/图标可访问性标注补齐；lint 规则覆盖范围扩大；axe-core image-alt 规则接入
- **不包含**：不做图片本身的视觉设计调整（如压缩、裁剪），只做可访问性标注

## R7 业务规则
- 装饰性图标一律 `aria-hidden`，不允许读屏器读出无意义的图标文件名或占位符文本

## R8 界面线索
- 前端入口：全站含图片/图标的位置，重点是 avatar、附件预览、空状态插图
- 提醒：本 feature 通常不改变可见视觉，不涉及签核；若发现某处需要补充可见的 alt 展示位（罕见）需重新评估
