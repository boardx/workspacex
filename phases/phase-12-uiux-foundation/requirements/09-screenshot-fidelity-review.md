# 原始需求 — 截图级保真度复核与视觉密度打磨

估点 **6**

> 来源：2026-08-23《WorkspaceX 十分制评估》缺口「视觉打磨精细度」+《十分冲刺 Backlog》IT-09。

## R1 概览
- **Use Case 名称**：正式 rev-uiux 评审 + 观感打磨
- **Actor**：`rev-uiux` 评审角色；负责整改的开发 agent
- **目标**：网格合规（间距走 4/8px、任意像素被 lint 拦截）不等于观感精致。本仓库之前的评估基于代码证据，未做逐屏截图打分。目标是用真实的 rev-uiux 评审对 chat 主屏、profile、org-admin 跑一轮正式评分（对照既有 rubric），并针对扣分项做视觉微调（卡片内边距、行高、信息密度等技术合规但观感局促的问题）。
- **系统边界**：`apps/web/app/chat/**`（对照 `chat-main-fidelity-rubric.md`）、`profile/**`、`org-admin/**`（对照 `uiux-screenshot-review-profile-org.md`）

## R2 前置条件 / 触发条件
- **前置条件**：本阶段前序 feature（尤其是 01/02/06/07 涉及可见改动的部分）已落地，避免评审对象是即将被替换的旧实现；「08-review-evidence-log」的日志结构已建立，评审结果需要落进去
- **触发条件**：本 feature 开工时按 rubric 逐项评审

## R3 主流程
1. 由 `rev-uiux` 角色分别对 chat 主屏（`chat-main-fidelity-rubric.md` 十维）、profile/org-admin（`uiux-screenshot-review-profile-org.md` 十项）做正式截图级评审
2. 记录每一维度的得分与扣分理由，写入「08-review-evidence-log」的结构化日志
3. 针对扣分项逐一制定修复方案，优先修复"技术合规但观感局促"类问题（如间距数值符合网格但视觉上仍显拥挤——可能是网格档位选择不当而非违规）
4. 修复落地后重新评审受影响的维度，直到达到既定通过门槛（chat ≥9，profile/org ≥9，均为已有人类裁决收窄后的门槛，不是满分要求）

## R4 备选流程与异常流程
- **备选流程**：
  - A1：某个扣分项的修复方案会与本阶段前序 feature 的产出冲突（如需要调整刚收口的组件原语）——需要评估是否值得为此再动组件原语，还是接受当前分数留待下一轮
- **异常流程**：
  - E1：评审发现某个维度对应的产品功能本身有数据缺口（如某个字段后端不支持），无法靠前端视觉修复解决——记录为超出本 feature 范围的产品缺口，不能靠伪造数据凑分（参照本仓库已有先例：#831/#728 因发现数据不支撑而直接从评分卡里移除相应维度，而不是硬做出假数据）
  - E2：修复过程中引入新的视觉回归——需要有截图对比作为回归检测依据

## R5 权限与可见性
- 评审覆盖的三个页面各自的权限模型不变，本 feature 不改变谁能看到什么，只改善已可见内容的呈现质量

## R6 后置条件 / 不包含
- **后置条件**：三个页面均完成正式评审并记录分数；达到既定通过门槛；评审记录写入结构化日志
- **不包含**：不覆盖三个页面之外的其他域（留给后续迭代）；不因为评审发现产品功能缺口就顺手做功能开发（转为独立 feature 处理）

## R7 业务规则
- 评审必须由 `rev-uiux` 角色在真实截图基础上打分，不能只读源码推断分数（沿用仓库既有规则：AGENTS.md「打分只由 rev-uiux 角色做，禁止只读源码打分」）

## R8 界面线索
- 前端入口：chat 主屏、profile、org-admin 三个既有页面
- 提醒：本 feature 涉及可见 UI 微调，属于 has_ui 阶段，开工前需人类签核；具体签核范围以实际改动的契约束为准

## R9 非功能约束
- 兼容与降级要求：评审需覆盖 375/768/1280 三档视口

## R10 已知约束 / 依赖
- 依赖：「08-review-evidence-log」的日志结构；前序涉及可见改动的 feature（01/02/06/07）
- 技术约束：无

## R11 切分提示
- 期望粒度：三个页面可拆成独立 feature，也可合并（工作量评估 L，1-2 周）
- 优先级：排在本阶段靠后，需要前序基础设施类 feature 先落地才有意义评审

## R12 AI Ready 验收线索
- 可验证行为：两份既有 rubric 均达到既定通过门槛（chat ≥9、profile/org ≥9）；评审记录可在「08-review-evidence-log」的日志中查到
