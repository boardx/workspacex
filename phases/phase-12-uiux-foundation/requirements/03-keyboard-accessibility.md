# 原始需求 — 键盘可达性专项

估点 **5**

> 来源：2026-08-23《WorkspaceX 十分制评估》P1 缺口「可访问性 a11y」+《十分冲刺 Backlog》IT-03。

## R1 概览
- **Use Case 名称**：核心任务全键盘可达
- **Actor**：依赖键盘操作的用户（含使用读屏器、运动障碍、纯键盘操作偏好的用户）
- **目标**：`aria-*` 标注覆盖 257 个文件，覆盖率不低，但 `onKeyDown` 仅 18 个文件——aria 标注解决的是"读屏器能不能懂"，键盘可达解决的是"能不能不用鼠标走完整个流程"，两者不等价。目标是对 chat / profile / org-admin 三个高频域做真实的"只用键盘走完核心任务"验证，把 focus trap、Esc 关闭、方向键导航从"默认应该有"变成"验证过没被业务层覆盖破坏"。
- **系统边界**：`apps/web/app/chat/**`、`apps/web/app/profile/**`、`apps/web/app/org-admin/**`，以及这些页面依赖的 IT-01 弹层组件

## R2 前置条件 / 触发条件
- **前置条件**：三个目标域的页面已存在且可访问（当前均已上线）；「01-component-primitives-overlays」的弹层组件已具备基础 focus trap（若未完成，本 feature 需要先补上业务层未覆盖的部分）
- **触发条件**：本 feature 开工时按核心任务清单逐一走查

## R3 主流程
1. 为三个域各定义 1-2 条核心任务（如 chat："发一条消息" "切换到另一个会话"；profile："修改一项资料并保存"；org-admin："打开一个成员的权限设置弹层并调整"）
2. 只用键盘（Tab/Shift+Tab/Enter/Esc/方向键）走完每条核心任务，逐步记录卡点：焦点丢失、Tab 顺序不符合视觉顺序、Esc 不生效、方向键在列表/菜单里不导航
3. 修复卡点，优先修复"任务无法完成"级别的阻塞（如弹层打开后焦点没有进入弹层内部）
4. 用 Playwright 的 `page.keyboard` API 把每条核心任务写成自动化用例，固化验证
5. 引入 axe-core（或等价工具）做自动化扫描，接入 CI，聚焦 keyboard/focus 相关规则

## R4 备选流程与异常流程
- **备选流程**：
  - A1：某个任务存在多种合法的键盘路径（如既可以 Tab 到按钮回车，也可以用快捷键）——都需要验证可用，不能只验证一条
- **异常流程**：
  - E1：某个第三方组件（如 CopilotKit 聊天输入框）的键盘行为不受本仓库控制——需要记录为已知限制并说明缓解方式（如是否提供替代路径）
  - E2：某个 focus trap 与浏览器原生行为冲突（如 Tab 到地址栏被拦截）——需要按 WAI-ARIA 规范修正，不能为了"看起来正确"而破坏浏览器无障碍标准
  - E3：走查过程中发现某条任务在鼠标模式下也存在体验问题（超出本 feature 范围）——记录下来转给相应 feature，不在本 feature 内顺手改

## R5 权限与可见性
- org-admin 域的核心任务仅对有管理权限的角色可见/可执行；本 feature 的键盘走查需在对应角色登录态下进行，不能用管理员账号验证普通用户可见的任务，反之亦然

## R6 后置条件 / 不包含
- **后置条件**：三个域的核心任务均有键盘可达性的自动化回归用例；已知卡点清单归档
- **不包含**：不覆盖 chat/profile/org-admin 之外的其他域（如 canvas、itv），留到后续迭代；不做完整的读屏器逐句朗读体验测试（属于更深的 a11y 工作，本 feature 聚焦键盘操作本身）

## R7 业务规则
- 任何新增的弹层/菜单类交互，默认必须支持 Esc 关闭与 Tab 焦点陷阱，除非有明确记录的例外原因

## R8 界面线索
- 前端入口：chat 消息输入与会话切换、profile 资料编辑表单、org-admin 成员权限弹层
- 线框/参考：无需新增视觉设计，本 feature 是行为修复，不改变现有视觉呈现（除非修复本身需要视觉调整，如补充可见的 focus 环）
- 提醒：本 feature 主要是行为/逻辑修复，通常不需要契约束级设计签核，但如涉及可见样式变化（如 focus ring 视觉调整）需评估是否需要签核

## R9 非功能约束
- 性能/规模预期：无特殊要求
- 安全/隐私/合规：无障碍访问是合规相关能力，需按现有 uiux-standards.md 的 a11y 章节执行
- 兼容与降级要求：验证需覆盖主流浏览器的键盘事件差异（至少 Chromium 系）

## R10 已知约束 / 依赖
- 依赖：IT-01 的弹层组件（若未完成，本 feature 需自行处理 focus trap 缺失的临时方案）
- 技术约束：Playwright 作为端到端验证工具（现有约定）

## R11 切分提示
- 期望粒度：可按域拆分为 3 个小 feature（chat/profile/org-admin 各一个），也可合并为一个中等 feature（工作量评估 M，3-5 天）
- 优先级：不强依赖 IT-01 完成即可先行部分工作，但弹层相关的走查最好在 IT-01 之后进行

## R12 AI Ready 验收线索
- 可验证行为：Playwright 自动化用例能只用键盘走完三个域各自的核心任务，无需鼠标介入；axe-core 扫描 keyboard 相关规则全过；人工截图证明 focus 环在关键节点可见
