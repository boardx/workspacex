# 原始需求 — 第三方组件接入前置校验关卡

估点 **2**

> 来源：2026-08-23《WorkspaceX 十分制评估》P1 缺口「第三方组件语言一致性」+《十分冲刺 Backlog》IT-04。

## R1 概览
- **Use Case 名称**：防止第三方组件样式覆盖复发
- **Actor**：负责接入第三方 UI 库的开发 agent；间接受益者是终端用户（避免视觉不一致复发）
- **目标**：`globals.css:202-218` 记录了 CopilotKit 曾强制 16px 覆盖气泡 12px 字号的真实事故，已修复，但仓库缺少一道"接入第三方组件前先检查样式覆盖"的机械关卡，同类问题会在下一次接入第三方组件时复现。目标是建立登记机制 + lint 规则，把"事后发现事后修"变成"接入前必须登记，未登记的覆盖被机械拦截"。
- **系统边界**：`apps/web/app/globals.css`、`apps/web/scripts/lint-design.sh`、当前已知的第三方 UI 依赖（CopilotKit 等）

## R2 前置条件 / 触发条件
- **前置条件**：`lint-design.sh` 已存在且在 `pnpm lint` 流程中生效（已确认）
- **触发条件**：本 feature 开工时先做一次全仓盘点；此后任何新增第三方 UI 依赖都必须触发登记流程

## R3 主流程
1. 盘点当前所有会渲染 UI 且自带样式的第三方依赖（CopilotKit 是已知一例，需要排查是否还有其他）
2. 在 `globals.css` 头部建立一个"第三方组件样式覆盖登记表"区块，记录：依赖名称、覆盖了哪些选择器、为什么需要覆盖、覆盖的具体值
3. 给 `lint-design.sh` 新增一条规则（沿用现有 U 系列命名，如 U9）：扫描 CSS 中出现的、明显针对第三方库 class 前缀（如 `.copilotKit*`）的选择器覆盖，若未在登记表中找到对应条目则报错
4. 做一次反证：故意在 `globals.css` 里新增一条未登记的第三方覆盖，确认 lint 能拦住；再补登记，确认 lint 放行

## R4 备选流程与异常流程
- **备选流程**：
  - A1：某个第三方库的样式覆盖是通过 inline style 或 JS 而非 CSS 选择器实现的——登记表需要能覆盖这种情况，或至少在文档里注明"本机制目前只覆盖 CSS 选择器路径"
- **异常流程**：
  - E1：第三方库版本升级导致其自带 class 名变化，登记表里的选择器失效——lint 规则报错的方式应该是"提醒复核"而不是静默失败，需要有明显的失败信号
  - E2：新第三方依赖引入时开发者忘记登记直接绕过 lint（如临时禁用规则）——这属于流程纪律问题，不是本 feature 要解决的技术问题，但 lint 规则本身不应该容易被绕过（如不应支持行内 disable 注释掉整个文件）

## R5 权限与可见性
- 无业务权限差异；这是开发流程层面的机械约束，不面向终端用户

## R6 后置条件 / 不包含
- **后置条件**：登记表建立并覆盖当前已知的第三方覆盖点；lint 新规则生效并通过反证
- **不包含**：不要求消除所有第三方样式覆盖（有些覆盖是合理且必要的），本 feature 只要求"覆盖必须被看见和记录"，不评判覆盖本身是否应该存在

## R7 业务规则
- 任何第三方组件的自带样式与本仓库 token 体系冲突时，覆盖值必须引用 `globals.css` 现有 token（如 `var(--foreground)`），不允许覆盖时写新的字面量数值

## R8 界面线索
- 前端入口：无新增可见 UI，本 feature 是纯基础设施/流程性质
- 提醒：本 feature 不涉及可见 UI 变化，大概率不需要契约束级设计签核，但需在束划分时确认归属

## R9 非功能约束
- 性能/规模预期：无特殊要求
- 安全/隐私/合规：无特殊要求
- 兼容与降级要求：无特殊要求

## R10 已知约束 / 依赖
- 依赖：`lint-design.sh` 现有实现模式（U5a/U5b 等规则的写法可作为参考）
- 技术约束：无
