# 原始需求（细化）— UC-0.4 前端内核与设计单源

> 所属：阶段零 · 共享内核 / M0 跨工具协议
> 来源：**无原始需求，亦无 Backlog 条目**——本用例是从 **ADR-003（UI 先行 sign-off 关卡）、
> D-35（`data-testid` 命名规范）、D-36（七种必现状态按统一规范实现）三项已有裁决
> 反推出的执行前提**。
> **补写缘由（2026-07-28，机器核实）**：ADR-003 规定 has_ui 阶段的 `feature_list` 必须
> 先由 `ui-prototyper` 用「`apps/web` 的**真实组件** + 设计 token」把界面做出来、经人类
> 确认后才能定稿。核实发现该前提**完全不成立**：
> ① `apps/` 是**空目录**，全仓 `package.json` 里**零 React / 零 Next.js 依赖**；
> ② `uiux-standards.md` 声称「加粗的必须/严禁条目同时是 harness 门控条件，`lint-design.sh`
> 会机器检查」，但 `lint-design.sh`、`scripts/check-token-contrast.mjs`、`lib/font-scale.ts`、
> `lib/utils.ts`、`globals.css` **五个被点名的产物一个都不存在**；
> ③ 该规范引用的 **ADR-013 在 `docs/adr/` 里不存在**（现有编号跳过 013）。
> 即：规范描述的是**上游模板项目（BoardX/Rooms）已建成、本仓尚未建成**的系统。
> 不补此件，phase-01/02/03 三个 `has_ui: true` 阶段的 `new-sprint` 将全部被拒，
> 且 `ui-prototyper` 无处落笔——**这是当前唯一的全局开工阻塞。**

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **13**；建议迭代 **阶段零 · 共享内核**。
> **本件不计入 699 点原始需求基线**（见 `phases/requirements/ESTIMATE-BASELINE.md`）——
> 它是流程前提而非产品范围。计入后全项目为 712 点。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-0.4 / 前端内核与设计单源
- **Actor**：**前端开发 agent**、**ui-prototyper**、**人类工程师（sign-off 执行者）**
- **目标**：[设计] 把 `uiux-standards.md` 从一份**描述性文档**变成一套**可运行、可机器门控的前端内核**，
  使 ADR-003 的 UI 先行关卡具备执行条件。
- **本用例结果**：`apps/web` 可 `pnpm dev` 启动；设计 token 有唯一事实源且对比度可机器验算；
  七种界面状态有共享外壳组件；`data-testid` 有命名规范且可被 lint 检查；
  `ui-prototyper` 可以在其上画任意业务屏而不需要每次重建基础设施。
- **系统边界**：前端应用骨架、设计 token 单源、字号档位单源、状态外壳组件、
  testid 命名规范、设计 lint 门控、角色视角切换外壳。
- **核心数据对象**：**无业务数据对象**——本件不落任何数据库表，不写任何后端逻辑。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **开发 agent 执行**：在 `apps/web` scaffold 一个 **Next.js（App Router）+ TypeScript 严格模式 +
   Tailwind + shadcn/ui** 应用，纳入 pnpm workspace 与 turbo pipeline
   （`typecheck` / `lint` / `test` 三个 task 必须被 `turbo run --affected` 命中）。
2. **开发 agent 执行**：建立**设计 token 单源**。
   - 色面 token 只在 `apps/web/app/globals.css` 定义（HSL 语义变量）；
   - **每个色面 token 必须有配对 foreground**；
   - `scripts/check-token-contrast.mjs` 对**明暗两套主题**机械计算 WCAG 对比度：
     中性对 ≥ 4.5:1，状态色对（destructive / success）≥ 3:1；缺对或不过线 **exit 1**。
3. **开发 agent 执行**：建立**字号档位单源** `apps/web/lib/font-scale.ts`。
   `tailwind.config.ts` 与 `lib/utils.ts`（`cn()` 的 tailwind-merge 登记）**一律 import 它**，
   任何地方不得手写第二份档位清单。
   > 依据 `uiux-standards.md` §1.2 记录的两次真实事故：字号表存在三份副本靠人肉对齐，
   > 修复了两份，第三份 24 小时后复发。**本步的验收就是「副本数 = 1」可被机器断言。**
4. **开发 agent 执行**：实现 `lint-design.sh`，机械检查 `uiux-standards.md` §0 的 U1–U8：
   硬编码 hex / 任意值像素、`disabled:opacity-*`、裸 `<input>/<select>/<button>`、
   `hover:` 无配对 `transition-*`、`<img>` 缺 `alt`、表外字号档位。**违规 exit 1。**
5. **开发 agent 执行**：实现**七态共享外壳**（对应 D-36 的「统一规范」）——
   `<StateShell>` 统一承载**默认 / 加载 / 空 / 校验失败 / 依赖失败 / 无权限 / 成功**七种状态，
   每种状态带固定 testid，并提供 **URL query 切换入口**（如 `?state=empty`）供人类逐个核对。
6. **开发 agent 执行**：落地 **`data-testid` 命名规范**（D-35 的载体），写进 `uiux-standards.md`
   并由 `lint-design.sh` 检查（见 R7 命名规则）。
7. **开发 agent 执行**：实现**应用外壳**——三栏骨架、左侧五段语义导航、
   顶部**组织切换器**（O-12）与**两层角色说明条**（UC-0.3 R8）。
   ⚠ 三者此刻**只有界面与本地 mock 状态，不接后端**；真实权限在服务端（UC-0.3）。
8. **系统收口**：`pnpm dev` 能起、`pnpm -w run verify:base` 仍通过、`pnpm lint-design` 通过、
   对比度脚本通过、七态可逐个访问且各自 testid 可被 Playwright 选中。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] 已有原型 `WorkspaceX Standalone.html` 是**单文件静态 HTML、零 `data-testid`、
    零异常态**。本件**不移植它的代码**，只沿用它**已确认的设计语言**
    （三栏骨架、左侧五段语义导航、AI 四种在场方式）。移植代码会把「零 testid、零异常态」
    这两个缺陷一并继承。
  - A2：[设计] shadcn/ui 组件按需引入，不一次性全量安装——未被任何屏使用的组件
    不进 lint 范围，避免门控噪音。
- **异常流程**：
  - E1：对比度脚本发现某 token 对不过线 → **回到 `globals.css` 改 token 值**，
    **严禁**在组件层用 opacity 或覆盖类「修」对比度（`uiux-standards.md` §1.1 第 4 条）。
  - E2：`lint-design.sh` 与 `uiux-standards.md` 的条目不一致 → 以**规范为准改脚本**，
    不得反向放宽规范来迁就实现。
  - E3：ADR-013 缺失（`uiux-standards.md` §1.2 引用了它，但 `docs/adr/` 无此编号）→
    **本件须补写 ADR-013「字号档位单一事实源」**，否则规范引用悬空。
    ⚠ 补写须走 `pnpm harness new-adr`（ADR-019 原子编号），不得手工占号。

## R5 权限与可见性

- 本件**不产生任何权限判定**——它是前端外壳，权限一律在服务端（UC-0.3）。
- ⚠ [设计] **角色视角切换器是预览手段，不是权限实现**。
  [原型] 已有原型的项目工作台以引导师 / 组长 / 组员 / 观察者四视角切换演示，
  本件沿用其交互，但必须在代码与文案上标明：**切换只改变本地展示，不改变服务端返回的数据**。
  违反此条会造出「前端隐藏即安全」的错觉——UC-0.3 R5 明确禁止。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - [设计验收] AC1：`apps/web` 可 `pnpm dev` 启动，`turbo run typecheck lint test --affected`
    能命中它。
  - [设计验收] AC2：**设计 token 与字号档位各自只有一份定义**，可被机器断言（副本数 = 1）。
  - [设计验收] AC3：七种状态各有独立可访问入口与固定 testid，可被 Playwright 逐个选中。

  - **任何后端逻辑与数据库表**——本件零迁移、零 API。

  - 国际化与主题自定义。

## R7 业务规则（不随具体实现变化的硬性约束）

- [设计] **单一事实源三条，均须机器可断言**：
  ① 色面 token 只在 `globals.css`；② 字号档位只在 `lib/font-scale.ts`；
  ③ `data-testid` 命名规则只在 `uiux-standards.md` 且由 `lint-design.sh` 执行。
  「还有没有别的副本」是修此类 bug 时的**必答题**（`uiux-standards.md` §1.2 第 4 条）。
- [设计] **能机器判定的一致性绝不交给人肉抽查**（`.harness/instructions/architecture.md` 结论句）。
  本件的每一条规范都必须有对应的门控脚本，**没有脚本的规范条目视为未落地**。
- [设计] **`data-testid` 命名规范**（D-35 的具体化）：
  - 结构 `<域>-<对象>-<角色>`，全小写 kebab-case，如 `files-tree-node`、`itv-transcript-seg`。
  - 七态使用**固定保留名**：`loading` / `empty` / `err-<字段>` / `denied` / `dep-failed` / `saved`。
  - **每个可交互元素与关键展示区必须有 testid**——这是新屏与旧原型（零 testid）
    最重要的差别，也是 verification 能锚 UI 的唯一前提。
  - testid **禁止**携带业务数据（如 `files-node-合同2024.pdf`），只标结构。
- [设计] **opacity 不得用于状态语义**——透明度只允许做过渡动画与遮罩层；
  禁用/次要/占位必须落在 token 上，否则对比度不可静态验证。
- [设计] **组件层不许「修」对比度**，一律回 `globals.css` 改 token。
- [设计] **视角切换不是权限**（见 R5）。
- [设计] 本件**不移植静态原型的代码**，只继承其设计语言（见 R4 A1）。

## R8 界面线索

- **前端入口**：`apps/web` 的根布局与一个 `/_kitchen-sink` 组件样板页（仅开发环境可达）。
- **信息架构**：[原型] 沿用已确认的**三栏骨架**与**左侧五段语义导航**；
  顶部为组织切换器 + 两层角色说明条（形如「顾问 · 能源组 ｜ 本项目：组长 · 第 2 组」）。
- **推荐交互**：`?state=<七态之一>` 切换状态；`?as=<四角色之一>` 切换预览视角。
  两者都**只在开发/预览环境生效**，生产构建必须移除。
- **必须呈现的状态**：默认态、加载态、空态、校验失败态、依赖失败态、无权限态、成功态
  ——本件是这七态的**实现载体本身**。
- **原型参考**：`phases/requirements/WorkspaceX Standalone.html` — 全局三栏骨架与左侧导航
- **UI sign-off**：**不适用**。本件是 UI 先行关卡的**前提**，不是它的对象——
  若要求本件先过 sign-off 则构成循环依赖（sign-off 需要 `ui-prototyper`，
  `ui-prototyper` 需要本件）。故本件**以机器门控代替人类 sign-off**：
  R12 的 V1–V8 全部为可执行断言，无一条依赖人工判断。

## R9 非功能约束

- **性能/规模预期**：[设计] `pnpm dev` 冷启动 < 15s；`lint-design.sh` 全量扫描 < 30s
  （超时会让 agent 倾向跳过门控）。
- **安全/隐私/合规**：`?as=` 视角切换与 `?state=` 状态切换**必须在生产构建中不可达**，
  否则等于给了一个「自称是引导师」的前端开关。须有断言覆盖（V8）。
- **兼容与降级要求**：门控脚本不可执行时 **verify 判失败**，不得静默跳过——
  与 `knowledge-ontology.md` 对 AGE 的立场一致：「不许假装没事」。
- **响应式**：375 / 768 / 1280 三档不出现横向溢出（`uiux-standards.md` U8）。

## R11 切分提示（给 requirement-author）

- 建议**合并为单个 feature**，不拆。理由：R3 的八步之间是强耦合的
  ——token 单源没建好，lint 脚本无从检查；lint 没建好，七态外壳无法验收。
  拆开会产生一串「做完了但验不了」的中间态，违反完成定义第 2 条。
- 若必须拆，唯一合理的切线是 **①~④（骨架 + 双单源 + lint 门控）** 与
  **⑤~⑦（七态外壳 + testid 规范 + 应用外壳）**，前者 8 点、后者 5 点，后者依赖前者。
- **优先级 / 先后依赖**：P0；13 点；阶段零共享内核；
  **必须先于所有 `has_ui` 阶段的任何 UI 工作**，与 phase-00 其余 13 个 feature **无依赖、可并行**。

## R12 AI Ready 验收线索

- V1（骨架）：`pnpm --filter web dev` 启动成功；`pnpm turbo run typecheck lint test --filter=web`
  退出码 0。
- V2（token 单源）：`node apps/web/scripts/check-token-contrast.mjs` 退出码 0；

- V3（token 单源·反证）：向 `globals.css` 注入一个**缺失 foreground 配对**的色面 token，
  断言脚本 exit 1；恢复后 exit 0。
- V4（字号单源）：断言全仓 `text-<数字>` 用到的档位**全部**存在于 `lib/font-scale.ts`；
  且 `tailwind.config.ts` 与 `lib/utils.ts` 均通过 import 取值，
  **正则断言两文件中不存在字面量档位清单**。
- V5（lint 门控·双向）：对 `apps/web/__fixtures__/lint-bad.tsx`（含硬编码 hex、

  ⚠ **这一条是本件最重要的验收**——只验「脚本能跑」不验「脚本能抓到违规」等于没有门控。
- V6（七态）：Playwright 依次访问 `?state=` 七个取值，断言七个固定 testid
  （`loading`/`empty`/`err-*`/`denied`/`dep-failed`/`saved`/默认内容）各自可见且互斥。
- V7（testid 规范）：对样板页断言**每个可交互元素都带 testid**，
  且全部匹配 `^[a-z0-9]+(-[a-z0-9]+)*$`；断言无 testid 含中文或数字业务值。
- V8（生产可达性）：以生产构建启动，断言 `?state=empty` 与 `?as=facilitator`
  **均不改变渲染结果**——预览开关在生产不可达。
- V9（响应式）：Playwright 在 375 / 768 / 1280 三档断言 `document.scrollWidth <= clientWidth`。
- V10（规范同步）：断言 `uiux-standards.md` §0 的 U1–U8 每一条都能在 `lint-design.sh`
  或 e2e spec 里找到对应检查——**没有脚本的规范条目视为未落地**（R7 第 2 条）。
