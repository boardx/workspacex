# 原始需求（细化）— 数字专家访谈 Studio 独立切片

> 估点 **31**（F01–F07 合计）

> 所属：Phase 04 · 数字专家访谈 Studio
> 来源：人类于 2026-08-11 连续确认的访谈 Studio 原型与交互方案；设计单源见
> `docs/superpowers/specs/2026-08-11-digital-expert-interview-studio-design.md`。  
> 范围裁决：只做数字专家；移除真人与用户画像选择；快捷访谈和批量访谈均进入独立页面，
> 不使用弹窗或右侧抽屉。

## R1 概览（Actor / 目标 / 系统边界）

- **Actor**：研究员。
- **目标**：从历史访谈继续工作，或选择数字专家快捷对话；需要系统性结论时，按主题确认、专家审核、个性化问题、批量访谈、报告生成五步完成一轮研究。
- **系统边界**：`/itv` 首屏、快捷访谈页、五步创建流程、访谈详情、可追溯报告，以及支撑这些页面的 interview 契约与 API。
- **明确不做**：真人受访者、用户画像类型选择、语音或视频数字人、把虚拟结论当作强证据。

## R2 前置条件 / 触发条件

- 用户具有当前组织的研究访问权限。
- 数字专家目录可读；不可用时页面显示明确失败态，不伪装为空列表。
- 触发入口为 `/itv` 的 `＋ 新建访谈`、专家卡 `快捷访谈`、历史卡 `继续访谈/继续创建/查看报告`。

## R3 主流程

1. 用户进入 `/itv`，在 `历史访谈` 与 `专家列表` 两个主标签间切换；右上角始终可新建访谈。
2. 用户可从专家卡进入全页快捷访谈；首轮对话保存为历史记录，并可转为批量访谈。
3. 新建访谈第一步填写名称、至少一个标签和主题；只有点击确认主题后才生成专家。
4. 系统生成互补数字专家，用户可以删除、从专家库添加并确认阵容；至少保留一位。
5. 系统按专家分别生成针对性问题；用户可切换专家并增删改问题，确认后开始访谈。
6. 系统并行执行各专家访谈；每位专家独立显示进度、记录、失败与单独重试。
7. 系统以名称、标签、主题、专家档案、针对性问题、问答记录和候选素材生成报告。
8. 每条报告发现都能回到具体专家与具体问题，并标记为探索性、列出待真人验证项。

## R4 备选 / 异常流程

- 主题生成专家失败：保留全部输入，提供重试与手动添加。
- 删除最后一位专家：拒绝并提示至少保留一位。
- 单位专家问题生成失败：仅该专家失败，可单独重试。
- 批量访谈部分失败：保留已完成结果，仅重跑失败专家。
- 报告生成失败：所有素材保持可读，可重新生成。
- 离开任何步骤：草稿、已确认内容和运行状态持久化，再次进入恢复到准确步骤。

## R5 权限与数据边界

- 所有读写均按 `org_id` 隔离；无权与不存在不可被响应体区分。
- 数字专家材料只经 Context API 读取；访谈保存专家、材料版本与来源指针的只读快照，不直读底层存储。
- 快捷对话转批量访谈时只复制当前用户有权使用的问题与回答。

## R6 范围排除与依赖

- 依赖已通过验证的 Phase 00 身份/RLS、Artifact 与 Context Pack，以及 Phase 01 `interview` 范围、错误信封和既有 `/itv` 路由；不得复制第二套契约。
- 本阶段仅消费现有 Agent/Context 形状并保存版本快照，不创建组织级数字专家身份或材料构建流程。
- 访谈域没有强洞察、决策依据或组织晋升写入口；这些全局出口仍由 Phase 03 治理能力负责。
- 本用例不修改真人访谈授权、录制和撤回链路。

## R7 领域不变量

1. 状态闭集为 `draft / topic_pending / experts_pending / questions_pending / running / report_pending / completed / failed`。
2. 历史卡、详情状态、当前步骤与主按钮全部由同一状态字段派生。
3. 未确认主题不得生成专家；未确认专家不得生成问题；未确认问题不得开始批量访谈。
4. 已确认专家集合不能为空；问题必须唯一归属于一位已选专家。
5. 部分失败不得回滚其他专家已完成的记录。
6. 报告发现必须同时引用 `expert_id` 与 `question_id`，且 `exploratory=true`。

## R8 UI 与导航

- `/itv` 只有 `历史访谈`、`专家列表` 两个主标签。
- 快捷访谈、新建访谈、详情和报告均为完整页面，不使用弹窗或抽屉。
- 详情页 `返回历史访谈` 必须明确导航回 `/itv` 并激活历史标签，不依赖偶然浏览器历史。
- 右上角 `＋ 新建访谈` 与当前主操作文字保持单行；空间不足时操作组整体换行。

## R9 状态与恢复

- 草稿与步骤状态在每次有效修改后保存。
- 运行中的专家访谈允许用户离开页面继续执行；重新进入展示服务端真实状态。
- 快捷访谈自动写入历史记录，并保留转批量访谈的来源引用。

## R10 可观测性与审计

- 记录状态迁移、专家增删、问题确认、运行重试与报告生成事件。
- 模型调用失败必须关联到具体 interview、expert 和 operation，不记录敏感正文。

## R11 非功能要求

- 桌面历史卡三列，窄屏降为两列或单列；详情侧栏在小屏改为上下布局。
- 所有可操作控件有稳定 `data-testid`、键盘焦点态和禁用态。
- 不新增依赖，不新增手写 mock 事实源；前端只消费契约派生形状。

## R12 验收线索

1. 契约只接受八个状态，非法跳步被领域状态机拒绝。
2. 草稿创建保存名称、标签、主题且不调用专家生成器。
3. 最后一位专家不可删除，问题只能归属于已选专家。
4. 单位专家失败后，其他已完成运行保持完成。
5. `/itv` 只显示两个主标签，历史卡操作与状态一致，专家快捷访谈进入独立路由。
6. 新建流程按五步恢复，第一步强制名称、标签、主题。
7. 详情返回历史列表有效，右上角按钮完整显示且不在按钮内部换行。
8. 报告每条发现均可追溯到具体专家和问题，并显示探索性与待验证项。
9. Playwright 从真实 `/itv` 入口跑通快捷访谈、转批量、继续未完成访谈和查看报告。
