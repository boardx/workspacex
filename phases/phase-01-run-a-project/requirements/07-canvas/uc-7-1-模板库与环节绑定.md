### 主线 A：后台维护模板库（组织管理员）

1. **管理员操作**：[原型] 在后台「画布模板」屏浏览模板库（原型示数「22 个 · 19 已发布 · 2 草稿待审 ·
   1 已归档」），可按 `全部 / 已发布 / 草稿 / 已归档` 筛选，切换卡片/列表视图。
   **系统响应**：按可见性范围过滤（全体成员 / 仅某组），每行显示模板名、状态、结构摘要
   （如「信息栏＋6 分区＋便签」「12 格·来自 A0 模板集第 18 页」）、`key` 与版本（如 `persona v3`）、
   底层类型（`canvas` / `mermaid`）、可见性、**被 N 场使用**。
2. **管理员操作**：[原型] `[＋ 新建画布模板]`（「和 AI 聊出分区结构」），或从现成模板复制后改
   （原型示例：「高琳从 `user-journey` 复制后改的 5 阶段版」→ `journey-procurement v0.4`）。
   **系统响应**：新建的模板落 **草稿** 态，仅作者可见。
3. **管理员操作**：[原型] 走**三段发布流程**——`草稿（仅作者可见）` → `试跑（指定一个项目）` →
   `发布（全员可绑定）`。**系统响应**：[设计] `[试跑]` 要求选定唯一一个项目；
   [原型确认缺失] 「只有试跑过的模板才允许 `[发布]`」的阻断档案未证实（草稿行 `[发布][试跑]` 并列，见 R4/E1b）；
   [设计] 发布时必须指定**可见性**（全体成员 / 仅某组）。
4. **管理员操作**：[原型] 发布新版本。**系统响应**：**旧版自动归档**；
   [原型] **已经建出来的画布实例不被改动——它们记着自己用的是哪个版本**；
   归档只影响「还能不能用它新建」。
5. **管理员操作**：[原型] 配置**成员能用哪些图表类型**（mermaid 类型白名单，12 类开关）。
   **系统响应**：白名单只作用于**渲染**，不作用于**书写**——[原型]「关掉的类型顾问仍可在文档里写，
   只是不会渲染成画布对象——画布顶部会提示『有 N 条语法被忽略』」。

### 主线 B：把模板绑到**议程环节**（引导师）

6. **引导师操作**：[设计] 在蓝本设计器的模板选择面板里浏览可绑定的模板。
   **系统响应**：只列出**已发布**且当前用户可见性范围内的模板；草稿与已归档模板不可绑定。
   **[原型确认缺失]** 该选择面板的**分类维度**在档案中没有任何依据——
   早期稿本写的「按阶段浏览：共情 / 定义 / 构思 / 原型 / 验证」五个词**全档案 0 命中**，
   已删除。档案里唯一成体系的环节序列是 proto-08「设计思维标准五步」的环节链
   `对齐目标 → 现状共识 → 假设风暴 · hmw → 分组共创 · business-model → 收敛投票 → 行动项`，
   那是**议程环节链**，不是模板分类。分类维度需补画原型或由产品定义。
7. **引导师操作**：[设计] 给每个**议程环节**绑定模板与材料要求，并绑定**本议程环节可用的 skill**
   （[原型] 画布屏左栏「本环节绑定的 skill」：`提取假设 → 假设树`、`语音转便签`、`Markdown ⇄ 画布`；

   即**议程环节 → 模板 + skill** 的绑定在原型中是写实的）。
   **系统响应**：校验 E1「同一议程环节最多绑两个模板」；记录绑定关系与所绑模板的**版本号**。
   **[待确认]** 「最多两个」这一上限在档案中未见，出自 `Backlog Use Case.html`。
8. **引导师操作**：[原型] 现场进入**议程环节**时自动推给对应分组。**系统响应**：为每个分组按绑定的模板版本
   **实例化**一张画布，实例上固化「模板 key + 版本」；[原型] 组员打开就是这张画布，不用自己找。

   图谱、看板或通知状态。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] 目标数据为空时展示空状态、原因和下一步入口，不生成示例数据冒充真实结果。系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
    （原型每屏均填满样例数据，**零空态**，本条无原型依据。）
  - A2：**[已裁决 O-10]（原 [待确认 · D11] 闭合）** **模板已归档后，已绑定该模板的
    `agenda_segment` 能否继续实例化新画布？**
    原问题：早期稿本写「仍可正常实例化」，但 proto-03 原文是「归档只影响『**还能不能新建**』」，
    与之**直接冲突**。档案确定的部分只有：[原型] **已经建出来的画布不会被改动**、
    [原型] 已归档模板提供 `[恢复]` 出口。

    **裁决（O-10）**：**归档禁止「新增绑定」，但不禁止「已绑定 `agenda_segment` 的实例化」**。
    具体：
    ① 模板归档后**不再出现在绑定选择器里**——这就是原型「还能不能新建」的所指，
      即新建**绑定关系**被禁止；
    ② **存量绑定关系仍可实例化**，现场切到该 `agenda_segment` 时照常出画布，
      且实例**固化归档时的模板版本号**；
    ③ 归档确认框须提示「**有 N 个 `agenda_segment` 仍绑定此模板**」，让人知道影响面；
    ④ 已建出来的画布不被改动（原型已确定）。
    理由：这是唯一同时满足「归档只影响还能不能新建」与「**现场不会跑挂**」的读法——
    若归档即禁止实例化，一场正在进行的工作坊切到该环节会直接失败。
  - A3：[原型] **内置模板**（如「假设树 · flowchart · **内置不可删**」）**不可删除**，只能停用或改可见性。
- **异常流程**：
  - E1：[Backlog] 同一**议程环节**最多绑两个模板，避免摊薄时间。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E1b：[原型确认缺失] 模板**未试跑就发布**时是否阻断，档案未证实。
    [原型] 画布模板的发布流程确为三段 `草稿(仅作者可见) → 试跑(指定一个项目) → 发布(全员可绑定)`，
    **但没有任何阻断态或提示文案**；草稿行的操作是 `[发布][试跑]` **并列**，界面上不强制先试跑。
    早期稿本引用的「试跑一场后才能发布」实际出自**项目蓝本**列表里「客户访谈复盘」一行的说明，
    **不是画布模板**，已停止在本处援引。阻断行为需补画原型。
  - E1c：[原型] 文档里写了**被白名单关闭**的 mermaid 类型时，不报错、不丢内容——保留源码，
    画布顶部提示「有 N 条语法被忽略」，并给出 `[源码]` 出口查看原文。
  - E2：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E4：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R7 业务规则（不随具体实现变化的硬性约束）

### 模板库与发布

- [Backlog] 同一**议程环节**最多绑两个模板，避免摊薄时间。
- [原型] **发布流程为三段**：`草稿（仅作者可见）` → `试跑（指定一个项目）` → `发布（全员可绑定）`。
  [原型确认缺失] 「**不可跳级 / 未试跑不得发布**」的阻断是**推断**——草稿行的操作是
  `[发布][试跑]` 并列，档案未见任何阻断。需补画原型或由产品裁定。
- [原型] **发布新版本时旧版自动归档，但已经建出来的画布不会被改动——它们记着自己用的是哪个版本**；
  [原型] **归档只影响「还能不能新建」**。
  **[已裁决 O-10]** 「还能不能新建」＝**不能新增绑定**（归档模板从绑定选择器消失），
  **但已绑定 `agenda_segment` 的实例化不被禁止**，实例固化归档时的版本号；
  归档确认框须提示「有 N 个 `agenda_segment` 仍绑定此模板」。见 R4/A2。
- **[已裁决 O-09]** 模板注册表**同时暴露 `key` 与 `display_name`**：
  `key` 取源码值、不可改、是跨模块契约；`display_name` 承载原型显示名、仅用于展示。
  **任何绑定、实例固化、围栏语法、契约测试一律以 `key` 为准。**
- [原型] 模板字段为一等约束：**内置模板不可删**、**可见性范围**（全体成员 / 仅某组，
  对齐 `00-core/uc-0-3` 的资源可见性字段）、**被 N 场使用**（使用计数必须真实统计，不得估算）。
- [原型] 画布实例必须**固化其模板 key 与版本号**，任何时候可回答「这张画布是哪个模板的哪一版建的」。

### mermaid 图表类型白名单（后台可配 12 类）

- [原型] 白名单取值：`flowchart` · `journey` · `mindmap` ｜ `quadrantChart` · `timeline` · `pie` ｜

### 画布的存储形态（[设计]，Context Engine · file-first 原则，架构第 2.0 节）

- **画布一律物化为文件，不存在「只活在数据库表里」的画布**。每张画布实例至少产出两份文件：
  1. **mermaid / canvas 源码 `.md`** —— 含 ```` ```canvas ```` 围栏与 `模板: <key>`，
     它是画布的**唯一权威内容**（可离线打开、可 diff、可 round-trip）；
  2. **布局快照** —— 便签坐标、分区尺寸、缩放等呈现状态，作为**派生文件**存放，
     带 `derived_from` 指回源码 `.md` 的版本，**不覆盖源码**。
- 两者都必须**能在项目文件浏览器（22-files）里看到、能下载**；
  可见性沿用同一套 `acl_bindings`，文件浏览器**不是权限旁路**。
- 每次保存产生**新的不可变 `artifact_version`（SHA-256）**，原版本永不覆盖；
  「实例固化模板 key + 版本」即记录在该版本的元数据上。
- **文件命名与目录结构一旦对外可见即为契约**，改名须走迁移。

- AC1：现场切 **`agenda_segment`**，每组自动拿到对应模板与材料清单。

- AC3：白名单关闭的类型可写不可渲染，且有「有 N 条语法被忽略」提示。

以下行为应可由自动化测试、接口断言或可复现人工步骤验证。
**[D-08 + D-35] 优先写不依赖浏览器与 `data-testid` 的 round-trip / 契约断言**——
`fabric-markdown` 的纯函数层可直接在 Node 里跑，绕开原型零 testid 的难题。

- **V0（契约态 · 优先级最高）· [已裁决 O-09]**：模板注册表返回的 19 个 A0 模板
  **`key` 与 R7 表格第 3 列逐字一致**（集合相等断言），缺一个或多一个都失败；
  **另断言每条都带 `display_name`，且五处差异逐字一致**
  （`empathy`→`empathy-map`、`journey-map`→`user-journey`、`bmc`→`business-model`、
  `burger`→`burger-comm`、`ai-bmc`→`ai-business-model`），其余 14 条 `display_name == key`。
  再断言：**绑定与实例固化使用的是 `key` 而非 `display_name`**（改 `display_name` 不影响既有绑定）。
- V1（成功态）：AC1 —— 现场切**议程环节**，每组自动拿到对应模板与材料清单（接口断言：切议程环节后
  每个分组各产生一张画布实例，其 `template_key` / `template_version` 与环节绑定一致）。
- **V2（round-trip · Node 可跑）**：对每个 A0 模板取一份含 `字段: 值` + `## 段落` + `- 便利贴` 的
  Markdown 夹具 → 解析成 `DiagramModel` → 序列化回 Markdown，**结果与输入等价**
  （段落顺序、便签归属、字段值全部保持）。19 个模板逐个跑，任何一个不等价即失败。
- **V3（版本固化态）**：模板发布 `v2` 后，读取 `v1` 建出的画布实例，其结构与 `template_version`
  仍为 `v1`；把 `v1` 归档后，新建绑定的可选列表不含它，但已有实例仍可打开编辑。
- **V3b（归档语义 · [已裁决 O-10]）**：把某模板归档后断言——
  ① 绑定选择器中**查不到**该模板（新增绑定被拒）；
  ② **已绑定该模板的 `agenda_segment` 在现场触发时仍能成功实例化**（不报错、不跑挂），
     且新实例的 `template_version` ＝ 归档时的版本；
  ③ 归档确认接口返回「仍绑定此模板的 `agenda_segment` 数 = N」，N 与实际一致；
  ④ `[恢复]` 后该模板重新出现在绑定选择器中。
- **V10（架构态 · [设计] file-first）**：新建并保存一张画布后断言——
  ① 对象存储中存在 **mermaid/canvas 源码 `.md`** 与**布局快照**两份文件；
  ② 二者在 **22-files** 项目文件浏览器中可见、可下载；

  ④ 再次保存生成**新版本**，旧版本 SHA-256 未变（原件永不覆盖）。
- **V11（架构态 · [设计] Context API）**：静态检查 + 运行时断言——

  每次 AI 调用有一条可重放的 `context_packs` 记录，其 item 的 anchor 指向源码 `.md` 中的位置。
- **V4（白名单态）**：关闭 `sequenceDiagram` 后提交一份含该类型的 Markdown ——
