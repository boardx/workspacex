## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-7.4 / 画布回流知识图谱
- **Actor**：**引导师**、**组长**、**组员**
- **目标**：[原型] 组长在本组画布上确认节点 → 节点带来源链进本组小树 → 汇入全场图谱
  （原型「现场协作 → 知识图谱 → 事实关系」屏）→ 引导师 `[批量确认]` 后写回组织大脑。
- **本用例结果**：[Backlog] 用户通过“画布回流知识图谱”完成从“组长确认某个节点”到可追踪业务结果的闭环。
- **系统边界**：**议程环节**绑定的 skill 运行、画布节点确认与状态标注、本组小树、全场图谱汇入、
  批量确认与写回组织大脑。
- **核心数据对象**：画布节点/便签、确认记录、**节点状态（`已确认` / `冲突` / `待确认`）**、
  本组小树、全场图谱节点与来源边（来自哪组、哪份证据）、**议程环节绑定的 skill**、
  组织大脑写回事件。
  **[口径更正]** 早期稿本写的 `已定 / 待决 / 冲突` 与档案不符——proto-06「事实关系」屏原文是
  「节点状态：**已确认 / 冲突 / 待确认**」，`已定`、`待决` 两词档案中不存在，已按原型改正。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“项目模板（环节绑定）、实时转录（素材来源）”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] 组长确认某个节点。
  - 系统从 **本组图谱 / 全场图谱** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

0. **组员/组长操作**：[原型] 在画布左栏「**本环节绑定的 skill**」（＝本**议程环节**绑定的 skill）
   里运行该议程环节可用的三类 skill：
   - `提取假设 → 假设树` `[运行]`——把本组便签与转录提炼成假设树（产出 mermaid `flowchart`）；
   - `语音转便签` `[已开]`——把口头发言实时转成便签（常开型，状态为「已开」而非「运行」）；
   - `Markdown ⇄ 画布`——三段互转的显式入口（详见 UC-7.3）。
   **系统响应**：只列出该**议程环节已绑定**的 skill（绑定动作在 UC-7.1）；skill 产出走 UC-7.2 的
   留白与引述规则，落笔带 AVA 角标且可回滚。
1. **组长操作**：确认过的节点进本组小树，标 `已确认` / `冲突` / `待确认`。**系统响应**：校验当前身份、
   项目范围、必填数据与资源版本；成功后更新界面和业务记录，并保留可追溯来源
   （[原型] 事实关系屏每条关系都带**来源组 + 来源模块 + 证据量 + 时间码**，
   如「第 3 组 · 研究模块 9 来源 · 12:05」）。
2. **引导师操作**：[原型] 汇入全场图谱（现场协作 → 知识图谱 → **事实关系**子视图，每 15 秒刷新），
   引导师 `[批量确认]` 后写回组织大脑（[原型] 该屏常驻硬约束原文：
   「**只有组长确认过的节点才会写回组织大脑。**」）。
   **系统响应**：校验当前身份、项目范围、必填数据与资源版本；成功后更新界面和业务记录，并保留可追溯来源。

   **[设计 · 与 9 个方法环节的映射（原缺失，本次补上）]**
   全场图谱不是画布节点的平铺——[原型] 同屏的「**推演流水线**」子视图以
   **9 个方法环节**为横轴（`01 PESTEL 趋势 / 02 SWOT 竞争 / 03 用户画像 / 04 旅程图 /
   05 HMW 定义 / 06 解决方案 / 07 MVP / 08 UI 原型 / 09 PRD 需求`）× 场景为纵轴计进度
   （[原型] 「进度 14 / 36 格已完成 · 4 场景 × 9 环节」）。
   **画布模板正是这些方法环节的产出载体**，映射如下（[设计]，需人类确认）：
   `03 用户画像 → persona` · `04 旅程图 → journey-map`（辅以 `empathy` 同理心地图）·
   `05 HMW 定义 → hmw`（辅以 `value-proposition` / `adlib`）· `01 PESTEL 趋势 → pestel` ·
   `02 SWOT 竞争 → swot` · `06 解决方案 → bmc` / `ai-bmc` · `07 MVP → mvp`。
   因此画布回流除了写节点与来源边，还须**回填对应方法环节格的完成状态**
   （`已完成 / 正在讨论 / 冲突停滞 / 建议下一步`），否则推演流水线的进度与完成预判无法成立。
   **[待确认]** 上述模板↔方法环节的对应表由本文首次提出，档案未直接给出，需产品确认。
3. **系统收口**：校验 AC1“全场图谱能看出每条结论来自哪组、哪份证据”；满足后记录操作者、时间、对象、结果与来源，并刷新相关列表、图谱、看板或通知状态。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] 目标数据为空时展示空状态、原因和下一步入口，不生成示例数据冒充真实结果。
    （原型每屏均填满样例数据，**零空态**，本条无原型依据。）系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
- **异常流程**：
  - E1：[原型] 互斥结论自动标 `冲突`，等现场判定（[原型]「冲突待判定 · 2」区，出口为 `[上台讨论]` `[标为不确定]`）。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E4：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R7 业务规则（不随具体实现变化的硬性约束）

- [原型] 互斥结论自动标 `冲突`，等现场判定；**不自动择一**，出口为 `[上台讨论]` / `[标为不确定]`。
- [设计] **回流必须携带来源链**：图谱上的每个节点都能反查到它的来源便签 → 来源引述 → 来源转录片段，
  中间任何一环断掉即不得写回组织大脑。
- [原型] **只有组长确认过的节点才会写回组织大脑**（事实关系屏原文）；AI 起草的未确认内容不进图谱、不进组织大脑
  （与 UC-7.2「组长未确认的内容不进产出」一致）。
- [设计] **本议程环节绑定的 skill 是议程环节级白名单**：画布左栏只列出该**议程环节**绑定的 skill；
  绑定关系在 UC-7.1 由引导师配置，组员不可自行加挂。
  本阶段该议程环节的三类 skill 为：`提取假设 → 假设树`、`语音转便签`、`Markdown ⇄ 画布`。
- **[设计]（Context Engine · 知识平面）** 回流的落点是架构的
  **`claims` + `claim_evidence`（支持 / 反驳）+ `ontology_objects` / `ontology_edges`**：
  · 节点三态 `已确认` / `冲突` / `待确认` 与 `claims.status` 的
    `accepted` / `contested` / `proposed` 对应；
  · 「互斥结论自动标 `冲突` 且不自动择一」＝ `contested` 状态下**支持与反驳边并存**，
    系统不得删除任一侧；
  · 「来源链不得断」＝ 每个 Claim 至少有一条 `claim_evidence` 指向可定位的 **Segment + anchor**。
- **[设计]（Context Engine · file-first）** 回流的输入是画布的
  **mermaid 源码 `.md`（权威内容）**，产出的假设树同样是 mermaid `flowchart` 源码文件；
  两者都在 **22-files** 中可见可下载，图谱不是它们的替代存储。
- **[设计]（Context Engine · 服务平面）** skill 运行（`提取假设 → 假设树`、`语音转便签`）
  取上下文**只能通过 Context API 取 Context Pack**，**不得绕过直查** `segments` / 向量库；
  **[已裁决 O-05]** 拒绝「交给 AI 分析」的受访者片段不进这些 skill 的输入。
- **[设计] 编排边界**：写回图谱的解析与索引走**持久任务系统**；
  多阶段综合与人工确认可用 **LangGraph**（动态 `interrupt()`，恢复时副作用幂等）。
- AC1：全场图谱能看出每条结论来自哪组、哪份证据。
- AC2：本 **`agenda_segment`** 绑定的 skill 在画布左栏可见且可运行。
- **AC3（[设计]）**：每个图谱节点可一路回到 22-files 中的 `transcript.jsonl` 与音频时间码
  （100% 引用可定位）；链断即拒绝写回。

- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。
