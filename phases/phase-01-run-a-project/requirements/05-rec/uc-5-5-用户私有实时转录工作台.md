# UC-5.5 用户私有实时转录工作台

> 来源：issue #945 与用户 2026-08-11 的逐轮确认。  
> 依据等级：历史页、创建弹窗、简化实时页为 [人类已确认 UI]；Fun-ASR、短期 ticket、用户私有范围与落库链路为 [人类已确认设计]。
> 元数据：优先级 **P0**；估点 **18**；建议迭代：独立 sprint，按 F164 → F165 → F166 交付。

## R1 目标与边界

已登录用户从全局 `/rec` 进入自己的实时转录工作台，创建带名称和标签的转录文档，使用麦克风开启或停止实时转录，刷新后仍能看到已经完成的最终文本。

本用例不要求关联项目。组织只作为租户、计费和数据驻留分区；转录内容属于创建用户的个人层，同组织管理员或其他成员不能读取正文。

## R2 前置条件

- 用户已登录且属于当前组织。
- 服务端已配置与地域匹配的阿里云百炼 Fun-ASR Workspace 和 API Key。
- 浏览器支持 `AudioWorklet`、`getUserMedia` 与 WebSocket。

## R3 历史与创建

1. `/rec` 展示当前用户的历史转录卡片，可按标签筛选、按名称或正文搜索、按更新时间排序。
2. 用户点右上角或网格末尾的“新建转录”，填写 1–100 字名称和最多 5 个标签。
3. 创建成功后进入详情页；创建本身不申请麦克风、不连接 ASR。
4. 刷新或重新登录后，名称、标签、时长、状态与最终文本仍可读回。

## R4 实时转录

1. 详情页主区域只显示一个“开始转录 / 停止转录”按钮和全宽逐字稿。
2. 点开始后，前端领取约 60 秒有效的一次性 ticket，再请求麦克风并建立 BoardX WebSocket。
3. 浏览器用 `AudioWorklet` 显式输出 mono / 16 kHz / PCM16 little-endian；不把 DashScope API Key 或长期 JWT 放入 WebSocket URL。
4. 后端连接 Fun-ASR，发送 `run-task`，只在收到 `task-started` 后转发 PCM。
5. `sentence_end=false` 只替换当前临时段；`sentence_end=true` 先落库，再推送 final。
6. 点停止后立即停止采音，发送 `finish-task` 并显示“正在收尾”；只在收到 `task-finished`、尾部 final 全部落库并完成用量记录后恢复按钮。
7. 同一转录文档可以再次开始；每次开始/停止形成一个 capture run，正文按时间顺序汇总展示。

## R5 权限与持久化

- `personal_transcriptions` 只保存名称、标签、owner 与聚合状态，不保存正文副本。
- capture run 复用 `recording_sessions`；最终正文只写 `recording_segments`，中间结果永不落库。
- 任何列表、搜索、详情、ticket 和 WebSocket 升级都校验 `owner_user_id == actor.userId`。
- 管理员只可见个人层计数，不可读取正文。
- ticket 原文只返回一次，数据库只存摘要；过期、重复、跨会话或非 owner 使用均拒绝。

## R6 异常与清理

- 麦克风拒绝、无设备、ASR 未配置、额度不足、启动超时、收尾超时、上游失败、背压和网络中断均显示稳定错误状态。
- 失败不得生成假 final；已经落库的 final 保留并可刷新读回。
- 页面卸载、停止、失败或断线都关闭麦克风轨、AudioContext、两侧 WebSocket、缓冲区与计时器。

## R7 不包含

- 说话人自动识别或跨场次声纹库。
- 浏览器直连阿里云。
- 项目级可见性、项目文件浏览器或项目机密分级。
- 实时详情内的 Skill、报告与引用面板；这些下游只读取已持久化 final。

## R8 验收线索

- V1：用户 A 创建的转录只出现在 A 的列表，用户 B 与管理员正文查询均为 0。
- V2：final 推送前数据库已经存在同一 `segmentId`，刷新后正文不丢、不重复。
- V3：`task-started` 前上游收到的 PCM 字节数恒为 0；`task-finished` 前客户端收不到 completed。
- V4：同一 ticket 第二次使用、过期使用、跨 session 使用均被拒绝。
- V5：双声道 48 kHz 输入经 AudioWorklet 后为单声道 16 kHz PCM16 little-endian。
- V6：页面只保留一个开始/停止按钮和逐字稿；停止后在 completed 前按钮不可再次触发。
- V7：停止后再次开始形成新的 capture run，但历史正文仍在同一转录文档中连续可读。
- V8：用量按上游任务最终累计值记一次，重复事件不会重复扣减。
