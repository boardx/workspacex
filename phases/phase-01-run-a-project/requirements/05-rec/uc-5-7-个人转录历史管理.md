# UC-5.7 个人转录历史管理

> 来源：用户 2026-08-14 对 `/rec` 历史页的确认。  
> 依据等级：标签、编辑、删除交互为 [人类已确认需求]；删除时保留无正文的用量审计为 [人类已确认数据边界]。
> 元数据：优先级 **P1**；估点 **5**；建议迭代：F178 独立垂直切片。

## R1 目标与边界

已登录用户在 `/rec` 管理自己的转录历史：筛选栏只显示其真实存在的标签；卡片菜单可修改名称与标签，或在二次确认后永久删除转录正文。此能力不改变实时转录、复制全文与正文编辑链路。

## R2 前置条件

- 用户已登录且属于当前组织。
- 转录文档由当前用户创建；跨用户与跨组织访问均按不存在处理。
- 正在录音或正在收尾的转录不能修改元数据或删除。

## R3 真实标签筛选

1. `/rec` 的标签筛选项来自当前用户全部转录文档的非空标签去重集合，不使用固定示例标签。
2. 标签集合与当前搜索、排序、分页结果无关；即使当前页没有某标签，该标签仍可被选择。
3. 创建、修改或删除转录后，筛选项立即刷新；不再被任何转录使用的标签立即消失。
4. 若当前选中的标签因修改或删除消失，筛选自动回到“全部标签”。

## R4 修改名称与标签

1. 用户点击历史卡片右下角菜单选择“修改”，弹窗预填当前名称与标签。
2. 名称为去除首尾空白后的 1–100 字；标签去空、去重，最多 5 个，单个标签最多 20 字。
3. 标签输入框中尚未按回车确认的非空文本，在保存时也作为标签提交。
4. 保存成功后卡片标题、标签和筛选项立即更新；刷新页面后仍保持修改结果。

## R5 永久删除

1. 用户点击历史卡片菜单的“删除”后，必须看到包含转录名称与不可恢复说明的确认弹窗。
2. 确认删除后，服务端永久删除个人转录文档、所有 capture、最终正文与一次性 ticket；删除成功后卡片立即消失。
3. 为计费与审计保留不含正文的用量事件；保留记录不得使被删除正文重新可读。
4. 取消确认不产生任何写入；重复删除或删除他人文档均按不存在处理。

## R6 并发与错误

- 任一 capture 仍为 `starting`、`recording` 或 `stopping` 时，修改和删除均返回稳定错误 `CAPTURE_ALREADY_ACTIVE`。
- 服务端失败时保留当前卡片及筛选状态，显示可重试错误，不做乐观删除。
- 同一用户在另一页面删除后，本页刷新列表时如实移除记录。

## R7 不包含

- 批量修改、批量删除与回收站。
- 标签颜色、标签管理后台与组织共享标签。
- 删除用量审计或恢复已删除正文。

## R8 验收线索

- V1：筛选项严格等于当前用户所有文档标签的非空去重集合，其他用户标签不可见。
- V2：修改名称与标签后，列表响应、详情响应、卡片与筛选项一致。
- V3：确认删除后，个人文档、capture 与正文查询均为 0，用量事件仍为 1 且不含正文。
- V4：有活动 capture 时修改和删除均失败，数据保持不变。
- V5：取消删除弹窗后未调用删除接口，卡片仍存在。
