# 原始需求（细化）— UC-24.5 现场深度研究与冲突判定

> 所属：阶段一 · 能跑完一场项目 / M24 研究 Studio（research）
> 口径与四标记见 `00-index.md`。`[原型 @n,nnn,nnnB]` = **字节**偏移。
> 元数据：优先级 **P1**；估点 **3**；建议迭代 **02**。
>
> ⚠ 本 UC 是「能跑完一场项目」这个 phase 目标里，研究域**唯一在现场发生**的部分。
> 它与 `uc-24-1/2/3/4` 不是并列关系，是**同一批实体在现场语境下的另一张面**。
> **不要为它新建第二套研究实体。**

## R1 概览

- **Use Case ID / 名称**：UC-24.5 / 现场深度研究与冲突判定
- **Actor**：**引导师**（主要，在主持台上判定冲突）、**组长**（提出研究）、
  **组员**（提出研究）、**观察者**（只读）
- **目标**：让现场提出的问题能**当场派出去查**、回来**带出处**，
  并在两条结论互相矛盾时**先标不确定、再上台讨论**，而不是让现场凭印象拍板。
- **系统边界**：项目内「深度研究 · 现场」屏（`isWsDrl` `[原型 @15,493,520B]`）：
  本场研究任务列表、`只看有冲突的` 筛选、`＋ 发起研究`、冲突待判定区与三个动作。
- **核心数据对象**：现场研究任务（= UC-24.1 的研究主题在现场语境下的投影）、
  任务状态、提出方（组 / 引导师）、来源计数、冲突项、判定动作。

## R2 前置条件 / 触发条件

**前置条件**
- 项目处于**进行中**（现场阶段）。原型该屏位于项目现场标签组内 `[原型 @15,493,520B]`。
- 至少存在一个由本场发起的研究任务（空态见 R4 A3）。

**触发条件**
- 引导师在项目现场点「深度研究 · 现场」标签。
- 组长/组员在小组能力面点研究能力（`capFnDef.key === "dr"` → `modal: "newRes"`，见 `uc-24-1` R2）。

## R3 主流程

1. 屏头逐字：「**深度研究 · 现场**」+ 副标题「**现场提出的问题交给研究 agent 跑，回来带出处**」
   + 筛选开关「**只看有冲突的**」`[原型 @15,494,157B]` + 主 CTA「**＋ 发起研究**」`[原型 @15,494,388B]`。
2. **本场研究任务**区，头部逐字「本场研究任务 | **4 个 · 2 个已就绪**」`[原型 @15,494,696B]`
   ——即**总数与已就绪数分开显示**。
3. 每行逐字四列 + 一个动作，原型四行为：

   | 时间 | 问题 | 提出方 · 来源 | 状态 | 动作 |
   |---|---|---|---|---|
   | 12:31 | 德国三家 EPC 在建规模能否查到 | **第 2 组提出** · 运行中 | **运行中** | 打开 |
   | 12:05 | 并网审批时长的项目样本中位数 | **第 3 组提出** · **9 来源** | **已就绪** | 打开 |
   | 11:40 | 本地化率 40% 的补贴口径原文 | **引导师提出** · **3 来源** | **已就绪** | 打开 |
   | 11:12 | 资质随主体变更是否需重新受理 | **第 2 组提出** · **冲突 2 处** | **待判定** | 打开 |

   ⇒ 现场态的状态枚举逐字为 **`运行中` / `已就绪` / `待判定`** 三值。
   ⚠ 与 `uc-24-3` 的 `进行中 / 已完成 / 待复核 / 已出结论 / 已归档` **不是同一套词**
   → **Q-10**（状态枚举单一事实源）。**本 UC 不自行映射。**
   ⇒ 第三列在无冲突时显示**来源数**、有冲突时显示**冲突数**——**同一列两种语义** → **Q-17**。
4. **冲突待判定**区，头部逐字：「**冲突待判定** | **两条结论互相矛盾时，先标不确定再上台讨论**」
   `[原型 @15,499,042B]`。
5. 冲突项正文逐字（原型示例）：
   「行业报告说平均 7 个月，项目样本中位 9.5 个月。**建议以样本为准，报告标为参考。**」
6. 冲突项下三个动作，逐字为：**`以样本为准`** `[原型 @15,499,518B]` · **`再补一路检索`** · **`上台讨论`**。
   ⇒ 三条对应三种处置：**采信一方** / **加检索** / **升级为现场议题**。
7. 点 `打开` → 进入该研究主题的详情（`uc-24-2`）。

## R4 备选流程与异常流程

**备选流程**
- **A1 `只看有冲突的`**：筛选后只保留状态为 `待判定`（或冲突数 > 0）的行。
  `[设计]` 判据取「冲突数 > 0」而非状态词——状态词枚举尚未收敛（Q-10）。
- **A2 冲突 0 处**：冲突待判定区显示空态（`[设计]`：「暂无待判定的冲突」），
  **不隐藏整个区块**——隐藏会让引导师以为这个能力不存在。
- **A3 无任何现场研究任务**：列表空态 + 主 CTA。**不得**显示编造示例。
- **A4 `上台讨论`**：`[待确认]` 它把冲突升级成什么——一个议程环节内的讨论项？
  一个待办？一个决策节点？原型只给了按钮，没给去向。→ **Q-18**。
  ⚠ **绝不由实现者发明。**

**异常流程**
- **E1 研究 agent 在现场跑挂**：该行状态标失败并可重试，**其余行不受影响**；
  现场不能因为一路挂了就整屏空白。
- **E2 冲突判定后又出现新证据**：`[待确认]` 已判定的冲突是否重开。→ **Q-19**。
- **E3 时间盒超出环节时长**：`[设计]` 现场发起时，若所选深度档位（UC-24.1 字段 4）的时间盒
  **长于当前环节剩余时间**，应给出提示但**不阻止**——引导师有权让结论落到下一环节。
  ⚠ 这条是 `[设计]`，原型未给此校验。
- **E4 观察者**：只读，无 `＋ 发起研究`、无三个判定动作（见 R5）。
- **E5 权限不足**：见 R5。

## R5 权限与可见性

- **引导师**：可见本场全部研究任务（不分组），**独有**三个冲突判定动作
  （`以样本为准` / `再补一路检索` / `上台讨论`）。→ **Q-14** 确认组长是否共享。
- **组长**：可发起、可见 `全场共用` + 本组的任务；`[设计]` **不可**执行冲突判定
  ——判定会改变全场口径。
- **组员**：可发起（限本组）、可见本组的。
- **观察者**：只读列表，不可发起、不可判定（原型 `roleNow === "obs"` → `actions` 空数组
  `[原型 @16,943,050B]`）。
- **未列出的角色默认无权限。**

## R6 后置条件 / 不包含

**后置条件**
- 现场任务列表的三个计数（总数 / 已就绪数 / 冲突数）反映真实数据。
- 冲突被判定后，其处置被记录（谁、何时、选了哪一条），且**记录不可静默删除**
  ——它会成为 `uc-24-4` 入库时的上下文。
- `上台讨论` 的去向 **Q-18 未裁前不实现**（按钮可存在但明确标为待定，或暂不渲染 → **Q-18**）。

**不包含**
- 研究本身的对话与结果 → `uc-24-2`（点 `打开` 进入）。
- 现场协作的其它面（主持台对话、本组能力、四组并行监看）→ `00-project` / `05-rec` 域。
  ⚠ `PROTOTYPE-SWEEP-UI.md` P-08 记录 `isLiveAll` / `isLiveGrp` 两屏未画，**那不是本域的活**。
- 冲突升级后的现场议程调整 → `00-project`。

## R7 业务规则

- **R7.1（本 UC 头号硬约束）冲突先标不确定，再上台讨论。**
  `[原型 @15,499,042B]` 逐字：「两条结论互相矛盾时，**先标不确定再上台讨论**。」
  ⇒ 系统**不得**自动挑一条当结论；冲突项在被人判定前，其两条结论都停留在
  `uc-24-2` 的段 ②「争议 / 不确定」，因而按 `uc-24-4` R7.2 **不可入库**。
- **R7.2 现场结论仍受 `uc-24-4` 的入库门槛约束。** 现场不是绕过门槛的旁路。
- **R7.3 「建议」是建议，不是默认执行。** 冲突项正文里的「**建议**以样本为准」是 agent 的推荐，
  三个动作里 `以样本为准` 需**人点**。⚠ 不许把 agent 建议做成预选或倒计时自动执行。
- **R7.4 提出方必须留痕。** 每行都带「第 n 组提出 / 引导师提出」——
  它是现场复盘与审计的输入（`00-project` 的审计记录四类事件之一）。
- **R7.5 状态枚举不在本域定义第二份。** 见 R3.3 与 **Q-10**。
