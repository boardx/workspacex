# 原始需求（细化）— UC-24.3 研究 Studio 列表与研究计划详情

> 所属：阶段一 · 能跑完一场项目 / M24 研究 Studio（research）
> 口径与四标记见 `00-index.md`。`[原型 @n,nnn,nnnB]` = **字节**偏移。
> 元数据：优先级 **P0**；估点 **5**；建议迭代 **01**。
>
> ⚠ 本 UC 覆盖**两个层级的列表**（研究项目 / 研究主题）与**一个汇总详情**（研究计划）。
> 原型把它们放在两处，**层级关系原型没有明说** → **Q-8**，这是本 UC 最大的未定项。

## R1 概览

- **Use Case ID / 名称**：UC-24.3 / 研究 Studio 列表与研究计划详情
- **Actor**：**引导师** / **组长** / **组员** / **观察者**（后者只读，R5）
- **目标**：让人在一屏里看清「**有哪些研究、各自跑到哪、证据够不够、有没有可以拿去用的洞察**」，
  并能从任一入口打开某一项深入（`uc-24-2`）。
- **系统边界**：Studio 侧研究项目列表、Studio 左栏研究三段、项目内深度研究主题列表、
  研究计划汇总详情（三计数 + 证据表）。
  单主题的对话与结果归 `uc-24-2`；发起归 `uc-24-1`。
- **核心数据对象**：研究项目（研究计划）、研究主题、证据条目、候选洞察、标签、状态。

## R2 前置条件 / 触发条件

**前置条件**：用户已登录并在当前组织/项目内有可见性（R5）。空列表是合法态（R4 A3）。

**触发条件**
- 点导航「研究」→ `/studio/research`（`navigation.ts:75`，**该路由当前承载 UC-0.2 Context Pack** → **Q-2**）。

1. 头部逐字：「**研究项目 · 3**」+ 副标题「**打开任意一个进入全屏管理：研究问题、证据表、候选洞察。**」

2. 标签筛选行逐字五项：`全部` / `客户` / `内部` / `高优先级` / `已归档`。

3. 每张卡逐字包含：标题（`德国工商储电价机制`）· 状态徽章（`进行中`）·

   ⇒ **卡片上的四个数是本域的核心指标**：证据数 / 证据目标 / 研究问题数 / 候选洞察数。

### B. 项目内深度研究主题列表（`isDrList` `[原型 @15,326,428B]`）

   「**每个主题是一段和 Scout 的深度对话：提问 → 检索与交叉验证 → 出结论。
   结论必须挂着外部来源才能进洞察库。**」`[原型 @15,326,937B]` + 主 CTA「**＋ 新建深度研究**」。
2. 标签筛选逐字五项：`全部标签` / `客户` / `内部` / `高优先级` / `已归档`。
3. 每行逐字包含：置顶标记（`关键 · 置顶`）· 状态（`已出结论`）· **问题原文**作为标题 ·
   标签 · 元信息「**林可提出 · 来源 14**」`[原型 @15,330,698B]`。
4. 行动作两个（原型的 handler 名可查）：
   - `copyDrItem` →「**已复制为新的深度研究**」`[原型 @16,906,921B]`
   - `delDrItem` →「**已归档该研究主题**」`[原型 @16,907,049B]`
     ⚠ 逐字是「**归档**」不是「删除」——**本域没有硬删除**。见 R7.3。

### C. Studio 左栏研究三段（`isStRes` `[原型 @16,003,815B]`）

⇒ **状态是四值以上**：`进行中` / `已完成` / `待复核` / （B 里另有）`已出结论` / `已归档` → **Q-10**。

### D. 研究计划汇总详情（`isResOne` `[原型 @16,168,869B]`）

1. 面包屑 `‹ 全部研究`，标题「**德国工商储电价机制 · 研究计划**」，副标题「**进行中 · Scout 并行 3 路**」。
2. **三计数条**，每格逐字为「大标题 | 数字 | 注脚」：

   | 计数 | 数字 | 注脚（逐字） |
   |---|---|---|
   | **研究问题** | 5 | **来自项目环节 2 的假设** |
   | **证据** | 41 / 50 | **含 6 条访谈引述** |
   | **候选洞察** | 7 | **待送综合 Studio 验证** |

   ⚠ 三条注脚各自指出一个**跨域依赖**：环节（`00-project`）、访谈（`06-itv`）、
   「综合 Studio」（**全仓无此名**，疑为 phase-02 `09-kg` 或 `10-report`）→ **Q-11**。
3. **证据表 · 按研究问题分组**，列逐字为 `证据 | 来源 | 置信度 | 去向`；原型三行：

   | 证据 | 来源 | 置信度 | 去向 |
   |---|---|---|---|

## R4 备选流程与异常流程

**备选流程**
- **A1 标签筛选**：点任一标签只过滤，不改变卡片形态；`已归档` 是标签之一而不是独立视图。
- **A2 置顶**：B 列表有 `关键 · 置顶` 标记。`[待确认]` 置顶由谁设、是否等同「标为关键问题」
  （`uc-24-4` 的出口动作之一）→ **Q-13**。
- **A3 空列表**：`[设计]` 显示「还没有研究」+ 主 CTA，**不得**显示编造的示例卡。
  同仓已有空态口径可复用（原型另处逐字「还没有可检查的合同 / 上传合同 / 用示例合同试一次」
  `[原型 @16,480,137B]`，属 phase-02 原型 Studio，**口径借用**）。

**异常流程**
- **E1 计数取不到**（如证据目标未设）：`[设计]` 显示 `证据 41 / —`，**不得**把缺失显示为 0
  ——0 会被读成「目标是 0，已超额完成」。
- **E2 某研究的 agent 挂了**：卡片状态显示失败并可重试，其余卡不受影响。
- **E3 归档后**：条目仍可通过 `已归档` 标签检索到；其证据的「去向」若为 `已引用`，
  **引用方不失效**（R7.3）。
- **E4 观察者**：见 R5。
- **E5 权限不足**：无权见的研究**不出现在列表里**（不是显示后禁止打开）。

## R5 权限与可见性

- **引导师**：可见项目内全部研究，可新建、可归档、可改标签。
- **组长**：可见 `全场共用` + 本组的研究；可新建、可归档**本组的**。
- **组员**：`[设计]` 可见 `全场共用` + 本组；**不可**归档他人发起的。→ **Q-14**。
- **观察者**：**只读已共享的**。原型同类口径逐字：「观察者只看已共享的」`[原型 @16,930,486B]`
  （原文是 `obs: "观察者只看已共享的"`，在 `resItems` 上方的 `vis` 角色映射里）。
  且看不到证据表中来自 `本场转写` 的原文（`uc-24-2` R5）。
- **未列出的角色默认无权限。**

## R7 业务规则

- **R7.1 计数必须是真实分子分母。** `证据 41 / 目标 50`、`证据 41 / 50`、`5 个研究问题 · 7 条候选洞察`
  必须取自真实数据，**不得**硬编码；且 E1 的缺失不得伪装成 0。
- **R7.2 「去向」是闭集。** 见 R3.D.3 与 **Q-12**。`反对证据` 与 phase-03 `14-brain`
  决策链模板的同名概念**收敛为单一事实源**——本域**引用**，不定义。
- **R7.3 只归档不删除。** `delDrItem` 的提示逐字是「已**归档**该研究主题」。
  已被引用的证据在归档后**不失效**，否则引用方会凭空断链。
- **R7.4 状态枚举单一事实源。** A/B/C 三处列表出现了 `进行中` / `已完成` / `待复核` /
  `已出结论` / `已归档` **至少五个词**，其中 `已完成` 与 `已出结论` 疑为同一状态的两种叫法
  → **Q-10**。⚠ **本 UC 不自行合并**——本仓已八次因「同名不同义 / 异名同义」漂移。
