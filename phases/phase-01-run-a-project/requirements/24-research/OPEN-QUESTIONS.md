### Q-8 · 「研究项目 / 研究计划 / 研究主题」是几层

- **现状（原型自相矛盾的地方）**：
  - Studio 侧 `isResList` `[原型 @16,157,163B]` 叫「**研究项目 · 3**」，卡上写
    「5 个研究问题 · 7 条候选洞察」——像是**项目 → 问题**两层。
  - 项目侧 `isDrList` `[原型 @15,326,428B]` 叫「**深度研究 · 4 个主题**」，每个主题
    「是一段和 Scout 的深度对话」——像是**主题 = 一段对话**一层。
  - `isResOne` `[原型 @16,168,869B]` 叫「… · **研究计划**」，三计数是「研究问题 5 / 证据 41 / 候选洞察 7」。
  - **三个词（项目 / 计划 / 主题）在原型里没有一处定义它们的关系。**
- **影响**：决定 UC-24.1 创建的到底是哪一层、UC-24.3 的列表是一个还是两个。

| | 方案 | 优点 | 缺点 |
|---|---|---|---|
| **A** | **一层**：研究主题 = 研究项目 = 研究计划，三词同义，统一叫「研究」 | 最简；phase-01 可直接落地 | 「5 个研究问题」无处安放（一个研究里的多个问题） |
| **B** | **两层**：研究（计划）→ 研究问题；每个问题一段 Scout 对话 | 三计数与卡片计数都说得通；与 `res.goal`「5 个研究问题各有 ≥3 条独立来源」一致 | 比 A 多一层，估点上浮 |
| **C** | **三层**：项目 → 计划 → 主题 | 每个词各有其位 | 原型无任何证据支持三层；属发明 |

**我的推荐：B**。理由：`[原型 @16,781,061B]` 的 `res.goal` 逐字「**5 个研究问题**各有 ≥3 条独立来源」
与 `isResOne` 的三计数「研究问题 5」互相印证，**两层是原型唯一自洽的读法**；C 无出处。
⚠ 若选 B，`uc-24-1` 创建的是**研究（计划）**还是**研究问题**，需一并指明。

**选择：**（未裁）

### Q-10 · 研究状态枚举到底有几个值

原型在四处给出**至少八个词**，无一处给全集：

| 出处 | 字节 | 词 |
|---|---|---|
| `isResList` 卡 | 16,157,163 | `进行中` |
| `isStRes` 左栏 | 16,003,815 | `进行中` / `已完成` / `待复核` |
| `isDrList` 行 | 15,326,428 | `已出结论` / `已归档`（标签） |
| `isWsDrl` 现场行 | 15,493,520 | `运行中` / `已就绪` / `待判定` |

疑似同义对：`进行中`≈`运行中`、`已完成`≈`已出结论`、`待复核`≈`待判定`。
**但「疑似」不能当依据。** ⚠ 本仓第八次事故就是「同名不同义 / 异名同义」。

| | 方案 | 优点 | 缺点 |
|---|---|---|---|
| **A** | 收敛为**一套五值**：`草稿 / 运行中 / 已就绪 / 待判定 / 已归档`，各屏用同一套词 | 单一事实源；门控可断言 | 与原型某些屏的文案不逐字一致 |
| **B** | 保留两套（Studio 侧 / 现场侧）+ 一张映射表 | 每屏与原型逐字一致 | 两套枚举 = 第二份声明，本仓已六次栽在这 |

**我的推荐：A**，并把各屏的显示文案做成 `枚举 → 文案` 的**单向映射**（枚举是权威，文案是派生）。
