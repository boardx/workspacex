### ⚠ 坐标系：本模块用**字节偏移**，不是字符偏移

`23-asset` 用的是**字符**偏移（`@16.55M`），`ui-preview/PROTOTYPE-SWEEP-UI.md` 用的是**字节**偏移。
两者在本文件上差约 **139,915**（全文件 17,050,600 字节 vs 16,910,685 字符）。
本模块**一律用字节偏移**并写全位数 + `B` 后缀，与 sweep 报告可直接对齐。
复现方法（macOS BSD `grep -bo` 在这种「整份文件只有一行」的 17MB 文件上会给**错误偏移**，别用）：

```bash
python3 - <<'PY'
import re
b = open('phases/requirements/WorkspaceX Standalone.html','rb').read()
print([m.start() for m in re.finditer(b'\xe6\x96\xb0\xe5\xbb\xba\xe6\xb7\xb1\xe5\xba\xa6\xe7\xa0\x94\xe7\xa9\xb6', b)])  # 「新建深度研究」
PY
```

## 为什么单独成一个能力域

1. **原型给了它一级导航，且是三个 Studio 之一**。`[原型 @16,780,654B]` 的 Studio 元数据里
   `res` 与 `itv` / `svy` / `proto` 并列，逐字为：
   「`res: { name: "研究 Studio", desc: "研究计划 · 桌面研究 · 证据 · 报告",
   newLabel: "＋ 新建研究", stage: "环节 2 · 证据补齐",
   slot: "环节 2 · 产出槽「研究简报」",
   goal: "5 个研究问题各有 ≥3 条独立来源，低置信度必须标出而不是丢弃。",
   expect: "研究简报 ＋ 证据表（Artifact 类型：report / evidence）" }`」
   ——`itv`（访谈）已经是 phase-01 的 `interview` 束（20 feature / 68 点），
   `res` 与它同构、同级，却一个 feature 都没有。
2. **已有 UC 明写「归研究 Studio，本文不定」**。
   `06-itv/uc-6-0-访谈-studio-列表与范围.md:133` 逐字：
   「研究 Studio / 问卷 Studio / 原型 Studio 的列表（**各自独立用例**，本文只定共用的范围模型）。」
   `22-files/uc-22-1-项目文件浏览器.md:68` 把 `research` 列为八类来源之一，产物是
   「网页快照 + `citations.json`（研究 Studio）」；`:255` 与 `contracts/files/domain.md:178`
   都把「来源类型八值枚举必须与 … **研究 Studio** 的产出侧一致」写成跨束约束。
   ⇒ **已签核的 `files` 束正在依赖一个不存在的束。** 这与 `project` 束当初被发现缺失时
   是同一形状（「被别的束依赖、自己却是空的」）。
3. **下游两个 phase 都在指望它**。`10-report/uc-10-2-对话式生成.md:50` 的取材表里
   「研究 | 研究 4 份 | **研究 Studio**」；`11-board/uc-11-2-任务自动汇入.md:256`
   的汇入来源里也有「研究（**研究 Studio**）」。D-20 的立论原文即：
   「它是 09-kg 证据的主要生产者、10-report 取材范围里「研究」那一项的实体。」

## 与其它模块的边界

- **不在本模块**：Context Pack 的读入/丢弃清单（`00-core/uc-0-2`，已在 phase-00）、
  访谈证据的生产（`06-itv`）、问卷证据的生产（phase-02 `12-survey`）、

  它产出的证据表与候选洞察、以及**结论离开本模块时的去向与门槛**。
