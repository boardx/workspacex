# 原始需求（细化）— UC-24.4 研究结论回流与去向

> 所属：阶段一 · 能跑完一场项目 / M24 研究 Studio（research）
> 口径与四标记见 `00-index.md`。`[原型 @n,nnn,nnnB]` = **字节**偏移。
> 元数据：优先级 **P0**；估点 **3**；建议迭代 **01**。
>
> ⚠ 本 UC 是 M24 的**出口门**。D-20 的立论逐字：「它是 **09-kg 证据的主要生产者**、
> **10-report 取材范围里「研究」那一项的实体**」——那两件都在 phase-02，
> 因此本 UC 在 phase-01 要做的是**把出口和门槛做出来**，而不是把下游做出来。

## R1 概览

- **Use Case ID / 名称**：UC-24.4 / 研究结论回流与去向
- **Actor**：**引导师** / **组长** / **组员**（视范围，R5）；**观察者不可执行任何出口动作**。
- **目标**：让一条研究结论**带着出处**离开研究 Studio，进入洞察库 / 报告 / 决策节点，
  并让「**够不够格离开**」这件事由**机械门控**判定，而不是由人的自觉。
- **系统边界**：结论区的出口动作、洞察库入库门槛、决策节点回流、报告取材登记、
  以及现场对话面里的三个同族动作。
  结论的生成归 `uc-24-2`；洞察进图谱后的推演归 phase-02 `09-kg`；报告成文归 phase-02 `10-report`。
- **核心数据对象**：研究结论、候选洞察、证据引用、决策节点引用、去向标记。

## R2 前置条件 / 触发条件

**前置条件**
- 存在一条已生成的研究结论（`uc-24-2` 段 ④）。
- **入库前置（硬）**：该结论**至少挂一条外部来源**（R7.1）。

**触发条件**
- 研究详情结论区三个按钮 `[原型 @15,347,541B / 15,347,705B / 15,347,866B]`，逐字为：
  **`加入洞察库`** · **`补充资料`** · **`标为关键问题`**。
- 现场/小组对话面的三个同族动作（`isRes` 分支）`[原型 @16,942,894B]`，逐字为：
  **`存为洞察`**（主按钮）· **`加入报告`** · **`开一场深度研究`**。
- 研究侧产出物三项 `[原型 @16,944,170B]`，逐字为：
  「候选洞察 2 条 · **待入定题池**」/「证据卡 3 张 · **带出处**」/「研究简报片段 · **可加入报告**」。

## R3 主流程

1. 用户在结论区点 **`加入洞察库`**。
2. 系统跑**入库门控**（R7.1–R7.3），三条全过才放行：
   - ① 结论挂了 ≥1 条**外部来源**（`uc-24-2` 段 ③ 非空）
   - ② 该结论**不在**「争议 / 不确定」段（段 ② 的条目**永不入库**）
   - ③ `[设计]` 若研究配置挂了决策节点（UC-24.1 字段 7 ≠ `n0`），入库同时**回流该节点并标注置信度**
     ——依据 UC-24.1 预览句逐字承诺「**结论回流到所选决策节点并标注置信度**」`[原型 @16,906,509B]`。
3. 门控通过 → 结论成为**候选洞察**，其在证据表里的「**去向**」标记更新（`uc-24-3` R3.D.3）。
   ⚠ 候选洞察逐字标注为「**待入定题池**」/「**待送综合 Studio 验证**」（`uc-24-3` D.2）
   ——即**入洞察库 ≠ 已被采信**，中间还有一道下游验证。**那道验证不在 phase-01**（→ Q-11）。
4. 门控不通过 → **阻断**，并逐条说明缺哪一条（对照 phase-02 问卷域已确立的
   「阻断必须修 · 修完才能发布」口径；⚠ 那是**别的域的**已有口径，此处为**形式借用**，不是本域出处）。
5. 用户点 **`补充资料`** → 回到 `uc-24-2` 的追问，且预填「补哪一类来源」。
6. 用户点 **`标为关键问题`** → 该研究在列表里获得 `关键 · 置顶` 标记（`uc-24-3` A2）→ **Q-13**。
7. 现场侧点 **`加入报告`** → 该结论被登记进报告取材范围。
   ⚠ **phase-01 只做登记，不做报告成文**（`10-report` 在 phase-02）。
8. 现场侧点 **`开一场深度研究`** → 以当前对话上下文为种子，打开 UC-24.1 的弹层（预填场景与问题）。

## R4 备选流程与异常流程

**备选流程**
- **A1 未挂决策节点**（UC-24.1 选了 `n0 不挂节点，只存进洞察库`）：跳过 R3.2③，
  只入洞察库。**这是合法路径，不是降级。**
- **A2 结论被改写后重新入库**：`[待确认]` 已入库的洞察在原研究结论被追问改写后，
  是**跟随更新**还是**保持快照**。→ **Q-6**（与 `uc-24-2` R3.8 同一问题）。
  ⚠ 本仓已有相关裁决 **D-38**「发布结论 · **必须绑定一个确定的产出版本**」
  （`DECISIONS-DELTA.md:305`）——**倾向快照**，但那条裁的是 Context Pack，
  **不能直接当本域的答案用**。请人类确认它是否外延到此处。
- **A3 反对证据入库**：置信度低但方向相反的证据，「去向」标 `反对证据`（`uc-24-3`）。
  `[设计]` 它**也应入库**——反对证据是决策链模板的硬要求之一。→ 与 phase-03 `14-brain` 收敛。

**异常流程**
- **E1 无外部来源**：`加入洞察库` **被阻断**，提示指明「结论必须挂着外部来源才能进洞察库」
  `[原型 @15,326,937B]`。⚠ 必须是**机械阻断**（按钮点了不生效 + 说明），
  **不是**灰掉按钮就算数——灰掉的按钮在无障碍与 API 层都挡不住。
- **E2 决策节点已被删除 / 已关闭**：`[设计]` 入库仍成功，但节点回流失败并**显式记录失败原因**，
  不得静默丢弃。
- **E3 重复入库**：`[待确认]` 同一结论再次点 `加入洞察库` 的行为（幂等 / 报错 / 新建一条）。→ **Q-15**。
- **E4 观察者点到**：动作按钮**不渲染**（原型 `roleNow === "obs"` 时 `actions` 返回**空数组**
  `[原型 @16,943,050B]`）——这是原型自己的实现，不是设计推断。
- **E5 下游（洞察库 / 报告）不可用**：入库操作**失败并保留结论原状**，可重试；
  **不得**产生「本地显示已入库、下游没有」的假成功。

## R5 权限与可见性

- **引导师**：全部三个出口动作，范围为全场。
- **组长**：全部三个，范围限本组产出的结论。
- **组员**：`[设计]` 可 `补充资料`；`加入洞察库` 与 `标为关键问题` 是否需组长/引导师确认 → **Q-14**。
- **观察者**：**零个出口动作**（E4 的原型实现即此）。
- **未列出的角色默认无权限。**

## R6 后置条件 / 不包含

**后置条件**
- 入库成功后：存在一条候选洞察，带完整证据引用链（可从洞察反查到证据、来源、原始对话轮）；
  证据表的「去向」已更新；若挂了节点，节点上有一条带置信度的回流记录。
- 入库失败后：结论**原封不动**，失败原因可见，可重试。

**不包含**
- 洞察库本身的管理界面（`14-brain` 三层记忆，**phase-03**）。
- 候选洞察的下游验证（「综合 Studio」→ **Q-11**）。
- 报告的取材与成文（`10-report`，**phase-02**）。
- 知识图谱的决策推演（`09-kg`，**phase-02**）。
- ⚠ 以上四条**都不在 phase-01**。本 UC 提供的是**出口与门槛**，不是下游。

## R7 业务规则

- **R7.1（本 UC 头号硬约束）结论必须挂外部来源才能进洞察库。**
  `[原型 @15,326,937B]` 逐字：「结论必须挂着外部来源才能进洞察库。」
  ⇒ 机械门控，不是文案。
- **R7.2 争议 / 不确定项永不入库。** `[原型 @15,344,827B` 段内`]` 逐字：
  「此条按「不确定」保留，**不进洞察库**。」
- **R7.3 低置信标出而不是丢弃**（`uc-24-2` R7.3）。⇒ 低置信来源**不阻断入库**，
  但必须随洞察一起带过去并保持标注。**「标出」与「阻断」是两件事，别混。**
- **R7.4 入库 ≠ 采信。** 候选洞察逐字「**待入定题池**」「**待送综合 Studio 验证**」。
  ⇒ 本域产出的是**候选**，任何下游把它当既成结论用都是缺陷。
- **R7.5 出口动作的枚举不在本域定义两份。** 结论区三个（`加入洞察库` / `补充资料` / `标为关键问题`）
  与对话面三个（`存为洞察` / `加入报告` / `开一场深度研究`）**是两组不同的动作**，
  但 `加入洞察库` 与 `存为洞察` 疑为同一动作的两种叫法 → **Q-16**。
  ⚠ **本 UC 不自行合并**——异名同义正是本仓第八次事故的形状。

## R9 非功能约束

- **性能 / 规模**：入库是单条操作，无批量需求（原型未给批量入口）。
- **安全 / 隐私**：入库的证据若含访谈引述，其受访者授权状态必须在入库时校验；
  **撤回后已入库洞察的失效链** → `06-itv` 是单一事实源（**已签核**），
  **本域不复述 SLA 天数**（本仓已因「撤回链 SLA 两处声明」漂移过一次）。
- **兼容与降级**：E5 的「失败保留原状 + 可重试」即降级要求；
  **禁止**乐观 UI（假成功）——它会制造引用不存在的洞察。

## R12 AI Ready 验收线索

1. **R7.1 / E1**：造一条无外部来源的结论，点 `加入洞察库` → **被阻断**且给出原因。
   ⚠ 断言必须打在**行为**上（入库未发生），不是打在按钮的 `disabled` 属性上。
2. **R7.2**：造一条落在「争议 / 不确定」的条目，断言它**没有**入库入口，或入口阻断。
3. **R7.3**：造一条含 0.3 低置信来源的合格结论，断言**入库成功**且低置信标注**随之带过去**
   （性质断言：入库后的洞察上仍能读到该来源与其置信度）。
4. **A1**：`n0 不挂节点` 的研究入库成功且**无**节点回流记录。
5. **R3.2③**：挂了 `n1` 的研究入库后，节点上出现一条带置信度的回流记录。
6. **E2**：删掉节点后入库 → 入库成功 + 回流失败原因可读。
7. **E5**：让下游返回 500 → 结论原状保留、可重试、**不显示已入库**。
8. **E4 / R5**：`?as=obs` 下三个出口按钮**不存在于 DOM**。
9. **R7.4**：入库后的对象类型是「候选洞察」，其状态逐字含「待…验证 / 待入定题池」之一。
