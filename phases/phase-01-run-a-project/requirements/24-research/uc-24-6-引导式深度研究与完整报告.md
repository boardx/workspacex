# 原始需求 — UC-24.6 引导式深度研究与完整报告

> 所属：阶段一 · M24 研究 Studio（research）
> 来源：用户 2026-08-12 明确需求 + `boardx-web` / `boardx-backend` Deep Research 参考实现。
> 本 UC 是既有 UC-24.1…24.5 的增量，不修改它们已经确认的行为。

## R1 目标

研究者从统一研究首页创建或恢复研究，依次确认主题、编辑 AI 建议的研究方向、编辑报告大纲，
再由系统按大纲执行 Web Search，最终生成带来源引用的完整研究报告。

## R2 角色与入口

- 已登录研究拥有者和协作者可进入 `/research?flow=home`。
- 首页展示历史研究，至少区分 `待确认主题 / 研究中 / 已完成`。
- 未完成项提供「继续研究」，恢复到持久化的当前步骤；完成项提供「查看研究」，进入报告。
- 「创建研究」进入主题确认，不直接触发搜索。

## R3 主流程

1. **研究首页**：查看历史研究或创建研究。
2. **确认主题**：编辑主题、目标、时间范围、地域范围和重点关注；主题与目标非空才可继续。
3. **研究方向**：AI 生成互补方向；每个方向可启用/停用、编辑、删除，也可新增或重新生成。
4. **报告大纲**：根据启用方向生成章节；章节可编辑、新增和排序，开始研究前必须再次确认。
5. **Web Search**：按章节执行，显示整体进度、当前查询、章节任务状态、来源数量和最新来源；离开后可恢复。
6. **完整报告**：按已确认大纲展示正文、目录、来源引用、生成时间和来源数。

## R4 失败与恢复

- 方向或大纲生成失败时保留用户已确认的上一阶段数据，并提供重试。
- Web Search 单个章节失败不抹掉其它章节已找到的来源；允许重试失败章节。
- 页面刷新或离开后，服务端状态是恢复依据，前端不得从头重新创建研究。
- 报告生成失败时仍可查看已完成搜索与来源，并可重新生成报告。

## R5 数据与证据约束

- 研究主题、方向、大纲分别有独立的确认时刻；后一步不得静默覆盖前一步的人类编辑。
- 搜索来源必须带标题、URL/域名、来源类型和可追溯引用身份。
- 报告的关键判断必须能回到来源；来源列表不是装饰性计数。
- 未完成研究的「继续」目标由服务端当前阶段决定，不由卡片文案猜测。

## R6 不包含

- 本 UC 不改变既有候选洞察入库、冲突判定和项目现场研究语义（UC-24.4 / 24.5）。
- 本轮 UI-first 不接真实后端；API 与持久化需在 design delta 签核后按 feature 拆分实现。
- 报告导出格式、分享权限与协同评论不在本 UC 范围。

## R7 UI 与可观测锚点

路由预览：`/research?flow=home|brief|directions|outline|search|report`。

关键锚点：

- `research-history` / `research-create`
- `research-brief-topic` / `research-confirm-brief`
- `research-directions` / `research-direction-title-<id>` / `research-add-direction`
- `research-outline` / `research-outline-title-<id>` / `research-start-search`
- `research-search-progress` / `research-current-query` / `research-source-<id>`
- `research-report` / `research-citation-<id>`

## R8 AI Ready 验收线索

1. 历史列表里，未完成项可继续到保存阶段，已完成项只进入报告。
2. 主题文本可编辑，且主题或目标为空时继续按钮禁用。
3. AI 研究方向可编辑、新增、删除、启停；修改结果用于后续大纲生成。
4. 大纲章节可编辑和新增；确认后才开始 Web Search。
5. 搜索态同时展示进度、当前查询、章节状态和来源，不是一个无限 spinner。
6. 刷新/离开再进入时恢复同一研究的阶段和已完成结果。
7. 完整报告包含正文、目录和至少一条可追溯来源引用。
