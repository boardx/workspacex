# 原始需求 — UC-24.6 引导式深度研究与完整报告

> 所属：阶段一 · M24 研究 Studio（research）
> 来源：用户 2026-08-12 明确需求 + `boardx-web` / `boardx-backend` Deep Research 参考实现。
> 本 UC 是既有 UC-24.1…24.5 的增量，不修改它们已经确认的行为。

## R1 目标

研究者从统一研究首页创建或恢复研究，依次确认主题、编辑 AI 建议的研究方向、编辑报告大纲，
再由系统按大纲执行 Web Search，最终生成带来源引用的完整研究报告。

## R2 角色与入口

- 已登录研究拥有者和协作者可进入 `/research?flow=home`。
- 首页展示历史研究，至少区分 `待确认主题 / 研究中 / 已完成`。
- 未完成项提供「继续研究」，恢复到持久化的当前步骤；完成项提供「查看研究」，进入报告。
- 「创建研究」进入主题确认，不直接触发搜索。

## R3 主流程

1. **研究首页**：查看历史研究或创建研究。
2. **确认主题**：编辑主题、目标、时间范围、地域范围和重点关注；主题与目标非空才可继续。
3. **研究方向**：AI 生成互补方向；每个方向可启用/停用、编辑、删除，也可新增或重新生成。
4. **报告大纲**：根据启用方向生成章节；章节可编辑、新增和排序，开始研究前必须再次确认。
5. **Web Search**：按章节执行，显示整体进度、当前查询、章节任务状态、来源数量和最新来源；离开后可恢复。
6. **完整报告**：按已确认大纲展示正文、目录、来源引用、生成时间和来源数。

## R4 失败与恢复

- 方向或大纲生成失败时保留用户已确认的上一阶段数据，并提供重试。
- Web Search 单个章节失败不抹掉其它章节已找到的来源；允许重试失败章节。
- 页面刷新或离开后，服务端状态是恢复依据，前端不得从头重新创建研究。
- 报告生成失败时仍可查看已完成搜索与来源，并可重新生成报告。

## R5 数据与证据约束

- 研究主题、方向、大纲分别有独立的确认时刻；后一步不得静默覆盖前一步的人类编辑。
- 搜索来源必须带标题、URL/域名、来源类型和可追溯引用身份。
- 报告的关键判断必须能回到来源；来源列表不是装饰性计数。
- 未完成研究的「继续」目标由服务端当前阶段决定，不由卡片文案猜测。

## R6 不包含

- 本 UC 不改变既有候选洞察入库、冲突判定和项目现场研究语义（UC-24.4 / 24.5）。
- 本轮 UI-first 不接真实后端；API 与持久化需在 design delta 签核后按 feature 拆分实现。
- 报告导出格式、分享权限与协同评论不在本 UC 范围。

## R7 UI 与可观测锚点

路由预览：`/research?flow=home|brief|directions|outline|search|report`。

关键锚点：

- `research-history` / `research-create`
- `research-brief-topic` / `research-confirm-brief`
- `research-directions` / `research-direction-title-<id>` / `research-add-direction`
- `research-outline` / `research-outline-title-<id>` / `research-start-search`
- `research-search-progress` / `research-current-query` / `research-source-<id>`
- `research-report` / `research-citation-<id>`

## R8 AI Ready 验收线索

1. 历史列表里，未完成项可继续到保存阶段，已完成项只进入报告。
2. 主题文本可编辑，且主题或目标为空时继续按钮禁用。
3. AI 研究方向可编辑、新增、删除、启停；修改结果用于后续大纲生成。
4. 大纲章节可编辑和新增；确认后才开始 Web Search。
5. 搜索态同时展示进度、当前查询、章节状态和来源，不是一个无限 spinner。
6. 刷新/离开再进入时恢复同一研究的阶段和已完成结果。
7. 完整报告包含正文、目录和至少一条可追溯来源引用。

## R9 已签 UI 保真与入口收口

- `/research` 和主导航「研究」默认进入本 UC 的研究首页，不把用户带到旧的
  `?screen=detail` 研究主题详情。引导式 Deep Research 六屏不渲染 Research Studio 二级左栏；
  旧 Studio 页面仍可通过显式 `?screen=` URL 访问，并仅在这些旧页面中保留自己的菜单。
- 六个步骤须保持 `ui-preview/01-home.png` 至 `06-report.png` 的信息层级、页面宽度、
  进度条、表单/卡片密度和主要操作位置；真实 API 接线不得把已签界面替换成旧 Studio 页面。
- 桌面 1280px 与 1920px 视口下，流程主内容不得被全局导航遮挡或横向裁切；步骤导航、主标题和
  当前任务必须在首屏形成与签核截图一致的视觉优先级。

## R10 创建研究命名

- 首页两个创建入口都先打开「创建研究」弹窗，不得直接跳进主题表单。
- 研究名称必填，最多 100 字；标签可选，单个最多 20 字、最多 5 个且不重复。
- 用户确认弹窗后才进入主题与范围确认；最终创建会话时，名称与标签必须与 brief 一起持久化，
  并在历史研究卡片中恢复显示。
- 创建请求重试的幂等意图必须同时包含名称、标签和 brief；任一项变化都不得复用旧意图键。

## R11 上下文 Skill、顺序门控与演示边界

本 R11 扩展并汇总 R9 的视觉与入口约束及 R10 的创建元数据约束；F180 以此单一可解析锚点覆盖 R9–R11。

- 除首页外，每个步骤都在左侧提供与当前编辑器同屏的「研究 Skill 助手」，右侧保持一个主工作区。
  Skill 只能针对当前步骤生成建议；建议不会自动写入表单、方向、大纲、检索任务或报告摘要，用户必须显式
  点击「应用建议」，并可以用「撤销上次应用」恢复应用前内容。
- 可访问的最远步骤由服务端持久化阶段决定：后续进度按钮必须禁用，直接请求未来步骤时前端必须先恢复会话
  并钳制到已确认阶段。每次确认只解锁紧接的下一步；搜索页刷新或返回后仍恢复到搜索阶段。
- 搜索与报告页必须明确标记为演示：搜索显示「演示检索结果，不代表真实 Web Search」，报告显示
  「演示报告，不作为真实研究结论」。演示任务和固定演示资料只用于展示流程，不得作为真实研究证据。
- 研究完成后，返回首页的历史卡片显示「已完成」，其唯一完成态操作是「查看报告」。

## R12 LangGraph 五节点状态与完整前端输入

- Brief、Directions、Outline、Research、Report 是同一个 Guided Research LangGraph thread 的五个节点；
  `thread_id` 固定为研究 `sessionId`，生产 checkpointer 使用 PostgreSQL，刷新、API/Graph 服务重启和
  节点失败后都必须从服务端 checkpoint 恢复。
- 前端提交任一步骤命令时，必须携带该页面当前可编辑的**完整 nodeState**：Brief 包含名称、标签、主题、
  目标、时间、地域和重点；Directions 包含完整排序方向数组；Outline 包含完整排序章节数组；Research
  包含完整采纳/排除来源集合；Report 包含标题和修订说明。服务端拒绝缺字段及 NodeMeta 等未知字段。
- 页面使用 `/research?session=<sessionId>` 单一路由；步骤切换只更新页面内状态，不通过 `flow=` 路由跳转，
  不触发整页刷新。左侧 Skill 助手约占三分之一，右侧步骤工作区约占三分之二；报告正文在右侧完整显示。
- 上游节点重确认创建新 revision，并只将其下游节点标记为 `stale`；历史 checkpoint 保留用于审计，
  但恢复和下一步解锁只以服务端当前 Graph projection 为准。

## R13 结构化模型与独立检索边界

- 只有用户显式点击 `generate / confirm / start / retry / reconfirm / complete` 的适用动作才调用模型；
  编辑、查看、GET 恢复、Skill 草稿和步骤切换不得自动调用模型。
- 所有研究节点生产模型固定为阿里云百炼 `qwen3.7-plus`，浏览器不能选择或覆盖 model ID。模型输出必须
  是 JSON object，并通过共享 strict schema 校验；缺少凭据、模型不在准入名单、JSON 无法解析或结构不合法
  时节点 fail closed，不回退 deterministic generator、Mock 或 localStorage。
- 确认 Brief 后模型生成结构化 Directions；确认 Directions 后生成结构化 Outline；确认 Outline 后生成
  结构化 Research Plan 与查询任务；Research 确认采纳来源后生成结构化 Report。
- Web Search 使用独立检索工具链执行查询、抓取与重试。`qwen3.7-plus` 负责查询规划、来源判断、结构化证据
  抽取和综合，但模型内置联网结果不得直接成为证据。每条报告引用必须解析到同一 revision 的已采纳来源。
