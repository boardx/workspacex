# 原始需求（细化）— UC-24.2 与 Scout 的深度研究对话与交叉验证

> 所属：阶段一 · 能跑完一场项目 / M24 研究 Studio（research）
> 口径与四标记见 `00-index.md`。`[原型 @n,nnn,nnnB]` = **字节**偏移。
> 元数据：优先级 **P0**；估点 **5**；建议迭代 **01**。

## R1 概览

- **Use Case ID / 名称**：UC-24.2 / 与 Scout 的深度研究对话与交叉验证
- **Actor**：**引导师** / **组长** / **组员**（可追问）、**观察者**（只读，见 R5）、
  **Scout**（研究 agent，非人类 Actor）。
- **目标**：把 UC-24.1 定下的问题，通过**多轮追问 + 分路检索 + 交叉验证**跑成一组
  「**关键发现 / 争议不确定 / 外部来源 / 研究结论**」四段式结果，
  且**每一条都能追到出处**、**低置信被标出而不是被丢掉**。
- **系统边界**：单个研究主题的详情屏左半（深度对话）与右半（研究结果）。
  发起与配置归 `uc-24-1`；列表归 `uc-24-3`；结论出口归 `uc-24-4`；现场那一份归 `uc-24-5`。
- **核心数据对象**：对话轮次、检索执行步骤、证据条目（来源类别 / 来源名 / 置信度）、
  争议项、研究结论。

## R2 前置条件 / 触发条件

**前置条件**
- 已存在一个由 UC-24.1 创建的研究主题，带完整七项配置。
- 该研究的**来源偏好**决定检索边界（R7.1），**深度档位**决定路数与时间盒。

**触发条件**
- 打开研究主题详情（`isDrOne` `[原型 @15,339,332B]`），系统展示已有对话与结果。
- 用户在底部输入框追问 → `askDr`，提示逐字：「**已追问 · Scout 正在检索并交叉验证**」
  `[原型 @16,906,779B]`（`askDr: () => this.notify("已追问 · Scout 正在检索并交叉验证")`）。

## R3 主流程

1. 用户打开研究主题 → 顶部面包屑 `‹ 全部研究主题`，主标题为**问题原文**，
   副标题为状态 + 来源数，原型示例逐字：
   「德国工商储的并网审批实际要多久？」/「**已出结论 · 来源 14**」`[原型 @15,339,332B` 块内`]`。
2. **左半：深度对话 · Scout**，头部逐字「深度对话 · Scout」+「**41 分钟 · 3 轮**」
   —— 即**耗时与轮次**是一等展示项（对应 UC-24.1 的时间盒）。
3. 每一轮由「**用户问**」与「**Scout 答**」组成，Scout 的答复分两层：
   - **结论层**（自然语言），原型示例逐字：「先查了 Bundesnetzagentur 2025 年报与 BVES 会员调查，
     再逐州比对：全国中位 11 个月，巴伐利亚与北威州相差近 4 个月。**有 3 条来源可信度偏低，我单独标了。**」
   - **执行步骤层**（编号三步，机器可枚举），原型逐字：
     ① 「检索 23 份材料 · **官方 6 / 行业 5 / 媒体 12**」
     ② 「交叉验证：**3 条冲突已标为不确定**」
     ③ 「抽取可规划变量：材料一次过 / 电网影响评估提交时点」
     ⚠ ① 的分类计数**必须与 UC-24.1 的来源偏好口径同源**（官方与监管 / 行业报告 / 媒体报道…），
     否则是第二份来源枚举。见 R7.4。
4. **样本不足时 Scout 必须自我设限。** 第二轮原型逐字：
   「只找到 1 例判例说明交割后资质要重新备案，**样本太少——这条我放进「争议 / 不确定」，不能作为报价依据。**」
   ⇒ 这是本 UC 最重要的行为：**不足以下结论时，产出的是一个被标记的争议项，不是一个弱结论。**
5. **右半：研究结果**，四段固定结构 `[原型 @15,344,112B / 15,344,827B / 15,345,292B / 15,347,036B]`：

   | 段 | 标题（逐字） | 内容形态 | 字节 |
   |---|---|---|---|
   | ① | **关键发现** | 无序条目，每条一句可判定陈述 | 15,344,112 |
   | ② | **争议 / 不确定** | 段落 + 明确的「**不进洞察库**」标注 | 15,344,827 |
   | ③ | **外部来源 · 14** | 表：类别 / 来源名 / **置信度** | 15,345,292 |
   | ④ | **研究结论** | 段落 + 三个出口动作（见 `uc-24-4`） | 15,347,036 |

6. 段 ③ 的行按**来源类别**分组，原型示例逐字：
   `官方 | Bundesnetzagentur《Netzanschluss 年报 2025》| 0.9`；
   `行业 | BVES 会员调查（2025）| 0.7`；
   `媒体 | 其余 12 条 · **含 3 条低可信度已标注** | —`。
   ⇒ **置信度是数值**（0–1，一位小数），不是标签。
7. 段 ② 的口径逐字：「行业媒体称 2026 年起将压缩到 6 个月，但监管方尚未发布正式文件。
   **此条按「不确定」保留，不进洞察库。**」
8. 用户继续追问 → 回到 3；每次追问都可能改写段 ①–④（**重算**，不是追加）。→ **Q-6**（见 `OPEN-QUESTIONS.md`）。

## R4 备选流程与异常流程

**备选流程**
- **A1 让 Scout 补某一类来源**：输入框占位符逐字「**继续追问，或让 Scout 补哪一类来源…**」
  ⇒ 追问支持「补来源类别」这一半结构化意图。`[设计]` 补的类别**仍受 UC-24.1 来源偏好约束**；
  若用户要补的类别不在偏好内，系统应提示需要先改配置，**而不是静默越界**（R7.1）。
- **A2 结论尚未产出**：研究处于运行中，右半只显示已就绪的段，并标明仍在跑
  （对照 `uc-24-5` 的 `运行中` / `已就绪` / `待判定` 三态）。
- **A3 观察者打开**：只读，无输入框、无出口动作（R5）。

**异常流程**
- **E1 检索失败 / 部分路失败**：`[设计]` 已完成的路数的结果**保留并可见**，
  失败路单独标出与可重试。依据同仓既有口径：原型在另一处（生成物 loading 态）逐字写
  「**已完成的 6 项可以先看，不必等全部跑完。**」`[原型 @16,478,885B` 块内`]`
  ——本 UC 采同一口径。⚠ 该出处属**原型 Studio**（phase-02），此处为**口径借用**，不是本域原型证据。
- **E2 零来源 / 检索无果**：`[设计]` 不得生成任何「关键发现」；段 ① 为空，
  段 ④ 显示为**数据需求说明**而非结论。依据：模板 R7 的通用硬规则
  「没有数据时不能生成真实结论，只能生成框架或数据需求说明」。
- **E3 所有来源均低置信**：`[设计]` 全部落入段 ②，段 ① 与段 ④ 不产出；
  出口动作 `加入洞察库` 按 R7.2 被**阻断**（`uc-24-4`）。
- **E4 用户中途离开**：研究在后台继续（原型 Studio 页脚逐字「自动保存 34:12 · **后台运行中**」
  `[原型 @16,224,131B]`），回来可见完整结果。
- **E5 权限不足**：见 R5。

## R5 权限与可见性

- **引导师 / 组长 / 组员**：可读、可追问、可触发补来源。
- **观察者（obs）**：**只读**。不能追问、不能触发 agent（原型逐字：「观察者只读：**不能发言、
  不能触发 agent**；原始逐字稿与私聊不在你的授权范围内」`[原型 @15,415,445B]`）。
  且 `[设计]` 观察者**看不到**段 ③ 中来自 `本场转写` 的行的原文引述——
  只能看到「来自本场转写」这一事实与置信度。→ 跨束约束，见 `contracts/research/domain.md`。
- **未列出的角色默认无权限。**

## R6 后置条件 / 不包含

**后置条件**
- 研究主题带有：n 轮对话、每轮的执行步骤枚举、一组带置信度的外部来源、
  段 ①–④ 的当前版本、以及可供 `uc-24-4` 消费的结论对象。
- 「已出结论」这一状态**当且仅当**段 ④ 非空且段 ③ 至少有一条外部来源（R7.2）。

**不包含**
- 出口动作的执行（加入洞察库 / 补充资料 / 标为关键问题）→ `uc-24-4`。
- 证据进入知识图谱之后的推演 → phase-02 `09-kg`。
- 研究简报的成文与排版 → phase-02 `10-report`。
- **对话消息本身的通用能力**（@某个 agent、改派、上下文勾选）→ 已在 `08-chat`（**已签核**），
  本 UC **复用**它，不重新定义。⚠ 这是防「第二份对话实现」。

## R7 业务规则

- **R7.1 检索不得越出来源偏好。** UC-24.1 的预览句逐字承诺「来源**限定**在 {…}」
  `[原型 @16,906,509B` 附近`]`。越界即缺陷。
- **R7.2 结论必须挂外部来源才能进洞察库。** `[原型 @15,326,937B]` 逐字。
  ⇒ 段 ③ 为空时，`uc-24-4` 的 `加入洞察库` 必须被**机械阻断**，不是灰掉提示。
- **R7.3 低置信标出而不是丢弃。** `[原型 @16,781,061B]` 逐字：
  「5 个研究问题各有 ≥3 条独立来源，**低置信度必须标出而不是丢弃**。」
  ⇒ 段 ③ 必须完整列出低置信来源并标注，**不允许**在渲染层过滤掉它们。
- **R7.4 来源类别是单一事实源。** 执行步骤里的「官方 / 行业 / 媒体」计数、
  段 ③ 的类别列、UC-24.1 的来源偏好五项，**必须是同一套枚举**。
  ⚠ 原型里前两处用简称（`官方` / `行业` / `媒体`）、配置面板用全称
  （`官方与监管` / `行业报告` / `媒体报道`），**且配置面板另有 `内部洞察库` / `本场转写` 两项
  在执行步骤里没有对应计数**。→ **Q-7**：枚举的权威形态与显示简称的映射由谁定。
  **本 UC 不自行发明映射。**
- **R7.5 样本不足时产出争议项，不产出弱结论。** 见 R3.4 的原型原文。
- **R7.6 置信度是数值不是标签。** 段 ③ 原型给的是 `0.9` / `0.7` / `0.3`（后者见 `uc-24-3`）。

## R12 AI Ready 验收线索

1. 打开一个「已出结论」研究，四段标题逐字出现，段 ③ 的置信度以数值渲染。
2. **R7.3**：造一条置信度 0.3 的来源，断言它**出现在**段 ③（性质断言：低置信条目不被过滤），
   而不是断言来源总数等于某个固定值。
3. **R7.5**：造一个只有 1 条来源的问题，断言它落进段 ②「争议 / 不确定」且段 ① 不含它。
4. **R7.2**：段 ③ 为空时，`加入洞察库` 被阻断（在 `uc-24-4` 验收）。
5. **E1**：让 12 路中 3 路失败，断言已完成路的结果可见 + 失败路可重试。
6. **E2**：零来源时段 ④ 是数据需求说明，不含任何断言性结论。
7. **R5**：`?as=obs` 下无输入框、无出口动作按钮（DOM 中不存在）。
8. **R7.1**：把来源偏好设为只有「官方与监管」，断言执行步骤里的类别计数**不含**媒体/行业。
