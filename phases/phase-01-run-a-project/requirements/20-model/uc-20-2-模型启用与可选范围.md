## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-20.2 / 模型启用与可选范围
- **Actor**：**组织管理员**（启用/停用）、**能力维护者**（在 agent/skill 里选模型的人）
- **目标**：[原型] 让「**只有测试通过的模型才会出现在 agent 与 skill 的模型选择里**」
  这条硬约束在系统里真实成立；
  [设计] 并在其上再加一层——启用/停用一个模型，其可选范围立即随之变化
  （**「已启用」参与过滤是设计补全，原型只约束「测试通过」**）。
- **本用例结果**：模型池中每个模型有明确状态；**模型选择器的候选集 ＝ 已启用集合**；
  停用一个模型后，它立即从所有选择器中消失，且已引用它的 agent/skill 进入依赖失败态。
- **系统边界**：状态机（已启用 / 未启用 / 待测试）、启用与停用动作、
  **可选范围过滤器**（agent 侧、skill 侧、蓝本模型策略侧）、
  停用前的引用清单、闭源/自托管二分的可见性、级联通知。
- **核心数据对象**：模型、状态、准入测试结论（来自 UC-20.1）、引用关系
  （agent / skill / 蓝本模型策略 / 项目实例）、停用记录、审计事件。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 模型已通过 UC-20.1 接入，且**五项准入测试的判读结论齐备**。
  - 当前用户是**组织管理员**（唯一可启用/停用的角色）。
  - 系统能枚举该模型的**全部引用**：agent 的模型配置（UC-4.1）、skill 的模型配置（UC-3.1）、
    蓝本的【模型策略】（现场 / 会后整理 / 机密材料三档）、项目实例的锁定配置。
- **触发条件**：
  - [设计] 管理员在模型管理列表对某模型执行启用/停用
    （**动作入口原型确认缺失**：行操作只有 `[配置] [测试]`）；
  - [设计] 或 UC-20.1 的测试结论变化（如改判为不通过 / 修改凭据后回到 `待测试`）
    自动触发可选范围收缩。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **组织管理员操作**：对一个 `待测试` 且五项**全部通过**的模型点「启用」。
   **系统响应**：状态转 **`已启用`**；
   **该模型立即进入 agent 与 skill 的模型选择器候选集**。
   若五项未全过则拒绝启用并指出卡在哪一项（UC-20.1 AC2）。
2. **系统处理**：**可选范围过滤器**在三个消费点生效（[设计] 同一个过滤器，三处复用）：
   | 消费点 | 归属 | 过滤规则 |
   |---|---|---|
   | **Agent 的模型下拉** | UC-4.1 R3 第 4 步 | 只出 `已启用` 模型；组合模型的每个成员都须已启用 |
   | **Skill 的模型下拉** | UC-3.1 R2 | 同上 |
   | **蓝本【模型策略】三档** | 02-tpl | 「现场（低延迟优先）/ 会后整理（质量优先）/ **机密材料（仅本地）**」三档的候选同样只出 `已启用`；第三档另受 UC-20.3 硬路由约束 |
   **口径拆三条**（此前合成一条「[原型硬约束] 未启用与待测试都不出现、不是置灰」是**语义偷换**）：
   - **[原型]** **只有测试通过的模型才会出现**在 agent 与 skill 的模型选择里
     ——原型顶部**逐字如此**，约束的对象是「**测试通过**」，不是「已启用」。
   - **[设计]** `未启用` 的模型**也不出现**。
     ⚠ 依据不足：原型的 6 个 `未启用` 模型（`gpt-5.2-mini` / `gemini-3-flash` /
     `mistral-large-3` / `kimi-k2` / `llama-4-70b` / `gemma-4-31b`）**均未标 `待测试`**，
     即**已通过测试但未启用**——按原型原文它们**恰恰满足「测试通过」**。
     「未启用亦不可选」是本文的补全，**需人类确认**。
   - **[设计]** 不可选的模型**不置灰、直接不出现**。
     ⚠ 「置灰」在原型档案 **0 命中**，呈现方式完全是设计选择。
3. **组织管理员操作**：对一个 `已启用` 模型点「停用」。
   **系统响应**：先**列出引用清单**（agent / skill / 蓝本模型策略 / 进行中项目四类），
   给出影响预览；确认后状态转 `未启用`。
4. **系统处理**：停用后的级联行为（[设计]，与 UC-3.4 的停用语义同源）：
   - **新的选择**：该模型从所有选择器中消失，新建/编辑 agent/skill 时选不到它；
   - **已有的引用**：**不静默改配**——已配它的 agent/skill 转「**依赖失败**」态并
     **停止被载入**，提示维护者改选模型；
   - **进行中的项目**：[设计] 承接 UC-3.4 的原则——已锁定配置的运行继续跑完当前任务，
     但**新任务不再启动**；
   - **绝不静默换模型**（对照 UC-4.1 R7「无合格替代模型 → 明确失败」）。
5. **系统处理**：**闭源 / 自托管二分**在可选范围中始终可辨。
   **系统响应**：[原型] 选择器需标出每个候选属于
   **闭源 API**（「凭据由管理员保管，**成员看不到**」——即维护者选它但看不到凭据）
   还是 **开源自托管**（「权重跑在自己的 GPU 上，**客户机密材料只走这一类**」）。
   [设计] 这个二分标记是 UC-20.3 硬路由的判据，**必须在选择器上可见**，
   否则维护者无法理解「为什么机密场景只能选这几个」。
6. **系统收口**：校验 AC1「**只有测试通过并已启用的模型才出现在 agent 与 skill 的
   模型选择里**」、AC2「停用后已有引用进入依赖失败态而非被静默改配」；
   记录启用/停用、引用清单、影响范围进审计。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] 停用时可指定**替代模型**并生成一份「建议改配清单」，
    但**改配必须由各 agent/skill 的维护者确认**，系统不代改。
  - A2：[设计] 可**按合规属性批量筛选后启用/停用**（如一次性停用所有非「国内合规」模型），
    批量操作仍需逐条列出引用清单。
  - A3：[原型] 列表按 `全部 / 闭源 API / 开源自托管 / 未测试` 筛选；
    [设计] 增加「已启用 / 未启用」维度以便审视可选范围。
  - A4：[设计] 引用清单为空时展示真实空态（大意：当前没有 agent、skill 或蓝本引用它；
    **文案待定，非原型原文**），停用可直接执行。
- **异常流程**：
  - E1：[设计] 停用**最后一个可用于某必需场景的模型**时（如停用最后一个自托管模型，
    导致「机密材料仅本地」无模型可用）——**必须显著警告并列出将失效的场景**；
    **[待确认]** 是否直接阻断。本文按「强警告 + 二次确认，不阻断」处理。
    ⚠ **[已裁决 O-19 · 关联收紧]** O-19 裁定 MCP 安全开关三「客户机密材料仅允许本地模型处理」
    **不允许关闭**——因此「组织内 0 个已启用自托管模型」会让**所有含机密的任务确定性失败**。
    这一后果是**预期行为**（宁可失败也不外发），但二次确认框**必须逐字说明该后果**，
    不得只给泛泛警告。「是否直接阻断」本身仍 `[待确认]`。
  - E2：[设计] 被停用的模型是某蓝本【模型策略】三档之一时，
    该蓝本标为「引用了已停用的模型」，新项目套用前须处置。
  - E3：[设计] 测试结论被改判为「不通过」时，模型**自动从 `已启用` 退出**，
    等同停用并走同一套级联；退出动作留痕。
  - E4：[设计] 启用/停用与 agent/skill 的模型配置并发发生时不得静默覆盖；
    以服务端最终状态为准并提示相关方刷新。
  - E5：[设计] 请求超时或依赖不可用时保留最后成功状态，明确失败并可安全重试。
  - E6：[设计] 权限在过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留。

## R5 权限与可见性

- **组织管理员**：唯一可执行启用/停用的角色；可见全部模型与其凭据（凭据仍不回显）。
- **能力维护者**：可**只读**已启用模型清单并在 agent/skill 中选用；
  **可见闭源/自托管二分标记与合规属性**（选型必需），**不可见凭据与端点**；
  不可启用/停用。
- **审核人**：审核 agent/skill 时可见其所选模型及状态，用于判断「是否选了合适的模型」。
- **引导师**：[设计] 可见蓝本【模型策略】三档的当前取值（只读）；不可改模型池。
- **组长 / 组员 / 观察者**：不可见模型管理；仅在对话中见到「降级运行 · sonnet」这类运行时标注。
- **项目负责人**：可查看本组织已启用模型清单（只读）。
- 未登录、链接失效或未列出的角色：默认无权限；接口不得返回越权数据，
  **尤其不得返回凭据与自托管端点**。

## R7 业务规则（不随具体实现变化的硬性约束）

- **[原型 · 本模块最核心的一条]** **只有测试通过的模型才会出现在 agent 与 skill 的
  模型选择里**——过滤在**服务端**执行，前端不得自行放宽。
- **[原型] 状态三取值**：已启用 / 未启用 / 待测试。
  **[原型]** `待测试` 不出现在选择器中（＝「只有测试通过的才出现」）；
  **[设计]** `未启用` 亦不出现（超出原型约束，需人类确认，理由见 R3 第 2 步）。
- **[设计]** 停用**必须先列出引用清单**；无清单不得停用。
- **[设计]** 停用后**已有引用进入依赖失败态**，**绝不静默换模型**
  （对照 UC-4.1 R7「无合格替代模型 → 明确失败」）。
- **[设计]** 测试结论改判为不通过 → 自动退出 `已启用`。
- **[原型]** 闭源 API 的**凭据成员看不到**；自托管的端点同样对非管理员不可见。
- **[原型]** **客户机密材料只走开源自托管**——本用例保证该类模型在候选集中可辨认，
  硬路由本身见 UC-20.3。
- **[已裁决 O-22③] 组合模型是模型池里的一条记录**（一个 `model_id` → 一个 pipeline），
  因此**启用/停用直接作用于组合本身**——这正是把组合建模进模型池的理由：
  若让每个 agent 各自拼两个模型，本用例的启用/停用**无从作用于组合**。
  级联规则：
  - 停用**组合记录** → 该组合从所有选择器消失，已配它的 agent/skill 进入依赖失败态；
  - 停用组合的**任一成员模型** → 该组合**自动转为不可选**（不静默降级为单模型），
    并在管理界面标注「因成员 `<model_id>` 停用而不可用」。
- **[设计]** 可选范围过滤器**只有一份实现**，三个消费点（agent / skill / 蓝本模型策略）复用；
  不得各写各的。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 启用、停用、自动退出都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：

- **安全/隐私/合规**：
  - **过滤必须在服务端执行**；即使前端被篡改也不能选到未启用模型
    （接口层面校验模型 ID 是否 `已启用`）。

  - [D-17] 闭源 API 调用构成**出域（出组织）**；停用/启用闭源模型是合规动作，须留痕。
- **兼容与降级要求**：
  - 响应式 Web；后台以桌面端为主。
  - 模型不可用时**明确失败**；仅在 UC-4.1 R7 允许降级的任务类型下才可切到替代模型，

## R12 AI Ready 验收线索

- V0（组合可停用 · O-22③）：模型池中存在一条组合记录（`whisper ＋ sonnet`）；
  **直接停用该组合** → 它从所有选择器消失、引用它的 agent 进入依赖失败态；
  **停用其成员 `whisper`** → 该组合自动转为不可选，且**不降级为单模型静默运行**。
- V1a（成功态 · [原型]）：AC1a —— `待测试` 的模型**在下拉中不出现**。
- V1b（成功态 · [设计]）：AC1b/AC1c —— 启用一个模型后它出现在 agent 与 skill 的模型下拉里；
  停用后立即消失；`未启用` 的模型**根本不出现**而非置灰。
- V2（服务端过滤）：直接构造请求把 agent 的模型设为一个 `未启用` 模型 ID，接口拒绝并记审计。
- V3（级联态）：AC2 —— 停用一个正被 3 个 agent 使用的模型：
  停用前列出引用清单；停用后这 3 个 agent 进入依赖失败态并停止被载入；
  **没有任何 agent 被自动改配到别的模型**。
- V4（二分可见）：AC3 —— 模型选择器上每个候选都标出「闭源 API / 开源自托管」，
  且机密场景下只列出自托管候选（配合 UC-20.3）。
- V5（改判态）：AC4 —— 把某已启用模型的一项测试改判为「不通过」，
  它自动退出 `已启用` 并从所有选择器消失，退出动作留痕。
- V6（组合模型态）：停用 `whisper` 后，配 `whisper ＋ sonnet` 的 agent 进入依赖失败态。
- V7（最后一个自托管）：停用最后一个自托管模型时出现强警告并列出将失效的机密场景。
- V8（蓝本态）：被停用的模型若是某蓝本【模型策略】三档之一，
  该蓝本标为「引用了已停用的模型」，新项目套用前须处置。
- V9（降级态）：允许降级的任务类型在降级时，**替代模型也必须是已启用的**；
  无合格替代时明确失败。
- V10（权限态）：逐一使用 组织管理员 / 能力维护者 / 审核人 / 引导师 / 组员 / 观察者 /
  未授权用户访问，可读数据与可执行动作严格符合 R5；非管理员请求不含凭据与端点。
- V11（空态 · [设计]）：无任何已启用模型时，agent/skill 的模型下拉显示真实空态
  （大意：请管理员先启用模型；**文案待定，非原型原文**），**不预置默认值**。
- V12（不造数态）：调用量相关列为空或「—」，不出现编造的统计数字。
- V13（审计态）：启用、停用、自动退出可按操作者、时间、模型、影响范围检索。
