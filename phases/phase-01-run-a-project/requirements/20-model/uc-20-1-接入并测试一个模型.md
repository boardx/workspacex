# 原始需求（细化）— UC-20.1 接入并测试一个模型

> 所属：阶段一 · 能跑完一场项目 / **M20 模型管理**（新增模块 20-model）
> 来源：**运行态原型** 后台 → AI 能力 → **模型管理（18 个模型 · 8 个开源自托管 · 3 个待测试）**：
> ```
> [＋ 接入模型]  筛选：全部 18 / 闭源 API 10 / 开源自托管 8 / 未测试 3
>
> 「只有测试通过的模型才会出现在 agent 与 skill 的模型选择里。
>   测试会跑五项：连通性、结构化输出、工具调用、长上下文、中文表达。」
>
> 闭源 API（凭据由管理员保管，成员看不到）
>   <模型名>  <状态>  <厂商>  <能力标签>  <上下文窗口>  <单价>
> 开源自托管（权重跑在自己的 GPU 上，客户机密材料只走这一类）
>   <模型名>  <状态>  <许可证/特性>
>
> 每行操作：[配置] [测试]  ｜ 状态取值：已启用 / 未启用 / 待测试
> ```
> **补写缘由**：原需求文档对模型管理**零覆盖**，而三处硬约束都指向它——
> ① 「只有测试通过的模型才会出现在 agent 与 skill 的模型选择里」（UC-4.1 / UC-3.1 的模型下拉来源）；
> ② 「客户机密材料只走自托管」（批准卡的「含机密，仅本地模型」与系统提示硬约束）；
> ③ 降级策略需要「有没有合格替代模型」这个判据（UC-4.1 R7）。

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-20.1 / 接入并测试一个模型
- **Actor**：**组织管理员**（凭据保管人）、**能力维护者**（模型的使用方，见 UC-20.2）
- **目标**：[原型] 把一个模型接进组织可用的模型池，经**五项准入测试**判定是否合格，
  合格后才允许被 agent 与 skill 选用。
- **本用例结果**：模型池中新增一条模型记录，带类型（闭源 API / 开源自托管）、厂商、
  能力标签、上下文窗口、单价、**合规属性**与**状态**（已启用 / 未启用 / 待测试），
  且五项测试的判读结论与证据已记录。
- **系统边界**：模型接入表单、凭据保管、连通性验证、**五项准入测试**（phase-1 为人工判读 + 记录）、
  状态机、合规属性标注、模型池列表与筛选。
- **核心数据对象**：模型、模型类型（闭源 API / 开源自托管）、厂商、能力标签、
  上下文窗口、单价、**合规属性**、凭据（仅管理员）、部署端点（自托管）、
  **准入测试记录**（五项 × 结论 × 判读人 × 时间 × 证据）、状态。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 当前用户是**组织管理员**（[原型]「闭源 API：**凭据由管理员保管，成员看不到**」）。
  - 闭源 API：已持有可用的厂商 API 凭据。
  - 开源自托管：模型权重已部署在自有 GPU 上并暴露可访问端点
    （[原型]「权重跑在自己的 GPU 上」）。
- **触发条件**：
  - [原型] 管理员在后台 → AI 能力 → 模型管理点 **`[＋ 接入模型]`**；
  - [原型] 或对已有模型点行内 **`[测试]`** 重新做准入测试；
  - [原型] 或点行内 **`[配置]`** 修改接入参数。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **组织管理员操作**：点 `[＋ 接入模型]`，选择**类型**。
   **系统响应**：[原型] 二分——
   - **闭源 API**：需填厂商、模型标识、**API 凭据**；
     [原型硬约束]「**凭据由管理员保管，成员看不到**」。
   - **开源自托管**：需填部署端点、许可证；
     [原型]「权重跑在自己的 GPU 上，**客户机密材料只走这一类**」。
   **[本项目安全边界]** 凭据的**录入与存储由管理员在本产品内完成**；
   系统必须加密存储、永不回显、永不写入日志或审计明文。
2. **组织管理员操作**：填**能力元数据**。
   **系统响应**：记录厂商、能力标签（如「推理 / 视觉 / 工具调用 / 扩展思考」
   「低延迟 / 分类与抽取」「超长上下文 / 视频理解」「中文长文」「中文转录 · 说话人分离」）、
   **上下文窗口**、**单价**。
   **[范围提示]** [人类已拍板] **具体的 18 个模型清单与单价不写进需求正文**，
   它们是**配置数据**；本用例只定义**字段与录入路径**。
3. **组织管理员操作**：标注**合规属性**（**本用例必须保留的能力**）。
   **系统响应**：[原型] 原型在模型行上直接给出了合规标签——
   如 **「欧盟数据驻留」**（某欧洲区厂商）与 **「国内合规」**（某国内厂商）。
   [设计] 因此模型需带**合规属性**字段（多值），供后续「**按合规属性选模型**」使用。
   **[已裁决 O-38]** 原问题：合规属性的取值域（欧盟数据驻留 / 国内合规 / 其它法域？）需合规负责人给出。
   **裁决（O-38）**：**取值域来自外部输入（部署区域清单 ∩ 目标客户法域清单），暂不可得**；
   实现上把合规属性做成 **受控枚举字段，取值从配置读取，枚举内容留空**——
   这样不阻塞编码，枚举到手后只改配置不改代码。
   [D-17] 「出法域」（数据驻留路由）本身列入 **phase-3 的 17-gov**；
   phase-1 只做**属性标注与筛选**，不做自动路由。
4. **系统处理**：模型落为 **`待测试`** 状态。
   **系统响应**：[原型] 状态三取值 **已启用 / 未启用 / 待测试**；
   `待测试` 的模型**不出现在 agent 与 skill 的模型选择里**（见 UC-20.2）。
5. **组织管理员操作**：点 `[测试]` 执行**五项准入测试**。
   **[原型] 五项固定为**：
   | # | 测试项 | 判什么 |
   |---|---|---|
   | 1 | **连通性** | 端点/凭据可达，能返回一次正常响应 |
   | 2 | **结构化输出** | 能按给定 schema 稳定返回结构化结果（skill 的输出 schema 依赖它） |
   | 3 | **工具调用** | 能正确发起并解析工具调用（agent 的工具白名单依赖它） |
   | 4 | **长上下文** | 在其声明的上下文窗口内不丢信息 |
   | 5 | **中文表达** | 中文输出质量达标（本产品主语言为中文） |
   **[人类已拍板 · D-07 最小子集]** phase-1 **不做五项测试的自动化**：
   - 系统提供**测试用例说明与记录表单**，由管理员**人工执行并判读**；
   - 每项记录：结论（通过 / 不通过 / 不适用）、判读人、时间、**证据**（粘贴的返回样例
     或截图路径）；
   - **仅第 1 项「连通性」允许做一次真实探活**（[设计] 因为它是接入是否成功的最低门槛，
     不做就无法判断录入是否有效）。**[待确认]** 连通性探活是否纳入 phase-1。
6. **系统处理**：汇总五项判读结论。
   **系统响应**：五项**全部通过**才允许转入可启用状态；任一项不通过则停在 `待测试`
   并显示卡在哪一项。
   [设计] **测试结论不可由使用方自填**——只有管理员可判读，且判读记录不可删除。
7. **组织管理员操作**：启用该模型（进入 **UC-20.2**）。
   **系统响应**：状态转 `已启用`，开始出现在 agent 与 skill 的模型选择里。
8. **系统收口**：校验 AC1「模型池中每个模型都能看到类型、能力元数据、合规属性、
   五项测试的判读结论与状态」、AC2「**未通过五项测试的模型不得进入 `已启用`**」；
   记录接入、测试判读、状态变更进审计。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] 列表可按 `全部 / 闭源 API / 开源自托管 / 未测试` 筛选；
    [设计] 另需支持按**合规属性**筛选（这是「按合规属性选模型」的入口）。
  - A2：[原型] 行内 `[配置]` 可修改接入参数（端点、凭据、能力元数据、合规属性）。
    [设计] **修改凭据或端点后必须重新测试**——否则测试结论与实际不符。
  - A3：[设计] 已有模型可复制接入（同一权重不同部署点，如多区域自托管），
    但**测试结论不随复制继承**。
  - A4：[设计] 模型池为空或筛选无结果时展示真实空态与 `[＋ 接入模型]`，
    **不预置示例模型**（原型每屏都填满样例数据，零空态）。
  - A5：**[已裁决 O-22③]** 原问题：`whisper ＋ sonnet`、`gpt-5.2 ＋ 本地 qwen3-32b`
    这类**组合模型**的配置形态——是模型池里的一条组合记录，还是每个 agent 各自拼两个字段。
    **裁决（O-22③）**：**建模为模型池里的一条组合记录**——
    **一个 `model_id` 指向一个 pipeline**（有序的成员模型列表 + 各自角色，
    如 `转录 → 生成`、`本地预处理 → 闭源生成`），
    **不是每个 agent 各自拼**。理由：否则 UC-20.2 的**启用/停用无从作用于组合**。
    因此：组合模型在列表中**作为一条模型记录出现**，有自己的状态、合规属性与测试结论；
    组合中的**每一个成员模型都必须独立通过准入测试**，且**组合本身也要走一次五项测试**
    （链路串起来后的结构化输出与工具调用行为可能与单模型不同）。
    组合记录的合规属性 ＝ **成员合规属性的交集**（取最严）；
    只要有一个成员是闭源 API，该组合即视为**闭源链路**，受 UC-20.3 机密硬路由约束。
- **异常流程**：
  - E1：[设计] 连通性失败时明确给出失败原因（凭据无效 / 端点不可达 / 超时），
    **不得把失败呈现为「待测试」而无说明**。
  - E2：[设计] 凭据在录入过程中被拒绝时**不保存半截配置**；已保存的凭据永不回显。
  - E3：[设计] 自托管端点在测试通过后变为不可达时，模型自动转「依赖失败」态并停止被选用；
    已配它的 agent/skill 按 UC-4.1 E4 处理（明确失败，不静默换模型）。
  - E4：[设计] 五项中任一项被判「不通过」后又被改判「通过」时，
    **两次判读都留痕**，不得覆盖历史结论。
  - E5：[设计] 请求超时或依赖不可用时保留已填内容，明确失败并可安全重试。
  - E6：[设计] 同一模型被并发配置时不得静默覆盖；提示已变化并允许刷新后重提。
  - E7：[设计] 权限在过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留。

## R5 权限与可见性

- **组织管理员**：唯一可接入、配置、测试判读、启用/停用模型的角色；
  **凭据仅其可见**（[原型]「凭据由管理员保管，成员看不到」），且系统内也不回显。
- **能力维护者**：可**只读**模型池（模型名、类型、能力标签、上下文窗口、单价、
  合规属性、状态），用于给 agent/skill 选模型；
  **不可见凭据、不可测试、不可启用/停用**。
- **审核人**：不参与模型管理；但在审核 agent/skill 时可看到其所选模型及其状态。
- **引导师 / 组长 / 组员 / 观察者**：不可见模型管理屏；
  [设计] 在对话中可见「当前用的是哪个模型」与「降级运行」标注（属 08-chat / UC-4.1）。
- **项目负责人**：可查看本组织已启用模型清单（只读），用于理解项目的模型策略。
- **[D-18] 管理员权力边界**在本用例不放宽：管理员保管凭据不等于可读项目内容。
- 未登录、链接失效或未列出的角色：默认无权限；接口不得返回越权数据，
  **尤其不得返回凭据字段**。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 模型池中存在该模型，字段齐备，状态明确。
  - [设计验收] AC1：模型池中每个模型都能看到类型、能力元数据、**合规属性**、
    五项测试的判读结论与状态。
  - [原型验收] AC2：**未通过五项测试的模型不出现在 agent 与 skill 的模型选择里**
    （原型顶部硬约束逐字如此）。
  - [设计验收] AC2b：未通过五项测试的模型**不得进入 `已启用`**——
    原型只约束「出现在选择器里」，未约束状态转移，故此条为设计补全（配合 UC-20.2）。
  - [设计验收] AC3：**凭据永不回显、永不出现在接口响应、日志与审计明文中**。
  - [设计验收] AC4：可按**合规属性**筛选模型（如只看「欧盟数据驻留」的）。
- **失败后置条件**：
  - 不产生「看似接入成功但不可用」的模型；失败保留为可重试草稿并进可观测日志。
- **不包含**（**[D-07] 被砍项，明确列出以免实现方误做**）：
  - **五项准入测试的自动化执行** —— phase-1 **改为人工判读并记录**；
    自动化测试套件（含评测集、评分器、回归跑批）列为 **phase-2**。
  - **调用量统计** —— 原型的「工具调用量」「N 次/月」类统计报表不在 phase-1 范围；
    实现时相关列可留空或显示「—」，**不得为了填满界面而造数**。
  - **模型清单与单价的内容本身** —— 属**配置数据**，不写进需求正文，
    由管理员在系统中录入；实现方**不得把 18 个模型硬编码进代码或种子数据**。
  - **成本核算与账单** —— 单价只作为展示与预算估算字段（对照批准卡的「约 ￥9.6」），
    不做计费。
  - **模型微调、私有化训练、路由权重调优**。
  - **[D-17] 出法域的数据驻留自动路由** —— 列入 **phase-3 的 17-gov**；
    phase-1 只做合规属性的**标注与筛选**。
  - 模型的启用/停用与可选范围过滤 —— 见 **UC-20.2**（本用例只负责接入与测试）。
  - 机密数据的模型路由 —— 见 **UC-20.3**。

## R7 业务规则（不随具体实现变化的硬性约束）

- **[原型]** **只有测试通过的模型才会出现在 agent 与 skill 的模型选择里**
  （本用例负责「测试通过」的判定，过滤动作见 UC-20.2）。
- **[原型] 五项准入测试固定为**：连通性、结构化输出、工具调用、长上下文、中文表达。
- **[人类已拍板 · D-07]** phase-1 五项测试为**人工判读 + 记录**，不做自动化。
- **[原型] 状态三取值**：已启用 / 未启用 / 待测试。
- **[原型] 模型二分**：闭源 API（**凭据由管理员保管，成员看不到**）
  / 开源自托管（**权重跑在自己的 GPU 上，客户机密材料只走这一类**）。
- **[设计]** 凭据加密存储、永不回显、永不进日志与审计明文。
- **[设计]** 修改凭据或端点后**必须重新测试**；测试结论不随复制继承。
- **[设计]** 测试判读只能由管理员执行；判读记录**不可删除**，改判留双份留痕。
- **[已裁决 O-22③] 组合模型 ＝ 模型池里的一条组合记录**（一个 `model_id` → 一个 pipeline），
  **不是 agent 侧的两个字段**；成员模型各自须通过测试，组合本身也须走一次五项测试；
  组合的合规属性取成员的**交集（最严）**；含闭源成员即视为闭源链路。
- **[设计]** 模型需带**合规属性**并可据此筛选（「按合规属性选模型」的能力必须保留）；
  **[已裁决 O-38]** 其取值域为受控枚举、从配置读取，枚举内容待外部输入。
- **[已裁决 O-35] AI 质量治理的口径**：**模型选择与提示词版本不在各 UC 里各自指定**，
  统一走**蓝本第 12 项「Agent 编排」与【模型策略】三档**（现场低延迟 / 会后质量优先 / 机密仅本地）；
  **人工复核责任人恒为该产出的负责人**（与 D-39「负责人恒为人」一致）；
  **质量阈值一律不用分数，改用结构性断言**——本用例的五项准入测试即按此写：
  每项只记 `通过 / 不通过 / 不适用` ＋ **必须附证据**，**不打分、不设分数线**。
- **[已裁决 O-40] 外部供应商不绑定**：转写等外部服务（如 `whisper-large-v3-zh` 的托管替代）
  在接口层按**可替换的 provider 抽象**实现，**不绑定具体厂商**；
  采购结果只改配置与凭据，不改代码路径。失败重试次数、费用上限与服务等级属采购输入，
  在到手前按 provider 抽象的默认策略走，不阻塞开工。
- **[已裁决 O-37] 单价与成本口径**：单价存为**组织可配的价目表**，**币种 CNY，手工维护**，
  **不随厂商调价自动同步**（自动同步需厂商 API，phase-1 不值当）；
  单价只作展示与预算估算，不做计费（见 R6 不包含）。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 接入、配置变更、测试判读、状态变更都必须记录审计事件，并显示动作影响范围。

## R12 AI Ready 验收线索

- V1（成功态）：AC1 —— 接入一个模型后，列表能看到其类型、厂商、能力标签、上下文窗口、
  单价、合规属性、五项测试结论与状态。
- V2（门禁态）：AC2 —— 五项中有一项判「不通过」时，该模型无法被启用；
  直接调接口置为 `已启用` 被拒绝并记审计。
- V3（凭据态）：AC3 —— 凭据录入后任何接口响应、页面、日志、审计条目中均不出现明文；
  以能力维护者身份请求模型详情时返回体不含凭据字段。
- V4（合规筛选态）：AC4 —— 按「欧盟数据驻留」筛选只返回带该属性的模型；
  按「开源自托管」筛选只返回自托管模型。
- V5（判读留痕态）：把某项测试从「不通过」改判为「通过」，两次判读均可查，历史不被覆盖。
- V6（重测态）：修改某模型的凭据或端点后，其状态自动回到 `待测试`，
  且从 agent/skill 的模型下拉中消失（配合 UC-20.2）。
- V7（依赖失败态）：把自托管端点置为不可达，模型转依赖失败态，
  已配它的 agent 明确失败而非静默换模型。
- V8（组合模型 · O-22③）：在**模型池**中创建一条组合记录（`whisper ＋ sonnet`）——
  断言它是**一条带独立 `model_id` 的模型记录**（而非 agent 侧两个字段）；
  其成员未全部通过测试时组合无法启用；停用该组合后，引用它的 agent 立即进入依赖失败态。
- V9（组合的合规取交集）：组合含一个闭源成员时，该组合被判定为**闭源链路**，
  在 UC-20.3 的机密路由中被拒绝处理机密内容。
- V10（价目表 · O-37）：单价来自组织可配价目表（CNY），改价目表后预算估算随之变化；
  系统**不发起任何厂商价格同步请求**。
- V11（provider 抽象 · O-40）：替换转写 provider 的配置后，
  调用路径无需改代码即可切换；未配置 provider 时明确失败而非静默降级。
- V12（trace 落血缘 · 架构对齐）：一次模型调用后，`provenance_events` 中存在一条事件，
  含 `model_id`、prompt version、token 用量、时延与结果状态。
- V8（权限态）：逐一使用 组织管理员 / 能力维护者 / 审核人 / 引导师 / 组员 / 观察者 /
  未授权用户访问，可读数据与可执行动作严格符合 R5。
- V9（空态）：模型池为空时显示真实空态与 `[＋ 接入模型]`，**不预置示例模型**。
- V10（不造数态）：调用量相关列在 phase-1 为空或「—」，不出现编造的统计数字。
- V11（并发态）：两名管理员同时配置同一模型不静默覆盖，可识别最终版本。
- V12（审计态）：接入、配置变更、测试判读、状态变更可按操作者、时间、模型检索；
  越权尝试也有安全审计记录。
