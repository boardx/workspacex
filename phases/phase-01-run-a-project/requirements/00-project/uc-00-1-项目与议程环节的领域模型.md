## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-00.1 / 项目与议程环节的领域模型
- **Actor**：**项目负责人**（组织角色 `lead`；[已签] `.../uc-0-3-…md:99` 逐字写「创建与管理项目」）、
  **引导师**（项目角色 `facilitator`，持 `stage.advance` 等控场动作）
- **目标**：让「项目」和「议程环节」成为系统里**真实存在、可外键引用、可判定状态**的对象——
  今天它们只是被别的模块当作字符串引用的两个 id。
- **本用例结果**：
  ① 项目可被创建（路径待裁），并落到 `projects` 表；
  ② 议程环节成为**有身份、有状态**的实体，`artifact_bindings.step_id` 可指向它；
  ③ phase-00 契约里两条**今天不可达**的失败码 `STEP_CLOSED` /
     `STEP_REJECTS_ARTIFACT_TYPE` 变成可以被断言红的门。
- **系统边界**：项目实体与创建、议程环节实体与状态机、环节推进、绑定时的环节校验。
  **不含**：蓝本本体与套用（UC-2.1 / UC-2.2）、成员授予（UC-00.3）、
  项目列表与主页（UC-00.2）、待办同步（11-board）、
  矩阵格 → 三视角首屏（UC-2.2 F27 已承接）。
- **核心数据对象**：`Project`、`AgendaStage`（命名 **[待裁] → OPEN-QUESTIONS Q-3**）、
  环节状态、环节可接受产出类型、`Binding.(projectId, stepId)`（[已签]）。
  ⚠ **`Project` 上有没有「项目类型」维度（研究项目 / 业务项目）：[待裁] → Q-12。**
  它比 Q-1 更靠上游——一旦存在，会同时波及创建路径、环节定义、列表与权限投影。
- ⚠ **项目不是内容的顶层容器**：[已签] `Artifact.projectId` 可空、
  「Studio 可独立发起、不依赖项目」（`packages/contracts/src/artifact.ts:126`）。
  Studio 与项目的从属关系 **[待裁] → Q-11**；本 UC **不假设**一切都挂在项目下。

## R3 主流程

1. **项目负责人操作**：发起新建项目。
   **系统响应**：**[待裁] → Q-1**（只能套蓝本 / 可空白新建 / 一条路径带可选蓝本参数）。
   本文**不预设**任何一种，因此本步的输入形状留空。
   [已签] 无论哪种，写入的行必须落在 `projects`，携带 `org_id`
   （`apps/api/migrations/0003-identity.sql:34-38`，`org_id NOT NULL` 外键）。

2. **系统处理**：校验创建者权限。
   [已签] 组织角色 `lead` 有「创建与管理项目」职责（`.../uc-0-3-…md:99`）。
   `admin` 能否创建、创建者是否自动获得项目角色：**[待裁] → Q-1 连带问题 2、3。**

3. **系统处理**：初始化议程环节。
   [已裁 O-02] 套蓝本时是**引用而非内联**：项目侧环节实例各持指回蓝本侧环节定义的引用
   （`.../02-tpl/uc-2-2-…md:392-394`）。
   **环节实例是不是一张独立表：[待裁] → Q-2 待答①。**
   未套蓝本时环节从哪来（空 / 手工搭 / 事后补套）：**[待裁] → Q-1 连带问题 1。**

4. **引导师操作**：推进议程环节。
   **系统响应**：[已签] 该动作是闭集动作词 `stage.advance`「推进环节」，
   仅 `facilitator` 持有（`apps/api/src/domain/identity/project-role-matrix.ts:26,58-63`）。
   **状态集合与迁移规则：[待裁] → Q-2 待答②。**
   [已裁] 已知两条以它为前提的规则，实现必须同时满足：
   - 临时提权在环节结束时失效，且**被提前结束 / 被跳过 / 被合并**同样立即失效；
     失效由**服务端在环节状态机变更时主动收回**，不得靠前端或定时轮询兜底
     （`.../01-auth/uc-1-4-…md:97-100`）。
   - 环节状态是**三视角首屏的唯一驱动源**，不得各视角各自判断当前环节
     （`.../02-tpl/uc-2-2-…md:286-287`）。

5. **系统处理**：`bindToProjectStep` 时校验环节。
   [已签] 该操作的失败枚举含 `STEP_CLOSED` 与 `STEP_REJECTS_ARTIFACT_TYPE`
   （`packages/contracts/src/artifact.ts:308-312`）。
   **两者的判据：[待裁] → Q-2 待答②③ / Q-8。**
   [已签] 绑定的身份是 `(artifact_id, project_id, step_id)` 三元组唯一
   （`apps/api/migrations/0008-f06-binding-modes.sql:66`），
   同一 artifact 可钉到多个环节的不同版本（同文件 `:62-65`）。

6. **系统收口**：写审计。
   [已签] `project` 是 provenance 的一等 target 类型
   （`packages/contracts/src/provenance.ts:71,93`）；
   **不得**为项目域另造一套审计表（X-2 的教训，`design-coherence.md:185`）。

## R4 备选流程与异常流程

- **备选流程**
  - **A1**：**空白新建（无蓝本）** —— **[待裁] → Q-1**。
    [已裁] 若允许，四子标签为真实空态，**不得伪造默认结构**
    （`.../02-tpl/uc-2-2-…md:174-175`、`:498` V15）。
  - **A2**：**事后补套蓝本** —— **[待裁]**，已登记在 `.../uc-2-2-…md:418`。
    合并策略（覆盖 / 只填空缺 / 拒绝）不得由实现者自选。
  - **A3**：**中途换工作流模板** —— **[待裁]**，已登记在 `.../uc-2-2-…md:396-397`（A5）。
    [已裁] 已知硬要求：**必须显式告知并确认，不得静默丢弃**已有编排与待办
    （`.../uc-2-2-…md:176-178`）。
  - **A4**：**环节被跳过 / 被合并** —— 状态表达 **[待裁] → Q-2 待答②**；
    但对**临时提权失效**的影响已定（见 R3 步骤 4）。
  - **A5**：**同一 artifact 绑到多个环节** —— [已签] 允许，且各环节可钉不同版本
    （`0008-f06-binding-modes.sql:62-65`）。

- **异常流程**
  - **E1**：**绑定到已关闭环节** → [已签] `STEP_CLOSED`；
    [已签] 界面文案「该环节已关闭，绑定失败；**内容已保留为草稿**」
    （`.../artifact/usecases.md:20`）——**草稿不丢是契约的一部分**。
  - **E2**：**环节不收此类产出** → [已签] `STEP_REJECTS_ARTIFACT_TYPE`。判据 **[待裁] → Q-2③**。
  - **E3**：**绑定到不存在的环节** → 今天**不可检出**（`step_id` 无外键，
    `0008-f06-binding-modes.sql:23-31`）。修法（加外键与否）**[待裁] → Q-8 待答 2**。
  - **E4**：**创建过程中部分写入失败** → [已裁] 六类初始化**要么全成功要么整体回滚**，
    不得建出「有议程没分组」的半成品（`.../uc-2-2-…md:194-195` E2）。
  - **E5**：**同一次创建请求重复提交** → [已裁] 幂等，只建出一个项目
    （`.../uc-2-2-…md:83`、`:495` V13）。
  - **E6**：**组织在操作中被停用** → [已签] 数据库 RESTRICTIVE 策略直接拒写
    （`0014-f22-org-lifecycle.sql:165-184`）；界面须显示只读原因而**不是隐藏**
    （同 F16 纪律，`packages/contracts/src/identity.ts:139-141`）。
  - **E7**：**鉴权服务不可用** → [已签] `AUTH_SERVICE_UNAVAILABLE`，
    **一律拒绝，不得降级放行**（`packages/contracts/src/identity.ts:199`）。

## R5 权限与可见性

> [已签] 一切判定取**组织层 × 项目层交集**，任一不过即拒（`.../uc-0-3-…md:58-59`）；

| **`facilitator`（引导师）** | [已签] `stage.advance` / `broadcast` / `timer` / `group` / `bulkConfirm`；`group.submitOutput`；全场可见含原始转写与私聊（`project-role-matrix.ts:58-63`） | — |
| **`groupLead`（组长）** | [已签] `group.submitOutput` / `confirmNode` / 三条 content 写 / `read.ownGroup` `allHands` `published`（`:65-69`） | [已签] **不能推进环节**（无 `stage.*`） |
| **`member`（组员）** | [已签] 三条 content 写 + 三条读（`:71-74`） | [已签] 不能提交本组产出、不能确认节点、[已裁] 不可定版（`.../artifact/usecases.md:55`） |

| **免注册现场组员/组长** | [已签] 持项目角色但无组织角色 | [已签] **不得访问任何组织级资源**（`.../uc-1-4-…md:182-183`） |
| **外部受访者** | [已签] 不持项目角色，走一次性令牌（UC-6.3；`.../identity/domain.md:43`） | — |

## R7 业务规则

**不可违反（[已签]，改动 = 回退已签核契约）**
1. 项目**必属于且只属于一个组织**；跨组织在当前模型里不可表达
   （`0003-identity.sql:35`；`acl_bindings` I-1，`.../identity/domain.md:84`）。
2. 项目角色**恒为四种**；一人一项目**恰好一个**角色
   （`identity.ts:177`；`0003-identity.sql:66,70`）。
3. 「无项目角色」是**正常状态**；且 `projectLayer === null`（无项目上下文）与
   `projectLayer.role === null`（有上下文无角色）**禁止合并**
   （`identity.ts:194,260-272`；`design-coherence.md:331-333`）。
4. 项目角色动作词是**闭集**；新增动作 = 修订已签束，不是实现动作
   （`project-role-matrix.ts:14-16`；`bind-to-project-step.ts:71-77`）。
5. 角色矩阵将来若被前端需要，**移进 `packages/contracts`，不得复制**
   （`project-role-matrix.ts:5-12`）。
6. 只有**固定快照**能被下游引用；固定快照**不可删、不可改、不可降级**
   （`.../artifact/domain.md:102,105`）。
7. 切换组织**必须清空当前项目与当前环节**（`identity.ts:516-521`）——
   项目域**不得**另起一套会话状态。
8. 可见性沿数据链路传播且**只收紧不放宽**（`.../artifact/domain.md:104`；
   `.../identity/domain.md:90` I-7）。

**本用例自己的规则（[推导]，不引入新决策）**
9. **不许造第二份项目/环节的事实源**：环节实例的唯一来源是本 UC 定义的实体，
   蓝本侧是**定义层**，两者是「定义 ↔ 实例」两层（[已裁 O-02]，`.../uc-2-2-…md:386-395`）。
10. **不许用"永远为真的检查"充数**：若某道校验今天无判据，写成**缺失**而不是写成
    永远放行的桩（`0008-f06-binding-modes.sql:29-31` 已立此规矩）。

**[待裁] 尚不能写成规则的**
- 创建路径（Q-1）、环节状态机（Q-2）、字段命名（Q-3）、生命周期（Q-5）、删除（Q-9）。

## R12 AI Ready 验收线索

> 以下每条都应可由自动化断言验证。⚠ 凡标 [待裁] 的，**在裁决前不写断言**——
> 写一个永远为真的断言比不写更糟（`0008-f06-binding-modes.sql:29-31`）。

- **V1（租户隔离）**：用非 owner 运行时角色直连 SQL 跨组织查 `projects`，断言返回 0 行
  （同 I-4 的断言法，`.../identity/domain.md:87`）。
- **V2（角色闭集）**：从 `pg_catalog` 读出 `project_memberships.project_role` 的 CHECK，
  断言其成员集**逐个等于** `packages/contracts/src/identity.ts:177` 的 `ProjectRole` 枚举
  （0005/0006/0008 已用同一技法）。
- **V3（无角色 ≠ 无上下文）**：构造「非项目请求」与「项目请求但无角色」两次调用，
  断言前者 `projectLayer === null`、后者 `projectLayer.role === null` 且
  `reasonCode === "NO_PROJECT_ROLE"`——**两者响应体可区分**。
- **V4（反证 · STEP_CLOSED）**：构造一个 closed 环节 → 绑定 → 断言 `STEP_CLOSED`；
  **再**构造一个 open 环节 → 绑定 → 断言成功。
  ⚠ **两条都要**：只有前者时，一个"永远返回 STEP_CLOSED"的实现也会全绿。
