# 原始需求（骨架）— UC-00.2 项目列表与项目主页

> 所属：阶段一 · 能跑完一场项目 / **M0 · 项目本身**
> 来源：从 **phase-00 已签核契约反推** + 原型已抽取的项目列表行证据。
> 出处逐条见同目录 **`DERIVED-FROM-CONTRACTS.md`**；待裁项见 **`OPEN-QUESTIONS.md`**。
> 口径四标记同 `uc-00-1`（[已签] / [已裁] / [待裁] / [推导]）。
>
> ⚠ **本 UC 的确定部分很小，不确定部分很大。**
> 确定的只有一件：**项目侧「已回流的产出与版本」列表**——它的路由、字段、徽标、
> 空态、失败码都已签核并已实现（F06 passing）。其余（项目列表返回谁的项目、
> 概览显示什么、准备度怎么算）全部待裁。本文按这个比例书写，不填补空白。
>
> 元数据：优先级 **P1**（不阻塞 uc-00-1，但阻塞"用户能不能找到自己的项目"）；
> 估点 **[待裁]**（依赖 Q-6）。建议迭代：**迭代 1 · 能进场**。

## R1 概览

- **Use Case ID / 名称**：UC-00.2 / 项目列表与项目主页
- **Actor**：四种**项目角色**（引导师 / 组长 / 组员 / 观察者）、
  组织角色 **项目负责人**（管理视角）、组织角色 **管理员**（审计视角，边界见 R5）
- **目标**：让一个人能**找到自己的项目**，并在进入后一眼看到「这场现在到哪一步、
  已经沉淀了什么」。
- **本用例结果**：
  ① 存在一个项目列表入口（返回集合的定义 **[待裁] → Q-6①**）；
  ② 项目概览页至少呈现**已签核的那一块**：某环节下已回流的产出与版本。
- **系统边界**：项目列表、项目概览页、回流列表的呈现。
  **不含**：回流列表的**产生**（phase-00 F06 已 passing）、项目筹备四子标签（UC-2.2）、
  文件浏览器（22-files）、创建与环节状态机（UC-00.1）。
- **核心数据对象**：`Project`、`BackflowEntry`（[已签] 闭形状）、
  当前议程环节（依赖 UC-00.1）、项目角色（[已签]）。

## R2 前置条件 / 触发条件

- **前置条件**
  - [已签] 调用者在当前组织有身份；组织切换会**清空当前项目与当前环节**
    （`packages/contracts/src/identity.ts:516-521`）——列表必须按**切换后的组织**重新求值。
  - [已签] 进入项目页时，两层身份条渲染项目层；非项目页不得渲染
    （`.../web-kernel/domain.md:107`）。
- **触发条件**
  - 用户打开项目列表 / 点进某个项目。

## R3 主流程

1. **用户操作**：打开项目列表。
   **系统响应**：**[待裁] → Q-6①**——返回「我持有项目角色的项目」，
   还是再加一段「我作为 lead/admin 可管理的项目」。
   ⚠ 本文**不预设**，因为两种的**存在性泄露**面完全不同。
   [已签] 无论哪种，判定必须走两层交集与 `acl_bindings`，不另建过滤
   （`.../identity/domain.md:54`）。
   ⚠ **列表要不要按项目类型（研究/业务）分区：[待裁] → Q-12**。
   ⚠ **「不属于任何项目」的产出在哪里被看见**：[已签] 它是一等状态
   （`.../context-pack/usecases.md:43`），但**项目列表不是它的家** → **[待裁] → Q-11 连带 3**。

2. **系统响应**：列表行内容。
   [已裁 · 原型证据] 行形如 `准备度 68% · 9/12 已确认 · 3 组 · 蓝本 商业模式共创 v3`
   （`.../02-tpl/uc-2-2-…md:337-338`）。
   ⚠ **准备度百分比的计算口径已被登记为 `[待确认]`**（同文件 `:419-420`）——
   本 UC **不定义它**，也**不复制一份分母**。在它裁决前，列表行**不显示准备度**
   优于显示一个编出来的数（本仓已因「编了一个数值制造出已算过的假象」出过事故，
   `design-coherence.md:200`）。

3. **用户操作**：进入某个项目。
   **系统响应**：[已裁] 一级标签 `概览 ｜ 研究洞察 ｜ 项目筹备 ｜ 现场协作 ｜ 成果沉淀 ｜ 待办 ｜ 设置`
   （`.../uc-2-2-…md:311-312`）；
   [已签] 顶栏出现两层身份条「顾问 · 能源组 ｜ 本项目：组长 · 第 2 组」
   （`.../web-kernel/usecases.md:127-128`）。

4. **系统响应**：概览页渲染**已回流的产出与版本**。
   [已签] 数据来自 `GET /projects/:projectId/backflow`
   （`packages/contracts/src/artifact.ts:333-339`），可按 `stepId` 过滤。
   [已签] 每行字段闭集：`bindingId / artifactId / title / mode / version / pinnedBy / pinnedAt / badge`
   （`:214-224`），其中 **`mode` / `version` / `pinnedBy` / `pinnedAt` 四字段非空**。
   [已签] 徽标三取值 `draft` / `live` / `pinned`，界面文案「草稿 / 实时 · 随源变动 / 已定版 vN」
   （`.../artifact/usecases.md:97`）。
   [已签] **草稿不出现在此列表**（I-12，`.../artifact/domain.md:103`）。

5. **系统响应**：概览页的其余板块。
   **[待裁] → Q-6②**。已知**可以**放进来的（都有出处）：当前议程环节（依赖 UC-00.1）、
   四类项目角色人数、蓝本名与版本。**不得**自行增加没有出处的板块。

## R4 备选流程与异常流程

- **备选流程**
  - **A1**：**空态**——[已签] 回流列表为空时返回 `[]`，**不生成伪数据**
    （`.../artifact/usecases.md:97`，V5）。界面显示真实空态 + 下一步。
  - **A2**：**只选了蓝本、主题与分组未定的低准备度项目**——[已裁 · 原型] 该状态真实存在
    （`.../uc-2-2-…md:170-171`）；列表须能表达它，且**不得伪造结构**。
  - **A3**：**按环节过滤**——[已签] `listBackflow.in.stepId` 可选（`artifact.ts:335`）。
  - **A4**：**组织被停用**——[已签] 数据只读。项目在列表中**显示且标注只读**还是消失：
    **[待裁] → Q-7③**（我的倾向已写在那里，此处不填）。
  - **A5**：**项目已归档**——**[待裁] → Q-5**。本 UC 不预设归档存在。

- **异常流程**
  - **E1**：**无项目角色者请求某项目的回流列表** → [已签] `NO_PROJECT_ROLE`
    （`artifact.ts:338`），且它是**正常状态不是异常**，界面渲染**分层的**无权限态：
    要说清是组织层还是项目层限制（`.../uc-1-4-…md:151`；`identity.ts:188-190`）。
  - **E2**：**该项目不存在 / 无权得知其存在** → 拒绝**不得泄露存在性**
    （同 `ARTIFACT_NOT_FOUND` 兼任草稿越权的处理，`.../artifact/usecases.md:31`）。
    ⚠ 项目级是否也用 404 而非 403：**[待裁] → Q-6①**（它取决于列表口径）。
  - **E3**：**检索/存储依赖不可用** → [已签] `DEPENDENCY_UNAVAILABLE`，
    保留最后成功数据、**不静默**（`.../artifact/usecases.md:29`）。
  - **E4**：**鉴权服务不可用** → [已签] 一律拒绝，**不得降级放行**（`identity.ts:199`）。
  - **E5**：**组织切换过程中的残留** → [已签] 必须清空当前项目/环节/鉴权缓存，
    **不得跨组织残留**（`identity.ts:516-521`；`.../uc-0-3-…md:78-79`）。

## R5 权限与可见性

| 角色 | 列表里能看到 | 项目内能看到 |
|---|---|---|
| **持项目角色者** | 该项目 | [已签] 按四角色矩阵裁剪（`project-role-matrix.ts:56-78`） |
| **`observer`** | 该项目 | [已签] **只有 `read.published`**；回流列表中未发布内容的可见性须按此收紧（⚠ 与 I-13「只收紧不放宽」同向，`.../artifact/domain.md:104`） |
| **组织 `lead`（项目负责人）** | **[待裁] → Q-6① / Q-4②** | [已签] 不因组织角色获得内容读取权（`.../uc-1-4-…md:131-132`） |
| **组织 `admin`** | **[待裁]**（同上） | [已签] 仅 `purpose: "audit"` 通道可读，**每次写审计且对项目负责人可见**（`identity.ts:219-226`、`provenance.ts:46`）。⚠ `audit` **只豁免项目层，不豁免组织层可见性范围**（`design-coherence.md:414-415`） |
| **组织 `compliance`** | **[待裁]** | [已签] 可查审计链，**不因此获得项目内容读取权**（`.../uc-0-3-…md:101`） |
| **免注册进场者** | 仅其进场的那个项目 | [已签] 不得访问任何组织级资源（`.../uc-1-4-…md:182-183`） |
| **未登录 / 链接失效** | 无 | 无；[已签] 不得只依赖前端隐藏（`.../uc-1-4-…md` R5 末条） |

## R6 后置条件 / 不包含

- **后置条件**：读操作，无状态变更。
  ⚠ 例外：[已签] `purpose: "audit"` 的内容读取**有副作用**（必写 provenance），
  所以它是 POST 而不是 GET（`identity.ts:430-441`）。项目概览若接入审计读取路径，
  须遵守同一形状。
- **不包含**：回流数据的产生（phase-00 F06）、准备度口径（uc-2-2 `[待确认]`）、
  项目筹备四子标签（UC-2.2 F24）、文件浏览器（22-files F31）。

## R7 业务规则

1. [已签] **空态返回 `[]`，绝不生成伪数据**（`.../artifact/usecases.md:97`）。
2. [已签] **草稿对非创建者不可见**，管理员亦然；越权直读返回 **404 而非 403**
   （`.../artifact/domain.md:103` I-12）——403 会泄露「这里有一份你看不到的草稿」。
3. [已签] 无权限态必须**分层**说明（组织层 / 项目层），不能只显示「无权限」
   （`identity.ts:188-190`；`.../uc-1-4-…md:151`）。
4. [已签] 项目层身份**只在项目上下文渲染**，非项目页不得泄漏（有机械门控，
   `.../web-kernel/domain.md:107`）。
5. [推导] **不在本 UC 定义准备度**——它在 uc-2-2 已有登记处，第二份定义即第七次漂移。
6. [已裁] 禁用而非隐藏：不可用的东西**整行禁用并注明原因**，藏起来会被读作
   「产品做不到」（`identity.ts:139-141` 的同一条纪律）。

## R10 已知约束 / 依赖

- **依赖**：UC-00.1（当前环节）、phase-00 `artifact` 束（回流列表，已 passing）、
  phase-00 `web-kernel` 束（身份条与七态门控）。
- **⚠ 检索面缺口**：`QueryContext.projectIds` 是数组且**没有任何按项目状态过滤的规定**
  （`packages/contracts/src/context-pack.ts:147`）。若 Q-5 裁定项目可归档，
  归档项目是否参与召回**必须一并裁决**，否则会出现「项目已归档但 AI 还在引用它」。
- **契约缺口**：**契约里没有 `GET /projects`**（`packages/contracts/src/*.ts` 全文只有
  `/projects/:projectId/backflow` 一处）。列表路由是本 UC 要新增的第一条项目级路由，
  其 `in`/`out`/`err` 需随 phase-01 契约束一起签核。

## R11 切分提示

⚠ **Q-6 裁决前不要为"项目列表"生成 feature。**
可先行的只有一件：**基于已签契约的回流列表呈现**（数据面已 passing，缺的是界面）。

裁决后的建议切法：
1. 项目列表 API + 两段式返回（我在里面 / 我管着它）+ 存在性不泄露断言
2. 项目概览页外壳 + 回流列表呈现（复用已签字段与徽标）
3. 分层无权限态与空态

## R12 AI Ready 验收线索

- **V1（回流字段非空）**：任取一条 `pinned` 绑定，断言返回行的
  `mode/version/pinnedBy/pinnedAt` 四字段**均非空**；徽标 ∈ 三取值。
- **V2（草稿不泄漏）**：用**非创建者**（含项目管理员与组织 `admin`）查回流列表，
  断言 draft 条目数为 **0**；越权直读断言返回 **404 而非 403**。
- **V3（空态真实）**：新建项目查回流列表，断言返回 `[]` 且界面渲染空态，
  **断言响应体中不含任何示例条目**。
- **V4（分层无权限）**：以无项目角色者请求，断言 `NO_PROJECT_ROLE`，
  且响应能区分「组织层拒绝」与「项目层拒绝」。
- **V5（观察者裁剪）**：以 `observer` 请求，断言其可见集 ⊆ 已发布内容
  （与 `read.published` 一致，不是「全部减去写按钮」）。
- **V6（组织切换隔离）**：切换组织后立即请求上一个组织的项目，断言被拒，
  且**任何缓存的判定都未被复用**（`identity.ts:516-521` 的三条副作用逐条断言）。
- **V7（非项目页不泄漏）**：在非项目页断言 `role-bar-project` /
  `role-preview-switcher` / `topbar-project-context` **均不存在**
  （复用 `verify-ui-states.sh` 反向段）。
- **V8（分页）**：构造超过一页的回流条目，断言分页或增量加载生效。
- **V9（依赖失败）**：注入存储不可用，断言显示可解释错误与重试，
  且**未把失败呈现为空列表**——空列表与失败必须可区分。
- **V10（列表口径）**：**[待裁 → Q-6①]**，裁决前不写。
- **V11（准备度）**：**[待裁 → uc-2-2:419-420]**，裁决前不写，界面亦不显示。
