## R1 概览

- **Use Case ID / 名称**：UC-00.3 / 项目成员与两层角色交互
- **Actor**：**引导师**（`facilitator`，控场者）、**项目负责人**（组织角色 `lead`）、
  **组织管理员**（`admin`，边界见 R5）
- **目标**：让「谁在这场项目里、以什么角色」成为一件**有明确写入路径、有审计、有即时生效语义**
  的事，并把**组织角色 × 项目角色**这两层的交叉情形逐格写清楚。
- **本用例结果**：项目成员可被授予 / 变更 / 移除；四种交叉情形各有确定行为；
  变更**立即生效**且可审计。
- **系统边界**：项目成员授予与变更、两层角色交叉判定、临时提权的授予与回收。
  **不含**：登录与凭据（UC-1.1）、邀请链接的生成与撤销（UC-1.3）、
  免注册进场（UC-1.2）、组织成员邀请与激活（UC-1.6）、
  受访者一次性令牌（UC-6.3）、分组编排（UC-2.2 F25）。
- **核心数据对象**：`ProjectMembership`（[已签]，主键 `(user_id, project_id)`）、
  `OrgMembership`（[已签]）、`AclBinding`（[已签]，唯一落库载体）、
  临时提权授予（[已裁] 见 R3 步骤 5）。

## R3 主流程

1. **授予者操作**：把某人加入项目并指定项目角色。
   **系统响应**：[已签] 项目角色四取值闭集
   （`packages/contracts/src/identity.ts:177`；DB CHECK `0003-identity.sql:66`）；
   [已签] 落一行 `project_memberships`，主键 `(user_id, project_id)`
   ⇒ **一人一项目恰好一个角色**（`:70`）。
   [已签] 若是引导师，可存在**多实例**，其中一名带 `is_host = true` 持最终确认权
   （`:69`；`.../identity/domain.md:41`）。
   **授予入口是一条还是两条（组织内直接指派 / 组织外走链接）：[待裁] → Q-4 待答①。**

2. **系统处理**：把授予落成权限事实。
   [已签] **组织角色、项目角色、团队可见性三者最终都归结为 `acl_bindings` 上的判定，
   不另建三套权限表**（`.../identity/domain.md:54`）；
   [已签] 不变量 I-1：`subject` 与 `object` **必属同一组织**（`:84`，有 SQL 约束）。

3. **系统处理**：解析该人的两层身份。
   [已签] `resolveIdentity` 返回 `{ org, orgRole, teamId, projectRole, groupId }`，
   其中 `projectRole` **可为 null**（`identity.ts:498-509`）；
   [已签] 无项目上下文时 `projectLayer = null`（I-11，`.../identity/domain.md:94`），
   与「有上下文但无角色」**必须可区分**（`identity.ts:260-272`）。

4. **授予者操作**：变更或移除某人的项目角色。
   **系统响应**：[已裁] **立即生效，不等会话过期**
   （`.../uc-0-3-…md:71` A3；`.../uc-1-4-…md:106` A4）。
   实现位置（不缓存 / 缓存失效广播）**[待裁] → Q-4 待答③**。
   [已签] 变更须写审计——`membership` 已是 provenance 的一等 target 类型
   （`packages/contracts/src/provenance.ts:71`）。

5. **引导师 / 项目负责人操作**：**临时提权**。
   **系统响应**：[已裁 · 原型] 在**既有项目角色之上追加**，
   失效条件是**流程节点**（`环节 3 结束`）**而不是时间点**；
   环节被**提前结束 / 跳过 / 合并**时同样立即失效；
   失效必须由**服务端在环节状态机变更时主动收回**，不得依赖前端或定时轮询兜底
   （`.../01-auth/uc-1-4-角色可见性判定.md:77-80,97-100`）。
   ⚠ 依赖 UC-00.1 的环节状态机（**[待裁] → Q-2 待答②**）。

6. **系统收口**：越权尝试留痕。
   [已签] `unauthorized-attempt` 事件（`.../artifact/domain.md:61`），
   且 [已签] **权限判定先于存在性判定**——防止用两种拒绝的差异去枚举资源
   （`apps/api/src/application/artifact/bind-to-project-step.ts:88-95` 已确立该顺序并写明理由）。

## R4 备选流程与异常流程

- **备选流程**
  - **A1**：**同一人在多个项目持不同角色** —— [已裁] 允许（`.../uc-0-3-…md:71`）。
    数量上限：**[待裁] → Q-7①**（我的倾向是不设，见该条）。
  - **A2**：**项目角色由一次性链接授予，持有者不必是组织成员** —— [已裁]
    （`.../uc-0-3-…md:69-70` A2；`.../uc-1-4-…md:182-183`）：
    其组织层判定按「本项目授权范围」处理，**不得访问任何组织级资源**。
  - **A3**：**多名引导师** —— [已裁 O-03] 是 `facilitator` 的多实例，权限完全相同，
    一名标 `is_host`。「协同引导师」是**进场身份的展示别名**，落库写 `facilitator`
    （`.../uc-1-4-…md:168-179`）。
  - **A4**：**受访者** —— [已签] 不持项目角色，走一次性令牌（UC-6.3）。本 UC 不处理。
  - **A5**：**组织角色 `lead` 创建了项目但没给自己项目角色** —— **[待裁] → Q-4 待答②**。
    ⚠ 这不是边角情形：若不裁决，创建者会立刻看不见自己刚建的项目。

- **异常流程**
  - **E1**：**有组织角色但无项目角色** → [已签] 项目内资源一律不可见，**管理员亦然**
    （`.../uc-0-3-…md:84` E1；`.../uc-1-4-…md:111` E3）。返回 `NO_PROJECT_ROLE`，
    且这是**正常状态不是异常**（`identity.ts:194`）。
  - **E2**：**资源标为「仅某团队」而请求者不在该团队** → [已签] 即使项目角色足够也拒绝，
    并说明是**组织层**限制而非项目层（`.../uc-0-3-…md:87-88` E3；`.../uc-1-4-…md:109-110`）。
  - **E3**：**权限在操作过程中被撤回** → [已裁] 立即终止后续写操作；已完成步骤按审计规则保留；
    未提交输入留本地草稿并提示重新授权（`.../uc-0-3-…md:85-86` E2）。
    ⚠ Context Pack 侧有对应失败码 `PERMISSION_REVOKED_MIDWAY`
    （`packages/contracts/src/context-pack.ts` 的 `assembleContextPack.err`）——两处须同源。
  - **E4**：**角色数据不一致**（项目角色指向已停用的组织成员）→ [已裁] 按**拒绝**处理并告警
    （`.../uc-0-3-…md:89` E4；`.../uc-1-4-…md:112`）。
  - **E5**：**鉴权服务不可用** → [已签] `AUTH_SERVICE_UNAVAILABLE`，
    **一律拒绝，不得降级放行**（`identity.ts:199`）。
  - **E6**：**移除最后一名引导师 / 最后一名 `is_host`** → **[待裁] → Q-4**。
    ⚠ 契约里 `is_host` 是布尔无约束（`0003-identity.sql:69`），
    「至少一名主持人」既没有 DB 约束也没有规则出处。本文**不自行设定**。
  - **E7**：**并发改同一人的角色** → [已裁] 不得静默覆盖；提示版本已变化
    （`.../uc-2-2-…md:199` E5 的通用条款）。

## R5 权限与可见性 —— 两层交叉的四格

> [已签] **组织层决定「能不能用这个资源」，项目层决定「在这场项目里能看到哪些内容、做哪些动作」；
> 两者任一不通过即拒绝**（`.../uc-0-3-…md:58-59`）。

| 交叉情形 | 行为 | 出处 / 状态 |
|---|---|---|
| 有组织角色 **+** 有项目角色 | 取两层交集 | [已签] `.../uc-0-3-…md:58` |
| 有组织角色 **+ 无**项目角色 | 项目内资源一律不可见，**管理员亦然** | [已签] `.../uc-0-3-…md:84`、`.../uc-1-4-…md:111` |
| **无**组织角色 **+** 有项目角色 | 仅本项目授权范围；**不得访问任何组织级资源** | [已签] `.../uc-1-4-…md:182-183` |
| 组织 `lead` 对**自己创建但未加入**的项目 | **未定** | 🔴 **[待裁] → Q-4 待答②** |

**逐角色**

- **组织 `admin`**：[已签] 后台全部配置；**不是超级用户**——不因管理员身份获得任何项目内容读取权
  （`.../uc-1-4-…md:131`）。唯一豁口是 `purpose: "audit"` 读取，
  **每次写审计且对项目负责人可见**（`identity.ts:219-226`；`provenance.ts:46`），
  且该豁口**只豁免项目层，不豁免组织层可见性范围**——两层都豁免会让它成为
  「谁都能敲出来的万能钥匙」（`design-coherence.md:412-415`）。
  ⚠ [已签] 管理员对他人**个人层**只能拿到**计数**，响应体中**不存在**内容字段
  （I-8，`.../identity/domain.md:91`；`identity.ts:476-494`）。
- **组织 `lead`（项目负责人）**：[已签] 创建与管理项目（`.../uc-0-3-…md:99`）；
  [已签] 与项目角色「引导师」是**独立授予**的（`.../uc-1-4-…md:132`）。管理范围 **[待裁]**。
- **组织 `compliance`**：[已裁 D-U3] 对整个组织的合规负责，可查审计链与撤回队列，
  **不因此获得项目内容读取权**（`.../uc-0-3-…md:101`）。
- **四种项目角色**：见 `uc-00-1` R5 的矩阵表（源自 `project-role-matrix.ts:56-78`，闭集）。
- **未登录 / 链接失效 / 未列出的角色**：[已签] 默认无权限；
  接口不得返回越权数据，**不能只依赖前端隐藏**。

## R7 业务规则

1. [已签] 项目角色**恒为四种**；协同引导师 = 多实例；研究员/参与者 = **展示别名不落库**；
   受访者**不持项目角色**（`.../identity/domain.md:41-43`）。
2. [已签] **一人一项目恰好一个项目角色**（主键约束）。
3. [已签] **不另建权限表**——一切归结到 `acl_bindings`（`.../identity/domain.md:54`）。
4. [已签] 拒绝必须**分层说明**（组织层 / 项目层），不能只说「无权限」
   （`identity.ts:188-190`）。
5. [已签] **管理员不是超级用户**；审计豁口只豁免项目层且必留痕
   （`design-coherence.md:412-415`）。
6. [已签] 个人层对任何人封闭，只出计数，**响应体中不得存在内容字段**
   ——不是「内容为空串」（I-8 的断言方式，`.../identity/domain.md:91`）。
7. [已裁] 临时提权的失效条件是**流程节点不是时间点**，由服务端主动收回
   （`.../uc-1-4-…md:97-100`）。
8. [已签] **权限判定先于存在性判定**，防枚举（`bind-to-project-step.ts:88-95`）。
9. [已签] 依赖不可用**一律拒绝，不降级**。
10. [推导] 角色矩阵若被前端需要，**移进 `packages/contracts`，不得复制**
    （`project-role-matrix.ts:5-12`）。

  ③ 无组织角色有项目角色 → 项目内可用、**组织级资源被拒**；
  ④ **[待裁 → Q-4②]**，裁决前不写。
- **V4（管理员不是超级用户）**：以 `admin` 且无项目角色调用 `readContent`，
  断言被拒且 `reasonCode === "ADMIN_NOT_SUPERUSER"`；
  再以 `purpose: "audit"` 调用，断言**放行且 `provenanceEventId` 非 null**——
  留痕写失败时本操作必须失败（`identity.ts:440-441`）。
- **V5（audit 不豁免组织层）**：把资源标为 `team-only`，以不在该团队的 `admin` +
  `purpose: "audit"` 调用，断言**仍被拒**（`design-coherence.md:414-415`）。
- **V6（个人层只出计数）**：断言 `getPersonalLayerSummary` 的响应 JSON
  **不存在** content/body/text/excerpt/preview/snippet 任一键——
  不是「值为空串」（`identity.ts:478-481`）。
- **V7（立即生效）**：在一个活跃会话中撤销某人的项目角色，断言**下一次请求**即被拒，
  不等会话过期、不等缓存 TTL。
- **V8（临时提权按流程节点失效 · 三向反证）**：授权后分别以
  ①正常结束 ②提前结束 ③跳过 ④合并 四种方式终结该环节，
  断言四种情形下权限**均**立即失效；**再**断言在环节仍进行时该权限有效
  （只有单向断言时，一个"从不授权"的实现也会全绿）。
- **V9（不一致即拒）**：构造指向已停用组织成员的项目角色，断言按拒绝处理并告警。
- **V10（防枚举）**：以无项目角色者对**存在**与**不存在**的两个 id 各请求一次，
  断言两次响应**不可区分**，且两次都写了越权审计。
- **V11（审计可检索）**：授予/变更/移除/临时提权均可按操作者、时间、对象、结果检索；
  断言 `provenance_events` 的 UPDATE / DELETE 被拒。
- **V12（组织冻结）**：组织置 `disabled` 后尝试改成员，断言被 PG 策略拒绝。
- **V13（展示别名不落库）**：以「协同引导师」身份进场，
