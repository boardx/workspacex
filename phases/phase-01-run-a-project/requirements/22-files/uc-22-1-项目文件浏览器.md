# 原始需求（细化）— UC-22.1 项目文件浏览器

> 所属：阶段一 · 能跑完一场项目 / M22 项目文件
> 来源：**人类新需求（2026-07-28）**「我们需要为项目建立一个文件的模块，用于存储所有的关于
> 项目的文件，context engine 是基于文件的上下文，用户可以在这里上传文件和下载所有的对应的
> 文件。**能保存成文件的数据，尽量保存成文件，可以在这文件浏览器看到。**」；
> 架构依据 `docs/architecture/context-engine.md` **第 2.0 节 file-first 原则**第 3 条
> 「文件浏览器是证据平面的用户界面——用户在那里看到的目录树，就是 `artifacts /
> artifact_versions` 的投影，不是另一套存储」与第 5 条「可见性沿用同一套 ACL」。
> **原型钩子（仅计数，不是浏览器本体）**：项目筹备「材料准备 **9 已入库材料**」、
> 蓝本第 9 项「项目材料 **9 件**」、第 10 项「分组打印素材 **4 件**」、
> 对话右栏五标签之一「**材料 12**」。
> **补写缘由**：这四处钩子都只显示**计数**，点进去是什么、文件从哪看、怎么下载，
> 原型全无。file-first 原则若没有一个可见的浏览器承载，就退化成「只写不读的导出」，
> 「删除后文件浏览器里那份必须真的消失」也无从演示。

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **13**；建议迭代 **迭代 2 · 材料入库**。
>
> ⚠ **本 UC 绝大部分是 `[设计]`**。原型在本模块只提供了「材料准备」那一张**环节维度的
> 材料要求表**和一个 `[上传材料]` 按钮（见 UC-22.2）；**文件浏览器本体在原型中确认缺失**，
> 判定依据见 R8。架构文档 `context-engine.md` 是**设计输入，不是原型**，
> 其中的表结构、状态机、file-first 五条一律标 `[设计]`。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-22.1 / 项目文件浏览器
- **Actor**：**项目负责人**、**引导师**、**顾问**（组织角色）；**组长 / 组员 / 观察者**（项目角色）；
  以及**只读取不写入**的 agent（检索时经 Context API，不经本界面）。
- **目标**：[设计] 给这个项目的**全部上下文**一个**唯一的、可浏览的、可下载的入口**——
  不管这份东西原本是上传的 Word、一场问卷的回收、一次访谈的录音、一段对话，
  用户都能在同一棵树里看到它、预览它、把它下载走。
- **本用例结果**：用户看到一棵按**来源类型**组织的项目文件树，每个节点是一个
  `artifact` 的当前版本；可预览、可下载单个、可批量导出为 zip；
  看到的范围**严格等于**他在 UC-0.3 两层角色 + `acl_bindings` 下被允许看到的范围。
- **系统边界**：目录树与列表渲染、来源类型分组、行元数据展示、预览、单个下载、
  批量导出、搜索与筛选、权限过滤、目录/命名契约。
  **不含**上传与摄取（UC-22.2）、非文件来源的物化（UC-22.3）、版本与删除传播（UC-22.4）。
- **核心数据对象**：`artifacts`、`artifact_versions`、`acl_bindings`、
  `agenda_segment`（可空的所属议程环节）、来源类型枚举、机密标记、导出任务。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已登录并在该项目中持有至少一个项目角色（或以组织角色获得受审计的读取路径，UC-0.3 A1）。
  - 项目已存在；项目内可以**零文件**（空态是合法状态，见 R8 与 V5）。
- **触发条件**：
  - [设计] 用户在项目工作台点击**「文件」标签**（新增标签，原型 7 标签中无此项，见 R8）。
  - [原型] 从「项目筹备 → 材料准备」的计数「**9 已入库材料**」下钻。
  - [原型] 从对话右栏「**材料 12**」标签的「查看全部」下钻。
  - [原型] 从蓝本第 9 项「项目材料 9 件」/ 第 10 项「分组打印素材 4 件」下钻。
  - [设计] 从任一引用角标（洞察报告的来源角标、Context Pack 的 `artifactVersionId`）
    跳转到该文件在浏览器中的位置。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **用户操作**：进入项目 → 文件。**系统响应**：以当前用户身份查询该项目下的 `artifacts`，
   **权限过滤在 SQL/RLS 层完成**（不在应用层，见 `context-engine.md` 第五节），
   返回他有权见到的集合；无权见到的**不出现、也不占位、不显示"已隐藏 N 项"**。

2. **系统处理**：按**来源类型**把结果分成八组，渲染为目录树的一级节点：
   | 一级节点 | 来源类型枚举 | 典型内容 |
   |---|---|---|
   | 文件 | `file` | 用户上传的 Word / PDF / PPT / 图片 / 音频 |
   | 问卷 | `survey` | `responses.csv` + `schema.json`（12-survey） |
   | 访谈 | `interview` | 音频 + `transcript.jsonl` + `notes.md`（06-itv） |
   | 工作坊 | `workshop` | 音频 + `transcript.jsonl` + 白板照片（05-rec） |
   | 研究 | `research` | 网页快照 + `citations.json`（研究 Studio） |
   | 对话 | `conversation` | `messages.jsonl`，**以会话为文件粒度**（08-chat） |
   | 画布 | `canvas` | mermaid 源码 `.md` + 布局快照（07-canvas，D-08） |
   | AI 生成 | `generated` | 内容文件 + `provenance.json`（醒目标 synthesized） |
   [设计] 二级节点按 `agenda_segment` 分组（未绑定环节的落在「**未归入环节**」节点，
   该节点**必须存在且不可隐藏**，否则通用上传的文件会从树上消失）。

3. **用户操作**：切换到**列表视图**。**系统响应**：以表格呈现，每行必须含以下列
   （[设计]，列可隐藏但**默认全显**）：
   | 列 | 说明 |
   |---|---|
   | 名称 | `artifact` 显示名 + 文件扩展名 |
   | 来源类型 | 上表八类之一，带图标与文字（不可只有图标） |
   | 大小 | 当前版本字节数，人类可读 |
   | 版本号 | `v3` 形式；点击展开版本列表（UC-22.4） |
   | 上传/生成时间 | 当前版本的创建时间 |
   | 上传者 | **人或 agent**；agent 必须显示 agent 名 + `agent_run_id` 可下钻，**不得显示为某个人** |
   | 所属环节 | `agenda_segment` 名称，**可空**（显示「—」而非留白） |
   | 可见性范围 | 全场 / 本组 / 私有 / 仅某团队（对齐 UC-0.3 第 3 步） |
   | 机密标记 | 有机密标记时显示醒目角标（O-17：材料级、上传时人工勾选、默认继承项目级） |
   | 摄取状态 | UC-22.2 九态中的当前态；非 `READY` 的行**必须显式可见**（见 UC-22.2 R7） |

4. **用户操作**：点击某一行。**系统响应**：右侧打开**预览面板**。
   [设计] 必须支持的预览类型：**PDF**（分页、可跳页）、**图片**（可缩放、显示 EXIF 摘要）、
   **音频**（波形 + 时间码定位）、**文本/Markdown**、**JSONL**（分行表格化，不是裸文本块）。
   不支持预览的类型**明确显示「此类型不支持预览，请下载查看」并给出下载按钮**，
   不得显示空白或转圈。

5. **用户操作**：点击**「下载」**。**系统响应**：签发**短时效、一次性、带
   `permissionDecisionId` 的下载 URL**；对象存储直连下载。
   下载动作写入 `provenance_events`（对齐 17-gov/UC-17.1 四类事件）。

6. **用户操作**：勾选多行（或选中一个树节点）→ 点击**「批量下载 / 导出为 zip」**。
   **系统响应**：创建**异步导出任务**；zip 内部目录结构**等于浏览器中看到的树结构**
   （这是 R7 的契约之一）；根目录附一份 `manifest.json`
   （含每个文件的 `artifact_id` / `version` / `sha256` / 来源类型 / 生成时间 / 机密标记）。
   导出完成后给出下载入口与**有效期**；**导出本身写审计**。

7. **用户操作**：使用搜索框与筛选器。**系统响应**：
   [设计] **搜索**走 PostgreSQL FTS（`context-engine.md` 第四节「FTS 必须是一等检索通道」），
   匹配**文件名 + 已抽取文本内容**，命中内容时在结果行显示命中片段与锚点。
   **筛选**六项：来源类型 / `agenda_segment` / 时间范围 / 上传者（人或 agent）/
   是否含机密标记 / 摄取状态。筛选条件**必须可组合、可从 URL 还原**（便于把一个视图发给同事）。

8. **系统收口**：校验 AC1「**文件浏览器不是权限旁路**」——同一份 `artifact`，
   用不同角色的会话请求，返回集合与 Context API 检索可见集合**完全一致**。

9. **系统收口**：校验 AC2「树上的每个节点都对应一个**真实可下载的对象存储文件**」——
   不存在只有元数据、下载即 404 的幽灵节点。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] **从引用角标反向定位**——洞察报告的来源角标点开后，浏览器自动展开到该
    `artifact_version` 并高亮对应锚点（页码/时间码/消息 ID）。这是「排查 AI 为什么这么答」
    的主路径（`context-engine.md` 第 2.0 节收益第 3 条）。
  - A2：[设计] **观察者视角**——观察者只见**已发布且已脱敏**的文件；未发布的、
    含机密标记的、未完成脱敏的**不进入其结果集**（对齐 D-12 观察者是一等项目角色）。
  - A3：[设计] **组员视角**——组员只见**本组**范围 + 全场范围；他组的分组材料不可见。
  - A4：[设计] **agent 生成物的过滤视图**——一键切到「只看 AI 生成」，
    每行强制显示 `synthesized` 标记与 `provenance.json` 入口（对齐 16-persona）。
  - A5：[设计] 目录树节点为空时（如该项目还没有任何访谈），该一级节点
    **仍然显示但标为空**，不隐藏——用户需要知道「这个来源存在但还没有内容」。

- **异常流程**：
  - E1：[设计] **对象存储不可用**——列表仍可渲染（元数据来自 PG），
    但预览与下载按钮变为**不可用并显示原因**；**不得让用户点了没反应**。
  - E2：[设计] **批量导出超过阈值**（[待确认] 文件数或总字节上限）——
    拒绝并提示改为分批，或转为「后台生成 + 完成后通知」。**不得静默截断**。
  - E3：[设计] 用户请求一个他**无权访问**的 `artifact_id`（如从旧链接进入）——
    返回**与「不存在」完全相同的响应**，不泄露资源存在性（对齐 UC-0.3 第 5 步）。
  - E4：[设计] 某 `artifact_version` 的对象存储对象校验失败（SHA-256 不匹配）——
    该行标为**「完整性校验失败」**，禁止下载，触发告警并写审计；
    **不得悄悄给出一个损坏文件**。
  - E5：[设计] 文件正处于摄取中间态（非 `READY`）——可见、可下载**原件**，
    但预览的派生物（转录/OCR）标为「生成中」；检索侧尚未可召回，界面须如实说明。
  - E6：[设计] 文件已被删除且处于**删除宽限期**内——**在浏览器中不再出现**
    （对齐 UC-22.4 与 17-gov）；仅合规负责人在「待删除队列」看得到。

## R5 权限与可见性

- **组织管理员**：不因管理员身份自动获得项目内容读取权（UC-0.3 AC1）；
  出于审计目的的读取走 UC-0.3 A1——**每次访问写审计日志且对项目负责人可见**（D-18）。
- **项目负责人 / 引导师**：可见本项目全部文件（机密标记文件同样可见，但其**处理路由**
  受 O-17/D-17 约束，见 20-model/UC-20.3）。
- **组长 / 组员**：可见「全场」范围 + **本组**范围；他组材料不可见、不可搜索、不可导出。
- **观察者**：只见**已发布且已脱敏**的文件；无下载权？——见 R10 `[待确认]`。
- **顾问**：按其团队归属与资源可见性范围（全组织可用 / 仅某团队）过滤。
- **外部受访者**：不进入本界面（其可见内容走 06-itv/UC-6.6 自助门户）。
- **硬约束**：权限判定必须在 **SQL/RLS 层**执行；**应用连接不得使用表 owner 身份**
  （PostgreSQL 表 owner 默认不受 RLS 限制，用 owner 连接等于 RLS 形同虚设）。
- **硬约束**：下载 URL 必须**短时效、绑定 principal、一次性**；
  **不得签发可转发的长期公开链接**。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 用户获得该项目上下文的完整、可下载视图；下载与导出动作全部留痕。
  - [设计验收] AC1：文件浏览器可见集合 ≡ Context API 检索可见集合（同 principal、同时刻）。
  - [设计验收] AC2：树上每个节点都能下载到一个 SHA-256 与元数据一致的真实文件。
  - [设计验收] AC3：zip 导出的内部目录结构与界面树结构一致，且含 `manifest.json`。
- **失败后置条件**：
  - 权限判定失败时**默认拒绝**（fail-closed），不得因为过滤器异常而"退化为全部可见"。
  - 导出任务失败不产生半截 zip；已产生的临时对象被清理。
- **不包含**：
  - 上传与摄取流水线 → UC-22.2。
  - 非文件来源物化为文件 → UC-22.3。
  - 版本、派生物、删除传播 → UC-22.4。
  - **在浏览器内直接编辑文件内容**（file-first 的原件不可变，编辑等于新版本上传）。
  - 跨项目的文件搜索（属组织级，phase-3）。
  - 文件夹的自由创建/拖拽整理——目录结构是 `artifacts` 的**投影**，不是用户自建的文件系统。

## R7 业务规则（不随具体实现变化的硬性约束）

- [设计｜架构 2.0.3] **文件浏览器是 `artifacts / artifact_versions` 的投影，不是另一套存储**。
  不得为浏览器单独建一张目录表，否则必然与证据平面漂移。
- [设计｜架构 2.0.5] **文件浏览器不是权限旁路**。`acl_bindings` 对浏览器与检索一视同仁；
  任何「浏览器能看到但检索看不到」或反之，都是缺陷而非特性。
- [设计｜架构 2.0.100] **目录结构与文件命名一旦对外可见即为契约**。
  改名、改目录层级必须走**迁移**：保留旧路径的重定向或别名，并在变更日志中记录；
  **禁止随手重构**。理由：客户已下载的 zip、已发出的引用链接、已归档的交付物都依赖它。
- [设计] **每个可见节点必须对应一个可下载的真实文件**——不存在「只活在数据库表里」的上下文。
  这是 file-first 的最小可验证形式（见 V2）。
- [设计] **来源类型是一等字段**，不是从 MIME 推断的。同为 `.jsonl`，
  对话导出与访谈转录是两个来源类型，分组、权限、脱敏策略都不同。
- [设计] **agent 上传者必须显示为 agent**，并可下钻到 `agent_run_id`。
  把 agent 产物记在人名下会污染证据链（对齐 D-39「负责人恒为人，执行者另记」的同源约束）。
- [设计] **AI 生成内容在列表中必须带 `synthesized` 醒目标记**，
  且**不得在下一次检索中伪装成一手证据**（架构第三节末条 + 16-persona / D-25）。
- [设计｜O-17] **机密标记为材料级**，产生方为上传时人工勾选（默认继承项目级默认值），
  归属 17-gov。浏览器只**展示**与**筛选**机密标记，**不是**机密标记的产生方。
- [设计] **不显示"你有 N 项无权查看"**。计数本身即信息泄露。
- [设计] 空态是合法状态：新项目文件为零时展示真实空态与「上传材料」下一步，
  **不生成示例数据**（对齐 UC-1.5 V5 的同类要求）。

## R8 界面线索

- **前端入口**：
  - [设计] 项目工作台**新增第 8 个标签「文件」**。
  - [原型] 项目筹备「材料准备」的计数「9 已入库材料」→ 下钻（原型只有计数，无下钻目标）。
  - [原型] 对话右栏五标签之一「材料 12」→ 「查看全部」（原型只有标签与计数）。
- **信息架构**：左树（来源类型 → `agenda_segment`）+ 中列表 + 右预览，三栏。
  顶部为搜索框 + 六项筛选 + 视图切换（树/列表）+ 「上传材料」「导出为 zip」两个主按钮。
- **推荐交互**：
  - [设计] 树与列表**联动**：点树节点，列表筛到该节点；筛选条件反映在 URL 中。
  - [设计] 预览面板支持**锚点直达**（PDF 跳页、音频跳时间码、JSONL 跳消息 ID）。
  - [设计] 批量选择后顶部出现操作条：下载 / 导出 zip / 归入环节 / 标记机密（有权者）。
- **必须呈现的状态**：默认 / 加载 / **空** / 校验失败 / **依赖失败（对象存储不可用）** /
  **无权限** / 成功。按 D-36 统一规范实现，sign-off 时豁免逐屏设计。
- **原型参考**：
  - `WorkspaceX Standalone.html` — 项目 → 项目筹备 → 材料准备（仅计数与要求表）
  - `WorkspaceX Standalone.html` — 对话右栏「材料 12」标签
- **UI sign-off**：**原型确认缺失**（不是「未探明」）。
  判定依据：项目工作台的 **7 个标签**与项目设置的 **6 个子标签**均已完整抽取
  （proto-05-deep-layer.md / proto-08-project-settings.md），
  其中**没有任何文件浏览/目录树/批量下载的界面**；
  「材料准备」屏是**环节维度的材料要求表**（列：环节 / 形式 / 负责人 / 材料要求 / 推演模板），
  **不是文件列表**——它回答「这个环节需要什么材料」，不回答「我们有哪些文件」。
  **实现前必须先补画原型并由产品/设计确认**（本模块四份 UC 共用同一判定）。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 单项目 **5000 个 artifact** 以内，列表首屏 P95 < 1.5s；树展开 < 300ms。
  - [设计] 单文件下载走对象存储直连，不经应用服务器转发（避免大文件占用 Node 事件循环）。
  - [设计] 批量导出为**异步任务**，不阻塞界面；[待确认] 单次导出的文件数/总字节上限。
- **安全/隐私/合规**：
  - 下载 URL 短时效、绑定 principal、一次性；不得可转发。
  - 预览渲染必须防 **XSS / SVG 脚本注入 / HTML 文件直接渲染**——
    未知类型一律以 `Content-Disposition: attachment` + 隔离域名提供，**不在主域内联渲染**。
  - **文件名与文件内容都是不可信数据**，不得被 agent 当作系统指令（见 UC-22.2 R7）。
  - 含机密标记的文件在列表中的**内容片段（搜索命中摘要）是否展示** → 见 R10 `[待确认]`。
- **兼容与降级要求**：
  - 响应式；移动端至少支持浏览、预览与单个下载（批量导出可降级为"发到邮箱/稍后下载"）。
  - 对象存储不可用时降级为只读元数据视图，且**明确告知**。

## R12 AI Ready 验收线索

- V1（权限态·可执行）：同一项目，分别以引导师 / 组长 / 组员 / 观察者会话调用
  `GET /projects/:id/artifacts`，把四组 `artifact_id` 集合与
  `POST /context/search` 在同 principal 下返回的 `artifactVersionId` 去重后的集合**逐一比对**，
  断言**四组均完全相等**。任一组不等即失败。
- V2（file-first 核心·可执行）：遍历 `GET /projects/:id/artifacts` 返回的**每一个**节点，
  对其 `current_version` 调 `GET /artifacts/:aid/versions/:vid/download`，
  断言 **HTTP 200**、`Content-Length > 0`、且响应体 SHA-256 **等于** `artifact_versions.sha256`。
  断言**零个节点**下载失败。
- V3（成功态）：上传 3 个文件 + 触发 1 场问卷物化 + 1 场对话物化后，
  `GET /projects/:id/artifacts` 返回的来源类型分布为 `file:3, survey:2, conversation:1`
  （问卷产出 `responses.csv` 与 `schema.json` 两个 artifact）。
- V4（导出 round-trip·可执行）：调批量导出 API 得到 zip，解压后断言
  ① 目录层级与 `GET /projects/:id/artifacts/tree` 的 JSON 结构同构；
  ② `manifest.json` 中每条的 `sha256` 与解压出的对应文件实际哈希相等；
  ③ 文件数等于 manifest 条目数（**无静默截断**）。
- V5（空态）：新建空项目，文件页返回八个来源类型节点、每个 `count:0`，
  界面显示真实空态与「上传材料」入口，**不生成任何示例数据**。
- V6（安全态·可执行）：以无权会话请求一个真实存在的 `artifact_id`，
  与请求一个随机不存在的 `artifact_id`，断言**两次响应的状态码、响应体、响应头完全一致**。
- V7（依赖失败）：断开对象存储，断言列表接口仍 200 返回元数据，
  下载接口返回明确的依赖失败错误码（非 500 裸错），界面下载按钮置灰并显示原因。
- V8（完整性态）：人为篡改对象存储中某个对象的字节，
  断言该行被标为「完整性校验失败」、下载被拒绝、且产生一条告警与审计事件。
- V9（审计态）：一次下载 + 一次导出后，按操作者、时间、对象三个维度均能检索到对应
  `provenance_events` 记录。
- V10（agent 归属态）：由 agent 生成的 artifact，其列表行 `uploader.type == "agent"`
  且 `agent_run_id` 非空；断言**不存在** `uploader.type == "human"` 却带 `agent_run_id` 的记录。
- V11（契约态）：对某 artifact 执行改名，断言旧路径的引用链接仍可解析（重定向或别名命中），
  且变更被记录；断言**不存在**改名后旧引用直接 404 的情况。
