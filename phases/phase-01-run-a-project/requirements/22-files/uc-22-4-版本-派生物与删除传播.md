## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-22.4 / 版本、派生物与删除传播
- **Actor**：**项目负责人**（删除发起）、**合规负责人**（待删除队列、legal hold、回执）、
  **引导师 / 组长**（版本查看与新版本上传）、**删除 worker**（系统 Actor）。
- **目标**：[设计] 让「改一版」和「删一份」这两件事都**说得清、演示得出来**——
  改版不丢旧证据，删除是真删且能级联到所有派生物与索引。
- **本用例结果**：每个 `artifact` 有一条可查的版本线（每版带 SHA-256、可下载）；
  每个派生物是独立文件且指回其原件版本；删除后**文件浏览器里那份真的消失**，
  其 OCR / embedding / 图边 / 摘要 / 缓存在 ≤5 分钟内可验证失效，
  ≤30 天内物理删除并出回执。
- **系统边界**：版本模型与版本列表 UI、派生物模型与 `derived_from`、
  删除的两级 SLA 与级联失效清单、待删除队列与回执、legal hold 与保留期。
  **不含**受访者侧的撤回界面（17-gov/UC-17.2）、组织级审计（D-34）、
  跨项目级联（phase-3）。
- **核心数据对象**：`artifact_versions`、`derived_representations`、
  `provenance_events`、待删除队列、删除任务与回执、legal hold、
  留存参数（O-01 五参数）。

## R2 前置条件 / 触发条件

- **前置条件**：
  - UC-22.1 / 22.2 / 22.3 已可用；`artifact` 至少有一个版本。
  - 项目已配置留存参数（继承组织默认值，项目级可覆盖，D-14）。
- **触发条件**：
  - **版本**：[设计] 同名文件再上传；业务对象内容变更触发重新物化（UC-22.3 第 4 步）；
    有权者在版本列表点「上传新版本」。
  - **派生物**：[设计] 摄取流水线的 `EXTRACTED` / `ENRICHED` 阶段产出；
    pipeline / parser / model 升版后的重跑。
  - **删除**：
    - [设计] 项目负责人在文件浏览器对某 `artifact` 执行「删除」。
    - [原型侧联动] 受访者在自助门户撤回同意（17-gov/UC-17.2 的四项独立同意之一）→
      触发对应范围的删除传播。
    - [设计] 留存期到期（O-01 材料保留期默认 **180 天**）→ 自动进入待删除队列。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

### R3.a 版本

1. **用户操作**：对已有 `artifact` 上传同名文件（或业务对象变更触发物化）。
   **系统响应**：计算 `content_hash`；若与当前版本相同 → **不新增版本**（幂等，UC-22.2 A3）；
   不同 → 创建**新的 `artifact_version`**，版本号递增，**旧版本对象保持原地不动**。

2. **用户操作**：在文件浏览器点版本号，展开**版本列表**。
   **系统响应**：[设计] 逐版显示：版本号、创建时间、创建者（人或 agent）、
   字节数、**SHA-256（可复制）**、变更来源（上传 / 物化 / 重跑）、
   以及**每一版独立的下载按钮**。
   🔴 **旧版仍可下载**——这是证据平面不可变性的用户可见形式。

3. **系统收口**：校验「**当前版本**」的指向唯一且明确；
   引用（Context Pack、报告来源角标、固定快照）指向的是**具体 `artifact_version_id`**，
   **不是** `artifact_id`——否则新版本一上传，历史结论的证据就被偷换了
   （对齐 D-30「引用必须指向不可变快照」）。

### R3.b 派生物

4. **系统处理**：摄取流水线产出 OCR 文本 / ASR 转录 / 摘要 / 视觉描述 / embedding。
   [设计] 每一项都创建一条 `derived_representations` 记录，
   **并且**（除 embedding 外）**物化为一个独立的、可见可下载的文件**
   （架构 2.0 第 4 条：「OCR 结果、转录稿、摘要各自是独立文件」）。

5. **系统处理**：每个派生物必须带 **`derived_from` 指回具体的 `artifact_version_id`**
   （不是 `artifact_id`），并记录**生成它的模型与版本**（`generator_model` /
   `generator_version` / `pipeline_version`）。

6. **系统处理**：派生物在文件浏览器中呈现为原件节点下的**子节点**
   （`原件.pdf` → `原件.ocr.txt`、`原件.summary.md`），
   [设计] 默认折叠，可展开；**不与原件混在同一层**，避免树被派生物淹没。

7. **系统收口**：校验 🔴「**派生物不覆盖原件**」——
   重跑 OCR 产生**新的派生物版本**，原件的 `artifact_version` 字节与哈希**不变**。

### R3.c 删除传播（两级 SLA，D-15）

8. **用户操作**：项目负责人对某 `artifact` 点「删除」。
   **系统响应**：显示**影响面预览**（[设计]，删除前必须让人看见代价）：
   本文件的版本数、派生物数、被引用的 Segment 数、
   **被哪些 Claim / 报告段落引用**、是否处于 legal hold。
   要求二次确认并填写删除原因。

9. **系统处理（级联失效清单，即时 ≤5 分钟）**：
   [设计] 删除一个 `artifact` 必须级联失效**以下全部六类**，缺一即验收不通过：
   | # | 对象 | 失效动作 |
   |---|---|---|
   | ① | **文件浏览器中的条目** | 🔴 **消失**——原件与全部版本、全部派生物均不再出现、不可下载 |
   | ② | **OCR / 转录 / 摘要等派生文件** | 一并进入待删除队列 |
   | ③ | **embedding** | 退出 pgvector 召回 |
   | ④ | **FTS 索引与 Segment** | 退出全文检索召回 |
   | ⑤ | **图边（`ontology_edges`）** | 相关边失效 |
   | ⑥ | **缓存与已构建的 Context Pack** | 失效；后续检索不得再返回其内容 |
   并把引用它的**报告段落标为「证据已撤回」**（D-19：对内可见；
   对外不自动改写，需人工确认后替换）。

10. **系统处理（待删除队列）**：删除对象进入**待删除队列**，
    状态可查（对齐 17-gov/UC-17.2 的五步数据流）；
    合规负责人可查看全部任务、对超时任务有升级权。

11. **系统处理（物理删除，≤30 天）**：删除宽限期（O-01：默认 **30 天**，
    上限受 UC-17.2 的 ≤30 天硬约束）到期后，
    从对象存储**物理删除**原件与派生物的全部版本，出具**删除回执**。
    [设计] 回执至少含：对象标识、哈希、删除时间、执行者、覆盖范围。
    ⚠ 回执的**格式与是否需要可验证签名**属 O-39 未定项，见 R10。

12. **系统收口**：校验 AC1「删除后**文件浏览器里那份真的消失**」——
    这是 file-first 的可演示性契约（架构 2.0 收益第 2 条）。

13. **系统收口**：校验 AC2「六类级联对象**全部可验证失效**」
    （架构第七节首批完成门槛第 4 条）；AC3「两级 SLA 达成」。

### R3.d 保留期与 legal hold

14. **系统处理**：材料到达**保留期**（O-01：材料保留期默认 **180 天**，项目级可覆盖）→
    自动进入待删除队列，走同一条传播路径；到期前给项目负责人可见提醒。

15. **系统处理**：处于 **legal hold** 的对象**豁免于留存期到期删除**，
    且**人工删除请求被拒绝**并说明原因；hold 解除后恢复正常留存计时。
    [设计] legal hold 的施加与解除**只有合规负责人**可操作，全程留痕。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] **版本回滚** = **把旧版内容作为新版本再上传**（新建 v4 内容等同 v2），
    **不是**把 v2 重新置为当前版。理由：与 O-18 对蓝本回滚的裁决同构，
    保留历史线性，与快照不可变一致。
  - A2：[设计] **删除单个版本 vs 删除整个 artifact**——
    默认删除是**整个 artifact 及其全部版本**。删除单个中间版本 → 见 R10 `[待确认]`。
  - A3：[设计] **部分撤回**——受访者只撤回「AI 分析」而不撤回录音时，
    音频**不删**，但其 embedding / Segment 退出检索（对齐 UC-17.2 R7
    「撤回 AI 分析不触发音频删除」）。这说明**级联清单是按撤回项裁剪的**，
    不是无差别全删。
  - A4：[设计] **派生物单独重跑**——不影响原件与其它派生物；
    产生新派生版本，旧派生版本保留可下载（便于对比 OCR 质量改进）。
  - A5：[设计] **删除撤销**——在宽限期内、物理删除执行前，
    合规负责人可撤销删除任务，对象恢复可见。
    [待确认] 是否提供此出口（撤销与「被遗忘权」的承诺可能冲突）。

- **异常流程**：
  - E1：[设计] **删除对象处于 legal hold**——拒绝并明确说明；
    若是受访者撤回触发，必须**如实告知受访者存在法定留存**，
    **不得出具虚假回执**（UC-17.2 R7 原文约束）。
  - E2：[设计] **对象已被导出到组织外**（客户已下载 zip / 已发出的交付物）——
    系统无法回收，**回执中必须如实说明该边界**并列出导出记录
    （来自 17-gov/UC-17.1 审计）。这直接依赖 UC-22.1 的导出留痕。
  - E3：[设计] **级联失效部分失败**（如图边删除成功、缓存未失效）——
    删除任务**不得标为完成**；标为「部分失败」并重试，
    向合规负责人告警。🔴 **半完成的删除比不删更危险**。
  - E4：[设计] **物理删除超过 30 天未完成**——触发升级告警；
    合规负责人可见超时任务列表并有升级权（UC-17.2 R5）。
  - E5：[设计] **对象存储物理删除失败**（存储层错误 / 版本化桶残留）——
    任务保持未完成，持续重试；**不得出具回执**。
    ⚠ 对象存储若开启版本化，物理删除必须删除**所有历史版本与删除标记**，
    否则「删了」是假的。
  - E6：[设计] **删除的对象仍被固定快照引用**——
    快照本身不可删（`uc-0-1`），但其指向的内容已删除时，
    快照必须**显式标为「证据已撤回」**而不是静默 404
    （对齐 D-19 与 O-01「不可删对象是否豁免留存期」的裁决建议）。
  - E7：[设计] **上传新版本时旧版本正在被下载**——旧版本对象不受影响（永不覆盖），
    下载正常完成。

## R5 权限与可见性

- **项目负责人**：可查看版本列表、上传新版本、发起删除（需二次确认 + 填原因）。
- **合规负责人**：可查看**待删除队列**与全部删除任务、施加/解除 **legal hold**、
  查看与补发**回执**、对超时任务升级。**唯一能看到"已从浏览器消失但尚未物理删除"对象的角色。**
- **引导师 / 组长**：可查看其权限范围内文件的版本列表与派生物；
  [待确认] 能否发起删除。
- **组员 / 观察者**：**不可删除**。观察者对版本列表 → 见 R10 `[待确认]`。
- **组织管理员**：不因管理员身份获得删除权（UC-0.3 AC1）；
  其对项目内容的访问写审计且对项目负责人可见（D-18）。
- **硬约束**：删除是**高影响操作**，必须服务端鉴权 + 二次确认 + 全程留痕；
  agent **不得**发起删除（对齐 D-39「AI 只拿行动权、不承担验收」）。
- **硬约束**：`provenance_events` 与审计留痕本身**不可删除**
  （O-39 ②「法定留存清单」的一部分），与被遗忘权的边界见 R10。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 每个 `artifact` 有可查、每版可下载、每版带 SHA-256 的版本线。
  - 每个派生物是独立文件、带 `derived_from`、不覆盖原件。
  - 删除后浏览器中该份消失；六类级联对象 ≤5 分钟内失效；≤30 天物理删除并出回执。
  - [设计验收] AC1：删除后**文件浏览器里那份真的消失**（V4）。
  - [设计验收] AC2：**六类级联对象全部可验证失效**（V5，＝架构门槛第 4 条）。
  - [设计验收] AC3：两级 SLA 达成——逻辑失效 ≤5 分钟、物理删除 ≤30 天并出回执。
  - [设计验收] AC4：**重跑派生不改变原件哈希**（V3）。
- **失败后置条件**：
  - 级联部分失败时任务不标完成、不出回执、告警升级。
  - legal hold 下的删除被拒绝且不产生虚假回执。
- **不包含**：
  - 受访者侧的撤回界面与四项独立同意 → 17-gov/UC-17.2 与 06-itv/UC-6.3。
  - 跨项目级联删除、已发布内容的替换流程、拍板人复核 → 17-gov/UC-17.2（phase-3 增量）。
  - 组织级跨项目审计检索屏 → D-34（后台，phase-3）。
  - 知识五态机中「过期知识转待复核」→ D-33 / 14-brain（知识有效期是另一个参数）。
  - 版本之间的**内容 diff 可视化**（[待确认] 是否需要，见 R10）。

## R7 业务规则（不随具体实现变化的硬性约束）

- 🔴 [设计｜架构 3] **原件写入后永不覆盖**；更新只能通过新 `artifact_version`；
  **旧版仍可下载**。
- 🔴 [设计｜架构 2.0.4] **派生物是独立文件、可见、带 `derived_from` 指回原件版本、
  不覆盖原件**。
- [设计] `derived_from` 指向**具体 `artifact_version_id`**，不是 `artifact_id`；
  引用（Context Pack / 报告来源角标 / 固定快照）同理（D-30）。
- [设计] 每个派生物必须记录**生成它的模型与版本**（架构第三节）。
- 🔴 [设计｜架构 2.0 收益 2] **删除后文件浏览器里那份必须真的消失**。
  这是 file-first 可演示性的核心断言，不是"标记为已删除但还能下载"。
- 🔴 [设计｜架构第七节门槛 4] **删除材料后，其 OCR / embedding / 图边 / 摘要 /
  缓存可验证失效**。六类清单见 R3 第 9 步，**缺一即不合格**。
- [裁决 D-15] **两级 SLA**：逻辑失效**即时（≤5 分钟）**；
  物理删除 **≤30 天并出回执**。**「24 小时」已废弃，不得再出现在实现中。**
- [裁决 O-01] **留存五参数**：材料保留期 **180 天** / 留痕保留期 **180 天** /
  删除宽限期 **30 天**（上限受 UC-17.2 硬约束）/ 知识有效期按资产类型 **6·12·24 个月** /
  审计保留期 **1095 天（3 年）**；**各有默认值且项目级可覆盖**（D-14）；
  **不得硬编码**，一处配置多处消费。
- [裁决 O-01 建议] **不可删对象（快照、绑定关系、审计留痕）不受留存期约束**，
  单独走 O-39 的法定留存清单。
- [设计] **legal hold 豁免于留存期删除，且拒绝人工删除**；
  只有合规负责人可施加/解除，全程留痕。
- 🔴 [设计｜UC-17.2 R7] **不得出具虚假回执**。已导出到组织外的内容无法回收时，
  **回执必须如实说明该边界**并列出导出记录。
- 🔴 [设计] **部分失败的删除不得标为完成**、不得出回执。
- [设计] **删除前必须显示影响面预览**（版本数 / 派生物数 / 被引用 Segment 数 /
  被哪些 Claim 与报告段落引用 / legal hold 状态）。
- [设计] **agent 不得发起删除**。
- [设计] 报告段落的「证据已撤回」标记：**对内可见；对外不自动改写，
  需人工确认后替换**（D-19，含 2026-07-28 措辞修正）。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 版本列表展开 P95 < 300ms（单 artifact 版本数按 50 上限设计）。
  - [设计] **逻辑失效必须在 ≤5 分钟内完成**（D-15），且该时限**可被自动化验证**——
    这是 SLA，不是"尽快"。
  - [设计] 删除任务为持久任务，可重放；重放必须幂等（重复删除不报错）。
- **安全/隐私/合规**：
  - 删除是高影响操作：服务端鉴权 + 二次确认 + 原因 + 全程审计。
  - 对象存储若开启版本化，物理删除必须清除**所有历史版本与删除标记**。
  - 回执不得虚假；已出域内容的边界必须如实说明。
  - 加密密钥策略、法定留存清单、删除证明格式属 **O-39 未定项**（见 R10）。
  - 审计留痕本身不可删（保留期 1095 天）——与被遗忘权的边界见 R10。
- **兼容与降级要求**：
  - 删除 worker 不可用时任务积压不丢失，但**逻辑失效不能等 worker**——
    逻辑失效必须在**同步事务或极短异步**内完成（否则 5 分钟 SLA 无法保证）。
  - 移动端至少可查看版本列表与下载旧版；删除建议限桌面端（防误触）。

## R12 AI Ready 验收线索

- V1（版本不覆盖·可执行）：上传 `a.pdf`（内容 A）→ 再上传同名 `a.pdf`（内容 B）。
  断言 ① `artifact_versions` 有 2 行；② v1 的 `sha256` == hash(A) 且
  `GET /versions/v1/download` 返回 200，响应体哈希 == hash(A)；
  ③ v2 的 `sha256` == hash(B)；④ v1 的对象字节在 v2 上传后**未发生任何变化**
  （对象存储 `ETag` / `LastModified` 不变）。
- V2（幂等）：第三次上传内容 B，断言 `artifact_versions` **仍为 2 行**（不新增）。
- V3（🔴 派生不覆盖原件·可执行）：对一个 PDF 跑 OCR → 记录原件 `sha256` →
  把 `parser_version` 升版后重跑 OCR → 断言
  ① 原件 `sha256` **完全不变**；② `derived_representations` 新增一行而非更新旧行；
  ③ 两个 OCR 派生物**都是可下载的独立文件**且都可见；
  ④ 每个派生物的 `derived_from` 指向**具体 version_id**（不是 artifact_id）；
  ⑤ 每个派生物都带非空的 `generator_model` 与 `generator_version`。
- V4（🔴 删除后浏览器消失·可执行）：删除一个 artifact，等待 ≤5 分钟后断言
  ① `GET /projects/:id/artifacts` 返回中**不含**它（任何版本、任何派生物）；
  ② 对其**每一个** version 的 download URL 调用返回 **404**（与"不存在"同响应）；
  ③ 对其派生物的 download URL 同样返回 404。
- V5（🔴 六类级联可验证失效·可执行·架构门槛 4）：删除前先建立基线——
  记录该 artifact 的 segment_ids、embedding 行数、ontology_edges 条数、
  派生物列表、引用它的 context_pack_ids、引用它的报告段落 ids。
  删除后 ≤5 分钟断言**六项全部成立**：
  ① 浏览器条目消失（同 V4）；
  ② 派生文件进入待删除队列且不可下载；
  ③ `POST /context/search`（向量路径）对其内容**零召回**；
  ④ FTS 路径对其原话**零召回**；
  ⑤ `ontology_edges` 中相关边 `status == invalidated`；
  ⑥ 新建的 Context Pack **不含**其任何 segment，且旧 pack 被标失效。
  外加：引用它的报告段落显示「证据已撤回」。
  **六项任一不成立即失败。**
- V6（两级 SLA·可执行）：删除后打点，断言逻辑失效完成时间戳 −
  删除请求时间戳 **≤ 300 秒**。把删除宽限期临时调为 0，
  断言物理删除执行、对象存储中该 key（含全部历史版本与删除标记）**不存在**、
  且生成回执记录。
- V7（部分失败不完成·可执行）：注入故障让第 ⑤ 项（图边失效）失败，断言
  ① 删除任务状态为「部分失败」而**非**完成；② **未生成回执**；
  ③ 产生告警；④ 重试后可收敛为完成。
- V8（legal hold·可执行）：对某 artifact 施加 legal hold，
  ① 断言人工删除请求被拒绝并返回明确原因；
  ② 把保留期到期时间调到过去，断言**未**进入待删除队列；
  ③ 解除 hold 后再次扫描，断言进入队列。
- V9（回执如实·可执行）：先对某 artifact 执行一次导出（UC-22.1 留痕），
  再删除它。断言回执中**包含**该导出记录（时间、操作者、导出包 ID）
  与「已出域内容无法回收」的说明；断言**不存在**声称"已完全删除"的回执。
- V10（部分撤回·可执行）：受访者撤回「AI 分析」但不撤回录音，断言
  ① 音频原件仍可下载；② 其 embedding 与 Segment 退出检索（③④ 项失效）；
  ③ 音频文件本身**未**进入待删除队列。
- V11（留存参数单点·可执行）：把项目级「材料保留期」从 180 改为 30，
  断言 ① 该项目材料在第 31 天进入待删除队列；
  ② 其它项目仍按 180；③ 代码中 `grep -r "180"` **不出现在留存判定逻辑里**
  （参数从配置读取，非硬编码）。
- V12（快照悬空·可执行）：删除一个被固定快照引用的 artifact，
  断言快照本身仍存在，但其引用项被标为「证据已撤回」，
  **不是**静默 404 或空白。
- V13（权限态）：以组员、观察者会话调用删除接口返回 403；
  以 agent 身份调用删除接口返回 403；断言待删除队列仅合规负责人可读。
- V14（审计态）：一次删除产生的事件（发起、级联失效、物理删除、回执）
  均可按操作者、时间、对象三个维度检索到。
