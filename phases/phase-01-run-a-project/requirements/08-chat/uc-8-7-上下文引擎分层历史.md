> **[人类已签核 2026-08-11 · chat-context-engine 束]** 参数逐字为硬边界，不得优化：
> 分层历史 **L1 最近 ~15 轮原文 + L2 持久化滚动摘要（每轮增量更新，不重读全史）+ L3 检索**；

> **边界**：`ModelCallPort` 契约不动（coord-main 裁决 A 条件）；V8 已合入部分（#913/#915 滚动摘要+观测）不在本 UC 重复实现，本 UC 是 L2 持久化 + L3 接线 + 快照表。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-8.7 / 对话上下文引擎 · 分层历史
- **Actor**：系统（agent run 组装层，`execute-run.ts` 端口内侧）；间接受益者为对话参与者。
- **目标**：打破 `HISTORY_MAX_MESSAGES=20` 造成的「第 20 轮以前对模型直接不存在」；用三层历史（L1 近端原文 / L2 持久滚动摘要 / L3 检索召回）让长对话「记得前几轮」，并让「这次到底喂了什么」可审计；个人对话零召回不伪造。
- **本用例结果**：一次 run 组装出的 `ModelCallInput.history` = L1 原文 + L2 摘要伪消息 + L3 检索伪消息，全部仍是 `role+content`（`ModelCallInput`/`ModelCallPort` 一字节不改）；喂入结构落 `agent_run_context` 快照。
- **系统边界**：`ContextAssemblyPort`（端口内侧，V8 已引入）；新表 `thread_context_state`（L2 持久增量摘要）；L3 = context-pack/retrieval 引擎接线；新表/列 `agent_run_context`（快照）。
- **核心数据对象**：线程历史消息、`thread_context_state`（thread_id / org_id / summary 文本 / covered_up_to / updated_at）、Context Pack（items/claims/omissions、segmentId/anchor）、`agent_run_context`（run_id / 喂入结构 jsonb）。

## R2 前置条件 / 触发条件

- **前置条件**：一次 agent run 已 claim；system/user 已定、原始历史已按行数上限取回；已配置 `ModelCallPort`（摘要调用复用它）；context-pack/retrieval 引擎已存在（有 domain/测试，缺调用方）。
- **触发条件**：`execute-run.ts` 在「history 已取、调 model 之前」的窗口调用 `ContextAssemblyPort.assemble`。

## R3 主流程（编号步骤）

1. **系统处理（L1 近端原文）**：取最近 ~15–20 条原文逐字保留（`readThreadHistory` 行数上限可配，但**不撑大** L1——更旧的不再整条丢，交给 L2）。
2. **系统处理（L2 持久滚动摘要）**：读 `thread_context_state` 中该线程已有的滚动摘要（覆盖到 `covered_up_to`）；对 L1 边界之前、尚未纳入摘要的更旧轮，**增量**喂给摘要调用（复用 `ModelCallPort.complete`）压成要点，**沿时间轴前推更新**摘要，写回 `thread_context_state`（不重读全史）。摘要作为一条约定前缀的伪历史消息注入。
3. **系统处理（L3 检索召回）**：以本轮 `inputText` 为 query，在**当前线程所属项目**范围内经 context-pack 引擎召回可引用片段（五路召回、权限约束），作为一段「检索上下文」伪消息注入。**个人对话（无项目）→ 不发起任何检索请求（零召回）**。
4. **系统处理（预算合并）**：三层按预算合并为 `history: ThreadHistoryMessage[]`，控制在预算内；产出 `summarizedTurns` 等观测。
5. **系统处理（快照）**：把本次实际喂入结构（L1 轮数 / L2 摘要覆盖边界 / L3 召回条数与来源 / token 估值）写入 `agent_run_context`（或 step jsonb 列），可审计。
6. **系统响应**：`ModelCallInput.history` = 合并结果，交给 `ModelCallPort`（契约不动）。

## R4 备选流程与异常流程

- **备选**：A1（个人对话）无项目 → 跳过 L3，`agent_run_context` 记录 `retrieval_requests = 0`（真栈反证：无项目 ⇒ 零检索请求）。
- **异常**：
  - E1（摘要失败）L2 摘要调用失败**不 fail run**，降级为现有「整条丢旧轮」保守行为，快照记录降级。
  - E2（检索失败）L3 召回失败不 fail run，降级为仅 L1+L2，快照记录降级。
  - E3（权限）L3 检索必须把当前 actor 可见范围传入（context-pack 本身权限约束）；越权范围不得被召回。

## R5 权限与可见性

- L3 检索复用 context-pack 引擎的权限约束检索：只召回当前 actor 在当前项目可见范围内的片段。
- 个人对话无项目上下文 ⇒ 零召回，不伪造项目知识（与 P 组「无项目上下文如实呈现」一致）。
- `agent_run_context` 快照按 run 归属组织隔离。

## R6 后置条件 / 不包含

- **正常后置**：`thread_context_state` 滚动摘要随对话前推更新；每次 run 有 `agent_run_context` 快照；长对话在第 20 轮以后仍能「记得前几轮」（经 L2 摘要 / L3 召回）。
- **不包含**：
  - 改 `ModelCallPort` 契约（裁决 A 条件，不动）。
  - 重写 context-pack/retrieval 引擎（只接线）。
  - V8 已合入的滚动摘要+观测本体（#913/#915，不重复实现；本 UC 是**持久化** L2 + L3 接线 + 快照表）。
  - 真实 tokenizer 选型（token 预算沿用 V8 的 `TokenEstimatorPort` 默认保守估算）。

## R7 业务规则（逐条来自 signoff，不得优化）

- [已签核] **分层历史 = L1 最近 ~15 轮原文 + L2 持久化滚动摘要（每轮增量更新，不重读全史）+ L3 检索**。
- [已签核] **`HISTORY_MAX_MESSAGES` 不撑大行数上限**：L1 保持 ~15–20 条原文，更旧交 L2 滚动摘要（省成本）。打破「第 20 轮以前对模型不存在」靠 L2/L3，**不是**把行数上限调到很大。
- [已签核] **L2 载体 = 新表 `thread_context_state`**，run 时**直读**已有摘要，只对新增区间增量更新，不每轮重读全史重算。
- [已签核] **L3 复用既有 context-pack/retrieval 引擎**（五路召回、权限约束），接线不重写。
- [已签核] **个人对话零召回**：无项目 ⇒ 不发起检索请求；须有真栈反证（`retrieval_requests == 0`）。
- [已签核] **可审计快照 `agent_run_context`**：记录本次实际喂入结构。
- [设计] **输出仍是 `ThreadHistoryMessage[]`（role+content）**，`ModelCallInput`/`ModelCallPort` 不改；摘要/检索以伪历史消息注入。
- [设计] 摘要/检索失败**降级不 fail run**（保守失败模式）。

## R8 界面线索

- 本 UC 无独立界面（端口内侧组装）。可观测出口：`agent_run_context` 快照可被审计视图读取（「这次到底喂了什么」），`summarizedTurns`/召回条数进 `agent_run_steps` digest。

## R9 非功能约束

- [设计] L2 增量摘要避免每轮重算全史（成本控制，直读 `thread_context_state`）。
- [设计] 提高 L1 行数上限会连带提高 SQL 取回量与组装成本，要与预算/摘要一起调，不能只改行数。

## R10 已知约束 / 依赖

- **内部依赖**：V8 的 `ContextAssemblyPort` + 摘要能力（#913/#915 已合入）；context-pack/retrieval 引擎（`application/context-pack/*`、`application/retrieval/*`、契约 `contracts/context-pack.ts`）；`execute-run.ts`（热点，动它前取 coord-main 串行窗口）。
- **跨束依赖**：`chat-file-upload` 束 V9-b（`uc-8-6` R11 ④）——文件抽取文本进的就是本 UC 的 L3 层，文件是 context engine 第一个大客户。
- **契约**：`thread_context_state` migration + `agent_run_context` migration/列 + context-pack 调用契约（跨域接线）→ 已在束级 `design-signoff.md` 签核。
- **边界**：`ModelCallPort` 不动（裁决 A）。

## R11 切分提示（给 requirement-author）

- **建议切法**：① 分层历史 L1/L2 打破 20 硬上限 + `thread_context_state` 持久滚动摘要（新表 + 增量更新 + run 时直读）→ ② L3 context-pack 接线进 chat（`ContextAssemblyPort` 内侧调引擎、权限约束、注入伪消息、`ModelCallPort` 不动）→ ③ 个人对话零召回（真栈反证）→ ④ 可审计快照 `agent_run_context`（记录喂入结构）。
- **不重复实现**：V8 滚动摘要本体已合入，本 UC 做**持久化**与**分层组装**；context-pack 引擎只接线不重写。
- **优先级/依赖**：P1；共 10 点；② 依赖 ①（L2 摘要能力就位）；`uc-8-6` 的 V9-b feature 依赖 ②（L3 接线）。

## R12 AI Ready 验收线索

以下行为应可由 API 层自动化测试断言。

- **V1（打破 20 硬上限 · L1+L2）**：构造一条 30+ 轮线程，第 5 轮埋一个可检出事实（如某代号）→ 组装后的 `ModelCallInput.history` 中，第 5 轮虽超出 L1 近端窗口，其要点仍经 L2 摘要伪消息可检出（该事实不因超过第 20 轮而消失）。
- **V2（L2 增量不重读全史）**：连续两轮 run，断言第二轮的摘要调用输入**只含新增区间**（`covered_up_to` 前推），未把全史重新喂给摘要调用；`thread_context_state` 该线程行被更新而非重建。
- **V3（L3 接线 · 权限约束）**：对属于某项目的线程发问 → context-pack 引擎被调用一次，召回片段作为伪消息进 history；传入的可见范围 == 当前 actor 范围，越权片段不出现。
- **V4（个人对话零召回 · 真栈反证）**：个人对话（无项目）run → context-pack/retrieval 引擎**零调用**，`agent_run_context.retrieval_requests == 0`；history 不含任何检索伪消息。
- **V5（快照可审计）**：一次 run 后 `agent_run_context`（或 step jsonb 列）存在一行，含 L1 轮数 / L2 摘要覆盖边界 / L3 召回条数 / token 估值四项，可据 run_id 检索。
- **V6（降级不 fail run）**：注入摘要调用失败 → run 不失败，降级为整条丢旧轮，快照记录降级；注入检索失败 → run 不失败，降级为仅 L1+L2。
- **V7（`ModelCallPort` 不动）**：契约层断言 `ModelCallPort` 的 `complete`/`completeStream`/`completeWithProgress`/`supportsProgress` 签名与语义未变；组装输出类型仍为 `ThreadHistoryMessage[]`（role+content）。
