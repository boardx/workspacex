# 原始需求（细化）— UC-8.5 对话可见性规则

> 所属：阶段一 · 能跑完一场项目 / M8 Chat  
> 来源：`Backlog Use Case.html` 的 UC-8.5；UI 线索来自 `WorkspaceX Standalone.html`
> **项目工作台的「视角切换：引导师 ｜ 组长 ｜ 组员 ｜ 观察者」四视角**——
> 这是本 UC 的完整原型（每个视角带状态标、权限说明原文与独有按钮）。  

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **3**；建议迭代 **迭代 2 · 能挂能力**。
>
> **[人类已拍板 2026-07-27 · D-12 / uc-0-3]** 角色模型统一为**两层正交**：
> **组织角色**（管理员 / 项目负责人 / 顾问 + 团队）× **项目角色**（引导师 / 组长 / 组员 / 观察者）。
> 原文档的「**项目经理**」＝组织角色「**项目负责人**」，**不是项目角色**，本文已逐处正名。
> **观察者是一等项目角色，留在 phase-1**——原型四视角完整，权限语义齐备。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-8.5 / 对话可见性规则
- **Actor**：**引导师**、**组长**、**组员**、**观察者**（四个**项目角色**，
  取值与 `00-core/uc-0-3` 一致）
- **目标**：[原型] 任何一条对话被读取时，系统都能按**两层角色的交集**判定可见范围，
  并能解释「为什么允许 / 为什么拒绝」。
- **本用例结果**：每条对话都有明确的可见范围，且该范围**由服务端强制**，不依赖界面隐藏。
- **系统边界**：对话的可见范围字段、两层交集判定、四视角投影、观察者只读降级、
  跨组不可见规则、可见范围的界面呈现。
- **核心数据对象**：对话、消息、**可见范围**（组员私聊 / 本组共享 / 全场 / 团队可见 / 私有）、
  组织角色 + 团队、项目角色 + 组号、权限判定记录。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“上传 Skill、上传 Agent、登录管理”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] 任何对话被读取。
  - 系统从 **全局** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **系统处理（第一层：组织层）**：解析请求者的**组织角色**（管理员 / 项目负责人 / 顾问）
   与**团队归属**。[原型 · uc-0-3] 组织层决定「**能不能用这个资源**」；
   **管理员不是超级用户**——在他没有项目角色的项目里，不因管理员身份获得对话读取权。
2. **系统处理（第二层：项目层）**：解析请求者在**目标项目**中的**项目角色**
   （引导师 / 组长 / 组员 / 观察者）与**组号**。项目层决定「**在这场项目里能看到哪些内容、
   做哪些动作**」。
3. **系统处理（解析对话的可见范围）**：
   - [原型] **组员私聊**：本人 + 组长 + 引导师。
   - [原型] **本组共享**：全组可见。
   - [原型] **研究阶段**：`团队可见` / `私有` 两档。
4. **系统处理（取交集判定）**：两层任一不通过即拒绝；拒绝时**不泄露资源是否存在**，
   并记录判定所依据的两层角色与可见范围，供审计与「为什么被拒」解释使用。
5. **系统响应（四视角投影，[原型] 项目工作台「视角切换」）**：同一份数据按四个视角投影出四种界面。
   下表**权限说明列为原型原文**：

   | 视角 | 状态标 | 权限说明（原型原文） | 该视角独有按钮 |
   |---|---|---|---|
   | **引导师** | 可发言 | 同一个界面，你有全部权限：四组对话、原始转写、切环节与介入。 | （全部） |
   | **组长** | 可发言 | **你能看第 2 组的全部对话与组员私聊，能提交本组产出；别组内容与全场控制不可见。** | `向引导师举手` `提交本组产出` |
   | **组员** | 可发言 | **你能看第 2 组的共享内容与自己的对话；别组内容、组员私聊与全场控制不可见。** | `举手` |
   | **观察者** | **只读** | **只读：已发布产出与脱敏聚合可见；原始转写、私聊与任何操作按钮都关掉了。** | （无） |

6. **系统响应（观察者降级）**：[原型] 观察者视角下**任何操作按钮都关掉了**——
   UC-8.2 的输入区、批准卡、`[改派]`、`[全屏编辑]`、`[停止录音]` 等**不渲染**（不是禁用）；
   原始转写与私聊**不返回**（服务端不下发，不是前端过滤）。
7. **系统收口**：校验 AC1「每条对话都明确标出可见范围」、
   AC2「跨组一律不可见，引导师除外」、AC3「观察者只读且操作按钮不渲染」；
   满足后记录操作者、时间、对象、结果与来源，并刷新相关列表、图谱、看板或通知状态。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] 跨组一律不可见，引导师除外（[原型] 组长「能看第 2 组的全部对话与组员私聊」）。系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
- **异常流程**：
  - E1：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

### 第一层 · 组织角色（[原型 · uc-0-3]）

| 角色 | 在对话上的能力 |
|---|---|
| **管理员** | **[已裁决 O-04（原 D4）]** 原问题：早期稿本写「对话内容**一律不可读**」，但 proto-03 原文相反：「个人层·只有计数」「**项目层·可读但留痕**」。约束强度被稿本反向改写。<br>**裁决（O-04）**：**按 D-18 落地——项目层可读、必留痕、对项目负责人可见；且不区分管理员是否持有该项目角色**。理由：D-18 已定方向、原型有明文；「一律不可读」是稿本单方收紧，**撤回**。若加「须有项目角色」的限制，组织级审计屏（D-34）将无法工作。<br>**个人层仍只见条目计数、内容不可见**（这一条不变）。<br>→ 越权断言随之改写：管理员读项目层对话应**断言返回内容 + 一条审计事件**，**不是** 403。 |
| **项目负责人**（＝原文档所称「项目经理」） | 可查看项目级状态与审计摘要；**内容读取仍需项目角色**；是否可代替业务 Actor 执行写操作需显式授权 |
| **顾问** | 参与项目、使用被授权能力；内容读取由项目角色决定 |

> **[口径更正]** 原文档的「**项目经理**」是**组织角色**，本文统一改称「**项目负责人**」，
> 避免与项目角色同层混用。

### 第二层 · 项目角色（[原型] 四视角，权限说明为原型原文）

| 角色 | 状态标 | 能看什么 / 不能看什么（原型原文） |
|---|---|---|
| **引导师** | 可发言 | 同一个界面，你有全部权限：四组对话、原始转写、切环节与介入 |
| **组长** | 可发言 | 你能看第 2 组的**全部对话与组员私聊**，能提交本组产出；**别组内容与全场控制不可见** |
| **组员** | 可发言 | 你能看第 2 组的**共享内容与自己的对话**；**别组内容、组员私聊与全场控制不可见** |
| **观察者** | **只读** | **只读：已发布产出与脱敏聚合可见；原始转写、私聊与任何操作按钮都关掉了** |

- **外部受访者**：不持项目角色，走一次性令牌身份（UC-6.3），不可读取任何对话。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。
- [原型 · uc-0-3] **观察者的单独授权**（如「授予客户方王毅『观察者』＋ 第 2 组原始内容临时读权」）
  必须**留痕**，且原型多给了一条：**环节结束自动失效**。

  - [原型验收] AC3：观察者只读——原始转写、私聊与任何操作按钮都不下发、不渲染。

  - 第三方 IM 同步、未授权跨组读取。
  - **自定义角色与细粒度权限编辑器**（`uc-0-3` R6：原型无此屏，属 phase-3）。
  - **另立一套角色枚举**——本 UC 的两层角色取值全部来自 `00-core/uc-0-3`，不得增删。
  - 不扩展到本 use case 未声明的跨组织、跨客户或公开发布能力。

## R7 业务规则（不随具体实现变化的硬性约束）

### 两层正交（[原型 · uc-0-3]）

- **组织角色决定资源准入，项目角色决定内容可见与动作许可，任一不通过即拒绝。**
- **[已裁决 O-04（原 D4）]** 「管理员不是超级用户 → 无项目角色即一律被拒」这一条
  **已撤回**。按 D-18 落地：**管理员对项目层对话内容可读、必留痕、对项目负责人可见，
  且不区分其是否持有该项目角色**（管理员的审计权本就是跨项目的）。
  [原型] 无争议的部分保留：审计目的访问**必然留痕且对项目负责人可见**。
- **个人层对管理员封闭**：只能看到条目**计数**，内容不可见。**这一条不变。**

### agent 私聊的归属层（**[已裁决 O-24]**）

- **agent 私聊正文归 `项目层`，不是个人层。**
  理由：私聊内容一旦被 `[转出到主线程]` 就成为**项目产出的来源**；
  若归个人层，会出现「项目产出的来源在个人层、管理员与项目负责人都查不到」的**审计断链**，
  与 D-18 的项目层可审计原则冲突。
- **随之而来的三条代价与约束（缺一不可）**：
  1. **私聊入口须明示**「**本对话属于本项目，可被审计**」——不能让人以为它是个人空间；
  2. **组员默认不可私聊**，由**引导师逐场开关**；
  3. **私聊不改变 agent 编制**——不计入线程的 agent 在场态。
- 归属项目层意味着：适用**项目层的留存策略**（`材料保留期`，O-01 默认 180 天，读参数不硬编码），
  且管理员按上条 O-04 可读、必留痕。详见 `04-agent/uc-4-3`。

### 对话可见范围（[原型]）

- **组员私聊**：本人 + 组长 + 引导师。**组长能看本组组员私聊**（原型原文），
  这是与「私聊」字面直觉不同的关键点，必须显式实现且在界面上让组员知情。
- **本组共享**：全组可见。
- **研究阶段**：`团队可见` / `私有` 两档。
- **跨组一律不可见，引导师除外。**
- **观察者只读**：已发布产出与脱敏聚合可见；**原始转写、私聊与任何操作按钮都关掉了**——
  服务端不下发，前端不渲染，两道都要做。
- [设计] 观察者的**单独授权**必须留痕，且**环节结束自动失效**（原型行为）。

### 判定与解释

- [设计] **拒绝不得泄露资源存在性**；同时系统内部须记录判定依据（组织角色 / 项目角色 /
  可见范围三项），供审计与「为什么被拒」解释使用。
- AC1（[设计]）：界面上每条对话都明确标出可见范围（**原型未见徽标，需补设计**）。
- AC2：跨组一律不可见，引导师除外。
- AC3：观察者只读，操作按钮不下发不渲染。
- AC4：拒绝原因可区分组织层 / 项目层。
- **AC5（[已裁决 O-04]）**：管理员读项目层对话内容**返回内容**（不是 403），
  同时**必然产生一条审计事件且对项目负责人可见**；读个人层只返回**计数**、不返回内容。
- **AC6（[已裁决 O-24]）**：agent 私聊按**项目层**判权与留存；
  私聊入口显示「本对话属于本项目，可被审计」；组员默认不可私聊（引导师逐场开关）；
  私聊**不计入 agent 在场态**。

### 存储形态与上下文获取（[设计]，Context Engine）

- **[设计] file-first**：对话物化为 **`messages.jsonl`**，
  **以会话为文件粒度**——不是每条消息一个文件（架构第 2.0 节：高频小对象不单独成文件）。
  **Segment 仍精确到消息，靠 anchor（`messageId`）定位**。
  文件在 **22-files** 项目文件浏览器中可见、可下载，
  **可见性沿用同一套 `acl_bindings`**——文件浏览器**不是权限旁路**，
  本文全部可见性规则对文件下载同样生效（尤其组员私聊与观察者只读两条）。
- **[设计] 权限传播**：Artifact 权限必须**传播到 Segment、embedding、图节点、缓存和 Context Pack**；
  **交集生成内容取所有来源权限的最严格结果**——避免摘要造成越权信息洗白。
- **[设计] Context API**：任何 AI 读对话内容**只能通过 Context API 取 Context Pack**，
  **不得绕过直查** `segments` / 向量库 / 对象存储；
  租户与项目隔离**在 SQL/RLS 层强制**，不能只靠 Context API 的代码过滤
  （⚠ 数据库连接不得使用表 owner 身份，否则 RLS 形同虚设）。
  Pack item 的 `permissionDecisionId` 让「为什么这条能给你看」可回溯。

- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R8 界面线索

- **前端入口**：[原型] **项目工作台顶部的「视角切换：引导师 ｜ 组长 ｜ 组员 ｜ 观察者」**
  是本 UC 的完整原型；对话侧全局生效。
- **信息架构**：[原型] 对话卡片、全屏线程、上下文 / 参与者抽屉与右侧执行栏。
- **推荐交互**：
  - [原型] 视角切换条常驻顶部，每个视角带**状态标**（`可发言` / `只读`）与**一句话权限说明**，
    并只渲染该视角的独有按钮（组长 `向引导师举手` `提交本组产出`；组员 `举手`；观察者无）。
  - [设计 · 承接 `uc-0-3`] 顶部角色说明条需同时显示**两层身份**，
    形如「顾问 · 能源组 ｜ 本项目：组长 · 第 2 组」。
  - [设计] 被拒绝时给出**可理解的原因**（是组织层还是项目层限制），不要只显示「无权限」。
  - **[设计 · 待补原型] 可见范围徽标**：AC1 要求「每条对话都明确标出可见范围」，

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R11 切分提示（给 requirement-author）

- 建议先拆“领域数据与权限 → 主流程服务 → 页面与状态 → 跨模块回流 → 审计/通知 → 自动化验收”。
- 单个 feature 应能在一次会话内实现并验证，不应把本 use case 的全部前后端与所有异常态塞进一个 feature。
- **建议切法（本 UC）**：① 对话可见范围字段与取值枚举 → ② 两层交集判定在对话侧的接线
  （调用 `uc-0-3` 中间件，不自建）→ ③ 四视角投影与观察者降级（**服务端不下发 + 前端不渲染**）→
  ④ 可见范围徽标（**依赖补原型**）→ ⑤ 验收。
- **③ 必须独立成 feature**：观察者降级是「服务端不下发」而非「前端隐藏」，验收方式与其余不同。
- **优先级 / 先后依赖**：P0；3 点；迭代 2 · 能挂能力；
  **必须在 `00-core/uc-0-3` 之后**，且**先于 UC-8.1 / 8.2 / 8.3 / 8.4 的权限态验收**。
- 对 P0 必做链路优先实现成功态、权限态与数据闭环，异常态不得延期到上线后。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证。
**[D-35] 全部权限断言在 API 层**——「前端隐藏」不构成通过。

- **V1（AC2 · 跨组不可见）**：第 2 组组员/组长请求第 3 组的对话 —— 拒绝且**不泄露其是否存在**；
  引导师请求同一对话 —— 成功。
- **V2（组员私聊三方可见）**：组员 A 的私聊，A 本人 / 本组组长 / 引导师三方均可读；
  同组组员 B 与观察者不可读。
- **V3（AC3 · 观察者降级 · 服务端）**：以观察者身份请求线程详情 —— 响应体中
  **不存在**原始转写字段、不存在私聊消息、不存在任何写操作能力标记
  （输入区 / 批准卡 / `[改派]` / `[全屏编辑]` / `[停止录音]`）；
  直接调用这些写接口全部拒绝。
- **V4（管理员审计读权 · [已裁决 O-04]）**：组织管理员在其**无项目角色**的项目里
  请求**项目层**对话内容 —— **成功返回内容**（**不是 403**），
  同时断言 ① 产生一条审计事件；② 项目负责人能查询到该事件；
  ③ 请求**个人层**内容时**只返回计数、不返回正文**。
  ⚠ 早期稿本的「无项目角色即拒绝」断言**作废**，不得据此写测试。
- **V4b（agent 私聊归属 · [已裁决 O-24]）**：
  ① 断言 agent 私聊记录的归属层字段为 **`project`**（不是 `personal`）；
  ② 管理员按 V4 可读其正文并留痕；
  ③ 私聊入口响应体/界面含「本对话属于本项目，可被审计」的告知文案；
  ④ 以**组员**身份发起私聊**默认被拒**，引导师打开本场开关后放行；
  ⑤ 发起私聊后线程的 **agent 在场态计数不变**；
  ⑥ `[转出到主线程]` 后该内容作为项目产出来源**可被审计检索到**（无断链）。
- **V5（AC4 · 拒绝可解释）**：分别构造组织层拒绝（资源标「仅能源组」而用户不在该团队）
  与项目层拒绝（无项目角色）—— 两次拒绝的内部判定记录中 `denied_layer` 分别为
  `organization` 与 `project`。
- **V6（研究阶段两档）**：`私有` 对话仅创建者可读；`团队可见` 对同团队成员可读、对其他团队不可读。
- **V7（单独授权与自动失效）**：给观察者授予「第 2 组原始内容临时读权」—— 授权期间可读且**留痕**；
  **环节结束后同一请求被拒绝**（自动失效）。
- **V8（AC1 · 徽标态 · 依赖补原型）**：列表与线程详情接口对每条对话返回
  `visibility_scope` 字段且取值在枚举内；界面徽标断言**待补原型后再定 `data-testid`**。
- V9（空态）：无可见对话时显示真实空态而非空列表伪装，不泄露存在但不可见的条目数。
- V10（依赖失败）：**鉴权服务不可用时一律拒绝，不得降级为放行**（承接 `uc-0-3` R9）。
- V11（并发态）：操作过程中项目角色被撤回，后续读写立即失败，已完成步骤保留审计。
- V12（审计态）：越权尝试、观察者单独授权、管理员审计访问三类事件均可按操作者、时间、对象检索。
- **V13（架构态 · [设计] file-first + 权限不旁路）**：
  ① 断言每个会话在对象存储中有**一个 `messages.jsonl`**（不是每条消息一个文件），
     且 Segment 的 anchor 为 `messageId`；
  ② 在 **22-files** 中以各角色访问该文件：组员**取不到**别组会话与他人私聊的 `messages.jsonl`、
     观察者取不到原始转写与私聊文件 —— 证明文件浏览器**不是权限旁路**；
  ③ 管理员按 O-04 可下载项目层文件，但**产生审计事件**。
- **V14（架构态 · [设计] Context API + RLS）**：
  ① 静态检查 AI 读对话路径中不存在对 `segments`/向量库/对象存储的直连查询；
  ② **跨 tenant / 项目泄漏测试为零**（架构首批门槛②）；
  ③ 断言应用数据库连接**不是表 owner 角色**（否则 RLS 失效）；
  ④ 由多来源摘要生成的内容，其可见性取**所有来源中最严格**的结果（防信息洗白）。
