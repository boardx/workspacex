## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-8.1 / 对话卡片列表
- **Actor**：**引导师**、**组长**、**组员**、**观察者**
- **目标**：[原型] 所有干活都发生在对话里：卡片列表管理线程，全屏窗口做事，挂载 skill、看工具调用、按角色控制可见性。
- **本用例结果**：[Backlog] 用户通过“对话卡片列表”完成从“进入研究洞察 → 对话，或某组 → 与 AI 的对话”到可追踪业务结果的闭环。
- **系统边界**：对话列表、全屏对话、参与者与上下文配置、产出落地、可见性。
- **核心数据对象**：对话、消息、参与者、上下文引用、可见范围、产出、来源。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“上传 Skill、上传 Agent、登录管理”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] 进入研究洞察 → 对话，或某组 → 与 AI 的对话。
  - 系统从 **对话卡片列表** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **用户操作**：打开对话列表。**系统响应**：[原型] 线程按**时间分组**呈现（档案原文：「线程列表（**今天 / 本周** 分组）」——
   **只有这两组**，早期稿本多写的「更早」在档案中 0 命中，已删除；更久线程的归组方式
   属 **[设计]**，需产品定义），
   每张线程卡显示：标题（含副标题，如「欧洲储能进入策略 · 假设梳理」）、
   **状态徽标**、**参与 agent 摘要**、**最后活动**。原型实测四类卡形态：
   - `欧洲储能进入策略 · 假设梳理`　**● 转录中**　`4 个 agent`
   - `德国工商储电价机制核查`　　`Scout · 14:02`　**`3 条待复核`**
   - `客户访谈 07 · 采购总监`　　`Echo · 11:20 · 已归档`
   - `竞品拆解：Sungrow / BYD 欧洲布局`　`周三`（仅时间，无进行中状态）
2. **用户操作**：[原型] 新建、改名、删除线程。**系统响应**：校验权限与命名；删除为可追溯动作，
   记审计并显示影响范围。
3. **用户操作**：按筛选条收窄（[原型] 移动端筛选：`全部` / `远洋项目` / `我的 AI 团队`）。
   **系统响应**：按当前项目上下文与可见范围过滤——**过滤规则本身定义在 UC-8.5**，
   本 UC 只负责调用其判定结果，不重复定义角色语义。
4. **系统收口**：校验 AC1「同一套列表在研究阶段与现场分组下用同一交互」与
   AC2「每张线程卡的状态徽标与其真实运行态一致」；满足后记录操作者、时间、对象、结果与来源，
   并刷新相关列表、图谱、看板或通知状态。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] 观察者只看已共享的，且无新建与删除（[原型] 观察者视角下操作按钮**不渲染**，不是禁用）。系统不得丢失当前上下文，且需提示用户当前采用了哪条替代路径。
- **异常流程**：
  - E1：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E2：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E3：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R5 权限与可见性

- **引导师**：可发起、查看并管理本 use case，范围限定在其有权访问的组织、项目或小组。
- **组长**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **组员**：可在被授权范围内参与流程并查看与自身角色相关的结果。
- **观察者**：默认只读已发布且已脱敏内容；不能输入、控制全场、读取私聊或原始转写，单独授权除外且必须留痕。
- **项目负责人**（**组织角色**；原文档所称「项目经理」，按 `00-core/uc-0-3` 正名）：
  可查看项目级状态与审计摘要；**内容读取仍需其持有项目角色**；是否可代替业务 Actor
  执行写操作需由角色模板显式授权。
- **未登录、链接失效或未列出的角色**：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。
- **[口径统一]** 本模块四个角色的完整语义与两层（组织 × 项目）交集判定见 **UC-8.5**
  与 `00-core/uc-0-3`；本 UC 只调用其判定结果，不重复定义。

## R7 业务规则（不随具体实现变化的硬性约束）

- [原型] 观察者只看已共享的，且无新建与删除（完整角色语义见 **UC-8.5**，本 UC 不重复定义）。
- [原型] **线程卡徽标是一等取值，不得自造**：
  - **运行态**：`● 转录中`（与录音/转录服务的真实状态绑定，不得只按最后消息时间推断）；
  - **待办态**：`N 条待复核`（与 UC-8.2 消息头的「待复核 N」同源同值）；
  - **归档态**：`已归档`（归档线程只读，不出现在默认筛选里）；
  - **参与摘要**：`N 个 agent` 或 `最近发言 agent · 时间`。
- [设计] **同一套列表在两种场景下复用**：研究阶段与现场分组只换数据源与筛选条，
  **交互与卡片结构不得分叉**。
- **[设计]（Context Engine · file-first）** 每个线程都有一份**可下载的证据文件**：
  **`messages.jsonl`，以会话/线程为文件粒度**（高频小对象不单独成文件，架构第 2.0 节）；
  Segment 精确到消息、靠 **`messageId` anchor** 定位。
  列表每一行应能跳到 **22-files** 中该线程的文件；
  可见性沿用同一套 `acl_bindings`——**文件浏览器不是权限旁路**（见 UC-8.5）。
- **[设计]（Context Engine · 服务平面）** 列表的语义搜索/相似线程推荐若用 AI，
  **只能通过 Context API 取 Context Pack**，不得直查 `segments` / 向量库；
  租户与项目隔离**在 SQL/RLS 层强制**，不能只靠应用层过滤。
- **[已裁决 O-24]** agent **私聊线程归项目层**：出现在列表中时须标明「属本项目、可被审计」；
  **组员默认不可私聊**（引导师逐场开关）；**私聊不计入卡片上的 `N 个 agent` 在场态计数**。
- **[已裁决 O-01]** 归档与到期删除读 `材料保留期`（默认 180 天）等五参数，**不硬编码**。
- AC1：同一套列表在研究阶段与现场分组下用同一交互。
- AC2：线程卡徽标与真实运行态一致（转录中 / 待复核数 / 已归档）。
- **AC3（[设计]）**：每个线程在 22-files 中有一个 `messages.jsonl`（不是每条消息一个文件），
  可见可下载且按 UC-8.5 的可见性规则判权。
- **AC4（[已裁决 O-24]）**：私聊线程的归属层为 `project`，且不改变 agent 在场态计数。
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- AI/Agent 的写回、覆盖、发布或高影响工具调用必须遵守原型中的批准点；未经确认只保留为草稿或候选。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 普通读取与本地校验应在 1 秒内给出可感知反馈；超过 1 秒显示加载状态，超过 10 秒的任务转为可离开页面的后台任务。
  - [设计] 列表、图谱、转写和审计记录必须分页或增量加载，禁止一次加载整个项目历史。
- **安全/隐私/合规**：
  - 最小权限、组织/项目/小组隔离、传输与静态加密、敏感字段脱敏、导出与 AI 读取留痕。
  - 原始材料、录音、转写、私聊、个人身份与客户数据按授权和留存策略处理。
- **兼容与降级要求**：
  - 响应式 Web；桌面端提供完整能力，移动端保证加入、查看、输入、投票/确认等现场关键动作。
  - WebSocket/实时通道不可用时降级为轮询并显示“非实时”；断网允许保留未提交输入，但不得伪装已同步。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证。
**[D-35] 逻辑层优先用接口断言**，UI 层按统一 `data-testid` 命名规范补 E2E。

- V1（成功态）：AC1 —— 研究阶段与现场分组两个入口调用同一列表接口，
  返回的卡片字段结构完全一致（只有数据不同）。
- **V2（成功态 · AC2 · 徽标同源）**：把一条线程的转录服务置为运行中 → 列表接口返回
  `status = 转录中`；停止转录后徽标消失。线程的 `待复核数` 与 UC-8.2 消息头「待复核 N」
  取自同一字段，**两处数值必须相等**。
- V3（权限态）：逐一使用 引导师、组长、组员、观察者、未授权用户访问；
  返回数据和可执行动作严格符合 **UC-8.5** 的判定结果（本 UC 不另行定义）。
- V4（空态）：无线程时显示真实空态与「新建对话」下一步，不生成示例线程。
- V5（归档态）：已归档线程在默认筛选下不返回，显式筛选可读但全部写操作被拒绝。
- V6（依赖失败）：模拟网络/外部依赖失败，输入和最近成功数据保留，错误可解释且可重试。
- V7（并发态）：两名用户同时改名/删除同一线程时不静默覆盖，并可识别最终版本。
- V8（审计态）：新建、改名、删除三类动作可按操作者、时间、对象和结果检索；
  越权尝试也有安全审计记录。
