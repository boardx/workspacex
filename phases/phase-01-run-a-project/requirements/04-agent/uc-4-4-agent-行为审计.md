# 原始需求（细化）— UC-4.4 Agent 行为审计

> 所属：阶段一 · 能跑完一场项目 / M4 上传 Agent
> 来源：`Backlog Use Case.html` 的 UC-4.4；UI 线索来自 `WorkspaceX Standalone.html`。
> **运行态原型**：
> **① tool-call 级调用明细**（对话屏 AI 消息内）：
> ```
> ▸ 思考了 8.2 秒 · 4 步
> 工具调用 · 3 ｜ 读了 64 条 · 12.4k token
>   graph.search(project:"远洋", type:["假设","证据"])   64 命中
>   brain.recall("资质尽调清单")                        复用 1 份
>   mcp:行业数据库.query_market(region:"DE")            运行中
> ```
> **② agent 互调与批准卡**（对话屏）：
> 「`[批准卡]` Ledger 想执行一个动作，等你批准　▸ **调用链 Ava → Ledger**　**已暂停**
>   模型：gpt-5.2 ＋ 本地 qwen3-32b `[改]` ｜ token 预算：800k（约 ￥9.6）
>   要读的数据：项目库 ＋ 电价曲线 · **含机密，仅本地模型**
>   `[批准执行] [改参数再跑] [不用了]`　批准后转后台任务，约 6 分钟回到本线程 `[看任务队列]`」
> **③ 项目级审计时间线**（`项目 → 成果沉淀 → **审计与反馈**`，214 条）：
> 「审计记录 —— 角色 · 版本 · Agent 调用 · 决策，**四类事件同一条时间线**，**不可删除**
>   筛选：全部 214 ｜ 角色变更 8 ｜ 版本 11 ｜ **Agent 调用 183** ｜ 决策 12　`[导出 CSV / JSON]`
>   **`11:20:33 调用  Ava → Ledger · 现金流对比（深度 2）    412k token · 人已批准`**」
> **④ 异常检测与自动限速**（后台 → **数据总览**）：
> 「异常待处理 3（2 个额度异常 · 1 个越权调用）
>   `[高]` 单人单日消耗**超均值 11 倍** —— 吴桐 7/18 03:12–05:40 触发 428 次 Deep Research，
>     疑似脚本循环调用。**已自动限速**。`[查看调用链] [标记为正常]`
>   `[中]` **越权调用尝试** —— 一个自建 agent 尝试访问未授权的 MCP「客户 CRM」，**已拦截 7 次**。」
> **⑤ 运行态明细**（任务 → AI 正在执行）：
> 「LG Ledger 3m42s 三路径 5 年现金流对比模型
>   ✓ 读取项目库与电价曲线 ｜ 敏感性分析 2/3 ｜ **已耗 412k token / 预算 800k**」

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P1**；估点 **5**（原 3，因审计粒度下沉到 tool-call 级 + agent 互调留痕 +
> 异常检测与自动限速上调）；建议迭代 **迭代 5 · 收尾项**。
>
> **[人类已拍板 · D-34] 两级审计**：**项目级**留在「项目 → 成果沉淀 → 审计与反馈」
> （**已存在，别搬走**）；后台新建**组织级**跨项目审计检索屏（按项目/人/时间 + 导出），估点 8 → 5。
> 本用例负责其中的 **Agent 行为**这一类事件在两级中的呈现与可追溯性。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-4.4 / Agent 行为审计
- **Actor**：**项目负责人 / 引导师**（项目级复盘）、**组织管理员**（组织级合规检查与异常处置）、
  **能力维护者**（定位 agent 行为问题）
- **目标**：[Backlog] 复盘或合规检查时，**任一条 AI 结论都能追到当时的输入与调用链**；
  [原型] 其载体已写实——按时间列出每次发言、调用的 skill、
  **每一次工具调用的函数签名与参数**、读了什么数据、谁调了谁、谁批准的、花了多少 token。
- **本用例结果**：形成一条**不可删除**的审计时间线；每条 AI 结论可下钻到 tool-call 级；
  异常行为被检测、限速与拦截并留下可处置的记录。
- **系统边界**：tool-call 级留痕、agent 互调（调用链）留痕、批准记录、
  项目级审计时间线（Agent 调用类事件）、组织级跨项目检索、异常检测与自动限速、
  越权拦截计数、导出。
- **核心数据对象**：审计事件、**tool-call 记录**（工具名 / 函数签名 / 参数 / 命中数 /
  运行态 / 耗时 / token）、调用链（主调 agent → 被调 agent × 深度）、批准记录、
  被采纳/被忽略标记、异常检测规则与命中、限速动作、拦截计数。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

### 阶段一 · tool-call 级留痕（本次修订的核心）

1. **系统处理**：agent 每发起一次工具调用即写一条 **tool-call 记录**。
   **[原型] 记录必须包含四个字段**（对话屏已写实）：
   | 字段 | 原型示例 | 说明 |
   |---|---|---|
   | **函数签名** | `graph.search` / `brain.recall` / `mcp:行业数据库.query_market` | 命名空间可区分**内建工具**（`graph.` / `brain.`）与 **MCP 工具**（`mcp:<服务器>.<工具>`） |
   | **参数** | `(project:"远洋", type:["假设","证据"])` / `("资质尽调清单")` / `(region:"DE")` | 结构化参数原样留痕 |
   | **命中数/结果量** | `64 命中` / `复用 1 份` | 每次调用的产出规模 |
   | **运行态** | `运行中`（其余两条已完成） | 逐条独立的状态，不是整体一个状态 |
   [设计] 另需记录：耗时、token 消耗、发起 agent、所属消息、所属线程/项目、
   命中的**权限层**（三层中哪一层放行）。
2. **系统处理**：把 tool-call 汇总为**消息级摘要**。
   **系统响应**：[原型] 消息头部呈现 `▸ 思考了 8.2 秒 · 4 步` 与
   `工具调用 · 3 ｜ 读了 64 条 · 12.4k token`；点开即展开逐条明细。

### 阶段二 · agent 互调留痕

3. **系统处理**：当一个 agent 调用另一个 agent 时，记录**调用链**与**深度**。
   **[原型证据]**：
   - 批准卡上的 `▸ **调用链 Ava → Ledger**　**已暂停**`；
   - 审计条目 `11:20:33 调用  **Ava → Ledger · 现金流对比（深度 2）**　412k token · 人已批准`。
   [设计] 因此调用链记录至少含：**主调 agent、被调 agent、任务名、调用深度、
   token 消耗、批准状态**。
4. **系统处理**：**被调方在需要批准的动作上暂停**。
   **系统响应**：[原型] 批准卡显示「Ledger 想执行一个动作，等你批准」并标 **`已暂停`**；
   卡上同时展示**模型**（`gpt-5.2 ＋ 本地 qwen3-32b`，可 `[改]`）、
   **token 预算**（`800k`，约 ￥9.6）、**要读的数据**（`项目库 ＋ 电价曲线 ·
   **含机密，仅本地模型**`）；三个出口 `[批准执行] [改参数再跑] [不用了]`。
   [设计] **agent 互调不绕过批准点**——被调方的权限**不继承主调方**，
   仍按 UC-4.1 的三层权限独立求交（这是「Agent 自主扩大权限」这条不包含的落地点之一）。
   [原型] 批准后转后台任务，约 6 分钟回到本线程（`[看任务队列]`）。
5. **系统处理**：批准动作与结果一并写入审计（[原型] 条目末尾的 **`人已批准`**）。
   [设计] 未获批准即终止的调用链同样留痕（`已拒绝` / `已取消`）。

### 阶段三 · 审计时间线与检索

6. **项目负责人操作**：进入 `项目 → 成果沉淀 → 审计与反馈`。
   **系统响应**：[原型] **四类事件同一条时间线**（角色变更 / 版本 / **Agent 调用** / 决策），
   **不可删除**；筛选计数（原型：全部 214 ｜ 角色变更 8 ｜ 版本 11 ｜ **Agent 调用 183** ｜
   决策 12）；`[导出 CSV / JSON]`。
   **[D-34] 这一屏已存在，本用例不新建、不搬走**，只负责把 Agent 调用类事件做实做全。
7. **能力维护者/项目负责人操作**：点开某条 Agent 调用事件下钻。
   **系统响应**：展开该次调用的完整上下文——当时的输入、注入的 skill（**带版本**）、
   逐条 tool-call 明细、调用链、批准记录、产出的结论。
   [原型 UC-4.4 原文] 并**标出被采纳与被忽略的建议**。
8. **组织管理员操作**：[D-34] 在**后台组织级审计检索屏**按**项目 / 人 / 时间**跨项目检索并导出。
   **系统响应**：返回跨项目的 Agent 调用事件；
   [D-18] 管理员**读项目内容须写审计日志且对项目负责人可见**。

### 阶段四 · 异常检测与自动限速

9. **系统处理**：持续对 agent 与人的调用行为做**异常检测**。
   **[原型] 两类已写实的异常**：
   - **额度异常（高）**：「单人单日消耗**超均值 11 倍** —— 吴桐 7/18 03:12–05:40
     触发 **428 次** Deep Research，疑似脚本循环调用。**已自动限速**。」
     出口 `[查看调用链]` `[标记为正常]`。
     [设计] 判据是**相对均值的倍数**（原型 11 倍）而非绝对阈值；
     **[已裁决 O-36 第 3 项]** 原问题：触发倍数与观察窗口未给。
     **裁决（O-36）**：**10 倍 / 24 小时滚动窗口**。属可先实现、后期调参的一类。
   - **越权调用（中）**：「一个自建 agent 尝试访问未授权的 MCP「客户 CRM」，**已拦截 7 次**。」
     [设计] 越权调用**必须拦截并计数**，而不是仅记录。
   [原型] 后台数据总览顶部呈现「异常待处理 3（2 个额度异常 · 1 个越权调用）」。
10. **系统处理**：命中额度异常时**自动限速**（[原型]「已自动限速」）。
    [设计] 限速是**系统自动动作**，不等人；限速本身写入审计并通知当事人与管理员。
11. **组织管理员操作**：`[查看调用链]` 下钻到具体 tool-call；
    或 `[标记为正常]` 解除限速。
    **系统响应**：处置动作与理由留痕；`[标记为正常]` 后同类行为在观察期内不再重复告警。
12. **系统收口**：校验 AC1「任一条 AI 结论都能追到当时的输入与调用链」、
    AC2「每一次工具调用都有函数签名、参数、命中数、运行态四要素」、
    AC3「agent 互调有调用链与深度，且被调方不继承主调方权限」、
    AC4「异常被检测、限速被执行、越权被拦截并计数」；
    审计不可删除，导出可复现。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] 目标数据为空时展示真实空态、原因和下一步入口，**不生成示例审计条目**
    （原型每屏都填满样例数据，**零空态**，故此条为设计补全）。
  - A2：[原型] `[标记为正常]`——把误报的异常标为正常并解除限速，须填理由。
  - A3：[设计] tool-call 参数含敏感值时，列表默认**脱敏展示**，
    有权者可展开原值（[D-16] 组织层内用可逆映射 + 权限门控，支持审计回溯）。
  - A4：[设计] 私聊（UC-4.3）中的工具调用同样进入本时间线，
    但其**正文**按私聊的归属层适用可见性规则；审计只暴露调用元数据，不暴露私聊正文。
  - A5：[设计] 试跑（UC-4.1）产生的调用单独标记为 `试跑`，
    不计入项目审计的正式事件流，但仍需留痕。
- **异常流程**：
  - E1：[原型] **读原始数据的记录保留期与项目数据保留期一致**；
    [D-14] 由「留痕保留期 / 审计保留期」两个独立参数控制，项目级可覆盖。
    **[已裁决 O-01]** 原问题：各参数默认值与允许区间仍需合规负责人给出。
    **裁决（O-01）**：**材料 180 天 / 留痕 180 天 / 删除宽限 30 天 /
    知识有效期按资产类型 6·12·24 个月 / 审计保留期 1095 天（3 年）**；
    允许区间由合规负责人收窄。
    且「**不可删对象（快照、绑定关系、审计留痕）不受留存期约束**，
    单独走 O-39 的法定留存清单」——本用例的审计时间线即属此类。
    **[已裁决 O-19]** 涉客户数据的工具调用留痕**读同一个「留痕保留期」参数**（默认 180 天），
    **不得硬编码 180**；「涉客户数据」**按服务器整体标注**（工具级留 phase-2）。
  - E2：[设计] tool-call 写入失败时**该次工具调用必须失败**——
    **不允许「调用成功但没留痕」**（审计是硬前置，不是旁路）。
  - E3：[设计] 调用链深度超过上限时终止并留痕（防止 agent 互调递归）。
    **[已裁决 O-36 第 4 项]** 原问题：深度上限（原型出现过「深度 2」）。
    **裁决（O-36）**：**深度上限 ＝ 2**（采信原型，是 O-36 八项中唯一有原型依据的一项）。
  - E4：[设计] 被调 agent 已不在 `运行中` 或其权限不覆盖本次请求时，
    调用被拒并留痕，主调方明确失败，**不静默换 agent**。
  - E5：[设计] 审计时间线的任何**删除/修改请求一律拒绝**（[原型]「不可删除」）；
    合规删除只能通过 17-gov 的正式流程，且以「标失效」而非物理抹除的方式呈现。
  - E6：[设计] 导出量过大时转为异步任务并给出下载回执，不阻塞页面。
  - E7：[设计] 请求超时或依赖不可用时保留最后成功数据，明确失败并可安全重试。
  - E8：[设计] 权限在过程中被撤回时立即终止后续读操作；已读记录按审计规则保留。

## R5 权限与可见性

- **项目负责人 / 引导师**：可查看**本项目**的审计时间线（含 Agent 调用类事件）与下钻明细；
  可导出本项目审计。
- **组织管理员**：[D-34] 可在后台组织级审计检索屏跨项目检索并导出；
  可处置异常（`[查看调用链]` / `[标记为正常]`）。
  [D-18] **权力边界**：个人层只见计数；**读项目内容须写审计日志且对项目负责人可见**；
  管理员的每次审计访问本身也是审计事件。
- **能力维护者**：可查看与其维护的 agent 相关的调用明细，用于定位问题；
  **不因此获得项目内容的读取权**——只暴露调用元数据（工具名、参数摘要、命中数、耗时），
  正文与数据内容需另行授权。**[待确认]** 参数中若含业务内容如何界定。
- **审核人**：不参与审计；其职责止于 agent/skill 发布。
- **组长 / 组员**：不可见审计屏。
- **观察者（只读）**：不可见审计屏。
- **被审计对象本人**：[设计] 应能看到针对自己的异常告警与限速状态及理由
  （原型的「吴桐已达 98%，本周起降级运行」是同源做法）。
- 未登录、链接失效或未列出的角色：默认无权限；接口不得返回越权数据，不能只依赖前端隐藏。

    越权调用**被拦截并计数**；两者都出现在后台数据总览的「异常待处理」里并可下钻。
  - [设计验收] AC5：审计条目的呈现形态与原型一致，至少能渲染出
    `11:20:33 调用  Ava → Ledger · 现金流对比（深度 2）　412k token · 人已批准` 这一条。
  - [设计验收] AC6：**没有留痕就没有调用**——tool-call 写入失败则该次调用失败。
- **失败后置条件**：
  - 不产生「调用发生了但审计里没有」的空洞；写入失败必须让调用失败并可观测。
- **不包含**：
  - **Agent 自主扩大权限**、未经批准的高风险动作
    （落地点：UC-21.2 的「禁止 agent 自行发现新 MCP」默认关 + 本用例的「被调方不继承权限」）。
  - **项目级审计屏的新建**——[D-34] **已存在，别搬走**；本用例只做实其中的 Agent 调用类事件。
  - **组织级审计检索屏的完整实现**——[D-34] 属 17-gov / 后台新增模块（估点 5），
    本用例只定义 Agent 调用事件在其中的字段与检索维度。
  - **[D-07 最小子集] 调用量统计**——「3,104 次/月」「工具调用量·近 7 天」
    不在 phase-1 范围。**注意区分**：异常检测所需的**实时用量判据**属安全能力，**保留**；
    面向展示的**统计报表**不做。
  - 配额与降级体系的完整实现（三级阈值 × 四类任务矩阵）——属后台成员与配额模块；
    本用例只承接其审计与异常处置面。
  - 反馈与迭代（消息级 👎 → skill 改进）——见 UC-3.6。

## R7 业务规则（不随具体实现变化的硬性约束）

- [原型] **审计记录不可删除**；四类事件（角色 / 版本 / Agent 调用 / 决策）同一条时间线。
- [原型] **读原始数据的记录保留期与项目数据保留期一致**；
  [21-mcp] 涉客户数据的工具调用**留痕 180 天**。
- **[设计 · 硬前置] 没有留痕就没有调用**——tool-call 写入失败则该次工具调用失败。
- **[原型] tool-call 四要素**：函数签名、参数、命中数/结果量、运行态；
  内建工具（`graph.` / `brain.`）与 MCP 工具（`mcp:<服务器>.<工具>`）必须可区分。
- **[原型] agent 互调必须留调用链与深度**；**被调方在需批准的动作上暂停等批准**。
- **[设计] 被调 agent 不继承主调 agent 的权限**——独立按三层权限求交（UC-4.1 R3）。
- **[原型] 异常检测与自动限速**：额度异常按**相对均值倍数**判定并**自动限速**；
  越权调用**拦截并计数**。
- **[设计]** 限速与拦截本身是审计事件，且对当事人可见。
- [D-18] 管理员的每次审计访问写入审计日志并**对项目负责人可见**；个人层只见计数。
- [D-16] 敏感参数默认脱敏展示，展开需权限门控且可审计回溯。
- AC1：任一条 AI 结论都能追到当时的输入与调用链。
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- AI/Agent 的写回、覆盖、发布或高影响工具调用必须遵守原型中的批准点。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。

### 架构对齐（Context Engine）

- **[设计 · 架构对齐] 审计落点 ＝ `provenance_events`**：
  本用例的 tool-call 记录、调用链、批准记录、越权拦截、限速动作
  **一律写入 Context Engine 的 `provenance_events` 表**——
  它是**append-only 的血缘表**（`docs/architecture/context-engine.md` 第二节核心表；
  与需求侧的对应见其「provenance_events ↔ 17-gov 全链路审计（UC-17.1）四类事件」）。
  由此：
  - **不另建一套审计存储**——17-gov（UC-17.1）、21-mcp（留痕）、20-model（路由决策）
    与本用例**共用同一份 append-only 数据**，各自只是不同视图；
  - **append-only 天然满足 R7 的「审计不可删除、不可篡改」**——
    更新与删除在**表层面**被拒绝，而不是靠应用层自觉；
  - E5 的「合规删除只标失效不物理抹除」由此获得实现依据。
- **[设计 · 架构对齐] agent run 必须保存四件套**（架构第七节 **P4**）：
  **计划（plan）、工具调用（tool calls）、checkpoint、Context Pack**，
  落在 `agent_runs` / `agent_steps` / `context_packs` 三张表上。
  验收含义：
  - AC1「任一条 AI 结论都能追到当时的输入与调用链」的「**当时的输入**」
    **就是那次 run 的 Context Pack**——必须**可重放**
    （对应架构首批完成门槛第 ⑥ 条「每次 Agent 运行能重放当时使用的 Context Pack」）；
  - Context Pack 中的 `retrievalReasons` / `omissions` / `permissionDecisionId`
    使「为什么读到这条」「少读了什么」「凭什么能看」三问可回答；
  - 高影响操作（批准卡）用 **LangGraph 动态 `interrupt()`** 做 HITL，
    其 checkpoint 必须落库，**节点恢复时副作用必须幂等**。
- **[设计 · 架构对齐] 上下文只经 Context API**：agent 与 skill 读取上下文
  **只能通过 Context API 取 Context Pack**，**不得绕过 Context Engine 直查库**——
  Context Engine 是唯一 AI 边界。旁路取数的内容**没有 Context Pack 记录**，
  会直接造成本用例 AC1 的审计断链，属实现级违规，应由架构测试拦截。
- **[设计 · 架构对齐] 编排边界**：**LangGraph 只用于深度研究、人工确认（HITL）、多阶段生成**；
  **摄取流水线用持久任务系统**（PG outbox + worker），**两者不可混用**。
  本用例的审计写入属**持久任务系统**侧（不可丢、可重放），
  不得挂在 LangGraph 图上；而批准卡的 HITL 中断属 LangGraph 侧。
