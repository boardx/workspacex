# 原始需求（细化）— UC-4.1 注册一个 Agent

> 所属：阶段一 · 能跑完一场项目 / M4 上传 Agent
> 来源：`Backlog Use Case.html` 的 UC-4.1；UI 线索来自 `WorkspaceX Standalone.html`。
> **运行态原型**：后台 → AI 能力 → **Agent 管理（14 个 agent · 4 个正在运行）**：
> ```
> [＋ 新建 Agent]（从空目录开始，或复制一个现成的）  筛选：全部标签/客户/内部/高优先级
> AV Ava    战略分析师·全组织可用  ● 运行中  claude-opus-4.6    12 skills  3,104 次/月 [编辑][试跑]
> SC Scout  市场研究·全组织可用    ● 运行中  claude-sonnet-4.6   8 skills  4,120 次/月 [编辑][试跑]
> EC Echo   转录与综合·全组织可用  ● 运行中  whisper ＋ sonnet    5 skills  1,930 次/月 [编辑][试跑]
> LG Ledger 财务建模·**仅能源组**  ● 运行中  gpt-5.2             6 skills    742 次/月 [编辑][试跑]
> DV Devil  反方论证·草稿          草稿      claude-sonnet-4.6   3 skills   未发布   [编辑][试跑]
>    「专门找结论的反例与失效场景。**还没配工具白名单，不能发布**。」
> JT Jobs 访谈助手  高琳 18 分钟前从社区导入  **待审核**  claude-sonnet-4.6  4 skills  —
>    「安全扫描通过，等待方法论审核；**工具白名单里有一条越权申请待确认**。」
>    [批准发布] [查看定义]
> 可见性范围取值：全组织可用 / 仅某组
> 状态机：草稿 → 待审核 → 运行中；未配工具白名单不得发布
> ```
> 另：后台「成员与配额」的 **Agent 级降级阈值**
> （`Scout 1.5M/日·80%` ｜ `Ledger 800k/次·**不降级**` ｜ `Ava 按组织级`，
> 「财务建模精度敏感，Ledger 设为不降级、超限直接请人批准」）；
> 后台「MCP 服务器」的授权范围与安全策略（见 21-mcp）；
> 后台「模型管理」的「**只有测试通过的模型才会出现在 agent 与 skill 的模型选择里**」（见 20-model）。

> 口径（四标记）：**[原型]** ＝ `WorkspaceX Standalone.html` **运行态实际存在**的行为（有界面可查，依据 scratchpad 的 proto-01~10 抽取档案）；**[Backlog]** ＝ `Backlog Use Case.html` 的**文档要求**（原型未必实现）；**[设计]** ＝ 依据前两者反推补全，**需人类确认**；**[待确认]** ＝ 不应由实现者自行决定。
> 元数据：优先级 **P0**；估点 **8**（原 5，因发布状态机 + 三层权限模型重写 + 五组新字段上调）；
> 建议迭代 **迭代 2 · 能挂能力**。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-4.1 / 注册一个 Agent
- **Actor**：**能力维护者**（创建与配置）、**审核人**（方法论审核，见 UC-3.1 R5）、
  **引导师**（使用方）
- **目标**：[原型] Agent 是带角色与权限的 AI 成员（战略分析师、市场研究、转录与综合、
  财务建模、反方论证…）。要能注册、配模型与工具、定按状态载入的规则、试跑，
  并经**双重门禁**发布。
- **本用例结果**：Agent 库中新增一个处于 `运行中` 的 agent，具备完整身份、skill 挂载、
  **工具白名单**、模型与并发、降级策略、可见性范围，且其**可读数据范围由三层权限求交决定**。
- **系统边界**：Agent 库、身份与职责、skill 挂载、**工具白名单**、模型与并发配置、
  降级策略、可见性范围、复制现成 agent、试跑、双重门禁与发布状态机、审计。
- **核心数据对象**：Agent、Agent 版本、Skill 挂载、**工具白名单条目**、模型配置、
  并发配置、降级策略、可见性范围、`clone_from` 来源、试跑记录、审核记录、调用链。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式身份，且在本组织持有能力维护者权限（组织角色见 `uc-0-3`）。
  - 依赖能力「上传 Skill（agent 通过 skill 干活）」可用（UC-3.1）。
  - **[设计]** 目标模型已在 **20-model** 中通过准入测试并处于「已启用」——
    [原型硬约束]「**只有测试通过的模型才会出现在 agent 与 skill 的模型选择里**」。
  - **[设计]** 要写进工具白名单的 MCP 工具，其所属服务器已在 **21-mcp** 注册且**未被隔离**，
    且该 agent 的使用者落在服务器的**授权范围**内。
- **触发条件**：
  - [原型] 维护者在后台 → AI 能力 → **Agent 管理** 点 `[＋ 新建 Agent]`
    （**「从空目录开始，或复制一个现成的」**——即支持 `clone_from`）。
  - [原型] 或从**社区导入**（原型：「Jobs 访谈助手 · 高琳 18 分钟前从社区导入 · 待审核」）。
    **[D-06 同源] phase-1 不实现社区导入**——只保留 `source=community` 的数据取值，
    入口置灰标 later；社区市场对接是 **phase-2** 能力升级。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **能力维护者操作**：填**身份**——名字、缩写角标（[原型] AV / SC / EC / LG / DV / JT）、
   **职责一句话**（[原型]「战略分析师」「市场研究」「转录与综合」「财务建模」「反方论证」，
   Devil 的详述「专门找结论的反例与失效场景」）。
   **系统响应**：落为 `草稿` 状态（[原型] Devil 即处于此态，显示「未发布」）。

2. **能力维护者操作**：配置 **`R3.2 能读哪些数据` → 已重写为三层权限模型**。
   **[人类已拍板] agent 的可读数据范围不是一个自由字段，而是三层求交的结果**：

   | 层 | 谁定义 | 归属 | 语义 |
   |---|---|---|---|
   | **① MCP 授权范围** | 组织管理员 | **21-mcp / UC-21.1** | 某台 MCP 服务器（及其 N 个工具）开放给谁——[原型] 取值 `仅项目负责人` / `全体成员`；未注册或**已隔离**的服务器不可用 |
   | **② Agent 工具白名单** | 能力维护者（本用例） | **本用例** | 这个 agent 被允许调用哪些工具（含 MCP 工具与内建工具）。[原型] **未配工具白名单不得发布** |
   | **③ 任务权限包 R1/R2/R3** | 任务模板 / 自动推导 | **00-core / 11-board** | 单次任务的风险等级与随之而来的批准要求。[D-28] 按操作类型自动推导（外发邮件恒 R3、读公开资料恒 R1），任务模板可覆盖 |

   **系统响应**：**有效权限 ＝ ① ∩ ② ∩ ③**；任一层不通过即拒绝，且服务端可解释「为什么被拒」。
   - **[原型]** 白名单里可以存在**越权申请**——形如「工具白名单里有一条**越权申请待确认**」：
     即 agent 申请的工具超出了 ① MCP 授权范围，该条目标为待确认，**由审核人在发布时逐条裁决**。
   - **[设计]** 白名单条目粒度到**工具**而非服务器（[原型] MCP 行显示「12 工具」「28 工具」
     「6 工具」「4 工具」「9 工具」，说明工具是可枚举的最小单位）。
   - [原型] 读原始转写、读客户资料要**单独授权**——这类数据范围即使在白名单里，
     仍需在任务层拿到批准（第 ③ 层）。

3. **能力维护者操作**：挂载 **skill**。
   **系统响应**：从 Skill 库选取 `已启用` 且可见性范围覆盖本 agent 的 skill
   （[原型] 计数示例：Ava 12 skills / Scout 8 / Echo 5 / Ledger 6 / Devil 3 / Jobs 4）；
   记录 **skill 版本**（UC-3.4 的快照绑定）。

4. **能力维护者操作**：配置**模型与并发**。
   **系统响应**：
   - **模型选择**：[原型硬约束] **下拉里只出现 20-model 中测试通过并已启用的模型**
     （原型取值示例：`claude-opus-4.6` / `claude-sonnet-4.6` / `gpt-5.2` /
     **`whisper ＋ sonnet`**）。
     **[已裁决 O-22③]** 原问题：`whisper ＋ sonnet` 说明「一个 agent 可配组合模型」，
     但组合该由 agent 侧两个字段承载，还是模型池里的一条记录？
     **裁决（O-22③）**：**组合模型是模型池里的一条组合记录**——
     **一个 `model_id` 指向一个 pipeline**，**不是每个 agent 各自拼**。
     因此 agent 侧的模型字段**恒为单个 `model_id`**，下拉中的 `whisper ＋ sonnet`
     是**一条组合记录的显示名**。理由：否则 UC-20.2 的启用/停用无从作用于组合。
   - **并发**：[原型 UC-4.1 原文] 「填身份、可用 skill、**模型与并发**」。
     **[已裁决 O-22②]** 原问题：并发是组织级、项目级还是 agent 级上限，
     超限时排队还是拒绝——**配置面板未探明**。
     **裁决（O-22②）**：**agent 级为主 ＋ 组织级兜底**（两级同时生效，取更严者）；
     **超限排队，不拒绝**——拒绝会让现场直接失败。
     即：`有效并发 = min(agent 级上限, 组织级剩余额度)`；
     超出时任务进**排队**并向发起人显示排队位次与预计等待，**不得静默丢弃**。
     **项目级并发上限 phase-1 不做**（无原型证据，且两级已足够）。

5. **能力维护者操作**：配置**降级策略**（[原型] 后台「成员与配额」的 Agent 级阈值）。
   **系统响应**：三取值 —
   - **按阈值降级**：[原型] `Scout 1.5M/日 · 80%` ——用量达阈值后降级到便宜模型；
   - **不降级**：[原型] `Ledger 800k/次 · **不降级**`，
     说明文案「**财务建模精度敏感，Ledger 设为不降级、超限直接请人批准**」；
   - **跟随组织级**：[原型] `Ava 按组织级`（组织级为「已用 90% → 降级到 sonnet-4.6」）。
   同时受[原型] **按任务类型分级**的约束（这层优先级更高，见 R7）：
   普通生成 → 自动降级＋**消息标注**（[原型] 对话里 Scout 消息带 `降级运行 · sonnet` 角标）；
   研究/财务/合规/决策辅助 → **先问人再降级**；含客户机密 → **禁止降级**；
   无合格替代模型 → **明确失败**。

6. **能力维护者操作**：设**行为**——是否主动插话、是否需要批准。
   **系统响应**：[原型] 需要批准的 agent（如财务测算）**默认不主动插话**；
   [原型 · 说明页四条规则] 「AI 主动插话：默认开，**单个 agent 可关**」。
   [原型 · 批次 8] 另有**项目级** AI 权限开关（`Facilitator 主动提议收敛` 等），
   与本处的 agent 级开关是**两个粒度**——见 UC-4.2 R3。

7. **能力维护者操作**：设**可见性范围**。
   **系统响应**：[原型] 二取值 **全组织可用** / **仅某组**
   （原型示例：Ava/Scout/Echo「全组织可用」，Ledger「**仅能源组**」）。
   范围之外的用户在任何入口都看不到该 agent。

8. **能力维护者操作**：**试跑**一个真实场景（[原型] 行内 `[试跑]`）。
   **系统响应**：执行一次真实调用，展示它的发言、**工具调用链**、读了哪些数据、
   耗时与 token 消耗；试跑不写入正式记录。

9. **能力维护者操作**：提交发布。
   **系统响应**：**发布状态机（[原型] 明确三态）**：
   ```
   草稿 ──提交──▶ 待审核 ──[批准发布]──▶ 运行中
     ▲                  │
     └──── [退回] ──────┘
   ```
   - **[原型 · 硬闸门] 未配工具白名单不得发布**——Devil 的原型文案即
     「还没配工具白名单，不能发布」；系统在提交时即阻断。
   - **[原型] 双重门禁**（与 skill 同源）：**安全扫描（自动）＋ 方法论审核（人工）**。
     [原型] 待审核条目的文案：「**安全扫描通过，等待方法论审核；
     工具白名单里有一条越权申请待确认。**」
   - **[已裁决 O-21]** 审核人必须对**每一条越权申请**给出准/否，未逐条裁决不得批准发布。
     **裁决（O-21）**：这里出现的是**两种不同职能**，不可合并——
     **① 方法论审核人**：审 agent 定义本身（职责、skill 挂载、方法对不对）；
     **② 安全评审人**：审**工具白名单里的越权申请**（权限给不给）。
     两者**均由组织管理员指派**，**不得自审自批**（审核人 ≠ 提交人）。
     **越权申请另需组织管理员会签**——即 `安全评审人 + 组织管理员` 双签才能准予，
     因为它实际上在**扩大 MCP 授权范围（第 ① 层）**。
     方法论审核通过 ＋ 越权申请全部裁决完毕，才允许 `[批准发布]`。
   - **[已裁决 O-22④⑤] 版本与锁定**：批准发布时**生成一个不可变的 agent 版本快照**
     （定义 + skill 挂载版本 + 工具白名单 + 模型 + 降级策略 + 可见性范围）。
     依据 **D-30「引用必须指向不可变快照」**：**项目开工时锁定 agent 版本**，
     项目运行期内不因 agent 被改动而漂移；否则 `uc-4-4` 无法回答「当时跑的是哪一版」。

10. **审核人操作**：`[查看定义]` 后 `[批准发布]` 或 `[退回]`。
    **系统响应**：批准后状态转 `运行中`（[原型] 列表显示 `● 运行中`），
    进入可被载入的池子（UC-4.2）。

11. **系统收口**：校验 AC1「库里每个 agent 都能看到职责、挂载 skill、数据范围与最近试跑」、
    AC2「**未配工具白名单的 agent 不得发布**」、
    AC3「**未同时通过安全扫描与方法论审核的 agent 不得进入运行中**」；
    记录操作者、时间、对象、门禁两道结论、越权申请裁决结果进审计，刷新 Agent 库。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] **复制一个现成的 agent**（`clone_from`）——`[＋ 新建 Agent]` 提供
    「从空目录开始，或**复制一个现成的**」两条路。
    [设计] 复制会带上身份模板、skill 挂载、模型与并发、降级策略；
    **[已裁决 O-22①]** 原问题：**工具白名单是否随复制带过来**（此前按「不带」处理，需确认）。
    **裁决（O-22①）**：**复制不继承权限**——工具白名单**不随复制带过来**，必须重新配。
    理由：避免**权限静默扩散**。复制出的 agent 记录 `clone_from` 来源，
    且因白名单为空而**处于「未配工具白名单不得发布」的硬闸门下**（见 E1）。
  - A2：[原型] 需要批准的 agent（如财务测算）**默认不主动插话**。
  - A3：[原型 · phase-2] 从**社区导入** agent（原型的 Jobs 访谈助手）；
    phase-1 只保留数据取值与置灰入口。
  - A4：[设计] 安全扫描判为「有风险项待确认」时不直接拒绝，把风险项与越权申请
    合并列给审核人，逐条裁决并留理由。
  - A5：[设计] 审核人同时是提交人时**不得自审自批**（沿用 UC-3.1 A4）。
  - A6：[设计] Agent 库为空或筛选无结果时展示真实空态与 `[＋ 新建 Agent]`，
    **不生成示例 agent**（原型每屏都填满样例数据，**零空态**，故此条为设计补全）。
- **异常流程**：
  - E1：[原型 · 硬闸门] **未配工具白名单**时提交发布被阻断，
    界面明确给出「还没配工具白名单，不能发布」。
  - E2：[原型] **读原始转写、读客户资料要单独授权**——未获授权的条目进不了白名单，
    或以「越权申请待确认」形态保留待审核人裁决。
  - E3：[设计] 白名单引用的 MCP 服务器**被隔离**（21-mcp 默认新服务器隔离）或**限流中**时，
    相关工具在该 agent 上标为不可用；agent 仍可运行但**必须明确告知能力受限**，
    不得静默跳过工具调用。
  - E4：[设计] 配置的模型在 20-model 被停用时，该 agent 转「依赖失败」态并停止被载入，
    提示维护者改选模型；**`运行中` 状态不被静默撤销，但运行时明确失败而非静默换模型**
    （除非该 agent 配了允许降级且当次任务类型允许降级）。
  - E5：[设计] 并发配置超过组织/团队配额上限时提交被拒并给出可用上限。
  - E6：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，
    明确失败原因并提供安全重试（原型无任何错误态屏）。
  - E7：[设计] 同一 agent 被并发修改时不得静默覆盖；提示版本已变化，允许刷新、对比或重提。
  - E8：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留。

## R5 权限与可见性

- **能力维护者**：可新建、复制、编辑、试跑、提交 agent；**不能自行批准发布**。
  范围限定在其有权访问的组织。
- **[已裁决 O-21] 审核职能拆为两种**（原写「审核人」一种，兼管方法论与越权申请）：
  - **① 方法论审核人**（UC-3.1 同一职能）：审 agent 定义本身，
    对 `待审核` 行使 `[批准发布]` / `[退回]`。**看的是方法对不对。**
  - **② 安全评审人**（UC-21.1 / UC-21.2 同一职能）：**逐条裁决工具白名单里的越权申请**。
    **看的是权限给不给。**
  - **组织管理员**：对越权申请**会签**（与安全评审人双签方可准予）——它在扩大 MCP 授权范围。
  两种职能**均由组织管理员指派**，**不得自审自批**（审核人/评审人 ≠ 提交人）；
  可由同一自然人兼任，但**同一事项上只能行使其中一种职能**。
- **组织管理员**：定义 **MCP 授权范围**（21-mcp），即三层权限的第 ① 层；
  [D-18] 管理员权力边界仍适用（个人层只见计数；读项目内容留痕且对项目负责人可见）。
- **引导师**：可浏览可见性范围覆盖自己的 `运行中` agent，
  可在编排里载入（UC-4.2）、私聊（UC-4.3）；**不能改配置、不能发布**。
- **组长 / 组员**：只被动接触被载入的 agent；Agent 库不可见。
- **观察者**：不可见 Agent 库。
- **项目负责人**：可查看本组织 `运行中` agent 清单与审计摘要；写操作需显式授权。
- **可见性范围**（[原型]）：**全组织可用** / **仅某组**（如 Ledger「仅能源组」）。
  范围之外的用户在任何入口都看不到该 agent，接口不得返回其存在性。
- 未登录、链接失效或未列出的角色：默认无权限；接口不得返回越权数据。

## R7 业务规则（不随具体实现变化的硬性约束）

- **[原型 ＋ 已裁决 O-22④] 发布状态机**：`草稿 → 待审核 → 运行中 → 已停用`；
  **未配工具白名单不得发布**。
  原问题：原型**未见 agent 侧的停用动作**（对照 UC-3.4 skill 有），停用/归档语义未定。
  **裁决（O-22④）**：**agent 与 skill 对齐——补齐 `已停用` 态**。
  语义与 UC-3.4 一致：停用后**不再被载入**、不出现在编排与私聊入口；
  **已锁版本的在跑项目不受影响**（见下一条）；`已归档` 作为 `已停用` 的终态子类**不单列**
  （与 O-11 对 skill 的处理同构）。
- **[已裁决 O-22⑤] agent 有版本，项目开工时锁版本**。
  原问题：agent 是否有版本与「已开项目锁版本」语义（skill 有，agent 未见明证）。
  **裁决（O-22⑤）**：**有**。每次批准发布生成**不可变版本快照**；
  项目开工时**锁定 agent 版本**，运行期内不漂移。
  依据 **D-30「引用必须指向不可变快照」**——否则 `uc-4-4` 的行为审计
  **无法回答「当时跑的是哪一版」**。
- **[原型 ＋ 已裁决 O-21] 双重门禁**：安全扫描（自动）＋ **方法论审核（人工，由方法论审核人）**，
  两道全过才能发布；**工具白名单里的越权申请必须逐条确认**，
  且由**安全评审人 + 组织管理员会签**（不是方法论审核人的职权）。
- **[人类已拍板] 权限模型三层**：
  **MCP 授权范围（21-mcp） × Agent 工具白名单（本用例） × 任务权限包 R1/R2/R3（00-core）**；
  **有效权限 ＝ 三层求交**，声明本身不构成授权。
- [原型] 读原始转写、读客户资料要**单独授权**。
- [原型] 需要批准的 agent（如财务测算）**默认不主动插话**；主动插话默认开，**单个 agent 可关**。
- **[原型] 模型硬约束**：只有 20-model 中**测试通过并已启用**的模型才出现在 agent 的模型选择里。
- **[原型] 降级策略三取值**：按阈值降级 / **不降级** / 跟随组织级；
  **按任务类型的分级优先于 agent 级设置**：
  - 普通生成 → 自动降级 ＋ **消息标注**（对话里显示 `降级运行 · sonnet`）；
  - 研究 / 财务 / 合规 / 决策辅助 → **先问人再降级**（静默降级等于污染证据）；
  - 含客户机密 → **禁止降级**（对照 UC-20.3 的机密硬路由）；
  - 无合格替代模型 → **明确失败**（宁可报错，也不给低质量伪结果）。
- **[原型] 可见性范围**二取值：全组织可用 / 仅某组。
- **[已裁决 O-22①] 复制不继承权限**：复制现成 agent 时**工具白名单不随复制继承**
  （避免权限静默扩散）；复制出的 agent 因白名单为空而受「未配白名单不得发布」硬闸门约束。
- **[已裁决 O-22②] 并发上限 ＝ agent 级为主 ＋ 组织级兜底，超限排队**：
  `有效并发 = min(agent 级上限, 组织级剩余额度)`；**超限排队而非拒绝**
  （拒绝会让现场直接失败）；项目级并发 phase-1 不做。
- **[已裁决 O-22③] 组合模型属模型池**：agent 侧模型字段恒为**单个 `model_id`**，
  `whisper ＋ sonnet` 是模型池里一条组合记录的显示名，**不是 agent 侧拼两个字段**。
- **[已裁决 O-23] 三层权限的合成规则 ＝ 取交集（收紧优先），且不可被下层放宽**：
  `有效权限 = MCP授权范围 ∩ agent工具白名单 ∩ 任务权限包`，任一层收紧即生效；
  **下层不得放宽上层**（agent 白名单写了、但 MCP 授权范围没给，一律不可用）。
- **[设计]** 提交人 ≠ 审核人 / 评审人（O-21：不得自审自批）。
- **[设计]** skill 挂载必须记录到**版本**粒度（UC-3.4 快照绑定）。
- AC1：库里每个 agent 都能看到职责、挂载 skill、数据范围与最近试跑。
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- AI/Agent 的写回、覆盖、发布或高影响工具调用必须遵守原型中的批准点；
  未经确认只保留为草稿或候选。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 发布、退回、停用、白名单变更都必须记录审计事件，并显示动作影响范围。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 库规模量级参照原型 14 个 agent；列表需支持按标签、状态、可见性范围筛选。

    「涉客户数据」**按服务器整体标注**。客户机密仅本地模型处理（开关不可关）。
  - agent 定义变更全量留痕；`clone_from` 关系可追溯。
- **兼容与降级要求**：
  - 响应式 Web；后台以桌面端为主，移动端保证查看与审批两个动作可用。
  - **降级必须按 R7 的任务类型分级执行**；含机密与无合格替代模型两种情形
    **明确失败，不得静默降级**。

  **裁决**：**有**——每次批准发布生成不可变版本快照，**项目开工时锁版本**
  （依据 D-30「引用必须指向不可变快照」），否则 `uc-4-4` 无法回答「当时跑的是哪一版」。
- **[已裁决 O-23]** 三层权限**合成 ＝ 取交集（收紧优先），且不可被下层放宽**。
- **[设计 · 架构对齐] agent 运行的持久化**：每次 agent run 须保存
  **计划、工具调用、checkpoint、Context Pack**（`docs/architecture/context-engine.md`
  第七节 P4 与核心表 `agent_runs` / `agent_steps` / `context_packs`），
  并写入 `provenance_events`。运行记录中必须带**当次锁定的 agent 版本号与 skill 版本号**。
- **[设计 · 架构对齐] 编排边界**：**LangGraph 只用于深度研究、人工确认（HITL）、多阶段生成**；
  **摄取流水线用持久任务系统**（PG outbox + worker）。两者**不可混用**——
  agent 的并发排队（O-22②）属**任务系统**职责，不得用 LangGraph 图承载。

## R11 切分提示（给 requirement-author）

- 建议拆分顺序：
  1. Agent 领域模型（身份 / skill 挂载带版本 / 可见性范围）
  2. **工具白名单模型**（MCP 服务器 → 工具两级，含「越权申请」标记）
  3. **三层权限求交的服务端判定**（① MCP 授权 ∩ ② 白名单 ∩ ③ 任务权限包）＋ 「为什么被拒」可解释
  4. 模型与并发配置（模型下拉只出已启用模型）
  5. 降级策略（三取值 + 按任务类型分级的优先级）
  6. 发布状态机 `草稿 → 待审核 → 运行中` ＋ **未配白名单阻断**
  7. 双重门禁 ＋ 越权申请逐条裁决
  8. 试跑与试跑记录
  9. `clone_from` 复制现成 agent
  10. 审计 + 自动化验收
- 第 2、3、6 三项是本用例的**权限内核**，应优先且各自成 feature，并有**绕过尝试被拒绝**的验收。
- **优先级 / 先后依赖**：P0；8 点；迭代 2；依赖 UC-3.1、UC-20.2、UC-21.1、`uc-0-3`。

## R12 AI Ready 验收线索

- V1（成功态）：AC1 —— 任取一个 `运行中` agent，能看到职责、挂载 skill（带版本）、
  三层权限求交后的实际数据范围、最近试跑结果。
- V2（硬闸门态）：AC2 —— 未配工具白名单的 agent 提交发布被阻断，界面给出原型文案；
  直接调接口置为 `运行中` 被拒绝并记审计。
- V3（门禁态）：AC3 —— 只过安全扫描未过方法论审核的 agent 停在 `待审核`；
  白名单里存在未裁决的越权申请时不允许批准发布。
- V4（三层权限态）：AC4 —— 构造矩阵验证：
  ① 把 MCP 服务器授权范围从「全体成员」收紧为「仅项目负责人」→ 普通成员触发该 agent 调用被拒；
  ② 从白名单移除某工具 → 该 agent 调不到，即使 MCP 授权仍开放；
  ③ 把任务风险升到 R3 → 调用暂停等人批准。三条各自独立生效且服务端可解释拒因。
- V5（模型态）：AC5 —— 在 20-model 停用某模型后，agent 编辑页的模型下拉里它消失；
  已配该模型的 agent 转依赖失败态并停止被载入。
- V6（可见性态）：AC6 —— 标为「仅能源组」的 agent 对平台组成员在 Agent 库、编排面板、
  对话参与者、私聊四处均不可见，接口不返回其存在性。
- V7（降级态）：普通生成任务达阈值 → 自动降级且消息带 `降级运行 · sonnet` 标注；
  财务任务达阈值 → 先问人；含客户机密 → 禁止降级；无合格替代模型 → 明确失败。
- V8（不降级态）：把某 agent 设为「不降级」，超限时**请人批准**而非降级。
- V9（复制态）：复制一个现成 agent，新 agent 记录 `clone_from`，
  且**工具白名单为空**（必须重新配，因此新 agent 无法直接发布）。
- V10（依赖失败态）：把白名单引用的 MCP 服务器置为「已隔离」，
  该 agent 明确告知能力受限，不静默跳过工具调用。
- V11（权限态）：逐一使用 能力维护者 / 审核人 / 组织管理员 / 引导师 / 组员 / 观察者 /
  未授权用户访问，可读数据与可执行动作严格符合 R5。
- V12（空态）：Agent 库为空时显示真实空态与 `[＋ 新建 Agent]`，不生成示例 agent。
- V13（并发态）：两名维护者同时改同一 agent 不静默覆盖，可识别最终版本。
- V14（审计态）：发布、退回、白名单变更、越权申请裁决可按操作者、时间、对象、
  门禁结论检索；越权尝试也有安全审计记录。
- V15（复制不继承权限 · O-22①）：复制一个已配好白名单的 agent →
  新 agent 的工具白名单为空，且因此无法发布。
- V16（并发排队 · O-22②）：把 agent 级并发上限设为 1 并发起 3 个任务 →
  后 2 个**进入排队**（显示位次），**不被拒绝、不被丢弃**；
  组织级额度耗尽时以更严者生效。
- V17（组合模型属模型池 · O-22③）：agent 的模型字段只接受**单个 `model_id`**；
  尝试在 agent 上配置两个模型 ID 被拒；`whisper ＋ sonnet` 作为一条组合记录可被选中。
- V18（停用态 · O-22④）：停用一个 `运行中` 的 agent →
  它不再进入可载入池、不出现在编制与私聊入口；**已锁版本的在跑项目不受影响**。
- V19（版本锁定 · O-22⑤）：项目开工后修改 agent 定义并发布新版 →
  该项目运行期内仍使用**开工时锁定的版本**；审计中可读出该版本号。
- V20（两种审核职能 · O-21）：方法论审核人尝试裁决越权申请被拒；
  安全评审人尝试 `[批准发布]` 被拒；越权申请缺组织管理员会签时不生效。
- V21（三层求交不可放宽 · O-23）：白名单里有某工具但 MCP 授权范围未覆盖 → 调用被拒；
  任务权限包未包含 → 任务阻塞；**任何下层配置都无法放宽上层**。
