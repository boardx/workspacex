## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-2.2 / 套用蓝本新建项目
- **Actor**：**引导师**（主 Actor）、**项目负责人**（组织角色，可协同筹备）
- **目标**：[原型] 选一个蓝本 + 一个时长档位，**一次性把六类默认值写进新项目**，
  引导师落到「项目筹备」页后**只改内容、不搭结构**。
- **本用例结果**：[原型] 新项目建成，绑定该蓝本的**具体版本快照**；打开即有完整议程环节、
  分组位与**输出物**槽位；项目筹备页四个子标签（定题与分组 / 议程 N 环节 / 材料准备 M 份 /
  会前任务 x/y）均已按蓝本预填，引导师可逐项覆盖。
- **系统边界**：新建项目向导（选蓝本 + 选档位）、**六类初始化写入**、项目蓝本版本快照绑定、
  **项目筹备页**（定题单点继承、分组编排、观察/访谈对象表结构、材料与会前任务清单）、
  **项目设置 → 工作流编排**（工作流模板两级继承、环节 × 三角色编排矩阵、可切换模板库）。
  **不含**：蓝本本身的编辑（UC-2.1）、改动回提（UC-2.3）、访谈对象的实际预约与转写回流（06-itv）、
  待办卡在任务模块内的生命周期（11-board，本用例只负责**产生**）。
- **核心数据对象**：蓝本、蓝本版本、**项目蓝本快照**、时长档位、**议程环节实例**、
  **工作流模板引用（含来源版本，如「来自后台 v2」）**、**环节 × 角色编排格**（每格 = 一条角色职责，
  也是一条待办的发生源）、项目定题（唯一主题 + 唯一背景）、分组与组长、组员名单、
  观察/访谈对象表、材料清单、会前任务清单、**输出物槽位与验收口径**、报告骨架。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有目标组织、项目、小组或资源的访问权。
  - 目标资源存在且未被删除/冻结；依赖能力“登录管理（谁能编辑与发布蓝本）”可用，或界面能明确显示其不可用状态。
  - 若动作涉及个人数据、录音、原始材料或跨范围读取，相应授权与留存策略已生效。
- **触发条件**：
  - [原型] 引导师点「新建项目」并选一个蓝本。
  - 系统从 **新建项目** 进入本流程，并携带当前组织、项目、小组、角色和资源标识。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **引导师操作**：点「新建项目」，选一个**已发布**的蓝本，并选**时长档位**。
   **系统响应**：[原型] 列表展示可选蓝本及其元数据（已发布版本、议程环节数与时长、用过 N 次、
   满意度、设计配置完成度 `n/N`，见 UC-2.4）；档位默认取蓝本的默认档位（原型默认「两天」），
   可改；改档位后议程环节数随之变化（半天 7 / 一天 11 / 两天 14 / 三天 19，见 UC-2.1）。

2. **系统处理**：**一次性写入六类初始化项**——这是 AC2「初始化项逐项对得上」的**确定分母**，
   与蓝本设计器「套用后会初始化什么」一览**逐项一一对应**（原型原文照录）：

   | # | 类别 | 写入内容（原型原文） | 落到项目的哪里 |
   |---|---|---|---|
   | 1 | **定题与分组** | 主题句式与背景要素、4 组 × 场景清单、组长规则、**访谈对象表结构** | 项目筹备 → 定题与分组 |
   | 2 | **议程与材料** | **7 环节与时长**（＝该档位的议程环节数）、每环节材料要求与推演模板 | 项目筹备 → 议程 / 材料准备 |
   | 3 | **会前** | 问卷 2 份、访谈脚本、按角色派发的会前任务清单 | 项目筹备 → 会前任务；研究洞察 → 问卷 |
   | 4 | **现场** | 组内能力开关、按状态载入的 agent 与 skill、录音与转录设置 | 现场协作 |
   | 5 | **角色与进场** | 4 种角色的可见性、邀请链接与有效期默认值 | 分组与签到（UC-1.3）、角色可见性（UC-1.4） |
   | 6 | **产出** | **6 件输出物的验收口径**、2 份报告骨架与写作硬约束 | 成果沉淀 → 产出物 / 洞察报告 |

   > 表中的具体数字（4 组、7 环节、2 份问卷、6 件输出物）是**原型示例蓝本的取值**，
   > 实际数量由被套用蓝本的各项设计配置决定；**六个类别本身是固定的**。

   **系统响应**：[原型] 写入的是**默认值**；同时把**蓝本 ID + 具体版本号**作为快照绑定到该项目
   （见 UC-2.4）；记录触发原因，校验数据、权限与幂等条件（同一次提交重复触发不得建出两个项目）。

3. **引导师操作**：落到**项目筹备页**，**只改内容不搭结构**。**系统响应**：[原型] 呈现四个子标签，
   标签名自带进度计数：**`定题与分组` ｜ `议程 7 环节` ｜ `材料准备 9 份` ｜ `会前任务 7/12`**。

4. **引导师操作**：在 `定题与分组` 里定**项目主题与背景**。**系统响应**：
   [原型] **单点继承硬约束**——原话：「**整场只有一个主题、一段背景；分组、议程与所有 AI 上下文
   都从这里继承**」。界面元素：
   - `主题·一句话`（建议 30 字内，**带时间与判断口径**）、`背景·为什么现在开这场`
   - AI 辅助：**`[AI 生成主题]` `[AI 生成背景]` `[按洞察重写]`**
   - **来源计数**：`来源：12 条洞察 · 4 场访谈 · 客户董事会时间表`（AI 生成必须挂来源）
   - **`[保存并同步到全场]`**：保存即向下游（分组、议程、各 AI 上下文）同步，
     不是「只存这一页」。

5. **引导师操作**：在同一子标签里做**分组编排**。**系统响应**：[原型]
   - 组数调节 **`分几组 [− 4 +]`**、**`[AI 按背景均衡分组]`**、**`[＋ 加一组]`**
   - 每组一行：序号 / **组状态** / 场景 / 人数 · 组长，例：
     `2 第 2 组  缺 1 人  采购委员会比选供应商  2 人 · 组长 高琳`
   - **组状态三取值**：**`录音就绪` / `缺 N 人` / `需介入`**
   - 组卡展开：`场景·本组要推演什么`、`组员 N 人 [加人][换组长]`、**观察/访谈对象表**（见第 6 步）

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] **蓝本被下架/归档时仍可用已套用的版本**——归档只影响「还能不能新建」，
    不影响已建项目（见 UC-2.4）。新建项目的蓝本选择列表中不再出现已归档蓝本。
  - A2：[原型] **只选蓝本，先不定题**：项目可停在「只选了蓝本，主题与分组还没定」的低准备度状态
    （原型项目列表真实存在此态：`准备度 15% · 未邀请 · 蓝本 假设风暴（快版）`）。
    → 套用**不要求**同时完成定题与分组；筹备是可分次推进的。
  - A3：[原型] **新建项目时改档位**：写入的议程环节数按所选档位而非蓝本默认档位；
    可选议程环节自动增删、必留环节只压缩时间（规则与 UC-2.1/A1 一致）。
  - A4：[设计] **不套蓝本直接新建空项目**：允许，但项目筹备页四子标签均为空态，
    不得伪造默认结构；此后可否补套蓝本见 R10 [待确认]。
  - A5：[原型] **中途换工作流模板**（`[改用这个]`）：整条环节链被替换，
    已在旧环节上做的编排与已生成的待办如何处置**必须显式告知并确认**，不得静默丢弃。
    [待确认] 具体处置策略（保留孤儿待办 / 归档 / 拒绝在项目已开始后换模板）。
  - A6：[原型] **`[＋ 从空白搭]`**：不套任何工作流模板，手工搭环节链；
    此时环节 × 三角色矩阵为空，需逐格填写。
  - A7：[原型] **`[另存为组织模板]`**：把本场调好的编排沉淀为组织级模板。
    这是与 UC-2.3「提交回蓝本」**并列的第二条沉淀路径**，但产物不同：
    另存产生**一份新的组织模板**，回提产生**已有蓝本的待审改动**。二者都不就地修改后台本体。
    [已裁决 O-02] **产物明确为「工作流模板」，不是新蓝本**——
    它只承载议程环节链与 Skill 绑定（蓝本第 2、13 项的投影），
    不含蓝本的其余配置项；因此它**不能被 UC-2.2 当作蓝本套用**，只能被套进工作流编排。
    另存**不需要蓝本维护者审核**（它没有改动定义层）；提回蓝本则必须审核。
- **异常流程**：
  - E1：[原型] **套用后在项目里的修改不回写蓝本 / 不动后台模板本体**——两处原话同义：
    「写入的是**默认值**。引导师在那一场里改，**不会回写蓝本**；要沉淀就在复盘里
    『**提交回蓝本**』。」＋「改动**只影响这场项目，不会动后台的模板本体**。」
    → 系统**不得**提供任何从项目直接改后台资产的旁路；沉淀只有两条显式路径：
    UC-2.3 的「提交回蓝本」与 `[另存为组织模板]`。
  - E2：[设计] **初始化部分失败**：六类写入必须**要么全部成功、要么整体回滚**，
    不得建出「有议程没分组」的半成品项目；失败时明确告知失败类别并可重试。
  - E3：[设计] **矩阵格 → 待办的同步失败**：不得出现「格子已填但任务里没卡」的静默不一致；
    同步失败必须可见并可重试，且重试幂等（不产生重复待办）。
  - E4：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，明确失败原因，并提供安全重试。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E5：[设计] 同一资源被并发修改时不得静默覆盖；系统提示版本已变化，并允许刷新、对比或重新提交。失败不得被呈现为成功，也不得产生无法追溯的半成品。
  - E4：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留，未提交输入留在本地草稿并提示重新授权。

## R7 业务规则（不随具体实现变化的硬性约束）

**默认值与不回写（本用例最核心的一条）**
- [原型] **写入的是默认值。引导师在那一场里改，不会回写蓝本；要沉淀就在复盘里『提交回蓝本』。**
  → 项目实例与蓝本之间是**单向 + 快照**关系：套用时单向写入，此后互不影响；
  反向通道只有 UC-2.3 的显式回提。
- [原型] **同一条规则在工作流编排屏的另一处表述，口径必须统一**：
  「套用后你可以在『议程与材料』里改时长、增删环节、换绑模板与 skill。
  **改动只影响这场项目，不会动后台的模板本体。**」
  → 推广为**通用硬约束**：项目对**任何后台资产**（蓝本 / 工作流模板 / 画布模板 / skill / agent）
  的调整一律**只影响本场**。系统中**不存在**从项目上下文就地修改后台资产的路径。
- [原型] 沉淀回后台**只有两条显式路径**，且都不就地覆盖本体：
  ① 复盘 → **`提交回蓝本`**（产生待审改动，UC-2.3）
  ② 工作流编排 → **`[另存为组织模板]`**（产生一份新的组织级模板）。
- [原型] **蓝本管骨架与默认值，不管具体内容**；套用后引导师**只改内容不搭结构**。
- [原型] 蓝本被下架/归档时**仍可用已套用的版本**；归档只影响「还能不能新建」。

**初始化的确定分母**
- [原型] 初始化项恒为**六类**：定题与分组 / 议程与材料 / 会前 / 现场 / 角色与进场 / 产出。
  各类的具体条目由被套用蓝本的各项设计配置决定，但**类别不可增删**——
  AC2「逐项对得上」以这六类为断言基准。
- [原型] 第 6 类必须包含「**6 件输出物的验收口径**」（数量随蓝本变，**验收口径字段不可省**）；
  按裁决 D-31，这就是原文档「产出槽」的正名，其验收口径即 UC-13.2 的验收标准。

**定题单点继承**
- [原型] **整场只有一个主题、一段背景**；**分组、议程与所有 AI 上下文都从这里继承**。
  不得出现「分组各自一个主题」或「议程另存一份背景」的第二份真相。
- [原型] `[保存并同步到全场]` 是**同步动作**，不是普通保存；同步范围必须可见。
- [设计] AI 生成的主题/背景必须标注为机器产出并挂来源（原型显示 `来源：12 条洞察 · 4 场访谈 ·
  客户董事会时间表`）；来源不足时不得伪造。

**分组**
- [原型] 组状态取值恒为三个：**录音就绪 / 缺 N 人 / 需介入**，不得自造第四态。
- [原型] 每组必须有一个场景与一位组长；`[AI 按背景均衡分组]` 与 `[AI 按背景分配]` 的结果
  是**建议**，需人确认后生效。

**议程环节 × 三角色编排矩阵（跨模块契约，不是界面细节）**
> 本组规则里引号内的原型原话保留裸词「环节」，**其语义一律为「议程环节」**；
> 落到字段名时须写全 `agenda_stage`。
- [原型] **「编排一次，三套视图与待办自动生成」**——矩阵是**单一编排源**，
  三种角色视图与三套待办都从它派生。**不得**让引导师/组长/组员各自维护一份职责表。
- [原型] **「每一格都会变成对应角色的一条待办，同步到『任务』里」**——
  这是 UC-2.2 → **11-board** 的硬契约：格 ↔ 待办卡是**可追溯的一一对应**，
  改格/删格必须联动更新对应待办，不留孤儿卡；同步须幂等（重试不产生重复卡）。
  [裁决 D-39] 生成的待办**负责人恒为人**（该格对应的角色），agent 记在「执行者」字段。
- [原型] **「组长切换环节状态后，三种视角的首屏立刻跟着换」**——
  **议程环节**状态是**三视角首屏的唯一驱动源**，不得各视角各自判断当前议程环节。
- [原型] 每个**议程环节行**的「绑定」列同时承载**画布模板**与 **skill**（如
  `模板 hmw ＋ 语音转便签`、`模板 business-model`）——这是 **UC-3.2** 的实际配置面，
  本用例负责矩阵结构，绑定语义归 UC-3.2。

**版本与快照**
- [原型] 项目绑定**具体蓝本版本**（如 `蓝本 HMW 定题 v4`），一经绑定不随蓝本发布漂移。
- [原型] 工作流模板同样带**后台来源版本**（`设计思维标准五步 · 已套用 · 来自后台 v2`），
  遵循同一快照语义。

**通用**
- AC1：新项目打开即有完整议程环节、分组位与输出物槽位。
- AC2：六类初始化项与蓝本一览逐项对得上。
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- AI/Agent 的写回、覆盖、发布或高影响工具调用必须遵守原型中的批准点；未经确认只保留为草稿或候选。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、撤销、签署、发布、写回或停用动作都必须记录审计事件，并显示动作影响范围。

## R12 AI Ready 验收线索

以下行为应可由自动化测试、接口断言或可复现人工步骤验证：

- V1（成功态 · AC1）：套用蓝本建项目后，接口返回的**议程环节数＝所选档位数**
  （半天 7 / 一天 11 / 两天 14 / 三天 19）、分组位数＝蓝本分组规则的组数、
  **输出物槽位数＝蓝本第 14 项件数且每件带非空「验收口径」**。
- V2（成功态 · AC2）：把蓝本「套用后会初始化什么」一览与新项目实际初始化项做**逐项 diff**，
  差异必须为空；断言六个类别（定题与分组 / 议程与材料 / 会前 / 现场 / 角色与进场 / 产出）
  **一个不缺**。
- V3（成功态 · AC3）：套用 v4 建项目 → 蓝本发布 v5 → 项目页仍显示 `蓝本 … v4`，
  且项目内结构不发生任何变化。
- V4（成功态 · AC4 · 关键）：在项目内改议程、改分组、改材料、改输出物验收口径，
  逐一断言**蓝本 v4 的对应字段字节不变**；且系统不存在从项目直接写蓝本的接口路径。
- V5（成功态 · AC6）：改主题后点 `[保存并同步到全场]`，断言分组卡、议程与 AI 上下文
  读到的是**同一个主题 ID**；系统中**不存在第二份主题/背景记录**。
- V6（成功态 · AC5）：四子标签的计数（议程 N 环节 / 材料 M 份 / 会前任务 x/y）
  与后端实际条目数一致；改数据后计数同步刷新。
- V7（分组态）：`[− 4 +]` 增减组数后组卡数量一致；构造「缺 1 人」「需介入」「录音就绪」
  三种组，断言状态取值**只在这三个之内**；`[加人]`、`[换组长]` 生效并写审计。
- V8（AI 建议态）：`[AI 按背景均衡分组]`、`[AI 按背景分配]`、`[AI 生成主题/背景]`、

- V9（对象表态）：组卡内观察/访谈对象表六列齐全（对象/部门角色/联系方式/背景与要问什么/方式/状态），
