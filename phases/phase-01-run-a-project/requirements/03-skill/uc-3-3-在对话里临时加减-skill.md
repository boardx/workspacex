## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-3.3 / 在对话里临时加减 Skill
- **Actor**：**任何能写这条对话的人**（引导师 / 组长 / 组员；个人对话为其所有者）。
  观察者是只读角色，不在此列。
  > ⚠ **2026-08-21 人类产品裁决改写了本项**（原为「引导师、组长（受权时）」）。
  > 裁决逐字：「个人对话必须要可以使用公共的 skills」「所有的人都可以用」。
  > 落地见 issue #1693；判据在 `domain/skill/thread-mount.ts` 的 `isThreadMountAllowed`。
- **目标**：[Backlog] 现场发现蓝本绑定之外还缺一个能力时，能在对话输入框上方点「＋加技能」
  从库里临时挂一个，**只对当前这条对话生效，不改蓝本**。
- **本用例结果**：当前对话线程持有一份「临时挂载 skill」列表，与蓝本绑定（UC-3.2）
  在来源上可区分；会后复盘里被标出来，可「提交回蓝本」。
- **系统边界**：对话内 skill 挂载栏、Skill 库可选池过滤、临时挂载的生效范围与生命周期、
  复盘标注与回写蓝本入口。
- **核心数据对象**：对话线程、临时挂载条目（Skill ID × 版本 × 挂载人 × 时间 × 作用域）、
  蓝本绑定快照（作为对照基线）、复盘标注。
- **三个粒度必须区分**（[设计]，避免与 UC-3.2 混淆）：
  1. **后台模板级绑定**（UC-3.2）——写在工作流模板 / 蓝本第 13 项，跨项目复用，是默认值；
  2. **项目实例级编排**（UC-3.2 R3，`设置 → 工作流编排`）——在某一场项目里换绑，
     持久到项目结束；[原型]「**改动只影响这场项目，不会动后台的模板本体**」；
  3. **对话内临时加减**（本用例）——**只对当前这条对话生效**，粒度最小、生命周期最短。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 用户已建立可校验的正式或临时身份，且拥有当前对话线程的参与权。
  - Skill 库中存在 `已启用` 且可见性范围覆盖当前用户的 skill（UC-3.1）。
  - [设计] 该 skill 依赖的模型在 20-model 处于「已启用」态，MCP 未被隔离（21-mcp）；
    否则在选择器里显示为不可选并说明原因。
- **触发条件**：
  - [Backlog] 参与者觉得缺一个能力，在**全屏对话 → 输入区上方**点「**＋加技能**」
    （该按钮**原型确认缺失**：输入区已完整渲染，无此入口）。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **能写这条对话的人操作**：在输入框上方点「＋加技能」。
   **系统响应**：[Backlog] 弹出 skill 选择器，池子 ＝ `已启用` ∩ `可见性范围覆盖当前用户`
   ∩ `当前用户角色被允许自行挂载`（见 R5）；已由蓝本绑定的 skill 标为「本**议程环节**已绑定」
   并置于顶部，避免重复挂载。
2. **能写这条对话的人操作**：选中一个或多个 skill 挂载。
   **系统响应**：把它们加入当前对话的挂载列表，输入区上方即时更新
   （[原型] 结果态形如 `Ava ＋3 · skill：假设拆解`）；
   [Backlog] **只对当前这条对话生效，不改蓝本**。
3. **能写这条对话的人操作**：也可把已挂载的 skill 摘掉。
   **系统响应**：即时生效；**已经产生的消息不回溯**——历史消息上的
   `skill: MECE 假设拆解` 角标保留，表明当时确实用过。
4. **系统处理**：每次 AI 回答时，把当前挂载列表注入上下文，并在消息头部标出实际使用的 skill。
   [原型] 大脑「AI 读到了什么」显示「方法：MECE＋尽调清单 3.4k（**两个 skill 的执行步骤与
   输出格式约束**）← Skill 库」——临时挂载与蓝本绑定在注入时**同源同格式**，只有来源标记不同。
5. **系统收口**：校验 AC1「临时加的 skill 在会后复盘里被标出来，可提回蓝本」；
   记录挂载人、时间、对象、来源与生效范围进审计，刷新复盘视图的「偏离蓝本」清单。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[设计] 可选池为空（无已启用 skill 或全部不在可见范围）时展示真实空态、
    原因和下一步入口，**不生成示例 skill**（原型每屏都填满样例数据，零空态）。
  - A2：[设计] 临时挂载可整体清空，一键回到「只用本议程环节蓝本绑定」的状态。
  - A3：[设计] 复盘时对每条临时挂载给出三个出口：
    `提交回模板`（走 UC-3.2；[原型] 项目侧的实际路径是 `设置 → 工作流编排` 的
    **`[另存为组织模板]`**，因为实例级改动不回写模板本体）/
    `只在本场保留`（转为项目实例级编排）/ `忽略`。
- **异常流程**：
  - E1：**写不了这条对话的人不能挂载**（2026-08-21 裁决后，这不再包括组员）——
    观察者、非本项目成员、以及别人的个人对话，入口不呈现，且直接调接口挂载
    被服务端拒绝（`PERMISSION_REVOKED`）并记安全审计。
    ⚠ 「线程不存在」与「无权写」**同码同出口**，否则这条接口就是一个线程 id 探测器。
  - E2：[设计] 挂载数量导致本轮上下文超预算（[原型] 大脑显示「上下文预算 14.9k / 120k」）时，
    明确提示并要求取舍，**不静默丢弃某个 skill 的注入**。
  - E3：[设计] 临时挂载的 skill 在对话进行中被停用（UC-3.4）或其模型被停用（20-model）时，
    当前对话继续使用已锁定的版本直到对话结束，新对话不再可选。
  - E4：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，
    明确失败原因并提供安全重试。
  - E5：[设计] 同一对话被多人并发改挂载列表时不得静默覆盖；提示已变化并允许刷新后重提。
  - E6：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留。

## R5 权限与可见性

> **2026-08-21 人类产品裁决**（逐字）：「个人对话必须要可以使用公共的 skills」
> 「所有的人都可以用」。此前「引导师专属 + 组长需下放」的设计**整体作废**，
> 连带 `KNOWN_CONTRACT_GAPS.S3`（下放开关从未实现）——不再需要「下放」这个动作。

- **判据只有一条**：**能写这条对话的人，就能在这条对话里加减 skill**。
- **个人对话**：`project_id IS NULL`，仅其创建者——与 `decidePersonalThreadRead`
  同一条 creator-only 规则，不另算一份。
- **项目对话**：**该项目的任意成员**（引导师 / 组长 / 组员一视同仁）。
- **观察者**：只读角色，**不能**加减 skill（只读却给写入口，等于取消这个角色）；
  但**看得见**已挂载列表（V5）。
- ⚠ **池子不因此放宽**：能挂的仍然只有「`已启用` ∩ 可见性范围覆盖当前用户」的 skill。
  放开的是**谁能挂**，不是**能挂到什么**；不可见的 skill 仍走 `SKILL_NOT_FOUND`
  （I-14 不泄露存在性）。
- ⚠ **授权在服务端从线程反查**，不看请求里的 `projectId`——否则带上任意一个
  自己有权限的 projectId 就能挂到别人的线程上（#1693 一并修掉的既有洞）。
- **能力维护者 / 审核人**：不因这两个组织职能自动获得某场对话的挂载权；
  两者的职责止于 skill 的创建与发布（UC-3.1）。
- **项目负责人**：可查看临时挂载记录与复盘偏离清单；写操作需显式授权。
- 未登录、链接失效或未列出的角色：默认无权限；接口不得返回越权数据。

## R6 后置条件 / 不包含

- **正常后置条件**：
  - 当前对话持有临时挂载列表，且**蓝本未被修改**。
  - [Backlog验收] AC1：临时加的 skill 在会后复盘里被标出来，可提回蓝本。
  - [设计验收] AC2：临时挂载**只对当前这条对话生效**——同一**议程环节**的其它对话/其它组不受影响。
  - [设计验收] AC3：历史消息上的 skill 角标在摘掉 skill 后仍保留，可追溯当时用了什么。
- **失败后置条件**：
  - 不产生「以为挂上了其实没注入」的状态；失败明确提示并进可观测日志。
- **不包含**：
  - **[D-06] 任意代码无沙箱执行**、组员自行扩大数据权限。
  - Skill 的创建、校验与发布——见 UC-3.1。
  - 蓝本级绑定与本场覆盖——见 UC-3.2。
  - Skill 版本与停用——见 UC-3.4。
  - 对 skill 效果的评价与改进反馈（消息级 👎）——见 **UC-3.6**。

## R7 业务规则（不随具体实现变化的硬性约束）

- **能写这条对话的人才能加减 skill**（2026-08-21 裁决；原为「组员不能自己加」）。
- [Backlog] 临时挂载**只对当前这条对话生效，不改蓝本**。
- [设计] 临时挂载必须与蓝本绑定**在来源上可区分**，否则复盘无法标出偏离。
- [设计] 摘掉 skill 不回溯历史消息的角标。
- [设计] 可选池只含 `已启用` 且可见性范围覆盖当前用户的 skill。
- AC1：临时加的 skill 在会后复盘里被标出来，可提回蓝本。
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源；来源不足时不得伪造结论。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 临时挂载与摘除都必须记录审计事件。

## R9 非功能约束

- **性能/规模预期**：
  - [设计] 选择器打开与挂载生效应在 1 秒内可感知；挂载后的下一轮回答即体现新能力。
  - [设计] 可选池需支持搜索与按来源标记筛选（库规模量级见 UC-3.1，原型为 86 条）。
- **安全/隐私/合规**：
  - 组员的挂载拒绝必须在服务端执行，越权尝试进安全审计。
  - 临时挂载的 skill 其数据范围仍受三层权限（MCP 授权 × agent 工具白名单 × 任务权限包）约束，
    **临时挂载不构成提权**。
- **兼容与降级要求**：
  - 响应式 Web；**现场移动端必须能看到当前挂载了什么**，加减动作可仅桌面端提供。
  - 实时通道不可用时降级为轮询并显示「非实时」，不得伪装已生效。

  skill 运行时若需读取项目材料、转写、知识或对话历史，
  **只能向 Context Engine 的 Context API 请求一个 Context Pack**
  （`docs/architecture/context-engine.md` 第四节），

  引用锚点（`anchor`）、召回理由（`retrievalReasons`）与遗漏说明（`omissions`）
  只在这条通路上产生。每次调用须留下 `context_packs` 记录以便重放。
- **[设计 · 架构对齐] 编排边界**：**LangGraph 只用于深度研究、人工确认（HITL）、多阶段生成**；
  **摄取流水线用持久任务系统**（PG outbox + worker），**两者不可混用**。

## R12 AI Ready 验收线索

- V1（成功态）：AC1 —— 对话中临时加一个 skill，会后复盘里该 skill 被标为「临时加载」
  并提供「提交回蓝本」入口。
- V2（作用域态）：AC2 —— 在第 2 组对话临时挂载后，第 1 组同议程环节对话的挂载列表不变，蓝本不变。
- V3（可追溯态）：AC3 —— 摘掉 skill 后，此前用它生成的消息仍带该 skill 角标。
- V4（权限态）：组员端无「＋加技能」入口；直接调挂载接口返回拒绝并写安全审计。
- V5（空态）：可选池为空时显示真实空态与原因，不生成示例数据。
- V6（依赖失败态）：把某 skill 依赖的模型停用，该 skill 在选择器里不可选并说明原因。
- V7（权限态·全量）：逐一使用 引导师 / 组长 / 组员 / 观察者 / 未授权用户访问，
  可读数据与可执行动作严格符合 R5。
- V8（并发态）：两人同时改同一对话的挂载列表不静默覆盖，可识别最终状态。
- V9（审计态）：挂载与摘除可按操作者、时间、对话、skill 检索；越权尝试也有安全审计记录。
