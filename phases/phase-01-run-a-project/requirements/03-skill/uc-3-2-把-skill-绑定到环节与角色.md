> 来源：`Backlog Use Case.html` 的 UC-3.2；UI 线索来自 `WorkspaceX Standalone.html`。

## R1 概览（Use Case 名称 / Actor / 目标 / 系统边界）

- **Use Case ID / 名称**：UC-3.2 / 把 Skill 绑定到环节与角色
- **Actor**：**引导师**（项目实例级编排的主要执行者）、**能力维护者**（后台模板级默认值的维护者）
- **目标**：[原型] 在**环节 × 角色**的矩阵上把 skill 挂上去，使「现场切环节时挂载的 skill
  自动换，不需要人手配」，并且「**编排一次，三套视图与待办自动生成**」。
- **[原型] 绑定是两级继承的**：
  - **后台模板级**——工作流模板 / 蓝本第 13 项，提供**默认值**（原型：`来自后台 v2`）；
  - **项目实例级**——套用后在 `设置 → 工作流编排` 里换绑，
    **「改动只影响这场项目，不会动后台的模板本体」**；
    要沉淀回组织，走 `[另存为组织模板]`。
- **本用例结果**：项目持有一张 `环节 × 绑定 × 三角色分工` 的编排表；现场推进环节时
  运行时按表自动挂载 skill 到对应角色的对话与画布上；每一格同时生成对应角色的待办。
- **系统边界**：工作流模板套用与切换、环节编排矩阵、环节行的绑定槽（skill / 画布模板）、
  三角色分工格、按角色下发解析、模板级 ↔ 实例级的继承与另存、运行时按环节挂载、
  三视角首屏切换、待办生成回流。
- **核心数据对象**：工作流模板（来源版本，如 v2）、项目实例编排表、议程环节、
  **绑定条目**（环节 ID × Skill ID × 版本 × 下发角色 × 触发方式）、三角色分工格、
  角色待办、项目绑定快照。

## R2 前置条件 / 触发条件

- **前置条件**：
  - 项目已存在且已**套用一个工作流模板**（[原型]「设计思维标准五步 · 已套用 · 来自后台 v2」），
    或从空白搭（`[＋ 从空白搭]`）。
  - 环节表已成形（[原型] 环节链示例六环节；其它模板 5 / 7 / 18 环节不等）。
  - Skill 库中至少有一条 `已启用` 且可见性范围覆盖本组织/本团队的 skill（UC-3.1）。
  - 当前用户对该项目持有引导师角色（或对后台模板持有编辑权，若在模板级操作）。
- **触发条件**：
  - **[原型 · 主路径]** 引导师进入 `项目 → [进入项目] → 设置 → 工作流编排`，
    在环节行上换绑 skill，或在三角色格里改分工。
  - **[原型 · 次路径]** 引导师点 `[去议程里细调]` 在议程编辑器里改时长、增删环节、换绑模板与 skill。
    **[未探明]** 议程编辑器本身尚未抽取（见 R8）。
  - **[原型 · 模板路径]** 能力维护者在后台蓝本设计器第 13 项「Skill 绑定」维护默认值。

## R3 主流程（编号步骤，写清楚谁做什么、系统怎么响应）

1. **引导师操作**：新建项目时选一个**工作流模板**（或事后 `[改用这个]` 切换）。
   **系统响应**：[原型] 把模板的环节链、每个环节的绑定与三角色分工**一次性写入这场项目**，
   并记录来源（`设计思维标准五步 · 已套用 · **来自后台 v2**`）。
   写入的是**默认值**；此后项目实例与模板本体解耦。
2. **引导师操作**：进入 `设置 → 工作流编排`，查看**环节编排矩阵**。
   **系统响应**：按 `环节 · 绑定 ｜ 引导师 ｜ 组长 ｜ 组员` 四列渲染，
   环节行显示时长与**绑定内容**（[原型] 形如 `45m · 模板 hmw ＋ 语音转便签`、
   `60m · 模板 business-model`、`25m · Scout 简报`），当前环节标「（当前）」。
3. **引导师操作**：在某环节的**绑定槽**里换绑 skill。
   **系统响应**：从可选池（`已启用` ∩ 可见性范围覆盖当前用户）中选择；
   校验 skill 状态、版本、数据范围声明；
   [原型] 绑定槽是**混合槽**——同时容纳 **skill**（如「语音转便签」）与
   **画布模板**（如 `hmw` / `business-model`）与 **agent 产物**（如「Scout 简报」）。
   **[设计] 本用例只负责其中的 skill 部分**；画布模板绑定属 07-canvas，
   agent 编排属 UC-4.2。三者在同一槽内呈现，但**数据模型必须可区分**。
4. **引导师操作**：在**三个角色列**里填/改每个角色在该环节要做的事。
   **系统响应**：[原型] 这就是「**按角色下发**」的实际形态——
   引导师列（如「计时 · 提议收敛 · 看四组进度」）、组长列（如「分工 · 补必填区 · 提交本组」）、
   组员列（如「写 ≥1 张便签 · 投票」）。
   [设计] 绑定的 skill 需指明**下发给哪几列**（可多选：引导师 / 组长 / 组员；
   另有「全场共用」）；原型的「语音转便签」显然是全场生效，「Scout 简报」是引导师侧播报。
5. **系统处理**：[原型 · 硬规则] **「每一格都会变成对应角色的一条待办，同步到「任务」里」**。
   **系统响应**：编排矩阵的每一个非空角色格生成一条待办，回流到任务模块（`[看任务]`），
   [D-39] 待办**负责人恒为人**；若该格的动作由 agent 执行，agent 记在独立的「执行者」字段。
6. **系统处理**：[原型] 为每条绑定确定**触发方式**。
   画布屏左栏可见两种形态：`[运行]`（**按需触发**，如「提取假设 → 假设树」）、
   `[已开]`（**默认常开**，如「语音转便签」），另有无按钮的常驻能力（「Markdown ⇄ 画布」）。
   [设计] 因此每条绑定带 `触发方式 ∈ {手动触发, 默认开启, 常驻}`。
7. **系统处理**：现场推进到某环节时按编排表**自动挂载** skill 到对应角色的上下文，
   并写明「因什么环节载入」。
   [原型 · 硬规则] **「组长切换环节状态后，三种视角的首屏立刻跟着换。」**
8. **引导师操作**（可选）：把本场调好的编排 `[另存为组织模板]`。
   **系统响应**：以当前实例编排为内容新建一个组织级工作流模板；
   [原型] **不回写**原模板本体。
9. **系统收口**：校验 AC1「现场切环节时挂载的 skill 自动换，不需要人手配」、
   AC2「改动只影响这场项目，不动后台模板本体」、AC3「每一格都生成了对应角色的待办」；
   记录操作者、时间、对象、结果与来源，刷新编排表、三视角首屏与任务列表。

## R4 备选流程与异常流程

- **备选流程**：
  - A1：[原型] 引导师可 `[改用这个]` 切换到另一个工作流模板
    （设计冲刺 5 天 18 环节 / 战略假设复盘 5 环节 / 客户共创 7 环节）。
    [设计] 切换会替换整张环节表，**已有的实例级改动会丢失**——
    必须**明确二次确认并列出将丢失的改动**，不得静默覆盖。
  - A2：[原型] `[＋ 从空白搭]`——不套模板，逐环节自建，绑定全部手工挂。
  - A3：[原型] `[去议程里细调]` 进入议程编辑器改时长、增删环节、换绑模板与 skill。
    环节增删会使部分绑定失去宿主，[设计] 必须**列出被孤立的绑定条目并要求逐条处置**
    （迁移 / 删除），**不得静默丢弃**。
  - A4：[原型] 一个环节挂超过 6 个 skill 时提示会分散注意力（**提示不阻断**，同 D-11 口径）。
  - A5：[原型] 未被任何环节绑定的 skill 在库里标为**闲置**。
  - A6：[设计] 编排矩阵为空（从空白搭且未填）时给出真实空态与推荐
    （按环节名推荐 skill，如「假设风暴」→「提取假设 → 假设树」），
    **推荐不自动生效**，必须引导师确认。
  - A7：[原型] 对话内的**临时**加减 skill 是更细的第三级粒度，只对当前对话生效——见 UC-3.3。
- **异常流程**：
  - E1：[设计] 绑定的 skill 被停用或归档（UC-3.4）时，**进行中的项目继续用它锁定的版本**；
    模板侧该条绑定标为「引用了已停用的 skill」，新项目套用前须处置。
  - E2：[设计] 绑定的 skill 依赖的模型被停用（20-model）或 MCP 被隔离（21-mcp）时，
    该绑定在现场标为「依赖失败」并明确告知引导师，**不静默跳过、不换模型**。
  - E3：[设计] 三角色格指向的分组在本场不存在（模板按 4 组配、本场只开 3 组）时，
    该格对不存在的组不生效，并列入项目筹备度的待处置项。
  - E4：[设计] 待办生成失败（任务模块不可用）时，编排保存成功但**必须显式提示
    「N 条待办未同步到任务」并提供重试**，不得静默丢失。
  - E5：[设计] 请求超时、网络中断或依赖不可用时，保留用户当前输入与最后成功数据，
    明确失败原因并提供安全重试。
  - E6：[设计] 同一项目编排被并发修改时不得静默覆盖；提示版本已变化，允许刷新、对比或重提。
  - E7：[设计] 权限在操作过程中被撤回时立即终止后续写操作；已完成步骤按审计规则保留。

## R5 权限与可见性

- **引导师**：可在自己主持的项目里做**实例级**编排（换绑 skill、改三角色分工、切模板、
  `[另存为组织模板]`）。
- **协同引导师**：[原型 · 批次 8 新增身份] 项目设置的「身份四选」为
  `组员 ｜ 组长 ｜ 观察者（只读）｜ **协同引导师**`。
  原问题：权限口径未定——原型只证明**身份选项存在**，**从未给出任何权限语义**；
  它是**第五种项目角色**还是「一场可有多名引导师」的实例？
  `uc-0-3` 的四项目角色里没有它，影响 RBAC 表
  （访谈详情的「周宁 联合主持」是同一概念的另一处证据）。
  **[已裁决 O-03]**：**协同引导师 ＝ 引导师的多实例**，**项目角色仍为四种**
  （引导师 / 组长 / 组员 / 观察者）。
  语义：一场项目可有多名引导师，其中一名为**主持人**，**最终确认权归主持人**
  （依据 `uc-6-4` R5 全仓唯一给出过权限语义的一处）。
  因此本用例中**协同引导师的编排权限与引导师相同**，但涉及「最终确认」的动作
  （如切换工作流模板、`[另存为组织模板]`）**须由主持人确认**。
  邀请屏的四选在文案上说明「协同引导师 ＝ 以引导师身份加入」。
- **能力维护者**：维护后台工作流模板 / 蓝本第 13 项的**默认值**；
  决定哪些 skill 进入可绑定池（经 UC-3.1 的发布与可见性范围）；**不代替引导师做实例级编排**。
- **审核人**：不参与绑定；其职责止于 skill 发布（UC-3.1 R5）。
- **组长**：[原型] 可**切换环节状态**（切换后三视角首屏跟着换）；
  可见本组的绑定与自己那一列的分工；**不能改绑定**。
- **组员**：只被动接收下发的能力；[原型] 画布左栏「本环节绑定的 skill」对其为**只读展示 + 触发入口**；
  [原型] 组员「只能用引导师下发的，不能自己加」（UC-3.3 E1）。
- **观察者（只读）**：[原型] 「观察者链接只读已发布内容」。
  [设计] 可见环节结构，**不可见**绑定的 skill 清单与运行按钮。
- **项目负责人**：可查看编排表与绑定快照；写操作需显式授权。
- **可见性范围继承**：绑定池只含可见性范围覆盖当前组织/团队的 skill；
  标为「仅能源组」的 skill 不出现在平台组引导师的绑定面板里。
- 未登录、链接失效或未列出的角色：默认无权限；接口不得返回越权数据。

  - [设计验收] AC5：画布屏左栏「本环节绑定的 skill」显示的清单与当前环节绑定表**完全一致**，

  - [设计验收] AC6：增删环节或切换模板时，**没有绑定条目被静默丢弃**。
- **失败后置条件**：
  - 不产生「看似已绑定但运行时挂不上」的配置；不产生「编排保存了但待办没生成且无人知晓」。
- **不包含**：
  - **[D-06] 任意代码无沙箱执行**、组员自行扩大数据权限。

## R7 业务规则（不随具体实现变化的硬性约束）

- **[原型 · 硬规则原文]** 「套用后你可以在『议程与材料』里改时长、增删环节、**换绑模板与 skill**。
  **改动只影响这场项目，不会动后台的模板本体。**」
  ——**绑定是两级的**：后台模板级（默认值） → 项目实例级（可覆盖，不回写）。
  沉淀回组织只有一条显式路径：`[另存为组织模板]`。
- **[原型 · 硬规则原文]** 「**每一格都会变成对应角色的一条待办，同步到「任务」里**；
  组长切换环节状态后，**三种视角的首屏立刻跟着换**。」
- **[原型]** 「**编排一次，三套视图与待办自动生成**」——编排表是三视角首屏与角色待办的**单一来源**，
  不得为三个角色各维护一份配置。
- **[原型]** Skill 绑定在后台是蓝本 **16 项设计配置的第 13 项**，与第 12 项「Agent 编排」并列。
- [原型] 一个环节挂超过 6 个 skill 时提示会分散注意力（**提示不阻断**）。
- [原型] 未被任何环节绑定的 skill 在库里标为闲置。
- **[原型 · D-30]** 已开过的项目**锁在自己的版本上**（模板改动生成新版本，不影响已开项目）。
- **[设计]** 只有 `已启用` 状态的 skill 可被绑定；`草稿` / `待审核` / `已停用` 不进绑定池。
- **[设计]** 绑定条目必须记录 **skill 版本**；现场运行时使用项目快照锁定的版本，不因发新版而漂移。
- **[设计]** 环节增删、模板切换不得静默丢弃绑定条目。
- **[设计]** 绑定槽是混合槽（skill / 画布模板 / agent 产物），但数据模型必须可区分，
  不得把三类混成一个字符串。
- **[D-39]** 生成的待办**负责人恒为人**；agent 记在独立的「执行者」字段。
- AC1：现场切环节时挂载的 skill 自动换，不需要人手配。
- AI/Agent 生成的候选内容必须标识为机器产出，展示可追溯来源。
- 所有权限判断必须在服务端执行；隐藏入口只是界面表现，不构成安全控制。
- 任何覆盖、删除、发布或停用动作都必须记录审计事件，并显示动作影响范围。
