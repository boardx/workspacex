# 原始需求（细化）— UC-23.4 治理与发布（可见范围 · 谁能改 · 责任人与复核周期）

> 所属：M23。口径见 `00-index.md`。优先级 **P0**；估点 **[待确认]**。
>
> **这是本模块横切性最强的一份 UC。** 它是「六种资产完全一样」那句话的落点。

## R1 概览

- **Use Case ID / 名称**：UC-23.4 / 治理与发布
- **Actor**：**能力维护者**（填三项、发起发布）、**领域负责人**（全组织可见时联签）、
  **资产负责人**（被指定的那个人）
- **目标**：在任何资产发布之前，把三件事定下来——原型逐字：
  「这一步**六种资产完全一样**：**谁能用、出问题谁负责、什么时候重新检查**。
  **三个都填完才能发布**。」`[原型 @16.611M]`
- **系统边界**：向导第 3 步、发布前检查清单、发布方式（直接 / 灰度）。
- **六种资产**：Agent / Skill / 模型 / MCP 服务器 / 画布模板 / 项目蓝本
  （`[人类截图 2026-07-30]` ＋ `AN_META` `[原型 @16.6511M]`，两份证据一致）。
  ⚠ 「完全一样」的**精确范围**待 Q-1b 裁：三项治理配置六类一致是确定的，
  「发布前检查」清单在原型里**按类型可变**（Agent 那条「四栏配置完整」是 Agent 专属）。

## R2 前置条件 / 触发条件

**前置条件**
- 资产草稿存在，且（若走社区导入）六道关无 `阻断`（`uc-23-2`）。
- 当前用户有该资产类型的维护权限。

**触发条件**
- 向导从第 2 步推进到第 3 步；或从编辑器点 `保存并发布`（`uc-23-3`）。

## R3 主流程（三项 + 一检查 + 一发布）

### 第一项 · 可见范围（三选一）`[原型 @16.611M]`

| 选项 | 副文案（原文） | 附加条件 |
|---|---|---|
| **指定团队** | 能源组 · 平台组 · **共 19 人** | 原型默认选中此项 |
| **全组织** | 48 人 · **需领域负责人联签** | ⇒ 触发联签流程（A1） |
| **仅自己 · 私有草稿** | **不进任何检索范围** | ⇒ 与 `uc-23-1` R7 规则 4 同源 |

⚠ 「共 19 人」「48 人」是**由所选团队推算出来的实时计数**，不是静态文案 → `[设计]`。

### 第二项 · 谁能改它 `[原型 @16.612M]`

chips：`负责人` · `平台组管理员` · `＋ 能源组负责人`（`＋` 表示可增）。
⇒ 这是一个**可编辑的角色/人集合**，不是单选。
⚠ `负责人 ∈ 可改集合` 是否为不变量 → **Q-9**。

### 第三项 · 责任与复核 `[原型 @16.612M]`

- **负责人**：一个人（原型实例：头像 `高` + `高琳 · 平台组`）。
- **复核周期**：三选一 `6 个月` / `12 个月` / **`24 个月`**（原型选中 24）。
- 规则文案逐字：「**到期后自动转「待复核」，仍可用但调用时会提示；30 天无人复核则降级为
  仅负责人可见。这与组织大脑里知识条目的规则一致。**」`[原型 @16.613M]`
  ⇒ 展开在 `uc-23-6`；⚠ **单一事实源见 Q-7，本 UC 与 `uc-23-6` 不各写一份周期数值**。

### 第四步 · 发布前检查 `[原型 @16.614–16.615M]`

标题右侧写「**红色项未清空时「发布」保持禁用**」，右上角计数 `1 项未完成`。
Agent 实例的四条：

| | 条目（原文） | 状态 |
|---|---|---|
| ✓ | 四栏配置完整（人格 · 能力 · 模型 · 边界） | 通过 ← **Agent 专属**，见 Q-1b |
| ✓ | 沙箱试跑至少 1 次且无阻断项 | 通过 |
| ✓ | 已指定负责人与复核周期 | 通过 ← **六类共用** |
| ✗ | 试跑里那条「重复了 Scout 的反对意见」还没处理——**改提示或标为可接受** + `[去处理]` | **红色未完成** |

⇒ 第四条证明：**`uc-23-5` 试跑台里的每一条 `!` 级发现，都会变成这里的一条待清项。**
⇒ 也证明 `提示` 级结论的第二个出口是「**标为可接受**」（`uc-23-2` A1 的待确认项在这里得到旁证）。

### 第五步 · 发布方式 `[原型 @16.616M]`

说明逐字：「**灰度到能源组 5 人试用一周，无异常再全量——比一次性铺开更容易回滚。**」
两个按钮：`直接发布` · **`灰度发布 · 5 人`**。
⚠ 向导主 CTA 的 label 逻辑 `anNextLabel: s.anStep === 3 ? "灰度发布" : "下一步"` `[原型 @16.867M]`
⇒ **灰度是主路径，直接发布是次要出口**。语义待 **Q-3**。

## R4 备选流程与异常流程

**备选流程**
- **A1 选「全组织」→ 领域负责人联签**：谁是领域负责人、联签在哪里做、多久超时，
  原型只有「需领域负责人联签」这七个字，**流程 0 命中** → `[待确认]`。
  ⚠ 这是一个完整的审批流，不能由实现者顺手发明。
- **A2 选「仅自己 · 私有草稿」**：不进任何检索范围 ⇒ 不进 embedding、不进 Context Pack、
  不出现在任何列表与搜索（与 `contracts/skills/domain.md` I-14 的四入口断言同形，复用不重造）。
- **A3 `[去处理]`**：跳回产生该红色项的地方（此例是试跑台）。
- **A4 `[存为草稿]`**：任何时刻可退出，草稿自动保存 `[原型 @16.551M]`。

**异常流程**
- **E1 三项未填全** → 「发布」禁用。⚠ 原型明写「三个都填完才能发布」，
  但**未画未填态**（三项在截图里都已填）→ `[设计]`。
- **E2 有红色项** → 「发布」禁用（原型明写）。**两条禁用条件是与的关系**。
- **E3 指定团队后该团队被解散 / 负责人离职** → 资产的可见范围与负责人悬空。
  原型 0 命中 → `[待确认]`。⚠ 这与 `uc-23-6` 的降级终态「仅负责人可见」直接相关：
  **负责人不存在时降级到谁**，没有答案就是一个能让资产彻底不可达的洞。
- **E4 灰度发布后一周到了、没人管** → 原型说「一周试用，无异常再全量」，
  但没说到期不管会怎样 → `[待确认]`（并入 Q-3）。
- **E5 权限不足**：非维护者进不到第 3 步（入口在第 1 步就没有）。
- **E6 六道关有阻断却直接调发布接口** → 必须拒绝并写审计
  （复用 `contracts/skills/usecases.md` 的 `GATE_NOT_PASSED`，不新建错误码）。

## R5 权限与可见性

- **能力维护者**：填三项、处理红色项、发起发布（`直接发布` / `灰度发布`）。
- **领域负责人**：可见范围选「全组织」时的联签人。`[待确认]` 他是一个角色还是按资产类型分。
- **资产负责人**：被指定后承担复核责任（`uc-23-6`）；⚠ 被指定时是否需要**他本人同意**，
  原型 0 命中 → `[待确认]`。指定一个不知情的人当负责人，会让 `uc-23-6` 的 30 天倒计时
  从一开始就注定超时。
- **明确无权**：引导师 / 组长 / 组员看不到本屏。
- **明确无权**：方法论审核人 / 安全评审人**不能**代替维护者填这三项
  ——那会变成审核人给自己批的东西设可见范围。

## R6 后置条件 / 不包含

**后置条件**
- 资产带上一份**治理记录**：`{可见范围, 可改集合, 负责人, 复核周期, 发布方式, 发布人, 发布时间}`。
- 复核到期时间 = 发布时间 + 复核周期（⇒ `uc-23-6` 的计时起点）。
- 发布后资产在可见范围内的成员的检索/列表/绑定面板里出现。

**不包含**
- **复核到期后的行为**（`uc-23-6`）。
- **试跑本身**（`uc-23-5`）——本屏只消费它的结论。
- **六类资产各自的发布语义**：skill 发布 ⇒ 产生一个不可变 `SkillVersion`
  （`contracts/skills/domain.md` I-2/I-6，**已签核**）；本 UC 不重定义版本语义。
- **MCP 的逐工具授权与 14 天隔离期** —— 归 `agent-runtime`（F52–F54，已签核）。
  本 UC 只负责 MCP 作为六种资产之一时的**三项治理配置**。两者的关系见 **Q-6**。

## R7 业务规则

1. **三个都填完才能发布**（原型原文）。
2. **红色项未清空时「发布」保持禁用**（原型原文）。1 与 2 是**两条独立的禁用条件**。
3. **「仅自己 · 私有草稿」不进任何检索范围**（原型原文）。
4. **六种资产的三项治理配置一致**（`[人类截图]` + 原型；精确边界见 Q-1b）。
5. **复核周期的规则与组织大脑知识条目一致**（原型原文）⇒ **单一事实源**，见 Q-7。
   ⚠ 本 UC **不写** `6/12/24 个月` 与 `30 天` 的语义，只写「有这三档、有这条规则」；
   语义与数值的家在 `uc-23-6` + 阈值登记表。
6. **发布前检查的每一条都必须可追回它的来源**（第四条来自试跑台的一条 `!` 发现）
   ——检查清单是**派生视图**，不是一张手写的固定清单。

## R9 非功能约束

- **安全**：可见范围的收敛必须**立即生效于全部消费面**（检索、Context Pack、embedding 相似度、
  列表、绑定面板）——这是 phase-00 `design-coherence.md` 的 **X-1 交叉约束**（六条路径共用同一判定函数），
  本 UC **是那条约束的消费者，不重新实现**。
- **可观测**：发布是一次不可逆的组织级动作，必须写审计（谁、什么资产、什么范围、什么时间）。

## R11 切分提示

- 建议切四个 feature：① 三项治理配置（**这是本模块最该先做的一件**，六类共用）；
  ② 发布前检查（派生清单 + 双禁用条件）；③ 发布动作与审计；④ 灰度发布（依赖 Q-3）。

## R12 AI Ready 验收线索

1. 第 3 步显示五块，标题与副标题文案与原型逐字一致。
2. 可见范围三选一，选「指定团队」时人数由所选团队实时推算（改选团队人数跟着变）。
3. 选「全组织」时出现「需领域负责人联签」的提示，且发布走联签路径。
4. 选「仅自己 · 私有草稿」发布后：该资产在**其他任何账号**的列表 / 搜索 / 绑定面板 /
   Context Pack 四处 0 命中。
5. 「谁能改它」是集合、可增可减；改完后非集合内账号在编辑器里只读（`uc-23-3` R12-13）。
6. 复核周期三档恰为 `6 / 12 / 24 个月`，构造第四档被拒。
7. 三项任一未填 → 「发布」禁用；三项填全但有红色项 → 仍禁用；两条都清 → 可发布。
8. 试跑台产生一条 `!` 级发现 → 发布前检查立刻多一条红色项；处理掉 → 红色项消失。
9. `[去处理]` 跳到产生该红色项的位置。
10. 六种资产类型各走一遍第 3 步，**三项治理配置的字段与取值集合完全相同**（规则 4 的直接断言）。
11. 六道关有阻断时直调发布接口 → `GATE_NOT_PASSED` + 审计留痕。
12. 发布后 `复核到期时间 = 发布时间 + 复核周期`（可断言）。
13. 发布写审计：谁、什么资产、什么可见范围、什么时间，可查。
14. 灰度发布 · 5 人后，第 6 个人看不到/看到的是什么 —— **按 Q-3 裁决结果断言**（未裁前不写验收）。
