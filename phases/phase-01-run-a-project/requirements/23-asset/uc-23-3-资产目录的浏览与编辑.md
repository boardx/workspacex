# 原始需求（细化）— UC-23.3 资产目录的浏览与编辑（文件树 ＋ 编辑器）

> 所属：M23。口径见 `00-index.md`。优先级 **P0**；估点 **[待确认]**。
>
> ⚠ 这是人类 2026-07-30 原话里两件事之一：「需要可以看到**项目文件的浏览和编辑**功能」。
> ⚠ **Q-0**：D-06 排除的是「多文件**可执行**包」；本 UC 的目录浏览与编辑
> **不涉及执行**（执行在 `uc-23-5`），故 `OPEN-QUESTIONS.md` 的 Q-0 推荐方案 C 把它留在 phase-1。

## R1 概览

- **Use Case ID / 名称**：UC-23.3 / 资产目录的浏览与编辑
- **Actor**：**能力维护者**
- **目标**：让一个资产**以目录的真实形态**被看见和修改——不是一个表单里的几个字段，
  而是一棵文件树加一个编辑器。原型对这件事的定性逐字为
  「一个 skill 是**一个目录**：`SKILL.md` ＋ 参考资料 ＋ 可选脚本」`[原型 @15.690M]`。
- **系统边界**：资产目录存储、文件树、文本编辑器（编辑/预览双模）、保存与发布入口。
- **核心不变量来源**：文件树底部提示逐字「**右键改名／删除 · 目录结构就是发布出去的结构**」
  `[原型 @15.710M]`。

## R2 前置条件 / 触发条件

**前置条件**
- 存在一份资产（草稿或已发布版本），且当前用户在其「谁能改它」集合内（`uc-23-4`）。
- 该资产是**目录形态**的类型。⚠ 原型只对 **Skill** 与 **Agent** 画了目录形态
  （`SK_FILES`/`SK_TREE` `[原型 @16.668M]`、`AG_FILES`/`AG_TREE` `[原型 @16.653M]`）；
  模型 / MCP / 画布模板 / 蓝本四类**是不是目录**，原型 0 命中 → `[待确认]`。

**触发条件**
- 从资产列表点该行的 `[编辑]`（原型 Skill 列表每行都有 `[编辑]` `[原型 @15.688M]`）。
- 或 `uc-23-1` 走「从空白开始」路径后直接落进编辑器。

## R3 主流程

1. 系统打开编辑器屏，顶栏逐字为 `‹ Skill 列表` · **资产名** · slug chip · 状态 chip ·
   `▶ 试跑` · `保存并发布` `[原型 @15.704M]`。
   - Skill 实例：`MECE 假设拆解` · `mece-decomposition` · `● 有未保存改动`
   - Agent 实例：`‹ Agent 列表` · `Ava` · model chip `claude-opus-4.6` · `有未保存改动` `[原型 @15.66xM]`
   - ⚠ Skill 的第二个 chip 是 **slug**，Agent 的第二个 chip 是 **model**——
     **两类的 chip 语义不同**，不是同一个字段 → `[设计]`，需在 domain 里建模成「类型专属徽标」。
2. 左栏渲染**文件树**，每行：缩进导引线、类型徽标、文件名、大小。
   目录行只有 `▾` 与名字，无大小 `[原型 @16.6515M `fileNode`]`。

   | 资产 | 树（原型实存，逐字） |
   |---|---|
   | Skill `SK_TREE` | `SKILL.md` 2.1k · `references/`（`output-schema.md` 0.8k, `question-bank.md` 1.4k）· `assets/`（`tree-template.canvas.md` 0.6k）· `scripts/`（`validate.py` 1.2k） |
   | Agent `AG_TREE` | `AGENT.md` 1.8k · `prompts/`（`system.md` 3.2k, `reflection.md` 0.9k）· `tools/`（`tools.json` 1.1k）· `evals/`（`regression.jsonl` 2.6k） |

3. 系统按扩展名给文件**徽标与配色**（`FILE_BADGE` `[原型 @16.6512M]`，这是实存逻辑不是装饰）：
   `.py → PY` · `.json/.jsonl → { }` · `.yaml/.yml → YM` · **其余一律 `MD`**。
   ⇒ **未知扩展名不报错，落到 MD**。
4. 树底部固定提示：「右键改名／删除 · **目录结构就是发布出去的结构**」`[原型 @15.710M]`。
5. 用户点某个文件 → 右栏加载其内容，该行高亮（`bg #EFEEE9`、字重 500）。
6. 右栏顶部：文件路径 + `编辑` / `预览` 双模切换 + 元信息 + `[格式化]` `[原型 @15.710M]`。
7. 编辑器带**行号**，语法着色按行首字符判定（`skLineFg`：`#` 标题、`---` frontmatter、
   `-`/数字列表、`"""`/`import`/`def`/`if` 代码 `[原型 @16.669M]`）。
8. 底部状态栏：`UTF-8 · Markdown · 空格缩进 2` 形态的元信息 + `未保存` 指示 + `[保存]`
   `[原型 @15.710M]`。
9. 用户改动 → 顶栏 chip 变 `● 有未保存改动`；点 `保存并发布` → 走 `uc-23-4` 的发布前检查。

### 根文件的 frontmatter（两类的实存结构）

- `SKILL.md`：`name` / `description` / `allowed-tools: Read, Grep, WebSearch` `[原型 @16.668M]`
- `AGENT.md`：`name` / `role` / `model` / `skills: [...]` / `memory: project + org(verified-only)`
  `[原型 @16.653M]`

⚠ **`AGENT.md` 的 `skills:` 里写的是 slug**（`mece-decomposition` 等），
而 `SKILL.md` 的 slug 是顶栏那个 chip ⇒ **两者必须是同一个命名空间**，否则引用解析不了 → `[设计]`。

## R4 备选流程与异常流程

**备选流程**
- **A1 预览模式**：Markdown 渲染。`.py` / `.json` 这类非 Markdown 文件预览什么，原型未画 → `[待确认]`。
- **A2 新建文件 / 新建文件夹**：「随时新建文件和文件夹」`[原型 @15.690M]` 有文字依据，
  但**界面上没有新建入口**（树底部只提到右键改名/删除）→ `[设计]`，入口待补。
- **A3 右键改名 / 删除**：文字依据在 `[原型 @15.710M]`，**无 handler**（Q-5）。
- **A4 `[格式化]`**：无 handler，格式化规则无依据 → `[待确认]`。

**异常流程**
- **E1 删除根文件**（`SKILL.md` / `AGENT.md`）→ **必须拒绝**。根文件是类型识别的依据
  （第 01 关「SKILL.md 格式合法」），删掉它资产就不再是一个可识别的资产。`[设计]`。
- **E2 frontmatter 被改坏**（YAML 不可解析 / 必填缺失）→ 保存时拦截并逐条报错，
  **不入库**（沿用 `contracts/skills/usecases.md` 的 `CONTRACT_VALIDATION_FAILED`，不新建错误码）。
- **E3 `AGENT.md` 的 `skills:` 引用了不存在或已停用的 slug** → 保存时报可解析但不可解析引用；
  ⚠ 是阻断还是警告，无依据 → `[待确认]`。
- **E4 未保存就离开** → 必须拦截确认。原型有 `● 有未保存改动` 这个状态但**未画拦截** → `[设计]`。
- **E5 并发编辑**（两人同时改同一资产）→ 原型 0 命中 → `[待确认]`。
  ⚠ 这不是可以由实现者默默选「后写覆盖」的事。
- **E6 文件过大 / 二进制文件**（有人把图片拖进 `assets/`）→ 编辑器该怎么表现，无依据 → `[待确认]`。
  ⚠ 与第 01 关的「无二进制附件」检查相关：**如果编辑器允许放二进制，六道关第 01 关就会自相矛盾**。
- **E7 权限不足**：不在「谁能改它」集合内的人 → 编辑器**只读**（能看树、能看内容、
  不能改、无 `[保存]`）。⚠ 原型未画只读态 → `[设计]`。

## R5 权限与可见性

- **能力维护者（在「谁能改它」集合内）**：全部读写。
- **可见范围内的其他成员**：`[待确认]` 能不能只读浏览目录。
  这一条影响很大——「可见范围 = 能调用」与「可见范围 = 能看源码」不是一回事，
  外部导入的资产尤其（作者不一定同意组织内全员读源码）。
- **可见范围外的成员**：资产**不存在性**都看不到（沿用 `contracts/skills/domain.md` I-14，不重造）。
- **负责人**：见 `OPEN-QUESTIONS.md` Q-9，`负责人 ∈ 可改集合` 是否为不变量待裁。

## R6 后置条件 / 不包含

**后置条件**
- 资产目录内容被修改，且**未保存的改动不影响线上**（这条与 `uc-23-5` 共用同一条规则，见 R7）。
- 保存并发布 ⇒ 进入 `uc-23-4` 的发布前检查，**不直接生效**。

**不包含**
- **试跑**（`uc-23-5`）——顶栏那个 `▶ 试跑` 是入口，行为在那份 UC。
- **发布**（`uc-23-4`）。
- **版本与 diff**：原型的编辑器**没有版本历史、没有 diff、没有回滚**（0 命中）。
  已发布资产的版本语义在 `03-skill/uc-3-4`（已签核），本模块不重造；
  但「目录形态的资产如何版本化」是一个**该有而没有**的洞 → `[待确认]`。

## R7 业务规则

1. **目录结构就是发布出去的结构**（原型原文）——编辑器里看到的树，
   与发布后被运行时装载的文件集合**必须逐一相等**。这是本 UC 的核心不变量，
   它排除了「编辑器是个视图、真正发布的是另一份打包产物」这种实现。
2. **未保存的改动不进线上**：顶栏 `● 有未保存改动` 与试跑台「用当前未保存的提示词跑，
   **不影响线上**」`[原型 @15.666M]` 是同一条规则的两处表达 ⇒ 必须**一处实现**。
3. **根文件不可删**（E1）。
4. **未知扩展名不报错**（`FILE_BADGE` 的 fallback）。
5. `[待确认]` 目录深度、文件数、单文件大小的上限——原型的两棵树都恰好是
   「1 根文件 + 3 个一级目录 + 每目录 1–2 个文件」，看不出是不是上限。

## R8 界面线索

- **屏**：编辑器屏（左树 + 右编辑器），Skill 与 Agent 各一个实例。
- **原型出处**：`[原型 @15.704–15.712M]`（编辑器界面）、`[原型 @16.653M]`（`AG_FILES`/`AG_TREE`）、
  `[原型 @16.668M]`（`SK_FILES`/`SK_TREE`）、`[原型 @16.6512M]`（`FILE_BADGE`/`fileNode`）。
- **截图目录**：`ui-preview/asset-governance/`。
- ⚠ 缺态（需 ui-prototyper 补）：只读态、新建文件/文件夹入口、右键菜单、
  预览模式（尤其非 Markdown 文件）、未保存拦截、frontmatter 报错态。

## R9 非功能约束

- **性能**：一棵树最多多少文件仍要求秒开 → 无依据 `[待确认]`。
- **安全**：编辑器保存的内容**必须重跑第 02 关安全扫描**——否则六道关只管导入那一刻，
  之后在编辑器里加一段提示注入就绕过了全部检查。⚠ 原型未写这条，但不写它
  整个六道关是可绕过的 → `[设计]`，**强烈建议人类确认**。
- **兼容**：编辑器只处理 UTF-8 文本；二进制见 E6。

## R10 已知约束 / 依赖

- 依赖 `03-skill` 的 `Skill` 实体（`fileCount` 字段：`contracts/skills/domain.md` 逐字写
  「phase-2 多文件包预留；**phase-1 恒为 1**（不得据此实现打包解析）」）
  ⚠ **本 UC 与这条已签核注释直接冲突**——目录形态就是多文件。并入 Q-0。
- 依赖 `uc-23-4` 的「谁能改它」集合做权限判定。

## R11 切分提示

- 建议切三个 feature：① 目录模型 + 文件树渲染（含徽标/大小/高亮）；
  ② 编辑器（编辑/预览/行号/着色/保存）；③ 目录变更操作（新建/改名/删除 + 根文件保护）。
- ③ 最容易被跳过，但它是 `目录结构就是发布出去的结构` 唯一能被证伪的地方。

## R12 AI Ready 验收线索

1. Skill 编辑器的文件树逐字等于 `SK_TREE`（5 文件 3 目录），大小与 `SK_FILES` 一致。
2. Agent 编辑器的文件树逐字等于 `AG_TREE`（5 文件 3 目录）。
3. `.py` 显示 `PY` 徽标、`.json`/`.jsonl` 显示 `{ }`、`.yaml` 显示 `YM`、
   一个 `.txt` 文件显示 `MD`（fallback 不报错）。
4. 目录行不显示大小；文件行显示大小。
5. 点文件 → 右栏内容变、该行高亮；点另一个 → 高亮转移（同一时刻至多一行高亮）。
6. `编辑` / `预览` 可切换，且预览渲染的是当前文件的当前内容（含未保存改动）。
7. 改动后顶栏出现 `有未保存改动`；保存后消失。
8. 有未保存改动时刷新/离开 → 被拦截。
9. 删除 `SKILL.md` → 被拒。
10. 把 `SKILL.md` 的 frontmatter 改成非法 YAML → 保存被拒并逐条列原因，且**库里内容未变**。
11. 发布后从运行时读到的文件集合，与编辑器树里的集合**逐一相等**（规则 1 的直接断言）。
12. 未保存的改动**不**改变任何线上调用的行为（规则 2）。
13. 不在「谁能改它」集合内的账号打开编辑器 → 只读，无 `[保存]`。
14. 可见范围外的账号直接访问该资产编辑器 URL → 404（不是 403）。
15. 在编辑器里加入一段已知的提示注入样本并保存 → 被第 02 关拦下（R9 的 `[设计]` 条，若人类确认）。
