# 原始需求（细化）— UC-23.8 后台外壳、左栏 IA 与组织额度条

> 所属：M23。口径见 `00-index.md`。优先级 **P0**；估点 **8**。
>
> **本 UC 是 2026-07-30 追加的**，起因是人类问：「**为什么在管理后台看不到项目蓝本**」。
> 它回答的问题是：**六种资产在后台里的公共宿主，由谁负责。**
> 答案在此之前是「**没人**」——这正是缺两项而无任何门控会红的原因。

## R1 概览

- **Use Case ID / 名称**：UC-23.8 / 后台外壳、左栏 IA 与组织额度条
- **Actor**：**组织管理员**（主要使用者）、**平台组管理员**
- **目标**：让六种资产**在后台都有位置**，并且这个位置的完整性是**可被机械验证的**——
  而不是靠有人恰好发现「怎么少了一项」。
- **系统边界**：后台路由外壳、左栏导航（分组 + 项 + 计数）、组织头部与额度条、数据总览入口。
- **明确不含**：六类资产各自的管理屏内容（那些在各自的束里）。

## R2 前置条件 / 触发条件

**前置条件**
- 用户已登录并属于某个组织，且具备后台访问权限。
- ⚠ 「后台访问权限」是一个权限还是按模块分，见 `uc-23-1` R5 的待确认项。

**触发条件**
- 用户进入 `/admin`（总览）或 `/admin/<module>`。

## R4 备选流程与异常流程

**备选流程**
- **A1 `生成月度报告`**：`AD_META.dashboard` 的第三个元素是 CTA 文案 `生成月度报告`
  `[原型 @16.6703M]`。⚠ 行为 0 命中 → `[待确认]`；且它更像 17-gov 的东西（Q-12）。
- **A2 某类资产 0 条**：左栏那一项仍然显示（计数为 0），**不隐藏**。
  ⚠ `[设计]`，但这条很重要：隐藏空模块 = 新组织进来看到一个残缺的后台，
  且会重现「看不到项目蓝本」这个原始投诉。

**异常流程**
- **E1 某类资产的计数取不到**（后端故障）→ 显示为「—」而不是 `0`。
  `0` 与「取不到」是两件事，混同会让人以为资产被清空了。`[设计]`。
- **E2 用户对某模块无权限** → 该项**是否显示** → `[待确认]`。
  ⚠ 两种做法都有道理（隐藏 = 干净；显示但禁用 = 知道存在、知道要申请），
  但不能由实现者随手选，因为它决定了「看不到项目蓝本」到底是缺项还是没权限——
  **正是本 UC 起因的那个歧义**。
- **E3 直接访问不存在的 `/admin/<module>`** → 404。
  ⚠ 已建成的 `generateStaticParams` 只产出 `SCREENS` 的键（6 个），
  故 `/admin/blueprint` 现在是 404 —— **这就是人类看不到项目蓝本的直接原因**。
- **E4 额度用尽**（`78%` → `100%`）→ 额度条的表现与是否阻断。
  ⚠ 归 `agent-runtime` 的三级降级阈值（`组织 85% / 团队 90% / 个人 95%`，
  「达阈值时**降级到更便宜的模型，不硬停**」`[原型 @16.601M]`）。
  **本 UC 只显示，不定义降级规则** —— 那是已签核的束的事。

## R5 权限与可见性

- **组织管理员**：可访问全部模块。
- **平台组管理员**：可访问 AI 能力组的六项（源维护见 `uc-23-7`）。
- **引导师 / 组长 / 组员 / 顾问**：**不能访问 `/admin` 任何路径**。
  ⚠ 例外：「我的本地」（F16）——它是单人组织，权限模型可能不同 → `[待确认]`，
  但那属 F16，本 UC 不改它。
- **组织额度条**：`[待确认]` 是否对非管理员可见（成员大概需要知道额度快用完了，
  但那可能有另一个入口）。
- ⚠ **管理员读项目内容要留痕**：已建成的 `ADMIN_ACCESS_LOGS` / `ADMIN_PROJECT_ACCESS_COUNT`
  说明这条规则已存在（属 `org-admin` 束，已签核）。本 UC 不重定义。

## R7 业务规则

1. **六种资产在左栏必须齐全**——这是本 UC 的**唯一核心不变量**，
   也是本 UC 存在的全部理由。它必须写成**机械门控**：
   「左栏 AI 能力组的项集合 ＝ 六种资产类型集合」，双向相等。
   ⚠ 只写单向（每一项都是合法资产）挡不住缺项——**缺项恰恰是发生过的那个故障**。
   本仓已有同形门控可照抄：`lint-ui-material.mjs` 的「双向集合相等 + 反证套件」。
2. **每一项都必须有可达路由**（E3 的反面）。
3. **计数是派生的，不是常量**。
4. **0 条也显示**（A2）。
5. **取不到 ≠ 0**（E1）。
6. **本 UC 只做容器**：任何一条规则只要「换成另一类资产就不成立」，就不属于本 UC
   （边界判据见 `00-index.md`）。

## R9 非功能约束

- **性能**：左栏六个计数不应产生六次串行查询（会让整个后台首屏变慢）。
- **可观测**：无。
- **兼容与降级**：某一类计数取不到时其余五类照常显示（E1），**不整栏失败**。

## R11 切分提示

- 建议切两个 feature：
  ① **左栏 IA 完整性 + 双向集合相等门控**（这一件最该先做，且是唯一能防止复发的）；
  ② 补齐画布模板与项目蓝本两项的路由与落点（依赖 Q-11 + 与两个已签核束协商）。
- ⚠ 先写门控再补项。按本仓纪律（「没有脚本的规范条目视为未落地」），
  先补两项而不建门控 = 这次修好、下次再缺。

## R12 AI Ready 验收线索

1. `/admin` 渲染组织头部：`远洋咨询 · 组织 ID org_8f21`，额度条 `78% · 4,820 万 / 6,200 万 · 还剩 6 天`。
2. 左栏「AI 能力」组的项集合与六种资产类型集合**双向相等**（规则 1，机械断言）。
3. **反证**：从资产类型集合里删掉一个（或从左栏删掉一项）→ 门控**必须报红**
   （按本仓纪律，写完门控立刻造反证）。
4. 左栏每一项的 `href` 都返回 200，无一个 404（规则 2）——**含 `项目蓝本` 那一项**。
5. 六个计数与各自资产类型的真实条目数相等（改一条资产 → 计数跟着变，规则 3）。
6. 某类资产 0 条时该项仍显示，计数为 `0`（规则 4）。
7. 某类计数查询失败时显示 `—` 而非 `0`，且其余五项照常（规则 5 + E1 + R9）。
8. 顾问/引导师/组员账号访问 `/admin` → 被拒（不是渲染一个空后台）。
9. 「我的本地」（F16）在改左栏后仍然可达、行为不变（回归断言）。
10. 左栏六个计数不产生六次串行请求（R9）。
11. 额度到 100% 时额度条的表现与 `agent-runtime` 的三级降级规则一致，
    且**本束没有第二份阈值定义**（全仓 `85/90/95` 的定义处恰 1 处）。
