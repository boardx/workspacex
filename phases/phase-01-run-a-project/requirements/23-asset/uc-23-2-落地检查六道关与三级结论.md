# 原始需求（细化）— UC-23.2 落地检查六道关与三级结论

> 所属：M23 外来资产的导入与生命周期治理。口径见 `00-index.md`。
> 元数据：优先级 **P0**；估点 **[待确认]**（Q-0 未裁）。
>
> ⚠ **Q-0**：第 **05 关沙箱试跑**正是 D-06 逐字排除的「phase-1 不做沙箱」。
> ⚠ **Q-1**：六道关的副标题挂在 `AN_META.skills` 上（「外来资产要过落地检查六道关」
> `[原型 @16.6511M]`），**没有证据说另外五类资产也走六道关**。本 UC 按「六道关属 skills
> 及其它走社区导入的类型」书写，具体适用范围待 Q-1 裁。

## R1 概览

- **Use Case ID / 名称**：UC-23.2 / 落地检查六道关与三级结论
- **Actor**：**能力维护者**（处理提示与阻断）、**方法论审核人**（第 04 关查重分歧的裁决）、
  **安全评审人**（第 02、03 关的风险与权限裁决）
- **目标**：让一份外来资产在进入组织的权限与方法体系前，逐关暴露它的问题，
  并把**不可跳过**的问题挡在发布之前。
- **系统边界**：向导第 2 步（`anIsImport` `[原型 @16.867M]`）的六关流水线、
  三级结论、查重分歧裁决面板、原文/改写对照面板。
- **屏标题**：`落地检查 · <资产名>`，副标题逐字为
  「来自 Codex 社区 · 作者 @strategyops · 4.2k stars。**导入不是上传文件，是把外来的东西放进
  我们的权限与方法体系里。六道关全过才能发布，任何一道阻断都不能跳过。**」`[原型 @16.559M]`
- **进度指示**：`4 / 6`，右侧 `已通过 · 1 项待处理` `[原型 @16.559M]`

## R2 前置条件 / 触发条件

**前置条件**
- 已有一份 provenance = `从社区导入` 的资产草稿（`uc-23-1` 后置条件）。
- 组织内**存在至少一名**方法论审核人与一名安全评审人，且**不是提交人本人**
  （沿用 `contracts/skills/domain.md` 的 I-4 / `NO_SECOND_REVIEWER`，本模块不另建一套）。

**触发条件**
- `uc-23-1` 把向导推进到第 2 步。
- 或用户从草稿列表重新进入一份未过关的草稿。

## R3 主流程（六关）

系统按序执行六关，每关给出**三级结论之一**：`通过` / `提示` / `阻断`。
原型逐关内容（`[原型 @16.560–16.561M]`，文案为原文）：

| # | 关名 | 原型结论 | 正文 |
|---|---|---|---|
| **01** | 解析与类型识别 | **通过** | 识别为 Skill · SKILL.md 格式合法 · 声明依赖 2 个工具 · 无二进制附件 |
| **02** | 安全扫描 | **通过** | 未发现提示注入模式、外部回传地址、隐藏指令。检查了 3 处 base64 片段，均为示例数据 |
| **03** | 依赖与权限核对 | **提示** | 它请求 `web_search`，但默认策略只允许通过「行业数据库」MCP 检索。建议改写为走内部 MCP，否则会绕过审计留痕 |
| **04** | 与现有资产查重 | **阻断** | 与已发布的「深度研究 · 多轮溯源」重合度 68%，但两者追问策略分歧明显。二选一：合并为一个 skill 的两种模式，或写清各自适用场景 |
| **05** | 沙箱试跑 | **进行中** | 用远洋项目的 3 段真实访谈跑评测：2 段完成，1 段进行中。当前归因正确率 0.93、耗时中位 41s |
| **06** | 发布范围与负责人 | ⚠ 见 E7 | 待第 3、4 关处理完后开放 |

1. 系统展示六关列表，每关一行：状态图标（`✓` / `!` / `×` / `·`）、序号、关名、三级结论标签、正文。
2. 系统**并发或按序**跑 01–05 关（原型未写执行顺序语义 → `[待确认]`），
   05 关可处于 `进行中` 并显示部分进度（`2 段完成，1 段进行中`）。
3. 出现 `提示` 的关 → 展开对应处置面板（第 03 关是「原文与改写对照」，见 A1）。
4. 出现 `阻断` 的关 → 展开对应裁决面板（第 04 关是「查重分歧」，见 A2），
   **在裁决前，第 3 步「治理与发布」不可进入**。
5. 全部关不为 `阻断` 且 05 关跑完 → 06 关开放 → 向导可推进第 3 步（`uc-23-4`）。

## R4 备选流程与异常流程

**备选流程**

- **A1 第 03 关 · 原文与改写对照**（`提示` 的处置）`[原型 @16.566M]`：
  系统给出一段 diff：
  ```
  － 原文    tools: [web_search]
  ＋ 改写为  tools: [mcp://data.wsx.cn/query_market]
  ```
  出口一个：`[采纳改写]`。
  ⚠ **`[采纳改写]` 无 handler**（Q-5）；且原型**没有画「不采纳」的出口**——
  提示级结论既然不阻断，就必须存在「知道了，就这样发布」的路径 → `[待确认]`。
  若不采纳，第 03 关的结论如何留痕（原型第 3 步的发布前检查有一条红色项写
  「……还没处理——**改提示或标为可接受**」`[原型 @16.615M]`，
  ⇒ **「标为可接受」是提示级结论的第二个出口**，但该出口在第 2 步没画）。

- **A2 第 04 关 · 查重分歧裁决**（`阻断` 的处置）`[原型 @16.564–16.565M]`：
  标题逐字为「第 04 关 · **查重分歧，需要你判断**」。并排两栏：

  | | 内容（原文） |
  |---|---|
  | **已有 · 深度研究 · 多轮溯源** | 先拆问题再并行检索，强调交叉验证与引用完整性。**调用 4,120 次，满意度 94%** |
  | **待导入 · Jobs-to-be-done** | 从「用户想完成什么任务」切入追问，弱化事实核查，强调动机还原。**无历史数据** |

  三个出口：`[合并为两种模式]` / `[分别保留 · 写清适用场景]` / `[放弃导入]`。
  ⚠ 三个都无 handler（Q-5）。
  - `合并为两种模式` ⇒ 结果是**一个** skill 的两个模式，导入方**不产生新资产**
    ——它会改到已发布资产，因而**必须走该资产自己的版本与审核流程**（`03-skill/uc-3-4`）→ `[设计]`。
  - `分别保留 · 写清适用场景` ⇒ 强制填写两个资产各自的适用场景，**填完才解除阻断** → `[设计]`。
  - `放弃导入` ⇒ 草稿终止；⚠ 是删除还是留痕归档，无依据 → `[待确认]`。

- **A3 第 05 关仍在跑**：允许用户离开、回来看结果；不阻塞其余关的处置。`[设计]`。

**异常流程**

- **E1 第 01 关失败**（格式非法 / 有二进制附件 / 声明依赖不可解析）→ `阻断`，
  后续各关**不再执行**（在类型都识别不出时跑安全扫描没有意义）。`[设计]`，原型未画失败态。
- **E2 第 02 关判定为拒绝**（真的发现提示注入 / 外部回传地址 / 隐藏指令）→ `阻断`，
  且**不可由维护者自行处置**，必须安全评审人裁决。
  ⚠ 与 `contracts/skills/domain.md` 的 `SecurityScanResult.verdict ∈ {pass, risk-pending-confirm, reject}`
  三态**必须复用同一个对象**，不得另建 → 见 R7 规则 4。
- **E3 第 03 关请求的 MCP 工具组织内不存在**（不只是策略不允许，是根本没接）
  → 结论应为 `阻断` 而非 `提示`（无法改写成一个不存在的端点）→ `[设计]`。
- **E4 第 04 关查到多个重合资产**（不止一个）→ 原型只画了 1v1 并排。多对的界面无依据 → `[待确认]`。
- **E5 第 05 关沙箱试跑失败/超时** → 结论、能否重跑、重跑几次，全部无依据 → `[待确认]`。
- **E6 第 05 关跑出的指标低于及格线** → **及格线无依据**（Q-8）。
  ⚠ 不得自行设定 0.93 为及格线——那是原型的示例结果，不是阈值。
- **E7 第 06 关的显示自相矛盾**：原型图标 `✓`、标签 `通过`，正文却写「待第 3、4 关处理完后开放」，
  且顶部计数 `4/6` 与之相加对不上 → **Q-4**。
- **E8 六关中途来源被撤**（社区源凭据过期 / 上游仓库删除）→ 已跑完的关的结论是否仍有效、
  能否继续 → 无依据 → `[待确认]`。
- **E9 权限不足**：维护者能看到 `阻断` 的存在与原因，但**不能**自行解除需要审核人裁决的阻断。
  界面上该出口显示为「等待 <职能> 裁决」而不是禁用按钮（`[设计]`，与 R5 一致）。

## R5 权限与可见性

- **能力维护者**：可查看全部六关结论、可处置 `提示`、可在第 04 关**提交**三选一的主张。
  **不能**自行把任何 `阻断` 改成通过。
- **安全评审人**：裁决第 02 关的 `reject` / `risk-pending-confirm`、第 03 关的权限越界。
  **不能**裁决第 04 关的方法分歧（职能错配 → `REVIEWER_FUNCTION_MISMATCH`，
  沿用 `contracts/skills/usecases.md` 的既有错误码，本模块不新建）。
- **方法论审核人**：裁决第 04 关的查重分歧。**不能**裁决第 02、03 关。
- **提交人 ≠ 审核人**（I-4，既有不变量，本模块复用）。
- **其它角色**（引导师/组长/组员）：**看不到落地检查屏**。
- `[待确认]` 第 04 关的三个出口，维护者是**提交主张**还是**直接决定**。
  原型标题写「需要**你**判断」，那个「你」是谁没有依据。

## R6 后置条件 / 不包含

**后置条件**
- 草稿带上一份**六关结论记录**：每关 `{关号, 关名, 结论三级值, 正文, 判定时间, 判定依据}`。
- 若有 `提示` 被处置：留下处置动作（采纳改写 / 标为可接受）与**处置人**。
- 若有 `阻断` 被解除：留下裁决记录（裁决人、职能、理由、时间）。
- 06 关开放 ⇒ 允许进入第 3 步。

**不包含**
- **第 3 步的三项治理配置本身**（`uc-23-4`）——但 06 关的通过条件与它同源（Q-4 推荐 C）。
- **试跑台**（`uc-23-5`）：第 05 关的「沙箱试跑」是**导入流水线里的一关**，
  试跑台是**编辑器里的一个工具**。⚠ 两者是否共用同一套执行器，无依据 → `[待确认]`。
- **既有 skill 的双门禁**（安全扫描 + 方法论审核，`03-skill/uc-3-1`）——本模块**复用**它，不重造。

## R7 业务规则

1. **六道关全过才能发布，任何一道阻断都不能跳过**（原型原文，本 UC 的核心不变量来源）。
2. **三级结论恰三值**：`通过` / `提示` / `阻断`。`进行中` 是**执行状态**不是结论（原型第 05 关
   同时用了「进行中」这个词做状态标签 → 状态与结论是两个字段，见 `domain.md`）。
3. **提示不阻断，但必须留下处置痕迹**：由第 3 步发布前检查那条红色项
   「改提示或**标为可接受**」`[原型 @16.615M]` 反证——未处置的提示会在发布前检查里变成红色项。
4. **安全扫描结论对象复用 `03-skill` 的 `SecurityScanResult`**（三态 + 风险项逐条留痕），
   **不得在本模块再定义一套三态**。这是「同一事实不得声明在两处」的直接适用。
5. **查重不用相似度打分做聚合判据**——注意 `contracts/skills/domain.md` 的 **O-35**
   裁决是「聚合用结构性判据，不用相似度打分」，而第 04 关**显式给了一个 68% 的重合度**。
   ⚠ 这两件是否同一件事（O-35 管的是改进建议聚合，第 04 关管的是资产查重）
   → `[待确认]`，需在阶段一致性复核里查。
6. **来源决定是否走六道关**（`uc-23-1` R7 规则 1）：不是所有草稿都过六道关。

## R9 非功能约束

- **性能**：六关总时长上限、05 关沙箱试跑的单次超时 → 无依据 `[待确认]`。
- **安全**：第 02 关未通过前，材料**不得被任何检索、embedding、模型调用消费**——
  第 05 关沙箱试跑本身要执行材料，因此 **02 关必须严格先于 05 关**（`[设计]`，
  这是「并发执行」在安全上的一个硬约束，与 R3 步骤 2 的待确认项相关）。
- **可观测**：每关的判定依据必须可重放（给的是「检查了 3 处 base64 片段」这种具体计数，
  说明结论正文是**由检查产生的**而不是模板文案）。

## R10 已知约束 / 依赖

- 依赖 `03-skill` 的 `SecurityScanResult` / `ReviewRecord` / `ReviewerFunction` 三个既有值对象。
- 依赖 `21-mcp` 的 MCP 工具目录（第 03 关要判断「改写成哪个内部 MCP」）。
- 依赖 `20-model`（第 05 关沙箱试跑要选模型）。
- ⚠ **Q-0**（沙箱）、**Q-1**（六道关适用范围）、**Q-8**（各关阈值）三条未裁前不可生成 feature。

## R11 切分提示

- 建议**每关一个 feature**（六关的实现体量差异极大：01/02 关有既有实现可复用，
  04 关要一个查重引擎 + 一个裁决面板，05 关要沙箱），
  另加一个「流水线壳 + 三级结论 + 阻断门」的 feature。
- 优先级：流水线壳 > 01 > 02 > 03 > 04 > 06 > 05（05 依赖 Q-0）。

## R12 AI Ready 验收线索

1. 第 2 步展示恰好六关，序号 01–06、关名与原型逐字一致。
2. 三级结论只可能是 `通过`/`提示`/`阻断` 三值；构造第四个值被拒。
3. 顶部进度分子 ＝ 结论为 `通过` 的关数，分母恒为 6，且与逐关状态一致（Q-4 修好后应自洽）。
4. 存在任一 `阻断` 时，「下一步」按钮禁用且第 3 步不可达（直接改路由也进不去）。
5. `提示` 不阻断：只有 03 关为 `提示`、其余通过时，可进入第 3 步。
6. 第 04 关 `阻断` 展开并排面板，左栏带调用次数与满意度、右栏标「无历史数据」。
7. 三个出口各自的后置：`分别保留` 要求填两个适用场景，未填不解除阻断；
   `放弃导入` 后草稿不再出现在待处理列表。
8. 第 03 关展开 diff，`－ 原文` / `＋ 改写为` 两行内容与草稿实际内容一致（不是写死的示例）。
9. 采纳改写后，草稿里的 `tools:` 字段真的变了（去编辑器里能看到，`uc-23-3`）。
10. 未处置的 `提示` 会在第 3 步「发布前检查」里出现为**红色未完成项**。
11. 安全扫描判 `reject` 时，维护者本人无法解除；以安全评审人身份可以。
12. 以方法论审核人身份裁决第 02 关 → 被拒 `REVIEWER_FUNCTION_MISMATCH`。
13. 提交人 ＝ 裁决人时被拒 `SELF_REVIEW_FORBIDDEN`。
14. 02 关未通过时，05 关不启动（R9 的硬约束）。
15. 每关结论都能取到 `{判定时间, 判定依据}`，且重放判定得到同样结论。
