## R1 概览

- **Use Case ID / 名称**：UC-23.1 / 选择资产来源并起草导入
- **Actor**：**能力维护者**（发起导入的人，原型示例是「高琳 · 平台组」`[原型 @15.691M]`）
- **目标**：把一个外部或内部来源的资产变成一份**草稿**，并据来源决定它后面要走哪些检查。
  原型对这件事的定性逐字为：「**导入不是上传文件，是把外来的东西放进我们的权限与方法体系里**」
  `[原型 @16.559M]`。
- **系统边界**：三步向导的**第 1 步**（`1 来源 — 2 配置 — 3 治理与发布` `[原型 @16.551M]`）、
  社区源目录、类型自动识别、草稿存储。
  第 2 步归 `uc-23-2`，第 3 步归 `uc-23-4`，源目录的维护归 `uc-23-7`。
- **核心数据对象**：资产草稿、来源路径（provenance）、资产类型、社区源、用法沉淀候选。

### 六种资产（本模块横切的对象集合）

`[原型 @16.6511M]` 的 `AN_META` 是这个集合的**权威定义**，六个键：

| 键 | 向导标题 | 副标题 | 名词 |
|---|---|---|---|
| `agents` | 新建 Agent | 人格 ＋ 能力 ＋ 模型 ＋ 边界 · 发布前必须试跑 | Agent |
| `skills` | 导入 Skill | 外来资产要过落地检查六道关 | Skill |
| `models` | 接入模型 | 端点与凭据 · 能力探测 · 成本与路由 | 模型 |
| `mcp` | 添加 MCP 服务器 | 连接 ＋ 逐工具授权 ＋ 隔离期 | 服务器 |
| `canvasadmin` | 新建画布模板 | 分区结构 ＋ 围栏语法绑定 | 画布模板 |
| `blueprint` | 新建项目蓝本 | 环节骨架 ＋ 三角色任务 ＋ 默认配置 | 蓝本 |

⚠ `[原型]` 里**只有五种**有第 2 步实现（`anIsImport/anIsAgent/anIsMcp/anIsModel/anIsCv`），
`blueprint` 被 `anOpenFn` 改道进另一个编辑器、**不走三步向导** `[原型 @16.867M]`。
这与「六种资产完全一样」的断言不一致 → **Q-1**。

## R2 前置条件 / 触发条件

**前置条件**
- 用户已登录，且在**后台**（`nav: admin`）拥有对应资产类型的维护权限（R5）。
- 走「从社区导入」时，目标源必须是**已连接且上次同步成功**的源（`uc-23-7`）。
- ⚠ **不**要求组织已有任何同类资产——空库也能导入。

**触发条件**
- 在后台某个资产管理页点主 CTA。CTA 文案由 `AD_META` 决定 `[原型 @16.6703M]`：
  `Skill 库与市场` → `导入 Skill`；`Agent 管理` → `＋ 新建 Agent`；
  `模型管理` → `＋ 接入模型`；`MCP 服务器` → `＋ 添加服务器`；
  `画布模板` → `＋ 新建画布模板`；`项目蓝本` → `＋ 新建蓝本`。
- 或在「新建 Skill」页选「导入」/「或从市场挑一个改」`[原型 @15.690–15.692M]`。

## R3 主流程

1. **能力维护者**点资产管理页主 CTA → 系统打开三步向导，停在第 1 步，标题与副标题取自
   `AN_META[类型]`，步骤条显示 `1 来源` / `2 配置` / `3 治理与发布`，
   右上角显示 `草稿自动保存 · 14:52` 与 `[存为草稿]` `[原型 @16.551M]`。
2. 系统显示第 1 步的定性说明（**这句话是本 UC 的规则来源**）：
   「这个{资产名词}从哪里来。**来源决定后面要走的检查。从社区导入的东西默认不可信，要过六道关；
   从组织自己的用法沉淀出来的，只需确认边界。**」`[原型 @16.552M]`
3. 系统给出**四条来源路径**（四选一）`[原型 @16.552–16.553M]`：

   | 路径 | 说明文案（原型原文） | 角标 |
   |---|---|---|
   | **从空白开始** | 自己写。适合组织特有的方法与内部服务。 | `最慢 · 最可控` |
   | **从社区导入** | Claude Code / Codex / 咨询方法库 / MCP Registry | `需过落地检查六道关` |
   | **复制现有并改** | 基于已发布资产开新版本，**保留谱系**。 | `继承原有权限与负责人` |
   | **从实际用法沉淀** | 大家已经在用、只是还没成为资产的东西。 | `检测到 3 个候选` |

4. 用户选定路径 → 系统按路径展开对应输入区（分支见 R4 的 A1–A4）。
5. 用户提交来源材料 → 系统做**类型自动识别**。可接受的输入形态逐字为
   「`SKILL.md`、`OpenAPI`、`mcp.json`、`.wsxtpl`、Git 仓库地址」，角标 `自动识别类型`
   `[原型 @16.555M]`。
6. 系统落一份**草稿**（含 provenance、识别出的类型、原始材料快照），并把向导推进到第 2 步。
   - `[设计]` 草稿在**任何**时刻都可通过 `[存为草稿]` 退出并稍后继续；
     原型只给了「草稿自动保存 · 时间戳」这一条证据，自动保存的**周期**无依据 → `[待确认]`。

## R4 备选流程与异常流程

**备选流程**

- **A1 从空白开始**：系统生成一个**只有一份根文件**的空目录，直接进编辑器（`uc-23-3`）。
  skill 的措辞是「生成一个只有 `SKILL.md` 的空目录，直接在编辑器里写；随时新建文件和文件夹」
  `[原型 @15.690M]`。
  ⚠ 其余五类资产的「空白起点长什么样」原型未写 → `[待确认]`（agent 是 `AGENT.md`
  可由 `AG_FILES` 反推 `[原型 @16.653M]`，其余四类无依据）。
- **A2 从社区导入**：两个子入口——
  ① 直接给地址：输入框 placeholder `github.com/org/skill-repo` + `[拉取]`，
     或 `↥ 上传 .zip 或整个目录` `[原型 @15.690M]`；
  ② 从已连接的源里挑：源目录表 + 每行 `[浏览]`（⚠ **`[浏览]` 在原型里无 handler，
     市场目录屏不存在** → Q-5）。
  导入后系统显示资产的**外部元数据**，原型示例逐字为
  「来自 Codex 社区 · 作者 `@strategyops` · **4.2k stars**」`[原型 @16.559M]`。
  ⇒ 进入六道关（`uc-23-2`）。
- **A3 从实际用法沉淀**：系统**主动检测**组织内重复出现的未成资产用法，列为候选。
  原型给了三条真实形状的候选 `[原型 @16.553M]`：
  - `14×` 同一段「客户访谈开场」提示被复制到 **14 个线程**
  - `6×` **6 场项目**手搓了结构相同的「供应链风险」画布
  - `9×` **Scout** 被 9 次临时授予同一组 MCP 工具
  ⇒ 按第 1 步的说明，这条路径**不过六道关**，「只需确认边界」`[原型 @16.552M]`。
  ⚠ 触发「成为候选」的次数阈值无依据 → `[待确认]`（Q-8）。
  ⚠ 这三条候选分别指向 skill / 画布模板 / MCP 授权三种不同资产
  ——说明检测器是**跨资产类型**的，不是每类一个 → `[设计]`。
- **A4 复制现有并改**：从已发布资产开新版本，**保留谱系**、**继承原有权限与负责人**
  `[原型 @16.552M]`。⇒ 第 3 步的三项治理配置**预填为原资产的值**（`[设计]`，
  由「继承原有权限与负责人」反推）。

**异常流程**

- **E1 类型识别失败**：材料既不是 `SKILL.md` / `OpenAPI` / `mcp.json` / `.wsxtpl` 也不是可拉取的仓库。
  → 明确告知「识别不出这是什么」，**不猜**，给出「手动指定类型」的出口。
  ⚠ 原型未画此态 → `[设计]`。
- **E2 识别出的类型 ≠ 用户进入向导时选的类型**（在 Skill 管理页导入了一个 `mcp.json`）。
  → **必须显式提示并让用户裁决**，不得静默改道；静默改道会让第 3 步的权限继承落错资产类型。
  `[设计]`，原型未画。
- **E3 拉取仓库失败**（地址不存在 / 无权限 / 网络）→ 保留已填内容，给重试；不清空草稿。`[设计]`。
- **E4 源不可用**：选中的社区源上次同步失败（原型实例：`Codex 社区 · 失败 · 凭据过期` + `[修复]`
  `[原型 @16.556M]`）→ 该源的条目**不可选**，`[修复]` 跳转到 `uc-23-7`。
- **E5 上传的目录里有二进制附件**：第 01 关会检查「无二进制附件」`[原型 @16.560M]`，
  但**第 1 步是否先拦**无依据 → `[待确认]`。
- **E6 权限不足**：无该资产类型维护权限的人，资产管理页的主 CTA **不出现**（不是点了报错）。
  `[设计]`，与 R5 一致。
- **E7 用户中途离开**：草稿自动保存，下次进入回到离开时的步骤。`[原型 @16.551M]` 有「草稿自动保存」
  但**未画恢复态** → `[设计]`。

## R5 权限与可见性

- **能力维护者**：可发起四条路径中的任意一条，可存草稿、可推进到第 2 步。
  **不能**自行发布（发布见 `uc-23-4`，且六道关不可跳过）。
- **平台组管理员**：能力维护者的全部权限，另可维护社区源（`uc-23-7`）。
- **方法论审核人 / 安全评审人**：**不在本 UC 出现**。他们的动作在 `uc-23-2` 的第 02、04 关。
  ⚠ 明确写出：审核人**不能**代替维护者发起导入（否则同一人可自导自审，
  违反 `contracts/skills/domain.md` 的 I-4 自审禁止）。
- **引导师 / 组长 / 组员**：**无权进入后台资产管理页**，看不到本 UC 的任何入口。
- **`[待确认]`**：六种资产类型的维护权限是**一个权限**还是**六个**。
  原型的后台导航把六类并列为六个标签页，但未画权限差异。

## R6 后置条件 / 不包含

**后置条件**
- 系统中新增一份资产**草稿**，带：类型、provenance（四条路径之一）、原始材料快照、
  外部元数据（社区来源时）、创建人、创建时间。
- 草稿**尚未进入任何检索范围**，对其他成员不可见。
- 向导停在第 2 步；`从社区导入` 的草稿已排入六道关。

**不包含**
- **六道关本身**（`uc-23-2`）、**治理与发布**（`uc-23-4`）、**目录编辑**（`uc-23-3`）。
- **市场目录的浏览/搜索/排序**——原型里 `[浏览]` 无 handler、无任何条目结构，
  **这一屏不存在**（Q-5）。本 UC 只做「已知地址/已知条目」的导入。
- **社区源的增删改**（`uc-23-7`）。
- **许可证与法务合规判定**：外部资产的开源许可证是否允许组织内分发，
  原型 0 命中 → 明确不做，登记 `[待确认]`。

## R7 业务规则

1. **来源决定检查强度**（原型原文，本 UC 的核心规则）：
   从社区导入 ⇒ 必过六道关；从实际用法沉淀 ⇒ 只需确认边界；
   从空白开始 / 复制现有 ⇒ 原型未写 → `[待确认]`。
2. **同步只拉清单，不自动安装任何东西** `[原型 @16.555M]`——
   源同步产生的是**可选条目**，永远不产生已安装资产。这条既约束 `uc-23-7` 也约束本 UC：
   「已同步 34 个」不等于「库里多了 34 个 skill」。
3. **复制现有并改保留谱系**：新资产必须能回指原资产，且继承其权限与负责人 `[原型 @16.552M]`。
4. **草稿不进任何检索范围**（与 `uc-23-4` 的「仅自己 · 私有草稿」同源规则）。
5. `[待确认]` **provenance 由系统按入口写入、调用方不可指定**——
   按 `contracts/skills/domain.md` I-11 对 `source` 的既有做法类推，需人类确认是否同样适用（Q-10）。

## R9 非功能约束

- **性能**：拉取一个外部仓库的超时与体积上限 → **无依据**，`[待确认]`。
- **安全/隐私**：外部地址拉取必须走服务端、不得由浏览器直连（`[设计]`，
  否则组织内网信息会随请求头外泄）；上传材料在通过第 02 关安全扫描前**不得被任何检索或 embedding 消费**。
- **兼容与降级**：源不可用时其余源仍可用，不整页失败。

## R10 已知约束 / 依赖

- 依赖 `21-mcp` 的凭据存储（社区源凭据；原型对 MCP 的措辞是「凭据存密钥库，不入日志」
  `[原型 @16.584M]`，本模块类推 → `[设计]`）。
- 依赖 `03-skill` 的 `Skill` 实体与四态状态机——**导入产物落成的仍是 skill 的 `待审核`**，
  本模块不新增状态。
- ⚠ 依赖 **Q-0 裁决**：仓库导入 / 社区导入本身被 D-06 推到 phase-2。

## R11 切分提示

- 建议按**来源路径**切 feature，而不是按屏切：四条路径的后端形状差异远大于界面差异。
- 优先级：`从社区导入`（人类需求的正题）> `复制现有并改` > `从空白开始` > `从实际用法沉淀`
  （最后一条需要一个跨资产类型的用法检测器，是本 UC 里最重的一件，且阈值待定）。

## R12 AI Ready 验收线索

1. 六个资产标签页的主 CTA 文案与 `AD_META` 逐字一致。
2. 向导打开后步骤条为 `1 来源 / 2 配置 / 3 治理与发布`，当前在 1。
3. 第 1 步显示四条来源路径，各自角标与原型文案逐字一致。
4. 选「从社区导入」后出现地址输入框、上传入口、源目录表三块。
5. 源目录表恰好列出**已连接的**源，且上次同步失败的源条目不可选、带 `[修复]`。
6. 提交 `SKILL.md` → 识别为 Skill；提交 `mcp.json` → 识别为 MCP；
   提交无法识别的材料 → 出 E1 的「识别不出」态而**不是**默认成某一类。
7. 在 Skill 页导入 `mcp.json` → 出 E2 的显式提示，且未静默创建 MCP 资产。
8. 选「从社区导入」的草稿，其后续必须经过六道关；选「从实际用法沉淀」的草稿不经过。
9. 「复制现有并改」产生的草稿，其第 3 步三项预填为原资产的值，且能回指原资产。
10. 「从实际用法沉淀」列出的候选条数与检测结果一致，且候选跨三种资产类型。
11. 任意时刻 `[存为草稿]` 退出后重进，停在同一步、内容不丢。
12. 草稿在任何成员的搜索/列表里 0 命中（含创建人自己以外的全部人）。
13. 无维护权限的账号在资产管理页**看不到**主 CTA（不是点了 403）。
14. 源同步后「已同步 N」的计数变化，而资产库条目数**不变**（R7 规则 2）。
