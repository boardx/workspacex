# Q-0 裁决：`asset-governance` 与已拍板 D-06 的冲突怎么处理

- 裁决人：**main coordinator（架构师角色，人类 2026-07-30 授权「做决定做调整，不需要我参加决策」）**
- 日期：2026-07-30
- 结论：**方案 C（拆）**
- ⚠ 本裁决**不推翻 D-06**。见下方「为什么这不算推翻」。

## 冲突是什么

人类 2026-07-30 提出新需求：
> 需要可以**导入市场上主流使用的 agents 和 skills**，接受各种社区的最佳实践
> （Claude Code 社区、Codex 社区、open claw 等），并且需要可以看到**项目文件的浏览和编辑**，
> 这样可以实现整个 agents 和 skills 的**生命周期管理**。

而 `phases/requirements/DECISIONS-FINAL.md:39` 的 **D-06**（同一个人此前拍板）逐字写着：
> Skill ＝ **声明式契约**（提示词模板 + 输入输出 schema + 数据范围），**phase-1 无沙箱**。
> **多文件可执行包留 phase-2**。UC-3.1 的 R6「不含任意代码无沙箱执行」保留。

D-06 已在**已签核**的 `skills` 束落地三处：
`design-signoff.md:13` · `domain.md:6` · `domain.md:43`（`DeclarativeContract` 值对象「三段，缺一不可」）
另 `ui.md:277` 据它写着「改进 PR = 契约变更提案，**不是代码 PR**（D-06）」。

**新需求要的三件，恰好是 D-06 排除的三件**：外部社区导入 · 仓库导入（多文件目录）· 沙箱试跑。

## 裁决：方案 C —— 拆成两半，各归其位

| 能力 | 归属 | 依据 |
|---|---|---|
| **资产目录的浏览与编辑**（文件树 + 编辑器，`SKILL.md` / `AGENT.md` + references/assets/scripts/prompts/tools/evals） | **phase-1** | D-06 **没有**排除「编辑一个多文件目录」。它排除的是**执行**任意代码。看和改文件不需要沙箱 |
| **治理与发布**（可见范围 / 谁能改 / 负责人 / 复核周期 / 发布前检查 / 灰度） | **phase-1** | D-06 完全没涉及。而这正是人类原话里「生命周期管理」的主体 |
| **复核到期与降级**（6/12/24 月 → 待复核 → 30 天无人复核降级） | **phase-1** | 同上 |
| **后台外壳与左栏 IA**（六种资产的宿主） | **phase-1** | 与 D-06 无关；且它是人类「为什么在管理后台看不到项目蓝本」那个投诉的直接答案 |
| **外部社区导入**（Claude Code / Codex / MCP Registry / 咨询方法库） | **phase-2** | D-06 逐字「外部社区导入…为 phase-2」 |
| **仓库导入 / 上传 .zip 或整个目录** | **phase-2** | D-06 逐字「多文件可执行包留 phase-2」 |
| **落地检查六道关** | **phase-2** | 它存在的理由就是「外来资产不可信」；没有外部导入就没有它要检查的对象 |
| **沙箱试跑**（第 05 关） | **phase-2** | D-06 逐字「phase-1 无沙箱」 |
| **试跑台**（`试跑 · Ava`，用未保存提示词跑） | **phase-1，但降级** | ⚠ 见下方「一处需要人类在验收时确认的」 |

## 为什么这不算推翻 D-06

D-06 的**立论**是「phase-1 的 skill 是**声明式契约**，不是可执行代码包」。
方案 C 完整保留了这条：phase-1 里 skill 仍然是 `SKILL.md` + schema + 数据范围声明，
**没有任何东西会被执行**。

新增的只有两件 D-06 从未涉及的事：
1. **能看见并编辑那个目录**——它本来就是多文件的（`references/` `assets/` `scripts/`），
   D-06 说的是不**执行** `scripts/`，没说不能**看**它
2. **有人负责、会过期、要复核**——纯治理，与执行无关

⇒ D-06 一个字都不用改，`skills` 束的三处引用也不用动，**那次签核依然有效**。

## 一处需要人类在验收时确认的（不阻塞开工）

**试跑台**（截图 F：`试跑 · Ava`，执行轨迹里有「调用 skill `MECE 假设拆解`」「检索本项目 9 条」
「拦截 1 次越权调用」「`evals/regression.jsonl 4/4 通过`」）——

它跑的是 **agent（LLM 调用）**，不是**执行 skill 的脚本**。所以严格讲它不违反 D-06
（D-06 管的是「不执行任意代码」，LLM 调用不是任意代码执行）。

⇒ **phase-1 保留试跑台，但第 05 关「沙箱试跑」不做**（那一关跑的是外来资产的脚本）。
两者同名不同物，`asset-governance/domain.md` 必须把这条区分写成不变量，
否则实现者会把「试跑台」做成「沙箱」。

⚠ 如果人类验收时认为「试跑台也该留 phase-2」，那就整块移走，代价是
`agent-runtime` 束里 F55–F60 的验收会失去一个可视化入口——但不影响它们的可实现性。

⚠ 已预告估点可能偏低的三处（照 `project` 束原估 32–40、实测 56 的教训）：
① 市场目录浏览屏——**原型里根本不存在**（六处 `[浏览]` 全无 click handler），
   一做会连带排序/筛选/评分/许可证一整套。**它随 phase-2 走，不进本轮估点**
② 「自动校验项从资产契约派生」本质是「为每类资产写一个契约→校验项编译器」
③ 跨束约束 X-C / X-E 会回头改**已签核**束的代码

   那 55 条依赖 phase-2 的 R12 线索显式标为「随 D-06 留 phase-2」。
3. **phase-2 的 requirements 里要建一个占位**，把移走的四件登记进去，
   否则「留 phase-2」会变成「没人再提」。这条我会办。
