## 一、本阶段目标与为什么是这个顺序

**一句话**：把「一场项目」从**进场**到**留下可用材料**跑通一遍——身份与邀请、项目蓝本、
Skill/Agent 能力平面、模型与 MCP、实时转录、访谈、推演画布、对话、项目文件，九件事缺一不可闭环。

**为什么是这个顺序**：本阶段的排序逻辑是**「上下文必须先有来路，才谈得上产出」**。
phase-02 的图谱 / 报告 / 交付全部消费本阶段产生的材料；若先做可视化再补采集，
会得到一堆没有证据支撑的空屏。原型的五个迭代名称已经把这条链写死：
**能进场 → 能挂能力 / 材料入库 → 能采集 → 能推演 → 收尾项**。

## 四、口径说明（给 requirement-author 的读法约定）

### 4.1 四标记

| 标记 | 含义 | 生成 feature 时怎么处理 |
|---|---|---|
| `[原型]` | `WorkspaceX Standalone.html` **运行态实际存在**的行为，有界面可查（依据 scratchpad 的 `proto-01`…`proto-10` 抽取档案） | 可直接落 `user_visible_behavior`；是**唯一**可较安全写 UI 断言的来源（仍受 4.3 的 testid 限制） |
| `[Backlog]` | `Backlog Use Case.html` 的**文档要求**，原型未必实现 | 可落 feature，但 UI 部分**必须先补画原型**；`verification` 只写 API / 逻辑断言 |
| `[设计]` | 依据前两者反推补全，**需人类确认** | 落 feature 时标注待确认；`has_ui` 阶段进不了 `new-sprint` |
| `[待确认]` | 不应由实现者决定（阈值 / 权限边界 / 合规口径） | **不得自行取默认值**。查 `DECISIONS-OPEN.md` 对应 O-nn 取已填裁决；无对应则挂阻塞 |

### 4.2 缺失三态（成本差一个数量级，务必区分）

| 状态 | 含义 | 补齐方式与成本 | 本阶段典型 |
|---|---|---|---|
| **未探明** | 原型档案**尚未点进那个屏**，不知道有没有 | **补抽取**。低成本，由抽取员/ui-prototyper 完成，**不占人类裁决名额**（`DECISIONS-OPEN.md` 附录 B） | 蓝本 16 项各配置面板内部；访谈 `[打开访谈]` `[进入现场]`（D-41 要求先补抽取）；项目复盘屏 |
| **原型待补** | 主屏存在，但**按钮已渲染、目标屏未见**（行为未接线），或下钻层缺失 | **补接线 / 局部补画**。中等成本 | 07-canvas 4 份、08-chat 5 份均含此状态 |
| **原型确认缺失** | **枚举完毕后确认不存在**——该层级所有标签页均已抽取，其中没有这个界面 | **补画整屏 + 产品/设计确认**。高成本，**卡 `ui-signoff`** | `22-files` 全部 4 份（项目工作台 7 标签 + 项目设置 6 子标签已完整抽取，其中无任何文件浏览 / 目录树 / 批量下载 / 版本列表 / 删除确认界面） |

> **硬规则**（`DECISIONS-FINAL.md` 通用规则第 2 条）：**不得把「未探明」写成「原型没做」**。
> 前者只是没看，后者是确认不存在；混淆会凭空制造整屏补画的工作量，也会让 sign-off 风险被高估。

### 4.3 本阶段必须遵守的术语约定（D-03a，全局权威）

三个概念是**三个不同字段**，**不得共用 `stage` / `phase` / `segment` 一个名**：

| 概念 | 字段名 | 基数 | 引用方 |
|---|---|---|---|
| 议程环节 | **`agenda_segment` / `agenda_segment_id`** | 7 / 11 / 14 / 19（随时长档位变，实例级可增删） | 04-agent（载入触发源）、03-skill UC-3.2、07-canvas、22-files |
| 16 项设计配置 | **`design_facet` / `design_facet_id`** | **恒 16** | 02-tpl、04-agent（第 12 项 Agent 编排）、03-skill（第 13 项 Skill 绑定） |
| 9 个方法环节 | **`method_stage` / `method_stage_id`** | **恒 9**（PESTEL→PRD） | 07-canvas（phase-02 的 09-kg 亦引用） |

**事件契约**：agent 载入规则的触发条件**只能引用 `agenda_segment_id`**，
禁止写入 `design_facet_id` 或 `method_stage_id`；
对外事件名为 `agenda_segment.switched` / `agenda_segment.state_changed`。
