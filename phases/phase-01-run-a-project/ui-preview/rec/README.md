## 二、界面上**无法自洽**的点（sign-off 必须先裁的）

1. **🔴 材料保留期到期删除 vs 定版快照不可删（I-11 / X-4）—— 这是本束最硬的冲突，界面已显式暴露。**
   见 `uc-5-4-retention-default.png` 里 `工作坊录音 · 第 2 组.transcript.jsonl` 那条红卡「**到期但删不掉**」。
   - UC-5.4 R7：材料保留期到期 → 逻辑失效 → 物理删除（删到文件层，22-files 里真的消失）。
   - phase-00 `artifact` 束 **I-11**：固定快照**不可删、不可改、不可降级**。
   - phase-00 一致性复核 **X-4**：撤回删除是不可变原则的**唯一豁口**。
   - **一份被终版报告定版引用过的逐字稿，保留期到了，删不掉。** 三条约束在这一格里直接相撞。
   → 我**没有替它做删/不删的决定**，只把冲突画成一张看得见的红卡 + 「待裁决」徽标。
   **落点建议**（择一，需合规+法务+契约共同拍板）：① 定版引用视为「法定留存豁免」，材料不删、到期任务跳过它
   （但受访者被承诺「180 天后删除」会落空）；② 走撤回豁口物理删除音频/逐字稿，同时让定版报告对应段落标
   「证据已撤回」（保住"删除"承诺，但动了"定版不可变"）。`thresholds.ts` 的 `legalHoldCategories`
   （标 `known:false`）正是这条冲突的判据缺口，**在它给出前这条无解**。

2. **观察者 / 组员能否"带走"转写——`denied` 态被迫先替 UC 表了半个态。**
   UC-5.1 R5 说观察者「仅已发布且授权允许时只读脱敏」，但**是否可下载音频/逐字稿**没写死。
   当前 `uc-5-1-live-observer.png` 画的是「只读、说话人以角色显示、写操作全隐藏」，
   `uc-5-1-live-denied.png`（组员）画的是「跨组不进结果集」。**"只读=能不能下载原件"这条边界我只能二选一呈现，实际未定**——
   不定，F69 的 RLS 断言与 file-first 下载权（F73）写不出。

3. **PII「查看原文」的授权形态未定——按钮在，点开后的授权流程是空的。**
   F72 逐字稿里「已自动遮盖：邮箱地址 与 手机号 · 查看原文需权限」旁有 `查看原文…` 按钮（`rec-pii-reveal-*`），
   但**点开后是弹二次授权、还是走审批、谁能批**，UC-5.1 R3 第 6 步只说「独立授权动作并写审计」，没说形态。
   加密密钥策略、法定留存清单（O-38/O-39 挂起项）不定，这个按钮后面接什么无法确定。

4. **`context-pack` 契约的 `ContextSourceType` 与本域载体词表**（第 4 节）**对不上一格**。
   契约 `ContextSourceType` 八值含 `workshop`，但 `artifact` 束的 `ArtifactSource` 七值**没有 `workshop`**
   （只有 survey/conversation/interview/prototype-run/research-run/upload/ai-generated）。
   而本域三载体是 `workshop / interview / thread`——**`workshop` 在 artifact 侧无对应来源、`thread` 归到 `conversation`**。
   file-first 物化（F73）要把工作坊录音登记为 artifact 时，`source` 该填什么？**这与 `files` 原型 README 第 #1 条是同一个词表分歧的另一面**，应在契约束 ③ 节一并收敛，我没有擅自合并。

5. **重叠语音数值阈值（DER speaker confusion / 漏检率）在界面上是空的。**
   O-13 已把 AC3 改为结构性断言（「两人同时说话·待人工指派」，不静默归属），本原型据此实现（F71）。
   但「置信度低于多少触发待校对」这三个数（UC-5.1 R10 待补数）界面上没有阈值显示，因为没有权威数——
   `识别置信度低·待校对` 是**定性**标注，非阈值触发。这不阻断验收，但 sign-off 应知道界面上没有那三个数。

## 三、我替 UC 做的判断（UC 没写明、我在界面上定了的，逐条看）

1. **`rec` 做成独立顶层路由 `/rec` 的"转写工作台"**，而非塞进 `/studio/interview` 或 `/projects/[id]`。
   理由：转写是三载体共享能力（UC-5.1 R1），用载体切换器（`?carrier=`）表达"同一套能力、三个入口"比分散到三处更能让人核对一致性。**已有的 `/studio/interview` 转录区（interview-stage.tsx）是访谈域的落点，本原型与之心智一致但不改它**（并行纪律）。
2. **匿名声道未指派时显示「说话人 A/B/C」，指派后显示真人名**；拒绝实名者一律用代称（P-11 Kraus→显示 P-11）。UC 只说"匿名声道→真人映射"，代称的落点形态是我定的（与 entry.ts 同源口径）。
3. **指派候选里把「授权未完成」的人（P-12）显式列出但置灰＋标「未授权」**，而不是从候选里悄悄拿掉。R7「未授权不被录也不进转写」是硬约束，但**候选列表里要不要显示他**没规定——我选"显示但不可选"，让"为什么少一个人"可见。
4. **AI 打点候选做成独立队列（引述与打点屏下半），集中一处批量处理**，而不是只散在滚动的转写流里。UC-5.3 R8「AI 候选集中一处」是 [设计] 建议，我把它落成一个带三出口（确认/编辑后确认/忽略）的队列，失效候选（依据被撤回）单独灰显划线。
5. **保留期到期删除做成"二次确认 + 影响范围四条"**（先逻辑失效/删到文件层/级联失效/不可删对象豁免），确认门控是勾选"我已了解影响范围"。UC-5.4 只要求"确认对话框明确影响范围"，具体门控形式我定为勾选解锁（与 `files` 删除屏、`itv` 撤回屏一致）。
6. **同意书"动态渲染"与"已提交快照"并排展示**，让"改了覆盖值（180→90）后新文案变、旧快照不变"一眼可见。UC-5.4 R8「三处同源」是文字要求，我把"同源 vs 快照冻结"做成两张并列卡，是把抽象规则做成可核对的对照。
7. **载体差异只体现在会话头（延迟秒数、语言方向、录音路数、file-first 产物清单）**，逐字稿区三载体同构。UC 说"共用同一套转写段模型"，我据此让三载体复用同一 `SegmentRow`，只在头部分叉。
8. **右栏五标签里只有「转录」是实的，其余四个（执行/洞察/产物/材料）是外壳占位**并注明属其他能力域。UC-5.1 R8 要求五标签齐备且带计数，但执行/洞察/产物/材料的内容属 06-itv/07-canvas/10-report——我做外壳＋计数徽标，不越界造它们的内容。

## 四、R8 线索之间互相矛盾、我怎么处理的

1. **「物化是同步契约」（UC-5.1 R7 file-first）vs「转写稿是异步派生物」**：原件（音频）入库是同步的（结束即
   物化可下载），**转写稿 transcript.jsonl 是派生物、允许后到**（带 `derived_from`）。我在 file-first 提示里
   把这两件事分开写，同步约束的是原件可见性，不是派生物。
2. **「PII 遮盖后照常参与检索与引述」（R7）vs「不确定文本不可引述」（R7）**：看似都作用在同一段。我的处理：
   遮盖是**内容变换**（遮盖后仍是 final 态，可引述），不稳定态（partial/low-confidence/pending-manual）是**状态门禁**
   （无论是否遮盖都不可引述）。两者正交，一个改文本、一个卡状态，`seg-03`（遮盖但可引述）与 `seg-06/07/08`
   （不可引述）在同屏可对照。
3. **「声纹允许」（原型访谈"可用声纹指派"）vs「无声纹身份库」（DECISIONS-FINAL）**：按 UC-5.2 头部拆成
   本场内聚类（允许，随本场销毁）与跨场次身份库（禁止）。指派候选**只来自本场在场名单**、无"上次这个声音是谁"，
   并在指派屏顶常驻 embedding 销毁提示（O-14：指派完成即销毁 / 兜底第 7 天）。

## 五、**没做 / 做不到**的部分（如实说，不糊）

1. **全部是 mock，零后端**：搜索框不真过滤、指派/回填/撤销只切本地状态、AI 打点确认不真入库、
   到期删除不真删。七态是**静态陈列**七个例子，不是真的状态机流转。
2. **实时性没假装**：多路录音的"实时出字"做成**可见的轨道状态**（录制中/断网缓存/已关麦/未录制），
   不是一个转圈动画；但**逐字稿不真的滚动、延迟秒数是静态值、"正在识别"是一条固定示例段**，不是真的流式。
3. **音频不真播**：点时间码 `rec-tc-*` 高亮该段（selected 态），但**没有真的音频播放器/波形/跳转**——
   AC2「点时间码跳回音频」的真实定位在后端 + 播放器，未做。
4. **diarization、ASR、PII 识别引擎全未接**：匿名声道 A/B/C、重叠检测、遮盖都是 mock 结果，
   whisper-large-v3-zh / pyannote 未接；**"两人同时说话"是预置的一条 seg，不是真的重叠检测**。
5. **声纹 embedding 的物理销毁 + 审计（F75）是后端不变量**，界面只画销毁提示，销毁本身不可见、未做。
6. **保留期参数读取接口（F78）、同意书渲染快照的不可改（F79）是后端**：界面读 mock 的
   `RETENTION_PARAM`（centralized，标注"数值待合规、待迁入 packages/contracts"），
   **"全仓无硬编码天数"的静态检查是后端 verification，前端只演示解析结果与三处同源**。
7. **响应式**：只抓了 1360 宽桌面图。375/768 档未抓图（AppShell 有响应式断点，本次未跑该屏）。
8. **契约缺的四组枚举**（SegmentStatus / PiiType / 匿名声道映射 / 保留期解析）**集中声明在
   `lib/mock/rec.ts` 顶部并注明"待迁入 packages/contracts"**；锚点/段模态（Anchor / SegmentKind）
   **已从 `@repo/contracts/artifact` import**，不另抄——证明引述锚点与 segment/anchor 对得上（本束高风险项）。

## 六、建议 sign-off 时重点核对的三处

1. **材料保留期删除 vs 定版快照不可删（第二节 #1，I-11 / X-4）**——这是全束最硬的冲突，
   `uc-5-4-retention-default.png` 已把它画成红卡。**先给这条一个裁决（豁免保留 or 撤回豁口删除），
   否则 F78 到期删除的 verification 与"对受访者的删除承诺"直接打架。**
2. **观察者/组员的下载权 + PII 查看原文授权形态（第二节 #2、#3，UC-5.1 R5/R10 两条挂起）**——
   直接定义客户交付边界与合规边界，界面已被迫先替它表了一半态。不定，F69/F72/F73 的 RLS 与授权断言写不出。
3. **载体词表与契约 `ArtifactSource`/`ContextSourceType` 的对齐（第二节 #4）**——
   `workshop` 在 artifact 侧无对应来源、`thread` 归 `conversation`，牵动 file-first 物化（F73）填什么 `source`。
   **这与 `files` 原型查出的同名词表分歧是同一条，应在契约束 ③ 节一次收敛，别让它成为第 N 次"同一事实两处"。**
