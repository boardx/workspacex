## 二、`rec`（录音与转写）

被审对象：`ui-preview/rec/`（32 张）、`apps/web/components/rec/*`、`apps/web/lib/mock/rec.ts`、
`requirements/05-rec/uc-5-1~5-4`。

### 原型里这个域的核心链路是什么

原型把「录音转写」拆成**两条不同场景的链路**，不是一套界面：

**① 访谈（用户洞察）链路**，字节 16,088,061 → 16,141,069：
```
准备室（逐人 × 三项授权矩阵 + 多人访谈设置 + 设备与转录检查 + 发言人标签校准）
  → 进行中（提纲覆盖 / 在场与发言 / 实时转录 / AI 副驾驶 / RQ 覆盖度）
  → 处理状态（6 个任务各自独立报状态，失败不阻塞）
  → 逐字稿校对（播放器 + 章节导航 + 低置信改词 + 说话人指派 + 主题确认 → 进正式证据库）
  → 单场复盘 → 摘要 → 证据矩阵 → 研究报告
```

**② 工作坊（项目）现场链路**，字节 15,449,589 → 15,462,300：
```
分组录音 → 实时转录与说话人分离 → 按环节匹配模板 → AI 填草稿 → 组长确认后成为产出
```
并附四条硬规则（15,462,071「模板与录音的绑定规则」）：每个环节在议程里已绑定模板、
AI 只从本组录音取素材不跨组混用、每条草稿保留原始时间码、组长未确认不进产出也不写回组织大脑。

### agent 画成了什么

一个统一的 `/rec` 四屏工作台：`live / assign / annotate / retention`，
用 `?carrier=workshop|interview|thread` 切换载体，三载体共用一套 `SegmentRow`，只在会话头分叉。

### 这份审计本身的判据风险

  反过来，**「有裁决背书 = 一定对」也不安全**——D-06 让 skill 从「可导入的目录包」变成「三段表单」，
  裁决合法，但它是否仍然服务于人类 2026-07-30 说的产品主线，不在我的判断范围内。

  我是靠读上下文区分的；`Atlas` 的 4 次全在 JS 数组里，若只看计数会误以为是噪音。

- **本文的偏移是原始文件字节偏移**（第 3 节的分区表除外，那是分桶估计）。
  但原型文件若被重新导出，所有偏移都会失效——**长期可用的证据是 grep 命中字符串与计数，不是偏移**。
- **「一份全是问题的审计和一份全是通过的审计，可疑程度相同。」**
  本次四个域里有三个判「主线对」，我把它们「查了什么、怎么查的」写在了各自小节开头，
