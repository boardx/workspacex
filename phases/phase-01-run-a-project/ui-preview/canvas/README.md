### F100 为什么没有独立屏
F100（模板注册表 `key`/`display_name` + 19 A0 模板契约）是 `CAP-API`、`needs_ui_signoff=false`，
验证走契约断言不依赖 UI。它的**界面落点**在模板库屏的 `key vN` 列：`persona v3`、
`empathy v4 显示: empathy-map`、`journey-map v3 显示: user-journey`、`bmc v3 显示: business-model`——
五处 `key≠display_name` 差异逐字画出（见 `uc-7-1-template-admin-default.png`）。

### 预览怎么走
顶部「预览控制条」（仅 dev，生产 `NODE_ENV=production` 不渲染）三行：
- **屏** `?screen=`：template-admin / segment-binding / editor / ai-draft / backflow
- **视角** `?as=`：facilitator / groupLead / member / observer（预览手段，真实权限在服务端 RLS）
- **七态** `?state=`：default / loading / empty / invalid / dep-failed / denied / success

每个可交互元素带 `data-testid`（`tpladmin-* / segbind-* / aidraft-* / backflow-* / canvas-*` +
七态保留名），供后续 verification 锚定。这是与旧原型（零 testid、零异常态）最大的差别。

## 二、从 UC 读出来、但界面上**无法自洽**的点（sign-off 必须先裁的）

1. **🔴「议程环节」一个概念四个名字，且 UC-7.1 明确要求不挑一个用。**
   `stepId`（`artifact.ts:205`）/ `stage.*`（动作词表）/ `agenda_stage` / `agenda_segment` 四名并存
   （OPEN-QUESTIONS Q-2/Q-3 仍未裁：环节实例是不是独立表、状态机取值、收不收某类产出）。
   **我在界面上一律显示中文「议程环节」、testid 用中性 `agenda-seg-*`、并把裁决指向 OPEN-QUESTIONS**
   （见 `segment-binding` 屏顶部橙色告警条）。**这条不定，F102 的绑定外键、`STEP_CLOSED` 判据都写不出。**

2. **🔴「未试跑不得发布」到底阻不阻断——界面被迫先按「不阻断」画了。** UC-7.1 R4/E1b、R7 明写
   这是**原型确认缺失**（草稿行 `[发布][试跑]` 并列、无阻断态）。我在模板库屏把草稿行的
   `[发布][试跑]` **并列渲染、不做硬阻断**，并在流程说明条里把这条判断显式写出来
   （`tpladmin-flow-note`）。**若产品要「必须先试跑」，这是加一道 gate 的事，但现在界面读作「可跳级」。**

3. **🔴 模板 ↔ 9 个方法环节的映射表是 UC-7.4 首次提出、档案未给。** 回流屏的推演流水线
   `进度 12/36 · 4 场景 × 9 环节` 依赖这张映射（`03 用户画像→persona` 等），我把它当 `[设计·待确认]`
   画进流水线底部的橙色注脚（`backflow-mapping-note`）。**映射不定，回填哪个格子无法确定。**

4. **观察者/组员能看到多少来源——界面在 `denied` 与 `member` 两态里只能各表一半。**
   UC-7.4 R5 说「组员只见本组小树、观察者只见脱敏聚合」，但**脱敏到什么粒度**（能不能看到
   来源组名、证据量、时间码）UC 没给。我在 `backflow-member.png` 画的是「组员看得到本组小树、
   看不到全场各组来源」，观察者态直接走 `denied`。真实脱敏边界需服务端定义，界面只是投影。

5. **「无来源·待补」到底算不算写进画布——D-11「不阻断」与 R7「不得以已填形态呈现」需并存。**
   我的处理：无引述草稿**真的写进画布**（不删、不拦，D-11），但用灰色虚线样式 + `无来源·待补` 徽标
   区分，且**不计入完成度分子**（R7）。见 `ai-draft` 屏「痛点」分区第三条。这是我读出的自洽解，
   但「无来源草稿能不能被组长确认后回流」UC 没说——我默认**不能**（回流屏该节点无确认入口）。

6. **完成度分母到底数什么——O-32 说「模板分区定义条数」，但填满一个分区算不算「完成」不清晰。**
   我取「该分区**至少有一条带引述的草稿**即计 1 分」（`computeCompletion`），分母＝分区数。
   AI 起草屏顶部显示 `3/3`。若产品要「按格数加权」，这个口径要改——但 O-32 明确禁止加权，我按它做。

## 三、我替 UC 做的判断（UC 没写明、我在界面上定了的，逐条看——**最重要**）

1. **UC-7.2「AI 故意没写完」怎么表达——本束最要紧的设计问题，UC 没给形态，我定了方案。**
   我不用「填了一半的空白」表达留白（那看着像 AI 出错/卡住），而是把**每个空位画成一张虚线卡
   「留给现场 · AI 故意没填」**（`aidraft-empty-slot-*`），并在分区头显示 `已填 2/4 · 留 2 格`。
   「这里是有意留白、等你补」是**画出来的一等状态**，不是一片空白。这是 sign-off 头号要看的判断。
2. **留白提示做成非阻断的分区内提示条 + `[清一格]`**（`aidraft-warn-*` / `aidraft-clear-*`），
   不用 modal、不拦写入——对应 D-11「只提示不阻断」。填满时提示「建议留一格给现场」并给一键留白。
3. **AVA 回滚做成「一键回滚本轮」+ 二次确认**（`aidraft-rollback` → confirm），
   回滚后画布回到「落笔前逐字节一致」的空态并给 `[重新起草]`。UC 只写「轮次级原子回滚」，
   撤回后长什么样、要不要二次确认由我定。
4. **归档危险动作 = 二次确认对话框 + 影响面「有 N 个议程环节仍绑定此模板」**
   （`tpladmin-archive-dialog` / `-impact`），并说清「从绑定选择器消失但已建实例不被改动、
   现场仍能实例化」（O-10）。UC 只要求提示 N，确认形式与文案由我定。
5. **两模板上限做成「计数 1/2 + 达上限后隐藏『添加模板』并给提示」**（`segbind-template-count`
   / `segbind-limit-hint`），另在 `invalid` 态演示「绑第三个被拒」。这条上限是**原型确认缺失**
   （档案未见提示），提示形态我补画。
6. **回流的三态节点每张都带一条来源链**「第 3 组 · 研究模块 9 来源 · 12:05 · seg-3#0142」
   （`backflow-source-*`），并**造了一个来源链断的节点**（`gn5` 运维响应，`来源链断·不得写回`）——
   把「链断即拒绝写回」做成界面上看得见的一条，而不是一个不可见的服务端不变量。
7. **互斥结论做成红条「冲突待判定」+ `[上台讨论]`/`[标为不确定]`，两侧边并存、不自动择一**
   （`backflow-conflict`）。UC 给了出口词，界面呈现由我定。
8. **本组小树是 UC-7.4 明写的 `[未探明]` 屏**——档案只探明全场，我按全场屏的语言原创了组级树
   （`backflow-group-tree`），并在屏内标注「原创设计 · sign-off 重点」。
9. **模板库 `key vN` 列同时显示程序 key 与展示名**（`persona v3 · 显示: empathy-map`），
   把 O-09「界面显示 display_name、契约用 key」这条画成人能核对的样子。
10. **五屏共用一套顶部预览控制条 + 复用 `AppShell` 三栏骨架 / 五段语义导航 / 底部 Ava 在场条**——
    不另起布局。编辑器屏用画布三区左右栏，其余四屏是全宽单栏。

## 四、R8 线索之间互相矛盾、我怎么处理的

- **「AI 直接落笔默认生效」（D-10）vs「组长未确认不进产出/不回流」（UC-7.2 E1 / UC-7.4 R7）**：
  看似冲突。我的处理：AI 在**本组画布上**可直接落笔（`ai-draft` 屏带角标、可回滚）；
  但**回流到图谱/大脑**这一步另设组长确认门控（`backflow` 屏「组长已确认·可写回」/「待组长确认」）。
  两者是画布内写权限与跨模块回流两件事，不在同一道门。
- **「白名单只关渲染不关书写」（UC-7.1 R7）vs 模板库是「配置」界面**：白名单开关放在模板库屏底部
  （`tpladmin-whitelist`），关掉 `sequenceDiagram` 后立刻显示 `有 1 条语法被忽略` 徽标——
  提示「关掉的类型仍可书写、只是不渲染、源码原样保留」。开关作用在渲染、说明文案讲清书写不受影响。
- **「归档禁新增绑定」vs「现场不跑挂」（O-10）**：归档确认框同时说两句——「从绑定选择器消失、
  不能新增绑定」+「已绑定环节现场仍能成功实例化、固化归档版本」。不把归档画成「一刀切禁用」。
- **编辑器屏出现两个状态切换器**（hub 的「七态」+ 既有 `canvas-main` 自带的「预览状态」）：
  这是复用既有组件的副作用，不是设计意图。**建议 sign-off 后把 `canvas-main` 内置的那条去掉、
  统一走 hub 控制条**——我没动既有组件（并行纪律：只加不改别人的文件）。

## 五、**没做 / 做不到**的部分（如实说，不糊）

1. **全部是 mock，零后端**：发布/归档/绑定/确认/写回都只弹乐观 toast 或本地态，不落库、不真跑。
   七态是**静态陈列**七个例子，不是真的状态机流转。
2. **画布本体不是真 mermaid 渲染**：编辑器屏的画布是既有的**静态占位壳**（角标写「非 mermaid 渲染」），
   `＋便签/＋节点/删除` 只落本地 chip，**没有 fabric.js、没有三段互转、没有几何归区判定引擎**——
   这些是 F103/F104 的真实实现（R12 的 round-trip 断言在纯函数层，不在这个壳里）。
3. **AI 起草不真取材**：引述三件套（segmentId+时间码+原文）是 mock 常量，`点听原话` 只展开原文文本，
   **不真连 Context API、不真回放音频**。F12「AI 不得引用不在本次 Pack 的证据」是服务端不变量，界面只标来源。
4. **回流不真入图谱**：事实关系/推演流水线/本组小树都是 mock 静态数据；`批量确认` 只做勾选清单 UI，
   **不真写 `claims`/`claim_evidence`/`provenance_events`**（append-only 由 phase-00 F08 保证，界面只声明）。
5. **实时协作全是 mock 的「可见状态」，没有真实时**（本束高风险点 2，如实说明）：
   在线头像（人+AI）、同步三态（已同步/待同步/画布领先）、组画布四态、LWW、冲突条——
   **都是陈列出来的状态样例，没有 WebSocket、没有真正的并发合并/锁**。冲突条靠 `?conflict=on` 触发演示。
6. **响应式只抓了 1360 宽桌面图**：375/768 档没抓图；网格/画布用了 `data-allow-x-scroll` 显式声明
   横向滚动是设计（推演流水线 9 列、画布平移），但三档无横向溢出的断言本轮未跑。
7. **模板「新建（和 AI 聊出分区结构）」「试跑选项目」是原型待补**——按钮在、点击弹说明 toast，
   对话面板/项目选择器未渲染（与 UC-7.1 原型缺口三态一致）。
8. **`[源码]` 视图是只读 pre 文本**（既有组件），UC-7.3「源码可直接手改并回传三段」未做。

**建议 sign-off 时重点核对这三处：**

3. **回流的组长确认门控 + 来源链断即拒（第三节 #6、第四节第 1 条）** —— 「谁确认才写回大脑」「链断
   不写回」是 UC-7.4 的价值核心，我把它做成看得见的确认入口与红色断链条。**这条界面表达一旦签，
   F107 的 `only-lead-confirmed-writeback` / `source-chain-unbroken` 验收断言就能锚定。**
