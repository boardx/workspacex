## 二、界面上无法自洽的点（人类签核重点看）

1. **报告模板：一等对象 还是 访谈模板的内嵌属性？**
   原型里报告模板在**问卷 Studio** 是一等对象（「问卷模板 · 客户体验诊断 / 含问卷结构与报告模板」，
   可挂到任何问卷）；而访谈侧原型的「研究报告」只有一个**内嵌**的「报告结构 · 10 段」，没有独立的
   报告模板库。我把它建成**「访谈模板 1:1 绑定一个报告模板」**（`reportTemplateId` 可空），
   并允许多个访谈模板共用同一报告模板（`rt-jtbd` 被两个模板绑定）。
   **这是我替产品做的建模判断**——若产品要「报告模板独立成库、多对多挂载」，模板库列的呈现要改。

2. **虚拟画像推演 ＝「专家推演」标签？还是独立的一类？**
   原型访谈详情第三组标签写的是 `虚拟 · 专家推演`（合并成一个入口），内部是「虚拟专家 5 · 用真实
   材料构造的推理角色」。人类原话叫「对虚拟的用户画像做推演访谈」。我把两者视为**同一件事**，
   屏名用「虚拟画像推演访谈」，内部沿用原型的「虚拟专家/构造依据/置信上限」。
   **若产品认为「虚拟画像」与「专家推演」是两种不同对象**，这屏要拆成两个。

3. **数据保留天数**：研究计划参数里「数据保留」的值我**没写死**，渲染成「读项目参数 · 默认 180 天
   （O-01）」。真实取值要等留存策略内核（UC-5.4）落地才能填，界面已按「读参数」占位。

4. **范围切换器的完整档位与默认值**（UC-6.0 R8 UI-sign-off / R10 待确认）：
   只做了原型确证的两档（研究项目 / 不属于任何项目），默认停在第一档。是否还需「全部」
   「按项目分组」未探明，需人拍板。

## 三、我替 UC / 产品做的、UC 没写明的设计决定（逐条，请人类核对）

- **信息架构以「链」为骨**：左侧导航直接按 ①→②→③→④⑤ 排列，而不是照抄原型的「详情六标签」。
  依据是人类那条链，但这是**结构性重排**，请确认。
- **报告模板落点在「模板编辑器」右栏**：把「针对访谈模板定义报告模板」做成模板编辑器的第二块
  （左提纲、右报告章节），每章可选「必须人写 / AI 起草」、映射一个数据来源，缺来源标红「发布被阻断」。
  这套「章节→数据来源」的映射语义与「必须人写/AI 起草」两档，是我从**问卷报告模板 + BP 报告骨架**
  两处原型证据合成的（原型访谈侧未直接给出这两档）。
- **洞察报告按报告模板逐章生成**：洞察屏底部「洞察报告 · 套报告模板逐章生成」把每个报告章节与其
  数据来源、成稿方式列出，缺来源章节标「缺来源 · 阻断发布」。这实现了「访谈结束后出洞察报告」，
  但**逐章内容的实际生成**是后端的事，此处只呈现骨架与映射状态。
- **证据矩阵五取值的视觉编码**：强=实心●绿、弱=◐灰、未提及=–、附和=≈虚线黄、反例=✕红框，
  色+形双通道兼顾色盲。UC-6.5 UI-sign-off 明确要产品/设计确认可辨识度与配色——**这套是我提的方案**。
- **虚拟来源的界面区分**（任务硬约束）：真人候选可「标为强洞察」，虚拟候选处显式锁标
  「虚拟来源不能标强（接口层拒绝）」；矩阵虚拟列 `V1` 带 bot 图标、单独计数、不并入人数；
  来源分布里「数字人／画像（探索性）」单列且标不可为强。**守住了「只有真人来源能标强」这条**。
- **拒绝 AI 分析的可视化**：逐字稿里 P-10 的片段打盾牌标「拒绝 AI 分析 · 仅原文引述」，矩阵列头
  用盾牌图标区分。文案「不进任何自动归纳」是我按 UC-6.5 AC2 落的（服务端强制，界面仅投影）。
- **访谈自有三角色**（研究员/受访者/观察者）：见第五节，人类原话为准。
- **向导默认停第 3 步**演示密度，用 `?step=` 可回看第 1、2 步。原型只给了「选模板→选对象→生成提纲」
  一行文字，三步的分步 UI 是我按 UC-6.2 R3 第一段设计的。

## 五、访谈到底属于哪一类（证据）

**结论：访谈属于「用户洞察」这一类，与「工作坊（项目）」平级、互相独立，不是工作坊下的标签页。**
- 人类 2026-07-30：项目≈工作坊（工作坊模板 + 会前/现场/会后 AI 增强）、研究项目、用户洞察 **三类独立**（Q-12=C）。
- 原型证据：左栏 `STUDIO` 分组「研究 · **访谈** · 问卷 · 原型」——访谈是**顶层 Studio**，副标题
  「独立发起，不依赖项目」；范围可为某研究项目或「不属于任何项目」。
- 访谈产出的洞察汇总进项目工作台的「用户洞察」视图（原型：`用户洞察 9 场已完成 真人 7 · 数字人与画像 2 · 41 条引述`）。
- 角色：`引导师`/`组长` 在原型里只出现在**工作坊区**（15.1M–15.3M 区段，68/87 次命中），
  访谈详情区（15.95M–16.1M）**0 命中**，且访谈屏原型**根本没有视角切换器**。⇒ 访谈成员模型自成一套，
  只有 研究员 / 受访者 / 观察者。已在 `lib/mock/itv.ts` 集中声明 `ITV_VIEWS`，注明「待迁入 packages/contracts」。

## 六、没做 / 未覆盖的部分（如实说）

- **报告模板独立成库**：只做了「访谈模板绑定报告模板」，未做独立的报告模板库列表页（见 §2.1 待确认）。
- **受访者授权页 / 自助门户**（UC-6.3 屏A / UC-6.6）：属进场/auth 域，已有既有实现，本次未重画、未纳入截图。
- **访谈对象表主入口**（UC-6.7 项目筹备侧组卡对象表）：跨出 itv Studio，未画；向导第二步只做了对象表的投影。
- **单场复盘子标签**：洞察屏聚焦「主题矩阵 + 洞察报告」，单场复盘只在现场屏的 AI 副驾驶里体现，未做独立子标签视图。
- **反向抽取的抽取向导/草案确认屏**：模板库用 Badge「从访谈抽取」+ 溯源链呈现结果，未做抽取动作的分步 UI（UC-6.1 A3 语义未定）。
- **拖拽排序、时长实时联动、真正的表单写入**：均为静态呈现（原型态）；可交互 Toggle 用只读 `StaticSwitch` 呈现档位。
- **移动端**：只截了模板库一张（375）验证不横向溢出；其余屏移动端降级未逐屏截。

## 七、建议 sign-off 时重点核对的 3 处

1. **§2.1 报告模板的建模** —— 1:1 绑定 vs 独立成库多对多。这决定模板库列、编辑器结构与洞察报告
   的生成入口，做错后面返工面最大。
2. **§三 证据矩阵五取值配色 + 虚拟/真人来源的界面区分** —— UC-6.5 UI-sign-off 硬性要求；一处关
   可辨识度（含色盲），一处关「只有真人能标强」这条合规红线的界面投影是否够醒目。
3. **§2.2 虚拟画像推演 是一屏还是两屏** —— 若产品认为「虚拟画像」与「专家推演」是两类对象，
   现在这屏要拆开；越早定越省。
