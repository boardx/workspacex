# v1 错在哪 —— 逐条对照原型证据（给签核人看）

> 你可能已经看过 v1（`ui-preview/itv/`，44 张）的截图。这份文件逐条说明 v1 的主线为什么是错的，
> 每条都给出**真实原型证据**（`phases/requirements/WorkspaceX Standalone.html`，17MB，按字节偏移抽取）。
> v2 在 `ui-preview/itv-v2/`，路由 `/itv`。v1 的目录与截图**保留不动**（推翻要留痕）。

人类 2026-07-30 原话（权威）：
> 需要是指**访谈模板的创建**，**新建访谈可以套用模板**，**质性访谈**，访谈还可以**对虚拟的用户画像
> 做推演访谈**，针对访谈模板还可以**定义报告模板**，这样访谈结束以后还要可以**出洞察报告**。

即链条：**访谈模板创建 → 套用模板新建访谈 → 质性访谈 / 虚拟画像推演访谈 → 报告模板 → 洞察报告**。
追加两条：**访谈没有引导师/组长**；**项目≈工作坊，访谈属「用户洞察」类、与工作坊平级独立**。

---

## 错误 1 · 缺了整条链的第一环：「访谈模板的创建」这一层不存在

- **v1 做了什么**：落地屏是「访谈 Studio 列表」，README 自述屏为「列表 + 研究设计 + 现场记录 +
  受访者名单 + 洞察矩阵」。模板只在列表里当一个次要标签，没有把「模板」当成链路起点。
- **为什么错**：人类那条链第一环就是「访谈模板的创建」。没有这一层，「套用模板新建」无从谈起。
- **原型证据**：
  - `访谈模板 · 5 —— 模板决定提纲结构、每段时长和要收集的数据字段；新建访谈时套用`（偏移 15977946）
  - 新建模板弹窗：`新建访谈模板 / 模板决定提纲结构、每段时长和要收集的数据字段；新建访谈时可直接套用`（偏移 15565506）
- **v2 修正**：模板库（`uc-6-1-模板库-*`）是链路起点与落地屏；每行含 用过 N 次 / 题数 / 时长区间 /
  **数据字段（→ 矩阵列）** / 配套报告模板。模板编辑器（`uc-6-1-报告模板编辑器-*`）是独立屏。

---

## 错误 2 · 没有「套用模板新建访谈」的三步向导

- **v1 做了什么**：README §七自认「未做三步逐屏的独立向导 UI」，只在研究设计屏顶部放了一个「向导已完成」回显条。
- **为什么错**：人类原话「新建访谈可以套用模板」正是这条；它是模板与执行之间的桥。
- **原型证据**：
  - 列表底部原文：`＋ 新建访谈  选模板 → 选对象 → 生成提纲`（偏移 15977946 附近）
  - 套模板弹窗：`访谈模板 助手按场景推荐了第一个；模板自带要收集的数据字段 / 采购决策链 推荐 … 12 题 · 45–60 分 · 4 个数据字段 / 空白提纲`（偏移 15532296）
- **v2 修正**：`uc-6-2-新建向导-*` 做成真正的三步（步骤条 + 选模板/选对象/生成提纲三个面板，
  `?step=1|2|3`），第一步显示每模板的「用过 N 次 · 数据字段 · 配套报告模板」，第二步带上下级拆场提示，
  第三步显示「AI 已按目标生成 · 待你确认」草案闸门。

## 错误 3 · 完全没有「报告模板」这个概念

- **v1 做了什么**：v1 的洞察屏叫「洞察与报告」，但只有「写作约束 + 候选洞察 + 主题矩阵」，
  **没有任何「针对访谈模板定义报告模板」的界面**，也没有「按报告模板出洞察报告」。
- **为什么错**：人类原话「针对访谈模板还可以定义报告模板，这样访谈结束以后还要可以出洞察报告」——
  这是整条链的终点，v1 整段缺失。
- **原型证据**（报告模板在原型里是**成熟功能**，只是长在问卷 Studio + 访谈研究报告里）：
  - `报告模板 · 客户体验诊断 / 每个问卷发布前必须映射到一个报告模板 —— 没映射完的题不能发布 / 报告章节：阻碍分布 映射 Q1 / 决策链与否决点 映射 Q2 / 按规模分群差异 缺分群字段 / ➕ 新增报告章节`（偏移 16136800）
  - `问卷模板 · 客户体验诊断 / 含问卷结构与报告模板 · 可挂到任何问卷`（偏移 16132503）
  - BP 报告骨架：`报告模板 报告的骨架写死，内容留空。结论先行、每条结论必须挂证据 …/ 01 一页纸结论 必须人写 / 02 方法与样本 AI 起草 / 03 逐一展开 AI 起草`（偏移 16542135）
  - 访谈侧研究报告：`报告结构 · 10 段：1 研究背景 2 研究对象与方法 3 参与者构成 4 核心发现 5 支持证据 6 反例与差异 7 产品机会 8 风险与限制 9 建议行动 10 后续研究问题`（偏移 16095500）
- **v2 修正**：模板编辑器右栏「配套报告模板」——受众/目的/开关 + 报告章节（每章「必须人写/AI 起草」+
  映射数据来源 + 缺来源标红「发布被阻断」）。洞察屏底部「洞察报告 · 套报告模板逐章生成」把这些章节
  与其数据来源、成稿方式列出。模板库每行显示绑定的报告模板，未绑定的显式提示「定义报告模板」。

## 错误 4 · 把「虚拟用户画像推演访谈」做成了 phase-3 空占位

- **v1 做了什么**：README §五自认「虚拟/专家推演做成占位屏（不实现），显式标 phase-3」。
- **为什么错**：人类点名要「对虚拟的用户画像做推演访谈」。而且原型里这个标签是**已实现的完整界面**，
  不是 phase-3 才有的东西——phase-3 只负责虚拟人的**构造能力**，界面本身早在原型里跑着。
- **原型证据**：
  - `虚拟专家 · 5 用真实材料构造的推理角色 · 不是真人，不产生语音与录音 / 构造规则：虚拟专家只能由已入库的真实材料构造：至少 2 场真人访谈或 3 条组织层判断 …`（偏移 15995000 附近）
  - 每位专家：`置信上限 中/低 / 构造依据 / 立场偏好 / 已知局限 / 不可用于`；`V2 材料不足，只能提问不能下结论`
  - 单条推演结果：`推理 12 步 · 8.4s / 立场 / 理由 / 推得 / 引用 / 不确定：…这是推理，不是观察到的行为 / 会被推翻：…`（偏移 16008215 附近）
  - 三条硬约束：`一，不计入证据强度…二，不能单独支撑决策…三，报告里单列章节并注明生成模型与日期`（偏移 16010500）
  - 采纳与标注：`待你判断 · 4 推演结论不会自动进任何地方 / 已采纳的去向 · 6`
- **v2 修正**：`uc-6-5-虚拟推演访谈-*` 做成可点三段——专家设定（V1–V4，含置信上限/材料不足）、
  提问与推演（RQ 问题清单 + 推演结果，**强制显示「不确定」「会被推翻」**）、采纳与标注（待判队列 +
  已采纳去向）。三条硬约束常驻页头。**只有真人来源能标强、虚拟单独计数**在此屏与洞察屏都做了界面区分。

## 错误 5 · 把工作坊的角色模型套到了访谈上

- **v1 做了什么**：视角切换器渲染 `研究员 | 引导师 | 组长 | 观察者 | 受访者` 五档
  （复用了 `interview.ts` 里 v1 自己造的 `INTERVIEW_VIEWS`，含 facilitator/groupLead）。
- **为什么错**：人类 2026-07-30 原话——「在访谈里是没有这几种角色的，引导师、组长什么的是不必要的」。
  引导师/组长是**工作坊**的角色，不该出现在访谈。
- **原型证据**：grep 全文——`引导师` 68 次、`组长` 87 次，**全部落在工作坊区**（偏移 15.1M–15.36M）；
  访谈详情区（偏移 15.95M–16.11M）`引导师`=0、`组长`=0、`视角`=0（访谈屏原型**根本没有视角切换器**）；
  访谈区只出现 `研究员`（1 次）与 `受访者`（12 次）。
- **v2 修正**：访谈自有 `ITV_VIEWS` = 研究员 / 受访者 / 观察者三档，集中声明在 `lib/mock/itv.ts` 并注明
  「待迁入 packages/contracts · 访谈成员形状」，**不复用 project 四角色、也不复用 interview.ts 的 5 档**。
  切换器见任一屏截图（如 `uc-6-5-洞察报告-观察者视角`）——只有三档。

## 错误 6 · 访谈的归属没定准（隐含挂在项目下）

- **v1 做了什么**：v1 README §四把「访谈同时归属研究项目与业务项目」当成主要待确认项，隐含把访谈
  当作项目的下级对象在纠结外键。
- **为什么错**：人类 2026-07-30 裁决 Q-12=C——项目（≈工作坊）、研究项目、用户洞察**三类互相独立**。
  访谈属「用户洞察」这一类，**与工作坊平级**，不是挂在工作坊/项目下的标签页。
- **原型证据**：左栏 `STUDIO` 分组「研究 · 访谈 · 问卷 · 原型」，访谈是**顶层 Studio**（偏移 15034576）；
  副标题「独立发起，不依赖项目」；产出汇总进项目工作台的「用户洞察」视图
  （`用户洞察 9 场已完成 真人 7 · 数字人与画像 2 · 41 条引述`，偏移 15265000 附近）。
- **v2 修正**：左栏标题「访谈 · 用户洞察 / 独立发起，不依赖项目」；范围切换器两档
  （研究项目 / 不属于任何项目），后者是一等档。归属结论写进 README §五并落进 `ITV_PLACEMENT_NOTE`。

## 可复用而 v2 沿用的（不是所有 v1 都错）

- **现场记录三栏**（提纲/逐字稿/AI 副驾驶）的信息架构 v1 大体对，v2 沿用其结构（`uc-6-4-现场记录-*`），
  并补上了 v1 缺的：拒绝 AI 分析的盾牌标、附和·非独立证据标、七态与受访者视角。
- **证据矩阵五取值** v1 已识别（强/弱/未提及/附和/反例），v2 沿用取值集，重做了色+形双通道编码与
  「独立强证据计数」写作约束、虚拟列单独计数。
- **研究计划参数四行 + 保留期读参数不写死** v1 的口径对，v2 沿用。
