# 原型到底已经定了什么 —— 对着运行态原型逐条核验 OPEN-QUESTIONS 的 12 条

> 作者：project 域 UI-prototyper（第 10 个域）。2026-07-30。
>
> **权威来源**：`phases/requirements/WorkspaceX Standalone.html` 的「项目工作台」那一屏
> （模板变量 `wsDetailView`；我用 grep/节选定位，未整份读入）。
>
> ⚠ **纪律（本仓四标记法）**：
> `[原型]` = 运行态里**确实存在这个行为/控件/文案**（不是「我觉得原型暗示了」）；
> 「原型空白」= 原型在这一点上没有任何体现；
> 「原型自相矛盾」= 原型内部两处措辞/控件互相打架（比空白更要紧）。
> **我只标 `[原型]` 与「空白/矛盾」，不替人类裁决，未改 OPEN-QUESTIONS.md。**
>
> ⚠ 一个反复出现的边界：**很多 Q 问的是「数据模型是一个外键还是两个」「独立表还是 JSON」
> 「响应体是不是两段式」——这些是后端形状，运行态 UI 天然看不出来。** 凡属此类我一律标「空白」，
> 不用 UI 的样子去反推后端，那正是本仓要防的「造出已算过的假象」。

## Q-1 项目怎么创建？ —— **原型给出答案：两条路径并存**

`[原型]` 新建项目视图（`isWsNew`，副标题「新建项目 · 套用蓝本」「先选流程，再定主题」）的「1 选蓝本」
九宫格里，六个蓝本卡（HMW 定题 / 商业模式共创 / 假设风暴快版 / 设计冲刺 5 天 / 用户旅程共创 / 尽调结论评审）
**之外**，明确有两张虚线卡：
- **「从空白开始 · 自己排环节，没有骨架约束」**
- 「复制一场已办的 · 连议程、画布绑定、AI 配置一起复制」

⇒ 运行态里「不套蓝本、空白新建」是一个**真实存在的一等入口**，不是被否定的。这直接支持
OPEN-QUESTIONS Q-1 的候选 **B/C 一侧**（uc-2-2 A4 的 `[设计]` 在原型里有落点）。

⚠ **但原型不能裁决数据模型**：候选 C（一条创建路径 + 可选参数 `blueprintVersionId?`）
渲染出来也正是「一个入口列表里放一张『空白』卡」——所以 UI 有空白入口 **≠** 后端是两条创建路径。
「一条还是两条创建事务」原型看不出，仍待裁。

## Q-2 议程环节是什么实体？ —— **部分**

`[原型]` 环节在运行态里是有血有肉的对象：
- 议程屏（`isWsAgenda`）每个环节有 **编号 / 标题 / 时长 / 绑定模板**（如「03 假设风暴 · 45m · 模板 hmw」）；
- 有 **「当前」态**（环节 03 高亮标「当前」），顶部恒显「环节 3 / 7」；
- 主持台（`isWsDuring`）有 **「下一环节」「＋5 分钟」** 两个动作 → 环节可推进、可延时；
- 议程屏文案逐字：**「组长切换环节状态后，三种视角的首屏立刻跟着换」** →
  这正是 uc-2-2 说的「环节状态是三视角首屏的唯一驱动源」，**原型运行态就是这么演示的**。

⇒ Q-2 待答②（状态机存在、且是唯一驱动源）**有原型证据**。

⚠ **空白的两处**：
- 待答①「环节是不是一张**独立表**」——是存储决策，原型看不出；
- 待答③「环节收不收某类产出（`acceptedSources`）」——原型的环节卡只显示「绑哪张模板」，
  **没有任何「本环节只接受哪几类来源」的白名单控件**。这条原型空白。

## Q-3 环节字段叫什么？ —— **否（空白）**

`stepId` / `stage.*` / `agenda_stage` / `agenda_segment` 是**代码层字段名**。运行态 UI 里
自始至终只出现中文「环节」和模板名（hmw / business-model），**没有任何一处把英文字段名画到屏幕上**。
⇒ 这条**不是原型能回答的**，它是契约/迁移层的命名一致性问题（且很可能已被 D-03a 定为 `agenda_segment_id`）。
本原型据此把 UI 显示中文、testid 用中性名 `agenda-item-*`，并在代码里注明「命名待裁决 → Q-3」。

## Q-4 成员怎么进来？两层角色交叉？ —— **部分**

`[原型]` 「参与者与邀请」屏（设置内）**同时**给了两个入口：
1. **直接指派**：顶部输入框「邮箱或手机号，逗号分隔」＋「邀请」按钮，下面是已在册名单（高琳/吴桐/周宁/陈默，各带角色与「已确认 / 邀请已发 2 天」）；
2. **链接进场**：「邀请链接 · 打开即带身份进场，不需要提前注册」＋「分组链接 · 打开直接进本组工作台」，
   并注「链接可单独撤销；观察者链接只读已发布内容」。
   身份四选：**组员 / 组长 / 观察者（只读）/ 协同引导师**。

⇒ Q-4 待答①「授权入口在哪」——原型明确是**两个入口并存**（支持候选 B）。

⚠ **空白**：待答②（组织角色 `lead` 对**自己创建但未加入**的项目，有管理权无读取权？）与
待答③（角色变更立即生效的实现位置）——原型里操作者始终是**已加入的引导师**，这条边的两端从未被演示。

## Q-6 列表 / 主页展示什么？ —— **主页：是；列表两段式：空白**

## Q-10 无项目内容怎么读回？ —— **部分**

`[原型]` 项目知识图谱（`isSetGraph`）按记忆层分带，**个人层带**里有「**我的笔记 · 未升到项目**」
「我的偏好 · 已开启」两个节点，且组织层有「复用自中盛项目」的跨项目节点。
⇒ 「不属于本项目 / 未升级的个人层内容」在运行态里是**一等可见**的（图谱专门给它一条带）。
这间接支持「无项目/个人层内容存在且要能被读回」。

⚠ 但「`readContent.in.projectId` 非空导致 `projectId=null` 的 artifact 无合法读取路径」
是**契约内部的紧张关系**，UI 层看不见——修不修契约是 Q-10 的核心，原型不能答。

## Q-11 项目与 Studio 从属关系？ —— **是（原型支持候选②）**

这是被点名重点核的三条之一。**原型的做法是「两者并存，不是二选一」**：

`[原型]` 证据一（Studio 是顶层一等）：左侧图标栏语义分段里，**「编排 · 项目」与「STUDIO ·
研究/访谈/问卷/原型」是平级的两个分段**（见 `apps/web/lib/navigation.ts` 已按原型实测抽取）。
Studio 不挂在某个项目下才能打开。

`[原型]` 证据二（项目内又能调用 Studio）：项目工作台「研究洞察」标签的左子导航有
「对话 / 问卷 / 用户洞察 / 深度研究」；「现场协作」里有 **「＋ 发起访谈」「＋ 发起研究」「派访谈 AI 代跑」**。
即项目内也能用 Studio 能力，产出回流到本项目。

⇒ **itv agent 的「Studio 一等、独立发起」与本 project 原型的「项目为容器」并不冲突**：
Studio 是一等对象（可独立发起），项目是它**可选的归属容器**（发起后可回流/挂载）。
这正是 OPEN-QUESTIONS **Q-11 候选②** 描述的形状，且与三处已签契约（`projectId` 可空 /
`saveDraft` 无项目也可 / context-pack「不属于任何项目」范围）一致。原型证据同向。

## Q-12 研究项目 vs 业务项目？ —— **矛盾 / 候选集没覆盖的新形状**

被点名重点核的第二条。**这里原型给出的形状，OPEN-QUESTIONS 的候选 A/B/C/D 都没画到。**

`[原型]` 我在运行态里**没有**找到任何「项目类型 / kind」维度：没有「研究项目 vs 业务项目」的切换器，
项目列表卡片上的「内部 / 已归档」是**标签(tag)**不是类型分区。

`[原型]` 但新建项目「2 主题与时长」步骤有一个字段逐字写着：
> **「挂到哪个项目（决定能读哪些洞察与图谱）：远洋新能源 · 欧洲市场进入 ▾」**

而正在新建的项目名叫 **「欧洲进入策略 · 定题项目」**。
⇒ 运行态里出现的是 **「一个项目挂到另一个（更大的）项目下」的父子/嵌套归属**——
「定题项目」是子，「欧洲市场进入」是父。**不是**「研究 vs 业务」两种并列类型（A/D），
**也不是**两张独立表（C），**更像**「项目有一个可选的父项目外键」。

⚠ **这与 itv agent 观察到的两级归属是同一个现象的另一面**：itv 看到「访谈范围=研究项目
（采购决策如何形成），行内所属=业务项目（欧洲进入策略）」——在 project 原型里，这两级正是
**父项目（欧洲市场进入）⊃ 子项目（定题/Kickoff）**，访谈挂在子项目的环节上、同时归属父项目。

⇒ **结论（不裁决，只报告）**：Q-12 现有四个候选**都没有「项目可嵌套 / 项目有可选父项目」这一形状**。
运行态证据倾向：**不是 kind 维度，而是项目自引用的父子归属**。请人类在裁 Q-12 时把这个第五种形状纳入考虑，
或确认「父项目」只是 UI 措辞、后端仍是别的模型。**这是本次核验最重要的一条发现。**
