## 二、我替 UC 做的设计决定 + **三处裁决处置**（sign-off 请逐条看）

### 三处已落地裁决的处置

1. **[裁决] 「项目」= 工作坊**（人类 2026-07-30）。新建向导标题写「新建项目（工作坊）」，四种项目角色只属它；
   研究项目 / 用户洞察不在这里创建（归属见第四节）。
2. **[裁决·处置] 「挂到哪个项目」字段** —— 原型步骤 2 有此字段（原型 JS 数据区 **byte 15208776**），
   默认值「远洋新能源 · 欧洲市场进入」，它宣称的是**父子项目模型（Q-12 候选 E）**。而 **Q-12 已裁 C（三类独立容器）+ D（超类型表）、E 未采纳**。
   **我的处置 = 三选项里的「改成明确的容器归属/关联」**：把它改成「**关联研究来源（可选 · 决定能读哪些洞察与图谱）**」，
   并在字段下挂一条紫色 callout：「把一个『研究项目 / 用户洞察』容器作为**只读来源**引用进来……这是**跨容器引用，不是父子归属** —— Q-12 裁定三类独立容器（C+D），父子模型（E）未采纳。」
   见 `uc-2-2-newproject-default.png`。**没有删除**它（读洞察/图谱的真实诉求要留个出口），也**没有留成遗留字段**（那会继续宣称错模型）。
3. **[裁决·改名] 议程环节 testid** —— Q-3① 裁「改名对齐 D-03a `agenda_segment`」，已把 `agenda-item-*` 全部改成 `agenda-segment-*`（`tab-prep.tsx`）。

### 其余 [设计] 决定（UC 未写明）

- 观察者「看得更少」**具体减了什么**（上一节列表）——原型只给了观察者说明条文案，逐屏裁剪是我定的。
- 组长/组员在现场协作里的**本组 vs 别组**边界（`ROLE_OWN_GROUP` / `ROLE_SEES_ALL_RAW` / `ROLE_STAGE_CONTROL`）。
- 组织停用只读条的文案（uc-00-1 V12 只说「显示只读原因而非隐藏」，具体话术是我写的）。
- 列表 ⋯ 菜单加「编辑项目」；**不加「删除」**（Q-9 裁不提供删除，归档承接退役）——这条也是处置，见第三节。
- 发布结论二次确认 + 影响范围文案 · 候选决策可签/不可签二态 · 概览用「就绪检查 3/3」而非「准备度%」（口径 [待确认]）。

## 三、界面上无法自洽 / R8 线索互相矛盾的点（sign-off 必须先裁）

1. **🔴 项目空间用哪套布局**（A-0）——见第四节，两版并存。
2. **🟠 `/project` 要不要纳入 `project-context`**：全局顶栏显示「不在项目上下文中 · 项目角色不适用」（见截图右上），
   而工作台第二级头满是项目身份与视角切换器——两处对「我在不在项目里」给相反答案。根因：`lib/project-context.ts`
   只认 `/projects/<id>`，不认 `/project`（我按并行纪律未改这个共享文件）。纳入后全局顶栏会重复渲染项目层身份，与第二级头冲突。
3. **🟠 U-2：归档是 status 还是 tag** —— 本实现按 **status** 做（`/projects` 有「已归档」**筛选 chip**，卡片上**没有**归档 tag，
   `uc-00-2-allprojects-archived.png` 是空态）。而人类给的 devapp 截图把「已归档」既当筛选 chip 又当**卡片标签 chip**，
   后者与 U-2「归档是 status 不是 tag」冲突。→ 我按 U-2 画，把冲突登记在此。
4. **🟠 观察者能否下载已发布产出**（B-1，原型空白）· **候选决策签署授权矩阵不全**（B-2）· **准备度%口径**（B-8，概览改用「就绪检查」）。

## 四、**两版并存 —— 项目空间用哪套布局**（去原型查过，附 byte offset）

人类截图里项目详情出现两种布局。我**没有自己挑**，按指令去静态原型 `phases/requirements/WorkspaceX Standalone.html`（17MB）grep 核实：

**Layout B（阶段式 tab，`/project` 工作台）= 静态原型权威布局。证据（byte offset）：**
- 项目列表卡片「进入项目 / 看现场大屏 / ⋯」三个按钮全部调 `openWs`（**byte 15169552** 区）。
- `openWs` 打开的 wsDetailView 顶部是**阶段式** sc-if：`isWsOver`@**15221492**（概览）· `isWsRov`@**15277095**（研究洞察）·
  `isWsScope`@**15348094** / `isWsAgenda`@**15368783**（项目筹备）· `isWsDuring`@**15401543**（现场协作）·
  `isWsAfter`@**15500356**（成果沉淀）· `isWsTodo`@**15530664**（待办）+ isSetup（设置）。

**Layout A（「工作面」清单，`/projects/[projectId]`）在静态原型里查无实据：**
- grep 全文：`推演画布` / `访谈现场` / `问卷与投票` = **0 命中**；`工作面` **仅 1 命中**（byte **16374379**），
  且那处是「设计说明 v0.1」里对**第三列的泛称**（"COLUMN 3 · 自适应 · 内容：工作面"），**不是**一个工作面清单。
- ⇒ Layout A 不是静态原型的转译。它来自 (a) 人类展示的 devapp 直播版（更新方向），和 (b) 本仓前一 agent
  2026-07-28 为补「进入项目死按钮」而**自造**的 `/projects/[projectId]` 页（该文件注释自认是填空缺）。

**结论**：静态原型 → Layout B；devapp 直播 → Layout A。**两者冲突，需人类拍板**。按指令**两版都画、标「待裁决」**：
Layout B 是本 v2 的主体（70 张 + 组织停用 3 张），Layout A 保留 2 张（`uc-00-2-projecthome-*`）供当场比对。
⚠ 人类原话「tabs 代表不同的功能 · tabs 需要查 UI prototype」——若最终要的是「**功能式 tab**」（对话/画布/文件/访谈/问卷/任务/大屏），
那是把 Layout A 的工作面**改造成 tab**，与原型的阶段式 tab（Layout B）都不完全等同，也请一并裁。

### 研究项目 / 用户洞察两类容器的界面归属 —— **我的判断：不归本束**

U-1 裁：这两类容器**各自一张成员表、只落「拥有者 + 协作者」两档**，不用四角色。依据下列证据，我判断它们的
**列表 / 详情 / 成员界面归 `interview`（itv）与 `research` 束，不在 project 束画**：
- `apps/web/lib/mock/itv.ts:95` 逐字：「访谈属于**用户洞察**这一类，与『工作坊（项目）』**平级**，不是挂在工作坊/项目下的标签页。」
- Q-12 裁 C+D = 三类**独立**容器（工作坊 / 研究项目 / 用户洞察），彼此平级；工作坊才有四角色。
- `ui-material-map.json` 已把 interview → `itv-v2`；「研究项目」在九束里**只**出现在 `contracts/interview/domain.md`（OPEN-QUESTIONS Q-12 记录）。
- 本束 = 工作坊。若在这里再画一套两档容器，就会与 itv/research 束**各画一套**，正是本仓要防的「同一事实两处」。

⇒ 本束**只**在新建向导里把这两类容器作为「关联研究来源」**引用**（只读下拉），不画它们的列表/详情/成员。**建议人类确认此归属**。
