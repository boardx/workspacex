# 为什么推翻 v1（`../project/` 19 张）

> 留痕文件。v1 目录不删，`ui-material-map.json` 的 `project` 指针改指 `project-v2`。
> 推翻不是「v1 全错」——v1 的工作台骨架、mock 密度、七态机制都被 v2 继承了。推翻的是**覆盖面**与**几处保真度**。

## 一、v1 的四条硬伤

1. **覆盖严重偏斜**：19 张里只有「概览」拿到七态；其余六个标签页各 1–2 张，**没有七态、没有四视角对照**。
   而本束第 ① 件最要紧的性质恰恰是「四视角是否真的改变界面」（UC-1.4 / phase-00 X-1）。
   v2 把六个标签页各补到七态 + 四视角（70 张），观察者的内部协作视图**整块消失**而非变灰。

2. **观察者延续了原型的 happy-path 缺陷**：v1 观察者基本是「引导师少几个按钮」，不是「显著更少」。
   v2 用 `*-observer-notice` 让被限内容**消失**，并新增组长/组员的**本组 vs 别组**边界（现场协作）。

3. **一处「屏在、控件在、默认值反了」的保真度错误**（本轮最贵的一课，看截图看不出，要对着 JS 数据区核）：
   设置「产出与留存」的「**客户可见的分享链接**」——v1 mock 画成「开 ✓」，
   **原型 JS 数据区（isSetOut 块，byte ~15274086）实际是关**：原型滑块底色 `#DEDCD3`、滑块在左 = OFF
   （对照「结束后自动写回组织大脑」底色 `#17171A` = ON）。v2 已改为**默认关**，并加旁注「开启后观察者/客户方才按已发布内容可见」。
   这条边界很关键：分享链接默认关，直接影响观察者到底能不能看到已发布产出（B-1 边界仍未定）。

4. **三屏缺屏 + 一个宣称错模型的字段 + 旧 testid**：
   - C-1 全部项目列表、C-2 新建向导、C-3 组织停用只读——v1 全缺，v2 补齐。
   - 「挂到哪个项目」字段（byte 15208776）在 v1 里**原样保留**，继续宣称 Q-12 已否决的父子模型（E）。v2 处置为「关联研究来源」跨容器引用。
   - v1 议程 testid 还是 `agenda-item-*`（Q-3① 已裁改名）。v2 改为 `agenda-segment-*`。

## 二、我在 JS 数据区核默认值的发现（byte offset）

原型 17MB，**没 Read 整份**，全部靠 grep byte offset + `dd` 抽窗口。核对结果：

| 控件 | 原型 JS 数据区 | v1 | v2 |
|---|---|---|---|
| AI 权限「Facilitator 主动提议收敛」 | **开**（`#17171A`，byte ~15274415）| 开 ✓ | 开 ✓ |
| AI 权限「实时转录与语音转便签」 | **开**（`#17171A`，byte ~15274802）| 开 ✓ | 开 ✓ |
| AI 权限「AI 直接在小组画布落笔」 | **关**（`#DEDCD3`，byte ~15275188）| 关 ✓ | 关 ✓ |
| 产出与留存「结束后自动写回组织大脑」 | **开**（`#17171A`，byte ~15274118）| 开 ✓ | 开 ✓ |
| 产出与留存「**客户可见的分享链接**」 | **关**（`#DEDCD3`，byte ~15274160）| **开 ✗（反了）** | **关 ✓（已修）** |
| 时长档位默认 | **半天·3.5h**（byte ~15207xxx）| 半天 ✓ | 半天 ✓ |
| 新建项目名默认 | 「欧洲进入策略 · 定题项目」→ v2 用工作台同名「欧洲进入策略 Kickoff 项目」 | — | 已对齐 |

**另外两处「判缺失、实则存在」的形态**（记录以防再被当缺口重画）：
- **「工作面」不是一个清单**：全文 `工作面` 仅 1 命中（byte 16374379），是「设计说明 v0.1」里对第三列的泛称，
  不是 Layout A 那种「对话/推演画布/项目文件…」清单。Layout A 的这些词在原型里 **0 命中**。
- **项目详情入口只有一个**：列表卡片「进入项目 / 看现场大屏 / ⋯更多」三个按钮**全部**调 `openWs`（byte 15169552 区），
  即都进 wsDetailView（阶段式 tab / Layout B）。原型里**没有**一个中间的「工作面清单」页。

## 三、v2 没有推翻 v1 的部分（继承）

工作台三栏骨架 + 第二级项目头 + 视角说明条 · mock 数据密度（四组、审计 214 条、候选决策两态）·
七态共享 `StateShell` 机制 · 发布结论的二次确认 · 概览用「就绪检查 3/3」而非「准备度%」。
这些 v1 做对了，v2 原样继承并在其上补覆盖面。
