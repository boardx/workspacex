## 二、从 UC 读出来、但界面上**无法自洽**的点（sign-off 必须先裁的）

1. **🔴🔴 UC-8.4「谁能给谁下发预设」是权限模型问题，UC 没写死 —— 我没替它表态，做成了三张待裁决卡。**
   R1 只写「**引导师**预先写好…下发给各组」。但界面一旦落地，至少三个判定必须有人拍板，
   全部渲染在预设屏右侧「待裁决」区（`chat-preset-question-*`）与顶部橙色横幅（`chat-preset-power-banner`）：
   - **谁能下发**：组长能不能给本组下发？项目负责人（组织角色）能不能跨组下发？
   - **被下发者能不能改**：R3 步骤 2 只说「打开即用、不需自己配」。改了开场提示 / 增删 agent 之后，
     还算「同一个预设的实例」吗？——这直接影响**使用计数口径**（AC1「真实实例数」到底数什么）。
   - **被下发者能不能拒 / 忽略**：下发是「推送」还是「上架供取用」？若组员默认不可私聊（O-24），
     下发一个含私聊的预设是否被拒？
   👉 **建议 sign-off 时先裁这三条，否则 8.4 的 feature_list 会把一个未定的权限模型当成已定。**

2. **🔴 UC-8.4 整屏是「补画原型」，不是既有原型的抽取。** 口径重标（2026-07-28）明确：
   「预设」二字在原型抽取档案 proto-01~10 中 **0 命中**——对话屏、后台九子模块、组员入口
   均无预设列表 / 编辑器 / 下发对象选择器 / 使用计数。故本屏**每一个控件都是新设计**，
   需逐条 sign-off；`chat-preset-proto-tag` 徽标在屏内已标「补画原型 · 待裁决」。

3. **🔴 UC-8.5「可见范围徽标」是 [设计] 待裁决，原型未见此控件。** R8/R10 明写线程卡与线程头上
   **均无可见范围徽标**。我做了一个提案组件（`VisibilityBadge`，取值 `组员私聊/本组共享/全场/团队可见/私有`），
   **仅嵌在 8.3 产物条上演示**（`chat-visibility-*`），未擅自铺到线程卡/线程头。
   待裁决：**徽标该放哪几处、文案、观察者视角下如何呈现**。服务端的 `visibility_scope` 字段本身是 [原型] 明确的。

4. **UC-8.3「对话侧未挂来源标灰」是 [原型确认缺失]。** 「未挂来源标灰」原文只在**洞察报告工作台**
   （proto-05），对话屏已完整探明、**未见标灰**。我按 R7/AC3 在对话侧也做了标灰（EPC 备忘那条），
   但这是**跨屏借证的推断**，需人类确认对话侧是否同规则。

5. **UC-8.3「加入报告」是否自动定版，UC 标 [待确认]。** 我按 uc-0-1 E1 的「阻断 + 一键定版入口」实现
   （`chat-gate-pin-now`），不是「点加入报告即自动定版」。这是我替 UC 选的一条路，见第三节 4。

## 三、我替你做的判断（UC 没写明、我在界面上先定了一个，请逐条看）

1. **三模式选择器做成「并列三卡 + 各自后果 + 可进决策徽标」，不是三个单选钮。**
   UC-8.3 R3 步骤 3 只要求「并列展示各自后果」。我把「能被拿来干什么 / 会不会随源变动 /
   可不可进决策」直接印在每张卡上，且**未挂来源时把「固定快照」卡禁用并给出原因**
   （`chat-mode-option-snapshot` disabled）。——这是把服务端门控前移到界面可见，属我的设计决定。

2. **引用资格门控做成「四个决策动作 chip 统一置灰 + 一行服务端阻断原因 + 一键定版」。**
   UC 只说「服务端强制要求固定快照、阻断并给一键定版入口」。四个动作
   （加入报告正式版 / 提交验收 / 引用为决策依据 / 写回图谱）我平铺成一排 chip
   （`chat-decision-action-*`），gate 不过时整排灰 + `chat-gate-blocked`。措辞「被服务端阻断」
   是刻意的——强调门控在服务端，界面只是投影。

3. **`VisibilityBadge` 的色调档位是我定的**：越私密越冷（私有/私聊=neutral、本组共享/团队=ai、
   全场=primary）。UC 未给色彩语义，这是我的取舍，可推翻。

4. **「加入报告」走「阻断 + 一键定版」而非「自动定版」**（第二节 5）。理由：自动定版会让
   「实时关联」在用户不知情下被固化成快照，破坏 uc-0-1「模式不可降级 / 快照不可变」的可预期性；
   显式一键定版让「这一步产生了不可变版本」这件事对用户可见。**这是 [待确认] 项，我选了保守的一路。**

5. **预设编辑器的「越范围拒绝」用「切到指定组=第5组」来触发演示**：预设 2 的「引述抽取」skill
   仅「能源组」可见，下发给第5组即越界（`chat-preset-scope-violation`）。这是我构造的可复现 mock
   路径，用来把 V1c「下发时即拒绝、不是下发后失败」变成人能点出来的东西。

6. **使用计数与下发人数**在预设卡上**分两行显示**（`用过 N 次` / `下发给 M 人`），并加了一句
   「⚠ 待裁决：使用计数按实例数算，不是下发人数」。UC AC1 强调「真实实例数」，我把这两个数
   刻意分开，避免 sign-off 时被误读成一个数。

7. **预设屏无右栏**（对话上下文五标签），因为预设编辑不在某个具体对话上下文里。这是我对信息架构的
   判断——若产品认为预设也应挂在某线程上，需推翻。

## 四、R8 线索之间互相矛盾 / 我怎么处理的

- **UC-8.3「未挂来源标灰」vs「原型对话屏零标灰」**：R7 要求标灰、R10 又说对话屏原型未见标灰。
  我按 R7 实现，但在本 README 第二节 4 显式标为待确认，界面上标灰处带 `title` 注明「AC3 服务端可判定状态」。
- **UC-8.4「打开即用、不需自己配」vs「使用计数=真实实例数」**：若被下发者能改预设，则「实例」是否仍算
  该预设的使用，口径不清。我没在界面上替它定，而是把「能不能改」列为待裁决卡之一，并在计数旁注明口径未定。
- **UC-8.5「观察者操作按钮不渲染」在 8.3/8.4 的落点**：8.3 观察者不渲染落地动作、8.4 观察者不渲染编辑器
  （都走 `readOnly` 分支，`StateShell` 的 denied 态另有独立截图）。**这是界面投影，真实权限由服务端不下发**
  ——README 与代码注释都反复强调，避免把视角切换误当权限实现。

## 五、明确没做的部分（本轮边界，如实说明哪些是 mock / 未接线）

- **流式输出没有假装**：AI 消息、转录卡的「实时文字」在既有 `/chat` 屏是静态 mock，本轮两屏
  （8.3/8.4）不涉及流式；未做打字机动画冒充流式。真实流式（run/event 权威在服务端，CopilotKit/AG-UI
  仅 presentation）属实现期。
- **一切写操作只到界面为止**：下发、定版、加入报告、越范围拒绝都是**纯前端 mock 判定**
  （`dispatchScopeViolation` / `canEnterDecision` 是 mock 纯函数）。服务端 gateway / RLS / provenance_events
  / artifact_versions / model registry 均未接。README 第二节的门控都需服务端落地才成立。
- **UC-8.1 / 8.2 / 8.5 未重画**：既有原型已覆盖，本轮只加 `VisibilityBadge` 一个提案组件。
  批准卡、工具调用链、五标签、四视角切换器沿用既有实现。
- **mock 数据集中在 `apps/web/lib/mock/chat.ts`**（已登记在 `DECLARED_MOCK_DEBT`）。本轮新增的
  BIND_MODES / LANDING_ARTIFACTS / PRESETS / VISIBILITY_SCOPE 等**待迁入 `packages/contracts`**——
  三模式与 Artifact 属 uc-0-1 契约、可见范围枚举属 identity/uc-0-3 契约，不应长期留在 web mock 里。
- **未探明区未补**：`[看任务队列]`→11-task 队列屏、`[全屏编辑]`→画布编辑器、产物卡
  `[加入报告]`/`[派给 Scout 验证]` 点击后的目标屏——均属跨域，不在本束范围。
- **响应式**：三栏骨架天然响应（AppShell ≥md 收右栏、<md 底部 tab），但本轮两屏的 375/768 档
  未逐一截图（既有 `e2e/responsive.spec.ts` 的 SCREENS 尚未加入 `/chat/landing`、`/chat/preset`，
  属实现期补测）。

## 建议人类在 sign-off 时重点核对的 3 处

1. **UC-8.4 的三张「待裁决」卡（`/chat/preset`）** —— 谁能下发 / 能不能改 / 能不能拒。
   这是本束唯一的权限模型空洞，界面已把它可视化，**请在此拍板，别让它漏进 feature_list**。
2. **UC-8.3 三模式选择器 + 引用资格门控（`uc-8-3-landing-default.png` / `-nosource-gate.png`）** ——
   确认「阻断 + 一键定版」这条路（而非自动定版），以及「对话侧标灰」是否与报告工作台同规则。
3. **`VisibilityBadge` 提案（`uc-8-3-landing-*` 产物条上的眼睛徽标）** —— UC-8.5 AC1 的界面部分是
   [设计] 待裁决，确认徽标**该放哪几处、文案、观察者视角下如何呈现**。
