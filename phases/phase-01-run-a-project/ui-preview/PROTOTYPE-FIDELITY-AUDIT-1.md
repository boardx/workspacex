## 一、`tpl`（工作坊蓝本） —— 部分错

主线对：**蓝本库 → 蓝本设计器 → 套用新建项目 → 项目筹备 → 提回蓝本 → 版本**。
原型里 `蓝本库 · 7`（偏移 15830211）→ `编辑设计 →`（15833230）→ `HMW 定题项目 · 蓝本设计`（15819917）
→ `＋ 新建蓝本 / 从空白开始、套用已有蓝本，或从已办过的项目反向生成`（15850141–15850375）。
agent 的七屏（list / designer / apply / prep / workflow / promote / versions）**逐屏对得上**，没有整层缺失式的主线错。
**角色使用正确**：`tpl` 用 引导师/组长/组员/观察者 四角色 —— 原型「角色权限默认值」矩阵逐字给的就是
`引导 / 组长 / 组员 / 观察者`（16570643–16570715）。**这是对的，不判错。**

  `[AI 能力] Agent编排 Skill绑定`（16527299–16528180）· `[产出] 输出物 报告模板`（16528321–16529180）。
  **每一行都有一个完整实现的面板**，state flag 依次为
  `isBpBasic 16529742 / isBpTopic 16540752 / isBpAgenda 16547369 / isBpGroups 16559626 / isBpRoles 16566736 /
  isBpSurvey 16574588 / isBpItv 16579329 / isBpHw 16584742 / isBpVenue 16589180 / isBpMat 16595266 /

### 错误 2 · 把 16 项数成 15 项：`基本配置` 被当成分组标题而非配置项 —— 【重做，与错误 1 同屏】

- **原型证据**：`基本配置` 在 16521891、其后紧跟 `✓`（16521997），**形状与 `场地与形式`（16525720）+`✓`（16525829）完全一致**，
  是一个**配置项行**；真正的分组标题 `会前输入`(16523943) / `现场`(16525394) / `AI 能力`(16527299) / `产出`(16528321)
  **都不带 ✓、不带计数**。计数条自报 `16 / 16`（16521552），列表页也逐行写 `16/16 环节已配`(15832832) `15/16`(15838126) `12/16`(15840778) `9/16`(15846012)。
- **agent 画成了什么**：`lib/mock/tpl.ts:73-89` 的 `CONFIG_ITEMS` **只有 15 条**，`基本配置` 不在其中；
  截图里 `基本配置 ✓` 与 `AI 能力 ✓` 一起被渲染成**分组标题**，进度条读 `13/15`。
  README §四把「第 16 项」列进「未探明」清单 —— 那个「找不到的第 16 项」就是被降格成标题的 `基本配置`。
- **后果**：`configTotal()` 恒读 `CONFIG_ITEMS.length` 是对的做法，但**表本身少一行**，
  于是不变量 I-5 的分母、F22 的发布门槛断言、以及列表页 `n/16` 与设计器 `n/15` 两处分母**互相打架**。

### 错误 3 · 把原型明写的规则报成「与原型冲突 · 待裁」（D-8） —— 【重做，与错误 1 同屏】

## 七、方法与局限（这份审计自己的盲区）

### 怎么做的

1. 原型是 bundler 打包页，可见内容全在一段 JS 转义字符串里（`</…>` 形式）。
   用正则 `>([^<>]+)<` 抽出 **7,559 条文本节点并保留字节偏移**，得到全文可 grep 的索引。
2. 用 `{{ isXxx }}` / `{{ showXxx }}` 绑定名建立**屏级偏移地图**（约 300 个 flag 的首末出现位置），
   再从 JS 侧 `this.set({ screen, nav, … })` 反推**真实路由表**
   （`nav ∈ {ava, workshop, canvas, studio, brain, tasks, admin}`，`adminTab` 9 值，`wsPhase` 十余值）。
   这一步是本次能定位「蓝本 16 面板」「画布模板编辑器」「预设屏」的关键 —— 它们都不在左栏导航上，
   靠肉眼点原型很容易漏。
3. 逐屏 dump 文本区间与被审对象（README / mock / components / 截图）对照，每条结论落到偏移或 grep 计数。

### 盲区（重要）

1. **我没有把原型跑起来点一遍。** 全部结论基于静态标记与 JS 数据。
   凡「这个面板是不是真能点开」「三态之间怎么切」这类**运行时行为**，本审计**无法判断**。
   一个屏的标记存在 ≠ 它在运行时可达（尽管 16 个 `isBpXxx` 都有对应的 `set({adminTab:"blueprint"})` 入口，可达性很可能成立）。
2. **截图我只逐像素看了 2 张**（`tpl/uc-2-1-designer-default.png`、`chat/uc-8-4-preset-default.png`）。
   其余 95 张只依据文件名 + README + 组件/mock 源码判断。
   **视觉层面的偏差（配色、字号、密度、七态是否真的不同）本审计基本没查。**
3. **未覆盖的原型区间**：
   - 15,162,900–15,378,400（工作坊筹备的 `wsOver / wsRov / wsScope / 议程编辑器 isWsAgenda`）—— 只抽查了 `材料准备`
