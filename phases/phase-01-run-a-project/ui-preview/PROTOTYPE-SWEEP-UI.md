## 零、这个区间到底是什么

原型的整个界面层由**一个模板引擎的条件块**构成：`<sc-if value=\"{{ <flag> }}\" hint-placeholder-val=\"{{ <默认> }}\">`。
- 全文件共 **309** 个 `sc-if` 块，首个在字节 **15,032,262**，末个在字节 **16,747,606**。
  → **整个应用的界面就在 15.03M–16.75M 这 1.7 MB 里**，本区间覆盖其中 **283 个（91.6%）**。
- 15.0M 之前是 `@font-face` / `unicode-range` 的字体子集 CSS（本区间开头 31,487 字节仍是它）。
- 16.6M 之后的 26 个块（`isBpPrint` `isBpCaps` `isBpAgent` `isBpSkill` `isBpOut` `isBpRep`
  `anOpen` `anIs1` `anIsImport` `anIsAgent` `anIsMcp` `anIsModel` `anIsCv` `anIs3` …）
  属于另一位 agent 的区间，本报告**不裁决**，仅在需要时引用。

⚠ **坑（我踩了，写下来给下一个人）**：macOS BSD `grep -bo` 在这种「整个文件只有 1 行」的
17 MB 文件上会**给出错误偏移并静默漏掉大部分命中**（我第一轮只拿到 27 个 flag，真实是 309 个）。
必须用 Python 在 `bytes` 上跑正则。另外 Python 若先 `.decode()` 再取 `m.start()`，
拿到的是**字符**偏移（全文件 16,910,685 字符 vs 17,050,600 字节），与仓库里已有的注释坐标差约 39 KB。
