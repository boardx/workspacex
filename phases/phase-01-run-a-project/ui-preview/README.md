# 一、🔴 必须先定的（不定就会把错的东西实现进后端）

## S-01 批准卡：机密数据能否与云端模型并存
原型同时印着「gpt-5.2 ＋ **本地** qwen3-32b」和「含机密，**仅本地模型**」，字面矛盾。
实现取的口径是：**机密数据只路由到本地模型，云端模型可并存承接非机密部分**。
故 `modelPolicyViolation()` 只在「有机密但无任何本地模型」时报违规，而非「有云端模型就违规」。
> **这直接决定后端 gateway 的拦截规则。** 若产品本意是「全程本地」，判定函数与二次确认文案都要改。
> 位置：`/chat`，`lib/mock/chat.ts` 的 `modelPolicyViolation`。

## S-02 合规负责人不在角色模型里
文件浏览器需要合规视角，但 `identity.ts` 的项目角色**恒为四种**（裁决 O-03），合规负责人缺位。
实现用 `?as=compliance` 临时投影，**这动摇了 O-03**。
> 两条出路：① 补第五个项目角色（推翻 O-03）；② 把合规职能归到**组织角色层**（不动项目角色）。
> 我倾向 ②，但这是你的裁决。位置：`/projects/demo/files`。

## S-03 访谈/问卷的角色不在枚举里
访谈与问卷的 R5 列了「研究员 / 受访者 / 参与者」，同样不在 `ProjectRole` 四值内。
实现另开了一根 `?view=` 预览轴，与身份 `?as=` 正交。
> 与 S-02 是同一个问题的两个面：**角色本体是否需要「场景角色」这一层**。建议合并裁决。

## S-04 三个数值 UC 明写「需产品给出」，界面目前不编造
任务屏的人时折算涉及三个未知数，实现**拒绝编造**并显式标注「产品待定」：
① 每项折算系数（几人时/项）② 最小样本量阈值（低于几项显示「样本不足」）③ token→金额单价与口径表版本号。
mock 里用 `minSampleKnown/coefficientKnown/ledgerVersionKnown: false` 标死，防止被硬编码。
> ⚠ 中途曾出现过 `sampleSize=18`、「口径表 v3」这类**编造值**，制造了「已算过、已过线」的假象，已删除。
> 这三个数定不下来之前，界面只能显示原型演示值（`11 项 / 6.5 人时`）。位置：`/tasks`。

## S-05 撤回五步的两个 SLA 是推断补的
D-13 撤回链档案只给了 01「即时」、04「需人工」、05「30 天内」。
实现按 D-15 两级 SLA **推断补了 02「≤5 分钟」、03「即时」**。
> 合规风险最高的一处。需合规确认或给出真实 SLA。位置：`/consent` → 「撤回同意」。

# 二、🟠 口径类（会影响多处数字与文案的一致性）

## S-06 「在场数」是否包含跑批中的 agent
原型同时有「团队 **4**」与「AI 团队 · **6**」。实现定义 `在场 = presence === "present"`（4 个），
**跑批中（Ledger）与空闲（Echo）不计入在场**，与编制数 6 分离。
> 影响线程头「团队 N」与列表「N 个 agent」的所有数字。位置：`/chat`。

## S-07 登录文案两个版本，哪个是 canonical
- 档案版：「进入你的战略工作空间」+ 引语「把顾问的判断力和 AI 的耐力放在同一张桌子上。」
- UC-1.1 R8 版：「与你的 AI 团队一起，把最难的问题拆开」
实现把两版分栏并用（一个当标题、一个当副标题、引语放右品牌栏）。

## S-08 「组织停用只读条」不放登录页
UC-1.1 R8 要求只读说明条常驻可见，但那属于**已登录**成员（A1）；登录页尚无会话。
实现判定它归 `AppShell` 顶栏，登录页的 `denied` 态映射的是 **E2 账号被停用（组织层）**。

## S-09 受访者授权「3/4」的四项拆法
UC-6.3 AC1 要「授权 3/4」但没枚举那四项。实现选了
录音✓ / 转写✓ / 引述✓ / 内部复用✗ = 3/4，**实名引用作为独立开关**（拒绝 → 用代称）。

## S-10 代称格式
小组工作台用「参与者 B（你）」，访谈侧用「某物流园区运营总监」。UC 列为「待确认」。
手机号一律掩码 `138 •••• 2049`。

# 三、🟡 设计决定（多数是补了原型缺的东西）

## S-11 观察者能看到多少
两处判断不同，需统一：
- **对话**：滤掉批准卡与转录卡，不渲染输入区/改派条/分享，仅留 AI 发言与产物卡。
  > 待定：是否还应保留「已发布产出」的只读展示。
- **访谈现场**：不硬拒，而是**转录只读 + 说话人掩码到角色标签**（连代称都不给）+ 显式横幅。
  理由：现场未发布，硬拒等于什么都看不到。
- **研究**：观察者被挡在**丢弃清单明细**之外（它会暴露撤回/越权/私有层内容）。

## S-12 丢弃清单的原因分类（7 类，是发明的）
UC-0.2 只说「丢弃清单带原因」。实现发明了这套词汇：
`已撤回 / 时效过期 / 低置信 / 无授权 / 预算截断 / 去重 / 越出范围`。
> 这套词汇是承重的——它会成为 Context Pack 的 `omissions[].reason` 枚举。位置：`/studio/research`。

## S-13 后台里三条被补的东西
- **新造了第 7 个 agent「Forge」**，把总览的「自建 agent 访问客户 CRM 被拦 7 次」与
  Agent 页的「越权申请待确认」串成同一条线索。原型是**两处独立提及**，没说是同一个。
- **18 台模型的型号与定价全是编的**（`gpt-5.2`、`claude-opus-4.6` 等）。原型只给了计数与闭源/自托管二分。
- **「可选范围」被降级为只读文字**（如「仅：Ledger（机密路由）」）+ 顶部筛选器，
  没做成逐模型的多选编辑器。D-07 要求「可选范围过滤」，这是范围上的收缩。
- **「可承接机密」徽标只贴自托管模型**——把「机密只走自托管」做成了模型列表上的显式标记，
  原型只在批准卡侧写过这条约束。

## S-14 危险动作都补了二次确认与影响范围（UC 只给了一个按钮）
- 项目 `归档`：三条影响范围
- 画布 AI 改动 `回退`：二次确认
- 组长「提交本组产出」：锁定 N 张便签快照 / 引导师与大屏可见 / 需引导师退回才能改 —— **这段发布语义全是拟的**
- 受访者撤回：加了「我已了解影响范围」勾选才解锁红色确认键
- 文件删除：六类级联逐条 + legal hold 拦截 + **强制填原因（≥4 字）才可删**

## S-15 摄取九态的表达方式
每份处理中文件一条**阶梯进度条**（走到哪一态一目了然）+ 失败态**三段式**（在哪步/为什么/能做什么）
+ 抽屉底部常驻**九态图例**。刻意反「转圈圈」。位置：`/projects/demo/files`。

## S-16 重叠语音「待人工指派」的力度（O-13）
`seg-08` 是真重叠：`speakerId: null`、`status: "pending-manual"`、列出候选人。
UI 显示 warning 徽章「待人工指派」+ 指派区明写「系统**不自动归属**」+ **无默认选中**，
另有「保持待指派」的退出口。相邻的 `seg-17` 演示「同一段被多人认领」→「争议·多人认领」，同样不静默解决。
> 请确认这个力度是否符合 O-13 的本意。

## S-17 画布的三件事
- **画布是壳不是引擎**：`canvas-stage` 是静态占位（已打标签），便签/节点/连线是 mock，
  **不要期待真实 mermaid 布局**。核对的是信息架构对不对。
- **「坐标不写回」的强调力度**：右栏用 warning 边框 + 禁止图标 + 「重开后位置变了不是 bug」。
  这条最容易被实现者误解为可存坐标。
- **`另存布局快照` 与「坐标不写回」并存**：快照是独立于文本的旁路数据，界面明写「不参与 Markdown 往返」。

## S-18 其余较轻的
- 准备度阈值配色：≥60% primary / 30–59% warning / <30% destructive（UC 未定分档）
- 四态项目卡走两套渲染（进行中/已交付用 chip 流，筹备中/草稿用 Progress+chip）——按状态换布局，非统一模板
- 冲突条做成可显式触发的一态（`?conflict=on`）；原型此条「确认缺失」
- Studio 五步进度（设计方向→信息架构→页面与调整→交互与状态→交付）是归纳出来的
- 后台无右栏（两栏），与对话/画布的三栏不同
- 合规邮箱 `compliance@yuanyang-consulting.cn` 是占位，UC 只写「合规邮箱」没给值
- 问卷右栏「点回原始分布」的锚点只在「分析」tab 激活时可解析（其余 tab 下目标不在 DOM）
