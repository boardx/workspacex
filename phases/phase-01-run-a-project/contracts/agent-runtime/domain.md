## 零、这个域的一句话

**三条链路，一个交点。**

```
20-model：模型能不能用（准入测试 → 启用 → 可选范围 → 机密硬路由）
21-mcp  ：工具能不能用（注册 → 默认隔离 → 放行 → 授权范围）
04-agent：这个 agent 现在能做什么 ＝ ① ∩ ② ∩ ③
                                      ↑     ↑     ↑
                                   21-mcp 本模块 11-board
```

交点是**有效权限求交**（O-23）与**每一次调用的留痕**（UC-4.4）。
这两件事把三条链路绑成一个不可拆的束。

## 一、实体与值对象

### A 组 · 模型池（`20-model`，F48–F51）

#### `Model`（实体）—— 模型池里的一条记录

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `ModelId` | **所有引用一律用 id，不用名称字符串**（否则停用无法级联，UC-20.1 R10） |
| `orgId` | `OrgId` | 租户隔离键（RLS） |
| `kind` | `"closed-api" \| "self-hosted"` | [原型] 二分。**客户机密材料只走 `self-hosted`** |
| `shape` | `"single" \| "composite"` | O-22③：组合模型是**池里的一条记录**，不是 agent 侧拼字段 |
| `vendor` / `displayName` | `string` | `whisper ＋ sonnet` 是一条**组合记录的显示名** |
| `capabilityTags` | `string[]` | 推理 / 视觉 / 工具调用 / 中文转录·说话人分离… |
| `contextWindow` | `number` | |
| `unitPrice` | `PriceEntry` | O-37：组织可配价目表，**CNY，手工维护，不自动同步** |
| `complianceAttrs` | `ComplianceAttr[]` | O-38：**受控枚举，取值从配置读取，枚举内容当前为空** |
| `status` | `"待测试" \| "未启用" \| "已启用"` | [原型] 三取值 |
| `credentialRef` | `CredentialRef \| null` | 闭源 API：加密存储、**永不回显**（I-6） |
| `endpointRef` | `EndpointRef \| null` | 自托管：端点对非管理员**不可见** |
| `isDefault` | `boolean` | ⚠ [待定]，见下 |

#### `CompositeMembers`（值对象）—— 组合记录的 pipeline

有序成员列表 + 各自角色（`转录 → 生成`、`本地预处理 → 闭源生成`）。
组合的 `complianceAttrs` = **成员交集（取最严）**；**含任一闭源成员即整条视为闭源链路**（I-4）。

#### `AdmissionTest`（值对象）—— 五项准入测试的**一条判读记录**

五项固定：`连通性` `结构化输出` `工具调用` `长上下文` `中文表达`。
每条记：`item` / `verdict: 通过|不通过|不适用` / `judgedBy` / `judgedAt` / `evidence`。

⚠ **O-35：不打分、不设分数线**，只记结构性断言 + **必须附证据**。
⚠ D-07：phase-1 **人工判读**，不做自动化；仅「连通性」允许一次真实探活（[待定]，见下）。

#### `RoutingDecision`（值对象）—— 每次模型调用前的一条判定记录

`callId` / `containsConfidential: boolean` / `evidenceMarks: ArtifactVersionId[]` /
`candidateModelIds` / `selectedModelId \| null` / `outcome: routed|rejected` / `reason`。

⚠ **记录中不得包含机密内容原文**（I-13），只记标记与依据 id。

### B 组 · MCP 服务器（`21-mcp`，F52–F54）

#### `McpServer`（实体）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` / `orgId` | | |
| `name` / `description` | `string` | [设计] 说明**必填**——「第三方·未审计」正是隔离的理由 |
| `endpoint` | `EndpointRef` | 对非管理员**不可见**（内网地址属敏感信息） |
| `credentialRef` | `CredentialRef` | 加密存储、永不回显 |
| `authScope` | `ToolAuthScope`（见下） | 🔴 **2026-07-30 修正**：此前写死为服务器级三值 `仅项目负责人 \| 仅某团队 \| 全体成员`。原型 `16,684,300` 的**逐工具授权表**给的是**五值**，且授权粒度在**工具**上。本字段现为**服务器级上限**，工具级在其内**只能更严**（同 O-23 收紧优先）。⚠ **与 O-20 冲突，需人类确认**（O-20 的问题陈述通篇未提 `逐工具` / `副作用` / `需人工确认每次` / `未开放`，很可能是没看过这张表时把模型收窄成三值的）——**不代改 O-20** |
| `quarantineUntil` | `Timestamp \| null` | 🔴 **新增**（原型 `16,683,800`）：第三方源的**隔离期截止时刻**。⚠ **是时间戳不是布尔**——布尔答不了「还剩几天」「到期了没有」。`null` = 非第三方源 / 未进入隔离期 |
| `quarantineDays` | —（**不落字段**） | ⚠ 隔离期**天数**不落在实体上，读组织级参数（与 O-01「留痕保留期」同形）。原型的 **14 天**是**有出处的默认值**（`16,683,800` 逐字），可落 `known: true`、`source = 原型 16,683,800`。**不得在此再抄一份 14** |
| `reviewStatus` | `"待安全评审" \| "已放行" \| "维持隔离" \| "有条件放行"` | **O-20：独立字段，与 `authScope` 正交** |
| `connectionStatus` | `"已连接" \| "限流中" \| "已隔离" \| "不可达" \| "凭据失效"` | **O-20：独立字段，`不可达` 不得写成 `已隔离`** |
| `reviewStatus` 补值 | `"已到期待复核"` | 🔴 **新增**（原型 `16,683,800`「**期满复核后**才对成员开放」）：隔离期到期**不自动开放**。缺这个态时，到期的服务器会静默停在 `待安全评审` 里无人处理——「到期了」和「还没人看」在界面上无法区分 |
| `involvesCustomerData` | `boolean` | **O-19：按服务器整体标注**，工具级留 phase-2 |
| `isEgress` | `boolean` | O-19 同源：「是否出组织」同粒度＝服务器整体 |

⚠ **三字段正交是一条硬不变量**（I-16）：隔离是**策略结果**，不可达是**运行事实**，
待评审是**流程状态**。压成一个枚举就无法排障，也无法回答「为什么这个工具用不了」。

#### `McpTool`（实体）

`fullName`（**恒为 `mcp:<服务器>.<工具>`**，I-19）/ `signature` / `paramSchema` /
`schemaFingerprint`（用于 I-20 的签名变更检测）。

🔴 **以下三项 2026-07-30 补**（此前 `逐工具` / `副作用` / `需人工确认每次` / `未开放`
在 `contracts/agent-runtime/**` 与 `requirements/21-mcp/**` **全部 0 命中**）。
出处：原型 `WorkspaceX Standalone.html` 偏移 `16,684,300`（面板 + 表头 + 实值）
与 `16,688,300`（封顶规则），逐行按字节复核。

| 字段 | 类型 | 说明 |
|---|---|---|
| `sideEffect` | `ToolSideEffect`（**闭集**） | 🔴 **新增域字段**。原型表头第 2 列逐字 `副作用`，实值 `只读`（绿 `#0E8F7C`）/ `对外发送` / `写入外部`（红 `#C0402B`） |
| `authScope` | `ToolAuthScope`（**闭集**） | 🔴 **新增**：授权挂在**工具**上（原型逐字 `逐工具授权 · 9 个`）。服务器级 `McpServer.authScope` 是**上限**，本字段**只能更严**（同 O-23 收紧优先，不另立一套） |
| — | 默认值 | 原型面板逐字 `默认全关 · 已开 3` ⇒ 新发现的工具默认 **`未开放`**。⚠ 这个「默认全关」**有原型出处**，与 O-23 那个**无出处**的「三个 AI 开关默认全关」是两件不同的事，**不要混用出处** |

**`ToolSideEffect`（闭集，3 值）**

| 值 | 语义 | 原型证据 |
|---|---|---|
| `只读` | 不改变外部世界 | `search_regulation` / `get_directive_text` / `compare_jurisdictions` |
| `对外发送` | 向组织外发出信息 | `submit_inquiry` |
| `写入外部` | 在外部系统落数据 | `upload_document` |

⚠ **与 `McpServer.involvesCustomerData`（O-19）正交**：后者答「数据敏不敏感」，
本字段答「**这次调用会不会改变外部世界**」。两者都要有，**不得合并**——
一个只读工具可以碰客户数据，一个外发工具可以只碰公开数据。
⚠ 取值**由握手探测得到还是由人标注，原型未演示** ⇒ **[待裁]**。
但**不给「默认只读」**：未标注时**按最严处理**（等同带副作用）。
默认只读会让一个未标注的外发工具被开放给全体成员，**这正是本不变式要防的那件事**。
⚠ 断言写「成员集合与契约相等 ∧ 未声明的值不能通过」，**不要 `toHaveLength(3)`**（E-4）。

**`ToolAuthScope`（闭集，5 值，按宽窄成全序）**

比 O-20 的服务器级三值多 **`需人工确认每次`** 与 **`未开放`** 两值。
**全序是本不变式服务端可判定的前提**，必须落成一个显式的序数常量，不靠字符串比较：

| 序 | 值 | 说明 |
|---|---|---|
| 4（最宽） | `全体成员` | 原型：`search_regulation` / `get_directive_text` |
| 3 | `仅某团队` | O-20 补齐（原型未直接出现在本表，但服务器级有） |
| 2 | `仅项目负责人` | 原型：`compare_jurisdictions` |
| 1 | `需人工确认每次` | 原型：`submit_inquiry`。⚠ 与前三者**不同类**——前三者答「谁可以」，它答「**每次都要人点**」 |
| 0（最严） | `未开放` | 原型：`upload_document`；也是新工具的默认值 |

⚠ `需人工确认每次` 必然带一条**逐次确认记录**（谁 / 何时 / 批的是哪一次调用），
否则「确认过」这件事无法证明，`I-27` 的第三层就没有落点。

##### 🔴 安全不变式 `I-28′` · 带副作用的工具**授权范围封顶**

原型 `16,688,300` 逐字：

> 带副作用的工具（对外发送、写入外部）永远不能设为"全体成员自动调用"，
> 最宽只能到"需人工确认每次"。

**形式化（服务端可判定）**：

```
maxScopeFor(sideEffect) = sideEffect === "只读" ? 4 /* 全体成员 */ : 1 /* 需人工确认每次 */

不变式：rank(tool.authScope) <= maxScopeFor(tool.sideEffect)
等价于：sideEffect ∈ {对外发送, 写入外部} ⟹ authScope ∈ {需人工确认每次, 未开放}
```

落地要求（缺任一条即判本不变式未落地）：

1. **判定抽成纯函数** `checkToolScopeCap({sideEffect, authScope}): {ok, reason?}`
   —— 与 I-P33 的 `checkProjectsColumnSet` 同形，可脱离 HTTP 直测。
2. **服务端强制**：`setToolAuthScope` 写路径上调用它，越界返回
   `TOOL_SCOPE_EXCEEDS_SIDE_EFFECT_CAP`。
   ⚠ **不得只在前端置灰**——置灰挡不住直接打 API，而这是**安全不变式**不是界面校验。
3. **`sideEffect` 变更时重新求值**：一个已开放给 `全体成员` 的工具，
   若探测后 `sideEffect` 由 `只读` 变为 `对外发送`，**必须当场收紧**（不是下次改动时才收）。
   ⚠ 这条最容易漏：只在「设置授权范围」这一个入口校验，
   会留下「从只读那一侧走进来」的绕过路径。
4. **双向断言**（不可省任一侧）：

   | 方向 | 断言 | 不写它会怎样 |
   |---|---|---|
   | **越界被拒** | `对外发送` × `全体成员` ⇒ 拒 + 该错误码；`写入外部` × `仅某团队` ⇒ 拒 | 不变式形同不存在 |
   | **合规值通过** ⭐ | `对外发送` × `需人工确认每次` ⇒ **通过**；`对外发送` × `未开放` ⇒ **通过**；`只读` × `全体成员` ⇒ **通过** | 🔴 **一个「一律拒绝」的实现会让越界那一侧全绿**（纪律第 9、10 条）。这是本条最关键的一格 |
   | **边界恰好** | `只读` × `全体成员` 通过 ∧ `对外发送` × `仅项目负责人` 被拒 | 封顶值取错一档（把 `仅项目负责人` 也放过）不会被发现 |
   | **变更路径** | `只读`+`全体成员` 的工具改 `sideEffect` 为 `对外发送` ⇒ 其 `authScope` 被收紧 | 第 3 条的绕过路径不会被发现 |

   ⚠ 断言**性质不是数量**：不要写「拒绝了 N 次」。

#### `SecurityPolicy`（值对象）—— 四开关

| # | 开关 | 默认 | 可关闭性（O-19） | 执行体 |
|---|---|---|---|---|
| 1 | 新服务器默认隔离，需人工评审后放行 | 开 | **允许关，需管理员二次确认并留痕** | 本束 |
| 2 | 涉客户数据的工具调用全量留痕 | 开 | **允许关，需管理员二次确认并留痕** | 本束 + UC-4.4 |
| 3 | 客户机密材料仅允许本地模型处理 | 开 | **不允许关**（只读常开） | UC-20.3（本束 A 组） |
| 4 | 允许 agent 自行发现新 MCP 服务器 | **关** | **phase-1 不提供打开能力**（只读常关） | 本束 |

⚠ **这个枚举是封闭的**：四条，新增或改可关闭性**必须走 ADR**。
理由与 ADR-021 对丢弃原因枚举的处理同构——zod 能写 `switches: 4 项`，写不了「这是封闭的」。
⚠ 断言要写「成员集合与契约一致 ∧ 未声明的值不能通过」，**不要写 `toHaveLength(4)`**
（`coding-standards` 修订 E-4 的教训）。

#### `ReviewRecord`（值对象）

`serverId` / `reviewerId` / `at` / `verdict: 放行|维持隔离|有条件放行` / `reason`（**必填**）/
`grantedToolIds`（有条件放行时）/ `authScopeSet`（放行时**必填**，I-24）。
**不可删除。**

### C 组 · Agent（`04-agent`，F55–F60）

#### `Agent`（实体，可变的「当前定义」）

`id` / `orgId` / `name` / `initials`（AV/SC/EC/LG/DV/JT）/ `role`（职责一句话）/
`visibility: "全组织可用" | "仅某组"` / `cloneFrom: AgentId | null` / `source: "self" | "community"`
（社区导入 phase-2，phase-1 只保留取值 + 置灰入口）/
`publishState: "草稿" | "待审核" | "运行中" | "已停用"`。

⚠ **发布状态机是封闭枚举**（O-22④ 补齐 `已停用`；`已归档` 作为 `已停用` 的终态子类**不单列**）：

```
草稿 ──提交──▶ 待审核 ──[批准发布]──▶ 运行中 ──停用──▶ 已停用
  ▲                │
  └──── [退回] ────┘
```

#### `AgentVersion`（实体）—— **不可变快照**（O-22⑤ / D-30）

每次「批准发布」生成一条，冻结：定义 + skill 挂载版本 + 工具白名单 + 模型 + 并发 +
降级策略 + 可见性范围。**项目开工时锁定 `agentVersionId`**，运行期内不漂移。

⚠ 没有这一条，UC-4.4 的「**当时跑的是哪一版**」无法回答——这是本束最关键的可审计性前提。

#### `SkillMount`（值对象）

`skillId` + **`skillVersion`**（UC-3.4 快照绑定，X-10 跨束）。**必须到版本粒度。**

#### `ToolWhitelistEntry`（值对象）—— 三层权限的第 ②

`toolFullName`（`mcp:<服务器>.<工具>` 或内建 `graph.*` / `brain.*`）/
`state: "在授权范围内" | "越权申请待确认" | "已准" | "已否" | "签名已变更需重新确认"` /
`elevationDecision: ElevationDecision | null`。

⚠ **粒度到工具，不是服务器**（[设计]，依据原型「12 工具 / 28 工具 / 6 工具…」可枚举）。

#### `ElevationDecision`（值对象）—— 越权申请的裁决（O-21）

`securityReviewerSig`（安全评审人）**＋** `orgAdminSig`（组织管理员会签）**＋** `reason`。
**两条签名缺一即流程不合规**，且该白名单条目不生效（I-28、UC-4.4 V22）。

#### `DegradePolicy`（值对象）

三取值：`按阈值降级`（`Scout 1.5M/日 · 80%`）/ `不降级`（`Ledger 800k/次`）/ `跟随组织级`。
**按任务类型的分级优先级更高**，且它本身是封闭四档：

| 任务类型 | 行为 |
|---|---|
| 普通生成 | 自动降级 ＋ **消息标注**（`降级运行 · sonnet`） |
| 研究 / 财务 / 合规 / 决策辅助 | **先问人再降级**（静默降级 = 污染证据） |
| **含客户机密** | **禁止降级** |
| 无合格替代模型 | **明确失败** |

#### `ConcurrencyLimit`（值对象）—— O-22②

`有效并发 = min(agent 级上限, 组织级剩余额度)`；**超限排队，不拒绝、不丢弃**，
向发起人显示**排队位次与预计等待**。**项目级并发 phase-1 不做。**

#### `LoadRule`（实体）—— 蓝本第 12 项「Agent 编排」

`trigger`（**只能引用 `agenda_segment_id`**，D-03a）/ `agentIds` / `priority`。
同时命中多条时按优先级**取前 4 个**，被裁剪的必须可查（不得静默丢弃）。

⚠ **D-03a 是全局定稿**：`agenda_segment`（基数随档位变）/ `design_facet`（**恒 16**）/
`method_stage`（**恒 9**）三名不得共用。对外事件只有
`agenda_segment.switched` / `agenda_segment.state_changed` 两个。

#### `ThreadAiTeam`（实体）

`threadId` / `roster: AgentPresence[]` / `manualOverride: boolean` /
**`rosterCount`（编制数）与 `presentCount`（在场数）是两个字段**。

`AgentPresence`：`在场` / `跑批中` / `空闲`（[原型] 三取值，封闭）。
⚠ `presentCount` 只数 `在场`（S-06 已定义：跑批中与空闲不计入在场）。

#### `ProjectAiPermission`（值对象）—— 项目级三开关

`facilitatorProposesConvergence` / `liveTranscription` / `aiWritesOnCanvas`。
