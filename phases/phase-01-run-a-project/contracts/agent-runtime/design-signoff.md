## 为什么 model + mcp + agent 是**一个**束而不是三个

判据是 `contract-design.md` §一：**这些东西的不变量互相依赖吗**。这里是互相依赖的，且是硬依赖：

- **三层权限求交**（`有效权限 = MCP授权范围 ∩ agent工具白名单 ∩ 任务权限包`，O-23）
  的第 ① 层住在 `21-mcp`、第 ② 层住在 `04-agent`。**拆开签，agent 束签的时候会发现
  MCP 束的授权范围模型不够用**——正是 ADR/执行书点名要避免的那种情况。
- **「只有测试通过并已启用的模型才出现在 agent 的模型选择里」** 是 agent 侧的硬闸门，
  但判定数据全在 `20-model`；组合模型（O-22③）更是「模型池一条记录 ⇔ agent 侧恒为单个
  `model_id`」的**同一条不变量的两面**。
- **机密硬路由**（UC-20.3）的开关住在 21-mcp（开关三）、执行体住在 20-model、
  展示与批准住在 agent 的批准卡、留痕住在 agent 的 tool-call 审计。**一条控制、四处落点。**
- **tool-call 审计**（UC-4.4）的命名空间 `mcp:<服务器>.<工具>` 由 21-mcp 定义，
  「没有留痕就没有调用」这条硬前置同时约束 MCP 调用与模型调用。

⇒ 三者的不变量绑在一起，必须同束。

      重点看这七类是否都覆盖：并发、越权、依赖失败、幂等重放、部分成功、超时、撤回中。
- [ ] **`NO_LOCAL_MODEL_AVAILABLE` 是不是真的「明确失败」而不是任何形式的回落**——
      UC-20.3 R9 明写「本用例不允许任何形式的功能降级」。这一条错了等于数据泄露。
- [ ] **`PROVENANCE_WRITE_FAILED` ⇒ 调用失败** 这条硬前置（UC-4.4 E2 / R7）
      是不是所有工具调用路径都遵守，还是只有涉客户数据的那条。
      两份 UC 说法不同：UC-4.4 说全部 tool-call，UC-21.2 E5 只说涉客户数据。**需你定口径。**
- [ ] **拒绝语义是否泄露存在性**：可见性范围外的 agent「接口不得返回其存在性」（UC-4.1 R5），
      因此必须是 `AGENT_NOT_FOUND` 而非 `FORBIDDEN`——与 phase-00 `artifact` 束
      对草稿的 404-非-403 处理同源，请确认口径一致。
- [ ] **超限排队不是拒绝**（O-22②）：`CONCURRENCY_LIMIT` 不是错误码而是一个**排队响应**，
      带位次与预计等待。请确认这个建模（错误 vs 正常响应）是你要的。

## ③ API 契约 —— 对外形状与错误码对不对

**本束有对外 HTTP 面。** 第 ③ 件的落点是：

```
packages/contracts/src/agent-runtime.ts     ← zod 单一事实源
```

⚠ **该文件尚未创建。本轮产出的是签核骨架，不含代码。**
它是**签核通过后、开工时的第一件产出**——`covers` 里第一个被 claim 的 feature
（依赖序上应是 F48 或 F52）必须先落这份 zod 契约，再写实现，因为：

- 前端 mock 必须从它生成（`contract-design.md` 硬规则 2：不许手写 mock）；
- 响应体也要被它校验（硬规则 6），**特别覆盖拒绝路径**——本束的价值一大半在拒绝路径上；
- 新增文件时同时在 `packages/contracts/src/index.ts` 导出。

⚠ 本束体量大（48 个操作），若在实现期发现单文件超 2000 行，按 AGENTS.md 的文件规模约束
**按 model / mcp / agent 三个域切分为 `agent-runtime/{model,mcp,agent}.ts` 并由
`agent-runtime.ts` 汇总导出**——但**束仍是一个**，签核面不因文件切分而分裂。

### 签核前请重点确认

- [ ] **错误码语义在三个域间是否一致**：同一种失败（依赖不可用 / 越权 / 并发冲突）
      在 model / mcp / agent 三侧必须是同一个码。这正是阶段一致性复核要查的「错误语义是否一致」，
      本束因为跨三模块，**在束内就已经有这个风险**。
- [ ] **`routeModelCall` 是不是唯一执行点**——UC-20.3 R10 要求「任何模块自行调用模型
      都必须经过同一个路由执行点，不得旁路」。这条要靠**架构测试**（依赖规则）保证，
      不是 zod 能表达的。请确认这条架构测试有人写。
- [ ] **`listSelectableModels` 只有一份实现**（UC-20.2 R7），三个消费点
      （agent 下拉 / skill 下拉 / 蓝本模型策略）复用。请确认不会各写各的。
- [ ] **凭据字段根本不在响应 schema 里**（不是「返回后再过滤」）——
      UC-20.1 AC3「凭据永不回显、永不出现在接口响应、日志与审计明文中」。
