# 契约束 `recording` 设计签核

**录音 / 转写 / 说话人 / 引述打点 / 保留期** —— 从「点开始录音」到「到期删除并出删除证明」的整条链。

依据 UC（四份全读）：
`05-rec/uc-5-1 开启多路录音并实时出字`（R12 17 条）·
`05-rec/uc-5-2 结束后指派说话人`（10 条）·
`05-rec/uc-5-3 标记引述与打点`（10 条）·
`05-rec/uc-5-4 转写回流与保留期`（11 条）

## 这个束为什么这么切

判据是「**这些东西的不变量互相依赖吗**」（`contract-design.md` §一）。这十一件互相咬死：

- **anchor 完整性**（F70）是 F76 引述、F77 AI 打点、F73 物化的**共同前提** ——
  没有可定位 anchor 的 Segment 不得入库、不得进检索、不得被 AI 引用。
- **重叠段门禁**（F71）是 F74 指派的**唯一解除出口**，也是 F76 引述的**拒绝条件**。
- **声纹销毁**（F75）挂在 F74 的指派完成动作上，且它的存活期（7 天）
  **必须短于**F78 的材料保留期（180 天）—— 拆开会出现「一个束签了，另一个束签的时候
  发现前者的不变量不够用」。
- **保留期参数化**（F78）是 F79 同意书渲染的唯一取值来源，三处呈现必须同源。

## ② 用例 —— 用例接口与失败模式穷举对不对

→ 详见本目录 **`usecases.md`**（28 个用例端口）
→ 支撑材料 **`domain.md`**（40 条不变量 I-1～I-40）与 **`coverage.md`**（R12 逐条映射 + 12 条缺口）

失败模式按九类穷举：并发 / 越权 / 依赖失败 / 幂等重放 / 部分成功 / 超时断网 /
撤回中 / 权限中途被撤回 / 空态。检查表在 `usecases.md` §八。

### 签核前请重点确认

- [ ] **声纹 embedding 的销毁时点与级联失效（O-14）是本束最硬的一条不变量。**
      I-13～I-18 六条：指派完成即**物理删除**（不是打标记）· 第 7 天兜底 ·
      写审计事件 · 级联失效派生物与缓存 · 重跑只产生新派生版本 ·
      **到期删除任务的作用域不含它**。
      ⚠ 最后一条最容易漏：把 embedding 当普通材料处理，就是把一条 **7 天**约束悄悄松成 **180 天**。
- [ ] **重叠段不得被静默归属（I-7）**：`status='pending-manual' ⟹ speakerChannelId IS NULL`。
      这条是 O-13 的数据层表述，且**不依赖任何数值阈值**，可以立即写 verification。
      数值型 DER 阈值保留为 [待补数]，**不阻断**。
- [ ] **引述的四个拒绝码必须可区分**（partial / lowConfidence / pending-manual / disputed），
      因为界面要给出**不同的「去校对」出口**。合成一个 `SEGMENT_NOT_CITABLE` 会让界面无法分流。
- [ ] **保留期一律读参数，不写常量（I-32）。** O-01 给出默认值（材料 180 天）
      **不放松这一条** —— 默认值是**留存策略内核的配置项初值**，不是本模块的常量。
      配套 I-33：组织默认值缺失时**拒绝开始录制**，不用隐含常量兜底。
- [ ] **保留期三处呈现必须同源（I-40）**：研究计划参数面板 / 材料库「保留至」/ 授权页告知文案。
      ⚠ 这正是本仓最高发缺陷（同一事实声明在多处，已发生五次）的下一个候选点。
- [ ] **真名不冗余进 Segment 行（I-10）**：`segments` 表**没有** `personId` / `personName` 列。
      冗余进去，撤销（uc-5-2 AC1）与撤回（uc-5-4 / uc-6-3）都无法一次到位。
- [ ] **两个端口是本束替 UC 补的**：`correctSegmentText`（D-10）与 `markDispute`（D-9）。
      请逐一裁定 —— 它们正是「实现者替 UC 做决定」最容易发生的位置。
- [ ] **五个枚举的封闭性未裁决**：`EvidenceNature`（D-7）· `AnnotationKind`（D-8）·
      `disputed` 是否入 `SegmentStatus`（D-9）· 数据驻留地区（D-6，明确留空）·
      `PiiType` 五类是否为**最小集**（O-39 说「只增不减」，那它就不是封闭的，
      新增要不要走 ADR 需明确）。

## ③ API 契约 —— 对外形状与错误码对不对

**本束有对外 HTTP 面。** 第 ③ 件的落点是：

```
packages/contracts/src/recording.ts        （zod 单一事实源，尚未创建）
```

⚠ **这个文件现在不存在。本轮只是骨架。** 它是**签核通过后、F69 开工时的第一件产出**，
且必须在写任何 `apps/api` / `apps/web` 代码之前完成 —— 因为**前端 mock 从它生成，不许手写**
（`contract-design.md` §五-2）。新增文件时同步在 `packages/contracts/src/index.ts` 导出。

这一份生成四样东西：后端 DTO + ValidationPipe · 前端 client 类型 · OpenAPI · 前端 mock。

⚠ **响应体也要被契约校验**，不只是请求体（`contract-design.md` §五-6）。
本束尤其要覆盖**拒绝路径** —— `markQuote` 的四个拒绝码、`revealPiiOriginal` 的越权拒绝、
`destroyVoiceprintEmbeddings` 的部分失败，都是契约最容易写错的地方。

### 签核前请重点确认

- [ ] **默认读接口的响应体里绝不能有 PII 明文**（I-19）。这要写成**契约级**约束：
      `listTranscript` / `getSegment` / Context Pack 三处的 out schema 都只有遮盖后文本，
      原文只从 `revealPiiOriginal` 这一个口出去。
- [ ] **`resolvedSpeaker` 是解析结果不是存储字段。** 契约里它是 out-only 的派生字段，
      没有对应的 in 字段 —— 否则会诱导实现把真名写回 Segment。
- [ ] **错误码的跨束一致性**：`EVIDENCE_WITHDRAWN` / `PERMISSION_REVOKED_MIDWAY` /
      `IDEMPOTENCY_KEY_CONFLICT` 三个语义在别的束里也会出现。
      同一种失败在不同束里必须是同一个错误码（这是阶段一致性复核的四查之一）。
- [ ] **`DeletionCertificate` 的字段与签名形态 [待定]**（缺合规输入，D-3）。
      契约现在只能断言「有/无」，断言不了「格式对不对」。请确认这样开工可接受。

## 本束与哪些束有交叉约束（留给阶段一致性复核）

> 详表见 `domain.md` §三（X-1～X-10）与 `coverage.md` §五（12 条缺口）。这里只列结论。

| 对方束 | 交叉的是什么 | 不复核会怎样 |
|---|---|---|
| **`files`（22-files）+ phase-00 `artifact`** | **F73 是显式跨束**：录制产物物化为文件、登记为 `artifacts`+`artifact_versions`、`derived_from` 指回原音频；到期删除要**删到文件层** | 本束若另建索引表，就有两套证据平面。或者两边都以为对方做了「在文件浏览器可见」 |
| **phase-00 `context-pack`** | Segment/anchor 是统一上下文模型；AI 侧**一律经 Context API**，不得直查 `segments`/向量库 | 各下游各自直连 ⇒ PII 策略与权限判定有 N 份实现 |
| **17-gov（D-16 两级脱敏）** | PII 遮盖内核。本束只做**转写侧接入点** | 本束再造一套遮盖规则 = 第 N 次「同一事实两处声明」 |
| **00-core / 17-gov 留存策略内核** | 五参数中的 `材料保留期`。本束是**消费方** | 告知受访者的天数与系统实际执行的天数不一致 —— 合规上的实质缺陷 |
| **17-gov UC-17.2 撤回与删除** | 声纹 embedding 纳入撤回范围，但**销毁时点完全不同**（7 天 vs 180 天） | 把 embedding 当普通材料 ⇒ 一条 7 天硬约束被松成 180 天 |
| **`consent` 束 / UC-6.3** | 授权 3/4 的四项拆法（S-09）· 同意书模板消费同一个参数接口 · 撤回链两级 SLA（D-15） | ⚠ SLA 已因两处声明漂移过一次。本束**只引用不重复定义** |
| **06-itv（UC-6.4 / 6.5）** | 引述↔RQ 绑定的消费方（覆盖度视图 / 证据矩阵） | `rqId` 生命周期归属不清 |
| **10-report / 09-kg** | 引述与打点的下游引用；报告来源角标要能一路追回音频位置 | AC1 的另一半没人验 |
| **`identity`** | 六类角色的可见性；观察者在访谈现场的掩码力度（S-11 三处不一致） | 权限断言在不同屏给出不同答案 |
| **provenance / 审计查询面** | 本束五类事件（指派 / 撤销 / PII 查看 / 声纹销毁 / 删除证明）都要写审计并可检索 | 与 phase-00 `artifact` 束缺口①同一件事：各束各造查询面 |

## 确认动作

人类逐节核对 ①②③ 后，把 frontmatter 的 `status` 改为 `confirmed`，
并填 `confirmed_by` / `confirmed_at`（**ISO 8601，且不得晚于签核当下**）。

⚠ **这是人的动作，不是 agent 的。** agent 一次 `Edit` 就能把 `pending` 改成 `confirmed` ——
这正是它必须被 CODEOWNERS + CI 机械保护的原因（ADR-023 决策五）。
在 `status` 转为 `confirmed` **且**本阶段一致性复核覆盖本束之前，
`new-sprint` 与 `claim` 都会拒绝把 F69–F79 开进 sprint。

⚠ 另注意：**第 ① 件目前不具备签核条件**（`ui-preview/` 无任何截图）。
若要在截图补齐前放行，那是一个**显式的取舍**，请在此处写明理由，不要默默签掉。
