材料：本束 [`ui.md`](./ui.md)。

> 旧断言「ui-preview/ 下只有三份 markdown、没有任何截图」**已不成立**。
> ui-prototyper 已用真实组件产出 **6 屏 × 七态 + 交互/视角态，共 59 张**截图，
> 位于 `phases/phase-01-run-a-project/ui-preview/skill/`（⚠ **目录名单数 `skill/`，与束名 `skills` 不同**）。
> 逐张索引、每张演示什么、以及 **8 条真实缺口**，**只在 [`ui.md`](./ui.md) 一处维护**——
> 本文件不重抄，避免第二事实源。
>
> ⚠ 但「材料到位」**≠**「已签」：`ui.md` 第四节列的 8 条缺口须逐条裁决后，
> 人类才可把上面的 `status` 改成 `confirmed`。

**签核前请重点确认：**

- [ ] **`ui.md` 第四节 8 条「未产出」缺口逐条裁决**（接受 / 要求补画 / 移出 phase-1）。
      其中第 8 条是本束最大风险，单列如下 ↓
- [ ] **两套 skill 界面并存，收敛路径必须当场定死** —— 59 张截图全部出自 ui-prototyper
      新建的 mock 并行路由 `/skill`；本仓**已建成**的 `/admin/skill`、`/admin/feedback`、
      `/chat`、`/projects/[id]/canvas` 四块**生产屏一张截图都没有**。
      原型画的是「应该长什么样」，生产屏仍是「现在错着的样子」。
      改造生产屏 / 原型屏转正 / 二选一 —— 不定就是 ADR-020 要防的第二事实源。
- [ ] **屏 5（项目 → 设置 → 工作流编排）在本仓生产平面根本不存在** —— `/projects/[id]` 下只有
      `canvas` 与 `files`。UC-3.2 R8 那句「该屏已存在、可直接签」指的是 **HTML 原型**，
      不是本仓已建成的 React 屏。**F63 + F64 合计 8 点几乎全压在这块未建的屏上**，
      请确认这个认知差已被消除。
      ⚠ 注意：原型平面**已把它画出来**（`uc-3-2-binding-*.png`，兑现 R8 三块中的 ①②，
      第 ③ 块无图）。「原型有」不等于「生产有」，两个平面别混。
- [ ] **两处已建界面与契约语义相反**（比「没建」更危险，因为看起来是有的）：
      ① `/chat` 的 `chat-settings-skill` 是**单选 chip**，而 UC-3.3 要的是**多选临时挂载列表 + 加/减**；
      ② `/admin/feedback` 的 `admin-feedback-triage-{id}` 把**归类**与**生成提案**合成一个按钮，
      而 UC-3.6 AC4 要求先归类、`实现层缺陷` 类**不出现**生成按钮。
      改造还是并存？**并存会立刻产生第二事实源。**
- [ ] **F66 notes 里「停用入口为原型确认缺失」这句已过期** —— 本仓已建成
      `admin-skill-disable-{id}` 与共享 `DisableDialog`。真正缺的是版本链、引用清单三栏、
      `[恢复]`、影响预览。请确认这处更正。
- [ ] **对话消息上没有任何 👍/👎 控件** —— UC-3.6 整条闭环的**数据源头缺失**，
      满意度百分比这个字段至今无来源（原型里的 94%/91% 是编的）。
- [ ] **本束特有的 7 个状态**（`被退回` / `源方法已过期` / `待复核` / `已退回` / `待上线` /
      `[恢复]` 出口 / `样本不足`）目前**全部未建**；`satisfaction === 0` 当前是被**隐藏**，
      不是显示「样本不足」——这正是 AC3 反对的那种「漂亮数字」的镜像失败。

## ② 用例 —— 用例接口与失败模式穷举对不对

材料：本束 [`usecases.md`](./usecases.md)（**33 个用例 · 38 种失败模式 · 12 个端口**）。

**签核前请重点确认：**

- [ ] **失败模式穷举了吗** —— 38 种。特别看六条**不得静默**的：
      `TODO_SYNC_FAILED`（编排保存成功但 N 条待办没同步）·
      `CONTEXT_BUDGET_EXCEEDED`（不得静默丢弃某个 skill 的注入）·
      `MODEL_UNAVAILABLE`（明确失败，**不静默换模型/不回退版本**）·
      `RELEASE_FAILED_PENDING`（已复核但没上线，必须有通知）·
      `ATTRIBUTION_MISSING`（无法归因的评价**不得随意归给某个 skill**）·
      `DEPENDENCY_UNAVAILABLE`（晋升时 Skill 库不可写，不得「知识已生效但无 skill 也无提示」）。
- [ ] **`SAMPLE_INSUFFICIENT` 被放在错误枚举里合适吗** —— 它其实是一种**正常返回态**，
      放进枚举是为了让前端有唯一的分支来源。若你认为该拆成 `out` 的联合类型，请在此裁决。
- [ ] **`hardDeleteSkill` 是一个只有失败出口的用例** —— 它存在的意义是「拒绝要有可断言的形状」
      （返回引用清单）。请确认这个建模，而不是干脆不提供该端点。
- [ ] **`disableSkill` 的 `mode`（立即中断 / 跑完当前一轮）复用 T03 的 `DisableDialog`** ——
      本束**不重复定义**这个二选一语义。请确认这条复用边界。
- [ ] **组员拒绝在服务端**（`MEMBER_CANNOT_SELF_MOUNT`）—— 不是前端隐藏入口。

## ③ API 契约 —— 对外形状与错误码对不对

**第 ③ 件的落点：`packages/contracts/src/skills.ts`（zod 单一事实源）。**

> ⚠ **该文件尚未创建。本轮只是设计骨架** —— 它是**签核通过后、开工时的第一件产出**，
> 且必须同时在 `packages/contracts/src/index.ts` 导出。
> 本束**有对外 HTTP 面**（33 个操作），因此走 ADR-023 决策一的第一种形态，
> 不适用「无对外 HTTP 面」的例外。

**签核前请重点确认：**

- [ ] **`Skill.status` 四态枚举的封闭性** —— 断言写成「成员集合与契约一致 **且未声明的值不能通过**」，
      **不要**写 `toHaveLength(4)`（修订 E-4 的教训：那会让经 ADR 评审的正当新增被自己的测试拦下）。
- [ ] **两个状态字段不得合并**：`Skill.status`（四态）与 `SkillVersion.state`（草稿/待审核/生效/已归档）。
      合并会让「skill 已启用、新版本在审」无法表达。⚠ 两处都有「已归档」但**含义不同**，
      这是本束最容易被误实现的一处（见 `domain.md` 第二节）。
- [ ] **来源标记五取值**（`CC / 自建 / 画布 / 社区 / 晋升生成`）—— 当前 mock 只有 `手工` / `方法晋升` 二值，
      **契约与实现已不一致**。请确认收敛方向：契约单源 → 生成 mock（不许手写）。
- [ ] **响应体也要被契约校验**（通用规则，修订 B-8）：每条路由的响应在测试里逐条
      `safeParse`，**并特别覆盖拒绝路径**——本束有 38 个拒绝码，拒绝体最容易漂。
- [ ] **最小样本量 10 / 聚合浮现阈值 3 不进本契约**，进 `packages/contracts/src/thresholds.ts`
      的待定阈值登记表（该机制已存在）。本仓已因编造数值出过一次事故（ui-preview S-04）。
