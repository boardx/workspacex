## 这个束的核心：快照不漂移

**蓝本是定义层，项目是实例层，两层之间只有「套用时单向写入 + 一个不可变版本引用」这一条线。**
本束全部不变量都在守这一条线的三个面：

1. **快照不漂移** —— 绑定后上游发布多少个新版本都不改写它（I-1 I-2 I-3 I-4）
2. **套用即脱钩** —— 项目侧的写永远打不到定义层，且这条要能**用「接口面为空集」断言**（I-9）
3. **不回写蓝本** —— 唯一反向通道是 UC-2.3 的显式回提，且**提交 ≠ 生效**（I-10 I-11 I-12）

## ③ API 契约 —— 对外形状与错误码对不对

**本束有对外 HTTP 面。** 第 ③ 件的落点是：

```
packages/contracts/src/templates.ts        （zod 单一事实源）
```

⚠ **该文件尚未创建，本轮只是骨架。** 它是**签核通过后、开工时的第一件产出**——
不是先写代码再补契约。`packages/contracts/src/` 现有 9 个文件（`artifact.ts` / `auth.ts` /
`context-pack.ts` / `identity.ts` / …），本束按同一形状新增 `templates.ts` 并在 `src/index.ts` 导出。

这一份生成四样东西：后端 DTO + ValidationPipe / 前端 client 类型 / OpenAPI / **前端 mock**。
⚠ **mock 必须从契约生成，不许手写**（本仓已五次因「同一事实声明在两处」而漂移）。
⚠ **响应体也要被契约校验**，不只请求体，并**特别覆盖拒绝路径**（修订 B-8）。

### 签核前请重点确认

- [ ] **33 个操作、22 个错误码的形状对吗** —— `coverage.md` 第六节已做反向检查：
      **33 个操作全部有 UC 要求，无孤儿接口。**
- [ ] **错误码语义跨束一致吗** —— 本束的 `NO_ORG_ROLE` / `NO_PROJECT_ROLE` / `ROLE_INSUFFICIENT`
      是从 `identity` 束**透传**的，不是本束新造的第二套。请确认同一种失败在各束里是同一个码。
- [ ] **拒绝响应不得泄露资源存在性** —— `BLUEPRINT_NOT_FOUND`（越权可见）与「真的不存在」
