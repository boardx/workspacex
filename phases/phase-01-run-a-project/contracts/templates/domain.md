## 〇、本束的一句话

**蓝本是定义层，项目是实例层，两层之间只有「套用时单向写入 + 一个不可变版本引用」这一条线。**
本束全部不变量都在守这一条线：**快照不漂移**（绑定后上游变化不改写它）、
**套用即脱钩**（项目侧的写永远打不到定义层）、**回流必须显式且需审核**（UC-2.3 是唯一反向通道）。

⚠ **术语三分（D-03，人类已拍板），本文严格区分，代码/字段/测试断言中不得互相替代、不得裸用「环节」**：

| 术语 | 字段前缀 | 数量 | 归属 |
|---|---|---|---|
| **设计配置项** `ConfigItem` | `config_item_*` | 由定义表驱动（原型面板标 16、实际枚举 15，见 I-5） | 蓝本设计器的配置维度，本束主体 |
| **议程环节** `AgendaStage` / `AgendaSegment` | `agenda_stage_*` / `agenda_segment_id` | 随时长档位变：半天 7 / 一天 11 / 两天 14 / 三天 19 | 第 2 项配置「流程 Agenda」的内容 |
| **方法环节** | — | 固定 9 个（PESTEL→PRD） | 属 09-kg，**与本束无关** |

### 定义层（后台侧）

#### `Blueprint`（实体）—— 蓝本本体

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `BlueprintId` | |

| `defaultTier` | `DurationTier` | 原型默认「两天」 |
| `visibility` | `"org-wide" \| "team-only"` | O-18 ④；`team-only` 时 `teamId` 非空。团队单一归属（O-12）⇒ 判定是一次相等比较 |

#### `ConfigItemDefinition`（值对象）—— **配置项定义表**，本束最重要的一张表

O-07 与 O-18 ⑤ 把两个未决（「第 16 项是什么」「哪些必填」）收进**同一张表**吸收。

| 字段 | 类型 | 说明 |
|---|---|---|
| `key` | `string` | 稳定标识，例 `topic-and-background` |
| `group` | `"basic" \| "pre-input" \| "onsite" \| "ai" \| "output"` | 五组，**封闭枚举**（I-20） |
| `ordinal` | `int` | 组内序 |
| `required` | `boolean` | **发布门槛的唯一驱动**（I-6） |
| `label` | `string` | 例「流程 Agenda」 |

已枚举的 **15 项**（uc-2-1 R3 表，V1b 逐项断言）：
基本配置 4（主题与背景 / 流程 Agenda / 分组规则 / 角色与权限）·
会前输入 3（问卷 / 访谈与对象 / 会前任务）·
现场 4（场地与形式 / 项目材料 / 分组打印素材 / 组内能力）·
AI 能力 2（Agent 编排 / Skill 绑定）· 产出 2（输出物 / 报告模板）。

> ⚠ **[待定 —— 需人类裁决]** 第 16 项是否存在（O-07 判为「待补抽取」而非「待裁决」）。
> **它不阻断本束**：分母恒读表（I-5），实现与测试都是参数化的 N，补出与否都不返工。
> 但 `required` 列的**内容**仍缺人类输入（O-18 ⑤ 明写「清单本身无依据，仍需人类给出」）——
> 缺的是**数据**，不是实现方式。见 §四 缺 D-2。

#### `BlueprintVersion`（实体）—— **不可变版本**，本束「快照不漂移」的落地点

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` / `blueprintId` / `versionNumber` | | `versionNumber` 单调递增、不复用、不缺号（I-3） |
| `content` | `BlueprintContent` | 15/N 项配置的取值 + 档位 + 形式语言 + 模型策略 + 配额策略 的**完整冻结快照** |
| `changedConfigItemKeys` | `string[]` | 版本差异：**改了哪几项设计配置**（uc-2-4 V6） |
| `rolledBackFrom` | `BlueprintVersionId \| null` | O-18 ②：回滚 = 新建等同旧版的新版本 |
| `state` | `"published" \| "archived"` | 归档只影响「还能不能新增绑定」（I-7） |
| `publishedBy` / `publishedAt` | | |

⚠ **「快照」= 一条 `BlueprintVersion` 记录**，写入后内容永不改写（I-2）——
不是应用层的一个布尔标记，也不是运行时从 `Blueprint` 当前状态反查。

#### `ModelStrategy` / `QuotaPolicy`（值对象）

`ModelStrategy` 是**三条按场景分派的策略并存，不是全局单选**：

| 场景 `lane` | 原型取值 | 语义 |
|---|---|---|
| `onsite` | `sonnet-4.6` | 低延迟优先 |
| `post-session` | `opus-4.6` | 质量优先 |
| `confidential` | 仅本地 `qwen3` | **隐私硬路由**，优先级高于配额降级（I-21） |

`QuotaPolicy`：`{ perSessionTokenBudget: 3_500_000, downgradeAtRatio: 0.9, hardStop: false }`。
达阈值**降级 + 在对话流可见提示，不硬停**（「现场卡住比多花钱贵。」）。

> ⚠ **[待定 —— 需人类裁决]** 3.5M / 90% 是否**项目级可覆盖**，以及与 proto-03
> 「组织级 90% / 成员级 85% / Agent 级」三级阈值的取舍（原型说明为「三级中最先触发的一条生效」）。
> 见 §四 缺 D-3。

#### `WorkflowTemplate`（实体）—— 蓝本第 2 项 + 第 13 项的**组织级投影**（O-02）

**不是**独立于蓝本的第二套体系。`[另存为组织模板]` 的产物是它，**不是新蓝本**。
它承载议程环节链与 Skill 绑定，带 `sourceBlueprintVersionId`（显示为 `来自后台 v2`）。

#### `AgendaStageInstance`（实体）—— 议程环节实例

持有 `agenda_segment_id` 指回**蓝本侧的议程环节定义**（D-03a 字段契约）。

#### `OrchestrationCell`（实体）—— 议程环节 × 角色编排格

矩阵的一格 = **一条角色职责，也是一条待办的发生源**。
列集**由角色表驱动，不硬编码**（O-03：项目角色恒 4，观察者只读故不入矩阵 ⇒ 三列是角色表的子集）。

#### `ProjectTopic` / `Group` / `InterviewSubject`（实体）

`ProjectTopic`：**整场唯一一个主题、一段背景**（I-13）。
`Group.status` ∈ `"recording-ready" | "short-n" | "needs-intervention"`（**封闭三值**，I-14）。
`InterviewSubject` 六列：对象 / 部门角色 / 联系方式 / 背景与要问什么 / 方式 / 状态。
⚠ 本束只负责**结构与填写**；预约、提纲、转写回流属 06-itv。

## 二、不变量

> 判据：**任何时刻都为真，违反即数据损坏**，且**能写成断言**。
> 写不成断言的是「规则」，已赶到 `usecases.md` 的 `pre:` 里。
> 🔗 = **跨束不变量**，不能在本束单独实现，须提**阶段一致性复核**。

### A 组 —— 快照不漂移（本束核心）

| # | 不变量 | 怎么断言 |
|---|---|---|
| **I-1** | `ProjectBlueprintSnapshot.blueprintVersionId` 一经写入**永不改变** | 用 v4 建项目 A → 发布 v5 → 再发布 v6 → 断言 A 的 `blueprintVersionId` 三次读取全等（uc-2-4 V2、uc-2-1 V8、uc-2-2 V3） |
| **I-2** | `BlueprintVersion.content` 一经写入**永不改写** | 对已发布版本的 UPDATE 被拒；发布 v5 后重读 v4 的 `content` 逐字段与发布时相等 |
| **I-3** | 一个蓝本内 `versionNumber` **单调递增、不复用、不缺号**；发布失败不占号 | 唯一索引 `(blueprintId, versionNumber)`；注入发布中途失败后断言下一次成功发布拿到的号 = 失败前的号（uc-2-1 V18、uc-2-4 V8） |
| **I-4** | 项目实例的**结构**恒等于其绑定版本的快照投影 | 发布 v5 后逐项 diff 项目 A 的议程环节/分组/输出物 与 v4 快照，差异为空（uc-2-4 V2） |
| **I-5** | 完成度分母 **恒等于 `ConfigItemDefinition` 的条目数**，代码与测试中不存在字面量 16 或 15 作为分母 | `grep` 断言实现与测试无硬编码分母；改表加一项后接口返回的分母自动 +1（uc-2-1 V1/V2） |
| **I-6** | 发布门槛判定语句恒为「**存在 `required = true` 且未完成的配置项 ⇒ 阻断**」，与具体是哪几项无关 | 把任一项 `required` 置 true 并留空 → 发布被拒；改回 false → 同样留空可发布（uc-2-1 V6） |

### B 组 —— 套用即脱钩（不回写）

| # | 不变量 | 怎么断言 |
|---|---|---|
| **I-7** | 归档**禁止新增绑定**，但**不禁止存量绑定的实例化**，且不影响版本可达性 | 归档 v4 后：① 新建项目可选列表不含 v4 ② 项目 A 打开/编辑/运行正常 ③ 在 A 中推进到某议程环节仍能新建画布/产出实例且实例记录版本号 = v4（uc-2-4 V7c，O-18 ③ / O-10）。⚠ 若归档即禁止实例化，进行中的工作坊切环节会当场失败 |
| **I-8** | `appliedProjectCount > 0` 的蓝本**不存在任何可达的物理删除路径** | 对已被套用的蓝本调删除接口 → 拒绝并指向「请改用归档」；**删除接口不得有任何强制参数可绕过此判定**（uc-2-4 V7b，O-18 ①） |
| **I-9** | 不存在任何 API 路径能从**项目上下文**写入 `Blueprint` / `BlueprintVersion` / `WorkflowTemplate` / 画布模板 / skill / agent 的本体 | 扫描接口面（路由 × 写方法 × 目标表）断言集合为空；在项目内改议程/分组/材料/输出物验收口径/时长/换绑模板后，逐一断言上游本体**字节不变**（uc-2-2 V4/V9d、uc-2-3 V7 —— 两者互为镜像断言） |
| **I-10** | `BlueprintChangeRequest` 处于 `pending` 时，目标蓝本的 `content` 与 `currentVersionId` **均不变** | 提交回提后重读蓝本，内容与版本号与提交前逐字段相等，只多出一条 change request（uc-2-3 V3） |
| **I-11** | 每条 `BlueprintChangeRequest.rationale` **非空** | NOT NULL + 长度 > 0 约束；不填理由的提交被拒（uc-2-3 V4） |
| **I-12** | 同一 `(blueprintId, configItemKey)` 上的多条 pending 改动**并存**，无后写覆盖、无自动择一 | 两场项目对同一处提回不同改动 → 断言 pending 集合大小 = 2，两条各自的 `rationale` 均可读（uc-2-3 V6） |

### C 组 —— 结构一致性

| # | 不变量 | 怎么断言 |
|---|---|---|
| **I-13** | 一个项目**恰好有一条** `ProjectTopic`（一个主题、一段背景）；系统中不存在第二份主题/背景记录 | 唯一约束 `projectId`；改主题后分组卡/议程/AI 上下文读到的是**同一个 topic id**（uc-2-2 V5） |
| **I-14** | `Group.status` ∈ 三值封闭集 `{录音就绪, 缺 N 人, 需介入}` | 断言成员集合与契约一致，且**未声明的值不能通过**（uc-2-2 V7）。⚠ 断言集合相等，**不要写 `toHaveLength(3)`**（修订 E-4 的教训） |
| **I-15** | 议程环节数 = `tier` 的函数（半天 7 / 一天 11 / 两天 14 / 三天 19），且第 2 项「流程 Agenda」的计数与之**相等** | 依次选四档断言两个数字同时正确；默认档位为两天（uc-2-1 V3） |
| **I-16** | 形式 = `全线上` ⟺ 议程环节表含「破冰」「举手排队」两项且各带 `addedBy: "format-setting"` 来源标记 | 选全线上后断言 +2 且带来源；切回混合后对称移除（uc-2-1 V5） |
| **I-17** | 六类初始化类别恒为封闭 6 值（定题与分组 / 议程与材料 / 会前 / 现场 / 角色与进场 / 产出），**类别不可增删** | 套用后逐项 diff「套用后会初始化什么」一览 vs 实际写入项，差异为空且六类一个不缺（uc-2-1 V9、uc-2-2 V2） |
| **I-18** | 每个输出物槽位的**验收口径字段非空** | 套用后遍历输出物槽位断言 `acceptanceCriteria` 全非空（uc-2-2 V1，D-31 正名，口径归 UC-13.2） |
| **I-19** | `satisfaction.sampleSize < 最小样本量` ⇒ 对外**不返回也不展示分数**，只返回「样本不足」标记 | 构造样本量低于阈值的蓝本，断言接口不含数值分数字段（O-37 ③；阈值取自配置，见 §四 缺 D-5） |
| **I-20** | `ConfigItemDefinition.group` ∈ 五组封闭集；`DurationTier` 的**内建**四档封闭，自定义档位另立 `custom` 且必须带显式的环节数推导规则 | 集合相等断言 + 未声明值被拒。⚠ 新增成员必须走 ADR（枚举封闭性，ADR-021 的口径） |
| **I-21** | `lane = confidential` 的调用**在任何配额状态下**都路由到本地模型 | 模拟用量达 90% 后发一条机密调用，断言仍走本地 `qwen3`；同时断言非机密 lane 确实降级了且会话未中断（uc-2-1 V10/V11）。**隐私硬路由优先级高于配额降级** |
| **I-22** | 试跑实例**不计入** `appliedProjectCount` | 试跑一场后断言计数不变；正式套用后 +1（uc-2-1 R3 第 8 步、uc-2-4 R7） |

## 三、这个域不负责什么

  Skill 绑定面板、输出物验收口径编辑器）——D-05 定为**二级 sign-off，待补抽取**。
