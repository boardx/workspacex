# 契约束 `org-admin` — 领域模型与不变量（支撑材料）

> 洋葱最内层。**不依赖任何外层**：这里出现的东西不知道 HTTP、不知道 PostgreSQL、不知道 NestJS。
> 覆盖 feature 见 `design-signoff.md` 的 frontmatter `covers:`（**权威**，ADR-023 决策三）。
> 依据 UC：`01-auth/uc-1-1`（仅 F03 涉及的设备与会话）· `uc-1-2` · `uc-1-3` · `uc-1-4` · `uc-1-6`
> 裁决：D-01（名单实名不建账号）· D-12（观察者一等角色）· D-13/D-15（撤回两级 SLA）·
> D-18（管理员边界）· O-03（项目角色恒四种）· O-06（分组链接 + 一次性令牌）·
> O-12（一账号多组织 / 团队单一归属）· O-28（链接有效期与双人复核）· O-29（团队增删改 / 成员移除 / 配额硬阻断）

---

## 零、本束建在 phase-00 之上，**不重复声明它的不变量**

| 已由谁声明 | 内容 | 本束的关系 |
|---|---|---|
| `phase-00/contracts/auth/domain.md` | `Credential` / `Session` / `InviteCode`（14 位建组织码）；I-1 防枚举含耗时 · I-2 慢哈希 · I-5 改密吊销全部会话 · I-6 SessionId 不可猜 · I-7 **吊销是写标记不是删行** | 本束的 `DeviceSession` **挂在** `Session` 上，只加设备维度；吊销语义直接沿用 I-7，**不另定义一套** |
| `phase-00/contracts/identity/domain.md` | `Organization` / `OrgMembership`（`orgRole` 四值含 `compliance`，`teamId` 单一归属）/ `ProjectMembership`（`projectRole` **恒四值**）/ `AclBinding` / `PermissionDecision`；I-1 绑定同组织 · I-4/I-5/I-6 RLS · **I-8 管理员对个人层只见计数** · I-11 无项目上下文时 projectLayer 为 null | 本束**不重新定义**两层角色，也**不新建第二套权限表**——邀请、链接、临时提权最终都归结为 `acl_bindings` 上的判定 |

⚠ **本束不做权限判定的第二个实现。** 一旦这里开始判「这个人能不能看 X」，
`identity` 束 `Authorize` 就不再是唯一判定源。本束负责的是**判定输入怎么被产生出来**
（谁被邀请进组织、谁被链接授予了项目角色、临时读权何时消失），判定本身在 `identity`。

## 一、实体与值对象

### `Team`（实体）—— O-29 ④ 把它从「成员表上的字符串」升为一等实体

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `TeamId` | **改名不改 ID**，已有绑定不受影响 |
| `orgId` | `OrgId` | |
| `name` | `string` | 组织内唯一 |
| `archivedAt` | `Date \| null` | |

⚠ `OrgMembership.teamId` 已在 phase-00 声明为**单一归属**（O-12）。本束只补 `Team` 本体的增删改
与**删除前占用校验**（I-7）——因为它被 `AclBinding.scope = "team-only"` 引用，
删掉一个仍被引用的团队 = 一批资源的可见性判定失去依据。

### `OrgInvite`（实体）—— UC-1.6 的核心

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` / `orgId` | | |
| `email` | `string` | 小写规范化后比较；组织内**未失效的**邀请唯一 |
| `orgRole` / `teamId` | | **服务端记录值是唯一权威**（I-2） |
| `status` | `OrgInviteStatus` | 见下枚举 |
| `token` | `string \| null` | 高熵随机；**7 天**、一次性（O-28 ④）。⚠ `awaiting-review` 状态下**必须为 null** |
| `invitedBy` / `reviewedBy` | `UserId \| null` | 双人复核用；`reviewedBy ≠ invitedBy`（I-4） |
| `sentAt` / `activatedAt` / `revokedAt` | | |
| `quotaReserved` | `number` | 邀请时按角色默认额度预留 |

**`OrgInviteStatus` 六取值（封闭枚举，新增走 ADR）**：
`awaiting-review`（邀请管理员待另一名管理员批准）/ `pending`（已发出待接受）/
`activated` / `revoked` / `expired` / `send-failed`。

⚠ 界面上的「待接受邀请 · 已发送 N 天」是 `pending` + `sentAt` 的**投影**，不是第七个状态。

### `Participant`（实体）—— 参与者名单条目，D-01「名单实名」的落点

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` / `projectId` | | |
| `phone` | 见 `[待定 A]` | **存储形态未定**；界面**恒掩码** `138 •••• 2049` |
| `email` | `string \| null` | 邀请载体二选一 |
| `displayAlias` | `string` | 展示层代称；生成规则见 `[待定 D]` |
| `groupId` | `GroupId \| null` | **落地组号的唯一依据**（I-13），不取链接里的组号 |
| `projectRole` | `ProjectRole` | 四值，来自 phase-00 identity |
| `confirmState` | `"invited" \| "confirmed"` | 「9 / 12 已确认」的分子 |
| `attendance` | `"lead" \| "present" \| "absent"` | 「11 / 12 已到」的分子。⚠ **`lead` 是原型的三取值之一**，它同时表达「组长」与到场，是原型的口径，见 `[待定 F]` |

### `InviteLink`（实体）—— UC-1.3；O-06 裁定携带**四元**：项目 + 组号 + 角色 + 令牌

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` / `projectId` | | |
| `kind` | `"main" \| "group"` | 主链接按身份进场；分组链接直落本组工作台 |
| `groupId` | `GroupId \| null` | `kind="group"` 时非空 |
| `projectRole` | `ProjectRole` | 身份四选的落库值；**「协同引导师」写入 `facilitator`**（I-17） |
| `validity` | `"24h" \| "7d" \| "once"` | **有效期三档**，封闭枚举 |
| `token` | `string` | **非空**（I-8）。「单条撤销」作用于**令牌** |
| `inviteCode` | `string \| null` | `KCK-8F21-EU24`，同一授权的另一载体，受同一套身份与有效期约束 |
| `usedBy` / `usedAt` | | 一次性链接的**使用者记录**（O-06 闭合了落点；呈现位置见 `[待定 E]`） |
| `revokedAt` | `Date \| null` | 撤销是写标记，不是删行 |

### `GuestIdentity`（实体）—— 免注册身份，**不是账号**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `PrincipalId` | ⚠ 与正式账号**共用同一套操作者标识空间**（uc-1-2 R10），使便签/投票/转写的归属可无缝引用 |
| `kind` | `"guest"` | **类型字段必须能区分**免注册与正式账号 |
| `participantId` | | 实名依据 = 名单条目 + 已验证手机号 |
| `projectId` / `groupId` / `projectRole` | | 权限绑定到**本场、本组、本次名单条目** |
| `archivedAt` | `Date \| null` | 项目结束自动归档；归档后不可再进场 |

⚠ **不创建账号**：走完进场流程，`credentials` 表行数不变（I-11）。

### `LiveSession`（实体）—— 现场会话，撤销语义的锚点

| 字段 | 说明 |
|---|---|
| `guestIdentityId` | |
| `deviceId` | 换设备接管时旧设备失效 |
| `enteredAtStageId` | 进场时的议程环节 |
| `survivesUntilStageId` | 令牌被撤销时写入**当前**议程环节 id；该环节结束即失效（O-06） |
| `revokedAt` | |

### `TempGrant`（实体）—— 临时提权，**失效条件是流程节点不是时间点**

| 字段 | 说明 |
|---|---|
| `subjectId` / `object` | 形如「客户方王毅」＋「第 2 组原始内容」 |
| `expiresAtStageId` | `环节 3 结束自动失效` |
| `grantedBy` / `grantedAt` / `expiredAt` | 授予、每次使用、失效三个时刻都写审计 |

### `AdminAccessLog`（实体）—— D-18 第 ② 条的落库载体

`{ adminId, projectId, objectRef, at }`。**对项目负责人可见**是它的契约属性，不是界面选项。

### `DeviceSession`（实体）—— F03，挂在 phase-00 `auth.Session` 上

| 字段 | 说明 |
|---|---|
| `sessionId` | 外键指向 phase-00 的 `Session`。**有效期、吊销语义不在本束重复定义** |
| `deviceFingerprint` / `location` / `lastActiveAt` | |
| `kickedAt` | 被踢时刻。踢 = 写 `Session.revokedAt`（沿用 auth I-7），**不是删行** |

⚠ **30 天有效期是 `[Backlog]` 数字，不是原型证据**（uc-1-1 R3 明写）。它已在 phase-00
`auth/domain.md` 的 `Session.expiresAt` 里声明，**本束不再声明第二份**。

## 二、不变量

> 判据：**任何时刻都为真，违反即数据损坏**，且**能写成断言**。
> 写不成断言的是「规则」，放进 `usecases.md` 的前置条件里。

### 组织侧（UC-1.6）

| # | 不变量 | 怎么断言 |
|---|---|---|
| **I-1** | 一条 `OrgInvite` 的 `token` **至多核销一次**；核销与 `org_member` 创建在**同一事务**内完成，不存在「令牌已核销但成员不存在」的中间态 | 并发两路激活同一 token：断言恰好一个成功、`org_member` 恰好一行；注入事务失败后断言 token 仍未核销 |
| **I-2** | 实际写入的 `orgId` / `orgRole` / `teamId` **恒等于** `org_invites` 行的服务端值，与请求携带的任何同名参数无关 | 篡改请求里的这三项后激活，逐字段比对落库值 = 邀请行原值；并断言产生一条安全审计 |
| **I-3** | `orgRole = "admin"` 的邀请在 `status = "awaiting-review"` 期间 **`token` 为 null**（链接尚未签发） | 断言该行 `token IS NULL`；断言此期间不存在任何可激活的链接 |
| **I-4** | 任一已批准的管理员邀请，`reviewedBy ≠ invitedBy` 且两者都是该组织的现任管理员 | 自批请求被拒；非管理员批准被拒 |
| **I-5** | 同一组织同一 email 至多存在**一条** `status ∈ {awaiting-review, pending}` 的邀请 | 部分唯一索引 `(orgId, lower(email)) where status in (…)`；并发两名管理员邀请同一邮箱，断言只产生一条 |
| **I-6** | `[重发]` 之后，旧 `token` 立即不可用，新 `token` 可用 | 双向断言：旧链接激活失败、新链接成功 |
| **I-7** | `Team` 被删除时，不存在任何 `OrgMembership.teamId` 或 `AclBinding.scope = "team-only"` 指向它 | 外键 + 删除前占用查询；构造占用后断言删除被拒**并返回占用项清单**（不做级联删除） |
| **I-8** | 成员被移除后：其全部 `Session.revokedAt` 非空、其全部 `status = "pending"` 的邀请转 `revoked`；**而其历史产出的行数与 `authorId` 字段完全不变** | 三段断言。⚠ 第三段是本条的重点——它与 UC-17.2 的授权撤回**结果相反**，两者不得共用同一条代码路径 |
| **I-9** | 组织未分配额度为 0 时，`InviteOrgMember` 一律失败，且不产生任何 `OrgInvite` 行 | 置零后调用断言拒绝 + 行数不变；恢复额度后同一邀请成功 |

### 项目链接侧（UC-1.3）

| # | 不变量 | 怎么断言 |
|---|---|---|
| **I-10** | 任一 `InviteLink` 行的 `token` **非空**；不带令牌的进场请求一律被拒 | 列级 `NOT NULL`；直接 GET `/w/<项目>/g/<组号>`（无 `?t=`）断言拒绝 |
| **I-11** | `validity = "once"` 的链接被使用后 `usedBy` / `usedAt` 非空，且**再次使用必失败** | 双向断言；`usedBy` 可按使用者检索 |
| **I-12** | 令牌被撤销后 **≤5 秒**，用该令牌发起的新访问被拒 | 时序断言：撤销后 t+5s 内轮询发起新访问，全部拒绝。⚠ 5 秒出自 `[Backlog]`，**原型无时限**（见 `[待定 G]`） |
| **I-13** | 撤销时刻已存在的 `LiveSession`，在其 `survivesUntilStageId` 结束**之前**写操作仍成功；该环节结束后同一会话的**下一次**请求即失败 | 双向跨环节断言：撤销 → 本环节内写成功 → 推进环节 → 同一会话写失败 |
| **I-14** | `[重置全部]` 与「逐人移出」**立即生效**，不等环节结束 | 断言执行后同一会话下一次请求即失败（与 I-13 的差别正是本条的价值） |
| **I-15** | 单条撤销**只**作废该条链接的令牌，其余链接的 `revokedAt` 保持 null | 撤销一条后逐条断言其余仍可进场 |
| **I-16** | 令牌明文与参与者手机号**不出现在**观察者与组员的任何响应体中 | 以这两种角色遍历本束全部读接口，逐响应扫描 `token` 键与手机号形态字符串 |
| **I-17** | 身份四选中的「协同引导师」落库为 `projectRole = "facilitator"`；`project_memberships.project_role` 的取值集合**恒为四值** | 签发协同引导师链接后断言落库值；并断言「协同引导师签发的链接进场后，可执行动作端点集合与引导师**逐项相等**」（O-03） |

### 免注册进场侧（UC-1.2）

| # | 不变量 | 怎么断言 |
|---|---|---|
| **I-18** | 走完整条进场流程，`credentials` / `accounts` 表的行数**前后相等** | 前后计数比对（AC1 / V1）。⚠ 这是 D-01「不建账号」唯一能被机械证明的形态 |
| **I-19** | `GuestIdentity` 的建立要求**两个条件同时成立**：令牌有效 ∧ 手机号在本场名单内。任一不成立则不建 | 四象限断言（令牌有效/无效 × 在名单/不在名单），只有一个象限成功 |
| **I-20** | 落地的 `groupId` **恒取名单条目的 `groupId`**，与链接里的组号无关 | 用第 3 组的链接、名单属第 2 组的手机号进场，断言落在第 2 组且**不返回错误**（AC3） |
| **I-21** | 名单外访客在被批准前，对本组任何资源的读取**返回 0 行**（不是空对象、不是 403 后仍可推断） | 待批期间遍历本组读接口断言 0 行 |
| **I-22** | 任一参与者可见的响应体与页面中，他人手机号**不以完整形式出现** | 全响应体正则扫描 11 位连续数字；界面快照比对掩码形态 |
| **I-23** | 换设备接管后，**旧设备会话立即失效**；恢复依据是「已验证手机号 + 名单条目」，**不依赖任何 Cookie** | 双向断言 + 清空 Cookie 后仍能恢复到同一组同一环节 |
| **I-24** | `GuestIdentity` 归档后不可再进场，但其产出仍可追溯到该名单条目 | 归档后进场断言拒绝；产出的 `authorId` 仍解析得到该条目 |
| **I-25** | 拒绝麦克风授权**不阻断进场**，且不影响任何文字类写操作 | 拒绝授权后断言进场成功 + 贴便签/投票成功 |

### 角色可见性侧（UC-1.4）

| # | 不变量 | 怎么断言 |
|---|---|---|
| **I-26** | 四视角的**可执行动作端点集合**满足 `引导师 ⊇ 组长 ⊃ 组员 ⊃ 观察者`，且**观察者集合 = ∅** | 端点集合差集断言（D-12：这是可验收断言，不是「还没设计」） |
| **I-27** | 越权字段（别组内容、组员私聊、原始转写）在响应体中**键不存在**——不是置空、不是前端隐藏 | 断言 JSON **无该键**，而非值为 null/空串 |
| **I-28** | `TempGrant` 在 `expiresAtStageId` 结束（含**提前结束 / 跳过 / 合并**）时由**服务端主动**置 `expiredAt`；其后同一请求被拒 | 三种环节终止方式各跑一遍；断言失效不依赖定时轮询（把轮询停掉仍失效） |
| **I-29** | 管理员每一次项目层内容读取，产生**恰好一条** `AdminAccessLog`，且该条对**项目负责人**的查询接口可见 | 读一次断言 +1；以项目负责人身份查询断言能查到同一条；管理员「看我的访问记录」也能查到同一条 |
| **I-30** | 视角**预览态**下不产生任何写入，也不获得超出真实角色的读权 | 预览态下全部写端点断言拒绝；读结果与真实低权角色逐字段相等 |
| **I-31** | 鉴权依赖不可用时**一律拒绝**，不存在放行分支 | 注入依赖失败断言全拒（承接 phase-00 `AUTH_SERVICE_UNAVAILABLE`） |

### 设备与会话侧（UC-1.1 / F03）

| # | 不变量 | 怎么断言 |
|---|---|---|
| **I-32** | 被踢设备的**下一次**请求即失效，不等自然过期 | 踢后立即用该设备令牌请求断言 401（沿用 phase-00 auth I-7：行仍在、`revokedAt` 非空） |
| **I-33** | 一次登录**恰好**产生一条 `DeviceSession`，且其 `sessionId` 指向的 `Session` 存在 | 计数 + 外键断言 |

### 合规侧（D-13 / D-15）

| # | 不变量 | 怎么断言 |
|---|---|---|
| **I-34** | 对某参与者手机号发起撤回后：① 进入待删除队列；② 其关联可识别信息 **≤5 分钟**退出检索范围；③ 引用过它的报告段落标为**失效而非静默删除**；④ **≤30 天**产生物理删除回执 | 四段断言。⚠ **两个时限一律引用 D-13/D-15 的单一事实源**（`apps/web/lib/withdrawal-flow.ts` + `lint-withdrawal-flow.mjs` 门控），**本束不另立数值** |

## 三、枚举的封闭性（新增必须走 ADR）

| 枚举 | 取值 | 封闭性依据 |
|---|---|---|
| `ProjectRole` | 4 值 | O-03。**已在 phase-00 identity 声明，本束不重复** |
| `OrgRole` | 4 值（含 `compliance`） | D-U3。**已在 phase-00 identity 声明，本束不重复** |
| `OrgInviteStatus` | 6 值 | 本束定义（见上） |
| `LinkValidity` | `24h` / `7d` / `once` | `[原型]` 有效期三档 |
| `Attendance` | `lead` / `present` / `absent` | `[原型]` 到场状态三取值 |
| `PermissionReason` | phase-00 identity 已定 8 码 | ⚠ 本束需要的新码（如「令牌已撤销」「不在名单」）**必须加进那一份**，不得在本束另立一套错误语义 |

⚠ 断言写法：断言**成员集合与契约一致，且未声明的值不能通过**；
**不要**写 `toHaveLength(n)`——经 ADR 评审的正当新增会被自己的测试拦下（`contract-design.md` 硬规则 7）。

## 五、这个域不负责什么

- **权限判定本身** —— 属 phase-00 `identity` 束的 `Authorize`（第零节）
- **凭据、会话有效期、改密吊销、14 位建组织邀请码** —— 属 phase-00 `auth` 束

  但不定义它。⚠ 这是本束最重的外部依赖：**两条核心不变量的锚点在另一个模块里**
- **撤回/删除的级联引擎** —— 属 22-files（T86）与 17-gov（UC-17.2）。
  本束只负责「手机号接入撤回触发」（I-34），级联的六类失效不在这里实现，**也不在这里重复计点**
- **配额策略本身**（按角色默认额度、应急池、三级降级） —— 属后台配额用例。
  本束只做**邀请时的初始额度写入**与**用尽时的硬阻断**（I-9）
