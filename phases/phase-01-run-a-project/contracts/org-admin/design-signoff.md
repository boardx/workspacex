## 这个束为什么这么切

按能力域切，判据是「**这些东西的不变量互相依赖吗**」。本束五片之所以同束：

- **免注册进场（uc-1-2）** 消费 **邀请链接（uc-1-3）** 产出的令牌——O-06 把两者绑成同一个数据结构的两面
  （`invite_link.token` + `used_by`），拆开会出现「链接束签了，进场束签的时候发现前者的令牌模型不够用」。
- **角色可见性（uc-1-4）** 是前两者的判定面：链接授予的项目角色、免注册身份的组织层空缺、
  观察者只读——**三处都必须共用同一套服务端判定**（uc-1-3 R7 与 uc-1-4 R7 互相点名要求）。
- **组织成员邀请（uc-1-6）** 与 **角色可见性** 共享「管理员不是超级用户」这条硬约束（D-18）：
  邀请权 ≠ 阅读权，两者拆开就会各写一遍。
- **设备与会话（F03）** 是唯一勉强的一片——见下方「签核前请重点确认」第 1 条。

### 签核前请重点确认

- [ ] **两条核心不变量的锚点在别的模块里。** I-13（撤销后已在场者的会话保留至**当前议程环节结束**）
      与 I-28（临时读权按**议程环节**失效，含提前结束/跳过/合并）都依赖 **06-现场协作的环节状态机**。

      **但那个锚点现在既不在本束、也还不存在。** 请确认 `StageEventSource` 的归属与事件形状。

- [ ] **邀请管理员的双人复核**（O-28 ⑥）：断言点不是「批准后能发」，而是

- [ ] **11 条 `[待定]`**（`domain.md` 第四节）：其中 **B（验证码阈值）** 与 **C（脱敏聚合最小样本量）**

## ③ API 契约 —— 对外形状与错误码对不对

**本束有对外 HTTP 面**（ADR-023 决策一要求显式声明，不接受沉默的第三种情况）。

第 ③ 件的落点：**`packages/contracts/src/org-admin.ts`（zod 单一事实源）**

⚠ **该文件尚未创建。本轮只做骨架** —— 它是**签核通过后、开工时的第一件产出**，
理由是它必须与 `usecases.md` 的 25 个用例逐条对齐，而那 25 条正是这次签核要确认的东西。
先写契约再签核，等于让评审去追着已经落库的形状跑。

创建时同步在 `packages/contracts/src/index.ts` 导出，束名与文件名对齐
（现有：`identity.ts` `auth.ts` `artifact.ts` `context-pack.ts`）。

### 签核前请重点确认

- [ ] **mock 必须从契约生成，不许手写**（`contract-design.md` 硬规则 2）。
      本项目已五次因「同一事实两处声明」漂移。⚠ 而本束现有的
      `apps/web/lib/mock/entry.ts` 是**手写的**——`/join` `/group` `/consent` `/session`
      四块屏的 mock 全在那里。契约建立时必须把它收敛掉，并由 `lint-contract-source` 门控。
- [ ] **响应体也要被契约校验，不只是请求体**（硬规则 6）。
      本束的高危面是**拒绝路径**：`INVITE_NOT_FOUND` 的四种情况必须返回**完全相同**的 body（V10）、
      观察者响应体里**不得存在**令牌与手机号键（I-16/I-27）。
      这些都要在 `contract-response.test.ts` 里逐条 `safeParse`，
      并配一组**反向断言**证明 schema 确实会拒绝漂移的 body——否则整个测试文件可能在空转。
- [ ] **枚举的封闭性是要守的性质，成员数不是**（硬规则 7）。
      本束新增四个封闭枚举（`OrgInviteStatus` 6 值 / `LinkValidity` 3 值 / `Attendance` 3 值 /
      本束新增的业务错误码）。断言写「成员集合与契约一致 ∧ 未声明的值不能通过」，
      **不要写 `toHaveLength(n)`**。
- [ ] **`ProjectRole` 与 `OrgRole` 不在本束的契约文件里重新定义** —— 它们在
      `packages/contracts/src/identity.ts`。本束 import 它们。
