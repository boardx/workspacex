## 这个束为什么现在才出现

人类 2026-07-30 提出：后台的 agents / skills 管理当前版本有问题，需要
「可以**导入市场上主流使用的 agents 和 skills**，接受各种社区的最佳实践（Claude Code 社区、
Codex 社区、open claw 等），并且需要可以看到**项目文件的浏览和编辑**功能，
这样可以实现整个 agents 和 skills 的**生命周期管理**」；
同日又问「**为什么在管理后台看不到项目蓝本**」。

核实结果（可复现）：

| 事实 | 证据 |
|---|---|
| phase-01 现有 21 个 skill/agent/model/mcp feature，**没有一条**覆盖这块 | `六道关` / `落地检查` / `查重` / `灰度发布` / `复核周期` / `AGENT.md` / `文件树` / `Codex 社区` 在 `feature_list.json` 与现有 `ui-preview/` 里**全部 0 命中** |
| F61「静态契约校验 + 安全扫描」不是同一件事 | 它校验的是**已在库中**的 skill；六道关治理的是「**把外来的东西放进我们的权限与方法体系里**」（`[原型 @16.559M]` 原文） |
| 后台左栏「AI 能力」组**缺两项** | `apps/web/lib/mock/admin.ts` 的 `ADMIN_NAV` 只有 agent/skill/model/mcp；`/admin/blueprint` 是 404，蓝本设计器在独立路由 `/tpl` |

**根因有两层：**

1. **横切机制没有宿主**。「治理与发布这一步**六种资产完全一样**」（`[原型 @16.611M]` 原文）
   是一条横切六类资产的机制。十个束按能力切，它不属于任何一个。
2. **后台外壳没有宿主**。六类资产各自的管理屏都有主，**装它们的那个容器没有**。
   于是「左栏该有几项」这个问题不属于任何人，**缺两项也就没有任何门控会红**。

### 为什么做成第 11 个束，而不是塞进 `skills` / `agent-runtime`

- **它横切六类**（上面第 1 层）。塞进某一束等于把一条横切机制实现六遍。
- **那两束人类已经签核**。往已签核的束里塞它没看过的设计，
  **等于让一次签名替新设计背书**。本仓已发生过一次同形事故，
  留痕在 `phases/phase-00-shared-kernel/design-coherence.md` frontmatter 的署名例外
  （`api-kernel` 与 `auth` 从未进入任何一致性复核，F19/F20/F21 由此被放行并已合入 main）。

> **把这条规则里的资产类型换成另一类，这条规则还成立吗？**
