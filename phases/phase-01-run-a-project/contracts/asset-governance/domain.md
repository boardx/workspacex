## 零、本束的边界判据（**先读这一节**，它决定后面每一条归谁）

本束是**横切六类资产的公共机制**，不是第七类资产，也不是任何一类资产的领域模型。
判据一句话，可机械执行：

> **把这条规则里的资产类型换成另一类，这条规则还成立吗？**
> **成立 ⇒ 归本束**（公共机制）。**不成立 ⇒ 归那类资产自己的束**（领域规则）。

| 例 | 换类后 | 归属 |
|---|---|---|
| 「负责人到期不复核则降级为仅负责人可见」 | 换成 MCP / 蓝本仍成立 | **本束** |
| 「目录结构就是发布出去的结构」 | 换成任何目录形态资产仍成立 | **本束** |
| 「带副作用的 MCP 工具永远不能设为『全体成员自动调用』」 | 换成 skill 无意义 | `agent-runtime`（F53，**已签核**） |
| 「Skill 契约 ＝ 提示词模板 ＋ ioSchema ＋ dataScope」 | 换成模型无意义 | `skills`（D-06，**已签核**） |
| 「蓝本的 16 项设计配置」 | 换成 MCP 无意义 | `templates`（**已签核**） |

⚠ **为什么这一节必须在最前面**：本束 2026-07-30 才建立，而它横切的六类资产
**有四束（`skills` / `agent-runtime` / `canvas` / `templates`）已由人类签核**。
本束若与它们重叠，就出现「一个 feature 被两个束声明」= 归属不唯一，
ADR-023 明确要红。判据写在这里，是为了让重叠**在写的时候就被挡住**，
而不是等一致性复核时才发现。

## 一、实体与值对象

### `AssetKind`（值对象）—— **恰六个取值的封闭枚举**

| 取值 | 后台左栏项 | 计数（截图/原型一致） | `AN_META` 键 |
|---|---|---:|---|
| `agent` | Agent 管理 | 14 | `agents` |
| `skill` | Skill 库与市场 | 86 | `skills` |
| `model` | 模型 | 18 | `models` |
| `mcp` | MCP 服务器 | 6 | `mcp` |
| `canvas-template` | 画布模板 | 22 | `canvasadmin` |
| `blueprint` | 项目蓝本 | 7 | `blueprint` |

**三份独立证据完全一致**：① 人类截图的后台左栏（2026-07-30）；
② 原型 `AN_META` 六个键（`[原型 @16.6511M]`）；③ 原型 `AD_META` 六个资产条目
（`[原型 @16.6703M]`），**连计数都逐个对得上**。
⇒ 「治理与发布这一步**六种资产完全一样**」（`[原型 @16.611M]`）指的就是这六个。

⚠ **`AssetKind` 是本束的锚**。本束的每一条不变量都必须能对这六个取值逐一成立；
不能逐一成立的，按第零节的判据它就不属于本束。
⚠ **不得为「六个」写 `toHaveLength(6)`**——按 coding-standards 修订 E-4，
断言的是**成员集合相等**且未声明的取值不能通过。

### `AssetGovernance`（值对象）—— 「六种资产完全一样」的那三项

原型逐字：「谁能用、出问题谁负责、什么时候重新检查。**三个都填完才能发布**。」`[原型 @16.611M]`

| 字段 | 类型 | 说明 |
|---|---|---|
| `visibility` | `指定团队 \| 全组织 \| 仅自己-私有草稿` | **三取值封闭枚举**；`指定团队` 时 `teamIds` 非空；`全组织` **需领域负责人联签** |
| `editableBy` | `Set<角色\|人>` | 「谁能改它」。原型 chips：`负责人` `平台组管理员` `＋ 能源组负责人` ⇒ **集合，可编辑** |
| `ownerId` | `UserId` | 责任人，**单值**（原型：高琳 · 平台组） |
| `reviewCycle` | `6m \| 12m \| 24m` | **三档封闭枚举**（原型选中 24 个月） |

⚠ **`Q-1b` 未裁前，本值对象只对「这三项＋周期」成立，不对「发布前检查」成立**——
原型的发布前检查第一条是「四栏配置完整（人格 · 能力 · 模型 · 边界）」，**Agent 专属**。
⚠ **代码侧现状是 3/6**：`apps/web/lib/mock/admin.ts` 只对 agent / skill / 画布模板 登记了
`VisibilityScope`；**MCP 走另一套** `McpAuthScope = lead|team|all`；**模型与蓝本连字段都没有**。
统一方案见 Q-1b，**本文不擅自收敛**。

### `AssetProvenance`（值对象）—— 「来源决定后面要走的检查」

原型逐字：「**来源决定后面要走的检查。从社区导入的东西默认不可信，要过六道关；
从组织自己的用法沉淀出来的，只需确认边界。**」`[原型 @16.552M]`

| 取值 | 角标（原型原文） | 是否过六道关 |
|---|---|---|
| `blank` 从空白开始 | 最慢 · 最可控 | `[待确认]` |
| `community-import` 从社区导入 | **需过落地检查六道关** | **是** |
| `copy-derive` 复制现有并改 | 继承原有权限与负责人 | `[待确认]` |
| `usage-crystallize` 从实际用法沉淀 | 检测到 3 个候选 | **否**（「只需确认边界」） |

⚠ **`AssetProvenance` 与 `skills` 束的 `Skill.source`（`CC \| 自建 \| 画布 \| 社区 \| 晋升生成`，
封闭五值、**已签核**、I-11 断言不可由调用方写入）是**两个正交维度**：
`source` = 这东西是哪一类；`provenance` = 它怎么进来的。
**方案待裁（Q-10，推荐 C：另加正交字段，不动已签核枚举）。本文不擅自加取值。**

### `LandingCheck`（实体）—— 落地检查六道关

原型逐字：「**六道关全过才能发布，任何一道阻断都不能跳过。**」`[原型 @16.559M]`

| # | `gate` | 原型结论 |
|---|---|---|
| 01 | `parse-and-typing` 解析与类型识别 | 通过 |
| 02 | `security-scan` 安全扫描 | 通过 |
| 03 | `deps-and-permissions` 依赖与权限核对 | **提示** |
| 04 | `dedup-against-existing` 与现有资产查重 | **阻断** |
| 05 | `sandbox-trial` 沙箱试跑 | 进行中 |
| 06 | `scope-and-owner` 发布范围与负责人 | ⚠ 显示自相矛盾，见 Q-4 |

### `GateVerdict` vs `GateRunState`（**两个字段，不得合并**）

| | 取值 | 为什么必须分开 |
|---|---|---|
| `GateVerdict` | `通过 \| 提示 \| 阻断`（**恰三值**） | 这是**结论** |
| `GateRunState` | `未开始 \| 进行中 \| 已完成 \| 失败` | 这是**执行状态** |

⚠ 原型把这两件事**用同一列渲染**：第 05 关的标签是「进行中」，与另外五关的
「通过/提示/阻断」并排显示。**合并会导致「跑完了但结论是阻断」与「还在跑」无法区分**，
而这恰恰决定「发布」按钮能不能亮。
⚠ 这与 `skills` 束「两个状态字段」（`Skill.status` vs `SkillVersion.state`）**是同形的坑**，
那一束的 domain.md 已注明它是「最容易被误实现的一处」。本束重复了同一个形状，签核时请一并确认。

### `GateFinding`（值对象）—— 关的产出，**必须可追回**

`{ gate, verdict, body, decidedAt, evidence }`。
原型每一关的正文都是**由检查产生的具体计数**，不是模板文案：
「检查了 **3 处** base64 片段，均为示例数据」（02 关）、
「重合度 **68%**」（04 关）、「**2 段完成，1 段进行中**，归因正确率 0.93」（05 关）。
⚠ 68% / 0.93 / 41s **全是示例结果，不是阈值**（Q-8）。**本文不登记任何数值。**

### `HintDisposition`（值对象）—— `提示` 级结论的**两个出口**

`采纳改写(adopt-rewrite) | 标为可接受(accept-as-is)`，带 `{ by, at, reason? }`。

⚠ 第二个出口的证据**不在第 2 步屏上**，在第 3 步发布前检查那条红色项里：
「试跑里那条『重复了 Scout 的反对意见』还没处理——**改提示或标为可接受**」`[原型 @16.615M]`。
⇒ 只实现「采纳改写」会让 `提示` 变成事实上的阻断（无法绕过 ⇒ 无法发布）。

### `DedupConflict`（值对象）—— 04 关阻断的三个出口

`{ existingAssetId, incomingDraftId, overlapRatio, resolution }`，
`resolution ∈ { 合并为两种模式, 分别保留-写清适用场景, 放弃导入 }`（**恰三值**）。
⚠ `合并为两种模式` 的产物是**已发布资产的新版本**，不是新资产 ⇒ 必须走那类资产自己的
版本与审核流程（`skills` 束，已签核），**本束不重造**。
⚠ `放弃导入` 是删除还是留痕归档 → `[待确认]`。

### `AssetDirectory` / `AssetFile`（实体）—— 目录形态

原型逐字：「一个 skill 是**一个目录**：`SKILL.md` ＋ 参考资料 ＋ 可选脚本」`[原型 @15.690M]`，
树底部：「右键改名／删除 · **目录结构就是发布出去的结构**」`[原型 @15.710M]`。

- `AssetDirectory = { assetId, rootFile, files: AssetFile[] }`
- `AssetFile = { path, sizeBytes, body }`；`path` 在一个资产内唯一。
- `rootFile` ∈ `{ SKILL.md, AGENT.md, … }`，**由 `AssetKind` 决定，不可删**。
- 徽标由扩展名派生（`FILE_BADGE` `[原型 @16.6512M]`）：`.py→PY` · `.json/.jsonl→{ }` ·
  `.yaml/.yml→YM` · **其余一律 `MD`（fallback 不报错）**。

⚠ **原型只对 `skill` 与 `agent` 给了目录形态**（`SK_FILES`/`SK_TREE` `[原型 @16.668M]`、
`AG_FILES`/`AG_TREE` `[原型 @16.653M]`）。其余四类**是不是目录，0 命中 → `[待确认]`**。
⇒ `AssetDirectory` **不是**对全部六个 `AssetKind` 都成立的，本文不假装它是。
⚠ 与 `skills` 束 `Skill.fileCount` 的注释「phase-2 多文件包预留；**phase-1 恒为 1**
（不得据此实现打包解析）」**直接冲突** ⇒ 并入 Q-0。

### `TrialRun` / `RegressionCase`（值对象）—— 试跑台

原型两处措辞：「用当前未保存的提示词跑，**不影响线上**」`[原型 @15.660M]`（Agent）/
「**改动未发布，只影响这次试跑**」`[原型 @15.695M]`（Skill）。**同一条规则的两种说法。**

- `TrialRun = { assetSnapshot(未保存), scenario, inputs, params, output, trace[], autoChecks[], latencyMs, tokens, cost }`
- `TraceStep = { ok, main, sub }` —— **主行必须点名实际装载的文件**
  （`prompts/system.md` · `references/question-bank.md` · `scripts/validate.py`）。
  ⇒ 这是 I-6「目录结构就是发布出去的结构」的**运行时证据面**。
- `AutoCheck = { label, detail, passed }` —— ⚠ **校验项从资产自己的契约派生**，不是固定清单：
  Skill 版第 1 条「必需的三个段落齐全」直接来自 `references/output-schema.md`，
  第 2 条「无证据分支未给置信度」直接来自 `SKILL.md` 的「禁止」小节 `[原型 @16.668M]`。
- `RegressionCase` —— **存在资产目录里**（`evals/regression.jsonl`，`[原型 @16.653M]` 四条实存），
  **不是另一张表**。

⚠ `TrialRun` 里出现的三个跨束事实——越权拦截（`agent-runtime`）、
组织层知识过期标注（`14-brain`）、skill 版本号（`skills`）——**本束只显示，不定义**。

### `ReviewClock`（值对象）—— 复核计时器

原型逐字：「**到期后自动转「待复核」，仍可用但调用时会提示；30 天无人复核则降级为
仅负责人可见。这与组织大脑里知识条目的规则一致。**」`[原型 @16.613M]`

`{ dueAt, state: 生效 | 待复核 | 已降级, pendingSince?, lastReviewedAt?, lastReviewedBy? }`

⚠ **`ReviewClock` 的规则与 `14-brain` 的知识条目到期规则是同一条**（原型自己这么说的）。
⇒ **单一事实源的落点未定（Q-7，推荐抽到 phase-00 共享内核）。
本文只声明「有这个概念、有这三态」，不写数值语义** —— 数值语义的唯一定义处是
`requirements/23-asset/uc-23-6` + 阈值登记表。**这是本仓头号失败模式的高危区（已八次）。**

`{ name, endpoint, providesKinds: Set<AssetKind>, credentialRef, lastSyncAt, lastSyncResult, availableCount }`

⚠ **人类提到的 `open claw` 在原型全文 0 命中（三种写法）** ⇒ **本文不发明这个源**。

## 二、不变量

> 判据：**任何时刻都为真，违反即数据损坏。** 写不成断言的是「规则」，已赶到 UC 的前置条件里。
> 🔗 ＝ **跨束不变量**，不能在本束单独实现，须提阶段一致性复核。
> ⚠ ＝ 该不变量依赖某条未裁问题，**裁决前不得据它生成 feature**。

| # | 不变量 | 怎么断言 |
|---|---|---|
| **I-1** | `AssetKind` 的取值集合**恰为**六个 `{agent, skill, model, mcp, canvas-template, blueprint}` | 断言枚举**成员集合相等**，且未声明的取值不能通过（**不写 `toHaveLength(6)`**，见 coding-standards E-4） |
| **I-2** | **左栏「AI 能力」组的项集合 ＝ `AssetKind` 的取值集合**（**双向相等**） | 双向集合差为空；**反证**：从任一侧删一个 ⇒ 门控必须报红。照抄 `lint-ui-material.mjs` 的双向相等 + 反证套件形状 |
| **I-3** | 左栏每一项的 `href` **都可达**（无一个 404） | 遍历 `ADMIN_NAV` 逐项请求，断言全部非 404；**含 `项目蓝本` 那一项**（今天它是 404） |
| **I-4** | 左栏计数是**派生值**：改一条资产 ⇒ 对应计数变 | 造一条资产后断言计数 +1；断言代码中无硬编码的 14/86/18/6/22/7 |
| **I-5** | `LandingCheck` 存在任一 `verdict = 阻断` ⇒ **该资产无法发布**（任何路径，含直调接口） | 构造阻断态后调发布端点，断言拒 `GATE_NOT_PASSED` **并写审计**（复用 `skills` 束既有错误码，不新建） |
| **I-6** | 发布后运行时装载的文件集合 **＝** 编辑器文件树里的集合（**逐一相等**） | 发布后从运行时枚举装载文件，与 `AssetDirectory.files` 做双向集合相等；改一个文件名后重断言 |
| **I-7** | `AssetDirectory.rootFile` **不可删除** | 删除 `SKILL.md` / `AGENT.md` 被拒；扫描无缺 `rootFile` 的资产 |
| **I-8** | **未保存的改动不影响线上**：`TrialRun` 用未保存快照，线上调用用已发布版本 | 改提示不保存 → 试跑输出变 **且** 同时断言线上调用输出不变（**两侧同时断言**，只断一侧挡不住） |

### 为什么 I-2 必须是**双向**的

单向（「左栏每一项都是一个合法 `AssetKind`」）在今天的代码上**就是绿的**——
`ADMIN_NAV` 里那 4 项确实都是合法资产类型。而**故障是缺 2 项**。
单向断言对缺项完全无感。**双向相等是唯一能挡住本 UC 起因那个故障的形状。**
本仓已有同形先例可照抄：`lint-ui-material.mjs` 的判定②（反向：目录里每张 png 都必须被引用到）
——那条门控的注释里写明了「空集使断言平凡为真」是本仓栽过的形状。

### 为什么 I-8 必须**两侧同时断言**

只断「改了不保存 ⇒ 试跑输出变」，一个把未保存改动直接写进线上的实现也能通过。
只断「线上不变」，一个根本不读未保存改动的实现也能通过。
**规则是「用未保存的跑」且「不影响线上」，它是两个断言的合取。**
