## ② 用例 —— 用例接口与失败模式穷举对不对

→ 本束 `usecases.md`（32 个端口 + 22 个错误码 + 八类失败模式自查表）

### 签核前请重点确认

- [ ] **归档语义（O-10）最容易做反**：归档**只挡新增绑定，不挡存量实例化**。
      若实现成「归档即禁止实例化」，**一场正在进行的工作坊切到该环节会直接失败**。
      `instantiateForSegment` 的错误码里刻意**没有** `TEMPLATE_ARCHIVED`。
- [ ] **`resolveConflict` 的 `preservedVersionId` 永不为空**——这是 D-09 的价值核心。
      三个出口任意一个丢弃另一侧即数据损坏；采纳侧写入与另一侧存版本必须**同一事务**。
- [ ] **`outcome: "compare"` 是中间态不是终态**：并排比较后仍要再选一侧，冲突不消失。
- [ ] **回滚的边界是本束替 UC 做的判断**：UC 只写「回滚到该轮落笔前状态」，**没说这轮之后
      有人工改动时怎么办**。本契约取 `AI_ROUND_SUPERSEDED`（拒绝直接回滚，避免吞掉别人的改动）。
      若产品要「强制回滚」，需要另一个显式端口 + 二次确认。
- [ ] **`NODE_NOT_CONFIRMED` 是服务端闸门**：直接调接口绕过界面也必须被拒。
      「前端把按钮置灰」不构成这条约束的实现。
- [ ] **批量写回返回 `written` + `rejected` 两个列表**：部分成功是常态，
      **不接受「整批失败」也不接受「静默跳过」**，被拒每条要带原因。
- [ ] **幂等键**：`instantiateForSegment` / `draftFromContextPack` / `runSegmentSkill` 都带。
      现场网络抖动重试是常态；不幂等会给每组开出两张空画布。
- [ ] **`TEMPLATE_NOT_TRIALED` 这个错误码可能不该存在**——见 `domain.md` [待定 D-b]。
      裁决为「不阻断」时它要删掉，`uc-7-1` V7 的后半句也要从验收里删。

## ③ API 契约 —— 对外形状与错误码对不对

**本束有对外 HTTP 面。** 第 ③ 件的落点是：

```
packages/contracts/src/canvas.ts        （zod 单一事实源，尚未创建）
```

⚠ **本轮只是骨架，该文件尚不存在。** 它是**签核通过后、开工时的第一件产出**——
在它存在之前，`packages/contracts/src/index.ts` 里没有 `canvas` 的导出，
mock 也无从生成。按 ADR-023 决策一，这属于「第 ③ 件的第一种可接受形态」，
**不适用「无对外 HTTP 面」那条**。

它一份生成四样东西：后端 DTO + ValidationPipe / 前端 client 类型 / OpenAPI / **前端 mock**。

### 签核前请重点确认

- [ ] **mock 必须从契约生成，不许手写。** 现在 `/projects/[id]/canvas` 的便签、节点、连线、
      四组画布状态**全是手写 mock**。它对自己永远自洽，所以「界面跑得通」不等于契约成立。
      本项目已五次因「同一事实两处声明」而漂移；手写 mock 是第六次。
- [ ] **响应体也要被契约校验，不只是请求体**：特别覆盖**拒绝路径**
      （`TEMPLATE_ARCHIVED` / `SEGMENT_TEMPLATE_LIMIT` / `NODE_NOT_CONFIRMED` /
      `CONFLICT_PENDING_ADJUDICATION`），外加一组反向断言证明这些 schema 确实会拒绝漂移的 body。
- [ ] **枚举的封闭性要守，成员数不要守**：12 类 mermaid 类型 / 4 种模板状态 / 4 种组画布状态 /
      3 种同步状态 / 3 种节点态 / 3 个冲突出口 / 2 种 AI 写权限模式 —— 断言的是
      「集合与契约一致 ∧ 未声明的值不能通过」，**不是 `toHaveLength(12)`**（修订 E-4 的教训）。
- [ ] **`key` 与 `display_name` 只在契约里定义一次**：19 个内置模板的双列对照
      当前同时存在于 `uc-7-1` R7 与 `fabric-markdown` 源码。签核后 zod 从源码取值、
      测试断言两者相等——**不许在契约里再抄一份字面量**。

## ③-补 · 2026-07-31 签核**之后**加进契约的 6 处设计增量（本次补签）

2026-07-31 那次签核之后，canvas 的契约面陆续长出 6 处新东西。它们**都已经上线并在
真实流量里跑**——人类在后台做的每一次改名、拖拽、保存、试运行，走的就是它们。
所以这一节不是「要不要做」的评审，是**对既成事实补一次授权**。

⚠ 六处逐条列在下面。每条给三件事：它是什么、为什么当时加、**你在界面上哪里已经用到它**。
  最后一条是 2026-08-26 本轮加的；前五条来自更早的会话，一并补上。

### 1. `updateTemplateDraft`（2026-08-23，coord-main 代裁）

**是什么**：改一份**草稿**模板的内容（全量替换 `sections`）。只对 `status === "draft"`
生效——已发布版本的 `sections` 是不可变快照（I-4），原地改会让已经用它开过的画布
在下次渲染时悄悄换版式。

**为什么加**：签核骨架里只有三段发布流程（create → trial → publish），没有「改内容」。
人类当时原话「所有的内容进入编辑的界面来管理」，而那个界面需要一个写入口。

**你在哪里用到**：模板编辑器点「保存」，草稿走的就是它。

### 2. `suggestTemplateSections`（2026-08-23，coord-main 代裁）

**是什么**：把一段自然语言提示词交给模型，回一组建议的分区（名字 + 类型 + 为什么）。

**为什么加**：`Design.pdf` §4.1「从提示词里提取字段」。人类写完提示词后，
逐个手敲字段名是重复劳动。

**你在哪里用到**：编辑器左上「提示词」抽屉里的「提取字段」按钮。
⚠ 模型不可用时**原样回显 reasonCode**，不降级成一份编出来的候选——这条有测试守着。

### 3. `updateTemplateMetadata`（2026-08-25）

**是什么**：改 `displayName` / `tags`（本轮又加了 `title` / `footer`，见第 6 条）。
它对**任何状态**生效，靠的是它物理上碰不到 `sections`。

**为什么加**：`Design.pdf` §3.1 卡片上的「改名 / 标签」。改名字不该被当成「改内容」——
「已发布版本内容不可变」这条限制的存在理由，跟名字/标签完全无关。

**你在哪里用到**：模板卡片上的「改名 / 标签」按钮。

### 4. `SectionLayout`（分区显式布局，2026-08-25）

**是什么**：`col/row/w/h`（12×8 网格坐标）+ `cols/max/tone/overflow`（怎么显示）。

**为什么加**：重设计要求分区位置**由人拖拽指定**，而不是 `computeAutoLayout` 纯算法排。
`layout` 就是「使用者手动放好的那个位置」。没有它，编辑器里拖出来的位置存不下来。

**你在哪里用到**：整个拖拽画布；也是 2026-08-26 那次「19 个内置模板打开全是空的」
之所以能修好的前提——推演出来的坐标就是存在这里。

### 5. `tags`（模板标签，2026-08-25）

**是什么**：自由字符串数组，无固定枚举。

**为什么加**：`Design.pdf` §2 数据模型逐字写「自由标签，无固定枚举」，用于模板库筛选。

**你在哪里用到**：模板库顶部的标签筛选条（你截图里那个「工作坊 1」）。

### 6. `title` / `footer`（纸面标题带与页脚署名带，2026-08-26 本轮）

**是什么**：`title` 是画在 A1 纸上的双语大标题（「用户画像 User Persona」）；
`footer` 是纸底部的署名/版权行。两者走 `updateTemplateMetadata` 写。

**为什么加**：人类 2026-08-26 截图实测原话「需要有一个功能是可以放 Title，
页脚也有一些版权的信息，需要可以预留这个空间」。

**你在哪里用到**：编辑器画布上方的「纸面标题」「页脚署名」两个输入框。

⚠ **`title` 与 `displayName` 刻意没有合并**，是两件事实：前者画在纸上（权威是
  fabric-markdown 的 `TemplateSpec.title`），后者是后台列表里的名字（权威是契约的
  `BUILTIN_CANVAS_TEMPLATES`）。合成一列会让「改了列表名，纸上标题跟着变」。

⚠ **装帧不进 `sections`**：`sections` 是「AI 要填什么」，装帧是纸本身长什么样。
  混进去模型会试图去"填标题"。这也是它能对已发布模板生效的原因。

⚠ **`footer` 在 19 个内置模板里一律留空**：老 spec 里没有这件事实（字段逐个查过）。
  人类参照图上 AI 战略画布底部确实印着「本工具基于 Bizzuka 的 AI 战略画布」，
  但那是图上的像素、不是数据——照着图写进代码等于凭空断言作品出处。由人自己填。

### 签核前请重点确认

- [ ] 这 6 处**都已在生产流量里跑**。如果其中任何一处你认为不该存在，
      它需要的是一次**回退**，而不是「下次别这么做」——告诉我哪一处，我来退。
- [ ] 第 3 条与第 6 条合起来意味着：**已发布模板的名字、标签、纸面标题、页脚可以直接改，
      不产出新版本**。内容（分区）仍然不行，改内容会自动铸下一版草稿。
      这条边界是刻意划的，请确认它符合你的预期。
- [ ] 第 2 条会把提示词发给模型。确认这条外发路径是你接受的。
