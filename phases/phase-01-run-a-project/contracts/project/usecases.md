## 零、裁决落到用例上的四条总纲

1. **容器是超类型，行为在子类型。**（Q-12 C + 连带 4 D）
   凡「创建 / 列表 / 归档」这类**容器级**用例，操作对象是 `projects`；
   凡「议程环节 / 分组 / 三视角」这类**工作坊级**用例，操作对象是 `workshops` 及其下属表。
   ⇒ **一个用例如果同时读写两层，它多半切错了。**
2. **四种项目角色只在工作坊里有意义。**（Q-12 追加裁决）
   凡涉及角色的用例，前置条件都要写明 `kind = 'workshop'`；
   另两类的成员模型 **U-1 待裁**，其用例**本文不写**。
3. **归档不删除任何东西。**（Q-5 B）凡涉及「结束」的用例，出口只有 `archived`，
   没有任何删除路径；`deleteProject` **不存在**（Q-9），它的交付物是一条断言它不存在的测试。
4. **两个失败码从今天起必须能红。**（Q-2① A + Q-8）
   任何声明这两个码的用例，验收都是**双向**的——见第三节。

### UC-P1 `createProject` 创建容器 —— **已定（主干）**

| 项 | 内容 |
|---|---|
| **谁** | 组织角色 `lead`（职责逐字「创建与管理项目」，D-11）。⚠ `admin` 能否创建 **待裁 → U-4** |
| **入** | `orgId` · `name` · **`kind`**（三值：`workshop` / `research_project` / `user_insight`）· `blueprintVersionId?: string \| null` |
| **出** | 容器 `id`（= 子类型行的 `id`）· `kind` · `status = 'active'` |
| **裁决依据** | **Q-1 C**：**一条创建路径 + 蓝本可选参数**。空白新建 = 传 `null`，**六类初始化跳过而非写空值**，不造「空白蓝本」这种语义空壳 |
| **事务** | **一处创建事务**，且必须原子地写**两行**：`projects` 一行 + 对应子类型表一行。⚠ 两行分两次提交 = 出现「有容器没子类型」的中间态，那正是 I-P34 想排除的东西 |
| **前置** | 组织 `status = 'active'`（组织 `disabled` 时 PG RESTRICTIVE 策略会拒，I-P28） |
| **副作用** | 写 `provenance` 事件（`kind: "project"`，通道已存在，**不许另造**，I-P3） |
| **不做** | **不自动给创建者授予项目角色**。⚠ 依据是 **Q-4 待答② 的裁决**（`lead` 对自建未加入的项目**持管理权、不持内容读取权**）——若创建即授角色，那条边的两端就不存在了，「管理员不是超级用户」随之破掉。⚠ **这是本文由 Q-4② 推出的**，Q-1 连带 3 的格子本身是空的 |
| **待裁** | `admin` 能否创建（**U-4**）· 空项目能否事后补套蓝本、已有内容如何合并（**U-5**）· 非 workshop 的 `kind` 是否接受 `blueprintVersionId`（**U-1 的下游**，蓝本是工作坊机件） |

**失败模式**

| 码 | 触发 | 备注 |
|---|---|---|
| `ORG_ROLE_INSUFFICIENT` | 非 `lead`（且 U-4 未裁前，`admin` 一律按不可创建处理并**登记为待裁**，不静默放行） | 与 phase-00 同码同义 |
| `AUTH_SERVICE_UNAVAILABLE` | 判定服务不可用 —— **一律拒绝，不得降级放行** | 已签核 |
| （组织冻结） | 组织 `disabled` ⇒ 写入被 **PG 策略**拒绝 | 不是应用层码；断言在数据库层 |
| `INVALID_KIND` | `kind` 不在三值闭集内 | ⚠ 新增码；DB CHECK 与 zod 枚举**成员逐个相等** |
| （蓝本无效） | **待裁 → U-5 的邻接面**，本文不命名这个码 | 一个不会被抛出的码读起来像覆盖 |

### UC-P2 `listProjects` 容器列表 —— **已定（返回形状）**

| 项 | 内容 |
|---|---|
| **裁决依据** | **Q-6① B**：返回**两段**——「**我持有项目角色的**」与「**我作为 `lead`/`admin` 可管理的**」，**响应体把两段分开**，**不是一个混合数组加 `canManage` 布尔** |
| **理由（已签同型纪律）** | 同 **D-8**：`projectLayer` 的两种 null 不许合并。「我在这个项目里」与「我管着这个项目」是两种不同的东西，压成一个列表会让前端猜 |
| **归档项目** | `archived` 的容器**显示且标注只读**，**不消失**（Q-5 B + Q-7③ 同一种只读呈现，两处必须一致） |
| **停用组织下的项目** | 同上：**显示且标注只读**（Q-7③ 裁「显示且标注只读」）。理由已签核：「藏起来读作『产品做不到这件事』，而真相是『这个组织不允许』」 |
| **层级** | **平铺，不折叠**（Q-12 必裁三件之 3 逐字「平铺」）。⚠ 在 D 下本来也没有父子边 |
| **分区** | 按 `kind` 分区**是展示决定不是响应体决定**——响应体只带 `kind` 字段，分不分区由 UI 决定。⚠ 本文**不**规定 UI 分区，那属第 ① 件 |
| **出（形状）** | `{ member: ProjectListItem[]; managed: ProjectListItem[] }`；`ProjectListItem` 至少含 `id` / `name` / `kind` / `status`。⚠ **出现在 `managed` 里 ≠ 能进去看内容**（D-18 边界），响应体**不得**因此附带任何内容摘要 |
| **待裁** | 列表项要不要带「准备度 %」——**不带**，口径未定（**U-6**）；带的是口径明确的计数 |

**失败模式**：`AUTH_SERVICE_UNAVAILABLE`（拒绝，不降级）。
⚠ **无项目 ≠ 失败**：两段都为 `[]` 是**正常空态**，且**不生成伪数据**（同 D-19 的空态纪律）。

### UC-P4 `archiveProject` / `unarchiveProject` —— **部分（主干已定，四个连带全空）**

| 项 | 内容 |
|---|---|
| **裁决依据** | **Q-5 B**：两态 `active` / `archived`；`archived` = **只读**；**归档不删除任何内容** |
| **形状复用** | 照 F22 组织冻结的形状：冻结做在 **PG 的 RESTRICTIVE 策略**里，不是应用层 if。已 passing、可断言 |
| **边界（重要）** | 「归档 ≠ 删除」本身就是 **X-4 豁口的正确一侧**——豁口只留给**合规撤回**，不该被「项目结束」这种日常动作借道（且 X-4 依赖的 O-39 法定留存清单**不存在**） |
| **待裁 → U-2（四条，裁决块四格全空）** | ⑴ `unarchiveProject` **是否存在**（归档可逆吗）——⚠ 因此本用例名里的第二个操作**现在不成立**，本文保留它只为标出这个洞；⑵ 归档时**进行中的议程环节**怎么办（自动 `closed`？拒绝归档？）；⑶ 归档容器的 artifact 还能被**其它容器下游引用**吗；⑷ **Context Pack 会不会召回**归档内容 |

⚠ ⑵ 与 Q-2② 的四态耦合：`active` 环节在归档时的去向**必须能被状态集合表达出来**，
而四态里没有「因容器归档而终止」这一档——**这是 U-2⑵ 必须回答的具体形状**。

### UC-P5 `deleteProject` —— **不提供（Q-9 已裁）**

交付物是**一条断言它不存在的测试**，不是一个接口：把 `DELETE /projects/*` 加进
`no-forbidden-routes.test.ts` 的禁止清单。理由逐字照抄 N-5：
「**『没有』这件事本身没人会去验**，某天有人为别的需求加上，不会有任何东西报警。」
⚠ 数据库层已有一个 BEFORE DELETE 触发器在替我们挡（`0008-f06:191` 逐字预见到级联会经由
父 artifact / project 到达绑定行），**但那是防御不是规范**，规范要写在路由表的断言里。

## 三、失败模式穷举

### 3.1 已在契约里、本束必须同码同义引用

| 失败码 | 语义 | 状态 |
|---|---|---|
| `NO_PROJECT_ROLE` | 无项目角色 —— **正常状态不是异常** | 已定 |
| `PROJECT_ROLE_INSUFFICIENT` | 有角色但该角色不含此动作 | 已定 |
| `ADMIN_NOT_SUPERUSER` | 管理员越过项目层读内容（`purpose != "audit"` 时） | 已定 |
| `STEP_CLOSED` | 目标环节已关闭，拒绝绑定 | **由本束变为可评估**（Q-2① A + Q-8） |
| `STEP_REJECTS_ARTIFACT_TYPE` | 目标环节不接受该来源类型 | **同上**（Q-2③ + Q-8） |
| `AUTH_SERVICE_UNAVAILABLE` | 判定服务不可用 —— **一律拒绝，不得降级放行** | 已定 |
