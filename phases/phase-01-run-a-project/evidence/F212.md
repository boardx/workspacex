## 技术悬念的核实结论（任务里明确要求核实，不许假设）

**问题**：三个虚拟工具是否需要在 Python 侧真的存在同名函数？

**结论：需要**——实测确认，不是纯前端约定：

- `apps/deep-agent-service/src/deep_agent_service/harness.py` 的 `build_interrupt_on()`（198-214 行）只是把 `DEEP_AGENT_HITL_TOOLS` 环境变量解析成 `{工具名: True}` 字典。
- `apps/deep-agent-service/src/deep_agent_service/graph.py`（44-50 行）把这个字典与 `build_tools(_model)` 注册的工具列表一起传给 `create_deep_agent(tools=..., interrupt_on=...)`。
- 模型只能调用 `tools` 列表里真实注册的工具——`interrupt_on` 只是「这个工具名被调用时要不要暂停」的开关，不创造新工具。
- 实测 langchain 0.7.6 源码 `human_in_the_loop.py`：`HumanInTheLoopMiddleware.__init__`（256-276 行）不校验 `interrupt_on` 的键是否对应已注册工具；真正查字典的地方在 `wrap_tool_call` 内（429 行 `self.interrupt_on.get(tool_call["name"])`），只在真实工具调用发生时才查——这意味着提前把三个名字写进环境变量是**惰性安全**的（不会报错、不会误触发），但**不会让中断真的发生**，因为模型永远无法调用一个不存在的工具。

⇒ **超出本轮范围**：Python 侧 `@tool confirm_task_intent` / `@tool fill_run_params` / `@tool choose_execution_option` 三个函数需要新建在 `apps/deep-agent-service/src/deep_agent_service/tools.py` 并注册进 `build_tools()`。这是**独立于 F212 的后续 feature**，已登记在 `coverage.md` AI-4b，未擅自扩大范围去做。

`packages/contracts/tests/agent-interrupts/cross-lang-tool-parity.test.ts` 因此没有照抄 `deep-agent-hitl.test.ts` 的逐字签名比对（那需要 Python 侧已存在的函数），而是断言：① 环境变量投影链条现在确实是对的；② **如实的反向锚点**——三个工具名此刻在 `tools.py` 里确实还不存在，一旦这条变红就是提醒把测试换成逐字签名比对，不是本测试的失败。
