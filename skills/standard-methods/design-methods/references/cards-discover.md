# 发现阶段方法卡片（M1–M3）

> 编号与 references/method-index.md 一致。每张卡片是本项目自写的操作说明，不是任何书籍原文。

## M1 Intent & Trends 趋势与意图

### M1-01 Signal Digest · 信号速览
- **来源**：通用设计实践
- **目的**：快速摸清一个领域最近在被讨论什么、热度往哪里走。
- **何时用**：项目刚启动、需要对话题建立共同语境；**不适用**：已有深入行业研究、或需要严谨量化结论时。
- **输入**：主题关键词、时间窗口（如近 6–12 个月）、可访问的新闻/博客/社区/行业报告来源。
- **步骤**：
  1. 与用户确定主题边界和时间窗口。
  2. 按来源类型（行业媒体、社区、发布会、投融资）收集条目，每条记录标题、日期、来源链接。
  3. 用一两句话摘要每条，并标注它指向的变化（技术 / 行为 / 商业 / 政策）。
  4. 归并同类条目为 5–10 个热点主题，标注各主题的条目数与代表链接。
  5. 写出「这对本项目意味着什么」的初步问题。
- **产出**：热点摘要表（主题、摘要、代表来源、日期、对项目的疑问）。
- **耗时 / 人数**：2–4 小时 · 1–2 人
- **AI 协作**：agent 可起草检索词、分类框架、归并与摘要用户给的材料；可联网时须附真实链接。无法检索时只能说明缺口，不得编造新闻、日期或来源。
- **衔接**：上游 M1-14 → 下游 M1-09、M1-16

### M1-02 Popular Media Scan · 大众媒体扫描
- **来源**：通用设计实践
- **目的**：从大众媒体（影视、广告、畅销书、社交平台）中读出社会对某话题的态度和想象。
- **何时用**：关注消费者文化、价值观变化；**不适用**：纯 B2B 技术选型或需要一手行为数据时。
- **输入**：主题、媒体类型清单、扫描时间段。
- **步骤**：
  1. 列出要扫描的媒体渠道和样本数量上限。
  2. 逐条记录媒体内容：出处、呈现的形象/叙事、隐含态度（向往 / 担忧 / 讽刺）。
  3. 标注每条背后的文化信号（例如「对自动化的焦虑」）。
  4. 聚合出反复出现的叙事与少见但新颖的信号。
- **产出**：媒体信号清单（出处、叙事、信号标签、频次、备注）。
- **耗时 / 人数**：3–6 小时 · 1–2 人
- **AI 协作**：agent 可提供扫描模板、帮用户对其收集的样本做信号标注与聚类。具体作品与引述必须来自用户或可核实来源，不得虚构剧情或广告内容。
- **衔接**：上游 M1-01 → 下游 M1-16、M1-11

### M1-03 Key Facts · 关键事实
- **来源**：通用设计实践
- **目的**：把散落的数据浓缩成少量可信、可引用的事实，作为团队共同起点。
- **何时用**：需要对齐基本盘（市场规模、用户数、增长率、法规）；**不适用**：数据来源无法核实时。
- **输入**：二手资料、内部报表、公开统计。
- **步骤**：
  1. 列出团队最需要回答的 5–10 个事实性问题。
  2. 为每个问题找到数据及原始出处，记录发布时间与口径。
  3. 交叉核对，冲突处并列而不是取平均。
  4. 每条事实写成一张卡：一句话事实 + 数字 + 出处 + 可信度。
- **产出**：关键事实卡（事实、数值、口径、出处、日期、可信度高/中/低）。
- **耗时 / 人数**：2–4 小时 · 1 人
- **AI 协作**：agent 可拆问题、整理和校对用户提供的数据口径。任何数字都必须有真实出处，找不到就写「待查」，绝不补写估算值冒充事实。
- **衔接**：上游 M2-02 → 下游 M1-14、M2-09

### M1-04 Case Collection · 创新案例集
- **来源**：通用设计实践
- **目的**：收集领域内外的创新案例，给团队提供「别人已经做到什么」的参照。
- **何时用**：寻找灵感和标杆、打开思路；**不适用**：已明确方向只需竞品细节对比时（用 M2-16）。
- **输入**：主题、案例来源（产品、服务、商业模式、研究项目）。
- **步骤**：
  1. 定义收录标准（新颖度、相关度、时间范围）。
  2. 收集 15–40 个案例，每个记录名称、做了什么、为什么算创新、链接。
  3. 用标签归类（按创新类型、用户群、技术）。
  4. 挑出最有启发的 5–8 个写出「可借鉴点」。
- **产出**：案例合集（案例卡 + 标签 + 可借鉴点）。
- **耗时 / 人数**：半天–2 天 · 1–3 人
- **AI 协作**：agent 可提出候选案例方向、设计案例卡模板、做归类。案例事实须可核实并附来源，不确定的案例标注「需核实」。
- **衔接**：上游 M1-01 → 下游 M1-07、M1-08、M2-06

### M1-05 Trends Expert Interview · 趋势专家访谈
- **来源**：通用设计实践
- **目的**：借助趋势研究者或行业观察者的判断，理解变化的方向和节奏。
- **何时用**：二手资料不足以判断趋势走向；**不适用**：没有可接触的真实专家时。
- **输入**：2–5 位专家、访谈提纲、已有趋势假设。
- **步骤**：
  1. 基于已有资料写出待验证的趋势假设。
  2. 设计 45–60 分钟提纲：现状、驱动力、时间线、不确定性、反例。
  3. 进行访谈并记录（征得录音同意）。
  4. 整理每位专家的观点、依据和分歧点。
- **产出**：专家观点纪要（专家背景、核心观点、依据、分歧、待验证问题）。
- **耗时 / 人数**：每场 1 小时 + 整理 1 小时 · 1–2 人
- **AI 协作**：agent 可写提纲、整理用户提供的转录并标出分歧。访谈必须由用户真实进行，agent 不得模拟专家发言或编造观点。
- **衔接**：上游 M1-01 → 下游 M1-09、M1-10

### M1-06 Keyword Bibliometrics · 关键词文献计量
- **来源**：通用设计实践
- **目的**：用关键词在出版物或检索中的出现频次，量化一个话题的兴起与衰退。
- **何时用**：判断话题热度随时间的变化；**不适用**：话题太新没有文献积累、或拿不到可计数的数据源时。
- **输入**：关键词组、数据库（学术库、新闻库、专利库、搜索趋势）、时间区间。
- **步骤**：
  1. 确定关键词及同义词，写清检索式。
  2. 在选定数据源按年/季度统计出现次数。
  3. 画出时间曲线，对比多个关键词。
  4. 解读拐点，并标注可能的数据偏差（数据库收录变化等）。
- **产出**：关键词热度曲线 + 检索式 + 数据源说明。
- **耗时 / 人数**：2–4 小时 · 1 人
- **AI 协作**：agent 可设计检索式、处理用户导出的计数数据并作图。计数必须来自真实检索结果，agent 不得估算或编造频次。
- **衔接**：上游 M1-01 → 下游 M1-09、M1-16

### M1-07 Innovation Types Framework · 创新类型框架
- **来源**：通用设计实践
- **目的**：用一组创新维度检查创新机会是否只盯着产品功能本身。
- **何时用**：拓宽创新视角、分析案例集；**不适用**：只需解决单一可用性问题时。
- **输入**：案例集或候选想法清单。
- **步骤**：
  1. 和团队约定本项目要看的创新维度（例如商业模式、合作伙伴、内部流程、产品功能、产品组合、服务、渠道、品牌、用户体验），维度可增删。
  2. 把每个案例/想法归入一个或多个类型。
  3. 统计分布，找出拥挤区与空白区。
  4. 讨论空白类型中可能的机会。
- **产出**：创新类型分布表（类型 × 案例），附空白区机会说明。
- **耗时 / 人数**：1–2 小时 · 1–4 人
- **AI 协作**：agent 可解释类型定义、对用户给的案例做初步归类供确认。归类依据须来自案例的真实信息。
- **衔接**：上游 M1-04 → 下游 M1-08、M2-08

### M1-08 Innovation Landscape · 创新版图
- **来源**：通用设计实践
- **目的**：把领域内的玩家和他们的创新做法放在同一张图上，看清格局与空位。
- **何时用**：需要理解谁在做什么、往哪里走；**不适用**：玩家信息极少、无法定位时。
- **输入**：玩家清单、各自的产品/创新信息、两条分析轴。
- **步骤**：
  1. 选两条有区分度的轴（如「渐进 ↔ 颠覆」「专业 ↔ 大众」）。
  2. 收集玩家信息并逐个定位，写明定位理由。
  3. 标注聚集区和空白区。
  4. 讨论空白区是机会还是陷阱。
- **产出**：玩家与创新定位图 + 定位理由表。
- **耗时 / 人数**：2–4 小时 · 1–3 人
- **AI 协作**：agent 可建议轴、生成图表、整理定位理由。玩家信息须真实可查，agent 不得编造公司或产品。
- **衔接**：上游 M1-07 → 下游 M1-12

### M1-09 Trends Matrix · 趋势矩阵
- **来源**：通用设计实践
- **目的**：把多个趋势和多个领域/维度交叉，看出每个趋势在哪些地方产生影响。
- **何时用**：已收集到一批趋势，需要系统梳理影响面；**不适用**：趋势尚未收集时。
- **输入**：趋势清单（行）、领域或用户活动维度（列）。
- **步骤**：
  1. 确定行（趋势）与列（如技术、商业、社会、用户场景）。
  2. 在每个格子写该趋势在该维度上的具体表现或影响。
  3. 标出影响最强的格子。
  4. 提炼跨行跨列的模式。
- **产出**：趋势 × 领域矩阵 + 重点格子说明。
- **耗时 / 人数**：2–3 小时 · 2–4 人
- **AI 协作**：agent 可搭矩阵、根据用户资料填初稿并标注依据；无依据的格子留空或标「推测」。
- **衔接**：上游 M1-01、M1-05 → 下游 M1-10

### M1-10 Convergence Map · 趋势交汇图
- **来源**：通用设计实践
- **目的**：找出多个趋势同时作用的交汇点，那里往往是新机会。
- **何时用**：已有趋势矩阵，想找组合型机会；**不适用**：趋势少于 3 个时。
- **输入**：趋势清单或趋势矩阵。
- **步骤**：
  1. 把趋势画成节点或圆圈。
  2. 两两（或三个）检查组合：同时成立时会出现什么新需求或可能。
  3. 记录有意义的交汇点，写一句机会描述。
  4. 按新颖度与相关度粗筛。
- **产出**：趋势交汇图 + 交汇点机会清单。
- **耗时 / 人数**：1–2 小时 · 2–4 人
- **AI 协作**：agent 可系统枚举组合、起草机会描述供用户判断；机会是假设，不写成已证实结论。
- **衔接**：上游 M1-09 → 下游 M1-12、M1-11

### M1-11 Shift Mapping · 转变映射
- **来源**：通用设计实践
- **目的**：用「从 A 到 B」的句式描述正在发生或期望的转变，明确变化方向。
- **何时用**：需要把零散趋势浓缩成清晰的方向；**不适用**：还没有任何观察或资料时。
- **输入**：趋势、信号、洞察材料。
- **步骤**：
  1. 从材料中找出「过去是这样、正在变成那样」的迹象。
  2. 每条写成「从…到…」一句话，并附支持证据。
  3. 按主题（用户、技术、商业、组织）归类。
  4. 选出对项目最关键的 3–5 条转变。
- **产出**：转变清单（从、到、证据、影响）。
- **耗时 / 人数**：1–2 小时 · 1–4 人
- **AI 协作**：agent 可从用户材料中提炼句式并标注证据位置；无证据的转变标为假设。
- **衔接**：上游 M1-10 → 下游 M1-12、M1-14

### M1-12 Initial Opportunity Map · 初始机会地图
- **来源**：通用设计实践
- **目的**：把前期发现的机会画在一张图上，确定下一步重点探索的区域。
- **何时用**：趋势与意图阶段收尾、要决定研究方向；**不适用**：机会来源尚未收集时。
- **输入**：趋势、交汇点、转变、案例分析的结论。
- **步骤**：
  1. 列出候选机会，每个一句话描述。
  2. 选两条轴（如用户价值 × 组织能力匹配）定位机会。
  3. 标注每个机会的依据和不确定性。
  4. 与相关方讨论，圈定 2–4 个优先探索区。
- **产出**：机会空间图 + 机会说明表（描述、依据、不确定性、优先级）。
- **耗时 / 人数**：2–3 小时 · 2–5 人
- **AI 协作**：agent 可整理候选机会、出图、提示依据薄弱处；优先级需用户和团队决定。
- **衔接**：上游 M1-10、M1-08 → 下游 M1-14、M2-01

### M1-13 Offering-Context Layers · 产品-活动-文化三层图
- **来源**：通用设计实践
- **目的**：在产品/服务、用户活动、文化三个层面上定位一个创新，看它只改了表层还是触及深层。
- **何时用**：评估想法或案例的影响深度；**不适用**：尚无具体产品或活动对象时。
- **输入**：待分析的产品/案例、相关活动与文化背景资料。
- **步骤**：
  1. 画三个同心层：内层产品（Offering）、中层活动（Activity）、外层文化（Culture）。
  2. 写出该对象在每层上的表现与改变。
  3. 比较多个对象在各层的影响深浅。
  4. 讨论本项目希望在哪一层发力。
- **产出**：三层定位图 + 每层说明。
- **耗时 / 人数**：1–2 小时 · 1–3 人
- **AI 协作**：agent 可提供模板、根据用户资料填初稿；文化层判断需结合用户的真实观察，不凭空断言。
- **衔接**：上游 M1-04 → 下游 M1-14

### M1-14 Project Intent Brief · 项目意图陈述
- **来源**：通用设计实践
- **目的**：用一页纸写清项目要解决什么、为谁、为什么现在、成功是什么样。
- **何时用**：项目启动或方向重新对齐；**不适用**：意图已被明确签核且无变化时。
- **输入**：项目背景、相关方期望、前期发现。
- **步骤**：
  1. 回答四个问题：要改变什么、服务谁、为什么是现在、不做什么。
  2. 写出 3–5 句的意图陈述初稿。
  3. 补充初始假设和已知约束。
  4. 与相关方评审并定稿，记录分歧。
- **产出**：项目意图一页纸（背景、意图、范围内/外、假设、成功标志）。
- **耗时 / 人数**：1–2 小时 · 1–3 人
- **AI 协作**：agent 可提问引导、起草与改写陈述；项目目标与约束必须来自用户，不替用户拍板。
- **衔接**：上游 M1-12 → 下游 M2-01、M3-02

### M1-15 STEEP / PESTLE Scan · 宏观环境扫描
- **来源**：未来学
- **目的**：系统扫描社会、技术、经济、环境、政治（及法律）等宏观因素对项目的影响。
- **何时用**：新市场、长周期项目、政策敏感领域；**不适用**：短期迭代的局部优化。
- **输入**：主题、地域、时间范围、二手资料。
- **步骤**：
  1. 选框架：STEEP（社会/技术/经济/环境/政治）或 PESTLE（加法律）。
  2. 每个维度列出相关因素并附来源。
  3. 评估每个因素的影响程度与不确定性。
  4. 挑出高影响因素，写对项目的含义。
- **产出**：宏观因素清单（维度、因素、来源、影响、不确定性、含义）。
- **耗时 / 人数**：2–4 小时 · 1–3 人
- **AI 协作**：agent 可提供维度提示、整理归类；具体政策、数据须有真实出处，拿不到则标「待查」。
- **衔接**：上游 M1-14 → 下游 M1-16、M1-18

### M1-16 Weak Signals & Drivers · 弱信号与驱动力
- **来源**：未来学
- **目的**：识别尚处边缘但可能放大的变化迹象（弱信号），以及推动变化的深层力量（驱动力）。
- **何时用**：做前瞻判断、想提前发现变化；**不适用**：只关注当前已成主流的需求时。
- **输入**：扫描材料（热点、媒体、案例、宏观因素）。
- **步骤**：
  1. 从材料里挑出「罕见、意外、但若扩散影响大」的迹象，写成信号卡。
  2. 每张卡记录：现象、出处、日期、为什么重要。
  3. 把信号归类，追问其背后的驱动力。
  4. 标注驱动力的强度与确定性。
- **产出**：信号卡集 + 驱动力清单。
- **耗时 / 人数**：2–4 小时 · 1–3 人
- **AI 协作**：agent 可筛选和归类用户材料中的信号、推理驱动力；信号必须有真实出处，agent 不编造「边缘现象」。
- **衔接**：上游 M1-15、M1-02 → 下游 M1-17、M1-18

### M1-17 Three Horizons · 三层地平线
- **来源**：Sharpe
- **目的**：把当前主导模式（H1）、过渡创新（H2）、未来新模式（H3）放在同一框架里讨论转型路径。
- **何时用**：长期战略、转型讨论；**不适用**：只需决定下个迭代做什么时。
- **输入**：现状描述、弱信号、驱动力、愿景设想。
- **步骤**：
  1. 描述 H1：当前主导的做法及其衰退迹象。
  2. 描述 H3：理想的未来模式及今天已存在的萌芽。
  3. 描述 H2：连接两者的过渡创新，区分延续 H1 的和通向 H3 的。
  4. 画出三条曲线并标注关键行动。
- **产出**：三地平线图 + 各地平线要素说明。
- **耗时 / 人数**：2–3 小时工作坊 · 3–8 人
- **AI 协作**：agent 可引导讨论、整理要素、出图；未来愿景和取舍由用户与团队决定。
- **衔接**：上游 M1-16 → 下游 M1-18、M6-23

### M1-18 Futures Cone · 未来锥
- **来源**：Voros
- **目的**：把多种可能未来按可能 / 合理 / 很可能 / 期望分层，避免只盯着一种未来。
- **何时用**：做情景规划或长期判断；**不适用**：需要短期确定性预测时。
- **输入**：驱动力、不确定性、弱信号。
- **步骤**：
  1. 从现在出发画一个向外张开的锥。
  2. 列出未来设想，分别归入：可能（possible）、合理（plausible）、很可能（probable）、期望（preferable）。
  3. 为每类写 1–3 个简短情景及其依据。
  4. 讨论期望未来与很可能未来之间的差距。
- **产出**：多种未来分类图 + 情景简述。
- **耗时 / 人数**：1–3 小时 · 2–6 人
- **AI 协作**：agent 可协助生成情景草稿、检查分类一致性；情景是推演，不写成预测结论。
- **衔接**：上游 M1-16、M1-15 → 下游 M6-05、M6-23

### M1-19 Wardley Map · 价值链演化地图
- **来源**：Wardley
- **目的**：把满足用户需求的价值链组件按可见度和演化阶段定位，辅助判断自建、购买或外包。
- **何时用**：技术 / 平台战略、架构选型；**不适用**：纯体验细节设计。
- **输入**：用户与其需求、支撑该需求的组件清单。
- **步骤**：
  1. 在顶端写用户及需求，向下列出支撑组件形成价值链（纵轴=对用户的可见度）。
  2. 把每个组件按演化阶段放在横轴：创世、定制、产品、商品/公用。
  3. 连线表示依赖，标注正在演化的组件。
  4. 讨论策略：哪些自研差异化、哪些用现成商品。
- **产出**：演化地图 + 策略要点。
- **耗时 / 人数**：2–4 小时 · 1–4 人
- **AI 协作**：agent 可引导拆组件、出图、提出策略问题；组件现状和组织能力需用户确认。
- **衔接**：上游 M2-14 → 下游 M1-12、M7-02

## M2 Context 行业与情境

### M2-01 Contextual Research Plan · 情境研究计划
- **来源**：通用设计实践
- **目的**：规划要研究哪些情境问题（行业、竞争、历史、技术）以及用什么方法、按什么顺序。
- **何时用**：进入情境研究前；**不适用**：只做一两次快速资料查阅时。
- **输入**：意图陈述、已知信息、时间与资源约束。
- **步骤**：
  1. 列出需要回答的情境问题。
  2. 为每个问题选择方法和数据源。
  3. 排定时间、负责人和交付物。
  4. 定义「够了」的标准，避免无止境研究。
- **产出**：研究问题与计划表（问题、方法、来源、负责人、截止、完成标准）。
- **耗时 / 人数**：1–2 小时 · 1–2 人
- **AI 协作**：agent 可拆问题、推荐方法、生成计划表；资源和优先级由用户确定。
- **衔接**：上游 M1-14 → 下游 M2-02、M2-11

### M2-02 Publications Research · 文献与二手研究
- **来源**：通用设计实践
- **目的**：通过报告、论文、书籍、行业资料快速掌握领域已知知识。
- **何时用**：任何研究的早期；**不适用**：代替一手用户研究。
- **输入**：研究问题、可访问的文献来源。
- **步骤**：
  1. 按研究问题写检索词，列出候选文献。
  2. 筛选相关性与可信度，精读 5–15 篇。
  3. 每篇记录要点、方法、结论、局限、引用信息。
  4. 汇总共识、争议和空白。
- **产出**：文献摘要表 + 综述要点。
- **耗时 / 人数**：半天–数天 · 1–2 人
- **AI 协作**：agent 可设计检索、摘要用户提供或可访问的原文；只引用真实存在的文献，不虚构标题、作者或结论。
- **衔接**：上游 M2-01 → 下游 M1-03、M2-03

### M2-03 Historical Timeline · 历史演进时间线
- **来源**：通用设计实践
- **目的**：把领域历史划分为若干时代，理解每个时代的主导技术、需求与范式。
- **何时用**：需要从历史中看出长期模式；**不适用**：领域历史很短或与问题无关。
- **输入**：历史资料、关键事件。
- **步骤**：
  1. 收集关键事件与时间点。
  2. 按范式变化划分 3–6 个时代并命名。
  3. 描述每个时代的技术、用户、商业与文化特征。
  4. 推测下一个时代可能的特征。
- **产出**：时代划分时间线 + 各时代特征表。
- **耗时 / 人数**：2–4 小时 · 1–2 人
- **AI 协作**：agent 可帮助结构化与划分；历史事件和日期需可核实，不确定处标注。
- **衔接**：上游 M2-02 → 下游 M2-04、M1-11

### M2-04 Innovation Timeline · 创新演化时间线
- **来源**：通用设计实践
- **目的**：追踪某类产品或解决方案随时间的创新演变，看清演化路径。
- **何时用**：判断产品品类下一步的演化方向；**不适用**：全新品类无历史可循时。
- **输入**：历代产品/方案资料。
- **步骤**：
  1. 选择追踪对象（某功能、某品类）。
  2. 按时间列出代表性创新，记录改变了什么。
  3. 标注演化维度（更小、更便宜、更智能、更互联等）。
  4. 沿维度外推可能的下一步。
- **产出**：创新演化时间线 + 演化维度说明。
- **耗时 / 人数**：2–4 小时 · 1–2 人
- **AI 协作**：agent 可整理时间线、提炼演化维度；具体产品与年份需可核实。
- **衔接**：上游 M2-03 → 下游 M1-11、M2-08

### M2-05 Financial Profile · 财务画像
- **来源**：通用设计实践
- **目的**：通过财务数据了解行业或企业的收入结构、成本、利润与投资方向。
- **何时用**：判断商业可行性、理解玩家实力；**不适用**：拿不到可信财务数据时。
- **输入**：财报、公开数据、内部财务资料。
- **步骤**：
  1. 确定分析对象和指标（营收、增速、毛利、研发投入等）。
  2. 从原始来源收集多期数据。
  3. 对比趋势与同业差异。
  4. 写出对项目的财务含义。
- **产出**：财务概况表 + 趋势图 + 解读。
- **耗时 / 人数**：2–4 小时 · 1 人
- **AI 协作**：agent 可计算、作图和解读用户提供的数据；不得编造财务数字，缺数据就标缺。
- **衔接**：上游 M2-02 → 下游 M2-09、M2-10

### M2-06 Analogous Models · 类比模型
- **来源**：通用设计实践
- **目的**：从结构相似但行业不同的案例中借鉴做法。
- **何时用**：本行业惯例限制了思路；**不适用**：问题强依赖本行业特有约束且需精确答案时。
- **输入**：问题的抽象描述（核心挑战）。
- **步骤**：
  1. 把问题抽象成通用挑战（如「在高压下快速交接」）。
  2. 找出面对同样挑战的其他行业/场景。
  3. 分析它们的解法和成立条件。
  4. 评估哪些可迁移、需要怎样改造。
- **产出**：跨行业类比清单（类比对象、做法、成立条件、迁移想法）。
- **耗时 / 人数**：1–3 小时 · 1–4 人
- **AI 协作**：agent 擅长提供候选类比领域和抽象化；具体案例细节需核实。
- **衔接**：上游 M1-04 → 下游 M5-06

### M2-07 Competitors-Complementors Map · 竞争者-互补者地图
- **来源**：通用设计实践
- **目的**：识别竞争者和互补者（让你的产品更有价值的伙伴），看清竞合格局。
- **何时用**：制定市场策略、寻找合作；**不适用**：尚不清楚自身产品范围时。
- **输入**：市场玩家清单、各自产品信息。
- **步骤**：
  1. 以本项目为中心，列出直接竞争、间接竞争、替代方案。
  2. 列出互补者（配套产品、渠道、平台）。
  3. 标注关系强弱和变化趋势。
  4. 找出可能由竞争转合作或反之的对象。
- **产出**：竞合关系图 + 玩家说明表。
- **耗时 / 人数**：1–3 小时 · 1–3 人
- **AI 协作**：agent 可提供分类框架和出图；玩家信息须真实，用户确认后定稿。
- **衔接**：上游 M2-02 → 下游 M2-15、M2-14

### M2-08 Innovation Types Diagnostics · 创新类型诊断
- **来源**：通用设计实践
- **目的**：用项目约定的创新维度（见 M1-07）诊断一个行业或企业，看创新集中在哪、缺在哪。
- **何时用**：评估行业创新现状、找差异化方向；**不适用**：玩家信息不足时。
- **输入**：行业主要玩家及其近年的创新举措。
- **步骤**：
  1. 列出玩家与其创新举措。
  2. 把每个举措归入一个或多个创新维度。
  3. 做热力表：玩家 × 类型。
  4. 找出行业普遍忽视的类型作为机会。
- **产出**：行业创新类型诊断热力表 + 机会说明。
- **耗时 / 人数**：2–4 小时 · 1–3 人
- **AI 协作**：agent 可归类和制表；举措事实需来自可核实资料。
- **衔接**：上游 M1-07 → 下游 M2-09、M1-12

### M2-09 Industry Diagnostics · 行业诊断
- **来源**：通用设计实践
- **目的**：综合评估行业的健康度：增长、盈利、竞争强度、创新活跃度、风险。
- **何时用**：进入新行业或评估战略方向；**不适用**：只关心单一产品细节时。
- **输入**：关键事实、财务画像、竞争分析结果。
- **步骤**：
  1. 选定评估维度与判断标准。
  2. 每个维度汇总证据并打分（附依据）。
  3. 汇总成健康度雷达或表格。
  4. 写出行业的机会与威胁。
- **产出**：行业健康度评估（维度、证据、评分、结论）。
- **耗时 / 人数**：2–4 小时 · 1–2 人
- **AI 协作**：agent 可建评估框架、汇总证据；评分须基于真实证据，缺证据的维度标「不可评」。
- **衔接**：上游 M2-05、M2-08 → 下游 M2-10

### M2-10 SWOT Analysis · SWOT 分析
- **来源**：通用设计实践
- **目的**：梳理内部优势/劣势与外部机会/威胁，形成战略判断基础。
- **何时用**：阶段性盘点、战略讨论；**不适用**：缺乏证据只凭感觉填四格时。
- **输入**：内部能力信息、外部环境分析结果。
- **步骤**：
  1. 分别列出 S、W（内部）与 O、T（外部），每条附依据。
  2. 删除模糊空泛的条目，保留具体的。
  3. 做交叉：SO（用优势抓机会）、WO、ST、WT 策略。
  4. 选出优先策略。
- **产出**：SWOT 四象限 + 交叉策略表。
- **耗时 / 人数**：1–2 小时 · 2–6 人
- **AI 协作**：agent 可引导、归类、挑出空泛条目；内部能力信息须由用户提供。
- **衔接**：上游 M2-09 → 下游 M1-12、M1-14

### M2-11 Subject Matter Experts Interview · 领域专家访谈
- **来源**：通用设计实践
- **目的**：向领域专家学习专业知识、行业惯例和隐性规则。
- **何时用**：领域专业性强、团队不熟悉；**不适用**：想了解普通用户真实行为时（用 M3 方法）。
- **输入**：专家名单、访谈提纲、已有疑问。
- **步骤**：
  1. 列出知识缺口，写成问题。
  2. 招募 2–5 位不同视角的专家。
  3. 访谈并请专家举具体例子。
  4. 整理术语表、流程、常见误区与分歧。
- **产出**：专家访谈纪要（观点、例子、术语、分歧、后续问题）。
- **耗时 / 人数**：每场 1 小时 · 1–2 人
- **AI 协作**：agent 可写提纲、整理用户给的转录；访谈须真实进行，不模拟专家回答。
- **衔接**：上游 M2-01 → 下游 M2-12、M3-02

### M2-12 Interest Groups Discussion · 兴趣小组讨论
- **来源**：通用设计实践
- **目的**：通过与特定兴趣群体（爱好者、社群、协会）的讨论，了解群体的看法和规范。
- **何时用**：目标人群有明显的社群组织；**不适用**：需要个体深入细节或敏感话题时。
- **输入**：群体渠道、讨论提纲、主持人。
- **步骤**：
  1. 确定要接触的群体及邀请方式。
  2. 准备讨论话题与引导问题。
  3. 主持 60–90 分钟讨论，注意平衡发言。
  4. 整理共识、分歧与群体特有用语。
- **产出**：群体观点汇总（话题、共识、分歧、代表发言定位）。
- **耗时 / 人数**：每场 1.5 小时 + 整理 · 2 人（主持 + 记录）
- **AI 协作**：agent 可准备提纲、整理记录；讨论内容来自真实记录，不编写群体发言。
- **衔接**：上游 M2-11 → 下游 M3-01、M4-20

### M2-13 Stakeholder Map · 利益相关方地图
- **来源**：服务设计
- **目的**：识别所有与项目相关的个人和组织，以及他们的关系、影响力和利益。
- **何时用**：服务或组织类项目、牵涉多方时；**不适用**：单人使用的小工具功能。
- **输入**：项目范围、已知相关方信息。
- **步骤**：
  1. 列出相关方：用户、内部团队、合作方、监管、其他受影响者。
  2. 按与核心的距离（核心 / 直接 / 间接）排布。
  3. 标注关系（信息、资金、服务、冲突）。
  4. 评估影响力与利益，确定参与策略。
- **产出**：相关方关系图 + 影响力/利益表。
- **耗时 / 人数**：1–2 小时 · 2–5 人
- **AI 协作**：agent 可提示可能遗漏的相关方类型并出图；实际关系需用户确认。
- **衔接**：上游 M1-14 → 下游 M2-14、M3-01

### M2-14 Ecosystem Map · 生态系统地图
- **来源**：服务设计
- **目的**：展示整个生态中各参与者之间的价值流（金钱、信息、服务、数据）。
- **何时用**：平台、多边市场、服务网络；**不适用**：只关注单一界面交互时。
- **输入**：相关方地图、业务流程资料。
- **步骤**：
  1. 以用户或核心服务为中心放置参与者。
  2. 用带方向的箭头标注各类价值流。
  3. 找出价值流的断点、瓶颈和单点依赖。
  4. 标注机会点。
- **产出**：生态价值流图 + 断点与机会说明。
- **耗时 / 人数**：2–3 小时 · 2–5 人
- **AI 协作**：agent 可整理参与者和流向并出图；流向事实需用户确认。
- **衔接**：上游 M2-13 → 下游 M1-19、M4-05

### M2-15 Porter's Five Forces · 五力模型
- **来源**：Porter
- **目的**：从现有竞争、新进入者、替代品、供应商议价、买方议价五个力量评估行业吸引力。
- **何时用**：进入市场或定位决策；**不适用**：内部工具或非市场化场景。
- **输入**：行业结构资料、竞争分析结果。
- **步骤**：
  1. 分别描述五种力量的现状，附依据。
  2. 为每种力量评估强弱（高/中/低）。
  3. 判断整体行业吸引力与利润来源。
  4. 写出应对策略。
- **产出**：五力评估表（力量、证据、强度、影响、策略）。
- **耗时 / 人数**：1–3 小时 · 1–3 人
- **AI 协作**：agent 可提供框架、整理证据；强弱判断需基于真实资料并由用户确认。
- **衔接**：上游 M2-07 → 下游 M2-10

### M2-16 Competitive UX Benchmark · 竞品体验对标
- **来源**：UX 实践
- **目的**：在相同任务下对比竞品的体验，找出行业基线与差异化空间。
- **何时用**：设计具体功能或流程前；**不适用**：尚未明确核心任务时。
- **输入**：竞品清单（3–6 个）、核心任务、评估维度。
- **步骤**：
  1. 定义 3–5 个核心任务和评估维度（步数、清晰度、容错、速度等）。
  2. 亲自在每个竞品上完成任务，截图记录。
  3. 按维度打分并写观察。
  4. 汇总最佳实践与普遍痛点。
- **产出**：竞品体验对比表（任务 × 竞品，含截图、评分、备注）。
- **耗时 / 人数**：半天–2 天 · 1–2 人
- **AI 协作**：agent 可设计任务与维度、整理截图记录、写对比；实际操作竞品由用户完成或提供截图，agent 不臆造竞品界面。
- **衔接**：上游 M2-07 → 下游 M6-20、M4-16

### M2-17 Existing Data / Analytics Review · 已有数据回看
- **来源**：UX 实践
- **目的**：先用已有的数据（埋点、客服工单、反馈、搜索日志）了解现状，发现疑点再做研究。
- **何时用**：已有上线产品；**不适用**：全新产品无数据时。
- **输入**：可访问的分析平台、导出数据、工单与反馈。
- **步骤**：
  1. 列出想回答的问题和对应数据源。
  2. 拉取数据，检查口径与完整性。
  3. 找出异常：流失点、高频投诉、低使用功能。
  4. 把疑点写成待研究问题，交给定性研究验证。
- **产出**：数据现状与疑点清单（指标、数值、口径、疑点、后续研究问题）。
- **耗时 / 人数**：2–6 小时 · 1–2 人
- **AI 协作**：agent 可分析用户导出的数据、写查询、找异常；数字只来自真实数据，无权限或无数据时直接说明。
- **衔接**：上游 M2-01 → 下游 M3-02、M7-18

## M3 People 用户研究

### M3-01 Participant Matrix · 研究对象矩阵
- **来源**：通用设计实践
- **目的**：规划要研究哪些类型的人，确保覆盖关键差异而不是只找方便的样本。
- **何时用**：招募用户研究对象前；**不适用**：研究对象已被严格限定时。
- **输入**：相关方地图、用户分群假设。
- **步骤**：
  1. 选 2 条影响行为的关键维度（如使用频率 × 专业程度）。
  2. 画出矩阵，每格描述一类对象。
  3. 为每格设定招募数量和筛选条件。
  4. 标注极端或边缘人群。
- **产出**：招募对象矩阵 + 筛选问卷要点。
- **耗时 / 人数**：1–2 小时 · 1–2 人
- **AI 协作**：agent 可建议维度、写筛选题；招募和联系真实参与者由用户完成。
- **衔接**：上游 M2-13 → 下游 M3-02、M3-19

### M3-02 User Research Plan · 用户研究计划
- **来源**：通用设计实践
- **目的**：明确研究问题、方法、对象、时间与伦理安排，让用户研究可执行、可追溯。
- **何时用**：任何一手用户研究前；**不适用**：几乎不适用——即使快速研究也值得写简版。
- **输入**：意图陈述、研究对象地图、资源约束。
- **步骤**：
  1. 写出 3–5 个研究问题及其要支持的决策。
  2. 为每个问题选方法（访谈、观察、日记等）。
  3. 定对象、人数、日程、分工。
  4. 写知情同意与数据处理方式。
  5. 准备提纲和记录模板。
- **产出**：研究计划（问题、方法、对象、日程、伦理、模板）。
- **耗时 / 人数**：2–4 小时 · 1–2 人
- **AI 协作**：agent 可起草计划、提纲、同意书模板；研究约束与伦理审批由用户确认。
- **衔接**：上游 M1-14、M3-01 → 下游 M3-07、M3-05

### M3-03 Human Factors Lens · 人因五维观察
- **来源**：通用设计实践
- **目的**：从身体、认知、社会、文化、情感五个人因维度观察和分析用户体验。
- **何时用**：需要全面、不遗漏地看待人的体验；**不适用**：只需快速验证单个假设时。
- **输入**：观察对象、情境、记录工具。
- **步骤**：
  1. 准备五列记录表：身体、认知、社会、文化、情感。
  2. 观察或访谈时按五维记录具体现象。
  3. 对每维标注问题与机会。
  4. 汇总跨对象的共性。
- **产出**：五维观察记录表。
- **耗时 / 人数**：视观察时长 · 1–2 人
- **AI 协作**：agent 可提供记录表、帮用户把原始笔记按五维归类；观察须由用户实地进行。
- **衔接**：上游 M3-05 → 下游 M3-14、M4-01

### M3-04 Five-Element Observation Frame · 五要素观察框架
- **来源**：通用设计实践
- **目的**：用人（People）、物件（Objects）、环境（Environments）、信息（Messages）、服务（Services）五要素结构化记录观察。
- **何时用**：实地观察时需要一致的记录框架；**不适用**：纯线上远程访谈且无情境可看时。
- **输入**：观察场景、Five-Element Observation Frame 记录表。
- **步骤**：
  1. 准备五栏记录表与拍照清单。
  2. 在现场按五要素记录所见。
  3. 当天整理，补充照片编号和时间。
  4. 在各要素内找模式和异常。
- **产出**：Five-Element Observation Frame 观察表（要素、观察、照片编号、时间、备注）。
- **耗时 / 人数**：每次观察 1–3 小时 · 1–2 人
- **AI 协作**：agent 可准备模板、整理用户笔记；观察内容来自用户现场，不编造。
- **衔接**：上游 M3-02 → 下游 M3-14、M4-02

### M3-05 Field Visit · 实地走访
- **来源**：通用设计实践
- **目的**：到用户真实环境中观察和交谈，理解行为发生的情境。
- **何时用**：情境对行为影响大；**不适用**：无法获准进入现场或纯数字化远程场景（可改用 M3-13）。
- **输入**：研究计划、现场许可、观察框架、拍摄同意。
- **步骤**：
  1. 预约现场并确认拍照/录音许可。
  2. 带着观察框架（Five-Element Observation Frame / AEIOU）前往。
  3. 先观察后提问，记录具体行为和环境细节。
  4. 当天整理笔记和照片。
- **产出**：走访笔记与照片（时间、地点、观察、引述、照片编号）。
- **耗时 / 人数**：每次 2–4 小时 · 1–2 人
- **AI 协作**：agent 可准备走访清单与提纲、事后整理笔记；实地走访只能由用户亲自完成。
- **衔接**：上游 M3-02 → 下游 M3-04、M3-14

### M3-06 Video Ethnography · 视频民族志
- **来源**：通用设计实践
- **目的**：用视频记录用户在情境中的行为，便于反复观看、发现细节。
- **何时用**：行为细节快速、复杂，笔记记不全；**不适用**：隐私敏感且无法获得拍摄同意时。
- **输入**：拍摄许可、设备、拍摄计划。
- **步骤**：
  1. 获得书面拍摄同意，说明用途与保存方式。
  2. 按计划拍摄完整活动过程。
  3. 回看视频，按时间码标注关键行为。
  4. 剪出代表性片段并写注释。
- **产出**：标注视频片段（时间码、行为、注释、标签）。
- **耗时 / 人数**：拍摄 + 回看约 3 倍时长 · 1–2 人
- **AI 协作**：agent 可设计标注体系、整理用户提供的时间码与转录；无法看视频时不猜测画面内容。
- **衔接**：上游 M3-05 → 下游 M3-14、M4-03

### M3-07 Ethnographic Interview · 民族志访谈
- **来源**：通用设计实践
- **目的**：在用户环境中进行开放式访谈，理解其行为背后的意义和价值观。
- **何时用**：想理解「为什么」和深层动机；**不适用**：需要统计分布时（用 M3-23）。
- **输入**：提纲、受访者、情境场所、录音同意。
- **步骤**：
  1. 以宽泛问题开场，请对方讲述具体经历。
  2. 追问细节：「上次是什么时候」「能给我看看吗」。
  3. 注意言行差异，记录环境线索。
  4. 结束后 24 小时内整理转录与要点。
- **产出**：访谈转录与要点（参与者代码、引述定位、要点、疑点）。
- **耗时 / 人数**：每场 1–2 小时 · 1–2 人
- **AI 协作**：agent 可写提纲、练习追问、整理用户提供的转录；绝不代替受访者回答或生成「模拟访谈」当真实数据。
- **衔接**：上游 M3-02 → 下游 M3-14、M4-01

### M3-08 Photo Elicitation Interview · 照片引导访谈
- **来源**：视觉人类学
- **目的**：请用户自己拍摄或提供照片，以照片为线索讲述生活和体验。
- **何时用**：研究者难以进入的场景、希望用户视角；**不适用**：用户不便拍照或涉及他人隐私时。
- **输入**：拍摄任务说明、回收渠道、访谈提纲。
- **步骤**：
  1. 给用户拍摄主题（如「一天中让你烦的时刻」）和期限。
  2. 回收照片并预览。
  3. 访谈时让用户逐张讲述背后的故事。
  4. 把照片与故事配对归档。
- **产出**：用户照片与故事（照片、用户叙述、主题标签）。
- **耗时 / 人数**：拍摄 3–7 天 + 访谈 1 小时 · 1–2 人
- **AI 协作**：agent 可写拍摄任务说明和提纲、整理故事；照片与叙述须来自真实用户。
- **衔接**：上游 M3-02 → 下游 M3-14、M4-01

### M3-09 Cultural Artifacts · 文化器物收集
- **来源**：通用设计实践
- **目的**：收集用户自制或常用的物件（便签、表格、改装工具），从中读出需求和变通做法。
- **何时用**：用户有自发的变通方案；**不适用**：数字化程度高、几乎没有实体痕迹时（可收集截图替代）。
- **输入**：访谈或走访机会、收集许可。
- **步骤**：
  1. 在走访中留意用户自制或改造的物件。
  2. 经许可拍照或收集，并询问来历与用法。
  3. 记录每件器物解决了什么问题。
  4. 归类并提炼背后的未满足需求。
- **产出**：器物清单与含义（器物、用法、来历、隐含需求）。
- **耗时 / 人数**：随走访进行 · 1–2 人
- **AI 协作**：agent 可设计清单并帮助解读；器物与用户说法须来自真实收集。
- **衔接**：上游 M3-05 → 下游 M3-14、M4-01

### M3-10 Image Sorting · 图片分类
- **来源**：通用设计实践
- **目的**：让用户对一组图片分组、排序或选择，揭示其情感联想和价值偏好。
- **何时用**：探索难以用语言表达的感受（品牌、氛围、愿景）；**不适用**：需要功能性需求细节时。
- **输入**：30–60 张图片、分类任务说明。
- **步骤**：
  1. 准备多样化图片集，避免引导性。
  2. 请用户按任务分组或选择（如「代表理想的一天」）。
  3. 请用户解释每组的理由。
  4. 记录结果并跨用户比较。
- **产出**：分类结果与理由（组别、图片编号、用户解释）。
- **耗时 / 人数**：每人 30–60 分钟 · 1–2 人
- **AI 协作**：agent 可建议图片主题、整理结果和比较；分组与理由来自真实用户。
- **衔接**：上游 M3-02 → 下游 M4-13、M4-03

### M3-11 Experience Simulation · 体验模拟
- **来源**：通用设计实践
- **目的**：研究者亲身模拟用户的处境（限制、工具、流程），获得第一人称体会。
- **何时用**：难以接触用户或想建立同理心；**不适用**：以此代替真实用户研究。
- **输入**：模拟设定（限制条件、任务）、记录工具。
- **步骤**：
  1. 设计模拟任务与限制（如戴厚手套操作界面）。
  2. 亲自完成任务，全程记录感受与障碍。
  3. 与团队交流体验。
  4. 把发现写成需用真实用户验证的假设。
- **产出**：亲身体验记录（任务、障碍、感受、待验证假设）。
- **耗时 / 人数**：1–4 小时 · 1–4 人
- **AI 协作**：agent 可设计模拟方案和记录模板；体验必须由用户亲自完成，agent 不描述「模拟出来的感受」。
- **衔接**：上游 M3-02 → 下游 M3-19、M4-21

### M3-12 Field Activity · 现场活动
- **来源**：通用设计实践
- **目的**：在现场让用户完成设计好的活动（绘图、排序、拼贴、角色扮演），激发平时说不出的想法。
- **何时用**：访谈难以挖出深层想法；**不适用**：时间极短或用户不适应互动形式时。
- **输入**：活动材料、活动说明、记录方式。
- **步骤**：
  1. 设计与研究问题对应的活动（如画出一天的流程）。
  2. 准备材料并试运行一次。
  3. 在现场引导用户完成，边做边请其讲解。
  4. 收集活动产物并记录观察。
- **产出**：活动产物与观察记录。
- **耗时 / 人数**：每场 1–2 小时 · 2 人
- **AI 协作**：agent 可设计活动与材料清单、整理结果；活动须真实执行。
- **衔接**：上游 M3-02 → 下游 M3-14、M4-02

### M3-13 Remote Research · 远程研究
- **来源**：通用设计实践
- **目的**：通过视频会议、远程测试、在线任务等方式研究分布各地的用户。
- **何时用**：用户分散、预算有限、数字产品；**不适用**：强依赖物理环境的研究。
- **输入**：远程工具、参与者、任务与提纲、同意书。
- **步骤**：
  1. 选择形式（远程访谈、远程可用性测试、在线任务）。
  2. 提前测试工具与网络，发送说明。
  3. 进行会话，请用户共享屏幕或展示环境。
  4. 整理录屏、转录与观察。
- **产出**：远程研究数据（录屏/转录、观察笔记、参与者代码）。
- **耗时 / 人数**：每场 30–60 分钟 · 1–2 人
- **AI 协作**：agent 可准备脚本与说明、整理用户提供的记录；会话须由真实参与者参加。
- **衔接**：上游 M3-02 → 下游 M3-14、M4-01

### M3-14 Observation Log · 观察记录库
- **来源**：通用设计实践
- **目的**：把所有观察结构化存入统一数据库，便于检索、比较和后续分析。
- **何时用**：观察条目多、来自多个方法和研究者；**不适用**：只有一两次访谈时（直接分析即可）。
- **输入**：各类研究记录（笔记、照片、视频、转录）。
- **步骤**：
  1. 定义字段：观察ID、来源、参与者代码、情境、描述、引述、标签、媒体链接。
  2. 把每条观察拆成独立条目录入。
  3. 统一标签体系并交叉校对。
  4. 按标签检索，初步查看模式。
- **产出**：结构化观察库（表格或数据库）。
- **耗时 / 人数**：数小时–数天 · 1–3 人
- **AI 协作**：agent 可设计字段、把用户提供的原始记录拆条、打标签；每条须可追溯到真实来源，不补写观察。
- **衔接**：上游 M3-05、M3-07 → 下游 M4-01、M4-20

### M3-15 Contextual Inquiry · 情境访查
- **来源**：Beyer & Holtzblatt
- **目的**：以「师傅-学徒」模式在用户工作时观察并提问，理解真实工作流程。
- **何时用**：复杂工作流、专业工具；**不适用**：行为不在可观察的场景中发生时。
- **输入**：参与者、工作现场、焦点问题、同意书。
- **步骤**：
  1. 简短开场，说明你是来学习的「学徒」。
  2. 用户正常工作，你观察并在合适时机追问原因。
  3. 即时向用户复述你的理解，请其纠正。
  4. 会后整理为工作模型（流程、顺序、文化、物件、物理环境）。
- **产出**：工作模型 + 访查笔记。
- **耗时 / 人数**：每场 1.5–2 小时 · 1–2 人
- **AI 协作**：agent 可准备焦点问题、协助把用户笔记整理成工作模型；访查须用户亲自完成。
- **衔接**：上游 M3-02 → 下游 M3-14、M4-11

### M3-16 Diary Study · 日记研究
- **来源**：UX 实践
- **目的**：让用户在一段时间内持续记录相关经历，捕捉随时间变化的行为和感受。
- **何时用**：行为跨天跨周、不定时发生；**不适用**：需要立即结果或参与者难以坚持时。
- **输入**：参与者（5–15 人）、日记工具、提示问题、激励方案。
- **步骤**：
  1. 设计记录频率和提示（事件触发或定时）。
  2. 开场说明并试记一次。
  3. 研究期间定期检查、提醒、追问。
  4. 结束后做收尾访谈并整理数据。
- **产出**：纵向日记数据（参与者、日期、条目、媒体、标签）+ 收尾访谈要点。
- **耗时 / 人数**：1–4 周 · 1–2 人
- **AI 协作**：agent 可设计提示与提醒话术、分析用户导出的日记条目；日记内容只能来自真实参与者。
- **衔接**：上游 M3-02 → 下游 M3-14、M4-16

### M3-17 Shadowing · 跟随观察
- **来源**：UX 实践
- **目的**：在一段时间内跟随用户，记录其行为和情境的完整时间线。
- **何时用**：想了解一整天或整个流程的真实节奏；**不适用**：跟随会显著干扰对方或涉及敏感场所时。
- **输入**：参与者许可、时间段、记录模板。
- **步骤**：
  1. 约定跟随范围和不可记录的内容。
  2. 保持低存在感，按时间记录行为、地点、工具、人。
  3. 在自然停顿处简短询问原因。
  4. 整理成带时间戳的行为时间线。
- **产出**：行为时间线（时间、行为、情境、工具、备注）。
- **耗时 / 人数**：半天–一天 · 1 人
- **AI 协作**：agent 可准备模板、把用户笔记整理为时间线；跟随须用户亲自完成。
- **衔接**：上游 M3-02 → 下游 M3-14、M4-16

### M3-18 Cultural Probes · 文化探针
- **来源**：Gaver
- **目的**：给用户一套开放性的任务包（明信片、相机、地图、日志），激发其表达生活和想法的灵感素材。
- **何时用**：探索性、启发性研究；**不适用**：需要可比较、可量化答案时。
- **输入**：探针包设计、参与者、回收方式。
- **步骤**：
  1. 设计开放、有趣的任务（如「寄一张让你安心的地方的照片」）。
  2. 制作并寄送探针包，说明期限。
  3. 回收物件，不急于分类，先整体浏览获取灵感。
  4. 必要时与参与者做回访。
- **产出**：探针回收物 + 启发笔记。
- **耗时 / 人数**：1–4 周 · 1–3 人
- **AI 协作**：agent 可构思任务与包内物件；回收物是用户真实产物，agent 只帮整理和提问，不代写。
- **衔接**：上游 M3-02 → 下游 M3-14、M5-04

### M3-19 Extreme Users · 极端用户访谈
- **来源**：IDEO
- **目的**：访谈极端使用者（重度、完全不用、特殊需求者），放大主流用户不明显的需求。
- **何时用**：想发现隐藏需求或创新机会；**不适用**：只需验证主流用户可用性时。
- **输入**：研究对象地图中的极端格、招募渠道、提纲。
- **步骤**：
  1. 定义「极端」的维度（频率、能力、情境）。
  2. 招募两端的用户各 2–3 人。
  3. 访谈其变通做法、痛点和期望。
  4. 思考这些需求在主流用户身上的弱化版本。
- **产出**：极端需求清单（用户类型、需求、变通方式、对主流的启示）。
- **耗时 / 人数**：每场 1 小时 · 1–2 人
- **AI 协作**：agent 可帮助定义极端维度和写提纲；访谈须真实，agent 不虚构极端用户故事。
- **衔接**：上游 M3-01 → 下游 M3-14、M5-03

### M3-20 AEIOU · 观察框架
- **来源**：Doblin
- **目的**：用活动（Activities）、环境（Environments）、互动（Interactions）、物件（Objects）、用户（Users）五要素组织观察。
- **何时用**：实地观察需要统一的编码框架；**不适用**：纯文本数据分析。
- **输入**：观察场景、AEIOU 记录表。
- **步骤**：
  1. 准备五栏记录表。
  2. 观察时按五要素分别记录。
  3. 事后在每个要素内找模式，并看要素之间的联系。
  4. 标出值得追问的现象。
- **产出**：AEIOU 观察表 + 模式备注。
- **耗时 / 人数**：每次 1–3 小时 · 1–2 人
- **AI 协作**：agent 可提供模板、把用户笔记按五要素归类；观察须来自现场。
- **衔接**：上游 M3-05 → 下游 M3-14、M4-20

### M3-21 JTBD Switch Interview · 转换访谈
- **来源**：Jobs to be Done
- **目的**：访谈最近换用（或放弃）某方案的人，重建其决策时间线，识别推力、拉力、焦虑、习惯四种力量。
- **何时用**：理解用户为何选择或离开产品；**不适用**：受访者没有近期真实的转换经历时。
- **输入**：近期发生转换的受访者、时间线提纲。
- **步骤**：
  1. 招募近期（通常 3 个月内）完成转换的人。
  2. 从购买/切换那一刻倒推：第一次想到、积极寻找、决定、使用。
  3. 在每个节点追问具体情境和情绪。
  4. 把发现归入四力：推（现状问题）、拉（新方案吸引）、焦虑（对新方案的担心）、习惯（对旧方案的依恋）。
- **产出**：四力图 + 转换时间线。
- **耗时 / 人数**：每场 45–60 分钟 · 1–2 人
- **AI 协作**：agent 可写提纲、帮用户把转录归入四力；访谈须真实，agent 不编造切换故事。
- **衔接**：上游 M3-02 → 下游 M4-22、M4-01

### M3-22 Card Sorting · 卡片分类
- **来源**：信息架构
- **目的**：让用户把内容卡片分组并命名，了解其心智模型，指导信息架构。
- **何时用**：设计导航、菜单、内容分类；**不适用**：内容项过少（少于 15 项）或尚未确定内容时。
- **输入**：30–60 张内容卡片、参与者（开放式 15 人左右）、线上或线下工具。
- **步骤**：
  1. 选形式：开放式（用户自定组名）、封闭式（给定组名）或混合。
  2. 准备卡片，措辞避免暗示分组。
  3. 让参与者分组并命名，记录其解释。
  4. 分析共现矩阵与常见组名。
- **产出**：用户心智分组（共现矩阵、分组建议、命名候选）。
- **耗时 / 人数**：每人 20–40 分钟 + 分析 · 1–2 人
- **AI 协作**：agent 可准备卡片、分析用户导出的分类结果；分组数据须来自真实参与者。
- **衔接**：上游 M3-02 → 下游 M4-08、M4-09

### M3-23 Survey · 问卷调查
- **来源**：通用
- **目的**：从较大样本收集量化数据，衡量态度、行为频率或需求分布。
- **何时用**：验证定性研究发现的普遍程度；**不适用**：探索「为什么」或尚不清楚该问什么时。
- **输入**：研究问题、目标人群、样本渠道、问卷工具。
- **步骤**：
  1. 从研究问题倒推要测量的变量。
  2. 写题目：避免诱导、双重问题；选合适量表。
  3. 小范围预测试并修改。
  4. 发放并监控样本构成。
  5. 清洗数据、分析，并说明样本局限。
- **产出**：量化数据 + 分析报告（样本说明、结果、置信度、局限）。
- **耗时 / 人数**：1–3 周 · 1–2 人
- **AI 协作**：agent 可设计和审查题目、分析用户导出的真实数据；不得生成模拟答卷，也不从小样本推断总体比例而不注明局限。
- **衔接**：上游 M3-14 → 下游 M4-14、M6-17
