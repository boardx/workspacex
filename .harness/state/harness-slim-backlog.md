> 本文件是**执行清单**，不是论证文档。每一条都带**实测数字**与**验收方式**；

> 硬约束（继承 AGENTS.md）：
> - **不得制造第二份事实副本**——本表里的行数不复述到别处，别处引用本文件。

## 为什么做这件事

不是「代码太多」，是**同一个形态被重复实现，以及为不存在的数据预建了治理机器**。
两条根因，四次实证（2026-08-18 同一会话内）：

| 模块 | 建的时候的假设 | 真实数据 | 代价 |
|---|---|---|---|
| H3A 治理机器 | 为 Epic E3 预建 | 0 task / 0 review / 2 event / 1 domain | 7,872 行守 3 个文件 |
| merge-gate approve 检查 | native APPROVE 是真实信号 | 100 个已合并 PR，**0** 个有 | 事后加 suspend 开关 |
| merge-gate verdict 标签检查 | `review:*-ok` 标签是真实信号 | 300 个 PR，**0** 个有 | 事后加 suspend 开关 |
| verify-risk 高风险分类器 | 对 feature 元数据子串匹配 | 304 个 feature，4/7 标记零命中 | 整个重写 |

## 为什么到不了 10,000

剩下的 25,500 里：8,632 是测试——本会话全部真发现（0/100 native approve、
4/7 风险标记零命中、6 个真失败样本、5 类变异捕获）都是靠回放真实数据 + 变异反证抓出来的，
砍测试等于砍掉唯一有效的机制；995 是真实部署脚本；约 15,000 是
`verify`（全仓引用 174 次）、`doctor`（46）、`sync`、`claim`、`readiness` 这些每天在跑的
路径及其 lib。**再砍就是砍在跑的东西，与「不影响项目」直接冲突。**
