# 原型截图审计评分卡（机器硬判 + 模型软判，分开记）

> 2026-09-09 人类指令：「你做完一次设计，界面出来以后，你要有一个机制，做截图 audit，
> 迭代到 80 分才放行，比如这个界面，没有 60 分，看起来很不专业。」
> 裁决：**卡开发期交付**（不是运行期自修复）；**机器硬判 + 模型软判分开记**。

## 为什么要有这道门

迭代 14 做完时：单测全绿、`apps/web` 3373 条全绿、PR 22 条 check 全绿、门控 doctor 干净。
而用户打开看到的是移动端聊天内容被塞进 1280×800 的笔记本画板、图层面板文字被切、
气泡全部左对齐。**所有既有的门看的都是「代码对不对」，没有一道看「它长得像不像个东西」。**

## 两个分数，分开卡，机器分不许被模型分抵消

| | 判什么 | 谁判 | 卡在哪 |
|---|---|---|---|
| **机器硬判** | 能量化的：占比 / 密度 / 裁切 / 字号档数 / 对齐轴 | `scripts/prototype-audit.mjs` | **≥ 80，不可协商** |
| **模型软判** | 主观的：看起来专不专业、像不像这类产品 | 视觉模型看截图 | ≥ 80，扣分项要写具体 |

⚠ **不合成一个总分。** 让模型给自己的产出打分、再用它盖掉机器分，就是把本仓「测试为了
错误的理由通过」那个坑重挖一遍。两个分数分开报，任一 < 80 都不许说做完。

## 机器硬判五条

| 指标 | 判什么 | 阈值 | 对应人类点名的毛病 |
|---|---|---|---|
| `fill` | 内容外接盒 ÷ 画板面积 | ≥ 0.6 满分，< 0.35 重伤 | 内容缩在角落 |
| `density` | **叶子**元素面积和 ÷ 画板面积 | ≥ 0.25 满分，< 0.12 重伤 | 「画板太大，中间一片空」 |
| `clipping` | 溢出**且没有省略号** | 一处都不许有 | 图层面板文字被切 |
| `typeScale` | 字号档数 | 3–6 档 | 「标题正文一样大，没有层次」 |
| `alignment` | 左边缘对齐轴数 ÷ 元素数 | ≤ 0.35 满分 | 「看起来乱」 |

权重写死在 `lib/prototype-audit-metrics.mjs` 的 `WEIGHTS`，是唯一事实源。

### 三条来之不易的判据，别改回去

1. **`density` 不能用 `fill` 代替。** `fill` 量外接盒——导航贴顶、输入框贴底时外接盒是满的，
   `fill` 给 90 分放行，而中间大片是空的。外接盒答的是「内容摊到哪」，答不了
   「这块画板上到底有多少东西」。这条是首跑对着截图核对时才发现的。
2. **`clipping` 必须排除 `text-overflow: ellipsis`。** 省略号是**告知**不是缺陷。首跑没排除，
   门红在两条正常截断的图层名上——一道会误报的门，迟早被调松或被无视。
3. **量程要覆盖用户看到的那一屏。** 只量「画板内部」时，画布缩到 18%、画板挤在正中、
   四周一大片空，五条指标全绿。门看不见用户看得见的东西，就是装饰。

## 空集防线

量不到画板、量不到节点、一个场景都没审到 —— **一律判 0 / 退非零**，绝不因为
「没发现问题」而判绿。本仓九次「全绿但空转」。

## 怎么跑

```bash
pnpm --filter web dev            # 另开一个终端
BASE=http://localhost:3187 OUT=/tmp/audit node apps/web/scripts/prototype-audit.mjs
```

截图与 `audit.json` 落在 `OUT`。模型软判：把 `OUT` 里的 PNG 交给视觉模型，按上表主观项
打 0–100 并列扣分项，结论连同机器分一起写进交付说明。
