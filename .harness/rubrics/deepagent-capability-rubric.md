## 对标对象（「行业顶级」的定义，可证伪）

以下产品 2026-08 的公开能力为 10 分锚点，逐维度取最强者：
- **Claude Code**（多步执行、工具透明、planning、subagent）

## 十个维度（每维 0-1 分，总分向下取整到 0.5）

打分纪律沿用 `chat-ux-acceptance-criteria.md`：真实运行取证，不看代码 diff 打分；
mock/占位最多 0.3；每次评分记录「实测 SHA + 复现命令 + 证据路径」。

### D1 规划可见性（planning）
- **1.0**：多步任务先产生结构化 todo（工具调用产生，非文本装饰），执行中逐项更新状态，前端可实时看到。
- **0.5**：有计划文本但非结构化状态，或有 todos 但不更新。
- **0**：直接开跑，无计划痕迹。
- 10 分锚点：deepagents `TodoListMiddleware` + AG-UI 状态流。

### D2 工具调用透明度
- **1.0**：每次工具调用的名称/参数摘要/状态/结果作为**独立事件**流出，前端逐个渲染（非终态一次性）。
- **0.5**：事后可见完整调用记录，但过程中不可见。
- **0**：黑盒。

### D3 真流式（token 级）
- **1.0**：模型 token 逐步流出（`TEXT_MESSAGE_CONTENT` 逐 delta），事件时间戳证明是逐步的。
- **0.3**：协议是 SSE 但内容为终态一次性打包（**当前 agui-bridge 的形状**）。
- **0**：纯轮询。

### D4 多轮持久上下文
- **1.0**：checkpointer 持久化（Postgres），跨会话/重启恢复线程状态，追问无需重复背景。
- **0.5**：进程内记忆（MemorySaver / 平台内存态），重启即失。
- **0**：每轮独立。

### D5 子代理委托（subagent）
- **1.0**：主 agent 能把子任务派给隔离上下文的 subagent，前端能看到委托发生与归并。
- **0.5**：有 `task` 工具但前端不可见，或仅单层。
- **0**：无委托能力。

### D6 人在环（HITL）
- **1.0**：敏感/破坏性工具调用前可暂停待人批准（`interrupt_on`），批准/拒绝/修改参数三种响应都通。
- **0.5**：只能全停或全放。
- **0**：无中断机制。

### D7 错误恢复与透明度
- **1.0**：工具失败/模型失败逐条以错误事件流出并渲染；agent 能对失败重试或改道，而不是编造成功。
- **0.5**：失败可见但 agent 不恢复。
- **0**：静默失败或编造。

### D8 上下文工程（context engineering）
- **1.0**：长对话自动摘要（SummarizationMiddleware 或等价）、大结果卸载到文件系统、静态段有 prompt cache。
- **0.5**：只有截断。
- **0**：无管理，长对话即溢出。

### D9 状态同步（agent state ↔ UI）
- **1.0**：agent 状态（todos/files/自定义字段）以状态 delta 实时同步到前端（AG-UI STATE_SNAPSHOT/DELTA），UI 可双向注入上下文（useCopilotReadable 等价）。
- **0.5**：单向、终态同步。
- **0**：无状态通道，只有消息文本。

### D10 架构融合健康度
- **1.0**：跑在 deepagents **当前 minor** 上（照 uv.lock 实锁），middleware 按官方口径配置；
  **无平行自研 loop**（或平行者有签核的存在理由）；依赖地板与 lock 一致；升级路径有 CI 门。
- **0.5**：版本新但用法停在旧 API（**当前形状：锁 0.7.6、用 0.0.5 的裸调用**）。
- **0**：版本漂移无人知。

## 评分流程（每个 backlog 条目完成后强制执行）

1. 实现者**不自评**。评分由独立会话按本文件逐维实测（沿用 rev-uiux 的隔离模式）。
2. 每次评分产出一行记录追加到本文件末尾的「评分史」：日期、SHA、十维分、总分、证据目录。
3. 分数只降不升的维度必须开 issue 说明回归原因。
4. 「10 分」必须由人类最终确认（同 chat-ux 的纪律：不能自评满分后直接发布）。
