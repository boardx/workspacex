# UIUX 截屏评估 rubric —— 个人资料菜单 + 组织管理菜单系列迭代

> 由 coord-agent-auth 按 `.harness/instructions/uiux-standards.md` 起草，2026-08-07。
> 适用范围：本轮"用户 profile"（左下角入口）+ "组织管理"（左上角入口）系列功能的
> 每一次迭代。**10/10 才能发 devapp**，9 分及以下打回重做，不打折扣、不"下次一起改"。

## 怎么用

每次功能迭代（新增/修改一个菜单入口或其下的一个子功能）完成后：
1. 起本地预览（`preview_start` / dev server），走到目标界面。
2. 对目标界面截图（含至少一次 hover/focus 态、一次 loading 态、一次 error/empty 态，
   如果该迭代范围内存在这些状态）。
3. 逐条对照下表打分，每条 0 或 1 分，不给 0.5——如果拿不准某条算不算过，按不过算，
   写清楚为什么拿不准，不要含糊过关。
4. 10 分 → 可以发 devapp。9 分及以下 → 列出扣分项 + 具体截图证据，打回本轮迭代重做，
   不进入下一个功能。

## 入口位置（本系列的硬性锚点，不是设计细节，扣分不商量）

- **个人资料入口固定在左下角**（侧栏底部，通常和登出/设置放一起的那个位置）。
- **组织管理入口固定在左上角**（侧栏顶部，通常和组织切换器/组织名同一区域）。
- 如果某次迭代把入口挪到了别的地方，这条直接判 0，其余 9 条分数作废不用打——
  位置错了，后面的视觉细节评了也没意义。

## 10 条评分项（每条 1 分）

| # | 条目 | 判断依据 |
|---|------|----------|
| 1 | **入口位置正确** | 个人资料在左下角、组织管理在左上角（见上）；且和现有侧栏其它入口的视觉权重一致，不突兀 |
| 2 | **Loading 态存在** | 数据加载期间有 `data-testid="loading"` 的骨架屏，不是空白（U1） |
| 3 | **Empty 态存在** | 列表/内容为空时有引导文案或图示 `data-testid="empty"`（U2），本迭代若无列表型内容则此项按"不适用即满分"处理，需在评估记录里写明理由 |
| 4 | **Error 态存在** | 请求失败/校验错误有 `role="alert"` + `data-testid="err-*"` 结构化展示，不静默失败（U3） |
| 5 | **成功反馈存在** | 每个有副作用的操作（保存/删除/创建）完成后有可见反馈（`data-testid="saved"` 一类），不是"点了但看不出发生了什么" |
| 6 | **微交互完整** | 所有可点击元素有 `hover:` + `transition-*`；输入框有 `focus-visible:ring-2`（U4） |
| 7 | **无硬编码颜色/像素** | 截图里目测配色符合语义 token 风格（不是纯黑/纯红等原生色），且 `lint-design.sh` 本地跑过（U5） |
| 8 | **无原生表单元素** | 表单控件是 shadcn/ui 组件外观，不是浏览器默认样式的 `<input>`/`<select>`/`<button>`（U6） |
| 9 | **无障碍基础** | 头像类图片有替代文案迹象（不强制看得出 alt，但截图里不能是"图裂了"占位）；表单字段有可见 label，不是纯 placeholder 充当 label（U7） |
| 10 | **响应式不溢出** | 375px（手机宽）截一张、1280px（桌面宽）截一张，两张都不出现横向滚动条或内容被裁切（U8 的抽样验证） |

```
|---|------|------|-----------|

| 2 | Loading | 1 | ... |
...

结论：<10/10 可发 devapp / 9 分及以下打回，扣分项：...>
```
