# Full-stack smoke environment

Issue #4842 keeps the existing full-stack and trace-geometry commands and 20-minute job budget. The lane runs in the official Playwright Noble environment instead of downloading OS browser dependencies through APT on every runner.

The installed `apps/web` Playwright version after frozen installation is authoritative. `.harness/playwright-runtime-images.json` binds that version to a reviewed official Linux/amd64 manifest digest. This is digest metadata, not a second package version selection. Unsupported versions fail before running tests; a Playwright upgrade requires checking the new official manifest and updating this binding. The runtime never pulls a floating tag. The current digest was read from the official registry's OCI manifest index for `v1.62.0-noble`.

The host starts the container with the runner's UID/GID and only the Docker socket's additional group. Node, pnpm, Docker CLI, Compose and unzip paths are discovered on the actual runner, then mounted read-only. The repository remains at the same absolute path. A private runner temporary HOME avoids mounting credentials. Only the listed CI identity variables enter the container; GitHub tokens do not. Host networking is required because the existing isolated PostgreSQL, Redis and MinIO services publish to host loopback addresses.

The workflow passes the original canonical command explicitly to the wrapper; exact argument verification preserves the existing coverage scanner without allowing partial test selection. Before the existing command executes, the container checks Docker/Compose, verifies unzip dynamic dependencies with ldd and executes unzip and launches the exact browser through the installed web package. APT executables are replaced by an exit-78 guard, and the browser probe verifies that guard really returns 78. Browser startup therefore cannot silently fall back to installing missing dependencies. Native microphone/ASR paths and all discovered tests remain unchanged. Existing test-isolation cleanup still runs inside the container; Docker signal forwarding and `--rm` preserve cancellation behavior. No infrastructure services are reused across attempts.

The independent geometry step uses the same sealed runtime and keeps its own evidence. Reuse checks and final success/failure handling remain unchanged. A failed runtime setup is a failed verification, not a passing cached verdict.

Measured incident: job `110092566229` spent 7m31 installing browser dependencies, including 7m08 fetching 34.9MB of OS packages. Browser downloads themselves took about seven seconds. The existing command ran 11m51 before cancellation at 123/133 started tests. Caching only browser archives would not fix this incident. The new container's cold pull and complete GitHub run must be measured; no speed SLA is claimed from static tests or a successful manifest lookup.

Validation: `.harness/scripts/ci-fullstack-runtime.test.ts` covers exact digest/version policy, UID/group and host topology, secret exclusion, APT blocking and unchanged workflow budget/commands. The GitHub smoke lane supplies the actual Linux Docker/browser/application proof. Local manifest access is evidence of image identity only, not a browser or full-stack pass.
