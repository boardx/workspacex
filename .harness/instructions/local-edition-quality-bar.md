# 本地版体验评分卡（单一事实源）

> 「本地版做到几分」只有这一份尺子。任何地方要引用分数，引用这里，不要另写一份。
> 依据：2026-09-23 的竞品与最佳实践调研（Obsidian / Logseq / Bear / Apple Notes /
> LM Studio / Ollama / Jan / GPT4All / AnythingLLM 的真实用户抱怨与官方文档）。

## 打分规则

每维 0–10。**9 分 = 有可复现的实测证据，且最坏路径也成立**（低配机器 / 冷启动 /
断电 / 本地服务起不来）。**7 分 = 正常路径好，最坏路径掉链子。**
总分取加权均值；**任一维 ≤5，整体不得高于 6**。

⚠ 三条硬纪律，违反则该维不得高于 7：
1. 所有时间指标一律在**冷路径 + 真实上下文长度**下测，热机数据不作数。
2. 每条判据都要配一个**反证**——停止键测 tok/s 是否归零、崩溃恢复测行数、
   内存预算靠回归门。否则会复现本仓「全绿但空转」的老毛病。
3. 不要盲目把首 token 压到 1 秒以下：现有唯一的实验证据方向相反
   （TTFT 2 秒组比 9 秒组**更觉得答案肤浅**，<https://arxiv.org/abs/2604.06183>）。

## 尺子（先固定，再打分）

| 锚点 | 数值 | 出处 |
|---|---|---|
| 直感 / 思维不断 / 注意力上限 | 0.1s / 1.0s / 10s | <https://www.nngroup.com/articles/response-times-3-important-limits/> |
| 冷启动「过长」判据 | ≥5s（温启 ≥2s） | <https://developer.android.com/topic/performance/vitals/launch-time> |
| 进度条该出现的阈值 | 2s 起、5s 必须 | <https://learn.microsoft.com/en-us/windows/win32/uxguide/progress-bars> |
| 人类阅读速度 | ≈238 wpm ≈ **5–7 tok/s 就跟得上眼睛** | <https://www.sciencedirect.com/science/article/abs/pii/S0749596X19300786> |
| Ollama 默认空闲卸载 | 5 分钟，回来第一句卡 3–11s | <https://blog.nashcom.de/nashcomblog.nsf/dx/ollama-keep-models-loaded-for-longer-than-5-minutes-idle.htm> |

## 八个维度

| # | 维度 | 权重 | 9 分 | 7 分 |
|---|---|---|---|---|
| 1 | 冷启动与首屏可交互 | 15% | 冷启 ≤3s 出**可交互**首屏，温启 ≤1s，重资源懒加载，有回归门钉住 | 冷启 3–6s，首屏可见但按钮还是灰的，没有回归门 |
| 2 | 首次运行与重资源就绪 | 15% | 全程确定性百分比 + 剩余时间，**零网络可完成**，可续传、有校验和、失败给出路 | 有进度条但是转圈，文案是「正在初始化…」，失败要重装 |
| 3 | 离线处境与能力边界可见 | 12% | 离线是**常态不是错误态**，不可用能力在**入口处**说明原因与替代 | 有个离线角标，但不可用功能仍可点，点了才报错 |
| 4 | 生成体验（首 token / 流式 / 可中断） | 15% | 冷路径首 token ≤3s 且期间有「正在加载模型 x%」；稳定 ≥7 tok/s；停止键**真的停掉采样**（tok/s 归零取证）；生成中可滚动可复制 | 热路径流畅，冷路径静默；停止键只断前端流；自动滚动劫持 |
| 5 | 数据安全 / 备份 / 迁移 / 崩溃恢复 | 15% | UI 里一键「显示数据位置 / 导出 / 导入」，导出是结构化机器可读格式，**备份自己被校验过**，`kill -9` 后能恢复并告知损失边界 | 能导出但**从没测过崩溃恢复**，换机靠手工 cp |
| 6 | 失败说人话 | 12% | 每个本地服务起不来都有具名诊断 + 一键自愈 + 日志一键导出；文案三段：发生了什么／对你的影响／你现在能做什么 | 有提示但含 EOF / ECONNREFUSED / exit code 1，只能重启应用 |
| 7 | 资源占用与长时稳定 | 8% | 自设并**门控**预算（空闲内存、生成峰值、磁盘、CPU）；低配机自动降配并**明说降了什么** | 数字尚可但无预算无门控，低配靠运气 |
| 8 | 更新、回滚与可访问性 | 8% | 支持**离线更新**，增量 + 灰度，回滚靠版本号前进，更新不打断生成，全键盘可达 | 有自动更新但强制联网，回滚要用户自己下老版本 |

## 十大缺陷（按用户感知严重度降序）

1. **数据丢了或打不开了**——异常退出后库损坏，且没有可用备份。
2. **停止键按了不停**——模型继续烧 CPU，用户以为死机。
3. **永远在「正在思考」**——后端已失败而前端无超时无错误。
4. **低配机器上被系统杀掉**——生成到一半整个应用消失，没有预警。
5. **号称离线却要联网**——首次运行必须下模型。
6. **冷启动后第一句卡 10 秒且全程静默**。
7. **不可用功能仍可点**——点了才弹错，且不说为什么。
8. **不知道数据在哪、也导不出来**——换机等于从头再来。
9. **更新把人卡住**——强制在线、全量重下、或无法回退。
10. **生成时界面半瘫**——不能滚动、不能复制、自动滚动抢视线。

## 从竞品里学到的三条，值得逐字记住

1. **「文件在磁盘上」是每次写入都要守的运行时不变量，不是一个架构决定。**
   Logseq 架构上有纯 markdown 文件，仍然因为文件写入是内存库的滞后投影，
   让用户丢了一个月的日记（至少 5 人复现，跨 9 个月）。
   <https://discuss.logseq.com/t/edits-in-logseq-not-being-written-to-local-files-unrecoverable-data-loss/23031>
2. **内存预估要保守、可覆盖、并且解释自己的算术。** LM Studio 的内存护栏同时是
   它最被称赞的功能和最大的抱怨来源——因为它只拦截、不解释。
3. **静默降级是这一类应用里最高杠杆的未解问题。** Ollama 装不下就静默回落 CPU，
   没有任何界面告诉用户「你现在慢了 20 倍，原因是这个」。
   <https://github.com/ollama/ollama/issues/14258>

## 一条与本仓直接相关的事实

**全行业没有一家把模型塞进主安装包**（Ollama / LM Studio / Jan / GPT4All /
AnythingLLM 都不塞），因为 macOS 对大体积载荷公证要 3.5–4.5 小时，Apple 自己建议
把大资源与被公证载荷分离。<https://developer.apple.com/forums/thread/813586>
本仓当前的 DMG 是 **13 GB、模型在里面**。9 分的正解是**签名的独立模型包 + 离线可安装**，
既不是塞进主包，也不是首启拉网。
