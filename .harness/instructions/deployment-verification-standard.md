# 部署验证标准 —— 验证层级不许比用户低一层

> 2026-09-06 一天之内，同一个用户可见缺陷（「生成中文 PDF」拿不到可用文件）被**四层**
> 各自"全绿"的验证一路放行。这份文档把那天的教训固化成可执行的规则。
> 适用对象：任何改动要经过「构建 → 部署 → 运行 → 产物」这条链的人与 agent。

## 一、核心规则：每一层都要问**运行体**，不能问痕迹

```
代码在 main 上   ≠  镜像是这份代码构建的
镜像是新的       ≠  跑着的容器是这个镜像
容器是新的       ≠  容器里的配置指向真实存在的东西
产物生成成功     ≠  产物打开是可用的
```

那天的四道缺口，逐条对应上面四个 `≠`：

| # | 现象 | 骗人的痕迹 | 该问的动态事实 |
|---|---|---|---|
| 1 | 镜像自 8/21 冻结 | `git log` 说改动在 main 上 | `docker compose up -d --build`，且部署后问容器要版本/依赖 |
| 2 | 部署脚本副本落后 | CI 全绿 + deploy job success | 把 `/usr/local/bin` 那份与仓库逐字节比对，不一致红退 |
| 3 | 容器配置指向已删除的字体 | 构建日志写着 `CJK font OK` | `docker exec` 进去 `statSync` 那个路径 |
| 4 | 产出的 PDF 打开全是方框 | 门控断言「字形编号 ≠ 0」全绿 | 把内嵌字体掏出来重新解析，字形要有轮廓 |

⚠ 第 4 条最值得记：判据本身是"真断言"（它确实解析了 PDF、确实检查了字形编号），
但它**测的东西比用户看到的低一层**。子集化会把字形重编号成 1,2,3…，编号非零恒真。
**一条测不到用户体验的判据，比没有判据更危险**——它把"没人验过"伪装成"验过了"。

## 二、冒烟必须落在**用户可见产物**上

健康检查（healthz 200、进程 active、socket 存在）证明的是"服务起来了"，
**不证明用户能拿到能用的东西**。每条用户可见能力至少要有一条冒烟，形状是：

1. 走真实链路产出**真实产物**（不是 mock、不是 fixture）；
2. 用**独立于生成路径**的方式验它可用（生成用 A 库，校验用 B 视角）；
3. 判据落在"用户会怎么用它"上（PDF 要能读出字形轮廓，不是文件大小 > 0）。

参考实现：
- `.github/workflows/devapp-sandbox-cjk-pdf-probe.yml` —— 向**线上正在跑的**沙箱要一份
  中文 PDF，就地验内嵌字体可用，PDF 作为 artifact 传回。不需要任何凭据。
- `apps/skill-sandbox/tests/produces-real-cjk-pdf.test.ts` —— 同一条判据的镜像侧版本。

## 三、每条门控配一条**反证**，且反证要能真的红

本仓已九次「全绿但空转」。写完门控立刻做一次：**把被测的东西弄坏，看它是不是真的红**。

那天新增的门控都带反证，形状可以照抄：

| 门控 | 反证 |
|---|---|
| 内嵌字体可用 | 同一段脚本加 `subset: true` → 必须红 |
| 部署带 `--build` | 去掉 `--build` → 断言必须落空 |
| 特权副本与仓库一致 | 把副本改回旧版 → 必须红退并给出修复命令 |
| deploy.env 补齐 | 已有值不许被改写（这条反证比正向断言更重要） |
| 续行中不许插注释 | 人为插一条 → 规则必须抓到 |

## 四、配置：一个事实一处声明，缺失要点名

- **单一事实源**：同一个路径/端口/密钥名不许声明两次。那天 `SKILL_SANDBOX_CJK_FONT`
  写在 Dockerfile + 两份 compose，换字体只改了一处 → 容器指着一个不存在的文件。
  修法**不是**"记得一起改"，是删掉副本 + 加机械门控。
- **必需键点名**：`set -u` 下直接用一个缺失的环境变量，报的是
  `XXX: unbound variable`，一句不说明怎么修的话。用之前先逐个点名，报错里给出
  可照抄的命令（见 `deploy.sh` 的 `for required_key in ...`）。
- **存量文件要能补齐**：只在"文件不存在"时生成配置的脚本，等于新增的必需键永远
  补不进老机器。provision 侧要逐键补齐（只补缺的，**绝不覆盖已有值**）。

## 五、密钥不进 argv、不进日志

那天有一次真实泄露：命令续行里插了注释，shell 把命令截断，`env` 退化成"打印当前环境"，
把 `SUDO_COMMAND=...`（含 deploy.env 全部密钥）打进了 CI 日志。

规则：
- 传密钥一律用 `--env-file` / `EnvironmentFile=`，**不用** `env K=V cmd` 这种形态
  （它让密钥出现在 `ps`、`SUDO_COMMAND`、审计日志里）；
- 部署脚本的诊断输出必须脱敏，且不许无差别 dump 环境；
- 一旦泄露：删除对应 run 的日志 + 轮换。⚠ `MODEL_CREDENTIAL_KEY` 轮换会让已入库的
  加密凭据解不开，必须连带重录，不能顺手换。
