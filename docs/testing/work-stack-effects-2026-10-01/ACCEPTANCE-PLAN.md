# Work Stack 完整验收计划

日期：2026-10-01（北京时间）。交付：统一后续 PR #4892（#4867 已合并）。此文件是验收计划，不是通过报告。

## 1. 目标与范围

目标：真实用户从可见入口发现数字人，理解职责，配置/启用依赖，完成任务与必要审批，得到可打开、可追溯、刷新后仍存在的产出；后台能够正确配置、控制权限、诊断失败。本轮 D002/D003/D011 必须各自有独立完整旅程及真实模型结果，不能用一张目录截图或一条共用聊天证明全部可用。

历史第一阶段基准：D002 研究与知识分析师、D003 产品经理、D005 销售代表、D011 设计思维专家，共 4 个数字人、19 个 Workflow、58 个 Skill。用户最新明确销售流程/CRM先跳过：本轮完整端到端范围为 D002/D003/D011；仅 D005 的完整销售/CRM任务及 W011/W012/W013/W014/W015/W016/W018 标 DEFERRED，非 PASS。原 81 实体分母保留，当前基础界面/普通聊天范围仍为 4 角色；完整领域任务范围为 3 角色、12 Workflow、58 Skill；不因销售范围暂缓而广泛排除共享 Skill。逐实体范围见 acceptance-entities.csv，逐场景步骤见 acceptance-cases.csv。

权威需求：requirements/work-stack-v2/WORK-STACK-320-LIST.md、DIGITALHUMAN-COMPOSITION-MATRIX.md、WORKFLOW-SKILL-MATRIX.md 及各实体规格。320 清单的勾选是作者化/评审结论，不能作为运行验收证据。清单为自动生成，不手改。已运行基线官方包 1.5.0 有 7 个角色；本轮修复目标为不可变新包 1.6.0。D001/D006/D007 纳入发现、启用、兼容回归，并与原四位共同参加第12节背景/身份/技能范围专项；这不替代原四位的核心旅程。

全量 320 个实体另见 acceptance-all-entities.csv，按清单四阶段登记需求评审状态和独立运行状态。其余 239 个实体记录覆盖与实现状态；不把未经作者化或未实现实体记为通过。本轮不承诺数字人能使用尚未装配的流程。

## 2. 验收环境和准入

必须记录：实际环境 URL、被测 Git SHA/部署 SHA、API/Web/沙箱/Deep Agent 版本、官方角色包与依赖包版本、所选模型/provider、浏览器与设备、组织和账号角色、测试数据版本、开始结束时间（北京时间）。以实际运行版本为准，PR 分支名和文件存在不能证明已部署。

| 通道 | 用途 | 可以证明 | 不能证明 |
|---|---|---|---|
| 本地真实全栈＋确定性上游 | 快速协议/权限/持久化/异常反证 | 实际浏览器、HTTP/WS、数据库、流程编排与可见反馈 | 真实模型领域能力、真实外部检索/CRM/语音质量 |
| 本地真实全栈＋真实模型与服务 | 本轮三角色完整任务、附件、工具、专业质量 | 在该版本和配置下的真实任务执行 | 未部署 devapp 的行为 |
| devapp 部署验收 | 用户实际站点回归 | 部署版本的入口、真实服务、交互与持久化 | 未测实体或未测组织 |

准入条件：独立测试组织 A/B；真实表单登录；管理员、普通成员、受限成员、审批者、平台运营账号；真实模型凭据仅通过批准的环境/后台配置装载；检索、原生文档解析、技能沙箱和实时音频配置分别验证；CRM 测试连接本轮 DEFERRED；不得把缺配置悄悄改成 mock。生产写操作只使用隔离测试数据，外发场景使用测试收件目标/沙箱，保留审批。

服务健康包括数据库迁移、认证、运行队列/事件流、存储、工具执行、模型调用。匿名 WebSocket 401 只证明路由和拒绝行为，不能替代登录通话测试。合成接口渲染截图只算 UI 展示证据。

开发负责修复、自动回归与准备可复现环境；测试工程师负责真实浏览器操作、证据及复验；业务用户确认真实产出是否解决任务。开发不能以自己的单元测试替代业务验收。

## 4. 四个数字人的完整旅程

本轮非暂缓旅程都从真实登录与产品导航开始，不只 page.goto 深链。共同步骤：后台打开官方数字人 → 查看待启用和依赖 → 启用 → 查看真实导入结果 → 成员目录/首页选择角色 → 查看职责/能力/授权边界 → 发送任务 → 跟踪执行 → 处理审批 → 打开产出 → 刷新 → 再次打开同一产出。不得预置一条完成对话当本次执行结果。

每位都追加“你好”“你可以做什么”“超出职责请求”“连续两轮澄清”四项，核对身份和能力介绍与实际挂载/可运行状态一致。角色包当前工作流白名单以发布快照及矩阵核对，越界不能绕过授权；合理转交必须可见且确认后发生。

## 5. 前端体验、功能和后台配置检查

acceptance-cases.csv 为105个跨功能场景模板（原89＋新增16个P0），包含步骤和预期；acceptance-execution-matrix.csv 为656个逐实体检查项（原第一阶段544＋七角色专项112）。新增专项不改变原81实体分母。输入/调用/审批/故障绑定还需按每个实体规格生成 fixture，prepared_status 初始 NEEDS_PREPARATION；不能把模板和矩阵当成已有可执行用例或验收结果。准备清单和生成规则见第 11 节。各组覆盖：

- ENV：部署版本、真实模型与检索、文档解析、音频、沙箱、测试数据与账号准入。
- ADM：角色发现/依赖导入/版本/幂等/局部失败恢复；目录与可执行定义一致；推荐区保存；模型、工具、MCP、Skill 与 Workflow 配置；审批、可见性、停用与诊断。
- DISC：四角色目录/详情/选择器可见，D005基础使用仍在本轮；职责、头像、能力、就绪/待配置状态；导航入口、推荐、筛选搜索、打开角色到使用页。
- CHAT：固定角色、记忆隔离、能力介绍、多轮/澄清、附件、工具终态、取消、重试、产出保存与重读。
- SKILL：真实固定版本指令与结构契约、目录点击加载、挂载、工具依赖、坏输出、缺权限、注入、报告漂移。
- FLOW：启动入口、角色白名单、阶段产出、审批/拒绝/修订、取消/恢复、并发/幂等、可打开最终结果、审计。
- ROLE：本轮三条独立的真实模型完整旅程与领域产出检查。
- VOICE：登录握手、麦克风、真实双向语音/字幕、打断、挂断后记录、失败恢复；若作为角色提供的功能显示，不能只验按钮。
- UX：新手理解和完成、真实任务满意度、空/加载/错误状态、桌面与移动、键盘、读屏、对比度/焦点、中文/长文本、等待反馈。
- SEC：组织/账号切换、对象直接引用、检索/附件权限、转交/审批权限、外发授权、凭据不暴露、恶意材料。
- REL：网络中断、模型/工具/解析失败、限流、重复点击、刷新重连、停用/版本更新、服务重启恢复、可诊断终态。

后台所有写操作验证“保存 → 服务端结果 → 重新进入/刷新 → 新建成员任务实际生效”；不能只验 toast。配置变更不应静默重写历史运行的固定版本/权限快照。平台运营、组织管理员和普通成员的能力必须分别验，不因同名“管理员”混用权限。

## 6. 实体级覆盖规则

acceptance-entities.csv 从当前 320 清单第一阶段机械提取，包含 81 项。每个实体每个规则在 acceptance-execution-matrix.csv 有独立行、规格路径、输入准备、执行动作、预期和证据要求。先实例化数据与账号并登记真实调用关系，再运行；结果可部分通过但最终 entity_result 只有满足全部必需项才是 PASS：

- 数字人：D1 发现/启用；D2 角色与能力；D3 权限/边界；D4 独立真实任务；D5 产出可见与刷新持久化；D6 异常恢复。
- Workflow：W1 配置/发布/可发起；W2 正常链各阶段；W3 全部审批点与拒绝/修订；W4 权限/角色/Skill 固定版本；W5 超时/取消/重连/幂等；W6 最终产出/审计。
- Skill：S1 作者化规格与可执行版本；S2 最小有效输入；S3 代表实际输入和专业结果；S4 无效输入/空输出/坏格式；S5 工具依赖/权限/注入；S6 被 Workflow 或角色调用且结果被真实消费；S7 评测套件/报告身份和人工领域判定。

同一 Skill 被多个流程使用，至少独立 Skill 验收一次，并验证每个调用流程传参/固定版本/结果消费。每个实体必须有实际执行时间、环境、版本、run/步骤对应证据。不存在可执行主体、只有 authored 样例或 grader 通过，记 BLOCKED 并建实现任务。

覆盖分母分别报告：4 角色、19 Workflow、58 Skill，不把一次参数化测试运行数加总为实体通过数。不将其他角色/包中的重复 Skill 副本当新增独立能力。计划覆盖率与运行通过率分别统计。

## 7. 可用性与真实质量判据

招募至少 5 位非开发测试用户，分别覆盖管理员和成员。给任务目标，不预先教点击步骤；记录独立完成/需提示/失败、首次找到角色时间、完成时间、误点、回退、疑惑原话、每任务 1–5 易用度评分。建议体验目标（本轮计划目标，不是既有 SLA）：核心任务至少 4/5 用户无需操作提示完成，易用度中位数至少 4/5；任何用户被不可解释状态永久卡住均建缺陷。

输出质量由业务评审检查：角色符合、事实/引用可核实、任务目标覆盖、结论可追溯、可执行性、边界/不确定性、结构完整性。每项记 PASS/FAIL 及具体段落证据；捏造来源/客户信息、无依据承诺、关键需求遗漏不能靠平均分抵消。对同一核心输入至少独立运行 3 次，另外覆盖明确缺信息和冲突输入；记录模型与版本，不挑选最好的一次截图作为结论。

桌面 Chrome/Edge 最新稳定版与 Safari；1440/1280 桌面及 390/768 移动/平板视口；语音按实际支持浏览器单列，不把不支持当支持。键盘可达、焦点可见/返回正确、弹窗焦点约束、输入标签、读屏状态、WCAG AA 对比度、200% 缩放、长中文不溢出。灰/禁用按钮必须有可理解原因，不暴露技术术语给用户做无意义决策。

性能记录首屏、目录加载、提交到首次可见状态、模型首响应、每阶段耗时与总耗时，比较同环境基线；禁止编造现有 SLA。建议交互反馈在 1 秒内出现，网络/模型等待期间应有真实状态和取消/恢复路径；超时按实现的超时策略检查，不能无限等待。若产品未定义耗时上限，报告基线与建议目标，不能标 SLA 已通过。

## 8. 必交证据与报告

本轮每个非暂缓角色最少 8 张按顺序截图：01 四角色目录同屏（D005基础使用仍在本轮）；02 当前角色详情/能力；03 后台真实启用结果和配置；04 选择角色后的输入；05 实际执行阶段/工具/Skill；06 审批及决定；07 可打开的真实最终产出；08 刷新后的同一产出。角色没有审批时记录“无审批点”并以实际执行结果替代，不制造审批截图。另录制一段从登录/入口到刷新重读的连续视频或 trace。四角色共用目录截图可以复用，但使用和产出证据必须逐角色独立。

证据目录建议：acceptance/<实际SHA>/<环境>/<case-id>/<role-id>/。保存全页及关键细节截图、Playwright trace、脱敏 HTTP/WS 时间线、工具终态、导入与发布版本、产出内容/可打开链接和刷新读回证据。所有“成功”要能把用户输入 → run → 阶段/工具 → 审批 → artifact 对上。截图不得伪造输出或事先注入已完成任务；模拟故障截图必须说明故障注入方式。

结果状态统一为 NOT_RUN / RUNNING / PASS / FAIL / BLOCKED / DEFERRED / NOT_APPLICABLE。NOT_APPLICABLE 必须说明规格依据；四角色核心旅程不能因未实现标 NOT_APPLICABLE。只有 PASS 才勾选；DEFERRED 表示用户明确暂缓，不是通过或规格不适用；BLOCKED、FAIL、DEFERRED、执行完成但待业务判定都不勾选。

每份报告包含：case_id、entity_ids、优先级、环境/SHA/配置版本、账号角色、输入与操作、预期、实际、状态、证据路径、缺陷与严重度、重现率、执行者、复验版本、未验证边界。不得发布密钥/token/私有用户线程/原始客户附件，使用隔离测试素材并脱敏网络与日志。

缺陷闭环：原步骤复现 → 证据与根因 → 同一统一 PR 修复 → 自动反证/回归 → 原场景浏览器复验 → 受影响场景与真实模型回归 → 更新状态和证据。旧版本截图不自动证明新版本通过。
