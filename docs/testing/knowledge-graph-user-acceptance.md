# 知识图谱：用户验收标准与端到端测试计划

制定日期：2026-10-01（Asia/Shanghai）。本计划对应当前仓库版本，测试结果另存于 `evidence/kg-user-acceptance/2026-10-01/`。

## 验收目标

用户无需理解知识图谱、向量或本体，即可让助手记住工作信息，在后续对话中得到正确、有出处的帮助；用户可以纠正、忘掉、控制分享范围。团队成员能使用获授权的项目与组织知识，不能获取他人的私人记忆。

验收单位是完整用户旅程：登录 → 从真实导航进入 → 输入或操作 → 真实 API → PostgreSQL/AGE/pgvector 与后台 worker → 浏览器显示结果 → 刷新或新会话再次验证。单元、组件、API 集成测试只能辅助定位，不能代替端到端结论。

所有被测记忆必须由浏览器输入形成，禁止预置 claims、向量或图节点。账号、组织、成员关系和模型配置可以作为前置条件。测试专用数据库必须隔离；故障注入只能发生在本轮独占实例。

用户补充范围：组织大脑的 **chat session、个人（跨 sessions）、项目** 三个层级，在 **云端组织、local 组织** 两种模式下分别验收。需把记录、召回、分享、项目证据、决策比较、人工确认和后续行动串起来；详细旅程与 D01–D10 标准见 [三级决策体验设计](organization-brain-decision-experience.md)。local 组织是产品组织类型，不等于本轮另部署一套桌面应用；本轮不宣称原生桌面或离线模型已经验收。

## 判定规则

- **通过**：本轮从用户入口到结果完整走通，断言通过且有截图、trace 或可核查的测量证据。
- **失败**：环境可用，用户旅程出现不符合验收标准的行为；记录具体触发、实际结果和用户影响。
- **阻塞**：环境或模型前置缺失，旅程未执行；不能计为产品失败，也不能计为通过。
- **未覆盖**：尚无对应旅程或本轮未运行。历史分数不替代当前版本验证。
- 不以总分抵消单项失败。隐私泄漏、纠正/遗忘失效、来源错误是发布阻断项；其他必要旅程也须逐项通过。图相对向量的提升是独立能力目标。
- 回环模型车道可证明系统链路，不能证明自然语言抽取和真实回答质量；真实模型车道独立报告。缺少真实模型车道时总体结论至多为“系统链路已验收，模型质量未验收”。

## 用户旅程与硬验收标准

| ID | 用户目标与完整旅程 | 验收标准 | 当前测试入口 | 优先级 |
|---|---|---|---|---|
| A01 | 新用户登录，聊三轮工作信息，开新对话提问 | 无记忆设置或确认点击；信息正确跨会话出现，标明来自历史对话 | E1.c1–c3 | P1 |
| A02 | 回忆人名、决策、数字、日期、原因 | 固定 20 题正确率 ≥90%；每道正确回答均有支持答案的引用 | E2（20题） | P1 |
| A03 | 问“谁决定、为什么、被什么取代” | 人、原因、沿革准确；改口后不再使用旧决定 | E3.c1–c3 | P1 |
| A04 | 用关系图解决向量检索难以回答的问题 | 相同语料、问题、候选范围，hybrid 相对 vector-only 答对率提高 ≥20 个百分点；报告样本量及基线 | E3.c4；真实语义嵌入另跑 | P1 |
| A05 | 点回答引用核查信息 | 每条引用可打开；看到正确的非空原话、来源会话和高亮；不以“存在一条引用”代替证据正确性 | E4.c1–c3 | P0 |
| A06 | 用户在列表纠正错误，继续询问 | ≤2次点击加输入；面板显示新值；后续回答与引用不再出现旧值 | E5.c1–c2 | P0 |
| A07 | 用户说“忘掉”，确认后再次询问 | 明确确认与后果说明；下一轮、刷新、新会话和重新登录后均不再召回旧内容 | E5.c3；U04/U05 | P0 |
| A08 | 已确认知识与新说法冲突 | 当轮可见提醒；选择新说法或保留两条有明确效果；忽略后不重复提醒 | E7.c1–c2 | P1 |
| A09 | 用户正常聊天，不被记忆提示打扰 | 每轮主动提示≤1；状态不遮正文；操作过程有可理解文案且不只靠颜色 | E6、E8 | P1 |
| A10 | 同组织的另一账号尝试读取私人记忆 | 内容、来源、图、回答均不泄漏；不可见与不存在的响应不可区分 | E9；U07 | P0 |
| A11 | 用户从产品导航管理已有记忆 | 点击个人菜单可进入大脑；能找到对话记忆并回到来源；无需知道 URL | U01 | P1 |
| A12 | 用户在列表、关系图之间切换并刷新 | 两种视图可操作，正确显示由用户输入形成的记忆；刷新不丢内容与范围说明 | E9.c1；U02 | P1 |
| A13 | 用户只问一个明确问题 | 答案与记忆引用不夹带无关项目事实；本轮相关引用 precision≥80%，正确答案仍存在 | U03；真实模型另跑 | P1 |
| A14 | 用户纠正后换一个新对话提问 | 新值被召回，旧值及其引用均不复活，不依赖原会话上下文 | U04 | P0 |
| A15 | 用户忘掉后换浏览器登录、再开新对话 | 被忘内容不出现在答案、引用或长期记忆中；原始对话历史是否保留单独说明 | U05 | P0 |
| A16 | 用户要查看已开放的项目与组织记忆 | 从“大脑→项目与组织”可继续点击访问真实内容或相关项目入口；文字说明不能代替操作入口 | U06 | P1 |
| A17 | 用户分享私人记忆给项目、同事使用、再撤回 | 分享前明确可见范围；项目成员新对话可引用；非成员不可见；撤回后成员新对话不再引用副本；私人原件仍可用 | 补充团队车道，账号/项目关系先建立 | P0 |
| A18 | 管理员晋升项目知识到组织，新成员使用 | 从真实 UI 操作，组织成员可找到并引用；不同组织看不到；不以 API 晋升成功代替用户可用 | 补充组织车道 | P1 |
| A19 | 用户在图或向量故障时继续聊天 | 对话仍结束且无系统报错；故障有一条明确的不完整说明；恢复后正常召回 | E10.c2（真图函数故障）；向量故障待补 | P1 |
| A20 | 用户等待回答 | 记忆相对空记忆首字中位数增量≤100ms；交替各5次；同时报告原始样本，真实模型另量 | E10.c1 | P1 |
| A21 | 手机用户打开记忆与来源 | 390×844下主要控件可点击、来源可关闭，正文和必需操作无横向溢出 | U08 | P1 |
| A22 | 用户上传附件并在新会话追问/删除来源 | 附件形成记忆且能回到正确证据；删除来源后派生知识按声明失效；不同账号不可读 | 补充附件车道（对象存储前置） | P0 |
| A23 | 真实用户用自然语言表达同义、否定和改口 | 未见过的表达能抽取，问题/猜测不误当事实，答案正确且不胡编；同义问题正确率≥90%，证据支持率100% | 真实模型车道（本地配置） | P0 |

以上新增用户目标是本轮提出的验收要求；尚未签核或尚未支持的目标标为产品能力 gap，不冒充已承诺功能回归。

## 执行计划

1. **环境检查**：记录 SHA、工作区变更、Node/pnpm版本；检查 `.env.local`、`.harness/config/local.env` 和已导出模型变量，只记录变量名与是否存在，不记录密钥。恢复仓库基础验证。
2. **隔离栈**：独占 PostgreSQL 16、pgvector、AGE、Redis、API、模型提供方与生产构建 Web；端口只绑定 loopback；记录镜像版本、扩展版本和配置是否真实模型。
3. **既有端到端车道**：原样运行冻结 E1–E10 共46条检查，保留本轮观察、截图、原始报告与退出码。使用新 `KG_EVAL_RUN_ID`，禁止复用历史观察。不改锁定语料、断言、打分或阈值来变绿。
4. **用户补充车道**：运行 U01–U08，从真实导航覆盖可发现性、图/list持久化、引用精准性、跨会话纠正、重新登录后的遗忘、共享层入口、隐私与窄屏；M 车道分别验证云端与 local 的 AGE/pgvector、组织隔离、刷新和真数据库故障/恢复；L 车道把会话决定→个人大脑→新会话→分享预览→项目大脑→项目新会话→撤回串成完整流程，默认通用项目与工作坊项目分别报告。新用例独立于冻结评测。
5. **团队/组织/附件车道**：只有确实从前台走通才通过；若当前无法通过前台完成，记录缺失入口与用户影响，不能用手工写 claims 或直调写 API 绕过。
6. **真实模型车道**：复用本地已有 provider/嵌入配置。配置缺失则标阻塞；不偷偷使用回环替代。真实模型执行原用户语料外的同义、否定、纠正、忘掉和两账号旅程。
7. **失败复现**：把断言失败、测试脚本过期、环境失败分开；保存浏览器可见事实，定位仅用于解释，静态推断标“待端到端确认”。独立重跑只在新失败/不确定性需要时进行。
8. **交付**：每个 gap写预期/实际、复现步骤、用户影响、优先级、证据、建议及复测方法；汇总“通过/失败/阻塞/未覆盖”，不使用模糊“基本完成”。测试完成后释放本轮创建的进程与数据库。

## 可复现命令

```bash
# 由独占测试环境注入 PGHOST/PGPORT/PGDATABASE/PGPASSWORD、REDIS_PORT、
# WORKSPACEX_API_PORT/WORKSPACEX_WEB_PORT/WORKSPACEX_MODEL_PROVIDER_PORT、
# WORKSPACEX_EMBEDDING_PROVIDER_PORT；系统 Chromium 时再设 PW_EXECUTABLE。
pnpm --filter web run e2e:kg-experience

# 复用本轮健康栈，但不复用观察；补充车道保留截图和失败 trace。
KG_EVAL_REUSE=1 pnpm --filter web exec playwright test \
  --config playwright.kg-user-acceptance.config.ts
```

正式报告必须记录实际执行命令、实际退出码和实际测试计数；环境启动失败时报告0条执行，不能当成用例失败。

## 修复后的统一复验入口

冻结 E1–E10 与所有 U/M/L 用户流程可在同一个真实浏览器/API/worker/AGE/pgvector 栈中执行：

```bash
# 不启用消融模式；独立检索对照使用单独配置，见 knowledge-graph-recall-ablation.md。
unset KG_EVAL_RECALL_MODE
KG_EVAL_RUN_ID=kg-comprehensive-fresh pnpm --filter web exec playwright test \
  --config playwright.kg-comprehensive-acceptance.config.ts
```

补充车道包括通用和研讨型项目的协作者/非成员共享边界、两模式个人原件忘掉与撤销恢复、AGE 与 pgvector 单独及同时故障。组织层新增验收是“项目晋升后从大脑入口读取实际条目”；它没有替代 A18 的完整新组织成员使用与跨组织隔离验收。

E3.c4 的冻结实现根据混合回答的相似引用推计 `vectorOnly`，没有独立关闭其他通道。因此其数值只能作为原有 proxy 指标，不能解释为独立纯向量准确率。真实消融模式与限制见 [独立检索对照验收](knowledge-graph-recall-ablation.md)，冻结阈值仍然保留。
