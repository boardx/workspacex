# 问卷完整用户流程验收（2026-09-21）

## 验收范围

本次使用真实 Chromium、Next.js、NestJS、PostgreSQL、Redis 与 MinIO，在独立测试栈中模拟普通用户完成以下流程：

1. 管理员登录并进入“我的问卷”。
2. 打开问卷模板库，选择内置完整模板“会议反馈调查”。
3. 创建真实问卷，核对 8 道题及 4 个报告章节。
4. 发布问卷并取得带签名的匿名答题链接。
5. 新开匿名页面，填写全部 8 道必答题并提交。
6. 管理端刷新后读取 1 份答卷，展开并核对答案内容。
7. 按报告模板生成正式报告，确认页面未出现“草稿”字样。
8. 下载完整 Word 报告，确认产物扩展名为 `.docx`。
9. 返回问卷列表，确认问卷、答卷数及发布状态已持久化。

## 发现的问题与处理

| 轮次 | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| 1 | 脚本未找到“会议日期” | 工作台目录显示带连续序号的题目名称；脚本错误地按无序号文本查找 | 改为核对真实目录文本，并保留首题、次题和末题三个反空转断言 |
| 2 | 脚本未找到“约束预览” | 该文案属于旧原型，不是正式报告模板编辑器的产品契约 | 改为核对真实报告标题、4 个报告章节及“预览完整报告”操作 |
| 3 | 公开链接格式校验失败 | 正式公开链接使用带签名 token，不是裸 UUID | 按真实安全 token 格式校验，继续使用浏览器打开链接 |
| 4 | 自动化未选中必答量表 | 题目的可访问名称包含必答星号，精确文本定位过窄 | 改为按题目 `group` 的可访问名称填写，更贴近键盘/读屏交互 |

前三项和第四项均为验收脚本对真实界面的错误假设；逐项查看失败截图与 trace 后确认产品数据、页面和接口正常，未通过放宽业务结果来消除失败。

## 固化的回归门

- 新增 `apps/web/e2e/survey-complete-flow.spec.ts`，覆盖完整用户链路和最终 Word 导出。
- 将该规格纳入 `playwright.fullstack-smoke.config.ts` 的 `seeded` 项目，后续问卷改动会持续执行同一条真实链路。
- 规格不拦截问卷 API、不注入答卷、不直接写数据库；创建、发布、提交、报告生成与导出均由页面操作触发。
