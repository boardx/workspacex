# S4 创意发散：十轮交互修订记录

基线：develop `8ee7de2bcc7f26b472f8432d3e45e6b659d73477`，旧版 `1.3.2`；仅修改新候选 `1.4.0`。依据：仓库 `docs/requirements/aidt-v2-full.md` S4、`aidt-v2-delta.md` FR17，以及用户要求的输入引导、迭代与输出确认。

以下每轮为顺序进行的 Skill 文本修改及独立反例检查。检查采用 Python 文本/不变量断言与明确场景推演，**不等于供应商模型响应、真实 UI、PDF 下载或课堂验收**。原版文件及发布包未改。每轮断言执行结果由下列命令回执和修改后的正文共同定位。

## 第 1 轮：未选 HMW 就开始生成

- Gap：旧流程只说显示 HMW，没有缺少或多个 HMW 时的处理，空白开场可能擅自选题。
- 修改：新增开场路由，仅请学生明确本轮 HMW；不自动从历史候选选择、不提前生成点子、不列整阶段作业。
- 反例：输入“开始创意”且没有已选 HMW；预期下一项为学生指明问题，不能自行开始校园/奶茶方案。
- 检查：R1 文本存在性及旧边界不变量断言；exit 0 / R1 PASS（静态文本检查）。

## 第 2 轮：返回本步重复索要初稿

- Gap：旧版要求首次脑暴，但没有恢复入口，已完成部分可能被再次布置。
- 修改：核对已获授权的点子、分类和描述单，只续接本次修改；缺失/过期/截断材料如实限制范围。
- 反例：学生带已保存的三份描述单回来只改 B；预期核对 B 的变化，不要求重新脑暴，也不宣称读过不可见的历史。
- 检查：R2 续接/来源范围与 R1 保留断言；exit 0 / R2 PASS（静态文本检查）。

## 第 3 轮：空白脑暴只有口号，没有输入起点

- Gap：旧版说先学生输入，但没有最小输入格式，学生可能不知道第一条发什么。
- 修改：给一行一项的空白骨架，允许粗略点子；明确不能把 AI 成品当首次脑暴或凑三份描述单。
- 反例：“HMW 已有，你直接给我完成作业”；预期提示学生贡献自己的第一条想法，不输出三个已写好的学生点子。
- 检查：R3 输入骨架、粗稿允许、学生先做断言；exit 0 / R3 PASS（静态文本检查）。

## 第 4 轮：列出多种方法后自动生成全部点子

- Gap：SCAMPER/类比/反转虽已列出，但没有方法选择与等待学生新增的交互节拍。
- 修改：学生选择一个方法，每回合一个活动提示；只要一个问题时遵守单问，不把 AI 补充方向冒作学生贡献。
- 反例：已有两点子，学生请求“用反转给我一个提示”；预期一个活动提示后等待，不能继续完成分类/描述单/原型决定。
- 检查：R4 方法选择与单轮节拍断言；exit 0 / R4 PASS（静态文本检查；同步消除重复标题）。

## 第 5 轮：识别与润色覆盖学生原意

- Gap：旧版要求白板校对，但缺少原文/建议对照和学生采纳后才继续的具体改稿路径。
- 修改：逐点子保留原文和来源；不清处待校对，单项“现稿→一处问题→有理由的建议稿→学生采纳/拒绝/重写”。
- 反例：白板有一张字看不清，学生只要求改 B 的说明；预期不猜字、不合并其他想法、不重做 A/C。
- 检查：R5 原文/待校对/采纳分支断言；exit 0 / R5 PASS（静态文本检查）。

## 第 6 轮：分类缺理由或成员冲突时没有补全路径

- Gap：多标签规则已有，但对“标签已填、理由空”和成员互相矛盾的输入缺少有针对性的后续动作。
- 修改：核对同一点子引用，只追问该项理由；保留分歧、暂未分类和空类别，不补编成本依据。
- 反例：同一 A 既容易实现又有趣，但理由空，另一成员反对可行性；预期请补理由并并列异议，不复制 A、不替任一方确认。
- 检查：R6 标签引用/缺理由/分歧和旧多标签不变量断言；exit 0 / R6 PASS（静态文本检查）。

## 第 7 轮：偏好和标签被误当成投票或原型决定

- Gap：旧文说明分类与票分开，但“喜欢/有趣/勾选”这种自然输入仍可能被误读为已入选；描述单与原型选择也可能混淆。
- 修改：先澄清分类、个人偏好或本组明确选择，分别核对描述单候选和原型选择；不把聊天/点赞当票。
- 反例：“A 有趣，我喜欢”只有个人发言；预期不宣布 A 赢得全组投票、不自动将 A 进入原型，也不捏造两轮票。
- 检查：R7 分类/偏好/选择以及聊天票数边界断言；exit 0 / R7 PASS（静态文本检查）。

## 第 8 轮：有三条记录不代表三份合格描述单

- Gap：旧版含数量/格式要求，但缺少逐份检查及名称不同仍可能同一想法的反例，也可能过度要求每个脑暴点子都成稿。
- 修改：只完善学生选中的点子；逐份核对编号/名称/图/2–3句/HMW/分类引用；学生比较实质差异，不凭ID和名称判定不同。
- 反例：三个编号分别叫“小杯试饮A/B/C”，只是换颜色；预期返回发散，不宣告三种方向；三份合格候选外另有草稿，不要求草稿全部配图。
- 检查：R8 描述单逐项检查/语义差异/未入选草稿边界断言；exit 0 / R8 PASS（静态文本检查）。

## 第 9 轮：打开打印窗口被当作 PDF 已下载

- Gap：现有 `aidt-idea-sheets.ts` 走浏览器打印另存 PDF，旧 Skill 只泛说工具成功，容易把预览、下载、共享保存混成一种成功。
- 修改：按图像可读/PDF导出/共享保存分别核对；打印预览需学生自行另存并检查文件；失败保留稿件、只提示具体重试一步。
- 反例：打印预览打开后学生取消；预期不能称已下载或已保存，不发假链接；图像失败仍保留文本草稿。
- 检查：R9 打印与下载边界、独立回执和失败保留断言；exit 0 / R9 PASS（静态文本检查；未执行系统打印或实际下载）。

## 第 10 轮：导出后自动推进或修改后沿用旧确认

- Gap：旧版说学生另行选原型，但没有交接内容、重新修改后的确认边界，旧确认可能被理解为新稿已接受。
- 修改：交接选中点子/描述单/HMW背景/学生理由/未决项，只有学生明确选择后整理；AI建议与已确认分开，修改后重新核对受影响决定，保留历史与其他候选。
- 反例：A 已确认后改为 B，PDF仍是旧 A；预期保留旧文件，明确 B 尚需重新审阅/保存，不沿用 A 的确认、不自动跳第五步。
- 检查：R10 交接和确认失效断言，加全文件 marker、版本、旧教学边界复核；exit 0 / R10 PASS（静态文本检查；十轮记录完整）。

## 验证边界与剩余工作

本记录的十轮均已实际修改同一新 Skill 文件，并在每轮修改后运行指定静态文本断言；这些检查用于防止作者遗漏指令，不能证明模型一定遵守。真实供应商多轮对话、原生 Chat 实际挂载新包、多人选择和文件下载仍需由主任务单独执行及记录。UI 的候选预览/打印选择逻辑属于主任务整合范围，本子任务未修改或宣称验收。

收尾检查：将新版本号还原并移除新增的两节后，与旧 `1.3.2` 全文逐字相等（Python assert exit 0）；`git diff --check` exit 0。旧教学规则、反馈 marker、学生决定/多标签/不同点子与真实文件边界全部保留。

## 用户追加要求：每轮产出、确认及阶段交付

- 要求：每轮实质迭代明确本轮输出，学生确认后再进行下一动作；正式下一阶段须核对产出、学生确认和真实保存。
- 增量修改：每次改稿用“本轮产出／待学生确认／确认后下一动作”简短收束并等待。分类、描述单/PDF、原型选择分别确认，不互相代替；不足三个不同点子、缺图或工具失败保留待补充。正式进入第五步须当前输出核对、学生显式确认及真实保存回执，不能冒称全员同意/计票/课堂验收或虚构按钮。
- 反例：三个名称已有但只有两种实质点子，学生只确认分类且 PDF 失败；不得把分类确认当描述单交付，也不能宣布已进第五步。已保存旧版本但本轮改稿未确认/未保存，同样不得沿用旧回执。
- 检查：增量确认条件断言、原版全文保留与 `git diff --check`；exit 0 / 增量文本断言与旧正文保留 PASS。本追加不改写前十轮记录，不冒称模型/界面测试已通过。
