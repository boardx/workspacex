## 第1轮：最小开场

- Gap：旧版直接陈述带入资料，空白入口不知道先交什么。
- 修改：增加最小点子提示，只处理一项，不预填或生成。
- 反例：学生只说“开始做原型”，没有已选点子。推演应先请其指出点子，不输出 App。
- 结构检查：进入区先于流程；提示与不生成约束存在；运行标记唯一，PASS。

- Gap：旧版只有“不只拿标题”的禁令，缺少可操作补充路径。
- 修改：用做法和帮助对象补充；未选点子回第4步；图片/研究缺口明示，禁止错用其他点子。

- 结构检查：描述单补充位于验证问题之前；保留学生选择与不同点子隔离，PASS。

- 结构检查：依据追问先于类型与生成讨论；未知分支及学生聚焦约束存在，PASS。

## 第5轮：学生确认与按类型补充

- 修改：确认验证问题与意图后分项补充；按服务/界面提供写法提示，等待人的方向选择。
- 反例：输入完整点子后只说“你决定，用服务也行”，没有选定表达。推演应给用途不同的静态选择，不能代确认，也不要求上传参考图。
- 结构检查：确认位于候选比较前；单项追问、参考图可选、沉默不确认约束存在，PASS。

- 结构检查：不匹配分支有学生选择、待定状态及原问题保护，PASS。

十轮逐次修改与结构断言已执行。反例为作者人工推演；没有真实provider输出、原生浏览器生成/保存回执、多人课堂结果。旧1.3.2源码未改。对`aidt-design-handoff.ts`“缺描述单只警告仍返回offer”的只读观察已交主agent处理，不能用本Skill修订冒称软件门控已通过。

## 用户新增要求增量：本轮产出 → 学生确认 → 下一动作

- Gap：十轮版在阶段交接时才展开产出清单，没有明确每次实质修订后的确认节点。
- 修改：每次实质修订以“本轮产出／待学生确认／确认后下一动作”三条短句收束；制作说明或方向的确认不冒充生成或保存成功。
- 交接条件：O1/O2/O3核对、学生对本次交付显式确认、真实版本保存回执均具备后再准备S6，保持待测试。输入不足/工具失败继续补充或重试，不宣称本轮完成，不虚构入口或自动跳转。
- 反例推演：只确认制作说明后说“去测试”，应继续制作并取得真实版本；已生成但保存失败，应标未保存；实际版本已保存且学生确认本次交付，才携同题与先前看法准备S6。确认不等于全组一致。
- 结构检查：三段收束、制作与生成区分、三项交接前置、失败分支、既有feedback marker保留，PASS。仅结构断言与人工反例推演，不是provider或浏览器测试。
