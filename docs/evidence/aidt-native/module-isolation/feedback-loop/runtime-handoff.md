# 实际试用前的运行条件

这份清单用于把本轮修复接入已有 WorkspaceX 开发或测试实例。它不是部署成功回执，也不批准生产操作或扩大访问权限。

## 实例与数据

1. 确认目标是允许本轮更新的开发/测试实例，记录当前业务提交、API/Web 启动身份和可供用户访问的真实 origin。容器内 loopback 地址不是外部地址。
2. 按已有实例流程安装依赖、构建与执行迁移。新增迁移是 `20261115092900_aidt_stage_revisions.sql`、`20261115093000_project_member_chat.sql`；本轮仅对前者补可重放，实际数据/权限不变。不能在未获得目标环境授权时对它执行迁移。
3. 构建 Web 时设 `NEXT_PUBLIC_ENABLE_AIDT=1`、`NEXT_PUBLIC_ENABLE_PROJECT_MEMBER_CHAT=1`；API 启动时设 `ENABLE_AIDT_MODULE=1`、`ENABLE_PROJECT_MEMBER_CHAT=1`。Web 必须重新构建，单独重启不改变旧 bundle 的公开开关。
4. 使用现有真实登录和项目成员管理。组织管理员查看项目概览不等于参加小组；本组入口、阶段稿和成员频道均核对真实成员，不增加组织管理员旁观写入特例。

## 真实 AI 单独验收

本轮环境只验证过 loopback 模型 fixture，当前目标工作区没有真实模型配置证据。已有 `/healthz` 成功、Skill 已安装或 Chat 界面加载均不能证明模型可用。

- 复用实例原有供应商与服务端配置流程；密钥留在既有安全配置中，不发到聊天、不打入 Web bundle 或交付包。
- 核对已发布 Agent 的模型 pin、当前组织可用模型、能力、额度与真实供应商配置一致；不能为通过测试关掉配额或改权限。
- 使用测试小组的无敏感材料完成一次真实原生 Agent run，记录真实供应商响应与持久消息来源；再由课程负责人判断追问质量。失败时保持可重试和未完成状态，不用 fixture 结果替代。

## 用户可操作验收

由实际用户在自己的浏览器打开该实例的 `/aidt` 并登录。至少两名小组成员验证以下闭环：创建/重入、六步各自原生 Chat、手动整理成果、真实共享保存/刷新恢复、并发编辑冲突、图片故障重试、跨页面成员文字沟通、报告保存与导出。另用组外账号核隔离、归档核只读，确认失败不会冒空态或保存成功。

关闭功能只关闭入口和新操作，不删除历史数据。访谈录音C按用户要求另排，语音房、教师评分及30人课堂负载均不在本轮通过范围。

临时验收工具如果使用标准 fullstack fixture，必须明确其 TTL、停止后清理测试数据及模拟模型性质；它不能冒充持久课堂工作区。
