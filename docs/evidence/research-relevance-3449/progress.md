# 研究来源相关性修复 #3449

用户场景：王者荣耀研究的第四步出现汽车库存、石油电池等无关资料。基线 622dfd2ee：搜索返回即 accepted，相关性校验只在报告证据阶段运行。

实现：自动来源先按当前 brief、大纲问题、任务和原文摘录做模型筛选；复用权威证据输出契约并校验逐条 chunk/来源/问题 ID 和逐字引用。无关结果不持久化为来源；失败不默认纳入，任务可重试。缓存绑定主题、大纲、标题、URL 和原文。旧会话在 start/report 复核，丢失全部来源的任务置失败可重试；保留部分报告授权。新增手动来源标记，用户排除记录保留。旧记录无手动标记时统一复核，不猜测其来源。

UI 区分已筛选、待复核与手动添加。计划提示词要求锚定主题实体或明确相关对照。

预审发现并修复：旧成功任务失去来源后的重试；旧部分报告的授权保留。

验证中：API 类型检查通过；来源 UI 4 项通过。标准数据库回归排队。尚未证明线上原会话恢复。真实检索+模型验证因自动审批认为外部发送缺少明确授权而未执行，已向用户询问。

验证完成：35 项真实PG、79 项纯后端、22 项契约、4 项界面回归共140项通过。组合测试曾因旧检索编排fixture未返回新相关性响应失败，修改fixture后79项纯后端全绿，生产代码未随此次夹具修正改变。旧基线用同一原始结果用例重现把汽车纳入的失败。预审另发现报告生成前步骤未恢复，已修并验证失败和持久化步骤。API/web类型检查通过。

远端审查补修：P1 指出全局问题集合可让 A 章节资料使 B 任务成功。现按来源与任务分别评价，chunk 只接受该任务章节问题；缓存包含任务定义，旧主 taskId/taskIds 一并裁剪，并恢复丢失证据任务的重试。自动检索候选不能借旧任务缓存或用户手动标记通过；已删除来源不追加新关联。新增五组反例及 PG 跨任务持久化回归。

初始 head 的 fullstack-smoke 失败与本改动相关：测试模型服务未识别 source_relevance，政策来源未出现。已补 HTTP loopback 回应，添加受控汽车负例及 E2E 不显示断言，等待新提交CI。85 项纯后端回归通过，真实 PG 回归按标准隔离排队；追加独立预审通过。

补修验证：标准隔离数据库组合回归 121/121 通过（36 项真实PG、85 项纯后端），连同既有22项契约与4项UI共147项。API类型检查通过。完整浏览器链路等待新head CI。
