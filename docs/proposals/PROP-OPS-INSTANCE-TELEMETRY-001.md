## 这份契约是什么

客户的 WorkspaceX 实例**主动**向我们的运营平面上报运行信号时，上报体长什么样。
它是超级实例六期里的 S2：**不依赖任何未决决策，可以现在就定稿**；S3 之后的实现要等 D16。

## 要守住的一句话，以及它落在哪

> **能不能从上报里重建出客户的一句话？能就不许传。**

| 约束 | 在契约里怎么落地 | 测试里怎么证明 |
|---|---|---|
| 出站上报，运营面对实例零读权限 | 契约只有「实例 → 边缘」一个方向，没有任何反向请求形状 | —（形状本身） |
| 传信号不传内容 | 每一层都 `.strict()`；**没有任何自由文本字段**——字符串全部受正则约束 | 在错误指纹里塞一句中文、在顶层加组织名，都被拒 |
| `personal-local` 一行不上报 | `excludesPersonalLocalOrgs: true` 为字面量必填，上报方必须显式声明 | `false` 或缺失都被拒 |
| 同意不坍缩成布尔 | 四项独立：health / usage / diagnostics / benchmark；某项未同意时对应分节**必须缺席** | 四项逐一关掉，带着分节就拒、去掉就过 |
| 实例不可被认出 | `instanceId` 只收 64 位十六进制哈希 | 可读名字被拒 |

「没有自由文本」这条由第 8 轮的 `lint-telemetry-schema.mjs` 机械检查：它遍历这份 zod schema 本身，
下一个人加一个不受约束的 `z.string()`，门就红。

## 为什么不复用 `consent-item.ts`

那份的对象是**自然人与一场对话**（录音 / 转写 / AI 归纳 / 署名）；这份的对象是**一个实例**。
复用的是它的结构——多项独立、互不合并、每项有自己的下游——不是它的枚举。
合成一份会让「录音同意」与「遥测同意」共用名字，那才是一词两义。

## 签核要看的三件（ADR-023）

本仓的签核门是束级 `design-signoff.md` 三节。这份提案目前**还没有所属阶段与 feature**，
因此先以 PROPOSED 契约 + 本文的形式公开；人确认方向后，按 `requirements-intake.md` 走需求录入、
建契约束，再签。三件分别是：

1. **UI**：实例管理员的「上报设置」页——四个独立开关，每个开关旁原样展示契约里的
   `TELEMETRY_CONSENT_COPY.ifOff`（关了会失去什么）；以及一个**「看见传了什么」**的只读视图，
   逐字展示最近一次上报体。**看不见的上报等于要求客户信任我们，这与自托管的前提相反。**
2. **用例**：上报器何时发（周期）、失败怎么办（丢弃，不重试到把实例拖慢；本地留一份最近上报供查看）、
   同意变更何时生效（下一个周期起）、**上报失败绝不影响实例本身的任何功能**。
3. **API 契约**：即 `instance-telemetry.ts`。

## 明确不在这份契约里的

- **任何客户内容**：会话、文档、画布、产出物、组织大脑里的材料
- **任何自然人信息**：成员姓名、邮箱、头像、IP
- **用量明细**：谁在什么时候跑了什么——只有计数
- **错误现场**：请求体、参数、日志原文——只有堆栈哈希与错误码
