# Fresh clone memory stage (Refs #5547)

This stage reuses the exact source5285 Agent image's existing `memory_deployment.prepare_memory_store` and readiness implementation. It adds no image, memory feature, cloud account or lifecycle owner. Call `clone_fresh_memory.run(payload, existingAdmission)` after the original eight recovery proofs are fully preserved and clone quiescence has a valid committed receipt, before API/Agent startup or final runtime identity watcher.

Default `mode=check` verifies target roles, original memory fingerprint and absence of the new schema without creating it or invoking readiness writes. `prepare` requires a separate root-pinned `binding.freshMemoryApproval` exactly binding original quiescence receipt raw hash, target/peer/source/attempt, schema and mode. This scope includes creating the dedicated schema and the existing tool's schema/table grants to the already approved memory_rw role. Neither old domain approval nor a boolean substitutes for this approval.

Payload keys: binding, approval, quiescenceReceipt, secret, optional mode. The quiescenceReceipt must be the exact same Admission directory's clone-quiescence.receipt.json. Schema is `wsx_fixture_` plus the canonical UUIDv4 attempt with hyphens removed only for this SQL identifier; the attempt itself is never normalized. binding.freshMemoryRuntime selects the fixed immutable Agent image and hash-bound engine exactly like the quiescence runtime. The shared fixed adapter accepts only these two compiled runtime kinds.

A new exclusive/fsynced intent and dispatch record precede prepare. Existing intent, pre-existing schema, missing response, deadline, failed postcondition or receipt write failure blocks replay; reconciliation is read-only. PostgresStore setup uses autocommit and concurrent indexes, so partial prepare cannot be rolled back and must remain unknown until reconciled or the exact temporary RDS is destroyed. No second schema, rename or retry is generated.

Secrets arrive through stdin and are converted in memory to fixed dbname workspacex_memory, users memory_owner/memory_rw, port5432, exact hostaddr and bound TLS. Actual owner identity/role flags and source-tool runtime privilege verification are required. The source module's SHA is verified inside the immutable image before import. Source PYTHONPATH is explicitly `/app/src` because isolated Python ignores image environment paths. The helper clears inherited environment before invoking the source tool, then restores it only within its private process.

Original `workspacex_memory.store` rows are compared before/after using ordered length-prefixed JSON row SHA256 and count; row contents are never emitted. Missing original schema fails closed. The new store must be empty, schema owner memory_owner, and the existing source readiness must verify limited runtime DML with no ownership, membership, DDL, migration-history or elevated table rights. Large history scans can exhaust the bounded helper and reject the stage; a count/hash receipt is not a substitute for the earlier full recovery evidence.

The same Admission UTC/monotonic deadlines bound the adapter and engine; expiry cannot grant success. The temporary helper is removed and absence checked before the final container identity-set watcher begins. Physical work termination still requires final exact runner destruction, not parent exit. Runtime must receive the new schema and runtime DSN only, never migration credentials.

Local validation: eight supervisor contracts plus four real PostgreSQL/source-tool tests passed (check leaves schema absent; prepare preserves old history, leaves fresh store empty and runtime DDL/TRUNCATE denied; wrong host rejection; existing schema rejection with no retry). Real tests used exact source5285 locked Python3.11 modules and a dedicated Docker loopback fixture; test-only transport mapping is disclosed, no provider/cloud privilege proof is claimed. The earlier six real source memory tests remain supporting evidence. All dedicated local containers were removed. Normal CI runs the supervisor/adapter contracts; real PG tests are explicit opt-in with a separately provisioned disposable local fixture.

This isolates memory storage, not arbitrary Agent tool content. New fixture tenant/model/skill instructions and tool-package review, storage/egress scope, lifecycle integration, normal CI and final execution approval remain separate requirements. Every receipt keeps a3Accepted=false.
