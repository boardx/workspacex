## 这是什么

workspacex 是一套 AI 原生的团队协作/知识管理系统(组织、聊天、Agent、Skill、
实时转录、深度研究……)。本文档教你在**自己的一台机器**上(本地电脑、云主机、
内网服务器均可)独立跑起一套完整实例,不依赖任何 SaaS 账号,不需要接入 GitHub
Actions 或任何 CI 系统。

**预计耗时:5 分钟**(不含你去模型服务商申请 API Key 的时间——这一步在系统之外)。

## 开工前你需要准备什么

下表是**全部**需要你主动提供的信息。逐条对照,缺哪个脚本会明确告诉你,不会让
你部署到一半才发现。

### 必填

| 你需要提供 | 用来做什么 | 从哪里拿 |
|---|---|---|
| **管理员邮箱** | 系统里第一个组织的超级管理员登录账号 | 你自己的任意邮箱,不需要能收信(见下方"发信凭据") |
| **管理员密码**(可留空) | 首次登录密码 | 留空 = 脚本自动生成一个强密码,在终端打印一次,自己记下来 |
| **模型服务 Base URL** | 系统里所有 AI 能力(聊天回复、通用助手、图片生成、语音转写)背后调用的推理服务地址 | 任选一个 **OpenAI 兼容**的网关。国内推荐阿里云百炼(DashScope兼容模式);也可以是 OpenAI 官方、或你自己搭的 vLLM/Ollama 网关 |
| **模型服务 API Key** | 同上,鉴权用 | 同上服务商的控制台生成 |
| **模型 ID** | 具体调用哪个模型,如 `qwen-plus`、`gpt-4o-mini` | 同上服务商文档里的模型名 |
| **访问方式** | 决定你和你的用户怎么打开这套系统 | 三选一:①`localhost`(只在本机浏览器访问,最简单)②局域网 IP(同一网络内其他设备也能访问)③你已经解析好的域名(需要 80/443 端口对公网开放,脚本会自动申请 HTTPS 证书) |

### 可选(不填也能跑,只是某个功能会降级,脚本会告诉你降级到哪)

| 你可以提供 | 用来做什么 | 不提供会怎样 |
|---|---|---|
| **发信凭据**(邮件网关 API Token + 发信域名,如 Cloudflare Email) | 用户注册/找回密码时的验证邮件 | 自动进入"开发直通模式":验证码直接显示在注册页面上,不需要真的收邮件。**适合你自己用或小范围试用;如果要给不完全信任的人开放注册,请务必补上这项** |
| **LangSmith Tracing 三件套**(是否开启 / API Key / 项目名) | 让"通用助手"每一次运行留下可排查的调用链 | 不影响使用,只是出问题时你自己排查会更难 |
| **对象存储目录**(文件/头像存哪个本地路径) | 用户上传文件的落盘位置 | 默认存在 `./data/objects`,跟随 compose 一起备份/迁移 |

### 完全不用你操心的

数据库密码、加密密钥、内部服务间的认证凭据——这些脚本会自动生成,写进
`.env.selfhost`(权限 0600,只有你能读),你不需要也不应该手动填。

## 开始部署

```bash
git clone https://github.com/<你的仓库地址>/workspacex.git
cd workspacex
./setup.sh
```

脚本会按上面的清单逐项问你(全部有默认值提示,直接回车 = 用默认/推荐值),
然后自动完成:

1. 生成 `.env.selfhost`
2. `docker compose -f docker-compose.selfhost.yml up -d`(数据库、对象存储、
   缓存、脚本沙箱、API、Web、通用助手引擎——一次起完)
3. 跑数据库迁移(幂等,重复执行安全)
4. 等待健康检查连续通过
5. 打印:

   ```
   ✅ 部署完成
      访问地址: http://localhost:3100
      管理员邮箱: you@example.com
      管理员密码: ************（仅显示这一次，请自行保存）
   ```

打开访问地址,用管理员邮箱+密码登录,即可使用。

### 非交互方式(适合脚本化/批量部署)

```bash
cp .harness/config/selfhost-answers.env.example answers.env
# 编辑 answers.env 填好上表的必填项
./setup.sh --answers answers.env
```

## 常用操作

| 我想… | 命令 |
|---|---|
| 查看服务状态 | `docker compose -f docker-compose.selfhost.yml ps` |
| 看日志排障 | `docker compose -f docker-compose.selfhost.yml logs -f api` |
| 更新到最新代码 | `git pull && ./setup.sh --upgrade`(保留已有配置与数据,只重建镜像+跑新迁移) |
| 备份数据 | `./setup.sh --backup ./backup-$(date +%F).tar.gz`(打包数据库 dump + 对象目录) |
| 从备份恢复 | `./setup.sh --restore ./backup-2026-xx-xx.tar.gz` |
| 完全卸载(含数据) | `docker compose -f docker-compose.selfhost.yml down -v` |

## 遇到问题怎么办

- 部署脚本红退时会**一次性列出全部**缺失或无效的配置项,不会只报一个让你反复
  重试——照着提示回到上面的表格补齐即可。
- 如果是模型相关功能(发消息没有回复)报错,先确认"模型服务 Base URL / API Key /
  模型 ID"三项是否确实对应同一个能用的服务——这是最常见的配置错误来源。
- 更深入的排障与生产化建议(备份策略、多机部署、接入公司已有 CI),参考
  `.harness/instructions/architecture.md` 的"部署三形态"一节。

## 这套系统会在你的机器上留下什么

- Docker 卷:数据库数据、对象存储数据、缓存数据——`docker compose down`(不带
  `-v`)不会删除它们。
- `./data/objects`:用户上传的文件(除非你在 setup 时指定了别的路径)。
- `.env.selfhost`:全部配置与凭据,0600 权限,**不要提交进任何版本控制**。

除此之外不会修改你机器上的任何系统配置(不建系统用户、不装 systemd unit、
不改你的防火墙规则——需要开放的端口由你在"访问方式"那一步自己决定并自己放行)。
