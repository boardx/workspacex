# Held candidate config and Nginx pointer CAS supplement

`candidate_pointer_adapter.CandidatePointerAdapter(transport, binding).promote_under_hold()` is an inertly imported, maintenance-only source adapter. It uses the existing retained candidate transport and its durable writer-fence Journal. The trusted root launcher must preload `compiled_maintenance_activation` from its verified FD source closure; there is no import-by-path fallback. Only that module's `private`, `replace`, and `invoke` primitives are reused. Legacy activation/Compose-up operations are never called.

## Package backlog and host ordering

Complete: fixed identity/profile/ref validation; held and closed-admission checks; actual candidate and baseline runtime/config/image/Compose/source-label validation; durable native flat migration completion plus live diagnostic ledger proof; durable intent before each real pointer CAS; raw readback; pinned Nginx check/reload; durable completion and conservative unknown-outcome handling. Root integration must call this after durable candidate resume intent and before opening candidate role admission or starting exact candidate containers. This source method opens no database admission and starts no container.

## Protected input contract

`trusted-tool-binding.json.candidatePointerPromotion` has exactly `schemaVersion: 1`, `sourcePath: '.harness/scripts/vm/candidate_pointer_adapter.py'`, `sha256`, and `binding`. Both this module and the preloaded activation module must match `filesSha256` from the unchanged protected profile. Binding has exactly `identity`, `toolRevision`, `host`, `holdGeneration`, `epoch`, `migrationCompletion`, `baselineConfig`, `candidateConfig`, `baselineNginx`, `candidateNginx`, and `binaries`.

Identity is the retained plan's fixed APP and baseline; tool revision, host, hold generation, epoch and migration completion hash must match retained source facts. Config refs are fixed candidate-configs/APP/attempt `baseline.json` and `deployment.json`; Nginx source refs are the existing native runtime/APP `baseline-nginx.conf` and `nginx.conf`. Completion ref is the existing attempt `.completed.json`. Each ref has exactly path/SHA-256. Completion bytes use the existing strict native flat `candidate_completion_contract.KEYS` schema; no `validated-migration-completion` wrapper is accepted. `validate_completed` checks the fixed identity, source evidence hashes, fresh provider timestamps, zero pending/drift/unknown counts and ledger SHA against rows read from the actual retained diagnostic connection. Its connection binding is independently checked against the retained source plan before the fixed migration-ledger query. Candidate config bytes must also equal `candidateComposeEmitter.configRef`, binding promotion to the native staged configuration. Candidate release must be the fixed release; baseline release must differ.

Target pointers are fixed `/etc/workspacex-cn/deployment.json` and `/etc/nginx/conf.d/workspacex-cn.conf`. The only executable inputs are reviewed hashes for fixed `/usr/sbin/nginx` and `/usr/bin/systemctl`. Existing `invoke` checks root-owned ordinary mode-0755 binary bytes and executes their held descriptors with fixed arguments `nginx -t` and `systemctl reload nginx`, preserving inherited canonical lock FD 9. No shell, user-selected command, legacy container name or network alteration is accepted.

## Outputs, idempotence, failure and rollback

A successful proof is `candidate-pointer-promoted-under-hold`, containing identity/tool/host/hold-generation/epoch and hash bindings only, with `writesHeld` and `lockRetained`. Both config and Nginx CAS intents are saved durably before their individual mutations. Config and Nginx raw readbacks, unchanged source refs/profile, and live held runtime are checked after reload before durable completion.

A repeat succeeds without mutation only with a matching durable promotion event and exact candidate bytes in both fixed pointers. An already-candidate pointer without durable completion is not success. Any pending intent, partial CAS, lost reply, Nginx validation/reload failure, authority race or failed journal persistence retains a sticky unknown outcome and forbids automatic retry. The method never restores baseline pointers, resumes baseline writers, clears the hold, changes role admission, deletes safety artifacts or treats container rollback as database recovery. Root recovery/reconciliation remains a separate reviewed action.
