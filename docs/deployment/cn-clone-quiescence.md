# Clone historical-work quiescence (Refs #5547)

This stage runs after the original eight isolated restore/migration/recovery stages and after their complete evidence is externally preserved. It precedes runtime startup and provider egress. It is not a production migration or A3 acceptance.

The lane calls `clone_quiescence.run(payload, admission)` with its existing, open `isolated_rehearsal.Admission` instance. No second admission or cloud cleanup owner is created. The Mac external owner remains responsible for RDS/OOS/IAM and final exact runner destruction. This module does not itself connect the future six-journey lane; that integration must call it inside the original lifecycle before final cleanup.

Default mode is `check`: the fixed SQL executes in a transaction and rolls back. `commit` requires an independently root-pinned `binding.cloneQuiescenceApproval` equal to the approval input. That approval must bind exact source5285, target/peer/attempt, all eight accepted receipt raw hashes, the external preservation receipt hash, the verified actor, fixed SQL SHA and allowed mode. No flag, caller-supplied hash or summary alone establishes external preservation: the trusted producer must verify the full externally retained original evidence first. A fresh provider/peer observation and application-stopped proof remain lane prerequisites.

Input keys are binding, optional mode, sql, approval, originalReceipts, sealedEvidence, secret, fixtureActor. `sql`, `approval`, each originalReceipts entry and sealedEvidence are exact `{path,sha256}` refs. The code defines the exact receipt schemas. The SQL is fixed SHA256 `7440c6dcccddfc1857fe3461344be4efb4794201bd6ffcfaac86da9a2f26d85f`. Its standalone file deliberately still rolls back; the reviewed engine removes only its known transaction wrappers after verifying the complete fixed hash. It cannot accept another SQL file, appended SQL or archive contents.

A commit writes and fsyncs a new exclusive intent before dispatch, then a dispatch marker before the engine call. Existing intent always blocks another commit, including uncertain outcomes. Only an exact typed engine receipt is stored; absent response, timeout, invalid output or local receipt failure leave the operation uncertain and forbid retry. Check mode does not grant commit authority. Check transactions and failures roll back; commit acknowledgement loss must be reconciled by a separately reviewed read-only process, not resubmitted.

The default adapter uses the root-bound quiescenceRuntime `{imageId,engine:{path,sha256}}`, where imageId is the immutable source5285 Linux amd64 Agent image containing its already locked psycopg runtime. It uses the existing isolated restore network after verifying its exact ID and attempt ownership. No image pull, new image, arbitrary command, cloud API or production environment mount is introduced. It sends secrets on stdin; stdout contains only target binding, fixed SQL hash, outcome and eleven aggregate counts. It rejects baked secret env values, verifies TLS/peer/database and non-superuser migration_admin with existing BYPASSRLS. It never grants privileges to make the SQL work. TLS disablement requires the existing independently approved provider exception.

The fixed DML handles historical run/interjection order, pending messages, schedules (including already accepted/read failed notifications), workflow state versions, mail, KG extraction/embedding and explicit empty project source policies, plus historical GitHub feedback associations. It neither disables triggers/RLS nor deletes whole tables. It does not isolate user memory or arbitrary tool content; fresh memory schema and reviewed fixture preparation are separate stages. Normal boot cleanup in the clone is separate from these statements.

Validation: exact source5285's 415 migrations were replayed into a newly created local PostgreSQL16/vector/AGE container. Eight original real-SQL tests passed, including the actual carry-over trigger and failed-notification CHECK constraint. The new wrapper has eleven admission/unknown/repeat/approval/result tests and five mocked Docker adapter contracts. Four additional real database tests passed through this supervisor and engine: rollback leaves historical rows, wrong secret host is rejected before connection, transaction expiry before COMMIT rolls back and forbids retry, and one commit changes the actual rows while a repeated wrapper call is rejected. For that Mac test only, psycopg's transport target was mapped to the dedicated Docker loopback port; SQL, constraints, database identity and commit were real. This is not an actual Linux image launch, cloud RDS privilege proof or six-journey run. All local test containers were removed.

The additional files enter build-tool FILES and the isolated producer source allowlist. Production qualification FD runtime sources are unchanged. Linux CI runs the admission contracts; full SQL replay/commit evidence is a separately retained local result, not mislabeled as CI. Final production/source closure must include the exact installed engine/adapter/SQL and normal CI/review before use.

The adapter inherits the same Admission UTC and monotonic deadlines (the container uses the host clock, without a separate time namespace); its subprocess budget is bounded by the remaining interval. The engine checks both clocks before connection and immediately before COMMIT. The supervisor preserves any valid commit acknowledgement before its final admission check, so a late return cannot report stage success or erase evidence of an acknowledged commit. This does not promise physical cancellation exactly at the deadline; unknown/in-flight work still requires the exact runner destruction boundary.

Run this helper before the final runtime container identity-set watcher is established. Its owned temporary container is removed and absence checked before returning; do not silently broaden the final watcher container allowlist to accommodate it. The local PostgreSQL test is explicit and requires a separately provisioned disposable source5285 schema/fixture database on localhost:55489; it is not a default CI or arbitrary database test.
