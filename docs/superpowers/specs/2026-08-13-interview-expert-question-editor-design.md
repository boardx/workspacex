# 访谈专家选择与问题编辑设计

## 目标

补齐 Phase 04 / F04 的 Mock 批量访谈创建体验：用户从完整专家目录中明确选择专家；系统为每位专家生成三条不同目的的默认问题；用户可继续增删改问题，且往返步骤不会覆盖已编辑内容。

## 用户流程

1. 用户在“确认访谈专家”步骤点击“添加专家”。
2. 页面打开居中弹窗，弹窗内可按姓名/角色搜索、按专家类型筛选，并多选专家。
3. 已加入访谈的专家保持勾选并标记“已添加”；本次新增选择在点击“添加所选专家”后一次写入草稿，取消则不修改草稿。
4. 用户确认专家后进入问题步骤。每位首次出现的专家生成三条问题，分别覆盖决策流程、否决风险、依据案例。
5. 问题按专家卡片分组。所有问题可编辑、删除；每位专家均可点击“添加问题”增加空白问题。删除默认问题后不会因步骤往返而自动恢复。
6. 用户返回专家步骤并增加专家后再次确认：已有问题原样保留，只为新专家补齐三条默认问题；已移除专家的问题被清理。

## 状态与数据

- 继续复用 `MockDigitalInterviewDraft.questions`，一个专家对应多条 `MockInterviewQuestion`，不新增后端 API。
- `MockInterviewQuestion` 增加稳定 `questionId` 与 `origin: "generated" | "manual"`。读取旧草稿时为缺字段的问题生成兼容值，避免历史草稿崩溃。
- 默认问题生成由纯函数负责，并以 `expertId + questionId` 保持稳定；确认专家时使用 reconcile 逻辑保留已有问题、删除未选专家问题、为新专家补足三条。
- 手动问题与已删除默认问题的稳定 ID 落入同一 localStorage 草稿，刷新及步骤往返后继续保持。

## UI 结构

- 新建 `ExpertPickerDialog`，沿用现有 `Dialog`、`Input`、`Checkbox` 和 `Button`，不引入依赖。
- 弹窗最大高度受视口约束，专家列表内部滚动；顶部固定搜索与类型筛选，底部固定取消/确认操作。
- 问题区按专家展示标题、角色、问题编号、目的标签、文本框与操作；“添加问题”在每张专家卡底部。
- 所有可操作项提供稳定 test id、键盘焦点、禁用态和明确文案。

## 错误与边界

- 专家至少保留一位；最后一位仍不可删除。
- 弹窗没有匹配结果时显示独立空态，不影响已选专家。
- 空问题会阻止进入访谈，并保留当前输入。
- 默认问题和手动问题都可删除；确认进入访谈时仍要求至少保留一个非空问题。
- Skill 助手对问题的建议继续作用于全部现存问题。

## 验证

- UI 测试验证弹窗打开、搜索筛选、多选确认和去重。
- UI 测试验证每位专家默认三问、手动新增/删除、编辑保持以及往返专家步骤不覆盖。
- 草稿测试验证旧问题迁移和新增字段持久化。
- 运行 Web typecheck，确保状态与组件接口一致。
