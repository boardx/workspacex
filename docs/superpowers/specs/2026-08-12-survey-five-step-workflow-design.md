# Survey 五步工作流 UI 设计

日期：2026-08-12
状态：用户已确认信息架构、组件边界、状态与验证设计；束级签核保持 pending

## 目标

以用户提供的五张截图为新权威，将 `/studio/survey` 收敛为单一五步工作流：设计问卷、报告模板、发布回收、查看答题、分析报告。

本轮使用真实前端组件、严格类型 mock 数据和本地交互完成 UI 签核原型。API、数据库、真实 AI、二维码、邀请、PDF/Word 导出、分享和现场快速投票不在范围。

## 架构

- 唯一路由：`/studio/survey/[surveyId]?step=design|template|publish|responses|report`。
- `SurveyWorkflowShell` 统一负责页头、步骤导航、保存反馈、状态边界和问卷上下文。
- 五个独立步骤组件消费同一 `SurveyWorkflowModel`。
- 题目数、回收数、有效样本、需复核数、完成率和报告样本数均由同一模型派生。
- 旧的“问卷设计 / 报告模板 / 回收与分析 / 现场投票”四标签不与新 UI 并存。

## 页面职责

1. 设计问卷：问题目录、题目编辑、选项/必答/章节映射和 AI 建议预览。
2. 报告模板：章节目录、管理问题、分析方法、输出组件与约束预览。
3. 发布回收：发布检查、链接/二维码、访问/回收规则和质量总览。
4. 查看答题：统计、筛选、答卷表、答卷详情与复核动作。
5. 分析报告：报告目录、摘要、能力缺口、事实/推断/建议和导出入口。

## 状态与质量

- loading、empty、error、success、readonly 均有稳定 `data-testid`。
- 发布阻断一次返回全部问题，存在阻断时不得显示已发布。
- 匿名问卷不得在详情中暴露可反查身份字段。
- 报告生成失败保留上一次成功报告。
- 375、768、1280 三档不得出现页面级横向溢出。
- 使用现有 Tailwind 语义 token 和 shadcn/Radix 组件，不新增依赖。

## 验收

- 五步 URL 均可直达和刷新恢复。
- 问题编辑、模板预览、发布阻断、答卷选择/复核和报告章节切换可见可操作。
- 重复指标保持同源一致。
- 五张桌面截图和一张移动端首屏截图进入 Survey 束 `ui.md`，集合与目录严格相等。
- Survey 束 `design-signoff.md` 由人类确认，agent 不修改其 pending 状态。
