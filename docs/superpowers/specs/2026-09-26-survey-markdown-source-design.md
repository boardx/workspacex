# 问卷 Markdown 源码与简化工作流设计

## 目标

将问卷系统重构为清晰的单一路径：**设计问卷 → 发布与回收 → 答卷 → 分析报告**。AI 在每个生成步骤返回 Markdown；Markdown 是草稿的唯一可编辑、可保存来源，界面中的题目、回收设置和报告仅是它的受控投影。

本设计以现有问卷的真实持久化、发布、填写和报告能力为基础。它不替换全站导航，也不新增问卷模块的重复侧栏。

## 用户可见流程

1. 在“我的问卷”查看状态、题目数、答卷数、有效答卷数及最近更新时间；每张卡片只有一个对应状态的主操作。
2. 新建或从模板创建后进入设计。设计页顶部只展示三个稳定阶段：设计问卷、发布与回收、答卷；报告是答卷完成后的可选产出入口。
3. 设计页包含 Markdown 源码与渲染预览两种视图。用户可在源码中编辑，服务端解析成功后更新预览；不能解析时保留原文、标出行号和原因，不静默修复或覆盖。
4. 发布页展示冻结版本的准备度、回收指标、分享链接和最少必要的回收设置。发布后题目与发布规则不可原地修改。
5. 答卷页提供筛选、列表、详情抽屉、标无效和导出；每份答卷始终按提交时绑定的问卷版本解释。
6. 报告页显示报告 Markdown 的阅读视图和源码视图，明确有效样本数、所用问卷版本和报告模板版本，并支持重新生成、Word 与 PDF 导出。

## Markdown 契约

四类文档各自有明确用途：

| 文档 | 唯一源码内容 | 派生投影 |
| --- | --- | --- |
| `问卷设计.md` | 标题、说明、分节、题型、选项、必答、显示逻辑 | 设计预览、填写器、发布检查 |
| `发布设置.md` | 匿名策略、答卷上限、截止时间、回收说明 | 回收设置、公开填写边界 |
| `报告模板.md` | 章节、题目映射、图表和叙述规则 | 报告编译模型 |
| `分析报告.md` | 正文、样本口径、证据引用、生成时间 | 阅读、导出、分享投影 |

AI 生成接口必须返回完整 Markdown 文本与生成元数据；不得只返回未经保存的结构化对象。用户编辑也以完整 Markdown 文本提交。结构化 `questions`、`publication`、`template` 和报告章节是解析结果，不能成为第二份可编辑事实源。

解析器必须是确定性的，并返回：解析出的受控结构、文档哈希、警告以及包含行列范围的错误。错误时不更新派生结构，也不丢弃草稿文本。

## 版本与数据完整性

草稿可反复保存 Markdown，每次保存形成可追溯修订。开始回收时服务端原子冻结以下对象：

```text
发布版本 = 问卷设计 Markdown + 发布设置 Markdown + 解析结构快照 + 内容哈希
```

答卷记录 `surveyVersionId`；答卷、有效性判定、导出和报告编译都只读取其绑定版本。已发布问卷要变更题目、逻辑或发布设置，必须从当前版本复制为新的草稿，而不能修改旧版本。

报告模板版本可独立演进。每份分析报告记录：所用问卷版本、报告模板版本、有效样本数、筛选口径、生成时间和报告 Markdown。重新生成创建新的报告版本，不覆盖既有报告。

现有未发布的结构化草稿迁移为语义等价的 Markdown；无法无损表示的内容保留原结构并在迁移报告中列出。已发布问卷和历史答卷保留既有冻结结构，不做自动重写。

## 页面组成

### 问卷列表

使用筛选、排序和卡片/列表视图展示问卷。卡片中只保留状态、关键数量、更新时间和主操作；更多管理操作收到菜单中。模板是新建入口，不与当前问卷流程并列成复杂导航。

### 设计问卷

中央区域为 Markdown 编辑器与预览切换。预览把解析结果呈现为题目清单和填写器效果；右侧属性抽屉仅显示当前题目的派生属性、相关源码范围和校验问题。AI 入口（文本、文件、转录）生成 `问卷设计.md` 的候选版本，用户可比较、应用或继续编辑，不能绕过保存和解析。

### 发布与回收

显示发布准备度、阻断项、预计时长和完成率；每个阻断项可定位到相应 Markdown 区间。已发布后展示回收状态、关键指标、链接和二维码，停止回收属于明确的危险操作并有二次确认。

### 答卷与报告

答卷页以表格和详情抽屉减少页面跳转。报告页的 AI 生成结果进入 `分析报告.md`，始终显示数据口径；未达匿名或最小样本阈值时，报告生成和分享按既有治理规则受阻。

## API 与组件边界

新增 Markdown 文档版本的专用契约，不扩展现有 `SurveyRuntime` 使其同时承担源码与投影两种职责：

- `SurveySourceDocument`：文档类型、Markdown、哈希、修订号、解析状态和诊断。
- `SurveyCompiledVersion`：只读解析快照，供发布、填写与答卷读取。
- `SurveyGenerationResult`：AI 生成的候选 Markdown、来源和版本基线；必须显式应用才会成为草稿修订。
- `SurveyReportVersion`：报告 Markdown、问卷/模板版本、样本口径与导出状态。

解析、校验、编译和冻结由服务端完成。前端只编辑源码、显示诊断、渲染投影并调用显式的保存、应用、发布、停止、导出命令。并发保存以版本号或内容哈希检测冲突；冲突时提供源码对比，不能静默覆盖本地编辑。

## 状态与失败处理

每个页面必须具有 loading、empty、error、无权限和成功状态，并且关键可交互元素使用稳定 `data-testid`。解析错误显示行号、字段和修复建议；依赖失败保留本地输入并提供重试；权限不足不泄露原始答卷或报告证据。危险动作（删除、发布、停止回收、外发报告）显示影响范围并二次确认。

## 验收与验证

实现按独立 Issue 和 PR 分批完成，每批都覆盖：

1. Markdown 解析/序列化的单元测试及确定性哈希验证。
2. 草稿保存、解析失败不覆盖原文、并发冲突对比的 API/组件测试。
3. 发布冻结后不可改题，复制后可继续编辑，答卷绑定正确版本的回归测试。
4. AI 生成候选 Markdown 的应用/拒绝/重试测试；不得把候选直接发布。
5. 报告样本口径、匿名阈值、Word/PDF 导出的一致性测试。
6. Playwright 覆盖列表 → 设计 → 发布 → 填写 → 答卷 → 报告主路径，以及 375px、768px、1280px 无横向溢出的浏览器检查。

## 分批边界

为避免重构中断现有可用问卷，实施顺序固定为：

1. Markdown 源码、解析器、草稿修订和兼容迁移。
2. 列表与设计页的源码/预览 UI。
3. 发布冻结、回收设置与链接投影。
4. 答卷列表/详情及版本绑定可视化。
5. Markdown 报告、样本口径与导出。
6. AI 候选 Markdown 生成、应用与回归验证。

每批单独建 Issue、独立分支和 PR；CI 与浏览器验证通过后提交 PR，始终等待人工合并。
