# 访谈创建弹窗与 Skill 助手设计

## 目标

将访谈 Studio 的新建入口改成轻量弹窗。用户只填写访谈名称和最多五个标签，创建后立即进入可点击的 Mock 五步访谈流程。流程左侧提供 Skill 对话助手，用户可通过对话优化当前访谈内容。

## 入口与弹窗

- Studio 右上角“新建访谈”改为按钮，不再直接跳转 `/itv/new`。
- 点击后打开居中弹窗并遮罩背景；支持关闭按钮、取消按钮和 Escape 关闭。
- 名称必填，最多 100 字；标签可选，最多 5 个，输入后按 Enter 或中文逗号确认，可单独删除。
- 名称为空时“开始访谈”禁用。提交后建立浏览器本地 Mock 草稿并进入 `/itv/<mock-id>/setup`。
- `/itv/new` 作为旧链接兼容入口，跳回 `/itv?create=1` 并自动打开弹窗。

## 五步 Mock 流程

- 顶部步骤为“主题、专家、问题、访谈、报告”，已满足前置条件的步骤可点击切换。
- 主题步骤补充主题文本；确认后写回草稿并解锁专家步骤。
- 专家步骤使用 Persona Mock，可选择、删除和补充专家，至少保留一位。
- 问题步骤按已选专家展示不同 Mock 问题，支持编辑和删除。
- 访谈步骤展示每位专家的 Mock 状态与问答入口。
- 报告步骤展示 Mock Markdown 正文和生成时间线，明确标记为探索性 Mock 内容。
- 草稿、当前步骤、专家、问题与报告均保存在同一 localStorage 草稿中，刷新可恢复。

## Skill 对话助手

- 桌面端在流程左侧固定展示约 320px 宽的助手；窄屏折叠为可打开区域。
- 助手读取当前草稿和步骤，提供“优化主题、推荐专家、补充问题、检查诱导、优化报告结构”快捷指令。
- 本阶段使用确定性的 Mock Skill 回复，不调用真实模型，也不生成真实证据。
- 回复只包含建议，不静默改动业务内容。用户点击“应用建议”后才更新对应主题、专家、问题或报告。
- 每次应用保留上一个快照，允许撤销最近一次修改。
- 对话、建议状态和撤销快照随草稿持久化。

## 错误与边界

- localStorage 内容损坏时返回安全空状态，不阻塞 Studio。
- 标签去空、去重并限制五个；超限显示明确提示。
- Skill 输入为空时不可发送；应用过的建议不可重复应用。
- 所有 Mock 内容明确标记，不得作为真实访谈证据。

## 验证

- 组件测试覆盖弹窗开关、名称校验、标签增删及上限、创建与跳转。
- 流程测试覆盖主题确认、五步点击、专家/问题 Mock 操作和刷新恢复。
- Skill 测试覆盖发送、建议不自动生效、应用后生效及撤销。
- `lint:design`、Web TypeScript 与访谈范围 UI 测试通过。
