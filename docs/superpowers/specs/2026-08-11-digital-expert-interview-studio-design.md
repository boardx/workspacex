# 数字专家访谈 Studio UI 设计

日期：2026-08-11  
状态：UI 方向与 Standalone 参考边界已由用户确认，待仓库签核门禁放行

## 1. 目标与范围

重新设计访谈 Studio，使用户可以：

1. 在首屏查看历史访谈及其进度，继续未完成访谈或查看已完成报告。
2. 在专家列表中选择数字专家，进入独立快捷访谈页面。
3. 创建批量访谈，确认主题并审核系统生成的专家阵容。
4. 为每位专家生成并调整针对性问题，批量执行访谈。
5. 使用主题、专家档案、问题和访谈记录生成可追溯的访谈报告。

本设计只包含数字专家。真人访谈、用户画像、访谈模板和侧边抽屉式访谈均不在本轮范围内。

### 1.1 Standalone 参考边界（2026-08-11 用户确认）

视觉参考文件：`WorkspaceX Standalone.html`（用户提供的 2026-07 本地导出）。

复用以下设计语言与工作台结构：

- WorkspaceX 左侧主导航、Studio 顶部范围栏和紧凑信息密度。
- 访谈首屏的卡片层级、状态徽标、进度表达和稳定操作区。
- 详情工作台的显式返回、分区导航、状态摘要和自动保存反馈。
- 数字专家答案的“立场/观点、理由、引用、不确定性、反例或推翻条件”结构。

不复用参考文件中的旧业务语义：

- 不使用弹窗式“新建访谈”，核心流程全部进入完整页面。
- 不保留真人排期、受访者、对象类型、用户画像或真人/数字对象切换。
- 不以模板为创建第一步；第一步固定为访谈名称、标签和主题。
- 不把数字专家推演描述成真人证据；报告恒标探索性并保留来源指针。

## 2. 信息架构

访谈 Studio 首屏只有两个一级标签：

- **历史访谈**：展示批量访谈和快捷访谈形成的历史记录。
- **专家列表**：展示可用数字专家，提供“快捷访谈”入口。

所有主流程使用完整页面切换，不使用模态弹窗或右侧抽屉承载核心工作。

```text
访谈 Studio
├── 历史访谈
│   ├── 继续未完成访谈
│   ├── 查看已完成访谈
│   └── 查看访谈报告
├── 专家列表
│   ├── 查看专家
│   └── 快捷访谈
├── 新建访谈
│   ├── 1. 基本信息与确认主题
│   ├── 2. 审核专家
│   ├── 3. 个性化问题
│   ├── 4. 批量访谈
│   └── 5. 生成报告
└── 访谈详情
    ├── 概览
    ├── 专家与问题
    ├── 访谈记录
    ├── 素材与发现
    └── 访谈报告
```

## 3. 首屏

### 3.1 公共页头

- 标题：`访谈 Studio`。
- 说明：回看或继续历史访谈，也可以选择一位数字专家快速开始对话。
- 右上角固定展示主按钮 `＋ 新建访谈`。
- 按钮必须保持单行显示，不因内容区变窄而裁切文字。

### 3.2 历史访谈

默认进入“历史访谈”标签。支持按全部状态、进行中、待确认、已完成筛选。

每张历史访谈卡片至少包含：

- 访谈名称。
- 数字专家数量与创建人。
- 状态：进行中、待确认、已完成。
- 当前阶段或结果摘要。
- 标签。
- 进度信息或完成时间。
- 与状态匹配的主操作。

状态与操作映射：

| 状态 | 卡片主操作 | 行为 |
| --- | --- | --- |
| 进行中 | 继续访谈 | 打开访谈详情并回到上次阶段 |
| 待确认 | 继续创建 | 打开创建流程并回到待确认步骤 |
| 已完成 | 查看访谈 / 查看报告 | 打开只读详情或报告 |

快捷访谈完成首轮对话后自动进入历史访谈，后续可转为批量访谈。

### 3.3 专家列表

支持按专家领域筛选。专家卡片包含：

- 专家名称与角色。
- 行业或市场范围。
- 可回答问题范围。
- 专长标签。
- `快捷访谈` 和 `查看专家` 操作。

点击 `快捷访谈` 打开独立对话页，而不是弹窗或右侧抽屉。

## 4. 快捷访谈页

快捷访谈页包含：

- 返回专家列表。
- 专家身份、角色和“探索性对话”提示。
- 完整对话记录。
- 固定在页面底部的消息输入区。
- `转为批量访谈` 操作。

转为批量访谈时，已有问题与回答作为新访谈素材保留，并进入批量访谈创建流程。

## 5. 新建访谈流程

### 5.1 第一步：基本信息与确认主题

必填内容：

- 访谈名称。
- 至少一个标签。
- 访谈主题。

访谈主题用业务语言描述需要验证的问题。系统可以提示主题是否过宽、是否混入多个问题，但必须在用户点击 `确认主题并生成专家` 后才生成专家。

支持保存草稿。离开页面后再次进入应恢复已填写内容和当前步骤。

### 5.2 第二步：审核专家

系统根据已确认主题生成一组互补数字专家。用户可以：

- 查看每位专家的角色、视角、材料充分度和推荐理由。
- 删除不合理专家。
- 从专家库添加专家。
- 确认专家阵容。

本步骤不出现真人和用户画像的类型选择；只能增删或替换数字专家。

### 5.3 第三步：个性化问题

系统针对每位专家的角色和材料范围分别生成问题，不向所有专家发送同一套题。

用户可以按专家切换问题列表，并执行：

- 添加问题。
- 删除问题。
- 修改问题。
- 查看问题目的。

确认问题后才开始批量访谈。

### 5.4 第四步：批量访谈

系统并行访谈已确认的数字专家。每位专家独立显示：

- 未开始、进行中、已完成或失败状态。
- 当前问题进度。
- 完整对话记录。
- 追加追问、插入追问或失败后重新运行的操作。

用户可以离开页面，访谈继续执行；再次进入时恢复运行状态。

### 5.5 第五步：生成报告

报告素材包括：

- 已确认的访谈名称、标签、主题和背景。
- 本次使用的数字专家档案。
- 每位专家的针对性问题。
- 完整问答记录。
- 从问答中提取的候选素材和发现。

每条报告发现必须能追溯到具体专家和具体问题。报告应明确标注数字专家结论的探索性，并单列待验证项。

## 6. 访谈详情页

详情页左侧显示：

- `返回历史访谈`。
- 访谈整体状态。
- 当前阶段和进度。
- 最后更新时间。
- 概览、专家与问题、访谈记录、素材与发现、访谈报告导航。

详情页主区域显示：

- 访谈名称与说明。
- 当前进度、问题数量、素材数量。
- 每位专家的完成状态和问题进度。
- 右上角 `＋ 新建访谈` 与当前访谈主操作。

`返回历史访谈` 必须切回访谈 Studio 首屏，并默认激活“历史访谈”标签、展示历史访谈卡片。返回行为不依赖浏览器偶然历史状态。

右上角按钮区必须使用稳定的横向布局：按钮文字不换行；空间不足时操作区整体换行或移动到下一行，不允许按钮内部文字被裁切。

## 7. 状态与恢复

访谈整体状态至少包含：

- 草稿。
- 待确认主题。
- 待确认专家。
- 待确认问题。
- 访谈进行中。
- 报告待生成。
- 已完成。
- 失败。

历史卡片、详情状态卡、步骤导航和主按钮必须由同一访谈状态派生，避免不同页面显示冲突状态。

## 8. 交互与异常状态

- 所有主导航和返回操作均使用明确的页面状态或路由，不使用无事件处理器的视觉按钮。
- 删除最后一位专家时阻止继续，并提示至少保留一位专家。
- 专家生成失败时保留主题输入，提供重试和手动添加专家。
- 问题生成失败只影响对应专家，可单独重试。
- 批量访谈部分失败时保留已完成结果，允许单独重跑失败专家。
- 报告生成失败不丢失访谈素材，可重新生成。
- 空历史记录展示新建访谈入口；空专家列表展示清晰的不可用原因和刷新入口。

## 9. 响应式与可用性

- 桌面端历史卡片使用三列布局，较窄屏幕降为两列或单列。
- 详情页在桌面端使用状态导航侧栏和主内容双栏；小屏改为上下布局。
- 页头操作区不得遮挡标题或超出内容容器。
- 所有交互按钮具有悬停、聚焦、按下和禁用状态。
- 关键交互元素需要稳定 `data-testid`，端到端验证不得依赖展示文案或 DOM 层级。

## 10. 验收场景

1. 从进行中的历史卡片点击“继续访谈”，进入对应详情和上次步骤。
2. 在详情页点击“返回历史访谈”，首屏显示历史访谈卡片且该标签处于激活状态。
3. 详情页右上角两个按钮在桌面内容宽度下完整显示且不换行。
4. 切换到专家列表，点击“快捷访谈”，进入独立对话页；返回后仍停留在专家列表。
5. 点击“新建访谈”，进入完整页面；第一步可填写名称、标签和主题。
6. 审核步骤只能操作数字专家，并支持删除和添加。
7. 每位专家显示不同的问题列表，可独立增删改问题。
8. 批量访谈显示每位专家的独立状态，离开再进入后状态可恢复。
9. 报告使用全部确认内容和访谈记录，并可从发现追溯到具体问答。
