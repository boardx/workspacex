# Agent / Skill 统一后台与卡片设计（#6418）

## 用户要求及确认

- 主侧栏「更多」中的 Agent 目录、Skill 库入口删除。导航只通过组织后台与平台后台进入。
- 组织拥有并管理自己的 Agent / Skill；平台可以管理所有组织的 Agent / Skill。
- 组织管理员可管理，普通成员可浏览、使用（用户已确认）。平台入口仍要求真实平台运营权限。
- 所有生产 Agent / Skill 目录参考给定截图的头像卡片，主信息只显示图像、名称、简短描述。

## 现状与范围

当前平台 AgentScreen 使用 session.currentOrgId，不能据此声称可管理所有组织。现有能力目录条目、可执行 Agent 定义、Skill 库与 Work Skill 是不同数据，不合并数据库实体、不把目录条目伪装为可执行定义。现有官方角色安装、开始对话、版本编辑、导入及发布保护保留。Skill的library、catalog、work-catalog三种生产内容均保留发现路径；平台范围必须贯穿详情、草稿、文件、版本和导入操作。

此次只改变这些实体的入口、管理范围与目录展示，不改变聊天选人、运行权限、版本固定、Skill审核与发布规则。选择器中的紧凑候选项无需强制改成大型目录卡片。

## 方案

推荐复用现有目录与编辑工作流，并明确组织/平台两种授权范围。另起一套平台CRUD会复制版本和导入约束；仅改导航则无法实现平台跨组织管理，因此不采用。

- `/org-admin/agent`、`/org-admin/skill` 为组织目录正式入口，左侧组织后台拥有这两项。
- `/platform-admin/agent`、`/platform-admin/skill` 为平台目录正式入口。
- 平台默认全组织视图，可搜索或筛选目标组织；卡片上方的分组/组织标签明确归属。写入前必须明确目标组织，禁止把“全部组织”当写入目标。
- 普通成员也能从组织统一入口找到这两个目录；只显示其有权查看的导航项，不因移除主侧栏入口失去使用路径。
- 组织目录固定当前组织。组织切换或平台目标切换后，列表、选中卡片、编辑器、异步回调均随范围刷新，旧请求不能覆盖新范围。
- 原 `/agent`、`/skill` 的生产入口兼容转到组织目录，保留实体深链和必要查询参数。原型路由不冒充生产入口。
- 平台管理可执行组织已有的新增/导入、修改、停用及详情/版本编辑能力；具体发布、审核、启用仍沿用已有规则。操作不能通过前端伪造组织管理员身份实现。

## 卡片与交互

- 共用同一目录卡片组件：白底、细边框、统一圆角/内边距，桌面三列，平板两列，手机一列。
- 左侧统一64px图像区域，右侧名称与最多两行简介；卡片高度一致，长名称截断且完整名称可被辅助技术读取。
- 有现成头像/图像时直接复用。无图像使用统一Agent/Skill图形占位，不能随意把未知实体映射为某个官方人物。
- 卡片主面不显示ID、技术说明、密集标签、多排动作按钮。平台组织归属在外部分组/上下文提供。
- 点击/键盘打开详情。状态、ID、能力/版本信息、编辑、停用等操作放详情或编辑页。已有开始任务/使用能力仍可在详情触达。
- 搜索与必要筛选保留，官方角色与本组织内容保持可区分。官方角色不再在每张卡片重复长篇启用说明，统一放说明区。
- 中文/英文文案、加载/错误/空态、键盘焦点及小屏可达性一并处理。

## API 与权限边界

- 契约定义在 packages/contracts，不能在前后端复制schema。
- 组织路径复用既有成员/管理员鉴权与租户范围，不扩大普通成员的写权限。
- 平台跨组织读写复用 PlatformOperatorGuard 与既有平台授权判定，显式目标orgId；服务端完成真实授权后才进入目标租户事务。
- 全组织卡片/详情以组织ID＋实体种类＋实体ID标识，避免不同组织同ID串选。
- 全组织查询有界分页，不能使用无界并行拉取全部组织的所有详情。平台组织选择复用已有组织目录。
- 不通过给平台用户新增org_membership、不伪造Principal、不对普通组织端点开放任意orgId来实现管理。
- 对修改/停用保留实体归属与版本检查，跨组织的实体ID不能在错误的目标组织下成功读取/写入。平台操作保留真实actor与目标组织审计。
- 详情与版本编辑的读写必须使用同一授权范围；禁止列表跨组织可读但后续编辑仍隐式落回当前组织。

## 验收

1. 导航测试：成员通过组织入口可发现全部原先有权访问的生产目录；更多菜单没有Agent/Skill；组织、平台入口都有有效落点；旧生产深链转向正确范围。
2. UI测试：各目录复用图像/名称/简介结构，ID及管理按钮移入详情；有图/无图、长文本、空态、语言切换。
3. API真实HTTP+PG：组织管理员仅写本组织、成员可读不可写；平台运营者可列举并管理其未加入的组织；普通用户/普通组织管理员不能调用平台路径。
4. 错误目标组织实体拒绝，切换组织的迟到请求不污染新列表或提交目标，写入审计保留真实actor/目标。
5. 真实浏览器截图核对组织/平台Agent及Skill，包含小屏和打开详情，保留截图证据。
6. 受影响typecheck/lint、相关回归与最新PR CI通过；不宣称真实模型运行或生产发布已经验证。
