# 用户访谈四处 UI 修复（#5890）

## 目标与范围

根据人类截图修复导入需求输入框、问题生成状态和访谈答案折叠。人类已明确确认：答案默认收起，可点击展开。复用当前 worktree，基于最新 origin/main；一个 issue 一个 PR，不自行合并或修改 passing。

## 方案与取舍

采用现有访谈页面内的局部修复。整体重做六步布局或修改共享研究组件会扩大影响范围，不适合此次三个具体问题。

### 1. 导入需求

- 保留可见标签，改为面向用户的“研究需求”，辅助说明支持 Markdown。
- 输入区与语音、上传、字符计数组成一个统一圆角编辑器，减少嵌套边框。
- 使用现有 Textarea 基础组件和语义颜色；焦点边框沿统一编辑器呈现，避免 textarea 内出现生硬的矩形框。
- 保留多行示例、手动调整高度、上传/语音、草稿保留和错误重试。

### 2. 生成访谈问题

- 正文保留一处可访问的生成状态，显示专家数量、预计等待和草稿保留说明，配一个加载图标。
- 问题生成期间，步骤条保留当前步骤与运行语义，但不重复旋转动画；页尾生成按钮禁用，保留稳定操作文案，不重复加载图标和长提示。
- 尚无问题时，生成状态占据问题内容区，不再同时显示“请先生成”的空态；已有问题重新生成时，继续保留旧问题和编辑内容。
- 保存、确认各自操作的加载反馈照常保留；失败由现有错误恢复流程接管。

### 3. 访谈答案

- 访谈记录初始折叠；标题旁提供“展开答案 / 收起答案”按钮，包含 aria-expanded 与 aria-controls，支持键盘。
- 点击专家定位并展开该专家的已保存答案；再点击当前专家可返回全部记录，全部记录恢复折叠。
- 回答生成完成或后台刷新不主动展开；用户已经展开的同一记录保持展开，避免刷新打断阅读。
- 折叠仅影响展示，完整 canonical Markdown、来源链接、证据模式和报告生成输入保持原样。

## 验证契约

### 补充：切换步骤时完成状态闪回

人类追加截图：全流程已完成，切换步骤后步骤条先显示未完成，再跳回完成。

当前代码中 InterviewMarkdownWorkbench 的 completed 初始值为空数组，挂载后另发 canonical Markdown 请求才填入完成步骤；独立 stage 路由重新挂载工作台时会暴露该默认值。这是明确的加载态与业务未完成状态混淆。

修复目标：首次加载期间不把未知状态画成未完成；同一访谈切换步骤时保留已确认的完成状态，服务端新修订返回后再按当前修订更新。不能靠当前路由位置推断前置步骤完成，也不能从 legacy workflow 伪造 canonical 状态。失败时显示可恢复的加载错误，不能把全流程重置成未完成。任何共享加载或缓存必须隔离访谈及 actor/组织，避免旧状态污染其他访谈。

新增验收：延迟 canonical 请求时没有未完成闪回；已完成访谈跨阶段切换、刷新、加载失败恢复、新修订使下游失效、切换访谈或身份，不串状态。

- UI 回归：生成状态唯一、生成中无误导空态、重新生成保留旧问题；初始折叠、手动展开/收起、专家切换与内容更新；来源链接仍可访问。
- 真实 Chromium：375 / 768 / 1280 宽度，输入与聚焦、延迟生成、已生成答案展开/收起、键盘可达，无横向溢出。
- 运行受影响 UI 测试、web 类型检查与设计 lint，提交截图及验证输出。浏览器若使用 HTTP/session 夹具，会明确标注，不能声称真实 DB/模型验收。
