# 用户访谈原型补齐：Markdown 内容单源

日期：2026-09-27

本文替代 2026-09-26 工作台设计中“结构化研究结果为权威、Markdown 为投影”的内容存储决策；不替代身份、权限和任务运行元数据的契约。

## 用户确认的目标

按用户提供的八张原型补齐列表和六阶段页面。进入访谈隐藏 Workspace 菜单，统一 header 提供步骤切换及返回列表；返回列表恢复菜单。每个页面独立 route。研究内容的输入、模型输出、API 传递、持久化和渲染均使用 Markdown。

## 内容单源与元数据边界

- 需求、分析、专家画像、问题提纲、访谈回答、摘要、报告的权威正文均为 UTF-8 Markdown 文档。
- 数据库保存原始 Markdown 正文和不可变版本，不再维护可独立编辑的 JSON 研究正文副本。
- API 使用正文为 Markdown 的文档契约。传输封装可以包含文档 ID、版本、内容哈希、状态及错误码，但不得用研究内容 JSON 替代正文。
- 文档 ID、稳定专家/问题/回答引用、组织权限、排序关联、幂等键、任务状态、时间及版本是运行元数据，不是研究正文。权限判断不依赖模型生成的 Markdown。
- 模型上下文使用已确认 Markdown 版本；模型返回 Markdown。需要用于页面卡片、检索及导航的内容，由统一解析器从文档生成只读投影，不成为第二个事实源。
- 专家和问题等对象通过文档元数据或规范锚点保持稳定关联；编辑正文不能伪造授权或把模拟证据改成真人证据。
- 附件原件和头像属于二进制资产，保留原件；提取的研究文本以 Markdown 入流，并记录原件引用。不得把附件或 SVG 任意原文当成可执行 HTML 渲染。

## 六阶段体验

1. 导入需求：文本、文件提取和录音转写形成需求 Markdown，审阅后确认。未接通能力不得显示为可用。
2. 确认分析：真实模型根据需求生成分析 Markdown；卡片展示研究目标、专家类型、范围、成功标准和建议，不使用固定通用结论。
3. 选择专家：搜索及筛选专家库、已选侧栏、排序、添加虚拟专家弹窗；画像以 Markdown 保存，沿用可修改头像能力。
4. 访谈问题：专家侧栏、问题分组、编辑/增加/删除/排序；所有操作保存新提纲 Markdown 版本。
5. 开始访谈：专家进度侧栏和实时摘要主体；回答先持久化再汇总。暂停阻止后续调度，已保存回答不丢失；失败重试仅补缺口。
6. 生成报告：目录侧栏和文档主体、完整 PDF/Word 导出、受权限约束的分享。模拟证据披露和审批门禁不因界面重构而放宽。

## 迁移与恢复

旧结构化研究数据通过确定性转换生成 Markdown 版本，记录迁移来源和哈希。先做可重跑的增量迁移及兼容读取，不删旧表、不改生产数据。迁移完成且验证一致后才切换内容单源；旧数据保留只读用于回滚。

确认版本不可变。重生成和人工修改产生新版本。失败保存已有 Markdown 片段、失败原因与可重试状态；刷新后恢复。运行中内容变更触发现有版本冲突检查，不静默覆盖已确认下游。

## 验收

- 八个原型视图逐页真实浏览器截图对照，桌面端保留布局与操作，窄屏不裁切关键操作。
- 完整主链路从需求到导出，独立 route 刷新及返回列表均可恢复。
- 契约/API/数据库测试证明 Markdown 原文往返一致，正文无 JSON 双写，版本不可变。
- 覆盖模型失败、部分结果、暂停/继续、重试、并发版本冲突及未授权访问。
- 导出含报告末尾、引用和证据边界；目录锚点来自同一渲染文档。
- UI 单测、API 测试及浏览器 E2E 通过后创建 PR，并处理 CI、冲突和 review；不自动合并。

## 实施前审阅边界
