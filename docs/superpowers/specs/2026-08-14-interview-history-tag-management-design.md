# 访谈历史 Tag 筛选与 Mock 卡片管理设计

## 背景

访谈 Studio 历史页当前按状态显示“全部、进行中、待确认、已完成”四个筛选项。用户希望把这一区域改为按访谈 Tag 筛选，并在本地 Mock 访谈卡片右下角提供编辑和删除入口。

本次只管理 `mock-batch-*` 本地访谈。后端真实访谈继续由服务端读模型提供，并保持只读；在后端补齐更新、删除契约前，前端不为真实访谈伪造本地覆盖状态。

## 已确认交互

### Tag 筛选

- 筛选栏显示“全部”和当前已加载历史访谈中的全部 Tag。
- Tag 去重后按历史数据首次出现顺序展示。
- 采用单选：选择一个 Tag 后，仅展示 `tags` 包含该值的访谈；点击“全部”恢复完整列表。
- 卡片右上角继续展示访谈状态，状态不再作为顶部筛选条件。
- 编辑或删除 Mock 访谈后，筛选项从最新列表重新派生；如果当前选中的 Tag 已不存在，自动回到“全部”。

### 卡片管理菜单

- 只有 `mock-batch-*` 卡片在右下角显示“更多”按钮。
- 菜单包含“编辑”和“删除”，支持键盘操作并提供明确的无障碍名称。
- 真实后端访谈不显示菜单，避免产生无法持久化的假操作。

### 编辑

- 点击“编辑”打开对话框，预填访谈名称和现有 Tag。
- 名称必填；Tag 最多 5 个，输入后按回车确认，可逐个移除。
- 保存调用现有 Mock 草稿存储更新入口，同时更新时间和版本。
- 保存成功后关闭对话框，卡片标题、Tag 和顶部筛选立即更新；刷新页面后仍保持。
- 编辑只改变名称和 Tag，不改变主题、步骤、专家、问题、运行结果或报告。

### 删除

- 点击“删除”先打开二次确认对话框。
- 确认文案明确说明会删除该 Mock 访谈的主题、专家、问题、进度和报告，且不可恢复。
- 取消不改变任何数据；确认后从 localStorage 删除完整草稿并从历史列表移除。
- 如果删除后当前 Tag 没有任何访谈，筛选自动回到“全部”。

## 数据与状态设计

`InterviewStudioHome` 保留一次完整的历史加载结果，不再把顶部选择传为服务端 `status` 参数。页面在客户端执行 Tag 筛选，从而保证 Mock 与真实访谈使用相同筛选语义。

Mock 存储模块新增两个小而明确的操作：

- 更新名称与 Tag：复用既有规范化逻辑，名称 trim，Tag 去空、去重并限制为 5 个。
- 删除草稿：只接受 `mock-batch-*` 标识，从现有 localStorage 记录中移除目标草稿。

编辑或删除完成后，首页重新从 Mock 存储与当前已加载服务端结果组合读模型，避免维护第二份卡片状态。

## 错误与边界

- 找不到 Mock 草稿时不静默成功；对话框保留输入并显示错误。
- localStorage 内容损坏时沿用现有安全读取逻辑，不让历史页崩溃。
- 空 Tag 不进入筛选栏；无 Tag 访谈只在“全部”中出现。
- 同名 Tag 只显示一次，比较采用当前精确字符串语义。
- 删除真实访谈、用本地覆盖真实访谈、增加后端 CRUD 均不在本次范围。

## 验证

在 `apps/web/tests/ui/interview-studio-home.test.tsx` 增加回归覆盖：

1. 顶部从加载结果动态生成 Tag，单选后只显示匹配卡片。
2. 编辑 Mock 访谈可修改名称与 Tag，页面和 localStorage 同步更新。
3. 删除必须二次确认；取消保留，确认后删除完整草稿。
4. 编辑或删除导致当前 Tag 消失时自动回到“全部”。
5. 后端真实访谈保持只读且不出现管理菜单。

同时运行 Web 类型检查与设计 lint，确保按钮焦点、对话框语义和稳定 `data-testid` 符合现有规范。
