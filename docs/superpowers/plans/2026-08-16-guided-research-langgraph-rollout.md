# Guided Research LangGraph Rollout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将引导式 Deep Research 的 Brief、Directions、Outline、Research、Report 五步迁移为一个可恢复、可幂等重放的 PostgreSQL-backed LangGraph 工作流；每次显式确认都提交完整前端节点状态，并由 `qwen3.7-plus` 生成通过共享 schema 校验的结构化下一步结果。

**Architecture:** `apps/deep-agent-service` 是唯一状态图运行时，持有 `await_command → route_command → handler → await_command` 的 Guided Research StateGraph 与 PostgreSQL checkpointer；`apps/api` 负责 BoardX 租户授权、公开契约、command/effect receipt、业务内容与读投影；`apps/web` 只消费统一 workflow projection，并在 `/research?session=grs_example` 形态的单页内切换步骤。六个垂直切片严格串行，每个切片一个 issue、一个 PR。

**Tech Stack:** TypeScript 5、Zod、NestJS、PostgreSQL/RLS、Python 3.11、LangGraph、langgraph-checkpoint-postgres、LangChain OpenAI-compatible client、阿里云百炼 `qwen3.7-plus`、React/Next.js、Vitest、Pytest。

## Global Constraints

- 权威设计：[2026-08-15-guided-research-langgraph-persistence-design.md](../specs/2026-08-15-guided-research-langgraph-persistence-design.md)。任何实现语义与其冲突时先改设计并重新签核，不在代码里另造规则。
- 开工前新增 F191–F194，并更新 F170/F171 依赖；每项经 `harness sync --apply` 建 issue 后才认领。不得复用已经被占用的 F188。
- 新 feature 加入 `guided-deep-research` 契约束后必须由人类重新确认 `design-signoff.md`，agent 不修改签核状态。
- 六个切片共享 `packages/contracts/src/research.ts`、Graph state、API controller、session repository 和单页 flow，禁止并行编辑，顺序固定为 F191 → F192 → F193 → F194 → F170 → F171。
- 浏览器不直接调用 LangGraph，也不能提交 `orgId`、`ownerUserId`、服务端 NodeMeta、checkpoint ID 或模型 ID。
- `thread_id` 固定为 `sessionId`，`checkpoint_ns` 固定为 `guided-research:v1`；生产不得使用内存 checkpointer。
- 模型只在用户点击 `generate`、`confirm`、`start`、`retry`、`reconfirm` 或 `complete` 的指定边界调用；编辑、查看、步骤切换和 GET 恢复不调用模型。
- 生产模型固定为 `KERNEL_GUIDED_RESEARCH_MODEL_ID=qwen3.7-plus`；配置缺失或 schema 校验失败时 fail closed，不回退 deterministic generator、Mock 或 localStorage。
- Web Search 必须走独立检索端口；Qwen 只负责查询规划、来源判断、证据抽取和报告综合。
- command receipt 与 effect receipt 必须分离；只有 `finalized` command 可短路，同指纹 `pending` command 必须恢复 Graph 并复用 effect receipt。
- 每个切片先写失败测试，再写最小实现；在该 feature 的 `harness verify` 通过前不声称完成。
