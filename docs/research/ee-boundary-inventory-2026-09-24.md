# 企业版边界盘点（C3 第一轮，2026-09-24）

> 人类决策 D21：C3 开始，**先盘点再拆**。本文是盘点，**不动任何代码**；拆分方案需人确认后才执行。
> 目的：给 `apps/api`、`apps/web` 标许可证之前，先弄清里面到底混了多少「将来要卖的企业功能」。

## 结论先行

**归属表列出的企业治理功能，绝大多数还不存在。** 真正已经建出来、又被列为售卖的只有一项：**token 配额（F160–F162）**。
所以 C3 不是一次大拆分，而是两件小事：

1. **现在就立边界**：约定企业版代码放在独立包里，加一道门控保证开源部分不依赖它——趁企业版功能还没写，边界成本最低；
2. **只有 token 配额一项需要人判断**：它算企业版还是开源。

判断之后，`apps/api` 与 `apps/web` 就可以按结果标许可证。

## 逐项实测

归属表「售卖 · 企业治理」一行写的是：SSO/SCIM、审计、多租户、配额、合规导出。

| 功能 | 仓库里有吗 | 证据 | 建议归属 |
|---|---|---|---|
| **SSO**（SAML / OIDC） | **没有** | 登录页原话「社交登录与企业 SSO phase-1 暂不开放」；关键词命中全是「processor」「single signature」这类子串噪音 | 企业版，**未来**写在企业版包里 |
| **SCIM** | **没有** | 全仓 0 处 | 同上 |
| **合规导出** | **没有** | 全仓 0 处 | 同上 |
| **计费 / 发票** | **没有** | 唯一命中是转写契约里的一个无关字段 | 同上 |
| **审计日志** | 有，**但不是企业功能** | 实现的是 D-18「管理员读项目内容必写审计日志且对项目负责人可见」（`identity.ts`、`boundary-screen.tsx`） | **开源**。这是保护用户的信任机制，锁进付费版等于说「只有付钱的客户才知道管理员读了什么」 |
| **多租户 / 平台管理** | 有 | `application/system/*`：平台成员、授予与撤销平台管理员、系统异常、服务可用性；`apps/web/app/platform-admin/*` | **开源**。任何一份部署——包括单组织自托管——都需要一个运维者；这是部署的基本操作面，不是多租户增值 |
| **token 配额**（F160–F162） | **有** | 成员与组织月度额度、用量监控、限额策略；3 张迁移表 | **需人判断**，见下 |

「tenant」关键词在 api 里命中 251 个文件，几乎全部是每张表的 `org_id` 与行级安全——那是**开源部分的地基**，不是企业功能。迭代记录第 53 条早就定过：开源保留单租户 RLS 基座，企业版只加租户路由与配额。

## 唯一的判断点：token 配额

| 读法 | 理由 | 后果 |
|---|---|---|
| **A 企业版** | 归属表原文列了「配额」；它是给有预算管控需求的机构用的 | 把 F160–F162（应用层 3 个用例、2 个仓储、领域求值、管理后台 3 个 tab、3 张迁移表）搬进企业版包；开源版保留**用量计量**（`token_usage_events`，上报契约的用量计数也要用它） |
| **B 开源** | 自托管的小团队同样需要控制模型花费；而且配额的「执行」今天根本不存在（见下），企业版卖的是一个还没兑现的功能 | 不用搬；`apps/api` 与 `apps/web` 现在就能标 Apache-2.0 |

**两种读法都要先修一件事**：盘点时发现 F162 标为 passing，但**调用路径从不求值限额规则，也从不写限额事件**——管理员设了拦截规则，真实调用不会被拦。已单独立 issue #4003，不在 C3 范围内修。

## 提议的拆分步骤（等人确认）

| 步 | 做什么 | 依赖 |
|---|---|---|
| 1 | 立边界：约定企业版代码放 `packages/ee-*`，归属表登记为 sold；`lint-ee-boundary` 断言开源包不 import 企业版包（与 R2、R3 同一种门控） | 无 |
| 2 | 人判断 token 配额 A / B | — |
| 3a | 若 A：F160–F162 搬进 `packages/ee-quota`，开源侧留用量计量与一个「配额检查」端口（开源版默认实现是不限额） | 2 |
| 3b | 若 B：不搬 | 2 |
| 4 | `apps/api`、`apps/web`、`packages/dev-mode-accounts` 按结果标许可证，退出「未定」清单 | 3 |

步骤 1 的边界门控在企业版包出现之前会检查一个空集——它会像本仓其他门控一样**报告「0 个企业版包」而不是判绿**，直到第一个企业版包出现。
