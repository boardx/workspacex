# 开源方案 — 第二轮十次迭代（第 11–20 轮）

> 第一轮（1–10 轮，100 个问题）见 `open-source-business-model-iterations.md`，产出 v11/v12。
> 本轮命题变了：**把方案迭代成一个完整解决方案，并为每一类利益相关者设计各自的体验。**
> 规则不变：每轮 10 个问题，锚定仓库真实事实，标出处；无出处的判断标「假设」。

| 轮次 | 主题 | 致命级发现 |
|---|---|---|
| 11 | 利益相关者盘点 | 漏掉了最终读者、被评估企业、维护者自己 |
| 12 | 个人与小团队 0→1 | 没有定义「第一个价值时刻」，因此无法优化 |
| 13 | 机构采购与合规 | 开源最大的卖点「退出自由」从没写成承诺 |
| 14 | MAAU 作者 | devportal 18 个页面里没有任何发布路径 |
| 15 | 贡献者与维护者 | 维护者自己的体验完全没设计 |
| 16 | 伙伴与渠道 | 把集成商列为风险，却没有伙伴计划去转化它 |
| 17 | 被服务者与数据主体 | 被评估企业没有知情与申诉路径 |
| 18 | 跨角色衔接 | 体验在接缝处断裂，而接缝从未被识别 |
| 19 | 度量 | 仓库已有的反馈闭环是现成资产，方案里没用 |
| 20 | 完整性收口 | 这是一堆改进项，不是一个能开始执行的方案 |

## 第 11 轮 · 利益相关者盘点是否完整

v12 列了 7 类。按「谁掏钱、谁使用、谁受益、谁供给、谁把门、谁被影响」六问重查。

| # | 问题 | 改法 |
|---|---|---|
| 101 | 漏掉**最终读者**（投委会、IC 委员）。报告是给他们看的，他们从不登录产品 | 单列一类，为「不登录的人」设计交付物体验 |
| 102 | 漏掉**被评估企业**。它的财务数据流经系统并被评级，却没有任何位置 | 单列一类，设计知情、更正、申诉 |
| 103 | 漏掉**维护者自己**。开源项目最常见的死法是维护者烧尽，v12 只给了 0.5 FTE 预算，没给体验 | 单列一类，把维护者负荷当作一级设计约束 |
| 104 | 漏掉**销售与实施顾问**。中国市场靠 POC 与实施驱动，这是主要交付角色 | 单列一类，给交付工具包 |
| 105 | 漏掉**安全研究者**。`SECURITY.md` 写了流程，但没设计他们的体验 | 复现环境、时间线通报、致谢署名 |
| 106 | 漏掉**审计方**。金融客户的合规审计要独立核验证据链 | 设计可离线核验的证据包 |
| 107 | 「社区贡献者」粒度太粗。首次贡献者、常规贡献者、维护者候选是三种体验 | 拆成三档，各自设计 |
| 108 | 「机构 IT」与「业务采购方」被合并。IT 关心部署与安全，业务关心结果，**两者各有否决权** | 拆开，分别设计说服路径 |
| 109 | 没区分**买家、用户、受益者**。团队 leader 买、分析师用、投委会受益 | 三者分别设计，不可合并 |
| 110 | 没有**反对者**视角。被替代的初级分析师、被挤掉的外部咨询供应商会在组织内部形成阻力 | 正面设计：把初级分析师变成复核者而不是被替代者 |

**结论**：从 7 类扩到 12 类。少算的 5 类里有 3 类握有否决权。

## 第 12 轮 · 个人与小团队的 0→1 体验

| # | 问题 | 出处 / 依据 | 改法 |
|---|---|---|---|
| 111 | **没有定义「第一个价值时刻」**，因此无从优化，也无从测量 | — | 定义为：上传一份真实材料，拿到第一条带证据引用的结论 |
| 112 | 桌面版首次启动要拉 qwen3.5:4b 权重（GB 级），等待期体验没设计 | `PROP-LOCAL-WORKSPACE-001` | 边下边用示例数据；进度与剩余时间可见 |
| 113 | 本地模型弱于云端，没做**期望管理**。用户会以为产品弱而不是模型弱 | 同上 | 首屏明示当前模型与能力边界，一键对比云端 |
| 114 | 没有示例数据。空产品演示不了价值，而投研材料敏感，用户不会立刻上传真实数据 | — | 内置脱敏示例项目，首次启动即可走完整条链路 |
| 115 | 通用 compose 不存在（第 1 轮已发现），但更要命的是**升级体验**没设计 | `deploy/` 只有 aliyun | 定义升级命令、数据迁移、回滚 |
| 116 | 失败体验没设计：模型拉取失败、端口占用、Docker 未装，各自该显示什么 | — | 每种失败给出可执行的下一步，不是堆栈 |
| 117 | **零出网是卖点却不可见**。egress guard 在跑，用户看不到任何证明 | `local-egress-guard.ts` | 做成可见状态：本次会话出网 0 次，可点开看 |
| 118 | 没有本地→云的迁移体验。用户攒了半年数据，升级时怎么带走 | — | 导出与导入是一等功能，不是补丁 |
| 119 | 断网体验没被当作可验证承诺 | — | 写成 e2e：拔网后本地版全链路仍可用 |
| 120 | 18 个 skill 对新用户是选择过载 | 实测 `find skills -name SKILL.md` = 18 | 按场景收敛成 3 个入口，其余藏进「更多」 |

## 第 13 轮 · 机构采购与合规体验

| # | 问题 | 改法 |
|---|---|---|
| 121 | 采购第一件事是安全问卷，没有预备答案包 | 准备标准安全问卷答案库，随发布维护 |
| 122 | SBOM 脚本有了，但**交付给客户的形态**没定义 | 每个 release 附 SBOM 与许可证清单，可下载 |
| 123 | POC 体验没设计：多久、谁参与、成功判据 | 定义 2 周 POC 剧本与可量化的通过线 |
| 124 | 试用与生产的数据隔离说明缺失，法务会卡 | 写成架构说明 + 可验证的隔离证据 |
| 125 | 私有部署的**升级与补丁体验**没设计：断网环境怎么拿安全更新 | 离线补丁包 + 签名校验 + 版本支持窗口 |
| 126 | 审计导出形态未定。审计员要的是可离线核验的证据包，不是后台页面 | 定义证据包格式：原件哈希、血缘、操作日志、可独立验签 |
| 127 | 权限模型可解释性缺失。RLS 在数据库里，采购方要人能读懂的说明 | 生成人类可读的权限矩阵，随部署产出 |
| 128 | EE 在公开仓库可见，客户法务会问「怎么证明我们没误用」 | 提供自查工具：扫描部署，输出许可合规报告 |
| 129 | **没有退出体验（exit plan）**。这是开源最大的卖点，却从没写成承诺 | 写成明文承诺：不续费后开源部分继续可用、数据可完整导出、有降级路径 |
| 130 | 缺参考架构图与容量规划，实施方无法估硬件 | 按并发与数据量给三档参考配置 |
