## 需求基线：这个 Agent 承诺过什么

功能性的评分对象不是我自己想做什么，而是**需求文档承诺过什么**：

- HMW 卡：帮投后管理人员在编制投后管理报告中，克服「数据局限、行业分析欠缺、
  风险识别滞后」，从而优化财务分析与风险预警。
- MAAU 画布的 Agent 侧分工：①读上传的财务报表出趋势结论 ②从权威公开渠道抓工商/
  诉讼/新闻/研报 ③抓可比上市公司做同业对比 ④结合行业政策与上下游地位出发展预测与
  风险提示 ⑤整合拼接出完整报告初稿。
- 交互时序图：人上传材料 → Agent 五步自处理 → 交报告初稿+数据来源清单 →
  人工逐条核对 → 人反馈修正/补充 → Agent 更新 → 交终稿。
- 测试方案：A/B/C 三组共 15 个隐藏测试点必须能被识别。

### F1 材料摄入（0.8）
投后材料天然是多格式多份（报表 Excel、审计 PDF、经营 PPT、合同 Word、录音）。
- 0.3 走真实附件通道，格式白名单覆盖 PDF/DOCX/XLSX/PPTX/图片/音频
- 0.3 方法论要求用 `wx_document_parse` 读附件，并要求给出「数值 → 来源文件+位置」依据表
- 0.2 解析不了的文件必须单列「未能解析清单」，不静默跳过（"我没读到" ≠ "材料里没有"）

### F2 财务分析与确定性派生计算（1.0）
- 0.3 字段集覆盖投后报告必需的 15 类字段（营收/净利/毛利率/现金流/应收周转/存货/
  研发资本化/补助/集中度/关联方/货币资金/月均净流出/股东协议条款/IP 到期日/里程碑）
- 0.3 六个派生公式有参照实现 + 真实数字单测（A 组 18.2%、80%；C 组 6.2 月）
- 0.4 方法论要求沙箱脚本算、给自检算例、禁止心算，并要求贴出脚本原始输出

### F3 风险识别覆盖（1.5）
15 个测试点（A-R01…C-R07）逐点检查方法论是否具备触发它的判据。得分 = 命中/15 × 1.5。

### F4 外部公开信息与同业对标（0.8）
MAAU 画布明确承诺的两件事，缺一不可：
- 0.3 受限渠道清单（企查查/天眼查/裁判文书网/交易所/证监会/统计局/研报）
- 0.2 每条外部数据带来源标题+URL+发布/获取时间，且与材料内事实分栏
- 0.2 可比上市公司同业对比（选取理由/口径年度/指标定义/偏离幅度）
- 0.1 取不到时显式降级为「未取证」，不得用记忆里的数字顶替

### F5 报告产出与逐数可追溯（1.0）
- 0.4 七件产出齐全（分析底稿/外部对标/风险清单/需核实清单/追问清单/退出前置条件/时间轴）
- 0.2 数据来源清单：每个进报告的数字能指回文件+位置
- 0.2 用 `pdf-create`/`xlsx-create` 出可带走的报告与指标明细表
- 0.2 风险窗口时间轴（政策生效日/合同到期日/回购截止日/专利到期日）

### F6 人在环路（0.9）
时序图里两处人工确认关口 + 定向深挖 + 反馈修正，是这个场景的核心工作方式。
- 0.3 第一轮确认：确认/驳回（写理由）/补充/存疑，且要求后续尊重驳回结论
- 0.3 第二轮：风险分级 + 只做被勾选的深挖 + 深挖结论带算式与出处
- 0.2 反馈修正五分类（算错/对标错/信息误解/信息缺失/主观偏差），主观偏差不改数字
- 0.1 定期报告（周期性任务用 `wx_schedule_create`，不复用旧数据出报告）

### U1 入口一步可达（0.8）
- 0.4 点 `/agent/team4` 直接进真 chat（中转 `replace` 或就地挂壳），不落在自建窄版 UI
- 0.2 Agent 与 Skill 自动就位，用户不需要懂后台、不需要运维改库
- 0.2 不自建第二套上传框/结果面板（chat 已有的能力不重画）

### U2 首次引导与示例材料（0.7）
- 0.3 落地/中转态有一句话说明这是谁、能干什么（不是空白转圈）
- 0.4 三包示例材料（测试方案 A/B/C）可获得，且真含 15 个测试点的触发证据

### U3 失败可读与降级不卡死（0.8）
- 0.3 非管理员撞 `ROLE_INSUFFICIENT` 时降级：可复制方法论，粘进任意对话照样能用
- 0.25 其它失败可重试，不整页白屏
- 0.25 文案是「发生了什么 / 影响哪一步 / 你可以怎么办」，不抛原始错误

### U4 续用与重来（0.7）
- 0.4 线程复用：反复点入口不堆出一串空对话（按标题在服务端搜）
- 0.3 `?new=1` 开全新一轮

### S1 防漂移（0.5）
阈值/公式文字/方法论正文/Skill 身份常量各只有一份，消费方 import 不手抄。

### S2 门控与反证（0.5）
打分器有门控测试；且有反证——篡改被评对象时分数必须下降（证明它真的在读内容，
不是恒返回一个好看的数）。

## 不在这 10 分里的（诚实声明）

**真实模型的输出质量**：命中率、幻觉率、报告可读性。本会话环境没有 docker 与模型
provider 凭据，跑不了真实链路。这 10 分保证的是「能力、判据、材料、入口、失败路径
都到位了」，不是「模型一定答得对」。满分也要在配了真实模型的环境里用三包材料跑一遍
人工核对（通过标准见 `team4-post-investment-report-mvp.md`）。把这两件事混为一谈
就是本仓反复强调的假绿。
