## FR15 / S1 I4、O3：价值与来源先于拆解

原文要求：原始命题提交后显示两个问题：“为什么这是一个值得研究的问题？”“问题来自观察、听到抱怨，还是某种猜测？”学生先回答，再看 AI 反馈；修改命题时保留对应反思。

内容包括：关联原始命题、为什么值得研究、可能影响谁及怎样影响；来源类型可多选（亲自观察／听到抱怨／猜测）、对应事件/原话/猜测说明、尚不确定的地方。理由和来源需填写，允许承认只是猜测或暂时说不清，不要求伪造证据。亲眼观察不自动证实原因，抱怨只表示听到的说法。

O3保存原命题与确认命题的联系、学生理由、来源类型及具体描述、事实/说法/猜测/未解问题、AI追问和学生回应。学生确认自己的理由和依据状态；确认的是研究方向，不表示研究已证实。进入第二步时带入，供真实访谈检验最初假设。

## FR16 / S3 I4、O4：先记录意外或暂无

原文问题：“访谈中，哪些发现与你之前的想法不同，或者让你感到意外？”

内容包括：原先想法、意外发现、差异在哪里、人物发现卡与访谈录音/转写位置；或显式“暂无”。在画像模板之前填写。“暂无”是正常选项，不阻塞画像、不扣分、不强制补访、不由AI编造惊喜。

非空发现必须有关联访谈材料；缺少引用先存待补充。一条发现不自动等于总体洞察，保留少数例外与矛盾，不能把所有人合为同一模式。画像对照此记录保留差异。显示有材料关联/待补充/暂无，状态名称是设计细化。

## FR17 / S4 I4、O4：学生分类与投票分开

原文三类：“最容易实现的、最具突破性的、最有趣的”。

学生在初步整理点子后分类并说明理由，然后投票；AI只能追问，不能自动归类确认。允许同一点子多个标签、暂未分类、类别为空；不要求等量或每点子唯一归类。保留不同成员意见，不把容易实现当成淘汰突破性方向的标准。

三栏/标签视图回到同一原点子引用，分类标签与投票选择分别保存。描述单展示已确认分类标签及理由。至少三份不同点子的描述单要求继续有效，不是三类各一份配额；跨类引用不能复制为多个点子凑数。每人票数/平票/两轮选择规则仍待定，不凭新增分类擅自发明投票服务。

## FR18 / S5 I4、O3：生成前明确要知道什么

原文问题：“通过这次制作原型，你最想知道什么？”

保存入选点子、本轮最想知道的问题、生成前看法或预期及依据；可附记其他问题，不强制未经讨论的量化阈值。未明确主问题可存草稿，但不启动原型生成。AI可追问，不能给一个问题后默认学生接受。

制作说明要解释原型如何帮助观察该问题。O3与版本绑定：主问题、学生先前看法和依据、原型版本、如何观察、当前能/不能验证的范围、待测试。问题修改保留修订，不悄悄覆盖原始预期。每个候选回应同一问题，静态图只能测试理解/意向时须明确边界，不能以口头赞同证明实际时间投入或付费。确认原型连同问题和先前看法进入第六步。

## FR19 / S6 I4、I5、O4：学习与返回路径

原文测试后问题：“测试之后，你对这个问题的认识有什么变化？”

带入第五步同一验证问题与先前看法，学生填写测试后看法、变化或未变、测试材料关联和仍不确定处；可回答“暂未改变”或“证据不足”。变化/不变都需说明依据。不因用户说不错认定解决；改写问题保留原文与原因，不可事后换题伪装成功。

原文本轮结束问题：“如果改进方案，从之前五个步骤，哪一步重新入手？”

学生选择优先返回步骤1理解问题/2共情用户/3综合定义/4创意发散/5原型制作，写理由、关联证据或未解问题、准备重做什么、下一轮想知道什么。可未决定并记录需要教师支持；AI提供候选提示，不自动路由。

O4保存原问题、前后认识、依据/未解、返回步骤、理由、下一步工作、旧/新原型引用（如有）。回第一至四步不强制先做新版，保留旧成果与版本，不清空历史；回第五步继续原型时另存新版并标待测试。本轮学习可先保存，不把认识改变、生成新版或归档等同验证成功。

## 总结、Skill 与跨阶段要求

- 报告输入自动汇集S1 O3、S3 O4、S4 O4、S5 O3、S6 O4；不要求学生重传。报告呈现最初依据、例外、验证前后认识、为什么返回某步及行动。
- 原生同一引导师依阶段使用Skill；不创建七个独立Agent。各Skill输入分别增加上述记录，学生先输入/决定，AI只提问整理。
- 保存须关联测试轮次、问题修订、原型版本和反思；返工保留历史。不因工具失败/缺材料自动推进，不把提示文字当成功文件。
- 学生可以保存未完成稿；八次课映射与阶段进入规则仍待课程负责人确认。不要加入文档没有明确的锁步、配额或评分规则。
- 现有成员文字聊天继续作为全局沟通插件；沿用原生Chat UI，不重造聊天界面。

## 实现映射（工程选择，不是原文或新增服务契约）

共享 API 的 `StageDraft.fields` 已允许最多100个string字段（每值6000字符）；优先以此承载，不扩strict ideas结构。所有新信息必须进入真实共享保存、可读Chat上下文与报告，不只保留本页状态。既有草稿缺少新键时显示未填写，不自动补答案/确认。

| 范围 | 现有fields中的键 |
| --- | --- |
| S1 | whyWorthStudying, problemSources(JSON observation/complaint/guess), sourceDetails, sourceUncertainty, problemReflectionConfirmed |
| S3 | surpriseStatus(none/found), priorBelief, surprisingFinding, surpriseCardIds(JSON), surpriseSourceDetails, surpriseInterpretation, surpriseConfirmed |
| S4 | ideaClassificationTags(JSON ideaId→easy/breakthrough/fun), ideaClassificationReasons(JSON), ideaClassificationConfirmed |
| S5 | verificationQuestion, beforeTestBelief, verificationBasis, verificationLimits, verificationQuestionConfirmed, verificationQuestionConfirmation(canonical确认快照) |
| S6 | questionSnapshot(明确带入的S5问题/先前看法/原型引用/可选S5源revision), afterTestBelief, understandingChangeStatus(changed/unchanged/insufficient), understandingEvidence, unresolvedQuestions, returnStep(1–5/undecided), returnReason, nextAction, reflectionConfirmed |

确认字段表示有权限的编辑者确认这份学生记录，不表示所有成员投票、后台真实性核验、课程完成或测试成功。组件编辑后取消相应确认；报告按有效状态派生，不盲信过期raw true。实际版本/材料缺失时保留缺口。

现有正式 `sourceStageRevisions` 只允许引用更早阶段；不能未经设计签核把Stage6的引用塞入Stage1。优先保存第六步的学习/返回决定，再以实际已保存revision显示返回上下文与导航；跨轮正式来源图若需要扩契约，须另列设计缺口，不伪装已接通。

实现补充：`surpriseSourceRevision` 保存学生使用发现卡确认时实际已读取的第2步共享版本；通过现有 `sourceStageRevisions` 固定历史引用。第2步更新不会把旧发现悄悄解释成使用了新版本，重新核对确认才更新引用。这是现有稿字段的实现细化，不新增后端契约。
