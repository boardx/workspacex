# Directory-only CN release (#5752)

This reviewed partial-release contract implements the human instruction to preserve existing production data and add no permissions. It is separate from the existing unified-source full-release contract; it does not weaken that contract or generate its receipts.

The production baseline is the actual five-container fingerprint, not the stale main-cn pointer. Record both independently; never force-update main-cn to pretend it proves runtime identity. This partial release records a Web source and immutable image ID separately from unchanged API/Agent/Sandbox source/image/container identities. It does not claim every service runs the Web source.

The application backport has exactly one parent, f0eb9d07398a66fdd5646a9e6b855fa1b940e571. Exactly five frontend files must equal the accepted #5710 merge payload bdd0a2911a05ac03de29b2cd2965ab3623116ee7. `directory-release-source.py` rejects all other tree changes, including migrations, dependencies, APIs and permissions. Full bdd0 release is not substituted: its extra migrations are unnecessary for the directory and outside this transaction.

`build-directory-web.yml` builds only this immutable backport, runs the existing real directory browser scenario against its unchanged baseline API and fresh isolated data, and stages the verified archive on the existing host through its existing runner. It neither loads images nor starts production services. Build metadata, source proof, public pinned base digest and archive hash identify the artifact; old candidates cannot be relabelled as the new source.

`web-only-release.py` accepts a root-private reviewed configuration, all original Compose files and interpolation/env file hashes, complete actual baseline fingerprints, immutable Web image and original build archive identity, existing release.lock, and a pinned browser probe/config. Plan mode verifies the baseline public login and directory before producing its reviewable plan. Apply rechecks input hashes and live CAS immediately before one `compose up --detach --no-deps --pull never --no-build web`.

No backend, Sandbox sessions, database or Redis container is restarted. No migrate/bootstrap/admin/seed command, grant, stable-secret change, dependency build/pull or data deletion is executed. Non-Web container IDs, image IDs, start times, configurations, mounts and networks must remain identical. Original Web environment references, mounts and network membership must remain identical too. Runtime image ID, not the unchanged public deployment UUID, establishes source identity.

Candidate public-browser failure restores the original exact Web image through the same original Compose files and image-only override, and reruns baseline public-browser verification. Failed or externally drifted recovery is FAILED_OR_UNCERTAIN, never successful. Retain all prior image/config artifacts. No automatic retry follows uncertain writes.

Production browser checks log in using existing protected credential references and capture desktop/tablet/mobile directory, loaded portraits, filters/empty recovery, official/organization tabs, and selected-role unsent example prefill. Its request guard blocks all non-read requests except existing login; it never enables/imports roles or sends a task. Actual enable/refresh and member boundaries are verified in the isolated compatibility scenario, not by modifying production data. Original selected-image pixel comparison remains unverified.

Execution uses the existing authorized Cloud Assistant root channel and Docker installation, with reviewed bytes staged privately. No new sudo rule, IAM action, account, role or credential is installed. Success requires the actual production browser receipt plus the unchanged non-Web fingerprint, followed by independent screenshot inspection. Health200 alone is insufficient.
