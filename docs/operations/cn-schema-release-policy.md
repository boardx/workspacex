# CN 数据库升级与镜像发布

2026-10-24 用户决定：各环境业务数据独立；每次发布自动处理经过审查的结构迁移，初始化与业务数据变更通过独立操作处理。本轮先规范 CN，DevApp 后续接入。

## 发布边界

- 固定 source SHA、构建 run、镜像 digest 和当前生产 baseline；开始后不跟随 main 移动。
- 以当前应用实际连接的 RDS endpoint、数据库名和完整迁移文件名/校验和确定差异。历史演练连接、迁移数量相同均不能代替身份校验。
- 结构包含表、字段、索引、函数、触发器、RLS 与必要的应用访问授权。字段转换和约束变化必须审查当前数据兼容性。
- 初始化套餐、配置初始值和数据回填必须列入独立清单；不导入其他环境的数据，不因部署覆盖本环境已有配置。
- 不能删掉 SQL 中的数据语句后，仍把整份历史 SQL 登记为已完成；历史文件保持原字节。
- 混合文件使用完整覆盖、不重叠的已审查字节片段，绑定原始及片段 SHA-256。结构组件和组件账本同事务提交；全部组件实际执行后才登记原始整文件 checksum。
- 原自动迁移器不能接管部分完成状态。CN 单次维护期间停止应用写入，保持发布锁，完成明确操作或维持维护；不将部分状态交给旧的整文件 migrator。
- 迁移前生成当前数据库备份；应用镜像回滚不代表数据库回滚。COMMIT 结果未知时保持维护，只核对账本，不重放 DDL。
- 切换只改变应用镜像，保留数据库、业务数据、稳定密钥、挂载与非镜像配置。通过完整账本、实际容器身份和公网登录验收才记录可用。
