# Linux runtime proposal package

`cn-linux-runtime-package.yml` builds only on Ubuntu 24.04 x86_64 / the runner’s system `/usr/bin/python3.12`. This follows the existing system-Python route in `archive-bridge-tests.yml`; no Python setup action or action-audit exception is required. It has contents-read permission, no OIDC, credentials, cloud API or production install step. Root coordinates its PR and explicit dispatch. Do not download the large artifact to a Mac.

Manual inputs bind one reviewed Git commit and the SHA256 of `.github/release-plans/linux-runtime-package/recipe-files.json`. The script checks HEAD, clean checkout and every recipe file before fetching dependencies. npm's full integrity lock is installed with lifecycle scripts disabled; native esbuild is supplied by the locked Linux optional package. RDS distributions and build tools are hash locked; runtime sdists build without network dependency resolution or build isolation. Missing runtime dependencies fail the installed METADATA closure check.

Node 22.20.0 is verified against the official distribution SHA256. Chromium comes from the exact official Playwright 1.62.0 Linux amd64 OCI manifest, not a mutable tag. Only its browser directory is copied. Its full tree and proposed Node executable are hashed; linked/special files and writable group/other modes fail. The source image is not the smoke environment: copied Chrome runs on the Ubuntu runner. Host shared libraries remain a target compatibility requirement.

The actual bundled business entry is executed with malformed synthetic input and must return its bounded failure protocol. A separate real Chromium fixture renders HTML and clicks a button. Offline RDS imports block socket connections and validate installed dependency requirements. These prove package execution, not production business acceptance or cloud access. No session, test identity, private approval or deployment plan enters the artifact.

The tree reader and builder allow 512 MiB only for the exact versioned `chromium/chrome` executable, matching its existing binary pin limit. All other tree files remain limited to 256 MiB (RDS SDK: 32 MiB). The outer package manifest uses the same exact relative-path exception. The first Linux run measured Chrome at 290,614,600 bytes; its entry/browser/RDS smoke completed before the former inconsistent 256 MiB tree limit rejected it. This observation does not certify the completed package. A package passing CI still has `productionProfileReady:false`: actual root ownership, target Node installation/path, Python/Docker/hold-helper hashes and clean host execution require approved installation and readback. A proposed Node hash must never be substituted for the existing `/usr/bin/node` hash.

Successful artifacts contain `business`, `chromium`, `node`, `rds-sdk`, the schema-compatible RDS manifest, a proposal and an external exact file manifest. Upload retains the compressed package for one day. A separate summary artifact contains only control/recipe identity, tar hash and size, file count, browser size and explicit smoke categories (under 256 KiB); it can be read back without downloading the package to Mac. Build failures report only fixed command/error metadata and stderr byte count/hash, never raw dependency output. Failed builds have no successful artifact. No claim about package size or real Linux smoke is made until that GitHub run completes.

Sources: [Node checksums](https://nodejs.org/dist/v22.20.0/SHASUMS256.txt), [official Playwright image](https://mcr.microsoft.com/v2/playwright/manifests/v1.62.0-noble), and exact PyPI URLs recorded in the source lock.
