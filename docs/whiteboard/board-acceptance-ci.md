# Board CI execution and evidence boundary

`.github/workflows/board-acceptance.yml` runs on every PR, push to main, and manual dispatch. Board change scope gates the automatic functional jobs. Manual screenshot capture uses an explicit category input. No new continue-on-error, permission, timeout or concurrency exceptions are introduced. The existing spec-gate can follow each literal `pnpm --filter web run ci:board:*` script to its actual Playwright config. It does not infer reachability from a dynamic lane name.

The existing nine producer lanes remain available. Automatic jobs include journeys, security, Board UI functionality/accessibility (Chromium/Firefox/WebKit), storage, API/WebSocket/ObjectStore convergence and meeting-room endurance. Captured-account import, performance and fifty-client collaboration retain their existing manual entry points. Screenshot capture has a separate manual job. Each owns the standard isolated stack through `with-test-isolation`; that wrapper performs teardown on normal failure/signals. Workflow cancellation does not intentionally interrupt another revision's producer. Job time budgets include build/cleanup headroom; the long tests retain their original 45-minute limit, >=30-minute observation interval, zero retries, fifty independent contexts and twenty concurrent writers. A resource-constrained runner fails; the load is never reduced to fit it.

`apps/web/scripts/board-ci-lane-map.mjs` is the single workflow-to-canonical mapping. The complete producer set covers the canonical twelve lanes: visual fans out to visual and accessibility, while performance fans out to the 1k, 5k and 10k budget lanes. A complete visual result covers visual plus accessibility; the functional-only result covers accessibility and explicitly records visual evidence as deferred-not-verified. Every lane result embeds its actual canonical lane list so downstream evidence collection does not infer coverage from a workflow display name. Import stays fail-closed when the repository variable does not identify the required captured-account manifest; schema fixtures never substitute for it.

The lane runner requires a clean exact revision and isolated environment, invokes the supplied real Playwright command, rejects zero/missing/skipped/retried/expected-failure tests, then reuses the existing evidence policies. The per-run marker and start time bind runtime and report to this invocation. It does not use the global acceptance runner, whose deliberate incomplete/fail-closed aggregate result is unchanged. A lane may pass engineering observations while keeping `approved:false`, `score:null` and explicit pending human/hardware/real-account checks.

Signed lanes generate a cryptographically random, per-job HMAC key in memory, register it with GitHub masking, and inject it only into the child producer environment and same-process verifier. Neither the key nor environment dumps are evidence artifacts. This proves internal artifact integrity, not an independently signed audit or human approval. Reports and screenshots are retained for fourteen days; browser traces are off for these lanes. No production/model secrets or permission relaxations are introduced.

The obsolete `board-three-browsers.config.ts` is removed; the visual lane owns the three-browser matrix and journey has its own evidence-producing config. These replacements do not claim all storage lifecycle or real vendor account acceptance: those remain pending and separate from these CI checks. Existing stronger R7/R8/R9 tests remain untouched.

Storage CI retains allowlisted PG, canonical, migration JSON and screenshot attachments as private files with SHA-256/byte-length descriptors in `playwright.json`. It validates those persisted bytes and all four distinct scenario identities, including each scenario's fresh-server marker, clean source SHA and served build chunk hashes. Missing PG evidence, a missing vendor fixture/screenshot, runtime mismatch or altered attachment fails the lane. The vendor inputs remain schema-derived diagnostics; this is not captured-account migration acceptance or completion of the entire storage lifecycle matrix. Original producer assertions remain in place. Meeting-room screenshot bodies use the same persistence path; configuration, environment, titles, stdout and error messages are not serialized.

The exact-SHA unified runner also exposes executable `storage`, `import`, and `api-ws-objectstore` lanes. Storage reuses the persisted PG/ObjectStore evidence above. Import requires `WHITEBOARD_CAPTURED_VENDOR_MANIFEST` and runs three hash-pinned, redacted Miro/Mural account exports with independent inventories; an absent or missing manifest writes a failed artifact with `CAPTURED_VENDOR_MANIFEST_REQUIRED` or `CAPTURED_VENDOR_MANIFEST_NOT_FOUND` rather than leaving the lane unimplemented. API/WS/ObjectStore runs the public Agent API, real shared-WebSocket outbox convergence, and portable media roundtrip plus revocation-lock race. Each integrated artifact carries the outer run marker, timestamps, exact source/build SHA and served chunk hashes. The runner rejects skipped/retried/missing tests, altered attachment bytes, stale builds, dirty source, missing negative evidence, and pending review states.

## Screenshot-only deferred category (#5308)

The policy authority is [ci-check-policy.json](../../.harness/config/ci-check-policy.json). Its version is read from the historical merge parent when reconstructing past obligations; v1/v2 do not acquire the new exemption. Only the exact `visual-deferred` check is advisory in v3. A missing manual result emits `DEFERRED_NOT_RUN`; failures and pending/terminal outcomes remain visible with their real status and never count as visual PASS. Unknown or inconsistent outcomes fail closed. `board-ui-functional`, Native, and all other existing functional failures still block. The normal PR queue, CLI output and historical doctor report preserve these advisories.

[board-observation-categories.mjs](../../apps/web/e2e/support/board-observation-categories.mjs) defines the categories once. `BOARD_OBSERVATION_MODE=functional` disables the repeated visual PNG capture only; the inherited `only-on-failure` diagnostic screenshot remains available. The category helper also identifies pixel comparisons for future consumers, but no Native pixel path is wired in this main baseline. Both modes execute the same complete [three-browser config](../../apps/web/e2e/board-visual-accessibility-acceptance.config.ts): three visual/accessibility journeys and Chromium's compact chrome journey, without grep, skip or changed expectations. Axe negatives, keyboard/focus, viewport/hit-target geometry, creation, saved canonical data, reload and synchronization remain actual assertions. Mode `all` is the default; unknown modes reject.

The producer writes a distinct `board-functional-accessibility` report and bundle, with screenshot fields exactly `null`. The validator binds the expected mode supplied by the caller, checks all three browsers, viewport/state coverage, runtime/build identity, geometry, axe and native creation evidence, and keeps the full visual entry point unable to accept this functional artifact. Functional summaries retain `approved:false`, `score:null`, `visualEvidence:deferred-not-verified`, and pending independent acceptance. This does not declare visual/human approval.

To request screenshot evidence for an exact published branch/tag/SHA, run:

```bash
gh workflow run board-acceptance.yml --ref <published-ref> -f acceptance_category=visual-deferred
```

This job does not depend on the automatic change-scope output. Selecting it excludes the pre-existing manual performance, captured-import and fifty-client jobs. `existing-manual-lanes` preserves their previous entry point. The screenshot job runs the unchanged full suite in `all` mode and retains `board-visual-deferred-<run-id>-<attempt>` for fourteen days. The blocking functional job retains `board-ui-functional-<run-id>-<attempt>`. Both keep the same exact-SHA runtime binding and original cleanup contracts.
