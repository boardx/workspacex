## Product fixes and remaining limits

Miro REST `captions[].content` now survives as a multiline plain-text canonical connector label. Formatting/routing loss remains explicit; labels above the canonical 1000-character limit report truncation. Per-object style loss descriptions are combined into one report issue, retaining each description while preventing a valid 200-item style-rich board from exceeding the 1000-issue report envelope.

The atomic vendor import limit remains the existing 200-object single source. Oversized boards reject; split source boards or coordinate a separate bounded multi-batch import change. Native RTB is unsupported. Mural REST excludes drawings. API image URLs alone are insufficient: obtain authorized image bytes and supply matching `assetPath` entries in the ZIP. Missing media is a failed item in the report, never a ready placeholder. Vendor import is a **reported subset conversion**, not the lossless portable canonical bundle.

Three real source boards remain a blocking acceptance input. To supply one, preserve the original downloaded bytes, board/vendor identity, collection date and API version, every pagination response (including the terminal page), separate Miro connector responses, authorized local media bytes, and an independently reviewed expected inventory. Keep credentials out of evidence. Record any edits needed to assemble the import package separately from the original responses and hash both. Source and target screenshots must be retained alongside the report. A synthetic case may be used for diagnosis but cannot substitute for any of these three boards.
