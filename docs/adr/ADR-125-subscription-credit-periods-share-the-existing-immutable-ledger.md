# ADR-125: Subscription credit periods share the existing immutable ledger

- 状态: Accepted
- 适用层：项目实现（专属）
- 日期: 2026-10-30
- 关联：#5995

## 背景
已有 owner-global 充值钱包和不可改消费流水。订阅原来只记录状态，无法表达到期额度；直接清空总余额会删除充值，重复发放则会造成额外权益。用户已确认统一 credit 设计、订阅周期清零与个人/企业差异，须在同一账本上实现。

## 决策
采纳 [统一 credit 设计](../superpowers/specs/2026-10-30-credit-subscription-design.md)。公开流水类型及来源的封闭枚举扩展只在 `packages/contracts/src/billing-credits.ts` 声明，数据库对应 CHECK 与它同步。月度额度数值单源为 `billing-subscription.ts` 的 `MONTHLY_SUBSCRIPTION_CREDITS`，不在 SQL 中复制另一个发放常量。

订阅周期批次记录尚未使用额度，原 wallet balance 保持总额投影。永久余额由总额减未到期批次余额计算，不增加第二个可独立更新的永久余额字段。授予、消费、到期都必须在钱包锁内事务提交；消费分配只扣批次，原消费结算负责总余额和唯一消费流水，避免扣两次。周期批次归属沿用已有 user-global wallet 边界；保留可信 HTTP 身份校验，不伪称这些全局表受租户 RLS 保护。

人类采纳记录：用户在本会话明确回复“确认”，随后选择“按计划由当前会话逐项实现”，并指定先合入 develop。已有束级签核文件保持原样。

## 后果
订阅剩余额度可准确过期，充值与欠款保留；重放不会重复授予或清除。所有余额访问需要周期归一化和钱包锁，增加一次数据库事务内读写；异步查询、回调与到期任务必须共用锁顺序。新增批次仍继承原 owner-global 钱包对受攻陷 app_rw 的可见面，公开读取必须核对付款方或使用人，不借此扩大用户权限。

## 备选

仅更新一个总余额无法清除赠送部分；另建独立消费账本会导致消费事实与扣费口径分叉。持久化永久余额、月度余额和总余额三份可写字段也容易漂移，故保留可推导字段并在同一事务维护总额投影。
