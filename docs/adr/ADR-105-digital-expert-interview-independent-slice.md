# ADR-105: 数字专家访谈采用独立交付切片

- 状态: Proposed
- 适用层：项目实现（专属）
- 日期: 2026-08-11

## 背景

最初登记在 Phase 03 的数字专家访谈 F48–F54 依赖数字专家治理 F42/F43；F43 又依赖决策台账和组织知识晋升链。该依赖图使一个只输出探索性报告的访谈工作台必须等待完整治理体系，无法形成可独立验收的产品切片。

已经存在且通过验证的共享能力包括组织鉴权与 RLS、Artifact/file-first、Context Pack，以及 Phase 01 的 interview 范围模型。这些能力足以支撑一个“只读数字专家目录快照 + 访谈域内探索性结果”的最小闭环，而不需要提前实现组织级强洞察或晋升入口。

## 决策

新建 Phase 04 `digital-expert-interview-studio`，把数字专家访谈定义为独立垂直切片。具体 feature、状态和验证命令只在 Phase 04 的 `feature_list.json` 与契约束中声明。

访谈域复用既有 Agent/Context/Artifact/Identity 契约：保存专家与材料版本的只读快照和来源指针，不创建第二套组织级数字专家身份。所有访谈发现恒为探索性，并在访谈 API 与报告中保留专家、问题、回答和材料来源；本阶段不提供写入强洞察、决策依据或组织晋升的出口。

Phase 03 原 F48–F54 在进入 sprint 前撤回，原需求和签核材料迁入 Phase 04，避免两个阶段同时成为同一功能的权威来源。

## 后果

正面影响：访谈可以沿已通过验证的共享契约独立交付；依赖图缩短；历史、快捷对话、五步批量流程和报告能用真实 API/DB 做端到端验收；不会为了赶进度复制数字专家身份或 Context 读取逻辑。

负面影响：Phase 04 产出的探索性发现不能直接进入强洞察、决策依据或组织晋升；未来接入这些出口时，仍必须完成 Phase 03 的全局 `synthesized` 强制策略，并通过新的跨束一致性复核。专家目录采用版本快照，来源版本变化需显式刷新，不自动改写已完成访谈。

## 备选

1. 继续等待 Phase 03 F16/F20/F42/F43：一致性最强，但把访谈 UI 与组织治理关键路径绑定，无法独立交付，因此否决。
2. 在 interview 内重新定义完整数字专家对象：可以快速开工，但会制造第二份身份、材料边界和来源标记事实，违反单一事实源，因此否决。
3. 只做前端 mock 原型：能展示界面，但无法验证恢复、失败重试和报告溯源，且错误会被伪装成静态数据，因此否决。
