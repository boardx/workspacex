# ADR-109: 数字访谈报告采用可恢复增量流

- 状态: Proposed
- 适用层：项目实现（专属）
- 日期: 2026-09-03

## 背景
旧报告流每次进度更新都返回完整 `DigitalInterviewWorkflowView`。专家档案、问题、回答、
历史报告正文等稳定字段在每帧重复；实测 16 帧达到约 1.14 MB，其中大部分是重复内容。
随着报告正文增长，累计传输量近似二次增长，也更容易触发代理超时与浏览器网络错误。

同时，报告任务必须允许刷新或断线恢复，因此不能只依赖浏览器内存里的增量。

## 决策
报告 NDJSON 连接采用连接内状态投影：

1. 每条连接以一条紧凑的、已持久化 `snapshot` 开始；快照只含报告生成态，不含专家、
   问题、回答等稳定工作流输入。
2. 后续只发送 `meta`、`finding`、`section` 增量。`section.markdown` 是相对上一持久化状态
   的精确后缀，浏览器只能追加，不能替换或重新拼接旧正文。
3. `complete` 和 `error` 是轻量终止事件；完成后浏览器只额外读取一次完整终态工作流。
4. 每条连接使用从 0 开始、严格递增的 `seq`。重连会获得新的 `snapshot(seq=0)`，以服务端
   持久化状态重新建立基线；不维护跨连接的永久事件日志。
5. 增量投影器遇到正文回退、既有 finding 被修改等非 append-only 状态时 fail closed，避免
   静默重复或损坏报告。

## 后果
正面影响：传输量从“每帧复制全部历史”变为“一次报告快照 + 新增内容”，稳定工作流数据
不再进入报告流；客户端追加语义明确；刷新恢复仍以数据库事实为准。

代价：服务端需要维护连接内投影状态，客户端需要按序应用事件；报告完成时仍有一次普通
工作流 GET。因为不保存永久事件日志，断线重连会重新传一次当前报告快照，但不会重放专家、
问题、回答，也不会在同一连接中重复正文。

未选择的方案：JSON Patch 对当前单向追加模型过于通用且难以审计；仅发送 token 会让刷新
恢复依赖浏览器内存；继续发送全量工作流会保留已确认的带宽与超时问题。
