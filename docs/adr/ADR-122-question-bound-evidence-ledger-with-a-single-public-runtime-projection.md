# ADR-122: Question-bound evidence ledger with a single public runtime projection

- 状态: Proposed
- 适用层：项目实现（专属）
- 日期: 2026-10-05
- 关联：#5365、#5366

## 背景

研究执行会经历重试、暂停、计划调整与正文变化。按章节数组下标缓存证据会把旧结论错误地关联到新问题，重新抽取全部材料也会重复模型工作。现有公开 runtime 是严格契约；把服务端证据账本直接放入响应会泄露内部引用与校验资料。用户报告半小时仍未完成，但当前没有该会话的可信后端诊断；此决策不把静态代码候选当成根因。

## 决策

沿用现有严格 quoteRef 校验作为语义证据入口，不增加向量索引、嵌入、置信度分数或第二个语义判定。账本只保存已经读取的真实正文：正文哈希必须与保存的 contentHash 一致，原始 chunk 和精确引用跨度可逐字复验。检索摘要保留原有兼容用途，不成为已核验账本证据。

问题身份使用稳定 sectionId、完整问题文字哈希和该问题的确认依据。重新排序不改变身份；问题删除、确认依据变化、正文变化、来源被排除或来源策略变化使记录不可复用。direct 与 context 分开，context 不补足 direct 覆盖。记录保存服务端 evidenceId、来源和任务、正文哈希、chunk、原文跨度、引用哈希、校验版本与时间。

账本记录和容器的 Zod 定义按仓库契约单源规则放在 packages/contracts/src/research-private-evidence-ledger.ts，通过显式内部子路径引用；它不注册公开操作，也不扩展公开 runtime 响应。账本写入现有租户隔离的 runtime JSON。内部 PersistedResearchRuntimeSchema 扩展公开契约，只增加可选 privateLedger，旧 JSON 仍合法；现有租户鉴权、请求幂等、版本 CAS、租约与暂停规则保持同一权威。对外唯一投影从公开契约字段集合正向选择，再以公开严格 schema 校验。GET、命令所有提前返回、重放和 SSE snapshot/result 都经过此投影；公开 delta、progress 和 fingerprints 不增加私有字段。

本 issue 交付账本与保存/公开边界基础；有界补搜、跨来源事实检查、写作全面读取账本与正文引用核验分别由 #5367、#5368、#5369 承担。整体十分钟是软目标，不引入整体 180/600 秒强制失败。

## 后果

精确证据可以跨执行版本保存并被确定性复验，同时对外 runtime 不扩大私有数据暴露面。持久化 JSON 体积增加，需要记录上限与失败闭合校验；旧会话不能凭旧摘要补造已核验账本。未来调整记录格式需要校验版本迁移。账本本身不保证搜索或报告性能；真实会话诊断和完整真实模型链路验收仍是独立必要证据。
