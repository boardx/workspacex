# ADR-021: context-pack 丢弃原因新增 unlocatable

- 状态: Accepted
- 适用层：项目实现（专属）
- 日期: 2026-07-29
- 关联：`context-pack` 束 I-1 / I-2 · `design-coherence.md` 修订 E-4 ·
  D-U4（丢弃原因是封闭枚举，新增走 ADR）

## 背景

丢弃原因是**封闭枚举**，新增必须走 ADR——这条是 D-U4 定的，理由是：
它承载「为什么这条没给你看」的可审查性，而**开放结构必然长出几十种说法**，
几十种说法等于没有说法。

F09 实现结构契约时撞到一个原来七种表达不了的状态。

## 问题

`context-pack` 的 I-1 写的是：定位不到 ⇒ 落 `omissions` **或** 抛 `ANCHOR_MISSING`。

但七种原因里**没有一种表示「定位不到」**：

| 原因 | 说的是 |
|---|---|
| `withdrawn` / `expired` / `unauthorized` | 合规或权限**不许**给 |
| `low-confidence` / `budget` / `deduped` / `out-of-scope` | 相关性或容量**不值得**给 |

「找得到、也该给，但**说不出它在哪**」不属于任何一类。

于是这类条目**既不被引用、也不被解释**——而那正是 I-2（每条未入选的都要有交代）
存在的全部理由。实现者面对它只有三条路，每条都坏：

1. 硬塞进 `low-confidence` —— **说谎**，它不是低置信
2. 一律抛 `ANCHOR_MISSING` —— 一张定位不到的照片让整次装配失败
3. 静默丢弃 —— 直接违反 I-2

## 决策

**新增第八种：`unlocatable`，`compliance: false`。**

```
unlocatable: 找不到可用的锚点（页码/时间码/消息/图像区域），
             无法给出可回溯的引用位置
```

### 为什么 `compliance: false`

定位失败是**技术问题**，不是合规丢弃。

标成 `true` 会让它进入「必须始终可见、不因只显示前 N 条而被折叠」那一栏——
**把真正的撤回/过期条目挤下去**。合规栏的价值恰恰在于它短。

## 后果

- 丢弃原因由 7 种变 8 种。`OMISSION_REASON_KEYS` 是派生的，前端与门控自动跟上。
- ⚠ **这不该成为常态路径。** 修订 E-1 补了 `imageRegion` 之后，绝大多数「定位不到」
  应当消失。`unlocatable` 数量居高不下就是**锚点模型有洞**的信号
  ⇒ 建议 F11 把它纳入可观测指标，而不是只当一个枚举值放着。
- **与 E-1 的关系**：E-1 是**修因**，本 ADR 是**兜底**。
  只做兜底会让照片永远进不了 Pack、却每条都带一个体面的解释——**那比报错更糟**。
  两件都要做。

## 备选方案与为什么否决

| 方案 | 否决理由 |
|---|---|
| 复用 `low-confidence` | 说谎。用户看到「低置信」会去调阈值，而问题在锚点 |
| 一律抛 `ANCHOR_MISSING` | 一张定位不到的照片让整次装配失败，代价与问题不成比例 |
| 让 `anchor` 可空 | 直接推翻 I-1「每条引用必须可定位」——那是 AI 引用可信度的地基 |
