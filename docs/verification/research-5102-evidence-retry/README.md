# #5102 原子证据块精确修复

原流程任一条证据失败即重做全部batch，且最终响应可保留部分无效块中的个别有效match。现在每块必须完整通过严格结构、来源/块/问题ID、逐字quote、irrelevant一致性、重复冲突校验。已完整验证的块不进入可归属失败块的修复；包含错误的块整体隔离，不会保留其中好match。

坏JSON、未知来源/块、坏信封或超限响应仍修复整batch，首轮不保留无法可信归属响应的块。最终可保留个别完整有效块但明确报告排除警告。任何坏身份声称已知chunkId都会隔离该块，顺序无关。无完整证据则拒绝。晚到修复不得覆写未被请求、已验证的块。

并发2、内容修复最多2次以及既有提供方重试不变。稳定batch/块顺序汇总不变。修复input仅含待修复块和对应坏evaluation；已验证块不被再次传输，无法归属错误仍含整批修复上下文。

沿用DebugTracePort记录research.report.evidence_attempt：原因分类/块数/attempt/耗时/sessionId/request trace；不写来源文本、问题、rawOutput、模型错误正文或密钥。记录器同步best effort；失败不能破坏业务。服务及kernel只做现有port依赖接线，kernel行数不增加、没有放入业务功能；纯校验拆在独立领域文件。公开API schema及正式报告门不变。

反证：初始6项全部失败。保留单位变化要求原“整batch丢弃”测试明确验证仅保留完全正确块，错误quote不泄漏；原警告夹具按source-a稳定ID制造错误，避免缩小retry后index0变正确。独立审核发现同块正确+伪造sourceId可残留，已修复；实际函数四种顺序/缺失身份均两次后拒绝，新增26重试测试覆盖该反例。最终6文件117项通过，API typecheck/lint及默认init快速路径通过。

合成反例3块中1坏：repair供应块3→1，首轮2个整块保留。诊断确认原因与非负耗时，服务接线确认records不含原文、sink故障仍正常生成。不是实际provider速度或全部报告质量通过。现有公开WCAG案例原日志只记invalid_model_evidence，无法回溯把24个failed modelCalls归为JSON；新打点供后续同配置复验。

边界：模型仍可错误判定相关性，逐字摘录并不自动证明推论成立；后续章节质量门与正式发布门仍负责。真实同配置质量和耗时复验待进行，#5056保持open，导出排除。禁止合并本PR。
