## 目标

用测试方案 v1.0（同一份需求文档 §9）的测试 A、B 作为验收标准，做一个**真正能跑**的最小版本：
用户在 `/agent/team3` 能和一个真实发布的 Agent 对话，粘贴文字、上传 PDF/文件、或给
一个 URL 提供访谈转录稿或产业链材料，
拿到测试 A、B 要求的结构化分析（里程碑、瓶颈原话 vs 转述、矛盾并列、隐性风险、切入点建议）。

## MVP 边界（做什么 / 不做什么）

### 做

1. **一个真实发布的 Agent**：用仓内已有的 `AgentDefinition` 机制注册「前沿赛道技术路线研判」，
   `instructions` 直接编码三步工作流里「采集与整理」这一步的分析纪律（专家原话与转述分开标注、
   引用可定位、矛盾并列不裁决、隐性风险靠关联推出不编造）。
2. **复用现有 chat 基础设施**：`/agent/team3` 打开一个绑定该 Agent 的真实对话（不是占位页），
   走仓内已有「新建对话 + 挂载 Agent」的路径，不新建后端接口、不新建领域表。
3. **工具白名单只给分析需要的**：文档解析、知识检索、web 只读检索——按需选择，不给写外部、
   不给图片生成、不给 SQL、不给 MCP。
4. **知识图谱画布（UC-T3-6 收窄版，人类 2026-09-15 追加要求）**：用仓内**已有的 fabric.js 画布管线**
   （`apps/web/components/chat/chat-diagram-fabric.tsx` / `chat-canvas-fabric.tsx`，同款机制已在
   `standard-canvas-tools.ts`/`wx_canvas_update` 里对 Agent 开放）渲染产业链节点图——上中下游分区、
   节点四态配色、点击节点看固定/动态属性与依据。**不做**版本历史下拉、版本差异对照、多图谱选择器、
   反馈卡片、对话分支——这些仍在「不做」清单里，只做单一当前版本的只读可视化 + 点击详情。
5. **验收**：用测试 A、B 的材料（转录稿 + 产业链纪要/政策汇编）作为真实上传内容跑一遍对话，
   核对输出覆盖测试方案给出的标准答案要点（里程碑数量、原话引用、矛盾识别数、隐性风险命中），
   并核对 Agent 能借助 `wx_canvas_update` 把材料中出现的产业链环节画成图。

### 做（2026-09-15 人类推翻原计划追加：「把产业图谱做完整」）

6. **图谱版本历史 + 版本差异对照**（原 UC-T3-7）：每次 agent 改图都留一个版本，用户能翻
   历史版本、能看两个版本之间逐项差异（哪个节点状态变了、哪条边变了）。
7. **多图谱选择器**（原 UC-T3-6 未做的那半）：同一项目/线程可以有多张命名图谱
   （如「产业链总览」与某个专题图），用户选择看哪一张、在哪一张上继续。
8. **反馈卡片**（原 UC-T3-8）：用户对图里某处判断有异议时，能提交结构化反馈
   （问题在哪、为什么、建议怎么改），agent 据此产出修订版本；UI 渲染成可确认/可拒绝的卡片，
   不是一条普通聊天消息。
9. **对话分支**（原 UC-T3-9）：能回到历史某个点继续——「新建分支」（独立推进，不动主线）
   与「基于最新继续」（保留历史引用）两种方式。

> ⚠ 上面四条原本在「不做」清单里（理由是临时 agent 不值得）。2026-09-15 人类明确
> 「推翻原来的计划」「就把产业图谱做完整」，因此移进「做」。实现纪律不变：优先复用
> 仓内既有的画布/产物版本化、线程与结构化卡片机制，能不新建表就不新建。

### 不做（记入 backlog，非本轮）

- UC-T3-4/5 的字段与判断逻辑确认卡仍推迟，降级为对话文字确认（见下方「明确的技术债」）。
- 数月后自动提醒回填、预测对比、工作流变更记录——UC-T3-10，测试 C 对应这部分，本轮不做。
- 材料人审三态卡片式 UI（待审/缺失/错误逐条勾选）——本轮先用普通对话来回代替，不做专门 UI。
- Agent 主动自搜（不给 URL 也自己去网上找材料）与真实语音转录管线——本轮只吃用户
  直接给的材料（粘贴文字 / 上传文件 / 给一个 URL），不主动出去找。
  用户给 PDF 或 URL 本身**在本轮范围内**（2026-09-15 人类追加要求）：复用平台已对
  每个 agent 开放的 `wx_document_parse`（文档解析）与 `fetch_url`/`web_search`
  （网页抓取），不新增工具准入代码，只在 instructions 里讲清楚可以这样用。
- 管理后台专门为 team3 定制的配置页——复用已有 admin agent 配置页。
- BOM 拆分口径确认卡（UI-01）、判断逻辑步骤确认卡（UI-02）——降级为 Agent 在对话里用文字确认。

## 验收标准（对齐测试方案 v1.0）

| 测试 | 通过判据（摘） |
|---|---|
| 测试 A（专家访谈转录稿） | 里程碑 ≥5 且带位置；两条路线瓶颈用原话；判断归拢 ≥3 条论据 |
| 测试 B（产业链纪要+政策汇编） | 上中下游成文；矛盾 ≥2 处且给采信理由；隐性风险命中 ≥1；≤500 字建议 |

测试 C（年度复盘）依赖 UC-T3-10（不在本轮范围），留作下一轮 backlog 第一项。

## 实施步骤

1. 注册 team3 `AgentDefinition`（复用已有创建机制，实际做法见实现 PR）。
2. `/agent/team3` 从占位页改为跳转/内嵌到与该 Agent 绑定的真实对话。
3. 用测试 A、B 材料手工过一遍真实对话，记录输出，对照通过判据逐条核对，证据存 PR 描述。
4. 验证跑绿后按 ad-hoc SOP 直接开 PR，`Refs` 关联一个跟踪 issue。
