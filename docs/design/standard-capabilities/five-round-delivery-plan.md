# 五轮交付计划

日期：2026-09-07。目标：完成 capability-catalog.json 的 75 项验收缺口，使 development-flow.md 中对应范围全部有真实绿色证据，并使汇总 PR #2869 达到可合并状态。保留用户“暂不合并 main”的约束。

本文件管理迭代，不复制能力定义或修改 harness passing。原编号、需求和验收仍以 capability-catalog.json 为准。每轮独立提交与证据更新到同一 PR；“可合并”必须以该轮冻结 SHA 的完整 CI、review 与无冲突证明，不能只看本地测试。

## 每轮先估时、三次优化、再定计划

1. 核对最新代码、验收、运行中的资源和实际可工作的 Agent，给出初估。
2. 优化一：复用与删重。删掉已经验收的开发，只保留必要集成；不删需求。
3. 优化二：并行与职责拆分。独立模块交 Agent，接口与共享文件有唯一 owner；云端只有返回实际执行证据才计入产能。
4. 优化三：缩短验收关键路径。共享一次隔离栈批测、复用镜像缓存、冻结待提交文件、提前运行 CI；不得跳测试、权限门控或把未知结果改成成功。
5. 固定本轮 items、owner、依赖、验收、预估及主要风险，再执行。下一轮开始前用实测时间重新做三次优化，不能照抄本次预测。

以下单位为小时，是工作假设，不是实测性能提升。第 1 轮现在固定；第 2–5 轮为候选计划，开轮时重新评估。包含一次顺利 CI 的时间，额外失败修复和云端不可用会延长；后续轮的独立实现可以提前并行，验收关口按轮次推进。

| 轮次 | 初估 | 优化一后 | 优化二后 | 优化三后目标 | 当前状态 |
|---|---:|---:|---:|---:|---|
| R1 已验证增量收口 | 1.5–2 | 1–1.5 | 0.75–1.25 | 0.5–1 | 固定并执行 |
| R2 原生运行闭环 | 3–4 | 2.5–3.5 | 1.5–2.5 | 1–2 | 开轮复估 |
| R3 检索与文档覆盖 | 4–6 | 3–5 | 2–3.5 | 1.5–3 | 开轮复估 |
| R4 浏览器与全部 Skill 验收 | 4–6 | 3–5 | 2–3.5 | 1.5–3 | 开轮复估 |
| R5 跨模块与最终 PR 门控 | 3–4 | 2.5–3.5 | 2–3 | 1–2 | 开轮复估 |

优化后各轮验收窗口合计 5.5–11 小时。并行准备可能缩短实际总历时，但尚无云端执行证据，不能额外扣除。当前不能承诺此前更激进的估时。
