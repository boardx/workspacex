# T010 explicit read-only attachment delegation

The catalog points to official synchronous `task(description, subagent_type)`, not the W16 asynchronous subtask store. No W16 files, queue state, cancellation engine, task parser or journal are changed.

The existing `general-purpose` remains text-only. When the trusted native factory receives an input manifest, it additionally registers an explicit `files-readonly` CompiledSubAgent using official `create_agent` and `FilesystemMiddleware(tools=['read_file'])`. Selecting that subagent delegates the current attested attachment set. Task prose is never parsed for file IDs or scope. This does not implement arbitrary per-call subsets or skill delegation.

`ReadOnlyDelegatedInputs` is a BackendProtocol capability wrapper. It permits exact paths from the immutable manifest and forwards read/aread to the existing HttpSessionSandbox; upstream read_file continues to format text, paginate lines and produce image blocks. No custom read tool, command parser, shell or file-copy engine is introduced. No write, execute, ls, grep, skills, parent custom tools or parent workspace paths are registered. Filesystem result eviction is disabled for this read-only child, so it cannot acquire a hidden write path.

Each actual child tool dispatch first checks the existing parent authority and then the source proof. The proof uses trusted run_control_callback identity and the actual tool-call ID/args; the expected file is selected from the parent manifest closure, not model identity. HttpFileDelegationAuthority reuses the existing absolute-deadline/bounded/no-redirect HttpNativeToolAuthority transport with an exact request/response schema override. It fails closed on missing callback, non-input path, denial or unknown response. ToolAuthorityError is already excluded from native retry.

The TS NativeFileDelegationProof reuses current PgNativeRunInputs.read: current human source-message binding, current thread visibility, object head/bytes/digest validation. Under the same DatabasePort tenant transaction it checks actual parent/attempt/epoch authority, then compares the exact current manifest entry to the pinned entry with canonicalNativeInputs. It introduces no SQL lookup or alternate visibility engine. Cancellation before dispatch, moved/private/revoked source, changed bytes and namespace mismatch deny the read. Like existing authority, this is authorization at dispatch, not a claim that an already-delivered model context can be recalled.

Composition root dependency: NATIVE_FILE_DELEGATION -> NativeFileDelegationProof(db, authority, PgNativeRunInputs(db,objects,{repo,ids,chat})); register NativeFileDelegationController. Root owns that kernel hunk. The internal endpoint is POST /internal/agent-runs/:runId/delegation/files/check with the existing internal key guard. Python inputs come only from resolved native-session manifest. Existing legacy graphs and text-only delegate remain unchanged.

Evidence distinctions: the core tests inspect official read_file function identity, tool allowlist and sync/async denied dispatch; real sandbox tests separately prove bytes returned and read-only /inputs. The PG/HTTP fixture uses actual ToolExecutionAuthority, PgParentRunControlReader, current source reader, object store, and a real private-owner change/cancel commit. With an explicitly owned container it launches a Python runner that executes two official task calls and observes actual source bytes. The runner uses real HTTP authority with a persisted task-only run grant, not a default allow. External models are replaced by a scripted model; no external model quality claim is made.

Initial fixture failure was a missing interjections/poll route in the standalone Nest fixture. It was fixed by registering the actual RunInterjectionController with real PG repositories, not by disabling parent middleware or weakening fail-closed behavior. The default old e003 image rejected input mounts; final sandbox tests use the existing input-capable w02-inputs image and the unchanged restricted sessions compose profile. No production deployment is changed.
