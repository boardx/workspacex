# W06: WX-T014 web_search / WX-T015 fetch_url

Implemented standard LangChain StructuredTool wrappers call the trusted internal bridge. The bridge validates service credentials, exact tool arguments and tool call ID, parent run/attempt/lease through actual ToolExecutionAuthority, then reads the real organization to deny local-only egress. Callback tokens are never model tool arguments or tool results. Default native policy treats both tools as L2; grants/HITL remain the existing control plane.

## Reuse decision and scope

The design catalog originally proposed Tavily. Current WorkspaceX already uses `GoogleGuidedSearch` for research. We reuse that adapter and provider protocol, configured by the existing `KERNEL_GUIDED_SEARCH_URL`, with the shared guarded fetch enforcing a 10-second wall-clock/network body limit. We do not introduce a second search engine or a Tavily credential/deployment dependency. Source limits differ: Google adapter exposes at most five candidates; `domains` filters only these returned candidates, `limit` is 1–5, `timeRange` only accepts `all`. Unsupported date/filter shapes fail validation. Outputs explicitly name provider, candidate cap, snippet content and post-filter semantics; an empty filtered set does not establish no source exists on the web.

Installed AnyDoc 0.1.8 supports document formats, not HTML (verified its Format enum and [official repository](https://github.com/firecrawl/anydoc)). It cannot supply the catalog's webpage extractor. HTML instead reuses [Mozilla Readability](https://github.com/mozilla/readability) 0.6.0 with jsdom 30.0.1. Official npm metadata requires Node ^22.22.2 / ^24.15.0 / >=26; validation host Node22.23.1 meets it. Readability uses Firefox Reader View's maintained extractor. No custom HTML/extraction engine was built.

Fetch accepts public HTTPS HTML or UTF-8 plaintext/Markdown only. It rejects all redirects, authentication in URLs, private literals and actual connection-time private DNS answers, non-UTF8 declared encodings, compressed responses, missing/unsupported media and extraction failure. PDFs/Office/OCR/login/browser-rendered pages are unsupported here, not silently treated as plain text. Existing AnyDoc document processing remains unchanged.

The response body is capped at 1MiB. HTML parsing runs in a Worker with 128MiB old/32MiB young generation limits and a 5-second termination deadline, plus Readability's element limit. At most two parsers run per API process; excess requests fail immediately, and capacity is released only after worker termination confirms. jsdom's default script execution and remote resource loading stay disabled; no `runScripts` or `resources` option is enabled. Raw HTML is not returned. Output text is capped at 60,000 UTF-16 code units with `truncated` and a SHA256 of full extracted text. `sourceId` is SHA256 of normalized URL without fragment, so search and fetch preserve source identity; snippet and extracted-text hashes have explicitly different provenance.
