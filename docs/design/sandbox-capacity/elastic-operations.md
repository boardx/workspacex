# Sandbox 阿里云弹性容量操作手册

适用状态：未来集群实现的建设与发布步骤；截至 2026-10-29，本轮没有部署节点代理、调度器或自动扩容控制器。关联 issue #5980。

容量算法、指标定义、试验参数、负载和验收阈值只定义在[实现方案](elastic-implementation.md)，本文引用，避免重复漂移。现有单机配置仍以[当前操作说明](../../../.harness/instructions/project/sandbox-capacity-operations.md)为准。

## 1. 谁负责、什么时候需要人工

| 工作 | 负责人 | 是否日常人工 |
|---|---|---|
| 初次开通 VPC、RAM、镜像仓库、ESS、日志和预算 | 运维/云账号管理员 | 一次性配置、权限变更时需要 |
| 实现调度器、节点代理、容量控制器 | 研发 | 上线前需要 |
| 压测并确定任务规格、容量和预算 | 研发 + 运维，产品确认服务目标 | 初次及大变更需要 |
| 监测、增减空位、新建 ECS、排空回收 | 上线后的控制器 + ESS | 正常情况下自动 |
| 云配额不足、预算到顶、严重故障 | 值班人员 | 告警后处理 |

自动扩容会产生实际云费用。文档交付不等于授权采购；首次生产启用前，资源归属人须确认地域、预算、最大规模与 RAM 权限。日常在已授权边界内扩容无需逐次确认。

## 2. 现在可以执行的只读检查

在仓库根目录检查生成器和当前接口；这些命令不会创建云资源：

```bash
git log -1 --oneline
rg -n 'sandbox|network_mode|mem_limit|cpus|SOCKET' packages/cloud-deploy/src/compose.ts
rg -n 'capacity|healthz' apps/skill-sandbox/src/server.ts
```

目标主机上先由运维取得当前 release 指针及 Compose 参数，再按现有操作说明从已有 API 容器读取私有 `/capacity`；不要猜项目名，不开放公网端口。记录实际镜像 digest、容器资源限制、Session 数、宿主 CPU/内存/磁盘与运行任务。

只修改 `/etc/workspacex/sandbox-capacity.env` 不能启动跨机扩容；增加并发也不改变容器 CPU、内存硬限制。现有两个服务的 1 CPU / 1 GiB 配置以生成器为事实来源，不能直接拿来承诺 500 人容量。

## 3. 阿里云控制台建设顺序

以下是运维操作清单，必须在未来集群软件验收后执行；当前不存在一键初始化命令。

1. **选择地域**：CN 执行节点、数据库、文件存储尽量同地域内网；devapp 单独建测试资源。填写账号、地域、VPC、子网/交换机、镜像仓库、资源标签、配额、预算和告警联系人。
2. **网络**：创建专用执行节点安全组。仅允许调度服务访问代理私有端口；不开放公网执行 API、Docker API 或数据库。控制通道 mTLS；执行容器默认禁网，镜像/升级流量由可信宿主控制。
3. **RAM**：控制器使用工作负载角色，限制到指定伸缩组和必要只读查询/伸缩操作；节点身份不持有伸缩权限。私钥和长期 AccessKey 不写镜像、代码、任务环境或日志。记录权限资源范围并做拒绝越权测试。
4. **镜像**：构建版本锁定的可信节点镜像，含容器运行时、代理和所需执行镜像缓存。登记 digest；开机脚本只做注册和自检。逐任务隔离运行时使用方案选定的 gVisor runsc/systrap，锁定完整发行包，在 CN 验证包分发可达性；不运行在线脚本临时拼装运行时。按设计完成兼容性和性能验收后才允许正式接单。
5. **ESS 伸缩组**：创建专用组，选择已验证的实例规格/启动模板、交换机和跨可用区分布；从单节点压测计算最小、最大、初始期望数，核对 ECS/vCPU 配额。明确单节点故障余量不等于整可用区容灾。
6. **控制权**：选择“应用容量控制器调整期望数”这一条主控制路径。关闭会同时修改同组期望数的其他动态/预测规则；云侧健康替换与应用账本协调。先运行 shadow（只计算、不修改云资源）比较建议值与实际需求。
7. **生命周期**：新增实例先自检、注册 ready；缩容先由应用选空闲候选并排空，再通过已验证的指定实例移除流程释放。挂钩超时策略必须验证；到期可能释放实例，不能把挂钩当永久保护。活跃节点启用伸缩保护，保护随排空状态管理。
8. **监控与费用**：收集实现方案要求的业务和宿主指标；对低余量、启动延迟、节点失联、指标缺失、扩容失败、OOM、费用/节点上限告警。控制器日志记录决策输入、期望数、云活动 ID、结果，禁止记录脚本、原始用户身份及凭据。

## 4. 研发落地顺序

按实现方案 A→B→C→D 推进，每步单独 issue/PR 与验证证据。普通 `/run` 与 Native Session 同时验证，不能只打通新入口、遗留调用绕过全局额度。

实施前必须补齐：contracts 里的代理协议和状态机；数据库迁移；可信身份传递；安全的跨机文件传输；取消与 unknown 处理；资源规格与隔离运行时；ESS 幂等操作与指定节点排空。预算、控制周期等参数只保留一个版本化配置源，禁止散落在开机脚本和控制台的多份副本。

建议实现的运维能力（尚无现成 CLI，不得复制为当前命令）：查看 ready/占用/预留/启动容量；冻结扩缩容；调整授权上下限；指定节点排空；查询 executionId 与 Session 路由；查询控制器 leader、fencing generation 和云活动。所有管理动作需鉴权、审计。

## 5. devapp 验收 → CN 上线

1. **基线**：先保存当前生产和测试环境配置、版本、故障率及费用。用独立测试账号和文件，不复制生产用户数据。
2. **节点验证**：一台测试 ECS 完成真实 PDF/Office/数据任务、资源峰值、文件隔离、取消、目录清理测试。得到每类任务规格、执行时长和每节点安全容量。
3. **两节点验证**：在一个节点创建多个固定 Session 并同时提交命令，确认每个 ready Session 的预留可兑现；固定 Session 路由、重复提交、租约超时、节点断联、控制器切换、全局用户额度、PG 故障全部跑通，确认没有重复执行。
4. **真扩缩容**：在有限预算的测试伸缩组触发真实新增节点，计时到可执行自检；注入启动失败、配额拒绝，验证告警与去重。缩容时保持一个活跃 Session，证明它不会被选中释放。
5. **500 人测试**：执行实现方案第 7 节完整负载，包含实际 UI/API/模型链路。只有连接成功、回环模型成功或队列接受成功均不能放行。
6. **CN 预检**：按实际地域重新核对镜像拉取、配额、模型配额、VPC、对象存储及启动时间。保留验证过的镜像 digest 和配置版本，遵循仓库现有 CN 发布流程，不手改活动 Compose。
7. **灰度**：按组织/新 Session 逐批切换集群适配器；已有本机 Session 留原路径直至结束。每批观察至少一个完整任务周期及扩容窗口，指标越界停止扩大。
8. **启用自动**：shadow 验证通过后才允许控制器写 ESS；核对最小/最大规模、费用上限、告警送达及回滚负责人。保存启用审计和验收报告。

## 6. 日常观察与故障操作

| 现象 | 首先检查 | 操作 |
|---|---|---|
| 启动变慢、CPU 不高 | 空位、Session 占额、文件准备、PG 连接、资源预留 | 定位阻塞，不盲目提高容器并发 |
| 期望数增加但没有 ready 节点 | ESS 活动、配额/库存、镜像拉取、代理自检、网络 | 告警、排除失败节点、限次重试；不将启动中当现成容量 |
| OOM/磁盘不足 | 单任务峰值、规格错配、空闲 Session/临时文件 | 节点停止接单，保留诊断，调整规格后重测 |
| 控制器失联 | leader 租约、数据库、指标新鲜度 | 决策实例按租约接管；云写入 actuator 须先隔离旧实例并对账未决活动，无法确认时冻结写入并告警；缺测时停止缩容 |
| 节点失联 | 心跳、云实例状态、在途 execution | 隔离节点并 fence，活动结果标 unknown/失败，禁止盲目重放 |
| 费用/最大节点到顶 | 实际任务增长、预算、云配额 | 通知负责人决策；保留准入保护并记录服务目标违约 |
| 缩容卡住 | 仍有任务、有效 Session、挂钩剩余时间 | 保留节点并告警，不能强杀以实现费用目标 |

故障时取消/超时仍必须能生效，不能把“等待扩容”变成无限挂起。队列和额度用于保护系统，不能在统计中掩盖容量不足。

## 7. 回滚

先冻结自动缩容及新增集群流量，保留现有已就绪容量。新 Session 可切回已验证的本机适配器；旧集群 Session 继续固定原节点直至结束或显式终止，不能随机搬到本机。

本机路径容量更小时，应限制入口或保留集群承担负载，不能一键切回后仍宣称支持同样 500 人。已开始或结果 unknown 的任务不自动重试。数据库迁移先采用向后兼容的增量方式，不在回滚时删表。执行节点排空后才回收，保留观测和审计证据。

## 8. 发布记录模板

- 日期 / 环境 / 变更负责人 / issue 和 PR：
- 精确镜像 digest / 配置版本 / 数据库版本：
- 实例规格 / 最小最大数量 / 每节点验证容量 / 故障余量：
- 任务样本版本 / 到达率 / 突发规模 / 500 人持续时间：
- 全请求数 / 拒绝与失败数 / 启动延迟 P50/P95/P99：
- 扩容就绪时长 / 峰值资源 / OOM / 费用：
- 取消、幂等、节点故障、Session 排空证据：
- 业务 API、实时连接、数据库、真实模型配额结果：
- 灰度范围 / 停止条件 / 回滚版本 / 告警联系人：

没有实际数据的字段留“未验证”，不填写推算成功值。
