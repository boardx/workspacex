# ② 用例（待签核）

UC-C1 创建课程：当前org的lead/admin显式填课程名并提交。服务端保存Course与幂等身份；失败保留名/operationId，重试不得重复建课程。普通member/consultant不能用手写URL创建。

UC-C2 关联已有小组：管理者从自己已加入且为owner的AIDT general Project选择。服务端再次核对course可管理、org一致、group owner及active；一组一课由唯一约束保证。没有合格小组时提供“新建小组”原生入口，不用自由标签假装关联。

UC-C3 学生重新进入：登录→AIDT课程列表→课程中自己在册的小组→原有 `/aidt/:projectId` 六步。新浏览器和重启后从服务器回读；无localStorage课程表。旧的未绑定小组仍出现在“其他学习小组”，不迁移或假推课程。

UC-C4 组间隔离：同课程的A/B组为不同Project，现有Stage/Chat/成员频道/资源授权继续有效。A成员看不到B组名/人数/内容；手写B URL/API仍由原权限拒绝。课程管理者未加入B也不因此能读取B成果。

UC-C5 成员维护：组内继续现有ProjectCollaboratorsPanel及原生授权操作。角色、邀请和退组不是课程列表的隐式副作用。首版不新增课程学生注册或独立教师权限。

UC-C6 撤权/切换：新列表请求或动作遇到401/403/404时清本次已读课程组投影；旧success/error不得让新账号/新org/已撤权状态回退。返回同一actor的ABA视为新生命周期。成员移除后重进不可读，错误不泄露他组正文。
