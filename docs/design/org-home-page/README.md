# 组织首页 + 后台配置 —— 设计原型

> 用户提供了一张参考截图（宽版 labeled 侧栏 + Banner + 快捷入口 + 任务/公告侧栏），要求：
> 每个组织可以有自己的首页，后台有配置页（logo / 标题 / 一句话 / banner 等），配置完成后
> **全部成员登录后先进入自己组织的首页**。
>
> 这是**设计原型**（纯静态 HTML），未改生产代码。色值/圆角/阴影镜像
> `apps/web/app/globals.css` 的既有 token，左侧导航直接复用已核对过的真实结构
> （见 `docs/design/ai-workspace-redesign/v4-nav.html`：13 个一级入口、五段分组顺序不变，
> UC-0.4 R4 A1 锁定）。

| 文件 | 内容 | 截图 |
|---|---|---|
| `home.html` | 组织首页（成员视角） | `shots/home-default.png`（桌面）、`shots/home-mobile.png`（手机） |
| `home-admin.html` | 首页设置（组织管理员后台，带实时预览） | `shots/home-admin.png` |

## 与参考截图的差异，以及为什么

参考截图左侧是一条宽版、带文字标签的导航（Home / Chat / Projects / Board / Agents / Knowledge / Templates / People / Settings），这与目前生产代码里**已经确认、多轮人类裁决锁定**的
76px 窄图标栏（`apps/web/lib/navigation.ts` 的 `NAV_SEGMENTS`，13 个一级入口、五段分组，
UC-0.4 R4 A1）是两套不同的信息架构。本设计选择**忠于真实产品的导航**，只在其最上方新增
一条「首页」（见下方「未决问题」①），其余分组/入口原样保留——而不是照抄参考图那套导航,
那会让"评审看到的和用户实际用的不是同一个产品"（本仓已经因为这类不一致返工过，见
`ui-preview/README.md` 的历史教训）。

## 组织首页（`home.html`）

结构：**顶部搜索/通知/头像**（全局，不属于首页配置）→ **Banner**（logo/标题/一句话/背景，
全部来自后台配置）→ **Universal Ask**（向 WorkspaceX 直接提问/下达任务，压在 Banner 下沿）
→ **快捷入口 4 宫格**（后台可配置显示哪几个、顺序、文案）→ **最近内容**（项目/Board/文档/
对话四个 tab，读全局既有数据，不属于"首页配置"范畴）→ **右栏**（我的任务 / 组织公告 / 邀请
团队，各自独立开关）。

- 首页只在**用户登录后的第一落点**出现（对应参考图"Home"的位置），不替代 `/chat` 或
  `/projects` 本身——原有入口都还在，只是不再是登录后看到的第一屏。
- 底部浮动条`仅组织管理员可见：这是你们的首页 / 预览为普通成员 / 编辑首页`：管理员自己访问
  首页时看到，一键跳转到后台配置，不需要先找菜单。
- 响应式：≤860px 导航栏隐藏（复用真实 `icon-rail.tsx` 已有的 `md:` 断点做法）、单栏、
  快捷入口 2×2、Banner 收窄。

## 后台配置页（`home-admin.html`）

三栏：真实 `admin-nav.tsx` 视觉语言的后台左栏（新增「首页设置」一项）→ 中间表单 → 右侧
**实时预览**（内嵌 `home.html`，缩放展示，修改表单即时反映，支持切桌面/手机预览）。

配置项分四组，对应 `home.html` 里的四个区域：

1. **身份**：组织 Logo（复用既有 `Organization.avatarUrl` 字段）、标题、副标题（留空则自动
   显示"企业空间 · N 位成员"，与成员配额模块联动，不是第二份人工维护的数字）。
2. **横幅**：标题、一句话、背景（4 个预设渐变 + 自定义上传图片二选一）、可选的"观看介绍"
   按钮（文案 + 链接，留空则不显示，不强迫每个组织都要挂一个视频）。
3. **快捷入口**：最多 4 个，可拖拽排序、可关闭（关闭的入口本身功能不受影响，仍能从左侧
   导航访问——首页配置只决定"要不要在首页露出"，不是能力开关）。
4. **信息板块**：右栏"我的任务/组织公告/邀请团队/最近内容"四个板块的显示开关，关闭后数据
   仍在，只是首页不展示。

操作栏：`恢复默认` / `仅自己预览`（不影响其他成员看到的版本）/ `发布给全部成员`（真正生效的
动作）。草稿自动保存，未发布前只有编辑者自己看得到改动。

## 数据模型建议（未落地，仅供后续 feature 参考）

```
OrgHomeConfig {
  orgId: string
  title: string              // 默认取 Organization.name
  subtitle: string | null    // null = 自动显示成员数
  bannerHeadline: string
  bannerTagline: string
  bannerBackground: { kind: "preset"; key: string } | { kind: "image"; url: string }
  bannerCtaLabel: string | null
  bannerCtaUrl: string | null
  quickActions: Array<{ key: string; enabled: boolean; order: number }>  // 最多 4 个enabled
  sections: { tasks: boolean; announcements: boolean; inviteCard: boolean; recentTabs: boolean }
  publishedAt: string | null  // null = 仍是草稿，成员看不到
  draftUpdatedAt: string
}
```

## 未决问题（需要人类决定，本轮不擅自定）

1. **导航要不要真的加一条「首页」**——✅ 已裁决并落地（2026-09-29）：`lib/navigation.ts`
   新增 `key: "home"`，href `/home`，排在未分段那组最前面（`chat` 之前）。
2. **多组织成员登录后去哪个组织的首页**：仍沿用既有 `session.currentOrgId`（当前登录会话
   所在组织），未新增"默认组织"概念——本轮不引入第二套组织记忆机制。
3. **未配置过首页的组织显示什么**——✅ 已裁决并落地：不是"官方欢迎首页"里编出来的示例内容，
   而是契约层的固定默认值（`get-home-config.ts` 的 `DEFAULT_HOME_CONFIG_*` 常量：通用横幅文案 +
   4 个快捷入口全部启用 + 空的组织推荐列表），首次进入即可用，不强迫组织先配置才能看。
4. **首页是否允许"仅自己预览"之外的分级发布**：本轮**没有实现**草稿/发布两态——
   `/org-admin/home-config` 保存即生效（同 `/org-admin/profile` 的既有模式），没有
   "仅自己预览"/"发布给全部成员"的中间态。若要分级发布，是独立的后续 feature。

## 已实现（ad-hoc，Refs #4634 / #4660，与本文档「后台配置页」一节的原型差异）

真实后端落地时对原型做了几处**刻意的范围收窄**，记录在这里避免下次有人对着原型问
"为什么生产环境跟这张图不一样"：

- **Logo**：复用组织已有头像（`org-menu.tsx` 既有上传入口），首页配置页**没有**单独的
  logo 上传控件，不新增第二个头像来源。
- **横幅背景**：4 个预设渐变（`ocean`/`forest`/`sunset`/`midnight`），**没有**自定义图片
  上传（原型「4 个预设 + 自定义上传二选一」里的后半段本轮未做）。
- **草稿/发布**：没有实现，见上方「未决问题」④。
- **右栏板块**：原型的"我的任务/组织公告/邀请团队"三个板块**没有落地**——这些数据源
  （任务清单、组织公告）本仓当前没有对应的真实契约，不编造假数据源。取而代之的是新增的
  两个真实数据板块（见下方），范围比原型窄但每一项都接的是真实契约。
- **快捷入口**：固定 4 个已知路由（对话/项目/Board/大脑），管理员只能勾选启用/禁用，
  **没有实现拖拽排序**（顺序固定为这四项的声明顺序）——原型里的"可拖拽排序"未做。

### 范围新增（超出本文档原型，来自后续人类需求）

用户在后台配置之外，另外要求首页能"推荐这个组织推荐的 agent/skill"、"继续之前的工作"，
两块都是真实数据、非本文档原型范围：

- **组织推荐**：管理员在 `/org-admin/home-config` 从真实 `listAgents`（仅已发布/运行中）/
  `listSkills`（仅已启用）里选最多 6 个，选中时把展示名快照进配置（`RecommendedCapability`），
  首页读取不反查那两个 admin-only 接口。
- **继续你的工作**：每个用户自己的真实数据（`listPersonalThreads` 最近对话、`listProjects`
  未归档项目），不是组织级配置项，两条请求独立拉取、互不影响。

契约、后端垂直切片、`/home` 消费与 `/org-admin/home-config` 编辑器均已实现并通过
`tests/home/home-config-authorization.test.ts`（5 个真实 Postgres 集成测试）验证。

## v2（Refs #4698，用户看过上线版后的反馈）

- **首页不显示顶部 header**：`app/home/page.tsx` 给 `AppShell` 传 `hideTopBar`。
- **横幅**：8 个预设渐变 + **自定义 `#RRGGBB`**（文本框与取色器双向同步，非法值即时报错，
  自定义底色上的字色按 WCAG 对比度在浅/深两档里自动选）+ **上传背景图片**（PNG/JPEG/WebP，≤5MB，
  服务端重做体积与 magic-byte 校验，存对象存储，表 `org_home_banner_artifacts`，形状同组织头像）。
  优先级：图片 > 自定义色 > 预设；图片拉不到回落配色。后台有与成员所见同一组件（`HomeBanner`）的实时预览。
- **推荐 Skill 直达对话**：首页点击 Skill = 新建个人线程 → 读挂载列表拿乐观锁版本 → 挂载该 Skill →
  进入 `/chat?thread=<id>`（`lib/start-chat-with-skill.ts`），第一轮消息发出前 Skill 已在线程上。
  挂载失败（权限/未启用）不假装成功：留在首页显示原因并给出已建空对话的入口。
- **推荐数字人（最多 6，带头像）**：后台候选来自成员可读的 Agent 目录（`listAgentDirectory`，只含已发布且对
  当前人可见的）；选中时快照名称/角色/头像 key（本仓 Agent 头像是插画 key，未知 key 回落首字母）。首页点击 =
  `/chat?agent=<id>` 与该数字人开始对话。
- **继续你的工作（卡片）**：对话（摘要、状态、产出物数）、项目（类型、标签、**协作者头像与名字**；工作坊项目走成员表，
  一般项目走协作者表，取不到就整块省略）、深度研究（进度条）、用户访谈（专家完成数）、问卷（收集中/草稿）。
  各类各自独立请求、独立降级，拉不到的类别整组隐藏，全空时如实说没有。
- **默认模块扩充**：快捷入口由 4 个扩到 10 个（聊天、项目、深度研究、用户访谈、问卷、录音、设计、大脑、Board、任务），
  未配置过的组织默认开前 8 个；另有「当前任务」栏（我的任务 + 进行中的项目）与「继续你的工作」两个整块开关。
  ⚠ 「当前任务」用 `GET /tasks/today`，它需要一个项目作锚点（后端未做跨项目聚合），与 `/tasks` 页同一处置：取第一个未归档项目。
- **每个首页都有「提交反馈」**（`FeedbackRow`，产品级反馈；不受组织配置影响，配置加载失败时也在）。

仍未做（保持原型差距）：草稿/发布两态、拖拽排序、logo 单独上传、录音卡片（录音没有可打开单条的路由）、设计卡片。
