# Team3 当前版本测试文档

> **版本定义**：main 上已合入的 team3 相关改动 + PR #3692（图谱版本化 / 差异 / 多图谱 / 内嵌 chat）。
> **用途**：人工在真实环境（devapp 或生产）逐条过，判定「这一版到底能用到什么程度」。
> **原则**：本文只列**当前版本真的能测**的项。测不了的单列在 §4，不混进用例里冒充覆盖。

## 0. 前置条件

| # | 条件 | 不满足会怎样 |
|---|---|---|
| P1 | 部署已跑过 `.harness/scripts/vm/deploy.sh`（含步骤 4d2 的 team3 补种） | `/agent/team3` 报「本组织尚未配置…Agent」 |
| P2 | 当前登录用户所属组织**名字正好是 `Workspace`** | 同上（补种脚本只种这个组织） |
| P3 | 部署已配置可用的模型供应商 | 能进对话但发消息后 run 失败 |
| P4 | 该用户在组织内至少能建项目 | 首次进入时建项目锚点会失败 |

> ⚠ P1–P3 未确认前，下面任何一条失败都**不能**判定成功能缺陷——先确认环境。

## 1. 入口与会话（T-01 … T-03）

| 编号 | 步骤 | 预期 | 判定 |
|---|---|---|---|
| T-01 | 访问 `/agent/team3` | 直接进入聊天界面（不是落地页+按钮）；地址栏保持 `/agent/team3` | 出现输入框与历史区即通过 |
| T-02 | 刷新页面 | 回到**同一条**对话，不新建空线程 | 线程标题仍是「前沿赛道技术路线研判」，历史消息还在 |
| T-03 | 观察左侧/顶部能力 | 附件上传、历史、编制等 chat 能力可见 | 与 `/chat` 同款壳即通过 |

## 2. 材料输入与分析（T-10 … T-14）

材料取自需求文档 §9 的测试方案（虚构材料，可直接粘贴）。

| 编号 | 步骤 | 预期 | 判定 |
|---|---|---|---|
| T-10 | 粘贴测试文件 A（陈教授访谈转录稿）全文，要求：提取里程碑、列两条路线瓶颈原话、归纳 2030 判断及论据 | 回复中里程碑带时间与出处位置；瓶颈用**引号原话**；判断给出 ≥3 条论据 | 见 §3 测试 A 判据 |
| T-11 | 上传一份 PDF（可把测试文件 B 存成 PDF） | Agent 读到内容并据此分析，不是说「我看不到附件」 | 回复能引用 PDF 里的具体数字/企业名 |
| T-12 | 给一个公开网页 URL，要求据此补充 | Agent 抓取并引用该页内容 | 回复含该页实际信息；抓不到时**明说抓不到**而不是编 |
| T-13 | 粘贴测试文件 B 三份材料，要求指出矛盾 | 矛盾**并列**列出双方出处，不直接裁决；给采信理由时标注是推断 | 见 §3 测试 B 判据 |
| T-14 | 问一个材料里没有的信息 | 明确说「未在材料中找到相关信息」 | 出现编造即失败（这是硬规则） |

## 3. 验收判据（来自测试方案 v1.0，原文判据）

**测试 A（专家访谈转录稿）**

| 判据 | 通过线 | 备注 |
|---|---|---|
| 里程碑数量与位置 | ≥5 条且注明原文位置 | ⚠ 见 §5 已知偏差：材料本身只支持 4 条 |
| 两条路线瓶颈原话 | 超导、离子阱各一条，**原话**非转述 | 离子阱应出现「激光打不准」那句 |
| 2030 判断论据 | ≥3 条 | 加分：识别出反问句那条隐藏论据 |
| 综合 | 3 项优秀 / 2 项通过 / ≤1 项需调整提示词 | |

**测试 B（产业链纪要 + 政策汇编 + 内部纪要）**

| 判据 | 通过线 |
|---|---|
| 产业链上中下游及国产化程度 | 成文，分层清楚 |
| 信息矛盾 | ≥2 处，且给出采信理由 |
| 隐性风险 | ≥1 个（EDA 空白 / 人才断层） |
| 建议 | ≤500 字 |
| 综合 | 矛盾≥2且采信有理=通过；隐性风险命中≥1=良好；四项全达标=优秀 |

## 4. 图谱能力（T-20 … T-26，PR #3692）

| 编号 | 步骤 | 预期 | 判定 |
|---|---|---|---|
| T-20 | 用测试文件 B 要求「画出产业链图」 | 回复中出现一张**可交互**的图（不是一段代码文本） | 图能点开放大即通过 |
| T-21 | 检查图内容 | 上中下游分层；节点带判断状态；连线体现供应/应用关系 | 只是照抄材料名词而无判断状态 = 未达标 |
| T-22 | 检查图之后的文字 | 每个节点状态有文字依据 | 只有图无依据 = 未达标 |
| T-23 | 保存该图 | 保存成功，成为一份产物 | |
| T-24 | 让 Agent 改图（如「把 EDA 标成严重缺失」）后再次保存 | 成为**同一张图的第 2 版**，不是第二份互不相关的产物 | 产物列表仍只有一行该图 |
| T-25 | 打开「版本」面板 | 看到版本线：版本号、时间、来源、内容哈希 | 至少两行 |
| T-26 | 查看差异 | 列出结构化变化（新增/删除/改动的节点与边） | 改了状态应显示为 changed 而非 added+removed |

## 5. 已知偏差与限制（测之前先知道，避免误判为 bug）

| # | 现象 | 原因 | 是否缺陷 |
|---|---|---|---|
| L1 | 测试 A 只能提取到 4 条里程碑 | 测试方案标准答案里的「2025H1 千比特原型机」「2027 逻辑比特<1e-6」**不在测试文件 A 原文里**（前者出自测试文件 B） | **测试文档自身不一致**，非实现缺陷。按材料如实提取 4 条是正确行为 |
| L2 | 只能比较「最新保存版 ↔ 当前画布」，不能任选两个历史版本互比 | 版本列表给了版本号但没给读字节所需的版本标识，补齐需要第二处契约改动 | 已知缺口，PR #3692 中如实记录 |
| L3 | 「审核/通过」这类流程门不存在 | 当前版本没有工作流状态机（见 `agent-team3-activity-flow-analysis.md`） | 未实现，非 bug |
| L4 | Agent 不会主动上网找材料 | 明确不在本轮范围 | 未实现 |
| L5 | 录音转录未验证 | 工具在平台工具表里，但从未真机验证过 | 未知 |
