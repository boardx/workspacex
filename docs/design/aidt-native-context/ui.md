# ① UI：在现有 Chat 中说明实际采用的材料

本页是待签核设计，不是已实现界面。继续使用 WorkspaceX 原生 Chat v2 的 composer、发送/运行状态、确认卡、消息、重试及产物；不做第二套聊天 UI，不增加第七步。

## 学生路径

1. 进入任一步后，沿现有 Skill 就绪流程确认实际 thread 和固定 Skill 版本。在现有教学来源区域显示准确的六步顺序及当前标题：第一步“理解与提出问题”，第二步“共情用户”。当前任务、期望产出与已保存版本供学生核对，不当成研究证据。
2. 只读材料区沿用现有阶段来源/返工详情。每条材料列出“第几步、V几、已保存/尚未选择/正文摘录截断”。选择的是确定修订，不会在发送时换成服务器新 head。学生当前未保存的表单不自动接入。
3. 学生在原生输入框写话并主动发送。输入框与持久 human message 逐字保留；host 只附命名 selector，不在背后加提示词正文。selector 尚未形成时，使用既有发送准备/失败状态保留输入，提示重试材料读取；普通 Chat 无此 host 时行为不变。
4. 服务端受理后，来源区域可展开该 run 的真实AIDT回执；不新增默认展开的大型技术面板。正常显示“本次材料已准备”；只有收到实际组装/首次消息派发或checkpoint继承回执后才分别显示相应状态。不要用“快照已创建”表示“模型已读到”。
5. 原生 `confirm_task_intent` 的误识仍由学生选择编辑/拒绝，不自动改卡；学生的修改与原始误识均保留。程序只确保当前阶段和真实材料送达，不代学生宣布决定。

## 来源、缺口和失败状态

| 状态 | 现有区域中的反馈及行为 |
| --- | --- |
| 快照已准备 | 列出实际 run、所选版本和缺口；“已准备”不代表派发或生成成功 |
| 模型输入已组装 | 展开来源时可见 snapshot/输入块 hash 及对应 attempt；不展示原始 prompt/凭据 |
| 首次消息已向原生 Agent 服务派发 | 仅在真实派发事件后显示；不等于供应商完整 prompt 已被独立检查或回答正确 |
| 同一checkpoint恢复 | 显示沿用原快照和首派发关联；本次没新messages不显示新的材料派发时间 |
| 尚无共享保存记录/未选择材料 | 显示实际缺口，允许仅讨论问题；不补造访谈/教师点评/学习轮次 |
| 部分正文被截断 | 显示哪些摘录被截断，保留真实版本定位；不要说材料全文已经发送 |
| 指定来源无权/不存在/返工目标不匹配 | 本次不派发、不自动改选最新；保留学生输入，统一“材料不可用，请重新核对” |
| 服务端读取或准备失败 | 本次不创建可执行 run；保留输入和选择，使用原生失败/重试；不能显示空材料成功 |
| 提交成功但回执读取失败 | 保留原 clientMessageId/run，显示“回执未核对”；重读或重连同一运行，不新发模型 |
| 同一输入的选择发生变化 | 要求学生作为新消息明确发送，不复用旧幂等键暗换材料 |

材料来源详情同时说明：“这里只纳入小组共享阶段与指定返工/历史；个人检查点和个人 Artifacts 未纳入本次服务端快照。”原有个人检查点 UI/人工查阅可继续使用，这句话不表示其原功能未开发。原始文件只呈现引用定位，不假称已读字节、已转写或已验证。

## SUM

报告按钮仍进入已安装 `dt-summarize-project` 的原生线程，是六步后的报告任务。学生先核对本次六步/历史版本，再点击带入请求、审阅并发送。生成后沿既有主动选择消息/产物→预览→勾选审阅→追加到当前报告→显式保存/导出流程。读取失败、没有教师点评或没有返工记录都保留缺口；不覆盖学生稿，不声称已创建 PDF/Word。
