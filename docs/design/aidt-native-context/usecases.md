# ② 用例与可反证的验收

本轮用户会话已批准以下规格，当前实现验证中；逐项是否实际通过另以证据记录。真实旧 S1 误识保留，不用学生修卡后的成功冒充模型自动正确。

| 用例 | 具体输入/触发 | 必须成立的结果 |
| --- | --- | --- |
| UC1 S1 阶段 | 第1步 thread 挂 `aidt-understand`，学生只写原命题 | 服务端派生第一步准确标题/任务，参考块明确六步；human message 逐字等于输入 |
| UC2 其余五步 | 在各步当前 thread 发送，带实际所选已存版本 | 挂载 Skill 与 stage 匹配；不会把通用五阶段顺序覆盖六步编号 |
| UC3 精确旧版 | UI 选 S5 V1，别人已保存 V2 | 本次快照仍取 V1，来源写 V1，不静默更新到 V2 |
| UC4 确定返工 | 回 S2，selector 指 S6 V7；该版选择返回 S2 | 只取真实 V7 的反思/问题快照；内含 S5 来源修订原样保留，不换当前 S5 head |
| UC5 错返工目标 | 回 S2 却指向“返回S4”/未确认/暂未决定记录 | 不把它当本次确定返工；明确拒绝该 selector，保留输入，学生可清除选择后另发 |
| UC6 SUM | 总结 thread 挂真实 `dt-summarize-project`，选定六步及有界历史 refs | 服务端回读精确修订；保存次数不冒充学习轮数；无记录、未决定、截断、没有教师点评均明确 |
| UC7 无材料 | 实际无共享保存记录，或学生尚未选择某些步 | 区分“服务器无记录”与“有记录但未选择”，可提问/生成带缺口草稿，不编造经历 |
| UC8 个人稿 | 浏览器有个人 Artifact/检查点正文 | v1 不据此读入模型；显示未纳入，不能把已在前端读取当作服务端已授权 |
| UC9 幂等重试 | 同 actor/thread/clientMessageId、原文、附件及 selector 重放 | 同一 run、同一 snapshot/hash；不重读新 head、不新增模型运行；当前权限仍重查 |
| UC10 幂等冲突 | 相同消息键更改 selector/refs/返工版本 | 冲突，旧消息与 snapshot 不变，不用新材料续旧 run |
| UC11 HITL/resume | 已暂停 run，随后出现新 head/客户端新 context | 同 run 继续用原快照；客户端新 selector 不替换它；重新验权限，不能拿审批放行当资料授权 |
| UC12 错范围 | 甲组 thread 搭乙组 project/ref，即使用户同时是两组成员 | 拒绝且不返回乙组摘要；principal、thread、project 与实际 pin 全部一致才可准备 |
| UC13 非成员/撤权/关闭模块 | 普通外组成员、仅组织管理员 observer、移除成员、AIDT关闭 | 统一不可用；不读正文、不派发、不发快照回执数据；普通无selector请求不受影响 |
| UC14 模型/角色伪造 | body.context 放 system/role/正文/教师点评，selector 添未知字段 | 不提升为指令/权限，不传该正文；selector严格拒绝未知键，既有正文消息不被改写 |
| UC15 准备失败 | 精确版本不存在、数据库故障或读取超时 | 无可执行的半成品 run/snapshot；没有“空材料已准备”；保留学生输入可重试 |
| UC16 派发失败 | snapshot 已准备，模型输入组装/发送失败 | 回执分别显示真实准备/组装/派发状态；不称“模型已读到”或“报告已生成” |
| UC17 跨域/普通Chat | 同源及允许的本地Web/API origin；普通thread不带selector | 现有鉴权/CORS不放宽；普通请求无AIDT表写入/回执字段/依赖 |
| UC18 marker缺快照 | AIDT run的marker非null但快照缺失/摘要不符 | 执行失败，不按ordinary降级，不重读最新材料补齐 |
| UC19 checkpoint无新消息 | 恢复只有command、未序列化新messages | 记录恢复与继承的首派发关联，不伪写本attempt材料派发时间 |
| UC20 学生审阅 | Agent产生回答或报告 | 不代保存/确认任何阶段；真实输出仍需学生选择、修改、保存；静态/无网络测试不等于教学质量验收 |

## 证据层级

1. **契约/纯函数**：selector严格解析、6步映射、摘要预算/UTF-8截断、规范化hash，恶意正文不晋升指令。
2. **应用+真实controller无网络反例**：当前失败样本必须修后通过；检查 context 不只留在 wire，而是服务端选择→快照→真实 ModelCallInput 的块 hash 一致。普通消息原文和普通Chat断言保留。
3. **真实 PostgreSQL**：消息/run/snapshot同事务，CAS/相同键冲突、唯一快照、RLS、撤权、归档、精确旧版、两张AIDT表的append-only、marker缺失失败、resume与重启后原快照回读。无 fixture 的事实另记。
4. **本机原生真实运行**：沿既有收费总账和批准窗口，不自动追加模型次数。采集实际挂载、server snapshot/hash、组装/原生服务派发证据及 durable assistant/run。只存合成材料与安全摘要，不记录凭据或完整供应商 prompt。
5. **教学审阅**：修复后正确识别 S1/六步和 SUM 材料缺口仍须观察真实回答；软件接线/学生编辑修正/模型自行识别分别记录。真人课堂质量和真实研究效果不由合成 E2E 代替。

核心验收必须先有2、3的反证通过，再申请既定真实运行；既有错误输出和学生修正记录不删除。
