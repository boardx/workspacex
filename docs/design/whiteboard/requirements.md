# WorkspaceX Board 产品需求文档

状态：Draft。下列范围与数值是建议验收目标，不是现有系统能力或已批准承诺。证据与竞品来源见 [research.md](research.md)。

## R1 产品目标、用户与成功标准

以便利贴作为想法的最小表达单位，以白板作为共同理解、关系表达和决策的共享空间。帮助组织把讨论沉淀成有来源、可复用、可执行的成果，并为人类、AI 和物理会议室共享这一空间提供基础。

主要角色：工作坊主持人、组织内参与者、受邀外部参与者、异步评论者、只读观察者、组织管理员；扩展角色为受委托的 Agent、API 应用及会议室设备。

**首版替代承诺有明确边界**：团队头脑风暴、亲和分组、复盘、简单流程与关系图、投票决策和行动梳理。不承诺覆盖组织在 Miro 上的所有应用；实际替代资格必须以该组织的代表性白板和工作坊验证。复杂工程制图、完整 UML/BPMN、任意第三方小组件兼容、视频会议和 Miro 全格式无损迁移不在首版。

建议试点：选择一个组织的两个团队，以 10 份代表性历史白板、3 场完整工作坊验收；目标场景全部完成且无阻断，连续两周无需因范围内缺陷退回 Miro，主持人与管理员共同确认可切换。记录回退原因、任务成功率、首次参与者创建便签耗时及会后成果使用率。

## R2 前置条件与入口

- WorkspaceX 内从项目工作台、议程环节、聊天引用或白板列表进入；同一白板可被多个入口引用，身份与内容不复制。
- 创建者具备所属组织/项目的创建权限，选择空白板或模板；既有模板遵守版本发布与绑定规则。
- 受邀参与者先完成有效身份或限时访客会话校验，再获取限定白板权限。分享链接不是无限制访问凭据。
- 独立开源部署有自有身份适配器及首个管理员引导流程；没有 WorkspaceX 或模型密钥也能完成多人工作坊。

## R3 首版主流程与能力范围

| 编号 | 用户目标 | 必须可观察的行为 |
|---|---|---|
| WB-01 | 准备与分享 | 创建、命名、复制、归档、恢复白板；按权限分享；从最近使用、项目和搜索找到白板 |
| WB-02 | 快速表达想法 | 工具栏或快捷键创建便签，连续输入；多行/表格粘贴预览为便签；支持中文输入法、颜色、大小、基础文字样式、作者与标签 |
| WB-03 | 组织想法 | 框选/多选、拖动、复制、对齐、等距分布、编组/解组；便利贴进入 Frame；按关键词/标签查找并定位 |
| WB-04 | 画清关系 | 文本、矩形、圆、菱形、自由笔迹、箭头连接线与线标签；端点绑定对象，移动对象后连线仍正确；图片/附件卡引用资产 |
| WB-05 | 导航与讲解 | 平移、缩放、适应内容、缩略地图、Frame 目录与顺序演示；主持人邀请跟随，参与者随时退出跟随 |
| WB-06 | 实时共同编辑 | 看见参与者、光标与正在编辑的对象；同一便签文字可并发编辑；重连收敛；本地撤销不撤回他人的操作 |
| WB-07 | 完成工作坊 | 模板、服务端计时、个人私密便签区与主动发布、定额匿名投票及结果排序；结束后仍可追溯本轮决策 |
| WB-08 | 异步讨论与行动 | 对象评论、提及、解决评论；删除对象后保留可定位的讨论上下文；选中便签创建或关联 WorkspaceX 任务，保存白板反链 |
| WB-09 | 安全保存与复用 | 自动持久化、明确保存状态、版本检查点、复制历史版本为新白板；导出 PNG、按 Frame 分页 PDF、便签 CSV、开放 JSON+附件包 |
| WB-10 | 迁入现有工作 | CSV/表格迁入便签；授权 Miro API 迁移受支持对象并输出逐项报告；不支持内容保留参考链接或经用户确认的静态附件 |
| WB-11 | 可编程集成 | 对象级读取/创建/更新/删除、批量命令、导入导出任务、变更事件；API 与界面遵循相同授权和校验规则 |
| WB-12 | 将 Chat 图表带入协作 | Chat 中当前可渲染的 Mermaid/Fabric 图表及 canvas/persona 模板可“插入 Board”；保留当前可见布局、内容、连接和来源，成为可编辑、可多人协作的图形对象集合 |

### R3.1 Chat 图表插入 Board（WB-12，用户明确要求）

1. 用户在 Chat 图表卡片或最大化编辑器点击“插入 Board”；选择有写权限的现有白板或新建白板，再选择 Frame/放置位置。
2. 系统展示将插入的完整图表预览；默认采用当前可见版本，包括编辑器尚未写回 Mermaid 的布局调整。若有未保存内容编辑，明确提示本次会生成独立副本。
3. 用户确认后，系统将图表作为一个可整体移动的图形组插入；进入组后可选择节点、改文字、移动节点、编辑连接，并在周围补便签。导入的特殊图型保留原有专用形状/数据和连接语义，不能一律降为矩形。
4. Board 协作者通过 Yjs 看见完整插入结果；收到持久化确认才提示成功，并提供“打开 Board 并定位”。刷新后仍保留插入时布局和后续编辑。
5. 图形组保留 Chat 会话、消息、图块及源版本引用；有来源访问权限者可跳回原对话。插入默认是独立副本，Board 修改不自动覆盖 Chat，Chat 后续重新生成也不自动覆盖 Board。

覆盖范围以 Chat 实际可渲染图型的权威注册/校验入口为准，每种图型建立 fixture 验收；不能只完成流程图就宣称“各种图表”已支持。包中存在但 Chat 尚未开放的语法不冒称已有入口。当前可渲染图型的对象转换缺口属于首版待完成项；图片降级不能充当 WB-12 的通过证据。对未来未知或损坏图型，可解释原因并让用户选择插入静态快照或取消，禁止静默截图替代。

典型 60 分钟工作坊：

1. 主持人从模板建板，设置议题和 Frames，邀请成员与受限访客。
2. 参与者在个人区输入想法，准备好后主动发布；其他参与者看不到未发布文字。
3. 大家拖动便签亲和分组、加标签和组名；同一便签可共同修订文字。
4. 用箭头和形状建立关系，主持人启动计时并邀请跟随当前 Frame。
5. 主持人锁定投票候选集合和每人额度；参与者投票，结束后只展示汇总。
6. 参与者讨论结果、补评论；主持人将选定便签关联行动任务。
7. 保存检查点，导出成果；会后通过对象链接继续异步讨论。

## R4 异常、并发与恢复

| 情况 | 产品行为 |
|---|---|
| 网络中断 | 显示“离线，改动暂存在此设备”；允许已授权内容本地编辑；禁用需要服务端裁决的投票、分享、发布私密内容和 AI 执行 |
| 重连且权限有效 | 上传待同步更新，合并差异；收到持久化确认后才显示“已保存” |
| 离线期间权限被撤销 | 不上传、不继续获取远端变化；保留隔离的待处理本地状态，按组织策略允许申请恢复，不能借“恢复”导出已被禁止的数据 |
| 两人编辑同一文字 | 合并字符操作；支持中文组合输入；不以整段覆盖替代并发编辑 |
| 两人拖同一对象 | 显示占用提示但不假装独占锁；最终位置确定性收敛；整个几何值原子更新，避免拼出混合坐标 |
| 删除与编辑并发 | 删除对象不因迟到修改自动复活；可从历史查看丢失上下文，显式恢复创建新对象并保留来源 |
| 被引用对象删除 | 连线隐藏或显示断链提示；评论保留“原对象已删除”；不静默改绑其他对象 |
| 保存失败/服务端崩溃 | 保留待同步提示和重试；重启恢复所有已确认更新；不把仅在内存的状态标为持久化成功 |
| 导入含不支持对象/超限附件 | 先预检；报告支持、降级、跳过与失败项，允许取消；重试不重复创建；原板保持不变 |
| AI 执行期间人工修改 | 基于对象前置版本检查，冲突项转为待重新审阅；不覆盖新的人工作业 |
| 批量操作失败 | 一个有界批次全成或全败；大型导入按分批任务报告部分成功与重试范围 |
| 计时/投票时主持人离开 | 服务端时间继续；授权共同主持人可接管；成员刷新后恢复同一会话状态 |
| 插件不可用 | 显示通用占位卡、保留原始字段与位置；仍可导出，其他对象可编辑 |
| Chat 图表仍在流式生成/渲染失败 | 禁用插入并说明原因；围栏闭合且图表完成校验后才允许确认 |
| 插入期间源版本改变 | 使用用户确认时冻结的版本；提示有新版本可重新预览，不混合两个版本的对象 |
| 重复点击或插入请求重试 | 同一操作幂等，只出现一组；主动再次插入产生独立的新组和对象 ID |
| 无源内容转出权或目标写权限 | 服务端拒绝且不泄露源内容；跨项目分享范围扩大时按组织策略确认或拒绝，不因能读私聊就可复制到任意公共板 |

## R5 权限与可见性

以下为白板能力角色，映射到现有身份域，不新建组织身份系统。权限同时受组织策略、项目成员关系和白板授权约束。

| 角色 | 能力 | 约束 |
|---|---|---|
| 所有者/管理员 | 授权、归档、恢复、保留策略、导出策略 | 管理身份本身不自动得到未发布私密便签或投票明细的产品读取入口 |
| 主持人 | 编辑、Frame 引导、计时、投票 | 不强制接管他人的视口；不读取个人私密区 |
| 编辑者 | 修改共享对象、投票、评论 | 无权修改权限、服务端审计和他人私密内容 |
| 评论者 | 读取与评论 | 不修改画布对象 |
| 查看者 | 读取、独立导航 | 导出须额外授权；不能写评论/对象 |
| 访客 | 被授予的上述能力子集 | 限定 board、到期时间，可撤销；不继承整个项目访问权限 |
| Agent/API 应用 | 受委托的明确能力集合 | 最终权限为调用者授权与应用能力的交集，不用全组织管理员 token |
| 会议室设备 | 展示或临时编辑 | 独立设备身份、指定 board、有限会期；扫码加入人员使用个人身份 |

对象“防误拖锁定”是交互功能，编辑者可显式解锁；不是安全边界。需要机密内容时使用独立授权文档/白板，不能靠隐藏 Frame、图层或前端遮罩实现。

## R6 范围与演进

**首版正式试点必须完成 WB-01—WB-12 及 R9 可靠性门槛。** 可按增量交付，但中途演示版不称为可替代 Miro。

后续 A：AI 聚类、摘要、基于便签生成流程图、提炼行动，支持逐项预览与应用；多 Agent 有独立身份、任务范围、预算与可取消运行。

后续 B：会议室扫码配对、触控优化、多端接力、会后自动收回设备授权；语音转写引用、相机采集实体便签均需另立用例，不默认持续录音。

后续 C：第三方对象插件、行业图形库、高级布局、组织级模板治理、更大规模板与跨板知识图谱。

首版不做插件市场、全自动主持、跨组织 AI 自主交换数据、原生移动端、AR/VR 或 3D 场景。普通浏览器投屏和基本触控参与从首版保留，会议室专用运营能力后续交付。

## R7 业务规则与内容语义

- 每个对象有稳定 ID；复制生成新 ID，保留来源引用。作者、最近修改者、AI 来源分开记录。
- 便签与任务不同：便签可关联任务；任务状态由原任务域权威管理，不在白板复制一套状态机。
- Frame 是导航、输出和空间组织单位；Group 是一起变换的对象集合；Tag 是语义分类。空间移动不应自动改变业务分类。
- 私密创意区按本人授权隔离；“发布”复制选定内容到共享板，并显示不可撤回他人已见内容的事实。
- 投票候选在开始时冻结，额度服务端校验，重试不能多计票；截止时以服务端接收为准；截止前不向普通成员暴露他人投票或实时排行。
- “匿名投票”指成员界面不展示投票者；是否保留受控审计映射由组织策略决定，不能宣传为运营方也无法关联的密码学匿名。
- 用户撤销只作用于自己的可撤销编辑；撤销已被协作者依赖的对象创建不得静默删除其后续内容，应提示并转为显式操作。
- 历史恢复默认复制为新白板，避免将旧快照直接并入当前 Y.Doc 后造成内容复活。
- AI 输出默认进入建议集，用户可逐项接受；若组织允许自动执行，必须预先限定板、对象/动作、有效期与预算，并保留停止入口。

## R8 交互设计线索

中心为白板，顶部放名称、参与者、保存状态、分享和演示；左侧常驻便利贴、选择、文字、形状、连接线、画笔和附件；底部放缩放、Frame 导航；评论、历史和 AI 建议按需打开右侧面板。

便利贴优先：点击工具后点击画布创建；输入中 Enter 换行、Esc 结束编辑；非输入状态快捷键才生效；连续创建使用明确按钮/快捷操作。多行粘贴先选择“一张便签”或“按行拆分”，表格按单元格预览。文字溢出提供展开编辑，不无限缩小字号。

框选起点、拖动画布、对象拖动、触控双指平移/缩放必须有一致规则；笔输入与手指导航分开。连接线支持吸附端口与自由端点。演示跟随带明显退出入口。

不只依靠颜色区分作者或类别。提供键盘对象列表、搜索定位、可访问的 DOM 文字编辑和评论控件；主要工作坊操作可不用精确鼠标完成。视觉原型须覆盖空板、满板、中文长文、断线、只读、冲突建议与触控状态。

## R9 非功能验收目标

以下为首版建议基线，须在技术探针后确认，未实测前不作性能宣传。

| 维度 | 测试条件与通过标准 |
|---|---|
| 基准板 | 5,000 对象，其中 3,000 便签、500 连线；50 同时在线、20 持续编辑；图片使用缩略图且懒加载 |
| 首次可交互 | 4 核/8GB 桌面、当前稳定 Chrome、50Mbps/100ms RTT，非缓存进入基准板 p95 ≤5 秒 |
| 操作反馈 | 同环境本地键入/拖动响应 p95 ≤50ms；20 人编辑时远端可见 p95 ≤500ms；持续拖动帧率 ≥30fps |
| 断线恢复 | 断网 60 秒期间每人编辑 100 次；恢复网络后 10 秒内收敛，无已确认数据丢失，待提交被拒明确可见 |
| 故障恢复 | 注入房间进程崩溃，已持久化确认更新零丢失，客户端 60 秒内重新连入；灾备另测，建议 RPO≤15 分钟/RTO≤4 小时 |
| 租户隔离 | 跨组织 HTTP/WS/附件/导出请求均被拒；撤权后 5 秒内断开在线连接，缓存敏感视图关闭 |
| 可用性 | 试点后服务月可用性目标 99.9%；定义成功接入、同步和持久化指标，排除计划维护须明示 |
| 兼容性 | 发布时 Chrome/Edge/Firefox/Safari 最近两个主要版本；iPad Safari 触控及中文 IME 专项验证 |
| 无障碍 | 核心流程以 WCAG 2.2 AA 为设计目标；键盘、读屏、缩放和对比度人工测试，不能只用自动扫描判完成 |
| 容量与降级 | 超过测试容量明确告警、限制新增或建议拆板；不承诺无限对象/无限并发；逐板限制更新大小、附件量与导入批次 |

数据保留、版本保留、私密区清理和删除策略需可配置；删除覆盖更新日志、快照、投影和附件引用，并定义备份到期清除。首版不默认遥测板内文字。

## R10 依赖与开源要求

复用 WorkspaceX 的身份/组织/项目权限、资产与文件治理、Agent 运行、任务对象和模板注册表；详见架构中的接入边界。

开放核心需包含便利贴、基本制图、Yjs 多人同步、持久化、基础权限、导入导出和 API，使自托管用户能独立完成主流程。交付 Docker Compose 示例、备份恢复操作、版本升级说明、SDK 示例与扩展对象示例。

许可证作为发布决策单独确认，建议评估 Apache-2.0；本需求不更改仓库许可证。依赖、字体、图标、模板、第三方源码需清单与兼容性审查；不得让开源核心启动依赖商业 GoJS 授权或 WorkspaceX 托管服务。

## R11 交付顺序与进入开发门槛

1. 设计与探针：评审本文；真实组件原型；证明中文编辑、Yjs 恶意更新拒绝、50 人基准、保存后崩溃恢复；对渲染器作证据选型。
2. 协作基础：领域对象、授权、便签交互、同步持久化、重连撤权与本地撤销。
3. 工作坊闭环：分组、Frame、图形连接、Chat 图表插入 Board、评论、私密区、计时投票、任务关联。
4. 替代上线：迁移报告、导出备份、版本恢复、开放 API、自托管安装、性能/权限验收和组织试点。
5. 后续扩展：AI 建议与多 Agent，再到会议室专用模式及插件生态；核心数据和身份模型从第一步预留。

以上是交付切片，不是 feature 清单，也不是工期承诺。每片继续拆成可独立验证的用户目标；UI 原型产出后生成唯一 feature 清单并建立契约束。正式 ADR 经 `harness new-adr` 起号，保持 Proposed，待评审后采纳。

## R12 验收场景与待确认项

| 场景 | Given / When / Then | 证据要求 |
|---|---|---|
| A01 工作坊 | 有主持人与成员，按 R3 完整操作，生成可重开的板、投票汇总、行动反链和导出成果 | 多浏览器录像、对象清单及产出文件 |
| A02 并发编辑 | 两浏览器同便签输入不同文本并交换更新，两端保留插入且语义状态一致 | 真实 WS、服务端记录、状态断言 |
| A03 撤销隔离 | A 创建、B 修改、A 撤销，不静默丢失 B 内容；A 撤销自己的文字编辑不撤销 B 文字 | 并发顺序测试与截图 |
| A04 持久化 | 收到已保存后杀进程，重启仍能读取全部已确认对象 | 确认序号、重启前后语义 hash |
| A05 隔离与撤权 | 未授权方伪造 boardId/更新/附件请求或权限被撤销，服务端拒绝且不泄露内容 | HTTP/WS 负例与审计 |
| A06 私密与投票 | 未发布便签和他人投票存在，检查网络/客户端文档/导出均无泄露；重复投票不超额度 | 协议捕获、服务端断言 |
| A07 迁移 | 10 份样板导入，受支持对象数量、文字、连接端点与 Frame 归属正确；所有损失都有报告 | 源/目标清单、差异报告与人工截图 |
| A08 API | API 创建便签在浏览器实时出现，浏览器修改后 API 可读；相同幂等键重放不重复 | 跨入口集成测试 |
| A09 自托管 | 无 WorkspaceX/AI 密钥的全新安装，两用户完成 A01 | 安装日志、重启与备份恢复记录 |
| A10 扩展兼容 | 未来对象插件不在当前客户端，旧客户端显示占位且往返导出保留数据 | 版本兼容 fixture |
| A11 Chat 图表插入 | 对 Chat 当前所有可渲染图型逐一插入，包括编辑器调整过布局的版本；图形可整体移动、逐对象编辑、与便利贴连线，第二客户端同步且刷新保留布局 | 图型覆盖矩阵、前后视觉对比、节点/边/专用属性断言与真实双浏览器 WS 证据 |
| A12 插入边界 | 同操作重试不重复；独立再次插入无 ID 冲突；源图变化不覆盖 Board；无源转出权/目标写权限、未闭合围栏均拒绝 | 幂等、版本隔离和权限负例；确认静态降级不计入 A11 通过数 |

这些是验收规格，尚无已运行的测试命令；实施时逐项绑定真实测试与证据路径，不将文档断言当成功证据。

待确认：目标组织的必用场景与实际并发量；是否以外部访客作为首批试点重点；Miro 迁移可获得的授权与样本；开源许可证；会议室设备类型与离线时长；保留/匿名投票审计策略。未答复前采用本文工作坊优先的起草假设。
