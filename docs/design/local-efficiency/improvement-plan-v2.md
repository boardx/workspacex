# 本地版效率与质量改进方案 v2（含级联架构评估）

对标的是**实测基线**，不是感觉。每条都给：针对哪个数字、预期收益、可证伪判据、成本与风险。

## 一、基线（实测，Apple M5 / 16 GB / macOS 26.5）

| 指标 | 现状 | 九分线 | 差距 |
| --- | --- | --- | --- |
| 更新后首次启动 | **33.7 s**（屏幕全黑） | — | 最刺眼 |
| 正常启动到界面 | **10.7 s** | ≤3 s 且首屏可交互 | 3.5× |
| 冷机第一条消息 | **~18 s**，无提示 | ≤3 s 且有「装载 x%」 | 6× |
| 温机首 token | 0.08 s | ≤3 s | ✅ |
| 吞吐 | 34–35 tok/s | ≥7 | ✅ 5× |
| 包体 | 7,009 MB | 行业 400 MB–4 GB | 1.8× |
| 关机收尾 | 459 ms ～ 5,268 ms | — | 方差 11× |

## 二、对级联架构（Jev / Laya / Kev / SemIf / GLiClass）的判断

提案是：`GLiClass → Laya/Kev → Qwen4B → 云`，理由是「60–80% 的 decision 不必进 Qwen4B」。

**这个前提在本仓可能不成立，而它是整个方案的地基。** 已知事实：

- 本地版实际的大模型调用只有四处：聊天、起标题、追问建议、agui-bridge
  ——**四个都需要自由文本**，而 decision model 产不出自由文本。
- research 那一串 `guided-*` 调用（source relevance、outline、direction…）
  **在本地版不可用**（深度研究是独立部署的服务，不随包）。
- 高频判断（意图路由、工具预算、skill 选择、模板匹配）**已经是正则或 embedding**
  ——也就是说**已经在 System-1 层了**，只不过用的是正则。
- #3770 实测：在本仓真实路由任务上，**正则 0.850 > Laya 0.775**；
  最好组合 0.875 只多对 1/40（n=40，噪声内）。成本 1.7 GB 常驻 / 4.7 GB 加载峰值 /
  18–20 s 加载 / DMG +1.5–2 GB。

**所以级联的价值取决于一件还没测的事**：agent 选择 / guardrail / retry / escalation
在我们系统里是不是**靠大模型**做的。这就是下面 R1。

**排序原则：先用零成本的方式验证收益，再考虑引入任何新模型。**
SemIf 那条路（拿现有 Qwen3.5-4B 读 option logits，不训练、不加模型、包体不涨）
是唯一满足这个原则的，所以它排在 Laya / Kev / GLiClass 之前。

「训练 WorkspaceX 自己的 System-1」这条**单独立轨**：它的第一个障碍不是训练方法，
而是**几十万条标注决策数据从哪来**——本地版是单机产品、刚发布。先做数据盘点再谈训练。

## 三、十条方案（按「每单位工作量能动多少实测数字」排）

| # | 方案 | 针对 | 预期 | 可证伪判据 | 成本/风险 |
| --- | --- | --- | --- | --- | --- |
| **1** | **前提测量**：一条真实消息触发几次模型调用、每次什么形状、各多长 | 级联地基 | — | 分类形状调用的**条数与占比** | 极低（发一条消息读日志） |
| **2** | **SemIf 式 logit 判断**（现有 Qwen，不加模型） | R1 测出的分类调用 | 每条 2 s → 数十 ms | 同一判断的 latency 与准确率 vs 现状 | 低；无包体增长 |
| **3** | **冷路径「正在加载模型 x%」** | 18 s 无提示 | 可感等待 ↓ | 装载期间界面有确定性百分比 | 低 |
| **4** | **首屏就是应用**，未就绪区域各自显示状态 | 10.7 s | 首个可交互元素提前 | 首个可交互元素出现时刻 | 中 |
| **5** | **NestJS 惰性模块加载** | API +7.9 s | 案例 −60% | API listening 时刻 | 中 |
| **6** | **停止键真的停掉采样** | 未取证 | 质量 | 掐断后 runner CPU / tok-s 归零 | 低 |
| **7** | **签名 + 公证 + staple** | **33.7 s** | 可能整条消除 | 首行日志时刻 | **卡人类：需证书** |
| **8** | **元任务不抢模型槽**（排队/降级，不加 2B） | 起标题挤后回复 | 用户等待 ↓ | 用户 run 的排队时间 | 中 |
| **9** | **日志一键导出 + doctor 先开日志** | 只有「打开数据目录」；doctor 模态框在任何日志之前 | 支持可查 | 菜单能导出归档；硬件不达标时磁盘有痕迹 | 低 |
| **10** | **29 处原生弹窗 → 应用内提示** | `confirm` 阻塞渲染进程 | 质量 | 计数归零 | 中 |

### 明确不做（已被实测或研究否掉，避免重复投入）

- **继续剪包换速度**：R16 减字节 12% → 首启税 0 变化；R17 减文件 34% → 只 −13%。已证伪。
- **优化吞吐**：34 tok/s 已 5× 于线，且研究显示 wrapper 之间 tok/s 无差异。
- **编译 API 换启动速度**：研究显示 tsx 只占 50–100 ms，方向错。（对包体仍有意义。）
- **常驻 Laya**：#3770 已测，三种配置（常驻/按需/与正则组合）都不成立。
- **加 2B 元模型**：人类决策 2026-09-24 不加。

## 四、十轮排程

R1 前提测量 → R2 SemIf（若 R1 成立；否则跳到 R3）→ R3 模型装载进度 →
R4 首屏 → R5 NestJS 惰性 → R6 停止键 → R7 元任务排队 → R8 日志导出 →
R9 原生弹窗 → R10 复盘重打分。

第 7 条（签名）**不占轮次**：拿到证书就插队先做——它同时解掉 33.7 s、
维度 8 的更新通道、以及维度 2/5/6 的真机验收。

每轮的纪律：① 落地前写下**可证伪预测** ② 实测前后对比 ③ 反证（去掉改动必须变红）
④ **结果与预测不符时说不符**，不改事后解释。
