# Recovery collection boundary for frozen 9b25

This is a reviewable collection/rehearsal scope, not authorization to run it. Application 9b25bfa65662b96c0826fe67506b562ea46aa6d0; baseline ba6343199f3c834d6a198f83d0c771614292c82b. No production data has been collected or restored by this iteration.

The existing prehold verifier compares ciphertext, table row hash streams, catalog/roles/sequences and restore receipts from root-private referenced bytes. It cannot prove cross-database consistency or full object recovery. Its unconditional common-snapshot/object/provenance rejection stays in place until the following causal producer chain is implemented and independently tested. Setting JSON passed/providerVerified/complete flags cannot discharge it.

Required producer-to-consumer chain:

1. A separately authorized collection attempt establishes the canonical inherited release lock, durable hold generation and an exhaustive writer fence. Three observed writer-role maps must exactly cover reviewed roles and every fenced role must be NOLOGIN; current sessions/processes/containers/automation and prepared transactions must be exhaustively classified. Preserve raw diagnostic observations and the source-bound journal before, during and after collection. Per-database exported PostgreSQL snapshots alone do not establish a common three-database point. A documented interval with all writers blocked throughout all dumps/catalog/row/object-reference captures is required; no release of the hold inside the interval.
2. The fixed collector produces three encrypted dumps and actual source catalogs, role/ACL/membership closures, sequences, version/peer identities, streaming table row hashes, and all object references from the same frozen interval. Bind each raw file's bytes/hash to the exact attempt, tool source, source instance, database, connection and barrier generation. Preserve actual provider response bytes and invocation identity/status/timestamps; independently validate them rather than reading a caller assertion. Collection errors retain the hold and label write state unproven unless a fresh independent barrier observation succeeds.
3. Object closure includes database references plus source catalog/schema discovery, unresolved references and unknown storage producers. Unknown tables/columns/namespaces reject. For every referenced object, retain bucket/prefix/key/version, actual provider response identity, streamed object bytes/hash/length, copied-object identity and restored-byte hash. Missing, deleted, ambiguous-version, same-key-different-content, cross-namespace, partial listing and unclassified producers reject. Existing cn_object_inventory and cn_restore_objects modules cover parts, not a complete closure or authenticated production collection.
4. An independently approved isolated target receives only the bound backups/objects. Actual restore execution and read-only comparison must replay the original raw artifacts, full schema/role/ACL/sequence/row closure and object content. It must verify target provider/peer identity differs from production before restore. A receipt boolean or an object's mere existence is insufficient.
5. A root-private artifact manifest closes over all originals and producer provenance. A separate offline validator recomputes common frozen interval, database/object closure and content equivalence; the existing prehold consumer may admit only that independently recomputed result, exact executor/tool capability and frozen source/baseline/plan/attempt. Positive fixture acceptance must not enable the production CLI or replace a real approved rehearsal.

Pending authorization must specify exact collection host/provider source, isolated target, private artifact destination and retention, allowed data transfer, object namespace, maintenance duration, fixture account/tenant and cleanup, backup capacity/client image, permissions, writer stop/resume and recovery plan. Current evidence is insufficient to populate those values honestly; the request must not be framed as approval for an unspecified broad restore. The shared historical ciphertext files do not establish a common snapshot or object closure.

Implementation remains incomplete: no authenticated common-barrier/object-provenance producer plus independent prehold positive consumer exists. This document does not mark recovery verified or production ready.
