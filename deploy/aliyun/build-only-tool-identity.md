# Reviewed tools for a frozen application build

`workspacex-cn-build-candidate --build-only <root-private-binding.json> <applicationSHA> <release> <attempt>` is an explicit artifact lane. The three-argument legacy entry retains its dynamic preactivate gate. Neither lane promotes main-cn here. This extends merged #5168 static bootstrap semantics without changing the frozen application.

The independently reviewed tool commit must be installed by an authorized operator in `/opt/workspacex-cn/release-tools/<toolSHA>` with clean HEAD and root-owned, non-writable ancestors/files. Before any new installation, review/approve exact files and hashes. The binding is an EXCL root:root 0600 JSON file with `schemaVersion:1`, `mode:"build-only"`, `applicationRevision`, `toolRevision`, `toolRoot`, `release`, `attemptId`, and `filesSha256` for exactly the ten paths enumerated by `cn-build-tool-identity.py`. This list includes the loader itself. Eight existing trusted executables plus the new loader must equal their tool Git objects and their listed hashes; the validator must also equal its exact tool object. No unchecked alternate tool directory or caller-provided executable is accepted.

The binding also contains `applicationSource:{path:"/var/lib/workspacex-cn/build-sources/<applicationSHA>.git",ref:"refs/heads/candidate",treeSha,inventorySha256}`. Prepare that dedicated root-private, complete bare cache from the already verified source artifact before invoking this lane; do not change the shared mirror's moving main. The loader checks exact candidate ref/commit/tree, hashes its recursive Git tree inventory, runs full fsck, and rejects alternates/promisor config/packs. The build fetches only this offline ref; the ordinary lane retains its existing origin/main source gate. Existing ancestry checking remains. Collector reuses this bound cache rather than asserting current shared main equals an older frozen candidate.

Application checkout/source cache, offline dependencies, config and stable secrets retain existing prebuild checks. The tool collector uses the frozen application's actual compatibility CLI with `--static` in the application cwd; it never copies application modules or claims production schema/permission/seed readiness. Tool collector/evidence/probe and validator bytes come from the independent reviewed tool identity, rather than the application SHA. Source revision in images/manifest remains the application SHA.

Publisher performs actual immutable registry inspections for all six services. After publishing, the explicit lane re-reads manifest, seal, and original prebuild evidence, verifies exact application/release/attempt and static-only facts, requires a fresh prebuild TTL and the actually held canonical FD9 lock, repeats six registry digest inspections, and creates EXCL root600 `build-only.sealed.json` alongside prebuild receipts. It binds application/tool revisions, all tool hashes, binding/prebuild/manifest/seal hashes, and immutable image references. `ready`, `prepared`, and `productionActivated` remain false. Registry failure or any changed tool/seal/static fact prevents this receipt.

This receipt is not accepted by deploy preparation or activation. Existing preactivate dynamic schema/permission and real production bootstrap gates remain unchanged; a source-static receipt cannot substitute for them. No migration, provisioning, service activation, traffic change, or production SQL is added by this change.

Local verification: nine Python stdlib tests (identity, source-cache, closure, drift and receipt negative fixtures), sixteen existing preflight validator tests and three Bash syntax checks. Local verification uses Python stdlib synthetic fixtures and shell syntax checks, not production credentials or a live build. Full CI and authorized exact tool installation are required before cloud use; this PR alone does not retrofit an already installed 9b25 toolchain.

The loader validates every Git metadata directory/file before invoking Git, rejects external Git directories, symlinks and config includes, and disables fsmonitor/hooks explicitly. Receipt admission re-executes the exact bound tool validator and compares its complete result with `prebuild.validated.json`; no subset of bootstrap fields substitutes for that gate.

Receipt publication uses a private temporary file, file fsync, an exclusive atomic hard link and directory fsync. An existing final receipt is never replaced. If interruption happens after the link, read back that exact final path and hash before deciding whether the operation committed; do not blindly retry. A killed process may leave its UUID temporary file, which requires ownership/inode proof before cleanup.
