This is not an execution instruction or approval.

`cn_backup_sql.py`, `backup_connection.cjs` and `cn_backup_channel.py` implement actual fixed-query PostgreSQL transport, catalog capture, object/grant/column ACL checks, guarded exact create/grant/login/close/revoke and readback. `cn_backup_profile.py`, `cn_backup_profile_host.py`, `backup_profile_transport.cjs` implement protected actual file capture and the compiled canonical provider/exception verifier. The configuration SHA and three-database canonical provider digest are bound to the plan; existing numeric destination .44, source .40/32, RDS/ECS identity and private exception are preserved. `cn_backup_host.py` runs the cached fixed PostgreSQL image only, no pull: before CREATE it verifies actual pg_dump/pg_restore16 output and pg_dump executable hash, protected custody/retention/escrow/recovery references, CMS synthetic encryption/decryption and an exact archive TOC. Exports are serial fixed pg_dump custom/serializable-deferrable snapshots, bounded memory plaintext piped directly to CMS ciphertext. `cn_backup_backend.py` binds the actual SQL backend PID/start/application name/client port to a unique host TCP inode, pg_dump PID/start/cgroup/container image and executable hash. Another backend's transaction_read_only GUC is not SQL-observable; receipts explicitly use pinned-pg_dump implementation attestation with sqlObserved=false.

The observer uses its own newly opened channel, not inherited IPC state. Only root600 metadata is returned atomically. Child, byte, EOF, dual-exit and ciphertext hash checks are required. Docker client exit does not prove cleanup. `cn_backup_watchdog.py` starts before CREATE, opens its own three cleanup-only channels, then owns cleanup on parent EOF, timeout or protocol failure. Before the final role scan it joins only the exact producer-owned administrative backends (PID/start/database/application name/client IP/port), so an in-flight CREATE/COMMIT cannot appear after cleanup reports completion. It never signals a foreign or its own cleanup session. It records a durable journal; journal failure does not skip NOLOGIN, exact owned-container stop, session absence, PASSWORD NULL/NOBYPASSRLS and exact revocation/readback. Foreign containers/backends are never killed. Recipient key is retained. Unknown cleanup fails the iteration.

The existing 300-second source-freshness limit is preserved. The shared total budget ends 120 seconds before the earliest freshness/lease/plan deadline; it is not a new one-hour unverified transport bypass. A too-slow run fails and cleans up rather than extending that bound.
