# Provision 执行核心

此模块负责执行纪律，不单独宣称应用安装成功。由实际部署入口提供 preflight → secrets → dependencies → migrate → bootstrap → start → readiness → business-probe 八个动作。Starter 需要在 dependencies 阶段启动 PG/Redis，生产则确认已准备的托管依赖。所有动作都在计时范围内。

- 总预算最多 300 秒，从调用入口开始计算；每步获得统一 AbortSignal 与剩余时间。
- 状态目录要求私有权限 0700，原子独占创建 provision.lock。并发运行明确失败。
- 每次尝试独立 UUID 报告，记录阶段、耗时和固定错误码，不覆盖历史记录，不记录原始异常或凭据。
- 普通阶段失败停止后续步骤，不删除已有用户数据，不自动执行危险回滚。重新运行所有阶段，各业务动作必须自身幂等。
- 超时/取消保留锁，原因是自定义动作可能不响应取消，不能在未知旧任务仍运行时启动新安装。确认旧进程与子进程结束、检查报告后才能由受控恢复流程解除锁；不以 PID 或文件年龄自动判断安全。
- POSIX 子进程执行使用 argv 和 shell:false，不拼 shell；取消时终止进程组。逃离进程组的守护进程不在此保证内，生产动作不得 daemonize，容器生命周期须经专用部署动作控制。
- 密钥引用支持 env: 与 file:。文件必须私有、常规文件、非符号链接、UTF-8 且 <=64KiB。自动密钥使用随机值原子发布，重跑和并发不会轮换已有值，损坏状态拒绝启动。

目前核心包含真实文件锁/报告/子进程/密钥测试。Docker、迁移、管理员初始化、HTTPS/模型/OSS/沙箱的实际动作正由独立工作项接入；本模块测试不能替代这些业务验收。宿主文件系统卡死、进程被强杀或事件循环被同步代码阻塞不能由 JavaScript 定时器提供硬实时保证，目标 Linux 部署命令须保持异步且受外层作业监督。
