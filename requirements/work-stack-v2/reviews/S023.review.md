## Professional depth
M1–M9 是针对账户计划本身的方法，不是模板化文字：足迹先行、目标必须有出处、覆盖要求客户侧回复、四因子白区打分、冲突与陈旧判定、refresh 差异，都是这个实体特有的内容，决策 1–5 也有论证。但下面几处有阻塞问题，会让规格无法按「可复算、可机检」落地：

**B1 白区打分只定义了 3 分和 0 分。** M5 表格只给出每个因子 3 分与 0 分的条件，1 分和 2 分没有定义；§10 又写了 CN「集团已有框架时 `accessPath` 给 2 分起」。决策 2 以「可复算、可被 reviewer 手算」作为理由，E1 也断言了具体分数，但两个实现者对同一输入会算出不同的 `total`。需要把四个因子各自 0/1/2/3 的判定条件写全，并把 CN 的调整写进表格。

**B2 客户侧证据无法从输入结构判定。** M4 的 `covered` 要求有「客户侧回复」，O9 要求「客户侧证据」，E5、E7 也依赖区分发言方。但 `evidence[]` 只有 `kind/quote/occurredAt`，没有发言方/方向（例如 `speakerSide: "customer" | "vendor"`、`direction`），也没有 `contactRef`。结果是：O9 只按 `kind ∈ {transcript,email,customer-doc}` 判定，而 E7 的会议转写（只有本方销售说话）的 kind 就是 transcript，按 O9 的规则放行 `create-new` 是合法的，这和 E7 期望的 `hold` 相矛盾。E5 的「3 封邮件无回复」也没法从 schema 推导出来。需要给 evidence 加上发言方与联系人关联字段，并据此重写 O9 和 M4 的判定。

**B3 O3/O5 所依赖的字段不在输出里。** O3 写的是「`parked` ⇔ `healthRef.overall`/S035 `expansionReadiness = blocked`」，但 `healthRef` 只有 `overall`，没有 `expansionReadiness`；`overall` 与 `expansionReadiness` 也是两个不同的量（S035 第 67 行：amber 对应 conditional）。只看输出无法机检 O3 和 O5，O3 的表述本身也有歧义。需要在输出中记录 `expansionReadiness`（以及 `blockedBy`，例如放进 `healthRef` 或单列 `expansionGateRef`），并把 O3 改成只依据 `expansionReadiness`。

**B4 E2 与 O4 相冲突。** E2 要求「至少一条动作的 `linkedTo` 指向阻塞原因」，但 O4 规定 `linkedTo` 只能指向本计划内的对象（白区项/风险/覆盖缺口），S035 的 `blockedBy` 不是计划对象。需要定义阻塞原因在计划内的承载对象（例如 `risks[].kind` 新增一类，或新增 `blockers[]`），或者修改 E2。

非阻塞：
- `horizon` 的注释「retention 缺省 quarter；其余缺省 quarter」是冗余写法；另外它是必填字段，却写了缺省值，应统一为可选并给出缺省。
- `coverage` 的 key 是 `buyingUnit` 字符串，但 `linkedTo` 需要指向「覆盖缺口 id」，而覆盖格没有 id。建议给覆盖格或缺口加上 id。
