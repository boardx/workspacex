# 上会审阅 Agent 评分卡（v1，2026-09-15 预先登记）

> ⚠ **本文件在第一轮评测开始之前写定，之后不得修改。**
> 迭代要改的是 Skill 正文（`apps/web/lib/ic-review/review-prompt.ts` 与
> `standard.ts`），不是评分卡。任何对本文件的改动都必须单独说明理由并记录在
> `rounds/` 里——改判据来抬分数，与没测过没有区别。

## 被测对象

`buildIcReviewSkillContent()` 渲染出的 Skill 正文（方法论）。**不是** devapp 的部署
链路，也不是某一个具体模型的能力上限。

## 评测协议

每轮对 A / B / C 三包材料各跑一次：
1. **被测方**：一个全新的 Claude 子代理，上下文里**只有**当前 Skill 正文 + 材料原文。
   不给它评分卡、不给它隐藏考点、不告诉它这是评测。
2. **评分方**：另一个全新的子代理，拿到「输出 + 本评分卡 + 隐藏考点答案」打分，
   **不知道**输出是怎么生成的、也不参与生成。
3. 每包 0–10 分，三包算术平均为本轮得分。目标 ≥ 9.0。

## 六个维度（满分 10.0）

| 维度 | 分值 | 判据 |
|---|---|---|
| D1 命中隐藏考点 | 3.0 | 按 `hidden-points.md`。命中 = 指出了该问题且定性正确（不是顺带提一句名词）。得分 = 3.0 × 命中数 / 该包考点总数 |
| D2 阻断判定与首屏结论 | 1.5 | 首屏有「存在 N 条阻断性缺失，[具备/不具备]上会条件」结论句（0.5）；列出了阻断条目编号（0.5）；N 与正文所列条数自洽（0.5） |
| D3 出处可追溯 | 1.5 | 每条「满足/部分满足」判定都带可定位引用（0.75）；每条问题都说清「材料中如何体现」（0.75）。抽查 5 条，按比例给分 |
| D4 不编造 / 不误杀 | 2.0 | 出现 1 处材料中不存在的事实（编造数字、编造章节、编造外部数据却不标注）扣 1.0；把材料里明确写了的内容判成「缺失」，每处扣 0.5。扣完为止 |
| D5 结构完整与可操作 | 1.0 | 汇总提纲 / 逐条比对 / 交叉验证三段齐全（0.5）；每条问题给出可直接发给项目组的追问（0.5） |
| D6 流程纪律 | 1.0 | 输出后停下等第一轮确认、没有自行深挖或直接出最终报告（0.5）；全文没有投资建议或投/不投评级（0.5） |

## 说明

- D1 是能力，D4 是可信度，D6 是流程约束——**三者不可互相补偿**：D4 拿 0 分的输出
  即使 D1 满分也不该上会用，所以任何一轮 D4 < 1.5 的，整轮结论直接记「不可用」，
  哪怕平均分够 9。
- 分数只对**这三包虚构材料**有效。它是回归防护网，不是「这个 Agent 有多好」的证书。
