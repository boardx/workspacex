# 评分卡 v2 —— 需求功能性满足 + 可用性（2026-09-15 人类指令后登记）

> **为什么新增而不是改 v1**：v1 评的是「审得准不准」（命中考点、不编造、出处可追溯）。
> 人类 2026-09-15 指令：「你要从需求的功能性满足，以及可用性的角度，来评估分数」。
> 这是评分维度不够，不是分数不好看——所以**另立一张卡**，v1 原样保留继续跑（作为
> 质量回归与否决项来源），不回头修改 v1 的任何判据或已打出的分数。
>
> 从第 2 轮起：**总分以本卡为准**（需求 5 + 可用性 5 = 10），目标 ≥ 9.0；
> v1 继续每轮打分，其 D4（不编造/不误杀）< 1.5 仍是一票否决。

## 需求来源（判 F 维的依据，不是我临时想的）

- 时序图：投资经理 ↔ 资料审阅 Agent，13 步，含 3 个人工确认关口
- HMW 卡：帮投资分析人员，在集团投决会前项目分析中，克服资料分析工作量大、时间长，
  从而快速识别资料问题
- 《大模型测试方案 V1.0》：三包材料与隐藏考点

## F 需求功能性满足（5.0）

| 维度 | 分值 | 判据 |
|---|---|---|
| F1 主链路覆盖 | 1.5 | 时序图的九个动作在输出里都实际发生：读材料 → 汇总提纲 → 对标准查缺 → 跨文档交叉验证 → 风险标注 → 停等第一轮确认 → （确认后）定向深挖 → 停等第二轮确认 → 整合最终报告。缺一个扣 0.17 |
| F2 人工确认关口 | 1.0 | 第一轮确认真实存在且**请求的是可回答的东西**（逐条确认/驳回 + 风险分级 + 圈选深挖）0.5；明确说明第二轮确认在哪、以及未经确认不会自行出最终报告 0.5 |
| F3 三类问题分列 | 1.0 | 显性矛盾 / 隐性异常 / 关联遗漏三类**分开标注**且归类正确 0.6；每条含「问题/原因/材料中如何体现/建议追问」四要素 0.4 |
| F4 边界遵守 | 0.75 | 不给投资建议或投/不投评级 0.25；不改写材料原文 0.25；材料中没有的事实只进「需核实清单」不进「已满足」0.25 |
| F5 读取失败可见 | 0.75 | 未能读取/未提供的材料单独列出并说明原因，不静默跳过（本轮材料齐全时，看它是否显式声明"本次无未能读取的文件"或等价表述）|

## U 可用性（5.0）—— 站在投资分析人员的位置看

| 维度 | 分值 | 判据 |
|---|---|---|
| U1 30 秒可判断 | 1.0 | 首屏就能回答「能不能上会、卡在哪几条」：结论句 + 分组编号 + 阻断项名称。要往下翻才知道结论的，扣满 |
| U2 信噪比 | 1.0 | 「写了但不够」与「根本没有」分开 0.5；38 条逐条判定没有淹没重点（有分组/有小结/能快速跳读）0.5 |
| U3 可直接行动 | 1.0 | 追问事项能**原样复制发给项目组**：具体、指名要什么材料 0.5；按对象或优先级组织而不是流水账 0.5 |
| U4 可核验 | 1.0 | 每个推算给出算式与每个输入项的出处，人能在 5 分钟内复核 0.5；外部/常识判断明确标注未取证 0.5 |
| U5 交互成本 | 1.0 | 要用户做的决定清晰有限（确认/驳回/分级/圈选），不是开放式「您怎么看」0.5；一次交互能完成，不需要用户反复澄清 0.5 |

## 本卡测不到的（不许折算进分数）

- `/agent/team1` 入口 → 真实 chat 的部署链路可用性（要 devapp，且 devapp 需配模型凭据）
- 真实上会材料（几十上百页 PDF/PPT）下的表现——本评测三包材料只有 800–1600 字
- 换一个模型 provider 后的表现

以上三条只能在真实环境验收，**不写进这 10 分**，也不在结论里含糊带过。
