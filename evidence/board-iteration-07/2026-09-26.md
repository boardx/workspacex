## Verified behavior

- Presence carries server-resolved `displayName`, avatar and human/Agent principal kind together with cursor, selection, editing state, viewport, presenter and follow state. Viewport revisions are monotonic at the gateway and follower.
- Comments no longer live in the client-writable Yjs document. Authenticated API commands bind the actor from the server principal, enforce the board ACL (Viewer is read-only), validate object/mention targets, persist comment threads and append audit events atomically. Object deletion archives its sidecar comments.
- Local edits are retained in a bounded AES-GCM IndexedDB outbox. Refresh/crash restore preserves update IDs for idempotent replay; ACK removes the durable entry; auth refresh rebinds it; revocation clears it and writes an auth-scoped tombstone that prevents stale restore.
- Comment success is rendered only after the authoritative HTTP response. Undo/redo are described as locally applied while the WebSocket provider visibly exposes pending count and the authoritative ACK sequence; offline state never claims synchronization.
- Checkpoint create/restore routes are wired through controller, application service, PostgreSQL metadata/CAS and immutable object storage. Restore retries are request-idempotent while the first execution retains the epoch/sequence compare-and-swap.
- Remote Yjs updates remain outside the personal `WhiteboardUndo` origin, so one collaborator's undo does not remove another collaborator's changes.
- Comment overlays keep the canvas pass-through layer `pointer-events-none` and opt only comment buttons into `pointer-events-auto`.

## Independent review remediation — 2026-09-27

- Delete undo now restores the authenticated tombstone with the original object ID, so connectors, comments and other references retain identity. The same `restore` command is exposed through the authenticated board command API.
- Undo/redo delivery is confirmed by the exact `{ updateId, gestureId }` receipt emitted for that gesture. A larger global sequence or an ACK with only one matching field cannot confirm the operation.
- A corrupt or missing requested checkpoint falls back to the newest verified checkpoint in the same epoch, requires a contiguous update segment through the requested sequence, rebuilds the Yjs snapshot and atomically records `CheckpointFallbackUsed` with `BoardRestored`.
- Auth-token rebind decrypts and re-encrypts all AES-GCM outbox rows before one IndexedDB transaction replaces source rows. Fault injection covers every put, delete and transaction-completion boundary and demonstrates rollback.
- `commenter` is now a separate board role: it can read and comment but cannot mutate board content, archive object comments or create checkpoints. Comments may be anchored to either an object ID or an immutable world position, with exactly one anchor required by the contract.
- The real-browser acceptance scenario covers commenter permissions and a world-position comment. It is listed successfully here and remains assigned to the main session for execution.
