# Board Iteration 08 — object storage and vendor import

Exact implementation branch: `codex/board-iteration-08-storage-import`.

## Review closure

- ZIP central-directory metadata is parsed and bounded before any entry inflation.
  Only stored/deflate entries are accepted; each extraction uses a hard output cap,
  exact advertised size and CRC32. Tests cover compression bombs, forged sizes,
  forged CRCs, traversal, and truncated image magic.
- ZIP general-purpose flags now fail closed with mask `0x2061`: traditional
  encryption (bit 0), patched data (bit 5), strong encryption (bit 6), and
  encrypted central-directory metadata (bit 13) are rejected from the central
  directory before extraction. The local and central flags must still match
  exactly. Regression tests mutate both real headers for every rejected bit,
  while valid STORE and DEFLATE archives remain accepted.
- Legacy document snapshots and accepted update bodies are uploaded through the
  tenant/board-scoped ObjectStore path, read back, verified, and published with a
  PostgreSQL compare-and-swap. A missing ObjectStore permits legacy reads only and
  rejects every new write. `apps/api/scripts/whiteboard-object-backfill-complete.sql`
  is the mechanical completion gate before legacy bytea removal.
- Checkpoint creation verifies hash and byte size after every `putOnce`, including a
  successful fresh write, before publishing recovery metadata.
- Import references are resolved only against final emitted objects. Parents must be
  emitted panels and connector endpoints must be emitted objects; each invalid link
  is reported and skipped without failing the batch. Mural circles retain the circle
  variant and every unknown shape downgrade produces `VALUE_NORMALIZED`.
- Versioned nested Miro/Mural archive fixtures preserve source version and board
  provenance. Raster assets require bounded structure and dimensions; truncated
  PNG/GIF/JPEG/WebP signatures are not accepted as assets.
