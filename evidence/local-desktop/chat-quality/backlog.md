# chat 质量 backlog（2026-09-24）

> 这份表只收**有证据的**问题：每条都指得出是哪一次实测、在哪份证据里看得见。
> 「怎么算修好」写成可执行判据，不写「优化一下」这种没法验收的话。
>
> 三份评测的现状（命令都在仓库根跑）：
>
> | 命令 | 回答什么 | 现状 |
> |---|---|---|
> | `pnpm run e2e:real-model-smoke` | **真实模型**下一次任务的真实形态 | **7/8**，缺的是产物 |
> | `pnpm run eval:always-lands` | 用户拿不拿得到结果（含故障注入） | 6/6 |
> | `pnpm run eval:plan-execute` | 七条路径连着跑稳不稳 | 21/21 |
> | `pnpm run eval:chat-ux` | 体验对标 Claude Code 几分 | 8.0/10 |
>
> ⚠ 后三份全跑在**确定性替身**上。P0 那两条在替身上**全绿**，只有真实模型才暴露——
> 这就是为什么 P0 排在最前面：我们最严的门，看不见用户最痛的那件事。

## P0 · 真实模型下用户拿不到东西（2026-09-24 实测，证据包 `apps/web/test-results/real-model-evidence/`）

### B1 · 系统提示与技能协议被当成回答吐给用户
- **证据**：`40-assistant-bubbles.json` 单条气泡 **66149 字**；`90-final-screen.png` 里
  用户屏幕上是 `run_script` 协议块、`The sandbox has NO network access`、
  画布模板的「条数上限〔分区名=N条〕」配置规则。用户问的是中国教育与 AI 融合。
- **为什么是 P0**：它同时是体验灾难与内部信息外泄；而且极可能**就是 B2 的成因**
  （模型把协议当内容复述，自然不会真去写文件）。
- **怎么算修好**：真实模型跑同一条 prompt，助手气泡里不出现
  `run_script` / `SKILL_SANDBOX_OUT_DIR` / `The sandbox has NO network access`
  / `模板: <key>` 这些**只应存在于系统提示**的字符串。加进 real-model lane 的断言，
  并在确定性替身上补一条同形状的单测（替身要能复现这个形状，否则门是空的）。

### B2 · 脚本退出码 0、没写任何文件 ⇒ 没有产物，而这一轮被当成成功
- **证据**：同一份气泡末尾「脚本执行成功（退出码 0），但没有向输出目录写入任何文件，
  因此这轮没有可下载的产物」；`01-verdict.txt` 断言 ⑥ 失败（产出文件卡数量为 0）；
  同时断言 ④「全程没有出现错误横幅」**通过**——界面认为一切正常。
- **怎么算修好**：脚本跑完但输出目录为空时，这一轮必须落**失败终态**并说清
  「没有产出文件」+ 下一步（重试 / 换表述）。判据接进 `eval:always-lands` 的不变量表
  （新增一格「脚本空产出」），要求终态、成因、下一步、刷新后仍在四项全绿。

### B3 · 跑了 429 秒才知道没有产物
- **证据**：`01-verdict.txt` 断言 ②「发出后 429s 走到终态」。
- **怎么算修好**：先有数据再定预算——把真实模型 lane 的耗时逐轮落进证据包并出 p50/p95，
  再对照 `.harness/instructions/chat-agent-performance-acceptance.md` 那张 SLO 表定阈值。
  **不先拍一个数字**（这一晚已经因为「没有真实耗时分布就调超时」按住过一次，见 B7）。

## P1 · 联网失败（F1 已修四件，剩这些）

### B4 · 联网工具的超时余量只有 +2 秒
- **证据**：`standard_web_tools.py` 的 `deadline=(deadlineMs+parseDeadlineMs)/1000+2`；
  网关稍慢就变成 Python 侧超时（不可重试、无成因）。
- **状态**：F1 只诊断未改——改预算要先有真实耗时分布，否则是拍脑袋。依赖 B3 的数据。
- **怎么算修好**：余量由实测 p95 推出并写进注释；补一条单测钉住「网关慢于 X 时
  报的是超时而不是别的成因」。

### B5 · `tool_call_unresolved`（工具调用发出去不回来）没有端到端取证
- **证据**：契约里有这个失败码（`wave2-runtime.ts`，2026-09-11 人类实测
  `render-office.py` 跑不回来那一幕），但 `eval:always-lands` 六格里没有它。
- **怎么算修好**：替身加一条「工具永不回执」剧本，进不变量表，四项全绿。
  这正是人类最早那张截图（「有一次工具调用始终没有返回结果」）的形状。

### B6 · deep research 不在成功率矩阵里
- **证据**：`guided-research-runtime.spec.ts` 在 `fullstack-smoke` 车道，
  与 office/画布不同栏，`eval:plan-execute` 覆盖不到。
- **怎么算修好**：research 场景进矩阵（或矩阵跨栏跑），与 office/画布同样重复跑并计成功率。

## P2 · 评测集自己的缺口

### B7 · 三份评测都没进 CI
- **现状**：只能本地手跑。回归发生时没有人会知道。
- **怎么算修好**：`eval:always-lands` + `eval:plan-execute` 进 PR 门控（约 3–4 分钟/条）；
  `e2e:real-model-smoke` 进定时车道（它要真实凭据与约 8 分钟，不适合每个 PR）。

### B8 · 探针抛异常时，记分卡文件仍是上一轮的内容
- **证据**：2026-09-24 评测集 E3，`distinct` 变量被误删导致探针抛异常，
  而 `ux-scorecard.md` 还是上一轮的数——差点被当成本轮结果读。
- **怎么算修好**：每轮开跑先把报告写成「本轮未完成」，跑完再覆盖；
  读报告的人看到的要么是这一轮的数，要么是「没跑完」，不会是上一轮的数。

### B9 · 语音（评测第 ⑤ 项）没有探针，占 1 分按 0 计
- **怎么算修好**：接 loopback ASR 替身（`chat-read` 车道已有该 provider 端口），
  量「实时转写是否逐段更新、结果可编辑后发送」。

### B10 · 多轮上下文（第 ⑥ 项）天花板 0.6
- **原因**：loopback 替身判不了「真的记得」。
- **怎么算修好**：二选一，需人类裁决——① 接真实模型车道量语义记忆；
  ② 改判据把这一项的满分定义为「链路通 + 上下文真的进了请求」。

### B11 · 评测判据覆盖不到「文件能否在右栏预览」
- **证据**：E4 做完文件右栏预览，`eval:chat-ux` 一分没动——十项判据里没有这一问。
- **怎么算修好**：要么并进第 ⑧ 项（消息呈现质量），要么在验收文档里新增一项
  （**改判据是人类的动作**，不是 agent 自己加）。

## P3 · 存量债

### B12 · 57 个文件 / 86 处内部错误码仍会上屏
- **证据**：`lint-user-facing-error-text` 的棘轮基线（只准变小）。
- **怎么算修好**：按屏优先级逐个销账，每次只减不增。

### B13 · 键盘用户要按 113 次 Tab 才能到输入框
- **证据**：并行会话 2026-09-23 真机实测（会话列表就占 30 个）。
- **状态**：并行会话在做（跳转链接），**我不重复**。

### B14 · 产物「来源」只能说「有没有出处」，说不出「出处有哪些」
- **证据**：E8 —— citations 在服务端 `findCitationsForMessage` 里，
  但**没有按产物读回的接口**。
- **怎么算修好**：需契约改动 ⇒ **人类签核**，不由 agent 自作主张。

## 依赖与顺序

```
B1 ──→ B2（B1 很可能就是 B2 的成因，先查 B1）
B3 ──→ B4（没有真实耗时分布就不定超时阈值）
B5、B6 可与 B1 并行
B7 在 B2/B5 有了判据之后再接 CI（否则接的是会漂的门）
B10、B11、B14 等人类裁决
```

**下一步我建议按 B1 → B2 → B5 → B3/B4 的顺序做**：B1 是唯一同时命中
「体验灾难 + 内部信息外泄 + 很可能是产物缺失成因」的一条。
