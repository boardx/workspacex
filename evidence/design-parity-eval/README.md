# 设计工作台 × Claude Design 对标评测

人类 2026-09-23：「做一个评测集，然后做 10 轮迭代，每轮要有 e2e 测试，找出问题和差距，到达 9 分。」

## 这把尺子量什么

**产品能力**：同样一份「Claude Design 水平的产出」，我们能不能画出来、能不能改、能不能协作、能不能交出去。
十个维度、42 条检查，每条都是真浏览器里一个用户看得见的结果（颜色、位置、文字、下载文件的内容）。

- 评测集：`apps/web/e2e/parity-eval/cases.mjs` —— 10 个普通人会提的需求 + 各自的金标准产出
- 检查：`apps/web/e2e/parity-eval/design-parity.eval.ts`（标题以 `[Dx.cy]` 开头）
- 维度定义与打分：`apps/web/e2e/parity-eval/score.mjs`（维度得分 = 通过条数 / 总条数，总分 = 十维之和）

## 它不量什么（必须说在前面）

1. **生成质量**。本容器没有真实模型的凭据，金标准是人写的「理想产出」，所以这里量不到「AI 画得好不好」。
   那要靠真实模型车道（`.harness/instructions/real-model-e2e.md`）+ 同题盲评——两边各跑同一组需求、截图、人来比。
2. **与 Claude Design 的逐像素对比**。维度来自 Claude Design 公开的产品行为（对话生成、行内批注、直接编辑、
   调参、设计系统、导出与交接），不是把两个产品并排截图。分数的含义是「这些能力我们有没有、做没做对」。
3. D5（生成体验）在基线就是满分：量的是既有的等待/取消/建议/照图画四件事。流式逐字生成不在检查里——
   夹具没法诚实地模拟它，写一条假的检查不如不写。

## 规则

- **冻结**：用例、金标准与检查在 R0 冻结。之后只允许修评测自身的 bug，并在下面的轮次记录里写明理由；
  不允许为了分数改金标准或放宽检查。
- **目标接口**：检查里引用的 testid / `data-proto` 有一部分基线时还不存在——那就是差距本身。
  实现时以检查里的名字为准，不在实现那边另起一个名字再回头改检查。
- **testid 门的豁免**：检查引用的目标 testid 基线时不存在，`lint-e2e-testid-gate` 会拦。这些行带
  `// testid-gate: absent …` 标注；实现了那个 testid 的一轮**必须删掉**对应标注——那道门在
  testid 出现后会把留着的标注判成陈旧而红，所以「实现了却忘了摘」不会发生。
- **不是 CI 门**：基线大面积失败。每一轮修掉的差距，另写回归 e2e 进 `playwright.design-loop.config.ts`
  车道——那条才是门；这里只负责出分。

## 跑法

```bash
cd apps/web
PW_EXECUTABLE=/opt/pw-browsers/chromium-1194/chrome-linux/chrome npx playwright test -c playwright.parity-eval.config.ts
node e2e/parity-eval/score.mjs --round R1     # → evidence/design-parity-eval/R1.md / R1.json
```

## 十轮计划（按差距大小与依赖排）

| 轮 | 要解决的问题 | 主要维度 |
|---|---|---|
| R1 | 品牌色只能从 8 个预设里挑，字体只有一种 | D1 |
| R2 | 没有设计系统：圆角 / 密度 / 字体不能一处改处处变，也不跟着导出 | D2 |
| R3 | 表达不了表格和带数据的图表（看板类需求直接缺一半） | D4 |
| R4 | 表达不了下拉、单选和弹窗叠层（表单与确认流程画不出来） | D4 |
| R5 | 只能做 App 屏：官网落地页的分区与页脚、幻灯片都做不了 | D3 |
| R6 | 预览里控件是死的：tabs 不能切、开关不能拨、输入框不能打字 | D9 |
| R7 | 直接编辑缺三样：重做、画布上直接改字、图层拖拽排序 | D6 |
| R8 | 没有批注：不能在元素上钉一句话，再一次交给 AI 改 | D7 |
| R9 | 没有变体：不能一次出几个方案并排比、挑一个 | D8 |
| R10 | 交不出代码：只能导出 HTML / 图片 / 文档 | D10 |
