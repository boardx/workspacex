# Chat failure controls #6244

The v2 message stream uses TaskTimeline → RunTracePanel. Terminal runs with failures (failed status or succeeded/cancelled with structured failed tool entries) now keep a compact summary; their plan and subtask detail remains available by expanding. Hide/restore stores only a browser preference keyed by organization, thread, run and latest attempt ID; no server journal mutation. Running runs and successful runs without failed tool entries ignore the preference.

Retry on the inline trace is offered only for the current error banner's run, with an existing resendable message, writable/nonbusy state, and no competing plan recovery. It reuses the same existing send/clientMessageId/attachments path as the error banner. Historical runs never dispatch retry against the current plan. Existing plan recovery remains unchanged.

Validation: unit.log (34 tests); browser.log (Chromium real component, compiled production styles, collapsed geometry <100px); compact-failed-trace.png visually inspected; typecheck.log (tsc --noEmit exit 0); design.log (lint-design passed). The first screenshot uses an SSR geometry fixture. timeline-browser.log and timeline-hidden.png additionally verify real CopilotKit + TaskTimeline browser interactions: hiding all associated assistant bubbles, preserving the user request and another successful run, persistence across reload, and restoring the full failed reply. This fixture uses a local runtime-info response and does not claim live API/model recovery. Scope/attempt and retry eligibility also have component regressions. PR CI provides the application regression lane.

The timeline owns shared hidden state, so all assistant messages and interjection receipts associated with the run disappear together; only the trace anchor keeps its restore placeholder. New browser spec is discovered by the existing playwright.trace-geometry.config.ts geometry pattern, executed in harness-verify.yml and harness-acceptance.yml.
