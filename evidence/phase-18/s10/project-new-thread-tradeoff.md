## S10 积压：项目里的「新对话」默认私有——设计取舍（待人类定，本轮不实现）

**现状。** 在项目页点「新对话」，建出的线程是组员私聊（`member-private`）：只有创建者看得到。要让同事看到，
创建者（或引导师）得在对话卡片的「可见范围」里手动改成「本组共享」或「全场」（R5）。结果是项目里的讨论默认
彼此不可见，同事之间没法接着同一段对话往下聊。项目大脑（R7「记到项目大脑」、S10「分享到项目…」）只能收
「结论」，收不了「对话本身」。

**影响这件事的两个已有决定。**
- #4284（2026-09-26）：提问人的**个人记忆**也用于项目对话里他本人的回答。回答正文对能看到这条线程的所有人
  可见，可能复述个人记忆。线程默认越开放，这个已知取舍的影响面越大。
- R7：只有线程创建者或引导师能把线程里的结论记到项目大脑。默认共享不会让别人替你记。

### 选项

| | 做法 | 好处 | 代价 / 风险 |
|---|---|---|---|
| **A** | 保持默认私有；第一条回答之后在对话顶部提示一次「这条对话只有你看得到 · 分享给本组 / 全场」 | 不改隐私默认；改动最小（只加前端提示）；不影响已有线程 | 仍要多点一步，多数人不会点，「同事没法共用」基本不变 |
| **B** | 默认改成共享：有分组的项目默认「本组共享」，没有分组的默认「全场」；想私聊在对话里改 | 协作默认成立，最贴近「项目里的对话」的直觉 | 隐私默认被翻转：已经习惯「项目里新对话 = 私人草稿」的人会在不知情时把东西说给全组；叠加 #4284，个人记忆被复述进共享回答的面变大；需要改服务端默认值 + 一条迁移说明（旧线程不动） |
| **C** | 建的时候就选：「新建对话」拆成两个按钮「和本组一起聊」（主按钮）/「只有我看得到」（次按钮），标题下写清谁能看到 | 选择是显式的、一眼看懂；默认倾向协作，但不在不知情时公开；和 S10「先预览范围再确认」是同一个交互原则 | 多一个选择；按钮文案要测；服务端要接受建线程时带可见范围（契约 `createThread` 已有 `visibilityScope` 参数的话只改前端） |
| **D** | 项目级设置：引导师给项目定「新对话默认可见范围」 | 不同项目（内部小组 vs. 客户访谈）可以各取所需 | 多一个设置、多一处要解释的规则；普通成员看不出为什么这个项目默认公开、那个默认私有；实现量最大 |

### 建议

**选 C**：保留私聊入口，但主按钮是「和本组一起聊」（没有分组的项目是「和全场一起聊」），按钮下一行写
「本组 N 人能看到」（和 S10 分享预览同一个说法）。理由：
1. 解决「同事没法共用」的主诉求，又不在用户不知情时把内容公开（B 的主要风险）；
2. 和 #4284 的已知取舍相容：人在建线程那一刻就知道回答会被谁看到；
3. 只动新线程的创建入口，已有线程的可见范围一个都不改，回滚就是恢复原来的一个按钮；
4. 比 D 少一套项目级规则要解释。

如果人类更看重「零新交互」，退一步选 **A**（提示条），它不改变任何默认。**不建议 B**（隐私默认翻转）。
